第 36 章

CSPGO の二段構え
— -fcs-profile-generate と再マージ

三段階だった PGO が、五段階になります。増えるのは「二周目の計装ビルド」と「二周目のトレーニング」。手順自体は素直ですが、マージの仕方に一つ勘所があります。

この章のゴール

  • CSPGO の五段階を把握する
  • CS 計装ビルドを作る
  • 二つのプロファイルを正しく合成する
  • 合成結果に CS 情報が入っていることを確認する

36.1 五段階

36.2 ③ CS 計装ビルド

ここが要点です。一周目のプロファイルを適用しつつ、二周目の計装を仕込みます。

C/C++ > コマンド ライン > 追加のオプション

/clang:-fprofile-use=app.profdata
/clang:-fcs-profile-generate=cs_prof

二つを同時に指定します。片方だけでは意味がありません。

オプション役割
-fprofile-use=<file>一周目のプロファイルで最適化する。これにより最終ビルドと同じインライン展開が起きる
-fcs-profile-generate[=<dir>]インライン展開が済んだ状態で計装を挿入する
なぜ -fprofile-use が必要なのか

第 35 章で述べたとおり、二周目に測りたいのは展開後のコードです。展開のされ方は一周目のプロファイルによって決まります。それを適用せずに計装すると、最終ビルドとは違う形のコードを測ることになり、得られた文脈が的外れになります。

36.2.1 CS 計装ビルドのコスト

LogLab で実測しました。

ビルド.text実行時間
通常（/O2）8,103 B基準
PGO 最適化ビルド8,312 B—
一周目の計装ビルド34,274 B約 1.9 倍
CS 計装ビルド34,146 B一周目とほぼ同等

実測の一例

一周目の計装ビルドとほぼ同じ規模になります。CSPGO の追加コストは「もう一度同じことをやる」ぶんだと考えてよいでしょう。

36.3 ④ 二周目のトレーニング

一周目とまったく同じワークロードを流します。LLVM_PROFILE_FILE の扱いも第 27 章と同じです。

set LLVM_PROFILE_FILE=cs_prof\run-%%p.profraw
ClangOptLab_cs.exe 200000 10
ClangOptLab_cs.exe  20000 20
ClangOptLab_cs.exe 500000  4
同じワークロードを使ってください

一周目と二周目で違うワークロードを使うと、二つのプロファイルが別々の現実を記録することになり、合成した結果が意味を成しません。トレーニングスクリプトは共通化しておくのが安全です。

36.4 マージ — ここが勘所

二周目の .profraw だけを使ってはいけません。一周目の .profdata と一緒にマージします。

llvm-profdata merge -output=combined.profdata ^
    app.profdata ^
    cs_prof\*.profraw

llvm-profdata は、入力に含まれるコンテキスト非依存の情報と CS の情報を、それぞれ別の領域として保持します。片方だけでは、もう片方の情報が欠けた不完全なプロファイルになります。

36.4.1 中身を確認する

合成できたかどうかは、show で確かめられます。

llvm-profdata show combined.profdata

Instrumentation level: IR  entry_first = 0
Total functions: 40
Maximum function count: 52000000
Maximum internal block count: 116121080

これは第 30 章で見た一周目のプロファイルと同じ数字です。CS の部分を見るには -showcs を付けます。

llvm-profdata show -showcs combined.profdata

Instrumentation level: IR  entry_first = 0
Total functions: 29
Maximum function count: 26000000
Maximum internal block count: 26000000

関数の数が 40 と 29 で違います。 これが「二つの領域が別々に入っている」ことの証拠です。CS 側が少ないのは、インライン展開後に独立した実体として残った関数だけが対象になるためです。

確認の手順として

-showcs で何も表示されない、あるいは Total functions: 0 になる場合、CS のプロファイルが取り込まれていません。次のいずれかを疑ってください。

  • -fcs-profile-generate が渡っていない（第 3 章のビルドログ確認）
  • 二周目のトレーニングで .profraw が出ていない（第 26 章 26.6 節）
  • マージの入力に二周目のファイルが含まれていない

36.5 ⑤ 最終ビルド

合成したプロファイルを、通常どおり -fprofile-use に渡します。

/clang:-fprofile-use=combined.profdata

専用のオプションはありません。CS 情報が入っているかどうかは、プロファイル側が持っている情報です。コンパイラはそれを見て、あれば使います。

ビルドしたら、いつもどおり checksum を確認してください。

36.6 LTO と組み合わせる場合

LTO を有効にしていると、インライン展開の主戦場はリンク時に移ります（第 16 章）。すると CS 計装も、リンク時に行う必要があります。

そのために、lld-link 側に対応するオプションが用意されています。

オプション役割
/lto-cs-profile-generateLTO のコード生成時に CS 計装を行う
/lto-cs-profile-file:<path>出力先を指定する

第 4 部で lld-link のオプション一覧を眺めたとき、この二つが出てきました。ここで使います。

:: リンカーの追加のオプション
/lto-cs-profile-generate
/lto-cs-profile-file:cs_prof\cs.profraw

コンパイラ側は /clang:-fprofile-use=app.profdata /clang:-flto=thin のままです。CS 計装だけをリンカに任せる形になります。

組み合わせは段階的に

CSPGO と LTO を同時に導入すると、うまくいかないときの切り分けが難しくなります。まず PGO 単体 → CSPGO 単体 → LTO を足すの順で進め、各段階で checksum と効果を確認するのが確実です。組み合わせの詳細は第 38 章で扱います。

36.7 スクリプト

第 31 章の pgo.cmd を拡張します。段階が増えるぶん、手順の管理が重要になります。

@echo off
:: cspgo.cmd — CSPGO の五段階
setlocal
set ROOT=%~dp0
set SLN=%ROOT%ClangOptLab.sln
set P1=%ROOT%app.profdata
set P2=%ROOT%combined.profdata

call :build "/clang:-fprofile-generate"                    instr  || exit /b 1
call :train instr prof1                                           || exit /b 1
llvm-profdata merge -output="%P1%" "%ROOT%prof1\*.profraw"        || exit /b 1

call :build "/clang:-fprofile-use=%P1% /clang:-fcs-profile-generate" csinstr || exit /b 1
call :train csinstr prof2                                         || exit /b 1
llvm-profdata merge -output="%P2%" "%P1%" "%ROOT%prof2\*.profraw" || exit /b 1

llvm-profdata show -showcs "%P2%" | findstr /C:"Total functions"

call :build "/clang:-fprofile-use=%P2%"                    cspgo  || exit /b 1
echo 完了: builds\cspgo\ClangOptLab.exe
exit /b 0

:build
msbuild "%SLN%" /p:Configuration=Release /p:Platform=x64 ^
    /p:ClangExtraOptions=%~1 /t:Rebuild || exit /b 1
if not exist "%ROOT%builds\%~2" mkdir "%ROOT%builds\%~2"
copy /y "%ROOT%x64\Release\ClangOptLab.*" "%ROOT%builds\%~2\" >nul
exit /b 0

:train
if exist "%ROOT%%~2" rmdir /s /q "%ROOT%%~2"
mkdir "%ROOT%%~2"
set LLVM_PROFILE_FILE=%ROOT%%~2\run-%%p.profraw
"%ROOT%builds\%~1\ClangOptLab.exe" 200000 10 >nul
"%ROOT%builds\%~1\ClangOptLab.exe"  20000 20 >nul
"%ROOT%builds\%~1\ClangOptLab.exe" 500000  4 >nul
set LLVM_PROFILE_FILE=
exit /b 0

リスト 36-1　cspgo.cmd

トレーニングをサブルーチンにして、一周目と二周目で同じ処理を使い回しているのが要点です。36.3 節の警告——同じワークロードを使う——を、仕組みとして保証しています。

36.8 ハンズオン

  1. 第 31 章で作った app.profdata を用意する
  2. /clang:-fprofile-use=... と /clang:-fcs-profile-generate=... を両方指定してビルドする
  3. checksum を確認し、.text が計装ビルド並みに膨らんでいることを確認する
  4. 同じトレーニングを流して .profraw を得る
  5. 一周目の .profdata と一緒にマージする
  6. llvm-profdata show と show -showcs で、関数の数が違うことを確認する
  7. 合成プロファイルで最終ビルドを作り、builds\cspgo\ に退避する

36.9 まとめ

  • CSPGO は PGO の三段階に、CS 計装ビルドと二周目のトレーニングを足した五段階
  • CS 計装ビルドは -fprofile-use= と -fcs-profile-generate を同時に指定する
  • 一周目のプロファイルを適用するのは、最終ビルドと同じインライン展開を再現するため
  • CS 計装ビルドのコストは一周目の計装ビルドとほぼ同等（実測で .text 34,146 B）
  • マージには一周目の .profdata も入力に含める
  • llvm-profdata show -showcs で CS 部分だけを確認できる。LogLab では 40 関数と 29 関数だった
  • 最終ビルドは通常どおり -fprofile-use=。専用オプションは不要
  • LTO と併用する場合は、リンカ側の /lto-cs-profile-generate を使う

次章では、その効果を検証します。手順を五段階に増やし、トレーニングを二回流した見返りは何だったのか。LogLab での結果は——正直に言えば、はっきりしています。
