第 29 章

llvm-profdata merge
— 複数回の実行結果をまとめる

.profraw は、そのままではコンパイラに渡せません。llvm-profdata merge による変換が必ず一度は必要です。単なる形式変換に見えますが、複数のトレーニングを配合する機能もここにあります。

この章のゴール

  • .profraw と .profdata の違いを理解する
  • 複数のプロファイルをまとめる
  • 重み付けで配合を調整する
  • テキスト形式で中身を覗く

29.1 二つの形式

.profraw.profdata
作るもの計装されたプログラム（実行時）llvm-profdata merge
性質実行時に効率よく書き出せる形式。生データコンパイラが読むためにインデックス化された形式
個数実行ごと・プロセスごとに複数通常ひとつ
-fprofile-use に渡せるかいいえはい

実行が一回だけでも、merge は必要です。「まとめる」だけでなく「変換する」コマンドでもあるからです。

29.2 基本形

llvm-profdata merge -output=app.profdata prof\*.profraw

ワイルドカードで複数のファイルをまとめて渡せます。第 27 章で %p を使ってプロセスごとに分けたファイルが、ここで一つになります。

サイズは次のようになりました。

prof\default_..._0.profraw    6,528 B
app.profdata                  8,888 B

インデックスが付くぶん、少し大きくなります。

29.2.1 合計されることの確認

第 27 章でも見ましたが、改めて確認します。二回の実行を merge すると、カウンタは合計されます。

run-2191.profraw （50000 行 × 2 反復）    Maximum function count: 1300000
run-2192.profraw （50000 行 × 4 反復）    Maximum function count: 2600000

llvm-profdata merge -output=both.profdata run-*.profraw
both.profdata                             Maximum function count: 3900000

29.3 重み付け

単純な合計では困る場面があります。第 28 章で触れた「起動処理と定常処理のバランス」がそれです。

起動中心のトレーニングを 1 回、定常中心のトレーニングを 1 回採って単純に合計すると、両者が同じ重みで扱われます。しかし実際の比重は違うはずです。

llvm-profdata merge -output=app.profdata ^
    -weighted-input=10,steady.profraw ^
    -weighted-input=1,startup.profraw

<重み>,<ファイル名> という書式です。上の例では、定常処理のプロファイルを 10 倍に重み付けしています。

実測で確認すると、重みがそのままカウンタに掛かることが分かります。

通常の merge                     Maximum function count: 52,000,000
-weighted-input=10,... の場合    Maximum function count: 1,300,052,000
重みの決め方

厳密な理論はありません。「本番でこの局面が占める割合」を目安に決めます。起動が全体の 1% なら、定常を 100 倍にする——といった見当です。

ただし、重みを付ける前に「そもそも分けて採る必要があるのか」を考えてください。第 28 章で書いたとおり、定常処理を十分に長く回せば起動は自然に薄まります。重み付けが必要になるのは、それができない事情があるときです。

29.4 中身をテキストで見る

-text を付けると、人間が読める形式で出力されます。

llvm-profdata merge -text -output=app.proftext app.profdata

中身はこうなっています。

# IR level Instrumentation Flag
:ir
_ZN6loglab10parse_lineESt17basic_string_viewIcSt11char_traitsIcEERNS_6RecordE
# Func Hash:
547674798947670709
# Num Counters:
25
# Counter Values:
52000000
52000000
52000000
4000000
4000000
4035880
...

読み取れることを整理します。

行意味
:irIR レベル計装であることの印（第 25 章）
関数名マングル名。llvm-undname で戻せる
# Func Hash関数の制御フローから計算されたハッシュ。第 34 章の主役
# Num Countersこの関数に埋め込まれたカウンタの数
# Counter Values各カウンタが数えた回数

parse_line の先頭三つのカウンタが 52000000 で揃っているのは、関数の入口と、必ず通る基本ブロックです。20 万行 × 10 反復 × ... と積み上がった数字が、そのまま記録されています。

テキストからバイナリに戻せます

-text で出したファイルを、そのまま merge の入力にできます。

llvm-profdata merge -output=back.profdata app.proftext

プロファイルを手で編集して実験する、といったことも技術的には可能です。実務で使う場面は多くありませんが、「プロファイルとは結局こういうテキストだ」と理解しておくと、第 34 章の陳腐化の話が腑に落ちます。

29.5 主なオプション

オプション意味
-output=<file>出力先（必須）
-weighted-input=<w>,<file>重み付きの入力
-text / -binary出力形式（既定は -binary）
-sparseカウントが 0 のエントリを省き、サイズを削る
-num-threads=<N>マージの並列度（既定は自動）
-failure-mode=<mode>壊れた入力があったときの挙動
-sparse はいつ使うか

大規模なプロジェクトでは .profdata が数十 MB になることがあります。-sparse を付けると、一度も実行されなかった関数のエントリが省かれてサイズが縮みます。プロファイルをバージョン管理に入れる場合（第 34 章）に効いてきます。

29.6 バージョンの不一致

第 5 章で予告した話が、ここで実際に問題になります。

.profraw を書くのは計装ビルドに埋め込まれたプロファイルランタイム、読むのは llvm-profdata。この二つのバージョンが食い違うと失敗します。

error: xxx.profraw: unsupported instrumentation profile format version

典型的なのは、Visual Studio 同梱の clang-cl でビルドし、あとから入れた公式 LLVM の llvm-profdata でマージしようとするケースです。

:: 作業前に必ず確認する
clang-cl --version
llvm-profdata --version

メジャーバージョンが揃っていることを確認してください。第 5 章のチェックリストに入れておいた項目です。

29.7 スクリプトにまとめる

第 27 章の train.cmd に、マージまでを含めます。

@echo off
:: train.cmd — トレーニング実行からプロファイル生成まで
setlocal

set ROOT=%~dp0
set PROFDIR=%ROOT%prof
set EXE=%ROOT%builds\instr\ClangOptLab.exe
set OUT=%ROOT%app.profdata

if exist "%PROFDIR%" rmdir /s /q "%PROFDIR%"
mkdir "%PROFDIR%"
set LLVM_PROFILE_FILE=%PROFDIR%\run-%%p.profraw

echo [1/3] 通常のワークロード
"%EXE%" 200000 10 >nul
echo [2/3] 小さめの入力
"%EXE%"  20000 20 >nul
echo [3/3] 大きめの入力
"%EXE%" 500000  4 >nul

echo.
echo マージ中...
llvm-profdata merge -output="%OUT%" "%PROFDIR%\*.profraw" || exit /b 1

llvm-profdata show "%OUT%" | findstr /C:"Total functions" /C:"Maximum function count"
echo 生成: %OUT%
endlocal

リスト 29-1　train.cmd（マージまで）

29.8 ハンズオン

  1. リスト 29-1 の train.cmd を作って実行する
  2. app.profdata ができることを確認する
  3. .profraw と .profdata のサイズを比べる
  4. -text でテキスト形式に変換し、parse_line のエントリを探す
  5. カウンタの値を見て、実行回数から見当が付くか確かめる
  6. 試しに -weighted-input で重みを変えてみて、show の値が変わることを確認する

29.9 まとめ

  • .profraw は生データ、.profdata はコンパイラが読む形式。実行が一回でも merge は必要
  • 複数の .profraw をまとめると、カウンタは合計される
  • -weighted-input=<w>,<file> で配合を調整できる。重みはカウンタに掛かる
  • -text で中身を読める。関数名・Func Hash・カウンタ値が入っている
  • 大きなプロファイルには -sparse
  • clang-cl と llvm-profdata のメジャーバージョンを揃える

次章では、できあがったプロファイルを読みます。どの関数がホットだったのか、第 12・13 章のプロファイラの結果と一致するのか。そして llvm-cov でソースコード上にカウンタを重ねて表示します——ただし、そこには一つ落とし穴があります。
