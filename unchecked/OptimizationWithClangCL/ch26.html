第 26 章

計装ビルド
— -fprofile-generate とプロファイルランタイム

オプションは一つです。しかし Windows では「ライブラリが見つからない」という壁にぶつかることがあります。仕組みを知っていれば数分で解決する問題なので、先に押さえておきます。

この章のゴール

  • LogLab の計装ビルドを作る
  • プロファイルランタイムがどうリンクされるかを理解する
  • 計装のコスト（サイズと速度）を実測する
  • ビルド構成を分ける準備をする

26.1 オプション

構成プロパティ > C/C++ > コマンド ライン > 追加のオプション

/clang:-fprofile-generate

これだけです。/O2 はそのまま残します。計装ビルドも最適化された状態で作るのが重要です。最適化を切ってしまうと、実際に出荷するバイナリとは違う構造のコードを計測することになり、プロファイルの意味が薄れます。

リンカ側の設定は不要ですが、注意点があります

-fprofile-generate はコンパイラのオプションですが、リンク時にプロファイルランタイムのライブラリが必要になります。次節で説明する仕組みにより自動的にリンクされますが、ライブラリが見つかる場所にある必要があります。

26.2 プロファイルランタイムはどうリンクされるか

計装ビルドで作った .obj の中身を調べると、リンカへの指示が埋め込まれていることが分かります。

llvm-readobj --coff-directives tokenizer.obj

Directive(s): /DEFAULTLIB:libcmt.lib /DEFAULTLIB:oldnames.lib
              /DEFAULTLIB:clang_rt.profile-x86_64.lib
              /INCLUDE:__llvm_profile_runtime_user

/DEFAULTLIB:clang_rt.profile-x86_64.lib。これが「このライブラリもリンクしてくれ」という指示です。C++ で #pragma comment(lib, "...") と書いたときと同じ仕組みで、コンパイラが自動的に埋め込んでいます。

つまり、リンカのプロパティに何も書かなくてもリンクされます。ただしリンカがそのファイルを見つけられれば、の話です。

26.2.1 見つからないとき

clang_rt.profile-x86_64.lib は、LLVM のインストール先の下にあります。

<LLVM のルート>\lib\clang\<バージョン>\lib\windows\clang_rt.profile-x86_64.lib

実際の場所は環境によって違うので、まず探してください。

:: Visual Studio 同梱の LLVM の場合
dir /s /b "%VCINSTALLDIR%Tools\Llvm\x64\lib\clang_rt.profile*"

:: 公式 LLVM を入れている場合
dir /s /b "C:\Program Files\LLVM\lib\clang_rt.profile*"

見つかったら、そのフォルダをリンカのライブラリ検索パスに追加します。

構成プロパティ > リンカー > 全般 > 追加のライブラリ ディレクトリ

C:\Program Files\LLVM\lib\clang\21\lib\windows;%(AdditionalLibraryDirectories)
見つからないときのエラー

clang_rt.profile-x86_64.lib が見つからない、という趣旨のリンクエラーになります。「PGO のオプションが間違っている」と誤解しやすいところですが、単にライブラリの場所を教えていないだけです。

そもそもファイル自体が存在しない場合もあります。Visual Studio 同梱の LLVM には含まれていないことがあるので、その場合は第 2 章の手順で公式 LLVM を導入してください。第 5 章のチェックリストで llvm-profdata の有無を確認しておいたのは、この伏線でもあります。

26.3 計装ビルドのコスト

計装ビルドは、あらゆる分岐と関数呼び出しにカウンタの更新を挿入します。当然ながら重くなります。LogLab で実測しました。

ビルド.text サイズ実行時間
通常（/O2）8,103 B150 ms
計装（-fprofile-generate）34,274 B（4.2 倍）284 ms（1.9 倍）

実測の一例

コードが 4 倍に膨らみ、実行時間が約 2 倍になりました。この数字は覚えておく価値があります。

計装ビルドを出荷してはいけません

当たり前のようですが、実際に起こる事故です。ビルド構成を分けずに -fprofile-generate を追加のオプションに書き、そのままリリースしてしまう。2 倍遅いバイナリが世に出ることになります。

しかも計装ビルドは、実行のたびにプロファイルデータをディスクに書き出します。ユーザーの環境に見慣れないファイルが増える、という副作用も付いてきます。

26.3.1 オーバーヘッドが問題になる場合

2 倍というのは、多くの場合は許容範囲です。トレーニング実行は開発者の手元か CI で行うものだからです。ただし次のような場合は困ります。

  • 実時間の制約があるアプリ（ゲーム、リアルタイム処理）。フレーム落ちで挙動そのものが変わってしまう
  • タイムアウトのあるテストスイート
  • 非常に長時間動かす必要があるワークロード

これらの場合は、トレーニングの範囲を絞る、あるいはサンプリング型のプロファイルを使うといった選択肢があります（付録 C）。

26.4 ビルドして確認する

  1. 追加のオプションに /clang:-fprofile-generate を設定する
  2. ビルドが通ることを確認する（通らなければ 26.2.1 節）
  3. 実行して checksum が 0x0e8685105a08f105 のままであることを確認する
  4. 実行時間が通常ビルドの約 2 倍になっていることを確認する
  5. .exe のサイズが大きくなっていることを確認する
  6. 実行後、カレントディレクトリに *.profraw ができていることを確認する

6 番のファイル名は次のような形です。

default_6242892255425663173_0.profraw

これが計測結果の生データです。中身の読み方と出力先の制御は次章で扱います。

checksum の確認を忘れずに

計装ビルドでも結果は同じになるはずです。ここで値が変わるなら、計装がプログラムの挙動を変えてしまっている——つまり元のコードに未定義動作がある可能性があります。第 23 章で LTO について書いたのと同じ話です。

26.5 ビルド構成を分ける

PGO では、同じソースから三つの異なるバイナリを作ることになります。

バイナリオプション用途
基準/O2比較の基準（第 4 部で builds\baseline\ に退避済み）
計装/O2 /clang:-fprofile-generateトレーニング実行専用。捨てる
最適化/O2 /clang:-fprofile-use=...成果物

プロパティを手で切り替えながら進めることもできますが、切り替え忘れの事故が起きます。MSBuild で構成を追加するのが本筋で、その手順は第 39 章で扱います。本書の第 5 部では、当面は手で切り替えつつ、できた .exe を退避していく方式で進めます。

builds\
  baseline\   ClangOptLab.exe   <- /O2 のみ（第 4 部で作成）
  instr\      ClangOptLab.exe   <- 計装ビルド
  pgo\        ClangOptLab.exe   <- 最適化ビルド（第 31 章）

26.6 よくある失敗

clang_rt.profile-x86_64.lib が見つからない

26.2.1 節。ライブラリ検索パスの設定か、公式 LLVM の導入。

.profraw ができない

プログラムが正常終了していない可能性があります。プロファイルはプロセス終了時に書き出されるため、abort() や TerminateProcess、あるいはクラッシュで終わると書き出されません。まず正常に main から return しているかを確認してください。

書き込み権限がない場所で実行している

.profraw はカレントディレクトリに出力されます。書き込めない場所（C:\Program Files の下など）で実行すると失敗します。出力先の指定方法は次章で扱います。

計装ビルドが遅すぎて終わらない

反復回数を減らしてください。トレーニングに必要なのは「代表的な分布」であって「長時間の実行」ではありません。この話は第 28 章で扱います。

26.7 まとめ

  • 計装ビルドは /clang:-fprofile-generate。/O2 はそのまま残す
  • プロファイルランタイムは .obj に埋め込まれた /DEFAULTLIB 指示で自動的にリンクされる
  • ライブラリが見つからないときは検索パスの問題。 lib\clang\<ver>\lib\windows\ を追加する
  • 実測では .text が 4.2 倍、実行時間が 1.9 倍になった
  • 計装ビルドは測定専用。出荷してはいけない
  • 計装ビルドでも checksum は変わらないはず。変わったら未定義動作を疑う
  • プロセスが正常終了しないと .profraw は書き出されない

次章では、プロファイルの出力先を制御します。既定ではカレントディレクトリに固定の名前で出るため、複数回実行すると上書きされてしまいます。LLVM_PROFILE_FILE 環境変数とそのパターン指定を使って、実行ごと・プロセスごとにファイルを分ける方法を扱います。
