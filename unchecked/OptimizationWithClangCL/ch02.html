第 2 章

Visual Studio 2026 と ClangCL のセットアップ

ClangCL は Visual Studio に同梱されていますが、既定ではインストールされません。この章では必要なコンポーネントを入れ、コマンドラインからバージョンを確認し、必要に応じて公式 LLVM に差し替えるところまでを行います。

この章のゴール

  • ClangCL に必要な二つのインストーラコンポーネントを入れる
  • 同梱 LLVM がどこに置かれるかを自分の目で確認する
  • clang-cl --version の出力を読めるようになる
  • 公式 LLVM に差し替える方法（LLVMInstallDir）を知る

2.1 二つのコンポーネントが必要

ClangCL を使うには、Visual Studio インストーラで二つのコンポーネントを入れる必要があります。片方だけでは動きません。

コンポーネント入るものこれが無いと
C++ Clang Compiler for Windows
（Windows 用 C++ Clang コンパイラ）		clang-cl.exe、lld-link.exe ほか LLVM のツール群コンパイラ本体が存在しない
MSBuild support for LLVM (clang-cl) toolset
（LLVM (clang-cl) ツールセットの MSBuild サポート）		MSBuild 用のツールセット定義（.props / .targets）プロジェクトのプラットフォームツールセットに「LLVM (clang-cl)」が出てこない

手順

  1. スタートメニューから Visual Studio Installer を起動します
  2. Visual Studio 2026 の 変更 をクリックします
  3. 個別のコンポーネント タブを開きます
  4. 検索ボックスに clang と入力します
  5. 上の表の二つにチェックを入れ、変更 を実行します
コンポーネント名の表記ゆれ

コンポーネントの表示名は Visual Studio のバージョンや表示言語によって細かく異なります（2019 では「C++ Clang tools for Windows」「C++ Clang-cl for v142 build tools」という名前でした）。名前を厳密に探すより、検索ボックスに clang と入れて出てきたものを見るほうが確実です。コンパイラ本体とツールセット統合の二つがある、という点だけ押さえてください。

ついでに入れておくもの

第 3 部で計測に使うため、「デスクトップ開発 C++」ワークロード内の C++ プロファイル ツール も入れておくと後がスムーズです。PIX for Windows は Visual Studio とは別に配布されているため、第 12 章で改めて導入します。

2.2 どこに入ったかを確認する

インストールが終わったら、実際にファイルがどこに置かれたかを確認します。GUI ではなくコマンドラインで確認するのは、これ以降の章でツールを直接叩くことが多いからです。

スタートメニューから Developer Command Prompt for VS 2026（または Developer PowerShell for VS 2026）を開きます。通常のコマンドプロンプトではなく、必ずこちらを使ってください。ツールへのパスや環境変数は、この開発者用シェルが設定してくれます。

:: Developer Command Prompt の場合
echo %VCINSTALLDIR%
dir "%VCINSTALLDIR%Tools\Llvm\x64\bin"
# Developer PowerShell の場合
$env:VCINSTALLDIR
Get-ChildItem "$env:VCINSTALLDIR\Tools\Llvm\x64\bin"

同梱の LLVM は次の場所に配置されます。

パス中身
%VCINSTALLDIR%Tools\Llvm\x64\bin\64 ビット版のツール（本書ではこちらを使います）
%VCINSTALLDIR%Tools\Llvm\bin\32 ビット版のツール
末尾のバックスラッシュに注意

%VCINSTALLDIR% は末尾に \ が付いた状態で定義されています。そのため %VCINSTALLDIR%Tools\Llvm のように、区切り文字を重ねずに連結します。%VCINSTALLDIR%\Tools\Llvm と書くと \\ になりますが、Windows は多くの場合これを許容してしまうため、間違いに気づきにくいところです。

2.3 バージョンを確認する

開発者用シェルで次を実行します。

clang-cl --version

次のような出力が返ってきます（数値は環境によって異なります）。

clang version 21.1.0
Target: x86_64-pc-windows-msvc
Thread model: posix
InstalledDir: C:\Program Files\Microsoft Visual Studio\2026\Community\VC\Tools\Llvm\x64\bin

三行それぞれに意味があります。

行読み方
clang versionLLVM のバージョン。本書では LLVM 18 以降を前提にします。特に CSPGO 関連は版によって挙動が変わるため、この数字は控えておいてください
Targetx86_64-pc-windows-msvc であること。-gnu で終わっている場合は MinGW 版の Clang を拾っています
InstalledDirいま動いている clang-cl.exe の実体の場所。差し替えを行ったときはここで確認します
Target が -gnu になっていたら

MinGW / MSYS2 経由で Clang を入れていると、PATH の順序次第でそちらが先に見つかります。本書のツールセットは MSVC の標準ライブラリと ABI を共有する *-windows-msvc 版が前提です。where clang-cl でどれが選ばれているかを確認してください。

ついでに、後の章で使うツールの存在も確認しておきましょう。

where clang-cl
where lld-link
where llvm-profdata
where llvm-cov
where llvm-objdump

ここで llvm-profdata や llvm-cov が見つからないことがあります。同梱される LLVM は完全なフルセットとは限らないためです。この場合の対処が次節です（詳しくは第 5 章で改めて扱います）。

2.4 公式 LLVM に差し替える

Visual Studio 同梱の LLVM は、Visual Studio のリリースサイクルに縛られます。バージョンを自分で選べませんし、含まれるツールも Microsoft が選んだ範囲です。本書の後半で扱う CSPGO のように比較的新しい機能を試すときや、llvm-profdata が同梱されていないときは、公式 LLVM を別に入れて差し替えるのが確実です。

2.4.1 公式 LLVM のインストール

LLVM の公式リリースページ（GitHub の llvm/llvm-project の Releases）から Windows 用インストーラを入手するか、winget を使います。

winget install LLVM.LLVM

既定では C:\Program Files\LLVM\ に入ります。インストーラの「Add LLVM to the system PATH」は、本書ではオフのままにしておくことをおすすめします。オンにすると同梱版と公式版のどちらが使われているのか分かりにくくなり、切り分けが難しくなるためです。

2.4.2 Directory.Build.props で切り替える

Visual Studio のインストールディレクトリを書き換える必要はありません。MSBuild のプロパティで指定できます。ソリューションファイルと同じフォルダに Directory.Build.props という名前でファイルを作り、次の内容を書きます。

<Project>
  <PropertyGroup>
    <LLVMInstallDir>C:\Program Files\LLVM</LLVMInstallDir>
    <LLVMToolsVersion>21.1.0</LLVMToolsVersion>
  </PropertyGroup>
</Project>

リスト 2-1　Directory.Build.props

プロパティ意味
LLVMInstallDir使用する LLVM のルートディレクトリ（bin の親）
LLVMToolsVersion使用する LLVM のバージョン。同一ルート下に複数バージョンがある場合の選択に使われます

Directory.Build.props は MSBuild が自動的に読み込む特別なファイルで、そのフォルダ以下のすべてのプロジェクトに設定が適用されます。.vcxproj を直接編集しなくて済むので、リポジトリを共有する場合にも扱いやすい方法です。

新しすぎる LLVM は壊れることがあります

ClangCL は MSVC の標準ライブラリ（MSVC STL）と Windows SDK のヘッダをそのまま使います。これらは Clang の特定バージョンに合わせて調整されているため、極端に新しい／古い LLVM を組み合わせると、標準ヘッダのコンパイルエラーという分かりにくい形で失敗することがあります。まずは同梱版で第 5 部まで進み、必要になった時点で差し替えるのが安全です。

2.4.3 差し替わったことを確認する

差し替えたつもりで差し替わっていない、というのはよくある事故です。次章でプロジェクトを作ったら、ビルド出力の詳細度を上げて、実際に起動された clang-cl.exe のフルパスを確認してください。手順は第 3 章 3.5 節で扱います。

2.5 セットアップ確認チェックリスト

次章に進む前に、以下がすべて満たされていることを確認してください。

  • Visual Studio Installer で clang 関連の二つのコンポーネントにチェックが入っている
  • Developer Command Prompt for VS 2026 が起動できる
  • clang-cl --version がバージョンを表示する
  • その Target が x86_64-pc-windows-msvc である
  • where lld-link でリンカが見つかる
  • clang version の数値をメモした（後の章で参照します）

2.6 よくあるつまずき

プラットフォームツールセットに「LLVM (clang-cl)」が出てこない

MSBuild サポートのコンポーネントが入っていません。コンパイラ本体だけを入れた場合に起きます。Visual Studio Installer に戻り、二つ目のコンポーネントを追加してください。追加後は Visual Studio の再起動が必要です。

clang-cl が「内部コマンドまたは外部コマンド〜ではありません」と言われる

通常のコマンドプロンプトを使っています。Developer Command Prompt for VS 2026 を使ってください。同梱の LLVM は システムの PATH には登録されません。

%VCINSTALLDIR% が空

同じく、開発者用シェルではないシェルを使っています。あるいは Visual Studio Installer での変更後にシェルを開き直していません。

32 ビット版のツールを拾っている

InstalledDir が Tools\Llvm\bin（x64 が無い）になっている場合です。本書は x64 ターゲットで進めるため、Tools\Llvm\x64\bin 側を使ってください。開発者用シェルにも「x64 Native Tools Command Prompt」など複数の種類があるので、起動したものを確認します。

2.7 まとめ

  • ClangCL にはコンパイラ本体とMSBuild ツールセット統合の二つのコンポーネントが必要
  • 同梱 LLVM は %VCINSTALLDIR%Tools\Llvm\x64\bin\ に置かれ、システムの PATH には入らない
  • 作業はすべて Developer Command Prompt / Developer PowerShell for VS 2026 から行う
  • clang-cl --version の Target が x86_64-pc-windows-msvc であることを確認する
  • 公式 LLVM への差し替えは Directory.Build.props の LLVMInstallDir / LLVMToolsVersion で行う

次章では、実際に Visual Studio でプロジェクトを作り、プラットフォームツールセットを LLVM (clang-cl) に切り替えます。C++23 の設定、リリース構成の確認、そして「実際に clang-cl にどんな引数が渡っているか」をビルドログから読み取る方法まで扱います。あわせて、ClangCL が既定で lld-link を使うという事実を確認します。これは第 4 部の LTO で効いてきます。
