第 39 章

MSBuild で最適化パイプラインを組む
— 構成の追加とプロパティシート

ここまで、プロパティページを手で切り替えながら進めてきました。切り替え忘れは実際に起こります。構成として定義してしまえば、コマンド一つで正しいビルドが得られます。

この章のゴール

  • プロパティシートで設定を切り出す
  • 最適化用のビルド構成を追加する
  • コマンドラインから構成を指定してビルドする
  • PGO の三段階を構成の切り替えとして表現する

39.1 なぜ構成を分けるのか

第 26 章で触れた事故を思い出してください。計装ビルドのオプションを外し忘れたまま出荷する、というものです。手でプロパティを切り替える運用では、これを防げません。

また、日常の開発では LTO を切りたい（第 19 章）という要求もあります。「Release」が一つしかないと、この使い分けができません。

構成用途オプション
Debug開発/Od
Release日常のビルド、比較の基準/O2
Release-Instrトレーニング用（使い捨て）/O2 -fprofile-generate
Release-PGOPGO 適用/O2 -fprofile-use
Release-Opt出荷用（PGO + ThinLTO）/O2 -fprofile-use -flto=thin

39.2 プロパティシート

構成ごとに .vcxproj を書き換えるのは保守しづらいので、共通部分をプロパティシート（.props）に切り出します。

39.2.1 共通の設定

<?xml version="1.0" encoding="utf-8"?>
<Project ToolsVersion="4.0" xmlns="http://schemas.microsoft.com/developer/msbuild/2003">
  <PropertyGroup>
    <!-- プロファイルの置き場所 -->
    <ProfileDir>$(SolutionDir)prof</ProfileDir>
    <ProfileData>$(SolutionDir)app.profdata</ProfileData>
    <LtoCacheDir>$(SolutionDir)ltocache</LtoCacheDir>
  </PropertyGroup>

  <ItemDefinitionGroup>
    <ClCompile>
      <LanguageStandard>stdcpp23</LanguageStandard>
      <DebugInformationFormat>ProgramDatabase</DebugInformationFormat>
      <AdditionalIncludeDirectories>
        $(ProjectDir)include;%(AdditionalIncludeDirectories)
      </AdditionalIncludeDirectories>
    </ClCompile>
    <Link>
      <GenerateDebugInformation>true</GenerateDebugInformation>
    </Link>
  </ItemDefinitionGroup>
</Project>

リスト 39-1　Common.props

39.2.2 最適化ごとのシート

<?xml version="1.0" encoding="utf-8"?>
<Project ToolsVersion="4.0" xmlns="http://schemas.microsoft.com/developer/msbuild/2003">
  <ItemDefinitionGroup>
    <ClCompile>
      <AdditionalOptions>
        /clang:-fprofile-generate=$(ProfileDir) %(AdditionalOptions)
      </AdditionalOptions>
    </ClCompile>
    <Link>
      <AdditionalLibraryDirectories>
        $(LLVMInstallDir)lib\clang\$(LLVMToolsVersion)\lib\windows;%(AdditionalLibraryDirectories)
      </AdditionalLibraryDirectories>
    </Link>
  </ItemDefinitionGroup>
</Project>

リスト 39-2　Instrument.props（計装ビルド用）

<?xml version="1.0" encoding="utf-8"?>
<Project ToolsVersion="4.0" xmlns="http://schemas.microsoft.com/developer/msbuild/2003">
  <ItemDefinitionGroup>
    <ClCompile>
      <AdditionalOptions>
        /clang:-fprofile-use=$(ProfileData)
        /clang:-Werror=backend-plugin
        %(AdditionalOptions)
      </AdditionalOptions>
    </ClCompile>
  </ItemDefinitionGroup>
</Project>

リスト 39-3　UseProfile.props（PGO 適用用）

-Werror=backend-plugin を入れておく

第 34 章で扱ったプロファイルの陳腐化を、ビルドエラーとして検出させます。「知らないうちにプロファイルが効かなくなっていた」という事態を防げます。

ただし、開発中はこれが邪魔になることもあります。その場合は CI 用の構成にだけ入れる、といった使い分けをしてください。

<?xml version="1.0" encoding="utf-8"?>
<Project ToolsVersion="4.0" xmlns="http://schemas.microsoft.com/developer/msbuild/2003">
  <ItemDefinitionGroup>
    <ClCompile>
      <AdditionalOptions>/clang:-flto=thin %(AdditionalOptions)</AdditionalOptions>
    </ClCompile>
    <Link>
      <AdditionalOptions>
        /lldltocache:$(LtoCacheDir)
        /lldltocachepolicy:cache_size_bytes=2g:prune_after=168h
        %(AdditionalOptions)
      </AdditionalOptions>
    </Link>
  </ItemDefinitionGroup>
</Project>

リスト 39-4　ThinLTO.props

%(AdditionalOptions) を必ず末尾に置く

第 4 章でも触れましたが、これは「既存の設定を引き継ぐ」という意味です。省くと、他のプロパティシートやプロジェクト設定で指定したオプションが消えます。プロパティシートを重ねる設計では、これが特に重要になります。

39.3 構成を追加する

Visual Studio の ビルド > 構成マネージャー から、Release をコピーして新しい構成を作ります。

  1. 「アクティブ ソリューション構成」のドロップダウンから <新規作成>
  2. 名前を Release-Opt とする
  3. 「設定のコピー元」に Release を選ぶ
  4. 「新しいプロジェクト構成を作成する」にチェック

次に、その構成にプロパティシートを適用します。表示 > その他のウィンドウ > プロパティ マネージャー を開き、対象の構成を右クリックして「既存のプロパティ シートの追加」を選びます。

構成適用するシート
ReleaseCommon.props
Release-InstrCommon.props + Instrument.props
Release-PGOCommon.props + UseProfile.props
Release-OptCommon.props + UseProfile.props + ThinLTO.props

組み合わせで表現できるのが、この方式の利点です。

39.4 コマンドラインからビルドする

msbuild ClangOptLab.sln /p:Configuration=Release-Instr /p:Platform=x64 /t:Rebuild
msbuild ClangOptLab.sln /p:Configuration=Release-Opt   /p:Platform=x64 /t:Rebuild

出力先も構成ごとに分かれるので、退避のコピーが不要になります。

x64\Release\        ← 基準
x64\Release-Instr\  ← 計装
x64\Release-PGO\    ← PGO
x64\Release-Opt\    ← 出荷用

39.5 パイプラインのスクリプト

第 31 章の pgo.cmd が、構成の切り替えだけで書けるようになります。

@echo off
:: build-pgo.cmd
setlocal
set ROOT=%~dp0
set SLN=%ROOT%ClangOptLab.sln
set MSB=msbuild "%SLN%" /p:Platform=x64 /m /nologo /v:minimal

echo ===== [1/4] 計装ビルド =====
%MSB% /p:Configuration=Release-Instr /t:Rebuild || exit /b 1

echo ===== [2/4] トレーニング =====
if exist "%ROOT%prof" rmdir /s /q "%ROOT%prof"
mkdir "%ROOT%prof"
set LLVM_PROFILE_FILE=%ROOT%prof\run-%%p.profraw
call "%ROOT%train.cmd" "%ROOT%x64\Release-Instr\ClangOptLab.exe" || exit /b 1
set LLVM_PROFILE_FILE=

echo ===== [3/4] マージ =====
llvm-profdata merge -sparse -output="%ROOT%app.profdata" "%ROOT%prof\*.profraw" || exit /b 1
llvm-profdata show "%ROOT%app.profdata" | findstr /C:"Maximum function count"

echo ===== [4/4] 出荷用ビルド =====
%MSB% /p:Configuration=Release-Opt /t:Rebuild || exit /b 1

echo.
echo 完了: x64\Release-Opt\ClangOptLab.exe
endlocal

リスト 39-5　build-pgo.cmd

トレーニングの中身を train.cmd に分けているのは、第 36 章で述べた理由——一周目と二周目で同じワークロードを使う——のためです。CSPGO に拡張するときも、この部分を使い回せます。

39.6 プロファイルが無いときのフォールバック

実務で必ずぶつかる問題です。Release-Opt 構成は app.profdata を必要としますが、そのファイルはリポジトリに無いかもしれません。新しく参加した開発者がクローンした直後がそうです。

MSBuild の条件で、存在しない場合は指定を落とせます。

<ItemDefinitionGroup>
  <ClCompile>
    <AdditionalOptions Condition="Exists('$(ProfileData)')">
      /clang:-fprofile-use=$(ProfileData) %(AdditionalOptions)
    </AdditionalOptions>
  </ClCompile>
</ItemDefinitionGroup>

<Target Name="WarnNoProfile" BeforeTargets="ClCompile"
        Condition="!Exists('$(ProfileData)')">
  <Warning Text="プロファイル $(ProfileData) が見つかりません。PGO 無しでビルドします。" />
</Target>

リスト 39-6　UseProfile.props（フォールバック付き）

黙って落とすか、失敗させるか

開発者の手元では「警告を出して PGO 無しでビルド」が親切です。一方 CI では、プロファイルが無いことに気づかず最適化されていないバイナリを出荷するのは避けたい。

この使い分けは、CI 側でプロパティを渡して切り替えるのが素直です。

msbuild ... /p:Configuration=Release-Opt /p:RequireProfile=true

そして RequireProfile が true のときは <Error> にする、という条件を書きます。詳しくは第 41 章で扱います。

39.7 CSPGO への拡張

構成をもう一つ足すだけです。

<!-- CsInstrument.props -->
<ClCompile>
  <AdditionalOptions>
    /clang:-fprofile-use=$(ProfileData)
    /clang:-fcs-profile-generate=$(CsProfileDir)
    /clang:-flto=thin
    %(AdditionalOptions)
  </AdditionalOptions>
</ClCompile>

構成名は Release-CsInstr。スクリプト側は、第 36 章のリスト 36-1 と同じ流れを構成の切り替えで書き直します。

39.8 ハンズオン

  1. リスト 39-1 の Common.props を作り、既存の Release に適用する
  2. プロパティページから、シートに移した設定が消えていることを確認する（継承されているので値は残る）
  3. 構成マネージャーで Release-Instr と Release-Opt を作る
  4. それぞれにシートを適用する
  5. コマンドラインから両方をビルドし、出力先が分かれることを確認する
  6. リスト 39-5 の build-pgo.cmd を作って通しで実行する
  7. app.profdata を一時的に別名にして、フォールバックが働くことを確認する

39.9 まとめ

  • 手でプロパティを切り替える運用は切り替え忘れの事故を防げない
  • 共通設定を Common.props に、最適化ごとの設定を個別のシートに切り出す
  • 構成（Release-Instr / Release-PGO / Release-Opt）とシートの組み合わせで表現する
  • %(AdditionalOptions) を末尾に置くのを忘れない
  • 構成ごとに出力先が分かれるので、退避のコピーが不要になる
  • Condition="Exists(...)" でプロファイルが無いときのフォールバックを書ける
  • -Werror=backend-plugin を入れて陳腐化を検出させる（第 34 章）

次章では、同じことを CMake で行います。ClangCL を使う設定、LTO の指定、そして PGO の三段階をどう表現するか。MSBuild と CMake の対応表も用意します。
