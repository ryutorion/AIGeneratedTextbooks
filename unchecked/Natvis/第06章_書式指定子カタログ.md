# 第6章 書式指定子カタログ

書式指定子は、Natvis の中で最も投資対効果が高い知識です。`Expand` を書かなくても、`,d` ひとつで表示が読めるようになることは珍しくありません。

この章はリファレンス寄りの構成になっています。一度通読して、以降は必要に応じて戻ってきてください。

## 6.1 構文

```
{式,指定子}
```

第3章でウォッチウィンドウに打ち込んだ `color.r,d` と同じ構文です。**ウォッチウィンドウで試せる指定子は、そのまま `DisplayString` に書けます**。迷ったらウォッチで確かめるのが確実です。

指定子は組み合わせられる場合があります。特に**サイズ指定子と文字列指定子の組み合わせ**（`{_data,[_size]na}`）は、自作の文字列型で必ず使うことになります（第9章）。

## 6.2 整数

| 指定子 | 意味 | `102` の表示 |
|---|---|---|
| `d` | 10進整数 | `102` |
| `o` | 8進（符号なし） | `000000000146` |
| `x` / `h` | 16進（小文字） | `0x00000066` |
| `X` / `H` | 16進（大文字） | `0x00000066` → `0X66` 形式 |
| `xb` / `hb` | 16進、`0x` なし（小文字） | `00000066` |
| `Xb` / `Hb` | 16進、`0x` なし（大文字） | `00000066` |
| `b` | 2進（`0b` 付き） | `0b00000000000000000000000001100110` |
| `bb` | 2進（`0b` なし） | `00000000000000000000000001100110` |
| `c` | 単一文字として | `102 'f'` |

**桁数は型のサイズで決まります。** `std::uint8_t` に `,Xb` を付ければ 2 桁、`std::uint32_t` なら 8 桁になります。この性質は後で使います。

`,d` の最大の用途は、第4章でやった `unsigned char` の文字表示を止めることです。`std::uint8_t` / `std::int8_t` を含む型を書いたら、反射的に `,d` を付けると考えてよいくらいです。

## 6.3 浮動小数点

| 指定子 | 意味 | `12.5` の表示 |
|---|---|---|
| （なし） | 既定（有効桁数を最大限） | `12.500000000000000` |
| `e` | 科学記法 | `1.250000e+01` |
| `f` | 固定小数点 | `12.500000` |
| `g` | `e` と `f` の短いほう | `12.5` |

座標・サイズ・比率のような「人間が読む数値」には `g` が最適です。第4章で `point2` に付けたのがこれです。

一方、**ビットパターンの違いを見たいときは既定のまま**にします。`0.1 + 0.2` が `0.30000000000000004` であることを確認したい場面で `,g` を付けてしまうと `0.3` と表示され、調べたい情報が消えます。

## 6.4 文字列

| 指定子 | 対象 | 引用符 |
|---|---|---|
| `s` | `const char*`（NUL 終端） | あり |
| `sb` | 同上 | なし |
| `s8` | UTF-8 | あり |
| `s8b` | UTF-8 | なし |
| `su` | UTF-16（`wchar_t*`） | あり |
| `sub` | UTF-16 | なし |
| `s32` | UTF-32 | あり |
| `s32b` | UTF-32 | なし |
| `bstr` | `BSTR` | あり |

引用符あり／なしは用途で選びます。`DisplayString` の中で他のテキストと連結するときは、引用符なし（`sb` / `s8b` / `sub`）のほうが読みやすいことが多いです。逆にコンテナのキーとして並べるときは、引用符ありのほうが「文字列である」ことが明確になります。

```xml
<!-- 引用符あり: ["apple"] 3  -->
<!-- 引用符なし: [apple] 3    -->
```

なお `s8b` / `s32` / `s32b` などは新しいデバッガエンジンでのみ利用できます。動かない場合は `s` / `su` で代替してください。

## 6.5 サイズ指定子

ここが自作コンテナで最重要です。

| 指定子 | 意味 |
|---|---|
| `[n]` | ポインタを **n 要素の配列**として表示（`10` 進または `0x` 付き 16 進） |
| `[式]` | 要素数を**式で**指定する |

```
vp,[5]                → {1.5, 2.5, 3.5, 4.5, 5.5}
_data,[_size]         → _size 個の配列として表示
_data,[_size - _head] → 式でもよい
```

第3章で見た「ポインタは 1 個しか見えない」問題を、その場で解決する指定子です。

### 文字列との組み合わせ

NUL 終端でない文字列（長さを別に持つ文字列）は、この組み合わせで表示します。

```
_data,[_size]na
```

MSVC の `STL.natvis` が `std::string_view` に対して実際に書いているのがこれです。

```xml
<Type Name="std::basic_string_view&lt;*,*&gt;">
  <Intrinsic Name="size" Expression="_Mysize" />
  <Intrinsic Name="data" Expression="_Mydata" />
  <DisplayString>{_Mydata,[_Mysize]na}</DisplayString>
  <StringView>_Mydata,[_Mysize]na</StringView>
  ...
```

なぜ `s8` ではなく `na` なのかは、`basic_string_view<*,*>` が `char` にも `wchar_t` にも当たるためです。`na` にしておけば、要素の型に応じてデバッガが適切な文字列表現を選びます。自作型で文字型が `char` に固定されているなら `s8` を明示しても構いません。第9章で実際に書きます。

## 6.6 表示そのものを制御する指定子

| 指定子 | 意味 | 使いどころ |
|---|---|---|
| `!` | Natvis を無視して生表示 | 切り分け。「Natvis のせいか元からか」 |
| `na` | ポインタのアドレスを表示しない | `{ptr}` が `0x00007ff... {...}` になるのを防ぐ |
| `nd` | 派生クラス情報を出さず、基底として表示 | 再帰的な Natvis 適用を止める（第12章） |
| `nr` | `[Raw View]` の行を出さない | 表示を締める（第13章） |
| `nvo` | 数値型にのみ `[Raw View]` を出す | |

`,na` は覚えておく価値があります。`DisplayString` の中でポインタメンバーをそのまま `{_ptr}` と書くと、アドレスまで表示されて行が長くなります。`{_ptr,na}` にすると指し先の表示だけになります。

`,!` は開発中のデバッグ用です。「いま見ている表示は Natvis が作ったのか、デバッガの既定なのか」が分からなくなったら、ウォッチウィンドウで `obj,!` を評価してください。

## 6.7 意味づけの指定子

| 指定子 | 意味 |
|---|---|
| `en` | enum の値を名前で表示（`6` → `Saturday`） |
| `fe` | ビットフラグ enum（`6` → `flag1 \| flag2 (6)`） |
| `hr` | `HRESULT` / Win32 エラーコードを名前で（`0` → `S_OK`） |
| `wc` | ウィンドウクラスフラグ |
| `wm` | Windows メッセージ番号（`16` → `WM_CLOSE`） |
| `handle` | Win32 ハンドルの情報 |

`en` と `fe` は自作 enum にも効きます。第37章で `flags<E>` を作るときに主役になります。`hr` は、Windows API を薄くラップしたライブラリで戻り値を保持する型を書いたときに、そのまま使えます。

## 6.8 実践：rgba を `#RRGGBB` にする

第4章の演習2への回答です。

`,x` を使うと `0xcc` になり、`#` と桁揃えが素直に書けないという問題がありました。答えは **`Xb`（`0x` なしの大文字16進）** です。

```xml
<Type Name="vizkit::rgba">
  <DisplayString Condition="a == 255">#{r,Xb}{g,Xb}{b,Xb}</DisplayString>
  <DisplayString>#{r,Xb}{g,Xb}{b,Xb} (a={a,d})</DisplayString>
</Type>
```

```
  color        #CC6633                  vizkit::rgba
  transparent  #000000 (a=0)            vizkit::rgba
```

うまくいく理由は 6.2 節で触れた「**桁数は型のサイズで決まる**」性質です。`std::uint8_t` は 1 バイトなので、`Xb` は必ず 2 桁になります。値が `5` なら `05` と 0 埋めされます。もし成分が `int` だったら 8 桁になってしまい、この手は使えません。

**Natvis を書きやすい型設計**という観点では、これは示唆的です。色成分を `int` ではなく `std::uint8_t` にしておくと、表示の面でも扱いやすくなる、ということです。

なお、10 進と 16 進の両方を見たい場合は素直に併記します。

```xml
<DisplayString>#{r,Xb}{g,Xb}{b,Xb} RGBA({r,d}, {g,d}, {b,d}, {a,d})</DisplayString>
```

## 6.9 version を 16 進でも見る

`version` にも応用します。パックされた整数はビットの並びを見たいことがあるので、16 進を併記しておくとデバッグが楽になります。

```xml
<Type Name="vizkit::version">
  <Intrinsic Name="major" Expression="packed >> 22" />
  <Intrinsic Name="minor" Expression="(packed >> 12) &amp; 0x3FF" />
  <Intrinsic Name="patch" Expression="packed &amp; 0xFFF" />
  <DisplayString>v{major()}.{minor()}.{patch()} ({packed,X})</DisplayString>
</Type>
```

```
  ver       v3.12.7 (0X00C8C007)      vizkit::version
```

## 6.10 注意点

**(1) デバッガエンジンによる差がある。**
Visual Studio 2022 以降の新しいデバッガでのみ使える指定子（`sb`、`s8b`、`s32`、`en`、`na`、`nd`、`hv`、`[式]` など）があります。また、古い指定子（`ma`、`mb`、`mw`、`md`、`mq`、`mu`、`m` などのメモリダンプ系）はサポート外になっています。本書は Visual Studio 2026 を前提としているので基本的に問題ありませんが、WinDbg や VS Code の cppdbg で同じ `.natvis` を使う場合は動作が変わることがあります（第44章）。

**(2) 指定子は式の一部ではない。**
`{_size,d}` の `d` は式ではなく表示方法です。`{_size + 1,d}` のように、カンマの前が式、後ろが指定子です。式の中にカンマを書きたくなったら（関数呼び出しがないので実際にはまず起きませんが）曖昧になるので避けてください。

**(3) 迷ったらウォッチウィンドウ。**
指定子の効果は環境依存の部分があります。`.natvis` に書く前にウォッチウィンドウで `obj.member,指定子` を評価するのが、最も速く確実な確認方法です。

## 6.11 現時点の vizkit.natvis

```xml
<?xml version="1.0" encoding="utf-8"?>
<AutoVisualizer xmlns="http://schemas.microsoft.com/vstudio/debugger/natvis/2010">

  <Type Name="vizkit::point2">
    <DisplayString>({x,g}, {y,g})</DisplayString>
  </Type>

  <Type Name="vizkit::rgba">
    <DisplayString Condition="a == 255">#{r,Xb}{g,Xb}{b,Xb}</DisplayString>
    <DisplayString>#{r,Xb}{g,Xb}{b,Xb} (a={a,d})</DisplayString>
  </Type>

  <Type Name="vizkit::rect">
    <DisplayString Condition="_max.x &lt;= _min.x || _max.y &lt;= _min.y">[empty]</DisplayString>
    <DisplayString>[{_min}, {_max}] {_max.x - _min.x,g}x{_max.y - _min.y,g}</DisplayString>
  </Type>

  <Type Name="vizkit::version">
    <Intrinsic Name="major" Expression="packed >> 22" />
    <Intrinsic Name="minor" Expression="(packed >> 12) &amp; 0x3FF" />
    <Intrinsic Name="patch" Expression="packed &amp; 0xFFF" />
    <DisplayString>v{major()}.{minor()}.{patch()} ({packed,X})</DisplayString>
  </Type>

</AutoVisualizer>
```

## 6.12 この章のまとめ

- 指定子はウォッチ式と `DisplayString` で共通。**書く前にウォッチで試す**。
- `,d` は `uint8_t` / `int8_t` の文字表示を止める。ほぼ反射的に付けてよい。
- `,g` は人間が読む浮動小数点向け。ビットの違いを見たいときは既定のまま。
- **`,[n]` / `,[式]` がコンテナ可視化の起点。** ポインタに要素数を与えると配列として見える。
- 文字列は `,[_size]na` の形で長さを与えるのが基本形。
- `,Xb` は「型のサイズで桁が決まる」性質を利用して 0 埋め 16 進を作れる。
- `,!` は切り分けの道具。`,na` は行を短くする道具。

## 6.13 演習

1. `version` の `DisplayString` に `{packed,bb}` を足し、ビットの並びを確認してください。上位 10 ビットが `major` になっていることを目で追えます。
2. `rgba` の `Xb` を `X` に変えて、なぜ `#0XCC0X660X33` のような表示になるか説明してください。
3. ウォッチウィンドウで `values,[3]`、`values,[sizeof(values)/sizeof(values[0])]` を評価し、後者が式で要素数を与えられることを確認してください。
4. `box,!` と `box` を比較し、`,!` が `rect` だけでなく入れ子の `point2` にも効いているかどうかを確認してください。
