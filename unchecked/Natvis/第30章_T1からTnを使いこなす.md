# 第30章 $T1〜$Tn を使いこなす

前章でマッチングを扱いました。マッチしたら、次は**マッチした型の引数を式の中で使う**段階です。

`$T1`、`$T2`、… は、そのためのマクロです。第14章で「`$T1` は型、`$T2` は値」と述べた区別を、この章で完全に整理します。

## 30.1 番号の対応

`Type` の `Name` に書いたワイルドカードの位置に、左から順に対応します。

```
vizkit::matrix < int , 3 , 4 >
                 ↑    ↑   ↑
                $T1  $T2 $T3
```

```xml
<Type Name="vizkit::matrix&lt;*,*,*&gt;">
  <DisplayString>{{ {$T2}x{$T3} of {($T1*)0} }}</DisplayString>
```

番号は 1 から始まります。`$T0` はありません。

前章 29.3節で述べたとおり、**`*` 1つで複数の引数を受けた場合の `$T2` 以降は環境依存**です。`$Tn` を使うなら、引数の個数だけ `*` を書いてください。

## 30.2 型として使う

テンプレート引数が型のとき、`$Tn` は**型名として**式に書けます。C++ の型が書ける場所すべてに使えます。

| 用途 | 書き方 | 使った章 |
|---|---|---|
| キャスト | `($T1*)_storage` | 第18章（SBO） |
| ポインタのキャスト | `*($T1*)this` | 第19章（侵入型リスト） |
| サイズ計算 | `sizeof($T1)` | 本章 |
| 型の確認 | `($T1*)0` | 第29章（プローブ） |

### C 形式キャストであること

第5章 5.4節の再確認です。`static_cast` や `reinterpret_cast` は書けません。

```xml
<!-- 動かない -->
<ValuePointer>static_cast&lt;$T1*&gt;(_sbo)</ValuePointer>

<!-- 正しい -->
<ValuePointer>($T1*)_sbo</ValuePointer>
```

キャストの `<` `>` も XML エスケープが必要になるので、C 形式のほうが書きやすいという実利もあります。

### sizeof($T1) の実用

第18章の `small_vector` に、記憶領域の情報を足してみます。

```xml
<Type Name="vizkit::small_vector&lt;*,*&gt;">
  <Intrinsic Name="is_inline" Expression="_capacity &lt;= $T2" />
  ...
  <Expand>
    ...
    <Synthetic Name="[storage]" IncludeView="detail">
      <DisplayString>sizeof(T)={sizeof($T1)}, inline capacity={$T2}, SBO={sizeof($T1) * $T2} bytes</DisplayString>
      <Expand>
        <Item Name="[sizeof(T)]">sizeof($T1)</Item>
        <Item Name="[inline capacity]">$T2</Item>
        <Item Name="[SBO bytes]">sizeof($T1) * $T2</Item>
        <Item Name="[object bytes]">sizeof(*this)</Item>
      </Expand>
    </Synthetic>
  </Expand>
</Type>
```

```
sv_small,view(detail)
  └ [storage]           sizeof(T)=4, inline capacity=4, SBO=16 bytes
       [sizeof(T)]      4
       [inline capacity] 4
       [SBO bytes]      16
       [object bytes]   32
```

`small_vector<T, N>` のインライン領域が実際に何バイト取っているか、`N` を変えたときに構造体全体がどれだけ大きくなるかを、デバッガ上で確認できます。**テンプレートのサイズ肥大を追うときに実際に使えます。**

`sizeof(*this)` も併記しておくと、パディングの影響まで見えます。

## 30.3 値として使う

非型テンプレート引数（`std::size_t N` など）のとき、`$Tn` は**値として**式に書けます。

```xml
<Size>$T2</Size>                              <!-- 第14章 -->
<ValueNode>_buf[(_head + $i) % $T2]</ValueNode>  <!-- 第17章 -->
<Intrinsic Name="is_inline" Expression="_capacity &lt;= $T2" />  <!-- 第18章 -->
```

型として使おうとすれば評価に失敗しますし、逆も同様です。**`$Tn` の使い方は、その引数が型か値かで決まります。**

```xml
<!-- fixed_array<int,5> に対して -->
<Item Name="ok">$T2</Item>          <!-- 5 -->
<Item Name="ng">sizeof($T2)</Item>  <!-- エラー: 5 は型ではない -->
<Item Name="ng2">$T1</Item>         <!-- エラー: int は値ではない -->
```

### bool や enum の非型引数

`bool` や enum も非型引数として使えます。

```cpp
template <class T, bool ThreadSafe>
class registry { ... };
```

```xml
<Type Name="vizkit::registry&lt;*,*&gt;">
  <DisplayString Condition="$T2">registry&lt;thread-safe&gt;</DisplayString>
  <DisplayString>registry&lt;single-thread&gt;</DisplayString>
</Type>
```

**コンパイル時のポリシーを、デバッガの表示に反映できます。** 第33章で扱うポリシークラスの可視化は、この延長です。

## 30.4 $Tn が使えない場面

### テンプレートテンプレート引数

```cpp
template <class T, template <class> class Container>
class adapter { ... };
```

`$T2` は `Container` にあたりますが、これは型でも値でもありません。**式の中で使えません。**

対処は、`Container<T>` の実体が現れるメンバーを経由することです。

```xml
<!-- $T2 は使わず、メンバーの型に任せる -->
<Type Name="vizkit::adapter&lt;*,*&gt;">
  <DisplayString>{_impl}</DisplayString>
  <Expand>
    <ExpandedItem>_impl</ExpandedItem>
  </Expand>
</Type>
```

`_impl` の型に Natvis があれば、そちらが使われます。**委譲できるなら委譲する**（第27章 27.6節）。

### 既定引数の省略

```cpp
template <class T, class Alloc = std::allocator<T>>
class my_vector { ... };
```

ユーザーが `my_vector<int>` と書いても、型名には `my_vector<int, std::allocator<int>>` と完全な形で現れます。**`$T2` はアロケータを指します。** 省略されているように見えても、実際には存在します。

### 参照型・関数型の引数

`$T1` が `int&` や `void(int)` のような型の場合、キャストに使うと構文的に成立しないことがあります。実務ではまれですが、`($T1*)` が動かないときは `$T1` の正体をプローブ（第29章 29.3節）で確認してください。

## 30.5 $Tn を使わずに済ませる

`$Tn` に依存しすぎると、テンプレート引数の順序を変えたときに壊れます。**代替手段があるなら、そちらのほうが堅牢**です。

| `$Tn` を使う書き方 | 代替 | 備考 |
|---|---|---|
| `<Size>$T2</Size>` | `sizeof(_data)/sizeof(_data[0])` | メンバーが配列なら可 |
| `sizeof($T1)` | `sizeof(_data[0])`、`sizeof(*_begin)` | 要素が実在すれば可 |
| `($T1*)_sbo` | 代替なし | 型を与えるには `$T1` が要る |
| `_capacity <= $T2` | 静的メンバー定数（`block_size` など） | クラスに定数を持たせる設計 |

最後の行は、**設計側で対応できる**例です。第28章の `deque` は次のように書きました。

```cpp
template <class T, std::size_t BlockSize = 8>
class deque {
public:
    static constexpr std::size_t block_size = BlockSize;   // ← これ
    ...
};
```

Natvis から `block_size` を参照できれば、`$T2` は不要になります。

```xml
<ValueNode>_blocks[($i + _offset) / block_size][($i + _offset) % block_size]</ValueNode>
```

**`static constexpr` メンバーがデバッグ情報に含まれるかは、コンパイラとビルド設定に依存します。** MSVC の Debug ビルドでは通常参照できますが、最適化ビルドでは消えることがあります。動かない場合は `$T2` に戻してください。

`STL.natvis` の `std::deque` が `_EEN_DS` という内部の enum 定数を使っているのは、この手法です（第27章 27.7節）。enum のほうが確実に残るため、標準ライブラリはそちらを選んでいます。

```cpp
// enum のほうが確実
template <class T, std::size_t BlockSize = 8>
class deque {
    enum : std::size_t { _block_size = BlockSize };
    ...
};
```

**「Natvis から参照できる定数をクラスに置く」というのは、Natvis を書きやすくするための設計判断**です。第6章 6.8節、第19章 19.6節、第27章 27.6節と、本書が繰り返し述べてきた観点の1つの形です。

## 30.6 Optional で $Tn の差を吸収する

テンプレート引数の順序や個数が、ライブラリのバージョンで変わることがあります。第8章 8.4節の手法がそのまま使えます。

```xml
<Type Name="vizkit::fixed_array&lt;*,*&gt;">
  <Intrinsic Optional="true" Name="count" Expression="$T2" />
  <Intrinsic Optional="true" Name="count" Expression="sizeof(_data) / sizeof(_data[0])" />
  <DisplayString>{{ size={count()} }}</DisplayString>
  <Expand>
    <ArrayItems>
      <Size>count()</Size>
      <ValuePointer>_data</ValuePointer>
    </ArrayItems>
  </Expand>
</Type>
```

上が失敗したら下が使われます。**引数の個数を変えるリファクタリングに耐えます。**

ただし第8章 8.5節の警告も思い出してください。**自分のライブラリで、壊れたら気づきたい箇所には `Optional` を付けない。** 保険は、壊れる可能性が現実にある場所にだけ掛けます。

## 30.7 実践：テンプレート引数を表示に出す

型名にテンプレート引数が出ているので、`DisplayString` に重ねて書く必要はふつうありません。ただし、**引数の一部を強調したい**場合はあります。

```xml
<Type Name="vizkit::ring_buffer&lt;*,*&gt;">
  <DisplayString Condition="_count == $T2">{{ size={_count}/{$T2} (FULL) }}</DisplayString>
  <DisplayString>{{ size={_count}/{$T2} }}</DisplayString>
</Type>
```

```
  rb           { size=5/5 (FULL) }        vizkit::ring_buffer<int,5>
  rb2          { size=1/5 }               vizkit::ring_buffer<int,5>
```

容量に対する使用率が一目で分かります。型名を読まなくても、値の列だけで判断できる ―― これが `$T2` を表示に使う理由です。

固定容量のコンテナ（`fixed_array`、`ring_buffer`、`small_vector`）では、この書き方が実用的です。

## 30.8 この章のまとめ

- `$T1`、`$T2`、… は `Name` のワイルドカードに左から対応する。番号は 1 始まり。
- **型引数は「型」として、非型引数は「値」として使う。** 混同すれば評価エラーになる。
- 型として：`($T1*)ptr`、`sizeof($T1)`、`($T1*)0`（プローブ）。**C 形式キャストのみ。**
- 値として：`<Size>$T2</Size>`、剰余計算、`Condition` の比較。**bool や enum の非型引数も使える。**
- `sizeof($T1)` と `sizeof(*this)` を並べると、**テンプレートのサイズ肥大やパディングをデバッガで確認できる**。
- **テンプレートテンプレート引数は式に使えない。** メンバーの型に委譲する。
- 既定引数も型名には現れる。省略されているように見えても `$Tn` は存在する。
- **`$Tn` に頼らない書き方があるなら、そちらが堅牢。** `sizeof(_data[0])`、クラス内の `enum` 定数など。
- **「Natvis から参照できる定数をクラスに置く」のは設計判断。** `STL.natvis` の `_EEN_DS` がその実例。
- 引数構成の変化には `Intrinsic Optional="true"` を並べて対応できる。ただし自分のライブラリでは付けすぎない。
- 固定容量コンテナでは `{_count}/{$T2}` のように**容量を表示に出す**と実用的。

## 30.9 演習

1. `matrix<*,*,*>` の `DisplayString` に `{($T1*)0}` を足し、「型」列ではなく値の列に何が出るか確認してください。`Item` のときとの違いを観察します。
2. `fixed_array<*,*>` に `<Item Name="[bytes]">sizeof($T1) * $T2</Item>` を足し、`fixed_array<double,5>` で `40` と表示されることを確認してください。
3. `sizeof($T2)` と書いて、どんなエラーになるか確認してください。型と値の区別の再確認です。
4. `deque` に `enum : std::size_t { _block_size = BlockSize };` を追加し、Natvis から `_block_size` を参照できるか確認してください。Debug と Release の両方で試してください。
5. `ring_buffer` の `DisplayString` を `{_count}/{$T2}` 形式に変え、`ring_buffer<int,5>` と `ring_buffer<int,100>` を並べて表示してください。型名を見ずに容量が分かることを確認します。
