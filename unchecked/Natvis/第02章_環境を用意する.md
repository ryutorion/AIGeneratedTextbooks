# 第2章 環境を用意する

この章では、本書を通して使うソリューションを作ります。ゴールは次の3点です。

1. 静的ライブラリ **vizkit** と、動作確認用のコンソールアプリ **playground** が並ぶソリューションができている
2. C++23 でコンパイルできている
3. 空の `vizkit.natvis` がプロジェクトに載り、デバッガに読み込まれている

Natvis はまだ1行も書きません。土台を確実に作ることに集中します。

## 2.1 必要なもの

- **Visual Studio 2026**（内部バージョンは 18 です。後の章で出てくるフォルダ名に関係します）
- ワークロード **「C++ によるデスクトップ開発」**

インストーラーの「個別のコンポーネント」で、**MSVC v14.5x 以降のビルドツール** と **Windows SDK** が入っていることも確認しておいてください。C++23 の一部機能はビルドツールのバージョンに依存します。

> **メモ：C++ モジュールは使いません**
> 本書はヘッダー（`.hpp`）＋ 実装（`.cpp`）の伝統的な構成で進めます。モジュールを使うとデバッグ情報の出方や PDB の内容が変わり、Natvis の話に余計な変数が混ざるためです。Natvis 自体はモジュールを使っていても動作します。

## 2.2 ソリューションを作る

### 手順1：静的ライブラリプロジェクト

1. Visual Studio を起動し、**新しいプロジェクトの作成**
2. テンプレート **「スタティック ライブラリ (C++)」** を選択
3. プロジェクト名：`vizkit`
4. ソリューション名：`vizkit`
5. **「ソリューションとプロジェクトを同じディレクトリに配置する」はチェックしない**（後で playground を足すため）

作成直後に生成される `pch.h` / `pch.cpp` / `framework.h` は本書では使いません。プロジェクトから削除し、プロパティで **C/C++ > プリコンパイル済みヘッダー > プリコンパイル済みヘッダー = 使用しない** に変更しておきます。デバッグ表示の話にプリコンパイル済みヘッダーが絡むと切り分けが面倒になるためです。

### 手順2：コンソールアプリプロジェクト

1. ソリューションを右クリック > **追加 > 新しいプロジェクト**
2. テンプレート **「コンソール アプリ」**
3. プロジェクト名：`playground`

こちらも `pch` 系は削除しておきます。

### 手順3：参照とインクルードパス

playground から vizkit を使えるようにします。

1. playground を右クリック > **追加 > 参照** > `vizkit` にチェック
   （これでリンクは自動的に通ります）
2. playground のプロパティ > **C/C++ > 全般 > 追加のインクルード ディレクトリ** に
   `$(SolutionDir)vizkit\include` を追加

vizkit 側も、自分自身のヘッダーを `#include <vizkit/...>` の形で書けるように、同じパスを追加のインクルードディレクトリに入れておきます。

### 手順4：スタートアップ プロジェクト

ソリューションエクスプローラーで playground を右クリック > **スタートアップ プロジェクトに設定**。以降、F5 を押すと playground が起動します。

### この時点の構成

```
vizkit\
  vizkit.sln
  vizkit\                       ← 静的ライブラリ
    include\vizkit\core\point2.hpp
    include\vizkit\core\rgba.hpp
    src\vizkit.cpp
    vizkit.natvis
    vizkit.vcxproj
  playground\                   ← コンソールアプリ
    main.cpp
    playground.vcxproj
```

## 2.3 C++23 を有効にする

両方のプロジェクトに対して設定します。ソリューションエクスプローラーで **vizkit と playground を Ctrl キーで両方選択**してからプロパティを開くと、一度に設定できます。

**構成プロパティ > C/C++ > 言語 > C++ 言語標準**

ここで **ISO C++23 標準 (`/std:c++23`)** を選びます。

> **バージョンによる表記の違い**
> MSVC のビルドツールのバージョンによっては、この項目が **「プレビュー - ISO C++23 標準 (`/std:c++23preview`)」** と表示されている場合があります。その場合はそれを選んでください。`/std:c++23preview` は、`/std:c++latest` と違って「C++23 として確定した機能だけ」を有効にするスイッチで、`/std:c++23` が実装された環境では自動的にそちらの意味に読み替えられます。どちらでも本書の内容には影響しません。

構成は **Debug / x64** を選択しておきます。あわせて次も確認します。

- **C/C++ > 全般 > デバッグ情報の形式** = `プログラム データベース (/Zi)`
- **C/C++ > 最適化 > 最適化** = `無効 (/Od)`
- **リンカー > デバッグ > デバッグ情報の生成** = `はい (/DEBUG)`

Debug 構成なら既定でこうなっていますが、Natvis が期待どおり動かないときに最初に疑う場所なので、いま目で確認しておく価値があります。

## 2.4 最初の型を書く

### point2

`vizkit\include\vizkit\core\point2.hpp`

```cpp
#pragma once

namespace vizkit {

// 本書で最初に可視化する型。あえてメンバーを素朴にしてある。
struct point2 {
    double x = 0.0;
    double y = 0.0;
};

[[nodiscard]] constexpr point2 operator+(point2 a, point2 b) noexcept {
    return point2{ a.x + b.x, a.y + b.y };
}

[[nodiscard]] constexpr point2 operator-(point2 a, point2 b) noexcept {
    return point2{ a.x - b.x, a.y - b.y };
}

} // namespace vizkit
```

### rgba

`vizkit\include\vizkit\core\rgba.hpp`

```cpp
#pragma once

#include <cstdint>

namespace vizkit {

// 各成分は 0..255。unsigned char なので、デバッガの既定表示が
// 「数値ではなく文字」になる ―― これが第4章の題材になる。
struct rgba {
    std::uint8_t r = 0;
    std::uint8_t g = 0;
    std::uint8_t b = 0;
    std::uint8_t a = 255;
};

[[nodiscard]] constexpr rgba from_argb(std::uint32_t v) noexcept {
    return rgba{
        static_cast<std::uint8_t>((v >> 16) & 0xFFu),
        static_cast<std::uint8_t>((v >>  8) & 0xFFu),
        static_cast<std::uint8_t>( v        & 0xFFu),
        static_cast<std::uint8_t>((v >> 24) & 0xFFu),
    };
}

} // namespace vizkit
```

### ライブラリ本体に .cpp を1つ置く

静的ライブラリは翻訳単位が0個だとビルドできないため、最低1つの `.cpp` が必要です。ついでに、後の章で「PDB が生成されているか」を確認する手がかりにもなります。

`vizkit\src\vizkit.cpp`

```cpp
#include <vizkit/core/point2.hpp>
#include <vizkit/core/rgba.hpp>

namespace vizkit {

// このライブラリのバージョン。ここでは単に「.cpp が1つある」ことに意味がある。
int library_version() noexcept {
    return 1;
}

} // namespace vizkit
```

### 実験場

`playground\main.cpp`

```cpp
#include <vizkit/core/point2.hpp>
#include <vizkit/core/rgba.hpp>

#include <cstdio>

int main() {
    vizkit::point2 p{ 12.5, -4.0 };
    vizkit::point2 q{ 1.0, 2.0 };
    vizkit::point2 sum = p + q;

    vizkit::rgba color = vizkit::from_argb(0xFF3366CCu);
    vizkit::rgba transparent{ 0, 0, 0, 0 };

    // ここにブレークポイントを張る
    std::printf("%f %f %d\n", sum.x, sum.y, static_cast<int>(color.r));
    return 0;
}
```

ここまででビルドが通ることを確認してください（**ビルド > ソリューションのビルド**、Ctrl+Shift+B）。

## 2.5 .natvis ファイルをプロジェクトに追加する

いよいよ Natvis ファイルを置きます。**vizkit プロジェクト**の直下に追加します。

1. vizkit プロジェクトを右クリック > **追加 > 新しい項目**
2. 左のツリーで **Visual C++ > ユーティリティ**（もしくは検索ボックスに `natvis`）
3. **「デバッガー ビジュアライゼーション ファイル (.natvis)」** を選択
4. 名前：`vizkit.natvis`

テンプレートが見つからない場合は、**追加 > 新しい項目 > テキスト ファイル** で `vizkit.natvis` という名前のファイルを作っても構いません。拡張子が `.natvis` であれば MSBuild が認識します。

中身を次の骨格に置き換えます。

```xml
<?xml version="1.0" encoding="utf-8"?>
<AutoVisualizer xmlns="http://schemas.microsoft.com/vstudio/debugger/natvis/2010">

  <!-- ここに <Type> を足していく -->

</AutoVisualizer>
```

**`xmlns` の URL は正確に写してください。** 末尾の `2010` は Natvis スキーマのバージョンで、現在も変わっていません。この属性が抜けている、あるいは URL に打ち間違いがあると、ファイル全体が無視されます。しかもエラーメッセージが出ないことがあるため、「なぜか何も起きない」という最も厄介な症状になります。

### ビルドに載っているか確認する

`vizkit.natvis` を選択してプロパティウィンドウ（F4）を開きます。

| プロパティ | 期待値 |
|---|---|
| 項目の種類 | **Natvis** |
| ビルドから除外 | いいえ |

「項目の種類」が `なし` になっていたら、`Natvis` に変更してください。この設定が、後の章で扱う **PDB への埋め込み**（第40章）にも関わってきます。

> **なぜ vizkit 側に置くのか**
> Natvis ファイルは「ソリューションに読み込まれている C++ プロジェクトのどれかに含まれていれば」デバッガに読み込まれます。playground に置いても動きます。しかし natvis は**ライブラリの一部**です。ライブラリを配布したときに一緒に届くべきものなので、最初からライブラリ側に置いておきます。

## 2.6 デバッガを起動して素の表示を見る

1. `main.cpp` の `std::printf` の行にブレークポイント（F9）
2. **F5** でデバッグ実行

ブレークしたら、**自動変数**ウィンドウ（デバッグ > ウィンドウ > 自動変数）を見てください。次のように見えているはずです。

```
名前        値                              型
────────────────────────────────────────────────────────────
▷ color     {r=204 'Ì' g=102 'f' b=51 '3' ...}   vizkit::rgba
▷ p         {x=12.500000 y=-4.000000 }           vizkit::point2
▷ q         {x=1.000000 y=2.000000 }             vizkit::point2
▷ sum       {x=13.500000 y=-2.000000 }           vizkit::point2
▷ transparent {r=0 '\0' g=0 '\0' b=0 '\0' ...}   vizkit::rgba
```

`rgba` に注目してください。`std::uint8_t` は `unsigned char` の別名なので、デバッガは「これは文字だ」と解釈し、`204 'Ì'` のように文字表現を添えてきます。色成分としては明らかに邪魔です。これを直すのが第4章の後半の課題になります。

`point2` のほうは `{x=12.500000 y=-4.000000 }` と表示されています。**この既定の表示形式を覚えておいてください。** 第4章で `(12.5, -4)` に変えたとき、変化がはっきり分かります。

## 2.7 うまくいかないときのチェックリスト

| 症状 | 確認する場所 |
|---|---|
| `vizkit/core/point2.hpp` が見つからない | 追加のインクルードディレクトリに `$(SolutionDir)vizkit\include` が入っているか |
| リンクエラー `library_version` が未解決 | playground から vizkit への**参照**が設定されているか |
| `/std:c++23` が選択肢にない | MSVC ビルドツールのバージョンが古い。`/std:c++23preview` か `/std:c++latest` を選ぶ |
| ブレークポイントが白丸になる | 構成が Debug か、デバッグ情報の形式が `/Zi` か |
| 変数がまったく表示されない | Release 構成でビルドしていないか |

## 2.8 この章のまとめ

- 静的ライブラリ `vizkit` ＋ コンソールアプリ `playground` の2プロジェクト構成を作った。
- C++23（`/std:c++23`、環境により `/std:c++23preview`）を有効にし、Debug / x64 / `/Zi` / `/Od` を確認した。
- `point2` と `rgba` を実装し、デバッガでの既定表示を観察した。
- 空の `vizkit.natvis` をライブラリ側に追加し、**項目の種類 = Natvis** になっていることを確認した。
- `xmlns` の URL は1文字も間違えられない。間違えると無言で無視される。

次章では、Natvis を書く前に「デバッガが素で何を見せているのか」をもう少し丁寧に読みます。Natvis の式が触れる名前は、そこに見えている名前だからです。
