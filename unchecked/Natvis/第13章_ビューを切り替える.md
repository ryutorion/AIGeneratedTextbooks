# 第13章 ビューを切り替える

ここまでで、1つの型に対して1つの表示を作ってきました。しかし実際には、同じ型でも**場面によって見たいものが違います**。

- コンテナを 200 個並べたときは、要素数だけ分かればいい
- 1つのコンテナを深追いしているときは、容量もアロケータも負荷率も見たい

この章では、`IncludeView` / `ExcludeView` 属性とウォッチ式の `view()` 指定子で、**同じ型に複数の見え方を用意する**方法を扱います。あわせて、第3部の締めくくりとして `[Raw View]` の制御方法も見ます。

## 13.1 ビューとは何か

Natvis の「ビュー」は、**名前を付けた表示のバリエーション**です。仕組みは単純で、次の2つしかありません。

1. 各要素に `IncludeView="名前"` または `ExcludeView="名前"` を付ける
2. ウォッチ式に `,view(名前)` を付けて、そのビューで表示させる

ビュー名は自由に決められます。ただし **`simple` という名前は慣習化しています**。`STL.natvis` が使っているためです。

```xml
<Item Name="[size]" ExcludeView="simple">_Mylast - _Myfirst</Item>
```

「`simple` ビューでは `[size]` を出さない」という意味です。

## 13.2 ExcludeView ―― 簡易ビューを作る

第11章までに作った `rect` は、開くと6〜7行が出るようになりました。要素を並べる場面では過剰です。

`simple` ビューでは幾何情報を隠します。

```xml
<Type Name="vizkit::rect">
  <Intrinsic Name="w" Expression="_max.x - _min.x" />
  <Intrinsic Name="h" Expression="_max.y - _min.y" />
  <DisplayString Condition="w() &lt;= 0 || h() &lt;= 0">[empty]</DisplayString>
  <DisplayString>[{_min}, {_max}] {w(),g}x{h(),g}</DisplayString>
  <Expand>
    <Item Name="min">_min</Item>
    <Item Name="max">_max</Item>
    <Synthetic Name="[geometry]" ExcludeView="simple">
      <DisplayString>{w(),g} x {h(),g}, area={w() * h(),g}</DisplayString>
      <Expand>
        <Item Name="width">w()</Item>
        <Item Name="height">h()</Item>
        <Item Name="area">w() * h()</Item>
        <Item Name="aspect" Condition="h() != 0">w() / h()</Item>
      </Expand>
    </Synthetic>
  </Expand>
</Type>
```

ウォッチウィンドウで比べます。

```
式                    表示
─────────────────────────────────────────────────────
box                   [(0, 0), (640, 480)] 640x480
  ├ min               (0, 0)
  ├ max               (640, 480)
  └ [geometry]        640 x 480, area=307200

box,view(simple)      [(0, 0), (640, 480)] 640x480
  ├ min               (0, 0)
  └ max               (640, 480)
```

`,view(simple)` を付けたほうから `[geometry]` が消えました。

## 13.3 IncludeView ―― 詳細ビューを作る

逆に、「特定のビューのときだけ出す」のが `IncludeView` です。デバッグ専用の重い情報や、内部実装の詳細に向きます。

```xml
<Type Name="vizkit::byte_span">
  <Intrinsic Name="ptr" Expression="_data" />
  <Intrinsic Name="len" Expression="_size" />
  <DisplayString Condition="ptr() == nullptr">[null]</DisplayString>
  <DisplayString Condition="len() == 0">[empty]</DisplayString>
  <DisplayString>{len()} bytes, first={ptr()[0],Xb}</DisplayString>
  <Expand>
    <Item Name="[size]" ExcludeView="simple">len()</Item>
    <Synthetic Name="[alignment]" IncludeView="detail" Condition="ptr() != nullptr">
      <DisplayString>{(unsigned __int64)ptr() % 16 == 0 ? "16-byte aligned" : "unaligned"}</DisplayString>
      <Expand>
        <Item Name="address">(unsigned __int64)ptr(),X</Item>
        <Item Name="mod 16">(unsigned __int64)ptr() % 16</Item>
      </Expand>
    </Synthetic>
  </Expand>
</Type>
```

```
whole                 6 bytes, first=DE
  └ [size]            6

whole,view(detail)    6 bytes, first=DE
  ├ [size]            6
  └ [alignment]       16-byte aligned

whole,view(simple)    6 bytes, first=DE
  (子行なし)
```

3段階の詳しさを1つの型に持たせられました。

## 13.4 複数のビューを指定する

`IncludeView` / `ExcludeView` は、**セミコロン区切り**で複数のビュー名を並べられます。

```xml
<Item Name="[capacity]" ExcludeView="simple;compact">_cap - _begin</Item>
<Synthetic Name="[stats]" IncludeView="detail;debug">...</Synthetic>
```

カンマではなくセミコロンです。カンマは書式指定子の区切りに使われているため、ここでは使えません。間違えやすいので注意してください。

## 13.5 Type 要素自体にも付けられる

`IncludeView` / `ExcludeView` は個々のメンバーだけでなく、**`Type` 要素そのもの**にも付けられます。

```xml
<!-- 通常時はこちら -->
<Type Name="vizkit::circle" ExcludeView="raw">
  <DisplayString>circle r={radius,g} @ {center}</DisplayString>
  ...
</Type>

<!-- raw ビューではこちら -->
<Type Name="vizkit::circle" IncludeView="raw">
  <DisplayString>circle {{ center={center} radius={radius,g} layer={layer} }}</DisplayString>
  <Expand>
    <Item Name="center">center</Item>
    <Item Name="radius">radius</Item>
    <Item Name="layer">layer</Item>
  </Expand>
</Type>
```

`c,view(raw)` で、平坦化も派生情報も使わない素朴な表示に切り替えられます。**型ごと丸ごと差し替えたいとき**に使う形です。

## 13.6 ビューは入れ子の表示にも伝わる

`DisplayString` の中で `,view(名前)` を使うと、**その式の評価にビューを指定**できます。

```xml
<Type Name="vizkit::named_rect">
  <DisplayString>{_name} {_bounds,view(simple)}</DisplayString>
  ...
</Type>
```

`STL.natvis` の `std::tuple` が、括弧の有無を切り替えるためにこの手法を使っています。

```xml
<DisplayString IncludeView="noparens" Optional="true" Condition="...">
    {_Myfirst._Val}, {*((_Mybase *) this),view(noparens)}}
</DisplayString>
```

再帰的に「括弧なしビュー」で展開していくことで、`(1, 2, 3)` のような表示を組み立てています。**ビューは、再帰的な表示を制御する道具でもある**ということです。第30章以降のテンプレート対応で、この考え方を使います。

## 13.7 ビュー設計の指針

ビューを増やしすぎると、どのビューに何があるか分からなくなります。実務では次の3つで足ります。

| ビュー | 用途 | 内容 |
|---|---|---|
| （既定） | 普段のデバッグ | 要約 ＋ 主要な情報 ＋ 実データ |
| `simple` | 大量に並べるとき | 実データのみ。派生情報は隠す |
| `detail` | 深追いするとき | 既定 ＋ 統計・内部構造・診断 |

そして重要な原則があります。**既定のビューは、何も知らない人が開いても意味が分かるものにする。** `,view(...)` の存在を知っているのは Natvis を書いた人だけです。ライブラリの利用者が何も指定せずに開いたときの表示が、最も投資すべき場所です。

## 13.8 [Raw View] を制御する

第3部の締めくくりとして、`[Raw View]` の扱いを整理します。

`<Expand>` を書くと、デバッガが自動的に `[Raw View]` の行を追加します。これは**素のメンバー構造への逃げ道**であり、Natvis を書いている本人にとっては生命線です（第3章 3.4節）。

隠す方法は2つあります。

### Expand の HideRawView 属性

```xml
<Expand HideRawView="true">
  <Item Name="[width]">w()</Item>
  <Item Name="[height]">h()</Item>
</Expand>
```

既定値は `false` です。`true` にすると、この型の `[Raw View]` が現れなくなります。

### 書式指定子 nr

ウォッチ式側から抑制することもできます。

```
box,nr
```

こちらは一時的な指定なので、`.natvis` を書き換えずに済みます。

### 隠すべきか

原則は **隠さない**です。理由は3つあります。

1. **Natvis の保守ができなくなる。** メンバー名を変えたとき、`[Raw View]` がなければ新しい名前を調べる手段が減ります。
2. **Natvis が嘘をついているときに気づけない。** 条件分岐を間違えて誤った値を表示していても、生の値と突き合わせられません。
3. **隠しても大して短くならない。** 1行です。

隠してよいのは、次のような場合に限られます。

- 生ビューが極端に大きく、開くとデバッガが重くなる型
- 利用者に内部構造を見せたくないライブラリ（それでも、開発者向けに `IncludeView="raw"` の逃げ道は残すべきです）

**`HideRawView="true"` は、「もう Natvis の開発が終わった型」に対して最後に付けるもの**と考えてください。書いている最中に付けるものではありません。

## 13.9 第3部のまとめ

第10章から第13章までで、`<Expand>` の周辺を一通り扱いました。

```
Expand                      子行を再定義する（既定の展開は消え、[Raw View] が出る）
 ├─ Item                    式の結果を1行として見せる（第10章）
 ├─ Synthetic               式に対応しない行を作る。中に Expand を入れて階層化（第11章）
 ├─ ExpandedItem            式の結果の子行を、この位置に平坦に展開する（第12章）
 └─ HideRawView 属性        [Raw View] を隠す（第13章。原則使わない）

共通の属性
 ├─ Condition               行の有無を条件で制御（第7章）
 ├─ Optional                解析に失敗したら黙って飛ばす（第8章）
 └─ IncludeView/ExcludeView ビューごとの出し分け（セミコロン区切り、第13章）
```

ここまでで作れるのは、**要素数が固定の型**までです。`rect` も `version` も `circle` も、子行の数はコンパイル時に決まっています。

次の第4部からは、**要素数が実行時に決まる型** ―― つまりコンテナに入ります。`<ArrayItems>` を筆頭に、Natvis の本領が発揮される領域です。

## 13.10 この章のまとめ

- ビューは「名前を付けた表示のバリエーション」。`IncludeView` / `ExcludeView` と `,view(名前)` の2つだけで成り立つ。
- **複数のビュー名はセミコロン区切り。** カンマではない。
- `Type` 要素そのものにも付けられるので、型ごと差し替えられる。
- `DisplayString` の中で `,view(...)` を使うと、入れ子の表示にビューを伝えられる。再帰的な表示の制御に使える。
- 実務では **既定 / `simple` / `detail`** の3つで足りる。**最も投資すべきは既定のビュー**。
- `[Raw View]` は `HideRawView="true"` か `,nr` で隠せるが、**原則として隠さない**。Natvis の保守と検証の生命線。

## 13.11 演習

1. `rect` の `[geometry]` に `ExcludeView="simple"` を付けたうえで、ウォッチウィンドウに `box` と `box,view(simple)` を並べ、違いを確認してください。
2. `ExcludeView="simple,detail"`（カンマ区切り）と書いて `.natvisreload` し、どうなるか確認してください。セミコロンに直して再確認してください。
3. `named_rect` の `DisplayString` を `{_name} {_bounds,view(simple)}` に変え、`_bounds` の表示が変わるか確認してください。`DisplayString` は 1 行なので、ビューによる差が出るかどうかも含めて観察してください。
4. `circle` の `Expand` に `HideRawView="true"` を付けたうえで、`shape_base` のメンバー名を1つ変更してください。`[Raw View]` がない状態で Natvis を直す作業がどれだけ不便か、体験しておいてください。
