# 第44章 他ツールでの互換性

Natvis は Visual Studio のために作られた仕組みですが、いまでは複数のデバッガが対応しています。

ただし**対応の度合いはツールごとに違います**。Visual Studio で完璧に動く `.natvis` が、WinDbg では一部の要素が無視される、ということが実際に起こります。

この章では、主要なツールの対応状況と、互換性を保つ書き方を扱います。

## 44.1 対応状況の全体像

| ツール | 対応 | 備考 |
|---|---|---|
| Visual Studio（C++ デバッガ） | **完全** | 本書の前提 |
| VS Code + `cppvsdbg` | **完全** | Windows 専用。Visual Studio と同じデバッグエンジン |
| VS Code + `cppdbg`（GDB / LLDB） | **部分的** | MIEngine による移植版 |
| WinDbg / CDB | **部分的** | `.nvload` で読み込む |
| Visual Studio for Mac / Rider など | 実装依存 | 別途確認が必要 |

「部分的」の内容がツールごとに違うのが厄介な点です。

## 44.2 VS Code + cppvsdbg

Windows で VS Code を使う場合、`launch.json` の `"type": "cppvsdbg"` は **Visual Studio と同じデバッグエンジンを使います**。

> Microsoft C++ デバッギング（`"type": "cppvsdbg"`）：デバッガには Natvis フレームワークの完全な実装が含まれている。

したがって、本書で書いてきた `.natvis` はそのまま動きます。

`launch.json` での指定：

```json
{
  "name": "Debug playground",
  "type": "cppvsdbg",
  "request": "launch",
  "program": "${workspaceFolder}/build/playground.exe",
  "visualizerFile": "${workspaceFolder}/vizkit/vizkit.natvis",
  "showDisplayString": true
}
```

| 設定 | 意味 |
|---|---|
| `visualizerFile` | 読み込む `.natvis` のパス |
| `showDisplayString` | `DisplayString` を評価して表示するか |

`showDisplayString` を `true` にすると表示が改善しますが、**評価コストがかかります**。要素数の多いコンテナを扱う場合、`false` のほうが快適なことがあります。

PDB に埋め込んだ `.natvis`（第40章）は、`visualizerFile` を指定しなくても自動的に読み込まれます。

## 44.3 VS Code + cppdbg（GDB / LLDB）

Linux や macOS で GDB / LLDB を使う場合です。

> GDB / LLDB デバッギング（`"type": "cppdbg"`）：Natvis フレームワークの**部分集合**が VS Code C/C++ 拡張機能に移植された。

MIEngine というコンポーネントが Natvis を解釈します。**主要な要素は動きます**が、完全ではありません。

実務的な指針です。

- **`DisplayString` / `Expand` / `Item` / `ArrayItems` は期待できる**
- **`CustomListItems` の複雑なものは要検証**
- **`Intrinsic` の凝った使い方（引数付き、`Optional` の重ね方）は要検証**
- **`SmartPointer` の `Usage` による違いは環境差が出やすい**

クロスプラットフォームのライブラリを書いているなら、**Linux 側でも実際にデバッグして確認する**しかありません。動かない機能が見つかったら、C/C++ 拡張機能のリポジトリに報告するのが正しい対応です（ドキュメントでもそう案内されています）。

## 44.4 WinDbg / CDB

WinDbg は Natvis に対応していますが、**読み込みは明示的**です。

```
.nvload FileName
.nvload ModuleName
```

> `.nvload` コマンドは NatVis ファイルをデバッガ環境に読み込みます。可視化が読み込まれると、可視化で定義されたデータの表示に使われます。

| 引数 | 意味 |
|---|---|
| `FileName` | `.natvis` ファイルのパス |
| `ModuleName` | **そのモジュールの PDB に埋め込まれた Natvis を読み込む** |

第40章で PDB に埋め込んでおけば、`.nvload vizkit` の一行で読み込めます。**埋め込みの検証手段としても使えます**（第40章 40.6節）。

表示には `dx` コマンドを使います。

```
dx v
dx -r2 v          ← 2 階層まで展開
```

ユーザーモード / カーネルモード、ライブ / クラッシュダンプのいずれでも使えます。

### WinDbg で動かない機能

WinDbg の Natvis 実装には、**Visual Studio にあって WinDbg にない機能**があります。報告されているものとして、次の2つが挙げられています。

1. **`IncludeView` / `ExcludeView` 属性が効かない**
2. **`Intrinsic` のオーバーロード（同名で条件を変えて複数定義する書き方）が効かない**

1つ目は影響が大きい点です。本書は第13章以降、**ビューによる出し分けを設計の中心に据えてきました**。`ExcludeView="simple"` を付けた `[size]` / `[capacity]` は、WinDbg では常に表示されることになります。逆に `IncludeView="detail"` を付けた診断情報は、**WinDbg では見えない可能性があります**。

2つ目は、第8章 8.4節・第38章 38.4節で使った「同名の `Intrinsic` を `Optional="true"` で複数並べる」手法が使えないことを意味します。

## 44.5 互換性を保つ書き方

複数のツールで使われる `.natvis` を書く場合の指針です。

### 段階的に設計する

```
【基本層】どのツールでも動く
  Type / DisplayString / Condition / Expand / Item
  ArrayItems / LinkedListItems / TreeItems
  ワイルドカードと $T1

【中間層】ほぼ動くが検証が必要
  IndexListItems / ExpandedItem / Synthetic
  Intrinsic（Expression 付き、単一定義）
  SmartPointer

【上位層】Visual Studio 前提
  IncludeView / ExcludeView / view()
  CustomListItems の複雑なもの
  Intrinsic の Optional 重ね / Parameter 付き
  HResult / Version
```

**基本層だけで「読める」表示になるように設計し、上位層は改善として重ねる。** これが最も安全な構成です。

具体的には、次のようにします。

```xml
<Type Name="vizkit::dynamic_array&lt;*&gt;">
  <!-- 基本層: これだけで十分読める -->
  <DisplayString>{{ size={_end - _begin} }}</DisplayString>
  <Expand>
    <Item Name="[size]" ExcludeView="simple">_end - _begin</Item>
    <ArrayItems>
      <Size>_end - _begin</Size>
      <ValuePointer>_begin</ValuePointer>
    </ArrayItems>
  </Expand>
</Type>
```

`ExcludeView="simple"` が無視されても、`[size]` が常に出るだけで、致命的ではありません。**ビューを「あれば嬉しい」程度の位置づけにしておく**のがコツです。

逆に、**`IncludeView` の中にしか要素の列挙を置かない**という設計は避けてください。WinDbg で中身がまったく見えなくなります。

### 検証用の最小セットを用意する

ライブラリの各型について、代表的な値を作るテストプログラムを用意しておくと、**複数のツールで同じプログラムをデバッグして表示を比べられます**。第45章 45.3節のテストにもそのまま使えます。

```cpp
// natvis_showcase.cpp ― すべての型の代表的な状態を作る
int main() {
    vizkit::point2 p{ 12.5, -4.0 };
    vizkit::dynamic_array<int> v; /* 3 要素 */
    vizkit::chain_map<vizkit::name32,int> cm; /* 5 要素 */
    vizkit::optional_like<int> opt_none, opt_some;
    // ...
    breakpoint_here();
    return 0;
}
```

### 動かないツールがあることを文書に書く

ライブラリの README に一言書いておくだけで、利用者の混乱を防げます。

```markdown
## デバッガ表示について

`vizkit.natvis` は Visual Studio および VS Code (cppvsdbg) で完全に動作します。
WinDbg では `.nvload vizkit` で読み込めますが、ビュー切り替え（`,view(detail)` など）は
サポートされていません。
```

## 44.6 この章のまとめ

- **VS Code の `cppvsdbg` は Visual Studio と同じエンジン**なので完全対応。`launch.json` の `visualizerFile` と `showDisplayString` で制御する。
- **`cppdbg`（GDB / LLDB）は MIEngine による部分実装。** 主要な要素は動くが、`CustomListItems` の複雑なものや `Intrinsic` の凝った使い方は要検証。
- **WinDbg は `.nvload` で明示的に読み込む。** `ModuleName` を渡せば **PDB に埋め込まれた Natvis** を読み込める。表示は `dx`。
- WinDbg では **`IncludeView` / `ExcludeView` が効かない**、**`Intrinsic` のオーバーロードが効かない**ことが報告されている。
- 設計は**基本層（どこでも動く）／中間層（要検証）／上位層（VS 前提）**に分ける。
- **基本層だけで読める表示にし、ビューは「あれば嬉しい」程度に位置づける。** `IncludeView` の中にしか要素の列挙を置かない設計は避ける。
- 全型の代表的な状態を作る**検証用プログラムを用意**すると、複数ツールで比較でき、第45章のテストにも使える。
- **動かないツールがあることを README に書く。**

## 44.7 演習

1. VS Code をインストールし、`launch.json` に `cppvsdbg` の設定を書いて `playground` をデバッグしてください。本書の Natvis がそのまま動くことを確認します。
2. `showDisplayString` を `false` にして、表示がどう変わるか確認してください。
3. WinDbg（または CDB）で `playground.exe` を起動し、`.nvload vizkit` で PDB に埋め込んだ Natvis を読み込んでください。`dx v` で表示を確認します。
4. WinDbg で `dx v` と `dx -r2 v` を比べ、`ExcludeView="simple"` を付けた `[size]` が表示されるかどうかを確認してください。
5. 44.5節の `natvis_showcase.cpp` を作り、Visual Studio と WinDbg で同じプログラムをデバッグして、表示の差分を一覧にしてください。ライブラリの README に書くべき内容が見つかります。
