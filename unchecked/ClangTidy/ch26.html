第 26 章

bind で節点に名前を付ける

ここまでのクエリは「条件に合うか」を判定するだけでした。しかし実際にチェックを作るには、「木のどのノードに対して警告を出すか」を指定しなければなりません。callExpr 全体を指すのか、その中の関数名を指すのか。それを決めるのが bind です。第6部の Diagnostic 設定は、この名前を参照します。

26.1 なぜ名前が要るのか

26.2 書き方

.bind("名前") を、名前を付けたい Matcher の直後に書きます。

callExpr(callee(functionDecl(hasName("strcpy")).bind("fn"))).bind("call")

この式では2つのノードに名前が付いています。

名前指すノード
"call"strcpy(...) という呼び出し式全体
"fn"strcpy という関数の宣言
.bind() が書けるのは Node Matcher だけ

hasName("strcpy").bind("x") のようには書けません。Narrowing Matcher は「属性の条件」であってノードではないからです。.bind() はノードに名前を付ける操作なので、Node Matcher の後ろにしか置けません。

結果の見え方

clang-query> m callExpr(callee(functionDecl(hasName("strcpy")).bind("fn"))).bind("call")

Match #1:
ch25_match.cpp:14:5: note: "call" binds here
    strcpy(dst, src);
    ^~~~~~~~~~~~~~~~
cstring:XX:XX: note: "fn" binds here
…
ch25_match.cpp:14:5: note: "root" binds here
    strcpy(dst, src);
    ^~~~~~~~~~~~~~~~
1 match.

bind した名前ごとに note が出ます。それぞれがソースのどこを指しているかを確認するのが、bind が正しいかの検証です。

"root" とは

自分で名前を付けなくても "root" という note が出ています。これは クエリ全体のマッチ対象（一番外側の Matcher が指すノード）に自動で付く名前です。邪魔なときは消せます。

clang-query> set bind-root false

bind を1つも使っていない状態でこれを実行すると、何も表示されなくなります。bind-root false にするなら、必ず自分で bind を付けてください。

26.3 hasDescendant と forEachDescendant

ここが本章で最も間違えやすい点です。名前が似ていますが、マッチの個数が変わります。

使い分けの原則

報告したい対象そのものを、一番外側の Matcher にするのが基本です。「strcpy の呼び出しを全部報告したい」なら、外側を callExpr にすればよく、forEachDescendant は不要です。

# これで十分（3件マッチする）
m callExpr(callee(functionDecl(hasName("strcpy")))).bind("call")

forEach… が要るのは、外側に別の条件を付けたいときです。「noexcept でない関数の中にある strcpy 呼び出しを全部」のような場合、外側は functionDecl にせざるをえません。

26.4 複数の bind を使い分ける

第6部では、警告本体（Warning）と補足（Note）を別々の位置に出せます。そのために複数の bind を用意します。

# 「配列で確保したものを、配列でない delete で解放している」
cxxDeleteExpr(
  unless(isArrayForm()),
  has(
    ignoringImplicit(
      declRefExpr(
        to(varDecl(hasInitializer(ignoringImplicit(cxxNewExpr(isArray()).bind("alloc")))))
      )
    )
  )
).bind("del")
名前役割第6部での使い方
"del"問題のある delete 式Level: Warning ── 主たる指摘
"alloc"対応する new[] 式Level: Note ── 「ここで確保されている」

第17章で見た clang-analyzer-* の note 連鎖と同じ効果を、自作チェックでも作れるということです。読み手が原因にたどり着ける診断は、それだけで価値があります。

26.5 bind した結果を確認する

bind が意図どおりの位置を指しているかは、必ず確認してください。よくある失敗が2つあります。

失敗1：期待と違うノードを指している

clang-query> m callExpr(callee(functionDecl(hasName("strcpy")).bind("fn")))
…
cstring:104:20: note: "fn" binds here

"fn" が指しているのは、ヘッダにある strcpy の宣言です。呼び出し箇所ではありません。ここに警告を出すと、ユーザーのコードではなく標準ヘッダに波線が出ます。報告したい位置を bind しているか、必ず出力で確認してください。

失敗2：暗黙ノードを指している

第23章で見たとおり、AST には ImplicitCastExpr が挟まります。うっかりそれを bind すると、位置がずれたり、意図しないマッチになったりします。これは次章の set traversal で対処します。

26.6 【ハンズオン】bind を使いこなす

HANDS-ON 26　名前を付けて、位置を確かめる
  1. 検証コードを用意する。 第25章の ch25_match.cpp を拡張し、同じ関数内に strcpy を3回呼ぶ関数を足します。 
    void triple(char* a, char* b, char* c, const char* s) {
    strcpy(a, s);
    strcpy(b, s);
    strcpy(c, s);
}
  2. bind なしで実行する。 
    clang-query ch25_match.cpp -- -std=c++23
    m callExpr(callee(functionDecl(hasName("strcpy"))))
    "root" の note だけが出ることを確認します。件数も記録してください。
  3. bind を付ける。 
    m callExpr(callee(functionDecl(hasName("strcpy")).bind("fn"))).bind("call")
    "call" と "fn" の note がそれぞれ違う場所を指していることを確認します。"fn" がヘッダを指していることが観察点です。
  4. bind-root を切る。 
    set bind-root false
m callExpr(callee(functionDecl(hasName("strcpy")))).bind("call")
    "root" の note が消えることを確認します。次に .bind("call") を外して実行し、何も表示されなくなることを確認してください。
  5. 件数の違いを確かめる。 set bind-root true に戻してから、次の2つを実行し、件数を比較します。 
    m functionDecl(hasName("triple"), hasDescendant(callExpr().bind("c")))
m functionDecl(hasName("triple"), forEachDescendant(callExpr().bind("c")))
    前者が1件、後者が複数件になることを確認します。後者では "c" が毎回違う呼び出しを指しているはずです。
  6. 外側を変えて簡潔にする。 
    m callExpr(callee(functionDecl(hasName("strcpy"))), hasAncestor(functionDecl(hasName("triple")).bind("outer"))).bind("call")
    forEachDescendant を使わずに3件マッチすることを確認します。「報告したい対象を外側にする」という原則の実例です。
  7. 2か所を指す診断を設計する。 26.4 節のクエリを alloc() 関数に対して実行し、"del" と "alloc" がそれぞれ delete p; と new int[10] を指すことを確認します。うまくマッチしない場合は、set output dump で AST を見ながら条件を調整してください。ここでつまずくのは正常です。次章の道具で解決します。
  8. 保存する。 動いたクエリを queries\ に保存します。bind 名には、後で Diagnostic のメッセージを書くときに意味が通る名前を付けてください（"x" や "a" は避ける）。

この章のまとめ

  • .bind("名前") で、マッチした木の中の特定のノードに名前を付ける。この名前が、第6部で診断を出す位置の指定になる。
  • .bind() は Node Matcher の後ろにしか置けない。Narrowing Matcher には付けられない。
  • 自動で付く "root" はクエリ全体のマッチ対象。set bind-root false で消せるが、その場合は自分で bind が必須。
  • hasDescendant は1件、forEachDescendant は該当する子孫の数だけマッチする。 全箇所に警告を出したいなら後者。
  • 原則は「報告したい対象を一番外側の Matcher にする」。そうすれば forEach… は不要になることが多い。
  • 複数 bind により、警告本体と note を別々の位置に出せる。原因箇所を示す診断が作れる。
  • bind した位置は必ず出力で確認する。ヘッダ側の宣言や暗黙ノードを指してしまう事故が起きやすい。
