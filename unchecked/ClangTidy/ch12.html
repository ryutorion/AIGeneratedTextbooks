第 12 章

コマンドラインから直接叩く

第3部に入ります。IDE の中だけで使っていると、うまく動かないときに手詰まりになります。この章では clang-tidy.exe を素で起動し、コンパイルオプションを自分の手で渡します。「ヘッダが見つからない」「C++23 の構文でパースエラーになる」という詰まりどころは、すべてここに原因があります。

12.1 起動の形は二つしかない

第2章で見たとおり、Clang-Tidy はソースを実際にパースして AST を作ります。そのためにはコンパイルオプションが必要です。オプションの渡し方が2通りあり、それが起動形態の違いになります。

-- を忘れるとこうなる 
> clang-tidy config_loader.cpp
Error while trying to load a compilation database:
Could not auto-detect compilation database for file "config_loader.cpp"

「コンパイルデータベースが見つからない」というエラーは、ほとんどの場合 -- の書き忘れ です。引数を渡す必要がなくても、clang-tidy foo.cpp -- のように末尾に -- だけ書けば形態A になります。

12.2 -- の後ろに何を書くか

-- の後ろは Clang に渡すコンパイラ引数 です。MSVC の /std:c++23preview ではなく、Clang の -std=c++23 を書きます（第3章の図3-2）。

> clang-tidy config_loader.cpp -- -std=c++23 -I..\include -DNDEBUG -D_WIN32_WINNT=0x0A00
渡すものClang での書き方忘れるとどうなるか
言語規格-std=c++23C++23 の構文でパースエラー
インクルードパス-I<path>'foo.h' file not found
マクロ定義-D名=値#ifdef の別ブロックが解析される
強制インクルード-include foo.hプリコンパイル済みヘッダ前提のコードが壊れる

12.3 追加引数を設定で持たせる

毎回長い引数を打つのは現実的ではありません。.clang-tidy に書いておけます。

# .clang-tidy
ExtraArgsBefore: ['-std=c++23']
ExtraArgs: ['-Wno-unknown-pragmas']

Visual Studio のプロパティにも対応する項目があります（第5章の図5-1）。

VS のプロパティコマンドライン.clang-tidy
Clang-Tidy 追加オプション--extra-args=…ExtraArgs
Clang-Tidy 事前追加オプション--extra-args-before=…ExtraArgsBefore

before と after の違い

12.4 MSVC 前提のコードを Clang に読ませる

Windows のコードには MSVC 固有の要素が入り込みます。Clang はこれらを扱うためのモードを持っています。

ドライバモード

Clang には2つの引数解釈モードがあります。

モード引数の形指定方法
GNU 風（既定）-std=c++23 -I path -D NAME既定
MSVC 風（clang-cl）/std:c++latest /I path /D NAME--driver-mode=cl

ビルドスクリプトから MSVC 形式の引数をそのまま流用したい場合は、後者を使います。

> clang-tidy config_loader.cpp -- --driver-mode=cl /std:c++latest /I..\include /DNDEBUG

MSVC 互換オプション

オプション効果
-fms-compatibilityMSVC の非標準な挙動を受け入れる
-fms-extensions__declspec などの MS 拡張を有効にする
-fms-compatibility-version=19.4xどのバージョンの MSVC に合わせるかを指定
-fdelayed-template-parsingテンプレートの解析を遅らせる（MSVC の従来挙動に近づく）
MSBuild 経由なら通常は自動

Visual Studio の MSBuild 統合は、これらの互換オプションを自動的に付けてくれます。手で書く必要が出るのは、コマンドラインや CI から素の clang-tidy を叩くとき です。IDE では出ないパースエラーがコマンドラインで出たら、まずこの節を疑ってください。

12.5 エラー別・切り分けの地図

エラーを黙らせるオプションは使わない

clang-tidy にはコンパイラの診断を絞る手段がありますが、パースエラーを隠して解析を続けても意味がありません。第2章 2.5 節で触れたとおり、パースに失敗した部分の AST は不完全で、そこから出る警告も出ない警告も信用できません。エラーは消すものであって、隠すものではありません。

12.6 【ハンズオン】素で叩いて壊して直す

HANDS-ON 12　引数の効果を一つずつ確かめる
  1. -- なしで実行する。 開発者コマンドプロンプトで TidyLab\TidyLab に移動し、 
    clang-tidy config_loader.cpp
    「compilation database が見つからない」というエラーになることを確認します。
  2. -- だけ付ける。 
    clang-tidy config_loader.cpp --
    エラーの種類が変わることを確認します。<string> などが見つからないか、規格関連のエラーになるはずです。
  3. 規格を指定する。 
    clang-tidy config_loader.cpp -- -std=c++23
    main.cpp でも同じことを試し、std::println の行がエラーにならないことを確認します。-std=c++17 にすると壊れることも見ておいてください。
  4. マクロの効果を見る。 config_loader.cpp に一時的に次を入れます。 
    #ifdef TIDYLAB_STRICT
    int* legacy = NULL;   // modernize-use-nullptr が反応する
#endif
    -DTIDYLAB_STRICT を付けたときだけ警告が出ることを確認します。マクロの指定漏れは「解析されていないコードがある」ことを意味します。
  5. MSVC 形式で渡す。 
    clang-tidy config_loader.cpp -- --driver-mode=cl /std:c++latest
    --driver-mode=cl を外すと unknown argument になることを確認します。
  6. 設定ファイルに逃がす。 .clang-tidy に 
    ExtraArgsBefore: ['-std=c++23']
    を書き、clang-tidy config_loader.cpp -- だけで動くようになることを確認します。
  7. 実効設定を確認する。 
    clang-tidy --dump-config config_loader.cpp --
    ExtraArgsBefore が反映されていることを確認します。
  8. 後片付け。 手順4で追加した #ifdef ブロックを削除します。
この章で手に入る一番の武器

「IDE で説明のつかない挙動が出たら、コマンドラインで再現する」という切り分け手段です。IDE は内部で clang-tidy.exe を呼んでいるだけなので、同じ引数を手で組み立てれば必ず再現できます。そして再現できた手順は、そのまま CI に持っていけます（第40章）。

この章のまとめ

  • 起動形態は2つ。-- の後ろに引数を書く形態A と、-p でコンパイルデータベースを指す形態B。
  • 「compilation database が見つからない」は、ほぼ -- の書き忘れ。
  • -- の後ろは Clang の引数。/std:c++23preview ではなく -std=c++23。
  • 常用する引数は ExtraArgsBefore（前に挿入）/ ExtraArgs（後ろに挿入）で設定ファイルに持たせる。上書きしたいなら後ろ。
  • MSVC 形式の引数を使うなら --driver-mode=cl。MS 拡張には -fms-extensions / -fms-compatibility。
  • パースエラーは「解析できなかった」の合図。隠さずに消す。
