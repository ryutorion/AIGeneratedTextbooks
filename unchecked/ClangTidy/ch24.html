第 24 章

clang-query を起動する

本書で最も長く付き合うことになる道具です。AST に対して問い合わせを打ち、結果を即座に見て、条件を変えてまた打つ。この反復が、独自チェックを書く作業の実体です。いきなり .clang-tidy にクエリを書くのは悪手で、必ずここで確定させてから移します。

24.1 位置づけ

24.2 起動する

起動の形は clang-tidy と同じ2通りです（第12章の図12-1）。

// 形態A：その場で引数を渡す
> clang-query tiny.cpp -- -std=c++23

// 形態B：コンパイルデータベースを使う
> clang-query config_loader.cpp -p out\build\ninja

起動するとプロンプトが出ます。

clang-query>
対話に入らず1発で結果がほしいとき

-c でコマンドを直接渡せます。同じクエリを繰り返し確認するときや、スクリプトから呼ぶときに便利です。

clang-query -c "match functionDecl()" tiny.cpp -- -std=c++23

利用できるオプションは clang-query --help で確認してください。

24.3 コマンド体系

24.4 最初の問い合わせ

第23章の tiny.cpp を読み込んで、関数宣言を探します。

> clang-query tiny.cpp -- -std=c++23
clang-query> m functionDecl()

Match #1:
tiny.cpp:2:1: note: "root" binds here
int add(int a, int b) {
^~~~~~~~~~~~~~~~~~~~~~~
1 match.

末尾の 1 match. が最重要です。クエリを書くときは、まず件数を見ます。 意図した数と合っているかどうかが、条件の正しさを判断する材料になります。

名前で絞る

clang-query> m functionDecl(hasName("add"))
…
1 match.

clang-query> m functionDecl(hasName("subtract"))
0 matches.

24.5 出力モードを使い分ける

set output で結果の見せ方を変えられます。用途がはっきり分かれています。

clang-query> set output dump
clang-query> m functionDecl(hasName("add"))
…（マッチしたノードの部分木だけが出る）
これが -ast-dump より便利な理由

第23章の -ast-dump は翻訳単位を丸ごと出しました。set output dump は マッチしたノードの部分木だけを出します。「この CallExpr の下がどうなっているか知りたい」というとき、まさに必要な部分だけが得られます。

24.6 間違えたときの挙動

存在しない Matcher 名を打つと、その場で教えてくれます。これが clang-query で試作すべき最大の理由です。

clang-query> m functionDeclaration()
1:1: Error parsing matcher. Matcher not found: functionDeclaration

引数の型が合っていない場合も指摘されます。

clang-query> m functionDecl(hasName(42))
1:14: Incorrect type for arg 1. (Expected = String) != (Actual = Unsigned)
同じ間違いを .clang-tidy に書くと？

第6部で扱いますが、設定ファイルに書いたクエリが誤っている場合、気づきにくい形で失敗することがあります。クエリは必ず clang-query で通してから設定ファイルに移してください。 これは本書全体を通しての鉄則です。

Matcher 名を調べる

正しい名前を思い出せないときの調べ方は3つあります。

  1. AST から推測する：第23章の規則で、ノード名を小文字始まりにする。
  2. 補完を使う：入力途中で Tab を押すと候補が出る環境があります。
  3. 公式リファレンスを引く：AST Matcher Reference（第28章 28.8 節で引き方を扱います）。

24.7 クエリをファイルにする

試行錯誤の結果は消えてしまいます。file コマンドで、クエリの並びをファイルから実行できます。

# queries/no-strcpy.txt
# 禁止 API の検出クエリ（第32章で .clang-tidy に移す）
set output diag
set traversal IgnoreUnlessSpelledInSource
m callExpr(callee(functionDecl(hasName("::strcpy"))))
clang-query> file queries/no-strcpy.txt

# で始まる行はコメントです。クエリには必ずコメントで「何を検出したいか」を日本語で書いてください。 3日後の自分が読めなくなります。

24.8 【ハンズオン】対話に慣れる

HANDS-ON 24　clang-query を手に馴染ませる
  1. 起動する。 
    clang-query tiny.cpp -- -std=c++23
    プロンプトが出たら help と打ち、使えるコマンドを一覧します。
  2. 件数を数える練習。 次を順に打ち、件数の変化を記録します。 
    m functionDecl()
m functionDecl(hasName("add"))
m parmVarDecl()
m declRefExpr()
m binaryOperator()
m stmt()
m expr()
    stmt() と expr() の件数が大きいことを確認してください。 広すぎる Matcher から始めて絞っていく、という感覚を掴みます。
  3. 出力モードを切り替える。 
    set output print
m functionDecl(hasName("add"))

set output dump
m functionDecl(hasName("add"))

set output diag
m functionDecl(hasName("add"))
    それぞれの見え方の違いを確認します。
  4. 組み合わせる。 
    set output diag
enable output dump
m returnStmt()
    位置と部分木が両方出ることを確認します。確認したら disable output dump で戻します。
  5. わざと間違える。 
    m funcDecl()
m functionDecl(hasNam("add"))
m functionDecl(hasName(add))
    それぞれ異なるエラーメッセージが出ることを確認します。エラーの読み方に慣れておくと、後の作業が速くなります。
  6. 題材コードに切り替える。 
    quit
    でいったん抜け、今度は実際のコードを読み込みます。 
    clang-query config_loader.cpp -p out\build\ninja
    コンパイルデータベースがない場合は -- -std=c++23 方式で、必要なら -I を足してください（第12章）。
  7. 実コードで探す。 
    m functionDecl()
m cxxMethodDecl()
m cxxMethodDecl(hasName("load"))
m callExpr()
    件数が一気に増えることを確認します。ヘッダの中身まで含まれるためです。 絞り込みの必要性が実感できるはずです。
  8. 目標のクエリに一歩近づく。 
    m callExpr(callee(functionDecl(hasName("strcpy"))))
    set output print にして、何にマッチしたかを確認してください。これが第32章で作るカスタムチェックの原型です。
  9. ファイルに保存する。 queries\ ディレクトリを作り、24.7 節の形式でこのクエリを保存します。file コマンドで実行できることを確認します。

この章のまとめ

  • clang-query <file> -- <args> または -p <build dir> で起動する。clang-tidy と同じ2形態。
  • コマンドは3系統。①問い合わせ（match / m）②設定（set / enable / disable）③名前と入出力（let / unlet / file / help / quit）。
  • 出力モードは diag（位置）／print（ソース）／dump・detailed-ast（AST）。set は置き換え、enable は追加。
  • クエリを書くときは、まず件数（N matches.）を見る。
  • 存在しない Matcher 名や型の誤りは、その場でエラーとして教えてくれる。これが設定ファイルに直接書いてはいけない理由。
  • file コマンドでクエリをスクリプト化できる。# でコメントを書き、意図を残す。

次章： 第25章「Matcher の三分類」では、callExpr(callee(functionDecl(hasName("strcpy")))) のような式が、なぜこの形になるのかを構造から理解します。三種類の Matcher の役割が分かれば、クエリは自分で組み立てられるようになります。
