第 30 章

最初のカスタムチェック

書きます。第28章で clang-query で確認したクエリを、.clang-tidy に移すだけです。ただし、そのまま貼っても動きません。clang-query のセッション設定は設定ファイルに持っていけないという第27章の話が、ここで具体的な作業になります。

30.1 公式の例

まず、公式ドキュメントに載っている最小の例を見ます。

Checks: -*,custom-call-main-function
CustomChecks:
  - Name: call-main-function
    Query: |
        match callExpr(
          callee(
            functionDecl(isMain()).bind("fn")
          )
        ).bind("callee")
    Diagnostic:
      - BindName: fn
        Message: main function.
        Level: Note
      - BindName: callee
        Message: call to main function.
        Level: Warning

リスト30-1　公式ドキュメントの例（main 関数の呼び出しを検出する）

この短い YAML に、必要な要素がすべて入っています。読み解きましょう。

要素役割
CustomChecksカスタムチェックのリスト。複数書ける
Nameチェック名。-checks で指定するときに使う
Queryclang-query の文字列。match キーワードから始まる
Diagnostic報告する診断のリスト
BindNameQuery の中で .bind() した名前
Message表示するメッセージ
LevelWarning または Note
この例は C++ ではコンパイルできない

C++ では main を呼び出すこと自体が規格違反です。この例はドキュメント上の説明用と考えてください。実際に動かすなら、次節以降の例を使います。

30.2 名前の流れ

混乱しやすいのが名前です。Name に書いた文字列と、Checks に書く文字列は一致しません。

30.3 clang-query から移すときの変換

第28章のハンズオンで作ったクエリファイルは、こんな形でした。

# queries/no-strcpy.txt
set traversal IgnoreUnlessSpelledInSource
set output diag
let unsafeName hasAnyName("::strcpy", "::strcat", "::sprintf")
m callExpr(callee(functionDecl(unsafeName)), isExpansionInMainFile()).bind("call")

このうち、設定ファイルに持っていけるのは 最後の1行だけです。

30.4 動く最小の例を書く

まずは確実に動くもので、仕組みを通します。goto の使用を検出するチェックです。

---
Checks: '-*,custom-no-goto'

CustomChecks:
  - Name: no-goto
    Query: |
      match gotoStmt().bind("g")
    Diagnostic:
      - BindName: g
        Message: "goto は使用しないでください"
        Level: Warning
...

リスト30-2　最初のカスタムチェック

// samples/ch30_goto.cpp
void f(int n) {
    for (int i = 0; i < n; ++i) {
        if (i == 5) goto done;
    }
done:
    return;
}
> clang-tidy --experimental-custom-checks ch30_goto.cpp -- -std=c++23
ch30_goto.cpp:4:21: warning: goto は使用しないでください [custom-no-goto]
        if (i == 5) goto done;
                    ^

末尾の [custom-no-goto] に注目してください。 標準チェックの警告とまったく同じ形式です。ここから先、第2部で学んだことがすべて使えます。

30.5 YAML の書き方の要点

| で複数行のクエリを書く

クエリは長くなります。YAML のリテラルブロック（|）を使うと、改行を含めてそのまま書けます。

    Query: |
      match callExpr(
        callee(functionDecl(hasAnyName("::strcpy", "::strcat"))),
        isExpansionInMainFile()
      ).bind("call")
インデントに注意

| の次の行から、一段深いインデントが必要です。そしてタブは使えません（第7章）。クエリの中の改行やインデントは、そのまま文字列として渡されます。clang-query は改行を含む式を受け付けるので、これで問題ありません。

メッセージの引用符

メッセージに日本語やコロン、括弧を含める場合は、ダブルクォートで囲むのが安全です。YAML ではコロンの後ろに空白があると、キーと値の区切りと解釈されてしまいます。

        Message: "strcpy は禁止です: SafeCopy() を使ってください"

30.6 【ハンズオン】最初のチェックを動かす

HANDS-ON 30-A　仕組みを通す
  1. 検証ファイルを作る。 samples\ch30_goto.cpp を 30.4 節の内容で作ります。
  2. 設定を書く。 samples\ ディレクトリに .clang-tidy を作り、リスト30-2 の内容を書きます。親ディレクトリの設定を引き継がないよう、ここでは独立した設定にします（第7章）。
  3. 実行する。 
    clang-tidy --experimental-custom-checks ch30_goto.cpp -- -std=c++23
    警告が出れば成功です。ここが第6部の最初の関門です。
  4. フラグを外してみる。 
    clang-tidy ch30_goto.cpp -- -std=c++23
    警告が出ないことを確認します。この挙動を体で覚えてください。 「設定は正しいのに動かない」の第一容疑者になります。
  5. チェック名を確認する。 
    clang-tidy --experimental-custom-checks --list-checks ch30_goto.cpp -- -std=c++23
    一覧に custom-no-goto が含まれることを確認します。
  6. 接頭辞を間違えてみる。 Checks を '-*,no-goto' に変えて実行し、エラーにならず、単に警告が出なくなることを確認します（図30-1）。確認したら戻します。
  7. 標準チェックと同じ扱いであることを確かめる。
    • goto done; の行末に // NOLINT(custom-no-goto) を付け、警告が消えることを確認（第9章）
    • WarningsAsErrors: 'custom-no-goto' を設定に足し、警告がエラーになることを確認（第22章）
    自作チェックが、標準チェックとまったく同じ仕組みに載っていることの実証です。
HANDS-ON 30-B　第28章のクエリを移す
  1. 元のクエリを確認する。 queries\no-strcpy.txt を開き、clang-query で実行して件数を記録します。 
    clang-query ch28_rules.cpp -- -std=c++23
    file queries/no-strcpy.txt
  2. 変換する。 図30-2 の表に従って、設定ファイルの形に直します。
    • set 行を削除
    • let を展開
    • m を match に
    • 走査モードに依存していた部分を ignoringImplicit() などに置き換え（このクエリでは不要のはず）
  3. 設定ファイルに書く。 
    ---
Checks: '-*,custom-*'

CustomChecks:
  - Name: no-goto
    Query: |
      match gotoStmt().bind("g")
    Diagnostic:
      - BindName: g
        Message: "goto は使用しないでください"
        Level: Warning

  - Name: no-unsafe-string-api
    Query: |
      match callExpr(
        callee(functionDecl(hasAnyName("::strcpy", "::strcat", "::sprintf"))),
        isExpansionInMainFile()
      ).bind("call")
    Diagnostic:
      - BindName: call
        Message: "境界チェックのない文字列 API は使用しないでください"
        Level: Warning
...
    CustomChecks はリストなので、複数のチェックを並べられます。
  4. 件数を突き合わせる。 
    clang-tidy --experimental-custom-checks ch28_rules.cpp -- -std=c++23
    手順1で記録した件数と一致することを確認してください。 一致しなければ、変換のどこかで意味が変わっています。第36章のデバッグ手順に進む前に、まず clang-query に戻って比較します。
  5. 検出されるべきでないコードを確認する。 ch28_rules.cpp の strncpy の行に警告が出ていないことを確認します。「出るべきものが出る」と「出るべきでないものが出ない」の両方を確認するのが鉄則です。
  6. ヘッダを対象外にしていることを確認する。 isExpansionInMainFile() を一時的に外して実行し、件数がどう変わるかを見ます。標準ヘッダ内の宣言に反応していないかを確認してください。
  7. 回帰テストの土台を作る。 手順4・5 の確認内容を、tests\custom-checks\README.md に書き留めます。 
    # カスタムチェックの期待動作

| チェック | 対象ファイル | 期待件数 | 検出されるべき行 | 検出されてはいけない行 |
|---|---|---|---|---|
| custom-no-goto | ch30_goto.cpp | 1 | goto done; | ─ |
| custom-no-unsafe-string-api | ch28_rules.cpp | 1 | strcpy(dst, src); | strncpy(...) |
    第37章で、この表を自動検証する仕組みを作ります。

この章のまとめ

  • CustomChecks はリスト。各要素が Name / Query / Diagnostic を持つ。
  • Name: no-goto と書くと、チェック名は custom-no-goto になる。 Checks では接頭辞込みで書く。付け忘れてもエラーは出ない。
  • クエリは match キーワードから始まる。対話中の略記 m ではなく正式名で書く。
  • set traversal / set output / let は設定ファイルに持っていけない。 走査モードは ignoringImplicit() 等で式に埋め込み、let は展開する。
  • YAML のリテラルブロック | で複数行のクエリを書く。インデントとタブに注意。
  • 登録されたチェックは標準チェックと完全に同じ扱い。NOLINT も WarningsAsErrors も効く。
  • 移したら必ず件数を突き合わせる。「出るべきものが出る」と「出るべきでないものが出ない」の両方を確認する。

次章： 第31章「フィールドを正確に理解する」では、Name / Query / Diagnostic の各フィールドの意味と制約を、一つずつ正確に押さえます。特に Warning と Note の使い分けは、診断の質を大きく左右します。
