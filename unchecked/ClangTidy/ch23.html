第 23 章

Clang AST を覗く

第5部が始まります。ここからは「自分でルールを書く」ための土台作りです。第2章で「Clang-Tidy は AST を見ている」と説明しました。その AST を、いま実際に自分の目で見ます。これから書くクエリは、この木構造に対する問い合わせです。 木の形が見えていないと、クエリは書けません。

23.1 ここからの道筋

23.2 -ast-dump で木を出す

Clang には、構築した AST をテキストで出力する機能があります。

> clang++ -Xclang -ast-dump -fsyntax-only -std=c++23 tiny.cpp
オプション意味
-Xclang -ast-dumpAST をテキストで出力する（-Xclang は「次の引数をフロントエンドに渡す」）
-fsyntax-onlyコード生成をせず、構文・意味解析まででやめる
-Xclang -ast-dump=jsonJSON 形式で出す（機械処理向け）
-Xclang -ast-dump-filter=<名前>名前が一致する宣言だけ出す（これがないと実用にならない）
まず小さなファイルで練習する

#include <string> が1行あるだけで、AST は数万行になります。標準ライブラリの中身がすべて木になるからです。AST を学ぶ段階では、インクルードを一切含まない小さなファイルを使ってください。 実プロジェクトのファイルを dump するのは、-ast-dump-filter の使い方を覚えてからです。

なお Windows で MSVC のヘッダを読ませる必要が出たら、開発者コマンドプロンプトから clang-cl ドライバを使うか、第12章の --driver-mode=cl と互換オプションを併用してください。

23.4 ノード名の読み方

ノード名には規則があります。末尾を見れば、そのノードが何の仲間か分かります。

これが「AST を見る」ことの実利

ルールを作りたいコードを -ast-dump して、目当ての箇所のノード名を読む。それを小文字始まりにすれば Matcher の出発点になる。 第25章以降でやることは、この出発点に条件を足していく作業です。

23.5 巨大な出力と付き合う

実プロジェクトのファイルを dump すると数万行になります。-ast-dump-filter で絞ります。

> clang++ -Xclang -ast-dump -Xclang -ast-dump-filter=ConfigLoader -fsyntax-only -std=c++23 config_loader.cpp

これで ConfigLoader という名前を含む宣言だけが出力されます。それでもメンバ関数の中身は全部出るので、さらに絞りたければ関数名を指定します。

> clang++ -Xclang -ast-dump -Xclang -ast-dump-filter=load -fsyntax-only -std=c++23 config_loader.cpp
次章の予告：もっと良い方法がある

-ast-dump は「全部出して目で探す」道具です。第24章で扱う clang-query は「条件に合うノードだけを出す」道具で、しかも対話的に条件を変えられます。実際の作業では clang-query が主役になります。
それでも -ast-dump を先にやる理由は、木の全体像を一度は見ておかないと、clang-query で何を探せばよいか分からないからです。

23.6 【ハンズオン】木を読む

HANDS-ON 23　AST の形を目で確かめる
  1. 最小のファイルを作る。 samples\tiny.cpp を 23.3 節の内容で作ります。インクルードは書かないでください。
  2. dump する。 
    clang++ -Xclang -ast-dump -fsyntax-only -std=c++23 tiny.cpp
    出力の末尾（FunctionDecl add 以降）を、図23-2 と見比べます。
  3. 暗黙ノードを確認する。 ImplicitCastExpr がどこに挟まっているか、ソースコードのどこにも書かれていないことを確認してください。<LValueToRValue> という注記も読みます。
  4. コードを変えて木の変化を見る。 次の順に tiny.cpp を書き換え、そのたびに dump します。
    • return a + b; → return a;（BinaryOperator が消える）
    • 引数を const int& a にする（ImplicitCastExpr の種類が変わる）
    • 関数をクラスのメンバにする（CXXRecordDecl と CXXMethodDecl が現れる）
  5. ノード名を Matcher 名に変換する。 出てきたノード名を、図23-3 の規則に従って小文字始まりに直し、一覧にします。この一覧が第25章の出発点になります。 
    FunctionDecl   → functionDecl
ParmVarDecl    → parmVarDecl
CompoundStmt   → compoundStmt
ReturnStmt     → returnStmt
BinaryOperator → binaryOperator
DeclRefExpr    → declRefExpr
CXXMethodDecl  → cxxMethodDecl
  6. 題材コードで -ast-dump-filter を使う。 
    clang++ -Xclang -ast-dump -Xclang -ast-dump-filter=load -fsyntax-only -std=c++23 config_loader.cpp
    ヘッダを含むためエラーが出る場合は、第12章の -I や互換オプションを足してください。出力の行数を数え、フィルタなしとの差を確認します。
  7. 探したい形を特定する。 出力の中から strcpy の呼び出しに対応する部分を探し、そこにどんなノードが並んでいるかを書き出します。おそらく CallExpr と、その下の ImplicitCastExpr → DeclRefExpr という形になっているはずです。これが第28章のレシピ1の元ネタです。
  8. JSON でも出してみる（任意）。 
    clang++ -Xclang -ast-dump=json -fsyntax-only -std=c++23 tiny.cpp > tiny-ast.json
    テキスト形式と同じ情報が構造化されて入っていることを確認します。ツールを自作するときに使えます。

この章のまとめ

  • clang++ -Xclang -ast-dump -fsyntax-only で AST をテキスト出力できる。
  • 学習段階ではインクルードのない小さなファイルを使う。 #include が1行あるだけで数万行になる。
  • 実ファイルでは -Xclang -ast-dump-filter=<名前> で絞る。
  • ノード名は系統で分かれる。…Decl（宣言）、…Stmt（文）、…Expr（式）。接頭辞 CXX は C++ 固有。
  • ノード名の先頭を小文字にすれば、そのまま Matcher の名前になる。 FunctionDecl → functionDecl()。
  • ソースに書かれていない ImplicitCastExpr などの暗黙ノードが挟まる。これが Matcher を書くときの最大のつまずきどころで、第27章で対処する。

次章： 第24章「clang-query を起動する」では、「全部出して探す」から「条件に合うものだけ出す」へ移ります。ここからが実作業の道具です。
