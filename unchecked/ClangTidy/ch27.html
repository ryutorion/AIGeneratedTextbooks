第 27 章

Matcher を書きやすくする道具

前章の最後で、new[] と delete のクエリがうまく書けなかったはずです。原因は第23章で予告した暗黙ノードです。ソースに書かれていない ImplicitCastExpr が木に挟まっていて、素直に書いた条件が通らない。この章でその問題を片付け、あわせてクエリを保守しやすくする道具を揃えます。

27.1 暗黙ノードという壁

int* p = new int[10]; という単純な行が、AST ではこうなっています。

clang-query> set traversal IgnoreUnlessSpelledInSource
最初にこれを打つ

clang-query を起動したら、まず set traversal IgnoreUnlessSpelledInSource を打つ ── これを習慣にしてください。初学者が「クエリが通らない」と悩む原因の大半は、暗黙ノードです。

逆に、暗黙の型変換そのものを検出したい場合（bugprone-narrowing-conversions のようなチェックを自作したい場合）は AsIs でなければなりません。「何を見たいか」でモードを選びます。

27.2 設定ファイルに移すときの注意

set traversal は clang-query のセッション設定です。第6部で .clang-tidy にクエリを移すとき、この設定はそのままでは持っていけません。

解決策は2つあります。

方法1：traverse() を式の中に書く

走査モードを Matcher 式の一部として埋め込みます。

traverse(TK_IgnoreUnlessSpelledInSource,
  varDecl(hasInitializer(cxxNewExpr(isArray()).bind("alloc"))).bind("var")
)

この形なら、式そのものにモードが含まれるので、どこに持っていっても同じ結果になります。

方法2：暗黙ノードを飛ばす Matcher を明示する

特定の位置だけ暗黙ノードを無視します。

Matcher飛ばすもの
ignoringImplicit(M)暗黙のノード全般
ignoringParenImpCasts(M)括弧と暗黙キャスト
ignoringParenCasts(M)括弧と（明示を含む）キャスト
varDecl(hasInitializer(ignoringImplicit(cxxNewExpr(isArray()).bind("alloc")))).bind("var")
どちらを使うか

方法2（明示的に飛ばす）を推奨します。 どこで何を無視しているかが式に書かれているので、後から読んだ人が理解できます。方法1 は式全体の挙動を変えるため、思わぬ副作用が出ることがあります。

なお第29章で述べるとおり Query Based Custom Check は実験的機能であり、設定ファイル側でどの記法が受け付けられるかはバージョンによって変わりえます。移行したら必ず、設定ファイル経由でも同じ件数が出ることを確認してください。

27.3 let で名前を付けて再利用する

クエリは長くなります。同じ部分式を何度も書くのは苦痛ですし、間違いのもとです。

clang-query> let unsafeName hasAnyName("strcpy", "strcat", "sprintf")
clang-query> m callExpr(callee(functionDecl(unsafeName))).bind("call")
clang-query> unlet unsafeName
let はセッション限りの道具

let で定義した名前も、設定ファイルには持っていけません。let は試行錯誤を速くするための道具と割り切り、確定したら展開した形で保存してください。第24章の file コマンドでクエリファイルを作るときは、let の行も一緒に書いておけば再現できます。

27.4 デバッグの補助

set print-matcher true

実行したクエリ式を結果の前に表示します。let を多用していると「いま何を実行したか」が分からなくなるので、そのときに有効です。

set enable-profile true

クエリの実行時間を計測します。hasDescendant や hasAncestor は木を広く歩くため重く、大きなファイルでは体感できるほど遅くなります。第6部で設定ファイルに入れるクエリは、解析のたびに全ファイルに対して実行されます。 重いクエリを入れる前に、ここで確認しておく価値があります。

27.5 マッチしない／しすぎるときの手順

名前の指定は完全修飾で

hasName("strcpy") は、名前の末尾が一致すればマッチします。自作の MyClass::strcpy も拾ってしまうということです。グローバルの strcpy だけを狙うなら hasName("::strcpy") と書きます。 先頭の :: がグローバル名前空間を意味します。件数が想定より多いときは、まずここを疑ってください。

27.6 【ハンズオン】積み残しを解決する

HANDS-ON 27　暗黙ノードを越える
  1. 問題を再現する。 ch25_match.cpp を読み込み、走査モードを既定のままで次を実行します。 
    m varDecl(hasInitializer(cxxNewExpr()))
    0 matches. になることを確認します。
  2. 木を見る。 
    set output dump
m varDecl(hasName("p"))
    初期化式のところに ImplicitCastExpr などが挟まっていることを確認してください。これが 0 件の理由です。
  3. 走査モードを変える。 
    set output diag
set traversal IgnoreUnlessSpelledInSource
m varDecl(hasInitializer(cxxNewExpr()))
    今度はマッチすることを確認します。
  4. 明示的に飛ばす形でも書く。 
    set traversal AsIs
m varDecl(hasInitializer(ignoringImplicit(cxxNewExpr())))
    走査モードを戻しても、こちらの形ならマッチすることを確認します。設定ファイルに持っていくのはこの形です。
  5. 前章の積み残しを完成させる。 「new[] で確保したものを、配列でない delete で解放している」を検出します。 
    m cxxDeleteExpr(
    isExpansionInMainFile(),
    unless(isArrayForm()),
    has(ignoringImplicit(
      declRefExpr(to(varDecl(
        hasInitializer(ignoringImplicit(cxxNewExpr(isArray()).bind("alloc")))
      )))
    ))
  ).bind("del")
    "del" と "alloc" がそれぞれ delete p; と new int[10] を指すことを確認します。
  6. let で整理する。 手順5 のクエリを分解します。 
    let arrayAlloc  cxxNewExpr(isArray())
let ourCode     isExpansionInMainFile()
m cxxDeleteExpr(ourCode, unless(isArrayForm()),
    has(ignoringImplicit(declRefExpr(to(varDecl(
      hasInitializer(ignoringImplicit(arrayAlloc.bind("alloc")))))))))
  .bind("del")
    同じ結果が出ることを確認します。
  7. 名前の指定を厳しくする。 strcpy のクエリで、完全修飾の有無による件数の違いを確認します。 
    m callExpr(callee(functionDecl(hasName("strcpy"))))
m callExpr(callee(functionDecl(hasName("::strcpy"))))
    検証用に MyClass::strcpy のようなメンバ関数を足してから試すと、差がはっきりします。
  8. コストを測る。 
    set enable-profile true
m callExpr(hasAncestor(functionDecl(hasDescendant(callExpr()))))
    重いクエリの実行時間を確認します。第6部で設定ファイルに入れるクエリは、全ファイルに対して毎回実行されることを思い出してください。
  9. クエリファイルにまとめる。 queries\new-delete-mismatch.txt を作り、let の定義とコメント、確定したクエリを保存します。 
    # new[] で確保したものを delete で解放している箇所を検出する
# → 第33章で .clang-tidy の CustomChecks に移す
set traversal AsIs
set output diag
let arrayAlloc cxxNewExpr(isArray())
m cxxDeleteExpr(isExpansionInMainFile(), unless(isArrayForm()),
    has(ignoringImplicit(declRefExpr(to(varDecl(
      hasInitializer(ignoringImplicit(arrayAlloc.bind("alloc")))))))))
  .bind("del")

この章のまとめ

  • AST にはソースに書かれていない暗黙ノードが挟まる。素直に書いたクエリが 0 件になる最大の原因。
  • set traversal IgnoreUnlessSpelledInSource で暗黙ノードを飛ばせる。起動したらまずこれを打つ習慣を。
  • ただし set traversal はセッション設定なので設定ファイルには持っていけない。移行時は ignoringImplicit() などで明示的に飛ばす形に書き換える。
  • let で部分式に名前を付けて再利用できる。ただしこれもセッション限りの道具。
  • set print-matcher と set enable-profile がデバッグを助ける。重いクエリは設定ファイルに入れる前に測る。
  • 0 件のときは条件を外側から1つずつ削って犯人を特定する。多すぎるときは isExpansionInMainFile()、unless(isInStdNamespace())、unless(isImplicit()) で削る。
  • hasName("strcpy") は末尾一致。グローバルだけを狙うなら hasName("::strcpy")。
