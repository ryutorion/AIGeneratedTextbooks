第 7 章

.clang-tidy 設定ファイルへ移行する

プロパティページに書いた設定は、そのプロジェクトファイルの中にしか存在しません。チームで共有できず、コマンドラインからも CI からも再現できません。この章で設定をテキストファイルに移し、Clang-Tidy 運用の土台を作ります。ディレクトリ階層による設定の継承は、大きなリポジトリで効いてくる仕組みです。

7.1 なぜファイルにするのか

プロパティページ.clang-tidy
保存先.vcxproj の中（XML）独立したテキストファイル
差分の読みやすさXML の中に埋もれる行単位で明瞭
コマンドラインからの再現できない自動的に読まれる
CI での再現MSBuild 経由でのみそのまま使える
ディレクトリ単位の使い分け不可可能（本章の主題）
カスタムチェックの定義不可可能（第6部）

最後の行が決定的です。Query Based Custom Check は .clang-tidy の中にしか書けません。 本書の主題に到達するには、この移行が必須です。

7.2 設定ファイルはどう探されるか

Clang-Tidy は 解析対象のソースファイルごとに 設定ファイルを探します。プロジェクト単位でも、実行したカレントディレクトリでもありません。ここを誤解すると、意図しない設定が効いて混乱します。

探索は「そのソースファイルが置かれているディレクトリから、親をたどって上へ」進み、最初に見つかった .clang-tidy が使われます。

この仕組みには実用上の意味があります。third_party\ に「全部無効」の設定ファイルを1つ置くだけで、外部ライブラリのソースをまるごと解析対象から外せます。

# third_party/.clang-tidy
Checks: '-*'

7.3 InheritParentConfig ── 親を引き継ぐ

既定では、最も近い設定ファイルが親を完全に置き換えます。しかし大きなリポジトリでは「全体の共通ルール＋このディレクトリ固有の追加」という形にしたくなります。そのためのオプションが InheritParentConfig です。

公式ドキュメントの説明はこうです。「このオプションが設定ファイルで true のとき、親ディレクトリの設定ファイル（あれば）が取得され、現在の設定ファイルがその上に適用される」。

大きなリポジトリでの定石

リポジトリのルートに「全体で守るべき最小限のルール」を置き、サブディレクトリでは InheritParentConfig: true を書いて追加分だけを記述します。新規開発中のモジュールだけ厳しくする、レガシーな部分だけ緩める、といった運用が自然にできます。第39章の段階導入で使う手です。

7.5 現在の設定を確認する二つのコマンド

--dump-config ── 実効設定の全体を見る

階層をたどった結果、最終的にどんな設定になっているかを YAML で出力します。解析対象のファイルを指定して実行する のがポイントです（ファイルごとに設定が違いうるため）。

> clang-tidy --dump-config config_loader.cpp --
---
Checks:              '-*,bugprone-*,clang-analyzer-*,performance-*'
WarningsAsErrors:    ''
HeaderFileExtensions:         ['', 'h','hh','hpp','hxx']
ImplementationFileExtensions: ['c','cc','cpp','cxx']
HeaderFilterRegex:   '.*'
FormatStyle:         none
InheritParentConfig: true
User:                user
CheckOptions:
  bugprone-argument-comment.CommentBoolLiterals: '0'
  ...
...

注目すべきは CheckOptions です。ここに 有効なチェックが持つ全オプションの現在値 が並びます。第8章で使う情報源はこれです。

--explain-config ── なぜ有効なのかを知る

設定ファイルが階層になっていると、「このチェックはどこで有効になったのか」が分からなくなります。そのときに使います。

> clang-tidy --explain-config config_loader.cpp --
'bugprone-use-after-move' is enabled in the C:\dev\TidyLab\.clang-tidy.
'performance-move-const-arg' is enabled in the C:\dev\TidyLab\src\.clang-tidy.

7.6 【ハンズオン】設定を移行する

HANDS-ON 7-A　プロパティから設定ファイルへ
  1. ソリューション直下の .clang-tidy を書き換える。 第3章で Checks: '-*' とだけ書いたファイルを、次の内容にします。 
    ---
# TidyLab 全体の基本設定
Checks: >
  -*,
  bugprone-*,
  clang-analyzer-*,
  performance-*

HeaderFilterRegex: '.*'
WarningsAsErrors: ''
FormatStyle: none
...
    YAML の >（折りたたみスカラー）を使うと複数行に分けて書けます。読みやすさのために、チェックが増えてきたらこの形にします。改行は空白1個に畳まれるので、各行の末尾にカンマを忘れないでください。
  2. プロパティ側を空にする。 構成プロパティ > コード分析 > Clang-Tidy > Clang-Tidy チェック の値を削除して空にします。これで設定の出どころが1か所になります。
  3. ビルドして、第6章と同じ警告が出ることを確認する。 出なければ、.clang-tidy の位置が正しいか（.txt が付いていないか）を確認します。
  4. 実効設定を確認する。 開発者コマンドプロンプトで、 
    cd C:\dev\TidyLab\TidyLab
clang-tidy --dump-config config_loader.cpp -- -std=c++23
    Checks の値が手順1で書いたものになっていることを確認します。
HANDS-ON 7-B　階層設定を体験する
  1. サブディレクトリを作る。 TidyLab\TidyLab\legacy\ を作り、そこに old_util.cpp を置きます（中身は何でもよいので、警告が出る古めのコードにします）。
  2. 置き換え型の設定を試す。 legacy\.clang-tidy を次の内容で作ります。 
    Checks: '-*'
    clang-tidy --dump-config legacy\old_util.cpp -- -std=c++23 を実行し、親の bugprone-* などが消えていることを確認します。
  3. 継承型に変える。 同じファイルを次の内容に書き換えます。 
    InheritParentConfig: true
Checks: '-performance-*'
    もう一度 --dump-config を実行し、親の設定を引き継いだうえで performance-* だけが外れていることを確認します。
  4. どこで有効になったかを見る。 
    clang-tidy --explain-config legacy\old_util.cpp -- -std=c++23
    親の .clang-tidy のパスが表示されることを確認します。
  5. 後片付け。 実験が済んだら legacy\ は削除するか、third_party\ の用途に転用してください。
YAML の落とし穴

設定ファイルは YAML です。次の3つが典型的なミスです。

  • タブ文字：YAML はインデントにタブを使えません。必ず空白で。
  • クォートの欠落：Checks: -*,bugprone-* のように書くと、先頭の - がリストの記号と解釈されて壊れます。'…' で囲むか > を使ってください。
  • パースエラーが静かに起こる：設定ファイルが壊れていても、実行が止まらず「チェック0件」になることがあります。--dump-config で確認する習慣をつけてください。

7.7 設定ファイルの全体像

この先の章で扱うキーも含め、.clang-tidy で使う主なオプションを一覧にしておきます。

キー意味扱う章
Checks有効にするチェックのグロブ列第6章
CheckOptionsチェックごとのオプション第8章
HeaderFilterRegex診断を出すヘッダの正規表現第10章
ExcludeHeaderFilterRegex除外するヘッダの正規表現第10章
SystemHeadersシステムヘッダの診断を出すか第10章
FormatStyle自動修正後の整形スタイル第11章
WarningsAsErrorsエラー扱いにするチェック第40章
InheritParentConfig親設定を引き継ぐか本章
ExtraArgs / ExtraArgsBeforeコンパイラへの追加引数第12章
CustomChecksQuery Based Custom Check の定義第29〜38章

この章のまとめ

  • 設定は .clang-tidy に一本化する。Query Based Custom Check はこのファイルにしか書けない。
  • 設定ファイルは ソースファイルの位置から親をたどって探され、最初に見つかった1つ が使われる。
  • InheritParentConfig: true で親を引き継げる。Checks は連結され、子側が後に来るので子が勝つ。
  • 優先順位は バイナリ既定 → 親設定 → 最も近い設定 → コマンドライン → --config。
  • --dump-config <file> -- で実効設定を、--explain-config でチェックの出どころを確認する。
  • YAML のタブ・クォート漏れに注意。壊れていても静かに「0件」になることがある。

次章： 第8章「チェックのオプションを変える」では、--dump-config で見えた CheckOptions に手を入れます。しきい値や命名規則を、自分のプロジェクトに合わせて調整できるようにします。
