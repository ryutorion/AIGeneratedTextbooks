第 25 章

Matcher の三分類

callExpr(callee(functionDecl(hasName("strcpy"))))。前章の最後に打ったこの式は、暗号ではありません。三種類の Matcher が、決まった役割で組み合わさっているだけです。公式リファレンスもこの三分類で整理されています。分類が分かれば、リファレンスを引けるようになり、クエリを自分で組み立てられるようになります。

25.1 三つの分類

AST Matcher Reference は、Matcher を次の3つに分類しています。

25.2 式を分解する

前章の式を、この三分類で色分けしてみます。

公式リファレンスの指摘

AST Matcher Reference には「効果的な matcher 式は、通常 node matcher と narrowing / traversal matcher を交互に組み合わせることで、英語のように読める構造になる」という趣旨の説明があります。「英語として読めるか」が、クエリが正しく書けているかの目安になります。

25.3 入れ子は AND を意味する

Node Matcher の括弧の中に複数の条件をカンマで並べると、そのすべてを満たすという意味になります。

cxxMethodDecl(
  hasName("load"),        // 名前が load で、
  isConst(),              // かつ const で、
  parameterCountIs(0)     // かつ引数が0個
)

論理演算

Matcher意味
allOf(A, B)A かつ B（カンマ区切りと同じ。明示したいとき使う）
anyOf(A, B)A または B
unless(A)A でない
eachOf(A, B)A と B のそれぞれについてマッチを生成する
optionally(A)A にマッチすれば bind するが、しなくてもマッチ全体は成立する
anything()常に真
# strcpy か strcat のどちらかの呼び出し
callExpr(callee(functionDecl(anyOf(hasName("strcpy"), hasName("strcat")))))

# 上と同じことを、専用の Matcher で簡潔に
callExpr(callee(functionDecl(hasAnyName("strcpy", "strcat"))))

# main 関数の中ではないもの
callExpr(unless(hasAncestor(functionDecl(hasName("main")))))

25.4 絞り込みは段階的に

クエリは一度に完成させません。広い Node Matcher から始めて、件数を見ながら条件を足していきます。

必要なのは三分類の考え方だけです。「ここで別のノードに移りたい」と思ったら Traversal を探し、「この属性で絞りたい」と思ったら Narrowing を探す。具体的な名前はリファレンスを引けば済みます。引き方は第28章 28.8 節で扱います。

25.6 【ハンズオン】三分類で組み立てる

HANDS-ON 25　クエリを段階的に育てる
  1. 検証用コードを用意する。 samples\ch25_match.cpp を作ります。マッチするはずのコードを先に用意するのが要点です。 
    #include <cstring>
#include <vector>

class Widget {
public:
    void draw() const {}
    void resize(int w, int h) {}
private:
    int  width_ = 0;
    int* data_ = nullptr;
};

void legacy(char* dst, const char* src) {
    strcpy(dst, src);          // ← 目標1
}

void alloc() {
    int* p = new int[10];      // ← 目標2
    delete p;                  // ← 目標3（new[] に delete）
}
  2. Node Matcher だけで数える。 
    clang-query ch25_match.cpp -- -std=c++23
    m callExpr()
m functionDecl()
m cxxRecordDecl()
m varDecl()
m cxxNewExpr()
m cxxDeleteExpr()
    それぞれの件数を記録します。ヘッダの中身が入るので、想像よりずっと多いはずです。
  3. Narrowing で絞る。 
    m functionDecl(hasName("legacy"))
m cxxRecordDecl(hasName("Widget"))
m cxxMethodDecl(isConst())
m varDecl(hasType(isInteger()))
    件数が減っていくことを確認します。
  4. Traversal で移動する。 
    m callExpr(callee(functionDecl()))
m callExpr(callee(functionDecl(hasName("strcpy"))))
m cxxMethodDecl(hasParent(cxxRecordDecl(hasName("Widget"))))
  5. 三分類を意識して読む。 手順4の最後の式について、どこが Node・Narrowing・Traversal かを図25-2 の形式で分解してみてください。日本語に直すと「Widget というクラスを親に持つメンバ関数」です。
  6. 論理演算を試す。 
    m functionDecl(hasAnyName("legacy", "alloc"))
m cxxMethodDecl(unless(isConst()))
m callExpr(callee(functionDecl(anyOf(hasName("strcpy"), hasName("memcpy")))))
  7. ヘッダを除外する。 手順2で件数が多かったのは、標準ライブラリのヘッダが含まれていたからです。 
    m functionDecl(isExpansionInMainFile())
m callExpr(isExpansionInMainFile())
    件数が激減することを確認します。この Matcher は今後ほぼ毎回使います。
  8. 目標3のクエリを組み立てる。 「配列で確保したものを、配列でない delete で解放している」を探します。まず AST を見て、それから条件を足してください。 
    set output dump
m cxxDeleteExpr(isExpansionInMainFile())
    出力を読み、isArrayForm のような属性がどう出ているかを確認してから、 
    set output diag
m cxxDeleteExpr(isExpansionInMainFile(), unless(isArrayForm()))
    を試します。ここで「AST を見てから条件を決める」という第23章の流儀が効いてきます。
  9. 保存する。 完成したクエリを queries\ に、コメント付きで保存します。

この章のまとめ

  • Matcher は3分類。① Node（どの種類のノードか）② Narrowing（その属性を持つか）③ Traversal（別のノードへ移る）。
  • Traversal だけが引数に別の Matcher を取る。 だからクエリは入れ子になる。
  • 典型的な形は Node → Traversal → Node → Narrowing の交互。英語（日本語）として読めるかが正しさの目安。
  • 括弧内のカンマ区切りは AND。anyOf / unless / allOf で論理を組む。
  • 広い Node Matcher から始め、件数を見ながら条件を足す。 一気に完成形を書かない。
  • 「0件」は最も危険な状態。マッチするはずのコードを先に用意しておく。
  • isExpansionInMainFile() はヘッダを除外する常用の Matcher。

次章： 第26章「bind で節点に名前を付ける」では、マッチした木の中の特定のノードに名前を付けます。これがないと、第6部で「どこに警告を出すか」を指定できません。
