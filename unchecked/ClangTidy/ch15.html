第 15 章

プロジェクト全体・差分だけを解析する

clang-tidy 本体は原則1ファイルずつです。数百ファイルのプロジェクトを回すには一括実行の道具が要り、既存コードに新ルールを入れるには「変更した行だけ」を見る道具が要ります。この章で第3部が完結し、Clang-Tidy を実プロジェクトで運用する準備が整います。

15.1 三つの粒度

15.2 run-clang-tidy ── 全体を並列で回す

どこにあるか

これは Python スクリプトです。LLVM のインストール先の bin に入ります。

> dir "C:\Program Files\LLVM\bin\run-clang-tidy*"
run-clang-tidy

実行には Python が必要です。拡張子が付かない形で入ることがあるので、明示的に Python から起動するのが確実です。

> python "C:\Program Files\LLVM\bin\run-clang-tidy" -p out\build\ninja

主なオプション

オプション意味
-p <dir>コンパイルデータベースのあるディレクトリ（必須級）
-j <N>並列数。既定は論理プロセッサ数
-checks=…チェック指定。.clang-tidy があれば不要
-header-filter=…ヘッダフィルタ（第10章）
-export-fixes <file or dir>修正案を書き出す
-fix修正を適用する
-quiet統計行を抑制する
（末尾の位置引数）対象ファイルを絞る正規表現

最後の項目が便利です。DB に載っている全ファイルのうち、パスが正規表現に一致するものだけを回せます。

> python run-clang-tidy -p out\build\ninja -j 8 "TidyLab[\\/]"

並列実行と自動修正の相性

第10章で見たとおり、複数の翻訳単位が同じヘッダを解析します。ここで -fix を素直に使うと、複数のプロセスが同じヘッダを同時に書き換えようとします。そのためのパイプラインが用意されています。

> mkdir fixes
> python run-clang-tidy -p out\build\ninja -j 8 -export-fixes fixes
> clang-apply-replacements fixes

15.3 clang-tidy-diff.py ── 変更した行だけ

どこにあるか

こちらは bin ではなく、共有データのディレクトリに入ります。Windows の LLVM インストールでは次のあたりです。

> dir /s /b "C:\Program Files\LLVM\clang-tidy-diff.py"
C:\Program Files\LLVM\share\clang\clang-tidy-diff.py
見つからないときは

インストール方法やバージョンによって配置は変わります（LLVM 側でも「bin に統一すべきでは」という議論があります）。見つからない場合は、LLVM のソースツリーから clang-tools-extra/clang-tidy/tool/clang-tidy-diff.py を取ってきて、リポジトリの tools\ に置いても構いません。単体の Python スクリプトなので、それで動きます。

使い方

標準入力から unified diff を受け取り、追加・変更された行に対してだけ解析を走らせます。

> git diff -U0 HEAD~1 | python clang-tidy-diff.py -p1 -path out\build\ninja -j 8
オプション意味
-p1diff のパスから先頭 1 階層を取り除く（a/src/foo.cpp → src/foo.cpp）。git diff の出力ならこれ
-path <dir>コンパイルデータベースのディレクトリ。clang-tidy の -p に相当
-j <N>並列数
-checks=…チェック指定
-fix修正を適用する
-p1 と -p を混同しない

clang-tidy 本体の -p は「ビルドディレクトリ」ですが、clang-tidy-diff.py の -p1 は「パスの階層を1つ削る」という patch コマンド由来の意味です。ビルドディレクトリを指定するのは -path のほうです。両者はまったく別物です。

15.4 Windows で動かすときの注意

  • Python が必要。 どちらのスクリプトも Python 製です。python --version で確認してください。
  • パイプはシェル依存。 git diff | python … はコマンドプロンプトでも PowerShell でも動きますが、PowerShell では文字エンコーディングの扱いで差分が壊れることがあります。うまくいかないときは、いったんファイルに落として < で流し込んでください。
  • パスに空白がある。 C:\Program Files\LLVM\... は空白を含みます。必ず引用符で囲みます。
  • コンパイルデータベースが要る。 どちらも -p / -path を前提としています。第14章の Ninja 構成を用意しておいてください。

15.5 【ハンズオン】全体と差分を回す

HANDS-ON 15　一括実行と差分実行
  1. 準備を確認する。 第14章で作った out\build\ninja\compile_commands.json があること、python --version が通ることを確認します。
  2. スクリプトの場所を特定する。 
    dir /s /b "C:\Program Files\LLVM\run-clang-tidy*"
dir /s /b "C:\Program Files\LLVM\clang-tidy-diff.py"
    見つかったパスを控えます。
  3. 全体を回す。 
    python "C:\Program Files\LLVM\bin\run-clang-tidy" -p out\build\ninja -j 4
    clang-tidy を1ファイルずつ実行したときと同じ警告が、全ファイル分まとめて出ることを確認します。
  4. 対象を絞る。 末尾に正規表現を付けて、特定のディレクトリだけを回します。 
    python "C:\Program Files\LLVM\bin\run-clang-tidy" -p out\build\ninja "config_loader"
  5. 修正を書き出す。 
    mkdir fixes
python "C:\Program Files\LLVM\bin\run-clang-tidy" -p out\build\ninja -j 4 -export-fixes fixes
    fixes\ の中に YAML ができることを確認し、中身を1つ開いて第11章で見た形式と同じであることを確認します。
  6. 一括適用する。 作業ツリーがきれいであることを確認してから、 
    clang-apply-replacements fixes
git diff
    差分を読み、ビルドが通ることを確認したら git checkout -- . で戻します。
  7. 差分だけを解析する。 config_loader.cpp に、警告が出る行を1行だけ足してコミットせずに置きます。 
        int* tmp = NULL;   // わざと
    そのうえで、 
    git diff -U0 | python "C:\Program Files\LLVM\share\clang\clang-tidy-diff.py" -p1 -path out\build\ninja
    追加した1行に対してだけ警告が出ることを確認します。ファイル内の他の既存警告が出ないことが観察点です。
  8. -U0 の効果を確かめる。 -U0 を外して同じことを実行し、触っていない周辺行の警告まで出ることを確認します。
  9. 後片付け。 わざと足した行を削除し、fixes\ ディレクトリを削除します。
この章の成果物をスクリプトにしておく

手順3と手順7のコマンドラインは、今後ずっと使います。tools\analyze-all.cmd と tools\analyze-diff.cmd としてリポジトリに置いておくと、チーム全員が同じ手順を踏めますし、そのまま CI の設定に転記できます（第40章）。パスの直書きは避け、LLVM の場所は環境変数で受け取る形にしておくと移植しやすくなります。

第3部の終わりに

Clang-Tidy を「実プロジェクトで動かす」ための道具が揃いました。

  • コマンドラインで直接叩き、引数の問題を切り分けられる（第12章）
  • Visual Studio が何を渡しているかを確認し、速度と設定を制御できる（第13章）
  • CMake の3つの経路と、それぞれの制約を理解している（第14章）
  • プロジェクト全体と、変更行だけを回し分けられる（第15章）

ここまでは 「どう動かすか」 の話でした。第4部では中身に入り、標準チェック群が実際に何を見ているのかをツアーします。そして第5部以降、「自分でチェックを作る」 側へ移ります。

この章のまとめ

  • 解析の粒度は3つ。1ファイル（切り分け）、全体（棚卸し）、差分（日常運用）。
  • run-clang-tidy は Python スクリプトで bin にある。-p でコンパイルデータベース、-j で並列数、末尾の正規表現で対象を絞る。
  • 並列実行時に -fix を直接使うとヘッダの奪い合いで壊れる。-export-fixes → clang-apply-replacements の二段構えにする。
  • clang-tidy-diff.py は share\clang にある。unified diff を標準入力から受け取り、内部で --line-filter を組み立てる。
  • git diff には -U0 を付ける。文脈行を含めると、触っていないコードまで対象になる。
  • -p1（パス階層を削る）と -path（ビルドディレクトリ）は別物。
  • 差分解析があるから、既存コードに 3000 件の警告があっても導入初日から運用を始められる。
