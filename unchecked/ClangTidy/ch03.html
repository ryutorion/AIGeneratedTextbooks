第 3 章

ハンズオン環境を作る

ここから手を動かします。Visual Studio 2026 に必要なコンポーネントを入れ、C++23 を有効にし、本書を通して使うソリューション TidyLab を組み立てます。地味な章ですが、ここで C++23 の指定を「二箇所」に入れる意味を理解しておかないと、第12章以降で必ず詰まります。

3.1 必要なコンポーネント

Visual Studio Installer を開き、次のものが入っているか確認します。

Clang ツールを入れなくても Clang-Tidy は動くことがある

プロパティに「Clang-Tidy を有効にする」項目は表示されるので、コンポーネントを入れ忘れていても設定はできてしまいます。しかし実行時に「clang-tidy が見つからない」となるか、あるいは何も起きずに終わります。警告が0件だったときは、まず本当に走ったのかを疑ってください。 確認方法は第4章で扱います。

MSVC ツールセットのままで構わない

「Windows 用 C++ Clang ツール」を入れても、プロジェクトのコンパイラが Clang に変わるわけではありません。ビルドは従来どおり MSVC で行い、Clang-Tidy は解析のためだけに Clang フロントエンドを使います（第2章の図2-1）。ツールセットを LLVM に切り替える必要はありません。

3.2 C++23 を有効にする ── 設定は「二箇所」ある

ここが本章で最も重要な節です。

Visual Studio でプロジェクトの言語規格を C++23 に設定すると、それは MSVC に対する指定 です。ところが Clang-Tidy は Clang でソースを読みます。Clang には別途 -std=c++23 を伝えなければなりません。この二重構造を最初に押さえておきます。

MSBuild なら自動で伝わることもある

Visual Studio の MSBuild 統合は、プロジェクトの設定から言語規格やインクルードパスを Clang-Tidy にある程度自動で引き継ぎます。うまく動いているうちは追加設定は要りません。しかし C++23 のような新しい規格や、プレビュー扱いのオプションでは引き継ぎが不完全になることがある ため、「C++23 の構文だけパースエラーになる」という症状が出たら図3-2 の右側を疑ってください。切り分け手順は第4章と第12章で扱います。

なぜモジュールを使わないのか

本書では C++23 を使いますが、モジュール（import / export）は使いません。理由は静的解析ツールの都合です。

  • モジュールのビルドには、事前にビルド済みモジュールインターフェイス（BMI）が必要で、しかも BMI はコンパイラごとに互換性がありません。MSVC が作った BMI を Clang は読めません。
  • つまり Clang-Tidy は、モジュールを使ったコードを解析するために Clang 自身でモジュールをビルドし直す 必要があります。ビルドシステムとの連携が一気に複雑になります。
  • ヘッダインクルード方式なら、Clang-Tidy は -I の設定さえ合っていれば単独で AST を作れます。

Clang-Tidy そのものを学ぶことが目的なので、余計な変数を持ち込まない、という判断です。#include ベースで進めます。

3.3 ソリューション TidyLab を作る

本書全体で使う作業場を作ります。構成はシンプルです。

TidyLab\ ├─ TidyLab.sln ├─ .clang-tidy ← 第7章で作成。当面は空 ├─ .gitignore ├─ TidyLab\ ← メインのプロジェクト（コンソールアプリ） │ ├─ TidyLab.vcxproj │ ├─ main.cpp │ ├─ config_loader.h ← 第1章のリスト1-1 │ ├─ config_loader.cpp │ └─ app.ini ← テスト用の設定ファイル └─ samples\ ← 章ごとの小さな検証用ソース └─ ch05_first_run.cpp

3.4 【ハンズオン】TidyLab を組み立てる

HANDS-ON 3　作業場を作り、C++23 でビルドする
  1. コンポーネントを確認する。 Visual Studio Installer を起動し、「変更」から
    • ワークロード：C++ によるデスクトップ開発
    • 個別のコンポーネント：Windows 用 C++ Clang ツール
    の両方にチェックが入っていることを確認します。入っていなければ追加してインストールします。
  2. ソリューションを作る。 「新しいプロジェクトの作成」から コンソール アプリ（C++）を選び、プロジェクト名 TidyLab、ソリューション名も TidyLab で作成します。「ソリューションとプロジェクトを同じディレクトリに配置する」は チェックを外して ください。ソリューション直下に .clang-tidy を置きたいためです。
  3. 題材コードを追加する。 第1章のリスト1-1 を config_loader.h / config_loader.cpp として追加し、main.cpp を次の内容にします。 
    #include "config_loader.h"
#include <print>

int main() {
    ConfigLoader loader("app.ini");
    if (!loader.load()) {
        std::println("load failed");
        return 1;
    }
    for (const auto& e : loader.entries()) {
        std::println("{} = {}", e.name, e.value);
    }
    return 0;
}
  4. テスト用の設定ファイルを置く。 プロジェクトフォルダに app.ini を作り、次を書きます。実行時のカレントディレクトリに置かれるよう、プロパティで「出力ディレクトリにコピー」を設定してもよいですし、手でコピーしても構いません。 
    width=1920
height=1080
title=TidyLab
  5. C++23 を有効にする。 プロジェクトのプロパティを開き、構成プロパティ > C/C++ > 言語 > C++ 言語標準 で C++23 に相当する項目を選びます。ドロップダウンの表記は VS のバージョンによって異なります。
    • 「ISO C++23 標準（プレビュー）(/std:c++23preview)」があればそれを選ぶ
    • なければ「最新の C++ ドラフト標準 (/std:c++latest)」を選ぶ
    すべての構成（Debug / Release、x64 / x86）に対して設定してください。 構成を切り替えたら C++23 が外れていた、というのは定番の事故です。
  6. 警告レベルを上げる。 構成プロパティ > C/C++ > 全般 > 警告レベル を /W4 にします。静的解析はコンパイラ警告の代わりではありません（第1章）。
  7. ビルドして実行する。 Ctrl+F5 で実行し、width = 1920 のような出力が3行出れば成功です。std::println でエラーになる場合は手順5の言語規格設定を確認してください。
  8. 空の .clang-tidy を置く。 ソリューション直下（TidyLab.sln と同じ階層）に、中身が次の1行だけのファイル .clang-tidy を作ります。 
    Checks: '-*'
    中身は第7章で本格的に書きます。いまは「置き場所を確保した」だけです。
ファイル名の先頭がドットで作れないとき

エクスプローラーからは .clang-tidy という名前のファイルを作れないことがあります。その場合は Visual Studio の「新しい項目の追加」でテキストファイルとして .clang-tidy を指定するか、コマンドプロンプトで type nul > .clang-tidy とします。拡張子は付けません。.clang-tidy.txt になっていると一切読まれず、しかもエラーも出ないので注意してください。

3.5 バージョン管理に載せる場合

チームで使うことを見据えるなら、この段階で .gitignore を用意しておきます。ビルド成果物は除外し、.clang-tidy は必ずリポジトリに含めます。設定ファイルを共有することが、Clang-Tidy 運用の前提だからです（第38章）。

# .gitignore
/.vs/
[Bb]in/
[Oo]bj/
[Dd]ebug/
[Rr]elease/
x64/
*.user

# .clang-tidy は除外しない（チームで共有する）

3.6 この時点で確認できること

ここまでで、次の状態になっているはずです。

  • C++23 でビルドが通り、実行できる
  • Clang ツールがインストールされている（ただし、まだ動かしていない）
  • .clang-tidy の置き場所が決まっている（ただし、まだ空）

次章では、インストールした clang-tidy.exe を初めて直接叩きます。目的はバージョンの確認です。本書の中心テーマである Query Based Custom Check は、比較的新しいバージョンでしか使えません。 Visual Studio に同梱されているものがそれを満たしているとは限らないので、先に確かめておく必要があります。

この章のまとめ

  • Clang-Tidy 本体はワークロードではなく、個別コンポーネント「Windows 用 C++ Clang ツール」に含まれる。
  • C++23 の指定は MSVC 向け（/std:c++23preview など）と Clang-Tidy 向け（-std=c++23）の二箇所 に関わる。同じソースを二つのコンパイラが別々に読むため。
  • 本書がモジュールを使わないのは、BMI がコンパイラ間で互換でなく、Clang-Tidy 側で解析用に作り直す必要が生じるため。
  • ソリューション TidyLab を作り、題材コードと空の .clang-tidy を配置した。.clang-tidy はソリューション直下に置き、リポジトリで共有する。

次章： 第4章「同梱 clang-tidy のバージョンを確認する」では、実際に clang-tidy.exe を探して --version を叩きます。本書の主題である Query Based Custom Check が使えるかどうかは、ここで決まります。
