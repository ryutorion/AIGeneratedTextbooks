第 4 章

同梱 clang-tidy のバージョンを確認する

本書の中心テーマである Query Based Custom Check は、比較的新しい LLVM にしか入っていない機能です。Visual Studio に同梱されている clang-tidy がそれを満たしているとは限りません。第6部まで進んでから「そもそも動かなかった」と気づくのは最悪なので、いま確かめます。満たしていなかった場合の差し替え方法まで、この章で用意します。

4.1 なぜ最初にバージョンを確認するのか

Clang-Tidy の機能は LLVM のリリースごとに増減します。特に本書が主題とする Query Based Custom Check は新しい機能で、次のような状況にあります。

LLVM のバージョン.clang-tidy の CustomChecks
21 系まで存在しない。 設定に書いても無視されるか、未知のキーとして扱われる
22 系以降使える。ただし 実験的機能 であり、有効化に --experimental-custom-checks が必要
「実験的」であることの意味

公式ドキュメントは、この機能について「設定の構造は将来変更される可能性がある」「クエリの記述も AST マッチャーライブラリの更新に伴っていつでも変わりうる」と明記しています。本書の第6部で書いたクエリが、将来のバージョンでそのまま動く保証はありません。だからこそ、いま自分が使っているバージョンを正確に把握しておくことが重要です。 「動かない」ときに、書き方が悪いのかバージョンが違うのかを切り分けられるようにしておきます。

加えて、バージョンを確認する習慣そのものに価値があります。標準チェックも版によって追加・削除・改名されるため、Web で見つけた記事のとおりに書いても動かないことが日常的に起こります。

4.2 clang-tidy.exe を探す

Visual Studio に同梱された Clang ツール群は、Visual Studio のインストールディレクトリ配下に置かれます。

最も確実なのは 「開発者コマンドプロンプト（Developer Command Prompt for VS 2026）」 を使う方法です。スタートメニューから起動すると、MSVC や LLVM ツールにパスが通った状態になります。

> where clang-tidy
C:\Program Files\Microsoft Visual Studio\2026\Community\VC\Tools\Llvm\x64\bin\clang-tidy.exe

パスが通っていない場合は、図4-1 の dir /s /b で探すか、フルパスを直接指定します。

4.3 バージョンと機能を確かめる

ステップ1：バージョン

> clang-tidy --version
LLVM (http://llvm.org/):
  LLVM version 22.1.0
  Optimized build.

この LLVM version の数字が判定の第一材料です。21 以下なら、Query Based Custom Check はまず使えません。

ステップ2：機能そのものの有無

バージョン番号だけで決めつけず、フラグの実在を確認するのが確実です。実験的機能はバージョン間で扱いが変わりうるためです。

> clang-tidy --help | findstr experimental-custom-checks
  --experimental-custom-checks   - Enable experimental custom checks.

この行が出れば使えます。何も出なければ、そのバイナリでは第6部の内容は動きません。

ステップ3：チェック一覧を眺める

ついでに、そのバイナリがどんなチェックを持っているかも見ておきます。

> clang-tidy --list-checks --checks=*
Enabled checks:
    abseil-cleanup-ctad
    ...
    bugprone-use-after-move
    ...
    modernize-use-nullptr
    ...

> clang-tidy --list-checks --checks=* | find /c /v ""
(有効なチェックの総数が出る)

数百件並ぶはずです。第4部でこの中身をツアーします。

4.4 判定と対処

3つのステップの結果から、次のように分岐します。

LLVM を別途インストールする

LLVM は Visual Studio とは独立してインストールできます。既存の環境を壊しません。

> winget install LLVM.LLVM
(または llvm.org のリリースページから Windows 用インストーラを取得)

インストール後、新しい方のバージョンを確認します。

> "C:\Program Files\LLVM\bin\clang-tidy.exe" --version
LLVM version 22.1.0
PATH を書き換えないほうがよい

システムの PATH で新しい LLVM を優先させると、Visual Studio の他の機能や別プロジェクトのビルドに影響が出ることがあります。PATH は触らず、プロジェクトのプロパティで明示的に指定する のが安全です。プロジェクトごとに使う clang-tidy を変えられるという利点もあります。

4.5 Visual Studio がどの clang-tidy を呼ぶか

差し替えの仕組みを理解しておきます。Visual Studio は解析を実行するとき、次の順で clang-tidy を決めます。

一番下のケースが厄介です。解析が走らなかったときと、警告が本当に0件だったときは、見た目が同じ になります。第5章では、まず意図的に警告が出る状態を作って「走っていること」を確認する手順を踏みます。

4.6 【ハンズオン】自分の環境を確定させる

HANDS-ON 4　バージョンを調べ、必要なら差し替える
  1. 開発者コマンドプロンプトを開く。 スタートメニューから「Developer Command Prompt for VS 2026」を起動します。
  2. 実行ファイルの場所を確認する。 
    where clang-tidy
    見つからなければ、図4-1 の dir /s /b で探します。
  3. バージョンを記録する。 
    clang-tidy --version
    出た数字をメモしておきます。本書を読み進める間、この数字を参照することになります。
  4. カスタムチェックの可否を判定する。 
    clang-tidy --help | findstr experimental-custom-checks
    • 出力あり → 手順7へ進みます。
    • 出力なし → 手順5へ。
  5. 新しい LLVM を入れる。 
    winget install LLVM.LLVM
    完了後、"C:\Program Files\LLVM\bin\clang-tidy.exe" --version で 22 以上になっていることと、手順4のコマンドで --experimental-custom-checks が出ることを確認します。
  6. Visual Studio に差し替えを教える。 TidyLab プロジェクトのプロパティを開き、 構成プロパティ > コード分析 > Clang-Tidy > Clang-Tidy ツール ディレクトリ に、新しい方の bin ディレクトリ（実行ファイル名は含めない）を入力します。 
    C:\Program Files\LLVM\bin
    ここでもすべての構成に対して設定してください。
  7. チェックの総数を数える。 
    clang-tidy --list-checks --checks=* | find /c /v ""
    数百件あるはずです。この数はバージョンによって変わります。
  8. カスタムチェックのモジュールが存在するか確認する（任意）。 --experimental-custom-checks を付けたうえで、空のカスタムチェック定義を読ませてもエラーにならないことを見ておくと安心です。実際の記述は第30章で行います。

4.7 バージョンを固定する意味

ここで確定させたバージョンは、チーム全体で揃えるべきものです。理由は単純で、バージョンが違うと警告の件数が変わる からです。

  • 新しい版で追加されたチェックは、古い版では単に無視されます（存在しないチェック名を指定しても、既定ではエラーになりません）。
  • 逆に、古い版で有効だったチェックが改名・削除されていることもあります。
  • 同じチェックでも、版が上がると検出精度が変わって件数が増減します。

「自分の環境では通るのに CI で落ちる」の原因の多くはこれです。第40章で CI を組むときに、使用する LLVM のバージョンを明示的に固定する話をします。いまの段階では、自分が使っているバージョンをメモしておく だけで十分です。

存在しないチェック名を書いてしまったら

既定では黙って無視されます。タイプミスに気づけないということです。--warnings-as-errors とは別に、設定した名前が本当に有効になっているかは --list-checks で確認するのが確実です（第7章）。

この章のまとめ

  • Query Based Custom Check（.clang-tidy の CustomChecks）は LLVM 22 系以降の機能で、--experimental-custom-checks による有効化が必要。21 系までには存在しない。
  • 実験的機能であり、設定の構造もクエリの書き方も将来変わりうる。だから使用中のバージョンを把握しておく。
  • 同梱 clang-tidy は VC\Tools\Llvm\x64\bin にある。バージョンが足りなければ LLVM を別途入れ、Clang-Tidy ツール ディレクトリ で差し替える。PATH は触らない。
  • Visual Studio は「ツール ディレクトリの指定 → 同梱版」の順に実行ファイルを探す。どちらも無ければ何も起こらず、警告0件に見えてしまう。
  • バージョン差は警告件数の差に直結する。チームでは版を揃える。
