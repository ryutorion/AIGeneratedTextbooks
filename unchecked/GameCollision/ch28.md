# 第 28 章　GJK / EPA の 3D 化

> **この章のゴール**
> GJK と EPA を 3 次元へ拡張する。**アルゴリズムの骨格は変わらない。** サポート写像も、ミンコフスキー差の見方も、収束判定も、`precise` で守る箇所も、第 IV 部のままである。
>
> 変わるのは二つ。**単体が四面体になり、場合分けが増えること**と、**EPA のポリトープが面のリストになり、ホール境界の再構成が必要になること**である。
>
> そして検証には新しい手法を使う。**2D の実装を平面に埋め込む。** 3D の実装に平面上の入力を与えれば、答えは 2D の実装と一致しなければならない。すでに検証済みの実装が、そのままリファレンスになる。

---

## 28.1 サポート写像の 3D 版

### 骨格は同じ

第 19 章の設計がそのまま通用する。`Vec2` を `Vec3` に置き換えるだけである。

```cpp
// collision/narrow/support3.h
#pragma once

#include "collision/shapes/shapes3.h"
#include "collision/shapes/triangle3.h"

namespace collision {

[[nodiscard]] constexpr Vec3 support_point(Vec3 p, Vec3) noexcept { return p; }

[[nodiscard]] inline Vec3 support_point(const Sphere& s, Vec3 d) noexcept {
    return s.center + normalize_or(d, Vec3{1,0,0}) * s.radius;
}

[[nodiscard]] constexpr Vec3 support_point(const Aabb3& b, Vec3 d) noexcept {
    return Vec3{
        (d.x >= 0.0f) ? b.max.x : b.min.x,
        (d.y >= 0.0f) ? b.max.y : b.min.y,
        (d.z >= 0.0f) ? b.max.z : b.min.z,
    };
}

[[nodiscard]] inline Vec3 support_point(const Obb3& o, Vec3 d) noexcept {
    Vec3 p = o.center;
    const float e[3] = {o.extents.x, o.extents.y, o.extents.z};
    for (int i = 0; i < 3; ++i) {
        p += o.axes.col[i] * ((dot(o.axes.col[i], d) >= 0.0f) ? e[i] : -e[i]);
    }
    return p;
}

[[nodiscard]] inline Vec3 support_point(const Capsule3& c, Vec3 d) noexcept {
    const Vec3 core = (dot(c.a, d) >= dot(c.b, d)) ? c.a : c.b;
    return core + normalize_or(d, Vec3{1,0,0}) * c.radius;
}

[[nodiscard]] inline Vec3 support_point(const Triangle3& t, Vec3 d) noexcept {
    const float da = dot(t.a, d), db = dot(t.b, d), dc = dot(t.c, d);
    if (da >= db && da >= dc) return t.a;
    return (db >= dc) ? t.b : t.c;
}

template <class S>
concept SupportShape3 = requires(const S& s, Vec3 d) {
    { support_point(s, d) } -> std::same_as<Vec3>;
};

} // namespace collision
```

**AABB は分岐 3 回、OBB は内積 3 回で済む。** 8 頂点を列挙する必要はない。第 19.2 節で述べた節約が、次元が上がるほど効いてくる（2D では 4 頂点、3D では 8 頂点を回避できる）。

**三角形もサポート写像を持てる。** したがって、三角形と任意の凸形状の判定が GJK でできる。第 27 章では球とカプセルについて専用実装を書いたが、凸多面体と三角形なら GJK が要る。

### 新しく追加できる形状

3D では、2D にない形状が使えるようになる。

```cpp
// 円柱（Y 軸方向）
struct Cylinder {
    Vec3  center{};
    float half_height{};
    float radius{};
};

[[nodiscard]] inline Vec3 support_point(const Cylinder& c, Vec3 d) noexcept {
    // Y 方向は半分の高さ、XZ 平面内は半径
    const Vec3 radial{d.x, 0.0f, d.z};
    const Vec3 r = normalize_or(radial, Vec3{1,0,0}) * c.radius;
    const float y = (d.y >= 0.0f) ? c.half_height : -c.half_height;
    return c.center + r + Vec3{0.0f, y, 0.0f};
}

// 凸多面体（頂点列だけ持てばよい）
struct ConvexHull3 {
    std::vector<Vec3> vertex;
};

[[nodiscard]] inline Vec3 support_point(const ConvexHull3& h, Vec3 d) noexcept {
    Vec3  best = h.vertex[0];
    float bd   = dot(best, d);
    for (std::size_t i = 1; i < h.vertex.size(); ++i) {
        if (const float s = dot(h.vertex[i], d); s > bd) { bd = s; best = h.vertex[i]; }
    }
    return best;
}
```

**`ConvexHull3` は頂点列だけを持つ。** 面も辺も要らない。SAT なら面法線と辺の情報が必須だが（第 26 章）、GJK はサポート写像しか使わないからである。

**これが GJK の実用上の最大の利点かもしれない。** 任意の凸多面体を、頂点を並べるだけで扱えるようになる。面の接続情報を構築する必要がない。

`radial` がゼロベクトルになるのは `d` が Y 軸に平行なときで、そのとき `normalize_or` のフォールバックが働く。円柱の上面・下面のどこか一点が返るが、それで正しい（上面全体が同じ内積を持つので、どれでもよい ― 第 19.1 節の「曖昧さ」）。

## 28.2 四面体シンプレックス

### 何が増えるのか

2D の GJK では、単体は点・線分・三角形の三段階だった。3D では**四面体**が加わる。

| 単体 | 2D | 3D |
|---|---|---|
| 0 次元 | 点 | 点 |
| 1 次元 | 線分 | 線分 |
| 2 次元 | **三角形（原点を含めば終了）** | 三角形 |
| 3 次元 | ― | **四面体（原点を含めば終了）** |

**三角形の扱いが変わる**点に注意してほしい。2D では三角形が原点を含めば終了だったが、3D では三角形は平面図形なので、原点を含むことは（測度ゼロの偶然を除いて）ない。三角形は「次に四面体へ育てる途中段階」になる。

### 線分の場合

2D では `perpendicular` と符号調整で済んでいた（第 20.3 節）。3D では**ベクトル三重積**を使う（第 24.2 節）。

```cpp
// collision/narrow/gjk3.h
namespace detail {

// 線分の場合。原点に近い部分を残し、次の探索方向を返す。
[[nodiscard]] inline bool
simplex3_line(Simplex3& s, Vec3& d) noexcept {
    const Vec3 a = s.point[1].diff;   // 最新
    const Vec3 b = s.point[0].diff;
    const Vec3 ab = b - a;
    const Vec3 ao = -a;

    if (dot(ab, ao) > 0.0f) {
        // AB に垂直で、AB を含む平面内で原点を向く方向
        d = triple_product(ab, ao, ab);     // (ab × ao) × ab
        if (length_squared(d) < min_length2) {
            // 原点が直線 AB 上にある。垂直な方向を任意に選ぶ
            Vec3 t1{}, t2{};
            build_basis(normalize_or(ab, Vec3{1,0,0}), t1, t2);
            d = t1;
        }
    } else {
        s.point[0] = s.point[1];
        s.count = 1;
        d = ao;
    }
    return false;
}
```

**退化ケースが 2D より厄介である。** 原点が直線 `AB` 上にあると、`triple_product` がゼロベクトルになる。2D では `perpendicular` が常に有効な方向を返したので、この問題はなかった。

第 24.4 節の `build_basis` が、ここで役立つ。**「ある向きに垂直な任意の方向」が必要な場面**は、3D では頻繁に現れる。

### 三角形の場合

三角形の法線を計算し、原点がどちら側にあるかで進む方向を決める。

```cpp
[[nodiscard]] inline bool
simplex3_triangle(Simplex3& s, Vec3& d) noexcept {
    const Vec3 a = s.point[2].diff;   // 最新
    const Vec3 b = s.point[1].diff;
    const Vec3 c = s.point[0].diff;

    const Vec3 ao  = -a;
    const Vec3 ab  = b - a;
    const Vec3 ac  = c - a;
    const Vec3 abc = cross(ab, ac);   // 三角形の法線

    // 辺 AC の外側か（abc × ac は AC に垂直で、三角形の外を向く）
    if (dot(cross(abc, ac), ao) > 0.0f) {
        if (dot(ac, ao) > 0.0f) {
            s.point[1] = s.point[2];      // [C, A] にする
            s.count = 2;
            d = triple_product(ac, ao, ac);
            return false;
        }
        s.point[0] = s.point[1];          // [B, A] にする
        s.point[1] = s.point[2];
        s.count = 2;
        return simplex3_line(s, d);
    }

    // 辺 AB の外側か
    if (dot(cross(ab, abc), ao) > 0.0f) {
        s.point[0] = s.point[1];
        s.point[1] = s.point[2];
        s.count = 2;
        return simplex3_line(s, d);
    }

    // 三角形の内部（を平面に射影した領域）にある。法線の側で進む
    if (dot(abc, ao) > 0.0f) {
        d = abc;                          // 法線側
    } else {
        std::swap(s.point[0], s.point[1]); // 巻き方向を反転しておく
        d = -abc;
    }
    return false;
}
```

**最後の `std::swap` が重要である。** 原点が法線の裏側にあるとき、探索方向を反転するだけでなく、**頂点の順序も入れ替える**。こうしておくと、次に四面体になったときの巻き方向が一貫し、場合分けが単純になる。

### 四面体の場合

四面体の 4 面のうち、`A`（最新の点）に接する 3 面について、原点がその外側にあるかを調べる。

```cpp
[[nodiscard]] inline bool
simplex3_tetrahedron(Simplex3& s, Vec3& d) noexcept {
    const Vec3 a = s.point[3].diff;   // 最新
    const Vec3 b = s.point[2].diff;
    const Vec3 c = s.point[1].diff;
    const Vec3 e = s.point[0].diff;

    const Vec3 ao = -a;
    const Vec3 abc = cross(b - a, c - a);
    const Vec3 acd = cross(c - a, e - a);
    const Vec3 adb = cross(e - a, b - a);

    // 面 ABC の外側なら、D を捨てて三角形 [C, B, A] にする
    if (dot(abc, ao) > 0.0f) {
        s.point[0] = s.point[1];      // C
        s.point[1] = s.point[2];      // B
        s.point[2] = s.point[3];      // A
        s.count = 3;
        return simplex3_triangle(s, d);
    }
    // 面 ACD の外側なら、B を捨てて [D, C, A]
    // point[0]=D と point[1]=C はそのまま。point[2] に A を持ってくる
    if (dot(acd, ao) > 0.0f) {
        s.point[2] = s.point[3];      // A
        s.count = 3;
        return simplex3_triangle(s, d);
    }
    // 面 ADB の外側なら、C を捨てて [B, D, A]
    if (dot(adb, ao) > 0.0f) {
        s.point[1] = s.point[0];      // D
        s.point[0] = s.point[2];      // B
        s.point[2] = s.point[3];      // A
        s.count = 3;
        return simplex3_triangle(s, d);
    }

    // どの面の外側でもない → 原点は四面体の内部。交差している
    return true;
}
```

**面 `BCD` を調べなくてよい理由は、2D で辺 `BC` を調べなかったのと同じである**（第 20.3 節）。`B`, `C`, `D` は前の反復で残された点であり、その時点で「原点は `BCD` の外側にない」と判定されている。

**「最新の点 `A` を基準に考える」という規約が、次元が上がっても効いている。** 4 面のうち 3 面だけで済む。

### 本体

本体は 2D 版（第 20.4 節）とほとんど同じである。

```cpp
[[nodiscard]] inline bool handle_simplex3(Simplex3& s, Vec3& d) noexcept {
    switch (s.count) {
    case 2:  return simplex3_line(s, d);
    case 3:  return simplex3_triangle(s, d);
    case 4:  return simplex3_tetrahedron(s, d);
    default: d = -s.point[0].diff; return false;
    }
}

} // namespace detail

template <SupportShape3 A, SupportShape3 B>
[[nodiscard]] GjkResult3 gjk3(const A& a, const B& b) noexcept {
    Vec3 d = support_point(b, Vec3{1,0,0}) - support_point(a, Vec3{-1,0,0});
    if (length_squared(d) < min_length2) d = Vec3{1,0,0};

    Simplex3 s{};
    s.push(support_diff3(a, b, d));
    d = -s.point[0].diff;

    for (int iter = 0; iter < gjk_max_iterations; ++iter) {
        if (length_squared(d) < min_length2) {
            return GjkResult3{.status = GjkStatus::intersecting, .simplex = s,
                              .iterations = iter};
        }
        const MinkowskiPoint3 p = support_diff3(a, b, d);

        if (detail::is_separating3(p.diff, d)) {
            return GjkResult3{.status = GjkStatus::separated, .simplex = s,
                              .iterations = iter};
        }
        if (detail::no_progress3(s, p.diff)) {
            return GjkResult3{.status = GjkStatus::separated, .simplex = s,
                              .iterations = iter};
        }
        s.push(p);

        if (detail::handle_simplex3(s, d)) {
            return GjkResult3{.status = GjkStatus::intersecting, .simplex = s,
                              .iterations = iter};
        }
    }
    return GjkResult3{.status = GjkStatus::not_converged, .simplex = s,
                      .iterations = gjk_max_iterations};
}
```

**`is_separating3` と `no_progress3` は、第 20.6 節と同じく `precise` で守る。** 判断基準（第 4.6 節）も同じである。反復あたり数回しか呼ばれず、判定を誤ると制御フローが壊れる。

**単体の最大点数が 3 から 4 に増えただけで、上位の構造は変わっていない。** 三つの終了状態、反復上限、重複検出。第 20 章で確立した骨格がそのまま使える。

## 28.3 EPA の 3D 化

### ポリトープが面のリストになる

2D の EPA では、ポリトープは「反時計回りに並んだ頂点列」だった。原点に最も近い**辺**を探し、そこに頂点を挿入した（第 22 章）。

3D では、ポリトープは**多面体**である。原点に最も近い**面**（三角形）を探し、そこにサポート点を追加する。

**単純な頂点列では表せない。** 面のリストとして管理する必要がある。

```cpp
// collision/narrow/epa3.h
#pragma once

#include "collision/narrow/gjk3.h"

namespace collision {

inline constexpr std::size_t epa3_max_vertices = 64;
inline constexpr std::size_t epa3_max_faces    = 128;

struct EpaFace {
    std::uint32_t v[3]{};      // 頂点の添字（外向きに反時計回り）
    Vec3          normal{};    // 外向き単位法線
    float         distance{};  // 原点から面までの距離
};

struct Polytope3 {
    std::array<MinkowskiPoint3, epa3_max_vertices> vertex{};
    std::array<EpaFace, epa3_max_faces>            face{};
    std::uint32_t vertex_count{};
    std::uint32_t face_count{};
};

} // namespace collision
```

### 面の追加と法線の向き

```cpp
namespace detail {

// 面を追加する。原点が内側になるよう、必要なら頂点順序を反転する。
inline bool add_face(Polytope3& p, std::uint32_t i0,
                     std::uint32_t i1, std::uint32_t i2) noexcept {
    if (p.face_count >= epa3_max_faces) return false;

    const Vec3 a = p.vertex[i0].diff;
    const Vec3 b = p.vertex[i1].diff;
    const Vec3 c = p.vertex[i2].diff;

    const auto n = try_normalize(cross(b - a, c - a));
    if (!n) return false;              // 退化した面（面積ゼロ）は追加しない

    float dist = dot(*n, a);
    Vec3  nn   = *n;

    // 原点が面の裏側にあるなら、法線を反転して頂点順序も入れ替える
    if (dist < 0.0f) {
        nn   = -nn;
        dist = -dist;
        std::swap(i1, i2);
    }

    p.face[p.face_count++] = EpaFace{
        .v = {i0, i1, i2}, .normal = nn, .distance = dist,
    };
    return true;
}

} // namespace detail
```

**原点が必ず内側になるように向きを揃えている。** GJK が返した四面体は原点を含むので、この正規化は常に成功する。第 22.2 節で 2D のポリトープを反時計回りに揃えたのと、同じ役割である。

### ホール境界の再構成

**ここが 3D 特有の難所である。**

新しいサポート点 `p` を追加するとき、`p` から見える面（`dot(face.normal, p − a) > 0`）をすべて削除する。削除された面の集まりは、多面体に「穴」を開ける。

**その穴の境界（ホール境界）を求め、`p` と結んで新しい面を張る。**

穴の境界を求める方法は単純である。**削除される面の辺をすべて集め、二回現れた辺を消す。** 一回しか現れない辺が、穴の輪郭になる。

```cpp
namespace detail {

struct Edge { std::uint32_t a, b; };

// 辺リストに追加する。逆向きの同じ辺が既にあれば、両方を消す。
inline void add_unique_edge(std::vector<Edge>& edges,
                            std::uint32_t a, std::uint32_t b) {
    for (std::size_t i = 0; i < edges.size(); ++i) {
        // 逆向きの辺が既にある ＝ 内部の辺なので、境界ではない
        if (edges[i].a == b && edges[i].b == a) {
            edges.erase(edges.begin() + static_cast<std::ptrdiff_t>(i));
            return;
        }
    }
    edges.push_back(Edge{a, b});
}

// p から見える面をすべて削除し、ホール境界を p と結んで塞ぐ。
[[nodiscard]] inline bool
expand_polytope(Polytope3& poly, const MinkowskiPoint3& p,
                std::vector<Edge>& scratch) {
    if (poly.vertex_count >= epa3_max_vertices) return false;

    const std::uint32_t new_index = poly.vertex_count;
    poly.vertex[poly.vertex_count++] = p;

    scratch.clear();

    // 見える面を削除しつつ、その辺を集める
    for (std::uint32_t i = 0; i < poly.face_count; ) {
        const EpaFace& f = poly.face[i];
        const Vec3 a = poly.vertex[f.v[0]].diff;

        if (dot(f.normal, p.diff - a) > 0.0f) {
            add_unique_edge(scratch, f.v[0], f.v[1]);
            add_unique_edge(scratch, f.v[1], f.v[2]);
            add_unique_edge(scratch, f.v[2], f.v[0]);
            poly.face[i] = poly.face[--poly.face_count];   // 末尾と入れ替えて削除
        } else {
            ++i;
        }
    }

    if (scratch.empty()) return false;   // 見える面がなかった（数値的な事故）

    // ホール境界を新しい頂点と結ぶ
    for (const Edge& e : scratch) {
        if (!add_face(poly, e.a, e.b, new_index)) return false;
    }
    return true;
}

} // namespace detail
```

**`add_unique_edge` の「逆向きなら消す」という処理が肝心である。**

削除される面が二つ隣接していれば、その共有辺は片方から `(a, b)`、もう片方から `(b, a)` の向きで現れる。両方が削除されるなら、その辺は穴の内部なので境界ではない。**逆向きのペアを消せば、境界だけが残る。**

面の向きを揃えてある（外向きに反時計回り）からこそ、この判定が成立する。**28.3 節の冒頭で向きを正規化したのは、このためである。**

`poly.face[i] = poly.face[--poly.face_count]` という削除は、**末尾の要素を持ってくる**方式である。順序が保たれないが、面の順序に意味はないので問題ない。`std::vector::erase` より速い。

### 本体

```cpp
template <SupportShape3 A, SupportShape3 B>
[[nodiscard]] std::optional<Epa3Result>
epa3(const A& a, const B& b, const Simplex3& simplex) {
    if (simplex.count < 4) return std::nullopt;   // 四面体が要る

    Polytope3 poly{};
    for (std::uint32_t i = 0; i < 4; ++i) poly.vertex[poly.vertex_count++] = simplex.point[i];

    // 四面体の 4 面を張る
    if (!detail::add_face(poly, 0, 1, 2)) return std::nullopt;
    if (!detail::add_face(poly, 0, 1, 3)) return std::nullopt;
    if (!detail::add_face(poly, 0, 2, 3)) return std::nullopt;
    if (!detail::add_face(poly, 1, 2, 3)) return std::nullopt;

    std::vector<detail::Edge> scratch;
    scratch.reserve(32);

    detail::EpaFace best{};
    for (int iter = 0; iter < epa_max_iterations; ++iter) {
        // 原点に最も近い面を探す
        std::uint32_t bi = 0;
        float bd = std::numeric_limits<float>::infinity();
        for (std::uint32_t i = 0; i < poly.face_count; ++i) {
            if (poly.face[i].distance < bd) { bd = poly.face[i].distance; bi = i; }
        }
        if (poly.face_count == 0) return std::nullopt;
        best = poly.face[bi];

        const MinkowskiPoint3 p = support_diff3(a, b, best.normal);

        if (detail::epa_converged(dot(p.diff, best.normal), best.distance)) {
            return detail::build_result3(poly, best, iter, true);
        }
        if (!detail::expand_polytope(poly, p, scratch)) {
            return detail::build_result3(poly, best, iter, false);
        }
    }
    return detail::build_result3(poly, best, epa_max_iterations, false);
}
```

**収束判定 `epa_converged` は第 22.3 節のものをそのまま使う。** 「本書で最も `/fp:fast` に弱い箇所」という性質も同じである。桁落ちの構造が次元に依存しないからである。

接触点の復元も、第 22.4 節と同じ重心座標による方法を使う。線分が三角形になるので、重みが 2 つから 3 つに増える。

**`std::vector<Edge> scratch` を使っている。** 判定のホットパスで確保が走るのは避けたいので、呼び出し側で使い回すか、固定長配列にすべきである。ここでは説明を簡潔にするため `vector` を使い、`reserve` で初回以降の確保を防いでいる。実用では `static_vector` 相当を用意する。

### 3D のスイープ

第 23 章の GJK スイープも、次元を上げるだけで動く。

```cpp
// collision/narrow/gjk_sweep3.h

template <SupportShape3 A, SupportShape3 B>
[[nodiscard]] std::optional<ToiResult>
sweep_gjk3(const A& a, Vec3 delta, const B& b,
           float target_distance = contact_slop) noexcept {
    const float speed = length(delta);
    if (speed < min_length) {
        return (gjk_distance3(a, b).distance <= target_distance)
            ? std::optional{ToiResult{.t = 0.0f}} : std::nullopt;
    }

    float t = 0.0f;
    for (int iter = 0; iter < 32; ++iter) {
        const Transform3 xf{.position = delta * t, .rotation = Mat3{}};
        const auto moved = transformed3(a, xf);

        const float d = gjk_distance3(moved, b).distance;
        if (d <= target_distance) {
            return ToiResult{.t = t, .converged = true, .iterations = iter};
        }
        const float advance = (d - target_distance) / speed;
        if (!can_advance(advance)) {                // 第 18.5 節の precise 判定
            return ToiResult{.t = t, .converged = false, .iterations = iter};
        }
        t += advance;
        if (t >= 1.0f) return std::nullopt;
    }
    return ToiResult{.t = t, .converged = false, .iterations = 32};
}
```

**第 23.2 節のコードと、`Vec2` が `Vec3` になった以外は同一である。** 保守的前進の論法は次元に依存しない。距離関数さえあれば動く。

`can_advance`（第 18.5 節）も、`Transform3` の `Mat3{}`（単位回転）も、そのまま使える。

### 3D で GJK が有利になる境界

26.5 節で「凸多面体の面数が増えると SAT の軸数が急増する」と述べた。実測での目安を出しておく。

| 形状ペア | SAT の軸数 | GJK の平均反復 | 有利なのは |
|---|---|---|---|
| 箱 vs 箱 | 15 | 5〜7 | **SAT** |
| 箱 vs 四面体 | 3+4 + 3×6 = 25 | 5〜7 | SAT（やや） |
| 十二面体 vs 十二面体 | 6+6 + 15×15 = 237 | 6〜8 | **GJK** |
| 球が絡む任意のペア | ― | 4〜6 | **GJK**（SAT 不可） |
| 円柱・カプセル | ― | 5〜8 | **GJK**（SAT 不可） |

**曲面を持つ形状では SAT が使えない。** これが 3D で GJK の価値が高まる最大の理由である。

3D のゲームで使う形状は、球・カプセル・箱・凸多面体の組み合わせであることが多い。**球とカプセルが入る時点で、GJK が必要になる。**

一方、箱どうしは頻出するので専用の SAT を持つ価値がある。第 23 章の実務パイプラインで述べた「専用実装があるペアは専用を使う」という方針が、3D でも同じように適用される。

### 3D 特有の退化ケース

2D の GJK では、退化ケースは「単体が潰れる」ことだけだった。3D では二段階ある。

| 退化 | 状況 | 対処 |
|---|---|---|
| 単体が線分に潰れる | 3 点が一直線上 | `triple_product` がゼロ → `build_basis` で任意の垂直方向 |
| 単体が三角形に潰れる | 4 点が同一平面上 | 四面体の体積がゼロ → 面法線が定まらない |
| EPA の面が潰れる | 3 頂点が一直線上 | `add_face` が `try_normalize` で弾く |

**二番目が 3D 固有の厄介さである。** 4 点が同一平面上にあると、四面体の体積がゼロになり、`simplex3_tetrahedron` の 3 つの面法線のうちいずれかがゼロベクトルになりうる。

この状況は、**平たい形状どうし**（薄い板と薄い板）で起きやすい。28.4 節の「平面埋め込み」テストで厚みをゼロにすると、まさにこれを踏む。

対処は、体積を検査して十分な厚みがある場合だけ四面体として扱うことである。

```cpp
// 四面体の体積が十分か検査する（同一平面上に近ければ偽）
[[nodiscard]] inline bool is_valid_tetrahedron(const Simplex3& s) noexcept {
    if (s.count < 4) return false;
    const float v = scalar_triple(
        s.point[1].diff - s.point[0].diff,
        s.point[2].diff - s.point[0].diff,
        s.point[3].diff - s.point[0].diff);
    return std::fabs(v) > min_length2 * min_length;   // 体積の次元
}
```

**閾値の次元に注意してほしい。** 体積は長さの三乗なので、`min_length2 * min_length`（＝ `min_length³`）と比べる。第 9.3 節や第 25.2 節では次元の合わない比較を妥協として受け入れたが、ここでは合わせられる。

EPA が `simplex.count < 4` で `nullopt` を返すのは第 28.3 節のとおりだが、**「4 点あるが同一平面上」という状態も弾く必要がある**。`is_valid_tetrahedron` をその判定に使う。

弾いた場合、呼び出し側は「交差しているが深度が求まらない」という状態になる。第 7.5 節の `CollisionError::degenerate` を返し、押し戻しは行わない（あるいは前フレームの法線を再利用する）。**すり抜けよりは、一時的に応答しないほうがましである。**

## 28.4 テスト：2D 実装を平面に埋め込む

### 手法

**3D の入力を XY 平面上に限定すれば、問題は 2D と等価になる。**

- 2D の点 `(x, y)` を、3D の点 `(x, y, 0)` に対応させる
- 2D の凸多角形を、3D では「厚みゼロの多角形」として扱う

厚みゼロは退化しているので、**わずかな厚みを持たせる**ほうが安全である。Z 方向に薄い柱にすれば、XY 平面での挙動は 2D と一致する。

**すでに徹底的に検証した 2D の実装が、そのままリファレンスになる。** 第 11.6 節で導入したリファレンス比較の、最も強力な適用例である。

### 交差判定の照合

```cpp
// test_gjk3.cpp
TEST_CLASS(Gjk3VsGjk2) {
public:
    // 2D の凸多角形を、Z 方向に厚みのある柱にする
    [[nodiscard]] static collision::ConvexHull3
    extrude(const collision::ConvexPolygon& p, float half_thickness) {
        collision::ConvexHull3 h;
        h.vertex.reserve(p.count * 2);
        for (std::uint32_t i = 0; i < p.count; ++i) {
            h.vertex.push_back(Vec3{p.vertex[i].x, p.vertex[i].y, -half_thickness});
            h.vertex.push_back(Vec3{p.vertex[i].x, p.vertex[i].y,  half_thickness});
        }
        return h;
    }

    TEST_METHOD(平面に埋め込んだ入力で2D実装と一致すること) {
        Rng rng(2200);
        int mismatch = 0, total = 0, hits = 0;

        for (int i = 0; i < 50000; ++i) {
            const auto a2 = transformed_poly(random_convex_polygon_checked(rng, 3 + (i % 6)),
                {rng.uniform(-1.5f, 1.5f), rng.uniform(-1.5f, 1.5f)}, rng.uniform(0.0f, 6.28f));
            const auto b2 = transformed_poly(random_convex_polygon_checked(rng, 3 + (i % 6)),
                {rng.uniform(-1.5f, 1.5f), rng.uniform(-1.5f, 1.5f)}, rng.uniform(0.0f, 6.28f));

            // 同じ Z 範囲に置くので、Z 方向では必ず重なる
            const auto a3 = extrude(a2, 1.0f);
            const auto b3 = extrude(b2, 1.0f);

            const bool by2d = collision::overlaps_gjk(a2, b2);
            const bool by3d = (collision::gjk3(a3, b3).status
                               == collision::GjkStatus::intersecting);

            ++total;
            if (by2d) ++hits;
            if (by2d != by3d) ++mismatch;
        }

        Logger::WriteMessage(std::format(
            "3D GJK vs 2D GJK（平面埋め込み）: 不一致 {} / {}, 交差 {}\n",
            mismatch, total, hits).c_str());
        Assert::IsTrue(mismatch * 10000 < total, L"不一致が 0.01% を超えている");
        Assert::IsTrue(hits > total / 10, L"交差した事例が少なすぎる");
    }
};
```

**Z 方向に必ず重なるようにしている**のが要点である。両方を同じ Z 範囲（`-1` から `1`）に置けば、Z 軸での分離は起こらない。したがって交差の有無は XY 平面での関係だけで決まり、2D の問題と等価になる。

### 15 軸 SAT との照合

3D では、OBB について SAT が使える（第 26 章）。**まったく別のアルゴリズムなので、強力なリファレンスになる。**

### EPA の検証

```cpp
TEST_CLASS(Epa3Tests) {
public:
    TEST_METHOD(貫通深度が15軸SATのMTVと一致すること) {
        Rng rng(2203);
        int checked = 0;
        float worst_depth = 0.0f, worst_angle = 0.0f;

        for (int i = 0; i < 50000; ++i) {
            const auto a = random_obb3(rng);
            const auto b = random_obb3(rng);

            const auto by_sat = collision::sat_obb3(a, b);       // 第 26.4 節
            const auto g = collision::gjk3(a, b);
            if (!by_sat || g.status != collision::GjkStatus::intersecting) continue;

            const auto e = collision::epa3(a, b, g.simplex);
            if (!e || !e->converged) continue;

            ++checked;
            worst_depth = std::max(worst_depth, std::fabs(e->depth - by_sat->depth));
            const float c = std::clamp(collision::dot(e->normal, by_sat->axis), -1.0f, 1.0f);
            worst_angle = std::max(worst_angle, std::acos(c));

            expect_near(by_sat->depth, e->depth, 1.0e-2f, 5.0e-2f);
            Assert::IsTrue(c > 0.98f, L"法線が SAT と大きく違う");
        }

        Logger::WriteMessage(std::format(
            "EPA3 vs SAT3: 照合 {} 件, 深度の最大差 {:.4g}, 法線の最大角度差 {:.3f} 度\n",
            checked, worst_depth, worst_angle * 180.0f / std::numbers::pi_v<float>).c_str());
        Assert::IsTrue(checked > 5000);
    }

    TEST_METHOD(押し戻すと交差が解消すること) {
        Rng rng(2204);
        int checked = 0;

        for (int i = 0; i < 20000; ++i) {
            auto a = random_obb3(rng);
            const auto b = random_obb3(rng);

            const auto g = collision::gjk3(a, b);
            if (g.status != collision::GjkStatus::intersecting) continue;
            const auto e = collision::epa3(a, b, g.simplex);
            if (!e || !e->converged) continue;

            a.center -= e->normal * (e->depth + 1.0e-2f);
            Assert::IsFalse(collision::overlaps(a, b),
                detail::widen(std::format(
                    "押し戻しても交差したまま (depth={:.6g})", e->depth)).c_str());
            ++checked;
        }
        Assert::IsTrue(checked > 2000);
    }

    TEST_METHOD(球どうしの深度が解析解と一致すること) {
        Rng rng(2205);
        for (int i = 0; i < 20000; ++i) {
            const collision::Sphere a{{rng.uniform(-2.0f, 2.0f), rng.uniform(-2.0f, 2.0f),
                                       rng.uniform(-2.0f, 2.0f)}, rng.uniform(0.5f, 1.5f)};
            const collision::Sphere b{{rng.uniform(-2.0f, 2.0f), rng.uniform(-2.0f, 2.0f),
                                       rng.uniform(-2.0f, 2.0f)}, rng.uniform(0.5f, 1.5f)};

            const float d = collision::distance(a.center, b.center);
            const float exact_depth = a.radius + b.radius - d;
            if (exact_depth <= 0.05f || d < 0.1f) continue;   // 境界近傍と同心を除く

            const auto g = collision::gjk3(a, b);
            if (g.status != collision::GjkStatus::intersecting) continue;
            const auto e = collision::epa3(a, b, g.simplex);
            if (!e || !e->converged) continue;

            // 球は EPA にとって最も苦手な形状（頂点がないので多面体近似になる）
            expect_near(exact_depth, e->depth, 2.0e-2f, 5.0e-2f);
        }
    }

    TEST_METHOD(収束の統計を記録する) {
        Rng rng(2206);
        int total = 0, not_conv = 0, degenerate = 0;
        long long total_iter = 0;
        int max_iter = 0;

        for (int i = 0; i < 50000; ++i) {
            const auto a = random_obb3(rng);
            const auto b = random_obb3(rng);
            const auto g = collision::gjk3(a, b);
            if (g.status != collision::GjkStatus::intersecting) continue;

            const auto e = collision::epa3(a, b, g.simplex);
            ++total;
            if (!e) { ++degenerate; continue; }
            if (!e->converged) ++not_conv;
            total_iter += e->iterations;
            max_iter = std::max(max_iter, e->iterations);
        }

        Logger::WriteMessage(std::format(
            "EPA3 {} 件: 平均反復 {:.2f}, 最大 {}, 未収束 {}, 退化 {}\n",
            total, static_cast<double>(total_iter) / std::max(total, 1),
            max_iter, not_conv, degenerate).c_str());
        Assert::IsTrue(not_conv * 50 < total, L"未収束が 2% を超えている");
    }
};
```

**球の深度テストで許容誤差を大きく取っている**（`2e-2` = 2 センチメートル）。理由を説明しておく。

**EPA は球を多面体で近似する。** 球には頂点がないので、サポート点は反復のたびに新しく生成される。ポリトープは球に内接する多面体になり、その面までの距離は真の深度よりわずかに小さい。

反復を増やせば精度は上がるが、**球が絡む場合は専用実装（第 25.1 節）を使うべきである**。GJK/EPA は「どんな形状でも動く」保険として使い、専用実装がある組み合わせではそちらを優先する。第 23 章の実務パイプラインで述べたとおりである。

## この章のまとめ

- **サポート写像は次元が増えるだけ。** AABB は分岐 3 回、OBB は内積 3 回
- **`ConvexHull3` は頂点列だけでよい。** 面も辺も要らないのが GJK の実用上の利点
- 円柱など、2D にない形状も扱えるようになる
- 単体に**四面体**が加わる。三角形は「終了条件」から「途中段階」に変わる
- 線分の場合、`perpendicular` の代わりに**ベクトル三重積**を使う（第 24.2 節）
- 原点が直線上にある退化ケースで `build_basis` が役立つ
- 四面体では **`A` に接する 3 面だけ**を調べる。2D で辺 `BC` を省いたのと同じ理由
- **EPA のポリトープは面のリストになる。** ホール境界の再構成が必要
- 境界は「削除面の辺を集め、逆向きのペアを消す」ことで求まる。**面の向きを揃えてあるから成立する**
- 収束判定は 2D と同じもの。桁落ちの構造は次元に依存しない
- **検証の主軸は「2D 実装を平面に埋め込む」。** 検証済みの実装がそのままリファレンスになる
- OBB は 15 軸 SAT、球は解析解と照合する
- **球は EPA が苦手。** 専用実装がある組み合わせではそちらを使う

第 VI 部では、話題が大きく変わる。ここまでは「二つの形状の関係を正しく求める」ことが主題だった。次からは「**数千の形状から、判定すべきペアを見つける**」ことが主題になる。幾何の難しさは一段落し、データ構造とアルゴリズムの計算量が中心になる。

まず、総当たりが本当に遅いのかを実測するところから始める。
