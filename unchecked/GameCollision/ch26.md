# 第 26 章　3D の SAT ― OBB vs OBB

> **この章のゴール**
> 3 次元の分離軸定理を実装する。第 11.3 節で「3D では面法線だけでは足りない」と予告した。その理由を**実際の反例で示し**、辺の外積 9 軸を加えた 15 軸の判定を書く。
>
> そして退化ケースが新しい形で現れる。**平行な辺の外積はゼロベクトルになり、正規化できない。** ここで `/fp:fast` と FTZ が意外な形で働く ― 第 5 章で「失うもの」として扱った FTZ が、この場面では**むしろ有利に働く**。逆説的だが、理由を追えば納得できる。

---

## 26.1 15 軸の内訳

### 2D からの拡張

第 11.3 節で、2D の SAT が調べる軸をまとめた。

| 形状ペア | 調べる軸 | 本数 |
|---|---|---|
| 2D OBB vs OBB | 各 OBB の 2 軸ずつ | 4 |

3D では次のようになる。

| 種類 | 内訳 | 本数 |
|---|---|---|
| A の面法線 | A の 3 軸 | 3 |
| B の面法線 | B の 3 軸 | 3 |
| **辺の外積** | A の 3 辺 × B の 3 辺 | **9** |
| 合計 | | **15** |

**面法線が 3 本ずつなのは、2D で 2 本ずつだったのと同じ理由である。** 直方体の向かい合う面は法線が逆向きなので、同じ軸として数える。6 面で 3 軸。

問題は 9 本の辺の外積である。**これがなぜ必要なのか**が、次節の主題になる。

### 投影半径

第 12.2 節で導いた公式が、そのまま項を増やして使える。

```cpp
// collision/narrow/obb3.h
#pragma once

#include "collision/shapes/shapes3.h"
#include "collision/narrow/sat.h"

namespace collision {

// 軸 n に投影したときの、中心からの半幅
[[nodiscard]] inline float projected_radius(const Obb3& o, Vec3 n) noexcept {
    return o.extents.x * std::fabs(dot(o.axes.col[0], n))
         + o.extents.y * std::fabs(dot(o.axes.col[1], n))
         + o.extents.z * std::fabs(dot(o.axes.col[2], n));
}

} // namespace collision
```

**2D の 2 項が 3 項になっただけである。** 8 頂点を列挙して min/max を取るより、はるかに安い。

### 素朴な実装

まず、動くものを書く。

```cpp
[[nodiscard]] inline bool overlaps_naive(const Obb3& a, const Obb3& b) noexcept {
    const Vec3 d = b.center - a.center;

    auto separated = [&](Vec3 n) {
        return std::fabs(dot(d, n)) > projected_radius(a, n) + projected_radius(b, n);
    };

    // 面法線 6 本
    for (int i = 0; i < 3; ++i) {
        if (separated(a.axes.col[i])) return false;
        if (separated(b.axes.col[i])) return false;
    }

    // 辺の外積 9 本
    for (int i = 0; i < 3; ++i) {
        for (int j = 0; j < 3; ++j) {
            const auto n = try_normalize(cross(a.axes.col[i], b.axes.col[j]));
            if (!n) continue;                  // 平行な辺（26.3 節）
            if (separated(*n)) return false;
        }
    }
    return true;
}
```

**中心間ベクトルの投影と、投影半径の和を比べる**という形になっている。第 11.2 節の `penetration` と同じ判定を、対称性を使って簡潔に書いたものである。

OBB は中心について対称なので、投影区間は `[c − r, c + r]` の形になる。二つの区間が分離する条件は `|c_a − c_b| > r_a + r_b` である。

## 26.2 なぜ辺の外積が必要なのか ― 反例

### 主張

**面法線 6 軸だけでは、分離しているのに「交差している」と誤判定する配置が存在する。**

言葉で説明するより、実物を見るほうが早い。

### 反例

**A**：一辺 2 の立方体（半幅 `(1,1,1)`）、原点に軸平行で配置

**B**：同じ立方体を、X 軸まわりに 5 度、次に Z 軸まわりに 5 度回転させ、中心を `(2.011, 0, 2.003)` に置く

B の軸は次のようになる。

```
axis[0] = ( 0.99619,  0.08716,  0.00000)
axis[1] = (-0.08682,  0.99240,  0.08716)
axis[2] = ( 0.00760, -0.08682,  0.99619)
```

**この配置で、6 本の面法線すべてが「重なっている」と判定する。**

| 軸 | 中心間距離の投影 | 投影半径の和 | 判定 |
|---|---|---|---|
| A の X | 2.0109 | 2.0906 | 重なり |
| A の Y | 0.0000 | 2.1664 | 重なり |
| A の Z | 2.0032 | 2.0834 | 重なり |
| B の X | 2.0032 | 2.0834 | 重なり |
| B の Y | 0.0000 | 2.1664 | 重なり |
| B の Z | 2.0109 | 2.0906 | 重なり |

**ところが、A の Y 軸と B の Y 軸の外積を取ると分離が見える。**

```
L = normalize(cross(A.axis[1], B.axis[1])) = (0.70845, 0.0, 0.70576)
```

| 軸 | 中心間距離の投影 | 投影半径の和 | 判定 |
|---|---|---|---|
| **辺の外積 L** | **2.8384** | **2.8284** | **分離** |

差はわずか 0.01 だが、確かに分離している。**総当たりで A の内部を格子サンプリングしても、B に入る点は一つもない。**

### 直感的な理解

なぜこういうことが起きるのか。

二つの箱が**辺どうしで斜めにすれ違う**配置を想像してほしい。A の一本の辺と B の一本の辺が、ねじれの位置で最も接近している。両者を隔てる平面は、**その二本の辺の両方に平行**でなければならない。

「二本の直線の両方に平行な平面」の法線は、**二本の方向ベクトルの外積**である。第 24.1 節で述べた「両方に垂直な向きが得られる」という外積の性質が、ここで効いてくる。

そしてこの向きは、一般にはどちらの箱の面法線とも一致しない。だから面法線だけでは見つからない。

**2D にこの問題がないのは、「辺どうしがすれ違う」配置が存在しないからである。** 2D の辺は線分であり、平面内でねじれることができない。

### 頻度

ランダムな配置 200,000 通りで検証すると、**約 2.1% で面法線のみの判定が誤る**。

決して珍しくない。50 回に 1 回である。「ほとんどの場合は面法線で足りる」と考えて省略すると、**時々物体がめり込む**という再現しにくい不具合になる。

### テストにする

```cpp
// test_obb3.cpp
TEST_CLASS(Sat15Axes) {
public:
    TEST_METHOD(面法線だけでは分離を検出できない配置があること) {
        const collision::Obb3 a{
            .center = {0,0,0}, .axes = {}, .extents = {1,1,1}};   // 単位行列

        collision::Obb3 b{};
        b.center  = {2.01089f, 0.0f, 2.00324f};
        b.axes.col[0] = { 0.99619f,  0.08716f,  0.0f};
        b.axes.col[1] = {-0.08682f,  0.99240f,  0.08716f};
        b.axes.col[2] = { 0.00760f, -0.08682f,  0.99619f};
        b.extents = {1,1,1};

        // 面法線 6 軸だけでは「交差している」と誤判定する
        Assert::IsTrue(collision::detail::overlaps_face_axes_only(a, b),
                       L"反例として成立していない（面法線で分離が見えてしまう）");

        // 15 軸なら正しく「分離」と判定する
        Assert::IsFalse(collision::overlaps(a, b),
                        L"15 軸でも分離を検出できていない");
    }
};
```

**この一件のテストが、9 本の追加軸の存在理由をすべて説明している。** 消してはいけないテストである。

## 26.3 平行な辺と外積のゼロ長

### 問題

`cross(a.axes.col[i], b.axes.col[j])` は、二つの軸が平行なときゼロベクトルになる。

これは特殊なケースではない。**二つの箱が軸平行に近い向きで配置されているとき、9 本の外積のうち複数がゼロに近づく。** そして軸平行な配置は、ゲームでは最も頻繁に現れる。

ゼロベクトルは正規化できない。素朴に正規化すると `NaN` が出る。

### 二つの対処

**対処 1：正規化に失敗したら、その軸を飛ばす。**

26.1 節の実装がこれである。`try_normalize`（第 6.4 節）が `nullopt` を返したら `continue` する。

**正しさは保たれる。** 二つの辺が平行なら、その外積が表す軸は「両方の辺に垂直な平面」を指すが、平行な辺は同じ平面を共有するので、その軸での分離は面法線のいずれかで既に検出される。**冗長な軸なので、飛ばしてよい。**

**対処 2：正規化せず、誤差項を加えて比較する。**

正規化を避けると、投影値のスケールが `|cross|` 倍になる。第 11.2 節で「軸は必ず正規化する」と強調したのは、**複数の軸の重なり量を比較するため**だった。

分離の**有無**だけを判定するなら、正規化は不要である（両辺が同じ倍率でスケールされる）。深度を求めないなら、この選択もありうる。

**本書は対処 1 を採る。** 深度（MTV）も求めたいので、軸は正規化する。

### ここで FTZ が有利に働く

第 5 章で FTZ/DAZ を有効にした（非正規化数をゼロに潰す）。**その副作用が、この場面では有利に働く。**

二つの軸がほぼ平行なとき、外積の各成分は非常に小さくなる。その二乗和 `length_squared` はさらに小さくなり、**非正規化域に落ちる**（第 5.7 節で述べた「二乗すると指数が倍になる」）。

FTZ が有効なら、これはゼロに潰される。すると `try_normalize` の `len2 < min_length2` が確実に真になり、**軸が飛ばされる**。

FTZ が無効だと、`len2` は微小な非ゼロのまま残る。それでも `min_length2`（`1e-8`）より小さければ飛ばされるので、結論は変わらない。

**つまり、閾値を単位系から決めておいたおかげで、FTZ の有無に関わらず同じ結果になる。** 第 5.8 節で「閾値を単位系から決めれば非正規化数の問題は自動的に回避される」と述べたことの、もう一つの実例である。

> **「FTZ が有利」とはどういう意味か**
> 正確には、「FTZ があると助かる」のではなく「**FTZ があっても困らない設計になっている**」である。
>
> 第 5.8 節では FTZ の副作用として「二乗長がゼロに潰れる」を挙げ、それが正規化のガードを壊す危険を述べた。ここでは同じ現象が、**弾きたいケースを確実に弾いてくれる**方向に働いている。
>
> 同じ性質が、文脈によって害にも益にもなる。**大事なのは、どちらに転んでも結論が変わらない閾値を選ぶことである。**

## 26.4 誤差項を加えた頑健な実装

### 境界近傍の不安定さ

15 軸の判定には、もう一つの問題がある。

**ほぼ平行だが完全には平行でない辺**の場合、外積は非常に短いが `min_length2` は超える、という状況が起こりうる。このとき正規化された軸は、**元のベクトルの方向誤差が増幅されたもの**になる。

短いベクトルの正規化は、方向の精度が悪い。桁落ち（第 4.2 節）が起きているからである。その軸で投影して比較すると、判定が誤りうる。

### Ericson の誤差項

Christer Ericson の *Real-Time Collision Detection* で示されている対処は、**比較の右辺に誤差項を加える**ことである。

```cpp
// collision/narrow/obb3.h（続き）

// SAT の比較に加える誤差項。/fp:fast の再結合と FMA 融合を見込んで
// 一般的な推奨値より大きめに取る（第 4.4 節）。
inline constexpr float sat3_epsilon = 1.0e-5f;

[[nodiscard]] inline bool overlaps(const Obb3& a, const Obb3& b) noexcept {
    const Vec3 d = b.center - a.center;

    // 面法線 6 本。誤差項は不要（軸が正規直交なので精度がよい）
    for (int i = 0; i < 3; ++i) {
        if (std::fabs(dot(d, a.axes.col[i]))
            > projected_radius(a, a.axes.col[i]) + projected_radius(b, a.axes.col[i])) {
            return false;
        }
        if (std::fabs(dot(d, b.axes.col[i]))
            > projected_radius(a, b.axes.col[i]) + projected_radius(b, b.axes.col[i])) {
            return false;
        }
    }

    // 辺の外積 9 本。誤差項を加える
    for (int i = 0; i < 3; ++i) {
        for (int j = 0; j < 3; ++j) {
            const Vec3 raw = cross(a.axes.col[i], b.axes.col[j]);
            const auto n = try_normalize(raw);
            if (!n) continue;                    // 平行な辺（26.3 節）

            const float lhs = std::fabs(dot(d, *n));
            const float rhs = projected_radius(a, *n) + projected_radius(b, *n);

            // スケール相対の誤差項（第 4.3 節の方針）
            const float tol = sat3_epsilon * (rhs + std::fabs(lhs));
            if (lhs > rhs + tol) return false;
        }
    }
    return true;
}
```

### 誤差項の設計

**なぜ辺の外積にだけ加えるのか。**

面法線は正規直交な軸そのものなので、正規化の誤差がない。投影半径の計算も素直である。誤差項を加える理由がない。

辺の外積は、正規化の際に短いベクトルを扱いうる。**精度が落ちる可能性があるのはこちらだけである。**

**なぜスケール相対にするのか。**

第 4.3 節の方針である。原点から 1000 離れた場所では投影値も 1000 のオーダーになり、そこでの `float` の刻み幅は `6.1e-5` である（第 4.1 節の表）。固定の `1e-5` では、遠方で厳しすぎる。

`rhs + |lhs|` を基準にすることで、値のスケールに応じて許容幅が広がる。

**なぜ「大きめ」なのか。**

`/fp:fast` の下では、`dot` と `cross` が FMA に融合されたり順序が入れ替わったりする（第 4.4 節）。誤差の見積もりが、`/fp:precise` を前提とした一般的な推奨値より緩くなる。

**安全側は「重なっていると判定する」側である。** 誤差項を大きくすると、分離しているのに「重なっている」と判定する可能性が増える。これは無駄な処理を招くが、すり抜けは起こさない。逆に誤差項が小さすぎると、重なっているのに「分離」と判定してすり抜ける。

第 18.1 節で「安全側に倒す」と述べたのと同じ判断である。

### MTV を求める

深度も欲しい場合は、第 11.2 節の `penetration` と同じ形にする。

```cpp
struct Sat3Result {
    Vec3  axis{};     // 正規化済み。A から B へ向く（第 7.3 節の規約）
    float depth{};
};

[[nodiscard]] inline std::optional<Sat3Result>
sat_obb3(const Obb3& a, const Obb3& b) noexcept {
    const Vec3 d = b.center - a.center;
    Sat3Result best{.depth = std::numeric_limits<float>::infinity()};

    auto test = [&](Vec3 n, float tol) -> bool {
        const float proj = dot(d, n);
        const float rhs  = projected_radius(a, n) + projected_radius(b, n);
        const float pen  = rhs - std::fabs(proj);     // 押し出し量

        if (pen <= -tol) return false;                // 分離
        if (pen < best.depth) {
            // 法線は A から B へ。proj の符号に合わせる
            best = Sat3Result{.axis = (proj >= 0.0f) ? n : -n, .depth = std::max(pen, 0.0f)};
        }
        return true;
    };

    for (int i = 0; i < 3; ++i) {
        if (!test(a.axes.col[i], 0.0f)) return std::nullopt;
        if (!test(b.axes.col[i], 0.0f)) return std::nullopt;
    }
    for (int i = 0; i < 3; ++i) {
        for (int j = 0; j < 3; ++j) {
            const auto n = try_normalize(cross(a.axes.col[i], b.axes.col[j]));
            if (!n) continue;
            const float rhs = projected_radius(a, *n) + projected_radius(b, *n);
            if (!test(*n, sat3_epsilon * (rhs + std::fabs(dot(d, *n))))) return std::nullopt;
        }
    }
    return best;
}
```

**OBB は中心対称なので、押し出し量が `rhs − |proj|` で直接求まる。** 第 11.2 節で一般の凸形状について `min(b.max − a.min, a.max − b.min)` と書いた式は、対称な形状ではこの形に簡約される。

含有のケース（片方が他方を完全に含む）も、この式なら正しく扱われる。`|proj|` が小さいほど押し出し量が大きくなるので、深く入り込んでいるほど深度が大きい。

**第 11.2 節で見つけたバグと同じ誤りを、ここでは犯していない。** 対称性を使った式が、たまたま正しい形になっている。

### 早期脱出の順序

15 軸をどの順に調べるかで、平均コストが変わる。

**分離している場合は、最初に見つけた分離軸で脱出できる。** ゲームでは判定するペアの大半が分離しているので、この効果は大きい（第 13.3 節で 2D について述べたのと同じ事情）。

実測すると、**面法線 6 軸で分離が判明する割合が圧倒的に高い**。26.2 節で「面法線だけでは 2.1% で誤る」と述べたが、裏を返せば **97.9% は面法線で決着する**ということである。

したがって、**面法線を先に調べる**のが正しい順序になる。26.1 節の実装はそうなっている。

さらに細かく見ると、面法線の中でも「中心間ベクトルに近い軸」が当たりやすい。だが第 13.3 節で述べたのと同じ理由（良い軸を探すコストが節約分を食う）で、本書では並べ替えを行わない。

### 15 軸 SAT と GJK の使い分け

3D では、OBB どうしの判定に二つの選択肢がある。

| 項目 | 15 軸 SAT | GJK + EPA |
|---|---|---|
| 分離している場合 | 平均 3〜5 軸で脱出 | 平均 2〜3 反復 |
| 交差している場合 | 15 軸すべて（MTV を求めるため） | GJK 数反復 ＋ EPA 十数反復 |
| 深度の精度 | 厳密 | 反復に依存 |
| 実装の複雑さ | 低い | 高い |
| 他の形状との混合 | 不可 | 可能 |

**OBB どうしなら SAT が有利である。** 特に交差している場合、EPA の反復コストが効いてくる。

**GJK を使う理由は、形状の多様性である。** 球、カプセル、円柱、任意の凸多面体を同じコードで扱いたいなら GJK になる。第 23 章の実務パイプラインで述べたとおり、**専用実装があるペアは専用を使い、GJK は保険として持つ**。

第 28 章で 3D の GJK を実装したら、この二つを実測で比較する（28.4 節）。

### 凸多面体どうしへの拡張

15 軸は OBB（直方体）に固有の数である。一般の凸多面体では、

- 面法線：`n + m` 本（それぞれの面数）
- 辺の外積：`n_edge × m_edge` 本

となる。**辺の数の積で効いてくるので、面数が増えると急速に高くなる。**

立方体は面 6・辺 12 だが、平行な辺をまとめると独立な面法線 3、独立な辺方向 3 になる。だから `3 + 3 + 3×3 = 15` である。

十二面体どうしなら、面法線 6+6、辺方向 15×15 = 225 で、合計 237 軸になる。**この規模になると SAT は現実的でない。** GJK に切り替えるべき境界がここにある。

## 26.5 テスト

### 15 軸のうち 1 つを消すと破綻する

**この章で最も価値のあるテストである。** 各軸が本当に必要であることを、機械的に確認する。

```cpp
TEST_CLASS(Sat15AxisNecessity) {
public:
    // 指定した軸だけを除外した SAT
    [[nodiscard]] static bool overlaps_skipping(
            const collision::Obb3& a, const collision::Obb3& b, int skip) {
        const Vec3 d = b.center - a.center;
        int idx = 0;
        auto sep = [&](Vec3 n) {
            const bool s = std::fabs(collision::dot(d, n))
                > collision::projected_radius(a, n) + collision::projected_radius(b, n);
            return (idx++ == skip) ? false : s;   // skip 番目は無視
        };

        for (int i = 0; i < 3; ++i) if (sep(a.axes.col[i])) return false;
        for (int i = 0; i < 3; ++i) if (sep(b.axes.col[i])) return false;
        for (int i = 0; i < 3; ++i)
            for (int j = 0; j < 3; ++j) {
                const auto n = collision::try_normalize(
                    collision::cross(a.axes.col[i], b.axes.col[j]));
                if (!n) { ++idx; continue; }
                if (sep(*n)) return false;
            }
        return true;
    }

    TEST_METHOD(どの軸を消しても誤判定が生じること) {
        Rng rng(2000);
        std::array<int, 15> broken{};

        for (int trial = 0; trial < 200000; ++trial) {
            const auto a = random_obb3(rng);
            const auto b = random_obb3(rng);
            const bool truth = collision::overlaps(a, b);   // 15 軸すべて

            for (int k = 0; k < 15; ++k) {
                if (overlaps_skipping(a, b, k) != truth) ++broken[k];
            }
        }

        for (int k = 0; k < 15; ++k) {
            Logger::WriteMessage(std::format(
                "軸 {:2}: 除外すると {} 件で誤判定\n", k, broken[k]).c_str());
            Assert::IsTrue(broken[k] > 0,
                detail::widen(std::format(
                    "軸 {} を消しても誤判定が生じない。冗長な軸かもしれない", k)).c_str());
        }
    }
};
```

**「消しても壊れない軸があれば、それは冗長である」**という論法である。実際に走らせると、15 軸すべてで誤判定が生じる。すなわち、どの軸も必要である。

このテストは実行に時間がかかるので、通常のテスト実行から外し、変更時だけ手動で回す運用が現実的である（第 22.6 節の `ground_truth` と同じ扱い）。

### 総当たりとの照合

```cpp
TEST_CLASS(Obb3Reference) {
public:
    // A の内部を格子サンプリングし、B に入る点があるか調べる
    [[nodiscard]] static bool brute_force(
            const collision::Obb3& a, const collision::Obb3& b, int steps = 40) {
        for (int i = 0; i <= steps; ++i)
        for (int j = 0; j <= steps; ++j)
        for (int k = 0; k <= steps; ++k) {
            const float u = static_cast<float>(i) / steps * 2.0f - 1.0f;
            const float v = static_cast<float>(j) / steps * 2.0f - 1.0f;
            const float w = static_cast<float>(k) / steps * 2.0f - 1.0f;
            const Vec3 p = a.center
                + a.axes.col[0] * (u * a.extents.x)
                + a.axes.col[1] * (v * a.extents.y)
                + a.axes.col[2] * (w * a.extents.z);
            const Vec3 q = p - b.center;
            if (std::fabs(collision::dot(q, b.axes.col[0])) <= b.extents.x &&
                std::fabs(collision::dot(q, b.axes.col[1])) <= b.extents.y &&
                std::fabs(collision::dot(q, b.axes.col[2])) <= b.extents.z) return true;
        }
        return false;
    }

    TEST_METHOD(交差している場合は総当たりでも検出されること) {
        Rng rng(2001);
        int checked = 0;

        for (int i = 0; i < 2000; ++i) {
            const auto a = random_obb3(rng);
            const auto b = random_obb3(rng);
            if (!collision::overlaps(a, b)) continue;

            // 深く重なっている場合だけ検証する（浅い接触は格子で捕まらない）
            const auto s = collision::sat_obb3(a, b);
            if (!s || s->depth < 0.2f) continue;

            Assert::IsTrue(brute_force(a, b),
                           L"SAT が交差と判定したのに格子で点が見つからない");
            ++checked;
        }
        Assert::IsTrue(checked > 100, L"検証できた事例が少なすぎる");
    }

    TEST_METHOD(分離している場合は総当たりでも検出されないこと) {
        Rng rng(2002);
        int checked = 0;

        for (int i = 0; i < 2000; ++i) {
            const auto a = random_obb3(rng);
            const auto b = random_obb3(rng);
            if (collision::overlaps(a, b)) continue;

            Assert::IsFalse(brute_force(a, b, 50),
                            L"SAT が分離と判定したのに格子で交差が見つかった");
            ++checked;
        }
        Assert::IsTrue(checked > 500);
    }
};
```

**「交差」側は深く重なっている場合だけ検証している。** 格子サンプリングは有限の解像度なので、浅い接触では点が見つからない。**リファレンスの限界を理解して、検証する範囲を限定する**のは重要な判断である。

一方「分離」側は、格子が粗くても偽陽性が出ないので、そのまま検証できる。

### 軸平行なケース

```cpp
TEST_CLASS(Obb3AxisAligned) {
public:
    TEST_METHOD(軸平行なOBBがAABBと同じ結果を返すこと) {
        Rng rng(2003);
        for (int i = 0; i < 50000; ++i) {
            const Vec3 alo{rng.uniform(-4.0f, 4.0f), rng.uniform(-4.0f, 4.0f),
                           rng.uniform(-4.0f, 4.0f)};
            const Vec3 blo{rng.uniform(-4.0f, 4.0f), rng.uniform(-4.0f, 4.0f),
                           rng.uniform(-4.0f, 4.0f)};
            const collision::Aabb3 aa{alo, alo + Vec3{rng.uniform(0.5f, 2.5f),
                rng.uniform(0.5f, 2.5f), rng.uniform(0.5f, 2.5f)}};
            const collision::Aabb3 bb{blo, blo + Vec3{rng.uniform(0.5f, 2.5f),
                rng.uniform(0.5f, 2.5f), rng.uniform(0.5f, 2.5f)}};

            const auto a = collision::obb3_from_aabb(aa);
            const auto b = collision::obb3_from_aabb(bb);

            Assert::AreEqual(collision::overlaps(aa, bb), collision::overlaps(a, b),
                             L"軸平行 OBB と AABB で結果が食い違う");
        }
    }

    TEST_METHOD(軸平行なケースで外積軸が全部ゼロになること) {
        // 26.3 節の確認。軸が一致するので 9 本すべてが飛ばされる
        const auto a = collision::obb3_from_aabb(
            collision::Aabb3{{-1,-1,-1}, {1,1,1}});
        const auto b = collision::obb3_from_aabb(
            collision::Aabb3{{0.5f,0,0}, {2.5f,2,2}});

        int skipped = 0;
        for (int i = 0; i < 3; ++i)
            for (int j = 0; j < 3; ++j)
                if (!collision::try_normalize(
                        collision::cross(a.axes.col[i], b.axes.col[j]))) ++skipped;

        // 同じ軸どうしの外積 3 本がゼロ。残り 6 本は座標軸に一致する
        Assert::AreEqual(3, skipped, L"ゼロになる外積の本数が想定と違う");
    }

    TEST_METHOD(FTZの有無で結果が変わらないこと) {
        // 26.3 節の主張の検証
        Rng rng(2004);
        std::vector<std::pair<collision::Obb3, collision::Obb3>> pairs;
        for (int i = 0; i < 20000; ++i) {
            pairs.emplace_back(random_obb3_nearly_aligned(rng),
                               random_obb3_nearly_aligned(rng));
        }

        std::vector<bool> with_ftz, without_ftz;
        with_ftz.reserve(pairs.size());
        without_ftz.reserve(pairs.size());

        collision::enable_flush_denormals();
        for (const auto& [a, b] : pairs) with_ftz.push_back(collision::overlaps(a, b));

        collision::disable_flush_denormals();
        for (const auto& [a, b] : pairs) without_ftz.push_back(collision::overlaps(a, b));
        collision::enable_flush_denormals();   // テスト全体の前提に戻す

        int diff = 0;
        for (std::size_t i = 0; i < pairs.size(); ++i)
            if (with_ftz[i] != without_ftz[i]) ++diff;

        Logger::WriteMessage(std::format("FTZ の有無での差: {} 件\n", diff).c_str());
        Assert::AreEqual(0, diff, L"FTZ の有無で判定結果が変わった");
    }
};
```

**最後のテストが、26.3 節の主張の実証である。** 閾値を単位系から取っておけば、FTZ の設定に関わらず同じ結果が出る。第 5 章の設計が、3D の SAT でも守られていることを確認している。

`random_obb3_nearly_aligned` は、わずかにずれた軸を持つ OBB を生成するヘルパである。外積が非常に短くなる状況を意図的に作る。

## この章のまとめ

- **3D の SAT は 15 軸。** 面法線 3+3、辺の外積 3×3 = 9
- 投影半径の公式は 2D の 2 項が 3 項になっただけ
- **面法線だけでは不十分。** 反例：単位立方体を 5 度ずつ 2 回転させ、対角方向に 2.84 離す
- 面法線 6 軸すべてが「重なり」と言い、辺の外積 1 本だけが分離を検出する
- ランダムな配置の**約 2.1%** で面法線のみの判定が誤る。珍しくない
- 2D にこの問題がないのは、辺どうしが「ねじれの位置」を取れないため
- **平行な辺の外積はゼロになる。** `try_normalize` が失敗したら飛ばす（冗長な軸なので正しい）
- **FTZ は、この場面ではむしろ有利に働く。** ただし本質は「どちらでも結論が変わらない閾値」を選んだこと
- 辺の外積にだけ誤差項を加える。面法線は正規直交なので不要
- 誤差項はスケール相対、`/fp:fast` を見込んで大きめに。**安全側は「重なっている」側**
- テストの決め手は「**15 軸のうち 1 つを消すと誤判定が生じる**」

### 落とし穴と練習問題

**落とし穴 1：面法線 6 軸で済ませる。**　50 回に 1 回誤る。再現しにくいめり込みの原因になる。

**落とし穴 2：外積を正規化せずに深度を比較する。**　第 11.2 節と同じ問題。軸ごとにスケールが違う。

**落とし穴 3：誤差項を分離側に倒す。**　すり抜けを招く。安全側は「重なっている」側である。

**練習問題 26-1**　26.2 節の反例を自分で構成してみよう。単位立方体を二つ用意し、片方の回転角と配置距離を変えながら、面法線のみの判定と 15 軸の判定が食い違う配置を探す。どのくらいの角度範囲で起きるだろうか。

**練習問題 26-2**　`sat3_epsilon` を 0 にして、26.5 節の総当たりテストを走らせよう。誤判定は増えるだろうか。次に `1e-3` まで大きくして、逆方向の影響（分離しているのに重なりと判定する）を測ってほしい。

**練習問題 26-3**　OBB のマニフォールドを 3D で生成しよう。第 14 章のクリッピングを 3D に拡張することになる。参照面が「辺」ではなく「面」（多角形）になるので、クリッピングも多角形どうしになる。接触点は最大 4 点になるはずである。

**練習問題 26-4**　15 軸すべてを常に調べる実装と、早期脱出する実装（26.1 節）の速度を比べよう。交差している場合と分離している場合で、差はどう変わるだろうか。

**練習問題 26-5**（発展）　3D の SAT を GJK（第 28 章）と比較しよう。OBB どうしなら 15 軸の SAT のほうが速いはずだが、実測ではどうだろうか。凸多面体の頂点数が増えるとどこで逆転するかも調べてほしい。
