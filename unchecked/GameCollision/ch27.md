## 27.1 レイと三角形 ― メラー＝トランボア法

### 型と法線

```cpp
// collision/shapes/triangle3.h
#pragma once

#include "collision/math/vec3.h"

namespace collision {

struct Triangle3 {
    Vec3 a{};
    Vec3 b{};
    Vec3 c{};
};

// 正規化されていない法線。頂点が反時計回りに見える側を向く（右手系、第 24.1 節）
[[nodiscard]] constexpr Vec3 normal_raw(const Triangle3& t) noexcept {
    return cross(t.b - t.a, t.c - t.a);
}

[[nodiscard]] inline std::optional<Vec3> normal(const Triangle3& t) noexcept {
    return try_normalize(normal_raw(t));
}

// 面積の 2 倍（正規化前の法線の長さ）
[[nodiscard]] inline float area2(const Triangle3& t) noexcept {
    return length(normal_raw(t));
}

} // namespace collision
```

**巻き方向の規約が、そのまま法線の向きを決める。** 第 13.1 節で 2D の多角形について決めたのと同じ構造である。メッシュを読み込むとき、この規約に合っているかを検証する必要がある。

### 考え方

レイと三角形の交差を、**重心座標で表す**。

三角形上の点は `a + u·(b − a) + v·(c − a)` と書ける（`u, v ≥ 0`、`u + v ≤ 1`）。レイ上の点は `o + t·d` である。等しいと置くと、

```
o + t·d = a + u·(b − a) + v·(c − a)
```

未知数は `t, u, v` の三つ、式は三成分ぶんで三本。**連立一次方程式として解ける。**

整理すると、

```
[ −d  (b−a)  (c−a) ] · [t u v]ᵀ = o − a
```

クラメルの公式で解くと、行列式がスカラー三重積になる。それを整理したものがメラー＝トランボア法である。

### 実装

```cpp
// collision/narrow/raycast3.h
#pragma once

#include "collision/shapes/triangle3.h"
#include "collision/narrow/raycast.h"

namespace collision {

struct RayHit3 {
    float t{};
    Vec3  point{};
    Vec3  normal{};
    float u{}, v{};        // 重心座標（w = 1 − u − v）
    bool  back_face{};     // 裏面に当たったか
};

using RayResult3 = std::optional<RayHit3>;

[[nodiscard]] inline RayResult3
raycast(const Ray3& ray, const Triangle3& tri, bool cull_back_face = false) noexcept {
    const Vec3 e1 = tri.b - tri.a;
    const Vec3 e2 = tri.c - tri.a;

    const Vec3  p   = cross(ray.dir, e2);
    const float det = dot(e1, p);          // スカラー三重積 = 平行六面体の体積

    // det がゼロに近い ＝ レイが三角形の平面と平行
    if (std::fabs(det) < min_length2) return std::nullopt;

    const bool back = (det < 0.0f);
    if (cull_back_face && back) return std::nullopt;

    const float inv_det = 1.0f / det;
    const Vec3  s = ray.origin - tri.a;

    const float u = dot(s, p) * inv_det;
    if (u < 0.0f || u > 1.0f) return std::nullopt;

    const Vec3  q = cross(s, e1);
    const float v = dot(ray.dir, q) * inv_det;
    if (v < 0.0f || u + v > 1.0f) return std::nullopt;

    const float t = dot(e2, q) * inv_det;
    if (t < 0.0f || t > ray.max_t) return std::nullopt;

    Vec3 n = normalize_or(normal_raw(tri), Vec3{0.0f, 1.0f, 0.0f});
    if (dot(n, ray.dir) > 0.0f) n = -n;    // レイに向かい合わせる（第 15.1 節の規約）

    return RayHit3{
        .t = t, .point = ray.origin + ray.dir * t, .normal = n,
        .u = u, .v = v, .back_face = back,
    };
}

} // namespace collision
```

### 三つの注意点

**1. 除算が一回しかない。** `inv_det` を先に計算して、三箇所で掛けている。除算は乗算よりずっと遅いので、この形が定石である。

**2. 早期脱出が三段階ある。** `u` の範囲、`v` と `u+v` の範囲、`t` の範囲。**多くの場合、最初の判定で弾ける。** 三角形スープに対して数千回呼ぶので、この早期脱出は効く。

**3. 裏面の扱いを選べるようにしている。** `cull_back_face` が真なら、法線と逆側から当たったレイを無視する。視線判定では裏面を無視したいことが多く、当たり判定では両面を見たいことが多い。**呼び出し側に選ばせる。**

### 重心座標の和が 1 にならない

計算された `u, v, w = 1 − u − v` は、理論上は `u + v + w = 1` を満たす。

**浮動小数点では、厳密には満たされない。**

`u` と `v` はそれぞれ独立に計算されており、`inv_det` の丸め誤差がそれぞれに乗る。`w` を `1 − u − v` で求めれば和は定義上 1 になるが、`w` を独立に計算すると和が 1 からずれる。

第 9.3 節で 2D の `barycentric` について、**「一つを従属させる」**という対処を述べた。ここでも同じである。`w` は独立に計算しない。

**衝突点を重心座標から復元するとき**に、この差が効く。

```cpp
// 重心座標から点を復元する
const Vec3 p_bary = tri.a * (1.0f - u - v) + tri.b * u + tri.c * v;
```

`u + v + w` が 1 からずれていると、復元した点が三角形の平面からわずかに浮く。**本書では `ray.origin + ray.dir * t` を衝突点として使う**ので、この問題は回避されている。

重心座標は、頂点属性（法線・UV）の補間に使うのが主な用途である。そのときは和が 1 であることが重要になる。

## 27.2 球・カプセルと三角形

### 点と三角形の最近接点

第 9.3 節の 2D 版を 3D へ拡張する。**素朴で確実な実装を採る**という判断も同じである。

```cpp
// collision/narrow/closest_point3.h（続き）

[[nodiscard]] inline Vec3
closest_point(Vec3 p, const Triangle3& tri) noexcept {
    // まず平面へ射影し、内部にあるかを調べる
    const auto n = normal(tri);
    if (!n) {
        // 退化した三角形（面積ゼロ）。最も長い辺で代用する
        return closest_point_on_segment(p, tri.a, tri.b);
    }

    const Vec3 proj = p - *n * dot(p - tri.a, *n);

    // 三辺すべての内側にあるか（第 9.3 節の 3D 版）
    const bool inside =
        dot(cross(tri.b - tri.a, proj - tri.a), *n) >= 0.0f &&
        dot(cross(tri.c - tri.b, proj - tri.b), *n) >= 0.0f &&
        dot(cross(tri.a - tri.c, proj - tri.c), *n) >= 0.0f;

    if (inside) return proj;

    // 三辺の最近接点のうち最も近いものを選ぶ
    const Vec3 pab = closest_point_on_segment(p, tri.a, tri.b);
    const Vec3 pbc = closest_point_on_segment(p, tri.b, tri.c);
    const Vec3 pca = closest_point_on_segment(p, tri.c, tri.a);

    const float dab = distance_squared(p, pab);
    const float dbc = distance_squared(p, pbc);
    const float dca = distance_squared(p, pca);

    if (dab <= dbc && dab <= dca) return pab;
    if (dbc <= dca)               return pbc;
    return pca;
}
```

**平面へ射影してから内外判定する**のが 3D 特有の部分である。2D では射影が不要だった。

内外判定に外積とスカラー三重積を使っている。`dot(cross(edge, to_point), n)` の符号が、点が辺の内側にあるかを表す。**第 6.6 節の 2D の外積による判定と、同じ構造**である。

### 球と三角形

第 9.4 節の統一実装が、そのまま次元を上げて使える。

```cpp
[[nodiscard]] inline std::optional<Contact3>
intersect(const Sphere& s, const Triangle3& tri) noexcept {
    const Vec3  q  = closest_point(s.center, tri);
    const Vec3  d  = q - s.center;
    const float d2 = length_squared(d);

    if (d2 >= s.radius * s.radius) return std::nullopt;

    const Vec3  n    = normalize_or(d, normalize_or(normal_raw(tri), Vec3{0,1,0}));
    const float dist = (d2 < min_length2) ? 0.0f : std::sqrt(d2);

    return Contact3{
        .normal = n,
        .depth  = s.radius - dist,
        .point  = s.center + n * s.radius,
    };
}
```

**フォールバックを二重にしている**点に注目してほしい。`d` がゼロベクトル（球の中心が三角形の面上にある）のとき、`normalize_or` は第二引数を返す。そこに三角形の法線を渡すことで、**意味のある向きが得られる**。

第 8.3 節では `Vec3{1,0,0}` という任意の向きを使ったが、ここではもっと良い候補がある。**退化ケースのフォールバックは、文脈に応じて最善のものを選ぶ。**

### カプセルと三角形

芯線（線分）と三角形の最近接点が必要になる。これは**線分と三角形**の問題であり、素直には解けない。

分解して考える。線分と三角形の最短距離を実現する点のペアは、次のいずれかである。

1. 線分の端点と、三角形の内部（または境界）
2. 線分と、三角形の三辺のいずれか

```cpp
[[nodiscard]] inline std::pair<Vec3, Vec3>
closest_points_segment_triangle(Vec3 p, Vec3 q, const Triangle3& tri) noexcept {
    float best = std::numeric_limits<float>::infinity();
    Vec3 bs{}, bt{};

    auto consider = [&](Vec3 on_seg, Vec3 on_tri) {
        const float d2 = distance_squared(on_seg, on_tri);
        if (d2 < best) { best = d2; bs = on_seg; bt = on_tri; }
    };

    // (1) 線分の端点 vs 三角形
    consider(p, closest_point(p, tri));
    consider(q, closest_point(q, tri));

    // (2) 線分 vs 三角形の三辺
    const Vec3 v[3] = {tri.a, tri.b, tri.c};
    for (int i = 0; i < 3; ++i) {
        const auto c = closest_points_segments(p, q, v[i], v[(i + 1) % 3]);
        consider(c.c1, c.c2);
    }
    return {bs, bt};
}
```

**第 25.2 節の線分間最近接点が、ここで使われている。** 「本書最大の山場の一つ」と述べたものが、カプセルとメッシュの判定という最も実用的な場面で報われる。

3D のキャラクターをカプセルで表し、地形を三角形メッシュで表すのは定番の構成である。**この関数がその中核になる。**

素朴に 5 通り（端点 2 ＋ 辺 3）を全部調べているが、それでよい。第 9.3 節の三角形の最近接点と同じ判断である。**正しさが読み取れることを優先する。**

## 27.3 三角形スープ

### 表現

```cpp
// collision/shapes/mesh.h
#pragma once

#include "collision/shapes/triangle3.h"
#include <vector>
#include <span>

namespace collision {

// 静的な三角形メッシュ（地形など）
struct TriangleMesh {
    std::vector<Vec3>          vertex;
    std::vector<std::uint32_t> index;    // 3 つで 1 三角形

    [[nodiscard]] std::size_t triangle_count() const noexcept {
        return index.size() / 3;
    }

    [[nodiscard]] Triangle3 triangle(std::size_t i) const noexcept {
        return Triangle3{
            vertex[index[i * 3 + 0]],
            vertex[index[i * 3 + 1]],
            vertex[index[i * 3 + 2]],
        };
    }
};

} // namespace collision
```

**頂点配列とインデックス配列に分ける**のが定石である。頂点を共有できるのでメモリが減り、後述する隣接情報の構築も容易になる。

### 総当たりで判定する

**この章では総当たりで書く。** 高速化は第 32 章の BVH に譲る。

```cpp
// collision/narrow/mesh_query.h

struct MeshHit {
    std::size_t triangle_index{};
    Contact3    contact{};
};

// 球とメッシュの衝突。すべての接触を集める。
inline void collide(const Sphere& s, const TriangleMesh& mesh,
                    std::vector<MeshHit>& out) {
    out.clear();
    for (std::size_t i = 0; i < mesh.triangle_count(); ++i) {
        if (const auto c = intersect(s, mesh.triangle(i))) {
            out.push_back(MeshHit{.triangle_index = i, .contact = *c});
        }
    }
}

// レイとメッシュ。最も手前のヒットを返す
[[nodiscard]] inline std::optional<std::pair<std::size_t, RayHit3>>
raycast(const Ray3& ray, const TriangleMesh& mesh, bool cull_back = false) noexcept {
    std::optional<std::pair<std::size_t, RayHit3>> best;
    Ray3 r = ray;

    for (std::size_t i = 0; i < mesh.triangle_count(); ++i) {
        if (const auto h = raycast(r, mesh.triangle(i), cull_back)) {
            best = std::pair{i, *h};
            r.max_t = h->t;      // 以降はこれより手前だけを探す（早期脱出）
        }
    }
    return best;
}
```

**`r.max_t` を更新している**のが実用的な工夫である。手前のヒットが見つかるほど探索範囲が狭まり、後半の判定が早く弾かれる。第 17.4 節の `sweep_nearest` と同じ発想である。

### 複数の接触をどう処理するか

球が三角形の継ぎ目にあると、**複数の三角形と同時に接触する**。それぞれが `Contact3` を返す。

素朴に全部の押し戻しを適用すると、二重に押し戻されて物体が飛ぶ。

対処は二つある。

**1. 最も深い接触だけを使う。** 単純だが、角に挟まれた場合に振動する。

**2. すべての接触を集めて、ソルバに渡す。** 第 40 章の逐次力積ソルバが、複数の接触を同時に解く。これが本来の解決である。

**この章では接触を集めるところまで**を担当し、解決は第 VII 部に委ねる。`collide` が `std::vector<MeshHit>` を返しているのは、そのためである。

### 厚みのない地形の問題

三角形メッシュは**厚みを持たない**。これが実用上いくつかの問題を生む。

**問題 1：裏側からすり抜ける。** 高速で移動する物体が、床の下から突き上げると通り抜ける。CCD（第 III 部）を使えば防げるが、コストがかかる。

**問題 2：どちら側にいるか分からない。** 閉じたメッシュなら「内側か外側か」が定義できるが、地形のような開いたメッシュでは定義できない。押し戻す向きは、最近接点から物体への向きで決めるしかない。

**問題 3：深くめり込むと向きが反転する。** 物体の中心が三角形の面を通り越すと、最近接点への向きが逆になり、**さらに深く押し込む**方向に押し戻してしまう。

問題 3 が最も厄介である。対処は二つある。

**対処 A：めり込みが半径を超えないようにする。** CCD かサブステップで、1 フレームの移動量を制限する。予防的な対処である。

**対処 B：法線の向きを面法線で検証する。** 押し戻す向きが面法線と大きく食い違っていたら、面法線を優先する。

```cpp
// 押し戻す向きが面の裏側を向いていたら、面法線側へ倒す
[[nodiscard]] inline Vec3
guard_against_backface(Vec3 raw_normal, Vec3 face_normal) noexcept {
    // raw が「物体 → 三角形」の向きなので、面法線とは逆を向くのが正常
    return (dot(raw_normal, face_normal) > 0.0f) ? -face_normal : raw_normal;
}
```

**片面だけの地形なら、この対処が有効である。** 両面から接触しうる薄い壁では使えない（どちらが正しい向きか決められない）。

**本書の方針。** 地形メッシュは片面（法線側からのみ接触する）と仮定し、対処 B を適用する。両面が必要なら、薄い `Aabb3` か凸多面体で表す。

## 27.4 内部エッジ問題

### 現象

平らな床を、複数の三角形で敷き詰めているとする。その上をキャラクター（球やカプセル）が滑らせて動かす。

**タイルの継ぎ目で、見えない段差に引っかかる。** あるいは、跳ね上げられる。

床は完全に平らで、段差はどこにもない。それでも起きる。

### 原因

球が三角形 T1 の上を滑って、T2 との境界に近づいたとする。

境界をまたぐ瞬間、球は T2 とも接触する。このとき **T2 が返す法線が、床の上向きではなく、辺の方向を向く**ことがある。

なぜか。第 27.2 節の `intersect(Sphere, Triangle3)` は、球の中心から三角形上の最近接点への向きを法線とする。球の中心が T2 の**面の真上にない**とき、最近接点は T2 の辺の上になる。すると法線は「辺から球の中心へ」の向きになり、これは水平成分を持つ。

**その水平成分が、球を横に弾く。** 引っかかりの正体である。

### 対処 ― 隣接情報を使う

根本的な対処は、**その辺が本当に「外側の辺」なのかを調べる**ことである。

- **境界辺**（隣に三角形がない）… 辺の法線を使ってよい。実際にそこで地形が終わっている
- **内部辺**（隣に三角形がある）… **辺の法線を使ってはいけない**。隣の三角形の面が続いているので、そこに壁はない

「内部エッジ問題」という名前は、この「内部辺なのに壁として扱ってしまう」ことから来ている。

### 隣接情報を作る

```cpp
// collision/shapes/mesh.h（続き）

// 三角形ごとの、3 辺それぞれの隣接三角形。なければ invalid_index。
inline constexpr std::uint32_t invalid_index = 0xFFFFFFFFu;

struct MeshAdjacency {
    std::vector<std::uint32_t> neighbor;   // 三角形あたり 3 つ
};

[[nodiscard]] inline MeshAdjacency
build_adjacency(const TriangleMesh& mesh) {
    // 辺（頂点添字の小さい順のペア）から、それを持つ三角形と辺番号への写像
    std::map<std::pair<std::uint32_t, std::uint32_t>,
             std::vector<std::pair<std::uint32_t, int>>> edge_map;

    const std::size_t n = mesh.triangle_count();
    for (std::uint32_t t = 0; t < n; ++t) {
        for (int e = 0; e < 3; ++e) {
            std::uint32_t i0 = mesh.index[t * 3 + e];
            std::uint32_t i1 = mesh.index[t * 3 + (e + 1) % 3];
            if (i0 > i1) std::swap(i0, i1);
            edge_map[{i0, i1}].emplace_back(t, e);
        }
    }

    MeshAdjacency adj;
    adj.neighbor.assign(n * 3, invalid_index);

    for (const auto& [edge, users] : edge_map) {
        if (users.size() != 2) continue;         // 境界辺、または非多様体
        const auto [t0, e0] = users[0];
        const auto [t1, e1] = users[1];
        adj.neighbor[t0 * 3 + e0] = t1;
        adj.neighbor[t1 * 3 + e1] = t0;
    }
    return adj;
}
```

**`std::map` を使っている。** この関数はメッシュの読み込み時に一度だけ呼ばれ、判定のホットパスでは呼ばれない。第 13.4 節の凸包と同じ判断である。**確保を避けるべき場所とそうでない場所を区別する。**

`users.size() != 2` を弾いているのは、境界辺（1 つ）と非多様体な辺（3 つ以上）を除外するためである。

### 法線を補正する

```cpp
// collision/narrow/mesh_query.h（続き）

// 接触法線を、隣接情報を使って補正する。
// 内部辺での接触なら、面法線へ寄せる。
[[nodiscard]] inline Vec3
correct_edge_normal(const TriangleMesh& mesh, const MeshAdjacency& adj,
                    std::size_t tri_index, Vec3 raw_normal, Vec3 contact_point) noexcept {
    const Triangle3 tri = mesh.triangle(tri_index);
    const auto face_n = normal(tri);
    if (!face_n) return raw_normal;

    // 面法線とほぼ一致しているなら、面での接触。補正不要
    if (dot(raw_normal, *face_n) > 0.999f) return raw_normal;

    // どの辺の近くで接触しているかを調べる
    const Vec3 v[3] = {tri.a, tri.b, tri.c};
    for (int e = 0; e < 3; ++e) {
        const Vec3 q = closest_point_on_segment(contact_point, v[e], v[(e + 1) % 3]);
        if (distance_squared(contact_point, q) > contact_slop * contact_slop) continue;

        if (adj.neighbor[tri_index * 3 + e] == invalid_index) {
            return raw_normal;      // 境界辺。辺の法線をそのまま使う
        }
        // 内部辺。面法線を使う（辺の法線を使うと引っかかる）
        return *face_n;
    }
    return raw_normal;
}
```

**「面法線とほぼ一致していれば補正不要」という早期脱出を最初に置いている。** 大半の接触は面の上で起きるので、隣接情報を調べるまでもない。

判定の閾値 `0.999f` は、角度にしておよそ 2.6 度である。それより傾いていれば、辺での接触を疑う。

### 別の対処 ― 法線を制限する

隣接情報を作るのが難しい場合（メッシュが動的に生成される、インデックスが共有されていないなど）、より簡便な対処もある。

**接触法線を、面法線から一定角度以内に制限する。**

```cpp
// 法線が面法線から離れすぎていたら、面法線へ寄せる
[[nodiscard]] inline Vec3
clamp_normal_to_face(Vec3 raw, Vec3 face_n, float max_angle_cos = 0.7f) noexcept {
    return (dot(raw, face_n) < max_angle_cos) ? face_n : raw;
}
```

**乱暴だが、実用上はかなり効く。** 隣接情報がなくても引っかかりが大幅に減る。

欠点は、本当に壁になっている境界辺でも面法線に寄せてしまうことである。地形の端で物体がすり抜ける可能性がある。

**メッシュの性質に応じて選ぶ。** 閉じた地形（境界辺がない）なら、この簡便法で十分なことが多い。

### メッシュの妥当性を検証する

メッシュは外部データとして読み込まれることが多い。**読み込み時に検証しておく**と、後の不可解な不具合を防げる。

```cpp
// collision/shapes/mesh.h（続き）

struct MeshValidation {
    std::size_t degenerate_triangles{};   // 面積がほぼゼロ
    std::size_t out_of_range_indices{};   // 頂点配列の範囲外
    std::size_t non_manifold_edges{};     // 3 枚以上の三角形が共有する辺
    std::size_t boundary_edges{};         // 隣がない辺（閉じていない）

    [[nodiscard]] bool is_usable() const noexcept {
        return out_of_range_indices == 0 && degenerate_triangles == 0;
    }
};

[[nodiscard]] inline MeshValidation validate(const TriangleMesh& mesh) {
    MeshValidation v{};

    if (mesh.index.size() % 3 != 0) ++v.out_of_range_indices;
    for (const auto i : mesh.index) {
        if (i >= mesh.vertex.size()) ++v.out_of_range_indices;
    }
    if (v.out_of_range_indices > 0) return v;   // これ以上調べても意味がない

    for (std::size_t t = 0; t < mesh.triangle_count(); ++t) {
        if (area2(mesh.triangle(t)) < min_length2) ++v.degenerate_triangles;
    }

    // 辺の共有数を数える
    std::map<std::pair<std::uint32_t, std::uint32_t>, int> count;
    for (std::size_t t = 0; t < mesh.triangle_count(); ++t) {
        for (int e = 0; e < 3; ++e) {
            std::uint32_t i0 = mesh.index[t * 3 + e];
            std::uint32_t i1 = mesh.index[t * 3 + (e + 1) % 3];
            if (i0 > i1) std::swap(i0, i1);
            ++count[{i0, i1}];
        }
    }
    for (const auto& [edge, n] : count) {
        if (n == 1) ++v.boundary_edges;
        else if (n > 2) ++v.non_manifold_edges;
    }
    return v;
}
```

**退化三角形が最も厄介である。** 面積がゼロだと法線が計算できず、`normal()` が `nullopt` を返す。判定は破綻しないが（フォールバックが働く）、その三角形は事実上「存在しない」ことになる。地形に穴が開く。

**非多様体な辺**（3 枚以上が共有）は、内部エッジの補正が機能しなくなる。`build_adjacency`（27.4 節）は `users.size() != 2` を飛ばすので、隣接情報が作られない。

**境界辺が多い**なら、それは閉じていないメッシュである。地形なら正常だが、閉じた物体のはずなら異常である。

### 実務でのパイプライン

3D のキャラクターがメッシュ地形の上を動く、という最も典型的な構成を素描しておく。第 41 章のキャラクターコントローラで本格的に扱う。

```
1. キャラクターの移動経路を覆う AABB を作る（第 10.3 節の swept）
2. その AABB と重なる三角形を BVH で絞り込む（第 32 章）
3. 絞り込んだ三角形それぞれについて：
     カプセル vs 三角形 の判定（27.2 節）
     接触があれば MeshHit に集める
4. 内部エッジの補正を適用する（27.4 節）
5. 法線が近い接触をまとめる
6. 押し戻しと壁ずり移動（第 17.3 節、第 41 章）
```

**この章が担当するのは 3 と 4 である。** 2 は第 32 章、6 は第 41 章。

**5 の「法線が近い接触をまとめる」**について補足しておく。平らな床の上では、複数の三角形と接触して同じ法線が何度も返る。素朴に全部をソルバに渡すと、床からの押し戻しが過剰になる。

```cpp
// 法線が近い接触をまとめる（最も深いものを代表とする）
inline void merge_similar_contacts(std::vector<MeshHit>& hits,
                                   float cos_threshold = 0.99f) {
    std::vector<MeshHit> merged;
    for (const auto& h : hits) {
        bool absorbed = false;
        for (auto& m : merged) {
            if (dot(m.contact.normal, h.contact.normal) > cos_threshold) {
                if (h.contact.depth > m.contact.depth) m = h;   // 深いほうを残す
                absorbed = true;
                break;
            }
        }
        if (!absorbed) merged.push_back(h);
    }
    hits.swap(merged);
}
```

**単純だが効果が大きい。** 平らな床では接触が 1 つにまとまり、角では 2〜3 個が残る。物理的に意味のある数になる。

### 内部エッジ問題

**27.4 節の主題そのものをテストにする。**

```cpp
TEST_CLASS(InternalEdge) {
public:
    // 平らな床を 2 枚の三角形で作る
    [[nodiscard]] static collision::TriangleMesh make_flat_floor() {
        collision::TriangleMesh m;
        m.vertex = {{-5,0,-5}, {5,0,-5}, {5,0,5}, {-5,0,5}};
        m.index  = {0,1,2,  0,2,3};    // 対角線 0-2 が内部辺
        return m;
    }

    TEST_METHOD(平らな床を滑らせても法線が暴れないこと) {
        const auto mesh = make_flat_floor();
        const auto adj  = collision::build_adjacency(mesh);

        std::vector<collision::MeshHit> hits;
        int bad = 0;

        // 対角線（内部辺）をまたぐように球を動かす
        for (int i = 0; i <= 400; ++i) {
            const float t = static_cast<float>(i) / 400.0f;
            const collision::Sphere s{{-3.0f + 6.0f * t, 0.45f, -3.0f + 6.0f * t}, 0.5f};

            collision::collide(s, mesh, hits);
            for (const auto& h : hits) {
                const Vec3 n = collision::correct_edge_normal(
                    mesh, adj, h.triangle_index, h.contact.normal, h.contact.point);

                // 補正後の法線は、ほぼ真下（球 → 床）を向いているはず
                if (collision::dot(n, Vec3{0,-1,0}) < 0.99f) ++bad;
            }
        }

        Logger::WriteMessage(std::format("法線が暴れた回数: {}\n", bad).c_str());
        Assert::AreEqual(0, bad, L"平らな床で法線が上向き以外を向いた");
    }

    TEST_METHOD(補正しないと法線が暴れること) {
        // 対策の効果を示すための対照実験
        const auto mesh = make_flat_floor();
        std::vector<collision::MeshHit> hits;
        int bad = 0;

        for (int i = 0; i <= 400; ++i) {
            const float t = static_cast<float>(i) / 400.0f;
            const collision::Sphere s{{-3.0f + 6.0f * t, 0.45f, -3.0f + 6.0f * t}, 0.5f};
            collision::collide(s, mesh, hits);
            for (const auto& h : hits) {
                if (collision::dot(h.contact.normal, Vec3{0,-1,0}) < 0.99f) ++bad;
            }
        }

        Logger::WriteMessage(std::format("補正なしで法線が暴れた回数: {}\n", bad).c_str());
        // 補正なしでは必ず暴れる。暴れなければテストの配置が悪い
        Assert::IsTrue(bad > 0, L"内部エッジ問題が再現していない");
    }

    TEST_METHOD(境界辺では法線を補正しないこと) {
        // 床の端では、辺の法線をそのまま使うべき
        const auto mesh = make_flat_floor();
        const auto adj  = collision::build_adjacency(mesh);

        // 端（x = 5）の外側に球を置く
        const collision::Sphere s{{5.4f, 0.2f, 0.0f}, 0.5f};
        std::vector<collision::MeshHit> hits;
        collision::collide(s, mesh, hits);

        Assert::IsTrue(!hits.empty(), L"端で接触していない");
        for (const auto& h : hits) {
            const Vec3 n = collision::correct_edge_normal(
                mesh, adj, h.triangle_index, h.contact.normal, h.contact.point);
            // 境界辺なので、水平成分を持つ法線が保たれるべき
            Assert::IsTrue(std::fabs(n.x) > 0.1f,
                           L"境界辺なのに法線が面法線へ寄せられた");
        }
    }

    TEST_METHOD(隣接情報が正しく構築されること) {
        const auto mesh = make_flat_floor();
        const auto adj  = collision::build_adjacency(mesh);

        int internal = 0, boundary = 0;
        for (std::size_t i = 0; i < adj.neighbor.size(); ++i) {
            if (adj.neighbor[i] == collision::invalid_index) ++boundary;
            else ++internal;
        }
        // 三角形 2 枚、辺は合計 6 本。うち共有辺 1 本が両側から数えられて 2
        Assert::AreEqual(2, internal,  L"内部辺の数が想定と違う");
        Assert::AreEqual(4, boundary, L"境界辺の数が想定と違う");
    }
};
```

**「補正しないと法線が暴れること」を確認するテスト**が、対照実験として重要である。対策の効果を示すには、対策なしで問題が起きることを先に確認しなければならない。

このテストが失敗するなら、それは「内部エッジ問題が再現していない」ということであり、**配置が悪い**（対策のテストも意味がなくなる）。第 9.6 節で「既知の制約をテストとして残す」と述べたのと、同じ発想である。

## この章のまとめ

- **メラー＝トランボア法**は、レイと三角形の交差を重心座標で解く。除算は一回、早期脱出は三段階
- 裏面カリングは呼び出し側に選ばせる。視線判定と当たり判定で要求が違う
- 重心座標の `w` は `1 − u − v` で求める。独立に計算すると和が 1 からずれる（第 9.3 節と同じ）
- 点と三角形の最近接点は、**平面へ射影してから内外判定**する。3D 特有の一手間
- 球と三角形は第 9.4 節の統一実装。**フォールバックに三角形の法線を渡す**のが良い設計
- 線分と三角形の最近接点は 5 通り（端点 2 ＋ 辺 3）を全部調べる。第 25.2 節がここで報われる
- メッシュは頂点配列＋インデックス配列。この章は総当たり、高速化は第 32 章
- **内部エッジ問題**：三角形の継ぎ目で、辺の法線が水平成分を持ち、物体を横に弾く
- 対処は隣接情報を作り、内部辺なら面法線を使うこと。簡便法として「法線を面法線から一定角度に制限する」もある
- テストは対照実験で。**対策なしで問題が起きることを先に確認する**

### 落とし穴と練習問題

**落とし穴 1：巻き方向の不統一。**　メッシュを読み込むとき、法線がすべて裏返っていないか検証する。

**落とし穴 2：複数の接触を素朴に全部適用する。**　二重に押し戻されて物体が飛ぶ。ソルバに渡す。

**落とし穴 3：内部エッジ問題を「たまに引っかかる」で片付ける。**　原因が特定できる現象であり、対策もある。

---

**練習問題 27-1**　メラー＝トランボア法を、クラメルの公式から自分で導出してみよう。`det = dot(e1, cross(dir, e2))` がスカラー三重積になることを確認してほしい。

**練習問題 27-2**　`cull_back_face` を有効にしたときの速度差を測ろう。閉じたメッシュに対するレイキャストでは、半分の三角形が裏面になるはずである。

**練習問題 27-3**　カプセルと三角形の判定を、`closest_points_segment_triangle` を使って書こう。球と三角形の実装（27.2 節）と同じ形になるはずである。

**練習問題 27-4**　27.4 節の簡便法（`clamp_normal_to_face`）と隣接情報を使う方法を、同じシナリオで比較しよう。境界辺での挙動にどんな差が出るだろうか。

**練習問題 27-5**（発展）　三角形メッシュとカプセルのマニフォールドを生成しよう。複数の三角形と接触している場合、接触点をどう統合すべきか考えてみてほしい。法線が近いものをまとめる、という方針が一般的である。
