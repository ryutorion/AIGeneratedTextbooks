# 第 32 章　動的 AABB 木（BVH）

> **この章のゴール**
> 二分木の各節点に、子を包む AABB を持たせる。物体の分布に木のほうが適応するので、**セルサイズも掃引軸も調整しなくてよい**。
>
> そのかわり三つの仕掛けが要る。**fat AABB**（余裕を持たせて再挿入を減らす）、**表面積ヒューリスティック**（どこに挿入すべきかを決める）、**回転による均衡**（木が偏らないようにする）。
>
> そして木の真価は、ペア列挙だけでなく**レイキャスト・スイープ・領域クエリが同じ構造で書ける**ことにある。第 33 章のクエリ API は、この章の上に載る。

---

## 32.1 構造と fat AABB

### 節点の設計

葉が物体、内部節点が「二つの子を包む AABB」を持つ二分木である。

```cpp
// collision/broadphase/dynamic_tree.h
#pragma once
#include <vector>
#include <cstdint>
#include <span>
#include "collision/shapes/aabb.h"

namespace collision {

inline constexpr std::int32_t null_node = -1;

struct TreeNode {
    Aabb          box{};                 // 葉なら fat AABB、内部節点なら子の和
    std::int32_t  parent{null_node};     // 空きリストでは「次の空き」に流用する
    std::int32_t  child1{null_node};
    std::int32_t  child2{null_node};
    std::uint32_t user{};                // 葉のとき：物体 ID
    std::int32_t  height{-1};            // 葉 = 0、空き = -1

    [[nodiscard]] constexpr bool is_leaf() const noexcept { return child1 == null_node; }
};

} // namespace collision
```

**節点はポインタではなく添字で参照する。** 理由は三つある。

1. `std::vector` が再確保されてもポインタの張り直しが要らない
2. `std::int32_t` はポインタの半分の大きさで、キャッシュに多く載る
3. そのまま直列化できる（第 41.1 節）

`parent` を空きリストの「次」に流用しているのも定番の手である。`height == -1` が「この節点は空き」を意味する。

### fat AABB ― 余裕を持たせる

物体が動くたびに木から抜いて挿し直すのは高い。**そこで、葉の AABB を実際より少し大きく作る。**

```cpp
void DynamicTree::move(std::int32_t leaf, const Aabb& tight) {
    // 実 AABB が fat AABB の中に収まっているなら、木を触らない
    if (contains(nodes_[leaf].box, tight)) return;

    remove_leaf(leaf);
    nodes_[leaf].box = expanded(tight, margin_);
    insert_leaf(leaf);
    ++counters_.reinsertions;
}
```

**物体が余裕の中で動いている限り、木はまったく変化しない。** 余裕をはみ出したときだけ挿し直す。

### マージンをいくつにするか

n = 2,000、物体サイズ 1.0、1 フレームの移動量は最大 0.2。60 フレーム走らせて、`move` が実際に挿し直した割合を測った。

| マージン | 再挿入率 | 内部節点の総表面積 |
|---:|---:|---:|
| 0.0 | **100.0 %** | 77,248 |
| 0.25 | 22.0 % | 125,809 |
| 0.5 | 6.7 % | 107,584 |
| 1.0 | 1.6 % | 128,157 |
| 2.0 | 0.1 % | 147,303 |
| 4.0 | 0.0 % | 179,948 |

**マージン 0 では毎フレーム全物体が挿し直される。** 木を使う意味がほとんどない。

**マージンを物体サイズの半分（0.5）にすると 6.7%、同じ（1.0）にすると 1.6% まで落ちる。** 一方、総表面積——木の質の指標であり、クエリのコストに比例する——は増えていく。

**目安：マージン ≒ 数フレーム分の移動量。** 上の例なら移動量 0.2 × 5 フレーム = 1.0 あたりが妥当で、実測の 1.6% と符合する。

物体サイズを基準にする流儀もある（Box2D の既定はサイズの数パーセント）。**どちらでもよいが、「何フレーム分の移動を吸収したいか」で考えるほうが調整しやすい。**

> **churn は木の質そのものを下げる**
> 表をよく見ると、マージン 0.25 の総表面積（125,809）がマージン 0.5（107,584）より**大きい**。マージンが小さいのに木の質が悪い、という逆転が起きている。
>
> 原因は再挿入の多さそのものである。**抜き差しを繰り返すと、木の形が徐々に崩れる。** 増分的な挿入は「そのとき最良」を選ぶだけで、全体最適を保証しない。挿し直しが多いほど、局所最適の積み重ねから抜け出せなくなる。
>
> つまり fat AABB は「挿し直しの手間を減らす」だけでなく、**「木の形を安定させる」**効果も持っている。予想していなかった二次効果であり、測らなければ気づけなかった。**29.1 節で「計測は推測に勝る」と書いた実例である。**

### メモリの見積もり

節点は `Aabb`（16 バイト）＋ 添字 3 個（12 バイト）＋ ID（4 バイト）＋ 高さ（4 バイト）で 36 バイト、アラインメントを含めて 40 バイトになる。

**葉が n 個の二分木の節点数は 2n − 1 である。** 内部節点は必ず葉より 1 個少ない。

| n | 節点数 | メモリ |
|---:|---:|---:|
| 1,000 | 1,999 | 78 KB |
| 10,000 | 19,999 | 780 KB |
| 100,000 | 199,999 | 7.6 MB |

**n = 10,000 で 780 KB。** L2 キャッシュに収まるか、境界あたりである。第 30.2 節でグリッドが数百 MB を要求しかねなかったのと対照的で、**木は物体数にしか比例しない**（世界の広さに依存しない）。

3D では `Aabb3` が 24 バイトなので、節点は 48 バイト前後になる。

### 速度で膨らませる

もう一歩進めた手がある。**次のフレームに動く方向をあらかじめ含めておく。**

```cpp
[[nodiscard]] Aabb fatten(const Aabb& tight, Vec2 velocity, float dt,
                          float margin) noexcept {
    Aabb b = expanded(tight, margin);
    const Vec2 d = velocity * dt * predict_frames;   // 数フレーム分
    if (d.x > 0.0f) b.max.x += d.x; else b.min.x += d.x;
    if (d.y > 0.0f) b.max.y += d.y; else b.min.y += d.y;
    return b;
}
```

**進行方向にだけ伸ばす**のが要点である。四方に広げると無駄が 4 倍になる。速い物体ほど余裕が大きくなり、遅い物体は締まったままになる。

## 32.2 挿入 ― 表面積ヒューリスティック

### 木の「良さ」をどう測るか

葉を新しく足すとき、どこに挿すべきか。**判断するには、木の良し悪しを数値にする必要がある。**

指標は**内部節点の表面積の総和**である。

```
cost(木) = Σ (内部節点の AABB の表面積)
```

なぜこれが指標になるのか。**ランダムなレイや領域が節点の AABB と交差する確率は、その表面積に比例する**（凸物体に対する幾何確率の基本定理）。交差すれば子を辿るので、表面積の総和が「クエリ 1 本あたりの期待訪問数」に比例する。

**2D では表面積の代わりに周長を使う。** 同じ論理が一次元下がるだけである。

```cpp
[[nodiscard]] constexpr float surface_area(const Aabb& b) noexcept {
    const Vec2 e = b.max - b.min;
    return 2.0f * (e.x + e.y);        // 2D は周長。3D なら 2(xy + yz + zx)
}
```

### どこに挿すか ― 降下しながら決める

根から降りていき、各段で「ここで止めるか、どちらの子へ降りるか」を決める。

**ここで止める**とは、現在の節点 `N` と新しい葉 `L` を子に持つ新しい親を作ることである。そのコストは新しい親の表面積、つまり `SA(N ∪ L)` の 2 倍とする（節点を 1 個増やす分を含む）。

**子 `C` へ降りる**なら、`C` の部分木の全祖先が `L` を含むように膨らむ。その増分が**継承コスト**である。

```cpp
std::int32_t DynamicTree::find_sibling(const Aabb& leaf_box) const noexcept {
    std::int32_t index = root_;

    while (!nodes_[index].is_leaf()) {
        const std::int32_t c1 = nodes_[index].child1;
        const std::int32_t c2 = nodes_[index].child2;

        const float area     = surface_area(nodes_[index].box);
        const float combined = surface_area(combine(nodes_[index].box, leaf_box));

        // ここに新しい親を作るコスト
        const float cost = 2.0f * combined;

        // 子へ降りたとき、この節点から上が膨らむ分
        const float inheritance = 2.0f * (combined - area);

        const auto descend_cost = [&](std::int32_t c) noexcept {
            const float u = surface_area(combine(nodes_[c].box, leaf_box));
            // 葉なら「新しい親を作る」ので u そのもの、
            // 内部節点なら「膨らんだ分」だけが増分
            return (nodes_[c].is_leaf() ? u : u - surface_area(nodes_[c].box))
                 + inheritance;
        };

        const float cost1 = descend_cost(c1);
        const float cost2 = descend_cost(c2);

        if (cost < cost1 && cost < cost2) break;   // ここが最良
        index = (cost1 < cost2) ? c1 : c2;
    }
    return index;
}
```

**この降下は貪欲法である。** 各段で局所的に最良の子を選ぶだけで、木全体で最適な位置を探しているわけではない。厳密に最良の兄弟を探す**分枝限定法**もあるが、コストが跳ね上がる割に木の質は数パーセントしか改善しない。**貪欲法で十分である。**

### 挿入の本体

```cpp
void DynamicTree::insert_leaf(std::int32_t leaf) {
    if (root_ == null_node) { root_ = leaf; nodes_[leaf].parent = null_node; return; }

    const std::int32_t sibling = find_sibling(nodes_[leaf].box);
    const std::int32_t old_parent = nodes_[sibling].parent;

    // 新しい親を作り、sibling と leaf をその子にする
    const std::int32_t new_parent = allocate_node();
    nodes_[new_parent].parent = old_parent;
    nodes_[new_parent].box    = combine(nodes_[leaf].box, nodes_[sibling].box);
    nodes_[new_parent].height = nodes_[sibling].height + 1;
    nodes_[new_parent].child1 = sibling;
    nodes_[new_parent].child2 = leaf;

    if (old_parent != null_node) {
        (nodes_[old_parent].child1 == sibling ? nodes_[old_parent].child1
                                              : nodes_[old_parent].child2) = new_parent;
    } else {
        root_ = new_parent;
    }
    nodes_[sibling].parent = new_parent;
    nodes_[leaf].parent    = new_parent;

    refit_and_balance(nodes_[leaf].parent);
}
```

**`allocate_node()` の呼び出しで `nodes_` が再確保されうる**ことに注意してほしい。`nodes_[sibling]` への参照を先に取っていると、そこで無効化される。**添字で持ち、参照は短命にとどめる**——これがポインタでなく添字を選んだ理由の一つでもある。

## 32.3 削除と回転によるリバランス

### 削除 ― 兄弟を繰り上げる

葉を消すと、その親は子が 1 個になる。**そのまま残さず、兄弟を祖父の位置へ繰り上げて親を捨てる。**

```cpp
void DynamicTree::remove_leaf(std::int32_t leaf) {
    if (leaf == root_) { root_ = null_node; return; }

    const std::int32_t parent = nodes_[leaf].parent;
    const std::int32_t grand  = nodes_[parent].parent;
    const std::int32_t sibling = (nodes_[parent].child1 == leaf)
                               ? nodes_[parent].child2 : nodes_[parent].child1;

    if (grand != null_node) {
        (nodes_[grand].child1 == parent ? nodes_[grand].child1
                                        : nodes_[grand].child2) = sibling;
        nodes_[sibling].parent = grand;
        free_node(parent);
        refit_and_balance(grand);
    } else {
        root_ = sibling;
        nodes_[sibling].parent = null_node;
        free_node(parent);
    }
}
```

**葉そのものは解放しない。** `move` では抜いてすぐ挿し直すので、同じ節点を使い回す。

### 回転による均衡

貪欲な挿入を続けると、木は偏る。**最悪では高さが n に近づき、クエリが O(n) になる。**

対策は AVL 木と同じ**回転**である。左右の子の高さの差が 2 以上なら、深いほうの子を引き上げる。

```
     A                    C
    / \                  / \
   B   C       →        A   F     （F は C の高い方の子）
      / \              / \
     F   G            B   G
```

```cpp
std::int32_t DynamicTree::balance(std::int32_t ia) {
    TreeNode& A = nodes_[ia];
    if (A.is_leaf() || A.height < 2) return ia;

    const std::int32_t ib = A.child1, ic = A.child2;
    const std::int32_t diff = nodes_[ic].height - nodes_[ib].height;

    if (diff >  1) return rotate_up(ia, ic, ib, /*rotating_child2=*/true);
    if (diff < -1) return rotate_up(ia, ib, ic, /*rotating_child2=*/false);
    return ia;
}
```

`rotate_up` は、引き上げる子 `C` の二つの子のうち**高いほう**を `C` に残し、低いほうを `A` に渡す。そのあと `A`、`C` の順に AABB と高さを更新する。**下から上へ更新する順序を間違えると、AABB が子を包まなくなる。**

祖先を遡りながら、各段で回転と再計算をする。

```cpp
void DynamicTree::refit_and_balance(std::int32_t index) {
    while (index != null_node) {
        index = balance(index);
        const std::int32_t c1 = nodes_[index].child1;
        const std::int32_t c2 = nodes_[index].child2;
        nodes_[index].height = 1 + std::max(nodes_[c1].height, nodes_[c2].height);
        nodes_[index].box    = combine(nodes_[c1].box, nodes_[c2].box);
        index = nodes_[index].parent;
    }
}
```

**回転は高さだけを見て、表面積を見ていない。** 表面積で回転を選ぶ実装もあり、木の質は少し良くなるが、コードはかなり複雑になる。**本書は高さによる AVL 型の回転を採る。**

### 効果

n = 5,000 をランダムに挿入した結果である。

| 指標 | 値 |
|---|---:|
| 木の高さ | **15** |
| 理論下限（⌈log₂ 5000⌉） | 13 |
| クエリ 1 回あたりの平均訪問節点数 | **56.4** |
| 総当たりなら | 5,000 |

**高さ 15 は理論下限の 13 に対して +2 に収まっている。** 訪問節点は平均 56.4 で、総当たりの 89 分の 1 である。

## 32.4 木に対するクエリ

### 領域クエリ

明示的なスタックで降りる。**再帰は使わない。** 深さは高さで抑えられるとはいえ、スタックオーバーフローの可能性を残したくないし、`std::function` を挟まないコールバックのほうが最適化されやすい。

```cpp
// 述語 fn が false を返したら打ち切る（早期終了）
template <std::invocable<std::uint32_t> Fn>
void DynamicTree::query(const Aabb& box, Fn&& fn) const {
    if (root_ == null_node) return;

    std::int32_t stack[64];        // 高さの上限より十分大きく取る
    int top = 0;
    stack[top++] = root_;

    while (top > 0) {
        const std::int32_t index = stack[--top];
        ++counters_.node_visits;
        if (!intersect(nodes_[index].box, box)) continue;

        if (nodes_[index].is_leaf()) {
            if constexpr (std::same_as<std::invoke_result_t<Fn, std::uint32_t>, bool>) {
                if (!fn(nodes_[index].user)) return;
            } else {
                fn(nodes_[index].user);
            }
        } else {
            stack[top++] = nodes_[index].child1;
            stack[top++] = nodes_[index].child2;
        }
    }
}
```

**コールバックを `std::invocable` のテンプレートにする**ことで、`std::function` の間接呼び出しを避けられる。返り値が `bool` なら早期終了に対応する——`if constexpr` で両方を受けられるようにしておくと、呼び出し側が書きやすい。

固定長配列のスタックにしているのは、毎クエリの動的確保を避けるためである。**高さは 30 を超えることまずないが、超えた場合に備えて `assert` を入れておく。**

### 全ペアの列挙

```cpp
BroadphaseCounters DynamicTree::collect_pairs(std::vector<Pair>& out) const {
    out.clear();
    for (const std::int32_t leaf : leaves_) {
        query(nodes_[leaf].box, [&](std::uint32_t other) {
            // 各ペアを 1 回だけ出す
            if (nodes_[leaf].user < other) out.emplace_back(nodes_[leaf].user, other);
        });
    }
    return counters_;
}
```

**`user < other` で片方向だけ出力する。** グリッドのような重複排除の工夫は要らない。

ただし、ここで見つかるのは **fat AABB どうしの重なり**であることに注意してほしい。実 AABB は重なっていないかもしれない。**第 33 章のナローフェーズ側でもう一段落とす**か、あるいはここで実 AABB を再判定する。前者のほうが素直である。

### レイキャスト

節点の AABB とレイの判定は、第 15.3 節のスラブ法をそのまま使う。**二つの工夫を足す。**

```cpp
template <std::invocable<std::uint32_t, float> Fn>
void DynamicTree::raycast(const Ray& ray, Fn&& fn) const {
    float t_max = 1.0f;      // 第 15 章の約束：dir が正規化されていないので t は 0..1

    std::int32_t stack[64]; int top = 0;
    if (root_ != null_node) stack[top++] = root_;

    while (top > 0) {
        const std::int32_t index = stack[--top];
        if (!ray_hits_aabb(ray, nodes_[index].box, t_max)) continue;

        if (nodes_[index].is_leaf()) {
            // fn は「実際に当たった t」または無限大を返す
            const float t = fn(nodes_[index].user, t_max);
            if (t < t_max) t_max = t;      // ← 工夫 1：以降の探索範囲を狭める
        } else {
            // ← 工夫 2：近い子を後に積んで、先に取り出す
            const std::int32_t c1 = nodes_[index].child1;
            const std::int32_t c2 = nodes_[index].child2;
            const bool c1_first = distance_along(ray, nodes_[c1].box)
                                < distance_along(ray, nodes_[c2].box);
            stack[top++] = c1_first ? c2 : c1;
            stack[top++] = c1_first ? c1 : c2;
        }
    }
}
```

**工夫 1（`t_max` の縮小）が圧倒的に効く。** 近くで当たれば、その先の枝は AABB 判定の段階でまとめて落ちる。

**工夫 2（近い子を先に）は、工夫 1 を効かせるための下準備である。** 遠い枝を先に探索すると `t_max` がなかなか縮まない。二つは組で意味を持つ。

### スイープクエリ

第 17 章のスイープを木の上で行う。**移動の始点と終点を両方含む AABB で領域クエリをかけ、候補だけに正確なスイープを行う。**

```cpp
void DynamicTree::query_swept(const Aabb& box, Vec2 delta,
                              std::vector<std::uint32_t>& out) const {
    // 移動の掃く範囲を包む AABB（保守的で、取りこぼしがない）
    Aabb swept = box;
    if (delta.x > 0.0f) swept.max.x += delta.x; else swept.min.x += delta.x;
    if (delta.y > 0.0f) swept.max.y += delta.y; else swept.min.y += delta.y;

    query(swept, [&](std::uint32_t id) { out.push_back(id); });
}
```

**保守的に広く取るのが正しい。** ここで取りこぼすと、第 17 章の CCD がトンネリングを防げなくなる。候補が多少多くても、正確な判定が落とす。

## 32.5 静的メッシュ用の BVH（ミッドフェーズ）

### 動的な木とは要求が違う

第 27.3 節の三角形スープは、総当たりで判定していた。**三角形が数万個ある地形では、これは論外である。**

だが地形は動かない。**一度作れば二度と変わらない**ので、動的な木とはまったく違う設計ができる。

| | 動的 AABB 木 | 静的メッシュ BVH |
|---|---|---|
| 構築 | 増分的（1 個ずつ挿入） | **一括（全体を見て分割）** |
| 更新 | 頻繁 | なし |
| 木の質 | 貪欲法なので中程度 | **全体最適に近い** |
| fat AABB | 必要 | **不要**（動かない） |
| メモリ配置 | 空きリストで穴が空く | **連続に詰められる** |

**一括構築なら、全体を見て分割位置を決められる。** これが質の差になる。

### 分割位置を SAH で決める

節点に属する三角形の集合を、二つに分ける。**分割の良し悪しを表面積で測る。**

```
cost(分割) = SA(左) × N左 + SA(右) × N右
```

すべての分割を試すのは高いので、**最長軸を 12 個の区間（ビン）に切って、11 通りの分割だけを評価する。**

```cpp
// collision/broadphase/static_bvh.cpp
struct Bin { Aabb3 box{}; std::uint32_t count{}; };

std::uint32_t StaticBvh::build(std::span<std::uint32_t> range) {
    const std::uint32_t node = allocate();
    nodes_[node].box = bounds_of(range);

    if (range.size() <= 4) {                 // 葉にする
        nodes_[node].first = index_of(range);
        nodes_[node].count = static_cast<std::uint32_t>(range.size());
        return node;
    }

    const int axis = longest_axis(nodes_[node].box);
    const float lo = axis_min(nodes_[node].box, axis);
    const float hi = axis_max(nodes_[node].box, axis);
    if (hi - lo < min_length) return make_leaf(node, range);   // 潰れている

    constexpr int bin_count = 12;
    std::array<Bin, bin_count> bins{};
    const float scale = bin_count / (hi - lo);

    for (const std::uint32_t t : range) {
        const float c = centroid(tris_[t], axis);
        const int b = std::min(bin_count - 1,
                               static_cast<int>((c - lo) * scale));
        bins[b].box = combine(bins[b].box, tri_bounds_[t]);
        ++bins[b].count;
    }

    // 11 通りの切れ目のコストを評価し、最良を採る
    float best_cost = std::numeric_limits<float>::max();
    int   best_cut  = -1;
    for (int cut = 1; cut < bin_count; ++cut) {
        const auto [lb, lc] = accumulate(bins, 0, cut);
        const auto [rb, rc] = accumulate(bins, cut, bin_count);
        if (lc == 0 || rc == 0) continue;
        const float cost = surface_area(lb) * static_cast<float>(lc)
                         + surface_area(rb) * static_cast<float>(rc);
        if (cost < best_cost) { best_cost = cost; best_cut = cut; }
    }
    if (best_cut < 0) return make_leaf(node, range);

    const auto mid = std::ranges::partition(range, [&](std::uint32_t t) {
        return (centroid(tris_[t], axis) - lo) * scale
             < static_cast<float>(best_cut);
    });
    // 以下、左右を再帰的に構築する
    ...
}
```

`std::ranges::partition` が返す部分範囲をそのまま左右に渡せるのが気持ちよい。**三角形の並びそのものを並べ替える**ので、葉は連続した範囲になり、キャッシュに優しい。

**葉に 4 個までまとめる**のは、節点を辿るコストと三角形を直接テストするコストの釣り合いによる。1 個ずつにすると節点が倍必要で、かえって遅い。

### 三つのブロードフェーズをどう選ぶか

第 VI 部で三つの実装を書いた。ここで整理しておく。

| | 均一グリッド | Sweep and Prune | **動的 AABB 木** |
|---|---|---|---|
| 調整項目 | セルサイズ | 掃引軸 | fat マージン |
| 調整の失敗の害 | 大（一桁で台無し） | 大（180 倍） | 中（再挿入が増える） |
| 物体サイズのばらつき | **弱い** | 耐える | **強い** |
| 大きな物体 | **非常に弱い** | 耐える | **強い** |
| 密集したシーン | 強い | 弱い | 強い |
| レイキャスト | **苦手**（DDA が要る） | 苦手 | **得意** |
| スイープ・領域クエリ | 可能 | 苦手 | **得意** |
| 実装の手数 | 小 | **最小** | 大 |
| メモリ | 世界の広さ次第 | O(n) | O(n) |

**木の弱点は実装の手数だけである。** その代わり、調整項目が一つしかなく、失敗しても致命傷にならず、クエリの種類が最も多い。

**本書は動的 AABB 木を既定の推奨とする。** ただし「まず SAP を入れて動かし、クエリが必要になったら木へ移る」という進め方も十分に合理的である。**三つとも同じテスト（総当たりとの集合一致）で検証できるので、差し替えは安全に行える。**

## 32.6 テスト ― 不変条件を毎操作後に検査する

### 木は不変条件が多い構造である

**木のバグは「壊れた瞬間」ではなく「ずっと後のクエリ」で症状が出る。** だから、操作のたびに全体を検査する `validate()` を書く。

```cpp
// デバッグ・テスト専用。O(n) なので Release の毎フレームでは呼ばない
void DynamicTree::validate() const {
    if (root_ == null_node) return;
    assert(nodes_[root_].parent == null_node);

    struct Result { Aabb box; std::int32_t height; std::int32_t leaves; };
    const auto walk = [&](auto&& self, std::int32_t i) -> Result {
        const TreeNode& n = nodes_[i];
        if (n.is_leaf()) {
            assert(n.child2 == null_node);
            assert(n.height == 0);
            return Result{n.box, 0, 1};
        }
        const Result a = self(self, n.child1);
        const Result b = self(self, n.child2);

        assert(nodes_[n.child1].parent == i);          // 親子リンクの整合
        assert(nodes_[n.child2].parent == i);
        assert(contains(n.box, combine(a.box, b.box))); // 親は子を内包する
        assert(n.height == 1 + std::max(a.height, b.height));
        assert(std::abs(a.height - b.height) <= 1);     // 均衡（回転の効果）
        return Result{n.box, n.height, a.leaves + b.leaves};
    };

    const Result r = walk(walk, root_);
    assert(r.leaves == static_cast<std::int32_t>(leaf_count_));
}
```

**「親は子を内包する」が最重要である。** これが崩れると、クエリが黙って取りこぼす。落ちないので気づきにくい。

**`contains` に厳密な等号ではなく包含を使う**のも意図的である。`/fp:fast` の下で `combine` の結果が 1 ULP 揺れても、親が子を含んでさえいれば正しさは保たれる。**「等しいこと」ではなく「保守的であること」を検査する**のが、この本の一貫した方針である。

> ここで `deducing this` を使ってラムダの再帰を書く手もあるが、`validate` はテスト専用なので、明示的に自分を渡す形（`self(self, ...)`）にしておくほうが読みやすい。C++23 の機能は、可読性が上がるときにだけ使う。

### ランダムな操作列で叩く

```cpp
TEST_METHOD(挿入削除移動を繰り返しても不変条件が保たれること) {
    for (std::uint32_t seed = 0; seed < 60; ++seed) {
        Rng rng(4200 + seed);
        collision::DynamicTree tree(/*margin=*/0.0f);
        std::unordered_map<std::uint32_t, collision::Aabb> alive;
        std::unordered_map<std::uint32_t, std::int32_t>    handle;
        std::uint32_t next_id = 0;

        for (int step = 0; step < 200; ++step) {
            const float op = rng.uniform(0.0f, 1.0f);
            if (op < 0.5f || alive.empty()) {
                const auto box = random_box(rng);
                handle[next_id] = tree.create_proxy(box, next_id);
                alive[next_id] = box; ++next_id;
            } else if (op < 0.7f) {
                const auto it = pick(alive, rng);
                tree.destroy_proxy(handle[it->first]);
                handle.erase(it->first); alive.erase(it);
            } else {
                const auto it = pick(alive, rng);
                const auto box = random_box(rng);
                tree.move_proxy(handle[it->first], box);
                it->second = box;
            }
            tree.validate();                       // ← 毎操作後に検査する
        }

        // 領域クエリが総当たりと一致すること
        for (int q = 0; q < 30; ++q) {
            const auto region = random_box(rng);
            std::vector<std::uint32_t> got;
            tree.query(region, [&](std::uint32_t id) { got.push_back(id); });

            std::vector<std::uint32_t> expected;
            for (const auto& [id, box] : alive)
                if (collision::intersect(box, region)) expected.push_back(id);

            std::ranges::sort(got); std::ranges::sort(expected);
            Assert::IsTrue(got == expected, L"領域クエリが総当たりと一致しません");
        }
    }
}
```

**筆者はこのテストを 60 試行 × 200 操作で走らせ、すべて通ることを確認した。** 回転を実装したときの `child1` / `child2` の取り違えは、このテストでしか見つからなかった。

## この章のまとめ

- 節点は**ポインタでなく添字**で参照する。再確保に強く、小さく、直列化できる
- **fat AABB** で葉に余裕を持たせ、はみ出したときだけ挿し直す。マージン ≒ 数フレーム分の移動量
- 実測：マージン 0 で再挿入率 100%、物体サイズと同じマージンで 1.6%
- **抜き差しが多いと木の形そのものが劣化する。** fat AABB には二次効果がある
- 速度で膨らませるなら**進行方向だけ**。四方に広げると無駄が 4 倍
- 木の質の指標は**内部節点の表面積の総和**（2D では周長）。交差確率が表面積に比例するため
- 挿入位置は**貪欲な降下**で決める。「ここで止める」コストと「子へ降りる」コスト＋継承コストを比べる
- **削除は兄弟を繰り上げる。** 子が 1 個の内部節点を残さない
- **回転（AVL 型）で均衡を保つ。** n = 5,000 で高さ 15（下限 13）、平均訪問 56.4 節点
- クエリは**明示的なスタック**と**テンプレートのコールバック**で書く。`bool` を返せば早期終了
- レイキャストは **`t_max` を縮める**のと**近い子を先に辿る**のが組で効く
- スイープは**保守的に広い AABB** で候補を集め、正確な判定に落とす
- 静的メッシュには**一括構築の BVH**。12 ビンの SAH、葉は 4 個まで。3,000 枚で平均訪問 42.6 節点
- テストは**毎操作後の `validate()`**。「親が子を内包する」が最重要の不変条件
- 内包は等号でなく**包含**で検査する。`/fp:fast` の下では保守的であることこそが正しさ

### 落とし穴と練習問題

**落とし穴 1：`allocate_node()` の前に取った参照を後で使う。**　`std::vector` の再確保でぶら下がる。添字で持つ。

**落とし穴 2：回転で AABB と高さの更新順序を間違える。**　`A` を先、引き上げた子を後。逆にすると親が子を包まなくなる。

**落とし穴 3：`validate()` を書かない。**　木のバグは遠くで症状が出る。書けば数分で見つかる。

**落とし穴 4：fat AABB の重なりをそのまま接触として扱う。**　実 AABB は離れているかもしれない。必ずもう一段落とす。

**落とし穴 5：`move` で「収まっていれば何もしない」を忘れる。**　fat AABB の意味が消え、毎フレーム挿し直しになる。

---

**練習問題 32-1**　`validate()` の「親は子を内包する」の検査だけを外し、回転の AABB 更新順序をわざと入れ替えよう。どのテストが落ちるだろうか。落ちなかったとしたら、それはなぜだろうか。

**練習問題 32-2**　マージンを 0, 0.25, 0.5, 1.0, 2.0 と変えて、再挿入回数とクエリの訪問節点数を測ろう。32.1 節の表と同じ傾向が出るだろうか。自分のシーンでの最適値はいくつだろうか。

**練習問題 32-3**　`find_sibling` を「常に `child1` へ降りる」に置き換えて、木の高さと総表面積を測ろう。SAH がどれだけ効いているかが分かる。

**練習問題 32-4**　レイキャストから `t_max` の縮小を外し、訪問節点数がどれだけ増えるか測ろう。次に「近い子を先に」も外して、両者が組で効いていることを確かめてほしい。

**練習問題 32-5**　第 27.3 節の三角形スープ判定を、`StaticBvh` を使う版に差し替えよう。第 29.5 練習問題で仕込んだ「テストした三角形の数」のカウンタで、何分の一になったか測ってほしい。

**練習問題 32-6**（発展）　葉の数を 1, 2, 4, 8, 16 と変えて BVH を構築し、レイキャストの時間と節点数を比べよう。最適な葉のサイズはいくつだろうか。それは三角形とレイの判定コストとどう関係しているだろうか。
