## 17.1 相対運動への還元

### 両方が動く場合

前章では「A が動き、B は静止している」場合を扱った。実際には両方が動く。

A が `delta_a`、B が `delta_b` だけ移動するとする。時刻 `t` での交差条件は、

```
0 ∈ (A + delta_a·t) ⊖ (B + delta_b·t)
```

ミンコフスキー差の中で平行移動を外に出すと、

```
= (A ⊖ B) + (delta_a - delta_b)·t
```

**`delta_a - delta_b` という一つのベクトルにまとまった。**

つまり、B を止めて A だけが `delta_a - delta_b` だけ動く、と考えてよい。これを**相対運動への還元**と呼ぶ。

### 実装

```cpp
// collision/narrow/sweep.h（続き）

namespace collision {

// スイープ判定の結果
struct SweepResult {
    float t{};          // 衝突時刻（フレーム内の比率、0〜1）
    Vec2  point{};      // 衝突位置（ワールド座標）
    Vec2  normal{};     // A から B へ向く単位法線（第 7.3 節の規約）
    bool  started_touching{false};   // 開始時点で既に交差していたか
};

using SweepHit = std::optional<SweepResult>;

// 両方が動く場合。相対運動に還元して片方を止める。
template <class A, class B>
[[nodiscard]] SweepHit sweep(const A& a, Vec2 delta_a,
                             const B& b, Vec2 delta_b) noexcept {
    return sweep(a, delta_a - delta_b, b);
}

} // namespace collision
```

一行で済む。**問題を既知の形に落とす**という手法は、第 12 章の練習問題（円 vs OBB をローカル座標へ）でも使った。本書で繰り返し現れる考え方である。

### 注意点：衝突「位置」は相対系では求まらない

還元によって衝突「時刻」は正しく求まる。だが衝突「位置」は、相対系での答えをそのまま使えない。

B を止めて考えたので、得られる位置は「B が動かなかった場合の位置」である。実際には B も動いている。

正しい衝突位置は、求めた `t` を使って元の系で計算する。

```
A の位置：a.center + delta_a · t
B の位置：b.center + delta_b · t
```

この二つから接触点を求める。17.3 節で扱う。

**時刻は相対系で、位置は元の系で。** この使い分けを忘れると、両方が動く場合にだけ接触点がずれる、という発見しにくいバグになる。

## 17.2 円のスイープ

### 円 vs 円

前章で見たとおり、`raycast(Ray, Circle)` を呼ぶだけである。法線の符号だけ調整する。

```cpp
// collision/narrow/sweep.h（続き）

[[nodiscard]] inline SweepHit
sweep(const Circle& a, Vec2 delta, const Circle& b) noexcept {
    // 開始時点で既に交差しているか
    if (overlaps(a, b)) {
        const auto c = intersect(a, b);
        return SweepResult{
            .t = 0.0f,
            .point = c ? c->point : a.center,
            .normal = c ? c->normal : Vec2{1.0f, 0.0f},
            .started_touching = true,
        };
    }

    // B ⊖ A への、原点からのレイキャスト（第 16.4 節）
    const Circle m = minkowski_diff(b, a);
    const Ray ray{.origin = Vec2{0.0f, 0.0f}, .dir = delta, .max_t = 1.0f};

    const auto h = raycast(ray, m);
    if (!h) return std::nullopt;

    // 衝突時刻での A の中心
    const Vec2 moved = a.center + delta * h->t;

    // ミンコフスキー空間の外向き法線は、A から B への向きの逆（第 16.4 節）
    const Vec2 n = -h->normal;

    return SweepResult{
        .t = h->t,
        .point = moved + n * a.radius,   // A の表面上（第 7.2 節の規約）
        .normal = n,
        .started_touching = false,
    };
}
```

### 開始時点で交差している場合を先に処理する

冒頭の `overlaps` チェックが重要である。

前章の帰着は、「原点が `B ⊖ A` の外にある」ことを前提としている。既に交差していると、原点は `B ⊖ A` の内部にある。この状態でレイキャストすると、第 15.5 節で決めた規約により円の場合は**出口**が返る。

出口の時刻は「めり込みが解消される時刻」であって、「衝突する時刻」ではない。**これを TOI として使うと、物体が離れる瞬間まで衝突を無視してしまう。**

そこで、交差している場合は `t = 0` と「既に接触している」フラグを返す。呼び出し側は、通常の押し戻し（第 34 章）で処理することになる。

**第 15.5 節で残した「円だけ出口を返す」という不統一が、ここで実害になりかけている。** 事前チェックで回避しているが、本来は規約を統一しておくべきだった。第 43 章のライブラリ仕上げで整理する。

### 法線の符号

`-h->normal` としている。前章 16.4 節の最後で予告した符号反転である。

導出を確認しておく。`B ⊖ A` の外向き法線は、ミンコフスキー空間で原点から遠ざかる向きを指す。原点は「A の位置」に対応するので、この向きは「B から A へ」に対応する。第 7.3 節の規約は「A から B へ」なので、反転する。

**この手の符号は、導出よりテストで確かめるほうが速い。** 17.5 節で検証する。

### 円 vs 線分（カプセルへの帰着）

動く円が静止した線分に当たるか。ミンコフスキー差 `線分 ⊖ 円` は、**カプセル**（線分を半径だけ膨らませた形）になる。

前章の練習問題 16-1 で作ったものである。ここで実装する。

```cpp
// collision/shapes/capsule.h
#pragma once

#include "collision/math/vec2.h"

namespace collision {

// 線分 [a, b] を半径 radius だけ膨らませた形
struct Capsule {
    Vec2  a{};
    Vec2  b{};
    float radius{};
};

} // namespace collision
```

```cpp
// collision/narrow/raycast.h に追加

[[nodiscard]] inline RayResult raycast(const Ray& ray, const Capsule& cap) noexcept {
    // 両端の円と、中間の「帯」に分けて考え、最も手前のヒットを採る
    RayResult best;

    auto keep_nearest = [&best](const RayResult& r) {
        if (r && (!best || r->t < best->t)) best = r;
    };

    // (1) 両端のキャップ
    keep_nearest(raycast(ray, Circle{cap.a, cap.radius}));
    keep_nearest(raycast(ray, Circle{cap.b, cap.radius}));

    // (2) 帯の部分：線分を法線方向へ ±radius ずらした 2 本の線分
    const Vec2 ab = cap.b - cap.a;
    if (const auto n = try_normalize(right_perpendicular(ab))) {
        const Vec2 off = *n * cap.radius;
        keep_nearest(raycast_segment(ray, cap.a + off, cap.b + off));
        keep_nearest(raycast_segment(ray, cap.a - off, cap.b - off));
    }

    return best;
}
```

**素朴だが確実な実装である。** カプセルの境界は「2 つの円弧＋2 本の線分」からなるので、それぞれにレイキャストして最も手前を採る。

無駄はある。円の全周にレイを当てているが、実際に使うのは円弧の部分だけである。円弧の外側で当たったヒットも採用されうる。

**この無駄が問題を起こさない理由を説明しておく。** 円弧でない部分（線分側に隠れる部分）に当たるレイは、その手前で必ず帯の線分に当たる。`keep_nearest` は最も手前を採るので、隠れた部分のヒットは選ばれない。

ただし、**レイの始点がカプセルの内部にある場合は、この論法が崩れる**。始点が内部なら円のレイキャストは `started_inside` を立てて出口を返すので、意図しない結果になりうる。実用では、事前に内部判定を行って弾く。

より効率的な実装（円柱部分を解析的に解く）もあるが、本書では素朴版を採る。**正しさが読み取れることを優先する**（第 9.3 節の三角形の最近接点と同じ判断）。

```cpp
// collision/narrow/sweep.h（続き）

// 円 a が delta だけ動く間に、静止した線分 [p, q] と衝突する時刻
[[nodiscard]] inline SweepHit
sweep_circle_segment(const Circle& a, Vec2 delta, Vec2 p, Vec2 q) noexcept {
    // 線分 ⊖ 円 = 線分を a.radius 膨らませたカプセル（中心は a.center 基準に平行移動）
    const Capsule cap{.a = p - a.center, .b = q - a.center, .radius = a.radius};

    const Ray ray{.origin = Vec2{0.0f, 0.0f}, .dir = delta, .max_t = 1.0f};
    const auto h = raycast(ray, cap);
    if (!h) return std::nullopt;

    const Vec2 moved = a.center + delta * h->t;
    const Vec2 n = -h->normal;

    return SweepResult{
        .t = h->t,
        .point = moved + n * a.radius,
        .normal = n,
        .started_touching = h->started_inside,
    };
}
```

## 17.3 TOI から位置と法線を復元する

### 何を返すべきか

スイープ判定の呼び出し側が知りたいことは、次の四つである。

| 情報 | 用途 |
|---|---|
| 衝突時刻 `t` | どこまで進めてよいか |
| 衝突位置 | エフェクトの配置、接触点 |
| 法線 | 反射、壁ずり、応答の計算 |
| 既に接触していたか | 押し戻しに切り替えるべきか |

`SweepResult` はこの四つを持っている。

### 使い方の典型

```cpp
Vec2 desired = velocity * dt;          // このフレームで動きたい量

if (const auto h = collision::sweep(player, desired, wall)) {
    if (h->started_touching) {
        // 既にめり込んでいる。押し戻しで対処する（第 34 章）
        player.center -= h->normal * penetration_depth;
    } else {
        // 衝突する直前まで進める
        player.center += desired * h->t;

        // わずかに隙間を残す（次フレームで再び t=0 にならないように）
        player.center -= h->normal * contact_slop;
    }
} else {
    player.center += desired;          // 何にも当たらない
}
```

**`contact_slop` だけ引き戻している**のが実務的な工夫である。第 5.9 節で決めた 1 ミリメートルである。

ちょうど `t` まで進めると、その位置で二つの形状は接している。次のフレームで判定すると、誤差次第で「既に交差している」と判定されうる。そうなると `t = 0` が返り、物体が動けなくなる（壁に貼りつく）。

わずかに隙間を残せば、次フレームでも通常のスイープ判定として処理できる。**第 7.7 節の `check_separation_resolves` で `margin` を足したのと同じ発想**である。

### スイープでは貫通深度が得られない

一つ、注意すべき性質がある。**スイープ判定は「衝突する瞬間」を返すので、貫通深度は常にゼロである。**

これは当然である。衝突する直前で止めるのだから、めり込みは発生しない。

したがって、第 7 章で設計した `Contact`（法線・深度・接触点）のうち、スイープが返せるのは法線と接触点だけである。`SweepResult` に `depth` フィールドがないのは、この理由による。

**深度が必要になるのは、既にめり込んでいる場合だけである。** そのときは `started_touching` が立つので、呼び出し側は通常の `intersect` に切り替えて深度を得る。

```cpp
if (const auto h = collision::sweep(a, delta, b)) {
    if (h->started_touching) {
        // 既にめり込んでいる → 深度を得て押し戻す
        if (const auto c = collision::intersect(a, b)) {
            a.center -= c->normal * c->depth;
        }
    } else {
        a.center += delta * h->t;    // 衝突直前まで進める
    }
}
```

**判定の種類によって返せる情報が違う**、という事実は API 設計上の重要な制約である。第 33 章でクエリ API を整理するとき、この区別を型に反映させる。

### 残った移動量をどうするか

上のコードには問題がある。壁に当たったところで移動が止まってしまう。壁に斜めに当たったなら、壁に沿って滑ってほしい。

これが第 38 章のキャラクターコントローラ（collide-and-slide）の主題である。概略だけ示しておく。

```cpp
Vec2 remaining = desired;
for (int iter = 0; iter < 4 && length_squared(remaining) > min_length2; ++iter) {
    const auto h = collision::sweep(player, remaining, world);
    if (!h) {
        player.center += remaining;
        break;
    }
    player.center += remaining * h->t - h->normal * contact_slop;

    // 残りの移動量を、壁に平行な成分だけにする（法線成分を除去）
    remaining = remaining * (1.0f - h->t);
    remaining -= h->normal * dot(remaining, h->normal);
}
```

反復回数に上限（ここでは 4）を設けているのが要点である。角に挟まれると無限に反復しうるので、**必ず上限を置く**。第 20 章の GJK でも同じ配慮が必要になる。

## 17.4 AABB のスイープ ― スラブ法の時間版

### ミンコフスキー差経由で十分

前章で示したとおり、AABB どうしのスイープは `minkowski_diff` してレイキャストするだけで済む。

```cpp
[[nodiscard]] inline SweepHit
sweep(const Aabb& a, Vec2 delta, const Aabb& b) noexcept {
    if (overlaps(a, b)) {
        const auto c = intersect(a, b);
        return SweepResult{
            .t = 0.0f,
            .point = c ? c->point : center(a),
            .normal = c ? c->normal : Vec2{1.0f, 0.0f},
            .started_touching = true,
        };
    }

    const Aabb m = minkowski_diff(b, a);
    const Ray ray{.origin = Vec2{0.0f, 0.0f}, .dir = delta, .max_t = 1.0f};

    const auto h = raycast(ray, m);
    if (!h) return std::nullopt;

    const Vec2 n = -h->normal;
    const Vec2 moved_center = center(a) + delta * h->t;

    return SweepResult{
        .t = h->t,
        .point = moved_center + hadamard(n, extents(a)),   // A の表面上（面の中心）
        .normal = n,
        .started_touching = false,
    };
}
```

接触点に `hadamard(n, extents(a))` を使っている。法線が `(±1, 0)` か `(0, ±1)` なので、これは「衝突した面の中心」を表す。第 10.5 節で AABB の接触点を「重なった領域の中心」としたのと同様、**面接触の代表点としての選択**である。

正確なマニフォールドが必要なら、`t` まで進めた位置で第 14 章の処理を行う。

### なぜ「時間版スラブ法」と呼べるのか

`raycast(Ray, Aabb)` の実装（第 15.3 節）を思い出してほしい。各軸について `t` の区間を求め、共通部分を取っていた。

ミンコフスキー差を経由すると、この `t` が**そのままフレーム内の時刻**になる。「X 軸方向にいつ重なり始めていつ終わるか」「Y 軸方向にいつ重なるか」を求め、両方が重なっている時間帯を探す、という処理になる。

**別々に導出されることの多い「スイープ AABB」と「レイ vs AABB」が、同じアルゴリズムだと分かる。** これが前章の帰着の見返りである。

### 手で計算してみる

数値で一度追っておく。

**A**：`min = (0, 0)`、`max = (1, 1)` の単位正方形
**B**：`min = (5, 0.5)`、`max = (6, 1.5)` の単位正方形
**delta**：`(10, 0)`（1 フレームで右へ 10 進む）

まず `B ⊖ A` を求める。

```
min = b.min - a.max = (5, 0.5) - (1, 1) = (4, -0.5)
max = b.max - a.min = (6, 1.5) - (0, 0) = (6, 1.5)
```

原点から `(10, 0)` 方向へレイを飛ばす。

**X スラブ。** `t1 = (4 - 0)/10 = 0.4`、`t2 = (6 - 0)/10 = 0.6`。区間 `[0.4, 0.6]`。

**Y スラブ。** `dir.y = 0` なので軸に平行。始点 `origin.y = 0` がスラブ `[-0.5, 1.5]` の内側にあるので、この軸は制約を課さない。

**共通部分。** `t_near = 0.4`、`t_far = 0.6`。`t_near <= t_far` なので交差する。

**TOI は 0.4。** X スラブの `lo` 側で `t_near` が更新されたので、法線は `(-1, 0)`。符号を反転して、規約どおりの法線は `(1, 0)`（A から B へ、右向き）。

検算しよう。`t = 0.4` のとき A は `(4, 0)` から `(5, 1)` に移動している。B の `min.x` は 5 なので、A の右辺と B の左辺がちょうど接している。Y 方向は A が `[0, 1]`、B が `[0.5, 1.5]` で重なっている。**確かに接触している。**

```cpp
TEST_METHOD(手計算の例と一致すること) {
    const Aabb a{{0.0f, 0.0f}, {1.0f, 1.0f}};
    const Aabb b{{5.0f, 0.5f}, {6.0f, 1.5f}};

    const auto h = collision::sweep(a, Vec2{10.0f, 0.0f}, b);
    Assert::IsTrue(h.has_value());
    expect_near(0.4f, h->t);
    expect_near(Vec2{1.0f, 0.0f}, h->normal, 1.0e-4f, 1.0e-4f);
}
```

### 複数の障害物のうち、最初に当たるものを選ぶ

実際のゲームでは、物体は多数の障害物に囲まれている。**そのうち最初に当たるものを見つけたい。**

```cpp
// collision/narrow/sweep.h（続き）

// 複数の静止形状に対してスイープし、最も早い衝突を返す。
template <class A, class B>
[[nodiscard]] SweepHit
sweep_nearest(const A& a, Vec2 delta, std::span<const B> obstacles,
              std::size_t* out_index = nullptr) noexcept {
    SweepHit best;
    for (std::size_t i = 0; i < obstacles.size(); ++i) {
        const auto h = sweep(a, delta, obstacles[i]);
        if (!h) continue;
        if (!best || h->t < best->t) {
            best = h;
            if (out_index) *out_index = i;
        }
        // 開始時点で接触しているものが見つかったら、それより早いものはない
        if (best->t <= 0.0f) break;
    }
    return best;
}
```

`best->t <= 0.0f` での早期脱出が効く。既に接触しているものが見つかれば、それより早い衝突は存在しない。

**この総当たりは、障害物が数十個までなら実用になる。** 数千個になると、当然だが持たない。そこで、まず AABB で粗く絞り込んでから精密判定する、という二段構えが必要になる。それが第 VI 部のブロードフェーズである。

移動経路全体を覆う AABB は、第 10.3 節で用意した `swept` で作れる。

```cpp
// 粗い絞り込み：移動経路の AABB と重なるものだけを精密判定する
const Aabb broad = collision::swept(bounds_of(a), delta);
for (const auto& obs : obstacles) {
    if (!collision::overlaps(broad, bounds_of(obs))) continue;   // 粗く弾く
    // ここで初めて sweep を呼ぶ
}
```

**第 10.3 節で `swept` を作ったのは、この場面のためだった。** 章をまたいで部品がつながっている。

### 専用実装を書くべきか

ミンコフスキー差を作るコストは、AABB では減算 4 回である。無視できる。**専用実装を書く理由はない。**

一般に、この章の実装はすべて「ミンコフスキー差＋レイキャスト」で統一されている。形状ペアごとに専用のスイープ公式を導出する必要がない。

**これが第 16 章を独立した章にした理由である。** 一つの見方を導入することで、実装すべきコードの量が劇的に減る。

## 17.5 テスト

### すり抜けないこと（回帰テスト）

第 1 章で挙げた課題そのものをテストにする。

```cpp
// test_sweep.cpp
TEST_CLASS(SweepTunneling) {
public:
    TEST_METHOD(高速の弾丸が薄い壁をすり抜けないこと) {
        // 時速 300km ≒ 83m/s、60fps で 1 フレーム 1.39m 進む
        // 壁の厚さ 0.1m
        const Aabb wall{{-0.05f, -5.0f}, {0.05f, 5.0f}};
        const float speed_per_frame = 1.39f;

        // 弾丸の開始位置を、壁の手前で少しずつ変えて全パターン試す
        int missed = 0;
        for (int i = 0; i < 1000; ++i) {
            const float x = -2.0f + static_cast<float>(i) * 0.002f;
            const Aabb bullet{{x - 0.01f, -0.01f}, {x + 0.01f, 0.01f}};
            const Vec2 delta{speed_per_frame, 0.0f};

            const Aabb moved{bullet.min + delta, bullet.max + delta};
            const bool discrete_hit =
                collision::overlaps(bullet, wall) || collision::overlaps(moved, wall);
            const bool sweep_hit = collision::sweep(bullet, delta, wall).has_value();

            // 離散判定で当たるなら、スイープでも必ず当たること
            if (discrete_hit) {
                Assert::IsTrue(sweep_hit, L"離散で当たるのにスイープで外れた");
            }
            // 離散で外れてスイープで当たる（＝すり抜けを捕捉した）ケースを数える
            if (!discrete_hit && sweep_hit) ++missed;
        }

        Logger::WriteMessage(std::format(
            "離散判定が見逃していたケース: {} / 1000\n", missed).c_str());
        Assert::IsTrue(missed > 100, L"すり抜けの捕捉が少なすぎる");
    }

    TEST_METHOD(速度を上げてもすり抜けないこと) {
        const Aabb wall{{-0.05f, -5.0f}, {0.05f, 5.0f}};
        const Aabb bullet{{-10.01f, -0.01f}, {-9.99f, 0.01f}};

        // 1 フレームの移動量を変えていく
        for (float d = 10.0f; d <= 1000.0f; d *= 2.0f) {
            const auto h = collision::sweep(bullet, Vec2{d, 0.0f}, wall);
            Assert::IsTrue(h.has_value(),
                detail::widen(std::format("移動量 {} ですり抜けた", d)).c_str());

            // 衝突位置は壁の手前（x ≒ -0.05 - 0.01）
            const float hit_x = -10.0f + d * h->t;
            expect_near(-0.06f, hit_x, 1.0e-3f, 1.0e-3f);
        }
    }
};
```

二つ目のテストが強い。**移動量を 10 から 1000 まで 100 倍に変えても、衝突位置は同じ**である。`t` が小さくなるだけで、`delta * t` の積は一定になる。

これは「速度を上げるほど精度が落ちる」という直感に反する。実際には、`t` の精度が落ちるので `delta * t` の精度もわずかに落ちるが、`float` の相対精度が一定である（第 4.1 節）ため、大きな劣化はない。

```cpp
TEST_CLASS(SweepReference) {
public:
    TEST_METHOD(円のスイープが総当たりと一致すること) {
        Rng rng(1100);
        int checked = 0;

        for (int i = 0; i < 5000; ++i) {
            const Circle a{{rng.uniform(-5.0f, 5.0f), rng.uniform(-5.0f, 5.0f)},
                           rng.uniform(0.2f, 1.0f)};
            const Circle b{{rng.uniform(-5.0f, 5.0f), rng.uniform(-5.0f, 5.0f)},
                           rng.uniform(0.2f, 1.0f)};
            const Vec2 delta{rng.uniform(-10.0f, 10.0f), rng.uniform(-10.0f, 10.0f)};

            if (collision::overlaps(a, b)) continue;

            const auto h = collision::sweep(a, delta, b);

            constexpr int steps = 4000;
            std::optional<float> brute;
            for (int k = 0; k <= steps; ++k) {
                const float t = static_cast<float>(k) / static_cast<float>(steps);
                if (collision::overlaps(Circle{a.center + delta * t, a.radius}, b)) {
                    brute = t; break;
                }
            }

            Assert::AreEqual(h.has_value(), brute.has_value(), L"衝突の有無が食い違う");
            if (!h || !brute) continue;

            Assert::IsTrue(std::fabs(h->t - *brute) < 2.0f / steps,
                detail::widen(std::format("TOI: sweep={:.6g} brute={:.6g}",
                                          h->t, *brute)).c_str());
            ++checked;
        }
        Assert::IsTrue(checked > 200, L"照合できた事例が少なすぎる");
    }

    TEST_METHOD(AABBのスイープが総当たりと一致すること) {
        Rng rng(1101);
        int checked = 0;

        for (int i = 0; i < 5000; ++i) {
            const Vec2 alo{rng.uniform(-5.0f, 5.0f), rng.uniform(-5.0f, 5.0f)};
            const Vec2 blo{rng.uniform(-5.0f, 5.0f), rng.uniform(-5.0f, 5.0f)};
            const Aabb a{alo, alo + Vec2{rng.uniform(0.3f, 2.0f), rng.uniform(0.3f, 2.0f)}};
            const Aabb b{blo, blo + Vec2{rng.uniform(0.3f, 2.0f), rng.uniform(0.3f, 2.0f)}};
            const Vec2 delta{rng.uniform(-10.0f, 10.0f), rng.uniform(-10.0f, 10.0f)};

            if (collision::overlaps(a, b)) continue;

            const auto h = collision::sweep(a, delta, b);

            constexpr int steps = 4000;
            std::optional<float> brute;
            for (int k = 0; k <= steps; ++k) {
                const float t = static_cast<float>(k) / static_cast<float>(steps);
                const Aabb moved{a.min + delta * t, a.max + delta * t};
                if (collision::overlaps(moved, b)) { brute = t; break; }
            }

            Assert::AreEqual(h.has_value(), brute.has_value());
            if (!h || !brute) continue;
            Assert::IsTrue(std::fabs(h->t - *brute) < 2.0f / steps);
            ++checked;
        }
        Assert::IsTrue(checked > 200);
    }
};

TEST_CLASS(SweepNormal) {
public:
    TEST_METHOD(法線がAからBへ向いていること) {
        // A が左から右へ進んで B に当たる → 法線は +X
        const Circle a{{-5.0f, 0.0f}, 1.0f};
        const Circle b{{ 0.0f, 0.0f}, 1.0f};

        const auto h = collision::sweep(a, Vec2{10.0f, 0.0f}, b);
        Assert::IsTrue(h.has_value());
        expect_near(Vec2{1.0f, 0.0f}, h->normal, 1.0e-4f, 1.0e-4f);
        Assert::IsFalse(h->started_touching);

        // 衝突時刻での中心間距離が半径の和
        const Vec2 moved = a.center + Vec2{10.0f, 0.0f} * h->t;
        expect_near(2.0f, collision::distance(moved, b.center), 1.0e-4f, 1.0e-4f);
    }

    TEST_METHOD(4方向から当てて法線が正しいこと) {
        const Circle b{{0.0f, 0.0f}, 1.0f};

        struct Case { Vec2 start, delta, expect_n; const wchar_t* label; };
        const Case cases[] = {
            {{-5.0f, 0.0f}, { 10.0f,  0.0f}, { 1.0f,  0.0f}, L"左から"},
            {{ 5.0f, 0.0f}, {-10.0f,  0.0f}, {-1.0f,  0.0f}, L"右から"},
            {{ 0.0f,-5.0f}, {  0.0f, 10.0f}, { 0.0f,  1.0f}, L"下から"},
            {{ 0.0f, 5.0f}, {  0.0f,-10.0f}, { 0.0f, -1.0f}, L"上から"},
        };

        for (const auto& k : cases) {
            const Circle a{k.start, 1.0f};
            const auto h = collision::sweep(a, k.delta, b);
            if (!h) Assert::Fail(k.label);
            if (!nearly_equal(k.expect_n.x, h->normal.x, 1.0e-4f, 1.0e-4f) ||
                !nearly_equal(k.expect_n.y, h->normal.y, 1.0e-4f, 1.0e-4f)) {
                Assert::Fail(k.label);
            }
        }
    }

    TEST_METHOD(押し戻し方向として使えること) {
        // 法線の向きに沿って進めば、確実に離れることの検証
        Rng rng(1102);
        for (int i = 0; i < 10000; ++i) {
            const Circle a{{rng.uniform(-5.0f, 5.0f), rng.uniform(-5.0f, 5.0f)},
                           rng.uniform(0.2f, 1.0f)};
            const Circle b{{rng.uniform(-5.0f, 5.0f), rng.uniform(-5.0f, 5.0f)},
                           rng.uniform(0.2f, 1.0f)};
            const Vec2 delta{rng.uniform(-10.0f, 10.0f), rng.uniform(-10.0f, 10.0f)};

            if (collision::overlaps(a, b)) continue;
            const auto h = collision::sweep(a, delta, b);
            if (!h || h->started_touching) continue;

            // 衝突時刻まで進めたあと、-normal 方向へ少し戻せば交差しない
            const Circle at_hit{a.center + delta * h->t, a.radius};
            const Circle backed{at_hit.center - h->normal * 0.01f, a.radius};
            Assert::IsFalse(collision::overlaps(backed, b), L"法線方向が逆");
        }
    }
};
```

三つ目のテストが、**符号の規約を最も直接的に検証している**。「法線と逆向きに戻せば離れる」という性質は、第 7.3 節の規約そのものである。

TEST_METHOD(両方が動く場合が相対運動と一致すること) {
    Rng rng(1103);

二つ目のテストが分かりやすい。**同じ速度で動く二つの物体は、相対速度がゼロなので衝突しない。** 相対運動への還元が正しければ、これは自明に通る。

## この章のまとめ

- **相対運動への還元：両方が動く場合は `delta_a - delta_b` で片方を止められる**
- ただし衝突「位置」は元の系で計算する。時刻だけが相対系で求まる
- 開始時点で交差している場合を先に処理する。しないと「出口の時刻」を TOI と誤る
- **ミンコフスキー空間の法線は、第 7.3 節の規約と逆向き。符号を反転する**
- カプセル（線分 ⊕ 円）へのレイキャストは、2 円＋2 線分の最も手前を採る素朴版で書く
- 衝突位置まで進めたら、`contact_slop` だけ引き戻す。壁への貼りつきを防ぐ
- 残った移動量を壁に沿わせれば壁ずりになる。**反復には必ず上限を置く**
- AABB のスイープは、ミンコフスキー差＋レイキャストで十分。専用実装は不要
- 「スイープ AABB」と「レイ vs AABB」は同じアルゴリズムである
- テストは、すり抜けの回帰・総当たりとの照合・法線の符号・相対運動の 4 系統

### 第 III 部の到達点と、残っている問題

第 1 章の対応表でいえば、**「第 18 章：弾丸がすり抜けない高速移動体の判定」の一歩手前**である。

**解けたこと。** 平行移動する凸形状どうしの、正確な衝突時刻が求まるようになった。どれだけ速く動いても、すり抜けない。

**まだ解けていないこと。** 三つある。

1. **回転する物体。** この章の帰着は平行移動のみを前提にしている。回転しながら移動する物体には使えない
2. **多数の物体との同時判定。** 一つずつスイープしていくと、「最初に当たるもの」を見つけるのに全部を調べることになる
3. **任意の凸形状。** 円と AABB は実装したが、OBB や凸多角形どうしのミンコフスキー差は明示的に構築しにくい

3 番目は第 IV 部（GJK）で、2 番目は第 VI 部（ブロードフェーズ）で解決する。**1 番目は、完全には解決しない。** その理由と実用上の割り切りが、次章の主題の一つである。

### 落とし穴と練習問題

**落とし穴 1：開始時点の交差を確認しない。**　出口の時刻を TOI と誤り、衝突を見逃す。

**落とし穴 2：法線の符号を反転し忘れる。**　押し戻しが逆向きになる。テストで守る。

**落とし穴 3：ちょうど `t` まで進める。**　次フレームで貼りつく。`contact_slop` だけ戻す。

---

**練習問題 17-1**　17.3 節の collide-and-slide を実装し、斜めの壁に向かって進むキャラクターが壁に沿って滑ることを確認しよう。反復回数を 1 にすると何が起きるか、4 を超えるとどうなるかも試してほしい。

**練習問題 17-2**　カプセルへのレイキャストで、レイの始点がカプセル内部にある場合の挙動を調べよう。17.2 節で「論法が崩れる」と述べた状況である。どう対処すべきか考えてみてほしい。

**練習問題 17-3**　円が静止した凸多角形に当たる時刻を求めよう。`多角形 ⊖ 円` は「角が丸まった多角形」になる。カプセルと同じ発想で、辺ごとのカプセルと頂点ごとの円に分解できる。

**練習問題 17-4**　17.5 節の「速度を上げてもすり抜けない」テストで、移動量をさらに増やして `1e6` や `1e9` にしてみよう。どこで破綻するだろうか。第 4.1 節の ULP の表と照らして、破綻する理由を説明してほしい。

**練習問題 17-5**（発展）　スイープ判定の結果として、単一の接触点ではなくマニフォールド（第 14 章）を返すようにしよう。`t` まで進めた位置で `collide` を呼べばよいが、ちょうど接している状態なので深度がゼロになる。どう扱うべきか考えてみてほしい。

---

次章で第 III 部が完結する。トンネリングが起きる条件を式にし、任意の凸形状に使える保守的前進という手法を導入する。そして回転を伴う運動という、完全には解けない問題に対する実用的な割り切りを扱う。`/fp:fast` の下で反復アルゴリズムが無限ループに陥る事故も、そこで具体的な形をとる。
