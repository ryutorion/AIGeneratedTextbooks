# 第 22 章　EPA ― 貫通深度と法線

> **この章のゴール**
> 交差している二つの凸形状について、**貫通深度**と**押し戻す向き**を求める。GJK が原点を囲む三角形を作ったところから始め、その三角形をミンコフスキー差の境界まで膨らませる。
>
> これが EPA（Expanding Polytope Algorithm、拡張多面体アルゴリズム）である。第 16.3 節で述べた「貫通深度は、原点から `A ⊖ B` の境界までの最短距離」を、実際に計算する。
>
> そして本章は、**本書で最も `/fp:fast` に弱い箇所**でもある。なぜそうなるのか、どこを `precise` で守るのかを、判断根拠とともに示す。

---

## 22.1 GJK の単体からポリトープを広げる

### 出発点

GJK が `intersecting` を返したとき、手元には**原点を含む三角形**がある（第 20.3 節）。

その三角形はミンコフスキー差の内部にあるが、**境界に達しているとは限らない**。頂点はミンコフスキー差の頂点（サポート点）だが、辺は内部を通る弦である。

求めたいのは「原点から境界までの最短距離」なので、この三角形を**境界まで膨らませる**必要がある。

### 膨らませ方

手順は単純である。

```
1. 三角形をポリトープ（多角形）として保持する
2. 繰り返す：
     原点に最も近い辺を見つける
     その辺の外向き法線 n の方向でサポート点 p を取る
     もし p が辺よりほとんど外側にないなら → その辺が境界。収束
     そうでなければ、p を辺の間に挿入してポリトープを広げる
```

**「原点に最も近い辺」を選んで広げる**のが要点である。最短距離を求めたいので、そこを優先的に精密化する。

反復のたびにポリトープは大きくなり、境界に近づく。原点に最も近い辺が境界に達した時点で、その距離が貫通深度である。

### なぜ収束するのか

サポート点 `p` は、その方向でミンコフスキー差の最遠点である。したがって、辺を `p` まで押し出せば、その方向については境界に達する。

反復ごとに「原点に最も近い辺」の距離は単調に増加する（あるいは変わらない）。上限は真の貫通深度なので、そこへ収束する。

**GJK が原点に近づいていくのに対し、EPA は原点から遠ざかっていく。** 内側から境界へ向かう。

## 22.2 実装

### ポリトープの表現

```cpp
// collision/narrow/epa.h
#pragma once

#include "collision/narrow/gjk.h"
#include <array>

namespace collision {

// EPA が保持するポリトープ。反時計回りに頂点を並べる。
inline constexpr std::size_t epa_max_vertices = 32;

struct Polytope {
    std::array<MinkowskiPoint, epa_max_vertices> vertex{};
    std::uint32_t count{};

    [[nodiscard]] bool insert(std::uint32_t index, const MinkowskiPoint& p) noexcept {
        if (count >= epa_max_vertices) return false;
        for (std::uint32_t i = count; i > index; --i) vertex[i] = vertex[i - 1];
        vertex[index] = p;
        ++count;
        return true;
    }
};

} // namespace collision
```

固定長配列を使う理由は第 13.1 節と同じである。**判定のホットパスで動的確保をしたくない。**

上限を 32 にしたのは経験則である。実測すると、通常の形状では 10 回程度の反復で収束する。32 に達するのは、極端に尖った形状か、数値的な問題が起きている場合である。

`insert` は挿入位置以降を後ろへずらす。`std::array` なので `memmove` 相当のコストがかかるが、頂点数が 32 以下なので問題にならない。

### 巻き方向を揃える

**ポリトープは反時計回りでなければならない。** 第 13.1 節で決めたとおり、反時計回りの多角形では `right_perpendicular(edge)` が外向き法線になる。

GJK が返す三角形の巻き方向は保証されていないので、最初に揃える。

```cpp
namespace detail {

// GJK の単体から EPA のポリトープを作る。反時計回りに揃える。
[[nodiscard]] inline Polytope
polytope_from_simplex(const Simplex& s) noexcept {
    Polytope p{};
    p.count = s.count;
    for (std::uint32_t i = 0; i < s.count; ++i) p.vertex[i] = s.point[i];

    if (p.count == 3) {
        const Vec2 e1 = p.vertex[1].diff - p.vertex[0].diff;
        const Vec2 e2 = p.vertex[2].diff - p.vertex[0].diff;
        if (cross(e1, e2) < 0.0f) {
            std::swap(p.vertex[1], p.vertex[2]);   // 時計回りだったので反転
        }
    }
    return p;
}

} // namespace detail
```

**`std::reverse` ではなく 2 頂点の交換で済ませている。** 3 頂点の反転は 1 番目と 2 番目を入れ替えるだけである。

### 原点に最も近い辺を探す

```cpp
namespace detail {

struct ClosestEdge {
    std::uint32_t index{};     // 辺の始点の添字
    float         distance{};  // 原点から辺までの距離
    Vec2          normal{};    // 外向き単位法線
    bool          valid{};
};

[[nodiscard]] inline ClosestEdge
find_closest_edge(const Polytope& p) noexcept {
    ClosestEdge best{.distance = std::numeric_limits<float>::infinity()};

    for (std::uint32_t i = 0; i < p.count; ++i) {
        const std::uint32_t j = (i + 1) % p.count;
        const Vec2 a = p.vertex[i].diff;
        const Vec2 e = p.vertex[j].diff - a;

        // 反時計回りなので right_perpendicular が外向き（第 13.1 節）
        const auto n = try_normalize(right_perpendicular(e));
        if (!n) continue;   // 退化した辺は飛ばす

        const float d = dot(*n, a);   // 原点から辺の直線までの符号付き距離
        if (d < best.distance) {
            best = ClosestEdge{.index = i, .distance = d, .normal = *n, .valid = true};
        }
    }
    return best;
}

} // namespace detail
```

`dot(n, a)` が原点から辺までの距離になる理由を確認しておく。`n` は単位法線、`a` は辺上の点である。原点から辺の直線への距離は、辺上の任意の点と法線の内積で得られる。

**原点がポリトープの内部にあれば、この値は正になる。** 外向き法線なので、内側から見た距離は正である。

`try_normalize`（第 6.4 節）を使っているので、退化した辺（長さゼロ）は自動的に弾かれる。**GJK の単体が潰れている場合の安全弁**になっている。

### 本体

```cpp
// collision/narrow/epa.h（続き）

struct EpaResult {
    float depth{};          // 貫通深度（非負）
    Vec2  normal{};         // A から B へ向く単位法線（第 7.3 節の規約）
    Vec2  contact_a{};      // A 上の接触点
    Vec2  contact_b{};      // B 上の接触点
    bool  converged{true};
    int   iterations{};
};

inline constexpr int   epa_max_iterations = 64;
inline constexpr float epa_tolerance      = 1.0e-5f;

template <SupportShape A, SupportShape B>
[[nodiscard]] std::optional<EpaResult>
epa(const A& a, const B& b, const Simplex& simplex) noexcept {
    Polytope poly = detail::polytope_from_simplex(simplex);
    if (poly.count < 3) {
        return std::nullopt;   // 三角形が作れていない（呼び出し側で対処）
    }

    detail::ClosestEdge edge{};

    for (int iter = 0; iter < epa_max_iterations; ++iter) {
        edge = detail::find_closest_edge(poly);
        if (!edge.valid) {
            return std::nullopt;   // ポリトープが退化した
        }

        const MinkowskiPoint p = support_diff(a, b, edge.normal);
        const float d = dot(p.diff, edge.normal);

        // この辺が境界に達したか（22.3 節）
        if (detail::epa_converged(d, edge.distance)) {
            return detail::build_result(poly, edge, iter, true);
        }

        // 進展がない（同じ頂点が返ってきた）
        if (detail::already_in_polytope(poly, p.diff)) {
            return detail::build_result(poly, edge, iter, true);
        }

        if (!poly.insert(edge.index + 1, p)) {
            return detail::build_result(poly, edge, iter, false);   // 容量超過
        }
    }

    return detail::build_result(poly, edge, epa_max_iterations, false);
}
```

**三箇所すべてで結果を返している**点に注意してほしい。収束しなかった場合も、それまでに求まった最良の推定値を返す。

第 18.5 節で述べたのと同じ理由である。**`nullopt` を返すと、呼び出し側が「交差していない」と扱ってすり抜ける。** 交差していることは GJK が確定させているのだから、深度が多少不正確でも値を返すほうが安全である。

`converged` フラグで品質を伝え、判断は呼び出し側に委ねる。

### 反復を手で追う

正方形どうしの EPA を追ってみる。

**A**：`(0,0)`, `(2,0)`, `(2,2)`, `(0,2)`
**B**：`(1,0)`, `(3,0)`, `(3,2)`, `(1,2)`

X 方向に 1 だけ重なっている。真の貫通深度は 1、法線は `(1,0)`（A から B へ）である。

ミンコフスキー差 `A ⊖ B` は、`(0,0)-(3,2) = (-3,-2)` から `(2,2)-(1,0) = (1,2)` までの矩形、つまり `[-3, 1] × [-2, 2]` である。原点から最も近い辺は `x = 1` の辺で、距離 1。**これが答えである。**

GJK が返す三角形の頂点は、たとえば `(1,2)`, `(-3,-2)`, `(1,-2)` のようになる（実際の値は初期方向による）。

**反復 1。** ポリトープは三角形。各辺の距離を測る。

- 辺 `(1,-2)→(1,2)`：法線 `(1,0)`、距離 `dot((1,0),(1,-2)) = 1`
- 辺 `(1,2)→(-3,-2)`：法線を求めると距離は約 2.8
- 辺 `(-3,-2)→(1,-2)`：法線 `(0,-1)`、距離 2

最も近いのは第 1 の辺、距離 1、法線 `(1,0)`。

サポート点：`support_diff(a, b, (1,0))`。A の `(1,0)` 方向の最遠点は `x = 2` の頂点、B の `(-1,0)` 方向の最遠点は `x = 1` の頂点。差は `(1, ...)`。

`dot(p, (1,0)) = 1`。辺の距離も 1。差はゼロなので**収束**。

**結果。** 深度 1、`edge.normal = (1,0)`。

符号を確かめる。A は `[0,2]`、B は `[1,3]` である。**A を左へ 1 動かせば分離する**（`[-1,1]` と `[1,3]` が x=1 で接触）。つまり A の移動ベクトルは `(-1,0)`。

第 7.3 節の規約は「A を `-normal * depth` 動かすと分離する」なので、`-normal * 1 = (-1,0)` から `normal = (1,0)`。

**`edge.normal` と一致した。反転は不要である。**

> **筆者はここで間違えた**
> 本書の初稿では、第 16.4 節のスイープで符号を反転したことに引きずられて、EPA でも `-edge.normal` を返していた。この手計算の例を書いていて、結論が合わないことに気づいた。
>
> 反転が必要だったのは、第 16.4 節が `B ⊖ A`（順序が逆）を使っていたためである。EPA は `A ⊖ B` を使うので、符号はそのままでよい。
>
> **符号の規約は、手で追える例とテストの両方で確認する。** 導出を一度追っただけで確信すると、こういう間違いをする。22.6 節のテストは、この種の誤りを機械的に捕まえるために書いてある。

## 22.3 収束判定と退化への対処

### 本書で最も `/fp:fast` に弱い箇所

EPA の収束判定は、次の形をしている。

```
dot(p, n) - edge.distance < tolerance
```

`dot(p, n)` は「サポート点までの距離」、`edge.distance` は「現在の辺までの距離」である。収束が近づくと、**この二つはほぼ同じ値になる**。

近い値どうしの引き算 ― 第 4.2 節で扱った**桁落ち**そのものである。有効桁数が激減する。

さらに `/fp:fast` の下では、`dot` の計算が FMA に融合されたり、順序が入れ替わったりする。**同じ数式でも、コンパイルのされ方によって差の符号が変わりうる。**

その結果、次のことが起きる。

- 収束したのに検出できず、反復を続ける
- 収束していないのに収束と判断し、不正確な深度を返す
- 反復ごとに判定が揺れ、上限まで回る

### なぜ EPA が特に弱いのか

GJK（第 20.6 節）や距離 GJK（第 21.3 節）でも同じ議論をした。EPA が「最も弱い」のには理由がある。

**1. 差が本質的に小さい。** GJK の分離判定 `dot(p, d) < 0` は符号を見るだけで、値の大きさに余裕があることが多い。EPA は「ほぼ等しい二つの距離の差」を見るので、最初から桁落ちが避けられない。

**2. 反復が多い。** EPA は 10〜30 回程度反復する。判定が揺れる機会がそれだけ多い。

**3. 幾何が退化しやすい。** ポリトープが尖ってくると、辺の法線が不安定になる。正規化する前のベクトルが短くなり、精度が落ちる。

### `precise` で守る

第 4.6 節の判断基準に照らす。

> **戻すのは「回数が少なく、かつ判定を誤ると制御フローが壊れる箇所」だけ**

EPA の収束判定は、反復あたり 1 回、最大 64 回である。**回数は十分に少ない。** そして判定を誤ると、深度が不正確になるか反復が終わらない。**制御フローが壊れる。**

```cpp
// collision/narrow/epa.h（続き）

namespace detail {

#pragma float_control(precise, on, push)

// EPA の収束判定。
// support_distance と edge_distance は収束時にほぼ等しくなるため、
// その差は桁落ちの塊である（第 4.2 節）。/fp:fast の再結合や FMA 融合で
// 符号が揺れると、収束を検出できず反復上限まで回る。
// 反復あたり 1 回しか呼ばれないので、precise のコストは無視できる。
__declspec(noinline)
[[nodiscard]] inline bool
epa_converged(float support_distance, float edge_distance) noexcept {
    const float diff = support_distance - edge_distance;

    // 絶対誤差と相対誤差の併用（第 4.3 節の方針）。
    // 深度が大きいほど許容幅も広げる
    const float tol = epa_tolerance * std::max(1.0f, edge_distance);
    return diff < tol;
}

// 同じ頂点が返ってきたか。これも進展の判定なので precise で守る。
__declspec(noinline)
[[nodiscard]] inline bool
already_in_polytope(const Polytope& p, Vec2 v) noexcept {
    for (std::uint32_t i = 0; i < p.count; ++i) {
        const Vec2  d  = p.vertex[i].diff - v;
        const float d2 = d.x * d.x + d.y * d.y;
        if (d2 < min_length2) return true;
    }
    return false;
}

#pragma float_control(pop)

} // namespace detail
```

**許容誤差をスケール相対にしている**のが、第 4.3 節の方針の適用である。深度が 100 メートルある状況で `1e-5` の絶対精度を要求するのは無理がある。`edge_distance` に比例して緩める。

`std::max(1.0f, edge_distance)` としているのは、深度が非常に小さいときに許容幅がゼロに潰れるのを防ぐためである。

### 二重の安全弁

収束判定に加えて、`already_in_polytope` を置いている。

**サポート点が既にポリトープの頂点なら、それ以上広げようがない。** 挿入しても同じ頂点が重複するだけで、次の反復も同じ結果になる。無限ループである。

第 20.5 節の重複検出とまったく同じ役割である。**反復アルゴリズムには「進展があったか」の判定を必ず入れる**、というのが本書の規則になりつつある。

### ポリトープの容量超過

`insert` が `false` を返したら、頂点数の上限に達している。

このとき、それまでの最良推定値を返す。**`nullopt` にしない。** 上限に達するのは異常な状況だが、深度の推定値としては十分使えることが多い。

上限を増やすべきかは、実測で判断する。22.6 節で「容量超過が起きた件数」を記録するテストを書く。

## 22.4 `Contact` を組み立てる

### 接触点の復元

深度と法線は `ClosestEdge` から直接得られる。**接触点は、第 21.2 節と同じく重心座標で復元する。**

原点に最も近い辺の上で、原点に最も近い点を求める。その点を辺の両端点の凸結合として表し、同じ重みを `on_a` / `on_b` に適用する。

```cpp
namespace detail {

[[nodiscard]] inline EpaResult
build_result(const Polytope& poly, const ClosestEdge& edge,
             int iterations, bool converged) noexcept {
    const std::uint32_t i = edge.index;
    const std::uint32_t j = (i + 1) % poly.count;

    const MinkowskiPoint& p0 = poly.vertex[i];
    const MinkowskiPoint& p1 = poly.vertex[j];

    // 辺 [p0, p1] 上で原点に最も近い点の重心座標を求める
    const Vec2  e    = p1.diff - p0.diff;
    const float len2 = length_squared(e);

    float t = 0.0f;
    if (len2 >= min_length2) {
        t = std::clamp(dot(-p0.diff, e) / len2, 0.0f, 1.0f);
    }
    const float w0 = 1.0f - t;
    const float w1 = t;

    return EpaResult{
        .depth     = std::max(edge.distance, 0.0f),
        // A ⊖ B の外向き法線は、そのまま「A から B へ」を向く。
        // 反転してはいけない（導出は 22.2 節、検証は 22.6 節）
        .normal    = edge.normal,
        .contact_a = p0.on_a * w0 + p1.on_a * w1,
        .contact_b = p0.on_b * w0 + p1.on_b * w1,
        .converged = converged,
        .iterations = iterations,
    };
}

} // namespace detail
```

### 法線の符号 ― 反転してはいけない

**`edge.normal` をそのまま使う。** 第 16.4 節のスイープでは反転が必要だったので、ここでも反転したくなるが、**それは誤りである**。

導出しておく。A を `v` だけ動かしたときのミンコフスキー差は `(A + v) ⊖ B = (A ⊖ B) + v` である。分離するには原点が外に出ればよく、これは `-v` が `A ⊖ B` の外にあることと同値である。

最短で外に出すには、`-v` を原点に最も近い境界点、すなわち `edge.normal * depth` に一致させればよい。したがって

```
-v = edge.normal * depth
 v = -edge.normal * depth
```

**A は `-edge.normal * depth` だけ動かせば分離する。**

第 7.3 節の規約は「A を `-normal * depth` 動かすと分離する」だった。両者を見比べると `normal = edge.normal` である。反転は不要。

第 16.4 節のスイープで反転が必要だったのは、あちらが `B ⊖ A`（順序が逆）を使っていたためである。**`A ⊖ B` と `B ⊖ A` のどちらを使っているかで符号が変わる。** 混同しやすい箇所なので、実装ごとに確認すること。

**そして、導出だけで確信してはいけない。** 22.6 節で SAT の MTV と照合し、テストで確定させる。

### `intersect` に組み込む

```cpp
// collision/narrow/gjk.h に追加

// 任意の凸形状ペアの交差判定と貫通情報。
// 内側は optional、外側は expected（第 7.5 節の方針）
template <SupportShape A, SupportShape B>
[[nodiscard]] std::expected<std::optional<Contact>, CollisionError>
collide_gjk(const A& a, const B& b) noexcept {
    const auto g = gjk(a, b);

    switch (g.status) {
    case GjkStatus::separated:
        return std::optional<Contact>{};                 // 交差していない（成功）

    case GjkStatus::not_converged:
        return std::unexpected(CollisionError::not_converged);

    case GjkStatus::intersecting:
        break;
    }

    const auto e = epa(a, b, g.simplex);
    if (!e) {
        return std::unexpected(CollisionError::degenerate);
    }

    return std::optional<Contact>{Contact{
        .normal = e->normal,
        .depth  = e->depth,
        .point  = e->contact_a,     // A 上の接触点（第 7.2 節の規約）
    }};
}
```

**第 7.5 節で設計した三状態が、ここで初めてすべて使われる。**

- 交差している → `Contact`
- 交差していない → `nullopt`
- 判定できなかった → `CollisionError`

第 7 章では「反復アルゴリズムで必要になる」と予告しただけだった。GJK と EPA が、その予告どおりの場面である。

## 22.5 マニフォールドへの拡張

### EPA は接触点を 1 個しか返さない

EPA が返すのは、ミンコフスキー差の境界上の 1 点に対応する接触点である。**面と面が接触していても、1 点しか出てこない。**

第 14.1 節で述べたとおり、これでは箱が転がる。床の上の箱には 2 点必要である。

### 第 14 章のクリッピングを再利用する

解決策は、**EPA が求めた法線を使って、第 14 章のマニフォールド生成を走らせる**ことである。

第 14.3 節の `select_faces` は、法線 `n` を受け取って参照面と入射面を選ぶ。この `n` は SAT が求めたものだったが、EPA が求めたものでも同じように使える。

```cpp
// collision/narrow/manifold.h に追加

// EPA の結果からマニフォールドを構築する。
// 法線の求め方が SAT から EPA に変わるだけで、クリッピングは共通（第 14 章）。
[[nodiscard]] inline std::optional<ContactManifold>
collide_gjk_manifold(const ConvexPolygon& a, const ConvexPolygon& b) noexcept {
    const auto g = gjk(a, b);
    if (g.status != GjkStatus::intersecting) return std::nullopt;

    const auto e = epa(a, b, g.simplex);
    if (!e) return std::nullopt;

    // 第 14.4 節の build_manifold をそのまま使う
    return build_manifold(a, b, e->normal, e->depth);
}
```

**第 14 章の投資がここで回収される。** クリッピングの実装は一行も変えていない。法線をどう求めたかは、マニフォールド生成にとって無関係である。

### 円が絡む場合

多角形どうしならこれでよい。**円が絡むと事情が違う。**

円には「面」がないので、参照面・入射面という枠組みが使えない。だが問題はない。**円と何かの接触は、本質的に 1 点である。** マニフォールドは 1 点で正しい。

したがって、円が絡むペアでは EPA の結果をそのまま使う。多角形どうしでのみクリッピングを行う。この分岐は呼び出し側（第 33 章のパイプライン）で行う。

## 22.6 テスト：SAT の MTV と一致すること

### 最も重要な検証

**SAT の MTV（第 13 章）と EPA の結果は、同じものを別の方法で求めている。** 一致しなければ、どちらかが間違っている。

```cpp
// test_epa.cpp
TEST_CLASS(EpaVsSat) {
public:
    TEST_METHOD(貫通深度がSATのMTVと一致すること) {
        Rng rng(1600);
        int checked = 0;
        float worst_depth = 0.0f, worst_angle = 0.0f;

        for (int i = 0; i < 50000; ++i) {
            const auto a = transformed_poly(random_convex_polygon_checked(rng, 3 + (i % 6)),
                {rng.uniform(-1.2f, 1.2f), rng.uniform(-1.2f, 1.2f)}, rng.uniform(0.0f, 6.28f));
            const auto b = transformed_poly(random_convex_polygon_checked(rng, 3 + (i % 6)),
                {rng.uniform(-1.2f, 1.2f), rng.uniform(-1.2f, 1.2f)}, rng.uniform(0.0f, 6.28f));

            const auto by_sat = collision::sat_polygon(a, b);
            const auto g = collision::gjk(a, b);
            if (!by_sat || g.status != collision::GjkStatus::intersecting) continue;

            const auto e = collision::epa(a, b, g.simplex);
            if (!e) continue;
            if (!e->converged) continue;

            ++checked;
            worst_depth = std::max(worst_depth, std::fabs(e->depth - by_sat->depth));

            const float c = std::clamp(collision::dot(e->normal, by_sat->axis), -1.0f, 1.0f);
            worst_angle = std::max(worst_angle, std::acos(c));

            expect_near(by_sat->depth, e->depth, 1.0e-3f, 1.0e-2f);
            Assert::IsTrue(c > 0.99f, L"法線の向きが SAT と大きく違う");
        }

        Logger::WriteMessage(std::format(
            "EPA vs SAT: 照合 {} 件, 深度の最大差 {:.3e}, 法線の最大角度差 {:.4f} 度\n",
            checked, worst_depth, worst_angle * 180.0f / std::numbers::pi_v<float>).c_str());
        Assert::IsTrue(checked > 5000, L"照合できた事例が少なすぎる");
    }
};
```

> **この照合が、第 11.2 節のバグを暴いた**
> 本書の初稿では、SAT の押し出し量を `min(a.max, b.max) - max(a.min, b.min)` で計算していた。この式は分離判定としては正しいが、**片方の区間が他方に含まれるとき押し出し量を過小評価する**（第 11.2 節）。
>
> EPA と照合したところ、深度が最大 1.6 も食い違った。EPA はミンコフスキー差の境界までの距離を直接求めるので、含有の有無に関係なく正しい。**照合によって、SAT 側の誤りが発見された。**
>
> リファレンス比較（第 11.6 節）は「新しい実装を検証する」ためのものだと述べたが、**逆方向にも働く**。二つの独立した実装を突き合わせることの価値は、どちらが正しいかを問わない点にある。

### 究極のリファレンス：ミンコフスキー差を陽に構築する

SAT と EPA が食い違ったとき、どちらが正しいかを決める必要がある。**ミンコフスキー差を実際に作れば、議論の余地なく決まる。**

```cpp
TEST_CLASS(EpaGroundTruth) {
public:
    // ミンコフスキー差を陽に構築し、原点から境界までの最短距離を求める。
    // 遅いが厳密。EPA と SAT の審判役になる。
    [[nodiscard]] static std::optional<std::pair<float, Vec2>>
    ground_truth(const collision::ConvexPolygon& a, const collision::ConvexPolygon& b) {
        std::vector<Vec2> pts;
        pts.reserve(static_cast<std::size_t>(a.count) * b.count);
        for (std::uint32_t i = 0; i < a.count; ++i)
            for (std::uint32_t j = 0; j < b.count; ++j)
                pts.push_back(a.vertex[i] - b.vertex[j]);

        const auto hull = collision::convex_hull_unbounded(pts);   // 頂点数無制限版
        if (hull.size() < 3) return std::nullopt;

        float best = std::numeric_limits<float>::infinity();
        Vec2  bn{};
        for (std::size_t i = 0; i < hull.size(); ++i) {
            const Vec2 p0 = hull[i], p1 = hull[(i + 1) % hull.size()];
            const auto n = collision::try_normalize(
                collision::right_perpendicular(p1 - p0));
            if (!n) continue;
            const float d = collision::dot(*n, p0);
            if (d < 0.0f) return std::nullopt;       // 原点が外 → 交差なし
            if (d < best) { best = d; bn = *n; }
        }
        return std::pair{best, bn};
    }

    TEST_METHOD(EPAが厳密解と一致すること) {
        Rng rng(1601);
        int checked = 0;
        float worst_epa = 0.0f, worst_sat = 0.0f;

        for (int i = 0; i < 5000; ++i) {
            const auto a = transformed_poly(random_convex_polygon_checked(rng, 3 + (i % 6)),
                {rng.uniform(-1.2f, 1.2f), rng.uniform(-1.2f, 1.2f)}, rng.uniform(0.0f, 6.28f));
            const auto b = transformed_poly(random_convex_polygon_checked(rng, 3 + (i % 6)),
                {rng.uniform(-1.2f, 1.2f), rng.uniform(-1.2f, 1.2f)}, rng.uniform(0.0f, 6.28f));

            const auto truth = ground_truth(a, b);
            if (!truth) continue;

            const auto g = collision::gjk(a, b);
            if (g.status != collision::GjkStatus::intersecting) continue;
            const auto e = collision::epa(a, b, g.simplex);
            if (!e || !e->converged) continue;

            const auto s = collision::sat_polygon(a, b);
            ++checked;

            worst_epa = std::max(worst_epa, std::fabs(e->depth - truth->first));
            if (s) worst_sat = std::max(worst_sat, std::fabs(s->depth - truth->first));

            expect_near(truth->first, e->depth, 1.0e-3f, 1.0e-3f);
        }

        Logger::WriteMessage(std::format(
            "厳密解との比較（{} 件）: EPA の最大差 {:.3e}, SAT の最大差 {:.3e}\n",
            checked, worst_epa, worst_sat).c_str());
        Assert::IsTrue(checked > 500);
    }
};
```

**この「究極のリファレンス」を持っておくことには、大きな価値がある。**

ミンコフスキー差を陽に構築するのは遅い（頂点数の積だけ点を作り、凸包を取る）。実用にはならない。だが**正しさの基準としては完璧である**。

新しい実装を疑ったとき、これに照らせば決着がつく。本書の執筆過程でも、SAT と EPA が食い違ったときにこれで判定した。

### 押し戻しの検証

```cpp
TEST_CLASS(EpaProperties) {
public:
    TEST_METHOD(押し戻すと交差が解消すること) {
        Rng rng(1602);
        for (int i = 0; i < 20000; ++i) {
            const auto a0 = transformed_poly(random_convex_polygon_checked(rng, 3 + (i % 6)),
                {rng.uniform(-1.2f, 1.2f), rng.uniform(-1.2f, 1.2f)}, rng.uniform(0.0f, 6.28f));
            const auto b  = transformed_poly(random_convex_polygon_checked(rng, 3 + (i % 6)),
                {rng.uniform(-1.2f, 1.2f), rng.uniform(-1.2f, 1.2f)}, rng.uniform(0.0f, 6.28f));

            const auto g = collision::gjk(a0, b);
            if (g.status != collision::GjkStatus::intersecting) continue;
            const auto e = collision::epa(a0, b, g.simplex);
            if (!e || !e->converged) continue;

            // -normal 方向へ depth + マージンだけ動かす
            auto a = a0;
            const Vec2 push = -e->normal * (e->depth + 1.0e-3f);
            for (std::uint32_t k = 0; k < a.count; ++k) a.vertex[k] += push;

            Assert::IsFalse(collision::overlaps_gjk(a, b),
                detail::widen(std::format(
                    "押し戻したのに交差したまま (depth={:.6g})", e->depth)).c_str());
        }
    }

    TEST_METHOD(接触点が両形状の境界付近にあること) {
        Rng rng(1603);
        for (int i = 0; i < 20000; ++i) {
            const auto a = transformed_poly(random_convex_polygon_checked(rng, 3 + (i % 6)),
                {rng.uniform(-1.2f, 1.2f), rng.uniform(-1.2f, 1.2f)}, rng.uniform(0.0f, 6.28f));
            const auto b = transformed_poly(random_convex_polygon_checked(rng, 3 + (i % 6)),
                {rng.uniform(-1.2f, 1.2f), rng.uniform(-1.2f, 1.2f)}, rng.uniform(0.0f, 6.28f));

            const auto g = collision::gjk(a, b);
            if (g.status != collision::GjkStatus::intersecting) continue;
            const auto e = collision::epa(a, b, g.simplex);
            if (!e || !e->converged) continue;

            // contact_a - contact_b が -normal * depth に等しいはず
            expect_near(-e->normal * e->depth, e->contact_a - e->contact_b,
                        1.0e-2f, 1.0e-2f);
        }
    }

    TEST_METHOD(引数を入れ替えると法線が反転すること) {
        Rng rng(1604);
        for (int i = 0; i < 20000; ++i) {
            const auto a = transformed_poly(random_convex_polygon_checked(rng, 3 + (i % 6)),
                {rng.uniform(-1.2f, 1.2f), rng.uniform(-1.2f, 1.2f)}, rng.uniform(0.0f, 6.28f));
            const auto b = transformed_poly(random_convex_polygon_checked(rng, 3 + (i % 6)),
                {rng.uniform(-1.2f, 1.2f), rng.uniform(-1.2f, 1.2f)}, rng.uniform(0.0f, 6.28f));

            const auto gab = collision::gjk(a, b);
            const auto gba = collision::gjk(b, a);
            if (gab.status != collision::GjkStatus::intersecting) continue;
            if (gba.status != collision::GjkStatus::intersecting) continue;

            const auto eab = collision::epa(a, b, gab.simplex);
            const auto eba = collision::epa(b, a, gba.simplex);
            if (!eab || !eba || !eab->converged || !eba->converged) continue;

            expect_near(eab->depth, eba->depth, 1.0e-3f, 1.0e-2f);
            expect_near(-eab->normal, eba->normal, 1.0e-2f, 1.0e-2f);
        }
    }
};
```

`contact_a - contact_b == -normal * depth` という関係が、**接触点と深度と法線の三者の整合を保証する**。どれか一つだけ間違えても落ちる。

### 収束の統計

```cpp
TEST_METHOD(収束の統計を記録する) {
    Rng rng(1605);
    int total = 0, not_conv = 0, degenerate = 0, capacity = 0;
    long long total_iter = 0;
    int max_iter = 0;

    for (int i = 0; i < 100000; ++i) {
        const auto a = transformed_poly(random_convex_polygon_checked(rng, 3 + (i % 6)),
            {rng.uniform(-1.2f, 1.2f), rng.uniform(-1.2f, 1.2f)}, rng.uniform(0.0f, 6.28f));
        const auto b = transformed_poly(random_convex_polygon_checked(rng, 3 + (i % 6)),
            {rng.uniform(-1.2f, 1.2f), rng.uniform(-1.2f, 1.2f)}, rng.uniform(0.0f, 6.28f));

        const auto g = collision::gjk(a, b);
        if (g.status != collision::GjkStatus::intersecting) continue;

        const auto e = collision::epa(a, b, g.simplex);
        ++total;
        if (!e) { ++degenerate; continue; }
        if (!e->converged) ++not_conv;
        total_iter += e->iterations;
        max_iter = std::max(max_iter, e->iterations);
    }

    Logger::WriteMessage(std::format(
        "EPA {} 件: 平均反復 {:.2f}, 最大 {}, 未収束 {}, 退化 {}\n",
        total, static_cast<double>(total_iter) / std::max(total, 1),
        max_iter, not_conv, degenerate).c_str());

    Assert::IsTrue(not_conv * 100 < total, L"未収束が 1% を超えている");
    Assert::IsTrue(degenerate * 1000 < total, L"退化が 0.1% を超えている");
}
```

**最大反復回数を記録している**のが、`epa_max_vertices = 32` の妥当性を判断する材料になる。実測で最大が 15 程度なら、32 は十分な余裕である。

`precise` 指定を外すと、この数字が悪化するはずである。**それが 22.3 節の判断の実証になる。**

## この章のまとめ

- **EPA は、GJK の単体をミンコフスキー差の境界まで膨らませる**
- 原点に最も近い辺を選び、その法線方向のサポート点で分割する
- ポリトープは反時計回りに揃える。`right_perpendicular` が外向き法線になる
- **収束判定は「ほぼ等しい二つの距離の差」。桁落ちの塊であり、本書で最も `/fp:fast` に弱い**
- 許容誤差はスケール相対にする。深度が大きければ許容幅も広げる
- 収束判定と重複検出を `precise` で守る。反復あたり 1 回なのでコストは無視できる
- 収束しなくても、それまでの最良推定値を返す。`nullopt` はすり抜けを招く
- **法線は `edge.normal` そのまま。** `A ⊖ B` の外向き法線は「A から B へ」と一致する（`B ⊖ A` を使う第 16.4 節とは逆なので注意）
- 接触点は重心座標で復元する（第 21.2 節と同じ手法）
- **第 7.5 節の三状態（交差・非交差・エラー）が、ここで初めてすべて使われる**
- マニフォールドは第 14 章のクリッピングをそのまま再利用できる
- **テストの決め手は「ミンコフスキー差を陽に構築した厳密解」。** 遅いが議論の余地がない

### 落とし穴と練習問題

**落とし穴 1：ポリトープの巻き方向を揃え忘れる。**　法線がすべて内向きになり、`find_closest_edge` が負の距離を返す。

**落とし穴 2：収束判定を絶対誤差で書く。**　深い貫通で収束しなくなる。スケール相対にする。

**落とし穴 3：`nullopt` を返して呼び出し側が「交差なし」と扱う。**　GJK が交差を確定させているのだから、値を返す。

---

**練習問題 22-1**　`epa_converged` の `precise` 指定を外し、22.6 節の統計テストを Release ビルドで走らせよう。平均反復回数と未収束の件数はどう変わるだろうか。

**練習問題 22-2**　`epa_max_vertices` を 8 に減らして、容量超過が起きる件数を数えよう。どんな形状ペアで起きるかを調べてほしい。

**練習問題 22-3**　円と多角形の EPA を試そう。円は頂点を持たないので、ポリトープの頂点は反復のたびに新しく生成される。多角形どうしより反復回数は増えるだろうか。

**練習問題 22-4**　22.6 節の `ground_truth` を使って、SAT と EPA の両方を検証するテストを常設しよう。実行は遅いので、通常のテスト実行から外し、変更時だけ手動で回す運用が現実的である。

**練習問題 22-5**（発展）　EPA の初期ポリトープが 2 点（線分）しかない場合を扱えるようにしよう。GJK が「原点が単体上に乗った」で終了したときに起こりうる。線分に垂直な方向でサポート点を取り、三角形を作ればよい。
