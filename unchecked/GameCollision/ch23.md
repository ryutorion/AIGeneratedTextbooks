# 第 23 章　GJK でスイープする

> **この章のゴール**
> 任意の凸形状に対するスイープ判定を実現する。第 17 章の方法（ミンコフスキー差を構築してレイキャスト）は、差を明示的に作れる形状にしか使えなかった。**GJK を使えば、その制約が外れる。**
>
> 二つの手法を扱う。**レイキャスト GJK** は、ミンコフスキー差を構築せずにレイキャストを行う。**保守的前進 + GJK 距離**は、第 18 章の枠組みに距離関数を差し込むだけで済む。
>
> 第 18 章で保留した宿題が、ここで完全に片付く。第 IV 部の締めくくりである。

---

## 23.1 レイキャスト GJK

### 発想

第 16.4 節の帰着を思い出してほしい。

> A が `delta` だけ動いて B に当たる時刻 `t` は、原点から向き `delta` へ放ったレイが `B ⊖ A` に当たる時刻に等しい。

第 17 章では、`B ⊖ A` を実際に構築してレイキャストした。円や AABB なら構築が簡単だからである。

**構築せずにレイキャストできないか。** それがレイキャスト GJK（Gino van den Bergen による手法）の問いである。

### アルゴリズム

考え方はこうである。**レイ上を進みながら、進んだ位置から見たミンコフスキー差との距離を GJK で測る。**

```
1. t = 0、現在位置 x = 原点、法線 n = 未定
2. 繰り返す：
     v = x から B⊖A への最短ベクトル（GJK 距離）
     もし |v| がほぼゼロなら → x が境界に達した。t が答え
     w = support(B⊖A, v) から見た平面までの距離を使って t を進める
     x = delta * t
```

要点は、**「原点を動かす代わりに、ミンコフスキー差を `-delta·t` だけ平行移動する」**と考えることである。すると、通常の GJK 距離計算がそのまま使える。

より正確には、レイ上の現在点 `x = delta·t` から見て、ミンコフスキー差の「手前の面」がどこにあるかを調べ、レイがその面に到達する時刻まで `t` を進める。面は保守的に選ばれるので、進めすぎることがない。

### 実装

```cpp
// collision/narrow/gjk_raycast.h
#pragma once

#include "collision/narrow/gjk_distance.h"

namespace collision {

inline constexpr int gjk_raycast_max_iterations = 32;

// 原点から dir 方向へのレイが、ミンコフスキー差 B ⊖ A に当たる時刻を求める。
// 見つかれば t ∈ [0, max_t] と、衝突面の外向き法線を返す。
template <SupportShape A, SupportShape B>
[[nodiscard]] RayResult
raycast_gjk(const A& a, const B& b, Vec2 dir, float max_t = 1.0f,
            float tolerance = 1.0e-4f) noexcept {
    if (length_squared(dir) < min_length2) {
        return std::nullopt;   // 動かない
    }

    float t = 0.0f;
    Vec2  x = Vec2{0.0f, 0.0f};      // レイ上の現在点
    Vec2  n = Vec2{0.0f, 0.0f};      // 最後に当たった面の法線

    // 現在の探索方向。x から原点方向へのベクトルで初期化する
    Vec2 v = x - support_diff(a, b, Vec2{1.0f, 0.0f}).diff;
    if (length_squared(v) < min_length2) v = Vec2{1.0f, 0.0f};

    for (int iter = 0; iter < gjk_raycast_max_iterations; ++iter) {
        // x から見たミンコフスキー差（平行移動して考える）への最短ベクトル
        const auto d = detail::distance_from_point(a, b, x);

        if (d.distance <= tolerance) {
            // 境界に達した
            return RayHit{
                .t = t,
                .point = dir * t,
                .normal = normalize_or(n, normalize_or(-dir, Vec2{1.0f, 0.0f})),
                .started_inside = (t <= 0.0f),
            };
        }

        v = d.direction;                 // x から境界へ向かう単位ベクトル
        const float denom = dot(v, dir);

        if (denom >= 0.0f) {
            // レイが境界から遠ざかっている → もう当たらない
            return std::nullopt;
        }

        // レイがこの面に到達する時刻まで進める（保守的）
        t -= d.distance / denom;
        if (t > max_t) return std::nullopt;
        if (t < 0.0f)  t = 0.0f;

        x = dir * t;
        n = -v;                          // 面の外向き法線
    }

    return std::nullopt;   // 収束しなかった
}

} // namespace collision
```

`detail::distance_from_point` は、「点 `x` からミンコフスキー差 `B ⊖ A` までの距離と向き」を返す補助関数である。第 21 章の距離 GJK を、点をずらした形で呼ぶだけで実装できる。

```cpp
namespace detail {

struct PointDistance {
    float distance{};
    Vec2  direction{};   // x から境界へ向かう単位ベクトル
};

// 点 x からミンコフスキー差 B ⊖ A までの距離。
// x を原点に持ってくるため、点そのものを形状として GJK に渡す。
template <SupportShape A, SupportShape B>
[[nodiscard]] PointDistance
distance_from_point(const A& a, const B& b, Vec2 x) noexcept {
    // B ⊖ A ⊖ {x} = B ⊖ (A ⊕ {x})。
    // A を x だけ平行移動したものとの距離を測ればよい
    const Transform xf{.position = x, .rotation = Vec2{1.0f, 0.0f}};
    const auto shifted = transformed(a, xf);

    const auto r = gjk_distance(shifted, b);
    if (r.intersecting) {
        return PointDistance{.distance = 0.0f, .direction = Vec2{1.0f, 0.0f}};
    }
    return PointDistance{
        .distance  = r.distance,
        .direction = normalize_or(r.closest_b - r.closest_a, Vec2{1.0f, 0.0f}),
    };
}

} // namespace detail
```

**第 19.4 節の `Transformed` が、ここで効いている。** 形状をコピーせず、変換を被せるだけで「ずらした形状」が作れる。頂点を書き換える必要がない。

`transformed(a, xf)` の `xf` は回転なしの平行移動だけである。回転が単位（`(1, 0)`）なので、`inverse_rotate` は恒等変換になる。無駄な計算が入るが、実装が統一されている価値のほうが大きい。

### なぜ「保守的」なのか

`t -= d.distance / denom` という更新に注目してほしい。

`d.distance` は現在位置から境界までの最短距離、`denom = dot(v, dir)` はレイの進行方向が境界へ向かう成分である（負の値）。したがって `-d.distance / denom` は正で、「この距離を詰めるのに必要な時間」を表す。

**最短距離を使っているので、進めすぎることがない。** どんなに速く進んでも、この時間だけは絶対に境界を越えない。第 18.2 節の保守的前進とまったく同じ論法である。

## 23.2 保守的前進と GJK 距離を組み合わせる

### もう一つの道

第 18.2 節で保守的前進を実装した。そのとき `distance_between` を要求するコンセプトを置いたが、凸多角形どうしの実装は「第 21 章まで待つ」としていた。

**第 21.3 節で、それが実装された。**

```cpp
template <SupportShape A, SupportShape B>
[[nodiscard]] float distance_between(const A& a, const B& b) noexcept {
    return gjk_distance(a, b).distance;
}
```

したがって、第 18 章の `conservative_advance` が**そのまま任意の凸形状に使える**。新しいコードは不要である。

```cpp
// 凸多角形のスイープ判定（保守的前進版）
const auto toi = collision::conservative_advance(
    poly_a, delta, poly_b,
    [](collision::ConvexPolygon& p, Vec2 d) {
        for (std::uint32_t i = 0; i < p.count; ++i) p.vertex[i] += d;
    });
```

**コンセプトで要求だけしておき、実装を後の章で埋める**という第 18 章の構成が、ここで完結した。

### `Transformed` を使うほうが速い

上の例では、多角形の全頂点を毎回書き換えている。第 19.4 節の `Transformed` を使えば、`Transform` を更新するだけで済む。

```cpp
// collision/narrow/gjk_sweep.h
#pragma once

#include "collision/narrow/ccd.h"
#include "collision/narrow/gjk_distance.h"

namespace collision {

// 任意の凸形状のスイープ判定（保守的前進 + GJK 距離）。
// 形状はコピーせず、Transform だけを更新する。
template <SupportShape A, SupportShape B>
[[nodiscard]] std::optional<ToiResult>
sweep_gjk(const A& a, Vec2 delta, const B& b,
          float target_distance = contact_slop) noexcept {
    const float speed = length(delta);
    if (speed < min_length) {
        return (distance_between(a, b) <= target_distance)
            ? std::optional{ToiResult{.t = 0.0f}} : std::nullopt;
    }

    constexpr int max_iterations = 32;
    float t = 0.0f;

    for (int iter = 0; iter < max_iterations; ++iter) {
        const Transform xf{.position = delta * t, .rotation = Vec2{1.0f, 0.0f}};
        const auto moved = transformed(a, xf);

        const float d = distance_between(moved, b);
        if (d <= target_distance) {
            return ToiResult{.t = t, .converged = true, .iterations = iter};
        }

        const float advance = (d - target_distance) / speed;
        if (!can_advance(advance)) {                    // 第 18.5 節の precise 判定
            return ToiResult{.t = t, .converged = false, .iterations = iter};
        }

        t += advance;
        if (t >= 1.0f) return std::nullopt;
    }

    return ToiResult{.t = t, .converged = false, .iterations = max_iterations};
}

} // namespace collision
```

**第 18.5 節の `can_advance` をそのまま使っている。** 前進量がゼロに潰れて無限ループになる事故への対策は、形状が変わっても同じである。

### 二つの手法の比較

| 項目 | レイキャスト GJK（23.1） | 保守的前進 + GJK 距離（23.2） |
|---|---|---|
| 収束の速さ | 速い（面に沿って一気に進む） | 遅い（距離ぶんずつ）|
| 実装の複雑さ | 高い（GJK と絡み合う） | 低い（距離関数を差すだけ）|
| 距離が近いときの挙動 | 安定 | 前進量が小さくなり反復が増える |
| 回転への対応 | 難しい | 可能（第 18.4 節の速度見積もりを使う）|
| 法線の取得 | 反復の副産物として得られる | 別途 EPA か距離が必要 |

**本書は、実用上は 23.2 節の方法を勧める。** 実装が単純で、第 18 章の枠組みをそのまま使えるからである。反復回数は増えるが、`target_distance` を適切に設定すれば実用範囲に収まる。

レイキャスト GJK は、収束が問題になる場面（極端に高速な物体、極端に近い配置）で検討する価値がある。

### 法線をどう得るか

保守的前進は TOI しか返さない。**衝突法線が必要なら、別途求める。**

方法は二つある。

**1. TOI の位置で距離 GJK を呼ぶ。** `closest_b - closest_a` が法線方向になる（第 21.2 節）。接触寸前なので距離はほぼゼロだが、方向は意味を持つ。

**2. TOI の位置で GJK + EPA を呼ぶ。** `target_distance` だけ手前で止まっているので厳密には交差していないが、わずかに進めれば交差する。

```cpp
// TOI の位置での法線を求める
template <SupportShape A, SupportShape B>
[[nodiscard]] Vec2 sweep_normal(const A& a, Vec2 delta, const B& b, float t) noexcept {
    const Transform xf{.position = delta * t, .rotation = Vec2{1.0f, 0.0f}};
    const auto moved = transformed(a, xf);

    const auto d = gjk_distance(moved, b);
    if (!d.intersecting) {
        // A から B へ向く向き（第 7.3 節の規約）
        return normalize_or(d.closest_b - d.closest_a, normalize_or(delta, Vec2{1.0f, 0.0f}));
    }
    // 既に交差しているなら EPA で求める
    const auto g = gjk(moved, b);
    if (g.status == GjkStatus::intersecting) {
        if (const auto e = epa(moved, b, g.simplex)) return e->normal;
    }
    return normalize_or(delta, Vec2{1.0f, 0.0f});
}
```

**フォールバックを重ねている**のが実務的な工夫である。距離が取れなければ EPA、それも駄目なら移動方向を法線とみなす。**最後の手段でも `NaN` を返さない**ことが重要である。

### 実務ではどう組み立てるか

第 IV 部までの道具が揃ったので、実際のゲームでの判定パイプラインの姿を素描しておく。第 33 章で本格的に組むが、見取り図を持っておくと残りの章が読みやすい。

```
1. ブロードフェーズ（第 VI 部）
     移動経路の AABB で粗く絞り込む
2. CCD が必要か判定（第 18.1 節）
     移動量 > 自分の厚さ + 最薄の障害物 なら CCD へ
3-a. CCD 経路
     sweep_gjk で TOI を求める
     TOI まで進め、contact_slop だけ戻す
     残った移動量を壁に沿わせる（第 17.3 節）
3-b. 通常経路
     移動してから GJK + EPA で交差判定
     マニフォールドを生成（第 14 章）
4. 応答（第 VII 部）
     位置補正、力積、ソルバ
```

**形状ペアごとに最適な手法を選ぶ**のが実務の姿である。

| ペア | 交差判定 | 深度 | スイープ |
|---|---|---|---|
| AABB vs AABB | 専用（第 10 章） | 専用 | 専用（第 17 章） |
| 円 vs 円 | 専用（第 8 章） | 専用 | 専用（第 17 章） |
| 多角形 vs 多角形 | SAT（第 13 章） | SAT | GJK（この章） |
| 円 vs 多角形 | GJK | EPA | GJK |
| その他の混合 | GJK | EPA | GJK |

**専用実装があるペアは専用を使う。** GJK は汎用だが、専用実装より速いことはない。「どんな形状でも動く」という保険として持ち、性能が要る組み合わせには専用実装を用意する。

この使い分けは、第 10 章で述べた「非テンプレートがテンプレートより優先される」というオーバーロード解決の規則で自然に実現できる。汎用の `SupportShape` 版をテンプレートで書き、専用版を非テンプレートで書けばよい。

## 23.3 テスト：第 17 章の実装と一致すること

### 円と AABB での照合

第 17 章の実装は、円と AABB について解析的に TOI を求めている。**それをリファレンスにする。**

```cpp
// test_gjk_sweep.cpp
TEST_CLASS(GjkSweepVsAnalytic) {
public:
    TEST_METHOD(円のスイープが第17章の実装と一致すること) {
        Rng rng(1700);
        int checked = 0;
        float worst = 0.0f;

        for (int i = 0; i < 20000; ++i) {
            const collision::Circle a{{rng.uniform(-5.0f, 5.0f), rng.uniform(-5.0f, 5.0f)},
                                      rng.uniform(0.2f, 1.0f)};
            const collision::Circle b{{rng.uniform(-5.0f, 5.0f), rng.uniform(-5.0f, 5.0f)},
                                      rng.uniform(0.2f, 1.0f)};
            const Vec2 delta{rng.uniform(-10.0f, 10.0f), rng.uniform(-10.0f, 10.0f)};

            if (collision::overlaps(a, b)) continue;

            const auto exact = collision::sweep(a, delta, b);          // 第 17 章
            const auto viagjk = collision::sweep_gjk(a, delta, b);     // この章

            Assert::AreEqual(exact.has_value(), viagjk.has_value(),
                             L"衝突の有無が食い違う");
            if (!exact || !viagjk) continue;
            Assert::IsTrue(viagjk->converged, L"保守的前進が収束しなかった");

            // 保守的前進は target_distance ぶん手前で止まる
            Assert::IsTrue(viagjk->t <= exact->t + 1.0e-4f,
                           L"GJK 版の t が厳密解を超えた");

            const float speed = collision::length(delta);
            const float slack = collision::contact_slop / std::max(speed, 1.0e-3f) + 1.0e-3f;
            worst = std::max(worst, exact->t - viagjk->t);
            Assert::IsTrue(exact->t - viagjk->t < slack + 1.0e-2f,
                detail::widen(std::format("t の差が大きすぎる: {:.6g} vs {:.6g}",
                                          exact->t, viagjk->t)).c_str());
            ++checked;
        }

        Logger::WriteMessage(std::format(
            "照合 {} 件, t の最大遅れ {:.4g}\n", checked, worst).c_str());
        Assert::IsTrue(checked > 3000);
    }

    TEST_METHOD(AABBのスイープが第17章の実装と一致すること) {
        Rng rng(1701);
        int checked = 0;

        for (int i = 0; i < 20000; ++i) {
            const Vec2 alo{rng.uniform(-5.0f, 5.0f), rng.uniform(-5.0f, 5.0f)};
            const Vec2 blo{rng.uniform(-5.0f, 5.0f), rng.uniform(-5.0f, 5.0f)};
            const collision::Aabb a{alo, alo + Vec2{rng.uniform(0.3f, 2.0f),
                                                    rng.uniform(0.3f, 2.0f)}};
            const collision::Aabb b{blo, blo + Vec2{rng.uniform(0.3f, 2.0f),
                                                    rng.uniform(0.3f, 2.0f)}};
            const Vec2 delta{rng.uniform(-10.0f, 10.0f), rng.uniform(-10.0f, 10.0f)};

            if (collision::overlaps(a, b)) continue;

            const auto exact  = collision::sweep(a, delta, b);
            const auto viagjk = collision::sweep_gjk(a, delta, b);

            Assert::AreEqual(exact.has_value(), viagjk.has_value());
            if (!exact || !viagjk) continue;
            Assert::IsTrue(viagjk->t <= exact->t + 1.0e-4f);
            ++checked;
        }
        Assert::IsTrue(checked > 3000);
    }
};
```

**「GJK 版の `t` が厳密解を超えないこと」を検証している**のが要点である。保守的前進の定義そのものであり、第 18.6 節でも同じ検証をした。

**超えたら、それはすり抜けを意味する。** 遅れるのは安全側（早めに止まる）だが、進みすぎは危険である。

### 凸多角形での検証

**第 17 章では扱えなかった形状**である。総当たりをリファレンスにする。

```cpp
TEST_CLASS(GjkSweepPolygon) {
public:
    TEST_METHOD(凸多角形のスイープが総当たりと一致すること) {
        Rng rng(1702);
        int checked = 0;

        for (int i = 0; i < 2000; ++i) {
            const auto a = transformed_poly(random_convex_polygon_checked(rng, 3 + (i % 6)),
                {rng.uniform(-5.0f, 5.0f), rng.uniform(-5.0f, 5.0f)}, rng.uniform(0.0f, 6.28f));
            const auto b = transformed_poly(random_convex_polygon_checked(rng, 3 + (i % 6)),
                {rng.uniform(-5.0f, 5.0f), rng.uniform(-5.0f, 5.0f)}, rng.uniform(0.0f, 6.28f));
            const Vec2 delta{rng.uniform(-10.0f, 10.0f), rng.uniform(-10.0f, 10.0f)};

            if (collision::overlaps(a, b)) continue;

            const auto h = collision::sweep_gjk(a, delta, b);

            // 総当たり：時刻を刻んで最初に交差する点を探す
            constexpr int steps = 3000;
            std::optional<float> brute;
            for (int k = 0; k <= steps; ++k) {
                const float t = static_cast<float>(k) / static_cast<float>(steps);
                auto moved = a;
                for (std::uint32_t v = 0; v < moved.count; ++v) moved.vertex[v] += delta * t;
                if (collision::overlaps(moved, b)) { brute = t; break; }
            }

            Assert::AreEqual(h.has_value(), brute.has_value(),
                             L"衝突の有無が総当たりと食い違う");
            if (!h || !brute) continue;

            // 保守的前進は手前で止まるので、必ず brute 以下
            Assert::IsTrue(h->t <= *brute + 2.0f / steps,
                detail::widen(std::format("t={:.6g} > brute={:.6g}",
                                          h->t, *brute)).c_str());
            ++checked;
        }
        Logger::WriteMessage(std::format("照合 {} 件\n", checked).c_str());
        Assert::IsTrue(checked > 200);
    }

    TEST_METHOD(すり抜けないこと) {
        // 第 17.5 節と同じ配置を、凸多角形で行う
        const auto wall = collision::make_box({0.0f, 0.0f}, {0.05f, 5.0f});
        const auto bullet = collision::make_box({-10.0f, 0.0f}, {0.05f, 0.05f});

        for (float d = 10.0f; d <= 500.0f; d *= 2.0f) {
            const auto h = collision::sweep_gjk(bullet, Vec2{d, 0.0f}, wall);
            Assert::IsTrue(h.has_value(),
                detail::widen(std::format("移動量 {} ですり抜けた", d)).c_str());

            const float hit_x = -10.0f + d * h->t;
            // 壁の手前（x ≒ -0.1）で止まること。target_distance ぶんの余裕を見る
            Assert::IsTrue(hit_x < -0.05f && hit_x > -0.3f,
                detail::widen(std::format("停止位置がおかしい: {:.6g}", hit_x)).c_str());
        }
    }

    TEST_METHOD(法線が押し戻し方向として使えること) {
        Rng rng(1703);
        int checked = 0;

        for (int i = 0; i < 5000; ++i) {
            const auto a = transformed_poly(random_convex_polygon_checked(rng, 4),
                {rng.uniform(-5.0f, 5.0f), rng.uniform(-5.0f, 5.0f)}, rng.uniform(0.0f, 6.28f));
            const auto b = transformed_poly(random_convex_polygon_checked(rng, 4),
                {rng.uniform(-5.0f, 5.0f), rng.uniform(-5.0f, 5.0f)}, rng.uniform(0.0f, 6.28f));
            const Vec2 delta{rng.uniform(-8.0f, 8.0f), rng.uniform(-8.0f, 8.0f)};

            if (collision::overlaps(a, b)) continue;
            const auto h = collision::sweep_gjk(a, delta, b);
            if (!h || !h->converged) continue;

            const Vec2 n = collision::sweep_normal(a, delta, b, h->t);
            expect_near(1.0f, collision::length(n), 1.0e-3f, 1.0e-3f);

            // 法線は移動方向におおむね逆らう向きのはず
            Assert::IsTrue(collision::dot(n, delta) > -1.0e-3f * collision::length(delta)
                        || collision::dot(n, delta) < 0.0f,
                           L"法線が移動方向と無関係");
            ++checked;
        }
        Assert::IsTrue(checked > 500);
    }
};
```

**「すり抜けないこと」のテストが、第 III 部と第 IV 部をつないでいる。** 第 17.5 節では AABB でしか書けなかったものが、凸多角形で書けるようになった。

### レイキャスト GJK との照合

二つの手法が一致することを確認する。

```cpp
TEST_METHOD(レイキャストGJKと保守的前進が一致すること) {
    Rng rng(1704);
    int checked = 0;

    for (int i = 0; i < 10000; ++i) {
        const auto a = transformed_poly(random_convex_polygon_checked(rng, 3 + (i % 6)),
            {rng.uniform(-5.0f, 5.0f), rng.uniform(-5.0f, 5.0f)}, rng.uniform(0.0f, 6.28f));
        const auto b = transformed_poly(random_convex_polygon_checked(rng, 3 + (i % 6)),
            {rng.uniform(-5.0f, 5.0f), rng.uniform(-5.0f, 5.0f)}, rng.uniform(0.0f, 6.28f));
        const Vec2 delta{rng.uniform(-10.0f, 10.0f), rng.uniform(-10.0f, 10.0f)};

        if (collision::overlaps(a, b)) continue;

        const auto ca = collision::sweep_gjk(a, delta, b);
        const auto rc = collision::raycast_gjk(a, b, delta, 1.0f);

        // どちらも「当たる／当たらない」の結論は一致すべき
        Assert::AreEqual(ca.has_value(), rc.has_value(),
                         L"二つの手法で結論が食い違う");
        if (!ca || !rc) continue;

        // 手法が違うので t には差が出る。桁が合っていることを見る
        Assert::IsTrue(std::fabs(ca->t - rc->t) < 0.05f,
            detail::widen(std::format("t が大きく食い違う: CA={:.6g} RC={:.6g}",
                                      ca->t, rc->t)).c_str());
        ++checked;
    }
    Logger::WriteMessage(std::format("照合 {} 件\n", checked).c_str());
    Assert::IsTrue(checked > 1000);
}
```

**許容差を 0.05 と大きく取っている。** 二つの手法は停止条件が違うので、`t` は厳密には一致しない。保守的前進は `target_distance` 手前で止まり、レイキャスト GJK は `tolerance` で止まる。**桁が合っていることを確認するテスト**である。

### 反復回数の比較

```cpp
TEST_METHOD(二つの手法の反復回数を比較する) {
    Rng rng(1705);
    long long ca_iter = 0;
    int n = 0;

    for (int i = 0; i < 20000; ++i) {
        const auto a = transformed_poly(random_convex_polygon_checked(rng, 4),
            {rng.uniform(-5.0f, 5.0f), rng.uniform(-5.0f, 5.0f)}, rng.uniform(0.0f, 6.28f));
        const auto b = transformed_poly(random_convex_polygon_checked(rng, 4),
            {rng.uniform(-5.0f, 5.0f), rng.uniform(-5.0f, 5.0f)}, rng.uniform(0.0f, 6.28f));
        const Vec2 delta{rng.uniform(-10.0f, 10.0f), rng.uniform(-10.0f, 10.0f)};

        if (collision::overlaps(a, b)) continue;
        const auto ca = collision::sweep_gjk(a, delta, b);
        if (!ca) continue;
        ca_iter += ca->iterations;
        ++n;
    }

    Logger::WriteMessage(std::format(
        "保守的前進: 平均反復 {:.2f} 回（{} 件）\n",
        static_cast<double>(ca_iter) / std::max(n, 1), n).c_str());
}
```

**数字を記録に残す**（第 11.6 節、第 20.6 節と同じ方針）。23.2 節で「反復回数は増えるが実用範囲」と述べた主張の裏づけになる。

## この章のまとめ

- **レイキャスト GJK**：ミンコフスキー差を構築せずにレイキャストする。最短距離を使って保守的に進める
- **保守的前進 + GJK 距離**：第 18 章の枠組みに距離関数を差し込むだけ。新しいコードは不要
- 第 18 章の `HasDistance` コンセプトが、第 21 章の `gjk_distance` で満たされた
- **`Transformed`（第 19.4 節）を使えば、形状をコピーせずに位置だけ更新できる**
- 本書は実装の単純さから 23.2 節の方法を勧める。収束が問題なら 23.1 節を検討する
- 法線は TOI の位置で距離 GJK か EPA を呼んで得る。フォールバックを重ねて `NaN` を出さない
- **保守的前進の `t` は、厳密解を絶対に超えない。** 超えたらすり抜けである
- テストは第 17 章（円・AABB の解析解）と総当たり（凸多角形）の二本立て

### 第 IV 部を終えて

第 1 章の対応表でいえば、**「第 23 章：任意の凸形状に対応した汎用判定エンジン（2D）」に到達した**。

| できること | 章 |
|---|---|
| 任意の凸形状のサポート写像 | 第 19 章 |
| 任意の凸形状の交差判定 | 第 20 章 |
| 任意の凸形状の距離と最近接点 | 第 21 章 |
| 任意の凸形状の貫通深度と法線 | 第 22 章 |
| 任意の凸形状のスイープ判定 | この章 |

**第 III 部で保留した宿題がすべて片付いた。** 円、AABB、OBB、凸多角形、カプセル、点、そして（練習問題で扱った）楕円まで、すべて同じアルゴリズムで扱える。

サポート写像という一つの窓口が、これだけの射程を持っていた。第 19 章の冒頭で「サポート写像は、それ自体では何も判定しない」と書いた。その意味が、ここまで来ると分かるはずである。

### 第 IV 部で確立した検証の構造

この部では、リファレンス比較（第 11.6 節）が多層になった。整理しておく。

| 検証したいもの | リファレンス | 章 |
|---|---|---|
| GJK の交差判定 | SAT | 第 20 章 |
| GJK の距離 | 解析解（円）、総当たり（多角形） | 第 21 章 |
| EPA の深度・法線 | SAT の MTV | 第 22 章 |
| **SAT と EPA の食い違い** | **ミンコフスキー差を陽に構築した厳密解** | 第 22 章 |
| GJK スイープ | 第 17 章の解析解、総当たり | この章 |

**最下段が重要である。** 二つの実装が食い違ったとき、決着をつける手段を持っておく。遅くてよい。正しければよい。

本書の執筆過程でも、この「究極のリファレンス」によって第 11.2 節のバグが発見された。**リファレンス比較は、新しい実装だけでなく古い実装も検証する。**

### 落とし穴と練習問題

**落とし穴 1：保守的前進の `t` が厳密解を超える。**　すり抜けを意味する。テストで必ず検証する。

**落とし穴 2：法線を求めるフォールバックがない。**　接触寸前では距離がほぼゼロで、向きが不安定になりうる。

**落とし穴 3：`Transformed` の寿命。**　第 19.4 節と同じ注意。ループ内で作って外へ持ち出さない。

**練習問題 23-1**　`target_distance` を変えて、`sweep_gjk` の反復回数と精度がどう変わるかを測ろう。第 18.6 節と同じ実験を、凸多角形で行う。

**練習問題 23-2**　`sweep_gjk` に「両方が動く」版を追加しよう。第 17.1 節の相対運動への還元がそのまま使える。

**練習問題 23-3**　円と凸多角形のスイープを試そう。第 17 章の方法では「角が丸まった多角形」を構築する必要があった（練習問題 17-3）。GJK なら構築が不要である。両者を比べてほしい。

**練習問題 23-4**　第 18.4 節で扱った回転を、`sweep_gjk` に組み込んでみよう。`Transform` の `rotation` も `t` に応じて更新し、最大速度に角速度の寄与を加える。反復回数はどれだけ増えるだろうか。

**練習問題 23-5**（発展）　レイキャスト GJK を、単体をフレーム間で保持する形に改良しよう。前回の単体から始めれば、GJK 距離の反復が減る。実際の実装ではこの最適化が効く。

---

第 V 部では、いよいよ 3 次元へ進む。**多くは次元が増えるだけである。** サポート写像も、GJK の骨格も、EPA の考え方も変わらない。変わるのは、単体が四面体になること、EPA のポリトープが面のリストになること、そして SAT で辺の外積が必要になることである。

一方で、新しい山場もある。線分と線分の最近接点、そして 3D の SAT における 15 軸。第 V 部の冒頭で、3D の数学から始める。
