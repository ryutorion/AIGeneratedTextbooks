# 第 16 章　ミンコフスキー和で「膨らませる」

> **この章のゴール**
> ミンコフスキー和・差という道具を導入し、二つの発見をする。
>
> 一つ目。**「A と B が交差する」は「原点が A ⊖ B に含まれる」と同じ**である。二つの形状の問題が、一つの形状と一点の問題になる。
>
> 二つ目。**「A が移動して B に当たるか」は「原点からのレイが B ⊖ A に当たるか」と同じ**である。動く形状の判定が、前章のレイキャストに帰着する。
>
> 新しいコードはほとんど書かない。**見方を変えるだけで、すでに持っている道具の射程が一気に広がる**、という章である。そしてこの見方は、第 IV 部の GJK へまっすぐ続いている。

---

## 16.1 ミンコフスキー和とは何か

### 定義

二つの点集合 A と B について、**ミンコフスキー和**を次のように定める。

```
A ⊕ B = { a + b : a ∈ A, b ∈ B }
```

A のすべての点と B のすべての点を、あらゆる組み合わせで足し合わせた集合である。

言葉だと分かりにくいので、具体例で捉える。

### 例 1：点 ⊕ 円

A が原点だけの集合 `{(0,0)}`、B が半径 1 の円（中心 `(0,0)`、内部を含む円板）だとする。

`A ⊕ B` は、`(0,0) + b` を全部集めたものだから、B そのものである。

では A を `{(3,0)}` にすると。`A ⊕ B` は、円全体を `(3,0)` だけ平行移動したものになる。

**点とのミンコフスキー和は、平行移動である。**

### 例 2：円 ⊕ 円

A が中心 `ca` 半径 `ra` の円、B が中心 `cb` 半径 `rb` の円。

`A ⊕ B` は、**中心 `ca + cb`、半径 `ra + rb` の円**になる。

なぜか。A の点は `ca + (半径 ra 以内の任意のベクトル)` と書ける。B も同様。足すと `ca + cb + (半径 ra 以内) + (半径 rb 以内)` になり、後半の和は「半径 `ra + rb` 以内の任意のベクトル」を作れる。

**これが「膨らませる」というイメージの源である。** 円とのミンコフスキー和は、形状をその半径だけ全方向に膨らませる。

### 例 3：線分 ⊕ 円

線分を円で膨らませると、**カプセル**（両端が丸い長方形）になる。

これは実装上も重要である。第 9 章の練習問題 9-3 でカプセルに触れたが、その正体は「線分 ⊕ 円」である。カプセルとの判定が「線分への最近接点＋半径の比較」で書けるのは、この構造による。

### 例 4：AABB ⊕ AABB

軸ごとに独立に考えればよい。X 方向の区間 `[a.min.x, a.max.x]` と `[b.min.x, b.max.x]` の和は、`[a.min.x + b.min.x, a.max.x + b.max.x]` になる。

```cpp
// collision/narrow/minkowski.h
#pragma once

#include "collision/shapes/aabb.h"
#include "collision/shapes/circle.h"

namespace collision {

// A ⊕ B
[[nodiscard]] constexpr Aabb minkowski_sum(const Aabb& a, const Aabb& b) noexcept {
    return Aabb{.min = a.min + b.min, .max = a.max + b.max};
}

[[nodiscard]] constexpr Circle minkowski_sum(const Circle& a, const Circle& b) noexcept {
    return Circle{.center = a.center + b.center, .radius = a.radius + b.radius};
}

} // namespace collision
```

**円どうし、AABB どうしのミンコフスキー和は、同じ種類の形状になる。** これは特別に都合のよい性質である。一般の凸多角形どうしでは、辺の数が増えた別の凸多角形になる。

### ミンコフスキー差

**ミンコフスキー差**は、B を反転してから足したものと定める。

```
A ⊖ B = A ⊕ (-B) = { a - b : a ∈ A, b ∈ B }
```

`-B` は「B のすべての点の符号を反転した集合」、つまり原点について点対称に移した形である。

```cpp
[[nodiscard]] constexpr Aabb negated(const Aabb& b) noexcept {
    // 各点の符号を反転すると、min と max も入れ替わる
    return Aabb{.min = -b.max, .max = -b.min};
}

[[nodiscard]] constexpr Circle negated(const Circle& c) noexcept {
    return Circle{.center = -c.center, .radius = c.radius};   // 円は対称なので半径は不変
}

[[nodiscard]] constexpr Aabb minkowski_diff(const Aabb& a, const Aabb& b) noexcept {
    return minkowski_sum(a, negated(b));
}

[[nodiscard]] constexpr Circle minkowski_diff(const Circle& a, const Circle& b) noexcept {
    return minkowski_sum(a, negated(b));
}
```

`negated(Aabb)` で `min` と `max` が入れ替わる点に注意してほしい。符号を反転すると大小関係が逆転するので、そのまま反転すると不正な AABB（`min > max`）になる。

> **用語の注意**
> 数学では「ミンコフスキー差」を別の意味（`{ x : x + B ⊆ A }`、収縮に相当する）で使うことがある。**衝突判定の文献では、本書の定義（`A ⊕ (-B)`）が標準である。** 混乱を避けるため、「ミンコフスキー差」と書いたら常にこちらを指すものとする。

## 16.2 交差判定が「原点を含むか」になる

### 中心的な等価性

ここが本章で最も重要な事実である。

> **A と B が交差する ⇔ 原点が `A ⊖ B` に含まれる**

証明は一行で済む。

- A と B が交差する
- ⇔ ある点 `p` が A にも B にも属する
- ⇔ ある `a ∈ A`、`b ∈ B` について `a = b`
- ⇔ ある `a ∈ A`、`b ∈ B` について `a - b = 0`
- ⇔ `0 ∈ A ⊖ B`

**二つの形状の関係が、一つの形状と一点の関係に変わった。** これが強力である。「二つの形状がどう重なっているか」という複雑な問題が、「原点がこの形状のどこにあるか」という単純な問題になる。

### 円で確かめる

`A ⊖ B` は、中心 `ca - cb`、半径 `ra + rb` の円である。

原点がこの円に含まれる条件は、中心から原点までの距離が半径未満、つまり

```
|ca - cb| < ra + rb
```

**第 8.1 節で書いた円と円の判定式そのものである。**

あの式は「中心間距離が半径の和より小さい」という直感から導いた。ミンコフスキー差の観点からは、「原点が膨らませた円に入っている」ことの言い換えだった、と分かる。

### AABB で確かめる

`A ⊖ B` は、`min = a.min - b.max`、`max = a.max - b.min` の AABB である。

原点がこれに含まれる条件は、

```
a.min.x - b.max.x <= 0 <= a.max.x - b.min.x
```

整理すると `b.min.x <= a.max.x` かつ `a.min.x <= b.max.x` になる。**第 10.2 節の区間の重なり判定と一致する。**

### コードで書く

```cpp
// collision/narrow/minkowski.h（続き）

// ミンコフスキー差に原点が含まれるかで交差を判定する。
// 直接の実装（第 8 章・第 10 章）と結果が一致することの確認用。
[[nodiscard]] constexpr bool
overlaps_via_minkowski(const Circle& a, const Circle& b) noexcept {
    const Circle m = minkowski_diff(a, b);
    return length_squared(m.center) < m.radius * m.radius;
}

[[nodiscard]] constexpr bool
overlaps_via_minkowski(const Aabb& a, const Aabb& b) noexcept {
    const Aabb m = minkowski_diff(a, b);
    return contains(m, Vec2{0.0f, 0.0f});
}
```

**これは実用のためのコードではない。** 直接の実装のほうが速い（ミンコフスキー差を作る手間がない）。等価性を確認し、理解を固めるためのコードである。16.5 節でテストにする。

### 凸多角形どうしの和は「構築できるが高くつく」

任意の凸形状どうしのミンコフスキー和も、原理的には構築できる。**両者の辺を、法線の角度順にマージすればよい。**

理由を説明する。凸多角形 `A ⊕ B` の境界は、A の辺と B の辺だけからなる。ある向きに最も突き出た点は、A のその向きに最も突き出た点と、B のそれとの和だからである。向きを一周させると、A の辺と B の辺が角度順に並んで現れる。

三角形と四角形の例で数えてみる。

- A の辺の法線：3 本、それぞれ角度を持つ
- B の辺の法線：4 本
- `A ⊕ B` の辺：**7 本**（角度順にマージ）

一般に、n 角形と m 角形の和は `n + m` 角形になる。

```
三角形 ⊕ 三角形 = 六角形
四角形 ⊕ 四角形 = 八角形
八角形 ⊕ 八角形 = 十六角形   ← 第 13.1 節の上限 8 を超える
```

**第 13.1 節で頂点数の上限を 8 にしたことが、ここで足枷になる。** 八角形どうしの和は十六角形になり、格納できない。上限を上げても、その上限でまた同じ問題が起きる。

さらに、構築のコストも無視できない。辺をソートしてマージする処理は、判定そのものより重くなりうる。**毎フレーム、判定するペアごとにこれを行うのは現実的でない。**

### 例外：円との和だけは安い

一方、**凸多角形と円のミンコフスキー和は、頂点数が増えない**。

各辺が法線方向に半径だけ押し出され、頂点が円弧に置き換わる。「角の丸まった多角形」になる。辺の本数は変わらず、頂点が円弧になるだけである。

カプセル（線分 ⊕ 円）がその最も単純な例である。第 17 章で、この性質を使って「動く円 vs 静止線分」を解く。

**円との和が安いことは、実装上きわめて有用である。** 「膨らませる」操作が形状の複雑さを増やさないので、マージンを持たせた判定（第 21.3 節）や、キャラクターの半径を考慮した経路判定に自然に使える。

### この見方が本領を発揮するのは第 IV 部

明示的に構築するのが難しい以上、別の道が要る。

**GJK（第 20 章）が画期的なのは、ミンコフスキー差を構築せずに「原点が含まれるか」を判定する点にある。** サポート写像という道具で、ミンコフスキー差の「必要な部分だけ」を問い合わせる。

この章の等価性を理解しておくと、GJK が「何をしているのか」が明快になる。**GJK は、この章の問題を、形状を作らずに解く方法である。**

## 16.3 距離もミンコフスキー差で表せる

### 交差していない場合

原点が `A ⊖ B` の外にあるとき、**原点から `A ⊖ B` までの最短距離が、A と B の最短距離に等しい**。

これも定義から従う。`A ⊖ B` の点は `a - b` の形をしており、その原点からの距離は `|a - b|` である。これを最小化することは、A の点と B の点の距離を最小化することに他ならない。

### 貫通深度も同様

原点が `A ⊖ B` の内部にあるとき、**原点から `A ⊖ B` の境界までの最短距離が、貫通深度になる**。

そして、その最短の向きが押し戻すべき法線である。

**これが第 22 章の EPA（Expanding Polytope Algorithm）がやっていることである。** ミンコフスキー差の内部にある原点から、最も近い境界を探す。

第 11 章の SAT が求めた MTV も、同じものを別の方法で求めている。SAT は軸を列挙して最小を選び、EPA はミンコフスキー差の境界を探索する。**答えは同じである**（第 22 章でこれをテストにする）。

### 一枚の表にまとめる

ミンコフスキー差の観点から、これまでの章とこれからの章を整理しておく。

| 問い | ミンコフスキー差での言い換え | 章 |
|---|---|---|
| 交差しているか | 原点が `A ⊖ B` に含まれるか | この章、第 20 章 |
| どれだけ離れているか | 原点から `A ⊖ B` までの距離 | 第 21 章 |
| どれだけめり込んでいるか | 原点から `A ⊖ B` の境界までの距離 | 第 22 章 |
| いつ衝突するか | 原点からのレイが `B ⊖ A` に当たる時刻 | 次節、第 17 章 |

**四つの異なる問いが、すべて「原点と `A ⊖ B` の位置関係」に帰着している。** これが本書で最も強力な統一である。

## 16.4 動く形状の判定をレイキャストに変える

### 問題設定

形状 A が、1 フレームで `delta` だけ平行移動する。静止している形状 B に、いつ当たるか。

時刻 `t ∈ [0, 1]` における A の位置を `A(t) = A + delta·t` と書く（形状全体を平行移動したもの）。求めたいのは、`A(t)` と `B` が交差する最小の `t` である。

### 帰着

前節の等価性を使う。

```
A(t) と B が交差する
⇔ 0 ∈ A(t) ⊖ B
⇔ 0 ∈ (A + delta·t) ⊖ B
```

ここで、平行移動はミンコフスキー差の中で外に出せる。`(A + v) ⊖ B = (A ⊖ B) + v` である（定義に戻れば明らか）。したがって、

```
⇔ 0 ∈ (A ⊖ B) + delta·t
⇔ -delta·t ∈ A ⊖ B
⇔ delta·t ∈ B ⊖ A
```

最後の変形は、`A ⊖ B` と `B ⊖ A` が原点について点対称であることを使った（`B ⊖ A = -(A ⊖ B)`）。

### 得られた結論

> **A が `delta` だけ動いて B に当たる時刻 `t` は、原点から向き `delta` へ放ったレイが、`B ⊖ A` に当たる時刻に等しい。**

**動く形状の判定が、静止形状へのレイキャストになった。** 前章で作った道具がそのまま使える。

`Ray{origin = (0,0), dir = delta, max_t = 1}` を `B ⊖ A` に飛ばす。返ってきた `t` が、そのままフレーム内の衝突時刻（TOI）である。第 15.1 節で `dir` を正規化しない設計にした理由が、ここで回収される。

### 円どうしで確かめる

A が半径 `ra` の円（中心 `ca`）、B が半径 `rb` の円（中心 `cb`）。

`B ⊖ A` は、中心 `cb - ca`、半径 `rb + ra` の円である。

原点から `delta` 方向へレイを飛ばし、この円に当たる時刻を求める。これは**まさに「動く円が静止円に当たる時刻」の正しい答え**である。

しかも、実装は前章の `raycast(Ray, Circle)` をそのまま呼ぶだけになる。

```cpp
// collision/narrow/sweep.h
#pragma once

#include "collision/narrow/minkowski.h"
#include "collision/narrow/raycast.h"

namespace collision {

// 円 a が delta だけ動く間に、静止円 b と衝突する時刻を求める。
[[nodiscard]] inline RayResult
sweep(const Circle& a, Vec2 delta, const Circle& b) noexcept {
    // B ⊖ A（原点からのレイを飛ばす対象）
    const Circle m = minkowski_diff(b, a);

    const Ray ray{.origin = Vec2{0.0f, 0.0f}, .dir = delta, .max_t = 1.0f};
    return raycast(ray, m);
}

} // namespace collision
```

**新しい判定コードを一行も書かずに、スイープ判定ができた。** これがミンコフスキー和という見方の威力である。

### AABB どうしでも同じ

```cpp
[[nodiscard]] inline RayResult
sweep(const Aabb& a, Vec2 delta, const Aabb& b) noexcept {
    const Aabb m = minkowski_diff(b, a);
    const Ray ray{.origin = Vec2{0.0f, 0.0f}, .dir = delta, .max_t = 1.0f};
    return raycast(ray, m);
}
```

`minkowski_diff(b, a)` は `min = b.min - a.max`、`max = b.max - a.min` の AABB である。これは A の大きさだけ B を膨らませたものになっている。

**「動く箱と静止する箱」の判定が、「動く点と、膨らませた箱」の判定になった。** 直感的にも納得できる。A を点に縮める代わりに、その分だけ B を大きくしたのである。

### 法線の扱いに注意

`raycast` が返す法線は、`B ⊖ A` の表面の外向き法線である。

**これは、A から見た衝突面の法線と一致する。** ミンコフスキー差の空間での向きは、元の空間での「B の表面から A へ向かう向き」に対応する。

第 7.3 節の規約は「法線は A から B へ」だった。`B ⊖ A` の外向き法線は A から B への向きの**逆**になるので、規約に合わせるには符号を反転する必要がある。第 17 章で扱う。

**ここが混乱しやすい。** 符号の規約は必ずテストで守る（第 7.3 節）。

## 16.5 テスト：帰着の前後で結果が一致すること

### 等価性テスト

第 11.6 節で導入したリファレンス比較を、この章の主張に対して適用する。

```cpp
// test_minkowski.cpp
#include "CppUnitTest.h"
#include "test_helpers.h"
#include "collision/narrow/minkowski.h"
#include "collision/narrow/sweep.h"

using namespace Microsoft::VisualStudio::CppUnitTestFramework;
using collision::Aabb;
using collision::Circle;
using collision::Vec2;

namespace collision_tests {

TEST_CLASS(MinkowskiEquivalence) {
public:
    TEST_METHOD(円の交差判定がミンコフスキー差経由と一致すること) {
        Rng rng(1000);
        for (int i = 0; i < 50000; ++i) {
            const Circle a{{rng.uniform(-4.0f, 4.0f), rng.uniform(-4.0f, 4.0f)},
                           rng.uniform(0.2f, 2.0f)};
            const Circle b{{rng.uniform(-4.0f, 4.0f), rng.uniform(-4.0f, 4.0f)},
                           rng.uniform(0.2f, 2.0f)};

            Assert::AreEqual(collision::overlaps(a, b),
                             collision::overlaps_via_minkowski(a, b),
                             L"円の判定が食い違う");
        }
    }

    TEST_METHOD(AABBの交差判定がミンコフスキー差経由と一致すること) {
        Rng rng(1001);
        for (int i = 0; i < 50000; ++i) {
            const Vec2 alo{rng.uniform(-4.0f, 4.0f), rng.uniform(-4.0f, 4.0f)};
            const Vec2 blo{rng.uniform(-4.0f, 4.0f), rng.uniform(-4.0f, 4.0f)};
            const Aabb a{alo, alo + Vec2{rng.uniform(0.3f, 3.0f), rng.uniform(0.3f, 3.0f)}};
            const Aabb b{blo, blo + Vec2{rng.uniform(0.3f, 3.0f), rng.uniform(0.3f, 3.0f)}};

            Assert::AreEqual(collision::overlaps(a, b),
                             collision::overlaps_via_minkowski(a, b),
                             L"AABB の判定が食い違う");
        }
    }
};
```

**この二つのテストが、16.2 節の主張の実証である。** 数学的には自明だが、実装が正しいかは別問題である。特に `negated(Aabb)` で `min`/`max` を入れ替える処理は、間違えやすい。

### ミンコフスキー和の性質

集合演算としての性質も検証しておく。

```cpp
TEST_CLASS(MinkowskiProperties) {
public:
    TEST_METHOD(ミンコフスキー和が可換であること) {
        Rng rng(1002);
        for (int i = 0; i < 10000; ++i) {
            const Vec2 alo{rng.uniform(-5.0f, 5.0f), rng.uniform(-5.0f, 5.0f)};
            const Vec2 blo{rng.uniform(-5.0f, 5.0f), rng.uniform(-5.0f, 5.0f)};
            const Aabb a{alo, alo + Vec2{1.0f, 2.0f}};
            const Aabb b{blo, blo + Vec2{3.0f, 1.0f}};

            const Aabb ab = collision::minkowski_sum(a, b);
            const Aabb ba = collision::minkowski_sum(b, a);
            expect_near(ab.min, ba.min);
            expect_near(ab.max, ba.max);
        }
    }

    TEST_METHOD(ミンコフスキー差が反可換であること) {
        // A ⊖ B と B ⊖ A は原点について点対称
        Rng rng(1003);
        for (int i = 0; i < 10000; ++i) {
            const Circle a{{rng.uniform(-5.0f, 5.0f), rng.uniform(-5.0f, 5.0f)},
                           rng.uniform(0.2f, 2.0f)};
            const Circle b{{rng.uniform(-5.0f, 5.0f), rng.uniform(-5.0f, 5.0f)},
                           rng.uniform(0.2f, 2.0f)};

            const Circle ab = collision::minkowski_diff(a, b);
            const Circle ba = collision::minkowski_diff(b, a);

            expect_near(-ab.center, ba.center);
            expect_near(ab.radius, ba.radius);
        }
    }

    TEST_METHOD(点とのミンコフスキー和が平行移動になること) {
        const Aabb box{{-1.0f, -2.0f}, {3.0f, 4.0f}};
        const Aabb point{{5.0f, 7.0f}, {5.0f, 7.0f}};   // 縮退した AABB ＝ 点

        const Aabb moved = collision::minkowski_sum(box, point);
        expect_near(Vec2{4.0f, 5.0f},  moved.min);
        expect_near(Vec2{8.0f, 11.0f}, moved.max);
    }

    TEST_METHOD(和の実体が定義どおりであること) {
        // 定義 { a + b } を総当たりで確認する（AABB の周上をサンプリング）
        const Aabb a{{-1.0f, -1.0f}, {1.0f, 1.0f}};
        const Aabb b{{ 2.0f,  0.0f}, {4.0f, 3.0f}};
        const Aabb sum = collision::minkowski_sum(a, b);

        Rng rng(1004);
        for (int i = 0; i < 20000; ++i) {
            const Vec2 pa{rng.uniform(a.min.x, a.max.x), rng.uniform(a.min.y, a.max.y)};
            const Vec2 pb{rng.uniform(b.min.x, b.max.x), rng.uniform(b.min.y, b.max.y)};
            Assert::IsTrue(collision::contains(sum, pa + pb),
                           L"a + b が和の外にある");
        }
    }
};
```

最後のテストが、**定義そのものの検証**である。「A の点と B の点を足したものが、必ず `A ⊕ B` に入る」ことを、ランダムサンプリングで確かめている。

第 9.6 節の「最近接点より近い点が存在しない」テストと同じ発想である。**定義に立ち返った素朴な検証は、公式の実装を裏づける最も直接的な方法**である。

### スイープの帰着が正しいこと

16.4 節の主張を、独立した方法で検証する。

```cpp
TEST_CLASS(SweepReduction) {
public:
    TEST_METHOD(スイープ結果が時刻を刻んだ総当たりと一致すること) {
        Rng rng(1010);
        int checked = 0;

        for (int i = 0; i < 5000; ++i) {
            const Circle a{{rng.uniform(-5.0f, 5.0f), rng.uniform(-5.0f, 5.0f)},
                           rng.uniform(0.2f, 1.0f)};
            const Circle b{{rng.uniform(-5.0f, 5.0f), rng.uniform(-5.0f, 5.0f)},
                           rng.uniform(0.2f, 1.0f)};
            const Vec2 delta{rng.uniform(-8.0f, 8.0f), rng.uniform(-8.0f, 8.0f)};

            // 開始時点で既に交差しているケースは除外する（別の議論になる）
            if (collision::overlaps(a, b)) continue;

            const auto h = collision::sweep(a, delta, b);

            // 総当たりリファレンス：時刻を細かく刻んで最初に交差する点を探す
            constexpr int steps = 2000;
            std::optional<float> brute;
            for (int k = 0; k <= steps; ++k) {
                const float t = static_cast<float>(k) / static_cast<float>(steps);
                const Circle moved{a.center + delta * t, a.radius};
                if (collision::overlaps(moved, b)) { brute = t; break; }
            }

            Assert::AreEqual(h.has_value(), brute.has_value(),
                             L"衝突の有無が総当たりと食い違う");
            if (!h || !brute) continue;

            // 刻み幅ぶんの誤差を許容する
            Assert::IsTrue(std::fabs(h->t - *brute) < 2.0f / steps,
                detail::widen(std::format("TOI が食い違う: sweep={:.6g} brute={:.6g}",
                                          h->t, *brute)).c_str());
            ++checked;
        }

        Logger::WriteMessage(std::format("照合できた事例 {} 件\n", checked).c_str());
        Assert::IsTrue(checked > 200, L"照合できた事例が少なすぎる");
    }

    TEST_METHOD(衝突時刻の位置で実際に接していること) {
        Rng rng(1011);
        for (int i = 0; i < 20000; ++i) {
            const Circle a{{rng.uniform(-5.0f, 5.0f), rng.uniform(-5.0f, 5.0f)},
                           rng.uniform(0.2f, 1.0f)};
            const Circle b{{rng.uniform(-5.0f, 5.0f), rng.uniform(-5.0f, 5.0f)},
                           rng.uniform(0.2f, 1.0f)};
            const Vec2 delta{rng.uniform(-8.0f, 8.0f), rng.uniform(-8.0f, 8.0f)};

            if (collision::overlaps(a, b)) continue;
            const auto h = collision::sweep(a, delta, b);
            if (!h) continue;

            // 衝突時刻での中心間距離は、半径の和にほぼ等しいはず
            const Vec2 moved_center = a.center + delta * h->t;
            const float d = collision::distance(moved_center, b.center);
            expect_near(a.radius + b.radius, d, 1.0e-4f, 1.0e-4f);
        }
    }

    TEST_METHOD(すり抜けないこと) {
        // 薄い壁を高速で通過させる。離散判定なら見逃す配置
        const Aabb wall{{-0.05f, -10.0f}, {0.05f, 10.0f}};   // 厚さ 0.1
        const Aabb bullet{{-5.05f, -0.05f}, {-4.95f, 0.05f}}; // 幅 0.1、x = -5
        const Vec2 delta{10.0f, 0.0f};                        // 1 フレームで 10 進む

        // 離散判定：始点と終点だけを見る
        const Aabb moved{bullet.min + delta, bullet.max + delta};
        Assert::IsFalse(collision::overlaps(bullet, wall), L"始点で交差している");
        Assert::IsFalse(collision::overlaps(moved,  wall), L"終点で交差している");

        // スイープなら捉えられる
        const auto h = collision::sweep(bullet, delta, wall);
        Assert::IsTrue(h.has_value(), L"スイープでもすり抜けた");
        Assert::IsTrue(h->t > 0.0f && h->t < 1.0f, L"衝突時刻がフレーム内にない");
    }
};
```

**最後のテストが、第 III 部の存在理由そのものである。**

始点でも終点でも交差していないのに、途中で確実に通過している。第 1 章で「時間が離散的である」と述べた問題が、具体的な数値として現れている。そして、この章の帰着によってそれが捉えられる。

一つ目のテストで**総当たりをリファレンスにしている**のも重要である。時刻を 2000 分割して最初に交差する点を探す、という素朴な方法は明らかに正しい。それと一致すれば、帰着が正しいと言える。

## この章のまとめ

- **ミンコフスキー和** `A ⊕ B = { a + b }`。円との和は「膨らませる」、点との和は「平行移動」
- **ミンコフスキー差** `A ⊖ B = A ⊕ (-B) = { a - b }`。`negated(Aabb)` では `min`/`max` が入れ替わる
- **交差判定の等価性：A と B が交差する ⇔ 原点が `A ⊖ B` に含まれる**
- 第 8 章の円の判定式も、第 10 章の区間の重なりも、この等価性の具体例だった
- 距離は「原点から `A ⊖ B` までの距離」、貫通深度は「原点から境界までの距離」
- **四つの問い（交差・距離・深度・衝突時刻）が、すべて原点と `A ⊖ B` の位置関係に帰着する**
- **スイープの帰着：A が `delta` 動いて B に当たる時刻 = 原点から `delta` 方向のレイが `B ⊖ A` に当たる時刻**
- 新しい判定コードを書かずに、前章のレイキャストでスイープが実現できた
- 法線の向きは反転が必要（`B ⊖ A` の外向き法線と、第 7.3 節の規約は逆）
- GJK（第 20 章）は、ミンコフスキー差を**構築せずに**この判定を行う方法である

### 落とし穴と練習問題

**落とし穴 1：`negated(Aabb)` で `min`/`max` を入れ替え忘れる。**　不正な AABB になり、以降のすべてが壊れる。

**落とし穴 2：`A ⊖ B` と `B ⊖ A` を取り違える。**　符号が反転する。スイープでは `B ⊖ A` を使う。

**落とし穴 3：法線の符号。**　ミンコフスキー空間の外向き法線は、第 7.3 節の規約と逆向き。

---

**練習問題 16-1**　線分と円のミンコフスキー和（カプセル）を表す型を作り、それへのレイキャストを実装しよう。第 17 章で「動く円と静止線分」の判定に使う。線分への最近接点と半径の比較で書ける。

**練習問題 16-2**　16.2 節で述べた辺のマージによって、二つの凸多角形のミンコフスキー和を実際に構築してみよう。三角形どうしで六角形になることを確認する。次に構築にかかる時間を測り、第 13 章の SAT による直接判定と比べてほしい。**これが「明示的に構築しない」GJK の動機である。**

**練習問題 16-3**　16.5 節の「すり抜けない」テストで、壁の厚さと移動量を変えながら、どの条件で離散判定が失敗するかを表にしてみよう。第 18.1 節でこの条件を式にする。

**練習問題 16-4**　`overlaps_via_minkowski` を凸多角形に対して書こう。練習問題 16-2 で作った和を使い、原点を含むかを判定する。第 13 章の直接実装と一致することを確認する。速度はどれだけ違うだろうか。

**練習問題 16-5**（発展）　「A が `delta_a` だけ動き、B も `delta_b` だけ動く」場合の帰着を導いてみよう。相対運動を使えば片方を止められる。次章 17.1 節の内容の先取りである。
