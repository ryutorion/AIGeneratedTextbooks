# 第 19 章　サポート写像 ― すべての凸形状を一つの窓口にする

> **この章のゴール**
> 「ある向きについて、形状の最も遠い点はどこか」を返す関数 ― サポート写像を実装する。円、多角形、カプセル、点、線分。それぞれ数行で書ける。
>
> この章だけを読むと、何のためにこんなものを作るのか分からないかもしれない。**サポート写像は、それ自体では何も判定しない。** だが次章から始まる GJK と EPA は、この関数だけを通して形状に触れる。形状の種類を知らないまま、あらゆる凸形状を扱えるようになる。
>
> 第 16 章で「ミンコフスキー差を構築せずに調べる方法が要る」と述べた。サポート写像がその窓口である。

---

## 19.1 サポート関数の定義と直感

### 定義

凸形状 `S` と向き `d` について、**サポート点**を次のように定める。

```
support(S, d) = argmax { dot(p, d) : p ∈ S }
```

`S` に属する点のうち、`d` との内積が最大になる点である。言い換えると、**`d` の向きに最も突き出た点**である。

第 6.5 節で述べた「内積の読み方 1：射影の長さ」を思い出してほしい。`dot(p, d)` は `p` を `d` に射影した長さである。それが最大の点、つまり `d` 方向の最先端にある点を返す。

### 直感

形状を平らな板で押し潰す様子を想像するとよい。板を `d` に垂直に構えて、形状に向かって押し込んでいく。**最初に板が触れる点がサポート点である。**

- 円なら、中心から `d` 方向へ半径だけ進んだ点
- 多角形なら、どれかの頂点
- 長方形なら、4 隅のどれか

### 二つの重要な性質

**性質 1：凸形状なら、サポート点は必ず境界上にある。** 内部の点は、必ずそれより `d` 方向に進んだ点が存在するので、最大にならない。

**性質 2：サポート点だけで凸形状は完全に決まる。** すべての向きについてサポート点が分かれば、その凸形状が復元できる。逆にいえば、**サポート関数は凸形状の完全な表現である**。

性質 2 が、この章の核心である。GJK は形状の頂点数も辺の並びも知らない。サポート関数を呼ぶだけで、必要な情報をすべて得る。

### なぜ「写像」と呼ぶか

`d` を入力、点を出力とする関数だから写像である。数学では**サポート写像**（support mapping）、あるいは値だけを見て**サポート関数**（support function、`max dot(p,d)` というスカラーを返す版）と呼び分けることがある。

本書では点を返すほうを主に使い、どちらも「サポート写像」「サポート関数」と呼ぶ。文脈で区別がつく。

### 曖昧さについて

`d` に垂直な辺が形状にあるとき、その辺上のすべての点が同じ内積を持つ。**サポート点は一意に決まらない。**

これは問題にならない。GJK も EPA も「どれか一つ」返ってくれば動く。ただし、**同じ入力に対して常に同じ点を返す**（決定論的である）ことは重要である。フレームごとに違う点が返ると、結果が揺れる。

実装では「最初に見つかった最大値の点」を返すことで、決定論を保つ。

## 19.2 形状ごとのサポート関数

### 共通のヘッダ

```cpp
// collision/narrow/support.h
#pragma once

#include "collision/math/vec2.h"
#include "collision/shapes/circle.h"
#include "collision/shapes/aabb.h"
#include "collision/shapes/obb.h"
#include "collision/shapes/polygon.h"
#include "collision/shapes/capsule.h"

namespace collision {
```

### 点

最も単純なケースから始める。

```cpp
// 点：どの向きに対しても自分自身
[[nodiscard]] constexpr Vec2 support_point(Vec2 p, Vec2) noexcept {
    return p;
}
```

「点は退化した凸形状である」という見方が、そのままコードになっている。**GJK は点も扱えるので、点と多角形の判定が自動的に手に入る。**

### 円

```cpp
// 円：中心から d 方向へ半径だけ進んだ点
[[nodiscard]] inline Vec2 support_point(const Circle& c, Vec2 d) noexcept {
    // d が意味のある長さを持たなければ、任意の点でよい
    const Vec2 n = normalize_or(d, Vec2{1.0f, 0.0f});
    return c.center + n * c.radius;
}
```

`normalize_or`（第 6.4 節）が使われている。`d` がゼロベクトルのときのフォールバックが自動的に効く。

**円は「点を膨らませたもの」という第 9.4 節の見方が、ここでも現れている。** `support_point(Vec2 p, d) = p` に対して、円は `p + normalize(d) * r` である。半径のぶんだけ `d` 方向へずれる。

### 線分と多角形

```cpp
// 線分：二つの端点のうち、内積が大きいほう
[[nodiscard]] inline Vec2 support_point(const Segment& s, Vec2 d) noexcept {
    return (dot(s.a, d) >= dot(s.b, d)) ? s.a : s.b;
}

// 凸多角形：全頂点を走査して最大を選ぶ
[[nodiscard]] inline Vec2 support_point(const ConvexPolygon& p, Vec2 d) noexcept {
    Vec2  best  = p.vertex[0];
    float best_d = dot(best, d);

    for (std::uint32_t i = 1; i < p.count; ++i) {
        const float s = dot(p.vertex[i], d);
        if (s > best_d) { best_d = s; best = p.vertex[i]; }
    }
    return best;
}
```

多角形は素朴に全頂点を走査する。頂点数が 8 以下（第 13.1 節）なので、これで十分速い。

> **頂点数が多い場合の高速化**
> 頂点が数百ある凸多角形では、線形走査が無視できないコストになる。凸多角形の内積は頂点順に単峰（一つの山）になるので、**山登り法**や**二分探索**で `O(log n)` にできる。
>
> さらに、フレーム間で `d` があまり変わらないことを利用して、**前回のサポート頂点から隣接頂点をたどる**（hill climbing with caching）手法もある。GJK の反復では方向が徐々に収束するので、この最適化はよく効く。
>
> 本書では扱わない。頂点数の上限が 8 では、走査のほうが分岐や間接参照より速いからである。

`>` と `>=` の使い分けに注意してほしい。多角形では `s > best_d` としている。等しい場合は更新しないので、**添字の小さい頂点が優先される**。これが 19.1 節で述べた決定論の担保である。

### AABB と OBB

```cpp
// AABB：各軸について、d の符号に応じて min か max を選ぶ
[[nodiscard]] constexpr Vec2 support_point(const Aabb& b, Vec2 d) noexcept {
    return Vec2{
        (d.x >= 0.0f) ? b.max.x : b.min.x,
        (d.y >= 0.0f) ? b.max.y : b.min.y,
    };
}

// OBB：ローカル軸ごとに符号で半幅の向きを決める
[[nodiscard]] inline Vec2 support_point(const Obb& o, Vec2 d) noexcept {
    const Vec2 ay = axis_y(o);
    const float sx = (dot(o.axis_x, d) >= 0.0f) ? o.extents.x : -o.extents.x;
    const float sy = (dot(ay,       d) >= 0.0f) ? o.extents.y : -o.extents.y;
    return o.center + o.axis_x * sx + ay * sy;
}
```

**AABB は分岐 2 回で済む。** 4 頂点を走査する必要はない。第 12.2 節で OBB の投影半幅を頂点なしで求めたのと、同じ構造の節約である。

実際、`support_point(Obb, d)` と `projected_radius(Obb, n)`（第 12.2 節）は表裏の関係にある。前者は点を返し、後者はその点の投影値から中心の投影値を引いたものを返す。

### カプセル

```cpp
// カプセル = 線分 ⊕ 円（第 16.1 節）。サポート関数も和になる
[[nodiscard]] inline Vec2 support_point(const Capsule& c, Vec2 d) noexcept {
    const Vec2 core = (dot(c.a, d) >= dot(c.b, d)) ? c.a : c.b;   // 線分のサポート点
    return core + normalize_or(d, Vec2{1.0f, 0.0f}) * c.radius;   // 円のぶん膨らませる
}
```

**ミンコフスキー和のサポート関数は、それぞれのサポート関数の和になる。**

```
support(A ⊕ B, d) = support(A, d) + support(B, d)
```

証明は簡単である。`A ⊕ B` の点は `a + b` の形で、`dot(a + b, d) = dot(a, d) + dot(b, d)` は二つの項を独立に最大化できる。

**この性質が極めて重要である。** 第 16 章で「ミンコフスキー和を明示的に構築するのは高くつく」と述べたが、**サポート関数なら足すだけで済む**。構築が不要になる。

## 19.3 コンセプトで表現する

### `SupportShape`

```cpp
// collision/narrow/support.h（続き）

// 「サポート写像を持つ」ことを型として表現する
template <class S>
concept SupportShape = requires(const S& s, Vec2 d) {
    { support_point(s, d) } -> std::same_as<Vec2>;
};

static_assert(SupportShape<Circle>);
static_assert(SupportShape<Aabb>);
static_assert(SupportShape<Obb>);
static_assert(SupportShape<ConvexPolygon>);
static_assert(SupportShape<Capsule>);
static_assert(SupportShape<Vec2>);
```

`static_assert` を並べているのは、**コンセプトを満たしていることをコンパイル時に保証する**ためである。新しい形状を追加したとき、ここに一行足せば検証される。

第 9.4 節の `HasClosestPoint`、第 11.4 節の `SatShape` と同じ設計である。**本書は「形状が満たすべき性質」をコンセプトで表現し、アルゴリズムをそれに対して書く**という方針を一貫して採っている。

### 三つのコンセプトの関係

| コンセプト | 要求 | 使うアルゴリズム | 章 |
|---|---|---|---|
| `HasClosestPoint` | 点への最近接点 | 円 vs 任意形状 | 第 9 章 |
| `SatShape` | 頂点列と軸列 | SAT | 第 11 章 |
| `SupportShape` | サポート点 | **GJK、EPA** | この章以降 |

**`SupportShape` が最も要求が緩い。** 頂点列も辺も要らず、「ある向きの最遠点」だけを返せればよい。

そのため、`SatShape` にできない形状も `SupportShape` にできる。円がその代表である。円には頂点も辺もないので SAT には載らないが、サポート写像は書ける。**GJK が円と多角形を同じコードで扱えるのは、この差による。**

### ミンコフスキー差のサポート点

GJK が実際に必要とするのは、二つの形状ではなく**そのミンコフスキー差**のサポート点である。

第 16 章で `A ⊖ B = A ⊕ (-B)` と定めた。前節の和の性質を使うと、

```
support(A ⊖ B, d) = support(A, d) + support(-B, d)
                  = support(A, d) - support(B, -d)
```

`support(-B, d) = -support(B, -d)` である（形状を反転すると、逆向きの最遠点の符号を反転したものになる）。

```cpp
// collision/narrow/support.h（続き）

// ミンコフスキー差 A ⊖ B のサポート点。
// 元の形状上の点も一緒に保持しておく（第 21 章の最近接点復元で使う）。
struct MinkowskiPoint {
    Vec2 diff{};    // on_a - on_b。ミンコフスキー差の上の点
    Vec2 on_a{};    // A 上のサポート点
    Vec2 on_b{};    // B 上のサポート点
};

template <SupportShape A, SupportShape B>
[[nodiscard]] MinkowskiPoint
support_diff(const A& a, const B& b, Vec2 d) noexcept {
    const Vec2 pa = support_point(a,  d);
    const Vec2 pb = support_point(b, -d);
    return MinkowskiPoint{.diff = pa - pb, .on_a = pa, .on_b = pb};
}
```

**`on_a` と `on_b` を一緒に保持している**のが要点である。GJK の交差判定だけなら `diff` で足りるが、第 21 章で「元の形状上のどこが最も近いか」を復元するときに必要になる。

後から追加するより、最初から持たせておくほうが素直である。コストは 16 バイトの増加だけで、GJK が保持する点は最大 3 個なので問題にならない。

## 19.4 変換をサポート関数の合成で表す

### 問題

ゲームでは、形状はローカル座標で定義され、位置と回転を持って世界に配置される。

素朴には、判定のたびに全頂点をワールド座標へ変換する。頂点が 8 個なら 8 回の変換である。

**サポート写像を使えば、変換は 1 回で済む。**

### 方向を逆変換し、点を順変換する

ワールド座標での向き `d` に対する、変換された形状のサポート点を求めたい。

考え方はこうである。**向きをローカル座標へ持ち込み、ローカルでサポート点を求め、その点だけをワールドへ戻す。**

```
support(T(S), d) = T( support(S, R⁻¹ d) )
```

`T` は変換（回転 `R` と平行移動）、`R⁻¹` は逆回転である。平行移動は向きに影響しないので、逆変換では回転だけを打ち消せばよい。

### 実装

```cpp
// collision/math/transform.h
#pragma once

#include "collision/math/vec2.h"

namespace collision {

// 2D の剛体変換。回転は (cos, sin) で保持する（第 12.1 節の Obb と同じ流儀）
struct Transform {
    Vec2 position{};
    Vec2 rotation{1.0f, 0.0f};   // 単位ベクトル
};

[[nodiscard]] constexpr Vec2 rotate(Vec2 r, Vec2 v) noexcept {
    return Vec2{v.x * r.x - v.y * r.y, v.x * r.y + v.y * r.x};
}

[[nodiscard]] constexpr Vec2 inverse_rotate(Vec2 r, Vec2 v) noexcept {
    // 逆回転は sin の符号を反転するだけ
    return Vec2{v.x * r.x + v.y * r.y, -v.x * r.y + v.y * r.x};
}

[[nodiscard]] constexpr Vec2 apply(const Transform& t, Vec2 v) noexcept {
    return rotate(t.rotation, v) + t.position;
}

} // namespace collision
```

**逆回転が符号の反転だけで済む**のは、回転行列が直交行列だからである。逆行列＝転置行列であり、2D では `sin` の符号が変わるだけになる。行列式を計算する必要はない。

```cpp
// collision/narrow/support.h（続き）

// 形状に変換を被せたもの。形状は参照で保持する（コピーしない）
template <SupportShape S>
struct Transformed {
    const S*  shape{};
    Transform xf{};
};

template <SupportShape S>
[[nodiscard]] Vec2 support_point(const Transformed<S>& t, Vec2 d) noexcept {
    // (1) 向きをローカルへ
    const Vec2 local_d = inverse_rotate(t.xf.rotation, d);
    // (2) ローカルでサポート点を求める
    const Vec2 local_p = support_point(*t.shape, local_d);
    // (3) 点だけをワールドへ
    return apply(t.xf, local_p);
}

// 便利な生成関数
template <SupportShape S>
[[nodiscard]] Transformed<S> transformed(const S& s, const Transform& xf) noexcept {
    return Transformed<S>{.shape = &s, .xf = xf};
}
```

`Transformed<S>` 自身も `SupportShape` を満たす。**変換を被せた形状が、また形状として扱える。** 入れ子にすることもできる（あまり使わないが）。

### この設計の見返り

**1. 変換のコストが頂点数に依存しない。** 8 頂点の多角形でも 100 頂点でも、変換は 1 点ぶんである。GJK の反復ごとに 1 回だけ。

**2. 形状データを共有できる。** 同じ形の敵が 100 体いても、`ConvexPolygon` の実体は一つでよい。各個体は `Transform` だけを持つ。メモリ使用量が大きく減る。

**3. 形状を書き換えなくてよい。** 物体が動いても回転しても、`ConvexPolygon` の中身は不変である。第 13.5 節の `transformed` は新しい多角形を作っていたが、その必要がなくなる。

**4. 剛体シミュレーションと相性がよい。** 第 35 章で剛体の状態を持つとき、`Transform` がそのまま状態になる。

> **ポインタで保持することの注意**
> `Transformed` は形状へのポインタを持つ。**元の形状より長生きしてはいけない。** 一時オブジェクトを渡すと dangling になる。
>
> ```cpp
> auto t = transformed(make_box({0,0}, {1,1}), xf);   // 危険：一時オブジェクト
> ```
>
> 本書では、`Transformed` を判定の呼び出し式の中だけで使い、保存しない方針とする。C++23 では、こうした誤用を防ぐために `[[clang::lifetimebound]]` に相当する属性が標準化されていないため、規約とレビューで守るしかない。

### サポート写像で表せない形状

万能に見えるが、限界もある。**凹形状はサポート写像で表せない。**

正確には、サポート写像を書くこと自体はできる（凹形状の頂点を走査して最遠点を返せばよい）。だが返ってくるのは**凸包上の点**である。凹んだ部分の情報は完全に失われる。

その結果、GJK は「凹形状を凸包で近似したもの」として扱う。凹んだ隙間に収まっている物体を、交差していると誤判定する。

**これは第 11.1 節で述べた「分離軸定理は凸形状にしか成り立たない」と同じ制約である。** 対処も同じで、凹形状は凸分解する。

もう一つの限界は、**無限に広がる形状**である。半平面や無限平面のサポート点は無限遠になる。実装上は、十分大きな有限の値で代用するか、専用の判定を書く。第 27 章で 3D の平面を扱うとき、この点に触れる。

### コストの比較

サポート写像は、形状ごとに呼び出しコストが違う。

| 形状 | 演算 | 分岐 |
|---|---|---|
| 点 | なし | なし |
| 円 | 正規化（平方根 1 回）＋乗算 | なし |
| AABB | なし | 2 |
| OBB | 内積 2 回 ＋ 乗算 | 2 |
| n 角形 | 内積 n 回 | n |
| カプセル | 内積 2 回 ＋ 正規化 | 1 |

**AABB が最も安い。** サポート写像は分岐 2 回で済み、平方根も内積も要らない。ブロードフェーズ（第 VI 部）で AABB を使う理由の一つである。

**円は平方根が入る**点が意外かもしれない。方向を正規化する必要があるためである。GJK の反復ごとに 1 回なので実害は小さいが、覚えておくとよい。

第 20 章の GJK は、1 反復あたりサポート写像を 2 回（A と B に 1 回ずつ）呼ぶ。反復が平均 5 回とすると、判定 1 回あたり 10 回の呼び出しになる。**この回数が、GJK の実行コストをおおむね決める。**

## 19.5 テスト

### サポート点は必ず境界上にある

19.1 節の性質 1 を検証する。

```cpp
// test_support.cpp
#include "CppUnitTest.h"
#include "test_helpers.h"
#include "collision/narrow/support.h"

using namespace Microsoft::VisualStudio::CppUnitTestFramework;
using collision::Vec2;

namespace collision_tests {

TEST_CLASS(SupportBasics) {
public:
    TEST_METHOD(多角形のサポート点が最大の内積を持つこと) {
        Rng rng(1300);
        for (int i = 0; i < 20000; ++i) {
            const auto poly = random_convex_polygon_checked(rng, 3 + (i % 6));
            const Vec2 d{rng.uniform(-1.0f, 1.0f), rng.uniform(-1.0f, 1.0f)};
            if (collision::length_squared(d) < collision::min_length2) continue;

            const Vec2  s = collision::support_point(poly, d);
            const float best = collision::dot(s, d);

            // 他のどの頂点も、これを超えないこと
            for (std::uint32_t k = 0; k < poly.count; ++k) {
                Assert::IsTrue(collision::dot(poly.vertex[k], d) <= best + 1.0e-5f,
                               L"サポート点より遠い頂点が存在する");
            }
        }
    }

    TEST_METHOD(円のサポート点が境界上にあること) {
        Rng rng(1301);
        for (int i = 0; i < 20000; ++i) {
            const collision::Circle c{
                {rng.uniform(-5.0f, 5.0f), rng.uniform(-5.0f, 5.0f)},
                rng.uniform(0.1f, 3.0f)};
            const Vec2 d{rng.uniform(-1.0f, 1.0f), rng.uniform(-1.0f, 1.0f)};
            if (collision::length_squared(d) < collision::min_length2) continue;

            const Vec2 s = collision::support_point(c, d);
            expect_near(c.radius, collision::distance(s, c.center), 1.0e-5f, 1.0e-5f);
        }
    }

    TEST_METHOD(サポート点が決定論的であること) {
        Rng rng(1302);
        for (int i = 0; i < 5000; ++i) {
            const auto poly = random_convex_polygon_checked(rng, 4);
            const Vec2 d{1.0f, 0.0f};

            const Vec2 s1 = collision::support_point(poly, d);
            const Vec2 s2 = collision::support_point(poly, d);
            Assert::IsTrue(s1 == s2, L"同じ入力で違う点が返った");
        }
    }
};
```

一つ目のテストが、サポート関数の定義そのものの検証である。**「これより遠い点は存在しない」を全頂点で確かめる。** 第 9.6 節の「最近接点より近い点が存在しない」テストと同じ発想である。

三つ目で `operator==` による厳密比較を使っている。第 6.3 節で「浮動小数点に `==` を使うな」と述べたが、ここは例外である。**同一性の確認**という、`==` が正しく使える数少ない用途にあたる。

### ミンコフスキー和の性質

19.2 節で使った `support(A ⊕ B, d) = support(A, d) + support(B, d)` を検証する。

```cpp
TEST_CLASS(SupportMinkowski) {
public:
    TEST_METHOD(カプセルが線分と円の和になっていること) {
        Rng rng(1310);
        for (int i = 0; i < 20000; ++i) {
            const collision::Segment seg{
                {rng.uniform(-3.0f, 3.0f), rng.uniform(-3.0f, 3.0f)},
                {rng.uniform(-3.0f, 3.0f), rng.uniform(-3.0f, 3.0f)}};
            const float r = rng.uniform(0.1f, 2.0f);
            const collision::Capsule cap{.a = seg.a, .b = seg.b, .radius = r};
            const collision::Circle  circle{{0.0f, 0.0f}, r};

            const Vec2 d{rng.uniform(-1.0f, 1.0f), rng.uniform(-1.0f, 1.0f)};
            if (collision::length_squared(d) < collision::min_length2) continue;

            const Vec2 sum = collision::support_point(seg, d)
                           + collision::support_point(circle, d);
            expect_near(sum, collision::support_point(cap, d), 1.0e-5f, 1.0e-5f);
        }
    }

    TEST_METHOD(ミンコフスキー差のサポート点が定義どおりであること) {
        Rng rng(1311);
        for (int i = 0; i < 20000; ++i) {
            const auto a = random_convex_polygon_checked(rng, 3 + (i % 6));
            const auto b = random_convex_polygon_checked(rng, 3 + (i % 5));
            const Vec2 d{rng.uniform(-1.0f, 1.0f), rng.uniform(-1.0f, 1.0f)};
            if (collision::length_squared(d) < collision::min_length2) continue;

            const auto m = collision::support_diff(a, b, d);

            // 定義：全ペア (pa - pb) の中で最大の内積を持つこと
            float best = -std::numeric_limits<float>::infinity();
            for (std::uint32_t i2 = 0; i2 < a.count; ++i2) {
                for (std::uint32_t j = 0; j < b.count; ++j) {
                    best = std::max(best, collision::dot(a.vertex[i2] - b.vertex[j], d));
                }
            }
            expect_near(best, collision::dot(m.diff, d), 1.0e-4f, 1.0e-5f);

            // on_a / on_b の整合
            expect_near(m.diff, m.on_a - m.on_b, 1.0e-6f, 1.0e-6f);
        }
    }
};
```

二つ目のテストが、**全頂点ペアの総当たりをリファレンスにしている**（第 11.6 節の手法）。ミンコフスキー差の頂点は必ず `a - b` の形をしているので、総当たりで最大を求めれば定義どおりの答えが得られる。

`on_a - on_b == diff` の検証も入れている。この不変条件が崩れると、第 21 章の最近接点復元が壊れる。

### 変換の合成

```cpp
TEST_CLASS(SupportTransform) {
public:
    TEST_METHOD(変換したサポート点が頂点を変換した場合と一致すること) {
        Rng rng(1320);
        for (int i = 0; i < 20000; ++i) {
            const auto local = random_convex_polygon_checked(rng, 3 + (i % 6));

            const float ang = rng.uniform(0.0f, 6.28f);
            const collision::Transform xf{
                .position = {rng.uniform(-5.0f, 5.0f), rng.uniform(-5.0f, 5.0f)},
                .rotation = {std::cos(ang), std::sin(ang)}};

            // (A) Transformed 経由
            const auto t = collision::transformed(local, xf);
            const Vec2 d{rng.uniform(-1.0f, 1.0f), rng.uniform(-1.0f, 1.0f)};
            if (collision::length_squared(d) < collision::min_length2) continue;
            const Vec2 sa = collision::support_point(t, d);

            // (B) 頂点を実際に変換してから求める（リファレンス）
            auto world = local;
            for (std::uint32_t k = 0; k < world.count; ++k) {
                world.vertex[k] = collision::apply(xf, local.vertex[k]);
            }
            const Vec2 sb = collision::support_point(world, d);

            expect_near(sb, sa, 1.0e-4f, 1.0e-5f);
        }
    }

    TEST_METHOD(逆回転が回転を打ち消すこと) {
        Rng rng(1321);
        for (int i = 0; i < 20000; ++i) {
            const float ang = rng.uniform(0.0f, 6.28f);
            const Vec2 r{std::cos(ang), std::sin(ang)};
            const Vec2 v{rng.uniform(-10.0f, 10.0f), rng.uniform(-10.0f, 10.0f)};

            expect_near(v, collision::inverse_rotate(r, collision::rotate(r, v)),
                        1.0e-4f, 1.0e-5f);
            expect_near(v, collision::rotate(r, collision::inverse_rotate(r, v)),
                        1.0e-4f, 1.0e-5f);
        }
    }

    TEST_METHOD(回転が長さを保つこと) {
        Rng rng(1322);
        for (int i = 0; i < 20000; ++i) {
            const float ang = rng.uniform(0.0f, 6.28f);
            const Vec2 r{std::cos(ang), std::sin(ang)};
            const Vec2 v{rng.uniform(-10.0f, 10.0f), rng.uniform(-10.0f, 10.0f)};

            expect_near(collision::length(v), collision::length(collision::rotate(r, v)),
                        1.0e-4f, 1.0e-5f);
        }
    }
};

} // namespace collision_tests
```

一つ目のテストが、19.4 節の設計の正しさを検証している。**「向きを逆変換して点を順変換する」が「全頂点を変換する」と同じ結果になる**ことを、20,000 通りで確かめる。符号を一つ間違えれば落ちる。

## この章のまとめ

- **サポート点：`d` 方向に最も突き出た点。** 凸形状なら必ず境界上にある
- **サポート関数は凸形状の完全な表現である。** 頂点も辺も知らずに形状を扱える
- 円・点・線分・多角形・AABB・OBB・カプセル、すべて数行で書ける
- **ミンコフスキー和のサポート関数は、それぞれの和になる。** 構築が不要になる
- `support(A ⊖ B, d) = support(A, d) - support(B, -d)`
- `MinkowskiPoint` に `on_a` / `on_b` も保持する。第 21 章の最近接点復元で使う
- `SupportShape` コンセプトは `SatShape` より要求が緩い。**円が載るのはこの差による**
- **変換は「向きを逆回転、点を順変換」。** 頂点数に依存しないコストで済む
- 2D の逆回転は `sin` の符号反転だけ
- テストは「これより遠い点は存在しない」と「全頂点ペアの総当たり」で定義を直接検証する

### 落とし穴と練習問題

**落とし穴 1：`support(A ⊖ B, d)` の第二引数の符号。**　`support(B, -d)` である。`support(B, d)` と書くとミンコフスキー**和**になってしまう。

**落とし穴 2：`Transformed` の寿命。**　形状へのポインタを持つので、元より長生きさせない。

**落とし穴 3：`>` と `>=` の使い分け。**　等値のときに更新すると、決定論が崩れる場合がある。

---

**練習問題 19-1**　楕円のサポート関数を書いてみよう。半軸 `(a, b)` の楕円について、`d` 方向のサポート点は `(a²dx, b²dy) / sqrt(a²dx² + b²dy²)` になる。導出も試みてほしい。**SAT では扱えない形状が GJK では扱える**ことの実例になる。

**練習問題 19-2**　「凸形状の凸包」のサポート関数を書こう。二つの形状 A と B の凸包 `hull(A ∪ B)` について、サポート点は「A と B のサポート点のうち内積が大きいほう」である。これも構築が不要な例である。

**練習問題 19-3**　`support_point(ConvexPolygon, d)` を、山登り法（前回の頂点から隣接をたどる）で実装してみよう。頂点数を 64 まで増やして、線形走査と速度を比べる。何頂点から逆転するだろうか。

**練習問題 19-4**　`Transformed` を入れ子にして `transformed(transformed(shape, xf1), xf2)` としたとき、結果は「変換を合成した一つの `Transform`」と一致するだろうか。確かめてみてほしい。

**練習問題 19-5**（発展）　サポート関数から凸形状を復元する処理を書いてみよう。向きを細かく刻んでサポート点を集め、凸包を取る（第 13.4 節）。19.1 節の性質 2 の実証になる。円に対して行うと、多角形近似が得られるはずである。

---
