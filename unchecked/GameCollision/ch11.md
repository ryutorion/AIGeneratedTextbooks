# 第 11 章　分離軸定理（SAT）の考え方

> **この章のゴール**
> 分離軸定理を理解し、その骨組みをコードに落とす。まだ OBB も凸多角形も扱わない。**AABB を SAT で書き直し、第 10 章の実装と一致することを確認する**ところまでが範囲である。

## 11.1 「隔てる線が引けるなら当たっていない」

### 定理

二つの凸形状 A と B について、次が成り立つ。

> **A と B が交差していない ⇔ 両者を隔てる直線が存在する**

「隔てる直線」とは、A が完全に片側、B が完全に反対側にあるような直線のことである。この直線を**分離超平面**、その法線方向を**分離軸**と呼ぶ。

直感的には当たり前に思える。離れている二つの物体の間には、線が引ける。だがこの定理が強力なのは、**逆向きにも使える**からである。「どんな直線を引いても隔てられない」ことを示せば、交差していることが証明できる。

### 凸であることが本質的である

この定理は**凸形状にしか成り立たない**。

三日月形とその内側に収まる円を考えてほしい。二つは交差していないが、どんな直線を引いても両者を隔てられない。三日月が凹んでいるからである。

本書が第 II 部から第 IV 部まで一貫して「凸形状」を扱うのは、この制約による。凹形状は、複数の凸形状に分解して扱う（凸分解）。それが実務での標準的な対処である。

### 軸への投影として言い換える

「隔てる直線がある」を、計算しやすい形に言い換える。

直線の法線方向を `n` とする。A のすべての点を `n` に投影すると、ある区間 `[a_min, a_max]` に収まる。B も同様に `[b_min, b_max]` に収まる。

**この二つの区間が重ならなければ、`n` を法線とする分離直線が引ける。**

区間が重ならないことは、第 10.2 節でやったのと同じ判定で調べられる。AABB の重なり判定が「区間の重なりを 2 回」だったのは、まさにこれである。

## 11.2 形状を軸へ投影する

### 投影区間

```cpp
// collision/narrow/sat.h
#pragma once

#include "collision/math/vec2.h"
#include "collision/narrow/contact.h"
#include <span>
#include <optional>

namespace collision {

// 軸に投影したときの、形状が占める区間
struct Interval {
    float min{};
    float max{};
};

// 頂点列を軸へ投影する。axis は正規化されている前提。
[[nodiscard]] inline Interval
project(std::span<const Vec2> verts, Vec2 axis) noexcept {
    float lo = dot(verts[0], axis);
    float hi = lo;
    for (std::size_t i = 1; i < verts.size(); ++i) {
        const float d = dot(verts[i], axis);
        lo = std::min(lo, d);
        hi = std::max(hi, d);
    }
    return Interval{.min = lo, .max = hi};
}

// 区間が重なっているか。
[[nodiscard]] constexpr bool intervals_overlap(Interval a, Interval b) noexcept {
    return a.max > b.min && b.max > a.min;
}

// A を軸方向へ押し出して分離するのに必要な距離。
// 正の値なら重なっている。負またはゼロなら分離している。
//   push_positive … A を +axis 方向へ動かして分離する距離
//   push_negative … A を -axis 方向へ動かして分離する距離
struct Penetration {
    float amount{};      // 最小の押し出し量（非負なら重なっている）
    bool  along_axis{};  // true なら +axis 方向へ押す
};

[[nodiscard]] constexpr Penetration penetration(Interval a, Interval b) noexcept {
    const float push_positive = b.max - a.min;
    const float push_negative = a.max - b.min;

    if (push_positive <= 0.0f || push_negative <= 0.0f) {
        return Penetration{.amount = std::min(push_positive, push_negative),
                           .along_axis = true};   // 分離している
    }
    return (push_positive < push_negative)
        ? Penetration{.amount = push_positive, .along_axis = true}
        : Penetration{.amount = push_negative, .along_axis = false};
}

} // namespace collision
```

`project` の中身は、第 6.5 節で述べた「内積の読み方 1：射影の長さ」そのものである。各頂点と軸の内積を取り、最小値と最大値を拾う。

### 「重なり量」と「押し出し量」は違う

**ここは本書で最も間違えやすい箇所である。** 素朴に書くと、区間の重なり量をこう定義したくなる。

```cpp
// よく見かける書き方。分離判定には正しいが、深度としては誤り
float overlap = std::min(a.max, b.max) - std::max(a.min, b.min);
```

分離の判定（`overlap <= 0` なら分離）としては、この式で正しい。**だが押し出す距離としては誤っている。**

反例を挙げる。区間 A が `[0, 10]`、区間 B が `[4, 6]` だとする。B は A に完全に含まれている。

- 素朴な式：`min(10, 6) - max(0, 4) = 6 - 4 = 2`
- 実際に必要な押し出し量：B を右へ出すなら `10 - 4 = 6`、左へ出すなら `6 - 0 = 6`。**どちらも 6**

素朴な式は「小さいほうの区間の長さ」を返してしまう。**片方の区間が他方に含まれるとき、押し出し量を大幅に過小評価する。**

正しくは、二つの押し出し方向それぞれについて距離を求め、小さいほうを取る。

```
push_positive = b.max - a.min     （A を右へ出す）
push_negative = a.max - b.min     （A を左へ出す）
penetration   = min(push_positive, push_negative)
```

分離判定も、この二つが両方とも正であることと同値である（どちらかが 0 以下なら既に分離している）。

**この誤りが引き起こす症状は特徴的である。** 小さい物体が大きい物体に深くめり込んだとき、押し戻しが足りずに内部に留まる。浅い接触では正しく動くので、発見が遅れる。第 10.5 節の AABB でも同じ問題が起きるので、そちらも同じ形に直す。

### 軸は必ず正規化されていなければならない

**この節で最も重要な注意点である。**

`project` は `axis` が単位ベクトルであることを前提にしている。そうでないと、`dot(v, axis)` は「射影の長さ × `|axis|`」になり、区間全体が `|axis|` 倍にスケールされる。

重なりの**有無**を判定するだけなら、これは問題にならない。A と B の両方が同じ倍率でスケールされるので、重なるかどうかは変わらない。

ところが**重なり量を比べるときに破綻する**。SAT では複数の軸の重なり量を比較して最小のものを選ぶ（最小移動ベクトル）。軸ごとに `|axis|` が違うと、比較する量の単位がバラバラになり、選ばれる軸が誤る。

```cpp
// 軸 A の長さが 1、軸 B の長さが 2 だとする
// 実際の重なりは A のほうが浅いのに、
// 投影上の値は B のほうが小さく見えることがある
```

**このバグは症状が分かりにくい。** 交差の有無は正しいのに、押し戻す向きだけが時々おかしい。しかも形状の大きさや回転角によって出たり出なかったりする。

対策として、軸を扱う関数にはコメントで前提を明記し、デバッグビルドで検査する。

```cpp
// 軸が正規化されていることをデバッグビルドで検査する
inline void assert_normalized([[maybe_unused]] Vec2 axis) noexcept {
#ifdef _DEBUG
    const float len2 = length_squared(axis);
    assert(std::fabs(len2 - 1.0f) < 1.0e-4f &&
           "SAT の軸は正規化されていなければなりません");
#endif
}
```

第 5.5 節で `assert_fpu_state` を書いたのと同じ発想である。**前提条件をコードで表明する。**

## 11.3 なぜ調べる軸が有限個で済むのか

### 無限にある軸のうち、どれを調べればよいか

分離軸の候補は、平面上のあらゆる向きである。無限にある。全部を調べることはできない。

ここが分離軸定理の実用上の核心である。**凸多角形どうしなら、調べるべき軸は有限個で足りる。**

### 直感的な説明

A と B が離れているとしよう。両者を隔てる直線が引ける。その直線を、A にも B にも触れるまで平行移動し、さらに回転させてみる。

隙間を詰めていくと、直線はいずれ**どちらかの形状の辺にぴったり沿った位置**で止まる。凸多角形の「隙間」は、必ずどちらかの辺の延長線によって最も強く制約されるからである。

したがって、**調べるべき軸は「A のすべての辺の法線」と「B のすべての辺の法線」だけでよい**。

| 形状ペア | 調べる軸 | 本数 |
|---|---|---|
| AABB vs AABB | X 軸、Y 軸（両者共通） | 2 |
| OBB vs OBB | 各 OBB の 2 軸ずつ | 4 |
| 三角形 vs 四角形 | 3 辺 ＋ 4 辺 | 7 |
| n 角形 vs m 角形 | n ＋ m | n + m |

AABB どうしで 2 本なのは、両者の辺の法線が同じだからである。X 軸方向の法線が 2 本（左右の辺）あるが、向きが逆なだけで同じ軸なので、1 本に数える。

### 3D では成り立たない

**この「辺の法線だけでよい」という性質は、2 次元に固有である。**

3 次元では、面の法線だけでは足りない。二つの箱が辺どうしで斜めに接触する配置があり、その場合の分離軸はどちらの面法線とも一致しない。「A の辺と B の辺の外積」を追加で調べる必要がある。

3D の OBB どうしで面法線 6 本＋辺の外積 9 本＝15 本になるのは、この事情による。第 26 章で反例とともに扱う。

**2D の間はこの心配がない**、という理解で第 II 部を進めてよい。

### 軸の重複を除く

n 角形の辺は n 本あるが、法線が同じ向き（または逆向き）の辺は、同じ軸を表す。長方形なら 4 辺で 2 軸である。

重複した軸を調べても結果は変わらないので、正しさの問題ではない。**速度の問題**である。第 12.4 節で OBB について、第 13.4 節で凸多角形について扱う。

## 11.4 AABB を SAT で書き直す

### 形状を SAT に渡すためのインターフェース

SAT には二つの情報が要る。**頂点列**（投影するため）と**軸の列**（調べる軸を得るため）である。

C++20 のコンセプトで、これを表現する。

```cpp
// collision/narrow/sat.h（続き）

// SAT で扱える形状：頂点列と、調べるべき軸の列を提供できるもの
template <class S>
concept SatShape = requires(const S& s, std::size_t i) {
    { vertices(s)   } -> std::convertible_to<std::span<const Vec2>>;
    { axis_count(s) } -> std::convertible_to<std::size_t>;
    { axis(s, i)    } -> std::same_as<Vec2>;   // 正規化済みであること
};
```

**軸を配列で返さず、添字でアクセスする形にした**のには理由がある。

多角形の辺の法線は、頂点から計算して求める。配列で返そうとすると、その配列をどこかに確保する必要がある。動的確保はしたくないし、固定長配列を返すと頂点数の上限に縛られる。

「i 番目の軸を返す関数」なら、呼ばれたときに計算すればよい。**確保が要らない。** 第 13 章で凸多角形に対してこの利点が効いてくる。

### AABB を SatShape にする

```cpp
// collision/shapes/aabb.h（続き）

// SAT インターフェース
[[nodiscard]] inline std::span<const Vec2> vertices(const Aabb& b) noexcept {
    // 呼び出しごとに頂点を組み立てる必要があるため、thread_local に置く。
    // ※ この実装は説明用。実用上の問題は下記のコラムを参照。
    thread_local std::array<Vec2, 4> buf{};
    buf = {Vec2{b.min.x, b.min.y}, Vec2{b.max.x, b.min.y},
           Vec2{b.max.x, b.max.y}, Vec2{b.min.x, b.max.y}};
    return buf;
}

[[nodiscard]] constexpr std::size_t axis_count(const Aabb&) noexcept {
    return 2;
}

[[nodiscard]] constexpr Vec2 axis(const Aabb&, std::size_t i) noexcept {
    return (i == 0) ? Vec2{1.0f, 0.0f} : Vec2{0.0f, 1.0f};
}
```

軸は座標軸そのものなので、正規化済みであることが自明である。AABB の大きな利点がここにも現れている。

> **`thread_local` を使うことの是非**
> 上の `vertices` は、静的な記憶域に頂点を組み立てて返している。呼び出しごとに書き換わるので、**二つの AABB の頂点を同時に保持できない**。`auto va = vertices(a); auto vb = vertices(b);` と書くと、`va` が指す先も `b` の頂点に書き換わってしまう。
>
> これは実用に耐えない。SAT の実装では両方の頂点が同時に必要になるからである。
>
> 第 12 章と第 13 章では、OBB と凸多角形が**頂点を実体として持つ**設計にすることで、この問題を回避する。`vertices` は保持している配列への `span` を返すだけになり、`thread_local` は不要になる。
>
> AABB だけがこの形になるのは、`min`/`max` から頂点を導出する表現だからである。SAT で AABB を扱うのはこの章の検証用途に限られるので、ここでは値をコピーして受け取ることにする。

検証用に、頂点を値で返す関数を用意しておく。

```cpp
[[nodiscard]] constexpr std::array<Vec2, 4> corners(const Aabb& b) noexcept {
    return {Vec2{b.min.x, b.min.y}, Vec2{b.max.x, b.min.y},
            Vec2{b.max.x, b.max.y}, Vec2{b.min.x, b.max.y}};
}
```

### SAT の本体

```cpp
// collision/narrow/sat.h（続き）

// SAT の結果：最小貫通軸と、その軸での重なり量
struct SatResult {
    Vec2  axis{};    // 正規化済み。A から B へ向く向きに揃えてある
    float depth{};   // 非負
};

// 片方の形状の軸だけを調べる補助関数。
// 分離軸が見つかったら nullopt を返す（＝交差していない）。
template <SatShape S>
[[nodiscard]] std::optional<SatResult>
sat_axes_of(const S& s,
            std::span<const Vec2> va, std::span<const Vec2> vb) noexcept {
    SatResult best{.axis = Vec2{}, .depth = std::numeric_limits<float>::infinity()};

    const std::size_t n = axis_count(s);
    for (std::size_t i = 0; i < n; ++i) {
        const Vec2 ax = axis(s, i);
        assert_normalized(ax);

        const Penetration p = penetration(project(va, ax), project(vb, ax));
        if (p.amount <= 0.0f) {
            return std::nullopt;      // 分離軸が見つかった。ここで確定
        }
        if (p.amount < best.depth) {
            // 押し出す向きを軸の符号に反映しておく（A を axis 方向へ動かすと分離する）
            best = SatResult{.axis = p.along_axis ? ax : -ax, .depth = p.amount};
        }
    }
    return best;
}
```

`ov <= 0.0f` で即座に `nullopt` を返しているのが**早期脱出**である。分離軸が一本でも見つかれば、残りの軸を調べる必要はない。交差していない場合のほうが圧倒的に多いので、この効果は大きい（第 13.4 節で詳しく扱う）。

両方の形状の軸を調べる本体は、こうなる。

```cpp
template <SatShape A, SatShape B>
[[nodiscard]] std::optional<SatResult>
sat(const A& a, const B& b,
    std::span<const Vec2> va, std::span<const Vec2> vb) noexcept {

    const auto ra = sat_axes_of(a, va, vb);
    if (!ra) return std::nullopt;

    const auto rb = sat_axes_of(b, va, vb);
    if (!rb) return std::nullopt;

    // 両方の探索を通ったので交差している。浅いほうを採用する
    SatResult best = (ra->depth <= rb->depth) ? *ra : *rb;

    // penetration() が「A を axis 方向へ押すと分離する」向きを返している。
    // 第 7.3 節の規約は「法線は A から B へ」なので、押し出し方向の逆になる。
    best.axis = -best.axis;
    return best;
}
```

最後の符号反転が肝心である。`penetration` が返す `along_axis` は「A をその向きへ押すと分離する」ことを表す。第 7.3 節の規約「法線は A から B へ」は、その逆向きである。

**重心を使った符号調整は不要になった。** 押し出し方向が投影区間の関係から一意に決まるためである。素朴な「重なり量」の式を使うと押し出し方向の情報が失われるので重心で補う必要があるが、正しい式を使えばその必要がない。

なお重心を求める関数は、第 14 章のフォールバックなどで使うので用意しておく。

```cpp
[[nodiscard]] inline Vec2 centroid(std::span<const Vec2> verts) noexcept {
    Vec2 sum{};
    for (const Vec2 v : verts) sum += v;
    return sum / static_cast<float>(verts.size());
}
```

頂点の平均は厳密な面積重心ではないが、凸形状なら必ず内部にあるので代表点として使える。

### 判定関数

```cpp
template <SatShape A, SatShape B>
[[nodiscard]] std::optional<Contact>
intersect_sat(const A& a, const B& b,
              std::span<const Vec2> va, std::span<const Vec2> vb) noexcept {
    const auto r = sat(a, b, va, vb);
    if (!r) return std::nullopt;

    return Contact{
        .normal = r->axis,
        .depth  = r->depth,
        .point  = centroid(va),      // 暫定。第 14 章で正しく求める
    };
}
```

**接触点はまだ正しくない。** 重心を返しているだけである。第 14 章のマニフォールド生成で解決する。

第 9 章で「円の中心が内部にある場合はまだ正しくない」と明示したのと同じ扱いである。**未完成の部分を隠さず、どこで解決するかを書いておく。**

### 第 10 章の実装と一致するか

AABB どうしで SAT を走らせて、第 10.5 節の `intersect(Aabb, Aabb)` と同じ結果になるかを確かめる。

```cpp
const Aabb a{{0.0f, 0.0f}, {2.0f, 3.0f}};
const Aabb b{{1.5f, 1.0f}, {4.0f, 4.0f}};

const auto ca = collision::corners(a);
const auto cb = collision::corners(b);
const auto direct = collision::intersect(a, b);                    // 第 10 章
const auto via_sat = collision::intersect_sat(a, b, ca, cb);       // この章
```

法線と深度は一致するはずである。接触点は一致しない（上述のとおり暫定値）。11.6 節でこれをテストにする。

## 11.5 「厳密にゼロ」を期待しない

### 境界の扱い

`penetration` の返す押し出し量がちょうどゼロになる状態、すなわち二つの形状が接している状態を考える。

`ov <= 0.0f` で分離と判定しているので、この場合は「交差していない」になる。第 8.1 節と第 10.6 節で決めた規約に沿っている。

**問題は、この判定が誤差に対して不安定であることである。**

`project` は各頂点と軸の内積を取る。頂点の座標が大きければ、内積も大きくなる。押し出し量は二つの大きな投影値の差なので、**桁落ちが起きる**（第 4.2 節）。

原点から 1000 離れた場所にある形状どうしなら、投影値は 1000 のオーダーになる。そこでの `float` の刻み幅は `6.1e-5` である（第 4.1 節の表）。したがって、`ov` の値は `6e-5` 程度の粒度でしか意味を持たない。「ちょうどゼロ」を判定することに意味はない。

### 設計上の帰結

三つのことが導かれる。

**1. 深度が極端に小さい `Contact` を信用しない。**　深度が `1e-5` の接触は、実際には接触していないかもしれないし、していてもゲーム上は無視できる。第 34 章で導入する「スロップ」（許容めり込み）は、この事情への対処でもある。

**2. 境界上の入力をテストの期待値にしない。**　第 3.5 節の原則 3 である。「ちょうど接する二つの箱」に対して `nullopt` を期待するテストは、書いてはいけない。

**3. 代わりに「境界の近くで単調に変化すること」を検証する。**　距離を徐々に縮めていったとき、判定が「交差なし → 交差あり」と一度だけ切り替わることを見る。行ったり来たりしないことを検証する。

### 分離を「わずかに離れている」まで含めるか

実装によっては、`ov <= 0.0f` ではなく `ov <= epsilon` として、わずかな接触を分離扱いにすることがある。

本書ではこれを採らない。理由は、**`epsilon` を適切に決められないから**である。前述のとおり、意味のある粒度は形状の位置によって変わる。固定値では原点付近で緩すぎ、遠方で厳しすぎる。

代わりに、**呼び出し側で深度を見て判断する**方針を採る。

```cpp
if (const auto c = intersect(a, b); c && c->depth > contact_slop) {
    // 意味のある深さで接触している
}
```

`contact_slop = 1e-3f`（1 ミリメートル）は第 5.9 節で単位系から決めた値である。**閾値は判定の内部ではなく、意味の分かる場所に置く。**

## 11.6 テスト：リファレンス比較という手法

### 手法の導入

新しい実装が正しいかを確かめるとき、最も強力な方法の一つは、**すでに正しいと分かっている実装と突き合わせる**ことである。本書ではこれを**リファレンス比較**（等価性テスト）と呼ぶ。

第 9.6 節で「最近接点より近い点が線分上に存在しないこと」を総当たりで検証したのが、この手法の最初の適用だった。そこでは総当たりがリファレンスだった。

この章では、第 10 章の `intersect(Aabb, Aabb)` がリファレンスになる。

**この手法は本書全体で繰り返し使う。**

| 新しい実装 | リファレンス | 章 |
|---|---|---|
| SAT による AABB 判定 | 第 10 章の直接実装 | この章 |
| SAT による OBB 判定 | 軸平行な OBB は AABB と一致 | 第 12 章 |
| GJK | SAT | 第 20 章 |
| EPA の MTV | SAT の MTV | 第 22 章 |
| 3D 実装 | 平面に埋め込んだ 2D 実装 | 第 28 章 |
| BVH のクエリ | 総当たり | 第 32 章 |

### AABB での等価性テスト

```cpp
// test_sat.cpp
#include "CppUnitTest.h"
#include "test_helpers.h"
#include "collision/narrow/sat.h"
#include "collision/narrow/aabb_aabb.h"

using namespace Microsoft::VisualStudio::CppUnitTestFramework;
using collision::Aabb;
using collision::Vec2;

namespace collision_tests {

TEST_CLASS(SatVsDirectAabb) {
public:
    TEST_METHOD(交差の有無が第10章の実装と一致すること) {
        Rng rng(500);
        int mismatch = 0;
        constexpr int trials = 20000;

        for (int i = 0; i < trials; ++i) {
            const Vec2 alo{rng.uniform(-5.0f, 5.0f), rng.uniform(-5.0f, 5.0f)};
            const Vec2 blo{rng.uniform(-5.0f, 5.0f), rng.uniform(-5.0f, 5.0f)};
            const Aabb a{alo, alo + Vec2{rng.uniform(0.5f, 3.0f), rng.uniform(0.5f, 3.0f)}};
            const Aabb b{blo, blo + Vec2{rng.uniform(0.5f, 3.0f), rng.uniform(0.5f, 3.0f)}};

            const auto ca = collision::corners(a);
            const auto cb = collision::corners(b);

            const bool direct = collision::intersect(a, b).has_value();
            const bool viasat = collision::intersect_sat(a, b, ca, cb).has_value();

            if (direct != viasat) ++mismatch;
        }

        // 境界近傍では食い違いうる。割合が十分小さいことを検証する
        Logger::WriteMessage(std::format("不一致 {} / {}\n", mismatch, trials).c_str());
        Assert::IsTrue(mismatch * 1000 < trials, L"不一致が 0.1% を超えている");
    }

    TEST_METHOD(法線と深度が第10章の実装と一致すること) {
        Rng rng(501);
        for (int i = 0; i < 20000; ++i) {
            // 明確に重なる配置だけを生成する（境界近傍を避ける）
            const Vec2 alo{rng.uniform(-2.0f, 2.0f), rng.uniform(-2.0f, 2.0f)};
            const Aabb a{alo, alo + Vec2{2.0f, 2.0f}};
            const Vec2 shift{rng.uniform(-1.5f, 1.5f), rng.uniform(-1.5f, 1.5f)};
            const Aabb b{a.min + shift, a.max + shift};

            const auto ca = collision::corners(a);
            const auto cb = collision::corners(b);

            const auto direct = collision::intersect(a, b);
            const auto viasat = collision::intersect_sat(a, b, ca, cb);

            Assert::IsTrue(direct.has_value() && viasat.has_value());
            check_contact_invariants(*viasat);

            // 二軸の重なりが拮抗していると、選ばれる軸が実装によって割れる。
            // その場合は深度だけを比べる
            expect_near(direct->depth, viasat->depth, 1.0e-4f, 1.0e-4f);

            if (std::fabs(direct->depth - viasat->depth) < 1.0e-4f) {
                const float agree = collision::dot(direct->normal, viasat->normal);
                Assert::IsTrue(agree > 0.99f || std::fabs(direct->depth) < 1.0e-3f,
                               L"法線が一致しない");
            }
        }
    }
};

} // namespace collision_tests
```

**一つ目のテストで「不一致が 0.1% 未満」という緩い判定にしている**のが、第 3.5 節の原則 3 の実践である。境界ぎりぎりの配置では、二つの実装が違う結論を出しうる。それを異常とはみなさず、割合で管理する。

不一致の数を `Logger::WriteMessage` で出力しているのも意図的である。**将来この数が急増したら、それは本物のバグの兆候**である。数字を記録に残しておく。

二つ目のテストで「二軸の重なりが拮抗していると軸の選択が割れる」ことに触れている。X と Y の重なり量がほぼ等しいとき、どちらを選ぶかは丸め誤差で決まる。深度は同じでも法線が 90 度違う、という状況が起こりうる。**これは正常である。** 押し戻す量が同じなら、どちらの方向でも解消する。

### 単調性のテスト

境界の扱いは、こう検証する。

```cpp
TEST_METHOD(境界近傍で判定が単調に変化すること) {
    const Aabb a{{0.0f, 0.0f}, {1.0f, 1.0f}};
    const auto ca = collision::corners(a);

    bool prev = true;   // 最初は重なっている想定
    for (float x = 0.5f; x < 1.5f; x += 0.001f) {
        const Aabb b{{x, 0.0f}, {x + 1.0f, 1.0f}};
        const auto cb = collision::corners(b);
        const bool now = collision::intersect_sat(a, b, ca, cb).has_value();

        // 一度離れたら、二度と交差しない
        Assert::IsTrue(prev || !now, L"判定が交差→非交差→交差と揺れた");
        prev = now;
    }
    Assert::IsFalse(prev, L"最後まで交差したままになっている");
}
```

境界がちょうど `x = 1.0` にあるかは問わない。**行ったり来たりしないことだけを問う。**

### 投影と重なり量の単体テスト

部品レベルのテストも書いておく。

```cpp
TEST_CLASS(SatPrimitives) {
public:
    TEST_METHOD(投影区間が正しいこと) {
        const std::array<Vec2, 4> square{
            Vec2{0.0f, 0.0f}, Vec2{2.0f, 0.0f}, Vec2{2.0f, 2.0f}, Vec2{0.0f, 2.0f}};

        const auto ix = collision::project(square, Vec2{1.0f, 0.0f});
        expect_near(0.0f, ix.min);
        expect_near(2.0f, ix.max);

        // 45 度方向。対角線上の投影は 0 〜 2√2/... 実際は (0,0)→0、(2,2)→2√2
        const Vec2 diag = collision::normalize_or(Vec2{1.0f, 1.0f}, Vec2{});
        const auto id = collision::project(square, diag);
        expect_near(0.0f, id.min);
        expect_near(2.0f * std::sqrt(2.0f), id.max, 1.0e-5f, 1.0e-5f);
    }

    TEST_METHOD(重なり量の計算が正しいこと) {
        using collision::Interval;
        // 通常の重なり：A を右へ 5-0=5、左へ 2-1=1 → 最小は 1
        expect_near( 1.0f, collision::penetration(Interval{0, 2}, Interval{1, 5}).amount);
        // 分離：押し出し量のどちらかが負になる
        Assert::IsTrue(collision::penetration(Interval{0, 2}, Interval{3, 5}).amount <= 0.0f);
        // 内包：A[0,2] が B[-1,3] の内側。右へ 3-0=3、左へ 2-(-1)=3 → 3
        // （素朴な min(max)-max(min) だと 2 になってしまう。11.2 節の議論）
        expect_near( 3.0f, collision::penetration(Interval{0, 2}, Interval{-1, 3}).amount);
    }

    TEST_METHOD(軸を正規化しないと深度が狂うこと) {
        // 11.2 節の警告の実証。正規化していない軸では投影がスケールされる
        const std::array<Vec2, 4> sq{
            Vec2{0.0f, 0.0f}, Vec2{1.0f, 0.0f}, Vec2{1.0f, 1.0f}, Vec2{0.0f, 1.0f}};

        const auto unit  = collision::project(sq, Vec2{1.0f, 0.0f});
        const auto scaled = collision::project(sq, Vec2{3.0f, 0.0f});

        expect_near(1.0f, unit.max - unit.min);
        expect_near(3.0f, scaled.max - scaled.min);   // 3 倍にスケールされている
    }
};
```

最後のテストが、11.2 節で警告した問題の実証である。**「壊れることを確認するテスト」**は、その前提が本当に成り立つかを記録に残す（第 4.7 節でも同じ手法を使った）。

## この章のまとめ

- **分離軸定理：凸形状 A と B が交差しない ⇔ 両者を隔てる直線が存在する**
- 凹形状では成り立たない。凹形状は凸分解して扱う
- 「隔てる直線がある」は「ある軸への投影区間が重ならない」と言い換えられる
- **軸は必ず正規化する。** そうでないと重なり量の比較が壊れ、MTV の選択を誤る
- 2D では、調べる軸は「両者の辺の法線」だけでよい。有限個で済む
- **3D では面法線だけでは足りない**（辺の外積が要る）。第 26 章で扱う
- `SatShape` コンセプトは「頂点列」と「i 番目の軸」を要求する。配列を返さないので確保が不要
- 分離軸が一本見つかった時点で早期脱出する
- 軸の向きは重心の位置関係で「A から B へ」に揃える
- **接触点はまだ正しくない。** 第 14 章で解決する
- 境界の「厳密にゼロ」は誤差で不安定。閾値は判定内部ではなく呼び出し側に置く
- **リファレンス比較**という検証手法を導入した。本書全体で繰り返し使う

### 落とし穴と練習問題

**落とし穴 1：軸の正規化忘れ。**　この章で最も強調した点。症状が「たまに押し戻す向きがおかしい」という分かりにくい形で出る。

**落とし穴 2：`thread_local` な頂点バッファ。**　二つの形状の頂点を同時に保持できない。第 12 章以降の設計で解消する。

**落とし穴 3：等価性テストで完全一致を要求する。**　境界近傍では実装によって結論が割れる。割合で管理する。
