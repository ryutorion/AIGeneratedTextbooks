# 第 10 章　AABB ― 最も使われる形

> **この章のゴール**
> AABB（軸平行境界ボックス）を本格的に実装する。二つの表現形式の使い分け、重なり判定、合成・拡張・内包といった補助操作、そして最小移動ベクトル（MTV）の計算。
>
> 前章で残した「円の中心が形状の内部にあると深度が正しくない」という制約を、AABB について解決する。そこで登場する「最も浅い軸を選ぶ」という考え方が、次章の分離軸定理そのものである。**この章は第 I 部の締めくくりであり、第 II 部への入口でもある。**

---

## 10.1 二つの表現形式

### min-max 表現

AABB は「軸に平行な辺を持つ長方形」である。最も素直な表現は、対角の二点を持つことである。

```cpp
// collision/shapes/aabb.h
#pragma once

#include "collision/math/vec2.h"
#include <algorithm>

namespace collision {

struct Aabb {
    Vec2 min{};
    Vec2 max{};
};

} // namespace collision
```

**不変条件として `min.x <= max.x` かつ `min.y <= max.y` を課す。** これが崩れた AABB（「反転した」AABB）は、以降のすべての演算で意味をなさなくなる。

### center-extents 表現

もう一つの表現がある。中心と、そこから各軸方向への半幅（half-extents）を持つ形である。

```cpp
struct AabbCE {
    Vec2 center{};
    Vec2 extents{};   // 各軸の半幅（非負）
};
```

### どちらを使うか

用途によって得手不得手がある。

| 操作 | min-max | center-extents |
|---|---|---|
| 二つの AABB の重なり判定 | 素直（区間の比較） | 差と和の比較で書ける |
| 合成（両方を含む AABB） | **素直**（min と max を取るだけ） | 一度 min-max に直す必要がある |
| マージンの拡張 | 両方を動かす | **素直**（extents に足すだけ） |
| 点の内包判定 | **素直** | 絶対値の比較 |
| SIMD 化 | 4 成分をまとめて扱いやすい | 同上 |
| OBB への一般化 | しにくい | **しやすい**（軸を足すだけ） |

**本書は min-max を主表現とする。** 合成と内包の判定が素直に書けること、そして第 32 章の BVH で AABB を大量に合成することが理由である。

center-extents が有利なのは、第 12 章の OBB（有向境界ボックス）へ拡張するときである。OBB は「中心・軸・半幅」で表すのが自然で、AABB はその軸が座標軸に固定された特殊ケースと見なせる。そのため、変換関数を用意しておく。

```cpp
[[nodiscard]] constexpr Vec2 center(const Aabb& b) noexcept {
    return (b.min + b.max) * 0.5f;
}

[[nodiscard]] constexpr Vec2 extents(const Aabb& b) noexcept {
    return (b.max - b.min) * 0.5f;
}

[[nodiscard]] constexpr Vec2 size(const Aabb& b) noexcept {
    return b.max - b.min;
}

[[nodiscard]] constexpr Aabb from_center_extents(Vec2 c, Vec2 e) noexcept {
    return Aabb{.min = c - e, .max = c + e};
}
```

`center` の計算に `(min + max) * 0.5f` を使っている。`(min + max) / 2.0f` でも同じだが、**乗算のほうが除算より速い**。`/fp:fast` ならコンパイラが変換してくれるが、こう書いておけば `/fp:precise` でも同じ結果になる。

> **桁落ちの注意**
> `(min + max) * 0.5f` は、`min` と `max` が非常に大きく符号が逆の場合にオーバーフローしうる。`min + (max - min) * 0.5f` と書けば回避できる。本書のスケール（第 5.9 節）では起こらないので単純な式を使うが、汎用ライブラリを書くなら意識すべき点である。

### 妥当性の検査

不変条件を確認する関数を用意しておく。

```cpp
[[nodiscard]] constexpr bool is_valid(const Aabb& b) noexcept {
    return b.min.x <= b.max.x && b.min.y <= b.max.y;
}

// 空の AABB（何も含まない）を表す番兵。合成の初期値に使う。
[[nodiscard]] inline Aabb empty_aabb() noexcept {
    constexpr float inf = std::numeric_limits<float>::infinity();
    return Aabb{.min = { inf,  inf}, .max = {-inf, -inf}};
}
```

`empty_aabb` は `min > max` なので `is_valid` を満たさない。**これは意図的である。** 合成の初期値として使い、点を足していくと自然に正しい AABB になる（10.4 節）。

`Inf` を使っている点について、第 4 章で「`/fp:fast` では `Inf` の扱いが保証されない」と述べたことと矛盾しないか気になるかもしれない。ここでの用途は「非常に大きな値」としての利用であり、`Inf` 特有の演算規則（`Inf - Inf = NaN` など）には依存していない。気になるなら `std::numeric_limits<float>::max()` に置き換えてもよい。**そのほうが安全**である。

## 10.2 重なり判定は「区間の重なり」の 2 回適用

### 1 次元で考える

AABB の重なり判定は、次元ごとに独立している。まず 1 次元、つまり区間の重なりを考える。

区間 `[a0, a1]` と `[b0, b1]` が重ならない条件は単純である。

```
a1 < b0  （A が完全に B の左）  または  b1 < a0  （B が完全に A の左）
```

重なる条件は、この否定である。

```
a0 <= b1  かつ  b0 <= a1
```

### 2 次元へ

X 軸と Y 軸の両方で区間が重なっていれば、AABB は重なっている。片方でも重なっていなければ、重なっていない。

```cpp
// collision/narrow/aabb_aabb.h
#pragma once

#include "collision/shapes/aabb.h"
#include "collision/narrow/contact.h"

namespace collision {

[[nodiscard]] constexpr bool overlaps(const Aabb& a, const Aabb& b) noexcept {
    if (a.max.x < b.min.x || b.max.x < a.min.x) return false;   // X で分離
    if (a.max.y < b.min.y || b.max.y < a.min.y) return false;   // Y で分離
    return true;
}

} // namespace collision
```

比較 4 回だけである。分岐も早期脱出する形になっていて、多くの場合は最初の 1〜2 回で決着がつく。ブロードフェーズ（第 VI 部）で数万回呼ばれても耐えられる速さである。

### これが分離軸定理の最も単純な形である

上のコードを読み直してほしい。**「X 軸で分離しているか」「Y 軸で分離しているか」を順に調べ、どれか一つでも分離していれば交差なし**、と判定している。

これはまさに**分離軸定理**（Separating Axis Theorem, SAT）の構造である。次章で一般の凸形状に対して展開する定理が、AABB という最も単純な形状では、たった 4 回の比較に退化している。

違いは調べる軸の数だけである。

| 形状ペア | 調べる軸 | 本数 |
|---|---|---|
| AABB vs AABB | X 軸、Y 軸 | 2 |
| OBB vs OBB（2D） | 各 OBB の 2 軸ずつ | 4 |
| 凸多角形 vs 凸多角形 | 両者のすべての辺の法線 | 辺数の合計 |
| OBB vs OBB（3D） | 面法線 6 ＋ 辺の外積 9 | 15 |

**この章で AABB を丁寧にやっておくと、次章が「同じことを一般化するだけ」に見えてくる。**

### 点の内包

点が AABB の中にあるかも、同じ形で書ける。

```cpp
[[nodiscard]] constexpr bool contains(const Aabb& b, Vec2 p) noexcept {
    return b.min.x <= p.x && p.x <= b.max.x &&
           b.min.y <= p.y && p.y <= b.max.y;
}

// b が a に完全に含まれるか
[[nodiscard]] constexpr bool contains(const Aabb& a, const Aabb& b) noexcept {
    return a.min.x <= b.min.x && b.max.x <= a.max.x &&
           a.min.y <= b.min.y && b.max.y <= a.max.y;
}
```

## 10.3 合成、拡張、面積

### 合成（union）

二つの AABB の両方を含む、最小の AABB を求める。

```cpp
[[nodiscard]] constexpr Aabb merge(const Aabb& a, const Aabb& b) noexcept {
    return Aabb{
        .min = Vec2{std::min(a.min.x, b.min.x), std::min(a.min.y, b.min.y)},
        .max = Vec2{std::max(a.max.x, b.max.x), std::max(a.max.y, b.max.y)},
    };
}

[[nodiscard]] constexpr Aabb merge(const Aabb& b, Vec2 p) noexcept {
    return Aabb{
        .min = Vec2{std::min(b.min.x, p.x), std::min(b.min.y, p.y)},
        .max = Vec2{std::max(b.max.x, p.x), std::max(b.max.y, p.y)},
    };
}
```

min と max を成分ごとに取るだけである。min-max 表現の利点がここに出ている。

**この関数は第 32 章の動的 AABB 木（BVH）の中核になる。** 木のノードは、子ノードの AABB を合成したものを持つ。木の構築と更新で、この関数が最も頻繁に呼ばれる。

### 拡張（マージン）

AABB を全方向に一定量広げる。

```cpp
[[nodiscard]] constexpr Aabb expanded(const Aabb& b, float margin) noexcept {
    const Vec2 m{margin, margin};
    return Aabb{.min = b.min - m, .max = b.max + m};
}

[[nodiscard]] constexpr Aabb expanded(const Aabb& b, Vec2 margin) noexcept {
    return Aabb{.min = b.min - margin, .max = b.max + margin};
}
```

用途は主に二つある。

**BVH の「太らせた AABB」（fat AABB）。**　物体が少し動くたびに木を更新するのは高くつくので、あらかじめ余裕を持たせた AABB を木に入れておく。物体がその範囲内で動く限り、木を更新しなくてよい（第 32.1 節）。

**スイープ判定の前段。**　移動する物体の判定では、移動経路全体を覆う AABB を作って粗く絞り込む（第 17 章）。

### 移動経路の AABB

スイープ用の補助関数も、ここで用意しておく。

```cpp
// AABB が delta だけ移動する間に通過する領域全体を覆う AABB
[[nodiscard]] constexpr Aabb swept(const Aabb& b, Vec2 delta) noexcept {
    Aabb result = b;
    if (delta.x < 0.0f) result.min.x += delta.x; else result.max.x += delta.x;
    if (delta.y < 0.0f) result.min.y += delta.y; else result.max.y += delta.y;
    return result;
}
```

移動方向の側だけを伸ばす。単純に `merge(b, translated(b, delta))` としても同じ結果が得られるが、こちらのほうが分岐が少なく速い。

### 面積と周長

BVH のコスト計算（第 32.2 節の表面積ヒューリスティック）で使う。

```cpp
[[nodiscard]] constexpr float area(const Aabb& b) noexcept {
    const Vec2 s = size(b);
    return s.x * s.y;
}

[[nodiscard]] constexpr float perimeter(const Aabb& b) noexcept {
    const Vec2 s = size(b);
    return 2.0f * (s.x + s.y);
}
```

> **2D では周長を使う**
> 表面積ヒューリスティック（SAH）は本来 3 次元の概念で、AABB の表面積を「ランダムな光線が当たる確率」の指標として使う。2 次元では、それに対応するのは面積ではなく**周長**である。第 32 章でこの点に触れる。名前は「表面積ヒューリスティック」のままだが、2D では周長を使うと覚えておいてほしい。

## 10.4 点群からの構築と、変換後の再計算

### 点群を包む

```cpp
#include <span>

[[nodiscard]] inline Aabb aabb_from_points(std::span<const Vec2> points) noexcept {
    Aabb result = empty_aabb();
    for (const Vec2 p : points) {
        result = merge(result, p);
    }
    return result;
}
```

`empty_aabb()` を初期値にすることで、最初の点で自動的に正しい AABB になる。`min = +Inf` なので、どんな点を入れても `std::min` で置き換わる。**番兵の使い方として定石**である。

点が一つもない場合、戻り値は `empty_aabb()` のまま、つまり `is_valid` を満たさない AABB になる。呼び出し側でチェックが要る。`std::optional<Aabb>` を返す設計もありうるが、この関数は BVH の内部で頻繁に呼ばれるので、単純さを優先する。

`std::span` を使っているのは、`std::vector` でも生配列でも `std::array` でも受け取れるようにするためである。C++20 の機能で、コピーを伴わない軽量なビューである。

### 回転した後の AABB

物体が回転すると、それを包む AABB は変わる。ここには落とし穴がある。

**間違ったやり方：AABB の 4 隅を回転させて、その AABB を取る。**

これは「AABB を回転させたもの」を包む AABB であって、「元の形状を回転させたもの」を包む AABB ではない。AABB は元の形状より大きいので、結果はさらに大きくなる。回転を繰り返すと AABB が際限なく膨らむ（この現象を「AABB の腐敗」と呼ぶことがある）。

**正しいやり方：元の形状の頂点を回転させて、その AABB を取る。**

```cpp
// 頂点列を変換してから AABB を作る
[[nodiscard]] inline Aabb
aabb_of_transformed(std::span<const Vec2> local_points, Vec2 translation, float cos_a, float sin_a) noexcept {
    Aabb result = empty_aabb();
    for (const Vec2 p : local_points) {
        const Vec2 rotated{p.x * cos_a - p.y * sin_a,
                           p.x * sin_a + p.y * cos_a};
        result = merge(result, rotated + translation);
    }
    return result;
}
```

角度ではなく `cos` と `sin` を受け取っている。**同じ角度で多数の点を回転させるとき、三角関数を一度しか計算しない**ためである。三角関数は平方根よりさらに遅い。

### OBB の AABB を求める公式

回転した矩形（OBB）の AABB は、頂点を回さなくても求まる。半幅を絶対値付きの回転行列で変換すればよい。

```cpp
// 中心 c、半幅 e、回転 (cos_a, sin_a) の OBB を包む AABB
[[nodiscard]] inline Aabb aabb_of_obb(Vec2 c, Vec2 e, float cos_a, float sin_a) noexcept {
    const float ax = std::fabs(cos_a);
    const float ay = std::fabs(sin_a);
    const Vec2 half{e.x * ax + e.y * ay,
                    e.x * ay + e.y * ax};
    return from_center_extents(c, half);
}
```

回転行列の各成分の絶対値を取って半幅に掛ける、という形になっている。頂点を 4 つ回して min/max を取るより速い。3D でも同じ考え方が使え、そちらでは 8 頂点を回す代わりに 3×3 行列の絶対値で済むので、差はもっと大きい。

第 12 章で OBB を実装したら、この関数がその境界ボックスの計算に使われる。

## 10.5 貫通深度の最小軸 ― MTV の初歩

### 交差情報を求める

`overlaps` は有無だけを返す。第 7 章の規約に従い、`Contact` を返す `intersect` を書く。

法線と深度をどう決めるか。AABB どうしの重なりは、一般には矩形の領域になる。押し戻す向きは一つに定まらない。X 方向にも Y 方向にも押し戻せる。

**本書の規約：重なりが最も浅い軸を選ぶ。** これが「最小移動ベクトル」（Minimum Translation Vector, MTV）である。移動量が最小になる押し戻し方を選ぶ、という自然な判断である。

### 各軸の押し出し量

X 軸方向を考える。A を X 方向に動かして B から離すには、二つの選び方がある。

```
push_positive = b.max.x - a.min.x     （A を右へ、B の右端の外まで）
push_negative = a.max.x - b.min.x     （A を左へ、B の左端の外まで）
```

必要な押し出し量は、この小さいほうである。どちらかが 0 以下なら、その軸で既に分離している。

> **`min(a.max, b.max) - max(a.min, b.min)` と書いてはいけない**
> 一見それらしく、分離の判定としては正しい。だが**押し出し量としては誤りである**。
>
> A の X 区間が `[0, 10]`、B が `[4, 6]` の場合を考えてほしい。この式は `6 - 4 = 2` を返すが、B を A の外へ出すには最低 6 動かす必要がある。**片方が他方に含まれるとき、押し出し量を大幅に過小評価する。**
>
> 症状は「小さい物体が大きい物体に深くめり込むと、押し戻しが足りずに内部に留まる」という形で現れる。浅い接触では正しく動くので発見が遅れる。第 11.2 節で、一般の軸に対して同じ議論をする。

### 実装

```cpp
// collision/narrow/aabb_aabb.h（続き）

[[nodiscard]] inline std::optional<Contact>
intersect(const Aabb& a, const Aabb& b) noexcept {
    // 各軸について、A を押し出して分離するのに必要な距離を求める。
    // 「重なり量」ではなく「押し出し量」であることが重要（第 11.2 節）。
    const float px_pos = b.max.x - a.min.x;   // A を +X へ押す
    const float px_neg = a.max.x - b.min.x;   // A を -X へ押す
    if (px_pos <= 0.0f || px_neg <= 0.0f) return std::nullopt;

    const float py_pos = b.max.y - a.min.y;
    const float py_neg = a.max.y - b.min.y;
    if (py_pos <= 0.0f || py_neg <= 0.0f) return std::nullopt;

    const float ox = std::min(px_pos, px_neg);
    const float oy = std::min(py_pos, py_neg);

    // 押し出し量が小さいほうの軸を選ぶ（＝最小移動ベクトル）。
    // 法線は「A から B へ」の規約なので、押し出す向きの逆になる。
    Vec2  normal{};
    float depth{};
    if (ox < oy) {
        normal = Vec2{(px_pos < px_neg) ? -1.0f : 1.0f, 0.0f};
        depth  = ox;
    } else {
        normal = Vec2{0.0f, (py_pos < py_neg) ? -1.0f : 1.0f};
        depth  = oy;
    }

    // 接触点：重なった領域の中心を使う
    const Vec2 overlap_min{std::max(a.min.x, b.min.x), std::max(a.min.y, b.min.y)};
    const Vec2 overlap_max{std::min(a.max.x, b.max.x), std::min(a.max.y, b.max.y)};

    return Contact{
        .normal = normal,
        .depth  = depth,
        .point  = (overlap_min + overlap_max) * 0.5f,
    };
}
```

### 設計上の判断がいくつかある

**法線は必ず座標軸に平行になる。** AABB どうしの押し戻しでは、斜め方向の法線は出てこない。これは正しい挙動である。押し戻す向きは面の法線であり、AABB の面はすべて座標軸に垂直だからである。

**`normalize` を呼んでいない。** 法線が `(±1, 0)` か `(0, ±1)` なので、すでに単位長である。正規化のコストも、ゼロ除算の心配もない。**これは AABB の大きな利点である。**

**接触点は「重なった領域の中心」とした。** 第 7.2 節では「A の表面上の点」と規約を決めたが、AABB どうしでは重なりが面をなすので、代表点として領域の中心を使うほうが自然である。

これは規約からの逸脱である。正直に認めておく。第 14 章でマニフォールドを導入すると、この曖昧さは解消する（複数の接触点を返せるようになる）。**それまでの暫定的な選択**である。

**符号は押し出し方向から決まる。** `px_pos < px_neg` なら A を +X へ押すのが近道であり、法線（A から B へ）はその逆の -X になる。中心の位置関係を見る必要はない。押し出し量を正しく計算すれば、向きの情報が自動的に付いてくる。

### 円の中心が AABB の内部にある場合を解決する

第 9.5 節で残した宿題に戻る。円の中心が AABB の内部にあるとき、正しい深度を求めたい。

考え方は上の MTV と同じである。**中心から 4 つの辺までの距離を測り、最も近いものを選ぶ。**

```cpp
// collision/narrow/circle_aabb.h
#pragma once

#include "collision/shapes/circle.h"
#include "collision/shapes/aabb.h"
#include "collision/narrow/contact.h"

namespace collision {

// 円と AABB の判定。円の中心が AABB の内部にある場合も正しく扱う。
// 第 9 章の統一実装（circle_vs.h）を、この形状ペアについて特殊化したもの。
[[nodiscard]] inline std::optional<Contact>
intersect(const Circle& a, const Aabb& b) noexcept {
    const Vec2 q = closest_point_on_aabb(a.center, b);
    const Vec2 d = q - a.center;

    if (const float d2 = length_squared(d); d2 >= min_length2) {
        // 中心は AABB の外部。第 9 章の実装と同じ
        if (d2 >= a.radius * a.radius) {
            return std::nullopt;
        }
        const float dist   = std::sqrt(d2);
        const Vec2  normal = d / dist;
        return Contact{
            .normal = normal,
            .depth  = a.radius - dist,
            .point  = a.center + normal * a.radius,
        };
    }

    // 中心が AABB の内部（または表面上）にある。
    // 4 辺までの距離を測り、最も近い辺の向きへ押し出す。
    const float to_left   = a.center.x - b.min.x;
    const float to_right  = b.max.x - a.center.x;
    const float to_bottom = a.center.y - b.min.y;
    const float to_top    = b.max.y - a.center.y;

    // 法線の向きの決め方（間違えやすいので導出を残す）:
    //   規約は「A(円) から B(箱) へ」。円は -normal 方向へ動かすと離れる。
    //   最も近い辺が「左」なら、円は左（-X）へ出るべき。
    //   よって -normal = (-1, 0)、すなわち normal = (+1, 0)。
    //   つまり *出ていく向きの逆* が法線になる。
    float best = to_left;
    Vec2  normal{ 1.0f,  0.0f};      // 左へ出る → 法線は +X

    if (to_right  < best) { best = to_right;  normal = Vec2{-1.0f,  0.0f}; }  // 右へ出る → -X
    if (to_bottom < best) { best = to_bottom; normal = Vec2{ 0.0f,  1.0f}; }  // 下へ出る → +Y
    if (to_top    < best) { best = to_top;    normal = Vec2{ 0.0f, -1.0f}; }  // 上へ出る → -Y

    return Contact{
        .normal = normal,
        .depth  = best + a.radius,       // 縁まで出る分 ＋ 半径の分
        .point  = a.center + normal * a.radius,
    };
}

} // namespace collision
```

**深度が `best + a.radius` になる**のが要点である。円の中心を縁まで動かす分（`best`）に加えて、円の半径だけさらに動かさないと完全には離れない。

第 9.5 節で挙げた例（10×10 の箱の中心にいる半径 1 の円）で確かめると、`best = 5`、`radius = 1` なので深度は `6` になる。前章の実装が返した `1` は誤りで、この実装が正しい。

法線の符号は本書で最も間違えやすい箇所の一つである。**「出ていく向き」と「法線の向き」は逆になる。** コードにも導出をコメントで残した。筆者も執筆中に一度符号を逆にし、10.6 節のテストで捕まえている。**符号の規約は必ずテストで守る。**

> **オーバーロード解決について**
> 第 9 章で `intersect(const Circle&, const S&)` というテンプレートを書いた。`Aabb` は `HasClosestPoint` を満たすので、そのテンプレートも `intersect(circle, aabb)` の候補になる。
>
> それでもこの節の非テンプレート版が選ばれる。C++ のオーバーロード解決では、**引数の変換が同等なら、テンプレートより非テンプレート関数が優先される**からである。第 9 章の汎用実装はそのまま残しておいてよく、AABB についてだけ正しい実装に差し替わる。
>
> 同じ手法で、第 11 章では凸多角形版を、第 12 章では OBB 版を追加していく。**汎用実装が既定で、形状ごとの特殊化が上書きする**という構造になる。

### 「最も浅い軸を選ぶ」という発想

この節で二度、同じ発想が出てきた。

- AABB vs AABB … 2 つの軸のうち、重なりが浅いほうを選ぶ
- 円の中心が AABB の内部 … 4 つの辺のうち、最も近いものを選ぶ

**これが分離軸定理における「最小貫通軸」の探索である。** 次章では、これを任意の凸形状に一般化する。調べる軸の本数が増えるだけで、「各軸の重なり量を計算し、最小のものを選ぶ」という構造はまったく変わらない。

```cpp
// [変更] intersect と整合させる
[[nodiscard]] constexpr bool overlaps(const Aabb& a, const Aabb& b) noexcept {
    if (a.max.x <= b.min.x || b.max.x <= a.min.x) return false;

}
```

## この章のまとめ

- AABB の表現は min-max（本書の主表現）と center-extents。合成しやすさで前者を選んだ
- **重なり判定は「区間の重なり」の 2 回適用。これが分離軸定理の最も単純な形である**
- 合成 `merge` は min/max を取るだけ。第 32 章の BVH の中核になる
- 拡張 `expanded` と移動経路 `swept` は、BVH とスイープ判定で使う
- 点群から作るときは `empty_aabb()` を番兵に使う
- 回転後の AABB は、AABB の隅ではなく**元の形状の頂点**を回して作る
- MTV は「重なりが最も浅い軸を選ぶ」。法線は常に座標軸に平行で、正規化が不要
- **円の中心が AABB の内部にある場合を解決した。** 深度は「縁までの距離 ＋ 半径」
- テストが仕様の不整合（`overlaps` と `intersect` の境界の扱い）を暴いた
- 第 9 章の「既知の制約」テストを削除できた。これが修正の証拠

### 第 I 部を終えて

ここまでで、円と AABB による 2D の当たり判定が一通り書けるようになった。第 1 章の対応表でいえば、「2D アクションの基本形」に到達したことになる。

到達点を確認しておこう。

| できること | 章 |
|---|---|
| 円 vs 円 | 第 8 章 |
| 円 vs 線分 / AABB / 三角形 | 第 9 章、第 10 章 |
| AABB vs AABB | 第 10 章 |
| 押し戻しに必要な法線・深度・接触点 | 第 7 章の規約に従って全ペアで |
| 退化ケース（同心・内包・中心が内部）の処理 | 各章 |

まだできないこと。**回転した形状が扱えない。** OBB も凸多角形も、この章の道具では判定できない。それが第 II 部の主題である。

### 落とし穴と練習問題

**落とし穴 1：反転した AABB。**　`min > max` の AABB を作ってしまうと、すべての演算が壊れる。`is_valid` で検査する習慣を持つ。

**落とし穴 2：回転後の AABB を、AABB の隅から作る。**　繰り返すと際限なく膨らむ。

**落とし穴 3：MTV の法線の符号。**　「円を左へ出す」と「法線が左向き」は違う。規約は「A から B へ」。必ずテストで守る。

---

**練習問題 10-1**　`intersect(Aabb, Aabb)` は X と Y の重なりが完全に等しいとき、`ox < oy` が偽になるので Y を選ぶ。この選択は妥当だろうか。正方形どうしが対角にちょうど重なったとき、どちらへ押し戻されるべきか考えてみてほしい。

**練習問題 10-2**　`aabb_of_obb` の公式が正しいことを、4 頂点を実際に回転させて AABB を取る方法と比較して検証しよう。ランダムな角度と半幅で 10,000 回試す。

**練習問題 10-3**　`empty_aabb()` に `Inf` ではなく `std::numeric_limits<float>::max()` を使うよう変更し、10.6 節のテストがすべて通ることを確認しよう。どちらが安全か、第 4 章の議論を踏まえて考えてみてほしい。

**練習問題 10-4**　円と AABB の判定で、円の中心がちょうど AABB の辺の上にあるとき（`min_length2` の境界）、どちらの分岐に入るだろうか。両方の分岐で結果が連続的につながっているかを、境界付近を細かく走査して確認しよう。第 3.5 節の原則 3 の実践である。

**練習問題 10-5**（発展）　AABB vs AABB の `intersect` を、center-extents 表現で書き直してみよう。`|ca.x - cb.x| < ea.x + eb.x` という形になる。min-max 版と比べて、命令数はどう変わるだろうか。`.asm` を出力して比べてみてほしい。

**練習問題 10-6**（発展）　`overlaps(Aabb, Aabb)` を 4 つの AABB に対して同時に判定する SIMD 版を書いてみよう。第 42.7 節の予習になる。`__m128` に 4 つの `min.x` を詰めて比較する形になる。
