# 第 39 章　3D への応用と積み残し

> **この章のゴール**
> 第 VII 部の締めくくりとして、剛体を 3D へ持ち上げる。**質量はスカラーのままだが、慣性はテンソルになる。** そして回転の積分に、2D にはなかった厄介な項が現れる。
>
> ジャイロ項 `ω × Iω` は、陽的に積分すると発散する。実測では **50 秒でエネルギーが 3.04 倍**になった。`dt` を半分にしても 1.61 倍で、根本的には解決しない。多くのエンジンがどう対処しているかを見る。
>
> 最後に、本書が扱わなかった領域への地図を描く。**何を知らないかを知っている**状態で本書を閉じてほしい。

## 39.1 3D 剛体の慣性テンソルと回転の積分

### 慣性はスカラーではなくテンソルになる

2D では慣性モーメントが 1 個のスカラーだった。「回しにくさ」は 1 種類しかなかったからである。

**3D では、どの軸まわりに回すかで回しにくさが違う。** 3×3 の対称行列——**慣性テンソル**——になる。

```cpp
// collision/dynamics/rigid_body3.h
struct RigidBody3 {
    Vec3 position{};
    Quat orientation{};              // 第 24.3 節で検討したクォータニオン

    Vec3 velocity{};
    Vec3 angular_velocity{};         // 3 成分のベクトルになる

    float inv_mass{};
    Mat3  inv_inertia_local{};       // ローカル座標系での逆慣性テンソル
    Mat3  inv_inertia_world{};       // 毎フレーム更新する（後述）
};
```

**主軸が座標軸に一致していれば、テンソルは対角行列になる。** 直方体・球・カプセルなど、本書で扱う形状はすべてそうである。

```cpp
// 直方体（各辺 w, h, d）の慣性テンソル（対角成分のみ）
[[nodiscard]] constexpr Vec3 box_inertia(float mass, float w, float h, float d) noexcept {
    return Vec3{
        mass * (h * h + d * d) / 12.0f,
        mass * (w * w + d * d) / 12.0f,
        mass * (w * w + h * h) / 12.0f,
    };
}
```

検算しておく。

| 形状（質量 1） | I₁ | I₂ | I₃ |
|---|---:|---:|---:|
| 1×1×1 の立方体 | 0.166667 | 0.166667 | 0.166667 |
| 1×2×3 の直方体 | 1.083333 | 0.833333 | 0.416667 |

**立方体は 3 軸とも等しく、第 35.1 節の 2D の値（1/6）と一致する。**

そして 1×2×3 では、**最も長い辺（3）の方向の軸まわりが最小（0.4167）**、最も短い辺（1）の方向の軸まわりが最大（1.0833）になる。**細長い棒は、長軸まわりには回しやすい。** 直感と合う。

### ローカル → ワールドへの変換

慣性テンソルは物体に固定された量である。**物体が回れば、ワールド座標での見え方が変わる。**

```
I_world = R · I_local · Rᵀ
```

逆テンソルも同じ形で変換できる。

```cpp
void update_inertia_world(RigidBody3& b) noexcept {
    const Mat3 r = to_matrix(b.orientation);
    b.inv_inertia_world = r * b.inv_inertia_local * transpose(r);
}
```

**第 24.3 節で「直交行列の逆は転置」と確かめておいたおかげで、逆行列の計算が要らない。**

対角テンソルなら、この積は展開して安く書ける。**まず素直に書き、プロファイルしてから詰める**（第 42.1 節）。

### 回転の積分

角速度から姿勢を更新する。**2D の `rotation += ω · dt` に相当する処理だが、3D では単純な足し算にならない。**

クォータニオンでは次の形になる。

```cpp
void integrate_orientation(RigidBody3& b, float dt) noexcept {
    // dq/dt = ½ · ω_quat · q     （ω_quat は実部ゼロの四元数）
    const Quat omega{b.angular_velocity.x, b.angular_velocity.y,
                     b.angular_velocity.z, 0.0f};
    b.orientation += (omega * b.orientation) * (0.5f * dt);
    b.orientation = normalized(b.orientation);      // ★ 毎フレーム正規化する
}
```

**正規化が必須である。** この積分は近似なので、放置するとクォータニオンの長さが 1 からずれ、姿勢が歪む（拡大縮小が混ざる）。

**第 24.3 節で「剛体シミュレーションではクォータニオンを検討する余地がある」と書いたのは、まさにこの点である。** `Mat3` を直接積分すると、直交性を回復するのにグラム・シュミットが要る。クォータニオンなら**正規化 1 回で有効な回転に戻る。**

**判定には `Mat3`、積分には `Quat`。** 用途で表現を選ぶ、という第 24.3 節の結論がそのまま効いている。

### 球とカプセルの慣性テンソル

```cpp
// 球（半径 r）。どの軸まわりも同じ
[[nodiscard]] constexpr Vec3 sphere_inertia(float mass, float r) noexcept {
    const float i = 0.4f * mass * r * r;      // 2/5 m r²
    return Vec3{i, i, i};
}

// カプセル（Y 軸方向、円柱部の高さ h、半径 r）。
// 円柱と半球二つに分けて、平行軸の定理で足し合わせる
[[nodiscard]] Vec3 capsule_inertia(float density, float r, float h) noexcept {
    const float cyl_mass = density * std::numbers::pi_v<float> * r * r * h;
    const float cap_mass = density * (2.0f / 3.0f)
                         * std::numbers::pi_v<float> * r * r * r;   // 半球ひとつ

    // Y 軸（長軸）まわり
    const float iy = cyl_mass * r * r * 0.5f
                   + 2.0f * cap_mass * r * r * 0.4f;

    // X・Z 軸まわり（円柱の寄与 ＋ 半球を h/2 ずらした寄与）
    const float ix = cyl_mass * (3.0f * r * r + h * h) / 12.0f
                   + 2.0f * cap_mass * (0.4f * r * r
                                        + 0.375f * r * h + 0.25f * h * h);
    return Vec3{ix, iy, ix};
}
```

**カプセルは「円柱 ＋ 半球 2 個」に分けて、平行軸の定理で足す**（第 35.1 節と同じ手である）。半球の重心が中心から `3r/8` ずれることが `0.375·r·h` の項に効いている。

**式が長いので、必ず検算する。** `h → 0` にすれば球の値 `0.4 m r²` に、`r → 0` にすれば細い棒の値 `m h²/12` に近づくはずである。**極限で既知の値に一致するかどうかは、こうした式の最も安価な検証法である。**

### 主軸への変換

一般の形状（凸包など）では、慣性テンソルは対角行列にならない。**対称行列なので、固有値分解で必ず対角化できる。**

- **固有値**が主慣性モーメント（`I₁, I₂, I₃`）
- **固有ベクトル**が主軸の向き

**主軸へ変換しておくと、テンソルを 3 個の `float` で持てる。** メモリも計算も軽くなる。形状のローカル姿勢を主軸に合わせて回しておけばよい。

**本書では対角のまま扱える形状しか使わないので、実装しない。** 3×3 対称行列のヤコビ法による対角化は 50 行程度で書ける。必要になったら、そのとき足せばよい。

### 角運動量の保存という視点

2D では `Iω` がスカラーだったので、外力がなければ `ω` は一定だった。

**3D では違う。** 保存するのは**角運動量 `L = I ω`** であって、角速度ではない。

`I` は物体の姿勢とともに変わるので、**`L` が一定でも `ω` は変化しうる。** これが次節の主題である。

## 39.2 ジャイロ効果と数値的不安定

### オイラーの運動方程式

外力がないとき、物体固定座標系での角速度は次の式に従う。

```
I dω/dt = -ω × (I ω)
```

**右辺が「ジャイロ項」である。** 2D には存在しない。`ω` と `Iω` が平行なら（＝主軸まわりの回転なら）ゼロになり、それ以外では回転の向きが勝手に変わる。

```cpp
// ジャイロ項による角速度の変化（陽的）
void apply_gyroscopic(RigidBody3& b, float dt) noexcept {
    const Vec3 L = b.inertia_world * b.angular_velocity;      // 角運動量
    const Vec3 torque = -cross(b.angular_velocity, L);
    b.angular_velocity += b.inv_inertia_world * torque * dt;
}
```

### 中間軸まわりの回転は不安定である

慣性主値が `I₁ < I₂ < I₃` の物体を、**それぞれの主軸まわりに回してみた**（`dt = 1/480`、20 秒）。

| 回転軸 | 主成分の範囲 | 符号反転 | 結論 |
|---|---|---:|---|
| 最小慣性軸（I=1） | [5.000, 5.000] | 0 回 | **安定** |
| **中間慣性軸（I=2）** | **[−5.092, 5.123]** | **2 回** | **不安定** |
| 最大慣性軸（I=3） | [5.000, 5.000] | 0 回 | **安定** |

**中間軸まわりの回転だけが、勝手に反転する。** 最小軸と最大軸は 5.000 のまま微動だにしない。

**これは数値誤差ではなく、物理現象である。** 「中間軸定理」または「テニスラケットの定理」と呼ばれる。宇宙飛行士ジャニベコフが無重力下で観測した現象として知られ、**T 字型のハンドルを放り投げると周期的にひっくり返る。**

**ゲームでこれを再現できると、投げた物体の動きが劇的にそれらしくなる。** だが代償がある。

### 陽的に積分すると発散する

同じ中間軸の回転を、`dt` を変えて 50 秒間シミュレートした。**外力がないので、エネルギーは厳密に保存されるはずである。**

| `dt` | 50 秒後のエネルギー比 |
|---|---:|
| 1/240 | 1.2512 |
| 1/120 | 1.6122 |
| **1/60** | **3.0402** |
| 1/30 | **49.2325** |

**60 fps では 50 秒でエネルギーが 3 倍になる。** 30 fps では 49 倍——完全な破綻である。

**`dt` を半分にしても、1.61 倍が 1.25 倍になるだけで、増え続けることに変わりはない。** 陽的な積分では原理的に解決しない。

陰的（後退オイラー）にすると逆にエネルギーが減る（50 秒で 0.494 倍）。**発散しないぶんずっとましだが、正しくもない。**

| 手法 | 50 秒後のエネルギー比 | 角運動量の誤差 |
|---|---:|---:|
| 陽的オイラー | **3.0402** | 7.44e−01 |
| 陰的オイラー | 0.4944 | 2.97e−01 |

### 実務上の答え ― 項ごと落とす

**多くのゲームエンジンは、ジャイロ項を単に計算しない。**

```cpp
void integrate_angular(RigidBody3& b, float dt) noexcept {
    // ジャイロ項 -ω × (Iω) を無視する。
    // 理由：陽的積分では発散し、陰的にしても正しくならない（39.2 節の実測）。
    //       そして多くのゲーム物体では効果が小さい。
    b.angular_velocity += b.inv_inertia_world * b.torque * dt;
}
```

**落とすと `ω` は一定になり、エネルギーも角運動量も厳密に保存される。** そのかわり中間軸の反転は再現されない。

**この判断は「正しさを捨てた」ように見えるが、そうではない。**

- 発散する近似より、**保存する別の近似**のほうが安全である
- 効果が目に見えるのは、**細長い物体が空中で長時間回転する場合だけ**である
- 箱・樽・キャラクタといった典型的なゲーム物体では、接触が頻繁に起きるので、ジャイロ効果が積み上がる前にリセットされる

**必要なら、項を持つ物体だけ限定的に有効にする。** 投げナイフ、ブーメラン、宇宙船——「回転が見せ場になる物体」だけである。

そのときは**部分陰的な扱い**（ジャイロ項だけを 1 段のニュートン法で解く）を使う。実装は数十行で済み、少なくとも発散はしなくなる。

> **これは本書全体を通じた姿勢でもある**
> 第 34.3 節の `slop`、第 37.3 節の `beta`、第 38.3 節のコヨーテタイム——どれも「物理的に正しくないが、予測可能で安全な近似」である。
>
> **ゲーム物理の設計判断は、「正しいかどうか」ではなく「予測可能かどうか」で下されることが多い。** 発散するくらいなら、少し嘘のほうがよい。

## 39.3 3D の摩擦 ― 接線が 2 本になる

ジャイロ項ほど劇的ではないが、**3D 化で必ず対処が要る箇所がもう一つある。摩擦である。**

2D では接線方向が 1 本しかなく、上限は区間 `[-μj_n, +μj_n]` だった（第 36.4 節）。**3D の接平面は 2 次元なので、摩擦力積の向きは円の内側のどこでもよい。**

```
|j_t| ≤ μ j_n          （j_t は 2 次元ベクトル）
```

**この「円へのクランプ」は、そのまま実装できる。**

```cpp
// 接平面の正規直交基底（第 24.4 節の build_basis）
Vec3 t1{}, t2{};
build_basis(contact.normal, t1, t2);

// 2 方向ぶんの力積を、まとめて円にクランプする
Vec2 accum{p.tangent_impulse1, p.tangent_impulse2};
accum += Vec2{delta1, delta2};

const float limit = friction * p.normal_impulse;
if (length_squared(accum) > limit * limit) accum *= limit / length(accum);
```

**円へのクランプは、正方形へのクランプ（`|j_t1| ≤ μj_n` と `|j_t2| ≤ μj_n` を別々に）より正しい。** 正方形だと対角方向で摩擦が `√2` 倍強くなり、**斜めに滑らせたときだけ止まりやすい**という不自然な挙動が出る。

**円へのクランプの計算量はほとんど変わらない**（平方根が 1 回増えるだけで、しかもクランプが必要なときだけ）。**正方形近似を選ぶ理由は、あまりない。**

> **接線基底の選び方が挙動に影響する**
> `build_basis`（第 24.4 節）は「最も小さい成分の座標軸」を選んで基底を作る。**法線がわずかに動くと、選ばれる軸が切り替わることがある。**
>
> 切り替わると `t1`, `t2` が別の向きになり、**前フレームの `tangent_impulse1/2` の意味が変わる。** ウォームスタート（第 37.2 節）が壊れる。
>
> 対策は、**前フレームの `t1` を法線に投影し直して使い回す**ことである。法線が大きく変わったときだけ作り直す。第 33.4 節の特徴 ID による対応づけと同じ問題意識——**フレームをまたいで意味が保たれる量を選ぶ**——がここでも出てくる。

## 39.4 本書で扱わなかったものへの地図

ここまでで、2D の完全な衝突判定・応答と、3D の判定、3D 剛体の基礎が揃った。**その先に何があるかを、簡単に地図として示しておく。**

### 関節拘束（ジョイント）

接触は「押すだけ・引っ張らない」という**不等式拘束**だった。関節は「常にこの距離を保つ」という**等式拘束**である。

**第 37 章のソルバは、ほとんどそのまま使える。** 変わるのは二点だけである。

| | 接触 | 関節 |
|---|---|---|
| 力積のクランプ | `max(0, ...)` | **なし**（両方向に効く） |
| ヤコビアン | 法線 1 方向 | 拘束の種類ごとに定義 |

**回転関節（ヒンジ）、距離拘束（ロープ）、モーター、角度制限**——どれも「ヤコビアンを定義して、実効質量を計算し、力積をクランプする」という同じ枠に収まる。**第 37.1 節の `solve_one` を一般化すれば届く。**

### TGS ソルバ

本書の逐次力積法は、**速度を解いてから位置を積分する**（Soft-Step、あるいは PGS）。

**TGS（Temporal Gauss-Seidel）は、反復のたびに位置も少しずつ進める。** 接触点の位置が反復中に更新されるので、**大きく回転する物体や、長い連鎖でずっと安定する。**

近年の主要な物理エンジンはこちらへ移行している。**第 37 章の構造を持っていれば、移行は反復ループの中に位置積分を挟むだけである。**

### 連続衝突検出の本格化

第 17・18 章でスイープと TOI を扱ったが、**回転を含む CCD**は扱わなかった。回転しながら移動する物体の最初の接触時刻を求めるのは、保守的前進（conservative advancement）を使っても難しい。

**実務では「並進のみの CCD ＋ 十分小さい `dt`」で妥協することが多い。** 弾丸のような高速物体だけを対象にし、それ以外は無効にする。

### ソフトボディ・布・流体

剛体は「変形しない」という強い仮定の上に立っている。**それを外すと、まったく別の世界が広がる。**

- **質点ばね系**：もっとも素朴。布・ロープに使える
- **位置ベース動力学（PBD/XPBD）**：速度ではなく位置を直接拘束する。安定していて実装が易しい
- **有限要素法（FEM）**：正確だが重い
- **SPH・格子法**：流体

**PBD は本書の位置補正（第 34 章）の延長線上にある。** 「めり込みを直す」を一般の拘束へ拡張したもの、と理解すると入りやすい。

### GPU 化と並列化

本書のコードはすべて単一スレッドである。

**並列化しやすいのはブロードフェーズ（第 VI 部）である。** グリッドへの登録、木のクエリ、SAP のソート——どれも独立性が高い。

**ソルバは難しい。** Gauss-Seidel は逐次性が本質だからである。並列化するには、**接触を「同時に解いても干渉しない集合」に色分けする**（グラフ彩色）か、Jacobi 法へ寄せて反復回数を増やすことになる。第 34.2 節で見たトレードオフが、そのまま並列化の設計判断になる。

### 決定論とネットワーク

第 41.3 節で扱うが、**クロスプラットフォームの決定論が要るなら、`/fp:fast` は使えない。** 本書の前提そのものが変わる。

固定小数点演算に切り替えるか、ソフトウェア浮動小数点を使うか。**どちらも本書の 43 章分の実装を書き直すことになる。** ロックステップ通信対戦を作るつもりなら、**最初に決めるべき判断である。**

## この章のまとめ

- 3D の慣性は**テンソル**（3×3 対称行列）になる。主軸が座標軸なら対角行列
- 直方体は `m(h²+d²)/12` など。**細長い棒は長軸まわりが最小**
- ワールド座標へは `R I Rᵀ`。**直交行列なので逆行列が要らない**（第 24.3 節）
- 姿勢はクォータニオンで積分し、**毎フレーム正規化する。** `Mat3` の直交化より安い
- **判定には `Mat3`、積分には `Quat`。** 用途で表現を選ぶ
- 3D で保存するのは**角運動量 `L = Iω`** であって角速度ではない
- ジャイロ項 `-ω × (Iω)` は 2D に存在しない。**主軸まわりの回転ではゼロ**
- **中間慣性軸まわりの回転だけが不安定**（中間軸定理／テニスラケットの定理）。実測で 20 秒に 2 回反転
- **陽的積分は発散する。** 50 秒でエネルギー 3.04 倍（60 fps）、49.2 倍（30 fps）
- `dt` を半分にしても 1.61 倍。**原理的に解決しない**
- **多くのエンジンはジャイロ項を落とす。** 発散する近似より保存する近似のほうが安全
- 必要な物体だけ限定的に、部分陰的な扱いで有効にする
- **3D の摩擦は接線が 2 本になる。** 上限は円で、正方形近似は対角方向で `√2` 倍強くなる
- 接線基底が切り替わるとウォームスタートが壊れる。**前フレームの `t1` を投影して使い回す**
- 関節拘束は**クランプを外すだけ**で第 37 章のソルバに乗る
- TGS は反復中に位置も進める。**近年の主流**で、移行は反復ループへの追加だけ
- PBD は第 34 章の位置補正の延長線上にある
- 並列化しやすいのはブロードフェーズ。**ソルバは Gauss-Seidel の逐次性が壁**
- クロスプラットフォーム決定論が要るなら **`/fp:fast` は使えない。最初に決める判断**

### 落とし穴と練習問題

**落とし穴 1：クォータニオンを正規化しない。**　姿勢に拡大縮小が混ざり、形状が歪む。

**落とし穴 2：慣性テンソルをローカルのまま使う。**　物体が回転すると回しにくさが合わなくなる。

**落とし穴 3：ジャイロ項を陽的に入れて放置する。**　数十秒後に物体が高速回転を始める。

**落とし穴 4：3D でも角速度が保存すると思い込む。**　保存するのは角運動量である。

**落とし穴 5：摩擦を 2 方向それぞれ独立にクランプする。**　対角方向の摩擦が `√2` 倍強くなり、斜めに滑らせたときだけ止まりやすくなる。

**落とし穴 6：接線基底を毎フレーム作り直す。**　`build_basis` の選ぶ軸が切り替わると、ウォームスタートで引き継いだ力積の意味が変わる。

**落とし穴 7：慣性テンソルの式を検算しない。**　長い式は必ず間違える。極限（`h → 0` で球、`r → 0` で棒）で既知の値に一致するかを確かめる。

## 第 VII 部を終えて

第 34 章で「めり込みを押し戻す」だけの応答から始め、第 39 章で 3D 剛体の限界まで来た。

**この部を通じて繰り返し現れた構造が三つある。**

**一つ目は「累積を持ち、クランプし、差分を適用する」。** 摩擦（第 36.4 節）でも法線力積（第 37.1 節）でも同じ形が出た。この形があるからウォームスタート（第 37.2 節）が成立し、めり込みが 4.6 分の 1 になった。

**二つ目は「押し出しすぎると接触が消える」。** 第 34.3 節のジッタ、第 37.3 節の `beta`、そして第 38.2 節の `skin_width`（こちらは逆向きだが同じ問題意識）。**接触の連続性を保つことが、安定性の鍵だった。**

**三つ目は「正しさより予測可能性」。** `slop`、コヨーテタイム、ジャイロ項の切り捨て——どれも物理的には嘘である。**それでも、発散する正確な近似より、安定する不正確な近似のほうがゲームには向いている。**

次の第 VIII 部は仕上げである。第 40 章で本書の全テストを分類し直し、`/fp:fast` の下で品質を守る戦略として整理する。**許容誤差の一覧表と、`precise` 領域の棚卸し**——ここまで各章で個別に決めてきた判断を、1 箇所にまとめる。
