# 第 24 章　3D の数学

> **この章のゴール**
> 3 次元へ進む準備をする。`Vec3` と外積、スカラー三重積、回転の表現。そして「2D のコードをどこまで共通化すべきか」という設計上の判断。
>
> **多くは次元が増えるだけである。** 内積の意味も、正規化のガードも、単位系から決めた閾値も、そのまま通用する。だが二つだけ、本質的に新しいものがある。**外積がスカラーではなくベクトルになること**と、**回転が 1 本の軸から導出できなくなること**である。この二つが、以降の章の難所すべての源になる。

## 24.1 `Vec3` と外積

### 型

```cpp
// collision/math/vec3.h
#pragma once

#include "collision/math/vec2.h"

namespace collision {

struct Vec3 {
    float x{};
    float y{};
    float z{};

    constexpr Vec3& operator+=(Vec3 r) noexcept { x += r.x; y += r.y; z += r.z; return *this; }
    constexpr Vec3& operator-=(Vec3 r) noexcept { x -= r.x; y -= r.y; z -= r.z; return *this; }
    constexpr Vec3& operator*=(float s) noexcept { x *= s; y *= s; z *= s; return *this; }
    constexpr Vec3& operator/=(float s) noexcept { x /= s; y /= s; z /= s; return *this; }

    [[nodiscard]] friend constexpr bool operator==(Vec3, Vec3) noexcept = default;
};

} // namespace collision
```

第 6 章の `Vec2` と同じ方針である。集成体、メンバ初期化子でゼロ初期化、複合代入だけメンバ関数。

**サイズは 12 バイトになる。** 第 6.1 節で「16 バイトまでは値渡し」と決めたので、`Vec3` も値渡しする。

> **なぜ 16 バイトに揃えないのか**
> SIMD を意識するなら、パディングを入れて 16 バイトにする設計もある（`float w` を足す）。そのほうが `_mm_load_ps` でアラインしたロードができる。
>
> 本書では 12 バイトのままにする。メモリ使用量が 33% 増えるのは、大量の頂点を扱うメッシュ（第 27 章）で効いてくるからである。SIMD 化は第 42 章で、必要になった箇所だけ専用のレイアウトを用意する形で扱う。

### 外積がベクトルになる

2D の外積（第 6.6 節）はスカラーだった。3D では**ベクトル**を返す。

```cpp
[[nodiscard]] constexpr Vec3 cross(Vec3 a, Vec3 b) noexcept {
    return Vec3{
        a.y * b.z - a.z * b.y,
        a.z * b.x - a.x * b.z,
        a.x * b.y - a.y * b.x,
    };
}
```

意味は三つある。2D のときと対応させて覚えるとよい。

| 意味 | 2D（スカラー） | 3D（ベクトル） |
|---|---|---|
| 大きさ | 平行四辺形の**符号付き面積** | 平行四辺形の**面積**（絶対値） |
| 向き | 符号が回転の向き | **両方に垂直な向き**（右手系） |
| ゼロになる条件 | 平行または反平行 | 平行または反平行 |

**「両方に垂直な向きが得られる」ことが、3D の外積の最も重要な性質である。** 2D では「平面に垂直な方向」が一つしかなかったので、この情報は符号だけで足りた。3D では方向そのものが意味を持つ。

三角形の法線が外積で求まるのは、この性質による。

```cpp
// 三角形 abc の法線（正規化されていない）。右手系で反時計回りに見える側を向く
[[nodiscard]] constexpr Vec3 triangle_normal_raw(Vec3 a, Vec3 b, Vec3 c) noexcept {
    return cross(b - a, c - a);
}
```

### 右手系を採用する

第 1.4 節で「3D では右手系、Y が上」と決めた。改めて確認しておく。

**右手系とは、`cross(X軸, Y軸) = Z軸` が成り立つ座標系である。**

```cpp
static_assert(cross(Vec3{1,0,0}, Vec3{0,1,0}) == Vec3{0,0,1});
static_assert(cross(Vec3{0,1,0}, Vec3{0,0,1}) == Vec3{1,0,0});
static_assert(cross(Vec3{0,0,1}, Vec3{1,0,0}) == Vec3{0,1,0});
```

`static_assert` で書けるのは、これらの値が `float` で正確に表現できるからである（第 6.8 節）。

**座標系の規約を間違えると、法線がすべて裏返る。** そして SAT では症状が出ない（第 13 章の巻き方向と同じ事情）。第 27 章のメッシュ判定で初めて破綻する。ここで固めておく。

### 2D と共通のもの

内積、長さ、正規化は、成分が一つ増えるだけである。

```cpp
[[nodiscard]] constexpr float dot(Vec3 a, Vec3 b) noexcept {
    return a.x * b.x + a.y * b.y + a.z * b.z;
}

[[nodiscard]] constexpr float length_squared(Vec3 v) noexcept { return dot(v, v); }
[[nodiscard]] inline    float length(Vec3 v) noexcept { return std::sqrt(dot(v, v)); }

[[nodiscard]] inline std::optional<Vec3> try_normalize(Vec3 v) noexcept {
    const float len2 = length_squared(v);
    if (len2 < min_length2) return std::nullopt;    // 第 5.9 節の閾値をそのまま使う
    return v / std::sqrt(len2);
}

[[nodiscard]] inline Vec3 normalize_or(Vec3 v, Vec3 fallback) noexcept {
    return try_normalize(v).value_or(fallback);
}
```

**`min_length2` がそのまま使える。** 第 5.9 節で単位系から決めた値（0.1 ミリメートルの二乗）は、次元に依存しない。1 単位 = 1 メートルという約束は 3D でも同じである。

第 0 部で単位系を明文化しておいた見返りが、ここでも出ている。

## 24.2 スカラー三重積

### 定義と意味

```cpp
// a · (b × c)
[[nodiscard]] constexpr float scalar_triple(Vec3 a, Vec3 b, Vec3 c) noexcept {
    return dot(a, cross(b, c));
}
```

**絶対値は、3 ベクトルが張る平行六面体の体積である。** 2D の外積が面積だったことの、そのままの拡張になっている。

**符号は向きを表す。** 正なら `a, b, c` が右手系の順、負なら左手系の順である。

四面体の符号付き体積は、これの 1/6 になる。

```cpp
[[nodiscard]] constexpr float signed_volume(Vec3 a, Vec3 b, Vec3 c, Vec3 d) noexcept {
    return scalar_triple(b - a, c - a, d - a) / 6.0f;
}
```

### 使い道

**1. 点が平面のどちら側にあるか。** 第 6.6 節で 2D の外積を「点が直線のどちら側か」に使ったのと同じ構造である。

```cpp
// 点 p が、三角形 abc の作る平面のどちら側にあるか（正なら法線側）
[[nodiscard]] constexpr float
plane_side(Vec3 p, Vec3 a, Vec3 b, Vec3 c) noexcept {
    return scalar_triple(p - a, b - a, c - a);
}
```

**2. 四面体の内外判定。** 4 つの面それぞれについて符号を調べ、すべて同じ側なら内部である。第 9.3 節の三角形の内外判定を、次元を上げただけの形になる。

**3. GJK の四面体シンプレックス。** 第 28 章で、原点が四面体のどの領域にあるかを判定するのに使う。

### 便利な恒等式

三重積には有用な恒等式がある。第 20.3 節で触れた**ベクトル三重積**である。

```
(a × b) × c = b·(a·c) − a·(b·c)
```

```cpp
// (a × b) × c を、外積を使わずに計算する
[[nodiscard]] constexpr Vec3 triple_product(Vec3 a, Vec3 b, Vec3 c) noexcept {
    return b * dot(a, c) - a * dot(b, c);
}
```

**これが GJK の 3D 化で必要になる。** 2D では `perpendicular` と符号調整で済んでいた「線分に垂直で原点を向く方向」が、3D では `triple_product(ab, ao, ab)` になる。

`cross(cross(a,b), c)` と書いても同じ結果だが、こちらのほうが演算数が少ない（外積 2 回に対し、内積 2 回とスカラー倍 2 回）。

第 20.3 節で「3D では三重積が要る」と予告したのは、この形のことである。

## 24.3 回転の表現

### 2D の手が使えなくなる

第 12.1 節で、2D の OBB は「軸を 1 本だけ持ち、もう 1 本は `perpendicular` で導出する」設計にした。直交性が誤差なしで保たれる、という利点があった。

**3D ではこの手が使えない。** 3 本の軸が必要で、1 本から他の 2 本を一意に決めることはできない（軸のまわりの回転が自由に残る）。

したがって、回転を明示的に表現する必要がある。選択肢は二つある。

### 回転行列

3×3 の直交行列で表す。本書では**行を 3 本の軸ベクトルとする**形を採る。

```cpp
// collision/math/mat3.h
#pragma once

#include "collision/math/vec3.h"

namespace collision {

// 回転行列。3 本の正規直交な軸を保持する。
// col[i] が、ローカル座標系の i 番目の軸のワールド表現。
struct Mat3 {
    Vec3 col[3]{Vec3{1,0,0}, Vec3{0,1,0}, Vec3{0,0,1}};
};

// ローカル → ワールド
[[nodiscard]] constexpr Vec3 rotate(const Mat3& m, Vec3 v) noexcept {
    return m.col[0] * v.x + m.col[1] * v.y + m.col[2] * v.z;
}

// ワールド → ローカル（直交行列なので転置が逆行列）
[[nodiscard]] constexpr Vec3 inverse_rotate(const Mat3& m, Vec3 v) noexcept {
    return Vec3{dot(v, m.col[0]), dot(v, m.col[1]), dot(v, m.col[2])};
}

} // namespace collision
```

**逆回転が転置で済む**のが、直交行列の最大の利点である。行列式を計算する必要がない。第 19.4 節で 2D の `inverse_rotate` が「`sin` の符号反転」だったのと、同じ事情である。

**利点。** 変換の適用が速い。軸が直接読み取れるので、SAT（第 26 章）と相性がよい。

**欠点。** 9 個の `float` を持つのに自由度は 3 しかない。回転を重ねると直交性が崩れる。

### クォータニオン

4 成分で回転を表す。

```cpp
struct Quat {
    float x{}, y{}, z{}, w{1.0f};
};
```

**利点。** 4 成分で済む。補間（球面線形補間）が自然にできる。正規化するだけで有効な回転に戻せる。

**欠点。** 軸を取り出すのに変換が要る。直感的に読みにくい。

### 本書の方針

**衝突判定の内部では `Mat3` を使う。** 理由は三つある。

1. SAT が軸を直接必要とする（第 26 章）
2. サポート写像も軸ごとの内積で書ける（第 28.3 節）
3. 判定中に回転を補間することはない

**剛体シミュレーション（第 39 章）では、クォータニオンを検討する余地がある。** 角速度による積分を繰り返すと直交性が崩れやすく、クォータニオンなら正規化一回で復元できるからである。

本書は 3D の剛体を深く扱わないので、`Mat3` で統一する。**用途によって表現を選ぶ**という判断があることだけ、意識しておいてほしい。

### 直交性の維持

回転を重ねると、`Mat3` の 3 軸は徐々に直交でなくなる。第 12.1 節で 2D の `axis_x` を毎回正規化したのと同じ問題だが、3D では正規化だけでは足りない。

**グラム・シュミットの直交化**を使う。

```cpp
// 直交性を回復する。col[0] を基準に、他を直交化する。
[[nodiscard]] inline Mat3 orthonormalized(const Mat3& m) noexcept {
    Mat3 r{};
    r.col[0] = normalize_or(m.col[0], Vec3{1,0,0});

    // col[1] から col[0] 成分を取り除く
    Vec3 c1 = m.col[1] - r.col[0] * dot(m.col[1], r.col[0]);
    r.col[1] = normalize_or(c1, Vec3{0,1,0});

    // col[2] は外積で作れば、必ず両方に直交する
    r.col[2] = cross(r.col[0], r.col[1]);
    return r;
}
```

**3 本目を外積で作っている**のが要点である。グラム・シュミットを 3 回繰り返すより速く、しかも**直交性が厳密に保たれる**（外積の定義から、両方に垂直であることが保証される）。

残る誤差は「`col[2]` の長さが 1 からわずかにずれる」ことだけだが、`col[0]` と `col[1]` が単位長で直交していれば、外積の長さも 1 になる。

## 24.4 正規直交基底を作る

### ある向きから基底を作る

法線 `n` が与えられたとき、それを 3 本目の軸とする正規直交基底を作りたい場面がある。摩擦の接線方向（第 39 章）や、平面上のローカル座標が必要なときである。

素朴にやるなら「`n` と平行でない適当なベクトルとの外積」を使う。

```cpp
// 素朴な実装。n がたまたま基準ベクトルと平行だと破綻する
Vec3 t = cross(n, Vec3{0,1,0});   // n が (0,±1,0) だとゼロベクトル
```

**分岐で回避する。** 最も成分の小さい座標軸を選べば、必ず平行にならない。

```cpp
// n（単位ベクトル）に垂直な正規直交基底 (t1, t2) を作る
inline void build_basis(Vec3 n, Vec3& t1, Vec3& t2) noexcept {
    // n の成分のうち最も小さいものに対応する座標軸を選ぶ
    const float ax = std::fabs(n.x), ay = std::fabs(n.y), az = std::fabs(n.z);
    const Vec3 pick = (ax <= ay && ax <= az) ? Vec3{1,0,0}
                    : (ay <= az)             ? Vec3{0,1,0}
                                             : Vec3{0,0,1};

    t1 = normalize_or(cross(n, pick), Vec3{1,0,0});
    t2 = cross(n, t1);     // 外積なので必ず直交かつ単位長
}
```

**「最も小さい成分」を選ぶ理由。** `n` がその座標軸と平行になることはない（もし平行なら、その成分が最大になるはずである）。外積の長さは `sin` に比例するので、なるべく直交に近い組み合わせを選ぶほうが精度もよい。

分岐のないやり方（Duff らの手法など）も知られているが、本書では読みやすさを優先する。

### テストで直交性を守る

```cpp
// test_vec3.cpp
TEST_CLASS(OrthonormalBasis) {
public:
    TEST_METHOD(任意の法線から正しい基底が作れること) {
        Rng rng(1800);
        for (int i = 0; i < 50000; ++i) {
            const auto n = collision::try_normalize(Vec3{
                rng.uniform(-1.0f, 1.0f), rng.uniform(-1.0f, 1.0f), rng.uniform(-1.0f, 1.0f)});
            if (!n) continue;

            Vec3 t1{}, t2{};
            collision::build_basis(*n, t1, t2);

            expect_near(1.0f, collision::length(t1), 1.0e-4f, 1.0e-4f);
            expect_near(1.0f, collision::length(t2), 1.0e-4f, 1.0e-4f);
            expect_near(0.0f, collision::dot(*n, t1), 1.0e-4f, 1.0e-4f);
            expect_near(0.0f, collision::dot(*n, t2), 1.0e-4f, 1.0e-4f);
            expect_near(0.0f, collision::dot(t1,  t2), 1.0e-4f, 1.0e-4f);
        }
    }

    TEST_METHOD(座標軸に平行な法線でも破綻しないこと) {
        // 素朴な実装が壊れるケース
        for (const Vec3 n : {Vec3{1,0,0}, Vec3{-1,0,0}, Vec3{0,1,0},
                             Vec3{0,-1,0}, Vec3{0,0,1}, Vec3{0,0,-1}}) {
            Vec3 t1{}, t2{};
            collision::build_basis(n, t1, t2);
            expect_near(1.0f, collision::length(t1), 1.0e-5f, 1.0e-5f);
            expect_near(0.0f, collision::dot(n, t1), 1.0e-5f, 1.0e-5f);
        }
    }

    TEST_METHOD(回転を繰り返しても直交性が保たれること) {
        // 24.3 節の orthonormalized の検証
        collision::Mat3 m{};
        Rng rng(1801);

        for (int i = 0; i < 100000; ++i) {
            // わずかに回転させて崩す
            const float d = 0.01f;
            m.col[0] += Vec3{0.0f, d, 0.0f} * 0.001f;
            m.col[1] += Vec3{d, 0.0f, 0.0f} * 0.001f;
            m = collision::orthonormalized(m);
        }

        expect_near(1.0f, collision::length(m.col[0]), 1.0e-4f, 1.0e-4f);
        expect_near(1.0f, collision::length(m.col[1]), 1.0e-4f, 1.0e-4f);
        expect_near(1.0f, collision::length(m.col[2]), 1.0e-4f, 1.0e-4f);
        expect_near(0.0f, collision::dot(m.col[0], m.col[1]), 1.0e-4f, 1.0e-4f);
        expect_near(0.0f, collision::dot(m.col[1], m.col[2]), 1.0e-4f, 1.0e-4f);
        expect_near(0.0f, collision::dot(m.col[2], m.col[0]), 1.0e-4f, 1.0e-4f);
    }

    TEST_METHOD(逆回転が回転を打ち消すこと) {
        Rng rng(1802);
        for (int i = 0; i < 20000; ++i) {
            collision::Mat3 m{};
            const auto n = collision::try_normalize(Vec3{
                rng.uniform(-1.0f, 1.0f), rng.uniform(-1.0f, 1.0f), rng.uniform(-1.0f, 1.0f)});
            if (!n) continue;
            Vec3 t1{}, t2{};
            collision::build_basis(*n, t1, t2);
            m.col[0] = t1; m.col[1] = t2; m.col[2] = *n;

            const Vec3 v{rng.uniform(-5.0f, 5.0f), rng.uniform(-5.0f, 5.0f),
                         rng.uniform(-5.0f, 5.0f)};
            expect_near(v, collision::inverse_rotate(m, collision::rotate(m, v)),
                        1.0e-4f, 1.0e-4f);
        }
    }
};
```

### 2D から 3D へ ― 何が変わり、何が変わらないか

第 V 部を読み進めるうえでの見取り図として、変化を一覧にしておく。

| 項目 | 2D | 3D | 章 |
|---|---|---|---|
| 内積 | 2 項 | 3 項 | この章 |
| 外積 | **スカラー**（面積と向き） | **ベクトル**（両方に垂直） | この章 |
| 「垂直な方向」 | `perpendicular` で一意 | 無限にある。`build_basis` で選ぶ | この章 |
| 回転 | 軸 1 本で表せる | 3 軸または四元数が要る | この章 |
| 最近接点の最難問 | 点と線分 | **線分と線分** | 第 25 章 |
| SAT の軸 | 辺の法線のみ | 面法線 ＋ **辺の外積** | 第 26 章 |
| 地形の表現 | 線分・凸多角形 | **三角形メッシュ** | 第 27 章 |
| GJK の単体 | 三角形まで | **四面体**まで | 第 28 章 |
| EPA のポリトープ | 頂点列 | **面のリスト** | 第 28 章 |
| マニフォールドの点数 | 最大 2 | 4 以上 | 第 27 章 |

**太字が、本質的に新しいものである。** それ以外は「項が増える」だけで、考え方は変わらない。

そして注目してほしいのは、**太字がすべて「外積がベクトルになった」ことの帰結である**という点である。

- 垂直な方向が一意に決まらない → `build_basis` が要る
- 回転が 1 軸で表せない → `Mat3` が要る
- 線分がねじれの位置を取れる → 線分間最近接点が要る
- 辺どうしがすれ違う → 辺の外積が分離軸になりうる
- 単体が一次元増える → 四面体
- ポリトープの境界が二次元になる → 面のリスト

**24.1 節で「外積がベクトルになる」ことを最重要と述べたのは、この波及の大きさによる。**

### 演算コストの比較

3D になると、単純に計算量が増える。目安を出しておく。

| 演算 | 2D | 3D | 比 |
|---|---|---|---|
| 内積 | 乗算 2、加算 1 | 乗算 3、加算 2 | 1.5 倍 |
| 外積 | 乗算 2、減算 1 | 乗算 6、減算 3 | 3 倍 |
| 正規化 | 内積 ＋ 平方根 ＋ 乗算 2 | 内積 ＋ 平方根 ＋ 乗算 3 | 1.3 倍 |
| OBB の投影半径 | 内積 2 | 内積 3 | 1.5 倍 |
| OBB vs OBB の SAT | 4 軸 | **15 軸** | 3.75 倍 |
| GJK 1 反復 | サポート写像 2 回 | サポート写像 2 回 | ほぼ同じ |

**SAT の軸数が最も大きく増える。** 一方 GJK は、1 反復あたりのコストがほとんど変わらない。反復回数も、次元が上がってもそれほど増えない（実測で 2D の 4〜5 回に対し 3D は 5〜7 回程度）。

**この差が、3D で GJK の相対的な優位を高めている。** 2D では「多角形どうしなら SAT が素直」だったが、3D では凸多面体の面数が増えると SAT の軸数が急増する（面法線 `n + m` ＋ 辺の外積 `n × m`）。GJK のほうが有利になる場面が広がる。

## 24.5 2D のコードをどこまで共通化すべきか

### 誘惑

`Vec2` と `Vec3` はよく似ている。テンプレートで一つにまとめたくなる。

```cpp
// 誘惑：次元をテンプレート引数にする
template <int N>
struct Vector {
    std::array<float, N> e{};
};

template <int N>
constexpr float dot(const Vector<N>& a, const Vector<N>& b) noexcept {
    float s = 0.0f;
    for (int i = 0; i < N; ++i) s += a.e[i] * b.e[i];
    return s;
}
```

コードの重複は減る。**だが本書はこれを採らない。**

### 採らない理由

**1. 外積が共通化できない。** 2D の `cross` はスカラーを返し、3D の `cross` はベクトルを返す。戻り値の型が違うので、同じテンプレートには収まらない。特殊化で分けることはできるが、それは共通化していないのと同じである。

そして外積は、コリジョンで最も頻繁に使う演算の一つである。**共通化できない部分が本質的に大きい。**

**2. `.x` `.y` `.z` でアクセスできなくなる。** `v.e[0]` と書くコードは読みにくい。`operator[]` を用意しても同じである。座標を名前で呼べることの価値は、思うより大きい。

**3. アルゴリズムのほうが共通化できない。** これが最大の理由である。

- SAT：2D は辺の法線だけ、3D は面法線＋辺の外積（第 26 章）
- 最近接点：2D は点と線分、3D は線分と線分（第 25 章）
- マニフォールド：2D は最大 2 点、3D は 4 点以上（第 27 章）
- GJK の単体：2D は三角形まで、3D は四面体まで（第 28 章）

**型を共通化しても、アルゴリズムは別々に書くことになる。** 得られるものが少ない。

### 本書の方針

**`Vec2` と `Vec3` は独立した型として書く。** 名前と意味を揃えることで、読者の学習コストを下げる。

| 2D | 3D | 関係 |
|---|---|---|
| `dot` | `dot` | 成分が一つ増えるだけ |
| `length`, `try_normalize` | 同名 | 同上 |
| `cross(Vec2, Vec2) -> float` | `cross(Vec3, Vec3) -> Vec3` | **意味が違う** |
| `perpendicular` | なし（`build_basis` で代替） | 3D には対応物がない |
| `min_length2` | 共通 | 単位系は次元に依存しない |

**同じ名前のものは同じ意味、違うものは違う名前。** これが「共通化」より価値のある一貫性である。

### 共通化してよいもの

一方、**次元に依存しない部分は共通化する**。

- 単位系の定数（`min_length`、`contact_slop` など、第 5.9 節）
- ビットパターン検査（`is_finite_bits`、第 4.5 節）
- 許容誤差の設計（`nearly_equal`、第 3.4 節）
- テストヘルパの構造

これらは第 0 部で作ったものである。**次元に依存しない設計になっていたおかげで、書き直しが不要になった。**

### 過度な抽象化への戒め

一般論として、**「似ている」ことと「同じである」ことは違う**。

`Vec2` と `Vec3` は似ているが、外積の意味が違う。第 9 章の `HasClosestPoint`、第 11 章の `SatShape`、第 19 章の `SupportShape` を別々のコンセプトにしたのも、同じ判断である。要求が違うものを無理に一つにすると、どちらにとっても使いにくい抽象になる。

**抽象化は、共通の性質が本当にあるときにだけ行う。** 見た目が似ているだけでは足りない。

## この章のまとめ

- `Vec3` は 12 バイト。`Vec2` と同じ設計方針（集成体・ゼロ初期化・値渡し）
- **3D の外積はベクトルを返す。「両方に垂直な向き」が得られることが最重要**
- 右手系を採用する。`cross(X, Y) = Z` を `static_assert` で固める
- `min_length2` などの単位系の定数は、次元に依存せずそのまま使える
- **スカラー三重積**は平行六面体の体積。符号が向きを表す。平面の側の判定に使う
- **ベクトル三重積 `(a×b)×c = b(a·c) − a(b·c)`** が GJK の 3D 化で必要になる
- 回転は `Mat3`（3 本の正規直交軸）で表す。逆回転は転置で済む
- 直交性の回復はグラム・シュミット。**3 本目は外積で作れば厳密に直交する**
- `build_basis` は「最も小さい成分の座標軸」を選んで平行を避ける
- **`Vec2` と `Vec3` はテンプレートで共通化しない。** 外積の意味が違い、アルゴリズムも別々になる
- 同じ名前のものは同じ意味、違うものは違う名前

### 落とし穴と練習問題

**落とし穴 1：座標系の左右。**　右手系と左手系を取り違えると法線がすべて裏返る。SAT では症状が出ず、第 27 章のメッシュで破綻する。

**落とし穴 2：`build_basis` の素朴な実装。**　固定の基準ベクトルを使うと、法線がそれと平行なときゼロ除算になる。

**落とし穴 3：回転を重ねて直交性が崩れる。**　`orthonormalized` を定期的に呼ぶ。

**練習問題 24-1**　`cross(a, b)` の各成分を導出してみよう。行列式の展開として覚えるより、「`a` と `b` の両方に垂直で、長さが平行四辺形の面積になるベクトル」という条件から導くほうが記憶に残る。
