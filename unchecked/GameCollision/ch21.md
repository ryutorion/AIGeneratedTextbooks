# 第 21 章　GJK ― 距離と最近接点

> **この章のゴール**
> 交差していない二つの凸形状について、**最短距離**と、**両形状上のどこが最も近いか**を求める。
>
> 前章の GJK は「交差しているか」だけを返した。単体の育て方をわずかに変えると、同じサポート写像だけで距離が求まる。そして第 19.3 節で `MinkowskiPoint` に `on_a` / `on_b` を持たせておいた理由が、ここで明らかになる。
>
> 第 18 章の保守的前進が要求していた `distance_between` が、この章で任意の凸形状に対して実装される。**第 III 部で残した宿題が片付く。**

---

## 21.1 距離を求める GJK

### 何が変わるのか

前章の GJK は、「原点を囲めるか」を調べていた。囲めれば交差、囲めなければ分離。それだけである。

距離を求める版では、**単体上で原点に最も近い点を追跡する**。

```
1. 単体を一点から始める
2. 繰り返す：
     v = 単体上で原点に最も近い点
     もし |v| がほぼゼロなら → 交差している
     d = -v （原点へ向かう向き）
     w = support(A⊖B, d)
     もし w がこれ以上 v を改善しないなら → 収束。距離は |v|
     w を単体に加え、原点に最も近い部分だけを残す
```

前章との違いは二つである。

**1. 単体上の最近接点 `v` を明示的に計算する。** 前章では「どの領域にあるか」だけを判定していたが、ここでは実際の点を求める。

**2. 終了条件が「改善しなくなったか」になる。** 前章は「分離軸が見つかったか」で止まったが、ここでは距離が確定するまで詰める。

### 収束判定

これが distance GJK の核心である。

現在の最近接点を `v` とする。真の最短距離を `dist` とすると、次の不等式が成り立つ。

```
dot(v, v̂) ≥ dist ≥ dot(w, v̂)      （v̂ = v / |v|）
```

左側は自明である（`|v|` は単体上の点までの距離なので、最短距離以上）。

右側が重要である。`w = support(A⊖B, -v)` は `-v` 方向の最遠点であり、`dot(w, v̂)` はミンコフスキー差全体が原点から離れている距離の**下界**を与える。

したがって、**`|v|` と `dot(w, v̂)` の差が小さくなれば、`|v|` は真の距離に十分近い**。

```
|v|² - dot(v, w) ≤ tol · |v|²
```

両辺を `|v|` で割ると `|v| - dot(w, v̂) ≤ tol · |v|` になる。**相対誤差での判定**である（第 4.3 節の方針に沿っている）。平方根を計算せずに済むよう、二乗のまま書く。

### 単体上の最近接点

単体は点・線分・三角形のいずれかである。それぞれで原点に最も近い点を求める。

**点の場合**は自明で、その点自身である。

**線分の場合**は、第 9.1 節の `closest_point_on_segment` がそのまま使える。原点を渡せばよい。

**三角形の場合**は、原点を含むなら距離ゼロ（交差している）。含まないなら、三辺のうち最も近い辺上の点である。第 9.3 節の三角形の最近接点と同じ構造である。

**距離 GJK では、三角形が原点を含んだ時点で「交差している」と分かって終了する。** そのため、三角形のまま反復を続けることはない。実質的に扱うのは点と線分だけである。

## 21.2 重心座標から最近接点を復元する

### 問題

距離だけなら `|v|` で足りる。だが実用では、**A 上のどこと B 上のどこが最も近いか**を知りたい。

- 引っ張り合う力を働かせる位置（バネ拘束）
- 最短距離を可視化する線分の端点
- 保守的前進で「どちらへ進めば近づくか」（第 23 章）

### 鍵は重心座標

単体上の最近接点 `v` は、単体の頂点の**凸結合**として書ける。

```
v = λ₀·w₀ + λ₁·w₁     （λ₀ + λ₁ = 1、λᵢ ≥ 0）
```

`λ` が重心座標である（第 9.3 節）。線分なら二つ、三角形なら三つ。

そして、各 `wᵢ` は `MinkowskiPoint` であり、`wᵢ.diff = wᵢ.on_a - wᵢ.on_b` を満たしている。

**同じ重み `λ` を、元の形状上の点に適用すればよい。**

```
closest_on_a = λ₀·w₀.on_a + λ₁·w₁.on_a
closest_on_b = λ₀·w₀.on_b + λ₁·w₁.on_b
```

これが求める最近接点である。`closest_on_a - closest_on_b = v` が成り立つ（線形性から明らか）。

**第 19.3 節で `on_a` / `on_b` を保持しておいた理由が、ここで回収される。** 後から追加しようとすると、GJK の反復をやり直すことになる。最初から持たせておくのが正しい。

### 凸性が保証すること

`λᵢ ≥ 0` かつ `Σλᵢ = 1` なので、`closest_on_a` は `w₀.on_a` と `w₁.on_a` の凸結合である。両者は A 上の点なので、**A が凸であればその結合も A 上にある**。

凸でない形状にこの手法を使うと、復元した点が形状の外に出る。**GJK が凸形状専用である理由の一つ**である。

## 21.3 実装

### 単体の縮約と重心座標

```cpp
// collision/narrow/gjk_distance.h
#pragma once

#include "collision/narrow/gjk.h"

namespace collision {

namespace detail {

// 単体を、原点に最も近い部分だけに縮約する。
// 縮約後の頂点に対応する重み（重心座標）を weights に書き、
// 原点に最も近い点を返す。
[[nodiscard]] inline Vec2
reduce_simplex(Simplex& s, std::array<float, 3>& weights) noexcept {
    if (s.count == 1) {
        weights[0] = 1.0f;
        return s.point[0].diff;
    }

    if (s.count == 2) {
        const Vec2 a = s.point[0].diff;
        const Vec2 b = s.point[1].diff;
        const Vec2 ab = b - a;
        const float len2 = length_squared(ab);

        if (len2 < min_length2) {           // 二点がほぼ同じ位置
            s.count = 1;
            weights[0] = 1.0f;
            return a;
        }

        const float t = std::clamp(dot(-a, ab) / len2, 0.0f, 1.0f);

        if (t <= 0.0f) {                    // A 側の頂点が最近
            s.count = 1;
            weights[0] = 1.0f;
            return a;
        }
        if (t >= 1.0f) {                    // B 側の頂点が最近
            s.point[0] = s.point[1];
            s.count = 1;
            weights[0] = 1.0f;
            return b;
        }
        weights[0] = 1.0f - t;
        weights[1] = t;
        return a + ab * t;
    }

    // 三角形：三辺のうち原点に最も近いものを選ぶ。
    // （原点が内部にある場合は呼び出し側が先に検出している）
    float best_d2 = std::numeric_limits<float>::infinity();
    Vec2  best_p{};
    std::uint32_t bi = 0, bj = 1;
    float bw0 = 1.0f, bw1 = 0.0f;

    for (std::uint32_t k = 0; k < 3; ++k) {
        const std::uint32_t i = k, j = (k + 1) % 3;
        const Vec2 a = s.point[i].diff;
        const Vec2 ab = s.point[j].diff - a;
        const float len2 = length_squared(ab);
        if (len2 < min_length2) continue;

        const float t = std::clamp(dot(-a, ab) / len2, 0.0f, 1.0f);
        const Vec2  p = a + ab * t;
        const float d2 = length_squared(p);

        if (d2 < best_d2) {
            best_d2 = d2; best_p = p;
            bi = i; bj = j; bw0 = 1.0f - t; bw1 = t;
        }
    }

    const MinkowskiPoint p0 = s.point[bi];
    const MinkowskiPoint p1 = s.point[bj];
    s.point[0] = p0;
    s.point[1] = p1;
    s.count = 2;
    weights[0] = bw0;
    weights[1] = bw1;
    return best_p;
}

} // namespace detail
```

**縮約と重み計算を一つの関数にまとめている。** 分けると、どの頂点が残ったかと重みの対応がずれる危険がある。同じ場所で決めるほうが安全である。

線分の場合、`t` を `[0, 1]` にクランプしてから端点かどうかを判定している。第 9.1 節と同じ構造だが、**クランプ後に端点なら単体を 1 点に縮約する**点が違う。単体を小さく保つことで、次の反復での計算が減る。

### 本体

```cpp
// collision/narrow/gjk_distance.h（続き）

struct DistanceResult {
    float distance{};        // 最短距離（交差していれば 0）
    Vec2  closest_a{};       // A 上の最近接点
    Vec2  closest_b{};       // B 上の最近接点
    bool  intersecting{};    // 交差しているか
    bool  converged{true};   // 収束したか
    int   iterations{};
};

inline constexpr int gjk_distance_max_iterations = 32;

template <SupportShape A, SupportShape B>
[[nodiscard]] DistanceResult
gjk_distance(const A& a, const B& b, float tolerance = 1.0e-6f) noexcept {
    Vec2 d = support_point(b, Vec2{1.0f, 0.0f}) - support_point(a, Vec2{-1.0f, 0.0f});
    if (length_squared(d) < min_length2) d = Vec2{1.0f, 0.0f};

    Simplex s{};
    s.push(support_diff(a, b, -d));

    std::array<float, 3> w{1.0f, 0.0f, 0.0f};
    Vec2 v = s.point[0].diff;

    for (int iter = 0; iter < gjk_distance_max_iterations; ++iter) {
        v = detail::reduce_simplex(s, w);

        const float v2 = length_squared(v);
        if (v2 < min_length2) {
            // 原点が単体上に乗った → 交差している
            return DistanceResult{.distance = 0.0f, .intersecting = true,
                                  .iterations = iter};
        }

        const MinkowskiPoint p = support_diff(a, b, -v);

        // 収束判定（21.1 節）。相対誤差で見る
        if (detail::distance_converged(v2, dot(v, p.diff), tolerance)) {
            break;
        }
        if (detail::no_progress(s, p.diff)) {
            break;
        }
        if (s.count >= 3) {
            break;   // これ以上は増やせない（数値的な事故の安全弁）
        }
        s.push(p);
    }

    // 重心座標から元の形状上の点を復元する（21.2 節）
    Vec2 ca{}, cb{};
    for (std::uint32_t i = 0; i < s.count; ++i) {
        ca += s.point[i].on_a * w[i];
        cb += s.point[i].on_b * w[i];
    }

    return DistanceResult{
        .distance = std::sqrt(length_squared(v)),
        .closest_a = ca,
        .closest_b = cb,
        .intersecting = false,
        .converged = true,
        .iterations = 0,
    };
}
```

### 収束判定を `precise` で守る

前章 20.6 節と同じ判断である。

```cpp
namespace detail {

#pragma float_control(precise, on, push)

// 21.1 節の収束判定。相対誤差なので、値のスケールに依存しない。
// /fp:fast の下では境界付近で振動しうるため precise で守る（第 4.6 節）。
__declspec(noinline)
[[nodiscard]] inline bool
distance_converged(float v_len2, float v_dot_w, float tolerance) noexcept {
    return v_len2 - v_dot_w <= tolerance * v_len2;
}

#pragma float_control(pop)

} // namespace detail
```

`v_len2 - v_dot_w` は、収束していれば非常に小さい二つの値の差になる。**桁落ち（第 4.2 節）が起きる典型的な形である。** ここが `/fp:fast` の再結合で揺れると、収束したりしなかったりする。

### 手で追ってみる

二つの正方形の距離を、GJK で求める過程を追う。

**A**：`(0,0)`, `(2,0)`, `(2,2)`, `(0,2)`
**B**：`(5,0)`, `(7,0)`, `(7,2)`, `(5,2)`

真の距離は 3（A の右辺と B の左辺の間）である。

**初期化。** 初期方向を大雑把に「B から A へ」とすると `d ≈ (-1, 0)`。`support_diff(a, b, -d) = support_diff(a, b, (1,0))`。A の `(1,0)` 方向の最遠点は `(2,0)` または `(2,2)`、B の `(-1,0)` 方向の最遠点は `(5,0)` または `(5,2)`。実装は添字の小さいほうを選ぶので `(2,0) - (5,0) = (-3, 0)`。

単体は 1 点 `{(-3,0)}`。

**反復 1。** 縮約すると `v = (-3, 0)`、`|v|² = 9`。ゼロではないので続行。

`w = support_diff(a, b, -v)`。`-v = (3, 0)` は `(1,0)` 方向なので、また `(-3, 0)` が返る。

収束判定：`|v|² - dot(v, w) = 9 - dot((-3,0), (-3,0)) = 9 - 9 = 0`。`0 ≤ tol · 9` なので**収束**。

**結果。** 距離は `|v| = 3`。重心座標は `λ₀ = 1` なので、`closest_a = (2,0)`、`closest_b = (5,0)`。

検算：`(5,0) - (2,0) = (3,0)`、長さ 3。正しい。

**この例は 1 反復で終わった。** 最近接点が頂点どうしの場合、GJK は非常に速い。辺どうしが向かい合う場合は、単体が線分に育つので 2〜3 反復かかる。

### なぜ交差判定より難しいのか

前章の GJK は「原点を囲めるか」だけを見ていた。この章の GJK は「原点に最も近い点」を追う。**後者のほうが難しい。**

理由は三つある。

**1. 終了条件が緩やかである。** 交差判定は `dot(p, d) < 0` という明確な符号判定で終わる。距離計算は「これ以上改善しない」という相対的な判定で終わる。**どこで止めるかを自分で決めなければならない。**

**2. 単体上の最近接点を明示的に求める必要がある。** 交差判定は「どの領域にあるか」の場合分けだけで済んだ。距離計算はクランプと重心座標が要る。

**3. 精度が結果に直結する。** 交差判定の答えは真偽値なので、多少の誤差では変わらない。距離は連続値なので、誤差がそのまま出力の誤差になる。

**この難しさが、収束判定を `precise` で守る動機でもある。**

### 第 18 章の宿題を片付ける

第 18.2 節で、保守的前進が `distance_between` を要求していた。凸多角形どうしの実装は「第 21 章の GJK まで待つ」としてあった。

```cpp
// collision/narrow/distance.h に追加

// 任意の凸形状ペアの距離。第 18 章の HasDistance コンセプトを満たす。
template <SupportShape A, SupportShape B>
    requires (!std::same_as<A, Circle> || !std::same_as<B, Circle>)
[[nodiscard]] float distance_between(const A& a, const B& b) noexcept {
    return gjk_distance(a, b).distance;
}
```

**これで保守的前進が任意の凸形状に使えるようになった。** 第 23 章でこれを使う。

第 18 章で「コンセプトで要求だけしておき、実装は後の章で埋める」と述べた構成が、ここで完結する。

### マージン付き形状

第 16.2 節で「凸多角形と円のミンコフスキー和は頂点数が増えない」と述べた。この性質は距離計算で直接使える。

**形状 A を半径 `r` だけ膨らませたものとの距離は、元の距離から `r` を引いたものである。**

```cpp
// 形状にマージンを持たせたもの。円との和なので、サポート点は足すだけ（第 19.2 節）
template <SupportShape S>
struct Inflated {
    const S* shape{};
    float    margin{};
};

template <SupportShape S>
[[nodiscard]] Vec2 support_point(const Inflated<S>& s, Vec2 d) noexcept {
    return support_point(*s.shape, d) + normalize_or(d, Vec2{1.0f, 0.0f}) * s.margin;
}
```

用途は二つある。

**1. キャラクターの半径を考慮した経路判定。** キャラクターを点として扱い、障害物を半径だけ膨らませる。第 16.4 節の帰着と同じ発想である。

**2. 数値的な安定化。** 尖った形状どうしの距離計算は、サポート点が飛びやすく収束が悪い。わずかなマージン（`contact_slop` 程度）を持たせると滑らかになる。**実務でよく使われる手法**である。

## 21.4 テスト

### 解析解との照合

円どうしなら距離が解析的に求まる。**最も確実なリファレンスである。**

```cpp
// test_gjk_distance.cpp
TEST_CLASS(GjkDistanceAnalytic) {
public:
    TEST_METHOD(円どうしの距離が解析解と一致すること) {
        Rng rng(1500);
        int checked = 0;

        for (int i = 0; i < 50000; ++i) {
            const collision::Circle a{{rng.uniform(-8.0f, 8.0f), rng.uniform(-8.0f, 8.0f)},
                                      rng.uniform(0.2f, 2.0f)};
            const collision::Circle b{{rng.uniform(-8.0f, 8.0f), rng.uniform(-8.0f, 8.0f)},
                                      rng.uniform(0.2f, 2.0f)};

            const float exact =
                collision::distance(a.center, b.center) - a.radius - b.radius;
            if (exact <= 0.01f) continue;   // 交差または接触寸前は除外

            const auto r = collision::gjk_distance(a, b);
            Assert::IsFalse(r.intersecting);
            expect_near(exact, r.distance, 1.0e-4f, 1.0e-4f);

            // 最近接点の検証：それぞれの円周上にあり、距離が一致すること
            expect_near(a.radius, collision::distance(r.closest_a, a.center),
                        1.0e-3f, 1.0e-4f);
            expect_near(b.radius, collision::distance(r.closest_b, b.center),
                        1.0e-3f, 1.0e-4f);
            expect_near(r.distance, collision::distance(r.closest_a, r.closest_b),
                        1.0e-3f, 1.0e-4f);
            ++checked;
        }
        Assert::IsTrue(checked > 10000, L"照合できた事例が少なすぎる");
    }

    TEST_METHOD(点と多角形の距離が最近接点と一致すること) {
        Rng rng(1501);
        for (int i = 0; i < 20000; ++i) {
            const auto p = transformed_poly(random_convex_polygon_checked(rng, 3 + (i % 6)),
                {rng.uniform(-2.0f, 2.0f), rng.uniform(-2.0f, 2.0f)}, rng.uniform(0.0f, 6.28f));
            const Vec2 q{rng.uniform(-8.0f, 8.0f), rng.uniform(-8.0f, 8.0f)};

            const auto r = collision::gjk_distance(q, p);
            if (r.intersecting) continue;

            // 第 13.2 節の closest_point をリファレンスにする
            const Vec2 cp = collision::closest_point(q, p);
            expect_near(collision::distance(q, cp), r.distance, 1.0e-3f, 1.0e-4f);
            expect_near(cp, r.closest_b, 1.0e-2f, 1.0e-3f);
        }
    }
};
```

**最近接点の検証を三重にしている**のが要点である。「円周上にあること」「二点間の距離が返り値と一致すること」の両方を確かめる。片方だけでは、重心座標の復元にバグがあっても通ってしまう。

### 総当たりとの照合

一般の凸多角形には解析解がない。第 9.6 節と同じく、**素朴な総当たり**をリファレンスにする。

```cpp
TEST_CLASS(GjkDistanceReference) {
public:
    // 総当たり：全辺ペアをサンプリングして最短距離を求める
    [[nodiscard]] static float brute_force_distance(
            const collision::ConvexPolygon& a, const collision::ConvexPolygon& b) {
        float best = std::numeric_limits<float>::infinity();
        constexpr int steps = 200;

        for (std::uint32_t i = 0; i < a.count; ++i) {
            const Vec2 a0 = a.vertex[i], a1 = a.vertex[(i + 1) % a.count];
            for (int k = 0; k <= steps; ++k) {
                const Vec2 p = a0 + (a1 - a0) * (static_cast<float>(k) / steps);
                for (std::uint32_t j = 0; j < b.count; ++j) {
                    const Vec2 q = collision::closest_point_on_segment(
                        p, b.vertex[j], b.vertex[(j + 1) % b.count]);
                    best = std::min(best, collision::distance(p, q));
                }
            }
        }
        return best;
    }

    TEST_METHOD(凸多角形の距離が総当たりと一致すること) {
        Rng rng(1502);
        int checked = 0;
        float worst = 0.0f;

        for (int i = 0; i < 2000; ++i) {
            const auto a = transformed_poly(random_convex_polygon_checked(rng, 3 + (i % 6)),
                {rng.uniform(-6.0f, 6.0f), rng.uniform(-6.0f, 6.0f)}, rng.uniform(0.0f, 6.28f));
            const auto b = transformed_poly(random_convex_polygon_checked(rng, 3 + (i % 6)),
                {rng.uniform(-6.0f, 6.0f), rng.uniform(-6.0f, 6.0f)}, rng.uniform(0.0f, 6.28f));

            if (collision::overlaps(a, b)) continue;

            const auto r = collision::gjk_distance(a, b);
            Assert::IsFalse(r.intersecting, L"分離しているのに交差と判定された");

            const float ref = brute_force_distance(a, b);
            worst = std::max(worst, std::fabs(r.distance - ref));
            // 総当たりの刻み幅ぶんの誤差を許容する
            Assert::IsTrue(std::fabs(r.distance - ref) < 0.01f,
                detail::widen(std::format("gjk={:.6g} brute={:.6g}",
                                          r.distance, ref)).c_str());
            ++checked;
        }
        Logger::WriteMessage(std::format(
            "照合 {} 件, 最大差 {:.4g}\n", checked, worst).c_str());
        Assert::IsTrue(checked > 300);
    }

    TEST_METHOD(交差の有無がGJKの交差判定と一致すること) {
        Rng rng(1503);
        for (int i = 0; i < 50000; ++i) {
            const auto a = transformed_poly(random_convex_polygon_checked(rng, 3 + (i % 6)),
                {rng.uniform(-1.5f, 1.5f), rng.uniform(-1.5f, 1.5f)}, rng.uniform(0.0f, 6.28f));
            const auto b = transformed_poly(random_convex_polygon_checked(rng, 3 + (i % 6)),
                {rng.uniform(-1.5f, 1.5f), rng.uniform(-1.5f, 1.5f)}, rng.uniform(0.0f, 6.28f));

            const bool by_gjk  = collision::overlaps_gjk(a, b);
            const bool by_dist = collision::gjk_distance(a, b).intersecting;

            // 境界近傍では割れうるので、距離が十分ある場合だけ厳密に比較する
            const auto r = collision::gjk_distance(a, b);
            if (!r.intersecting && r.distance > 0.05f) {
                Assert::IsFalse(by_gjk, L"距離があるのに交差と判定された");
            }
            (void)by_dist;
        }
    }
};
```

**総当たりの刻みが 200 なので、許容誤差を 0.01 に取っている。** これはリファレンス側の精度であって、GJK の精度ではない。テストの許容誤差が何に由来するかを意識するのは重要である（第 4.3 節）。

## この章のまとめ

- **距離 GJK は、単体上で原点に最も近い点 `v` を追跡する**
- 収束判定は `|v|² - dot(v, w) ≤ tol · |v|²`。相対誤差なのでスケールに依存しない
- この判定は桁落ちしやすい形なので、`precise` で守る（第 4.6 節）
- **最近接点は重心座標で復元する。** 単体上の重み `λ` を `on_a` / `on_b` に適用する
- 第 19.3 節で `MinkowskiPoint` に元の点を持たせておいた理由が、ここで回収される
- 凸性が「復元した点が形状上にある」ことを保証する
- 単体の縮約と重み計算は同じ関数で行う。分けると対応がずれる
- **第 18 章の `distance_between` が、任意の凸形状に対して実装された**
- `Inflated` で形状にマージンを持たせられる。経路判定と数値安定化に使う
- テストは解析解（円）・総当たり（多角形）・性質（最近接点の整合、単調性）の三本立て

### 落とし穴と練習問題

**落とし穴 1：重みと頂点の対応がずれる。**　縮約で頂点を捨てたのに重みを更新し忘れると、復元した点が形状の外に出る。

**落とし穴 2：交差している場合に距離を返す。**　`intersecting` が立っているときの `distance` は 0 である。貫通深度が欲しいなら次章の EPA を使う。

**落とし穴 3：収束判定を絶対誤差で書く。**　遠く離れた形状では厳しすぎ、近い形状では緩すぎる。相対誤差にする。

---

**練習問題 21-1**　`tolerance` を `1e-3f` から `1e-9f` まで変えて、反復回数と精度がどう変わるかを測ろう。第 18.6 節で `target_distance` について行ったのと同じ実験である。

**練習問題 21-2**　最近接点が一意に決まらない配置（平行な辺どうしが向かい合う）を作り、`gjk_distance` が何を返すか観察しよう。距離は一意だが、点は辺上のどこでもよい。実装はどこを返すだろうか。

**練習問題 21-3**　距離 GJK を使って「二つの形状を最短経路で接触させるための移動ベクトル」を求めてみよう。`closest_b - closest_a` がその向きになる。第 23 章の保守的前進で使う考え方である。

**練習問題 21-4**　`Inflated` を入れ子にして二重にマージンを付けると、距離は二つ分縮むだろうか。確かめてみてほしい。

**練習問題 21-5**（発展）　距離 GJK に「打ち切り距離」を追加しよう。`|v|` がある閾値を超えた時点で「十分遠い」として早期に終了する。ブロードフェーズ（第 VI 部）で「近いものだけ精密判定する」場面で役立つ。

---

次章では、逆の問い ―「交差しているとき、どれだけめり込んでいるか」― に答える。GJK が原点を囲む三角形を作ったところから始めて、その三角形をミンコフスキー差の境界まで膨らませる。それが EPA である。**本書で最も `/fp:fast` に弱い箇所**でもある。
