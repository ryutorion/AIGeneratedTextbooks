# 第 14 章　接触点を作る ― マニフォールド生成

> **この章のゴール**
> 接触点を一つではなく複数生成する。第 11 章から「暫定」と書き続けてきた `Contact::point` を、ここで正しく求める。
>
> 「箱が床に平らに乗っているのに、なぜか転がり出す」という現象の原因を突き止め、参照面・入射面・クリッピングという道具で解決する。**第 II 部の締めくくりであり、第 VII 部（衝突応答）への前提を整える章**でもある。

---

## 14.1 なぜ「点 1 つ」では箱が転がってしまうのか

### 現象

第 12 章の `intersect(Obb, Obb)` は、接触点を一つ返す。それを使って剛体シミュレーションを組むと、こういうことが起きる。

床の上に箱を置く。箱は平らに接している。物理的には静止するはずである。ところが、箱はゆっくりと傾き、やがて片方の角を支点にして転がり落ちる。

### 原因

接触点が一つしかないと、そこに働く力が箱の重心からずれている場合、**トルクが生じる**。

箱の底面全体が床に接しているとき、床が箱を支える力は底面全体に分布している。合力は重心の真下を通り、トルクはゼロになる。だから静止する。

ところが接触点を一つしか報告しないと、その一点だけで支えることになる。その点が重心の真下からわずかでもずれていれば、トルクが発生する。箱は回り始める。回ると接触点の位置がさらにずれ、トルクが増える。**正のフィードバックが働き、箱は転がる。**

### 必要なもの

面と面が接触しているとき、その接触は「点」ではなく「線分」（3D なら「面」）である。これを離散的に表すには、**両端の 2 点**が要る。

2 点あれば、その間のどこに合力が働いてもよいことになり、トルクを打ち消せる。箱は静止する。

この接触点の集合を **接触マニフォールド**（contact manifold）と呼ぶ。

### 2D では 2 点で足りる

2 次元では、二つの凸多角形の接触領域は必ず線分（または点）になる。したがって接触点は最大 2 個である。

3 次元では、面どうしの接触領域は多角形になるので、点はもっと必要になる（実装によっては 4 点や 8 点に制限する）。第 27 章で扱う。

## 14.2 マニフォールドの型と、第 7 章の規約の見直し

### 型

```cpp
// collision/narrow/manifold.h
#pragma once

#include "collision/narrow/contact.h"
#include <array>
#include <cstdint>

namespace collision {

// マニフォールド上の 1 点
struct ManifoldPoint {
    Vec2  point{};   // 接触位置（ワールド座標、参照面上）
    float depth{};   // この点での貫通深度（非負）
};

// 二つの凸形状の接触の記述。2D では接触点は最大 2 個。
struct ContactManifold {
    Vec2 normal{};                        // A から B へ（第 7.3 節の規約）
    std::array<ManifoldPoint, 2> point{};
    std::uint32_t count{};
};

} // namespace collision
```

### 第 7 章で予告した設計からの変更点

第 7.2 節でこう書いた。

> 第 14 章で `ContactManifold` 型を導入し、`Contact` を複数持てるようにする。そのとき `Contact` 型自体は変えない（法線と深度はマニフォールド全体で共有し、点だけを複数持つ形にする）。

**この予告は、一部が誤っていた。深度は点ごとに持たなければならない。**

理由は簡単である。箱がわずかに傾いて床に接しているとき、二つの接触点のめり込み量は違う。片方の角が深く、もう片方は浅い。単一の深度では、この状況を表せない。

同じ深度を両点に割り当てると、傾いた箱を押し戻すときに**傾きが解消されない**（両端が同じだけ持ち上がるので、傾いたまま浮く）。点ごとに深度を持てば、深い側がより強く押し戻され、箱は水平に戻る。

**法線は共有でよい。** 面と面の接触なら、法線は接触面の法線ひとつである。

### 接触点の位置の規約も見直す

第 7.2 節では「接触点は A の表面上」と決めた。マニフォールドでは、これを次のように改める。

**マニフォールドの各点は、参照面（14.3 節で定義）の上に置く。**

参照面は A の面のこともあれば B の面のこともある。したがって、「常に A の表面上」という規約は維持できない。

これは妥協ではなく、**より適切な規約への更新**である。マニフォールドが記述しているのは「二つの物体の間の接触面」であって、片方の物体の表面ではない。接触面の代表として参照面を選ぶのは自然である。

第 36 章で力積を計算するときも、接触点がどちらの物体の表面にあるかは本質的でない。重要なのは、**両物体の重心からの相対位置**であり、それは参照面上の点から計算できる。

> **規約が途中で変わることについて**
> 本書は「規約を先に決めて守る」という方針で書いている（第 7.3 節）。それでも設計が進むと、当初の規約が不適切だと分かることがある。
>
> 大事なのは、**変えたことを明示し、なぜ変えたかを書き残す**ことである。黙って変えると、古い規約を前提にしたコードが残って矛盾する。この節はそのための記録である。

### 単一接触点との橋渡し

既存の `Contact` を返す API も残しておきたい。マニフォールドから代表点を選ぶ関数を用意する。

```cpp
// 最も深い点を代表として、単一の Contact に落とす
[[nodiscard]] inline std::optional<Contact>
to_contact(const ContactManifold& m) noexcept {
    if (m.count == 0) return std::nullopt;

    std::size_t deepest = 0;
    for (std::uint32_t i = 1; i < m.count; ++i) {
        if (m.point[i].depth > m.point[deepest].depth) deepest = i;
    }
    return Contact{
        .normal = m.normal,
        .depth  = m.point[deepest].depth,
        .point  = m.point[deepest].point,
    };
}
```

トリガー判定やレイキャストのように、接触点が一つで足りる用途ではこちらを使う。

## 14.3 参照面と入射面を選ぶ

### 考え方

SAT が返した最小貫通軸 `n`（A から B へ向く）を出発点にする。

**参照面**（reference face）は、接触の「基準」になる面である。法線が `n` に最も近い面を選ぶ。A の面と B の面の両方が候補になり、より `n` に沿っているほうを選ぶ。

**入射面**（incident face）は、反対側の形状の面のうち、参照面に最も向き合っている面である。参照面の法線と最も逆向きの法線を持つ面を選ぶ。

床の上の箱でいえば、床の上面が参照面、箱の底面が入射面になる。

### 面を表す型

```cpp
// collision/narrow/manifold.h（続き）

// 多角形の 1 辺（2D では「面」は辺である）
struct Face {
    Vec2 v0{};       // 始点
    Vec2 v1{};       // 終点（反時計回りで次の頂点）
    Vec2 normal{};   // 外向き単位法線
};

[[nodiscard]] inline Face face_of(const ConvexPolygon& p, std::size_t i) noexcept {
    const std::size_t j = (i + 1) % p.count;
    return Face{
        .v0     = p.vertex[i],
        .v1     = p.vertex[j],
        .normal = axis(p, i),          // 第 13.1 節の外向き法線
    };
}

// 法線が dir に最も近い面の添字を返す
[[nodiscard]] inline std::size_t
most_aligned_face(const ConvexPolygon& p, Vec2 dir) noexcept {
    std::size_t best = 0;
    float best_dot = -std::numeric_limits<float>::infinity();
    for (std::size_t i = 0; i < p.count; ++i) {
        const float d = dot(axis(p, i), dir);
        if (d > best_dot) { best_dot = d; best = i; }
    }
    return best;
}
```

`most_aligned_face` は `axis(p, i)` を呼ぶので、辺の数だけ正規化が入る。第 13.1 節で述べたとおり、ここでは繰り返し参照するので**局所変数にキャッシュする価値がある**。実装を簡潔に保つため本書ではそのまま呼んでいるが、性能が問題になれば法線を事前計算する構造に変える（第 42 章）。

### 参照面と入射面の決定

```cpp
namespace detail {

struct FacePair {
    Face reference{};
    Face incident{};
    bool flipped{};   // true なら参照面は B 側（法線の向きが反転している）
};

[[nodiscard]] inline FacePair
select_faces(const ConvexPolygon& a, const ConvexPolygon& b, Vec2 n) noexcept {
    // n は A から B へ向く。
    // A 側の面は n に沿った向き、B 側の面は -n に沿った向きを探す
    const std::size_t ia = most_aligned_face(a,  n);
    const std::size_t ib = most_aligned_face(b, -n);

    const Face fa = face_of(a, ia);
    const Face fb = face_of(b, ib);

    const float align_a = dot(fa.normal,  n);
    const float align_b = dot(fb.normal, -n);

    // より深く n に沿っているほうを参照面にする。
    // 拮抗している場合は A を優先する（決定論のため）
    if (align_a >= align_b - 1.0e-4f) {
        // 参照面は A の面。入射面は B の面のうち、参照法線と最も逆向きのもの
        const std::size_t inc = most_aligned_face(b, -fa.normal);
        return FacePair{.reference = fa, .incident = face_of(b, inc), .flipped = false};
    } else {
        const std::size_t inc = most_aligned_face(a, -fb.normal);
        return FacePair{.reference = fb, .incident = face_of(a, inc), .flipped = true};
    }
}

} // namespace detail
```

**`align_b - 1.0e-4f` という許容差を入れているのが実務的な工夫である。**

`align_a` と `align_b` がほぼ等しいとき（両方の面が同じくらい `n` に沿っているとき）、どちらを選ぶかが丸め誤差で決まってしまう。フレームごとに参照面が入れ替わると、接触点の位置が飛び、物体が震える。

許容差を入れて A を優先することで、**拮抗した状況では常に同じ選択がなされる**。フレーム間で安定する。

これは第 3.5 節の原則 3（境界ぎりぎりを信用しない）を、テストではなく実装側で適用した例である。

## 14.4 クリッピング

### サザーランド＝ホジマン法

入射面（線分）を、参照面の「側面」で切り取る。

参照面 `[v0, v1]` に対して、二つの側面がある。`v0` を通り参照面に垂直な線と、`v1` を通る同様の線である。入射面のうち、この二本の線の間に収まる部分だけを残す。

これが**サザーランド＝ホジマン法**（Sutherland–Hodgman clipping）である。本来は多角形を多角形で切る一般的なアルゴリズムだが、2D では「線分を 2 本の線で切る」という単純な形になる。

### 線分を半平面で切る

```cpp
namespace detail {

// 線分 [p0, p1] を、半平面 { x : dot(x, n) <= offset } で切り取る。
// 切り取った結果の点数（0〜2）を返す。
[[nodiscard]] inline std::uint32_t
clip_segment(Vec2 p0, Vec2 p1, Vec2 n, float offset, std::array<Vec2, 2>& out) noexcept {
    const float d0 = dot(p0, n) - offset;
    const float d1 = dot(p1, n) - offset;

    std::uint32_t count = 0;

    // 半平面の内側にある端点は、そのまま残す
    if (d0 <= 0.0f) out[count++] = p0;
    if (d1 <= 0.0f) out[count++] = p1;

    // 境界をまたいでいるなら、交点を追加する
    if (d0 * d1 < 0.0f && count < 2) {
        const float t = d0 / (d0 - d1);        // d0 - d1 は非ゼロ（符号が違うため）
        out[count++] = p0 + (p1 - p0) * t;
    }
    return count;
}

} // namespace detail
```

`d0 * d1 < 0.0f` は「符号が異なる」ことを表す。このとき `d0 - d1` は必ず非ゼロなので、**除算が安全である**。

第 4.5 節のパターン 3（片側だけの閾値比較）を思い出してほしい。ここでは積の符号で判定しているので、`d0` や `d1` が誤差でわずかに揺れても、両方が同符号なら交点を作らない。**素直で安全な形**になっている。

`count < 2` という条件を付けているのは、両端点とも内側にある場合（`count == 2`）に、さらに交点を足して配列を溢れさせないためである。ただし両端が内側なら `d0 * d1 > 0` なので、この条件は本来不要である。**防御的に書いている。**

### マニフォールドの構築

```cpp
[[nodiscard]] inline ContactManifold
build_manifold(const ConvexPolygon& a, const ConvexPolygon& b,
               Vec2 n, float depth) noexcept {
    const auto fp = detail::select_faces(a, b, n);
    const Face& ref = fp.reference;
    const Face& inc = fp.incident;

    ContactManifold m{};
    m.normal = n;   // 常に A から B へ（規約は SAT 側で保証済み）

    // 参照面に沿った方向
    const Vec2 tangent = normalize_or(ref.v1 - ref.v0, Vec2{1.0f, 0.0f});

    // 入射面を、参照面の 2 つの側面で切る
    std::array<Vec2, 2> buf{inc.v0, inc.v1};
    std::array<Vec2, 2> tmp{};

    // 側面 1：v0 側（tangent の負方向を切り落とす）
    std::uint32_t cnt = detail::clip_segment(
        buf[0], buf[1], -tangent, -dot(ref.v0, tangent), tmp);
    if (cnt < 2) return m;   // 退化：接触領域がない
    buf = tmp;

    // 側面 2：v1 側（tangent の正方向を切り落とす）
    cnt = detail::clip_segment(
        buf[0], buf[1], tangent, dot(ref.v1, tangent), tmp);
    if (cnt < 2) return m;
    buf = tmp;

    // 参照面より内側（めり込んでいる側）にある点だけを残す
    const float ref_offset = dot(ref.v0, ref.normal);
    for (const Vec2 p : buf) {
        const float separation = dot(p, ref.normal) - ref_offset;
        if (separation > 0.0f) continue;   // めり込んでいない点は捨てる

        m.point[m.count] = ManifoldPoint{
            // 参照面上へ射影する（14.2 節の規約）
            .point = p - ref.normal * separation,
            .depth = -separation,
        };
        ++m.count;
        if (m.count == 2) break;
    }

    // 1 点も残らなかった場合（数値的な事故）、SAT の結果で 1 点だけ作る
    if (m.count == 0) {
        m.point[0] = ManifoldPoint{.point = centroid(vertices(a)), .depth = depth};
        m.count = 1;
    }
    return m;
}
```

### 各段階の説明

**接線方向でのクリッピング。** `dot(p, tangent)` が `dot(ref.v0, tangent)` 以上、かつ `dot(ref.v1, tangent)` 以下の範囲に収める。参照面の「幅」の中に入射面を押し込む操作である。

**参照面からの分離量。** `separation = dot(p, ref.normal) - dot(ref.v0, ref.normal)` は、点 `p` が参照面からどれだけ外側にあるかを表す。負ならめり込んでいる。

**深度は点ごとに `-separation`。** 14.2 節で述べたとおり、点ごとに違う値になる。傾いた箱では、片方が深く、もう片方が浅い。

**参照面上への射影。** `p - ref.normal * separation` で、点を参照面の平面上へ移す。`separation` が負なので、法線方向に持ち上げる形になる。

**フォールバック。** クリッピングの結果が空になることが、数値的な事故として起こりうる。そのとき無言でマニフォールドを空にすると、交差しているのに応答が働かず、物体がすり抜ける。**SAT が交差と判定した以上、最低 1 点は返す。**

### 判定関数に組み込む

```cpp
// collision/narrow/polygon_polygon.h に追加

[[nodiscard]] inline std::optional<ContactManifold>
collide(const ConvexPolygon& a, const ConvexPolygon& b) noexcept {
    const auto r = sat_polygon(a, b);
    if (!r) return std::nullopt;
    return build_manifold(a, b, r->axis, r->depth);
}

// [変更] 第 13 章の暫定実装を、マニフォールドから導く形に置き換える
[[nodiscard]] inline std::optional<Contact>
intersect(const ConvexPolygon& a, const ConvexPolygon& b) noexcept {
    const auto m = collide(a, b);
    if (!m) return std::nullopt;
    return to_contact(*m);
}
```

**第 11 章から「暫定」だった `Contact::point` が、ここで正しくなった。** 重心でも代表点でもなく、実際に接触している位置である。

## 14.5 退化した配置

### 頂点どうしの接触

二つの多角形が、面ではなく頂点で触れている場合を考える。

このとき、入射面をクリッピングすると 1 点しか残らない。マニフォールドは 1 点になる。**これは正しい。** 頂点どうしの接触は、実際に点接触である。

問題は起きない。ただし、そこから生じるトルクは打ち消せないので、物体は回転する。それも物理的に正しい。

### 平行な辺どうし

床の上の箱のように、参照面と入射面がぴったり平行な場合。

このとき `select_faces` で `align_a` と `align_b` が拮抗する。14.3 節で入れた許容差 `1.0e-4f` が効き、A 側が選ばれる。**フレーム間で安定する。**

クリッピングの結果は 2 点になり、両方の深度がほぼ等しくなる。これが本章の目標だった状況である。

### ほぼ平行だが、わずかに傾いている

最も微妙なのがこの場合である。箱が床に対して 0.01 度だけ傾いているとしよう。

参照面の選択は安定している（許容差のおかげ）。クリッピングも 2 点を返す。ただし二つの深度に差が生まれる。傾きに応じた差なので、これも正しい。

**むしろこの差が必要である。** 深度の差があるからこそ、押し戻しで傾きが解消される。

### 潰れた多角形

面積がゼロの多角形（すべての頂点が一直線上）を渡すと、`axis` がフォールバックの `(1,0)` を返す辺が出てくる。SAT は動くが、参照面の選択が無意味になる。

**対処は入力側で行う。** `is_convex_ccw`（第 13.1 節）は頂点数が 3 未満を弾くが、面積ゼロは弾かない。必要なら `signed_area` の下限も検査する。

```cpp
[[nodiscard]] inline bool is_usable_polygon(const ConvexPolygon& p) noexcept {
    return is_convex_ccw(p) && signed_area(p) > min_length2;
}
```

面積と長さの二乗を比べているので次元は合っていないが、「極端に潰れていないこと」の粗い検査としては機能する。第 9.3 節の `barycentric` でも同じ妥協をした。

### クリッピングが 0 点を返す場合

14.4 節でフォールバックを入れた理由である。理論上は、SAT が交差と判定していればクリッピングは 1 点以上を返すはずである。

実際には、深度が極端に小さい（`1e-6` オーダー）ときに、`separation > 0.0f` の判定で両点とも捨てられることがある。丸め誤差で `separation` がわずかに正になるためである。

**フォールバックがないと、この状況で物体がすり抜ける。** 症状は「ごくまれに、ほとんど接触していない状態で通り抜ける」という再現しにくいものになる。デバッグは困難である。

こうした「理論上は起きないが、浮動小数点では起きる」ケースに備えるのが、**防御的なフォールバック**の役割である。

## 14.6 テスト

### 箱が床に平らに乗ったとき、接触点は 2 個

この章の目標そのものをテストにする。

```cpp
// test_manifold.cpp
TEST_CLASS(ManifoldFlatContact) {
public:
    TEST_METHOD(床に平らに乗った箱の接触点が2個であること) {
        // 床：幅 20、厚さ 1、上面が y = 0
        const auto floor = collision::make_box({0.0f, -0.5f}, {10.0f, 0.5f});
        // 箱：一辺 2、わずかにめり込んでいる（下端 y = -0.1）
        const auto box   = collision::make_box({0.0f,  0.9f}, {1.0f, 1.0f});

        const auto m = collision::collide(floor, box);
        Assert::IsTrue(m.has_value());
        Assert::AreEqual(2u, m->count, L"接触点が 2 個でない");

        // 法線は床から箱へ、つまり上向き
        expect_near(Vec2{0.0f, 1.0f}, m->normal, 1.0e-4f, 1.0e-4f);

        // 両方の深度が 0.1 程度で、ほぼ等しいこと
        expect_near(0.1f, m->point[0].depth, 1.0e-4f, 1.0e-3f);
        expect_near(0.1f, m->point[1].depth, 1.0e-4f, 1.0e-3f);

        // 2 点は箱の底面の両端付近、つまり x = ±1 の近く
        const float x0 = m->point[0].point.x;
        const float x1 = m->point[1].point.x;
        Assert::IsTrue(std::fabs(std::fabs(x0) - 1.0f) < 0.1f, L"接触点が底面の端にない");
        Assert::IsTrue(std::fabs(std::fabs(x1) - 1.0f) < 0.1f, L"接触点が底面の端にない");
        Assert::IsTrue(std::fabs(x0 - x1) > 1.0f, L"2 点が離れていない");
    }

    TEST_METHOD(傾いた箱では深度に差が出ること) {
        const auto floor = collision::make_box({0.0f, -0.5f}, {10.0f, 0.5f});

        // 5 度傾けた箱
        auto box = collision::make_box({0.0f, 0.9f}, {1.0f, 1.0f});
        box = transformed_about(box, {0.0f, 0.9f}, 5.0f * std::numbers::pi_v<float> / 180.0f);

        const auto m = collision::collide(floor, box);
        Assert::IsTrue(m.has_value());

        if (m->count == 2) {
            const float d = std::fabs(m->point[0].depth - m->point[1].depth);
            Assert::IsTrue(d > 1.0e-3f, L"傾いているのに深度が同じ");
        }
        // count == 1 でもよい（角だけで接している場合）
    }

    TEST_METHOD(頂点で触れる配置では接触点が1個でもよいこと) {
        // 45 度回転した正方形の角が、床に触れている
        auto diamond = collision::make_box({0.0f, 1.35f}, {1.0f, 1.0f});
        diamond = transformed_about(diamond, {0.0f, 1.35f},
                                    std::numbers::pi_v<float> / 4.0f);
        const auto floor = collision::make_box({0.0f, -0.5f}, {10.0f, 0.5f});

        const auto m = collision::collide(floor, diamond);
        Assert::IsTrue(m.has_value());
        Assert::IsTrue(m->count >= 1u && m->count <= 2u);

        for (std::uint32_t i = 0; i < m->count; ++i) {
            Assert::IsTrue(m->point[i].depth >= 0.0f, L"深度が負");
        }
    }
};
```

`transformed_about` は、指定した点を中心に回転させるヘルパである。テスト補助として用意しておく。

```cpp
// test_helpers.h に追加
[[nodiscard]] inline collision::ConvexPolygon
transformed_about(const collision::ConvexPolygon& p, collision::Vec2 pivot, float angle) {
    const float c = std::cos(angle), s = std::sin(angle);
    collision::ConvexPolygon r = p;
    for (std::uint32_t i = 0; i < p.count; ++i) {
        const auto v = p.vertex[i] - pivot;
        r.vertex[i] = collision::Vec2{v.x * c - v.y * s, v.x * s + v.y * c} + pivot;
    }
    return r;
}
```

```cpp
// test_helpers.h に追加
inline void check_manifold_invariants(
        const collision::ContactManifold& m,
        std::source_location loc = std::source_location::current()) {
    using namespace Microsoft::VisualStudio::CppUnitTestFramework;

    Assert::IsTrue(m.count >= 1u && m.count <= 2u,
        detail::widen(std::format("接触点数が範囲外: {} at {}:{}",
            m.count, loc.file_name(), loc.line())).c_str());

    // 法線は単位長
    expect_near(1.0f, collision::length(m.normal), 1.0e-5f, 1.0e-5f, loc);

    for (std::uint32_t i = 0; i < m.count; ++i) {
        const auto& p = m.point[i];
        Assert::IsTrue(collision::is_finite_bits(p.point.x) &&
                       collision::is_finite_bits(p.point.y) &&
                       collision::is_finite_bits(p.depth),
            detail::widen(std::format("マニフォールドに非有限値 at {}:{}",
                loc.file_name(), loc.line())).c_str());

        Assert::IsTrue(p.depth >= 0.0f,
            detail::widen(std::format("深度が負: {:.9g} at {}:{}",
                p.depth, loc.file_name(), loc.line())).c_str());
    }

    // 2 点あるなら、互いに異なる位置であること
    if (m.count == 2) {
        const float d2 = collision::distance_squared(m.point[0].point, m.point[1].point);
        Assert::IsTrue(d2 > collision::min_length2,
            detail::widen(std::format("2 点が同一位置 at {}:{}",
                loc.file_name(), loc.line())).c_str());
    }
}
```

### ランダム入力での網羅

第 13.4 節の生成器が、ここで本領を発揮する。

```cpp
TEST_CLASS(ManifoldProperties) {
public:
    TEST_METHOD(ランダムな凸多角形対で不変条件が保たれること) {
        Rng rng(800);
        int total = 0, two_points = 0;

        for (int i = 0; i < 50000; ++i) {

                rng.uniform(0.0f, 6.28f));

                {rng.uniform(-2.0f, 2.0f), rng.uniform(-2.0f, 2.0f)},
                rng.uniform(0.0f, 6.28f));

            const auto m = collision::collide(a, b);
            if (!m) continue;

            check_manifold_invariants(*m);
            ++total;
            if (m->count == 2) ++two_points;
        }

        Logger::WriteMessage(std::format(
            "交差 {} 件中、2 点マニフォールド {} 件 ({:.1f}%)\n",
            total, two_points, 100.0 * two_points / std::max(total, 1)).c_str());

        Assert::IsTrue(total > 1000, L"交差した事例が少なすぎる");
    }

    TEST_METHOD(接触点が両形状の近傍にあること) {
        Rng rng(801);
        for (int i = 0; i < 20000; ++i) {
            const auto a = transformed(random_convex_polygon_checked(rng, 3 + (i % 6)),
                {rng.uniform(-1.5f, 1.5f), rng.uniform(-1.5f, 1.5f)},
                rng.uniform(0.0f, 6.28f));
            const auto b = transformed(random_convex_polygon_checked(rng, 3 + (i % 6)),
                {rng.uniform(-1.5f, 1.5f), rng.uniform(-1.5f, 1.5f)},
                rng.uniform(0.0f, 6.28f));

            const auto m = collision::collide(a, b);
            if (!m) continue;

            for (std::uint32_t k = 0; k < m->count; ++k) {
                const Vec2 p = m->point[k].point;
                // 接触点は両方の形状の表面近くにあるはず
                const float da = collision::distance_squared(
                    p, collision::closest_point(p, a));
                const float db = collision::distance_squared(
                    p, collision::closest_point(p, b));

                Assert::IsTrue(da < 0.01f, L"接触点が A から遠い");
                Assert::IsTrue(db < 0.01f, L"接触点が B から遠い");
            }
        }
    }

    TEST_METHOD(引数を入れ替えても接触点の位置がほぼ一致すること) {
        Rng rng(802);
        for (int i = 0; i < 10000; ++i) {
            const auto a = transformed(random_convex_polygon_checked(rng, 4),
                {rng.uniform(-1.5f, 1.5f), rng.uniform(-1.5f, 1.5f)},
                rng.uniform(0.0f, 6.28f));
            const auto b = transformed(random_convex_polygon_checked(rng, 4),
                {rng.uniform(-1.5f, 1.5f), rng.uniform(-1.5f, 1.5f)},
                rng.uniform(0.0f, 6.28f));

            const auto mab = collision::collide(a, b);
            const auto mba = collision::collide(b, a);

            Assert::AreEqual(mab.has_value(), mba.has_value());
            if (!mab) continue;

            check_manifold_invariants(*mab);
            check_manifold_invariants(*mba);

            expect_near(-mab->normal, mba->normal, 1.0e-4f, 1.0e-4f);
            // 接触点の個数は一致するとは限らない（参照面の選択が変わるため）
        }
    }
};
```

**「2 点マニフォールドの割合」を出力している**のが、この節で最も実用的な工夫である。

ランダムな凸多角形どうしでは、多くが頂点や角で接触するので、2 点になる割合はそれほど高くない。だが**割合がゼロに近ければ、クリッピングが機能していない**ということである。数値を記録しておけば、将来の変更で割合が急落したときに気づける。

三つ目のテストで「接触点の個数は一致するとは限らない」と明記している。参照面の選択が A と B で入れ替わるので、クリッピングの結果も変わりうる。**対称性を期待してよい範囲を、正しく限定する。**

### 第 13 章の実装との整合

```cpp
TEST_METHOD(法線と深度が第13章のSATと一致すること) {
    Rng rng(803);
    for (int i = 0; i < 20000; ++i) {
        const auto a = transformed(random_convex_polygon_checked(rng, 3 + (i % 6)),
            {rng.uniform(-2.0f, 2.0f), rng.uniform(-2.0f, 2.0f)}, rng.uniform(0.0f, 6.28f));
        const auto b = transformed(random_convex_polygon_checked(rng, 3 + (i % 6)),
            {rng.uniform(-2.0f, 2.0f), rng.uniform(-2.0f, 2.0f)}, rng.uniform(0.0f, 6.28f));

        const auto sat = collision::sat_polygon(a, b);
        const auto man = collision::collide(a, b);

        Assert::AreEqual(sat.has_value(), man.has_value());
        if (!sat) continue;

        expect_near(sat->axis, man->normal, 1.0e-5f, 1.0e-5f);

        // 最も深い点の深度が、SAT の深度とほぼ一致すること
        float max_depth = 0.0f;
        for (std::uint32_t k = 0; k < man->count; ++k) {
            max_depth = std::max(max_depth, man->point[k].depth);
        }
        expect_near(sat->depth, max_depth, 1.0e-3f, 1.0e-2f);
    }
}
```

**マニフォールドの最大深度が SAT の深度と一致する**、というのが重要な整合条件である。クリッピングは接触点の位置を求めるだけで、めり込みの量を変えてはいけない。

許容誤差を `1e-3f / 1e-2f` と緩めに取っている。参照面上への射影や、クリッピングでの補間によって、わずかな差が生じるためである。桁が合っていることを確認するテストである。

## この章のまとめ

- 接触点が 1 つだと、面接触でトルクが生じて箱が転がる。**2D では 2 点必要**
- `ContactManifold` は法線を共有し、**点ごとに深度を持つ**（第 7.2 節の予告を訂正）
- 接触点の位置の規約を「A の表面上」から「**参照面上**」に更新した
- 参照面は法線が最小貫通軸に最も沿った面。入射面は反対側の最も向き合う面
- **参照面の選択に許容差を入れる。** 拮抗した場合に A を優先し、フレーム間で安定させる
- クリッピングは、入射面を参照面の 2 つの側面で切り取る（サザーランド＝ホジマン法）
- 参照面より内側の点だけを残し、`separation` から点ごとの深度を得る
- **クリッピングが 0 点を返す事故に備えてフォールバックを置く。** ないとまれにすり抜ける
- テストは「床の上の箱で 2 点」が中心。ランダム入力では 2 点の割合を記録に残す

### 第 II 部の到達点

第 1 章の対応表でいえば、**「第 14 章：回転する箱・凸多角形の判定と押し戻し」に到達した**。

| できること | 章 |
|---|---|
| 回転する箱（OBB）の判定 | 第 12 章 |
| 任意の凸多角形の判定 | 第 13 章 |
| 押し戻しに使える法線・深度 | 第 11 章（SAT の MTV） |
| 面接触で安定する接触点 | この章 |

2D の物理エンジンとして実用になる水準の、判定側の材料が揃った。あとは第 VII 部で応答を作れば、箱が積み上がるシミュレーションができる。

**まだできないこと。** 高速に移動する物体がすり抜ける。これは判定の精度の問題ではなく、時間が離散的であることに起因する。第 III 部の主題である。

### 落とし穴と練習問題

**落とし穴 1：深度をマニフォールド全体で共有する。**　傾きが解消されなくなる。点ごとに持つ。

**落とし穴 2：参照面の選択に許容差を入れない。**　拮抗した状況でフレームごとに選択が入れ替わり、物体が震える。

**落とし穴 3：クリッピングが空になったときに何も返さない。**　まれにすり抜ける。再現しにくく、デバッグが極めて困難。

---

**練習問題 14-1**　14.3 節の許容差 `1.0e-4f` をゼロにして、床の上の箱のテストを走らせよう。箱をごくわずかに動かしながら参照面がどちらになるかを記録し、入れ替わりが起きるかを観察してほしい。

**練習問題 14-2**　14.4 節のフォールバックを外して、14.6 節のランダムテストを走らせよう。`m->count == 0` になる事例は出るだろうか。出るなら、その入力を記録して原因を調べてみてほしい。

**練習問題 14-3**　OBB どうしのマニフォールドを生成できるようにしよう。`from_obb`（第 13.1 節）で多角形に変換すれば動くが、OBB のまま扱う専用実装のほうが速い。両者の結果が一致することを等価性テストで確認する。

**練習問題 14-4**　接触点の個数の上限を 2 から 4 に増やしてみよう。2D では 3 点以上の接触は起こらないはずである。ランダムテストで 3 点以上が出るなら、それはクリッピングのバグである。上限を上げることが検査になる、という発想を試してほしい。

**練習問題 14-5**（発展）　マニフォールドに「特徴 ID」を持たせる設計を考えよう。第 7 章の練習問題 7-1 で触れた話である。参照面と入射面の添字、およびクリッピングで生成された点かどうかを符号化すれば、フレームをまたいで同じ接触点を対応づけられる。第 37 章のウォームスタートで必要になる。

第 III 部では、時間の話に入る。フレームとフレームの間で物体はワープしており、その間の衝突は今の道具では捉えられない。レイキャスト、ミンコフスキー和、スイープ判定、そして連続衝突判定。「弾丸が壁をすり抜ける」問題に、正面から取り組む。
