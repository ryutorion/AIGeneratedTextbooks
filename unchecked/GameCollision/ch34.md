# 第 34 章　まず「めり込みを直す」

> **この章のゴール**
> ここまでの 33 章は、すべて「当たったかどうか」を答えるための仕組みだった。**この章から「当たったあとどうなるか」を作る。**
>
> 最初に試すのは、考えうる最も素朴な方法である。**めり込んだ分だけ、法線方向に押し戻す。** 速度も力も運動量も出てこない。位置を直接動かすだけである。
>
> 驚くべきことに、これだけでかなり戦える。だが**三つの壁**にぶつかる。二重適用、順序依存、そしてジッタ。三つとも数字で押さえてから、次章以降へ進む。

## 34.1 位置補正（押し出し）だけでどこまで戦えるか

### 考え方

第 14 章の `ContactManifold` は、法線 `n`（A から B へ向く）と、点ごとのめり込み深さ `depth` を持っている。

**A を `-n` 方向へ、B を `+n` 方向へ、合わせて `depth` だけ動かせば、めり込みは消える。**

どちらをどれだけ動かすか。**質量の逆数で配分する。** 重いものは動きにくく、静的物体（質量無限大 ＝ 逆質量ゼロ）はまったく動かない。

```cpp
// collision/response/position_correction.h
#pragma once
#include "collision/narrowphase/contact_manifold.h"

namespace collision {

struct RigidBody {
    Vec2  position{};
    Vec2  velocity{};
    float inv_mass{};       // 0 なら静的
};

// 位置補正の設定
struct CorrectionConfig {
    float slop{contact_slop};   // 許容するめり込み（第 5.9 節：1 mm）
    float percent{0.8f};        // 一度に直す割合
};
```

補正そのものは短い。

```cpp
void correct_positions(RigidBody& a, RigidBody& b,
                       const ContactManifold& m, const CorrectionConfig& cfg) {
    const float total_inv_mass = a.inv_mass + b.inv_mass;
    if (total_inv_mass <= 0.0f) return;     // 両方とも静的

    // マニフォールドの中で最も深い点を代表にする
    float depth = 0.0f;
    for (const ContactPoint& p : m.points) depth = std::max(depth, p.depth);

    const float amount = std::max(0.0f, depth - cfg.slop)
                       * cfg.percent / total_inv_mass;

    a.position -= m.normal * (amount * a.inv_mass);
    b.position += m.normal * (amount * b.inv_mass);
}
```

### 押し戻すだけでは足りない

位置を直しても、**速度はめり込む向きを向いたままである。** 次のフレームでまた同じだけめり込む。

**法線方向の速度成分を消す**必要がある。

```cpp
void cancel_normal_velocity(RigidBody& a, RigidBody& b, Vec2 n) noexcept {
    // 近づく向きの成分だけを消す（離れていく物体は止めない）
    if (a.inv_mass > 0.0f) {
        const float vn = dot(a.velocity, n);
        if (vn > 0.0f) a.velocity -= n * vn;     // A は -n 側にいる
    }
    if (b.inv_mass > 0.0f) {
        const float vn = dot(b.velocity, n);
        if (vn < 0.0f) b.velocity -= n * vn;
    }
}
```

**「近づく向きだけ消す」のが要点である。** 離れていく物体まで止めると、床の上の物体が永久に貼り付く。

### どこまで戦えるのか

1 m 角の箱を 10 個積み上げ、5 秒間（300 フレーム、60 fps）走らせて測った。位置補正の反復は 4 回、`percent = 0.8`。

| slop | 最上段の y（理想 9.5） | 振れ幅 | 最大めり込み |
|---:|---:|---:|---:|
| 0 mm | 9.4149 | 0.0055 mm | 14.8 mm |
| 1 mm | 9.4049 | 0.0058 mm | 15.8 mm |
| 5 mm | 9.3649 | 0.0077 mm | 19.8 mm |

**静止する。** 振れ幅は 0.01 mm を切っており、目で見て震えているようには見えない。

**ただし 8.5 センチ沈む。** 10 個の箱がそれぞれ 1.5 mm ずつめり込んで積み上がった結果である。**箱を積むゲームなら許されるが、精密な積み上げを見せるゲームには足りない。**

そして重要なのは、**この方法には「跳ね返り」も「摩擦」も「回転」もない**ことである。箱は落ちて止まるだけで、跳ねない。斜面に置いても滑らない。押しても転ばない。

**それでも、これだけで作れるゲームはある。** 落ちものパズル、見下ろし型の移動、シンプルなプラットフォーマー。**「剛体シミュレーションが要るかどうか」を、作る前に考える価値はある。**

### 何が足りないのか

以降の章で何を足すことになるのかを、先に一覧にしておく。

| 欲しい挙動 | 位置補正だけ | 必要なもの | 章 |
|---|---|---|---|
| 落ちて止まる | **できる** | — | この章 |
| 跳ね返る | できない | 反発係数と法線力積 | 第 36 章 |
| 斜面を滑る／止まる | できない | 摩擦とクーロンの法則 | 第 36 章 |
| 押されて転ぶ | できない | 角速度と慣性モーメント | 第 35・36 章 |
| 積み上げが深く沈まない | 不十分（8.5 cm） | 反復ソルバとウォームスタート | 第 37 章 |
| 静止したら計算を止める | できない | スリープ処理 | 第 37.4 節 |

**「できない」の三つは、いずれも速度を扱わないことに由来する。** 位置だけを見ていると、「どれだけの勢いでぶつかったか」という情報がそもそも存在しない。

### 現代のエンジンにも残っている

位置補正は「素朴な入門用の手法」ではない。**現在も実用的に使われている。**

- 第 37.3 節の Baumgarte 安定化は、位置補正を速度の制約に翻訳したものである
- **位置ベース動力学（PBD/XPBD）**は、この章のやり方を一般の拘束へ拡張した体系である。布・ロープ・ソフトボディで主流になっている
- 第 38 章のキャラクターコントローラは、実質的に位置補正だけで動く

**「速度を経由せず、位置を直接直す」という発想は、安定性の面で優れている。** 力積による応答は、条件が悪いと発散する（第 37.5 節）。位置補正は、押し戻しすぎない限り発散しない。

### パイプラインのどこに入るか

第 33.1 節の 5 段構成に、この章の処理を差し込む。

```cpp
void World::step(float dt) {
    // 1〜4. AABB 更新 → 候補収集 → フィルタとナローフェーズ → 期限切れ（第 33 章）
    broadphase_and_narrowphase(dt);

    // 5. 応答
    integrate_velocity(dt);                     // 第 35 章（この章ではまだ重力だけ）
    for (int i = 0; i < correction_iterations_; ++i)
        for (const PairKey key : solve_order_)  // ★ 順序を固定する（34.2 節）
            correct_positions(key);
    cancel_normal_velocities();
    integrate_position(dt);
}
```

**`solve_order_` は第 33.2 節で `PairKey` によってソートした順序である。** ここで初めて、その仕込みが効く。

## 34.2 複数接触が競合するときの順序依存

### 直しても直せないことがある

物体が二方向から挟まれると、**両方のめり込みを同時に消すことができない**。

幅 1.0 m の箱を、幅 0.9 m の通路に置く。左右の壁に 50 mm ずつめり込む。どう動かしても、どちらかにはめり込んだままである。

**このとき、処理する順序によって結果が変わる。**

| 反復 | 昇順で処理 | 逆順で処理 | 差 |
|---:|---:|---:|---:|
| 1 | −0.050 | +0.050 | 100 mm |
| 4 | −0.050 | +0.050 | 100 mm |
| 64 | −0.050 | +0.050 | 100 mm |
| 256 | −0.050 | +0.050 | **100 mm** |

**反復回数をいくら増やしても、差は縮まらない。** 「反復すれば収束する」という直感は、**制約が矛盾しているときには成り立たない**。

理由は単純である。左の壁を先に処理すると箱は右へ 50 mm 動き、右の壁のめり込みが 100 mm になる。次に右の壁を処理すると 100 mm 左へ戻る。結果として箱は左に寄る。順序を逆にすれば右に寄る。**どちらも「正しい」答えであり、選ぶ理由がない。**

### Gauss-Seidel と Jacobi

上の実験は、**接触ごとにその場でめり込みを測り直す**やり方である。数値計算では **Gauss-Seidel 法**と呼ぶ。

もう一つのやり方がある。**すべての接触のめり込みを先に全部測り、それから一括で適用する。Jacobi 法**である。

```cpp
// Jacobi：測る段階と適用する段階を分ける
void correct_jacobi(std::span<const ContactPair> pairs, const CorrectionConfig& cfg) {
    std::vector<Vec2> delta(bodies.size(), Vec2{});

    for (const ContactPair& c : pairs) {            // ① 全部測る
        const float amount = compute_amount(c, cfg);
        delta[c.a] -= c.normal * (amount * body(c.a).inv_mass);
        delta[c.b] += c.normal * (amount * body(c.b).inv_mass);
    }
    for (std::size_t i = 0; i < bodies.size(); ++i)  // ② 一括で適用
        bodies[i].position += delta[i];
}
```

同じ通路の実験を Jacobi でやると、**順序によらず箱は x = 0 のまま**になる。左右から同じだけ押されて釣り合うからである。

| 手法 | 昇順 | 逆順 | 順序依存 | 結果 |
|---|---:|---:|---|---|
| Gauss-Seidel | −0.050 | +0.050 | **あり** | どちらかの壁から離れる |
| Jacobi | 0.000 | 0.000 | なし | **両方に 50 mm めり込んだまま** |

**Jacobi は対称だが、何も解決していない。** そして一般に収束が遅い。同じ回数の反復で、Gauss-Seidel のほうが深く直せる。

### 本書の選択

**Gauss-Seidel を使い、順序を固定する。**

順序依存そのものは消せない。**消せないなら、せめて再現可能にする。** 第 33.2 節で `PairKey` によるソート順を導入したのは、まさにこのためである。

```cpp
// 第 33.2 節の build_solve_order() で作った順序を、毎フレーム同じように使う
for (const PairKey key : solve_order_) {
    ContactPair& c = pairs_[key];
    correct_positions(body(key.first()), body(key.second()), c.manifold, cfg);
}
```

**「物理的に一意な答えがない」ことと「実行のたびに答えが変わる」ことは別問題である。** 前者は受け入れるしかないが、後者は設計で防げる。

## 34.3 ジッタが起きる理由と、スロップ

### 筆者はここで間違えた

本章のコードを最初に書いたとき、**箱が床から 28 センチ浮いた状態で激しく振動した。**

| 方式 | slop | 平均 y（理想 0.5） | 振れ幅 | 平均速度 |
|---|---:|---:|---:|---:|
| **接触点ごとに適用** | 0 mm | **0.782** | 61.5 mm | **45.1 m/s** |
| 接触点ごとに適用 | 1 mm | 0.781 | 61.5 mm | 45.1 m/s |
| 接触点ごとに適用 | 5 mm | 0.496 | 0.0 mm | 0.0 m/s |
| **接触ペアごとに一度** | 0 mm | **0.499** | **0.0 mm** | **0.0 m/s** |

**原因は接触点の数だった。** 第 14 章のマニフォールドは、面と面が接するとき **2 点**を返す。その 2 点それぞれに対して補正を適用すると、**押し出す量が 2 倍になる。**

押しすぎると物体は面から完全に離れる。離れると次の検出で接触が見つからない。**接触が見つからないと、`cancel_normal_velocity` が呼ばれない。** 重力による速度が消されないまま毎フレーム積み上がり、45 m/s に達していた。

そして翌フレームには深くめり込み、また 2 倍押し出される。**この往復が振動の正体だった。**

**症状は「当たり判定がおかしい」ようにしか見えなかった。** 箱が宙に浮いて震えているのだから、まず疑ったのはマニフォールドである。第 14 章のテストを全部走らせても何も落ちず、原因にたどり着くまで時間を溶かした。

**正しい実装は、接触ペアごとに一度だけ適用することである。**

```cpp
// 誤り：点ごとに適用すると、点の数だけ押し出しが重複する
for (const ContactPoint& p : m.points) correct_positions(a, b, p, cfg);

// 正：ペアごとに一度。深さは最大値を代表として使う
correct_positions(a, b, m, cfg);
```

点ごとに扱いたい場合は、**点の数で割る**。ただし位置補正では「最も深い点を直せば他も浅くなる」ので、最大値を使うほうが素直である。

> **押し出しすぎると接触が消える**——この構造は、位置補正に限らず衝突応答全体に共通する落とし穴である。第 37.3 節の Baumgarte 安定化でも同じ理由で係数を 1 未満にする。

### スロップは何のためにあるのか

`slop`（許容めり込み）は、**接触を生かしておくためにある。**

めり込みをちょうどゼロまで直すと、次の検出で接触が見つからない。見つからなければ速度も消せず、次のフレームでまた沈む。**接触が「ついたり消えたり」する状態そのものが、ジッタの温床である。**

**わざと少しめり込ませたままにしておけば、接触は毎フレーム安定して見つかる。**

`percent` を 1 未満にするのも同じ狙いである。`percent = 0.8` なら、一度の補正で 80% しか直さない。残り 20% が接触を保つ。

**二つは目的が同じで、効き方が違う。**

| 仕掛け | 残るめり込み | 特徴 |
|---|---|---|
| `slop` | 常に一定（1 mm） | 深さによらず一定量残る |
| `percent` | 深さに比例（20%） | 深いほど多く残り、浅いほど速く収束 |

**両方使うのがよい。** 深いめり込み（トンネリング直後など）は `percent` が段階的に直し、浅いところは `slop` が安定させる。

### 反復回数と収束

反復を増やすと、深い箇所まで直る。だが**反復 1 回で情報が伝わるのは接触 1 段ぶんだけ**である。

10 段積みなら、いちばん上の箱の重みが床まで伝わるのに、最低 10 回の反復が要る。

| 反復回数 | 最大めり込み | 最上段の y（理想 9.5） |
|---:|---:|---:|
| 1 | 60.65 mm | 9.1639 |
| 2 | 30.99 mm | 9.3189 |
| 4 | 15.83 mm | 9.4049 |
| 8 | 8.16 mm | 9.4482 |
| 16 | 4.35 mm | 9.4698 |

**反復を倍にすると、めり込みはおよそ半分になる。** きれいな比例関係だが、裏を返せば **1 mm まで詰めるには 64 回以上の反復が要る**ということでもある。

**これが第 37 章のウォームスタートを導入する動機である。** 前フレームの結果を覚えていれば、反復をやり直さなくてよい。

### スロップの値をどう決めるか

第 5.9 節で `contact_slop = 1.0e-3f`（1 mm）と決めた。**この値は「見えないが、ゼロではない」という条件から来ている。**

- 1 mm は、1 m の物体に対して 0.1%。カメラが寄っても、まず見えない
- 一方、`float` の有効桁からは十分に離れており、丸め誤差に埋もれない

**もう一つの目安がある。1 フレームに重力で沈む量である。**

```
g · dt² = 10 m/s² × (1/60 s)² ≒ 2.8 mm
```

**スロップがこれより大きければ、重力による沈み込みは「許容範囲内」に収まり、補正が一度も呼ばれない。** 逆に小さいと、毎フレーム補正が走る。

どちらが良いかは目的による。**本書は 1 mm（見た目優先）を既定にし、積み上げの安定性が問題になる場面では 5 mm まで上げてよい**という方針を採る。上の表のとおり、5 mm でも沈み込みは 2 cm 程度である。

---

### 深いめり込みをどう扱うか

トンネリング（第 17 章）や物体のスポーンで、**いきなり深くめり込んだ状態から始まる**ことがある。

`percent = 0.8` のまま処理すると、1 フレームで 80% が押し戻される。**深さが 5 m なら 4 m 飛ぶ。** 見た目に破綻するし、飛んだ先で別の物体にめり込む。

**補正量に上限を設ける。**

```cpp
struct CorrectionConfig {
    float slop{contact_slop};
    float percent{0.8f};
    float max_correction{0.2f};   // 1 フレームに押し戻す上限（m）
};

const float amount = std::min(cfg.max_correction,
                              std::max(0.0f, depth - cfg.slop) * cfg.percent)
                   / total_inv_mass;
```

**上限 0.2 m は「1 フレームで 20 cm 以上は動かさない」という意味である。** 深いめり込みは数フレームかけてゆっくり解消される。

**「速く直す」より「暴れずに直す」を選ぶ。** 第 37.3 節の Baumgarte 安定化でも、まったく同じ判断をすることになる。

> **なぜ上限が要るのかは、単位系から説明できる**
> 第 5.9 節で 1 単位 = 1 メートルと決めた。60 fps で 0.2 m は毎秒 12 m、時速 43 km に相当する。**押し戻しでこれ以上の速さが出るのは、明らかに異常である。**
>
> 単位系を明文化しておくと、こうした閾値を「勘」ではなく「意味」で決められる。第 0 部でしつこく単位を確認した見返りが、応答の章でも出ている。

## 34.4 テスト：積み上げた箱が静止すること

### 何を検証するのか

**位置を検証してはいけない。** 「300 フレーム後に最上段の y が 9.4149 であること」というテストを書くと、実装をわずかに変えるたびに落ちる。

**検証すべきは性質である。**

| 性質 | 具体的な検査 |
|---|---|
| 静止する | 十分な時間のあと、速度が閾値以下 |
| 沈みすぎない | めり込みが上限以下 |
| 崩れない | 各箱の x が初期値から大きくずれない |
| 順序が再現する | 同じ入力で 2 回走らせて同じ結果 |

```cpp
// test_position_correction.cpp
TEST_CLASS(PositionCorrectionTest) {
public:
    TEST_METHOD(十段積みが静止すること) {
        auto world = make_box_stack(/*count=*/10, /*size=*/1.0f);

        for (int frame = 0; frame < 300; ++frame) world.step(1.0f / 60.0f);

        // ① 静止している
        for (const RigidBody& b : world.dynamic_bodies())
            Assert::IsTrue(length(b.velocity) < min_speed,      // 第 5.9 節：1 mm/s
                std::format(L"速度 {:.5f} m/s", length(b.velocity)).c_str());

        // ② 沈みすぎていない（1 個あたり slop の 3 倍まで）
        const float sink = 9.5f - world.body(10).position.y;
        Assert::IsTrue(sink < 10 * contact_slop * 3.0f,
                       std::format(L"沈み込み {:.4f} m", sink).c_str());

        // ③ 横に崩れていない
        for (const RigidBody& b : world.dynamic_bodies())
            expect_near(0.0f, b.position.x, 1.0e-2f, 1.0e-2f);
    }
```

**② の閾値を「箱の数 × slop × 3」という式で書く**のが要点である。段数を変えてもテストが生き残る。定数を直接書くと、シーンを変えるたびに書き直すことになる。

### ジッタを検出する

「静止している」だけでは、**微小な振動を見逃す**。速度が閾値以下でも、位置が毎フレーム上下しているかもしれない。

**位置の履歴を取り、振れ幅を見る。**

```cpp
    TEST_METHOD(静定後に振動していないこと) {
        auto world = make_box_stack(10, 1.0f);
        for (int frame = 0; frame < 240; ++frame) world.step(1.0f / 60.0f);

        // 静定したあと 60 フレーム分の位置を記録する
        float lo = std::numeric_limits<float>::max();
        float hi = std::numeric_limits<float>::lowest();
        for (int frame = 0; frame < 60; ++frame) {
            world.step(1.0f / 60.0f);
            const float y = world.body(10).position.y;
            lo = std::min(lo, y); hi = std::max(hi, y);
        }

        // 振れ幅が slop の 10 分の 1 未満（実測は 0.006 mm）
        Assert::IsTrue(hi - lo < contact_slop * 0.1f,
            std::format(L"振れ幅 {:.6f} m（許容 {:.6f}）",
                        hi - lo, contact_slop * 0.1f).c_str());
    }
```

**このテストが、34.3 節のバグを捕まえる。** 二重適用があると振れ幅は 61 mm になり、閾値の 0.1 mm を大きく超える。

### 順序依存を検証する

矛盾する制約では答えが一意に決まらないことを、**テストとして明示しておく。**

```cpp
    TEST_METHOD(順序を固定すれば結果が再現すること) {
        const auto run_once = [] {
            auto world = make_wedged_box();     // 幅 0.9 の通路に幅 1.0 の箱
            for (int f = 0; f < 100; ++f) world.step(1.0f / 60.0f);
            return world.body(1).position;
        };
        const Vec2 a = run_once();
        const Vec2 b = run_once();
        expect_near(a, b, 0.0f, 0.0f);   // 同じ順序なら完全に同じ値になる
    }

    TEST_METHOD(既知の制約_矛盾する接触では答えが一意でないこと) {
        // 34.2 節の実測をテストとして残す。
        // 「バグではなく仕様」であることをコードで宣言する意味がある
        const float forward = solve_corridor(/*reverse=*/false);
        const float reverse = solve_corridor(/*reverse=*/true);
        Assert::IsTrue(std::abs(forward - reverse) > 0.09f,
                       L"順序依存が消えている。実装が変わった可能性がある");
    }
};
```

**二つ目のテストは「差があること」を検査している。** 奇妙に見えるが、意図がある。将来この差が消えたら、**誰かが Jacobi に変えたか、収束の性質が変わった**ということである。**知っている性質は、良いものも悪いものもテストに書く。**

第 9 章で「既知の制約」をテストとして残したのと同じ考え方である。

## この章のまとめ

- 位置補正は**法線方向に、逆質量の比で配分して押し戻す**だけ。10 行に満たない
- **押し戻すだけでは足りない。** 近づく向きの速度成分も消す必要がある
- 10 段積みは**静止する**（振れ幅 0.006 mm）が、**8.5 cm 沈む**。跳ねず、滑らず、転ばない
- **補正は接触ペアごとに一度だけ適用する。** 点ごとに適用すると押し出しが 2 倍になる
- 二重適用の症状は「箱が 28 cm 浮いて 45 m/s で振動する」。**当たり判定のバグにしか見えない**
- 矛盾する制約では**順序依存が消えない**。反復を 256 回に増やしても 100 mm の差が残る
- **Jacobi は順序依存を消すが、何も解決しない**うえ収束が遅い。Gauss-Seidel ＋ 順序固定を採る
- **スロップは接触を生かしておくためにある。** ゼロまで直すと接触が消え、速度を消せなくなる
- `slop`（一定量）と `percent`（比例）は目的が同じで効き方が違う。**両方使う**
- スロップの目安は「見えない大きさ」と「`g·dt²` ≒ 2.8 mm」の二つ
- 反復を倍にするとめり込みは約半分。**1 mm まで詰めるには 64 回以上**が要る
- **足りないもの（跳ね返り・摩擦・回転）は、すべて速度を扱わないことに由来する**
- 位置補正は入門用の手法ではない。**PBD/XPBD として現役**であり、発散しない強みがある
- パイプラインでは**第 33.2 節でソートした順序**をここで使う
- テストは**位置ではなく性質**。静止・沈み込み上限・崩れない・再現する
- **振れ幅を測るテスト**を書く。速度だけでは微振動を見逃す

### 落とし穴と練習問題

**落とし穴 1：接触点ごとに位置補正を適用する。**　押し出しが点数倍になり、激しく振動する。

**落とし穴 2：離れていく速度まで消す。**　床の上の物体が跳ねなくなるどころか、貼り付いて動かなくなる。

**落とし穴 3：`slop` をゼロにする。**　「めり込みは完全に消すべき」という直感が、ジッタを生む。

**落とし穴 4：順序を `unordered_map` の走査順に任せる。**　実行のたびに結果が変わる（第 33.2 節）。

**落とし穴 5：テストで位置を厳密に検証する。**　実装を少し変えるだけで落ち、やがて誰も直さなくなる。

**落とし穴 6：補正量に上限を設けない。**　トンネリング直後の深いめり込みから、物体が数メートル飛ぶ。

**落とし穴 7：静的どうしのペアで無限ループに入る。**　`total_inv_mass == 0` の早期リターンを忘れると、ゼロ除算で `Inf` が伝播する。`/fp:fast` では静かに広がる（第 4.5 節）。

次章では、**位置ではなく速度を扱う**ところへ進む。質量・慣性モーメント・角速度を導入し、力を積分して運動を作る。この章で「跳ねない・滑らない・転ばない」と書いた三つのうち、**転ぶ**を可能にするのが回転の導入である。そして半陰的オイラー法という、ゲーム物理でほぼ唯一使われる積分法の性質を、解析解と突き合わせて確かめる。
