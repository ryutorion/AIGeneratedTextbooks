# 第 37 章　逐次力積ソルバ

> **この章のゴール**
> 接触が 1 個なら第 36 章の式で終わる。**接触が複数あると、一つを解いた先で別の一つが壊れる。**
>
> 逐次力積法は、全接触を順に解くことを何度も繰り返して、全部が「だいたい満たされる」状態へ近づける。単純だが、実用的な剛体シミュレーションの中核である。
>
> そこに**ウォームスタート**を足すと効果が劇的に変わる。10 段積みの沈み込みが **4.6 分の 1** になり、反復 8 回で `slop` と同じ深さまで収束する。実測で示す。
>
> そして `/fp:fast` の下で反復ソルバを走らせるとき、何に気をつけるべきかを整理する。

---

## 37.1 複数の接触を反復で解く

### 一つ解くと別の一つが壊れる

箱を 3 段積む。上の箱を支えるために中段が力積を受ける。**その力積が中段の速度を変えるので、中段と下段の接触が満たされなくなる。**

下段を解き直すと、今度は上段が壊れる。**同時に解く連立方程式を、行列を組まずに近似的に解きたい。**

**逐次力積法（Sequential Impulse）の答えは単純である。順に解くのを何度も繰り返す。**

```cpp
// collision/dynamics/solver.h
void Solver::solve_velocity(std::span<ContactConstraint> constraints, int iterations) {
    for (int iter = 0; iter < iterations; ++iter)
        for (ContactConstraint& c : constraints)
            solve_one(c);            // 第 36 章の法線＋摩擦
}
```

これは Gauss-Seidel 反復そのものである（第 34.2 節）。**接触を一つ解いた結果が、次の接触の計算にすぐ反映される**ので、Jacobi より速く収束する。

### 制約をあらかじめ組み立てる

反復のたびに実効質量を計算し直すのは無駄である。**プリステップで一度だけ計算する。**

```cpp
struct ContactConstraint {
    std::uint32_t body_a{}, body_b{};
    Vec2  normal{};
    float friction{};
    float restitution{};

    struct Point {
        Vec2  ra{}, rb{};              // 各重心から接触点へのベクトル
        float normal_mass{};           // 法線方向の実効質量（第 36.3 節）
        float tangent_mass{};
        float bias{};                  // 位置補正のための目標速度（37.3 節）
        float normal_impulse{};        // 累積。ウォームスタートで引き継ぐ
        float tangent_impulse{};
        ContactId id{};                // 第 33.4 節の特徴 ID
    };
    std::array<Point, 2> points{};
    std::uint8_t point_count{};
};
```

```cpp
void Solver::prestep(ContactConstraint& c, float dt, const SolverConfig& cfg) {
    RigidBody& a = body(c.body_a);
    RigidBody& b = body(c.body_b);
    const Vec2 t = perpendicular(c.normal);

    for (std::uint8_t i = 0; i < c.point_count; ++i) {
        auto& p = c.points[i];
        p.normal_mass  = normal_effective_mass(a, b, p.ra, p.rb, c.normal);
        p.tangent_mass = normal_effective_mass(a, b, p.ra, p.rb, t);
        p.bias         = cfg.beta / dt * std::max(0.0f, p.depth - cfg.slop);

        // ウォームスタート：前フレームの力積をそのまま加える（37.2 節）
        const Vec2 impulse = c.normal * p.normal_impulse + t * p.tangent_impulse;
        apply_impulse_at(a, b, impulse, p.ra, p.rb);
    }
}
```

**`normal_effective_mass` を法線と接線の両方に使い回している**のが実装上の小技である。式の形が同じなので、方向を差し替えるだけでよい。

### 1 反復の中身

```cpp
void Solver::solve_one(ContactConstraint& c) {
    RigidBody& a = body(c.body_a);
    RigidBody& b = body(c.body_b);
    const Vec2 t = perpendicular(c.normal);

    for (std::uint8_t i = 0; i < c.point_count; ++i) {
        auto& p = c.points[i];

        // ① 法線：めり込みを解消する向きの相対速度を作る
        {
            const float vn = dot(relative_velocity(a, b, p.ra, p.rb), c.normal);
            const float delta = (-vn + p.bias) * p.normal_mass;

            const float old = p.normal_impulse;
            p.normal_impulse = std::max(0.0f, old + delta);   // 引っ張らない
            apply_impulse_at(a, b, c.normal * (p.normal_impulse - old), p.ra, p.rb);
        }

        // ② 摩擦：法線力積が決まったあとで、その上限にクランプする
        {
            const float vt = dot(relative_velocity(a, b, p.ra, p.rb), t);
            const float delta = -vt * p.tangent_mass;

            const float limit = c.friction * p.normal_impulse;
            const float old   = p.tangent_impulse;
            p.tangent_impulse = std::clamp(old + delta, -limit, limit);
            apply_impulse_at(a, b, t * (p.tangent_impulse - old), p.ra, p.rb);
        }
    }
}
```

**`std::max(0.0f, ...)` が「接触は押すだけで引っ張らない」という物理を表している。** これがないと、離れようとする物体を引き戻してしまう。

そして**クランプするのは累積値であり、適用するのは差分である。** 第 36.4 節で摩擦について述べたのと同じ構造が、法線にも当てはまる。

## 37.2 ウォームスタート

### 前フレームの答えは、今フレームの良い初期値である

物体はフレーム間でほとんど動かない（第 31.2 節でブロードフェーズについて見たのと同じ性質）。**ということは、必要な力積もほとんど同じである。**

**前フレームの力積を初期値として使えば、反復の出発点が答えのすぐ近くになる。**

```cpp
// 第 33.4 節の match_and_warm_start で、特徴 ID をたよりに引き継ぐ
void match_and_warm_start(const ContactConstraint& prev, ContactConstraint& next) {
    for (auto& np : next.points | std::views::take(next.point_count)) {
        for (const auto& op : prev.points | std::views::take(prev.point_count)) {
            if (np.id == op.id) {
                np.normal_impulse  = op.normal_impulse;
                np.tangent_impulse = op.tangent_impulse;
                break;
            }
        }
    }
}
```

引き継いだ値は、`prestep` の中で**そのまま剛体に加える**。反復はその状態から差分を求めることになる。

### どれだけ効くのか

1 m 角の箱を 10 段積み、3 秒間走らせて、**最後の 30 フレームの平均**を測った（`slop = 5 mm`）。

| 反復 | ウォームなし めり込み | 残留速度 | ウォームあり めり込み | 残留速度 |
|---:|---:|---:|---:|---:|
| 1 | 108.4 mm | 3.26 m/s | 7.5 mm | 6.69 m/s |
| 2 | 17.3 mm | 6.09 m/s | 25.5 mm | 1.36 m/s |
| 4 | 51.0 mm | 0.211 m/s | 15.1 mm | 0.864 m/s |
| **8** | 25.3 mm | 0.0094 m/s | **5.08 mm** | 0.0174 m/s |
| 16 | 20.1 mm | 0.0443 m/s | **4.92 mm** | 0.00003 m/s |
| 32 | 9.4 mm | 0.0045 m/s | **5.00 mm** | 0.00016 m/s |
| 64 | 6.9 mm | 0.00028 m/s | **5.00 mm** | 0.00001 m/s |

**ウォームスタートありは、反復 8 回で `slop = 5 mm` そのものに到達する。** これ以上は原理的に沈まない。

**なしは 64 回反復しても 6.9 mm で、`slop` に届かない。** そして反復回数を増やしても単調には減らず、途中で行きつ戻りつしている。

**実用的な反復回数（8〜10 回）で比べると、めり込みは 5 分の 1 である。**

### 段数を増やすとさらに差が開く

反復 10 回に固定して、段数を変えた。

| 段数 | ウォームなし | ウォームあり | 比 |
|---:|---:|---:|---:|
| 1 | 2.80 mm | 2.78 mm | 1.0 |
| 2 | 5.41 mm | 5.00 mm | 1.1 |
| 5 | 10.6 mm | 5.00 mm | 2.1 |
| **10** | **23.2 mm** | **5.00 mm** | **4.6** |
| 20 | 44.4 mm | 16.3 mm | 2.7 |
| 30 | 61.1 mm | 22.6 mm | 2.7 |

**ウォームスタートなしでは、めり込みが段数にほぼ比例して増える。** 30 段で 6 cm である。

**ありなら 10 段までは `slop` に張り付いたまま**で、それ以上でようやく増え始める。

理由は直感的である。**力を下まで伝えるには、接触の連鎖を通らなければならない。** 反復 1 回で情報は 1 段しか伝わらないので、10 段には最低 10 回の反復が要る。**ウォームスタートは、その伝達をフレームをまたいで記憶している。**

---

### 反復回数をどう決めるか

反復回数は、**予算と品質の直接のトレードオフ**である。

| 反復回数 | 用途 |
|---:|---|
| 4 | 接触が少ないゲーム。積み上げがない |
| **8〜10** | **標準。積み上げが 10 段程度まで安定する** |
| 20+ | 高い積み上げ、精密な機械仕掛け |

**コストは接触点の総数 × 反復回数にほぼ比例する。** 第 29.4 節のカウンタに「ソルバの反復回数 × 接触点数」を入れておくと、予算を見積もりやすい。

**そして反復回数はシーンによって変えてよい。** 島（第 37.4 節）ごとに、含まれる物体数に応じて反復回数を決める設計もある。**箱 2 個の島に 20 回まわすのは無駄である。**

### ブロックソルバという先の話

同じペアの 2 接触点は、**互いに強く影響し合う。** 片方を解くともう片方が壊れ、反復を何度も往復することになる。

**2 点を連立方程式として一度に解く**手法がある（ブロックソルバ）。2×2 の行列を解くだけなので閉じた形で書け、収束が目に見えて速くなる。

**本書では実装しない。** 場合分け（どちらか片方だけが有効な場合を含めて 4 通り）が煩雑で、得られる改善はウォームスタートほど大きくない。**ウォームスタートを先に入れるべきである**——これが 37.2 節の実測から言えることである。

## 37.3 位置補正の再訪 ― Baumgarte 安定化とソフト拘束

### 速度だけでは、めり込みは直らない

第 36 章の力積は「相対速度をゼロにする」ものであって、**すでにめり込んでいる分は直さない。** 沈んだ箱は沈んだままになる。

**Baumgarte 安定化**は、めり込みの深さを目標速度に変換して、速度の制約に混ぜ込む。

```cpp
p.bias = cfg.beta / dt * std::max(0.0f, p.depth - cfg.slop);
```

**「`dt` 秒で、めり込みの `beta` 倍を解消する速度」**である。`beta = 0.2` なら、1 フレームで 20% ずつ直る。

第 34.3 節と同じ理由で、**`beta` は 1 未満にする。** 1 にすると 1 フレームで完全に押し出し、接触が消えてジッタになる。

```cpp
struct SolverConfig {
    int   velocity_iterations{10};
    float beta{0.2f};                    // Baumgarte 係数
    float slop{contact_slop};            // 第 5.9 節：1 mm
    float max_linear_correction{0.2f};   // 1 フレームの補正上限（m）
};
```

### bias が持ち込むエネルギー

**Baumgarte には副作用がある。** 押し出す速度は「どこからともなく」与えられるので、**系にエネルギーが注入される。**

深くめり込んだ物体が勢いよく飛び出す現象は、これが原因である。

対策は二つある。

**対策 1：補正量に上限を設ける。**

```cpp
p.bias = cfg.beta / dt
       * std::min(cfg.max_linear_correction,
                  std::max(0.0f, p.depth - cfg.slop));
```

**対策 2：bias による力積を、跳ね返りに使わせない。** 蓄積を法線力積とは別に持ち、位置補正専用の反復を分ける（Box2D の "position solver" にあたる）。より正確だが、実装が増える。

**本書は対策 1 を採る。** 上限 0.2 m は「1 フレームで 20 cm 以上は押し戻さない」という意味である。

### ソフト拘束という見方

`beta` を小さくすると、押し戻しがゆっくりになる。**ばねのように振る舞う。**

これを積極的に使う設計が**ソフト拘束**である。剛性と減衰をパラメータに取り、`bias` と実効質量の両方を調整する。

本書では扱わないが、**「`beta` は硬さのパラメータである」**という見方を持っておくと、値を調整するときの見通しがよくなる。

## 37.4 スリープ処理

### 動いていない物体を計算しない

積み上がった箱の山は、いずれ静止する。**静止した物体を毎フレーム解き続けるのは無駄である。**

```cpp
struct SleepState {
    float timer{};              // 静止し続けている時間
    bool  awake{true};
};

void update_sleep(RigidBody& b, SleepState& s, float dt, const SleepConfig& cfg) {
    const bool slow = length_squared(b.velocity) < cfg.linear_threshold_sq
                   && std::fabs(b.angular_velocity) < cfg.angular_threshold;

    s.timer = slow ? (s.timer + dt) : 0.0f;

    if (s.timer > cfg.time_to_sleep) {
        s.awake = false;
        b.velocity = Vec2{}; b.angular_velocity = 0.0f;   // 明示的にゼロへ（第 35.5 節）
    }
}
```

閾値は第 5.9 節の `min_speed`（1 mm/s）を基準にする。`time_to_sleep` は 0.5 秒程度が実用的である。

### 島（アイランド）単位で眠らせる

**接触でつながった物体は、まとめて眠らせなければならない。**

箱の山のうち 1 個だけ眠らせると、そこだけ力が伝わらなくなって山が崩れる。

```cpp
// 接触グラフの連結成分（島）を求め、島の全員が静止していれば島ごと眠らせる
void World::update_sleeping(float dt) {
    for (const Island& island : build_islands()) {
        const bool all_slow = std::ranges::all_of(island.bodies,
            [&](std::uint32_t i) { return is_slow(body(i)); });

        for (const std::uint32_t i : island.bodies)
            update_sleep(body(i), sleep_[i], all_slow ? dt : 0.0f, sleep_config_);
    }
}
```

**島の構築は Union-Find でも幅優先探索でもよい。** 接触ペアの数に対して線形で済む。

**静的剛体は島をつながない。** 床を経由して世界中の物体が一つの島になってしまう。

### 起こす条件

- 新しい接触が発生した
- 外部から力・力積が加わった
- ゲームロジックが明示的に起こした

**眠っている物体をブロードフェーズから外してはいけない。** 外すと、新しい物体が飛び込んできても検出できない。**AABB は木に残したまま、ソルバの対象から外す**のが正しい。

## 37.5 反復ソルバと `/fp:fast`

### 何が揺らぐのか

反復ソルバの結果は、次の三つで変わる。

| 要因 | 影響 | `/fp:fast` との関係 |
|---|---|---|
| **接触の処理順序** | 大きい | 無関係（第 34.2 節） |
| 浮動小数点の再結合 | 小さい | **あり** |
| 反復回数 | 大きい | 無関係 |

**最大の要因は順序であり、これは `/fp:fast` とは無関係である。** 第 33.2 節で `PairKey` によるソートを入れたのは、この最大の揺らぎを潰すためだった。

`/fp:fast` による再結合の影響は、それに比べればはるかに小さい。**だが反復ソルバは差を増幅する。** 1 反復目の 1 ULP の差が、10 反復後には目に見える差になりうる。

**結論として、`/fp:fast` の下では「同一バイナリ・同一マシンなら再現するが、ビルドを変えたら再現しない」。** 第 41.3 節で扱う方針そのままである。

### 発散を検出して打ち切る

**反復ソルバは、条件が悪いと発散する。** 質量比が極端（1 対 10,000）だったり、矛盾する制約が積み重なると、力積が指数的に増える。

**`/fp:fast` では `NaN` が静かに伝播する**（第 4.5 節）ので、気づいたときには全物体が消えている。

**安全弁を入れる。**

```cpp
// 1 フレームの終わりに一度だけ検査する。反復の中では検査しない（重い）
void World::guard_against_divergence() {
    for (RigidBody& b : bodies_) {
        // ① NaN / Inf を検出する（第 4.5 節のビットパターン検査）
        if (!is_finite_bits(b.velocity) || !is_finite_bits(b.angular_velocity)) {
            ++counters_.nan_resets;
            b.velocity = Vec2{}; b.angular_velocity = 0.0f;
            continue;
        }
        // ② 上限クランプ。物理的にありえない速度は切る
        const float v2 = length_squared(b.velocity);
        if (v2 > max_speed * max_speed) {
            b.velocity *= max_speed / std::sqrt(v2);
            ++counters_.speed_clamps;
        }
        b.angular_velocity = std::clamp(b.angular_velocity,
                                        -max_angular_speed, max_angular_speed);
    }
}
```

**`is_finite_bits` を使うのが要点である。** `/fp:fast` では `x != x` による `NaN` 判定がコンパイラに削除されうる（第 4.5 節）。ビットパターンで見るしかない。

**そして `nan_resets` をカウンタに残す。** 黙って直すと、原因を追う手がかりが消える。第 29.4 節の「決定論的な仕事量を測る」の応用である。

`max_speed` は単位系から決める。1 単位 = 1 m なら、**音速（340 m/s）を超える剛体はまず異常**である。

### `precise` に戻す価値があるか

第 4.6 節の判断基準は「呼び出し回数が少なく、制御フローが壊れる箇所」だった。

**ソルバは呼び出し回数が非常に多い。** 10 段積みで接触 20 個 × 2 点 × 10 反復 = 400 回／フレーム。ここを `precise` にすると、最適化の抑止も含めて確実に遅くなる。

**そして制御フローは壊れない。** `std::max(0.0f, ...)` や `std::clamp` の境界が 1 ULP ずれても、次の反復で吸収される。**反復法は、小さな誤差に対して自己修復的である。**

**結論：ソルバ本体は `/fp:fast` のままでよい。** 例外は「発散の検出」だけで、そこはビット検査なので浮動小数点演算を通らない。

**ただし測ってから決めること。** 第 29.3 節のとおり、`precise` ビルドを用意して比較するのは難しくない。第 40.6 節で `precise` 領域の棚卸しをするとき、この判断も一覧に載せる。

## 37.6 テスト：安定性という性質を検証する

### 位置ではなく性質

10 段積みの最終位置を期待値として書いてはいけない。反復回数を 10 から 12 に変えただけで落ちる。

**検証すべきは「性質」である。**

```cpp
// test_solver.cpp
TEST_CLASS(SequentialImpulseTest) {
public:
    TEST_METHOD(十段積みの沈み込みが閾値以下であること) {
        auto world = make_box_stack(10, 1.0f);
        world.config().velocity_iterations = 10;

        for (int frame = 0; frame < 300; ++frame) world.step(1.0f / 60.0f);

        // 実測 5.00 mm。slop（1 mm）の 3 倍を上限とする
        const float pen = world.max_penetration();
        Assert::IsTrue(pen < contact_slop * 3.0f,
            std::format(L"最大めり込み {:.4f} m（上限 {:.4f}）",
                        pen, contact_slop * 3.0f).c_str());
    }

    TEST_METHOD(ウォームスタートが実際に効いていること) {
        const auto measure = [](bool warm) {
            auto w = make_box_stack(10, 1.0f);
            w.config().warm_starting = warm;
            w.config().velocity_iterations = 10;
            for (int f = 0; f < 300; ++f) w.step(1.0f / 60.0f);
            return w.max_penetration();
        };
        const float with    = measure(true);
        const float without = measure(false);

        Logger::WriteMessage(std::format("あり {:.4f} / なし {:.4f}（比 {:.2f}）\n",
                                         with, without, without / with).c_str());
        Assert::IsTrue(without > with * 2.0f,
                       L"ウォームスタートの効果が消えています");
    }
```

**二つ目のテストは「効果が 2 倍以上あること」を検査している。** 実測は 4.6 倍なので余裕がある。**将来ウォームスタートが壊れたら（特徴 ID の対応づけが崩れるなど）、このテストが捕まえる。**

第 31.5 節の「交換回数の上限」と同じ発想である。**性能に効く仕掛けは、それが効いていること自体をテストする。**

### 崩れないこと

```cpp
    TEST_METHOD(積み上げが横に崩れないこと) {
        auto world = make_box_stack(10, 1.0f);
        for (int frame = 0; frame < 600; ++frame) {
            world.step(1.0f / 60.0f);
            for (const RigidBody& b : world.dynamic_bodies()) {
                Assert::IsTrue(std::fabs(b.position.x) < 0.05f,
                    std::format(L"フレーム {} で横ずれ {:.4f} m",
                                frame, b.position.x).c_str());
                Assert::IsTrue(std::fabs(b.rotation) < 0.05f, L"傾いています");
            }
        }
    }
```

**毎フレーム検査する**のが要点である。最後だけ見ると、「途中で崩れて偶然元に戻った」を見逃す。そして落ちたときに**フレーム番号が分かる**ので、原因の特定が速い。

### 発散の安全弁

```cpp
    TEST_METHOD(極端な質量比でも発散しないこと) {
        // 1 kg の箱の上に 10,000 kg の箱を載せる（現実には起こらないが、防御は必要）
        auto world = make_extreme_mass_ratio_stack();
        for (int frame = 0; frame < 300; ++frame) world.step(1.0f / 60.0f);

        for (const RigidBody& b : world.dynamic_bodies()) {
            Assert::IsTrue(is_finite_bits(b.position), L"NaN が発生しました");
            Assert::IsTrue(length(b.velocity) <= max_speed, L"速度が上限を超えました");
        }
        // 安全弁が発動したこと自体は許容する。ただし記録に残っていること
        Logger::WriteMessage(std::format("NaN リセット {} 回 / 速度クランプ {} 回\n",
            world.counters().nan_resets, world.counters().speed_clamps).c_str());
    }

    TEST_METHOD(スリープした島が起きないこと) {
        auto world = make_box_stack(5, 1.0f);
        for (int f = 0; f < 600; ++f) world.step(1.0f / 60.0f);

        for (const auto& s : world.sleep_states())
            Assert::IsFalse(s.awake, L"10 秒経っても眠っていません");

        // 眠ったあとに位置が動かないこと
        const auto before = world.snapshot_positions();
        for (int f = 0; f < 300; ++f) world.step(1.0f / 60.0f);
        expect_near(before, world.snapshot_positions(), 0.0f, 0.0f);
    }
};
```

**最後のテストは厳密比較（許容誤差 0）を使っている。** 眠っている物体は積分すらされないので、位置は**ビット単位で不変**であるべきである。**「計算していないこと」の検証には、厳密比較が正しい。**

第 3.5 節で禁じたのは「計算結果の一致をビットで比較する」ことであって、「計算していないことの確認」は別である。第 35.6 節の速度クランプのテストと同じ理屈である。

## この章のまとめ

- 逐次力積法は**全接触を順に解くのを反復する**。行列を組まない Gauss-Seidel 反復
- 実効質量は**プリステップで一度だけ**計算し、逆数で保持して使い回す
- 法線は `std::max(0, ...)` でクランプ。**接触は押すだけで引っ張らない**
- **クランプするのは累積値、適用するのは差分。** 法線も摩擦も同じ構造
- **ウォームスタートは前フレームの力積を初期値にする。** 特徴 ID で対応づける
- 実測：10 段積み・反復 10 回で、めり込みが **23.2 mm → 5.00 mm（4.6 分の 1）**
- ウォームスタートありは**反復 8 回で `slop` に到達**する。なしは 64 回でも届かない
- なしではめり込みが**段数にほぼ比例**。30 段で 6 cm
- 力の伝達には段数ぶんの反復が要る。**ウォームスタートはそれをフレーム間で記憶している**
- **Baumgarte 安定化**は、めり込みを目標速度 `beta/dt · (depth − slop)` に変換する
- `beta` は 1 未満。**補正量に上限を設けないと、深いめり込みから物体が飛び出す**
- スリープは**島（連結成分）単位**で。1 個だけ眠らせると山が崩れる
- 眠っている物体も**ブロードフェーズには残す**。外すと新しい接触を検出できない
- 結果の揺らぎの最大要因は**順序**であり、`/fp:fast` とは無関係
- **ソルバ本体は `/fp:fast` のままでよい。** 反復法は小さな誤差に対して自己修復的
- 発散の安全弁は入れる。**`is_finite_bits` によるビット検査 ＋ 速度クランプ ＋ カウンタ記録**
- 反復回数は 8〜10 が標準。**島ごとに変えてもよい**（箱 2 個に 20 回は無駄）
- **ブロックソルバより先にウォームスタートを入れる。** 効果の桁が違う
- テストは**性質**。沈み込みの上限、ウォームスタートの効果、毎フレームの崩れ検査

### 落とし穴と練習問題

**落とし穴 1：ウォームスタートで力積を「加算」ではなく「代入」する。**　累積の意味が壊れ、収束が悪化する。

**落とし穴 2：法線のクランプを忘れる。**　接触が物体を引っ張り、離れられなくなる。

**落とし穴 3：`beta` を 1.0 にする。**　1 フレームで完全に押し出し、接触が消えてジッタになる。

**落とし穴 4：物体を 1 個ずつ眠らせる。**　積み上げの途中が眠って山が崩れる。島単位で判定する。

**落とし穴 5：`NaN` を黙って直す。**　症状は消えるが原因が追えなくなる。必ずカウンタに残す。

**落とし穴 6：`x != x` で `NaN` を検出する。**　`/fp:fast` では削除されうる。ビットで見る。

**落とし穴 7：接触が消えた次のフレームも力積を引き継ぐ。**　特徴 ID が一致しないのに位置の近さで対応づけると、無関係な力積が注入されて物体が飛ぶ。

**落とし穴 8：眠っている物体をブロードフェーズから外す。**　新しい物体が飛び込んでも検出できず、すり抜ける。

**落とし穴 9：反復の内側で `NaN` を検査する。**　接触点 × 反復回数ぶんの検査になり、目に見えて遅くなる。フレームの終わりに一度でよい。
