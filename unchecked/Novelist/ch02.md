# 第2章 uvでプロジェクトを作る

この章では、Pythonのプロジェクト管理ツール **uv** を使って `novelist` プロジェクトを作ります。章の終わりには、次の状態になっています。

- `uv run novelist` でCLIが起動し、`version` と `env` の2つのサブコマンドが動く
- 依存ライブラリのバージョンが `uv.lock` に固定されている
- `pytest` によるテストと、`ruff` によるLint・フォーマットが実行できる
- Gitで管理され、別のマシンでも同じ環境を再現できる

ここで作る土台に、第3章以降で機能を積み上げていきます。

## 2.1 uvとは

uvは、Rustで書かれたPythonのパッケージ・プロジェクト管理ツールです。これまで複数のツールを組み合わせて行っていた作業を、1つのコマンドで扱えます。

| これまでの道具 | 役割 | uvでは |
|---|---|---|
| pyenv など | Python本体のインストールと切り替え | `uv python install` |
| venv | 仮想環境の作成 | `uv venv`（多くの場合は自動） |
| pip | パッケージのインストール | `uv add` / `uv sync` |
| pip-tools / Poetry | 依存関係の解決とロックファイル | `uv lock`（`uv.lock`） |
| pipx | CLIツールの独立インストール | `uv tool install` |

本書でuvを使う理由は3つあります。

1. **速い**：依存関係の解決とインストールがとても速く、ライブラリの追加や入れ替えを気軽に試せます。
2. **再現できる**：`uv.lock` に、間接的な依存まで含めたすべてのパッケージのバージョンとハッシュが記録されます。本書と同じ環境を確実に作れます。
3. **仮想環境を意識しなくてよい**：`uv run` を付けてコマンドを実行すると、仮想環境の作成・同期・有効化を自動で行います。`activate` を忘れて別の環境のPythonで実行してしまう、といった事故が起きません。

## 2.2 uvをインストールする

### Linux / macOS

```console
$ curl -LsSf https://astral.sh/uv/install.sh | sh
```

Homebrewを使っている場合は、次のコマンドでもインストールできます。

```console
$ brew install uv
```

### Windows

PowerShellで次のどちらかを実行します。

```powershell
PS> powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

```powershell
PS> winget install --id=astral-sh.uv -e
```

### 確認

インストールが終わったら、**ターミナルを開き直して**からバージョンを確認します。インストーラーがPATHを書き換えるので、開き直さないと `uv` コマンドが見つからないことがあります。

```console
$ uv --version
uv 0.8.17
```

表示されるバージョンは、インストールした時期によって異なります。本書の手順は、この章を書いた時点のバージョンで確認しています。

公式のインストーラー（`curl` や `irm`）で入れた場合は、次のコマンドでuv自体を更新できます。Homebrewやwingetで入れた場合は、それぞれのツールで更新してください。

```console
$ uv self update
```


インストール済みのPythonは、次のコマンドで確認できます。OSに最初から入っているPythonも一緒に表示されます。

```console
$ uv python list --only-installed
```

## 2.4 プロジェクトを作る

作業用のディレクトリに移動して、プロジェクトを作ります。

```console
$ uv init --package --python 3.12 novelist
Initialized project `novelist` at `/home/you/novelist`
$ cd novelist
```

`--package` を付けると、**パッケージ形式**のプロジェクトになります。付けない場合（アプリケーション形式）との違いは次のとおりです。

| | `--package` なし | `--package` あり（本書） |
|---|---|---|
| ソースの置き場所 | ルート直下の `main.py` | `src/novelist/`（srcレイアウト） |
| ビルドの設定 | なし | `[build-system]` が入る |
| コマンドの登録 | できない | `[project.scripts]` で `novelist` コマンドを登録できる |

`novelist` はサブコマンドを持つCLIツールで、ソースファイルも増えていきます。そのため、最初からパッケージ形式にしておきます。

これ以降のコマンドは、特に断りがない限り、この `novelist/` ディレクトリ（プロジェクトのルート）で実行します。

### 生成されたファイル

```text
novelist/
├── .git/
├── .gitignore
├── .python-version
├── README.md
├── pyproject.toml
└── src/
    └── novelist/
        └── __init__.py
```

`uv init` は、Gitリポジトリの初期化（`.git/`）もしてくれます。主なファイルを見ていきましょう。

**`pyproject.toml`**

```toml
[project]
name = "novelist"
version = "0.1.0"
description = "Add your description here"
readme = "README.md"
authors = [
    { name = "Your Name", email = "you@example.com" }
]
requires-python = ">=3.12"
dependencies = []

[project.scripts]
novelist = "novelist:main"

[build-system]
requires = ["uv_build>=0.8.17,<0.9.0"]
build-backend = "uv_build"
```

- `[project]`：プロジェクトの名前、バージョン、対応するPythonのバージョンなどです。`authors` には、Gitに設定した名前とメールアドレスが入ります。
- `dependencies`：実行に必要なライブラリの一覧です。今は空です。
- `[project.scripts]`：コマンド名と、そのとき呼ばれる関数の対応です。`novelist` コマンドを実行すると、`novelist` パッケージの `main` 関数が呼ばれます。
- `[build-system]`：パッケージをビルドするツールの指定です。`uv_build` のバージョンの範囲は、使っているuvのバージョンによって変わります。

**`src/novelist/__init__.py`**

```python
def main() -> None:
    print("Hello from novelist!")
```

**`.python-version`**

```text
3.12
```

このファイルは、プロジェクトで使うPythonのバージョンをuvに伝えます。あとから変えたいときは `uv python pin 3.13` のように実行すると書き換わります。

## 2.5 最初の実行

さっそく動かしてみましょう。

```console
$ uv run novelist
Using CPython 3.12.11
Creating virtual environment at: .venv
   Building novelist @ file:///home/you/novelist
      Built novelist @ file:///home/you/novelist
Installed 1 package in 2ms
Hello from novelist!
```

`uv run` を実行しただけで、裏では次のことが起きています。

1. `.python-version` を見て、Python 3.12 を選ぶ
2. `.venv/` に仮想環境を作る
3. 依存関係を解決して `uv.lock` を作る
4. `novelist` パッケージを、**編集可能モード**で仮想環境にインストールする
5. 仮想環境の中で `novelist` コマンドを実行する

編集可能モードでは、`src/novelist/` のソースを直接参照します。ソースを書き換えたら、再インストールしなくてもすぐに反映されます。

2回目以降は、環境が最新なら手順2〜4は省略され、すぐにコマンドが実行されます。`pyproject.toml` を書き換えた場合は、`uv run` が変更を検出して自動で同期し直します。

> **コラム：仮想環境を有効化したい場合**
>
> `uv run` を付けるのが面倒な場合は、従来どおり仮想環境を有効化してもかまいません。
>
> ```console
> $ source .venv/bin/activate      # Linux / macOS
> PS> .venv\Scripts\Activate.ps1   # Windows
> (novelist) $ novelist
> ```
>
> ただし有効化した状態では、`pyproject.toml` を変更しても自動では同期されません。その場合は `uv sync` を実行してください。本書では、常に `uv run` を付けて実行します。

## 2.6 依存ライブラリを追加する

CLIを作るために、**Typer**（コマンドライン引数の処理）と **Rich**（ターミナルへのきれいな表示）を追加します。

```console
$ uv add typer rich
Prepared 8 packages in 128ms
Installed 8 packages in 8ms
 + markdown-it-py==4.2.0
 + mdurl==0.1.2
 + pygments==2.21.0
 + rich==15.0.0
 + shellingham==1.5.4
 + typer==0.27.2
 ...
```

`uv add` は、次の3つをまとめて行います。

1. `pyproject.toml` の `dependencies` にライブラリを追記する
2. 依存関係を解決し直して `uv.lock` を更新する
3. 仮想環境にインストールする

`pyproject.toml` は次のように変わります。

**`pyproject.toml`**（変更）

```diff
 authors = [
     { name = "Your Name", email = "you@example.com" }
 ]
 requires-python = ">=3.12"
-dependencies = []
+dependencies = [
+    "rich>=15.0.0",
+    "typer>=0.27.2",
+]

 [project.scripts]
 novelist = "novelist:main"
```

`pyproject.toml` に書かれるのは「このバージョン以上」という**範囲**です。実際にインストールされた正確なバージョンは `uv.lock` に記録されます。

`uv.lock` は、uvが自動で管理するファイルです。手で編集しないでください。中身は、次のようにパッケージごとのバージョン、取得元、ハッシュ値が並んでいます。

**`uv.lock`**（抜粋）

```toml
[[package]]
name = "typer"
version = "0.27.2"
source = { registry = "https://pypi.org/simple" }
dependencies = [
    { name = "annotated-doc" },
    { name = "rich" },
    { name = "shellingham" },
]
```

バージョン番号は、あなたが実行した時点の最新版になるので、本書と違っていてかまいません。本書のサンプルリポジトリの `uv.lock` を使えば、本書と同じバージョンにそろえられます（2.10節）。

依存関係の全体は、`uv tree` で確認できます。

```console
$ uv tree
novelist v0.1.0
├── rich v15.0.0
│   ├── markdown-it-py v4.2.0
│   │   └── mdurl v0.1.2
│   └── pygments v2.21.0
└── typer v0.27.2
    ├── annotated-doc v0.0.5
    ├── rich v15.0.0 (*)
    └── shellingham v1.5.4
(*) Package tree already displayed
```

## 2.7 CLIの骨組みを作る

第1章で見たように、`novelist` は `vram-check`、`doctor`、`write` のようなサブコマンドを持つCLIです。この章では、その骨組みとして2つのサブコマンドを作ります。

- `version`：バージョンを表示する
- `env`：Pythonのバージョンや、実行しているPythonの場所など、実行環境を表示する

`env` は、「本当にプロジェクトの仮想環境で動いているか」を確認するのに役立ちます。うまく動かないときに最初に見るコマンドとして、これからも使います。

### パッケージの初期化ファイル

`__init__.py` の `main` 関数は、この後に作る `cli.py` に役割を移すので削除します。代わりに、パッケージのバージョンを `__version__` として公開します。

**`src/novelist/__init__.py`**（変更後の全文）

```python
"""novelist: ローカルLLMで小説を書くエージェント。"""

from importlib.metadata import version

__version__ = version("novelist")
```

`importlib.metadata.version()` は、インストールされたパッケージの情報からバージョンを読み取ります。バージョン番号は `pyproject.toml` の `version` だけで管理し、ソースコードに二重に書かないようにしています。

### CLI本体

**`src/novelist/cli.py`**（新規）

```python
"""novelist のコマンドラインインターフェース。"""

import platform
import sys

import typer
from rich.console import Console
from rich.table import Table

from novelist import __version__

app = typer.Typer(
    help="ローカルLLMで小説を書くエージェント",
    no_args_is_help=True,
)
console = Console()


@app.command()
def version() -> None:
    """バージョンを表示します。"""
    console.print(f"novelist {__version__}")


@app.command()
def env() -> None:
    """実行環境の情報を表示します。"""
    table = Table(title="novelist 実行環境")
    table.add_column("項目", style="cyan")
    table.add_column("値", overflow="fold")
    table.add_row("novelist", __version__)
    table.add_row("Python", platform.python_version())
    table.add_row("実行ファイル", sys.executable)
    table.add_row("OS", platform.platform())
    console.print(table)
```

ポイントを見ていきます。

- `typer.Typer(...)` でアプリケーションを作ります。`help` はヘルプに表示される説明文です。`no_args_is_help=True` を指定すると、サブコマンドなしで実行したときにヘルプを表示します。
- `@app.command()` を付けた関数が、サブコマンドになります。関数名がそのままコマンド名になり、docstring（`"""..."""`）がヘルプの説明文になります。
- `Console` はRichの出力先です。これからは `print` の代わりに `console.print` を使います。第6章では、LLMの出力をストリーミング表示するときにもこれを使います。
- `Table` はRichの表です。`overflow="fold"` は、長い値（ここではPythonのパス）を省略せずに折り返して表示する指定です。

### コマンドを登録し直す

`novelist` コマンドが `cli.py` の `app` を呼ぶように、`pyproject.toml` を変更します。ついでに `description` も書き換えておきましょう。

**`pyproject.toml`**（変更）

```diff
 [project]
 name = "novelist"
 version = "0.1.0"
-description = "Add your description here"
+description = "ローカルLLMで小説を書くエージェント"
 readme = "README.md"
```

```diff
 [project.scripts]
-novelist = "novelist:main"
+novelist = "novelist.cli:app"

 [build-system]
```

`"novelist.cli:app"` は、「`novelist.cli` モジュールの `app` を呼ぶ」という意味です。Typerのアプリケーションは関数のように呼び出せるので、そのまま登録できます。

## 2.8 開発用ツールを追加する

テストツールの **pytest** と、Linter兼フォーマッターの **ruff** を追加します。これらは開発中にだけ使うもので、`novelist` を実行するのには必要ありません。そこで `--dev` を付けて、開発用の依存関係として追加します。

```console
$ uv add --dev ruff pytest
Installed 6 packages in 3ms
 + iniconfig==2.3.0
 + packaging==26.3
 + pluggy==1.6.0
 + pytest==9.1.1
 + ruff==0.16.8
 ...
```

`pyproject.toml` の末尾に `[dependency-groups]` が追加されます。

**`pyproject.toml`**（変更）

```diff
 [build-system]
 requires = ["uv_build>=0.8.17,<0.9.0"]
 build-backend = "uv_build"
+
+[dependency-groups]
+dev = [
+    "pytest>=9.1.1",
+    "ruff>=0.16.8",
+]
```

`dev` グループは、`uv run` や `uv sync` で既定でインストールされます。実行に必要なものだけを入れたい場合は `uv sync --no-dev` とします。

### ツールの設定

ruffとpytestの設定を `pyproject.toml` の末尾に追加します。

**`pyproject.toml`**（変更）

```diff
 [dependency-groups]
 dev = [
     "pytest>=9.1.1",
     "ruff>=0.16.8",
 ]
+
+[tool.ruff]
+line-length = 100
+target-version = "py312"
+
+[tool.ruff.lint]
+select = ["E", "F", "I", "UP", "B"]
+
+[tool.pytest.ini_options]
+testpaths = ["tests"]
```

- `line-length`：1行の最大文字数です。日本語の文字列やプロンプトを書くことが多いので、少し長めの100にしています。
- `select`：有効にするルールです。`E`/`F` は基本的な誤り、`I` はimportの並び順、`UP` は新しいPythonの書き方への更新、`B` はバグになりやすい書き方の検出です。
- `testpaths`：pytestがテストを探すディレクトリです。

### テストを書く

CLIのテストを書きます。Typerには、コマンドをプログラムから呼び出してテストするための `CliRunner` が用意されています。

**`tests/test_cli.py`**（新規）

```python
from typer.testing import CliRunner

from novelist import __version__
from novelist.cli import app

runner = CliRunner()


def test_version() -> None:
    result = runner.invoke(app, ["version"])
    assert result.exit_code == 0
    assert __version__ in result.output


def test_env() -> None:
    result = runner.invoke(app, ["env"])
    assert result.exit_code == 0
    assert "Python" in result.output
```

`runner.invoke(app, [...])` は、`novelist version` のようにコマンドラインから実行したのと同じ処理を行い、終了コードと出力を返します。

### テストとLintを実行する

```console
$ uv run pytest
============================= test session starts ==============================
configfile: pyproject.toml
testpaths: tests
collected 2 items

tests/test_cli.py ..                                                     [100%]

============================== 2 passed in 0.07s ===============================
```

```console
$ uv run ruff check
All checks passed!
$ uv run ruff format
4 files left unchanged
```

`ruff check` は問題のある書き方を報告します。`--fix` を付けると、自動で直せるもの（importの並び順など）を直します。`ruff format` はコードの書式を整えます。本書のコードは、すべて `ruff format` で整形済みです。

> **コラム：エディタとの連携**
>
> VS Codeを使っている場合は、Python拡張機能で `.venv` のPythonを選んでおくと、補完や型チェックがプロジェクトのライブラリを認識します。コマンドパレットで「Python: Select Interpreter」を実行し、`./.venv/bin/python`（Windowsでは `.\.venv\Scripts\python.exe`）を選んでください。ruffにもVS Code拡張機能があり、保存時に自動で整形できます。


- `models/`・`*.gguf`：第5章でダウンロードするモデルファイルです。数GB〜数十GBあるので、Gitでは管理しません。
- `works/`：生成した作品の置き場所です。作品は自分のものなので、プログラムとは別に管理します。

`.venv/` がすでに除外されていることも確認しておきましょう。仮想環境は `uv.lock` からいつでも作り直せるので、コミットしません。一方で、**`uv.lock` は必ずコミットします**。これが環境を再現するための情報だからです。

```console
$ git add .
$ git commit -m "第2章: uvでプロジェクトを作成"
```

コミットされたファイルを確認しておきます。

## 2.10 別の環境で再現する

別のPCで作業するときや、サンプルリポジトリを使うときは、リポジトリを取得してから `uv sync` を実行します。

```console
$ git clone <リポジトリURL> novelist
$ cd novelist
$ uv sync --locked
```

`uv sync` は、`uv.lock` のとおりに `.venv/` を作ります。Python 3.12がなければ、自動でダウンロードします。

`--locked` は、「`uv.lock` が `pyproject.toml` と食い違っていたら、ロックを更新せずにエラーにする」という指定です。本書と同じバージョンを確実に使いたいときは、これを付けてください。

仮想環境がおかしくなったと思ったら、`.venv/` を消して作り直せば元に戻ります。

```console
$ rm -rf .venv          # Windows: Remove-Item -Recurse -Force .venv
$ uv sync --locked
```

### ライブラリを更新する・削除する

```console
$ uv lock --upgrade-package typer   # typer だけを最新版に更新
$ uv lock --upgrade                 # すべてを更新（本書と違うバージョンになるので注意）
$ uv remove rich                    # 依存関係から削除（今は削除しないでください）
```

## 2.11 この章で使ったuvコマンド

| コマンド | 内容 |
|---|---|
| `uv python install 3.12` | Pythonをインストールする |

| `uv init --package <名前>` | パッケージ形式のプロジェクトを作る |

## 2.12 うまくいかないとき

**`uv` コマンドが見つからない**

ターミナルを開き直してください。それでも見つからない場合は、インストーラーの最後に表示されたディレクトリ（Linux/macOSでは `~/.local/bin`、Windowsでは `%USERPROFILE%\.local\bin`）がPATHに入っているか確認します。

**Windowsで「スクリプトの実行が無効」と表示される**

`.venv\Scripts\Activate.ps1` を実行するときに出るエラーです。本書のように `uv run` を使えば、有効化は不要です。どうしても有効化したい場合は、`Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` を実行します。

**社内ネットワークで証明書のエラーが出る**

プロキシがTLSの通信を中継している環境では、パッケージのダウンロードで証明書のエラーになることがあります。環境変数 `UV_NATIVE_TLS=1` を設定すると、OSの証明書ストアを使うようになります。

**`env` の「実行ファイル」が `.venv` を指していない**

`uv run` を付けずに `novelist` を実行していないか確認してください。別の場所に以前インストールした `novelist` が動いている可能性があります。

## 2.13 まとめ

- uvは、Python本体・仮想環境・依存関係・ロックファイルを1つのツールで扱えます
- `uv init --package` でsrcレイアウトのプロジェクトを作り、`[project.scripts]` で `novelist` コマンドを登録しました
- `uv add` で依存関係を追加すると、`pyproject.toml` と `uv.lock` が更新されます。`uv.lock` はGitにコミットします
- Typerで `version` と `env` の2つのサブコマンドを作り、pytestでテストしました
- `uv run` を付けて実行すれば、仮想環境の作成と同期は自動で行われます
