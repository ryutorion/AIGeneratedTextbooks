# 第23章 文体サンプルとfew-shot — 参照文の選び方と入れ方

第15章から、本文を書くプロンプトのシステムプロンプトには「文章の方針」を書いてきました。「説明より描写を優先する」「文末の形に変化をつける」といった指示です。しかし、言葉で書いた方針は、思ったほど効きません。「短い文で書く」と指示しても、どのくらい短ければよいのかはモデルの解釈しだいです。書き進めるうちに、モデルがもともと持っている書きぶり（感情を言葉で説明する、読点で文を長くつなぐ、など）に戻っていくこともよくあります。

文体は、言葉で説明するより、**見せる**ほうが伝わります。お手本となる文章を何本かプロンプトに入れ、「このように書いて」と頼む方法を、**few-shot**（少数の例を示す方法）と呼びます。

この章では、文体の見本（文体サンプル）をまとめた**文体ライブラリ**を作り、シーンごとに合う見本を選んで、本文を書くプロンプトに入れます。見本の入れ方は2通り用意して、比べられるようにします。見本をまねすぎて、見本の文をそのまま使ってしまっていないかも確かめます。

この章で作るものは次のとおりです。

| ファイル・コマンド | 内容 |
|---|---|
| `styles/shizuka/` | 文体「しずか」の方針と見本の文章 |
| `src/novelist/style.py` | 文体を読み込み、見本を選び、プロンプトに入れる |
| `prompts/style/` | 文体の方針と見本を、プロンプトに書き出すテンプレート |
| `novelist styles` | 使える文体の一覧 |
| `novelist style` | 文体の見本を表示する。作品で使う文体を設定する。書いた本文と比べる |
| `novelist write --style` | 文体を指定して書く |

## 23.1 言葉で指示するか、見せるか

### 見本からまねされること

LLMは、プロンプトに入った文章の表面的な特徴を、とてもよくまねます。

| まねされやすいこと | 例 |
|---|---|
| 文の長さ | 一文が20字前後で、読点が少ない |
| 文末 | 「〜た。」のあとに、現在形「〜る。」や体言止めを挟む |
| 段落の長さと改行 | 2〜4文で改行し、ときどき1文だけの段落を置く |
| 会話の書き方 | 台詞が短く、台詞のあとに説明を足さない |
| 語彙の硬さ | 漢語が多いか、和語が多いか |

これらは、言葉で指示しようとすると長い説明が要るうえに、それでも伝わりにくいものです。見本を見せれば、数百字でまとめて伝わります。

その一方で、LLMは**見本の内容**もまねてしまいます。見本に出てくる人物の名前、場所、印象的な言い回しが、本文にまぎれ込むことがあります。見本を選ぶときと入れるときには、これを防ぐ工夫が必要です。

### 見本の入れ方

見本をプロンプトに入れる方法は、大きく2つあります。

**システムプロンプトに入れる（`system`）**

```text
system: あなたは日本語の娯楽小説を書く、経験豊富な小説家です。…
        # この作品の文体
        - 次の見本の、語り口・文の長さ・語尾・改行の癖をまねてください。
        ## 見本1（雪がやんだ冬の朝、古い商店の店主が店を開ける）
        シャッターは三度目で上がった。…
user:   次のシーンの本文を書いてください。…
```

**依頼と応答の組にする（`turns`）**

```text
system:    あなたは日本語の娯楽小説を書く、経験豊富な小説家です。…
           # この作品の文体
           - これまでのやりとりにある文章は、文体の見本です。…
user:      次の場面を、この作品の文体で書いてください。
           場面: 雪がやんだ冬の朝、古い商店の店主が店を開ける
assistant: シャッターは三度目で上がった。…
user:      次の場面を、この作品の文体で書いてください。
           場面: 高校の同級生だった二人が、十年ぶりに帰り道を並んで歩く
assistant: 「まだ、あの坂の上に住んでるの」…
user:      次のシーンの本文を書いてください。…
```

`turns` では、見本の文章を、**モデル自身がこれまでに書いた応答**（`assistant`）としてプロンプトに入れます。モデルから見ると、「この作品の文体で」という依頼に、自分はこれまでこう答えてきた、という形になります。そのため、同じ書きぶりを続けやすくなります。一般に「few-shot」と言うと、この形を指すことが多いです。

| | `system` | `turns` |
|---|---|---|
| まねさせる強さ | 弱め。説明の一部として読まれる | 強い。自分の過去の応答として読まれる |
| 内容の持ち込み | 少なめ | 起きやすい |
| トークン数 | 同じくらい | 同じくらい |
| 向いている場面 | 方針の補足として、軽く効かせたい | 文体をはっきり変えたい |

どちらがよいかは、モデルと見本しだいです。本書では `turns` を既定にし、`style.toml` で切り替えられるようにします。23.7節で、両方を試して比べます。

### 見本の選び方

見本の文章は、次の点に気をつけて選びます（あるいは書きます）。

- **1本は300〜400字くらい**：短すぎると癖が伝わらず、長すぎるとプロンプトの予算を圧迫します
- **1つの場面として完結している**：途中で切れた文章を見せると、途中で終わる書き方をまねします
- **種類を散らす**：描写、会話、心理、緊張した場面など。会話の見本がないと、台詞の書き方は伝わりません
- **作品と違う内容にする**：書いている作品の人物や場所が出てくる見本は、内容がそのまま持ち込まれます。見本は、あえて別の話にします
- **見本どうしで、同じ癖を持つ**：見本ごとに文体がばらばらだと、どれをまねればよいのかがぼやけます

1つのシーンに入れる見本は、2〜3本にします。多くするほど文体は安定しますが、プロンプトが長くなり、内容の持ち込みも増えます。そこで、見本は4〜8本ほど用意しておき、シーンごとに、そのシーンに合うものを選んで入れます。夜の倉庫で物音を聞くシーンなら緊張した場面の見本を、二人が語り合うシーンなら会話の見本を、という具合です。選ぶのには、第18章の埋め込みを使います。

> **見本の文章と著作権**
>
> 見本には、**自分で書いた文章**か、**著作権の保護期間が終わった作品**の文章を使ってください。日本では、著作権の保護期間は原則として著作者の死後70年です（2018年12月30日から。それより前に保護期間が終わっていた作品は、そのままです）。青空文庫には保護期間が終わった作品が多く収められていますが、翻訳作品は翻訳者の権利が残っていることがあります。作品ごとに、底本や翻訳者を確かめてください。
>
> 現役の作家の文章を見本にして、その作家の文体をまねた小説を書かせ、公開したり販売したりすることは避けてください。文体そのものは著作権で保護されないとされていますが、見本の文や表現がそのまま出てくれば問題になりますし、作家への敬意の面でも好ましくありません。
>
> 本書の見本の文章は、すべて筆者が本書のために書いたものです。

## 23.2 文体ライブラリ

文体は、プロジェクトの `styles/` ディレクトリに、1つの文体を1つのディレクトリとして置きます。プロンプトのテンプレート（`prompts/`）と同じく、作品をまたいで使い回せます。

```text
styles/
└── shizuka/                 # 文体の名前（ディレクトリ名）
    ├── style.toml           # 説明、見本の入れ方、言葉で書いた方針
    └── samples/             # 見本の文章（1ファイル1本）
        ├── 01-asa.md
        ├── 02-kaerimichi.md
        ├── 03-tegami.md
        └── 04-oto.md
```

### 文体の方針

**`styles/shizuka/style.toml`**（新規）

```toml
# 文体「しずか」（第23章）: 見本の文章は samples/ に置く
description = "静かな三人称。短い文で、目に見えるもの・聞こえるものを淡々と積み重ねる"
mode = "turns"  # 見本の入れ方。"turns"（依頼と応答の組）か "system"（システムプロンプト）
notes = [
  "一文は短くする。長くても40字くらいまでにし、読点で長くつながない",
  "悲しい・嬉しいなど、感情を表す言葉を使わない。感情は、動作と物で示す",
  "比喩は、1つの場面に1つまでにする",
  "台詞は短くする。台詞のあとに、その意味を説明する地の文を足さない",
  "段落は2〜4文にする。間（ま）は、1文だけの短い段落で示す",
]
```

- `description` は、`novelist styles` の一覧に出す短い説明です。プロンプトにも入ります。
- `mode` は、見本の入れ方です。`"turns"` か `"system"` を指定します。
- `notes` は、言葉で書いた文体の方針です。見本だけでは伝わりにくいこと（「感情を表す言葉を使わない」など）を補います。見本と方針の両方を渡すと、見本のどこをまねればよいのかがはっきりします。

### 見本の文章

見本の文章は、第7章の `story_file.py` と同じ形式（先頭にメタデータを付けたMarkdown）で書きます。メタデータには、どんな場面の文章か（`situation`）と、文章の種類（`kind`）を書きます。`situation` は、`turns` モードで見本を引き出す依頼の文にもなります。

## 23.3 文体を読み込む

### 文体のモジュール

**`src/novelist/style.py`**（新規）

```python
"""文体の見本（スタイルガイド）を読み込み、本文を書くプロンプトに入れる（第23章）。

styles/<名前>/style.toml に方針を、styles/<名前>/samples/*.md に見本の文章を置く。
"""

import re
import tomllib
from dataclasses import dataclass, field
from pathlib import Path
from typing import Literal

from pydantic import BaseModel, ConfigDict, Field, ValidationError

from novelist.llm.client import Message
from novelist.llm.embedding import EmbeddingClient, Vector, most_similar
from novelist.prompts import PromptLibrary
from novelist.story_file import read_story

STYLE_FILE = "style.toml"
SAMPLES_DIR = "samples"
NO_STYLE = "none"  # 文体の見本を使わないことを表す名前
COPY_NGRAM = 10  # 見本の丸写しを調べるときの、文字の並びの長さ
COPY_WARNING = 0.03  # 見本と重なる割合が、これを超えたら警告する


class StyleError(Exception):
    """文体の見本を読み込めなかったときの例外。"""


class StyleSettings(BaseModel):
    """style.toml の中身。"""

    model_config = ConfigDict(extra="forbid")

    description: str = ""  # 文体の短い説明
    # 見本の入れ方。"turns" は依頼と応答の組（few-shot）、"system" はシステムプロンプトに入れる
    mode: Literal["turns", "system"] = "turns"
    notes: list[str] = Field(default_factory=list)  # 言葉で書いた文体の方針


@dataclass
class StyleSample:
    """見本の文章1つ。"""

    id: str  # ファイル名（拡張子を除く）
    situation: str  # どんな場面の文章か
    kind: str  # 文章の種類（描写、会話、心理など）
    text: str


@dataclass
class StyleGuide:
    """1つの文体の、方針と見本の文章。"""

    name: str
    description: str
    mode: str
    notes: list[str]
    samples: list[StyleSample]
    # 見本の文章の埋め込み。はじめて検索したときに計算して、覚えておく
    vectors: list[Vector] | None = field(default=None, repr=False)

    def pick(self, ids: list[str]) -> list[StyleSample]:
        """id の順に見本を取り出す。見つからない id は無視する。"""
        by_id = {s.id: s for s in self.samples}
        return [by_id[i] for i in ids if i in by_id]


def list_styles(styles_dir: Path) -> list[str]:
    """使える文体の名前の一覧。"""
    if not styles_dir.is_dir():
        return []
    return sorted(p.name for p in styles_dir.iterdir() if (p / STYLE_FILE).is_file())


def load_style(styles_dir: Path, name: str) -> StyleGuide:
    """styles/<name>/ から、文体の方針と見本を読み込む。"""
    root = styles_dir / name
    path = root / STYLE_FILE
    if not path.is_file():
        names = ", ".join(list_styles(styles_dir)) or "(なし)"
        raise StyleError(f"文体 '{name}' が見つかりません（{path}）。使える文体: {names}")
    try:
        with path.open("rb") as f:
            settings = StyleSettings.model_validate(tomllib.load(f))
    except (tomllib.TOMLDecodeError, ValidationError) as e:
        raise StyleError(f"{path} を読み込めません: {e}") from e

    samples = []
    for sample_path in sorted((root / SAMPLES_DIR).glob("*.md")):
        meta, text = read_story(sample_path)
        if not text:
            raise StyleError(f"見本の文章が空です: {sample_path}")
        samples.append(
            StyleSample(
                id=sample_path.stem,
                situation=meta.get("situation", ""),
                kind=meta.get("kind", ""),
                text=text,
            )
        )
    if not samples:
        raise StyleError(f"見本の文章がありません: {root / SAMPLES_DIR}/*.md")
    return StyleGuide(name, settings.description, settings.mode, settings.notes, samples)


def _diverse(samples: list[StyleSample], k: int) -> list[StyleSample]:
    """種類（kind）がなるべく重ならないように、先頭から k 件選ぶ。"""
    picked: list[StyleSample] = []
    kinds: set[str] = set()
    for s in samples:
        if len(picked) < k and s.kind not in kinds:
            picked.append(s)
            kinds.add(s.kind)
    for s in samples:
        if len(picked) < k and s not in picked:
            picked.append(s)
    return picked


def select_samples(
    guide: StyleGuide, k: int, query: str = "", embedder: EmbeddingClient | None = None
) -> list[StyleSample]:
    """シーンに合う見本を k 件選ぶ。

    埋め込み用のサーバーがあれば、query（シーンカード）に近い見本を選ぶ。
    なければ、種類が重ならないように、ファイル名の順に選ぶ。
    """
    if k >= len(guide.samples):
        return list(guide.samples)
    if embedder is None or not query:
        return _diverse(guide.samples, k)
    if guide.vectors is None:
        guide.vectors = embedder.embed_documents(
            [f"{s.situation}\n{s.text}" for s in guide.samples]
        )
    ranked = most_similar(embedder.embed_query(query), guide.vectors, k)
    return [guide.samples[i] for i, _ in ranked]


def style_messages(
    prompts: PromptLibrary,
    messages: list[Message],
    guide: StyleGuide,
    samples: list[StyleSample],
) -> list[Message]:
    """本文を書くプロンプトに、文体の方針と見本を入れる。

    文体の方針は、どちらのモードでもシステムプロンプトの最後に足す。
    "system" モードでは、見本もシステムプロンプトに入れる。
    "turns" モードでは、見本を「依頼と、それへの応答」の組にして、最後の依頼の前に入れる。
    """
    guide_text = prompts.render_text("style/guide.md", guide=guide, samples=samples)
    result = [dict(m) for m in messages]
    if result and result[0]["role"] == "system":
        result[0]["content"] += "\n\n" + guide_text
    else:
        result.insert(0, {"role": "system", "content": guide_text})
    if guide.mode != "turns":
        return result

    shots: list[Message] = []
    for sample in samples:
        request = prompts.render_text("style/example.md", sample=sample)
        shots.append({"role": "user", "content": request})
        shots.append({"role": "assistant", "content": sample.text})
    return result[:-1] + shots + result[-1:]


def _ngrams(text: str, n: int) -> set[str]:
    compact = re.sub(r"\s", "", text)
    return {compact[i : i + n] for i in range(len(compact) - n + 1)}


def copied_ratio(text: str, samples: list[StyleSample], n: int = COPY_NGRAM) -> float:
    """本文の n 文字の並びのうち、見本の文章にも出てくるものの割合。

    文体をまねるのはよいが、見本の文をそのまま使うのは困る。その目安にする。
    """
    grams = _ngrams(text, n)
    if not grams:
        return 0.0
    sample_grams = set().union(*(_ngrams(s.text, n) for s in samples)) if samples else set()
```

- **`load_style`**：`style.toml` を `StyleSettings` で検証してから、`samples/*.md` をファイル名の順に読み込みます。`mode` に `"few-shot"` のような値を書くと、ここでエラーになります。
- **`select_samples`**：シーンに合う見本を `k` 本選びます。
  - 見本が `k` 本以下なら、すべて使います。
  - 埋め込み用のサーバーがあれば、シーンカード（第20章の `scene_query`）に近い見本を選びます。見本の埋め込みは、はじめて選ぶときに1回だけ計算して、`StyleGuide.vectors` に覚えておきます。
  - なければ、`_diverse` で、種類（`kind`）が重ならないようにファイル名の順に選びます。「描写」の見本ばかりが選ばれて、会話の書き方が伝わらない、ということを防ぎます。
- **`style_messages`**：プロンプトのメッセージのリストに、文体の方針と見本を入れた、新しいリストを返します。元のリストは変えません。方針（`style/guide.md`）はどちらのモードでもシステムプロンプトの最後に足し、`turns` モードでは、見本を依頼と応答の組にして、最後の依頼（シーンを書く依頼）の直前に入れます。
- **`copied_ratio`**：本文の10文字の並びのうち、見本にも出てくるものの割合です。第7章の `repeated_ratio`（文章の中の繰り返し）と同じ考え方で、見本の文をそのまま使っていないかの目安にします。

## 23.4 執筆のグラフに組み込む

### どこで選び、どこで入れるか

見本を**選ぶ**のは、第20章の `gather_context` ノードです。ここでは、シーンを書くプロンプトの予算を計算しています。見本はシーンを書くたびに必ず入るので、「必ず入れる部分」（`fixed`）に数える必要があります。見本の分を数えずに予算を計算すると、あらすじや検索結果を入れすぎて、コンテキスト長をはみ出します。

選んだ見本は、グラフの状態に**idだけ**を記録します。見本の文章そのものは、`WriteContext` に入れた `StyleGuide` から取り出します。`WriteContext` は第17章のチェックポイントに保存されないので、`CHECKPOINT_TYPES` に型を加える必要はありません。

見本を**入れる**のは、本文を書く・推敲する・食い違いを直す、の3つのノードです。どれも本文を生成するので、同じ文体で書かせます。批評（第16章）・一貫性のチェック（第21章）・要約・状態の更新（第22章）のプロンプトには入れません。これらは本文を書くわけではないので、見本は予算の無駄になるうえに、見本の内容を作品の内容と取り違えるおそれがあります。

```text
gather_context ─── 見本を選ぶ（予算に数える）→ context_style: ["01-asa", "02-kaerimichi"]
   │
write_scene ────── 見本を入れる
   │
critique_scene     （入れない）
   │
revise_scene ───── 見本を入れる
   │
check_consistency  （入れない）
   │
fix_scene ──────── 見本を入れる
   │
summarize_scene    （入れない）
```

さらに、`style.toml` の `mode` を `"system"` に変えて、もう一度書き直してみてください（`--from 1-1 -n 3 -r 0`）。多くのモデルでは、`turns` のほうが文末の割合などの数字が見本に近くなり、`system` のほうが元の書きぶりが残ります。その一方で、`turns` のほうが、見本の言い回し（「シャッターは三度目で上がった」のような文の形）を借りてくることが多くなります。「文体の見本との重なり」のログと、読み比べた印象の両方で、どちらを使うか決めてください。

> **見本と、プロンプトのキャッシュ**
>
> llama-server は、前のリクエストとプロンプトの先頭が同じなら、その部分の計算を省きます（プロンプトのキャッシュ）。埋め込みでシーンごとに違う見本を選ぶと、見本より後ろの部分は毎回計算し直しになります。`system` モードでは見本がシステムプロンプトの中に入るので、影響がより大きくなります。
>
> プロンプトの処理が遅いと感じたら、`[style]` の `samples` を、用意した見本の数と同じにしてみてください。すべての見本を毎回同じ順で入れるので、見本までの部分がキャッシュされます。そのぶんトークンは増えるので、コンテキスト長に余裕がある場合に向いています。

## 23.8 うまくいかないときは

**見本の人物や場所が、本文に出てくる**

`turns` モードで起きやすい問題です。まず、「文体の見本との重なり」のログが高くなっていないかを確かめてください。対策は次のとおりです。

- 見本の人物の名前を減らす。「和子は」を「彼女は」にするなど、固有名詞の少ない見本にする
- 作品と似た場面の見本を減らす。雪の駅の作品に、雪の朝の見本を使うと、情景がそのまま持ち込まれやすくなります
- `mode = "system"` にする

**見本を入れても、文体が変わらない**

- `novelist context` で「文体の見本: …」の行が出るか、`write` のログに「[gather_context] 文体の見本: …」が出るかを確かめてください。出ない場合は、作品に文体が設定されていません。`novelist style 名前 --use 作品のID` で設定してください。
- ログは出るのに、`write_scene` のログに「文体の見本との重なり」が出ない場合は、見本がプロンプトに入っていません。`WriteState` に `context_style` を宣言し忘れていないかを確かめてください（23.4節）。宣言していないと、`gather_context` が選んだ見本のidが捨てられ、`with_style` は見本なしのプロンプトをそのまま返します。
- 見本が効きにくいモデルもあります。`samples` を3に増やす、`notes` に具体的な数字（「一文は40字まで」）を書く、を試してください。第25章では、モデルによる違いを比べます。

**`turns` モードで、サーバーがエラーを返す、または応答がおかしい**

チャットテンプレートによっては、`user` と `assistant` が交互に並び、最後が `user` で終わることを前提にしています。`style_messages` は、見本を「最後のメッセージの直前」に入れるので、最後のメッセージがシーンを書く依頼（`user`）であれば、交互に並びます。プロンプトのテンプレートを自分で書き換えて、`user.md` のあとに別のメッセージを足している場合は、並びが崩れます。テストの `test_write_with_style` のように、実際に送ったメッセージの `role` の並びを確かめてください。

思考（reasoning）モデルでは、チャットテンプレートが、過去の `assistant` の応答から思考の部分を取り除く処理をしていることがあります。見本には思考がないので影響はありませんが、第15章のとおり、本文を書くプロファイルでは思考を止めておいてください。

`novelist.toml` の `styles_dir` は、コマンドを実行したディレクトリからの相対パスです。プロジェクトのディレクトリ（`novelist.toml` があるところ）でコマンドを実行してください。

## 23.9 まとめ

- 文体は、言葉で説明するより、**見本を見せる**ほうが伝わります。文の長さ・文末・段落・会話の書き方といった表面的な特徴を、数百字の見本でまとめて伝えられます
- 文体を、方針（`style.toml`）と見本の文章（`samples/*.md`）の組として、**文体ライブラリ**（`styles/`）に置くようにしました
- シーンごとに、埋め込みでシーンカードに近い見本を選び、埋め込みがなければ種類が重ならないように選ぶようにしました。見本は予算の「必ず入れる部分」に数えます
- 見本の入れ方として、システムプロンプトに入れる `system` と、依頼と応答の組にする `turns`（few-shot）を用意しました。`turns` のほうが強く効き、内容の持ち込みも起きやすくなります
- 見本を入れるのは、本文を書く・推敲する・食い違いを直すプロンプトだけにしました
- 本文と見本の**重なり**を測り、見本の文をそのまま使っていないかを確かめるようにしました
- `novelist style --compare` で、見本と書いた本文の統計を並べて、文体が近づいたかを数字で確かめられるようにしました

見本は、文体の「雰囲気」をまねさせるのには向いていますが、「必ず三人称で」「会話文のあとは改行する」のような、守ってほしい**規則**を確実に守らせることはできません。第24章では、視点・時制・語尾・会話文・改行といった日本語の文体の規則を、プロンプトで指示し、守れていないところを**後処理**で見つけて直す方法を扱います。
