# 第27章 好みデータを集める — CLIでのA/B比較・採点、JSONLへの記録

第26章の終わりで、こう書きました。「LLMの採点をどれだけ工夫しても、最後に『良い』を決めるのは、読者である自分です」。

この本の目的は、**自分好みの**娯楽小説を書くエージェントを作ることです。しかし、「自分の好み」を言葉で書き出すのは、思った以上に難しいものです。「テンポのいい文章が好き」と書いても、どのくらいのテンポなのか、何がテンポを良くしているのかは、はっきりしません。一方、2つの文章を並べられれば、「こっちのほうが好き」とはすぐに答えられます。

この章では、2つの文章を読み比べて、どちらが好みかを記録するコマンドを作ります。1つの文章を1〜5で採点して記録することもできます。記録はJSONL形式のファイルにためていき、第26章のLLMの判定が自分の判定とどのくらい合うかを調べるのに使います。第28章では、記録から好みのルールを取り出し、第29章では、記録を学習データにします。

## 27.1 好みの集め方

### 読み比べと採点

好みを記録する方法は2つあります。

- **読み比べ（A/B比較）**：同じシーンを書いた2つの文章を読んで、どちらが好みかを選ぶ
- **採点**：1つの文章を読んで、どのくらい好みに合うかを1〜5で答える

第26章で見たとおり、LLMも人間も、絶対的な点数を付けるより、2つを比べるほうが得意です。採点は、その日の気分や、直前に読んだ文章に左右されます。昨日「4」を付けた文章を、今日読み直すと「3」かもしれません。読み比べなら、「AとBのどちらが好きか」という判断は、それよりずっと安定しています。

そこで、この章では読み比べを中心にします。採点は、書き終えた作品のシーンを読み返して、「これは好き」「これは違う」と記録しておきたいときに使います。

### 人間にも偏りがある

第26章で、LLMには位置の偏り（先に見せたほうを選びがち）があることを見ました。人間にも、同じような偏りがあります。また、どちらがどの条件で書いた文章なのかを知っていると、「温度を上げたほうが良いはずだ」のような思い込みが判断に入ります。

そこで、次のようにします。

- 2つの文章を見せる順番は、**ランダム**に決めます。どちらを先に見せたかも記録しておき、あとで自分に位置の偏りがないかを確かめられるようにします
- どの条件で書いた文章なのかは、**答えるまで見せません**。答えたあとで、「1 は base、2 は temp1.3 でした」と明かします

このように、評価する人に条件を伏せて比べる方法を、**ブラインドテスト**と呼びます。

### 理由を書く

どちらが好みかを答えたら、**理由**を1行で書きます。理由は任意ですが、できるだけ書いてください。第28章では、たまった理由から、「台詞のあとに、その意味を説明する地の文を書かない」のような好みのルールを取り出します。

理由は、「こっちが好き」ではなく、**文章のどこが、どう良かったか**を具体的に書きます。

| 役に立ちにくい理由 | 役に立つ理由 |
|---|---|
| こっちのほうが良い | 台詞のあとに、その意味を説明する地の文がない |
| 雰囲気が好き | 雪の音やストーブの匂いで、待合室の寒さが伝わる |
| テンポが良い | 謎の提示から手がかりまでが短く、途中で説明が入らない |

## 27.2 記録の形式

### JSONL

好みの記録は、**JSONL**（JSON Lines）形式のファイルに保存します。JSONLは、1行に1件のJSONを書いていく形式です。

```text
{"id":"f8e01c30","kind":"pair","created_at":"...","source":"bench",...,"choice":"B","reason":"台詞のあとの説明がない"}
{"id":"2a9c4e17","kind":"pair","created_at":"...","source":"write",...,"choice":"tie","reason":""}
{"id":"7b3d0f52","kind":"score","created_at":"...","source":"scene",...,"score":4,"reason":"静かでよい"}
```

JSONLには、記録をためていくのに向いた性質があります。

- **追記するだけでよい**：1件を記録するたびに、ファイルの最後に1行を書き足します。ファイル全体を読み込んで、書き直す必要がありません
- **壊れても、その行だけで済む**：書き込みの途中でプログラムが止まったり、手で編集して1行壊してしまったりしても、ほかの行はそのまま読めます
- **行ごとに扱える**：`grep` で探したり、行数で件数を数えたりできます
- **学習データの形式としてよく使われる**：第29章のLoRAの学習データも、JSONLで作ります

### 1件の記録

1件の記録を、見やすく整形すると、次のようになります。

```json
{
  "id": "f8e01c30",
  "kind": "pair",
  "created_at": "2026-10-06T01:05:32.966676+09:00",
  "source": "bench",
  "work": "kiri-no-eki",
  "scene": "1-1",
  "genre": "ミステリー",
  "a": {
    "key": "bench:kiri-sampling:base:1-1:2",
    "label": "base",
    "text": "最終列車の運休を告げる放送が、待合室に響いた。…",
    "model_file": "my-model-14b-Q4_K_M.gguf",
    "settings": {"temperature": 1.0, "min_p": 0.05, "max_tokens": 7000, "seed": 2}
  },
  "b": {
    "key": "bench:kiri-sampling:temp1.3:1-1:2",
    "label": "temp1.3",
    "text": "放送が終わると、待合室には雪の音だけが残った。…",
    "model_file": "my-model-14b-Q4_K_M.gguf",
    "settings": {"temperature": 1.3, "min_p": 0.1, "max_tokens": 7000, "seed": 2}
  },
  "shown_first": "A",
  "choice": "B",
  "score": null,
  "reason": "台詞のあとの説明がない"
}
```

- `kind` は、読み比べなら `"pair"`、採点なら `"score"` です。
- `source` は、どのコマンドで記録したかです（`"write"` は `rate`、`"bench"` は `bench rate`、`"scene"` は `rate --score`）。
- `a` と `b` が、読み比べた2つの文章です。**本文をそのまま記録します**。比較実験の本文はあとで消すかもしれませんし、作品の本文は書き直すかもしれません。第29章で学習データにするときに、そのときの本文が必要になります。生成に使ったモデルとパラメータも記録しておくと、「どの設定の文章が好まれたか」をあとで調べられます。
- `shown_first` は、先に見せた文章です。`choice` は、選んだ文章（`"A"`・`"B"`・同じくらいなら `"tie"`）です。画面に表示した順番（1・2）ではなく、記録の `a`・`b` で記録します。

## 27.3 記録を読み書きする

**`src/novelist/preferences.py`**（新規）

```python
"""自分の好みを、JSONL（1行に1件のJSON）に記録する（第27章）。

preferences/ratings.jsonl に、2つの文章を読み比べた結果（pair）と、
1つの文章を採点した結果（score）を、1行ずつ追記していく。
"""

import random
import secrets
from collections import Counter
from dataclasses import dataclass
from datetime import datetime
from pathlib import Path
from typing import Any, Literal

from pydantic import BaseModel, Field, ValidationError, model_validator

RATINGS_FILE = "ratings.jsonl"
CANDIDATES_DIR = "candidates"  # 読み比べる文章を、エディタで開けるように書き出す場所
Choice = Literal["A", "B", "tie"]


class Candidate(BaseModel):
    """読み比べる文章1つ。あとで学習データ（第29章）に使えるように、本文ごと記録する。"""

    key: str  # 文章を識別する文字列（"bench:kiri-sampling:base:1-1:1" など）
    label: str  # 条件の名前など、人間が読むための説明
    text: str
    model_file: str | None = None
    settings: dict[str, Any] = Field(default_factory=dict)  # 生成に使ったパラメータ


class Rating(BaseModel):
    """好みの記録1件。"""

    id: str = Field(default_factory=lambda: secrets.token_hex(4))
    kind: Literal["pair", "score"]
    created_at: datetime = Field(default_factory=lambda: datetime.now().astimezone())
    source: str  # どこで記録したか（"write"、"bench"、"scene"）
    work: str | None = None
    scene: str | None = None
    genre: str | None = None
    a: Candidate
    b: Candidate | None = None  # pair のときだけ
    shown_first: Literal["A", "B"] = "A"  # 先に見せた文章（人間の位置の偏りを調べるため）
    choice: Choice | None = None  # pair のときの答え
    score: int | None = Field(default=None, ge=1, le=5)  # score のときの答え（1〜5）
    reason: str = ""  # 理由（任意）。第28章で、好みのルールを取り出すのに使う

    @model_validator(mode="after")
    def _check_kind(self) -> "Rating":
        if self.kind == "pair" and (self.b is None or self.choice is None):
            raise ValueError("pair には、b と choice が必要です")
        if self.kind == "score" and self.score is None:
            raise ValueError("score には、score が必要です")
        return self

    def chosen(self) -> Candidate | None:
        """選ばれた文章。引き分けや score なら None。"""
        if self.kind != "pair" or self.choice == "tie":
            return None
        return self.a if self.choice == "A" else self.b

    def rejected(self) -> Candidate | None:
        """選ばれなかった文章。引き分けや score なら None。"""
        if self.kind != "pair" or self.choice == "tie":
            return None
        return self.b if self.choice == "A" else self.a


class PreferenceStore:
    """preferences/ratings.jsonl を読み書きする。"""

    def __init__(self, root: Path) -> None:
        self.root = root

    @property
    def path(self) -> Path:
        return self.root / RATINGS_FILE

    @property
    def candidates_dir(self) -> Path:
        return self.root / CANDIDATES_DIR

    def append(self, rating: Rating) -> None:
        """1件を、ファイルの最後に1行で追記する。"""
        self.root.mkdir(parents=True, exist_ok=True)
        with self.path.open("a", encoding="utf-8") as f:
            f.write(rating.model_dump_json() + "\n")

    def load(self) -> tuple[list[Rating], int]:
        """記録をすべて読み込む。読めない行は飛ばし、その数も返す。

        手で編集して壊した行や、書き込みの途中で止まった最後の行があっても、
        ほかの記録は使えるようにする。
        """
        if not self.path.is_file():
            return [], 0
        ratings, broken = [], 0
        for line in self.path.read_text(encoding="utf-8").splitlines():
            if not line.strip():
                continue
            try:
                ratings.append(Rating.model_validate_json(line))
            except ValidationError:
                broken += 1
        return ratings, broken

    def rated_pairs(self) -> set[frozenset[str]]:
        """すでに読み比べた、文章の組（順番は問わない）。"""
        ratings, _ = self.load()
        return {frozenset((r.a.key, r.b.key)) for r in ratings if r.b is not None}

    def write_candidates(self, first: Candidate, second: Candidate) -> tuple[Path, Path]:
        """読み比べる2つの文章を、エディタで開けるファイルに書き出す（前回の分は上書き）。"""
        self.candidates_dir.mkdir(parents=True, exist_ok=True)
        paths = (self.candidates_dir / "1.md", self.candidates_dir / "2.md")
        for path, candidate in zip(paths, (first, second), strict=True):
            path.write_text(candidate.text + "\n", encoding="utf-8")
        return paths


def display_order(rng: random.Random) -> Literal["A", "B"]:
    """先に見せる文章を、ランダムに決める。人間にも、位置の偏りがあるため。"""
    return "A" if rng.random() < 0.5 else "B"


# ---- 集計 ----


@dataclass
class LabelStats:
    """条件（label）ごとの、読み比べの成績。"""

    label: str
    wins: int = 0
    losses: int = 0
    ties: int = 0

    @property
    def win_rate(self) -> float | None:
        """勝率。引き分けを除いて計算する。"""
        decided = self.wins + self.losses
        return self.wins / decided if decided else None


def label_stats(ratings: list[Rating]) -> list[LabelStats]:
    """読み比べの結果を、条件ごとに集計する。勝率の高い順に並べる。"""
    stats: dict[str, LabelStats] = {}
    for r in ratings:
        if r.kind != "pair" or r.b is None:
            continue
        a = stats.setdefault(r.a.label, LabelStats(r.a.label))
        b = stats.setdefault(r.b.label, LabelStats(r.b.label))
        if r.choice == "tie":
            a.ties += 1
            b.ties += 1
        elif r.choice == "A":
            a.wins += 1
            b.losses += 1
        else:
            b.wins += 1
            a.losses += 1
    return sorted(stats.values(), key=lambda s: (s.win_rate is None, -(s.win_rate or 0)))


def first_shown_rate(ratings: list[Rating]) -> float | None:
    """先に見せた文章を選んだ割合（引き分けを除く）。0.5から大きく離れていれば、位置の偏りがある。"""
    decided = [r for r in ratings if r.kind == "pair" and r.choice in ("A", "B")]
    if not decided:
        return None
    return sum(1 for r in decided if r.choice == r.shown_first) / len(decided)


def summary_counts(ratings: list[Rating]) -> Counter[str]:
    """種類ごとの件数（"pair"、"score"、"tie"、source ごと）。"""
    counts: Counter[str] = Counter()
    for r in ratings:
        counts[r.kind] += 1
        counts[f"source:{r.source}"] += 1
        if r.choice == "tie":
            counts["tie"] += 1
    return counts
```

### 記録のモデル

- **`Candidate`**：読み比べる文章1つです。`key` は、文章を識別する文字列で、同じ組を2回読み比べないようにするのに使います。
- **`Rating`**：記録1件です。`model_validator` で、読み比べなら `b` と `choice` が、採点なら `score` があることを確かめます。`id` と `created_at` は、`default_factory` で、記録を作るときに自動で入ります。
- **`chosen`・`rejected`**：選ばれた文章と、選ばれなかった文章を返します。第29章で、好みの学習データ（選ばれた文章と選ばれなかった文章の組）を作るときに使います。

### 読み書き

- **`append`**：`open("a")`（追記モード）で開き、1行を書き足します。Pydanticの `model_dump_json` は、日本語を `雪` のようにエスケープせず、そのまま書きます。ファイルを開いて、記録を目で読めます。
- **`load`**：1行ずつ読み、読めない行は飛ばして、その数を返します。JSONLの「壊れても、その行だけで済む」性質を活かしています。
- **`rated_pairs`**：すでに読み比べた組を、`frozenset`（順番を問わない集合）で返します。AとBを比べた組と、BとAを比べた組を、同じ組として扱うためです。
- **`write_candidates`**：読み比べる2つの文章を、`preferences/candidates/1.md` と `2.md` に書き出します。数千字の文章を端末で読むのは疲れるので、エディタで開いて読めるようにします。

### 集計

- **`label_stats`**：条件（`label`）ごとに、勝ち・負け・同じくらいの数と、勝率を数えます。勝率は、「同じくらい」を除いて計算します。
- **`first_shown_rate`**：先に見せた文章を選んだ割合です。50%から大きく離れていれば、自分に位置の偏りがあります。
- **`display_order`**：先に見せる文章を、ランダムに決めます。

+        choice = shown_first if answer == "1" else other
+    reason = typer.prompt("理由（任意）", default="", show_default=False).strip()

+def rate(

+                        settings=result.settings,

+    except (BenchError, LLMError, StyleError, RulesError, PromptError) as e:

+        raise typer.Exit(1) from e

+@prefs_app.command("agree")
+def prefs_agree(
+    ctx: typer.Context,
+    url: Annotated[str | None, typer.Option("--url", help="比較に使う llama-server のURL")] = None,
+    rubric_name: Annotated[
+        str | None, typer.Option("--rubric", help="ルーブリックの名前（rubrics/<名前>.toml）")
+    ] = None,

+    ] = None,
+) -> None:

+    agree = disagree = undecided = 0
+    try:

+                        client, prompts, config, rubric, r.a.text, r.b.text, context
+                    )
+                if pair.overall == "tie":
+                    undecided += 1
+                    verdict = "LLMは引き分け"
+                elif pair.overall == r.choice:
+                    agree += 1
+                    verdict = "一致"
+                else:
+                    disagree += 1
+                    verdict = "不一致"
+                console.print(
+                    f"  {r.scene or '-'}: あなた {r.choice} / LLM "
+                    f"{WINNER_NAMES[pair.overall]} → {verdict}"

+        console.print(str(e), style="red", markup=False)
+        raise typer.Exit(1) from e
+
+    decided = agree + disagree
+    rate_text = f"{agree / decided:.0%}" if decided else "-"
+    console.print(
+        f"一致率: {rate_text}（一致 {agree}件、不一致 {disagree}件、LLMが引き分け {undecided}件）"

### 読み比べの共通部分

`_read_pair` は、`rate` と `bench rate` で共通の、読み比べの部分です。

1. `display_order` で、先に見せる文章を決めます。
2. 2つの文章を「[1]」「[2]」として表示し、`candidates/` にも書き出します。
3. 「1」「2」「=（同じくらい）」「s（飛ばす）」「q（終わる）」のどれかを入力してもらいます。ほかの文字なら、聞き直します。
4. 画面の番号（1・2）を、記録の `A`・`B` に読み替えます。先に見せたのが `B` なら、「1」は `B` です。
5. 理由を入力してもらいます（Enterだけで飛ばせます）。

戻り値は、答え（`Answer`）か、`"skip"`・`"quit"` のどちらかです。

### rate

`novelist rate 作品のID --scene シーン` は、作品のシーンを、シードを変えて2回書かせ、読み比べます。書かせる処理には、第25章の `write_sample` をそのまま使います。そのため、文体（第23章）と文章の規則（第24章）も、`novelist write` と同じように効きます。2つの版の違いはシードだけなので、「同じ設定で、どちらの書きぶりが好みか」を記録することになります。

`--score` を付けると、書き終えたシーンの本文を表示して、1〜5で採点してもらいます。

`--seed` は、書かせる版のシードと、見せる順番を決める乱数のシードです。普段は指定しません。テストで、結果を毎回同じにするために使います。

### bench rate

`novelist bench rate 評価の名前` は、第25章の比較実験の本文を読み比べます。

- 同じシーン・同じシードの、違う条件の本文を組にします。条件が4つなら、1つのシーン・シードにつき6組です。
- すでに読み比べた組は除き、残りからランダムに `-n`（既定は5）組を選びます。一度にたくさん読むと疲れて判断がいい加減になるので、少しずつ読み比べてください。
- 答えたあとで、「1 は base、2 は temp1.3 でした」と、条件を明かします。
- `-v` で、比べる条件を絞れます。第26章の `bench compare` で候補を2つに絞ったあと、その2つだけを読み比べるときに使います。

### prefs show と prefs agree

`novelist prefs` は、`show` と `agree` の2つのサブコマンドを持つコマンドにします。

- **`prefs show`**：記録の件数、先に見せた文章を選んだ割合、条件ごとの成績、最近の理由を表示します。
- **`prefs agree`**：読み比べの記録を、第26章の `compare_texts`（順番を入れ替えた一対比較）にかけ、LLMの判定が自分の判定と同じかを数えます。自分が「同じくらい」と答えた記録と、LLMが引き分けにした記録は、一致率の計算から除きます。第26章の26.8節で「いちばん大事」とした、採点するモデルの3つめの確かめ方です。

### LLMの判定と比べる

```console
$ uv run novelist prefs agree --url http://127.0.0.1:8090
  1-1: あなた B / LLM B → 一致
  1-1: あなた A / LLM A → 一致
  2-1: あなた A / LLM 引き分け → LLMは引き分け
  2-1: あなた B / LLM A → 不一致
  ...
一致率: 70%（一致 14件、不一致 6件、LLMが引き分け 3件）
```

※ 上の結果は例です。

一致率は、次のように読みます。

- **50%前後**：LLMの判定は、自分の好みとはほとんど関係がありません。コイン投げと同じです
- **60〜70%**：大まかな傾向は合っています。比較実験で候補を絞るのには使えますが、最後は自分で読んで決めてください
- **80%以上**：LLMの判定を、自分の好みの代わりとして、かなり信用できます

一致率が低い場合は、ルーブリック（第26章）の観点が、自分が重視していることとずれている可能性があります。「不一致」になった記録の理由を読み返すと、自分が何を重視しているのかが見えてきます。たとえば、不一致の理由に「台詞」の話ばかりが出てくるなら、ルーブリックの「人物」の重みを上げたり、台詞についての観点を加えたりします。こうした見直しを、第28章で、記録から自動で行えるようにします。

## 27.7 好みを集めるコツ

- **少しずつ、何回かに分けて**：一度に読み比べるのは、5〜10組くらいにします。疲れると、判断が雑になり、位置の偏りも大きくなります
- **「同じくらい」をためらわない**：無理にどちらかを選ぶと、記録にノイズが入ります。差がわからなければ「=」を選んでください
- **迷ったら飛ばす**：「s」で、記録せずに次の組へ進めます
- **理由は具体的に**：27.1節の表のように、文章のどこがどう良かったかを書きます
- **量の目安**：条件ごとの勝率に意味が出てくるのは、1つの条件につき10組くらいからです。第28章で好みのルールを取り出すには、理由付きの記録が20〜30件あると、傾向が見えてきます

## 27.9 うまくいかないときは

**`読めない行が 1行ありました` と表示される**

`ratings.jsonl` に、JSONとして読めない行があります。手で編集したときに、引用符やカンマを消してしまったか、書き込みの途中でコマンドを止めた可能性があります。その行は集計に使われないだけなので、そのままでもかまいません。直す場合は、エディタでその行を消すか、正しいJSONに直してください。

**読み比べる2つの文章が、ほとんど同じ**

`rate` は、同じ設定でシードだけを変えて書かせます。モデルや設定によっては、似た文章になることがあります。その場合は「=」で答えるか、`bench rate` で、設定の違う条件どうしを読み比べてください。

**`bench rate` で `読み比べる組がありません` と表示される**

比較実験の本文が1つの条件にしかないか、すべての組を読み比べ終えています。`novelist bench report 評価の名前` で、条件ごとの件数を確かめてください。

**`prefs agree` に時間がかかる**

読み比べの記録1件につき、第26章の一対比較で2回LLMを呼び出します。記録が増えたら、`-n 20` のように、新しいものから件数を絞ってください。

## 27.10 まとめ

- 2つの文章を読み比べる**A/B比較**と、1つの文章の**採点**で、自分の好みを記録するようにしました
- 見せる順番をランダムにし、どの条件の文章かは答えるまで伏せる**ブラインドテスト**にして、人間の偏りを減らしました
- 記録は**JSONL**に、1件1行で追記します。本文・モデル・パラメータ・理由をまとめて残すので、あとで分析にも学習データにも使えます
- `prefs show` で条件ごとの勝率を、`prefs agree` で第26章のLLMの判定と自分の判定の一致率を確かめられるようにしました

記録には、「どちらが好きか」に加えて、「なぜ好きか」の理由がたまっています。第28章では、この理由をLLMに読ませて、「台詞のあとに説明を足さない」のような**好みのルール**を取り出し、本文を書くプロンプトと、第26章のルーブリックに反映します。
