# 第12章 企画とログライン

第III部では、企画から推敲までの工程を順に作り、1本の短編を仕上げる多段パイプラインを完成させます。

```text
企画（第12章）→ 設定（第13章）→ プロット（第14章）→ 執筆（第15章）→ 推敲（第16章）
                                    ↑
                       中断・再開・人間の介入（第17章）
```

最初の工程は**企画**です。第7章の一発生成では、「ミステリー、鉄道、冬」という条件だけを渡して、いきなり本文を書かせていました。どんな話にするかをLLMにすべて任せたため、ありきたりな展開になりやすかったのです。

人間の書き手は、書き始める前に「どんな話にするか」をいくつか考え、その中から面白いものを選びます。この章では、LLMに**切り口の違う企画案を複数出させ、人間がその中から選ぶ**工程を作ります。選んだ企画は、作品のディレクトリに保存し、第13章以降のすべての工程の出発点にします。

この章で作るものは次のとおりです。

| ファイル・コマンド | 内容 |
|---|---|
| `src/novelist/schemas/concept.py` | 企画案のモデル |
| `src/novelist/schemas/work.py` | 作品のメタデータのモデル |
| `src/novelist/work.py` | 作品のディレクトリ（`works/<ID>/`）を作る・読む |
| `src/novelist/planning.py` | 企画案を作る工程 |
| `prompts/concept/` | 企画案を作るプロンプト |

| `novelist works` | 作品の一覧を表示するコマンド |

## 12.1 企画に必要なもの

### ログライン

企画の中心になるのが**ログライン**です。ログラインは、物語を**1文**で要約したもので、映画や小説の企画でよく使われます。よいログラインには、次の3つが含まれています。

| 要素 | 内容 | 例 |
|---|---|---|
| 主人公 | 誰の物語か | 元駅員の男が |
| 目的 | 主人公は何を求めているか | 消えた切符の持ち主を突き止めようとする |
| 障害 | 何がそれを阻むか | 雪で足止めされた終着駅で、夜明けまでに |

```text
雪で足止めされた終着駅で、元駅員の男が、消えた切符の持ち主を夜明けまでに突き止めようとする。
```

1文で書けない企画は、たいてい物語の芯がはっきりしていません。LLMに企画を作らせるときも、ログラインを必須にすることで、物語の芯を最初に決めさせます。

### 企画案の項目

本書では、1つの企画案を次の項目で表します。

| 項目 | 内容 | あとの工程での使い道 |
|---|---|---|
| タイトル | 作品のタイトル | 原稿の書き出し |
| 切り口 | 何を中心にした物語か | 企画案どうしの違いを出す |
| ログライン | 物語の芯（1文） | すべての工程の指示に含める |
| 舞台 | 時代と場所 | 世界設定（第13章） |
| 主人公 | 主人公の人物像 | 登場人物の設定（第13章） |
| あらすじ | 結末までの流れ（200字程度） | プロット（第14章） |
| 仕掛け | 読者を最後まで引き込む要素 | プロット、伏線（第31章） |

**あらすじには結末まで書かせる**ことが大切です。ミステリーなら、謎の答えまで決めておきます。結末が決まっていないまま書き始めると、第7章で見たように、伏線が回収されないまま終わってしまいます。

### 切り口を変えて似た企画を避ける

第7章の実験3で、同じ条件で何度書かせても、似た人物や展開になることを見ました。企画案を3つ出させても、そのままでは「少しずつ違うだけの似た案」が3つ並びがちです。

そこで、企画案ごとに**切り口**を選ばせ、3つとも違う切り口にすることを条件にします。

| 切り口 | 物語の中心 |
|---|---|
| 人物の葛藤 | 主人公の内面の変化 |
| 事件の謎 | 事件の真相 |
| 舞台の特殊性 | その場所ならではの状況 |
| 意外な組み合わせ | ふつうは一緒にならない要素の組み合わせ |
| 時間の仕掛け | 過去と現在、時間の制限など |

「切り口が重複しない」という条件は、JSONスキーマでは表せないので、第10章の `model_validator` で検証し、満たさなければLLMに直させます。

## 12.2 モデルを定義する

### 企画案

**`src/novelist/schemas/concept.py`**（新規）

```python
"""作品の企画（第12章）。"""

from typing import Literal

from pydantic import BaseModel, Field, model_validator

CONCEPT_COUNT = 3  # 一度に出す企画案の数

Angle = Literal["人物の葛藤", "事件の謎", "舞台の特殊性", "意外な組み合わせ", "時間の仕掛け"]


class Concept(BaseModel):
    """1つの企画案。"""

    title: str = Field(description="作品のタイトル", max_length=30)
    angle: Angle = Field(description="この企画の切り口")
    logline: str = Field(description="ログライン。主人公・目的・障害がわかる1文", max_length=120)
    setting: str = Field(description="舞台となる時代と場所", max_length=60)
    protagonist: str = Field(description="主人公の人物像", max_length=80)
    premise: str = Field(description="結末まで含めたあらすじ（200字程度）", max_length=400)
    hook: str = Field(description="読者を最後まで引き込む仕掛け", max_length=120)


class ConceptList(BaseModel):
    """企画案の一覧。"""

    concepts: list[Concept] = Field(min_length=CONCEPT_COUNT, max_length=CONCEPT_COUNT)

    @model_validator(mode="after")
    def _check_variety(self) -> "ConceptList":
        """企画案どうしが似すぎないようにする。"""
        angles = [c.angle for c in self.concepts]
        if len(set(angles)) != len(angles):
            raise ValueError(f"企画案ごとに異なる切り口にしてください（現在: {'、'.join(angles)}）")
        titles = [c.title for c in self.concepts]
        if len(set(titles)) != len(titles):
            raise ValueError("タイトルが重複しています")
        return self
```

- **`Angle`**：切り口の5つの選択肢を `Literal` で定義しています。型に名前を付けておくと、ほかのモジュールからも使えます。
- **`CONCEPT_COUNT`**：一度に出す企画案の数です。`ConceptList` の `min_length` と `max_length` の両方に指定して、ちょうど3つにしています。
- **`_check_variety`**：切り口とタイトルが重複していないかを確かめます。`set` にすると重複が取り除かれるので、元のリストと長さが違えば重複があるとわかります。

```python
"""作品のメタデータ（第12章）。"""

from datetime import datetime
from typing import Literal

from pydantic import BaseModel, ConfigDict, Field

from novelist.schemas.concept import Concept

# 作品の長さの区分と、目標の文字数
TARGET_CHARS = {"short": 10_000, "long": 100_000}


class WorkMeta(BaseModel):
    """works/<slug>/work.toml に保存する、作品の基本情報。"""

    model_config = ConfigDict(extra="forbid")

    slug: str  # 作品のID（ディレクトリ名）
    genre: str
    tags: list[str] = Field(default_factory=list)  # 取り入れたい要素
    avoid: list[str] = Field(default_factory=list)  # 避けたい要素
    length: Literal["short", "long"] = "short"
    target_chars: int  # 目標の文字数
    created_at: datetime
    concept: Concept  # 採用した企画
```

- **`slug`**：作品のIDです。作品のディレクトリの名前に使います。
- **`tags` と `avoid`**：取り入れたい要素と、避けたい要素です。どちらも自分の**好み**を表すもので、第VI部で好みを学習するときの手がかりにもなります。
- **`length` と `target_chars`**：長さの区分と目標の文字数です。第III部から第VI部までは短編（約1万字）を扱い、第VII部で長編（`long`）に対応します。
- **`concept`**：採用した企画案です。第13章以降の工程は、ここから始まります。

### 作品のディレクトリを扱うモジュール

**`src/novelist/work.py`**（新規）

```python
"""作品ディレクトリ（works/<slug>/）を扱う（第12章）。"""

import re
import tomllib
from pathlib import Path

import tomli_w

from novelist.schemas.work import WorkMeta

SLUG_RE = re.compile(r"^[a-z0-9][a-z0-9-]{0,63}$")


class WorkError(Exception):
    """作品ディレクトリを扱えなかったときの例外。"""


class Work:
    """1つの作品のディレクトリ。"""

    def __init__(self, root: Path) -> None:
        self.root = root

    @property
    def slug(self) -> str:
        return self.root.name

    @property
    def meta_path(self) -> Path:
        return self.root / "work.toml"

    @property
    def concepts_path(self) -> Path:
        return self.root / "concepts.json"

    @staticmethod
    def check_slug(slug: str) -> None:
        """作品のIDとして使える文字列か確かめる。"""
        if not SLUG_RE.match(slug):
            raise WorkError(
                f"作品のID '{slug}' は使えません。"
                "半角の英小文字・数字・ハイフンで、英小文字か数字から始めてください"
            )

    @classmethod
    def create(cls, works_dir: Path, meta: WorkMeta) -> "Work":
        """新しい作品のディレクトリを作り、メタデータを保存する。"""
        cls.check_slug(meta.slug)
        root = works_dir / meta.slug
        try:
            root.mkdir(parents=True, exist_ok=False)
        except FileExistsError as e:
            raise WorkError(f"作品 '{meta.slug}' はすでにあります（{root}）") from e
        work = cls(root)
        work.save_meta(meta)
        return work

    @classmethod
    def open(cls, works_dir: Path, slug: str) -> "Work":
        """既存の作品を開く。"""
        work = cls(works_dir / slug)
        if not work.meta_path.is_file():
            raise WorkError(f"作品 '{slug}' が見つかりません（{work.meta_path}）")
        return work

    def save_meta(self, meta: WorkMeta) -> None:
        """メタデータを work.toml に保存する。"""
        data = meta.model_dump(exclude_none=True)
        self.meta_path.write_text(tomli_w.dumps(data), encoding="utf-8")

    def load_meta(self) -> WorkMeta:
        """work.toml からメタデータを読み込む。"""
        with self.meta_path.open("rb") as f:
            return WorkMeta.model_validate(tomllib.load(f))


def list_works(works_dir: Path) -> list[WorkMeta]:
    """作品の一覧を、作成日時の順に返す。"""
    if not works_dir.is_dir():
        return []
    metas = [Work(p).load_meta() for p in works_dir.iterdir() if (p / "work.toml").is_file()]
    return sorted(metas, key=lambda m: m.created_at)
```

**`check_slug`**

作品のIDに使える文字を、半角の英小文字・数字・ハイフンに限定しています。IDはディレクトリ名になるので、日本語や空白、大文字を使うと、OSによっては扱いにくくなるためです。

**`create`**

`root.mkdir(parents=True, exist_ok=False)` は、`exist_ok=False` を指定しているので、同じ名前のディレクトリがすでにあると `FileExistsError` を発生させます。これを `WorkError` に変換して、うっかり既存の作品を上書きしないようにしています。

**`save_meta` と `load_meta`**

`model_dump()` でPydanticのモデルを辞書にし、`tomli_w.dumps()` でTOMLの文字列にします。TOMLには「値がない」ことを表す書き方（JSONの `null` のようなもの）がないので、`exclude_none=True` で `None` の項目を除いています。

読み込むときは、`tomllib.load()` で辞書にし、`WorkMeta.model_validate()` で検証します。TOMLは日時の型を持っているので、`created_at` は `datetime` のまま保存・読み込みできます。

**`list_works`**

`works/` の中で、`work.toml` があるディレクトリだけを作品として読み込み、作成日時の順に並べます。

### 企画案を作る関数

**`src/novelist/planning.py`**（新規）

```python
"""企画の工程（第12章）。"""

from novelist.config import Config
from novelist.llm.client import LLMClient
from novelist.llm.structured import generate_structured, schema_text
from novelist.prompts import PromptLibrary
from novelist.schemas.concept import CONCEPT_COUNT, Concept, ConceptList


def generate_concepts(
    client: LLMClient,
    prompts: PromptLibrary,
    config: Config,
    *,
    genre: str,
    tags: list[str],
    avoid: list[str],
    target_chars: int,
    profile: str | None = "creative",
) -> list[Concept]:
    """ジャンルと好みから、切り口の異なる企画案を作る。"""
    messages = prompts.render(
        "concept",
        genre=genre,
        tags=tags,
        avoid=avoid,
        target_chars=target_chars,
        count=CONCEPT_COUNT,
        schema=schema_text(ConceptList),
    )
    sampling = config.sampling_for(profile)
    sampling = sampling.model_copy(update={"max_tokens": max(sampling.max_tokens, 4096)})
    return generate_structured(client, messages, ConceptList, sampling).concepts
```

第10章の `generate_structured` で、`ConceptList` の形式の企画案を作ります。

既定のプロファイルは `creative` です。企画は、意外性やアイデアの幅が大事な工程なので、`precise` ではなく `creative` を使います。第10章で説明したとおり、形式は文法で守られるので、`temperature` を上げても出力が壊れる心配はありません。

企画案は3つ分の項目をJSONで出力するので、出力はかなり長くなります。`max_tokens` は、プロファイルの値が小さくても4096から始めるようにしています。それでも途中で切れた場合は、第10章の `generate_structured` が `max_tokens` を2倍にしてやり直します（上限は16384）。

**思考モデルを使っている場合**は、思考の部分だけで数千トークンを使うことがあり、生成に時間がかかります。第10章で説明したとおり、プロファイルに `reasoning_effort = "none"` を指定して、思考を止めてください。企画案の生成は `creative` プロファイルを使うので、`creative` にも指定します。

```toml
[profiles.creative]
...
reasoning_effort = "none"  # 思考モデルの場合
```

この関数は、LangGraphのノードではなく、ふつうの関数として作っています。企画の選択は人間が行うので、CLIのコマンドの中で「作る → 表示する → 人間が選ぶ」を繰り返すほうが自然だからです。選んだ企画は `work.toml` に保存され、第13章以降のグラフは、そこから始まります。

```diff
+        console.print(f"    舞台: {c.setting} / 主人公: {c.protagonist}", markup=False, style="dim")
+        console.print(f"    {c.premise}", markup=False)
+        console.print(f"    仕掛け: {c.hook}", markup=False, style="dim")
+        console.print()
+
+
+@app.command()
+def new(
+    ctx: typer.Context,
+    slug: Annotated[str, typer.Argument(help="作品のID（英小文字・数字・ハイフン）")],
+    genre: Annotated[str, typer.Option("--genre", "-g", help="ジャンル")] = "ミステリー",
+    tags: Annotated[
+        str, typer.Option("--tags", "-t", help="取り入れたい要素（カンマ区切り）")
+    ] = "",
+    avoid: Annotated[str, typer.Option("--avoid", help="避けたい要素（カンマ区切り）")] = "",
+    length: Annotated[Length, typer.Option("--length", help="長さの区分")] = Length.short,
+    profile: Annotated[
+        str | None, typer.Option("--profile", "-p", help="novelist.toml のプロファイル名")
+    ] = "creative",
+    pick: Annotated[
+        int | None, typer.Option("--pick", help="選ぶ企画の番号（省略すると入力を求める）")
+    ] = None,
+) -> None:
+    """企画案を作って選び、新しい作品を作ります。"""
+    config = _load_config(ctx)
+    try:
+        Work.check_slug(slug)
+        if (config.works_dir / slug).exists():
+            raise WorkError(f"作品 '{slug}' はすでにあります（{config.works_dir / slug}）")
+    except WorkError as e:
+        console.print(str(e), style="red", markup=False)
+        raise typer.Exit(1) from e
+
+    tag_list = [tag.strip() for tag in tags.split(",") if tag.strip()]
+    avoid_list = [a.strip() for a in avoid.split(",") if a.strip()]
+    target_chars = TARGET_CHARS[length.value]
+    history: list[dict] = []  # 作った企画案をすべて記録する
+
+    try:
+        with LLMClient(config.server) as client:
+            prompts = PromptLibrary(config.prompts_dir)
+            round_no = 0
+            while True:
+                round_no += 1
+                with console.status("企画案を考えています..."):
+                    concepts = generate_concepts(
+                        client,
+                        prompts,
+                        config,
+                        genre=genre,
+                        tags=tag_list,
+                        avoid=avoid_list,
+                        target_chars=target_chars,
+                        profile=profile,
+                    )
+                history += [
+                    {"round": round_no, "index": i, **c.model_dump()}
+                    for i, c in enumerate(concepts, start=1)
+                ]
+                console.print(f"企画案を{len(concepts)}件生成しました。\n")
+                _print_concepts(concepts)
+
+                choice = pick if pick is not None else _ask_choice(len(concepts))
+                if choice != 0:
+                    break
+    except (LLMError, PromptError) as e:
+        console.print(str(e), style="red", markup=False)
+        raise typer.Exit(1) from e
+
+    if not 1 <= choice <= len(concepts):
+        console.print(f"番号は1〜{len(concepts)}で指定してください", style="red")
+        raise typer.Exit(1)
+
+    chosen = concepts[choice - 1]
+    meta = WorkMeta(
+        slug=slug,
+        genre=genre,
+        tags=tag_list,
+        avoid=avoid_list,
+        length=length.value,
+        target_chars=target_chars,
+        created_at=datetime.now().astimezone().replace(microsecond=0),
+        concept=chosen,
+    )
+    for item in history:
+        item["chosen"] = item["round"] == round_no and item["index"] == choice
+    try:
+        work = Work.create(config.works_dir, meta)
+    except WorkError as e:
+        console.print(str(e), style="red", markup=False)
+        raise typer.Exit(1) from e
+    work.concepts_path.write_text(
+        json.dumps(history, ensure_ascii=False, indent=2), encoding="utf-8"
+    )
+    console.print(f"{work.root}/ を作成しました。「{chosen.title}」")
+
+
+@app.command()
+def works(ctx: typer.Context) -> None:
+    """作品の一覧を表示します。"""
+    config = _load_config(ctx)
+    metas = list_works(config.works_dir)
+    if not metas:
+        console.print(f"作品はまだありません（{config.works_dir}/）")
+        return
+    table = Table()
+    table.add_column("ID", style="cyan")
+    table.add_column("タイトル")
+    table.add_column("ジャンル")
+    table.add_column("長さ", justify="right")
+    table.add_column("作成日時")
+    for m in metas:
+        table.add_row(
+            m.slug,
+            m.concept.title,
+            m.genre,
+            f"{m.target_chars:,}字",
+            f"{m.created_at:%Y-%m-%d %H:%M}",
+        )
+    console.print(table)
```

**`Length`**

`--length` の選択肢を、列挙型（`StrEnum`）で定義しています。Typerは、引数の型が列挙型だと、その値だけを受け付ける選択肢として扱い、ヘルプに `<short|long>` のように表示してくれます。`StrEnum` は、値が文字列の列挙型で、Python 3.11から標準ライブラリに入っています。

**`_ask_choice`**

`typer.prompt(..., type=int)` で、整数の入力を求めます。整数でない入力は、Typerが自動で聞き直します。範囲外の数字は自分で確かめて、聞き直すようにしています。

**`new`**

1. 作品のIDが使えるか、すでに同じ作品がないかを、**LLMを呼ぶ前に**確かめます。企画案を作ってから「その名前は使えません」と言われると、時間が無駄になるからです。
2. `generate_concepts` で企画案を作り、番号付きで表示します。
3. 採用する番号を選んでもらいます。`0` を選ぶと、企画案を作り直します。`--pick` を指定すると、入力を求めずにその番号を選びます（スクリプトから実行するときやテストで使います）。
4. 選んだ企画で `WorkMeta` を作り、`Work.create` で作品のディレクトリを作ります。
5. 作り直した分も含めて、作った企画案をすべて `concepts.json` に記録します。どれを選んだかは `chosen` で区別します。

作ったすべての企画案と、その中からどれを選んだかの記録は、第VI部で好みを学習するときのデータになります。「どんな企画を選び、どんな企画を選ばなかったか」は、自分の好みをよく表すからです。

作成日時は、`datetime.now().astimezone()` でタイムゾーン付きにし、`replace(microsecond=0)` で秒より細かい部分を切り捨てています。

**`works`**

作品の一覧を表にして表示します。

```diff
+    assert 'title = "最終列車の忘れ物"' in (work_dir / "work.toml").read_text(encoding="utf-8")
+    history = json.loads((work_dir / "concepts.json").read_text(encoding="utf-8"))
+    assert [item["chosen"] for item in history] == [False, True, False]

+def test_new_interactive(monkeypatch: pytest.MonkeyPatch, tmp_path: Path) -> None:
+    concepts = json.dumps(CONCEPTS_DATA, ensure_ascii=False)
+    server = ChatRecorder([concepts, concepts])
+    use_chat_recorder(monkeypatch, server)
+    config = write_works_config(tmp_path)
+    # 0: 作り直す → 5: 範囲外 → 3: 3番目を選ぶ
+    result = runner.invoke(app, ["--config", str(config), "new", "shasho"], input="0\n5\n3\n")
+    assert result.exit_code == 0
+    assert len(server.requests) == 2  # 作り直したので2回生成した
+    assert "0〜3の番号を入力してください" in result.output
+    history = json.loads(
+        (tmp_path / "works" / "shasho" / "concepts.json").read_text(encoding="utf-8")
+    )
+    assert len(history) == 6
+    chosen = [item for item in history if item["chosen"]]
+    assert chosen[0]["round"] == 2
+    assert chosen[0]["title"] == "車掌日誌"

+
+def test_new_invalid_slug(tmp_path: Path) -> None:
+    config = write_works_config(tmp_path)

+    assert result.exit_code == 1
+    assert "使えません" in result.output

+def test_works(monkeypatch: pytest.MonkeyPatch, tmp_path: Path) -> None:
+    config = write_works_config(tmp_path)
+    result = runner.invoke(app, ["--config", str(config), "works"])
+    assert "作品はまだありません" in result.output

+    assert "霧の終着駅" in result.output
```

- **`write_works_config`**：第8章の `write_config` で作った設定ファイルの先頭に、`works_dir` を追加します。作品が、テストごとの一時ディレクトリに作られるようにするためです。TOMLのセクションに属さない項目は、ファイルの先頭に書く必要があるので（第8章）、既存の内容の前に追加しています。

## 12.7 まとめ

- 企画の中心は**ログライン**です。主人公・目的・障害を1文で書かせることで、物語の芯を最初に決めます
- あらすじは**結末まで**書かせ、謎には答えを用意させます
- 企画案ごとに**切り口**を選ばせ、重複を `model_validator` で禁止することで、似た企画案が並ぶのを防ぎます
- 企画は、LLMが複数の案を出し、**人間が選ぶ**工程にしました。選ばなかった案も含めて記録し、好みの学習に使えるようにしています
- 作品ごとに `works/<ID>/` を作り、メタデータを `work.toml` に保存するようにしました。TOMLなので、人間が読んで直せます
- `novelist new` で企画を選んで作品を作り、`novelist works` で一覧を表示できるようになりました

次の第13章では、選んだ企画から、**登場人物と世界設定のシート**を作ります。第10章の登場人物の生成を発展させ、場所や用語も含めた設定資料として `bible/` に保存します。
