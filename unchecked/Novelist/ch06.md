# 第6章 PythonからLLMを呼ぶ

第5章で `llama-server` が動くようになりました。この章では、`novelist` のPythonコードから `llama-server` を呼び出す**LLMクライアント**を作ります。第I部の最後の章で、これ以降のすべての章がこのクライアントを使ってLLMとやり取りします。

この章で作るものは次のとおりです。

| ファイル | 内容 |
|---|---|
| `novelist.toml` | 接続先や生成のパラメータをまとめた設定ファイル |
| `src/novelist/config.py` | 設定ファイルを読み込むモジュール |
| `src/novelist/llm/client.py` | `llama-server` と通信するクライアント |
| `novelist doctor` | `llama-server` に接続できるかを確認するコマンド |
| `novelist tokens` | 文字列のトークン数を数えるコマンド |
| `novelist ask` | LLMに指示を送り、応答をストリーミングで表示するコマンド |

## 6.1 llama-serverのAPI

まず、`novelist` から使う `llama-server` のAPIを整理しておきます。第5章で `curl` を使って試したものです。

| メソッド | パス | 種類 | 内容 |
|---|---|---|---|
| GET | `/health` | 独自 | サーバーの状態。読み込み中は503を返す |
| GET | `/v1/models` | OpenAI互換 | モデル名（`--alias`）とコンテキスト長など |
| GET | `/props` | 独自 | GGUFファイルのパスなど、サーバーの設定 |
| POST | `/tokenize` | 独自 | 文字列をトークンに分割する |
| POST | `/v1/chat/completions` | OpenAI互換 | チャットの応答を生成する |

`llama-server` のAPIは、**OpenAI互換のAPI**と、**llama.cpp独自のAPI**の2種類からなります。OpenAI互換のAPIは、OpenAIのサービスと同じ形式のリクエストを受け付けるので、多くのツールからそのまま使えます。独自のAPIは、トークン数の計算など、ローカルで動かすからこそ使える機能を提供します。

### チャットのリクエストと応答

`/v1/chat/completions` に送るJSONは、次のような形です。

```json
{
  "model": "novelist",
  "messages": [
    {"role": "system", "content": "あなたは小説家です。"},
    {"role": "user", "content": "雪の駅を舞台に、書き出しの一文を書いてください。"}
  ],
  "temperature": 0.8,
  "top_p": 0.95,
  "max_tokens": 1024,
  "stream": false
}
```

`temperature` や `top_p` は、第3章で説明した「次のトークンをどう選ぶか」を決めるパラメータです（詳しくは第9章で扱います）。`max_tokens` は、生成するトークン数の上限です。

`llama-server` は、OpenAIのAPIにはない**独自のパラメータ**も受け付けます。たとえば `min_p`（確率の低いトークンを除外する）や `repeat_penalty`（同じ表現の繰り返しを抑える）などです。第9章以降で、小説の文章の質を調整するのに使います。

### ストリーミング

`"stream": true` にすると、生成が終わるのを待たずに、生成されたそばから少しずつ応答が返ってきます。形式は **Server-Sent Events（SSE）** で、`data: ` で始まる行に、JSONが1つずつ入っています。

```text
data: {"choices":[{"finish_reason":null,"index":0,"delta":{"role":"assistant","content":null}}],...}

data: {"choices":[{"finish_reason":null,"index":0,"delta":{"content":"終電"}}],...}

data: {"choices":[{"finish_reason":null,"index":0,"delta":{"content":"の"}}],...}

data: {"choices":[{"finish_reason":"stop","index":0,"delta":{}}],...}

data: {"choices":[],"usage":{"completion_tokens":18,"prompt_tokens":35,...},"timings":{...},...}

data: [DONE]
```

- `delta.content` に、新しく生成された文字列が入っています。これを順につなげると、応答の全文になります。
- 生成が終わると、`finish_reason` に終了の理由が入ります。
- リクエストに `"stream_options": {"include_usage": true}` を付けておくと、最後に `usage`（トークン数）と `timings`（処理時間）が届きます。
- 最後の `data: [DONE]` が、応答の終わりの印です。

小説の本文のように長い文章を生成するときは、全部を待つと数分かかることもあります。ストリーミングで表示すれば、生成の様子を見ながら、おかしな方向に進んでいたらすぐに止められます。

## 6.2 HTTPクライアントにhttpxを使う

OpenAI互換のAPIを呼ぶには、OpenAIの公式Python SDK（`openai` パッケージ）を使う方法もあります。しかし本書では、HTTPクライアントライブラリの **httpx** を使って、APIを直接呼び出します。理由は3つあります。

1. **llama-server独自の機能を素直に使える**：`min_p` などの独自のパラメータや、応答の `timings` は、OpenAIのAPIにはありません。SDKで扱うには、特別な書き方が必要になります。
2. **やり取りの中身が見える**：送るJSONと受け取るJSONを自分で組み立てて読むので、何が起きているかがわかります。うまく動かないときに、第5章の `curl` の結果と見比べられます。
3. **依存が少ない**：SDKは頻繁に大きく更新されます。本書で使うのはAPIのごく一部なので、自分で書いても数十行で済みます。

必要なライブラリを追加します。httpxに加えて、設定ファイルの検証に **Pydantic** を使います。

```console
$ uv add httpx pydantic
```

## 6.3 設定ファイル

### novelist.toml

接続先のURLや、生成のパラメータをコードに直接書いてしまうと、モデルを替えたり調整したりするたびにコードを書き換えることになります。そこで、これらを設定ファイルにまとめます。形式は、`pyproject.toml` と同じ **TOML** です。

プロジェクトのルートに `novelist.toml` を作ります。

**`novelist.toml`**（新規）

```toml
# novelist の設定ファイル

[server]
url = "http://127.0.0.1:8080"  # llama-server のURL
model = "novelist"             # llama-server の --alias で付けた名前
timeout = 600                  # 1回のリクエストの制限時間（秒）

# 生成のパラメータの既定値（第9章で詳しく扱います）
[sampling]
temperature = 0.8
top_p = 0.95
max_tokens = 1024

# プロファイル: [sampling] の一部を上書きする設定のまとまり
[profiles.precise]  # 設定資料やJSONなど、正確さが大事な出力
temperature = 0.3

[profiles.creative]  # 小説の本文など、表現の豊かさが大事な出力
temperature = 1.0
max_tokens = 4096
```

3つのセクションがあります。

- **`[server]`**：`llama-server` への接続設定です。`model` には、第5章で `--alias` に指定した名前を書きます。
- **`[sampling]`**：生成のパラメータの既定値です。
- **`[profiles.名前]`**：**プロファイル**です。`[sampling]` の一部を上書きする設定に名前を付けたものです。

プロファイルを使うのは、工程によって適した設定が違うからです。設定資料をJSONで出力するときは、指定した形式を正確に守ってほしいので `temperature` を低くします。小説の本文を書くときは、表現に幅を持たせたいので高くします。第III部で工程ごとのノードを作るときに、それぞれのノードがプロファイルを指定して生成します。

プロファイルに書いた項目だけが上書きされ、書いていない項目は `[sampling]` の値を引き継ぎます。たとえば `creative` プロファイルは、`temperature = 1.0`、`top_p = 0.95`（`[sampling]` から）、`max_tokens = 4096` になります。

### 設定を読み込むモジュール

**`src/novelist/config.py`**（新規）

```python
"""設定ファイル（novelist.toml）を読み込む。"""

import tomllib
from pathlib import Path
from typing import Any

from pydantic import BaseModel, ConfigDict, Field

DEFAULT_CONFIG_PATH = Path("novelist.toml")


class ServerConfig(BaseModel):
    """llama-server への接続設定。"""

    model_config = ConfigDict(extra="forbid")

    url: str = "http://127.0.0.1:8080"  # llama-server のURL（/v1 は付けない）
    model: str = "novelist"  # llama-server の --alias で付けた名前
    api_key: str | None = None  # llama-server の --api-key を使う場合だけ指定
    timeout: float = 600.0  # 1回のリクエストの制限時間（秒）


class SamplingConfig(BaseModel):
    """生成のパラメータ。

    ここに定義していないパラメータ（llama-server 独自のものなど）も、
    そのままリクエストに含めて送る。
    """

    model_config = ConfigDict(extra="allow")

    temperature: float = 0.8
    top_p: float = 0.95
    max_tokens: int = 1024
    seed: int | None = None


class Config(BaseModel):
    """novelist.toml 全体。"""

    model_config = ConfigDict(extra="forbid")

    server: ServerConfig = Field(default_factory=ServerConfig)
    sampling: SamplingConfig = Field(default_factory=SamplingConfig)
    profiles: dict[str, dict[str, Any]] = Field(default_factory=dict)

    def sampling_for(self, profile: str | None = None) -> SamplingConfig:
        """プロファイルの設定で [sampling] を上書きした、生成のパラメータを返す。"""
        if profile is None:
            return self.sampling
        if profile not in self.profiles:
            names = ", ".join(self.profiles) or "(なし)"
            raise KeyError(f"プロファイル '{profile}' がありません。定義済み: {names}")
        merged = self.sampling.model_dump() | self.profiles[profile]
        return SamplingConfig.model_validate(merged)


def load_config(path: Path | None = None) -> Config:
    """設定ファイルを読み込む。ファイルがなければ既定値を使う。"""
    path = path or DEFAULT_CONFIG_PATH
    if not path.exists():
        return Config()
    with path.open("rb") as f:
        data = tomllib.load(f)
    return Config.model_validate(data)
```

**Pydanticのモデル**

`BaseModel` を継承したクラスは、Pydanticの**モデル**です。フィールドの型と既定値を書いておくと、`model_validate()` に辞書を渡したときに、型が合っているかを検証し、足りない項目には既定値を入れてくれます。

```python
>>> ServerConfig.model_validate({"url": "http://127.0.0.1:9000"})
ServerConfig(url='http://127.0.0.1:9000', model='novelist', api_key=None, timeout=600.0)
>>> ServerConfig.model_validate({"timeout": "たくさん"})
pydantic_core._pydantic_core.ValidationError: 1 validation error for ServerConfig
timeout
  Input should be a valid number, unable to parse string as a number ...
```

Pydanticは、第10章でLLMの出力（JSON）を検証するときにも使います。ここで基本的な使い方に慣れておきましょう。

**`extra="forbid"` と `extra="allow"`**

`model_config = ConfigDict(extra=...)` は、定義していない項目が来たときの扱いを決めます。

- `ServerConfig` と `Config` は `forbid`（禁止）にしています。`url` を `urll` と書き間違えたときに、黙って無視されるのではなく、エラーで気づけるようにするためです。
- `SamplingConfig` は `allow`（許可）にしています。`llama-server` は多くの独自のパラメータを受け付けるので、それらをすべて定義しなくても、設定ファイルに書けばそのままリクエストに含められるようにしています。

**`sampling_for`**

プロファイルを適用した `SamplingConfig` を返します。`model_dump()` で `[sampling]` を辞書にし、`|` 演算子でプロファイルの辞書を重ねます（右側の値が優先されます）。その結果をもう一度 `model_validate()` に通して、型を検証しています。

**`load_config`**

TOMLファイルを読み込むには、Python 3.11から標準ライブラリに入った `tomllib` を使います。`tomllib.load()` にはバイナリモード（`"rb"`）で開いたファイルを渡します。設定ファイルがない場合は、すべて既定値の `Config()` を返します。`novelist.toml` がなくても、`llama-server` を既定の設定で起動していれば、そのまま動きます。

## 6.4 LLMクライアント

`llama-server` と通信するクライアントを作ります。

**`src/novelist/llm/client.py`**（新規）

```python
"""llama-server と通信するクライアント。"""

import json
from collections.abc import Callable
from dataclasses import dataclass
from typing import Any

import httpx

from novelist.config import SamplingConfig, ServerConfig

Message = dict[str, str]


class LLMError(Exception):
    """llama-server との通信に失敗したときの例外。"""


@dataclass
class Usage:
    """1回の生成で使ったトークン数と速度。"""

    prompt_tokens: int = 0  # 入力のトークン数
    completion_tokens: int = 0  # 出力のトークン数
    tokens_per_second: float | None = None  # 生成速度（llama-server の timings から）


@dataclass
class ChatResult:
    """チャットの応答。"""

    text: str
    finish_reason: str | None  # "stop"（終了トークン）または "length"（長さの上限）
    usage: Usage


@dataclass
class ServerInfo:
    """llama-server で動いているモデルの情報。"""

    model: str  # モデル名（--alias）
    model_path: str | None  # GGUFファイルのパス
    n_ctx: int | None  # 実行時のコンテキスト長（-c）
    n_ctx_train: int | None  # 学習時のコンテキスト長


def _parse_usage(data: dict[str, Any]) -> Usage:
    """応答のJSONから usage と timings を取り出す。"""
    usage = data.get("usage") or {}
    timings = data.get("timings") or {}
    return Usage(
        prompt_tokens=usage.get("prompt_tokens", 0),
        completion_tokens=usage.get("completion_tokens", 0),
        tokens_per_second=timings.get("predicted_per_second"),
    )


class LLMClient:
    """llama-server のOpenAI互換APIと独自APIを呼び出すクライアント。"""

    def __init__(self, server: ServerConfig, transport: httpx.BaseTransport | None = None) -> None:
        headers = {"Authorization": f"Bearer {server.api_key}"} if server.api_key else {}
        self.server = server
        self._http = httpx.Client(
            base_url=server.url,
            headers=headers,
            timeout=server.timeout,
            transport=transport,
        )

    def close(self) -> None:
        self._http.close()

    def __enter__(self) -> "LLMClient":
        return self

    def __exit__(self, *exc: object) -> None:
        self.close()

    def _post(self, path: str, payload: dict[str, Any]) -> dict[str, Any]:
        """JSONをPOSTし、応答のJSONを返す。"""
        try:
            response = self._http.post(path, json=payload)
        except httpx.HTTPError as e:
            raise LLMError(f"{self.server.url} に接続できません: {e}") from e
        if response.status_code != 200:
            raise LLMError(
                f"{path} がエラーを返しました（{response.status_code}）: {response.text}"
            )
        return response.json()

    def health(self) -> bool:
        """サーバーがリクエストを受け付けられる状態かどうか。"""
        try:
            response = self._http.get("/health")
        except httpx.HTTPError:
            return False
        return response.status_code == 200

    def server_info(self) -> ServerInfo:
        """動いているモデルの情報を取得する。"""
        try:
            models = self._http.get("/v1/models").json()
            props = self._http.get("/props").json()
        except httpx.HTTPError as e:
            raise LLMError(f"{self.server.url} に接続できません: {e}") from e
        model = models["data"][0]
        meta = model.get("meta") or {}
        return ServerInfo(
            model=model["id"],
            model_path=props.get("model_path"),
            n_ctx=meta.get("n_ctx"),
            n_ctx_train=meta.get("n_ctx_train"),
        )

    def count_tokens(self, text: str) -> int:
        """文字列のトークン数を、動いているモデルのトークナイザーで数える。"""
        data = self._post("/tokenize", {"content": text})
        return len(data["tokens"])

    def _chat_payload(
        self, messages: list[Message], sampling: SamplingConfig, stream: bool
    ) -> dict[str, Any]:
        """チャットのリクエストのJSONを組み立てる。"""
        payload = {
            "model": self.server.model,
            "messages": messages,
            "stream": stream,
            **sampling.model_dump(exclude_none=True),
        }
        if stream:
            # ストリーミングでも、最後にトークン数（usage）を送ってもらう
            payload["stream_options"] = {"include_usage": True}
        return payload

    def chat(self, messages: list[Message], sampling: SamplingConfig) -> ChatResult:
        """チャットの応答を、生成が終わってからまとめて受け取る。"""
        data = self._post("/v1/chat/completions", self._chat_payload(messages, sampling, False))
        choice = data["choices"][0]
        return ChatResult(
            text=choice["message"]["content"] or "",
            finish_reason=choice.get("finish_reason"),
            usage=_parse_usage(data),
        )

    def stream_chat(
        self,
        messages: list[Message],
        sampling: SamplingConfig,
        on_text: Callable[[str], None],
    ) -> ChatResult:
        """チャットの応答を、生成されたそばから on_text に渡す。"""
        payload = self._chat_payload(messages, sampling, True)
        parts: list[str] = []
        finish_reason = None
        last: dict[str, Any] = {}  # 最後に届いた usage と timings
        try:
            with self._http.stream("POST", "/v1/chat/completions", json=payload) as response:
                if response.status_code != 200:
                    response.read()
                    raise LLMError(
                        f"/v1/chat/completions がエラーを返しました"
                        f"（{response.status_code}）: {response.text}"
                    )
                for line in response.iter_lines():
                    # Server-Sent Events: "data: {...}" の行だけを読む
                    if not line.startswith("data: "):
                        continue
                    body = line.removeprefix("data: ")
                    if body == "[DONE]":
                        break
                    chunk = json.loads(body)
                    for choice in chunk.get("choices", []):
                        text = choice.get("delta", {}).get("content")
                        if text:
                            parts.append(text)
                            on_text(text)
                        if choice.get("finish_reason"):
                            finish_reason = choice["finish_reason"]
                    for key in ("usage", "timings"):
                        if chunk.get(key):
                            last[key] = chunk[key]
        except httpx.HTTPError as e:
            raise LLMError(f"{self.server.url} に接続できません: {e}") from e
        return ChatResult(
            text="".join(parts), finish_reason=finish_reason, usage=_parse_usage(last)
        )
```

順に見ていきます。

**データクラス**

`Usage`、`ChatResult`、`ServerInfo` は、応答から必要な情報だけを取り出して入れておく入れ物です。`@dataclass` を付けると、`__init__` などを自動で作ってくれます。設定ファイルと違って外から来た値を検証する必要がないので、Pydanticではなく標準ライブラリの `dataclasses` を使っています。

**`LLMClient.__init__`**

`httpx.Client` を作ります。`base_url` を指定しておくと、以降は `/health` のようにパスだけでリクエストを送れます。`timeout` は、1回のリクエストの制限時間です。小説の本文を生成するときは数分かかることもあるので、既定値を600秒と長めにしています。

`transport` 引数は、テストのためのものです（6.7節）。通常は `None` のままで、本物のネットワークで通信します。

**`__enter__` と `__exit__`**

これらを定義すると、`with` 文で使えるようになります。`with` のブロックを抜けるときに `close()` が呼ばれ、ネットワークの接続が確実に片付けられます。

```python
with LLMClient(config.server) as client:
    result = client.chat(messages, sampling)
```

**`_post` と `LLMError`**

JSONを送り、応答のJSONを返す共通の処理です。接続できない場合（`httpx.HTTPError`）や、サーバーがエラーを返した場合（ステータスコードが200以外）は、`LLMError` という独自の例外に変換します。呼び出す側は `LLMError` だけを受け止めればよくなります。

**`health`、`server_info`、`count_tokens`**

第5章で `curl` で試した `/health`、`/v1/models`、`/props`、`/tokenize` を呼び出します。`health` は、接続できない場合も含めて `False` を返すだけにしています。サーバーが動いているかの確認に使うので、例外にしないほうが扱いやすいからです。

**`_chat_payload`**

チャットのリクエストのJSONを組み立てます。`sampling.model_dump(exclude_none=True)` で、生成のパラメータを辞書にして展開しています。`exclude_none=True` は、値が `None` の項目（`seed` を指定しない場合など）を含めないという指定です。`SamplingConfig` は `extra="allow"` なので、設定ファイルに書いた独自のパラメータもここに含まれます。

**`chat`**

生成が終わるまで待って、応答をまとめて受け取ります。LLMの出力をプログラムで処理する場合（第10章のJSON出力など）は、こちらを使います。

**`stream_chat`**

ストリーミングで応答を受け取ります。

- `self._http.stream(...)` は、応答の本文を一度に読み込まず、届いたそばから読めるようにする書き方です。
- `response.iter_lines()` で、応答を1行ずつ読みます。`data: ` で始まる行だけを取り出し、`[DONE]` が来たら終わります。
- `delta.content` に文字列があれば、`on_text` に渡します。

新しい文字列が届くたびに呼ばれる関数（**コールバック**）を、引数 `on_text` で受け取る設計にしています。こうすると、クライアントは「文字列が届いた」ことを知らせるだけで、それをどう表示するか（画面に出す、ファイルに書く、何もしない）は呼び出す側が決められます。戻り値は、全文をつなげた `ChatResult` です。

`usage` と `timings` は、最後のほうのデータに入って届きます。届いたものを `last` に取っておき、最後に `_parse_usage` で取り出しています。

- ファイルがなければ、すべて既定値になる

## 6.8 まとめ

- `llama-server` のAPIには、OpenAI互換のAPI（`/v1/chat/completions` など）と、独自のAPI（`/health`、`/tokenize` など）があります
- 独自のパラメータや `timings` を素直に扱うため、SDKを使わず、httpxでAPIを直接呼び出すクライアントを作りました
- ストリーミングでは、SSEの `data: ` の行を1行ずつ読み、`delta.content` をつなげて全文にします
- 接続先と生成のパラメータを `novelist.toml` にまとめ、**プロファイル**で工程ごとに切り替えられるようにしました。Pydanticで設定の書き間違いを検出します
- `novelist doctor` で接続を確認し、`novelist tokens` でトークン数を数え、`novelist ask` でLLMに指示を送れるようになりました
- httpxの `MockTransport` を使って、本物のサーバーなしでクライアントとCLIをテストしました

これで第I部は終わりです。自分のGPUに合うモデルを選び、`llama-server` で動かし、Pythonから呼び出す準備が整いました。

次の第II部では、いよいよ小説を書かせます。第7章では、1回の呼び出しで短編を書かせる最小の実装を作り、その限界を観察するところから始めます。
