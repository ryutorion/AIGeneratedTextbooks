# 第25章 モデル・量子化・サンプリングの比較実験 — 同一プロットで出力を比べる評価ハーネス

ここまでで、本文の書き方を左右する設定がたくさん増えました。どのモデルを使うか（第4章）、どの量子化にするか（第3章・第4章）、サンプリングのパラメータ（第9章）、文体の見本（第23章）、文章の規則（第24章）です。

設定を変えたとき、文章はよくなったのでしょうか。1回書かせて読み比べるだけでは、よくわかりません。LLMの出力は同じ設定でも毎回違うので、1回の差が設定の違いによるものか、たまたまなのか、区別できないからです。第9章の `sweep` コマンドでは、1つのパラメータを変えながら短編を書かせて比べましたが、1回ずつしか書かせていませんでした。

この章では、同じ作品の同じシーンを、条件を変えて何回も書かせ、測った値を条件ごとに集計する**評価ハーネス**（比較実験の仕組み）を作ります。

この章で作るものは次のとおりです。

| ファイル・コマンド | 内容 |
|---|---|
| `benches/<名前>/bench.toml` | 比較実験の条件 |
| `src/novelist/bench.py` | 条件を読み込み、書かせ、測り、集計する |
| `novelist bench run` | 条件ごとにシーンを書かせて測る |
| `novelist bench judge` | 書いた本文を、同じモデルで採点する |
| `novelist bench report` | 条件ごとに、平均とばらつきを表にする |

## 25.1 比較実験の組み立て方

### 変えるものと、そろえるもの

比較実験では、**比べたいもの以外をすべてそろえる**ことが大切です。

**変えるもの（条件）**

- モデルと量子化（`llama-server` に読み込ませるGGUFファイル）
- サンプリングのパラメータ（プロファイルと、その上書き）
- 文体の見本（第23章）と、文章の規則（第24章）

**そろえるもの**

- 作品の設定資料とプロット
- 書かせるシーンと、その前までのあらすじ・直前の本文
- プロンプトのテンプレート

書かせるシーンの情報は、作品にすでに保存されている本文とあらすじから作ります。どの条件でも、まったく同じシーンの情報を渡すので、違いは条件だけから生まれます。書いた本文は作品には保存せず、比較実験のディレクトリに保存します。作品の本文を書き換えてしまうと、次の条件に渡す「直前の本文」が変わってしまうからです。

この章の比較実験では、第20章の検索と予算、第21章の一貫性のチェック、第22章のストーリーステート、第16章の推敲は使いません。これらを使うと、条件の違いの影響が、何段もの処理を通って混ざり合い、何が効いたのかわかりにくくなるからです。比べるのは、**1回で書かせた初稿**です。

### 何回書かせるか

同じ条件でも、書かせるたびに文章は違います。そこで、1つの条件で何回か書かせて、その平均とばらつきを見ます。

- **シード**（第9章）を変えて、同じシーンを何回か書かせます。本書では3回を目安にします
- **シーン**を2つ以上にします。会話の多いシーンと描写の多いシーンのように、性格の違うシーンを選ぶと、1つのシーンの得意・不得意に引っぱられにくくなります

2つのシーンを3つのシードで書かせると、1つの条件で6回です。条件が4つなら24回になります。1回に1〜2分かかるとすると、30分から1時間ほどの実験になります。条件やシーンを増やすときは、時間と相談してください。

### 何を測るか

書いた本文ごとに、次の値を測ります。

| 指標 | 内容 | 出どころ |
|---|---|---|
| 長さ | 目安の文字数との比 | 第15章 |
| 速度 | 1秒あたりに生成したトークン数 | `llama-server` の `timings` |
| 会話 | 会話文の文字の割合 | 第7章の `text_stats` |
| 繰り返し | 同じ10文字の並びが2回以上出てくる割合 | 第7章の `text_stats` |
| 違反・警告 | 文章の規則を守れていない箇所の数 | 第24章の `lint` |
| 見本との重なり | 文体の見本の文を、そのまま使った割合 | 第23章の `copied_ratio` |
| 点数 | 第16章の批評の点数（5つの観点の平均） | LLMによる採点 |

点数以外は、プログラムで確実に測れる値です。点数はLLMの判断なので、測り方に注意が要ります。

### 採点は、同じモデルで

条件ごとに違うモデルで書かせるとき、それぞれのモデルに自分の本文を採点させてはいけません。採点の甘さ・厳しさもモデルによって違うので、点数の差が文章の差なのか、採点者の差なのか、わからなくなるからです。**採点は、すべての条件を同じモデルで行います**。

もう1つ、LLMには、自分が書いた文章を高く評価しがちな傾向があることが知られています（**自己選好**）。採点に使うモデルが、ある条件で書いたモデルと同じなら、その条件の点数は割り引いて見る必要があります。採点のぶれや偏りを減らす方法は、第26章で詳しく扱います。この章では、採点に使うモデルを書くモデルと分けられるようにしておき、同じ場合は注意を表示します。

### 数字だけで決めない

測った値は、あくまで目安です。「繰り返し」が少なくても退屈な文章はありますし、「点数」が高くても自分の好みに合わない文章もあります。数字で候補を絞り、最後は**本文を読んで**決めてください。書いた本文は、すべてファイルに残るようにします。

### モデルの入れ替え

サンプリングの条件は、同じ `llama-server` にパラメータを変えて頼むだけなので、すぐに切り替えられます。しかし、モデルや量子化を変えるには、`llama-server` を起動し直す必要があります。

そこで、比較実験は**条件ごとに分けて実行できる**ようにします。

1. 1つめのモデルで `llama-server` を起動し、その条件だけを実行する
2. `llama-server` を止めて、2つめのモデルで起動し直し、その条件だけを実行する
3. …

実行した結果はすぐにファイルに保存し、同じ条件・シーン・シードの組み合わせがすでにあれば飛ばします。途中で止まっても、もう一度実行すれば続きから書きます。

モデルを入れ替える手順では、「別のモデルを読み込ませたつもりで、前のモデルのまま実行してしまう」という失敗が起きがちです。条件に**期待するモデルのファイル名**（`expect_model`）を書いておき、`llama-server` の `/props` で動いているモデルのファイル名を確かめて、違えば実行しないようにします。

## 25.2 比較実験の条件を書く

比較実験は、プロジェクトの `benches/` ディレクトリに、1つの実験を1つのディレクトリとして置きます。

```text
benches/
└── kiri-sampling/
    ├── bench.toml            # 条件
    └── results/              # 結果（bench run で作られる。Gitでは管理しない）
        ├── base/
        │   ├── 01-01-s1.md   # 本文（1-1 をシード1で書いたもの）
        │   ├── 01-01-s1.json # 測った値と点数
        │   ...
        └── temp0.7/
            ...
```

### サンプリングを比べる

**`benches/kiri-sampling/bench.toml`**（新規）

```toml
# 同じモデルで、サンプリングの設定を比べる（第25章）
description = "サンプリングの比較（温度・min_p・DRY）"
work = "kiri-no-eki"     # 設定資料とプロットを借りる作品
scenes = ["1-1", "2-1"]  # 書かせるシーン（性格の違うシーンを選ぶ）
seeds = [1, 2, 3]        # シードを変えて、同じ条件で何回書かせるか

[[variants]]
name = "base"            # novelist.toml の creative プロファイルのまま

[[variants]]
name = "temp0.7"
sampling = { temperature = 0.7 }

[[variants]]
name = "temp1.3"
sampling = { temperature = 1.3, min_p = 0.1 }

[[variants]]
name = "no-dry"
sampling = { dry_multiplier = 0.0 }  # 繰り返しを抑える DRY を止める
```

- `work` は、設定資料とプロットを借りる作品です。書かせるシーンより前のシーンは、作品で書き終えておいてください。前のシーンがなくても実行はできますが、あらすじと直前の本文が空のまま書かせることになります。
- `[[variants]]` が、比べる条件です。`name` は結果のディレクトリ名になるので、英数字と `_` `.` `-` だけを使います。
- 条件に書かなかった項目は、`novelist.toml` と作品の設定に従います。`base` は何も書いていないので、`novelist write` で書くときと同じ設定になります。比べる条件には、このような**基準**を必ず1つ入れておきます。
- `sampling` は、`profile`（既定は `creative`）のパラメータを上書きします。書き方は第6章のプロファイルと同じです。

### モデルと量子化を比べる

**`benches/kiri-models/bench.toml`**（新規）

```toml
# モデルと量子化を比べる（第25章）
# 条件ごとに llama-server を起動し直し、novelist bench run kiri-models -v 条件名 で書かせる
description = "モデルと量子化の比較"
work = "kiri-no-eki"
scenes = ["1-1", "2-1"]
seeds = [1, 2, 3]

# 採点は、すべての条件を同じモデルで行う。書くモデルとは別のサーバーを用意する
[judge]
url = "http://127.0.0.1:8090"

[[variants]]
name = "14b-q4"
expect_model = "my-model-14b-Q4_K_M"  # サーバーのモデルのファイル名に、この文字列を含むこと

[[variants]]
name = "14b-q6"
expect_model = "my-model-14b-Q6_K"

[[variants]]
name = "moe-q4"
expect_model = "my-moe-30b-a3b-Q4_K_M"
```

- `expect_model` は、`llama-server` で動いているモデルのファイル名に含まれるはずの文字列です。違うモデルが動いていれば、その条件は実行しません。
- `[judge]` の `url` は、採点に使う `llama-server` です。省略すると、`novelist.toml` の `[server]` を使います。
- 条件ごとに別の `llama-server` を立てておけるなら、`url` を条件ごとに書くこともできます（`url = "http://127.0.0.1:8082"` など）。そうすれば、起動し直さずに、すべての条件を一度に実行できます。ただし、複数のモデルを同時に読み込むだけのVRAMが必要です。

BENCH_FILE = "bench.toml"

NAME_RE = r"^[A-Za-z0-9_.-]+$"  # 条件の名前（ディレクトリ名に使う）


class BenchError(Exception):
    """評価ハーネスの設定や実行に問題があるときの例外。"""


class Variant(BaseModel):
    """比べる条件の1つ。書かなかった項目は、novelist.toml と作品の設定に従う。"""

    model_config = ConfigDict(extra="forbid")

    name: str = Field(pattern=NAME_RE)  # 条件の名前
    url: str | None = None  # llama-server のURL。省略すると novelist.toml の [server] の url
    expect_model: str | None = None  # モデルのファイル名に含まれるはずの文字列（"Q4_K_M" など）
    profile: str = WRITE_PROFILE  # サンプリングのプロファイル
    sampling: dict[str, Any] = Field(default_factory=dict)  # プロファイルをさらに上書きする値
    style: str | None = None  # 文体の見本。省略すると作品の設定、"none" で使わない
    rules: dict[str, Any] = Field(default_factory=dict)  # 文章の規則の上書き


class JudgeSettings(BaseModel):
    """採点に使う llama-server。すべての条件を、同じモデルで採点する。"""

    model_config = ConfigDict(extra="forbid")

    url: str | None = None  # 省略すると novelist.toml の [server] の url


class BenchSpec(BaseModel):
    """bench.toml の中身。"""

    model_config = ConfigDict(extra="forbid")

    description: str = ""
    work: str  # 設定資料とプロットを借りる作品のID
    scenes: list[str] = Field(min_length=1)  # 書かせるシーン（"1-1" など）
    seeds: list[int] = Field(default_factory=lambda: [1, 2, 3], min_length=1)
    variants: list[Variant] = Field(min_length=1)
    judge: JudgeSettings = Field(default_factory=JudgeSettings)

    @field_validator("scenes")
    @classmethod
    def _check_scenes(cls, scenes: list[str]) -> list[str]:
        for key in scenes:
            parse_scene_key(key)  # 形が正しくなければ ValueError
        return scenes

    @field_validator("variants")
    @classmethod
    def _check_names(cls, variants: list[Variant]) -> list[Variant]:
        names = [v.name for v in variants]
        duplicates = sorted({n for n in names if names.count(n) > 1})
        if duplicates:
            raise ValueError(f"条件の名前が重なっています: {', '.join(duplicates)}")
        return variants


class SampleResult(BaseModel):
    """1回の生成（条件・シーン・シードの組）の結果。"""

    variant: str
    scene: str
    seed: int
    model_file: str | None  # 書いたモデルのファイル名
    settings: dict[str, Any]  # 実際に使ったサンプリングのパラメータ
    style: str | None  # 使った文体の見本
    target_chars: int  # シーンの目安の文字数
    chars: int
    finish_reason: str | None
    prompt_tokens: int
    completion_tokens: int
    seconds: float  # 生成にかかった時間（秒）
    tokens_per_second: float | None  # 生成速度（llama-server の計測）
    dialogue_ratio: float  # 会話の割合（第7章）
    repeated_ratio: float  # 繰り返しの割合（第7章）
    errors: int  # 文章の規則の違反の数（第24章）
    warnings: int  # 文章の規則の警告の数（第24章）
    copied: float | None  # 文体の見本との重なり（第23章）。見本を使わなければ None
    created_at: datetime
    # 採点（bench judge で入る）
    score: float | None = None
    scores: dict[str, int] | None = None
    judge_model: str | None = None

    @property
    def key(self) -> tuple[str, str, int]:
        return self.variant, self.scene, self.seed


def _file_name(scene: str, seed: int) -> str:
    i, j = parse_scene_key(scene)
    return f"{i:02d}-{j:02d}-s{seed}"


class Bench:
    """benches/<名前>/ の評価ハーネス。"""

    def __init__(self, root: Path, spec: BenchSpec) -> None:
        self.root = root
        self.name = root.name
        self.spec = spec

    @property
    def results_dir(self) -> Path:
        return self.root / RESULTS_DIR

    def text_path(self, variant: str, scene: str, seed: int) -> Path:
        return self.results_dir / variant / f"{_file_name(scene, seed)}.md"

    def result_path(self, variant: str, scene: str, seed: int) -> Path:
        return self.results_dir / variant / f"{_file_name(scene, seed)}.json"

    def has_result(self, variant: str, scene: str, seed: int) -> bool:
        return self.result_path(variant, scene, seed).is_file()

    def save(self, result: SampleResult, text: str) -> None:
        """本文（先頭に条件を書いたMarkdown）と、結果のJSONを保存する。"""
        meta = {"variant": result.variant, "scene": result.scene, "seed": result.seed}
        meta |= {"model": result.model_file, **result.settings}
        write_story(self.text_path(*result.key), meta, text)
        self.update(result)

    def update(self, result: SampleResult) -> None:
        """結果のJSONだけを保存し直す（採点したとき）。"""
        self.result_path(*result.key).write_text(result.model_dump_json(indent=2), encoding="utf-8")

    def load_text(self, result: SampleResult) -> str:
        return read_story(self.text_path(*result.key))[1]

    def load_results(self) -> list[SampleResult]:
        """保存した結果を、bench.toml の条件・シーン・シードの順に読み込む。"""
        results = []
        for v in self.spec.variants:
            for scene in self.spec.scenes:
                for seed in self.spec.seeds:
                    path = self.result_path(v.name, scene, seed)
                    if path.is_file():
                        results.append(SampleResult.model_validate_json(path.read_text("utf-8")))
        return results


def list_benches(benches_dir: Path) -> list[str]:
    if not benches_dir.is_dir():
        return []
    return sorted(p.name for p in benches_dir.iterdir() if (p / BENCH_FILE).is_file())


def load_bench(benches_dir: Path, name: str) -> Bench:
    """benches/<name>/bench.toml を読み込む。"""
    path = benches_dir / name / BENCH_FILE
    if not path.is_file():
        names = ", ".join(list_benches(benches_dir)) or "(なし)"
        raise BenchError(f"評価 '{name}' が見つかりません（{path}）。あるもの: {names}")
    try:
        with path.open("rb") as f:
            spec = BenchSpec.model_validate(tomllib.load(f))
    except (tomllib.TOMLDecodeError, ValidationError) as e:
        raise BenchError(f"{path} を読み込めません: {e}") from e
    return Bench(path.parent, spec)

@dataclass
class BenchInputs:
    """作品から読み込んだ、すべての条件で共通の材料。"""

    work: Work
    meta: WorkMeta
    world: WorldSheet
    characters: CharacterSheet
    plot: Plot
    records: dict[str, SceneRecord]

    @classmethod
    def load(cls, work: Work) -> "BenchInputs":
        world, characters = work.load_bible()
        plot = work.load_plot()
        return cls(work, work.load_meta(), world, characters, plot, work.load_scene_records(plot))

    def brief(self, scene: str) -> SceneBrief:
        """シーンを書くための情報。作品に保存されている本文とあらすじを、そのまま使う。"""
        i, j = parse_scene_key(scene)
        if (i, j) not in [(ci, cj) for ci, cj, _ in self.plot.scenes()]:
            raise BenchError(f"シーン {scene} は、作品のプロットにありません")
        previous = previous_scene_text(self.work, self.plot, i, j)
        return build_brief(self.plot, self.world, self.characters, i, j, self.records, previous)


def variant_sampling(
    config: Config, variant: Variant, seed: int, max_tokens: int
) -> SamplingConfig:
    """条件のサンプリングのパラメータ。プロファイル → 条件の sampling → シードの順に重ねる。"""
    try:
        base = config.sampling_for(variant.profile)
        merged = base.model_dump() | variant.sampling | {"seed": seed, "max_tokens": max_tokens}
        return SamplingConfig.model_validate(merged)
    except (KeyError, ValidationError) as e:
        raise BenchError(
            f"条件 '{variant.name}' のサンプリングの設定が正しくありません: {e}"
        ) from e


def variant_rules(config: Config, guide: StyleGuide | None, variant: Variant) -> RulesConfig:
    """条件の文章の規則。novelist.toml → 文体 → 条件の rules の順に重ねる。"""
    rules = merge_rules(config.rules, guide.rules if guide is not None else None)
    return merge_rules(rules, variant.rules)


def style_name(variant: Variant, meta: WorkMeta) -> str | None:
    """条件で使う文体の名前。書いていなければ作品の設定に従う。"""
    name = variant.style if variant.style is not None else meta.style
    return None if name in (None, NO_STYLE) else name


def check_model(client: LLMClient, variant: Variant) -> str | None:
    """サーバーで動いているモデルのファイル名を返す。期待したモデルでなければエラーにする。"""
    info = client.server_info()
    model_file = Path(info.model_path).name if info.model_path else None
    if variant.expect_model and variant.expect_model not in (model_file or ""):
        raise BenchError(
            f"条件 '{variant.name}' は、ファイル名に '{variant.expect_model}' を含むモデルを"
            f"想定していますが、{client.server.url} では {model_file} が動いています"
        )
    return model_file


def write_sample(
    client: LLMClient,
    prompts: PromptLibrary,
    config: Config,
    inputs: BenchInputs,
    variant: Variant,
    guide: StyleGuide | None,
    scene: str,
    seed: int,
    model_file: str | None,
) -> tuple[SampleResult, str]:
    """1つの条件・シーン・シードで本文を書き、測る。"""
    brief = inputs.brief(scene)
    rules = variant_rules(config, guide, variant)
    messages = prompts.render(
        "scene", meta=inputs.meta, world=inputs.world, brief=brief, feedback=None, rules=rules
    )
    samples = select_samples(guide, config.style.samples) if guide is not None else []
    if guide is not None:
        messages = style_messages(prompts, messages, guide, samples)
    sampling = variant_sampling(config, variant, seed, int(brief.scene.chars * WRITE_TOKENS_RATIO))

    started = time.perf_counter()
    result = client.chat(messages, sampling)
    seconds = time.perf_counter() - started
    if not result.text.strip() and result.reasoning:
        raise LLMError(
            "本文が書かれないまま、思考（reasoning）だけで終わりました。"
            f"条件 '{variant.name}' の sampling に reasoning_effort = \"none\" を指定してください"
        )

    text = result.text
    if result.finish_reason == "length":
        text = trim_incomplete(text)
    text, _ = normalize(clean_scene_text(text), rules)
    stats = text_stats(text)
    findings = lint(text, rules)
    return (
        SampleResult(
            variant=variant.name,
            scene=scene,
            seed=seed,
            model_file=model_file,
            settings=sampling.model_dump(exclude_none=True),
            style=guide.name if guide is not None else None,
            target_chars=brief.scene.chars,
            chars=stats.chars,
            finish_reason=result.finish_reason,
            prompt_tokens=result.usage.prompt_tokens,
            completion_tokens=result.usage.completion_tokens,
            seconds=round(seconds, 2),
            tokens_per_second=result.usage.tokens_per_second,
            dialogue_ratio=stats.dialogue_ratio,
            repeated_ratio=stats.repeated_ratio,
            errors=sum(1 for f in findings if f.severity == "error"),
            warnings=sum(1 for f in findings if f.severity == "warning"),
            copied=copied_ratio(text, samples) if samples else None,
            created_at=datetime.now().astimezone(),
        ),
        text,
    )

@dataclass
class Summary:
    """1つの条件の結果の、平均とばらつき。"""

    variant: str
    n: int  # 結果の数
    models: list[str]  # 書いたモデルのファイル名
    values: dict[str, list[float]]  # 指標ごとの値

    def mean(self, name: str) -> float | None:
        values = self.values.get(name) or []
        return statistics.mean(values) if values else None

    def stdev(self, name: str) -> float | None:
        values = self.values.get(name) or []
        return statistics.stdev(values) if len(values) >= 2 else None


# 集計する指標（SampleResult から値を取り出す関数）
METRICS = {
    "length": lambda r: r.chars / r.target_chars,
    "tps": lambda r: r.tokens_per_second,
    "dialogue": lambda r: r.dialogue_ratio,
    "repeated": lambda r: r.repeated_ratio,
    "errors": lambda r: r.errors,
    "warnings": lambda r: r.warnings,
    "copied": lambda r: r.copied,
    "score": lambda r: r.score,
}


def summarize_results(bench: Bench, results: list[SampleResult]) -> list[Summary]:
    """条件ごとに、指標の値を集める。値のない指標（採点していない、など）は除く。"""
    summaries = []
    for v in bench.spec.variants:
        mine = [r for r in results if r.variant == v.name]
        values = {
            name: [float(x) for r in mine if (x := get(r)) is not None]
            for name, get in METRICS.items()
        }
        models = sorted({r.model_file for r in mine if r.model_file})
        summaries.append(Summary(v.name, len(mine), models, values))
    return summaries


def export_csv(results: list[SampleResult], path: Path) -> None:
    """結果を1行1件のCSVにする。表計算ソフトで詳しく調べるときに使う。"""
    fields = [name for name in SampleResult.model_fields if name not in ("settings", "scores")]

### 条件の設定

- **`Variant`**・**`BenchSpec`**：`bench.toml` を検証するモデルです。シーンの形（`"1-1"`）と、条件の名前が重なっていないことを、読み込んだ時点で確かめます。
- **`SampleResult`**：1回の生成の結果です。条件・シーン・シードの組で1つです。測った値に加えて、使ったモデルのファイル名と、実際に使ったサンプリングのパラメータも記録します。あとで「この結果は、どの設定で書いたものか」を確かめられるようにするためです。これは、第32章で扱う再現性の考え方にもつながります。
- **`Bench`**：結果の保存先を決め、保存と読み込みをします。本文は、第7章の `write_story` で、先頭に条件を書いたMarkdownとして保存します。本文を開けば、どの条件で書いたものかがすぐにわかります。

### 書かせて測る

- **`BenchInputs`**：作品から、すべての条件で共通の材料（設定資料・プロット・書き終えたシーンの記録）を読み込みます。`brief` は、第15章の `build_brief` で、シーンを書くための情報を作ります。
- **`variant_sampling`**：プロファイル → 条件の `sampling` → シードと `max_tokens` の順に重ねます。`sampling` に `temprature` のような書き間違いがあれば、`SamplingConfig` の `extra="forbid"` のおかげで、エラーになります。
- **`variant_rules`**：`novelist.toml` → 文体 → 条件の `rules` の順に、第24章の規則を重ねます。
- **`check_model`**：`llama-server` の `/props` で、動いているモデルのファイル名を調べます。`expect_model` があれば、ファイル名に含まれているかを確かめます。
- **`write_sample`**：本文を書かせて、測ります。
  - プロンプトは、`novelist write` と同じ `scene` のプロンプトに、第23章の文体の見本を入れたものです。見本は、埋め込みを使わずに選びます（`select_samples` に埋め込みのクライアントを渡しません）。シーンごとに選ぶ見本が変わると、条件のほかに見本の違いが混ざるからです。
  - `stream_chat` ではなく `chat` を使います。比較実験では、生成中の本文を表示する必要がないからです。かかった時間は、`time.perf_counter` で測ります。
  - 書いた本文は、第15章の `clean_scene_text` と第24章の `normalize` で整えてから測ります。`novelist write` で保存される本文と同じ形で比べるためです。

### 採点する

- **`judge_sample`**：第16章の `critique_scene_text` で批評させ、5つの観点の点数の平均を、点数として記録します。批評のプロンプトとプロファイル（`precise`）は、第16章と同じです。

### 集計する

- **`summarize_results`**：条件ごとに、指標の値を集めて `Summary` にします。値のない指標（採点していない結果の点数など）は除きます。
- **`Summary`**：平均（`mean`）と標準偏差（`stdev`）を計算します。標準偏差は、値が2つ以上ないと計算できないので、そのときは `None` を返します。
- **`export_csv`**：すべての結果を、1行1件のCSVにします。文字コードを `utf-8-sig`（BOM付きのUTF-8）にしているのは、ExcelでCSVを開いたときに、日本語が文字化けしないようにするためです。

## 25.8 差があると言えるか

表の「点数」が、条件Aは7.43、条件Bは7.20だったとします。Aのほうがよいのでしょうか。

同じ条件で6回書かせた点数には、±0.3ほどのばらつきがあります。0.23の差は、このばらつきより小さいので、たまたまの差かもしれません。本書では、次の目安で判断することにします。

- **差が、両方の条件の標準偏差より小さい**：差があるとは言えない。ほかの指標や、本文を読んだ印象で決める
- **差が、標準偏差の2倍より大きい**：差がありそう。シードやシーンを増やして、もう一度確かめる価値がある

これは統計的な検定ではなく、大まかな目安です。より厳密に比べたい場合は、`--csv` で書き出した結果を、表計算ソフトや統計のツールで分析してください。1件1行になっているので、シーンごと・シードごとに並べて、同じシーンの同じシードどうしで比べる（対応のある比較）こともできます。

差を見つけやすくするには、次のようにします。

- **シードを増やす**：3回を5回にすると、平均のぶれが小さくなります
- **シーンを増やす**：1つのシーンだけでは、そのシーンとの相性の差を、条件の差と取り違えることがあります。`--by-scene` で、シーンごとに同じ傾向が出ているかを確かめてください
- **採点のぶれを減らす**：採点そのものがぶれると、差が見えにくくなります。第26章で、採点のぶれを減らす方法を扱います

> **シードと再現性**
>
> 第9章で見たとおり、同じモデル・同じ設定・同じシードなら、`llama-server` は普通は同じ文章を返します。この章の比較実験でも、条件ごとに同じシードの組を使っています。ただし、モデルが違えば、同じシードでも書く文章はまったく違うので、シードをそろえることに特別な意味はありません。シードは、「同じ条件で、違う文章を何本か書かせる」ために使っています。
>
> また、GPUの計算の順番や、`llama-server` の並列処理の設定によっては、同じシードでも少し違う文章になることがあります。比較実験の結果は、「そのとき、その環境で測った値」として扱ってください。

## 25.10 うまくいかないときは

**正しいモデルを起動したのに、`expect_model` が合わないと言われる**

`expect_model` は、モデルのファイル名に、その文字列がそのまま含まれるかを調べます。大文字と小文字も区別します。量子化の名前は、ファイルによって `Q4_K_M` だったり `q4_k_m` だったりするので、エラーメッセージに表示されたファイル名に合わせて書いてください。

**思考モデルで、本文が書かれない**

第15章と同じく、思考（reasoning）だけで `max_tokens` を使い切っています。比較実験では、`novelist.toml` のプロファイルとは別に、条件の `sampling` に `reasoning_effort = "none"` を書くこともできます。思考を止めた場合と止めない場合を、条件として比べることもできます。

**速度が「速度不明」になる**

`llama-server` の応答に `timings` が含まれていません。古い `llama-server` や、OpenAI互換の別のサーバーを使っている場合に起きます。第5章の手順で、新しい `llama.cpp` をビルドしてください。

**採点の点数が、どの条件もほとんど同じ**

採点に使うモデルが、差を見分けられていない可能性があります。第16章の批評の点数は、1〜10点の整数を5つ平均したものなので、細かい差は出にくくなっています。採点用のモデルを大きなものにするか、第26章の評価ルーブリックで、差が出やすい採点の仕方に変えてください。

**書いた本文がどれも短い、または途中で切れている**

作品に、書かせるシーンより前のシーンが保存されていないと、あらすじと直前の本文が空になり、シーンのつながりがわからないまま書くことになります。`novelist plot 作品のID` で、前のシーンが書き終えてあるかを確かめてください。

## 25.11 まとめ

- 同じ作品の同じシーンを、条件（モデル・量子化・サンプリング・文体・規則）を変えて何回も書かせ、測った値を条件ごとに集計する**評価ハーネス**を作りました
- 比べたいもの以外は、そろえます。シーンの情報は作品に保存された本文とあらすじから作り、推敲や検索などの処理は使わずに、初稿を比べます
- シードとシーンを変えて何回か書かせ、**平均と標準偏差**で比べます。差が標準偏差より小さければ、差があるとは言えません
- 文章の長さ・会話・繰り返し・規則の違反など、**プログラムで測れる指標**と、LLMによる**点数**を組み合わせました。採点は、すべての条件を同じモデルで行います
- モデルの入れ替えに合わせて、条件ごとに実行し、続きから書けるようにしました。`expect_model` で、違うモデルのまま実行してしまう失敗を防ぎます
- 数字で候補を絞ったあと、最後は本文を読んで決めます

これで第V部は終わりです。文体を見本で伝え（第23章）、規則で整え（第24章）、設定の違いを実験で確かめる（第25章）仕組みがそろいました。

第VI部では、「よい文章」の基準を、自分の好みに合わせていきます。この章では、第16章の批評の点数をそのまま使いましたが、LLMの採点には、ぶれや偏りがあります。第26章では、評価の観点と基準を**ルーブリック**としてはっきり書き、採点のぶれを減らす方法を扱います。
