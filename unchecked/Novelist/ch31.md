第30章で、長編を部・章・シーンの3段で書けるようになりました。アウトラインには「どの章で手がかりを置き、どの章で回収するか」を書かせています。ただし、それが本文で本当に置かれ、回収されたかは、まだ誰も確かめていません。

- **置き忘れ**：章のシーンカードを作るとき、LLMはアウトラインの章の内容を読みますが、その章で置くはずの手がかりが、シーンカードから抜け落ちることがあります

- **巻をまたげない**：1作を書き終えて続編を書こうとすると、設定資料も、人物の状態も、未回収の謎も、すべて一から作り直すことになります

この章では、伏線を一覧にして追いかける**伏線トラッカー**と、1巻目から2巻目へ設定を引き継ぐ**シリーズ**を作ります。

## 31.1 伏線トラッカーの考え方

### 3つの工程

伏線は、次の3つの工程で扱います。

```text
novelist plan
  アウトラインを作る ─▶ 伏線を登録する（threads.json）
                         F01: 第1章で置く → 第9章で回収
                         F02: 第3章で置く → 第14章で回収
                         …
novelist write
  第3章のシーンカードを作る ◀─ 第3章で置く伏線（F02）と、回収する伏線を渡す
  第3章を書く
  第3章を要約する ─▶ 第3章の本文で、伏線が置かれた・回収されたかを確かめる
                     F02 を置きました（3-2）: …
                     伏線の警告: F04 は第3章で置く予定でしたが、まだ置いていません
```

1. **登録**：アウトラインができたら、LLMに伏線を取り出させます。伏線ごとに、置くもの・回収の内容・置く章・回収する章を決めさせ、プログラムが `F01` から順に id を付けて `threads.json` に保存します
2. **計画**：章のシーンカードを作るときに、その章で置く伏線と回収する伏線を、プロンプトに入れます。どのシーンで置くかはLLMに決めさせ、シーンの出来事（beats）に書かせます。本文を書くプロンプトにはbeatsが入るので、本文を書くLLMにも伝わります
3. **確認**：章を書き終えたら、章の本文と伏線の一覧をLLMに渡し、伏線が置かれた箇所・回収された箇所を、本文からの引用つきで挙げさせます。プログラムは、引用が本文に本当にあるかを確かめてから、伏線の状態を更新します

### 伏線の状態

| 状態 | 意味 | 次に変わるとき |
|---|---|---|
| 予定（`planned`） | 登録しただけで、本文にはまだない | 本文で置かれた箇所が見つかった |
| 置いた（`planted`） | 本文に置いた。まだ回収していない | 本文で回収された箇所が見つかった |
| 回収した（`paid`） | 本文で回収した | ― |
| 取りやめ（`dropped`） | 使わないことにした（`threads.json` を手で直す） | ― |

確認のたびに、予定どおりでない伏線を**警告**として挙げます。

- 置く予定の章を書き終えたのに、まだ置いていない
- 回収する予定の章を書き終えたのに、まだ回収していない
- 置いた箇所が見つからないまま、回収した
- 最後の章まで書き終えたのに、回収する章が決まっていない（次の巻へ持ち越せる）

警告が出ても、執筆は止めません。伏線が予定の章からずれるのはよくあることで、次の章で置けば済む場合も多いからです。警告を見て、`plot.json` のシーンカードや `threads.json` を直すかどうかは、作者が決めます。

### 判断はLLM、確かめるのはプログラム

「この本文で、伏線が置かれたか」は、意味を読まないと判断できないので、LLMに任せます。ただしLLMは、置かれていない伏線を「置かれた」と答えることがあります。第16章の批評や第21章の一貫性チェックと同じく、本文からの**引用**を出させ、引用が本文にそのままあるかをプログラムで確かめます。引用が本文にない答えは採用しません。

## 31.2 伏線のモデル

**`src/novelist/schemas/threads.py`**（新規）

```python
"""伏線（第31章）。"""

from typing import Literal

from pydantic import BaseModel, Field, ValidationInfo, model_validator

ThreadStatus = Literal["planned", "planted", "paid", "dropped"]
STATUS_NAMES = {"planned": "予定", "planted": "置いた", "paid": "回収した", "dropped": "取りやめ"}


class Thread(BaseModel):
    """伏線1つ。threads.json に保存する。"""

    id: str  # "F01" など
    clue: str  # 置くもの（読者に見せる手がかり・謎・約束）
    payoff: str  # どう回収するか
    plant_chapter: int | None = None  # 置く予定の章（通し番号）。None なら前の巻で置いた
    payoff_chapter: int | None = None  # 回収する予定の章。None なら、この巻では回収しない
    status: ThreadStatus = "planned"
    planted_at: str | None = None  # 置いたシーン（"3-2" など）
    planted_quote: str | None = None  # 置いた箇所の、本文からの引用
    paid_at: str | None = None  # 回収したシーン
    paid_quote: str | None = None
    carried_from: str | None = None  # 前の巻から持ち越した伏線なら、その巻の作品ID

    @property
    def is_open(self) -> bool:
        """まだ回収していない（取りやめてもいない）か。"""
        return self.status in ("planned", "planted")


class ThreadList(BaseModel):
    """threads.json の中身。"""

    threads: list[Thread] = Field(default_factory=list)


# ---- LLMに書かせる形 ----


class PlannedThread(BaseModel):
    """アウトラインから取り出す、伏線の計画1つ。"""

    clue: str = Field(
        description="置くもの。読者に見せる手がかり・謎・人物の約束など。具体的に書く",
        max_length=80,
    )
    payoff: str = Field(description="どう回収するか。何が明らかになるか", max_length=80)
    plant_chapter: int = Field(description="置く章の番号（通し番号）", ge=1)
    payoff_chapter: int = Field(description="回収する章の番号（通し番号）", ge=1)


class CarriedAssignment(BaseModel):
    """前の巻から持ち越した伏線を、この巻のどの章で回収するか。"""

    id: str = Field(description="持ち越した伏線の id")
    payoff_chapter: int | None = Field(
        description="回収する章の番号。この巻でも回収しないなら null"
    )


class ThreadPlan(BaseModel):
    """アウトラインから取り出した、伏線の計画。"""

    threads: list[PlannedThread] = Field(
        description="物語の結末に関わる、大事な伏線だけ。最大12件", max_length=12
    )
    carried: list[CarriedAssignment] = Field(
        default_factory=list, description="前の巻から持ち越した伏線の、回収する章"
    )

    @model_validator(mode="after")
    def _check_chapters(self, info: ValidationInfo) -> "ThreadPlan":
        """章の番号がアウトラインにあり、置く章が回収する章より前かを確かめる。"""
        context = info.context or {}
        n = context.get("n_chapters")
        carried_ids = context.get("carried_ids")
        errors = []
        if n is not None:
            for t in self.threads:
                if not (1 <= t.plant_chapter <= n and 1 <= t.payoff_chapter <= n):
                    errors.append(f"「{t.clue}」の章の番号を、1〜{n}にしてください")
                elif t.plant_chapter >= t.payoff_chapter:
                    errors.append(f"「{t.clue}」は、置く章を回収する章より前にしてください")
            for c in self.carried:
                if c.payoff_chapter is not None and not 1 <= c.payoff_chapter <= n:
                    errors.append(f"持ち越した伏線 {c.id} の章の番号を、1〜{n}にしてください")
        if carried_ids is not None:
            unknown = sorted({c.id for c in self.carried} - set(carried_ids))
            if unknown:
                errors.append(f"持ち越した伏線にない id があります: {', '.join(unknown)}")
        if errors:
            raise ValueError("\n".join(errors))
        return self


class ThreadEvent(BaseModel):
    """章の本文の中で、伏線が置かれた・回収された箇所1つ。"""

    id: str = Field(description="伏線の id")
    event: Literal["planted", "paid"] = Field(description="planted: 置かれた、paid: 回収された")
    scene: str = Field(description="その箇所があるシーン（例: 3-2）")
    quote: str = Field(
        description="その箇所。本文から一字一句そのまま、30字程度を引用する", max_length=80
    )


class ThreadCheck(BaseModel):
    """章の本文で、伏線が置かれた・回収された箇所のリスト。"""

    events: list[ThreadEvent] = Field(description="見つかった箇所。なければ空にする", max_length=24)

    @model_validator(mode="after")
    def _check_ids(self, info: ValidationInfo) -> "ThreadCheck":
        context = info.context or {}
        ids, scenes = context.get("ids"), context.get("scenes")
        errors = []
        for e in self.events:
            if ids is not None and e.id not in ids:
                errors.append(f"伏線の一覧にない id です: {e.id}")
            if scenes is not None and e.scene not in scenes:
                errors.append(f"この章にないシーンです: {e.scene}（{', '.join(scenes)} のどれか）")
        if errors:
            raise ValueError("\n".join(errors))
        return self
```

- **`Thread`**：保存する伏線です。`plant_chapter`・`payoff_chapter` は予定の章、`planted_at`・`paid_at` は実際に置いた・回収したシーンです。予定と実際を分けて持つので、ずれがわかります。`carried_from` は、シリーズで前の巻から持ち越した伏線のときに、元の巻の作品IDを入れます（31.7節）。
- **`ThreadPlan`**：アウトラインから取り出す伏線の計画で、LLMに書かせる形です。id はLLMに付けさせず、プログラムで付けます。
  - 検証のコンテキストに `n_chapters` があれば、章の番号がアウトラインの範囲にあるか、置く章が回収する章より前かを確かめます。
  - `carried` は、前の巻から持ち越した伏線を、この巻のどの章で回収するかです。コンテキストの `carried_ids` にない id は、エラーにします。
- **`ThreadCheck`**：章の本文で、伏線が置かれた・回収された箇所のリストです。コンテキストの `ids`（確かめる伏線）と `scenes`（章のシーン）にない値は、エラーにして書き直させます。引用が本文にあるかは、ここでは確かめません。引用の照合は、本文がそろっている `threads.py` で行います。

## 31.3 伏線トラッカー

**`src/novelist/threads.py`**（新規）

```python
"""伏線トラッカー（第31章）。

- 登録: アウトラインから、伏線（置く章と回収する章）をLLMに取り出させる
- 計画: 章のシーンカードを作るときに、その章で置く・回収する伏線を渡す
- 確認: 章を書き終えたら、本文で伏線が置かれた・回収された箇所をLLMに探させ、
  引用が本文にあるかをプログラムで確かめてから、状態を更新する
"""

import re
from dataclasses import dataclass, field

from novelist.config import Config
from novelist.llm.client import LLMClient
from novelist.llm.structured import generate_structured, schema_text
from novelist.prompts import PromptLibrary
from novelist.schemas.bible import CharacterSheet, WorldSheet
from novelist.schemas.outline import Digest, Outline
from novelist.schemas.plot import Plot
from novelist.schemas.threads import Thread, ThreadCheck, ThreadPlan
from novelist.schemas.work import WorkMeta

PROFILE = "precise"  # 伏線の登録と確認は、正確さを優先する
PLAN_MAX_TOKENS = 4096


def _sampling(config: Config):
    sampling = config.sampling_for(PROFILE)
    return sampling.model_copy(update={"max_tokens": max(sampling.max_tokens, PLAN_MAX_TOKENS)})


def _compact(text: str) -> str:
    """空白と改行を取り除く（引用の照合用）。"""
    return re.sub(r"\s", "", text)


def next_id(threads: list[Thread]) -> int:
    """新しい伏線に付ける番号（F01 の 1）。今ある伏線の番号の最大 + 1。"""
    numbers = [int(t.id[1:]) for t in threads if re.fullmatch(r"F\d+", t.id)]
    return max(numbers, default=0) + 1


# ---- 登録 ----


def register_threads(
    client: LLMClient,
    prompts: PromptLibrary,
    config: Config,
    meta: WorkMeta,
    world: WorldSheet,
    characters: CharacterSheet,
    outline: Outline,
    carried: list[Thread] | None = None,
    volumes: list[Digest] | None = None,
) -> list[Thread]:
    """アウトラインから伏線を取り出し、id を付けて返す。

    carried は、前の巻から持ち越した伏線（第31章のシリーズ）。LLMには、回収する章だけを
    決めさせる。volumes は、前の巻までの要約。
    """
    carried = carried or []
    messages = prompts.render(
        "threads_plan",
        meta=meta,
        world=world,
        characters=characters,
        outline=outline,
        carried=carried,
        volumes=volumes or [],
        schema=schema_text(ThreadPlan),
    )
    context = {"n_chapters": len(outline.chapters()), "carried_ids": [t.id for t in carried]}
    plan = generate_structured(
        client, messages, ThreadPlan, _sampling(config), validation_context=context
    )
    assigned = {c.id: c.payoff_chapter for c in plan.carried}
    threads = [t.model_copy(update={"payoff_chapter": assigned.get(t.id)}) for t in carried]
    start = next_id(carried)
    for k, p in enumerate(sorted(plan.threads, key=lambda p: p.plant_chapter)):
        threads.append(
            Thread(
                id=f"F{start + k:02d}",
                clue=p.clue,
                payoff=p.payoff,
                plant_chapter=p.plant_chapter,
                payoff_chapter=p.payoff_chapter,
            )
        )
    return threads


# ---- 計画 ----


def chapter_threads(threads: list[Thread], number: int) -> tuple[list[Thread], list[Thread]]:
    """第 number 章で、置く伏線と、回収する伏線。"""
    to_plant = [t for t in threads if t.plant_chapter == number and t.status == "planned"]
    to_pay = [t for t in threads if t.payoff_chapter == number and t.is_open]
    return to_plant, to_pay


# ---- 確認 ----


@dataclass
class CheckResult:
    """章の本文を確認した結果。"""

    threads: list[Thread]  # 状態を更新した伏線
    log: list[str] = field(default_factory=list)  # 置いた・回収した伏線
    dropped: list[str] = field(default_factory=list)  # 引用が本文になく、採用しなかった箇所


def check_chapter_threads(
    client: LLMClient,
    prompts: PromptLibrary,
    config: Config,
    threads: list[Thread],
    plot: Plot,
    number: int,
    texts: dict[str, str],
) -> CheckResult:
    """書き終えた第 number 章の本文で、伏線が置かれた・回収された箇所を探す。

    texts は、章のシーンの本文（キーは "3-1" など）。LLMが挙げた箇所は、引用が本文に
    そのままあるときだけ採用する。
    """
    targets = [t for t in threads if t.is_open]
    if not targets:
        return CheckResult(threads)
    to_plant, to_pay = chapter_threads(threads, number)
    messages = prompts.render(
        "threads_check",
        number=number,
        chapter=plot.chapters[number - 1],
        texts=texts,
        threads=targets,
        expected={t.id for t in to_plant + to_pay},
        schema=schema_text(ThreadCheck),
    )
    context = {"ids": [t.id for t in targets], "scenes": list(texts)}
    check = generate_structured(
        client, messages, ThreadCheck, config.sampling_for(PROFILE), validation_context=context
    )
    by_id = {t.id: t for t in threads}
    result = CheckResult(threads)
    # 同じ章の中で置いて回収することもあるので、置いた箇所を先に反映する
    for e in sorted(check.events, key=lambda e: e.event != "planted"):
        t = by_id[e.id]
        if _compact(e.quote) not in _compact(texts[e.scene]):
            result.dropped.append(f"{e.id}（{e.scene}）「{e.quote}」")
            continue
        if e.event == "planted":
            if t.status != "planned":
                continue  # すでに置いてある。最初に置いた箇所を残す
            by_id[e.id] = t.model_copy(
                update={"status": "planted", "planted_at": e.scene, "planted_quote": e.quote}
            )
            result.log.append(f"{e.id} を置きました（{e.scene}）: {t.clue}")
        else:
            if not t.is_open:
                continue
            by_id[e.id] = t.model_copy(
                update={"status": "paid", "paid_at": e.scene, "paid_quote": e.quote}
            )
            result.log.append(f"{e.id} を回収しました（{e.scene}）: {t.payoff}")
    result.threads = [by_id[t.id] for t in threads]
    return result


def thread_warnings(threads: list[Thread], checked: int, total: int) -> list[str]:
    """第 checked 章まで確認した時点で、予定どおりでない伏線を挙げる。

    total は、この巻の章の数。最後の章まで確認したら、回収していない伏線も挙げる。
    """
    warnings = []
    for t in threads:
        if t.status == "planned" and t.plant_chapter is not None and t.plant_chapter <= checked:
            warnings.append(f"{t.id}: 第{t.plant_chapter}章で置く予定でしたが、まだ置いていません")
        elif t.is_open and t.payoff_chapter is not None and t.payoff_chapter <= checked:
            warnings.append(
                f"{t.id}: 第{t.payoff_chapter}章で回収する予定でしたが、まだ回収していません"
            )
        elif t.status == "paid" and t.planted_at is None and t.carried_from is None:
            warnings.append(f"{t.id}: 置いた箇所が見つからないまま、回収しています")
    if checked >= total:
        left = [t.id for t in threads if t.is_open and t.payoff_chapter is None]
        if left:
            warnings.append(f"この巻で回収しない伏線: {', '.join(left)}（次の巻へ持ち越せます）")
    return warnings
```

- **`register_threads`**：アウトラインから伏線を取り出します。
  - LLMが返した伏線は、置く章の順に並べ直してから、`F01`・`F02`…と番号を付けます。持ち越した伏線があれば、その番号の続きから付けます（`next_id`）。
  - 持ち越した伏線（`carried`）は、LLMが決めた回収する章だけを書き換えて、先頭に残します。
- **`chapter_threads`**：第 `number` 章で置く伏線（まだ置いていないもの）と、回収する伏線（まだ回収していないもの）を返します。
- **`check_chapter_threads`**：書き終えた章の本文で、伏線を確かめます。
  - 確かめるのは、まだ回収していない伏線だけです。1つもなければ、LLMを呼びません。
  - 引用は、空白と改行を取り除いてから照合します。第16章の `verify_issues` と同じです。
  - 同じ章の中で置いて回収することもあるので、置いた箇所を先に反映します。
  - すでに置いた伏線が、また「置かれた」と挙げられたら、最初に置いた箇所を残します。前の章で置いた手がかりに、あとの章で触れることはよくあるからです。
- **`thread_warnings`**：第 `checked` 章まで確かめた時点で、予定どおりでない伏線を挙げます。

### 伏線を登録するプロンプト

**`prompts/threads_plan/system.md`**（新規）

```jinja
{# アウトラインから伏線を取り出す（第31章） #}
あなたは長編小説の構成を担当する編集者です。
アウトラインを読み、物語の結末に関わる伏線を取り出して、置く章と回収する章を決めます。

# 伏線の選び方
- 伏線とは、前の章で読者に見せておき、あとの章で意味が明らかになるもの（手がかり、謎、人物の約束や秘密など）。
- 物語の結末や、大きな転換に関わるものだけを選ぶ。1つの章の中で始まって終わるものは選ばない。
- 置くもの（clue）は、本文に書ける具体的な物・言葉・出来事にする。「何かを隠している」のような、ぼんやりしたものにしない。
- 回収（payoff）には、何が明らかになるかを書く。
- 置く章は、回収する章より前にする。章の番号は、アウトラインの通し番号を使う。
- アウトラインの章の内容に合うようにする。アウトラインにない出来事は作らない。
{% if carried %}
- 前の巻から持ち越した伏線は threads に入れず、carried に、回収する章を書く。この巻でも回収しないなら null にする。
{% endif %}
```

## 31.7 シリーズ

### 引き継ぐもの

1作を書き終えたら、その続きを2巻目として書けるようにします。次の4つを、前の巻から引き継ぎます。

| 引き継ぐもの | 前の巻の | 次の巻での使いみち |
|---|---|---|
| 設定資料 | `bible/` | そのままコピーして使う。`novelist plan` は設定資料を作らずに読み込む |
| 人物の状態 | 最後に記録した `states/NN-NN.json` | 最初のシーンを書く前の状態にする（第22章） |
| 前の巻までの要約 | 巻の要約（新しく作る） | 企画・アウトライン・あらすじに入れる |
| 未回収の伏線 | `threads.json` の「置いた」伏線 | 持ち越して、この巻のどこで回収するかを決める |

本文は引き継ぎません。前の巻の出来事は、**巻の要約**で伝えます。第30章の要約のピラミッドに、もう1段を足すことになります。

```text
          巻の要約（800字）         ← 最後の部を要約したら、部の要約から作る
         ／      ｜     ＼
   部の要約  部の要約  部の要約 …
```

伏線のうち、「予定」のまま置かなかったものは、持ち越しません。前の巻で使わなかった案なので、次の巻で回収する相手が本文にないからです。

シリーズは、`series/<名前>.toml` に、題名と、巻の作品IDを順に書いて定義します。

```toml
title = "霧の駅"
volumes = [
    "kiri-1",
    "kiri-2",
]
```

### シリーズのモジュール

**`src/novelist/series.py`**（新規）

```python
"""シリーズ（第31章）。

series/<名前>.toml に、シリーズの題名と、巻の作品IDを順に書く。
次の巻を作るときは、前の巻から次のものを引き継ぐ。

- 設定資料（世界設定と登場人物）
- 前の巻の終わりの、登場人物の状態
- 前の巻までの要約（巻ごとに1つ）
- 置いたが回収していない伏線
"""

import tomllib
from dataclasses import dataclass
from pathlib import Path

import tomli_w
from pydantic import BaseModel, Field, ValidationError

from novelist.schemas.outline import Digest
from novelist.schemas.threads import Thread
from novelist.work import SLUG_RE, Work, WorkError


class SeriesError(Exception):
    """シリーズを扱えなかったときの例外。"""


class Series(BaseModel):
    """series/<名前>.toml の中身。"""

    title: str
    volumes: list[str] = Field(min_length=1)  # 巻の作品ID（1巻から順に）


def series_path(series_dir: Path, name: str) -> Path:
    return series_dir / f"{name}.toml"


def load_series(series_dir: Path, name: str) -> Series:
    path = series_path(series_dir, name)
    if not path.is_file():
        raise SeriesError(f"シリーズ '{name}' が見つかりません（{path}）")
    try:
        with path.open("rb") as f:
            return Series.model_validate(tomllib.load(f))
    except (tomllib.TOMLDecodeError, ValidationError) as e:
        raise SeriesError(f"シリーズを読み込めません（{path}）: {e}") from e


def save_series(series_dir: Path, name: str, series: Series) -> Path:
    if not SLUG_RE.match(name):
        raise SeriesError(
            f"シリーズの名前 '{name}' は使えません。半角の英小文字・数字・ハイフンにしてください"
        )
    series_dir.mkdir(parents=True, exist_ok=True)
    path = series_path(series_dir, name)
    path.write_text(tomli_w.dumps(series.model_dump()), encoding="utf-8")
    return path


# ---- 前の巻から引き継ぐもの ----


def previous_volumes(prev: Work) -> list[Digest]:
    """前の巻までの要約（前の巻が引き継いだ要約 + 前の巻の要約）。

    前の巻の要約がなければ（最後まで書いて要約していなければ）、SeriesError にする。
    """
    if not prev.has_outline():
        raise SeriesError(f"{prev.slug} は長編ではありません。シリーズにできるのは長編だけです")
    volumes = prev.load_inherited_summaries()
    digest = prev.load_digest("volume", len(volumes) + 1)
    if digest is None:
        raise SeriesError(
            f"{prev.slug} の巻の要約がありません。最後まで書いてから、"
            f"novelist summarize {prev.slug} で作ってください"
        )
    return [*volumes, digest]


def carried_threads(prev: Work) -> tuple[list[Thread], list[Thread]]:
    """前の巻から持ち越す伏線と、持ち越さない伏線。

    置いたが回収していない伏線を持ち越す。置いてもいない伏線は、前の巻で
    使わなかった案なので持ち越さない。
    """
    carried, dropped = [], []
    for t in prev.load_threads():
        if t.status == "planted":
            update = {
                "plant_chapter": None,
                "payoff_chapter": None,
                "carried_from": t.carried_from or prev.slug,
            }
            carried.append(t.model_copy(update=update))
        elif t.status == "planned":
            dropped.append(t)
    return carried, dropped


@dataclass
class Inherited:
    """次の巻に引き継いだもの。"""

    volumes: list[Digest]
    state: bool  # 前の巻の終わりの状態を引き継いだか
    threads: list[Thread]
    dropped: list[Thread]


def inherit(prev: Work, new: Work) -> Inherited:
    """前の巻（prev）から、次の巻（new）に、設定資料・状態・要約・伏線を引き継ぐ。"""
    volumes = previous_volumes(prev)
    try:
        world, characters = prev.load_bible()
        state = prev.last_story_state(prev.load_plot())
    except WorkError as e:
        raise SeriesError(str(e)) from e
    carried, dropped = carried_threads(prev)
    new.save_bible(world, characters)
    new.save_inherited(state, volumes)
    if carried:
        new.save_threads(carried)
    return Inherited(volumes, state is not None, carried, dropped)
```

- **`previous_volumes`**：前の巻までの要約を返します。前の巻が引き継いだ要約（1巻〜前の前の巻）に、前の巻の要約を足したものです。前の巻の要約がなければ、エラーにします。書き終えていない巻から、続きは書けないからです。
- **`carried_threads`**：前の巻から持ち越す伏線です。予定の章（`plant_chapter`・`payoff_chapter`）は、前の巻の章の番号なので消し、`carried_from` に元の巻の作品IDを入れます。3巻目へさらに持ち越すときも、最初に置いた巻の作品IDを残します。置いた箇所（`planted_at`・`planted_quote`）は、前の巻のシーンのものですが、どこで置いたかの記録として残します。
- **`inherit`**：設定資料・最後の状態・要約・伏線を、次の巻の作品のディレクトリに保存します。最後の状態は、31.4節で足した `Work.last_story_state` で、最後に記録したシーンの状態を探します。

## 31.10 うまくいかないときは

**置いたはずの伏線が「まだ置いていません」になる**

LLMが本文の中に伏線を見つけられなかったか、引用を言い換えたために採用されなかったかのどちらかです。`novelist write` のログに「引用が本文にないので、採用しません」とあれば、後者です。小さいモデルは、引用を少しだけ言い換えることがよくあります。`novelist threads 作品のID --check 章の番号` で確かめ直すか、`threads.json` の `status`・`planted_at`・`planted_quote` を手で書いてください。

**伏線の数が多すぎる・ぼんやりしている**

`ThreadPlan` は最大12件ですが、10万字の長編で本当に大事な伏線は、5〜8件程度です。多すぎると、章のシーンカードが伏線を詰め込むための場面ばかりになります。不要な伏線は、`threads.json` で `status` を `"dropped"` にしてください。取りやめた伏線は、シーンカードにも確認にも使いません。

**`--redo outline` で、伏線の記録が消えた**

アウトラインを作り直すと、伏線も登録し直します。置いた・回収した記録は残りません。書き進めたあとでアウトラインを直したいときは、`outline.json` を手で直してください。伏線の予定も、`threads.json` を手で直します。作り直す前の `threads.json` を残しておきたいときは、先にコピーしておきます。

**`new --series` で「巻の要約がありません」と表示される**

前の巻の最後の部の要約と、巻の要約がありません。`novelist outline 前の巻のID` で書き進み具合を確かめ、書き終えていれば `novelist summarize 前の巻のID` を実行してください。

**2巻目の人物の状態が、1巻目の途中のものになっている**

最後のシーンの状態が記録されていないと、記録のある、いちばん後のシーンの状態を引き継ぎます。1巻目を書くときに、第22章の状態の記録を止めていた（`novelist.toml` の `[story_state] enabled = false` や、`write --no-state`）場合です。`works/2巻目のID/inherited/state.json` を手で直してください。

## 31.11 まとめ

- **伏線トラッカー**を作りました。アウトラインから伏線を**登録**し、章のシーンカードを作るときに**計画**として渡し、章を書き終えたら本文で**確認**します
- 確認では、LLMに本文からの引用を出させ、引用が本文にあるかをプログラムで確かめてから、伏線の状態（予定・置いた・回収した）を更新しました。予定どおりでない伏線は、警告として表示します
- 長編を書き終えたら、部の要約から**巻の要約**を作るようにしました
- **シリーズ**を定義し、次の巻に、設定資料・前の巻の終わりの人物の状態・前の巻までの要約・未回収の伏線を**引き継ぐ**ようにしました。企画・アウトライン・あらすじには、前の巻までの要約が入ります
- `novelist threads` で伏線を確かめ、`novelist series` と `novelist new --series` でシリーズを扱えるようにしました

10万字の長編は、書き終えるまでにLLMを数百回呼び出し、まる1日以上かかることもあります。第32章では、長時間のバッチ実行を、ログと、seed・設定の記録で再現できるようにし、途中で失敗しても続きから再開できるようにします。
