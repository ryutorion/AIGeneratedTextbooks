## 29.1 LoRAとは

### 重みに、小さな差分を足す

LLMの追加学習（ファインチューニング）では、モデルの重みを、学習データに合わせて少しずつ変えます。しかし、数十億個ある重みをすべて変えるには、重みそのものに加えて、学習の途中の値（勾配や、最適化アルゴリズムの状態）を、重みの何倍ものメモリに置く必要があります。14Bのモデルなら、数百GBのメモリが要ります。

**LoRA**（Low-Rank Adaptation）は、元の重みは変えずに、重みの行列に**小さな差分**を足して、その差分だけを学習する方法です。

```text
元の重み W（4096×4096 など）は固定する
          ＋
差分 = B × A
  A: 4096×16   B: 16×4096   ← この2つの小さな行列だけを学習する
```

差分を2つの細長い行列の積にするのが工夫です。16のような小さな数（**ランク**）を選ぶと、学習する値の数は、元の重みの1%にも満たなくなります。学習が軽くなるだけでなく、学習した結果（**アダプタ**）のファイルも、数十〜数百MBと小さくなります。

アダプタは、元のモデルとは別のファイルです。`llama-server` では、元のモデルに、起動時にアダプタを重ねて使います（29.8節）。アダプタを外せば、元のモデルに戻ります。

### QLoRA

LoRAで学習するときも、元の重みはGPUのメモリに置く必要があります。そこで、元の重みを4ビットに量子化して読み込み、その上でLoRAの差分を学習します。これを**QLoRA**と呼びます。第3章で見たGGUFの量子化と同じように、重みのメモリを、16ビットのときの約4分の1にできます。

学習に使う量子化（`bitsandbytes` というライブラリの4ビット量子化）は、GGUFの量子化とは別のものです。学習には、GGUFではなく、Hugging Face形式（`safetensors`）の元のモデルを使います。

## 29.2 SFTとDPO

好みを学習させる方法は、2つあります。

| 方法 | 学習データ | 学習すること |
|---|---|---|
| **SFT**（教師ありファインチューニング） | プロンプトと、好まれた文章 | 好まれた文章を、そのまま書けるようになる |
| **DPO**（直接選好最適化） | プロンプトと、選ばれた文章・選ばれなかった文章の組 | 選ばれなかった文章より、選ばれた文章を書きやすくなる |

SFTは、「お手本をまねる」学習です。好まれた文章だけを使うので、データを集めやすい一方、「何が好まれなかったのか」は学べません。

DPOは、「2つを比べて、良いほうに寄せる」学習です。第27章の読み比べの記録が、そのまま学習データになります。選ばれた文章と選ばれなかった文章の**違い**を学ぶので、好みの差をとらえやすくなります。DPOでは、学習を始める前のモデル（**参照モデル**）から離れすぎないように、`beta` という値で、変わり方の強さを調整します。`beta` を大きくすると、元のモデルからあまり離れず、控えめに学習します。

本書では、DPOを基本にし、SFTも選べるようにします。

### どのくらいのデータが要るか

DPOでは、数十組のデータでも、文章の傾向が少し変わるのがわかることがあります。しかし、はっきりした効果を期待するなら、数百組は欲しいところです。第27章のペースで1日に10組読み比べると、1か月で300組ほどになります。

データが少ないうちに学習を回しすぎると、学習データの文章を丸暗記したり（**過学習**）、元のモデルが持っていた日本語の力が落ちたりします。29.6節で、過学習の見分け方を説明します。

## 29.3 全体の流れ

```text
preferences/ratings.jsonl（第27章）
      │  novelist prefs export
      ▼
datasets/prefs-dpo/train.jsonl・valid.jsonl
      │  train/train_lora.py（PyTorch・Transformers・PEFT・TRL）
      │  ＋ Hugging Face 形式の元のモデル（models/hf/my-model-14b/）
      ▼
lora/prefs-v1/（adapter_model.safetensors・adapter_config.json）
      │  llama.cpp の convert_lora_to_gguf.py
      ▼
lora/prefs-v1.gguf
      │  llama-server --model models/my-model-14b-Q4_K_M.gguf --lora lora/prefs-v1.gguf
      ▼
novelist write・bench（第25章）・bench rate（第27章）で使う・確かめる
```

いちばん大事な決まりは、**学習に使う元のモデルと、`llama-server` で使うGGUFのモデルが、同じモデルであること**です。第5章でダウンロードした `my-model-14b-Q4_K_M.gguf` が、あるモデルを量子化したものなら、学習にはその量子化する前のモデル（Hugging Faceで公開されている、同じ名前・同じバージョンのモデル）を使います。違うモデル（同じシリーズの別の大きさ、別のバージョン、別の人が追加学習したもの）のアダプタを重ねると、文章が壊れるか、`llama-server` がアダプタを読み込めません。

アダプタは16ビットのままGGUFにし、元のモデルは第4章で選んだ量子化（Q4_K_Mなど）のまま使えます。

## 29.4 VRAMの要件

学習に必要なVRAMは、次の合計です。

| 内訳 | 大きさ | 減らし方 |
|---|---|---|
| 元のモデルの重み | 4ビットなら、パラメータ数 × 約0.6バイト | 4ビットで読み込む（QLoRA） |
| LoRAの重みと、学習の途中の値 | 数百MB程度 | ランクを小さくする |
| 活性化（計算の途中の値） | 系列の長さに比例して増える | 勾配チェックポイント（計算し直す代わりに、覚えておく値を減らす） |
| 出力の確率（logits） | 系列の長さ × 語彙の数 × 4バイト | 系列を短くする |

最後の行が、意外と大きくなります。最近のモデルは語彙が15万語を超えるものが多く、8,192トークンの系列なら、8,192 × 150,000 × 4バイトで、約5GBになります。DPOでは、選ばれた文章と選ばれなかった文章の両方を計算するので、さらに増えます。

DPOでは参照モデルも使いますが、LoRAの場合は、アダプタを外した状態の同じモデルを参照モデルとして使うので、モデルをもう1つ読み込む必要はありません。

これらをまとめた、DPO・QLoRA・バッチサイズ1・勾配チェックポイントありのときの目安は、次のとおりです。

| モデル | 最大 2,048トークン | 最大 4,096トークン | 最大 8,192トークン |
|---|---|---|---|
| 3〜4B | 6GB | 8GB | 14GB |
| 7〜8B | 9GB | 12GB | 20GB |
| 12〜14B | 14GB | 18GB | 28GB |
| 27〜32B | 24GB | 32GB | 48GB以上 |

※ 目安です。モデルの構造（層の数・語彙の数）、ライブラリのバージョン、ドライバによって変わります。SFTは、この表の3分の2くらいです。

### 系列の長さを決める

本書のシーンの学習データは、長くなりがちです。シーンを書くプロンプト（シーンカード・登場人物・あらすじ・直前の文章など）が2,000〜4,000字、本文が目安の文字数（3,000字前後）なので、合わせて5,000〜7,000字になります。日本語は、トークナイザーによって1文字が0.7〜1.2トークンくらいになるので、4,000〜8,000トークンです。

`train_lora.py` の `--max-length`（既定は4,096）を超えたデータは、**後ろが切り捨てられます**（TRLの `truncation_mode="keep_start"`）。プロンプトは残り、本文の後半が学習に使われなくなります。好みの違いが本文の前半にも表れていれば、それでも学習できます。

VRAMが足りない場合は、次のどれかを選びます。

- `--max-length` を小さくする（本文の後半を学習しない）
- 小さいモデル（7〜8B）で学習する。そのモデルで書くことになります
- 第4章の見積もりで、クラウドのGPUを時間単位で借りる。学習だけをクラウドで行い、アダプタを手元に持ち帰れば、使うのは手元の `llama-server` です

## 29.5 学習データを書き出す

**`src/novelist/dataset.py`**（新規）

```python
"""記録した好みから、LoRAの学習データを作る（第29章）。

DPO（好みの組）と SFT（好まれた文章）の2つの形式で、JSONLに書き出す。
どちらも、TRL（Hugging Face のライブラリ）の「会話形式」のデータセットに合わせる。
"""

import json
import random
from collections.abc import Callable
from dataclasses import dataclass
from pathlib import Path
from typing import Any, Literal

from novelist.llm.client import Message
from novelist.preferences import Rating

Format = Literal["dpo", "sft"]
SFT_MIN_SCORE = 4  # SFT に使う、採点の記録の下限


class DatasetError(Exception):
    """学習データを作れないときの例外。"""


# (作品のID, シーン) から、そのシーンを書くプロンプトを作る関数
PromptBuilder = Callable[[str, str], list[Message]]


@dataclass
class DatasetStats:
    """書き出した学習データの件数と長さ。"""

    train: int
    valid: int
    skipped: int  # 作品やシーンがわからないなどで、使えなかった記録の数
    max_chars: int  # 1件の、プロンプトと文章を合わせた文字数の最大


def _assistant(text: str) -> list[Message]:
    return [{"role": "assistant", "content": text}]


def build_examples(
    ratings: list[Rating], fmt: Format, prompt_for: PromptBuilder
) -> tuple[list[dict[str, Any]], int]:
    """記録を、学習データの1件ずつにする。使えなかった記録の数も返す。

    - dpo: 読み比べで、どちらかを選んだ記録 → {"prompt", "chosen", "rejected"}
    - sft: 読み比べで選ばれた文章と、4以上の採点の文章 → {"prompt", "completion"}
    """
    examples: list[dict[str, Any]] = []
    seen: set[tuple[str, ...]] = set()  # 同じ組・同じ文章を、2回入れない
    skipped = 0
    cache: dict[tuple[str, str], list[Message]] = {}
    for r in ratings:
        if fmt == "dpo":
            chosen, rejected = r.chosen(), r.rejected()
            if chosen is None or rejected is None:
                continue  # 同じくらい、または採点の記録
            texts = [chosen.text, rejected.text]
        else:
            if r.kind == "pair":
                chosen = r.chosen()
                texts = [chosen.text] if chosen is not None else []
            else:
                texts = [r.a.text] if (r.score or 0) >= SFT_MIN_SCORE else []
            if not texts:
                continue
        if r.work is None or r.scene is None:
            skipped += 1
            continue
        key = (r.work, r.scene, *texts)
        if key in seen:
            continue
        seen.add(key)
        if (r.work, r.scene) not in cache:
            try:
                cache[(r.work, r.scene)] = prompt_for(r.work, r.scene)
            except Exception:  # 作品を消した、プロットを作り直した、など
                cache[(r.work, r.scene)] = []
        prompt = cache[(r.work, r.scene)]
        if not prompt:
            skipped += 1
            continue
        if fmt == "dpo":
            examples.append(
                {
                    "prompt": prompt,
                    "chosen": _assistant(texts[0]),
                    "rejected": _assistant(texts[1]),
                }
            )
        else:
            # プロンプトと文章を分けておくと、TRL は文章の部分だけを学習する
            examples.append({"prompt": prompt, "completion": _assistant(texts[0])})
    return examples, skipped


def _chars(example: dict[str, Any]) -> int:
    """1件の文字数（DPO は、プロンプトと長いほうの文章）。"""
    prompt = sum(len(m["content"]) for m in example["prompt"])
    answers = [
        example[k][0]["content"] for k in ("chosen", "rejected", "completion") if k in example
    ]
    return prompt + max(len(a) for a in answers)


def write_dataset(
    examples: list[dict[str, Any]], out_dir: Path, valid_ratio: float, seed: int, skipped: int = 0
) -> DatasetStats:
    """学習用（train.jsonl）と検証用（valid.jsonl）に分けて書き出す。"""
    if not examples:
        raise DatasetError("学習データにできる記録がありません")
    shuffled = list(examples)
    random.Random(seed).shuffle(shuffled)
    n_valid = round(len(shuffled) * valid_ratio) if len(shuffled) >= 10 else 0
    valid, train = shuffled[:n_valid], shuffled[n_valid:]
    out_dir.mkdir(parents=True, exist_ok=True)
    for name, rows in (("train.jsonl", train), ("valid.jsonl", valid)):
        with (out_dir / name).open("w", encoding="utf-8") as f:
            for row in rows:
                f.write(json.dumps(row, ensure_ascii=False) + "\n")
    return DatasetStats(len(train), len(valid), skipped, max(_chars(e) for e in examples))
```

- 学習データは、TRL（29.6節）の**会話形式**に合わせます。メッセージのリスト（`role` と `content`）で書いておくと、TRLが、モデルのチャットテンプレート（第3章）で1つの文字列にしてくれます。
  - DPO: `{"prompt": [...], "chosen": [...], "rejected": [...]}`
  - SFT: `{"prompt": [...], "completion": [...]}`。プロンプトと文章を分けておくと、TRLは**文章の部分だけ**を学習します。プロンプト（シーンカードなど）まで学習すると、シーンカードを書く練習をすることになってしまいます。
- `build_examples` は、DPOでは「同じくらい」の記録を除き、SFTでは選ばれた文章と、4以上の採点の文章を使います。同じ組（AとBの順番が逆のものも含む）は、1回だけ入れます。
- プロンプトは、記録には入っていないので、`prompt_for` で作り直します。記録の作品とシーンから、第25章の `scene_messages` で、`novelist write` と同じプロンプト（文体の見本と文章の規則を含む）を作ります。作品を消したなど、プロンプトを作れない記録は、使えなかった記録として数えます。
- `write_dataset` は、データを混ぜてから、学習用（`train.jsonl`）と検証用（`valid.jsonl`）に分けます。10件に満たないときは、検証用には分けません。

```diff
+    seed: Annotated[int, typer.Option("--seed", help="分け方を決める乱数のシード")] = 0,
+) -> None:
+    """記録した好みから、LoRAの学習データ（JSONL）を書き出します（第29章）。"""
+    config = _load_config(ctx)
+    ratings, _ = PreferenceStore(config.preferences_dir).load()
+    # 好みのルールは入れない。好みは、ルールではなくモデルの重みに覚えさせる
+    prompts = PromptLibrary(config.prompts_dir)
+    inputs_cache: dict[str, BenchInputs] = {}
+
+    def prompt_for(slug: str, scene: str) -> list[Message]:
+        """記録した作品とシーンから、いまの作品の状態で、シーンを書くプロンプトを作り直す。"""
+        if slug not in inputs_cache:
+            inputs_cache[slug] = BenchInputs.load(Work.open(config.works_dir, slug))
+        inputs = inputs_cache[slug]
+        variant = Variant(name="export")
+        style = style_name(variant, inputs.meta)
+        guide = load_style(config.styles_dir, style) if style else None
+        messages, _, _ = scene_messages(prompts, config, inputs, variant, guide, scene)
+        return messages
+
+    examples, skipped = build_examples(ratings, fmt.value, prompt_for)
+    try:
+        stats = write_dataset(examples, out_dir, valid_ratio, seed, skipped)
+    except DatasetError as e:
+        console.print(str(e), style="red", markup=False)
+        raise typer.Exit(1) from e
+    console.print(
+        f"書き出しました → {out_dir}（学習用 {stats.train}件、検証用 {stats.valid}件、"
+        f"使えなかった記録 {stats.skipped}件）"
+    )
+    console.print(
+        f"1件の長さ: 最大 {stats.max_chars:,}文字。"
+        "学習の max_length（トークン数）は、これを目安に決めてください"
+    )
```

- 学習データのプロンプトには、第28章の好みのルールを**入れません**。好みをルールで伝えたプロンプトで学習すると、モデルは「ルールが書かれていれば、それに従う」ことを覚えるだけで、好みそのものは覚えません。
- 記録したときと今とで、作品のあらすじや直前のシーンの本文が変わっていることがあります。その場合、プロンプトは記録したときとは少し違いますが、同じシーンの組どうしを比べる学習なので、大きな問題にはなりません。

## 29.6 学習する

### 学習用のプロジェクト

学習には、PyTorch・Transformers・PEFT・TRLなど、大きなライブラリが必要です。PyTorchのCUDA版だけで、数GBあります。これらを `novelist` の依存に加えると、学習しない人にとっても、インストールが重くなります。

そこで、学習用に、`train/` という別のuvのプロジェクトを作ります。`train/` に `pyproject.toml` を置くと、`train/` の中で実行した `uv run` は、`novelist` とは別の仮想環境（`train/.venv`）を使います。

**`train/pyproject.toml`**（新規）

### 学習のスクリプト

**`train/train_lora.py`**（新規）

```python
"""novelist の好みデータで、LoRAアダプタを学習する（第29章）。

使い方（train/ ディレクトリで実行する）:
  uv run train_lora.py --model ../models/hf/my-model-8b --data ../datasets/prefs-dpo \
      --out ../lora/prefs-v1
  uv run train_lora.py --method sft --model ../models/hf/my-model-8b \
      --data ../datasets/prefs-sft --out ../lora/prefs-sft-v1

--data には、novelist prefs export で書き出したディレクトリ（train.jsonl、valid.jsonl）を指定する。
"""

import argparse
from pathlib import Path

import torch
from datasets import load_dataset
from peft import LoraConfig
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig
from trl import DPOConfig, DPOTrainer, SFTConfig, SFTTrainer


def parse_args() -> argparse.Namespace:
    parser = argparse.ArgumentParser(description="好みデータで LoRA アダプタを学習する")
    parser.add_argument("--method", choices=["dpo", "sft"], default="dpo")
    parser.add_argument(
        "--model", required=True, help="ベースモデル（Hugging Face 形式のディレクトリか、モデルID）"
    )
    parser.add_argument("--data", type=Path, required=True, help="学習データのディレクトリ")
    parser.add_argument("--out", type=Path, required=True, help="アダプタを保存するディレクトリ")
    parser.add_argument("--epochs", type=float, default=2.0, help="データを何周するか")
    parser.add_argument(
        "--lr", type=float, default=None, help="学習率（省略すると方法ごとの既定値）"
    )
    parser.add_argument("--beta", type=float, default=0.1, help="DPO の beta（大きいほど控えめ）")
    parser.add_argument("--max-length", type=int, default=4096, help="1件の最大トークン数")
    parser.add_argument("--rank", type=int, default=16, help="LoRA のランク")
    parser.add_argument("--grad-accum", type=int, default=8, help="何件ごとに重みを更新するか")
    parser.add_argument("--no-4bit", action="store_true", help="4ビット量子化（QLoRA）を使わない")
    return parser.parse_args()


def main() -> None:
    args = parse_args()

    # 1. 学習データ（検証用は、空でなければ使う）
    files = {"train": str(args.data / "train.jsonl")}
    valid = args.data / "valid.jsonl"
    if valid.is_file() and valid.stat().st_size > 0:
        files["validation"] = str(valid)
    dataset = load_dataset("json", data_files=files)

    # 2. トークナイザーとベースモデル。既定では4ビットで読み込み、VRAMを節約する（QLoRA）
    tokenizer = AutoTokenizer.from_pretrained(args.model)
    if tokenizer.pad_token is None:
        tokenizer.pad_token = tokenizer.eos_token
    quantization = None
    if not args.no_4bit:
        quantization = BitsAndBytesConfig(
            load_in_4bit=True,
            bnb_4bit_quant_type="nf4",
            bnb_4bit_compute_dtype=torch.bfloat16,
            bnb_4bit_use_double_quant=True,
        )
    model = AutoModelForCausalLM.from_pretrained(
        args.model, quantization_config=quantization, dtype=torch.bfloat16, device_map="auto"
    )

    # 3. LoRA の設定。すべての線形層に、小さな行列を足して学習する
    peft_config = LoraConfig(
        r=args.rank,
        lora_alpha=args.rank * 2,
        lora_dropout=0.05,
        target_modules="all-linear",
        task_type="CAUSAL_LM",
    )

    # 4. 学習の設定（DPO と SFT で共通の部分）
    common = {
        "output_dir": str(args.out / "checkpoints"),
        "num_train_epochs": args.epochs,
        "max_length": args.max_length,
        "per_device_train_batch_size": 1,
        "gradient_accumulation_steps": args.grad_accum,
        "gradient_checkpointing": True,
        "bf16": True,
        "logging_steps": 1,
        "eval_strategy": "epoch" if "validation" in dataset else "no",
        "save_strategy": "epoch",
        "report_to": "none",
    }
    if args.method == "dpo":
        config = DPOConfig(learning_rate=args.lr or 1e-5, beta=args.beta, **common)
        trainer = DPOTrainer(
            model=model,
            args=config,
            train_dataset=dataset["train"],
            eval_dataset=dataset.get("validation"),
            processing_class=tokenizer,
            peft_config=peft_config,
        )
    else:
        config = SFTConfig(learning_rate=args.lr or 1e-4, **common)
        trainer = SFTTrainer(
            model=model,
            args=config,
            train_dataset=dataset["train"],
            eval_dataset=dataset.get("validation"),
            processing_class=tokenizer,
            peft_config=peft_config,
        )

    # 5. 学習して、アダプタ（adapter_config.json と adapter_model.safetensors）を保存する
    trainer.train()
    trainer.save_model(str(args.out))
    print(f"アダプタを保存しました → {args.out}")


if __name__ == "__main__":
    main()
```

1. **学習データ**：`datasets` の `load_dataset("json", ...)` で、`prefs export` で書き出したJSONLを読み込みます。
2. **モデル**：`BitsAndBytesConfig` で4ビット（NF4）に量子化して読み込みます。計算は `bfloat16` で行います。`device_map="auto"` は、モデルをGPUに置く指定です。
3. **LoRA**：`r` がランク、`lora_alpha` が差分の大きさの係数です（ランクの2倍にするのが一般的です）。`target_modules="all-linear"` で、すべての線形層に差分を足します。
4. **学習の設定**：1回に1件ずつ計算し（`per_device_train_batch_size=1`）、8件ごとに重みを更新します（`gradient_accumulation_steps=8`）。8件をまとめて計算するのと同じ効果を、少ないメモリで得られます。学習率は、DPOでは `1e-5`、SFTでは `1e-4` を既定にしています。DPOのほうが、少しの変化で効果が出るためです。
5. **保存**：`trainer.save_model` で、アダプタ（`adapter_config.json` と `adapter_model.safetensors`）を保存します。元のモデルの重みは保存されません。

## 29.7 GGUFに変換する

学習したアダプタは、Hugging Face形式（`safetensors`）です。`llama-server` で使うには、GGUFに変換します。変換には、第5章でビルドした llama.cpp の `convert_lora_to_gguf.py` を使います。

```console
$ uv run --no-project --with-requirements ~/src/llama.cpp/requirements/requirements-convert_lora_to_gguf.txt \
    python ~/src/llama.cpp/convert_lora_to_gguf.py lora/prefs-v1 \
    --base models/hf/my-model-14b --outfile lora/prefs-v1.gguf --outtype f16
```

```powershell
PS> uv run --no-project --with-requirements $HOME\src\llama.cpp\requirements\requirements-convert_lora_to_gguf.txt `
      python $HOME\src\llama.cpp\convert_lora_to_gguf.py lora\prefs-v1 `
      --base models\hf\my-model-14b --outfile lora\prefs-v1.gguf --outtype f16
```

- `--no-project` は、`novelist` プロジェクトの仮想環境を使わない、という意味です。`--with-requirements` で、変換に必要なライブラリ（llama.cpp が用意している一覧）だけを入れた、使い捨ての環境で実行します。
- `--base` には、元のモデルのディレクトリを指定します。変換には、元のモデルの設定ファイル（`config.json`）だけが使われ、重みは読みません。
- `--outtype f16` で、アダプタを16ビットで保存します。アダプタは小さいので、量子化しなくてもかまいません。

変換スクリプトは、llama.cpp の本体と組み合わせて使うものです。変換に失敗したり、変換したアダプタを `llama-server` が読み込めなかったりする場合は、第5章の手順で llama.cpp を新しくして（`git pull` してビルドし直して）から、変換し直してください。

## 29.8 llama-server で使う

`llama-server` に `--lora` を付けると、元のモデルにアダプタを重ねて起動します。第5章の起動スクリプトは、残りの引数を `llama-server` にそのまま渡すので、次のように起動できます。

```console
$ MODEL=models/my-model-14b-Q4_K_M.gguf scripts/start-server.sh --lora lora/prefs-v1.gguf
PS> powershell -ExecutionPolicy Bypass -File scripts\start-server.ps1 -Model models\my-model-14b-Q4_K_M.gguf --lora lora\prefs-v1.gguf
```

アダプタの効き方の強さは、`--lora-scaled` で変えられます。`lora/prefs-v1.gguf:0.5` のように、ファイル名のあとに倍率を書きます。1.0が学習したとおりの強さで、0.5なら半分です。効きすぎて文章が崩れる場合に、弱めて使います。

```console
$ MODEL=models/my-model-14b-Q4_K_M.gguf scripts/start-server.sh --lora-scaled lora/prefs-v1.gguf:0.5
```

読み込んでいるアダプタは、`/lora-adapters` で確かめられます。

```console
$ curl http://127.0.0.1:8080/lora-adapters
[{"id":0,"path":"lora/prefs-v1.gguf","scale":1.0}]
```

`--lora-init-without-apply` を付けて起動すると、アダプタを読み込むだけで、使わない状態（倍率0）で始まります。`/lora-adapters` にPOSTすると、サーバーを起動し直さずに、倍率を変えられます。

```console
$ curl -X POST http://127.0.0.1:8080/lora-adapters -d '[{"id": 0, "scale": 1.0}]'
```

Windows の PowerShell では、第5章で説明したとおり、`curl.exe` を使い、JSONはファイルに保存して `-d "@lora.json"` のように渡してください。

## 29.11 うまくいかないときは

**`CUDA out of memory` で止まる**

VRAMが足りません。29.4節の表を目安に、`--max-length` を小さくするか、`--rank 8` にするか、小さいモデルで学習してください。ほかにGPUを使っているプログラム（`llama-server` など）があれば、止めてから学習します。

**Windowsで、`bitsandbytes` や CUDA のエラーが出る**

`bitsandbytes` は Windows にも対応していますが、ドライバやCUDAの組み合わせで問題が起きることがあります。解決しない場合は、WSL2（Windows上のLinux）の中で、`train/` を実行してください。学習したアダプタは、Windows側の `llama-server` で使えます。

**変換で、`config.json` が見つからないと言われる**

`--base` に、元のモデルのディレクトリを指定し忘れているか、ディレクトリが違います。`models/hf/my-model-14b/config.json` があるかを確かめてください。

**`llama-server` が、アダプタを読み込めない**

アダプタを学習した元のモデルと、GGUFのモデルが違う可能性があります（29.3節）。モデルの大きさ（層の数や隠れ層の次元）が違うと、アダプタの行列の形が合わず、読み込めません。また、llama.cpp が古いと、新しい形式のアダプタを読み込めないことがあります。

**文章が崩れる、同じ言い回しばかりになる**

学習が強すぎます。`--lora-scaled` で倍率を下げて（0.5など）試してください。改善すれば、次の学習では、エポック数を減らすか、`beta` を大きくします。

**効果がわからない**

データが少ないか、学習が弱すぎます。読み比べの記録を増やすのがいちばんの近道です。`--epochs` を増やす、`beta` を小さくする（0.05など）方法もありますが、過学習しやすくなるので、検証用の値を見ながら調整してください。

## 29.12 まとめ

- **LoRA**は、元の重みを固定し、小さな差分の行列だけを学習する方法です。元のモデルを4ビットで読み込む**QLoRA**なら、手元のGPUでも学習できます
- 第27章の読み比べの記録を、**DPO**（選ばれた文章と選ばれなかった文章の組）と**SFT**（好まれた文章）の学習データとして書き出せるようにしました。プロンプトは、記録した作品とシーンから作り直し、好みのルールは入れません
- 学習は、PyTorchなどの大きな依存を分けるため、`train/` という別のuvのプロジェクトで行います。TRLの `DPOTrainer` と、PEFTの `LoraConfig` を使います
- 学習したアダプタは、llama.cpp の `convert_lora_to_gguf.py` でGGUFにし、`llama-server` の `--lora` で、元のモデルに重ねて使います。学習とGGUFの元のモデルは、同じモデルでなければなりません
- VRAMは、モデルの大きさと系列の長さで決まります。語彙の多いモデルでは、出力の確率のメモリが大きくなります
- 効果は、第25章の比較実験と第27章の読み比べで確かめます。好みに近づいたかに加えて、文章が壊れていないかも確かめます

これで第VI部は終わりです。LLMの採点を整え（第26章）、自分の好みを記録し（第27章）、ルールとして（第28章）、モデルの重みとして（第29章）生成に返す仕組みがそろいました。

第VII部では、ここまで作ってきた仕組みを、**連作長編**に広げます。第30章では、部・章・シーンの階層を持つ長編の構造と、章ごとの要約を積み上げて長い物語の流れを保つ方法を扱います。
