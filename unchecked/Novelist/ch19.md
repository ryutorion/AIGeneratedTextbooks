# 第19章 設定資料のインデックス

第18章では、設定資料を項目ごとの文書にして、`search` コマンドで内容の近い項目を探せるようにしました。しかし、この方法には2つの問題があります。

- **検索のたびに、すべての文書をベクトルにし直している**：設定資料の項目は数十件なので、今は困りません。しかし、書き終えた本文も探せるようにすると、文書は数百件に増えます。検索のたびに全部を埋め込み直すのは、むだが大きすぎます。
- **本文は長い**：シーンの本文は、1つで数千字になることがあります。埋め込みモデルには入力の長さの上限がありますし、上限に収まったとしても、1つのシーンの中のいろいろな出来事が、1つのベクトルにまとめられてしまいます。

この章では、文章を小さな**チャンク**に分け、そのベクトルを**インデックス**としてファイルに保存します。保存には、SQLiteでベクトル検索ができるようにする拡張機能、**sqlite-vec** を使います。インデックスは、設定資料や本文が変わった部分だけを更新します。

この章で作るものは次のとおりです。

| ファイル・コマンド | 内容 |
|---|---|
| `src/novelist/rag/chunking.py` | 文章をチャンクに分ける。設定資料と本文からチャンクを集める |
| `src/novelist/rag/index.py` | チャンクとベクトルを sqlite-vec に保存し、検索する |
| `src/novelist/llm/embedding.py` | 埋め込みモデルのファイル名も取り出す |
| `novelist index` | 作品のインデックスを作る・更新する |
| `novelist search` | インデックスを使って、設定資料と本文を探す |

## 19.1 チャンクに分ける

### なぜ分けるのか

長い文章を、そのまま1つのベクトルにしない理由は3つあります。

1. **入力の長さの上限**：埋め込みモデルには、1回に読める長さの上限があります（第18章の表。EmbeddingGemma なら2,048トークン）。
2. **1つのベクトルには、1つの話題**：ベクトルには、文章全体の意味がまとめられます。「待合室で朝を待つ」「金庫が開いていた」「硬券の束が消えた」という3つの出来事を含むシーンを1つのベクトルにすると、どの出来事で探しても、中くらいの類似度にしかなりません。
3. **プロンプトに入れる量**：検索した結果は、第20章で、本文を書くときのプロンプトに入れます。関係のある部分だけを入れたいので、検索の単位は小さいほうが使いやすくなります。

一方で、小さすぎるのも困ります。1文だけのチャンクでは、「彼はそれを金庫にしまった」の「彼」や「それ」が何を指すのかがわかりません。

| チャンクの大きさ | よいところ | 困るところ |
|---|---|---|
| 小さい（1〜2文） | 話題がはっきりしていて、ぴったり当たる | 前後の文脈がわからない。件数が増える |
| 大きい（シーン全体） | 文脈がそろっている | 話題が混ざって、見つけにくい。プロンプトに入れると長い |

本書では、本文のチャンクを**400字以内**にします。日本語の小説なら、段落が2〜5つくらいの長さです。多くの埋め込みモデルの入力の上限にも、十分に収まります。

### 境目の決め方

文章を400字ごとに機械的に切ると、文の途中で切れてしまいます。そこで、次の順に、切ってよい場所を探します。

1. **段落**の境目
2. 段落が400字を超える場合は、**文**の境目（第15章の `SENTENCE_END_RE` で、句点や閉じかっこを探す）
3. 1つの文が400字を超える場合は、400字ごとに切る

段落（または文）を、400字を超える手前まで、1つのチャンクに詰めていきます。

### となりのチャンクと重ねる

チャンクの境目にまたがる内容は、どちらのチャンクにも半分ずつしか入らないので、見つけにくくなります。そこで、次のチャンクの先頭に、前のチャンクの最後の段落を重ねて入れます。これを**オーバーラップ**と呼びます。

```text
本文:    [段落1][段落2][段落3][段落4][段落5][段落6]

チャンク1: [段落1][段落2][段落3]
チャンク2:               [段落3][段落4][段落5]      ← 段落3を重ねる
チャンク3:                             [段落5][段落6]
```

重ねる量は、**100字以内**にします。重ねすぎると、同じ内容のチャンクが増え、検索の結果に似たものが並んでしまいます。

### 設定資料は1項目で1チャンク

設定資料の項目は、第18章の文書のままで、1項目を1チャンクにします。項目はもともと短く、1つの話題（1人の人物、1つの場所）にまとまっているからです。

### チャンクに付ける情報

チャンクには、本文のほかに、どこから来たかを付けておきます。

| 項目 | 例 | 使い道 |
|---|---|---|
| `source`（種類） | `"bible"`（設定資料）、`"scene"`（本文） | 種類を絞って検索する |
| `ref`（出どころ） | `"人物:沢渡透"`、`"1-2"` | 変わった部分だけ更新する。検索の結果を元の場所とつなぐ |
| `seq`（順番） | `0`、`1`、`2` | 同じ出どころの中での順番 |
| `label`（表示名） | `人物「沢渡透」`、`本文 1-2「消えた束」#1` | 表示 |

## 19.2 sqlite-vec でベクトルを保存する

### ベクトルの保存先

ベクトルを保存して検索する仕組み（**ベクトルデータベース**）には、いろいろなものがあります。

| 種類 | 例 | 特徴 |
|---|---|---|
| 専用のサーバー | Qdrant、Milvus | 大量のベクトルを扱える。別にサーバーを動かす必要がある |
| ライブラリ | FAISS | 速い。保存の仕組みは自分で作る |
| SQLiteの拡張機能 | sqlite-vec | 1つのファイルに保存できる。SQLで扱える |

本書では **sqlite-vec** を使います。作品のディレクトリに1つのファイル（`index.sqlite`）として置けて、サーバーを動かす必要がありません。第17章のチェックポイントと同じく、Python標準の `sqlite3` から使えます。

小説のベクトルの数は、それほど多くなりません。1万字の短編なら、設定資料と本文を合わせて50件ほど、10万字の長編でも数百件です。sqlite-vec は、すべてのベクトルとの距離を計算して並べる**総当たり**の検索をします。第18章の総当たりと同じ方法ですが、C言語で書かれていて、ベクトルもあらかじめ保存してあるので、この規模なら一瞬で終わります。何百万件ものベクトルを扱う場合は、近似的に速く探す**近似最近傍探索**（ANN）を使うデータベースが必要になりますが、本書の用途では要りません。

### vec0 仮想テーブル

sqlite-vec は、SQLiteの**拡張機能**です。接続を開いたあとで読み込むと、`vec0` という**仮想テーブル**が使えるようになります。仮想テーブルは、見た目はふつうのテーブルですが、中身の保存や検索を拡張機能が行うテーブルです。

```python
import sqlite3
import sqlite_vec

db = sqlite3.connect("index.sqlite")
db.enable_load_extension(True)   # 拡張機能の読み込みを許可する
sqlite_vec.load(db)              # sqlite-vec を読み込む
db.enable_load_extension(False)  # 読み込んだら、許可を戻す
```

`vec0` のテーブルは、ベクトルの次元数を指定して作ります。

```sql
CREATE VIRTUAL TABLE vec_chunks USING vec0(
    embedding float[768] distance_metric=cosine,
    source text
);
```

- **`embedding float[768]`**：768次元のベクトルを入れる列です。**次元数は、テーブルを作るときに決まります**。別の次元数のベクトルを入れようとすると、エラーになります。
- **`distance_metric=cosine`**：距離の測り方を、コサイン距離（1 − コサイン類似度）にします。指定しないと、ユークリッド距離（L2）になります。
- **`source text`**：**メタデータ列**です。検索するときに、`source = 'scene'` のように条件を付けて絞り込めます。

ベクトルは、`sqlite_vec.serialize_float32()` で、32ビットの浮動小数点数を並べたバイト列にして入れます。検索は、`MATCH` と `k` で行います。

```sql
SELECT rowid, distance FROM vec_chunks
WHERE embedding MATCH ?     -- クエリのベクトル
  AND k = 5                 -- 近いものを5件
  AND source = 'scene'      -- 本文だけ
ORDER BY distance;
```

チャンクの本文や表示名は、ふつうのテーブル（`chunks`）に入れ、`vec0` のテーブルとは**同じ `rowid`（id）**でつなぎます。

### モデルが変わったら作り直す

第18章で述べたとおり、埋め込みモデルが違えば、同じ文章でもまったく違うベクトルになります。別のモデルで作ったベクトルを混ぜて検索しても、意味のある結果にはなりません。プレフィックスを変えた場合も同じです。

そこで、インデックスを作るときに、使ったモデルのファイル名、プレフィックス、次元数を記録しておきます。次に更新するときに、今のモデルと違っていれば、エラーにして、作り直すように案内します。

### 変わった部分だけ更新する

インデックスは、検索の前に毎回更新します。ただし、変わっていない部分まで埋め込み直すのはむだなので、**出どころ**（設定資料の1項目、または本文の1シーン）ごとに、チャンクの内容の**ハッシュ**を記録しておきます。

```text
出どころ        前回のハッシュ   今回のハッシュ   処理
人物:沢渡透     3fa2…            3fa2…            そのまま
場所:駅長室     81c0…            d4e7…            チャンクを削除して、埋め込み直す
1-3             （なし）         a09b…            新しく埋め込む
1-4             55e1…            （なし）         削除する（シーンを消した）
```

ハッシュは、文章から計算する短い値で、文章が1文字でも変われば、まったく違う値になります。ハッシュを比べれば、文章そのものを比べなくても、変わったかどうかがわかります。

## 19.3 チャンクを作る

**`src/novelist/rag/chunking.py`**（新規）

```python
"""検索の対象にする文章を、チャンク（小さなかたまり）に分ける（第19章）。"""

from dataclasses import dataclass

from novelist.rag.documents import bible_documents
from novelist.schemas.scene import scene_key
from novelist.work import Work
from novelist.writing import SENTENCE_END_RE

CHUNK_CHARS = 400  # 1つのチャンクの文字数の上限の目安
OVERLAP_CHARS = 100  # となりのチャンクと重ねる文字数の目安


@dataclass
class Chunk:
    """検索の対象にする、文章のかたまり。"""

    source: str  # 出どころの種類（"bible" 設定資料、"scene" 本文）
    ref: str  # 出どころの中の場所（設定資料の項目、シーンの番号）
    seq: int  # 同じ出どころの中での順番（0から）
    label: str  # 表示用の名前
    text: str  # 埋め込む文章


def _sentences(paragraph: str) -> list[str]:
    """段落を文に分ける。文の終わりがなければ、段落全体を1文とする。"""
    sentences = []
    start = 0
    for m in SENTENCE_END_RE.finditer(paragraph):
        sentences.append(paragraph[start : m.end()])
        start = m.end()
    if start < len(paragraph):
        sentences.append(paragraph[start:])
    return [s for s in sentences if s.strip()]


def _units(text: str, max_chars: int) -> list[tuple[str, bool]]:
    """文章を、チャンクに詰める単位に分ける。

    単位は、基本は段落。max_chars を超える段落は文に分け、それでも超える文は、
    max_chars ごとに切る。各単位は、(文字列, 段落の先頭かどうか) の組にする。
    """
    units = []
    for paragraph in (p.strip() for p in text.splitlines()):
        if not paragraph:
            continue
        if len(paragraph) <= max_chars:
            units.append((paragraph, True))
            continue
        pieces = [
            sentence[i : i + max_chars]
            for sentence in _sentences(paragraph)
            for i in range(0, len(sentence), max_chars)
        ]
        units += [(piece, n == 0) for n, piece in enumerate(pieces)]
    return units


def _join(units: list[tuple[str, bool]]) -> str:
    """単位をつなぐ。段落の先頭の単位の前だけ改行する。"""
    text = ""
    for piece, starts_paragraph in units:
        text += ("\n" if text and starts_paragraph else "") + piece
    return text


def _length(units: list[tuple[str, bool]]) -> int:
    return sum(len(piece) for piece, _ in units)


def split_text(
    text: str, max_chars: int = CHUNK_CHARS, overlap_chars: int = OVERLAP_CHARS
) -> list[str]:
    """文章を、max_chars 文字以内のチャンクに分ける。

    段落（長い段落は文）の単位で詰めていき、上限を超える手前で次のチャンクに移る。
    次のチャンクの先頭には、前のチャンクの最後の単位を、overlap_chars 文字以内で重ねる。
    重ねておくと、チャンクの境目にまたがる内容も、どちらかのチャンクで見つかりやすくなる。
    """
    chunks: list[list[tuple[str, bool]]] = []
    current: list[tuple[str, bool]] = []
    for unit in _units(text, max_chars):
        if current and _length(current) + len(unit[0]) > max_chars:
            chunks.append(current)
            # 前のチャンクの末尾から、overlap_chars 文字以内の単位を引き継ぐ
            overlap: list[tuple[str, bool]] = []
            for previous in reversed(current):
                if _length(overlap) + len(previous[0]) > overlap_chars:
                    break
                overlap.insert(0, previous)
            # 引き継いだ単位と新しい単位で上限を超えるなら、引き継がない
            if _length(overlap) + len(unit[0]) > max_chars:
                overlap = []
            current = overlap
        current.append(unit)
    if current:
        chunks.append(current)
    return [_join(chunk) for chunk in chunks]


def bible_chunks(work: Work) -> list[Chunk]:
    """設定資料を、項目ごとのチャンクにする（第18章の文書を、そのまま1チャンクにする）。"""
    if not work.has_bible():
        return []
    world, characters = work.load_bible()
    return [
        Chunk("bible", f"{doc.kind}:{doc.name}", 0, f"{doc.kind}「{doc.name}」", doc.text)
        for doc in bible_documents(world, characters)
    ]


def scene_chunks(work: Work) -> list[Chunk]:
    """書き終えたシーンの本文を、チャンクにする。"""
    if not work.has_plot():
        return []
    chunks = []
    for i, j, scene in work.load_plot().scenes():
        if not work.has_scene(i, j):
            continue
        key = scene_key(i, j)
        for seq, text in enumerate(split_text(work.load_scene_text(i, j))):
            chunks.append(Chunk("scene", key, seq, f"本文 {key}「{scene.title}」#{seq + 1}", text))
    return chunks


def work_chunks(work: Work) -> list[Chunk]:
    """作品の、検索の対象にするすべてのチャンク。"""
    return bible_chunks(work) + scene_chunks(work)
```

**`_units`**

文章を、チャンクに詰める**単位**に分けます。19.1節の順に、段落、文、400字ごとの切れ端、と細かくしていきます。各単位には、段落の先頭かどうかの印を付けておきます。

**`_join`**

単位をつないで、チャンクの文字列にします。段落の先頭の単位の前だけ改行し、同じ段落から分けた文は、改行せずにつなぎます。こうすると、チャンクの中の段落の区切りが、元の本文と同じになります。

**`split_text`**

単位を、`max_chars` を超える手前まで詰めていきます。次のチャンクに移るときは、前のチャンクの末尾から、`overlap_chars` 以内に収まる単位を引き継ぎます。引き継いだ単位と次の単位を合わせて `max_chars` を超える場合は、引き継ぎません。

文字数は、Pythonの `len()` で数えています。埋め込みモデルの上限はトークン数ですが、日本語の文章なら、1文字あたり1トークン前後です（第3章）。400字なら、2,048トークンの上限には十分に収まります。

**`bible_chunks`、`scene_chunks`、`work_chunks`**

作品のディレクトリから、チャンクを集めます。設定資料は第18章の `bible_documents` を1項目1チャンクに、本文は書き終えたシーンを `split_text` で分けます。`ref` には、設定資料なら「種類:名前」、本文ならシーンの番号を入れます。

```python
"""チャンクとベクトルを SQLite（sqlite-vec）に保存し、検索する（第19章）。"""

import hashlib
import sqlite3
from collections.abc import Callable
from dataclasses import dataclass
from pathlib import Path

import sqlite_vec

from novelist.llm.embedding import EmbeddingClient
from novelist.rag.chunking import Chunk, work_chunks
from novelist.work import Work

Vector = list[float]
EmbedFunc = Callable[[list[str]], list[Vector]]  # 文章のリストをベクトルのリストにする関数

SCHEMA = """
CREATE TABLE IF NOT EXISTS meta (
    key TEXT PRIMARY KEY,
    value TEXT NOT NULL
);
CREATE TABLE IF NOT EXISTS chunks (
    id INTEGER PRIMARY KEY,
    source TEXT NOT NULL,
    ref TEXT NOT NULL,
    seq INTEGER NOT NULL,
    label TEXT NOT NULL,
    text TEXT NOT NULL,
    UNIQUE (source, ref, seq)
);
CREATE TABLE IF NOT EXISTS groups (
    source TEXT NOT NULL,
    ref TEXT NOT NULL,
    hash TEXT NOT NULL,
    PRIMARY KEY (source, ref)
);
"""


class VectorIndexError(Exception):
    """インデックスを使えないときの例外。"""


@dataclass
class SearchResult:
    """検索の結果1件。"""

    chunk: Chunk
    similarity: float  # コサイン類似度


@dataclass
class UpdateStats:
    """インデックスの更新で、何件のチャンクを追加・削除したか。"""

    added: int = 0
    removed: int = 0
    unchanged: int = 0


def _group_hash(chunks: list[Chunk]) -> str:
    """同じ出どころのチャンクの、内容のハッシュ。内容が変わったかを調べるのに使う。"""
    digest = hashlib.sha256()
    for chunk in chunks:
        digest.update(chunk.label.encode())
        digest.update(b"\0")
        digest.update(chunk.text.encode())
        digest.update(b"\0")
    return digest.hexdigest()


class VectorIndex:
    """1つの作品のインデックス（works/<slug>/index.sqlite）。"""

    def __init__(self, path: Path) -> None:
        self.db = sqlite3.connect(path)
        try:
            # sqlite-vec は SQLite の拡張機能。読み込みを許可してから読み込む
            self.db.enable_load_extension(True)
            sqlite_vec.load(self.db)
            self.db.enable_load_extension(False)
        except AttributeError as e:
            raise VectorIndexError(
                "この Python の sqlite3 は、拡張機能の読み込みに対応していません。"
                "uv で入れた Python を使ってください（第2章）"
            ) from e
        self.db.executescript(SCHEMA)

    def close(self) -> None:
        self.db.close()

    def __enter__(self) -> "VectorIndex":
        return self

    def __exit__(self, *exc: object) -> None:
        self.close()

    # ---- どのモデルで作ったか ----

    def _meta(self, key: str) -> str | None:
        row = self.db.execute("SELECT value FROM meta WHERE key = ?", (key,)).fetchone()
        return row[0] if row else None

    def prepare(self, model: dict[str, str], dimensions: int) -> None:
        """インデックスを、埋め込みモデルに合わせて準備する。

        model は、モデルを見分けるための情報（ファイル名、プレフィックスなど）。
        初めてなら記録し、ベクトルの表を作る。すでに別のモデルで作られていれば、エラーにする。
        モデルが違えば、同じ文章でもベクトルがまったく違うので、混ぜて検索できないため。
        """
        model = {**model, "dimensions": str(dimensions)}
        saved = {key: self._meta(key) for key in model}
        if all(value is None for value in saved.values()):
            with self.db:
                self.db.executemany("INSERT INTO meta (key, value) VALUES (?, ?)", model.items())
                # 次元数は、表を作るときに決める。distance_metric=cosine で、コサイン距離を使う
                self.db.execute(
                    f"CREATE VIRTUAL TABLE IF NOT EXISTS vec_chunks USING vec0("
                    f"embedding float[{dimensions}] distance_metric=cosine, source text)"
                )
            return
        different = [key for key, value in model.items() if saved[key] != value]
        if different:
            details = "、".join(f"{key}: {saved[key]} → {model[key]}" for key in different)
            raise VectorIndexError(
                f"インデックスは、別の埋め込みモデルの設定で作られています（{details}）。"
                "--rebuild を付けて、作り直してください"
            )

    def clear(self) -> None:
        """インデックスを空にする（作り直すとき）。"""
        with self.db:
            self.db.execute("DROP TABLE IF EXISTS vec_chunks")
            self.db.execute("DELETE FROM chunks")
            self.db.execute("DELETE FROM groups")
            self.db.execute("DELETE FROM meta")

    # ---- 更新 ----

    def update(self, chunks: list[Chunk], embed: EmbedFunc) -> UpdateStats:
        """チャンクの一覧に合わせて、インデックスを更新する。

        出どころ（source と ref の組）ごとに内容のハッシュを比べ、変わった出どころの
        チャンクだけを埋め込み直す。一覧にない出どころのチャンクは削除する。
        """
        groups: dict[tuple[str, str], list[Chunk]] = {}
        for chunk in chunks:
            groups.setdefault((chunk.source, chunk.ref), []).append(chunk)
        saved = {
            (source, ref): value
            for source, ref, value in self.db.execute("SELECT source, ref, hash FROM groups")
        }

        stats = UpdateStats()
        changed = []
        for key, group in groups.items():
            if saved.get(key) == _group_hash(group):
                stats.unchanged += len(group)
            else:
                changed.append(key)
        removed = [key for key in saved if key not in groups]

        # 埋め込みは時間がかかるので、書き込みを始める前にまとめて済ませておく
        new_chunks = [chunk for key in changed for chunk in groups[key]]
        vectors = embed([chunk.text for chunk in new_chunks]) if new_chunks else []

        with self.db:  # ここから先は、すべて成功するか、何もしないかのどちらか
            for key in [*changed, *removed]:
                stats.removed += self._delete_group(*key)
            for chunk, vector in zip(new_chunks, vectors, strict=True):
                self._insert(chunk, vector)
            stats.added = len(new_chunks)
            for key in changed:
                self.db.execute(
                    "INSERT INTO groups (source, ref, hash) VALUES (?, ?, ?)",
                    (*key, _group_hash(groups[key])),
                )
        return stats

    def _delete_group(self, source: str, ref: str) -> int:
        """1つの出どころのチャンクとベクトルを削除し、削除したチャンクの数を返す。"""
        ids = [
            row[0]
            for row in self.db.execute(
                "SELECT id FROM chunks WHERE source = ? AND ref = ?", (source, ref)
            )
        ]
        self.db.executemany("DELETE FROM vec_chunks WHERE rowid = ?", [(i,) for i in ids])
        self.db.execute("DELETE FROM chunks WHERE source = ? AND ref = ?", (source, ref))
        self.db.execute("DELETE FROM groups WHERE source = ? AND ref = ?", (source, ref))
        return len(ids)

    def _insert(self, chunk: Chunk, vector: Vector) -> None:
        """チャンクと、そのベクトルを追加する。2つの表の行は、同じ id（rowid）でつなぐ。"""
        cursor = self.db.execute(
            "INSERT INTO chunks (source, ref, seq, label, text) VALUES (?, ?, ?, ?, ?)",
            (chunk.source, chunk.ref, chunk.seq, chunk.label, chunk.text),
        )
        self.db.execute(
            "INSERT INTO vec_chunks (rowid, embedding, source) VALUES (?, ?, ?)",
            (cursor.lastrowid, sqlite_vec.serialize_float32(vector), chunk.source),
        )

    # ---- 検索 ----

    def search(self, query: Vector, k: int = 5, source: str | None = None) -> list[SearchResult]:
        """query に近いチャンクを、近い順に k 件返す。source を指定すると、その種類だけを探す。"""
        if self._meta("dimensions") is None:
            raise VectorIndexError("インデックスがまだありません。novelist index で作ってください")
        sql = (
            "SELECT c.source, c.ref, c.seq, c.label, c.text, v.distance "
            "FROM vec_chunks AS v JOIN chunks AS c ON c.id = v.rowid "
            "WHERE v.embedding MATCH ? AND k = ?"
        )
        params: list = [sqlite_vec.serialize_float32(query), k]
        if source:
            sql += " AND v.source = ?"
            params.append(source)
        sql += " ORDER BY v.distance"
        return [
            SearchResult(Chunk(src, ref, seq, label, text), 1.0 - distance)
            for src, ref, seq, label, text, distance in self.db.execute(sql, params)
        ]

    def counts(self) -> dict[str, int]:
        """種類ごとのチャンクの数。"""
        return dict(self.db.execute("SELECT source, COUNT(*) FROM chunks GROUP BY source"))


def update_work_index(index: VectorIndex, work: Work, client: EmbeddingClient) -> UpdateStats:
    """作品の設定資料と本文に合わせて、インデックスを更新する。"""
    info = client.info()
    if info.n_embd is None:
        raise VectorIndexError("埋め込みモデルの次元数がわかりません")
    # モデルを見分けるための情報。プレフィックスが変わっても、ベクトルは変わる
    model = {
        "model_file": info.model_file or info.model,
        "query_prefix": client.config.query_prefix,
        "document_prefix": client.config.document_prefix,
    }
    index.prepare(model, info.n_embd)
    return index.update(work_chunks(work), client.embed_documents)
```

**テーブル**

| テーブル | 内容 |
|---|---|
| `meta` | インデックスを作ったモデルの情報（ファイル名、プレフィックス、次元数） |
| `chunks` | チャンクの出どころ、表示名、本文 |
| `groups` | 出どころごとの、チャンクの内容のハッシュ |
| `vec_chunks` | ベクトル（`vec0` の仮想テーブル）。`rowid` が `chunks` の `id` と対応する |

`SCHEMA` の `CREATE TABLE IF NOT EXISTS` は、テーブルがなければ作り、あれば何もしない、という書き方です。インデックスを開くたびに実行しても問題ありません。`vec_chunks` だけは次元数がわからないと作れないので、`prepare` で作ります。

**`__init__`**

sqlite-vec を読み込みます。Pythonの `sqlite3` によっては、拡張機能の読み込みができないように作られていることがあります。その場合は `enable_load_extension` がなく、`AttributeError` になるので、対処のしかたを添えたエラーにしています。uv でインストールしたPython（第2章）なら、読み込めます。

**`prepare`**

インデックスを、使う埋め込みモデルに合わせて準備します。

- 初めてなら、モデルの情報を `meta` に記録し、次元数を指定して `vec_chunks` を作ります。
- 記録があれば、今のモデルの情報と比べます。違う項目があれば、何がどう違うかを示して、エラーにします。

`with self.db:` は、SQLiteの**トランザクション**です。`with` の中の処理がすべて成功すれば確定（コミット）し、途中で例外が起きれば、すべて取り消します（ロールバック）。

**`update`**

19.2節の手順で、インデックスを更新します。

1. チャンクを、出どころ（`source` と `ref` の組）ごとにまとめます。
2. 出どころごとにハッシュを計算し、記録と比べて、変わったもの（`changed`）と、なくなったもの（`removed`）を調べます。
3. 変わった出どころのチャンクを、**まとめて**埋め込みます。
4. トランザクションの中で、古いチャンクを削除し、新しいチャンクとハッシュを追加します。

埋め込みを、書き込みのトランザクションの前に済ませているのには理由があります。埋め込みは、サーバーとのやりとりで時間がかかり、途中で失敗することもあります。書き込みを始めてから失敗すると、トランザクションは取り消されますが、その間データベースを長く書き込み中にしてしまいます。先に埋め込みを済ませておけば、書き込みは短時間で終わり、埋め込みで失敗した場合は、データベースは何も変わりません。

`embed` には、文章のリストをベクトルのリストにする**関数**を渡します。実際には `EmbeddingClient.embed_documents` を渡しますが、テストでは偽の関数を渡せます。`EmbedFunc` は、その関数の型に付けた名前です。`Callable[[list[str]], list[Vector]]` は、「`list[str]` を1つ受け取り、`list[Vector]` を返す関数」という意味です。

**`search`**

`vec_chunks` で近いものを探し、`chunks` と `JOIN` して、チャンクの本文と一緒に返します。sqlite-vec のコサイン距離は「1 − コサイン類似度」なので、`1.0 - distance` で類似度に戻しています。`source` を指定すると、メタデータ列の条件で絞り込みます。

**`update_work_index`**

作品のインデックスを更新する手順を、1つの関数にまとめたものです。埋め込み用のサーバーからモデルの情報を取り出して `prepare` し、`work_chunks` で集めたチャンクで `update` します。モデルの情報には、ファイル名のほかに、クエリと文書のプレフィックスも入れています。

```python
from pathlib import Path

import pytest
from conftest import EmbeddingRecorder

from novelist.rag.chunking import Chunk
from novelist.rag.index import VectorIndex, VectorIndexError

MODEL = {"model_file": "fake.gguf", "query_prefix": "", "document_prefix": ""}
DIM = EmbeddingRecorder.DIM


class CountingEmbedder:
    """偽のサーバーと同じベクトルを返し、埋め込んだ文章を記録する。"""

    def __init__(self) -> None:
        self.texts: list[str] = []

    def __call__(self, texts: list[str]) -> list[list[float]]:
        self.texts += texts
        return [EmbeddingRecorder.vector(text) for text in texts]


def chunk(source: str, ref: str, text: str, seq: int = 0) -> Chunk:
    return Chunk(source, ref, seq, f"{source}:{ref}", text)


CHUNKS = [
    chunk("bible", "場所:駅長室", "駅長室。金庫がある。"),
    chunk("bible", "場所:待合室", "待合室。ストーブが燃えている。"),
    chunk("scene", "1-1", "雪の夜、待合室で朝を待つ。"),
    chunk("scene", "1-2", "金庫の扉が開いていた。", 0),
    chunk("scene", "1-2", "硬券の束が消えていた。", 1),
]


def open_index(tmp_path: Path) -> VectorIndex:
    index = VectorIndex(tmp_path / "index.sqlite")
    index.prepare(MODEL, DIM)
    return index


def test_update_and_search(tmp_path: Path) -> None:
    embed = CountingEmbedder()
    with open_index(tmp_path) as index:
        stats = index.update(CHUNKS, embed)
        assert (stats.added, stats.removed, stats.unchanged) == (5, 0, 0)
        assert index.counts() == {"bible": 2, "scene": 3}

        results = index.search(EmbeddingRecorder.vector("金庫の扉"), k=2)
        assert [r.chunk.ref for r in results] == ["1-2", "場所:駅長室"]
        assert results[0].chunk.text == "金庫の扉が開いていた。"
        assert results[0].similarity > results[1].similarity

        # 種類を指定すると、その種類だけを探す
        results = index.search(EmbeddingRecorder.vector("金庫の扉"), k=2, source="bible")
        assert [r.chunk.source for r in results] == ["bible", "bible"]


def test_update_only_changed_groups(tmp_path: Path) -> None:
    with open_index(tmp_path) as index:
        index.update(CHUNKS, CountingEmbedder())

        # 1-2 の本文だけを書き換え、1-1 を削除した
        changed = [c for c in CHUNKS if c.ref not in ("1-1", "1-2")]
        changed.append(chunk("scene", "1-2", "金庫は空だった。"))
        embed = CountingEmbedder()
        stats = index.update(changed, embed)
        assert embed.texts == ["金庫は空だった。"]  # 変わった出どころだけを埋め込む
        assert (stats.added, stats.removed, stats.unchanged) == (1, 3, 2)
        assert index.counts() == {"bible": 2, "scene": 1}


def test_index_is_kept_on_disk(tmp_path: Path) -> None:
    with open_index(tmp_path) as index:
        index.update(CHUNKS, CountingEmbedder())
    with open_index(tmp_path) as index:
        embed = CountingEmbedder()
        index.update(CHUNKS, embed)
        assert embed.texts == []  # 2回目は、何も埋め込まない


def test_different_model_is_rejected(tmp_path: Path) -> None:
    with open_index(tmp_path) as index:
        index.update(CHUNKS, CountingEmbedder())
        with pytest.raises(VectorIndexError, match="model_file: fake.gguf → other.gguf"):
            index.prepare({**MODEL, "model_file": "other.gguf"}, DIM)
        # 作り直せば、別のモデル（次元数も違う）で使える
        index.clear()
        index.prepare({**MODEL, "model_file": "other.gguf"}, 8)
```

## 19.7 うまくいかないときは

**「拡張機能の読み込みに対応していません」と表示される**

使っているPythonの `sqlite3` が、拡張機能を読み込めないように作られています。macOSに最初から入っているPythonや、一部の方法でビルドしたPythonで起きます。`uv run` で実行しているか、`uv python install` で入れたPythonを使っているかを確かめてください（第2章）。

**インデックスの更新で「文章が長すぎます」と表示される**

チャンクのトークン数が、埋め込み用のサーバーの物理バッチを超えています。日本語をあまり学習していないモデルでは、1文字が複数のトークンになり、400字でも上限を超えることがあります。起動スクリプトの `CTX` を大きくするか、`chunking.py` の `CHUNK_CHARS` を小さくしてください。`CHUNK_CHARS` を変えると、本文のチャンクがすべて変わるので、次の更新で本文はすべて埋め込み直されます。

**「別の埋め込みモデルの設定で作られています」と表示される**

19.2節のとおり、埋め込みモデルやプレフィックスを変えると、インデックスを作り直す必要があります。`--rebuild` を付けて `index` を実行してください。

**検索の結果に、設定資料ばかり（または本文ばかり）が出る**

設定資料のチャンクは、内容が凝縮されていて、クエリの言葉を含みやすいので、上位に来やすい傾向があります。`--source` で種類を絞って探してください。第20章では、設定資料と本文を、別々の枠で検索して組み合わせます。

**`index.sqlite` を消してしまった**

インデックスは、設定資料と本文から、いつでも作り直せます。`index` を実行すれば、元どおりになります。

## 19.8 まとめ

- 長い本文は、400字以内の**チャンク**に分けて埋め込みます。段落、文の順に境目を探し、となりのチャンクと少し**重ねる**ことで、境目にまたがる内容も見つけやすくしました
- チャンクには、種類（設定資料・本文）と出どころ（項目・シーン）を付けて、絞り込みや、変わった部分だけの更新に使います
- **sqlite-vec** の `vec0` 仮想テーブルで、ベクトルを作品ごとの `index.sqlite` に保存しました。`MATCH` と `k` で近いチャンクを探し、メタデータ列で種類を絞り込めます
- 埋め込みモデルが変わるとベクトルも変わるので、インデックスには作ったモデルの情報を記録し、違うモデルでは**作り直す**ように案内しました
- 出どころごとの**ハッシュ**を比べて、変わった部分だけを埋め込み直すようにしました。`search` は検索の前に自動でインデックスを更新します

次の第20章では、この検索を本文の執筆に組み込みます。検索した設定資料と本文、これまでのあらすじ、直前の文章を、**トークンの予算**の中に収まるように選んで、プロンプトに詰める方法を考えます。
