# 第21章 一貫性チェッカー

第20章で、シーンを書くときに、関係する設定資料と過去の本文を検索して渡せるようになりました。これで、設定との食い違いは起きにくくなります。しかし、なくなるわけではありません。LLMは、プロンプトに書かれた設定を読み落とすこともあれば、物語を面白くしようとして、設定にない展開を書き足すこともあります。

この章では、書き上がったシーンを、設定資料・あらすじ・過去の本文と**突き合わせて**、食い違いを探す**一貫性チェッカー**を作ります。見つかった食い違いは、第16章の推敲の仕組みを使って直させます。

第16章の批評でも、「つながり」の観点で、設定との矛盾を見ていました。しかし、批評は文章の良し悪しを広く見るもので、設定資料を1つずつ照らし合わせるものではありません。人間の出版の工程でも、文章を良くする**編集者**と、事実や表記の誤りを探す**校閲者**は、別の役割です。この章では、LLMに校閲者の役を与えます。

## 21.1 何を、何と突き合わせるか

### 3種類の食い違い

小説の食い違いは、大きく3つに分けられます。

| 種類 | 例 |
|---|---|
| **人物** | 名前や呼び方が変わる（「沢渡さん」が「透さん」に）。口調が変わる。知らないはずのことを知っている |
| **時系列** | 夜だったのに朝になっている。雪がやんだはずなのに降っている。出来事の順番が入れ替わる |
| **設定** | 世界の決まりを破る（外へ出られないはずの駅から出る）。物の有無や持ち主が変わる |

「知らないはずのことを知っている」は、推理小説では特に困る食い違いです。探偵役が、まだ手に入れていない手がかりをもとに推理してしまうと、物語が成り立ちません。

### 突き合わせる資料

食い違いを見つけるには、原稿と、それが「正しい」と決まっている資料を比べます。

| 資料 | 見つけられる食い違い | 集め方 |
|---|---|---|
| 世界の決まり、用語 | 設定 | 必ず入れる |
| 場所 | 設定 | シーンカードの場所 |
| 人物の設定 | 人物 | シーンカードの人物と、**本文に名前が出てくる人物** |
| 直前のシーンの末尾 | 時系列 | 第15章の `previous_tail` |
| これまでのあらすじ | 時系列、人物（知っていること） | 第20章の予算に収まるだけ |
| 過去の本文 | 人物（呼び方、口調）、設定（物） | **書いた本文**で検索する |

人物の設定は、シーンカードの人物だけでなく、本文に名前が出てくる人物も入れます。シーンにいない人物が話題に上ったとき、その人物について誤ったことを書いていないかを確かめるためです。

過去の本文は、第20章ではシーンカードをクエリにして検索しましたが、ここでは**書いた本文**をクエリにします。何が書かれたかが、もうわかっているからです。本文をチャンクに分け、チャンクごとに検索して、結果をまとめます。

### 根拠を示させ、確かめる

第16章の批評では、LLMが原稿にない文を「引用」することがあったので、引用を確かめました。一貫性のチェックでは、さらに**根拠**も示させます。

```text
原稿の箇所: 沢渡は駅の外へ出て、雪の中を歩いた。
根拠の資料: [R1] 世界の決まり
根拠の箇所: 駅の外へは出られない
問題:       世界の決まりでは駅の外へ出られないのに、沢渡が外を歩いている
直し方:     駅舎の窓から外の雪を眺める場面に変える
```

資料には、R1、R2 のような番号を付けて渡し、根拠は「資料の番号」と「資料からの一字一句の引用」で示させます。そして、プログラムで次の3つを確かめます。

1. 原稿の箇所の引用が、原稿にあるか
2. 資料の番号が、渡した資料にあるか
3. 根拠の箇所の引用が、その資料にあるか

どれかを満たさない指摘は、取り除きます。LLMは、資料に書かれていない「設定」を思い込みで作り出して、それと矛盾すると指摘することがあります。根拠の引用を確かめれば、こうした指摘を機械的に取り除けます。

### 重大度と、直すかどうか

食い違いには、**重大度**を付けさせます。

| 重大度 | 意味 | 直すか |
|---|---|---|
| `high`（重大） | 物語の事実が食い違う | 直す |
| `medium`（中） | 注意深い読者が気づく | 直す |
| `low`（軽微） | 細かい違い | 直さない（表示だけ） |

直すときは、第16章の推敲のプロンプト（`scene_revise`）を使い、食い違いと根拠を「直してほしいこと」として渡します。直したあとで、もう一度チェックし、まだ食い違っていれば、決めた回数（既定は1回）まで直します。それでも直らなければ、そのまま先に進み、シーンの記録に「直しきれなかった食い違いの数」を残します。

```python
"""一貫性チェックの結果（第21章）。"""

from typing import Literal

from pydantic import BaseModel, Field

Category = Literal["人物", "時系列", "設定"]
Severity = Literal["high", "medium", "low"]

# 重大度の説明と、表示に使う名前
SEVERITY_NAMES = {"high": "重大", "medium": "中", "low": "軽微"}


class Contradiction(BaseModel):
    """原稿と資料の食い違い1件。"""

    category: Category = Field(
        description="人物（名前・呼び方・外見・口調・知っていること）、"
        "時系列（時刻・日付・出来事の順番）、設定（世界の決まり・場所・物）のどれか"
    )
    severity: Severity = Field(
        description="high: 物語の事実が食い違う。medium: 注意深い読者が気づく。low: 細かい違い"
    )
    quote: str = Field(
        description="原稿の、食い違っている箇所。原稿から一字一句そのまま引用する", max_length=80
    )
    reference: str = Field(description="根拠にした資料の番号（例: R3）", max_length=10)
    evidence: str = Field(
        description="資料の、根拠になる箇所。資料から一字一句そのまま引用する", max_length=80
    )
    problem: str = Field(description="何と何が、どう食い違っているか", max_length=120)
    fix: str = Field(description="原稿をどう直せば食い違いがなくなるか", max_length=120)


class ConsistencyReport(BaseModel):
    """一貫性チェックの結果。"""

    contradictions: list[Contradiction] = Field(
        description="見つかった食い違い。重大なものから順に最大6件。なければ空にする",
        max_length=6,
    )
```

- **`category`**：3つの種類を、日本語の `Literal` にしています。`description` に、それぞれ何を含むかを書いて、LLMが分類に迷わないようにしています。
- **`quote` と `evidence`**：原稿の箇所と、資料の箇所の引用です。どちらも「一字一句そのまま」と念を押しています。
- **`reference`**：資料の番号です。
- **`ConsistencyReport`**：食い違いのリストです。第16章の批評と同じく、「なければ空にする」と書いて、無理に探させないようにしています。

```python
"""一貫性チェックで、原稿と突き合わせる資料を集める（第21章）。"""

from dataclasses import dataclass

from novelist.rag.documents import bible_documents
from novelist.rag.index import SearchResult
from novelist.schemas.bible import CharacterSheet, WorldSheet
from novelist.writing import SceneBrief


@dataclass
class Reference:
    """原稿と突き合わせる資料の1件。"""

    id: str  # 資料の番号（R1、R2、…）。LLMは、この番号で根拠を示す
    label: str  # 表示名
    text: str


def name_forms(name: str) -> list[str]:
    """人物の名前が本文に出てくるときの形。

    日本語の小説では、フルネームのほかに、姓だけで呼ぶことが多い。姓と名の区切りは
    漢字だけではわからないので、ここでは先頭の2文字を姓とみなす（「沢渡透」→「沢渡」）。
    1文字や3文字の姓の人物では、うまく見つけられないことがある。
    """
    forms = [name]
    if len(name) >= 3:
        forms.append(name[:2])
    return forms


def mentioned_characters(text: str, characters: CharacterSheet) -> list[str]:
    """本文に名前が出てくる人物（設定資料の順）。"""
    return [
        c.name for c in characters.characters if any(form in text for form in name_forms(c.name))
    ]


def unexpected_characters(text: str, brief: SceneBrief, characters: CharacterSheet) -> list[str]:
    """本文に名前が出てくるのに、シーンカードの登場人物にいない人物。"""
    listed = set(brief.scene.characters)
    return [name for name in mentioned_characters(text, characters) if name not in listed]


def fixed_references(
    brief: SceneBrief, world: WorldSheet, characters: CharacterSheet, text: str
) -> list[Reference]:
    """必ず突き合わせる資料：世界の決まり、用語、場所、名前が出てくる人物、直前の文章。"""
    docs = {f"{d.kind}:{d.name}": d for d in bible_documents(world, characters)}
    names = set(brief.scene.characters) | set(mentioned_characters(text, characters))
    refs = [("世界の決まり", docs["世界:世界の概要"].text)]
    refs += [(f"用語「{t.name}」", docs[f"用語:{t.name}"].text) for t in world.terms]
    if f"場所:{brief.scene.place}" in docs:
        refs.append((f"場所「{brief.scene.place}」", docs[f"場所:{brief.scene.place}"].text))
    refs += [
        (f"人物「{c.name}」", docs[f"人物:{c.name}"].text)
        for c in characters.characters
        if c.name in names
    ]
    if brief.previous_tail:
        refs.append(("直前のシーンの末尾", brief.previous_tail))
    return [Reference(f"R{n}", label, text) for n, (label, text) in enumerate(refs, start=1)]


def numbered(refs: list[Reference], labels_and_texts: list[tuple[str, str]]) -> list[Reference]:
    """資料を、refs の続きの番号を付けて追加する。"""
    start = len(refs) + 1
    return refs + [
        Reference(f"R{n}", label, text)
        for n, (label, text) in enumerate(labels_and_texts, start=start)
    ]


def search_references(results: list[SearchResult]) -> list[tuple[str, str]]:
    """検索した過去の本文を、資料の (表示名, 本文) にする。"""
    return [(r.chunk.label, r.chunk.text) for r in results]
```

**`name_forms` と `mentioned_characters`**

本文に名前が出てくる人物を、文字列の一致で探します。日本語の小説では、「沢渡透」をフルネームで書くより、「沢渡」と姓だけで書くことのほうが多いので、姓の形でも探します。

ただし、漢字の名前だけでは、どこまでが姓かはわかりません。ここでは簡単に、**先頭の2文字を姓とみなしています**。日本人の姓は2文字のものが多いので、多くの場合はこれで見つかりますが、「林」「佐々木」のような1文字や3文字の姓の人物は、姓だけで書かれると見つけられません。正確にするには、設定資料の人物に「呼び方」の欄を加えて、「沢渡、沢渡さん、透」のように、本文で使う呼び方を列挙しておく方法があります。

**`unexpected_characters`**

本文に名前が出てくるのに、シーンカードの登場人物にいない人物です。第20章の「うまくいかないときは」で触れた、検索した人物をシーンに登場させてしまう問題を見つけるのに使います。ただし、名前が出てくるだけで、登場しているとは限りません（「黒川さんはどこへ行ったのかしら」のように、話題に上っているだけかもしれません）。そこで、これ自体を食い違いとはせず、プロンプトで「シーンカードにない人物の名前も出てくる」とLLMに伝えて、判断させます。

**`fixed_references`**

必ず突き合わせる資料を集めて、番号を付けます。資料の本文には、第18章の `bible_documents` の文書を使います。人物の設定には、人間関係も含まれています。

**`numbered`**

あらすじや検索した本文のように、あとから加える資料に、続きの番号を付けます。

```markdown
書き上がったシーンの原稿を、設定資料・これまでのあらすじ・過去の本文と突き合わせて、食い違いを探します。

# 探す食い違い
- 人物: 名前や呼び方、年齢、外見、口調、その人物が知っているはずのこと・知らないはずのこと

- 資料と食い違っている箇所だけを挙げる。資料に書かれていないことを、原稿が新しく書き足しているのは、食い違いではない。

- 原稿の箇所と、根拠にした資料の箇所は、どちらも一字一句そのまま引用する。資料は、番号（R1など）で示す。
- 同じ食い違いは、1件にまとめる。
- 食い違いがなければ、空のリストを返す。無理に探さない。
```

```python
"""シーンの原稿と資料を突き合わせて、食い違いを探す（第21章）。"""

import re
from collections.abc import Callable
from dataclasses import dataclass

from novelist.config import Config
from novelist.consistency.references import (
    Reference,
    fixed_references,
    numbered,
    unexpected_characters,
)
from novelist.context import ContextBudgetError, Item, Section, pack
from novelist.llm.client import LLMClient
from novelist.llm.structured import generate_structured, schema_text
from novelist.prompts import PromptLibrary
from novelist.rag.index import SearchResult
from novelist.schemas.bible import CharacterSheet, WorldSheet
from novelist.schemas.consistency import ConsistencyReport, Contradiction
from novelist.writing import SceneBrief

CHECK_PROFILE = "precise"  # 校閲は、ぶれの少なさを優先する
CHECK_MAX_TOKENS = 4096  # 結果のJSONのために確保するトークン数
SUMMARY_SHARE = 0.4  # 資料の予算のうち、あらすじにまず割り当てる割合
SCENE_SHARE = 0.6  # 資料の予算のうち、過去の本文にまず割り当てる割合


@dataclass
class CheckResult:
    """一貫性チェックの結果。"""

    contradictions: list[Contradiction]  # 引用を確かめられた食い違い
    dropped: list[Contradiction]  # 引用を確かめられず、除いた食い違い
    unexpected: list[str]  # シーンカードにないのに、名前が出てくる人物
    references: list[Reference]  # 突き合わせた資料

    def serious(self) -> list[Contradiction]:
        """直すべき食い違い（重大度が low 以外）。"""
        return [c for c in self.contradictions if c.severity != "low"]


def _compact(text: str) -> str:
    return re.sub(r"\s", "", text)


def verify_contradictions(
    contradictions: list[Contradiction], text: str, references: list[Reference]
) -> tuple[list[Contradiction], list[Contradiction]]:
    """食い違いを、引用を確かめられたものと、確かめられないものに分ける。

    原稿の引用が原稿にあり、資料の番号が存在し、資料の引用がその資料にあるものだけを残す。
    第16章の批評の引用の確認を、資料の側にも広げたもの。
    """
    by_id = {ref.id: _compact(ref.text) for ref in references}
    compact = _compact(text)
    kept, dropped = [], []
    for c in contradictions:
        source = by_id.get(c.reference.strip("[] "))
        ok = _compact(c.quote) in compact and source is not None and _compact(c.evidence) in source
        (kept if ok else dropped).append(c)
    return kept, dropped


def check_scene_text(
    client: LLMClient,
    prompts: PromptLibrary,
    config: Config,
    count: Callable[[str], int],
    world: WorldSheet,
    characters: CharacterSheet,
    brief: SceneBrief,
    text: str,
    retrieved: list[SearchResult],
) -> CheckResult:
    """シーンの原稿を、資料と突き合わせる。

    資料のうち、あらすじと検索した過去の本文は、第20章の予算の考え方で、
    コンテキスト長に収まるだけ入れる。
    """
    refs = fixed_references(brief, world, characters, text)
    unexpected = unexpected_characters(text, brief, characters)

    def render(references: list[Reference]):
        return prompts.render(
            "consistency",
            brief=brief,
            references=references,
            unexpected=unexpected,
            text=text,
            schema=schema_text(ConsistencyReport),
        )

    total = config.context.max_tokens or client.server_info().n_ctx
    if total is None:
        raise ContextBudgetError("コンテキスト長がわかりません")
    fixed = sum(count(m["content"]) for m in render(refs))
    available = total - fixed - CHECK_MAX_TOKENS - config.context.margin
    if available < 0:
        raise ContextBudgetError(
            f"一貫性チェックに、コンテキスト長（{total:,}トークン）が足りません"
        )

    # あらすじは1行ずつ、過去の本文はチャンクごとに、1件の資料にする
    summaries = [line.split(": ", 1) for line in brief.story_so_far]
    sections = [
        Section(
            "scenes",
            [Item(f"{r.chunk.label}\n{r.chunk.text}", n) for n, r in enumerate(retrieved)],
            SCENE_SHARE,
        ),
        Section(
            "summaries",
            [Item(line, n) for n, line in enumerate(brief.story_so_far)][::-1],
            SUMMARY_SHARE,
        ),
    ]
    chosen, _ = pack(sections, available, count)
    extra = [
        (f"あらすじ {summaries[item.order][0]}", summaries[item.order][-1])
        for item in chosen["summaries"]
    ]
    extra += [
        (retrieved[item.order].chunk.label, retrieved[item.order].chunk.text)
        for item in chosen["scenes"]
    ]
    references = numbered(refs, extra)

    sampling = config.sampling_for(CHECK_PROFILE)
    sampling = sampling.model_copy(
        update={"max_tokens": max(sampling.max_tokens, CHECK_MAX_TOKENS)}
    )
    report = generate_structured(client, render(references), ConsistencyReport, sampling)
    kept, dropped = verify_contradictions(report.contradictions, text, references)
    return CheckResult(kept, dropped, unexpected, references)
```

**`verify_contradictions`**

21.1節の3つの確認を行います。資料の番号は、LLMが `[R1]` のように括弧を付けて返すこともあるので、`strip("[] ")` で括弧と空白を取り除いてから探します。引用は、第16章と同じく、空白と改行を取り除いて照合します。

**`check_scene_text`**

1. 必ず突き合わせる資料（`fixed_references`）と、シーンカードにない人物（`unexpected_characters`）を集めます。
2. 必ず入れる資料だけでプロンプトを展開し、そのトークン数を数えます。コンテキスト長から、これと、結果のJSONのための分（`CHECK_MAX_TOKENS`）、余白を引いた残りが、あらすじと過去の本文に使える予算です。
3. 第20章の `pack` で、過去の本文とあらすじを予算に詰めます。一貫性のチェックでは、過去の本文のほうが根拠として使いやすいので、過去の本文を先の区画にして、多めに割り当てています。あらすじは、第20章と同じく、新しいものから入れます。
4. 選んだあらすじと過去の本文に、続きの番号を付けて、資料に加えます。あらすじは1行を1件の資料にし、「1-2「消えた束」: 要約」の、コロンの前を表示名にします。
5. LLMに突き合わせさせ、`verify_contradictions` で根拠を確かめます。

第20章の予算の仕組みを、そのまま使い回せていることに注目してください。区画と割り当てを変えるだけで、別の用途のプロンプトにも使えます。

**`CheckResult`**

チェックの結果です。`serious` は、直すべき食い違い（重大度が `low` 以外）だけを返します。

```python
def check_consistency(state: WriteState, runtime: Runtime[WriteContext]) -> dict:
    """書いたシーンを、設定資料・あらすじ・過去の本文と突き合わせる。"""
    ctx = runtime.context

    retrieved = []

def route_after_consistency(
    state: WriteState, runtime: Runtime[WriteContext]
) -> Literal["fix_scene", "summarize_scene"]:
    """直すべき食い違いがあり、まだ直せるなら直す。そうでなければ要約へ進む。"""
    if state["contradictions"] and state["fixes"] < runtime.context.config.consistency.max_fixes:
        return "fix_scene"

def fix_scene(state: WriteState, runtime: Runtime[WriteContext]) -> dict:
    """食い違いを直すように、シーンを推敲する。"""
    ctx = runtime.context
    brief = scene_brief(state, runtime)
    messages = ctx.prompts.render(
        "scene_revise",
        meta=state["meta"],
        world=state["world"],
        brief=brief,
        text=state["text"],
        issues=[fix_request(c) for c in state["contradictions"]],
    )

    fixes = state["fixes"] + 1

        "text": draft.text,
        "chars": draft.chars,
        "fixes": fixes,
        "log": [f"修正{fixes}回目: {draft.describe()}"],
    }
```

```python
    """執筆のグラフを組み立てる（第15章・第16章・第20章・第21章）。

    builder.add_node("start_scene", start_scene)

    builder.add_node("check_scene", check_scene)

    builder.add_node("revise_scene", revise_scene)  # 第16章
    builder.add_node("finalize_scene", finalize_scene)  # 第16章
    builder.add_node("check_consistency", check_consistency)  # 第21章
    builder.add_node("fix_scene", fix_scene)  # 第21章
    builder.add_node("summarize_scene", summarize_scene)
    builder.add_node("save_scene", save_scene)
    builder.add_node("export", export)

    builder.add_edge(START, "prepare")
    builder.add_conditional_edges("prepare", route_next, ["start_scene", "export"])
    builder.add_edge("start_scene", "gather_context")
    builder.add_edge("gather_context", "write_scene")
    builder.add_edge("write_scene", "check_scene")
    builder.add_conditional_edges(
        "check_scene",

    # 推敲のループ（第16章）

    )

    builder.add_edge("summarize_scene", "save_scene")
```

## 21.8 うまくいかないときは

**食い違いでないものまで指摘される**

資料に書かれていない細部を「食い違い」として指摘してくる場合は、システムプロンプトの「資料に書かれていないことを、原稿が新しく書き足しているのは、食い違いではない」を、例を添えて強めてください。たとえば、「資料に書かれていない小道具や動作（コーヒーを飲む、窓を開けるなど）を書くのは自由」のように書きます。

**本当の食い違いを見逃す**

資料が予算に収まりきらず、根拠になる資料が入っていない可能性があります。`[context]` の `scene_k` を大きくするか、コンテキスト長を大きくしてください。また、小さなモデルは、資料と原稿を細かく突き合わせるのが苦手です。チェックだけ、より大きなモデルで行うのも1つの方法です（第16章の「うまくいかないときは」を参照）。

**根拠を確かめられない指摘が多い**

LLMが、資料や原稿を正確に引用できていません。第16章と同じく、`Contradiction` の `quote` と `evidence` の `max_length` を小さくして、短く引用させてください。

**人物の名前が見つからない**

21.3節のとおり、先頭の2文字を姓とみなしているので、1文字や3文字の姓の人物は、姓だけで書かれると見つかりません。`name_forms` を、設定資料に呼び方の欄を加えて、それを使うように変えてください。

**修正で、別の食い違いが生まれる**

直したあとのチェックで、新しい食い違いが見つかることがあります。`max_fixes` を2以上にすると、もう一度直させることができます。ただし、直すたびに文章が崩れる可能性もあるので、多くても2回程度にとどめ、残った食い違いは `check` で確かめて、人間が直すのがよいでしょう。

## 21.9 まとめ

- 書き上がったシーンを、設定資料・あらすじ・過去の本文と突き合わせて、**人物・時系列・設定**の食い違いを探す一貫性チェッカーを作りました。文章の良し悪しを見る批評（第16章）とは、役割を分けています
- 突き合わせる資料には番号を付け、食い違いの**根拠**を「資料の番号」と「資料からの引用」で示させました。原稿の引用・資料の番号・資料の引用の3つをプログラムで確かめ、根拠のない指摘を取り除きます
- 本文に名前が出てくる人物の設定も資料に加え、シーンカードにない人物の名前があれば、LLMに伝えて判断させました
- 過去の本文は、**書いた本文**で検索しました。資料は、第20章の**予算**の仕組みで、コンテキスト長に収まるだけ入れます
- 重大な食い違いは、第16章の推敲のプロンプトで**直させ**、もう一度チェックします。直しきれなかった食い違いは記録に残し、`plot` で印を付けます。`novelist check` で、書き終えたシーンをあとからまとめてチェックできます

次の第22章では、登場人物の居場所・持ち物・知っていること・関係を、シーンを書くたびに更新していく**ストーリーステート**を作ります。「今、誰が何を知っているか」を記録しておけば、一貫性のチェックでも、執筆のときにも、根拠として使えます。
