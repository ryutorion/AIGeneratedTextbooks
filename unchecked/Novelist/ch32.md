# 第32章 長時間バッチ実行と運用 — ログ、seed と設定の記録による再現性、失敗からの再開

第30章で触れたとおり、10万字の長編を書き上げるには、LLMを数百回から千回以上呼び出します。手元のGPUでは、まる1日以上かかることもあります。これだけ長く動かすと、短編では気にならなかった問題が出てきます。

- **途中で止まる**：llama-server が落ちる、メモリが足りなくなる、PCがスリープする、ネットワークが一瞬切れる。1日に1回起きる失敗でも、1日かかる実行では、ほぼ確実に起きます
- **何が起きたかわからない**：朝起きて画面を見ると、エラーで止まっています。いつ、どのシーンで、何回目の呼び出しで止まったのか、画面に残った最後の数行からはわかりません
- **同じ結果を出せない**：途中の章の出来がよかったので、設定を少し変えて続きを書き直したい。ところが、そのときの設定・モデル・seed がわからないので、比べようがありません

この章では、長い実行を、止まっても自動で再開し、あとから何が起きたかを調べられ、同じ条件で再現できるようにします。

| ファイル・コマンド | 内容 |
|---|---|
| `src/novelist/llm/client.py` | 一時的な失敗のやり直し、seed の決め方、呼び出しの記録 |
| `src/novelist/runlog.py` | 実行の記録（設定・seed・モデル・LLMの呼び出し・失敗と再開） |
| `novelist write --seed` | seed のもとを指定して書く |
| `novelist batch` | 設計から最後のシーンまで、失敗しても再開しながら書く |
| `novelist runs` | 実行の記録を一覧し、前の実行との違いを表示する |

## 32.1 長い実行を支える3つの仕組み

### 失敗の種類

長い実行で起きる失敗は、次のように分けられます。

| 失敗 | 例 | 待てば直るか | この章での対処 |
|---|---|---|---|
| 一時的な通信の失敗 | 接続できない、時間切れ、503（モデルの読み込み中） | 数秒〜数分待てば直ることが多い | クライアントが、待ってからやり直す |
| サーバーの停止 | llama-server が落ちた、再起動中 | サーバーを起動し直せば直る | `batch` が、待ってから続きを再開する |
| LLMの出力の失敗 | 何回書き直させても、正しいJSONにならない | 同じ条件では、また失敗する | `batch` が、seed をずらしてから再開する |
| 設定やファイルの誤り | プロンプトのテンプレートがない、作品のファイルが壊れた | 直さない限り直らない | すぐに止めて、記録に残す |
| プロセスの停止 | Ctrl+C、PCの再起動 | ― | 第17章のチェックポイントから、続きを再開する |

第17章で、執筆のグラフのチェックポイントを SQLite に保存するようにしました。ノードが終わるたびに状態を書き込んでいるので、プロセスが止まっても、`novelist write` をもう一度実行すれば、止まったノードから再開できます。この章では、その上に3つの仕組みを足します。

1. **やり直しと再開**：一時的な失敗は、クライアントの中で待ってからやり直します。それでも失敗したら、`batch` が少し待ってから、チェックポイントから再開します
2. **記録**：実行ごとに、設定・seed・モデル・LLMの呼び出し・失敗と再開を、作品のディレクトリの `runs/` に残します
3. **再現性**：LLMに渡す seed を、実行ごとの「seed のもと」とプロンプトから決めます。seed のもとを記録しておけば、同じ条件で同じ結果を出せます

## 32.2 一時的な失敗をやり直す

### やり直してよい失敗

失敗のたびに何でもやり直すと、直らない失敗でも時間を無駄にします。やり直すのは、待てば直る見込みがある失敗だけにします。

| 失敗 | やり直す | 理由 |
|---|---|---|
| 接続できない・時間切れ（`httpx` の通信エラー） | する | サーバーの再起動中や、ネットワークの一時的な切断 |
| 502・503・504 | する | llama-server は、モデルの読み込み中に503を返す |
| 400 | しない | コンテキスト長を超えたなど、リクエストの誤り |
| 500 | しない | サーバーの中の誤りで、同じリクエストではまた起きやすい |
| 本文を受け取り始めたあとの切断 | しない | 途中までの本文を、もう画面に表示してしまっている |

最後の場合は、クライアントではやり直さず、そのまま失敗にします。`batch` がチェックポイントから再開すると、そのシーンを書くノードから実行し直すので、本文は最初から書き直されます。

やり直すまでの待ち時間は、1回ごとに2倍にします（10秒、20秒、40秒…、最大5分）。これを**指数バックオフ**と呼びます。サーバーが再起動に1分かかる場合でも、短い間隔で何十回も問い合わせずに済みます。

## 32.3 seed を決める

### サンプリングと seed

第9章で見たとおり、LLMは次のトークンを確率に従って選びます。この「くじ引き」に使う乱数の種が **seed** です。llama-server は、同じモデル・同じプロンプト・同じサンプリングの設定・同じ seed なら、同じトークンを選びます。seed を指定しなければ、リクエストのたびに違う乱数を使うので、同じプロンプトでも毎回違う本文になります。

第9章のプロファイルでは、`seed` を指定できるようにしてありました。しかし、`[sampling] seed = 42` のように1つの値に固定すると、すべてのリクエストが同じ seed になります。同じプロンプトで書き直させたいとき（第15章の、短すぎる本文の書き直しなど）でも、同じ本文が返ってきてしまいます。

### プロンプトから seed を決める

そこで、実行ごとに1つの**seed のもと**を決め、リクエストごとの seed は、seed のもととプロンプトから計算します。

```text
seed = SHA-256( seed のもと, salt, プロンプト（messages）) の先頭4バイト
```

- 同じ seed のもとで、同じプロンプトなら、同じ seed になります。プロンプトが1文字でも違えば、まったく違う seed になります
- 書き直させるときは、前回の本文や指摘がプロンプトに入るので、seed も変わります
- 途中で止まって再開しても、再開したあとのプロンプトが同じなら、止まらなかった場合と同じ seed になります。リクエストの回数を数えて seed を決める方法では、再開すると数え直しになるので、こうはなりません

**salt** は、同じプロンプトでも、わざと別の seed にしたいときに変える数です。LLMの出力の失敗（何回書き直させても正しいJSONにならないなど）で止まった場合、同じ seed で再開すると、同じ出力が返ってきて、また同じところで失敗します。`batch` は、失敗から再開するたびに salt を1つ増やします。

- **`_record`**：チャットが終わるたびに（失敗したときも）、`CallRecord` を作って `on_call` に渡します。プロンプトや本文そのものは入れません。本文は `scenes/` にあり、記録を小さく保つためです。

### 再現できる範囲

seed をそろえても、次の条件のどれかが違えば、同じ本文にはなりません。

- モデルのファイル（量子化の種類を含む）と、LoRAアダプタ
- llama.cpp のバージョンと、使っているバックエンド（CUDA・Metal・Vulkan・CPU）
- llama-server のオプション（`-c`・`-ngl`・`--cache-type-k` など）
- プロンプト（テンプレート・設定資料・文体の見本・好みのルールを含む）と、サンプリングの設定

同じ条件でも、ビット単位で同じになるとは限りません。llama-server は、前のリクエストと共通するプロンプトの先頭を、計算し直さずに使い回します（`cache_prompt`）。GPU の計算は、一度に処理するトークンの数によって、結果がごくわずかに変わることがあり、使い回したかどうかで出力が変わる場合があります。`-np` で複数のリクエストを同時に処理している場合も同じです。

## 32.4 実行の記録

### 記録するもの

1回の実行（`novelist write` や `novelist batch` の1回）ごとに、作品のディレクトリの `runs/` に、次の2つのファイルを作ります。

```text
works/kiri-long/runs/
├── 20261007-021132/
│   ├── run.json        # 何を、どの設定・seed・モデルで実行し、どうなったか
│   └── events.jsonl    # 実行中の出来事を、1行1件で
└── 20261007-093015/
    └── …
```

ディレクトリの名前が**実行ID**で、実行を始めた日時です。

`run.json` には、次のものを記録します。

| 項目 | 内容 |
|---|---|
| `command`・`args` | 実行したコマンドと、その引数 |
| `version` | novelist のバージョン |
| `status` | 実行中・完了・失敗・中断 |
| `seed` | seed のもと |
| `failures` | 失敗から再開した回数（`batch`）。salt にも使う |
| `server` | モデルのファイル・コンテキスト長・LoRAアダプタ（llama-server に問い合わせる） |
| `config` | 設定のすべて（`novelist.toml` に書かなかった項目は、既定値で） |
| `hashes` | プロンプト・文体の見本・好みのルールのファイルのハッシュ |
| `stats` | LLMの呼び出しの回数・失敗・やり直し・トークン数・かかった時間 |

設定は、`novelist.toml` のファイルをコピーするのではなく、読み込んで既定値を足したものを記録します。あとで既定値が変わっても、そのときに実際に使った値がわかります。プロンプトなどのファイルは、中身ではなくハッシュだけを記録します。ハッシュが前の実行と違えば、ファイルを変えたことがわかります。

`events.jsonl` には、出来事を1行に1つずつ、JSONで追記していきます。

```json
{"time": "2026-10-07T02:11:40+09:00", "kind": "session", "resume": false}
{"time": "2026-10-07T02:11:41+09:00", "kind": "log", "node": "prepare", "text": "書くシーン: 57件（1-1〜17-3）"}
{"time": "2026-10-07T02:13:05+09:00", "kind": "llm", "stream": true, "seed": 1827364519, "prompt_hash": "3fa9c2e1b07d", "temperature": 1.0, "max_tokens": 4096, "elapsed": 83.912, "retries": 0, "prompt_tokens": 6211, "completion_tokens": 2874, "tokens_per_second": 34.6, "finish_reason": "stop", "error": null}
{"time": "2026-10-07T04:52:17+09:00", "kind": "failure", "error": "/v1/chat/completions がエラーを返しました（503）: …", "failures": 1, "wait": 60.0}
```

※ 値は例です。

1行ずつ追記するJSONなので、プロセスが強制終了されても、それまでの行は残ります。書きかけで終わった最後の1行だけが壊れますが、読むときに飛ばします。第27章の好みの記録（`ratings.jsonl`）と同じ考え方です。

```python
def new_run_id(runs_dir: Path, now: datetime) -> str:
    """実行ID（20261007-021132 のような、開始した日時）。同じ秒に重なったら -2 などを付ける。"""
    base = now.strftime("%Y%m%d-%H%M%S")
    run_id, n = base, 1
    while (runs_dir / run_id).exists():
        n += 1
        run_id = f"{base}-{n}"
    return run_id


def hash_tree(path: Path) -> str:
    """ディレクトリ（またはファイル）の中身のハッシュ（16進数12桁）。なければ "-"。"""
    if not path.exists():
        return "-"
    files = [path] if path.is_file() else sorted(p for p in path.rglob("*") if p.is_file())
    h = hashlib.sha256()
    for f in files:
        h.update(f.relative_to(path).as_posix().encode() if f != path else b"")
        h.update(b"\0")
        h.update(f.read_bytes())
        h.update(b"\0")
    return h.hexdigest()[:12]


def input_hashes(config: Config) -> dict[str, str]:
    """出力を左右する、設定ファイル以外のファイルのハッシュ。"""
    return {
        "prompts": hash_tree(config.prompts_dir),
        "styles": hash_tree(config.styles_dir),
        "preferences": hash_tree(config.preferences_dir / "rules.md"),
    }


def server_snapshot(client: LLMClient) -> dict[str, Any] | None:
    """動いているモデルの情報。サーバーに接続できなければ None。"""
    try:
        info = client.server_info()
        adapters = client.lora_adapters()
    except (LLMError, KeyError, ValueError):

    return {
        "model": info.model,
        "model_path": info.model_path,
        "n_ctx": info.n_ctx,
        "lora": [{"path": a.path, "scale": a.scale} for a in adapters],
    }


class RunLog:
    """1回の実行の記録。with で使い、抜けるときに結果（完了・失敗・中断）を書く。"""

    def __init__(self, runs_dir: Path, manifest: RunManifest) -> None:
        self.dir = runs_dir / manifest.id
        self.manifest = manifest

    @classmethod
    def start(
        cls, runs_dir: Path, command: str, config: Config, seed: int | None = None
    ) -> "RunLog":
        """実行を始める。seed を省略すると、設定の [run] seed、それもなければ乱数を使う。"""
        now = datetime.now().astimezone().replace(microsecond=0)
        if seed is None:
            seed = config.run.seed if config.run.seed is not None else random.randrange(2**31)
        manifest = RunManifest(
            id=new_run_id(runs_dir, now),
            command=command,
            args=sys.argv[1:],
            version=__version__,
            started_at=now,
            seed=seed,
            config=config.model_dump(mode="json"),
            hashes=input_hashes(config),
        )
        run = cls(runs_dir, manifest)
        run.dir.mkdir(parents=True)
        run.save()
        return run

    @property
    def id(self) -> str:
        return self.manifest.id

    @property
    def events_path(self) -> Path:
        return self.dir / "events.jsonl"

    def save(self) -> None:
        """run.json を書き直す。"""
        (self.dir / "run.json").write_text(
            self.manifest.model_dump_json(indent=2), encoding="utf-8"
        )

    def event(self, kind: str, **data: Any) -> None:
        """出来事を events.jsonl に1行追加する。"""
        time = datetime.now().astimezone().isoformat(timespec="seconds")
        line = json.dumps({"time": time, "kind": kind, **data}, ensure_ascii=False)
        with self.events_path.open("a", encoding="utf-8") as f:
            f.write(line + "\n")

    def attach(self, client: LLMClient) -> None:
        """LLMクライアントに、seed のもとと、呼び出しの記録を設定する。"""
        client.seed_base = self.manifest.seed
        client.seed_salt = self.manifest.failures
        client.on_call = self.record_call
        if self.manifest.server is None:
            self.manifest.server = server_snapshot(client)
            self.save()

    def record_call(self, call: CallRecord) -> None:
        """LLMの呼び出しを記録し、集計する。"""
        self.event("llm", **asdict(call))
        stats = self.manifest.stats
        stats.calls += 1
        stats.errors += call.error is not None
        stats.retries += call.retries
        stats.prompt_tokens += call.prompt_tokens
        stats.completion_tokens += call.completion_tokens
        stats.llm_seconds = round(stats.llm_seconds + call.elapsed, 3)

    def log(self, node: str, line: str) -> None:
        """グラフのノードのログを記録する。シーンを保存したら、run.json も書き直す。"""
        self.event("log", node=node, text=line)
        if node == "save_scene":
            self.manifest.scenes += 1
            self.save()

    def failed(self, error: Exception, wait: float) -> None:
        """失敗を記録する。再開するときは、seed をずらす（同じ失敗を繰り返さないため）。"""
        self.manifest.failures += 1
        self.event("failure", error=str(error), failures=self.manifest.failures, wait=wait)
        self.save()

    def finish(self, status: RunStatus, error: str | None = None) -> None:
        self.manifest.status = status
        self.manifest.error = error
        self.manifest.finished_at = datetime.now().astimezone().replace(microsecond=0)
        self.event("finish", status=status, error=error)
        self.save()

    def __enter__(self) -> "RunLog":
        return self

    def __exit__(self, exc_type: type[BaseException] | None, exc: BaseException | None, tb) -> None:
        if self.manifest.status != "running":
            return  # すでに結果を書いた（失敗を表示してから終了した、など）
        if exc_type is None:
            self.finish("done")
        elif issubclass(exc_type, KeyboardInterrupt):
            self.finish("interrupted")
        else:
            self.finish("failed", str(exc) or exc_type.__name__)

def load_runs(runs_dir: Path) -> list[RunManifest]:
    """実行の記録を、古い順に返す。読めないものは飛ばす。"""
    if not runs_dir.is_dir():
        return []
    runs = []
    for path in sorted(runs_dir.glob("*/run.json")):
        try:
            runs.append(RunManifest.model_validate_json(path.read_text(encoding="utf-8")))
        except ValueError:
            continue
    return sorted(runs, key=lambda r: (r.started_at, r.id))


def load_events(runs_dir: Path, run_id: str) -> list[dict[str, Any]]:
    """実行の出来事。途中で強制終了して壊れた最後の行は飛ばす。"""
    path = runs_dir / run_id / "events.jsonl"
    if not path.is_file():
        return []
    events = []
    for line in path.read_text(encoding="utf-8").splitlines():
        try:
            events.append(json.loads(line))
        except json.JSONDecodeError:
            continue
    return events


def _flatten(data: Any, prefix: str = "") -> dict[str, Any]:
    """入れ子の辞書を、"server.retries" のようなキーの平らな辞書にする。"""
    if not isinstance(data, dict):
        return {prefix: data}
    flat: dict[str, Any] = {}
    for key, value in data.items():
        flat |= _flatten(value, f"{prefix}.{key}" if prefix else key)
    return flat


def config_changes(old: dict[str, Any], new: dict[str, Any]) -> list[str]:
    """2つの設定の違いを、「キー: 前 → 後」の行にする。"""
    a, b = _flatten(old), _flatten(new)
    return [
        f"{key}: {a.get(key, '（なし）')} → {b.get(key, '（なし）')}"
        for key in sorted(a.keys() | b.keys())
        if a.get(key) != b.get(key)
    ]
```

- **`RunLog.start`**：実行IDを決め、`runs/<実行ID>/` を作って、`run.json` を書きます。seed のもとは、引数・設定の `[run] seed`・乱数の順に決めます。
- **`attach`**：LLMクライアントに、seed のもと・salt・`record_call` を設定します。最初に呼んだときに、llama-server にモデルの情報を問い合わせて記録します。サーバーに接続できなくても、実行は止めません。
- **`record_call`**：LLMの呼び出しを `events.jsonl` に書き、`stats` に足し込みます。
- **`log`**：グラフのノードのログを書きます。シーンを保存したら（`save_scene`）、`run.json` も書き直します。PCが突然止まっても、`run.json` の `scenes` は、最後に保存したシーンまでの数になります。
- **`failed`**：失敗を記録し、`failures` を1つ増やします。次に `attach` したクライアントは、これを salt に使います。
- **`with` で使う**：`with` を抜けるときに、結果（完了・失敗・中断）を書きます。先に `finish` で結果を書いていれば、そちらを残します。
- **`config_changes`**：2つの設定を、`server.retries` のような平らなキーにしてから比べ、違う項目を「キー: 前 → 後」の行にします。

## 32.6 batch：止まっても最後まで書く

### batch の流れ

```text
novelist batch kiri-long
  │
  ├─▶ プロットがなければ、設計のグラフを実行する（確認は求めない）
  ├─▶ 執筆のグラフを実行する（前回止まったところがあれば、そこから）
  │      │
  │      ├─ 最後まで書いた ──────────────────────────────▶ 完了
  │      ├─ LLMの失敗 ─▶ 再開の回数が上限なら ─────────────▶ 失敗
  │      │                それ以外は、失敗を記録して待つ ─▶ 設計・執筆に戻る（seed をずらす）
  │      └─ 設定やファイルの誤り ─────────────────────────▶ 失敗
  └─ Ctrl+C ──────────────────────────────────────────────▶ 中断
```

`batch` は、1つの実行IDのまま、設計と執筆を何回でもやり直します。失敗と再開も、同じ `events.jsonl` に記録されます。

設計の途中で失敗した場合も、もう一度設計のグラフを実行すれば、できている成果物（設定資料・アウトラインなど）は読み込んで、残りから作ります。ただし、長編で、アウトラインを保存したあと、伏線を登録する前に止まった場合は、第31章までのグラフでは、伏線を登録せずにプロットへ進んでしまいます。アウトラインはあるのに伏線の一覧がなければ、アウトラインを読み込んで、伏線の登録から続けるようにします。

- **`_plan_session`**：設計のグラフを、プロットの確認を求めずに（`review` を `False` にして）実行します。夜中に確認を待って止まらないようにするためです。プロットの確認が必要なら、先に `novelist plan` を実行してから `batch` を使います。
- **`batch`**：本文は表示せず、ログだけを表示します。推敲の回数のほかは、執筆の条件を `novelist.toml` に従わせます。長い実行の条件は、コマンドの引数より、記録に残る設定ファイルで決めるほうが、あとで調べやすいからです。
- **`_batch_loop`**：失敗の扱いを、例外の種類で分けます。
  - `LLMError`（`TransientError` と、第10章の `StructuredOutputError` を含む）なら、失敗を記録し、`--wait` 秒待ってから再開します。再開すると、新しいクライアントに `attach` し直すので、salt が1つ増えます。
  - それ以外の `WRITE_ERRORS` は、再開しても直らないので、すぐに止めます。
  - 待っている間の Ctrl+C も中断として扱えるように、Ctrl+C は `_batch_loop` の外で受け止めます。
- **`runs`**：引数が作品のIDだけなら、実行の一覧を表にします。実行IDも指定すると、その実行の詳しい記録を表示します。
  - 前の実行から変わった設定と、ハッシュが変わったファイル
  - その実行で書いたシーン（シーンの記録の `run` から探す）
  - 最後の出来事（`--events` で行数を変える。LLMの呼び出しの行は省く）

### 同じ条件で書き直す

## 32.7 夜通し動かす

### 止まらないようにする

| 止まる原因 | 対処 |
|---|---|
| PCのスリープ | Windows では、「設定」の「電源」で、電源に接続時のスリープを「なし」にする。コマンドなら `powercfg /change standby-timeout-ac 0`（あとで元の分数に戻す）。macOS では `caffeinate -i uv run novelist batch 作品のID` |
| 端末を閉じた | Linux・macOS では、`tmux` や `screen` の中で実行するか、`nohup` を付ける。Windows では、実行中のターミナルのウィンドウを閉じない |
| llama-server が落ちた | `batch` は、`--max-failures` 回まで待って再開を繰り返す。その間に llama-server を起動し直せば、続きから書く |
| VRAMが足りなくなった | 長編では、プロンプトが長くなるほど、KVキャッシュが増える。llama-server の `-c` は起動時に確保するので、実行の途中で増えることはないが、ほかのアプリがVRAMを使うと足りなくなる。長い実行の間は、ゲームや動画の編集などを避ける |

### 出力をファイルに残す

画面の出力は、`events.jsonl` にほぼ同じものが残るので、ファイルに書き出す必要はありません。書き出したい場合、Windows で出力をファイルにリダイレクトすると、Python 3.12 は、日本語版の Windows では Shift_JIS（cp932）で書き出そうとします。`✓` のような、Shift_JIS にない文字を表示しようとしたところで、エラーになります。先に UTF-8 モードにしてください。

```console
PS> $env:PYTHONUTF8 = "1"
PS> uv run novelist batch kiri-long > batch.log
```

## 32.9 うまくいかないときは

**`batch` が同じところで、何回再開しても失敗する**

`runs 作品のID 実行ID` で、最後の記録を確かめてください。「正しい形式の出力が得られませんでした」が続くなら、そのモデルでは、そのJSONを作るのが難しいということです。salt を変えても直らなければ、`precise` プロファイルの温度を下げる、思考を止める・許す（第10章）、より大きいモデルを使う、のどれかを試してください。

**再開したら、前の実行と違う本文になった**

`write` を新しく実行すると、seed のもとも新しくなります（`[run] seed` を書いていない場合）。続きを同じ seed のもとで書きたいときは、前の実行の seed を `--seed` で指定してください。`batch` の中で再開した場合は、salt が変わるので、同じプロンプトでも違う本文になります。これは、同じ失敗を繰り返さないための動きです。

**`runs` で、状態が「実行中」のまま残っている**

PCの電源が切れたなど、記録に結果を書く前にプロセスが止まった実行です。`run.json` の `scenes` と、`events.jsonl` の最後の行で、どこまで進んでいたかがわかります。続きは、`novelist write` か `novelist batch` で再開できます。

**`runs/` が大きくなる**

`events.jsonl` には、本文もプロンプトも入れていないので、10万字の長編を書いても、1つの実行で1MB前後です。古い実行の記録が要らなければ、`runs/` のディレクトリごと消してかまいません。シーンの記録の `run` から、その実行の記録をたどれなくなるだけです。

**seed を指定したのに、同じ本文にならない**

32.3節の「再現できる範囲」を確かめてください。`runs 作品のID 実行ID` で、前の実行とモデルのファイル・設定・ファイルのハッシュが同じかを確かめ、同じなら、llama-server を `-np 1`（同時に処理するリクエストを1つ）で起動して、もう一度試してください。

## 32.10 まとめ

- 一時的な失敗（接続できない、時間切れ、503）は、クライアントが**指数バックオフ**で待ってから、やり直すようにしました。やり直すのは、待てば直る見込みがある失敗だけです
- LLMに渡す seed を、実行ごとの**seed のもと**とプロンプトから決めるようにしました。同じ seed のもとで同じプロンプトなら、途中で止まって再開しても、同じ seed になります。失敗から再開するときは、salt で seed をずらします
- 実行ごとに、設定・seed・モデル・プロンプトのハッシュ・LLMの呼び出し・失敗と再開を、`runs/` に**記録**するようにしました。シーンの記録から、そのシーンを書いた実行をたどれます
- `novelist batch` で、設計から最後のシーンまでを、失敗しても止まったところから再開しながら書けるようにしました
- `novelist runs` で、実行の記録と、前の実行から変わった設定を確かめられるようにしました

これで、`novelist` の機能はすべてそろいました。最後の第33章では、全体のコードを見直し、ここから先の拡張のアイデアを紹介します。
