# 第22章 ストーリーステート

第21章の一貫性チェッカーで、「知らないはずのことを知っている」という食い違いを取り上げました。推理小説では特に困る食い違いですが、これを見つけるのは簡単ではありません。「沢渡は、葉子の切符が昨日の日付だと知っているか」を確かめるには、これまでのすべてのシーンで、沢渡がその場にいて、それを見聞きしたかを調べる必要があります。あらすじや検索した本文から、LLMにそれを推し量らせるのは、確実な方法ではありません。

同じことは、人物の居場所や持ち物にも言えます。前のシーンで駅長室にいた人物が、次のシーンの冒頭で、説明もなく待合室にいる。硬券を黒川に渡したはずの沢渡が、まだ硬券を持っている。こうした食い違いは、「今、誰が、どこにいて、何を持ち、何を知っているか」を記録していれば、すぐにわかります。

この章では、その記録を**ストーリーステート**（物語の状態）として作ります。シーンを書き終えるたびに、LLMに本文を読ませて、状態の**変化**を記録させます。記録した状態は、次のシーンを書くときと、一貫性をチェックするときに使います。

この章で作るものは次のとおりです。

| ファイル・コマンド | 内容 |
|---|---|
| `src/novelist/schemas/story.py` | ストーリーステートと、状態の変化のモデル |
| `src/novelist/consistency/story_state.py` | 状態を作り、変化を反映する |
| `prompts/state_update/` | 本文から状態の変化を読み取るプロンプト |
| `prompts/_parts/story_state.md` | 状態を書き出す、プロンプトの共通部品 |
| `src/novelist/graph/nodes/story.py` | シーンを書き終えたときに、状態を更新するノード |

## 22.1 何を記録するか

### 人物ごとの状態

ストーリーステートには、登場人物ごとに、次のことを記録します。

| 項目 | 例 | 見つけられる食い違い |
|---|---|---|
| 場所 | 駅長室 | 説明のない移動 |
| 状態 | 右手に軽いやけど。コートが濡れている | けがや身なりの変化が、次のシーンで消える |
| 持ち物 | 硬券、懐中時計 | 手放した物をまだ持っている。持っていない物を使う |
| 知っていること | 葉子の切符は昨日の日付だった（1-1で、葉子の切符を見て） | 知らないはずのことを知っている |

そのほかに、物語全体の**時刻**（「翌日の午前一時ごろ」など）を記録します。

「知っていること」は、物語にとって大事な事実だけにします。ほかの人物の秘密、事件の手がかり、誰かの嘘などです。人物が見聞きしたことをすべて記録すると、あっという間に長くなり、プロンプトに入らなくなります。

### 状態はシーンごとに保存する

状態は、**シーンを書き終えるたびに**、そのときの状態を丸ごと保存します。

```text
works/kiri-no-eki/states/
├── 01-01.json   # 1-1 を書き終えたときの状態
├── 01-02.json   # 1-2 を書き終えたときの状態
...
```

最新の状態だけを1つ保存しておく方法もありますが、第15章の `--from` でシーンを書き直すときに困ります。2-1から書き直すなら、2-1を書く前の状態、つまり1-3を書き終えたときの状態が必要だからです。シーンごとに保存しておけば、どのシーンからでも書き直せます。

### 変化を記録させ、反映はプログラムで

状態を更新するとき、LLMに「前の状態と本文を読んで、新しい状態を丸ごと書いて」と頼む方法もあります。しかし、この方法では、前の状態にあったことを、LLMがうっかり書き落とすことがあります。書き落とした持ち物や知っていることは、それ以降の状態から消えてしまいます。

そこで、LLMには**変化だけ**を書かせ、それを前の状態に**反映するのはプログラム**で行います。

```text
前の状態（1-1 のあと）          LLMが読み取った変化（1-2）           新しい状態（1-2 のあと）
沢渡透                          沢渡透 location  駅長室              沢渡透
  場所: 待合室          ＋      沢渡透 learn     硬券の束が消えた  ＝   場所: 駅長室
  持ち物: 硬券                                                         持ち物: 硬券
  知っていること:                                                      知っていること:
    葉子の切符は昨日の日付                                               葉子の切符は昨日の日付
                                                                         硬券の束が消えた
```

変化に書かれていないことは、前の状態のまま残ります。第14章で、文字数の配分をプログラムで行ったのと同じ考え方です。LLMには判断（何が変わったか）を、プログラムには確実にできること（反映）を任せます。

変化の種類は、次の5つです。

| 種類 | 意味 |
|---|---|
| `location` | 移動した先の場所 |
| `status` | 体の具合・気分・身なりの変化 |
| `add_item` | 手に入れた物 |
| `remove_item` | 手放した・なくした物 |
| `learn` | 新しく知った、大事な事実 |

## 22.2 状態のモデル

**`src/novelist/schemas/story.py`**（新規）

```python
"""ストーリーステート：物語の今の状態（第22章）。"""

from typing import Literal

from pydantic import BaseModel, Field, ValidationInfo, model_validator


class CharacterState(BaseModel):
    """1人の登場人物の、今の状態。"""

    name: str
    location: str = ""  # 今いる場所。まだ登場していなければ空
    status: str = ""  # 体の具合、気分、身なりなど
    items: list[str] = Field(default_factory=list)  # 持っている物
    knows: list[str] = Field(default_factory=list)  # 物語の中で知ったこと（知った順）


class StoryState(BaseModel):
    """物語の今の状態。シーンを書き終えるたびに更新する。"""

    time: str = ""  # 物語の中の時刻・日付
    characters: list[CharacterState]

    def character(self, name: str) -> CharacterState | None:
        return next((c for c in self.characters if c.name == name), None)


ChangeKind = Literal["location", "status", "add_item", "remove_item", "learn"]


class StateChange(BaseModel):
    """状態の変化1件。"""

    character: str = Field(description="変化した人物の名前。登場人物の名前と同じ表記にする")
    kind: ChangeKind = Field(
        description="location: 移動した先の場所。status: 体の具合・気分・身なりの変化。"
        "add_item: 手に入れた物。remove_item: 手放した・なくした物。"
        "learn: 新しく知った、物語にとって大事な事実"
    )
    value: str = Field(description="場所、状態、物、知った事実", max_length=80)


class StateUpdate(BaseModel):
    """1つのシーンでの、状態の変化。LLMに作らせる。"""

    changes: list[StateChange] = Field(
        description="このシーンで起きた変化。起きた順に。変化がなければ空にする", max_length=20
    )
    time: str = Field(
        description="シーンの終わりの、物語の中の時刻や日付（例: 翌日の午前一時ごろ）。"
        "わからなければ、前の状態の時刻をそのまま書く",
        max_length=40,
    )

    @model_validator(mode="after")
    def _check_names(self, info: ValidationInfo) -> "StateUpdate":
        """人物の名前が、登場人物にあるかを確かめる（第14章と同じ、検証のコンテキスト）。"""
        names = (info.context or {}).get("character_names")
        if names is None:
            return self
        unknown = sorted({c.character for c in self.changes if c.character not in names})
        if unknown:
            raise ValueError(
                f"登場人物にない名前があります: {'、'.join(unknown)}"
                f"（使える人物: {'、'.join(sorted(names))}）"
            )
        return self
```

**`CharacterState` と `StoryState`**

22.1節の項目を、そのままフィールドにしています。どれも既定値を空にしているので、名前だけで、まだ何もわからない状態の人物を作れます。`StoryState.character` は、名前で人物の状態を探すメソッドです。

**`StateChange` と `StateUpdate`**

LLMに書かせる、状態の変化です。`kind` の `description` に、5つの種類の意味を書いています。

`StateUpdate` の `_check_names` は、変化の人物の名前が、登場人物にあるかを確かめます。第14章のプロットと同じく、**検証のコンテキスト**で登場人物の名前を受け取ります。「沢渡透」を「沢渡」と書いてしまった場合は、第10章の修正のループで、使える人物の一覧を添えて書き直させます。

## 22.3 状態を作り、更新する

**`src/novelist/consistency/story_state.py`**（新規）

```python
"""ストーリーステートを作り、シーンごとに更新する（第22章）。"""

from novelist.config import Config
from novelist.llm.client import LLMClient
from novelist.llm.structured import generate_structured, schema_text
from novelist.prompts import PromptLibrary
from novelist.schemas.bible import CharacterSheet
from novelist.schemas.plot import Plot
from novelist.schemas.story import CharacterState, StateUpdate, StoryState
from novelist.work import Work

UPDATE_PROFILE = "precise"
KNOWS_LIMIT = 8  # プロンプトに入れる「知っていること」の件数の上限（新しいものから）


def initial_state(characters: CharacterSheet) -> StoryState:
    """物語が始まる前の状態。場所も持ち物も、まだわからない。"""
    return StoryState(characters=[CharacterState(name=c.name) for c in characters.characters])


def state_before(
    work: Work, plot: Plot, characters: CharacterSheet, chapter: int, scene: int
) -> StoryState:
    """シーンを書き始める前の状態。

    直前のシーンの状態を使う。直前のシーンの状態がなければ（状態の記録を始める前に
    書いたシーンなど）、さらに前にさかのぼり、1つもなければ最初の状態にする。
    """
    order = [(i, j) for i, j, _ in plot.scenes()]
    for i, j in reversed(order[: order.index((chapter, scene))]):
        saved = work.load_story_state(i, j)
        if saved is not None:
            return merge_characters(saved, characters)
    return initial_state(characters)


def merge_characters(state: StoryState, characters: CharacterSheet) -> StoryState:
    """設定資料の登場人物に合わせる。設定資料に人物を加えた場合でも使えるようにする。"""
    known = {c.name: c for c in state.characters}
    return StoryState(
        time=state.time,
        characters=[known.get(c.name, CharacterState(name=c.name)) for c in characters.characters],
    )


def apply_update(state: StoryState, update: StateUpdate) -> tuple[StoryState, list[str]]:
    """変化を状態に反映した、新しい状態を返す。反映した変化の説明も返す。

    元の状態は変えない。変化にない項目は、前の状態のまま残る。
    """
    new = state.model_copy(deep=True)
    new.time = update.time or state.time
    notes = []
    for change in update.changes:
        c = new.character(change.character)
        if c is None:
            notes.append(f"（無視）登場人物にない: {change.character}")
            continue
        value = change.value.strip()
        if change.kind == "location":
            c.location = value
            notes.append(f"{c.name}の場所 → {value}")
        elif change.kind == "status":
            c.status = value
            notes.append(f"{c.name}の状態 → {value}")
        elif change.kind == "add_item":
            if value not in c.items:
                c.items.append(value)
            notes.append(f"{c.name}が手に入れた: {value}")
        elif change.kind == "remove_item":
            if value in c.items:
                c.items.remove(value)
                notes.append(f"{c.name}が手放した: {value}")
            else:
                notes.append(f"（無視）{c.name}は持っていない: {value}")
        elif change.kind == "learn":
            if value not in c.knows:
                c.knows.append(value)
            notes.append(f"{c.name}が知った: {value}")
    return new, notes


def update_state(
    client: LLMClient,
    prompts: PromptLibrary,
    config: Config,
    before: StoryState,
    scene_label: str,
    text: str,
) -> tuple[StoryState, list[str]]:
    """シーンの本文から状態の変化を読み取らせて、新しい状態を作る。"""
    messages = prompts.render(
        "state_update",
        state=before,
        scene_label=scene_label,
        text=text,
        knows_limit=KNOWS_LIMIT,
        schema=schema_text(StateUpdate),
    )
    sampling = config.sampling_for(UPDATE_PROFILE)
    sampling = sampling.model_copy(update={"max_tokens": max(sampling.max_tokens, 4096)})
    context = {"character_names": {c.name for c in before.characters}}
    update = generate_structured(
        client, messages, StateUpdate, sampling, validation_context=context
    )
    return apply_update(before, update)
```

**`initial_state`**

物語が始まる前の状態です。設定資料の登場人物を、名前だけで並べます。場所も持ち物も、まだわかりません。

**`state_before`**

あるシーンを書き始める前の状態を返します。直前のシーンを書き終えたときの状態を読み込みますが、それがなければ、さらに前のシーンにさかのぼります。この章より前に書いたシーンのように、状態を保存していないシーンがあっても、使える状態を返せるようにするためです。1つも見つからなければ、最初の状態にします。

**`merge_characters`**

保存した状態の人物を、今の設定資料の登場人物に合わせます。第13章の設定資料を手で直して人物を加えた場合でも、その人物を、名前だけの状態で加えます。

**`apply_update`**

22.1節の「反映はプログラムで」の部分です。`model_copy(deep=True)` で前の状態をまるごとコピーしてから、変化を1つずつ反映します。

- **`remove_item`**：持っていない物を手放したという変化は、反映せずに「（無視）」として記録します。LLMの読み違いか、本文の食い違いのどちらかです。
- **`learn` と `add_item`**：すでにある事実や物は、二重に加えません。
- **時刻**：LLMが空で返したら、前の時刻のままにします。

戻り値には、反映した変化の説明（`notes`）も含めます。ログに出して、何が変わったかを確かめられるようにするためです。

**`update_state`**

状態の変化を読み取るプロンプトを展開し、`StateUpdate` を受け取って、`apply_update` で反映します。`validation_context` に登場人物の名前を渡しています（第14章）。

### プロンプト

状態を書き出す部分は、本文を書くプロンプトでも使うので、共通部品にします。

**`prompts/_parts/story_state.md`**（新規）

```markdown
{# ストーリーステート。state（StoryState）、names（表示する人物の名前。None ならすべて）、knows_limit を受け取る（第22章） #}
{% if state.time %}
- 時刻: {{ state.time }}
{% endif %}
{% for c in state.characters if names is none or c.name in names %}
- {{ c.name }}
  - 場所: {{ c.location or "（まだ登場していない）" }}
{% if c.status %}
  - 状態: {{ c.status }}
{% endif %}
{% if c.items %}
  - 持ち物: {{ c.items | join("、") }}
{% endif %}
{% if c.knows %}
  - 知っていること:
{% for fact in c.knows[-knows_limit:] %}
    - {{ fact }}
{% endfor %}
{% endif %}
{% endfor %}
```

- `names` に名前のリストを渡すと、その人物だけを書き出します。`None` なら、全員を書き出します。Jinja2では、`{% for ... if 条件 %}` のように、ループに条件を付けられます。
- 「知っていること」は、`c.knows[-knows_limit:]` で、新しいものから `knows_limit` 件だけを書き出します。物語が進むにつれて増え続けるので、プロンプトが長くなりすぎないようにするためです。

```python
"""シーンを書き終えたときに、登場人物の状態を更新するノード（第22章）。"""

from typing import Literal

from langgraph.runtime import Runtime

from novelist.consistency.story_state import update_state
from novelist.graph.nodes.write import scene_brief
from novelist.graph.state import WriteContext, WriteState


def route_after_summary(state: WriteState) -> Literal["update_story_state", "save_scene"]:
    """状態を記録するなら更新へ、そうでなければ保存へ進む。"""
    return "update_story_state" if state.get("track_state") else "save_scene"


def update_story_state(state: WriteState, runtime: Runtime[WriteContext]) -> dict:
    """書き終えたシーンの本文から、状態の変化を読み取り、新しい状態を作る。"""
    ctx = runtime.context
    brief = scene_brief(state, runtime, with_context=False)
    before = brief.story_state
    assert before is not None  # track_state が True なら、scene_brief が入れている
    after, notes = update_state(
        ctx.client,
        ctx.prompts,
        ctx.config,
        before,
        f"{brief.key}「{brief.scene.title}」（視点: {brief.scene.pov}）",
        state["text"],
    )
    log = [f"状態: {note}" for note in notes] or ["状態: 変化なし"]
    if after.time and after.time != before.time:
        log.append(f"状態: 時刻 → {after.time}")
    return {"story_after": after, "log": log}
```

**`update_story_state`**

`scene_brief` で、シーンの前の状態を取り出し、`update_state` で、本文から変化を読み取って、新しい状態を作ります。要約（`summarize_scene`）のあとに置くので、推敲（第16章）や一貫性の修正（第21章）を終えた、最終的な本文から読み取ります。

`assert` は、「ここでは必ず成り立つはず」という条件を書く文です。条件が成り立たなければ、`AssertionError` になります。`track_state` が `True` なら、`scene_brief` が必ず状態を入れているはずなので、そのことを書いておくと、コードを読む人にも伝わります。

**`route_after_summary`**

## 22.8 うまくいかないときは

**「知っていること」に、その場にいない人物の分まで記録される**

状態の更新のプロンプトの「知ったことは、その場にいて見聞きした人物だけに記録する」を、LLMが守れていません。`novelist state` で状態を確かめ、おかしければ、`states/` のJSONを手で直してください。状態は、次のシーンを書くときに、直したファイルから読み込まれます。

**大事でないことまで記録されて、「知っていること」が増えすぎる**

プロンプトに入るのは新しい8件だけですが、古い大事な事実が押し出されてしまいます。`prompts/state_update/system.md` の learn の説明に、「物語の結末にかかわる事実だけ」のように、条件を厳しく書いてください。

**場所の名前が、設定資料と違う表記になる**

「駅長室」が「駅長の部屋」と記録されることがあります。第14章のプロットのように、場所の名前も検証のコンテキストで確かめる方法がありますが、本文には設定資料にない場所（「ホームの端」など）も出てくるので、本書では厳しく確かめていません。気になる場合は、`StateUpdate` の検証で、`location` の値が設定資料の場所にあるかを確かめ、なければ書き直させるように変えてください。

**本文を手で直したのに、状態が古いまま**

状態は、本文を書いたときにだけ更新されます。本文を手で直したあとは、`novelist state kiri-no-eki --rebuild` で作り直してください。

- 登場人物の**場所・状態・持ち物・知っていること**と、物語の**時刻**を、**ストーリーステート**として記録するようにしました。シーンを書き終えるたびに、そのときの状態をシーンごとに保存するので、どのシーンからでも書き直せます
- LLMには状態の**変化**だけを書かせ、前の状態への**反映はプログラム**で行いました。変化に書かれていないことは前の状態のまま残るので、LLMの書き落としで情報が消えることがありません
- 「知ったことは、その場にいた人物だけに記録する」ことで、「知らないはずのことを知っている」という食い違いを見つける根拠にしました
- 状態は、本文を書くときにシーンの情報として渡し、一貫性のチェックでは資料として使います
- `novelist state` で状態を確かめ、`--rebuild` で書き終えたシーンから作り直せるようになりました

これで第IV部は終わりです。設定資料と本文を検索して参照しながら書き（第18〜20章）、書いたものを資料と突き合わせて直し（第21章）、物語の状態を記録し続ける（第22章）仕組みがそろいました。

第V部では、文章そのものの質に目を向けます。第23章では、お手本となる文章（文体サンプル）をプロンプトに入れて、書き方をまねさせる**few-shot**の方法を扱います。
