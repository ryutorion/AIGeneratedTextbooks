# 第 21 章　LBS の限界

**この章で作るもの**：LBS の破綻を**数値として検出するテスト**。「見た目がおかしい」を「体積が 20.5% 失われる」「半径が 0 になる」に翻訳します。描画せずに破綻を捉える、本書の方針が最も試される章です。

---

## 21.1　見た目の破綻を、どう測るか

リニアブレンドスキニングには、よく知られた 2 つの破綻があります。

**キャンディラッパー現象。** 関節を軸まわりにねじると、その部分が飴の包み紙をひねったように細くなる。

**関節のへこみ。** 肘や膝を深く曲げると、内側がへこんで痩せる。

どちらも「見た目の問題」として語られます。しかし本書は描画をしません。**では、どうやってこれを検出するのか。**

答えは、破綻を**幾何学的な量**に翻訳することです。

| 見た目の症状 | 測れる量 |
| --- | --- |
| 細くなる、痩せる | **体積** |
| 潰れる、断面が消える | **軸からの最小距離（半径）** |
| 陰影が壊れる | 法線の長さ、法線どうしの角度 |

第 17 章で円柱メッシュと `MeshVolume` を用意したのは、この日のためでした。

---

## 21.2　ねじる

第 17 章の円柱（長さ 1 m、半径 0.15 m、24 × 24 分割）を、中央のボーンで**軸まわりにねじります**。ボーン 0 は固定、ボーン 1 を X 軸まわりに θ 回転させます。

未変形の体積は **0.069881**（第 17 章で確認済み）。ねじり角ごとに測ります。

| ねじり角 | 体積 | 未変形比 | 軸からの最小距離 |
| --- | --- | --- | --- |
| 0° | 0.069881 | 100.00% | 0.15000 |
| 45° | 0.067690 | 96.86% | 0.13858 |
| 90° | 0.062582 | 89.55% | 0.10607 |
| 135° | 0.057548 | 82.35% | 0.05740 |
| **180°** | **0.055538** | **79.48%** | **0.00000** |

**180 度で、最小半径が 0 になりました。** 円柱の表面が軸に触れています。断面が完全に潰れ、そこだけメッシュが一本の線になっている ―― これがキャンディラッパー現象の正体です。

体積の損失が 20.5% に留まっているのは、潰れるのが**ウェイトが混ざる区間だけ**だからです。円柱の 70% は 1 本のボーンに 100% 属していて、そこは剛体変換なので何も起きません。**平均的な指標だけ見ていると、局所的な破綻を見逃す**という良い例です。だから最小半径も一緒に測ります。

---

## 21.3　なぜそうなるのか ―― 閉じた式で理解する

数値を見て「ふーん」で終わらせず、**なぜその値になるのか**を導いておきます。

軸から距離 `r` の点を考えます。ボーン 0 は恒等変換、ボーン 1 は軸まわりに `θ` 回転。ウェイトは `w₀`, `w₁`（`w₀ + w₁ = 1`）。

断面（YZ 平面）を複素数で表すと、この点は `r·e^{iφ}` です。2 つのボーンによる変換結果はそれぞれ `r·e^{iφ}` と `r·e^{i(φ+θ)}`。LBS はこれを加重平均するので、

```
p' = r · ( w₀·e^{iφ} + w₁·e^{i(φ+θ)} )
   = r · e^{iφ} · ( w₀ + w₁·e^{iθ} )
```

したがって変形後の半径は

```
r' = r · | w₀ + w₁·e^{iθ} |
   = r · √( w₀² + w₁² + 2·w₀·w₁·cos θ )
```

**確かめます。** 数値実験の結果と並べます。

| `w₁` | ねじり角 | 実測（比） | 式の値 |
| --- | --- | --- | --- |
| 0.20 | 60° | 0.916515 | 0.916515 |
| 0.20 | 180° | 0.600000 | 0.600000 |
| 0.35 | 120° | 0.563471 | 0.563471 |
| 0.50 | 60° | 0.866025 | 0.866025 |
| 0.50 | 120° | 0.500000 | 0.500000 |
| **0.50** | **180°** | **0.000000** | **0.000000** |
| 0.70 | 180° | 0.400000 | 0.400000 |

**すべて小数第 6 位まで一致。**

式から 2 つのことが読み取れます。

**① 50:50 のとき `r' = r·cos(θ/2)`。** `w₀ = w₁ = 0.5` を代入すると `√(0.5(1+cos θ)) = cos(θ/2)` です。90 度で 0.707 倍、180 度で 0 倍。**半分だけ回すのではなく、弦の長さになる** ―― これが LBS の本質です。

**② 180 度では `r' = r·|w₀ − w₁|`。** ウェイトがちょうど半々の頂点だけが完全に潰れます。0.4 : 0.6 なら 20% は残る。**だから、ねじり関節ではウェイトを 50:50 にしない、という回避策が生まれます**（21.6 節）。

破綻の原因も、この式から明らかです。**LBS は 2 つの点を直線で結んだ中点を取る。** 円弧の上を進むのではなく、弦を横切ってしまう。第 10 章で `Lerp` した回転を正規化して `Nlerp` にしたのと、まったく同じ構図です。**ただし今回は、正規化する先がありません。** 頂点の位置には「長さ 1 に戻す」に相当する操作が存在しないからです。

## 21.4　曲げる

ねじりだけでなく、**曲げ**でも同じことが起きます。今度はボーン 1 を Z 軸まわりに回します（肘を曲げる動き）。

| 曲げ角 | 体積 | 未変形比 |
| --- | --- | --- |
| 0° | 0.069881 | 100.00% |
| 45° | 0.068794 | 98.44% |
| 90° | 0.066170 | 94.69% |
| 120° | 0.064314 | 92.03% |
| 150° | 0.062955 | 90.09% |

ねじりほど劇的ではありません。150 度でも 10% の損失です。理由は、曲げでは**回転軸が断面に含まれている**ため、軸上の点（半径 0 の点）が動かず、潰れ方が一方向に限られるからです。ねじりでは断面全体が縮みます。

とはいえ 10% は無視できる量ではありません。肘の内側がへこんで見えるのは、この損失が関節付近に集中しているためです。

---

## 21.5　法線も壊れる

第 19 章で `NormalizeSafe` にフォールバックを渡した理由が、ここで明らかになります。

180 度ねじった関節の 50:50 の頂点では、2 つのボーンが法線を正反対の向きに変換します。加重平均すると**ゼロベクトル**になります。

```cpp
// 第 19 章のテストで確認済み
const Vec3 n = SkinNormalLBS(v, palette);   // ゼロベクトルになる
return NormalizeSafe(n, v.normal);          // フォールバックが働く
```

フォールバックがなければ NaN になり、その頂点から先の計算がすべて汚染されます。**「めったに起きない特殊ケース」ではなく、LBS の構造から必然的に生じる状況**でした。第 10 章の Slerp の特異点と同じです。

---

## 21.6　実務での回避策と、その限界

キャンディラッパー現象は、LBS を使う限り消えません。**式から導かれる帰結**なので、実装を改善しても直りません。

現場では、次の方法で緩和します。

**① ウェイトを 50:50 にしない。** 21.3 節の式から、`|w₀ − w₁|` が残ります。ただしこれは「潰れる場所をずらす」だけで、なめらかさは失われます。

**② ねじりを分散させる。** 1 つの関節で 180 度ねじる代わりに、前腕に補助ボーンを 2〜3 本入れて 60 度ずつ分担させる。60 度なら `cos(30°) = 0.866` で 13% の縮みに収まります。**実務で最もよく使われる方法**で、「ツイストボーン」「ロールボーン」と呼ばれます。

**③ 補正ボーンを入れる。** 関節の角度に応じて動く追加のボーンで、へこんだ分を押し戻す。手間がかかりますが、アーティストが結果を直接制御できます。

**④ アルゴリズムを変える。** これが次章です。

①〜③ はいずれも**モデル側の作り込み**で対処する方法です。LBS が高速で、シェーダが単純で、あらゆるツールが対応しているという利点は大きいので、**多くの現場では今もこの道が選ばれます**。

補助ボーンによる緩和を、数値で確かめておきます。180 度のねじりを 3 本のボーンで 60 度ずつ分担させると、各関節の縮みは `cos(30°) = 0.866` 倍。半径は 13.4% しか減りません。**1 本で 180 度ねじって 100% 潰れるのとは、まったく違う結果です。**

## 21.7　テストを書く ―― 壊れることを検査する

`AnimLib.Tests/LbsLimitationTests.cpp`：

```cpp
#include "CppUnitTest.h"

#include "TestSupport/MathAssert.h"
#include "TestSupport/MeshSupport.h"
#include "TestSupport/Tolerance.h"

#include "anim/Skinning.h"
#include "anim/SkinnedCharacter.h"

#include <format>
#include <numbers>

using namespace Microsoft::VisualStudio::CppUnitTestFramework;
using namespace anim;

namespace {

constexpr float kPi = std::numbers::pi_v<float>;

struct TwistFixture {
    SkinnedModel model;
    SkinnedMesh mesh;
    std::vector<Vec3> deformed;
    double restVolume = 0.0;

    TwistFixture() {
        SkeletonBuilder b;
        b.AddRoot("root");
        b.AddBone("joint", "root", Transform{{0.5f, 0, 0}, QuatIdentity(), {1, 1, 1}});
        model.skeleton = b.Build();
        model.inverseBind.resize(model.skeleton.BoneCount());
        ComputeInverseBindMatrices(model.skeleton, model.skeleton.RestLocals(),
                                   model.inverseBind);

        mesh = anim::test::MakeCylinder(24, 24, 1.0f, 0.15f);
        deformed.resize(mesh.vertices.size());

        std::vector<Vec3> rest;
        for (const SkinnedVertex& v : mesh.vertices) { rest.push_back(v.position); }
        restVolume = anim::test::MeshVolume(rest, mesh.indices);
    }

    // axis まわりに angle 回転させて変形し、体積を返す
    double Deform(Vec3 axis, float angle) {
        SkinnedCharacter c(model);
        c.LocalPose()[1].rotation = MakeQuatAxisAngle(axis, angle);
        c.Update(model);
        SkinMeshLBS(mesh, c.Palette().Matrices(), deformed);
        return anim::test::MeshVolume(deformed, mesh.indices);
    }

    // ウェイトが混ざる区間での、軸からの最小距離
    [[nodiscard]] float MinRadiusInBlendRegion() const {
        float minRadius = 1.0e9f;
        for (std::size_t i = 0; i < mesh.vertices.size(); ++i) {
            const SkinnedVertex& v = mesh.vertices[i];
            if (v.weights[0] < 0.01f || v.weights[1] < 0.01f) { continue; }
            const Vec3 p = deformed[i];
            minRadius = std::fmin(minRadius, std::sqrt(p.y * p.y + p.z * p.z));
        }
        return minRadius;
    }
};

}  // namespace

namespace AnimLibTests {

TEST_CLASS(LbsLimitationTests) {
public:

    // --- 破綻しないことの確認（対照群）----------------------------

    TEST_METHOD(RigidRotationPreservesVolume) {
        TwistFixture f;
        // 両方のボーンを同じだけ回せば、全体が剛体変換になる
        SkinnedCharacter c(f.model);
        const Quat q = MakeQuatAxisAngle({1, 1, 0}, 1.3f);
        c.LocalPose()[0].rotation = q;
        c.Update(f.model);
        SkinMeshLBS(f.mesh, c.Palette().Matrices(), f.deformed);

        const double v = anim::test::MeshVolume(f.deformed, f.mesh.indices);
        Assert::IsTrue(std::fabs(v - f.restVolume) < 1.0e-6);
    }

    // --- キャンディラッパー現象 -----------------------------------

    // 「壊れること」を検査する。これは仕様であってバグではない。
    TEST_METHOD(TwistCollapsesTheCrossSection) {
        TwistFixture f;

        struct Expectation { float degrees; double minVolumeRatio; double maxVolumeRatio; };
        const Expectation cases[] = {
            {  0.0f, 0.999, 1.001},
            { 45.0f, 0.955, 0.985},
            { 90.0f, 0.880, 0.910},
            {135.0f, 0.810, 0.840},
            {180.0f, 0.780, 0.810},
        };

        for (const Expectation& e : cases) {
            const double v = f.Deform({1, 0, 0}, e.degrees * kPi / 180.0f);
            const double ratio = v / f.restVolume;
            Logger::WriteMessage(std::format(
                L"twist {:5.0f} deg : volume {:.2f}%, min radius {:.5f}\n",
                e.degrees, ratio * 100.0, f.MinRadiusInBlendRegion()).c_str());
            Assert::IsTrue(ratio >= e.minVolumeRatio && ratio <= e.maxVolumeRatio);
        }
    }

    // 180 度で断面が完全に潰れること
    TEST_METHOD(HalfTurnCollapsesRadiusToZero) {
        TwistFixture f;
        f.Deform({1, 0, 0}, kPi);
        anim::test::AssertNear(0.0f, f.MinRadiusInBlendRegion(), test::kEpsPos);
    }

    // 21.3 節の閉じた式が成り立つこと
    TEST_METHOD(CollapseFollowsTheClosedForm) {
        const std::vector<Mat4> palette{
            Identity(), ToMat4(MakeQuatAxisAngle({1, 0, 0}, 0.0f))};

        for (float w1 : {0.2f, 0.35f, 0.5f, 0.7f}) {
            for (float degrees : {60.0f, 120.0f, 180.0f}) {
                const float theta = degrees * kPi / 180.0f;
                const std::vector<Mat4> p{
                    Identity(), ToMat4(MakeQuatAxisAngle({1, 0, 0}, theta))};

                SkinnedVertex v{};
                v.position = {0.0f, 0.15f, 0.0f};
                v.joints[0] = 0;  v.weights[0] = 1.0f - w1;
                v.joints[1] = 1;  v.weights[1] = w1;

                const Vec3 out = SkinPositionLBS(v, p);
                const float measured = std::sqrt(out.y * out.y + out.z * out.z) / 0.15f;

                const float w0 = 1.0f - w1;
                const float predicted = std::sqrt(w0 * w0 + w1 * w1
                                                  + 2.0f * w0 * w1 * std::cos(theta));
                anim::test::AssertNear(predicted, measured, test::kEpsDir);
            }
        }
    }

    // 50:50 では r' = r·cos(θ/2)
    TEST_METHOD(FiftyFiftyFollowsHalfAngleCosine) {
        for (float degrees : {45.0f, 90.0f, 135.0f, 180.0f}) {
            const float theta = degrees * kPi / 180.0f;
            const std::vector<Mat4> p{
                Identity(), ToMat4(MakeQuatAxisAngle({1, 0, 0}, theta))};

            SkinnedVertex v{};
            v.position = {0.0f, 0.15f, 0.0f};
            v.joints[0] = 0;  v.weights[0] = 0.5f;
            v.joints[1] = 1;  v.weights[1] = 0.5f;

            const Vec3 out = SkinPositionLBS(v, p);
            anim::test::AssertNear(0.15f * std::cos(theta * 0.5f),
                                   std::sqrt(out.y * out.y + out.z * out.z),
                                   test::kEpsPos);
        }
    }

    // --- 曲げ -----------------------------------------------------

    TEST_METHOD(BendAlsoLosesVolumeButLess) {
        TwistFixture f;
        const double bend150  = f.Deform({0, 0, 1}, 150.0f * kPi / 180.0f) / f.restVolume;
        const double twist150 = f.Deform({1, 0, 0}, 150.0f * kPi / 180.0f) / f.restVolume;

        Logger::WriteMessage(std::format(
            L"150 deg: bend {:.2f}%, twist {:.2f}%\n",
            bend150 * 100.0, twist150 * 100.0).c_str());

        // 曲げのほうが損失が小さい
        Assert::IsTrue(bend150 > twist150);
        Assert::IsTrue(bend150 > 0.88 && bend150 < 0.92);
    }

    // --- 法線の破綻 -----------------------------------------------

    TEST_METHOD(NormalsCancelAtHalfTurn) {
        const std::vector<Mat4> palette{
            Identity(), ToMat4(MakeQuatAxisAngle({1, 0, 0}, kPi))};

        SkinnedVertex v{};
        v.normal = {0, 1, 0};
        v.joints[0] = 0;  v.weights[0] = 0.5f;
        v.joints[1] = 1;  v.weights[1] = 0.5f;

        // 混ぜる前の生の和はゼロベクトル
        Vec3 raw{0, 0, 0};
        for (int k = 0; k < kMaxInfluences; ++k) {
            if (v.weights[k] == 0.0f) { continue; }
            raw = raw + v.weights[k] * TransformVector(palette[v.joints[k]], v.normal);
        }
        Assert::IsTrue(LengthSquared(raw) < 1.0e-10f);

        // それでも SkinNormalLBS は妥当な値を返す（フォールバック）
        const Vec3 n = SkinNormalLBS(v, palette);
        Assert::IsFalse(std::isnan(n.x));
        anim::test::AssertNear(1.0f, Length(n), test::kEpsUnit);
    }

    // --- 回避策の効果 ---------------------------------------------

    // ツイストボーンで分散させると縮みが劇的に減ること
    TEST_METHOD(SplittingTwistAcrossBonesReducesCollapse) {
        // 180 度を 1 関節で
        const float single = 0.15f * std::cos(kPi * 0.5f);      // = 0
        // 180 度を 3 関節で 60 度ずつ
        const float split  = 0.15f * std::cos(kPi / 6.0f);      // cos(30°)

        Logger::WriteMessage(std::format(
            L"180 deg in 1 joint: radius {:.5f} / in 3 joints: {:.5f}\n",
            single, split).c_str());

        anim::test::AssertNear(0.0f, single, test::kEpsPos);
        Assert::IsTrue(split > 0.13f);   // 13% の縮みに留まる
    }
};

}  // namespace AnimLibTests
```

`TwistCollapsesTheCrossSection` は、**期待値に「範囲」を書いている**点が特徴的です。「体積比は 88% から 91% のあいだ」。ピンポイントの値にしないのは、メッシュの分割数やコンパイラによってわずかに変わるからです。しかし範囲を広げすぎると意味がなくなるので、**実測値の周囲 ±1.5% 程度**に絞っています。

そして、このテストが主張しているのは「LBS は壊れる」ということです。**壊れないように直すためのテストではありません。** 第 11 章の非一様スケール、第 15 章のレスト／バインド取り違え、第 18 章の未正規化ウェイトと同じく、**「そういう性質である」ことを実行可能な形で記録**しています。

次章で DQS を実装したら、**同じ測定関数で DQS を測ります**。そのとき、この章の数値が比較の基準になります。

## 21.8　つまずきやすいところ

**体積が負になる**
三角形の巻き方が内向きです（第 17 章）。変形しても巻き方は変わらないので、原因は必ずメッシュ生成側にあります。

**体積が予想より大きく減る**
ウェイトの合計が 1 になっていないかもしれません（第 17 章）。`RigidRotationPreservesVolume` を先に通してください。**剛体変換で体積が変わるなら、それは LBS の問題ではなく実装のバグです。**

**最小半径が 0 にならない**
ウェイトがちょうど 50:50 の頂点が存在しないだけかもしれません。`MakeCylinder` の分割数が偶数なら、ちょうど中央にリングが来ます（24 分割なら 13 番目）。奇数だと 50:50 の頂点が存在せず、最小半径が 0 より少し大きくなります。

**ねじり角を 180 度より大きくしたら、値が戻り始めた**
式のとおりです。`cos(θ/2)` は 180 度を超えると符号が反転し、絶対値は増えます。物理的には「反対側へ潰れて、また膨らむ」という動きになります。360 度で元に戻ります。

**曲げでは大した損失が出ない**
そのとおりです。ねじりのほうが深刻です。ただし実際のキャラクターでは、肩や前腕にねじりが日常的に発生します（手のひらを返す動作は前腕の 180 度ねじりです）。

## この章のまとめ

- 見た目の破綻は、**体積・最小半径・法線の長さ**という測れる量に翻訳できる。描画せずに検出するとは、こういうことをする。
- **ねじりで体積が 20.5% 失われ、180 度で断面の半径が 0 になる。** これがキャンディラッパー現象。
- **体積の平均だけ見ていると局所的な破綻を見逃す。** 円柱の 70% は剛体変換なので無傷、潰れるのは混合区間だけ。最小半径も一緒に測る。
- 破綻には**閉じた式がある**： `r' = r·√(w₀² + w₁² + 2w₀w₁cos θ)`。実測と小数第 6 位まで一致した。50:50 なら `r·cos(θ/2)`、180 度なら `r·|w₀ − w₁|`。
- 原因は「**円弧の上ではなく弦を横切る**」こと。第 10 章の `Lerp` と同じ構図だが、**位置には正規化に相当する操作がない**。
- 法線も 180 度でゼロベクトルになる。第 19 章の `NormalizeSafe` のフォールバックは、**特殊ケースではなく必然**への備えだった。
- 実務の回避策は**ウェイトの調整・ツイストボーンによる分散・補正ボーン**。180 度を 3 本に分ければ縮みは 13% で済む。LBS の速度と互換性は大きな利点なので、今もこの道が選ばれることは多い。
- **「壊れること」をテストとして記録する。** 次章の DQS を、同じ測定関数で評価するための基準になる。

次章、この数値を DQS で書き換えます。
