# 第 9 章　クォータニオンと回転行列

**この章で作るもの**：クォータニオン ⇔ 回転行列 ⇔ 軸角 の相互変換。行列からクォータニオンへの変換は、素朴に書くと 180 度付近で壊れます。実際に壊れる数値を見てから対策します。あわせて、デバッグ専用のオイラー角変換も作ります。

---

## 9.1　なぜ相互変換が必要なのか

第 8 章で「姿勢はクォータニオンで持つ」と決めました。ではなぜ行列との変換が要るのでしょうか。

**クォータニオン → 行列（`ToMat4`）** が必要なのは、**大量の頂点を変換するとき**です。第 16 章でスキニング行列パレットを作るとき、ボーンごとに 1 回この変換を行い、それを何千個もの頂点に使い回します。100 ボーンぶんの変換コストは、10 万頂点ぶんの `Rotate` 呼び出しに比べれば無視できます。

**行列 → クォータニオン（`ToQuat`）** が必要なのは、**外から行列で渡されたものを取り込むとき**です。glTF のノードは行列で姿勢を指定できます（第 34 章）。IK ソルバが構築した姿勢を階層に書き戻すときにも使います（第 50 章）。

そして両方向の変換があると、**テストが強くなります**。「行列で計算した結果」と「クォータニオンで計算した結果」が一致することを確かめられるからです。独立した 2 つの実装を突き合わせる、第 7 章と同じ手口です。

---

## 9.2　クォータニオン → 行列

第 8 章の `Rotate`（`v + 2w(u×v) + 2u×(u×v)`）を 3 つの基底ベクトルに適用し、結果を列に並べれば行列が得られます。展開して整理すると次の形になります。

```cpp
// AnimLib/include/anim/QuatMat.h
#pragma once

#include "anim/Mat4.h"
#include "anim/Quat.h"

namespace anim {

// 単位クォータニオンから回転行列を作る。
// 列ベクトル規約（第 6 章）。
[[nodiscard]] inline Mat4 ToMat4(const Quat& q) {
    const float x = q.x, y = q.y, z = q.z, w = q.w;

    Mat4 r = Identity();
    r.m[0][0] = 1.0f - 2.0f*(y*y + z*z);
    r.m[0][1] =        2.0f*(x*y - w*z);
    r.m[0][2] =        2.0f*(x*z + w*y);

    r.m[1][0] =        2.0f*(x*y + w*z);
    r.m[1][1] = 1.0f - 2.0f*(x*x + z*z);
    r.m[1][2] =        2.0f*(y*z - w*x);

    r.m[2][0] =        2.0f*(x*z - w*y);
    r.m[2][1] =        2.0f*(y*z + w*x);
    r.m[2][2] = 1.0f - 2.0f*(x*x + y*y);
    return r;
}

}  // namespace anim
```

構造を眺めると覚えやすくなります。

- **対角成分**は `1 - 2(残り 2 つの成分の二乗和)`
- **対角以外**は `2(2 つの成分の積 ± w × 残りの成分)`
- **符号は対称位置で反転**する。`m[0][1]` が `-wz` なら `m[1][0]` は `+wz`

最後の性質が実用的です。`m[i][j]` と `m[j][i]` で `w` の項の符号が逆になっていなければ、書き間違いです。**この行列が転置されていたら、すべての回転が逆向きになります。** 第 6 章の `MakeRotationZ` などと一致することを、必ずテストで確かめてください。

## 9.3　行列 → クォータニオン ―― 素朴な実装は壊れる

逆変換を考えます。前節の行列の**対角成分の和（トレース）**を計算してみると、

```
trace = 3 - 4(x² + y² + z²)
```

単位クォータニオンでは `x² + y² + z² = 1 - w²` なので、

```
trace = 3 - 4(1 - w²) = 4w² - 1
```

つまり `w = √(trace + 1) / 2` で `w` が求まります。`w` が分かれば、非対角成分の差から `x, y, z` が取れます。

```
m[2][1] - m[1][2] = 2(yz + wx) - 2(yz - wx) = 4wx
m[0][2] - m[2][0] = 4wy
m[1][0] - m[0][1] = 4wz
```

素朴に実装すると、こうなります。

```cpp
// ⚠ この実装は壊れています（このあと直します）
Quat ToQuatNaive(const Mat4& m) {
    const float trace = m.m[0][0] + m.m[1][1] + m.m[2][2];
    const float s = std::sqrt(trace + 1.0f) * 2.0f;    // = 4w
    return { (m.m[2][1] - m.m[1][2]) / s,
             (m.m[0][2] - m.m[2][0]) / s,
             (m.m[1][0] - m.m[0][1]) / s,
             0.25f * s };
}
```

**`w` が 0 に近づくと、この式は破綻します。** `w = cos(θ/2)` なので、`w → 0` は `θ → 180°` です。X 軸まわりの回転で確かめてみましょう。

| 回転角 | trace | `√(trace+1)·2` | 計算された `x` | 正しい `x` |
| --- | --- | --- | --- | --- |
| 179.0° | −0.999695 | 0.034911 | 0.9998 | 1.0000 |
| 179.9° | −0.999997 | 0.003383 | **1.0320** | 1.0000 |
| 180.0° | −1.000000 | 0.000000 | **−inf** | 1.0000 |

179.9 度で既に 3% ずれ、180 度ちょうどでゼロ除算です。

**そして 180 度回転は、実際に起こります。** キャラクターが後ろを向く、腕を真横から真下へ振る、ツールで軸を反転させる。どれも珍しくありません。「めったに起きないから」で済ませられる話ではないのです。

## 9.4　4 つの分岐で解く

解決の考え方は単純です。`w` が小さくて割れないなら、**`x`, `y`, `z` のうち最も大きいものを先に求めればよい**。単位クォータニオンでは 4 成分の二乗和が 1 なので、**少なくとも 1 つは絶対値が 0.5 以上**あることが保証されます。

どれが大きいかは、行列から判定できます。

```
4x² = 1 + m[0][0] - m[1][1] - m[2][2]
4y² = 1 - m[0][0] + m[1][1] - m[2][2]
4z² = 1 - m[0][0] - m[1][1] + m[2][2]
4w² = 1 + m[0][0] + m[1][1] + m[2][2]   （= trace + 1）
```

つまり、トレースが正なら `w` が最大、そうでなければ対角成分のうち最大のものが対応する成分を選べばよいことになります。これが**シェパードの方法（Shepperd's method）**です。

```cpp
[[nodiscard]] inline Quat ToQuat(const Mat4& a) {
    const auto& m = a.m;
    const float trace = m[0][0] + m[1][1] + m[2][2];
    Quat q{};

    if (trace > 0.0f) {
        // w が最大
        const float s = std::sqrt(trace + 1.0f) * 2.0f;   // = 4w
        q.w = 0.25f * s;
        q.x = (m[2][1] - m[1][2]) / s;
        q.y = (m[0][2] - m[2][0]) / s;
        q.z = (m[1][0] - m[0][1]) / s;
    } else if (m[0][0] > m[1][1] && m[0][0] > m[2][2]) {
        // x が最大
        const float s = std::sqrt(1.0f + m[0][0] - m[1][1] - m[2][2]) * 2.0f;   // = 4x
        q.w = (m[2][1] - m[1][2]) / s;
        q.x = 0.25f * s;
        q.y = (m[0][1] + m[1][0]) / s;
        q.z = (m[0][2] + m[2][0]) / s;
    } else if (m[1][1] > m[2][2]) {
        // y が最大
        const float s = std::sqrt(1.0f - m[0][0] + m[1][1] - m[2][2]) * 2.0f;   // = 4y
        q.w = (m[0][2] - m[2][0]) / s;
        q.x = (m[0][1] + m[1][0]) / s;
        q.y = 0.25f * s;
        q.z = (m[1][2] + m[2][1]) / s;
    } else {
        // z が最大
        const float s = std::sqrt(1.0f - m[0][0] - m[1][1] + m[2][2]) * 2.0f;   // = 4z
        q.w = (m[1][0] - m[0][1]) / s;
        q.x = (m[0][2] + m[2][0]) / s;
        q.y = (m[1][2] + m[2][1]) / s;
        q.z = 0.25f * s;
    }
    return q;
}
```

分岐によって、**非対角成分の「差」を使うか「和」を使うか**が変わることに注意してください。差は `4w·(成分)`、和は `4·(成分)·(成分)` に対応します。選んだ成分で割るので、その成分が関わる式を使う必要があるのです。

**この 4 分岐は、めったに使わない例外処理ではありません。** ランダムな回転 20 万個で分岐の到達率を測ると、

| 分岐 | 到達率 |
| --- | --- |
| `w`（trace > 0） | 44.6 % |
| `x` | 18.5 % |
| `y` | 18.6 % |
| `z` | 18.3 % |

**半分以上が trace 以外の分岐を通ります。** 素朴な実装は「180 度付近だけ壊れる」のではなく、90 度を超えたあたりから精度が落ち始めているのです。4 つの分岐すべてがテストで到達されることを、必ず確認してください。

### 符号の曖昧さ

`ToQuat` が返すのは `q` か `-q` のどちらかです。分岐ごとに「選んだ成分を正とする」ので、どちらになるかは行列の中身次第です。**これはバグではありません** ―― 第 8 章で見たとおり、行列 1 つに対してクォータニオンは 2 つ対応するからです。

テストでは `AssertSameRotation`（第 8 章）を使います。呼び出し側で符号を揃えたい場合は `AlignSign` を使ってください。

## 9.5　オイラー角 ―― デバッグ専用の出入り口

第 8 章で「オイラー角は内部表現に使わない」と決めました。それでも変換を用意するのは、**人間が読み書きする境界**が必要だからです。

- テストコードに「Y 軸まわり 30 度」と書きたい
- デバッガでボーンの姿勢を見て「これは肘が 90 度曲がっている状態だな」と判断したい
- ログに姿勢を残したい

順序の曖昧さを避けるため、**本書で使う定義を 1 つに固定します。**

```cpp
// 本書のオイラー角：ヨー(Y) → ピッチ(X) → ロール(Z) の順に「外側から」適用する。
// クォータニオンでは q = Ry(yaw) * Rx(pitch) * Rz(roll)。
// 第 6 章の規約どおり、右にあるロールが最初に効く。
struct EulerAngles {
    float pitchX;   // X 軸まわり（うなずき）
    float yawY;     // Y 軸まわり（首振り）
    float rollZ;    // Z 軸まわり（傾げ）
};

[[nodiscard]] inline Quat MakeQuatFromEuler(const EulerAngles& e) {
    return MakeQuatAxisAngle({0, 1, 0}, e.yawY)
         * MakeQuatAxisAngle({1, 0, 0}, e.pitchX)
         * MakeQuatAxisAngle({0, 0, 1}, e.rollZ);
}
```

生成側は合成するだけなので、間違えようがありません。問題は逆方向です。

前節の `ToMat4` に、この順序で構成した回転を当てはめると、

```
m[1][2] = -sin(pitch)
m[1][0] =  cos(pitch)·sin(roll)     m[1][1] = cos(pitch)·cos(roll)
m[0][2] =  sin(yaw)·cos(pitch)      m[2][2] = cos(yaw)·cos(pitch)
```

という関係が得られます。つまり `pitch` は `asin` で、`roll` と `yaw` は `atan2` で取り出せます。

```cpp
// デバッグ・入出力用。内部の計算には使わないこと。
[[nodiscard]] inline EulerAngles ToEuler(const Quat& q) {
    const Mat4 m = ToMat4(q);
    EulerAngles e{};

    // 誤差で定義域を出ることがあるので必ずクランプする
    float sinPitch = -m.m[1][2];
    if (sinPitch >  1.0f) { sinPitch =  1.0f; }
    if (sinPitch < -1.0f) { sinPitch = -1.0f; }
    e.pitchX = std::asin(sinPitch);

    const float cosPitch = std::sqrt(1.0f - sinPitch * sinPitch);
    if (cosPitch > kEulerGimbalThreshold) {
        e.rollZ = std::atan2(m.m[1][0], m.m[1][1]);
        e.yawY  = std::atan2(m.m[0][2], m.m[2][2]);
    } else {
        // ジンバルロック：ヨーとロールが同じ軸の回転になり、区別できない。
        // ロールを 0 に固定し、合計をヨーに寄せる。
        e.rollZ = 0.0f;
        e.yawY  = std::atan2(-m.m[2][0], m.m[0][0]);
    }
    return e;
}
```

### しきい値を実測で決める

`kEulerGimbalThreshold` をいくつにすべきか。これは**理屈では決まらないので、測って決めます**。ランダムな回転 20 万個の往復（`quat → euler → quat`）と、ピッチが ±90 度ちょうどのケースの両方を試しました。

| しきい値 | ランダム往復の最大誤差 | 失敗数 | ピッチ ±90° の復元 |
| --- | --- | --- | --- |
| `1e-4` | 2.8e-05 | 0 / 200000 | **失敗**（ヨーもロールも 0 になる） |
| `1e-3` | 2.8e-05 | 0 / 200000 | 成功 |
| `1e-2` | 6.5e-03 | **14 / 200000** | 成功 |

`1e-4` では、ピッチ 90.0 度のとき `cosPitch` が `7e-4` となって通常分岐に入り、そこで `atan2(≈0, ≈0)` を計算して意味のない値を返します。逆に `1e-2` にすると、ロック近傍でないケースまでフォールバックに落ちて精度が落ちます。

```cpp
// 実測で決めた値（本文の表を参照）。
inline constexpr float kEulerGimbalThreshold = 1.0e-3f;
```

**この表そのものが、オイラー角を内部表現に使わない理由の説明になっています。** ピッチが 90 度に近づくと、ヨーとロールの区別が原理的に失われる。しきい値をどう選んでも、この情報の欠落は避けられません。クォータニオンなら、そんな特異点はどこにもありません。

> **`atan2` の引数順**
> `std::atan2(y, x)` です。`atan2(x, y)` と書くと、角度が `π/2 - θ` になります。符号の間違いより気づきにくいので注意してください。

3 つ、意図を補足しておきます。

**`QuatMatrixMatchesAxisRotationMatrices`** は、第 6 章と第 9 章という独立に書いた 2 つの実装を突き合わせています。`ToMat4` が転置されていたら、ここで必ず落ちます。**この 3 行が、本書の回転規約すべての土台を固定しています。**

**`AllShepperdBranchesAreExercised`** は少し変わったテストで、変換の結果ではなく**テストの網羅性そのもの**を検査しています。「4 分岐を書いたが、実は 1 つも通っていなかった」という事態を防ぎます。カバレッジツールを使わずにブランチ到達を保証する、安価な方法です。

**`EulerGimbalLockStillReproducesTheRotation`** は、**あえて弱い主張**をしています。「角度が一致すること」ではなく「姿勢が一致すること」だけを要求しています。ジンバルロック時に角度が一致しないのは仕様であり、バグではないからです。テストは**主張したいことだけを主張する**のが正しく、余計な条件を足すと壊れやすいテストになります。

## 9.7　つまずきやすいところ

**すべての回転が逆向きになる**
`ToMat4` が転置されています。`m[0][1]` と `m[1][0]` の `w` の項の符号を確認してください。`QuatMatrixMatchesAxisRotationMatrices` が捕まえます。

**180 度付近で NaN や不正な値が出る**
`ToQuat` の 4 分岐が正しく実装されていません。`else if` の条件（`m[0][0] > m[1][1] && m[0][0] > m[2][2]`）を書き間違えて、常に同じ分岐に入っていないか確認してください。

**`ToQuat` の結果の符号が期待と違う**
仕様です。`AssertNear` ではなく `AssertSameRotation` を使ってください。

**非対角成分の「和」と「差」を取り違えた**
`trace` 分岐だけ通るテストでは検出できません。`RoundTripAt180Degrees` を必ず実行してください。7 本の軸で 4 分岐すべてを踏むように選んであります。

**`ToEuler` の結果が変**
`atan2` の引数順（`y` が先）と、`ToMat4` の添字を確認してください。また、`ToEuler` が返す角度をそのまま比較するテストは、ジンバルロック近傍で必ず落ちます。姿勢で比較してください。

**`asin` が NaN を返す**
`sinPitch` のクランプを忘れています。数学的には `|m[1][2]| ≤ 1` ですが、float の誤差で `1.0000001` になることが実際にあります。**定義域を持つ関数の前では必ずクランプする** ―― これは第 10 章の `acos` でも同じ話が出てきます。

## この章のまとめ

- **クォータニオン → 行列**は、大量の頂点を変換する前に一度だけ行う（第 16 章のスキニング行列パレット）。
- **行列 → クォータニオン**を素朴に（トレースだけで）書くと、**180 度付近で破綻**する。179.9 度で 3% ずれ、180 度でゼロ除算。
- **シェパードの 4 分岐**で解く。ランダムな回転では **55% が trace 以外の分岐**を通るので、これは例外処理ではなく主要な経路。
- `ToQuat` が返すのは `q` か `-q`。**符号の曖昧さは仕様**であり、テストは `AssertSameRotation` で書く。
- オイラー角は**人間との境界専用**。順序を 1 つに固定し（`Ry·Rx·Rz`）、ジンバルロックのしきい値は**実測で決めた**（`1e-3`）。この実測表そのものが、オイラー角を内部で使わない理由になっている。
- `asin` / `acos` の前では**必ずクランプ**する。誤差で定義域を出るのは日常的に起きる。
- **分岐の到達を検査するテスト**は、カバレッジツールなしでブランチの網羅を保証できる安価な手段。

次章では、いよいよ回転の補間に入ります。クォータニオンを採用した最大の理由がここで回収されます。
