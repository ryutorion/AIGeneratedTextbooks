# 第 26 章　クリップとポーズ生成

**この章で作るもの**：`Clip` ―― トラックをボーンぶん束ね、時刻を受け取ってポーズを返すもの。ループの折り返し（`AdjustTime`）が主題です。

---

## 26.1　クリップの構造

第 23 章で決めたとおり、ボーンごとに 3 本のトラックを持ちます。

```cpp
// AnimLib/include/anim/Clip.h
#pragma once

#include "anim/Pose.h"
#include "anim/Track.h"

namespace anim {

// ボーン 1 本ぶんのアニメーション。空のトラックは「変化しない」を意味する。
struct BoneTracks {
    Track<Vec3> translation;
    Track<Quat> rotation;
    Track<Vec3> scale;
};

enum class LoopMode {
    Once,       // 末尾で停止
    Loop,       // 先頭に戻る
    PingPong    // 往復
};

// 1 つのアニメーション。モデル固有で不変。1000 体で共有する。
class Clip {
public:
    void Resize(std::size_t boneCount) { bones_.resize(boneCount); }
    [[nodiscard]] std::size_t BoneCount() const noexcept { return bones_.size(); }

    [[nodiscard]] BoneTracks& Bone(BoneIndex i) { return bones_[i]; }
    [[nodiscard]] const BoneTracks& Bone(BoneIndex i) const { return bones_[i]; }

    void SetDuration(float d) { duration_ = d; }
    [[nodiscard]] float Duration() const noexcept { return duration_; }

    void SetLoopMode(LoopMode m) { loopMode_ = m; }
    [[nodiscard]] LoopMode GetLoopMode() const noexcept { return loopMode_; }

    // 再生時刻をクリップの範囲に折り返す。
    [[nodiscard]] float AdjustTime(float time) const;

    // ポーズを書き込む。空トラックのチャンネルは変更しない。
    void Sample(float time, Pose& out) const;
    void Sample(float time, SampleContext& context, Pose& out) const;

    // 全トラックの最終キー時刻から duration を決める。
    void ComputeDurationFromKeys();

private:
    std::vector<BoneTracks> bones_;
    float duration_ = 0.0f;
    LoopMode loopMode_ = LoopMode::Loop;
};

}  // namespace anim
```

**`duration_` を独立に持つ**のがポイントです。「全トラックの最終キー時刻の最大値」で決まりそうですが、そうしません。

理由は 2 つあります。**① 最後のキーの後に「間」がある**モーションが存在します。攻撃モーションの最後に 0.2 秒の余韻を入れる、といった作り方です。**② glTF が独立に持っている**わけではありませんが、実務上のクリップ定義（Unity の AnimationClip など）は長さを明示的に持ちます。

`ComputeDurationFromKeys()` は、長さの情報がないデータのための補助です。

## 26.2　時刻の折り返し

`AdjustTime` が、この章の中心です。

```cpp
float Clip::AdjustTime(float time) const {
    if (duration_ <= 0.0f) {
        return 0.0f;
    }

    switch (loopMode_) {
    case LoopMode::Once:
        return std::fmin(std::fmax(time, 0.0f), duration_);

    case LoopMode::Loop: {
        float wrapped = std::fmod(time, duration_);
        if (wrapped < 0.0f) {
            wrapped += duration_;      // ← 忘れやすい
        }
        return wrapped;
    }

    case LoopMode::PingPong: {
        const float period = duration_ * 2.0f;
        float wrapped = std::fmod(time, period);
        if (wrapped < 0.0f) {
            wrapped += period;
        }
        return (wrapped <= duration_) ? wrapped : (period - wrapped);
    }
    }
    return time;
}
```

### `fmod` の落とし穴

C++ の `std::fmod` は、**被除数の符号を保ちます**。

```
std::fmod(-0.5f, 2.0f)  =  -0.5f     （数学的な mod なら 1.5）
```

負の時刻は、逆再生で日常的に発生します。折り返しの後に `+= duration_` を忘れると、**負の時刻がそのままトラックに渡り、クランプされて先頭の値が返り続けます**。症状は「逆再生すると最初のフレームで止まる」。

`std::fmod` を使わずに済ませることもできます。

```cpp
// 別解：floor を使う（分岐がない）
const float wrapped = time - duration_ * std::floor(time / duration_);
```

こちらは常に `[0, duration_)` を返します。ただし `time` が大きいと `time / duration_` の精度が落ちるので、本書は `fmod` + 補正を採用します。**そもそも `time` を大きくしない**のが第 27 章の設計です。

### ピンポン

往復再生は、周期が `2 × duration` になります。前半はそのまま、後半は折り返します。

```
時刻:  0 → 2 → 4 → 6      （duration = 2）
結果:  0 → 2 → 0 → 2
       ↑ 上り  ↓ 下り
```

`wrapped <= duration_` の境界に `=` を含めているのは、`wrapped == duration_` のときに `period - wrapped == duration_` となって同じ値になるためで、どちらでも構いません。明示しておくと読み手が迷いません。

## 26.3　ポーズを書き込む

```cpp
void Clip::Sample(float time, Pose& out) const {
    ANIM_ASSERT(out.Size() >= bones_.size());
    const float t = AdjustTime(time);

    for (std::size_t i = 0; i < bones_.size(); ++i) {
        const BoneTracks& tracks = bones_[i];
        Transform& target = out[static_cast<BoneIndex>(i)];

        if (!tracks.translation.IsEmpty()) { target.translation = tracks.translation.Sample(t); }
        if (!tracks.rotation.IsEmpty())    { target.rotation    = tracks.rotation.Sample(t); }
        if (!tracks.scale.IsEmpty())       { target.scale       = tracks.scale.Sample(t); }
    }
}
```

**空トラックのチャンネルは書き換えません。** 第 23 章で述べた設計がここに現れます。

これは単なる最適化ではなく、**意味のある動作**です。呼び出し側はポーズをレストポーズで初期化しておき、クリップがアニメーションさせるチャンネルだけが上書きされる。「このクリップは腕しか動かさない」という部分アニメーションが、これだけで表現できます。

```cpp
Pose pose = Pose::FromRest(skeleton);   // 基準はレストポーズ
clip.Sample(time, pose);                // クリップが持つチャンネルだけ上書き
```

ヒント付きの版も用意します（第 25 章）。

```cpp
void Clip::Sample(float time, SampleContext& context, Pose& out) const {
    ANIM_ASSERT(context.Size() == bones_.size() * 3);
    const float t = AdjustTime(time);

    for (std::size_t i = 0; i < bones_.size(); ++i) {
        const BoneIndex bone = static_cast<BoneIndex>(i);
        const BoneTracks& tracks = bones_[i];
        Transform& target = out[bone];

        if (!tracks.translation.IsEmpty()) {
            target.translation = tracks.translation.SampleHint(t, context.Hint(bone, 0));
        }
        if (!tracks.rotation.IsEmpty()) {
            target.rotation = tracks.rotation.SampleHint(t, context.Hint(bone, 1));
        }
        if (!tracks.scale.IsEmpty()) {
            target.scale = tracks.scale.SampleHint(t, context.Hint(bone, 2));
        }
    }
}
```

`SampleHint` はヒントを参照で受け取り、更新します。**2 つの `Sample` が同じ結果を返すこと**は、第 25 章の設計上の約束であり、テストで保証します。

## 26.4　ループの連続性は、データの性質

ループ再生で滑らかにつながるには、**クリップの最初と最後の姿勢が一致している**必要があります。

```
t = 0            t = duration
  ●━━━━━━━━━━━━━━●
  ↑               ↑
  この 2 つが同じでなければ、ループのたびにカクつく
```

これは**コードでは保証できません**。アニメーターがそう作るか、ツールがそう出力するかの問題です。

しかし**検査はできます**。

```cpp
// ループの継ぎ目でのポーズの食い違いを測る。
// 0 に近いほど滑らかにつながる。
[[nodiscard]] float MeasureLoopDiscontinuity(const Clip& clip, const Skeleton& skeleton) {
    Pose atStart = Pose::FromRest(skeleton);
    Pose atEnd   = Pose::FromRest(skeleton);
    clip.Sample(0.0f, atStart);
    clip.Sample(clip.Duration(), atEnd);   // Loop モードでは AdjustTime が 0 に戻す

    // ※ Loop モードだと両方 t=0 になってしまうので、
    //    末尾はわずかに手前をサンプルする
    clip.Sample(clip.Duration() - 1.0e-4f, atEnd);

    float worst = 0.0f;
    for (BoneIndex i = 0; i < skeleton.BoneCount(); ++i) {
        worst = std::fmax(worst, Length(atStart[i].translation - atEnd[i].translation));
        const float dot = std::fabs(Dot(atStart[i].rotation, atEnd[i].rotation));
        worst = std::fmax(worst, 2.0f * std::acos(std::fmin(1.0f, dot)));
    }
    return worst;
}
```

**この関数のコメントが、実は重要な注意を含んでいます。** `Loop` モードでは `AdjustTime(duration)` が `0` を返すので、末尾をサンプルしたつもりが先頭を見てしまいます。継ぎ目を調べたいなら、`duration - ε` を使う必要があります。

第 62 章の総合演習では、読み込んだクリップに対してこの検査を走らせ、不連続の大きいクリップを警告します。**データの品質検査をテストの形で持つ**のは、実務では非常に有効です。

`PingPongIsContinuous` は面白いテストです。**`AdjustTime` が連続関数であることを、1000 分割して差分を見ることで確認**しています。折り返しの計算を間違えると、折り返し点で値が飛びます。「グラフを描けば一目で分かる」ことを、数値で検査する形にしています。

`EmptyTracksLeaveTheChannelUntouched` は、26.3 節の設計を守る番人です。うっかり `target = Transform{...}` のように丸ごと代入する実装に変えてしまうと、ここで落ちます。

## 26.6　つまずきやすいところ

**逆再生すると最初のフレームで止まる**
`fmod` の後の `+= duration_` を忘れています（26.2 節）。負の時刻がそのままトラックに渡り、クランプされています。

**ループのたびにカクつく**
データの問題です（26.4 節）。`MeasureLoopDiscontinuity` で確認してください。コードでは直せません。

**アニメーションさせていないボーンが原点に飛ぶ**
空トラックのチャンネルを書き換えています。`Pose::FromRest` で初期化してから `Sample` を呼んでいるかも確認してください。

**`AdjustTime(duration)` が 0 を返す**
`Loop` モードでは仕様です。末尾の姿勢を見たいなら `duration - ε` を使ってください（26.4 節）。

**ピンポンで折り返し点が 2 フレーム続く**
`wrapped <= duration_` の境界です。折り返し点で 1 フレームだけ同じ値になるのは仕様ですが、気になるなら `<` にしてください。

**`duration` が 0 のクリップで割り算エラー**
`AdjustTime` の先頭でガードしています。キーが 1 つもないクリップや、読み込みに失敗したクリップで実際に起こります。

## この章のまとめ

- `Clip` は**ボーンぶんの `BoneTracks` + 長さ + ループモード**。モデル固有で不変、1000 体で共有する。
- `duration` は**独立に持つ**。最後のキーの後に「間」があるモーションが存在するため。
- **`std::fmod` は被除数の符号を保つ。** `fmod(-0.5, 2.0)` は `-0.5`。`+= duration` の補正を忘れると「逆再生で最初のフレームから動かない」。
- **空トラックのチャンネルは書き換えない。** これは最適化ではなく仕様であり、部分アニメーションがこれだけで表現できる。
- **ループの連続性はデータの性質**でコードでは保証できない。しかし**検査はできる**（`MeasureLoopDiscontinuity`）。データの品質検査をテストとして持つのは実務で有効。
- `AdjustTime` が**連続関数であること**を、分割して差分を見る形でテストできる。

次章では、この `AdjustTime` を毎フレーム駆動する再生側を作ります。第 4 章で見た「float の時刻が凍結する」問題に、設計で決着をつけます。
