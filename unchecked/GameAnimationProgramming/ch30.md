# 第 30 章　JSON パーサを書く（1）字句解析

**この章で作るもの**：`JsonLexer` ―― JSON のテキストをトークンの列に分解するもの。エスケープの処理、数値の解釈、そして**エラーが起きた行と列を報告する**仕組みまで作ります。

---

## 30.1　JSON パーサを自作する

外部ライブラリを使わない、という本書の方針からすれば当然の選択ですが、それだけではありません。

**JSON は、自作するのに手ごろな大きさの言語**です。仕様は 1 ページに収まり、文法は再帰下降で素直に書けます。字句解析と構文解析という、パーサの基本構造を 2 章で体験できます。

そして実利もあります。**エラーメッセージを自分の都合に合わせられる**こと。glTF ファイルが壊れているとき、「JSON parse error」だけ言われても困ります。「37 行目 12 列で、キーの後に ':' が必要」と教えてくれるパーサを、自分で作ります。

---

## 30.2　字句解析と構文解析を分ける

パーサは 2 段階に分けるのが定石です。

**字句解析（lexical analysis）** ―― 文字の列を**トークン**の列にする。`{`, `"name"`, `:`, `1.5`, `,` …。この段階では文法を知りません。「`"abc"` は文字列トークン」と判定するだけです。

**構文解析（parsing）** ―― トークンの列を**構造**にする。「`{` の後にはキーか `}` が来る」といった文法規則を扱います。

分ける利点は、**それぞれが単純になる**ことです。エスケープシーケンスの処理と、オブジェクトの入れ子の処理を同じ関数に書くと、すぐ手に負えなくなります。

この章が字句解析、次章が構文解析です。

---

## 30.3　トークンの種類

JSON に現れるトークンは、これで全部です。

```cpp
// AnimLib/include/anim/JsonLexer.h
#pragma once

#include <string>
#include <string_view>

namespace anim {

enum class TokenType {
    End,            // 入力の終わり
    ObjectBegin,    // {
    ObjectEnd,      // }
    ArrayBegin,     // [
    ArrayEnd,       // ]
    Colon,          // :
    Comma,          // ,
    String,         // "..."
    Number,         // 123, -4.5e6
    True, False, Null,
    Error
};

struct Token {
    TokenType type = TokenType::End;

    std::string_view text;      // 元の文字列（数値の桁を見たいときなど）
    double number = 0.0;        // Number のとき
    std::string decoded;        // String のとき、エスケープを解いた中身

    std::size_t offset = 0;     // 入力先頭からのバイト位置
    int line = 1;
    int column = 1;
};

}  // namespace anim
```

**`text`（`string_view`）と `decoded`（`std::string`）を両方持っている**のが目を引くかもしれません。

`string_view` は入力を指すだけなのでコピーが発生せず、高速です。しかし**エスケープを含む文字列はそのまま使えません**。`"a\nb"` の中身は 4 文字ではなく 3 文字（`a`, 改行, `b`）で、元のテキストのどこにも連続して存在しません。

だから、エスケープを解いた結果は新しい文字列に組み立てます。エスケープを含まない文字列でも `std::string` を作るのは無駄ですが、**まず正しく動くものを作る**（第 20 章の方針）。最適化は必要になってからです。

## 30.4　字句解析器の骨格

```cpp
class JsonLexer {
public:
    explicit JsonLexer(std::string_view source) : source_(source) {}

    // 次のトークンを 1 つ返す。入力の終わりでは End を返し続ける。
    [[nodiscard]] Token Next();

    [[nodiscard]] const std::string& ErrorMessage() const noexcept { return error_; }

private:
    void SkipWhitespace();
    Token MakeError(std::string message);
    Token LexString();
    Token LexNumber();
    Token LexLiteral(std::string_view word, TokenType type);
    [[nodiscard]] int Column() const {
        return static_cast<int>(position_ - lineStart_) + 1;
    }

    std::string_view source_;
    std::size_t position_ = 0;
    std::size_t lineStart_ = 0;   // 現在行の先頭位置。列番号の計算に使う
    int line_ = 1;
    std::string error_;
};
```

`lineStart_` を持っているのが工夫です。**列番号を「現在位置 − 行頭位置」で計算できる**ので、改行を数え直す必要がありません。

```cpp
void JsonLexer::SkipWhitespace() {
    while (position_ < source_.size()) {
        const char c = source_[position_];
        if (c == '\n') {
            ++line_;
            ++position_;
            lineStart_ = position_;      // ← 行頭を更新
        } else if (c == ' ' || c == '\t' || c == '\r') {
            ++position_;
        } else {
            break;
        }
    }
}
```

JSON が空白として認めるのは、この 4 種類だけです。全角スペースやタブ以外の制御文字は**エラー**にします。緩く受け付けると、壊れたファイルを「読めた」ことにしてしまいます。

```cpp
Token JsonLexer::Next() {
    SkipWhitespace();

    if (position_ >= source_.size()) {
        Token t;
        t.type = TokenType::End;
        t.offset = position_;
        t.line = line_;
        t.column = Column();
        return t;
    }

    const char c = source_[position_];
    Token t;
    t.offset = position_;
    t.line = line_;
    t.column = Column();

    switch (c) {
    case '{': t.type = TokenType::ObjectBegin; ++position_; return t;
    case '}': t.type = TokenType::ObjectEnd;   ++position_; return t;
    case '[': t.type = TokenType::ArrayBegin;  ++position_; return t;
    case ']': t.type = TokenType::ArrayEnd;    ++position_; return t;
    case ':': t.type = TokenType::Colon;       ++position_; return t;
    case ',': t.type = TokenType::Comma;       ++position_; return t;
    case '"': return LexString();
    case 't': return LexLiteral("true",  TokenType::True);
    case 'f': return LexLiteral("false", TokenType::False);
    case 'n': return LexLiteral("null",  TokenType::Null);
    default:
        if (c == '-' || (c >= '0' && c <= '9')) {
            return LexNumber();
        }
        return MakeError("予期しない文字");
    }
}
```

**1 文字目で分岐が決まる**のが JSON の良いところです。先読みが要りません。

## 30.5　文字列とエスケープ

いちばん長い関数になります。

```cpp
Token JsonLexer::LexString() {
    Token t;
    t.type = TokenType::String;
    t.offset = position_;
    t.line = line_;
    t.column = Column();

    ++position_;   // 開きクォート
    std::string out;

    while (true) {
        if (position_ >= source_.size()) {
            return MakeError("文字列が閉じていない");
        }
        const char c = source_[position_];

        if (c == '"') {
            ++position_;
            break;
        }
        if (c == '\\') {
            ++position_;
            if (position_ >= source_.size()) {
                return MakeError("エスケープが不完全");
            }
            switch (source_[position_]) {
            case '"':  out += '"';  break;
            case '\\': out += '\\'; break;
            case '/':  out += '/';  break;
            case 'b':  out += '\b'; break;
            case 'f':  out += '\f'; break;
            case 'n':  out += '\n'; break;
            case 'r':  out += '\r'; break;
            case 't':  out += '\t'; break;
            case 'u': {
                if (position_ + 4 >= source_.size()) {
                    return MakeError("\\u が不完全");
                }
                unsigned code = 0;
                for (int k = 1; k <= 4; ++k) {
                    const char h = source_[position_ + k];
                    code <<= 4;
                    if (h >= '0' && h <= '9')      { code |= static_cast<unsigned>(h - '0'); }
                    else if (h >= 'a' && h <= 'f') { code |= static_cast<unsigned>(h - 'a' + 10); }
                    else if (h >= 'A' && h <= 'F') { code |= static_cast<unsigned>(h - 'A' + 10); }
                    else { return MakeError("\\u に不正な 16 進数"); }
                }
                position_ += 4;
                AppendUtf8(out, code);
                break;
            }
            default:
                return MakeError("未知のエスケープシーケンス");
            }
            ++position_;
        } else if (static_cast<unsigned char>(c) < 0x20) {
            // 生の制御文字は JSON では不正
            return MakeError("文字列中に制御文字");
        } else {
            out += c;
            ++position_;
        }
    }

    t.decoded = std::move(out);
    return t;
}
```

### `\u` と UTF-8

`A` は文字 `A`（コードポイント 0x41）を表します。C++ の `std::string` は UTF-8 のバイト列として扱うのが自然なので、コードポイントを UTF-8 に符号化します。

```cpp
// コードポイントを UTF-8 バイト列として追加する。
// サロゲートペア（😀 のような 2 個組）は本書では扱わない。
inline void AppendUtf8(std::string& out, unsigned codePoint) {
    if (codePoint < 0x80) {
        out += static_cast<char>(codePoint);
    } else if (codePoint < 0x800) {
        out += static_cast<char>(0xC0 | (codePoint >> 6));
        out += static_cast<char>(0x80 | (codePoint & 0x3F));
    } else {
        out += static_cast<char>(0xE0 | (codePoint >> 12));
        out += static_cast<char>(0x80 | ((codePoint >> 6) & 0x3F));
        out += static_cast<char>(0x80 | (codePoint & 0x3F));
    }
}
```

**サロゲートペアを扱わない**と決めました。絵文字などの U+10000 以上の文字は、`😀` のように 2 つの `\u` で表現されます。これを正しく扱うには、前の `\u` の値を覚えておいて組み立てる必要があります。

glTF のボーン名やアニメーション名に絵文字が入ることは、まずありません。**扱わないと決めて、そう書いておく**ほうが、中途半端に実装して静かに壊れるより誠実です。必要になったら、この関数だけ直せば済みます。

### 制御文字を弾く

`if (static_cast<unsigned char>(c) < 0x20)` の行を忘れがちです。JSON の仕様では、生の制御文字（改行、タブなど）を文字列の中に直接書くことは許されていません。`\n` とエスケープする必要があります。

これを弾かないと、**文字列の中で改行された壊れたファイル**が「読めて」しまい、しかも行番号のカウントが狂います。

## 30.6　数値

```cpp
Token JsonLexer::LexNumber() {
    Token t;
    t.type = TokenType::Number;
    t.offset = position_;
    t.line = line_;
    t.column = Column();

    const std::size_t start = position_;

    if (position_ < source_.size() && source_[position_] == '-') { ++position_; }
    while (position_ < source_.size() && IsDigit(source_[position_])) { ++position_; }

    if (position_ < source_.size() && source_[position_] == '.') {
        ++position_;
        while (position_ < source_.size() && IsDigit(source_[position_])) { ++position_; }
    }
    if (position_ < source_.size()
        && (source_[position_] == 'e' || source_[position_] == 'E')) {
        ++position_;
        if (position_ < source_.size()
            && (source_[position_] == '+' || source_[position_] == '-')) { ++position_; }
        while (position_ < source_.size() && IsDigit(source_[position_])) { ++position_; }
    }

    t.text = source_.substr(start, position_ - start);
    if (t.text.empty()) {
        return MakeError("数値が空");
    }

    const auto result = std::from_chars(t.text.data(),
                                        t.text.data() + t.text.size(),
                                        t.number);
    if (result.ec != std::errc{}) {
        return MakeError("数値を解釈できない");
    }
    return t;
}
```

**`std::from_chars` を使います。** `std::stod` や `atof` ではありません。理由が 3 つあります。

**① ロケールに依存しない。** `std::stod` は現在のロケールを見るので、小数点が `,` の環境（ドイツ語圏など）では `1.5` を `1` と解釈します。**これは実際に起こる事故で、しかも「そのロケールの環境でだけモデルが壊れる」という最悪の再現性を持ちます。**

**② 例外を投げない。** エラーは戻り値で返ります。

**③ 速い。** ロケール処理も文字列のコピーもありません。

数値を `double` で保持する点にも触れておきます。JSON の数値には型の区別がなく、`5` も `5.0` も同じです。glTF の配列添字（整数）も、座標値（浮動小数点）も、同じ `Number` トークンになります。`double` なら 2^53 までの整数を正確に表せるので、添字として使うぶんには問題ありません。

## 30.7　リテラル

```cpp
Token JsonLexer::LexLiteral(std::string_view word, TokenType type) {
    if (source_.substr(position_, word.size()) != word) {
        return MakeError("不正なリテラル");
    }
    Token t;
    t.type = type;
    t.offset = position_;
    t.line = line_;
    t.column = Column();
    position_ += word.size();
    return t;
}
```

`substr` が範囲を超えても安全（短い文字列が返るだけ）なので、境界の検査は不要です。`tru` という入力は `"tru" != "true"` で弾かれます。

## 30.8　エラーの位置

```cpp
Token JsonLexer::MakeError(std::string message) {
    error_ = std::move(message);
    Token t;
    t.type = TokenType::Error;
    t.offset = position_;
    t.line = line_;
    t.column = Column();
    return t;
}
```

**メッセージと位置を分けて持つ**設計にしています。メッセージは字句解析器が、位置はトークンが持つ。次章の構文解析器も同じ形でエラーを作るので、両者を統一して扱えます。

実際に壊れた JSON を食わせると、こうなります。

```
入力:
{
  "a": 1,
  "b": @
}

出力:
  error: 予期しない文字 (line 3, col 8)
```

**3 行 8 列**。`@` の位置を正確に指しています。glTF ファイルは数千行になることもあるので、この情報の有無が調査時間を大きく変えます。

## 30.9　テストを書く

`AnimLib.Tests/JsonLexerTests.cpp`：

```cpp
#include "CppUnitTest.h"

#include "TestSupport/Tolerance.h"

#include "anim/JsonLexer.h"

#include <vector>

using namespace Microsoft::VisualStudio::CppUnitTestFramework;
using namespace anim;

namespace {

// 入力を全部トークンにして返す
std::vector<Token> Tokenize(std::string_view src) {
    JsonLexer lexer(src);
    std::vector<Token> out;
    for (;;) {
        Token t = lexer.Next();
        out.push_back(t);
        if (t.type == TokenType::End || t.type == TokenType::Error) { break; }
    }
    return out;
}

}  // namespace

namespace AnimLibTests {

TEST_CLASS(JsonLexerTests) {
public:

    // --- 記号 -----------------------------------------------------

    TEST_METHOD(StructuralCharacters) {
        const auto t = Tokenize("{}[],:");
        Assert::IsTrue(t[0].type == TokenType::ObjectBegin);
        Assert::IsTrue(t[1].type == TokenType::ObjectEnd);
        Assert::IsTrue(t[2].type == TokenType::ArrayBegin);
        Assert::IsTrue(t[3].type == TokenType::ArrayEnd);
        Assert::IsTrue(t[4].type == TokenType::Comma);
        Assert::IsTrue(t[5].type == TokenType::Colon);
        Assert::IsTrue(t[6].type == TokenType::End);
    }

    TEST_METHOD(WhitespaceIsSkipped) {
        const auto t = Tokenize("  \t\r\n  {  \n }  ");
        Assert::IsTrue(t[0].type == TokenType::ObjectBegin);
        Assert::IsTrue(t[1].type == TokenType::ObjectEnd);
        Assert::IsTrue(t[2].type == TokenType::End);
    }

    // --- リテラル -------------------------------------------------

    TEST_METHOD(Literals) {
        const auto t = Tokenize("true false null");
        Assert::IsTrue(t[0].type == TokenType::True);
        Assert::IsTrue(t[1].type == TokenType::False);
        Assert::IsTrue(t[2].type == TokenType::Null);
    }

    TEST_METHOD(TruncatedLiteralIsAnError) {
        for (const char* bad : {"tru", "fals", "nul", "trX"}) {
            Assert::IsTrue(Tokenize(bad).back().type == TokenType::Error);
        }
    }

    // --- 数値 -----------------------------------------------------

    TEST_METHOD(NumberForms) {
        const auto t = Tokenize("0 -1 1.5 -0.25 1e3 1E+3 -1.5e-3 12345678901234");
        anim::test::AssertNear(0.0f,     static_cast<float>(t[0].number));
        anim::test::AssertNear(-1.0f,    static_cast<float>(t[1].number));
        anim::test::AssertNear(1.5f,     static_cast<float>(t[2].number));
        anim::test::AssertNear(-0.25f,   static_cast<float>(t[3].number));
        anim::test::AssertNear(1000.0f,  static_cast<float>(t[4].number));
        anim::test::AssertNear(1000.0f,  static_cast<float>(t[5].number));
        anim::test::AssertNear(-0.0015f, static_cast<float>(t[6].number), 1.0e-6f);
        // double なら 2^53 までの整数は正確
        Assert::IsTrue(t[7].number == 12345678901234.0);
    }

    // 小数点がカンマのロケールでも壊れないこと（30.6 節）
    TEST_METHOD(NumberParsingIsLocaleIndependent) {
        const char* previous = std::setlocale(LC_NUMERIC, "de_DE");
        const auto t = Tokenize("1.5");
        anim::test::AssertNear(1.5f, static_cast<float>(t[0].number));
        std::setlocale(LC_NUMERIC, previous ? previous : "C");
    }

    // --- 文字列 ---------------------------------------------------

    TEST_METHOD(PlainString) {
        const auto t = Tokenize(R"("hello")");
        Assert::IsTrue(t[0].type == TokenType::String);
        Assert::AreEqual(std::string("hello"), t[0].decoded);
    }

    TEST_METHOD(EscapeSequences) {
        const auto t = Tokenize(R"("a\"b\\c\/d\be\ff\ng\rh\ti")");
        Assert::AreEqual(std::string("a\"b\\c/d\be\ff\ng\rh\ti"), t[0].decoded);
    }

    TEST_METHOD(UnicodeEscapes) {
        // ASCII、2 バイト、3 バイトの各領域
        Assert::AreEqual(std::string("A"),      Tokenize(R"("A")")[0].decoded);
        Assert::AreEqual(std::string("\xC3\xA9"), Tokenize(R"("é")")[0].decoded);  // é
        Assert::AreEqual(std::string("\xE6\x97\xA5"), Tokenize(R"("日")")[0].decoded);  // 日
    }

    TEST_METHOD(EmptyString) {
        const auto t = Tokenize(R"("")");
        Assert::IsTrue(t[0].type == TokenType::String);
        Assert::IsTrue(t[0].decoded.empty());
    }

    TEST_METHOD(MalformedStrings) {
        for (const char* bad : {
                R"("unterminated)",
                R"("bad escape \q")",
                R"("incomplete \u12")",
                R"("bad hex \uZZZZ")",
                "\"raw newline\n\""}) {
            Assert::IsTrue(Tokenize(bad).back().type == TokenType::Error);
        }
    }

    // --- 位置情報 -------------------------------------------------

    TEST_METHOD(LineAndColumnAreTracked) {
        const auto t = Tokenize("{\n  \"a\"\n}");
        Assert::AreEqual(1, t[0].line);
        Assert::AreEqual(1, t[0].column);
        Assert::AreEqual(2, t[1].line);
        Assert::AreEqual(3, t[1].column);      // 2 スペースの後
        Assert::AreEqual(3, t[2].line);
        Assert::AreEqual(1, t[2].column);
    }

    TEST_METHOD(ErrorReportsItsPosition) {
        JsonLexer lexer("{\n  \"a\": 1,\n  \"b\": @\n}");
        Token t;
        do { t = lexer.Next(); } while (t.type != TokenType::Error
                                     && t.type != TokenType::End);
        Assert::IsTrue(t.type == TokenType::Error);
        Assert::AreEqual(3, t.line);
        Assert::AreEqual(8, t.column);
    }

    // --- 実データ -------------------------------------------------

    // 生成した glTF が字句解析だけは通ること
    TEST_METHOD(RealGltfTokenizesWithoutError) {
        const std::string src = anim::test::ReadTextFile(
            anim::test::TestDataDir() / "cylinder.gltf");
        Assert::IsFalse(src.empty());

        JsonLexer lexer(src);
        int count = 0;
        for (;;) {
            const Token t = lexer.Next();
            Assert::IsFalse(t.type == TokenType::Error);
            if (t.type == TokenType::End) { break; }
            ++count;
        }
        Assert::IsTrue(count > 500);
    }
};

}  // namespace AnimLibTests
```

`NumberParsingIsLocaleIndependent` は、30.6 節で述べた事故を狙い撃ちするテストです。**ロケールを一時的に変更して、それでも正しく解釈できることを確かめます。** `std::stod` を使う実装に戻したら、このテストが落ちます。

（環境によっては `de_DE` ロケールが利用できず `setlocale` が `nullptr` を返します。その場合このテストは無意味になりますが、失敗はしません。ロケールが使える環境で 1 度でも通れば、実装が正しいことは確認できます。）

`MalformedStrings` に**生の改行**を含めているのも意図的です。文字列の中で改行された JSON は、テキストエディタで手編集したときに実際に生まれます。

## 30.10　つまずきやすいところ

**ドイツ語環境でだけモデルが読めない**
`std::stod` や `atof` を使っています。`std::from_chars` にしてください（30.6 節）。**最も再現しにくい種類のバグ**なので、最初から避けるべきです。

**エスケープを含む文字列が壊れる**
`string_view` をそのまま使っていませんか。`decoded` を見てください。

**行番号がずれる**
文字列の中の改行を数えていない、あるいは制御文字を弾いていません。JSON では文字列中の生の改行は不正なので、弾くのが正解です。

**列番号が常に 1**
`lineStart_` の更新を忘れています。`\n` を読んだ直後に `lineStart_ = position_` を設定してください。

**日本語のボーン名が化ける**
`\u` の UTF-8 符号化を確認してください。ただし多くの glTF エクスポータは日本語をエスケープせず生の UTF-8 で出力するので、その場合は `\u` の処理を通りません（バイトをそのままコピーするパスになります）。**両方のパスをテストしてください。**

**絵文字が壊れる**
サロゲートペアを扱っていないためです（30.5 節）。仕様どおりの制限です。

## この章のまとめ

- パーサは**字句解析と構文解析に分ける**。エスケープの処理と入れ子の処理を同じ関数に書くと手に負えなくなる。
- JSON は**1 文字目で分岐が決まる**ので、先読みが不要。
- 文字列は `string_view` では足りない ―― **エスケープを解いた結果は元のテキストに存在しない**ので、新しい文字列に組み立てる。
- **`std::from_chars` を使う。** `std::stod` はロケール依存で、小数点が `,` の環境で `1.5` を `1` と読む。「その環境でだけモデルが壊れる」という最悪の再現性を持つ事故。
- **生の制御文字を弾く。** 弾かないと、壊れたファイルが「読めて」しまい、行番号も狂う。
- **サロゲートペアは扱わないと決めて、そう書く。** 中途半端に実装して静かに壊れるより誠実。
- `lineStart_` を持てば、列番号は**引き算 1 回**で求まる。
- エラーは「メッセージ（字句解析器）＋位置（トークン）」に分けて持つ。次章の構文解析器と統一して扱える。

次章、このトークン列を構造に組み立てます。
