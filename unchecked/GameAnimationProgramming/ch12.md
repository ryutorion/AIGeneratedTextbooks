# 第 12 章　デュアルクォータニオン

**この章で作るもの**：`DualQuat`。剛体変換（回転 + 平行移動）を 8 個の float で表し、**ブレンドしても剛体性が保たれる**という性質を持つ道具です。出番は第 22 章のデュアルクォータニオンスキニングですが、数学としてここで完成させておきます。

---

## 12.1　なぜ今、これを作るのか

第 18 章で作るリニアブレンドスキニング（LBS）には、有名な弱点があります。関節を大きくねじると、そこが**キャンディの包み紙のように潰れる**のです。第 21 章でこの現象を数値として測り、第 22 章でデュアルクォータニオンスキニング（DQS）によって解決します。

なぜ LBS が潰れるのかを、先に一言で言っておきます。**行列を重み付き平均したものは、もはや剛体変換ではないから**です。2 つの回転行列を 50:50 で混ぜると、その結果は「両者の中間の回転」ではなく「縮んだ何か」になります。第 10 章で「2 つのクォータニオンを成分ごとに平均すると長さが 1 でなくなる」と述べたのと、まったく同じ話です。

クォータニオンは、正規化することでこの問題を解決しました。**デュアルクォータニオンは、それを平行移動込みで行える**ようにしたものです。

先に結論の数字を見ておきましょう。単位変換と「Z 軸まわり 90 度回転 + X 方向に 1 移動」を 50:50 で混ぜ、点 `(1, 0, 0)` に適用した結果です。

| 手法 | 結果 | 原点からの距離 |
| --- | --- | --- |
| LBS（行列を平均） | `(1.000, 0.500, 0.000)` | 1.118 |
| DQS（デュアルクォータニオンを平均） | `(1.207, 0.500, 0.000)` | **1.307** |

LBS のほうが原点に近い ―― これが「潰れ」です。DQS は、2 つの剛体変換の中間として自然な、より外側の位置に点を置きます。

---

## 12.2　二重数

デュアルクォータニオンを理解する近道は、**二重数（dual number）**から入ることです。

複素数が `i² = -1` という数 `i` を導入したように、二重数は

```
ε² = 0    （ただし ε ≠ 0）
```

という数 `ε` を導入します。二重数は `a + bε` の形をしていて、掛け算は

```
(a + bε)(c + dε) = ac + (ad + bc)ε + bd·ε² = ac + (ad + bc)ε
```

`ε²` の項が消えるのがポイントです。

この「消える無限小」が、**平行移動を回転と同じ枠組みで扱う**ための仕掛けになります。回転は掛け算で合成されますが、平行移動は足し算です。この 2 つを 1 つの積にまとめるために `ε` を使います。

---

## 12.3　定義する

デュアルクォータニオンは、2 つのクォータニオンの組です。

```
d = q_real + q_dual · ε
```

回転 `q` と平行移動 `t` からなる剛体変換は、次のように埋め込みます。

```
q_real = q
q_dual = ½ · (t.x, t.y, t.z, 0) · q       （クォータニオンの積）
```

`½` と、平行移動を「純クォータニオン」（`w = 0`）として扱う点が要点です。第 8 章の `θ/2` と同じく、あとで 2 回使うぶんを先に半分にしています。

`AnimLib/include/anim/DualQuat.h`：

```cpp
#pragma once

#include "anim/Quat.h"
#include "anim/Transform.h"
#include "anim/Vec3.h"

namespace anim {

// 剛体変換（回転 + 平行移動）を 8 個の float で表す。
// スケールは表現できない（12.6 節）。
struct DualQuat {
    Quat real;   // 回転
    Quat dual;   // 平行移動を回転と絡めて埋め込んだもの
};

[[nodiscard]] constexpr DualQuat DualQuatIdentity() {
    return {{0, 0, 0, 1}, {0, 0, 0, 0}};
}

[[nodiscard]] inline DualQuat MakeDualQuat(const Quat& rotation, Vec3 translation) {
    const Quat t{translation.x, translation.y, translation.z, 0.0f};
    return {rotation, (t * rotation) * 0.5f};
}

[[nodiscard]] inline DualQuat MakeDualQuat(const Transform& tr) {
    ANIM_ASSERT(!HasNonUniformScale(tr));   // スケールは失われる
    return MakeDualQuat(tr.rotation, tr.translation);
}

}  // namespace anim
```

`dual` の単位元は**ゼロクォータニオン**です。`real` は `(0,0,0,1)`、`dual` は `(0,0,0,0)`。ここだけは `Quat{}` が正しい値になります。

## 12.4　積と成分ごとの演算

二重数の掛け算の規則をそのまま当てはめます。

```cpp
// a * b は「b を適用してから a を適用する」（第 6・8・11 章と同じ順序）。
[[nodiscard]] inline DualQuat operator*(const DualQuat& a, const DualQuat& b) {
    return { a.real * b.real,
             a.real * b.dual + a.dual * b.real };
}

// ブレンドのための成分ごとの演算。単体では剛体変換を表さない。
[[nodiscard]] constexpr DualQuat operator*(const DualQuat& a, float s) {
    return {a.real * s, a.dual * s};
}
[[nodiscard]] constexpr DualQuat operator+(const DualQuat& a, const DualQuat& b) {
    return {a.real + b.real, a.dual + b.dual};
}
[[nodiscard]] constexpr DualQuat operator-(const DualQuat& a) {
    return {-a.real, -a.dual};
}
[[nodiscard]] constexpr float Dot(const DualQuat& a, const DualQuat& b) {
    return Dot(a.real, b.real);   // 実部だけで見る（符号合わせ用）
}
```

積が 2 行で書けるのは、`ε² = 0` によって `a.dual * b.dual` の項が消えるからです。二重数を導入した甲斐がここにあります。

`Dot` を**実部だけ**で定義しているのは、用途が「符号合わせ」だからです。デュアルクォータニオンにも第 8 章と同じ二重被覆があり（`d` と `-d` は同じ変換）、ブレンドの前に符号を揃える必要があります。その判定に必要なのは実部の内積だけです。

## 12.5　点を変換する、平行移動を取り出す

定義どおりなら `d · (1 + pε) · d*`（`d*` は共役）ですが、展開した形を使います。

```cpp
// 平行移動を取り出す：t = 2 · dual · conj(real)
[[nodiscard]] inline Vec3 GetTranslation(const DualQuat& d) {
    const Quat t = (d.dual * 2.0f) * Conjugate(d.real);
    return {t.x, t.y, t.z};
}

[[nodiscard]] inline Transform ToTransform(const DualQuat& d) {
    return {GetTranslation(d), d.real, {1.0f, 1.0f, 1.0f}};
}

// 点を変換する。
// 回転部分は第 8 章の Rotate と同じ形、平行移動部分が dual から出る。
[[nodiscard]] inline Vec3 TransformPoint(const DualQuat& d, Vec3 p) {
    const Vec3 r{d.real.x, d.real.y, d.real.z};
    const Vec3 u{d.dual.x, d.dual.y, d.dual.z};

    const Vec3 rotated = p + 2.0f * Cross(r, Cross(r, p) + d.real.w * p);
    const Vec3 shifted = 2.0f * (d.real.w * u - d.dual.w * r + Cross(r, u));
    return rotated + shifted;
}
```

`rotated` の行は、第 8 章の `Rotate` を展開した形です。`shifted` の行が平行移動に相当します。

**なぜ `GetTranslation` してから足すのではなく、この形で書くのか。** 2 つの理由があります。第 22 章のスキニングでは、これを頂点ごとに実行します。クォータニオンの積（16 乗算）を経由するより、外積 3 回のこの形のほうが軽く済みます。もう一つは、この形なら `GetTranslation` と独立にテストでき、両者が一致することを検査できるからです。

## 12.6　正規化 ―― ブレンドの後始末

ここがデュアルクォータニオンの本題です。

第 22 章では、複数のボーンのデュアルクォータニオンを**重み付きで足します**。その結果はもはや剛体変換ではありません。2 つの条件が崩れているからです。

**条件 ①：`|real| = 1`。** 実部は回転を表すクォータニオンなので、長さが 1 でなければなりません。

**条件 ②：`real · dual = 0`。** 実部と双対部が直交していること。これが「デュアルクォータニオンが剛体変換を表す」ための条件です（幾何学的には、スケールもせん断も含まないことに対応します）。

両方を回復するのが正規化です。

```cpp
[[nodiscard]] inline DualQuat Normalize(const DualQuat& d) {
    const float lengthSquared = LengthSquared(d.real);
    ANIM_ASSERT(lengthSquared > kTinyLengthSquared);

    const float inverseLength = 1.0f / std::sqrt(lengthSquared);
    const Quat real = d.real * inverseLength;
    Quat dual = d.dual * inverseLength;

    // 直交化：dual から real 方向の成分を取り除く。
    // グラム・シュミットの 1 ステップそのもの。
    dual = dual - real * Dot(real, dual);

    return {real, dual};
}

// ブレンドの前に符号を揃える。d と -d は同じ変換だが、
// 揃えずに足すと打ち消し合ってしまう。
[[nodiscard]] constexpr DualQuat AlignSign(const DualQuat& d, const DualQuat& reference) {
    return (Dot(d, reference) < 0.0f) ? -d : d;
}
```

**`AlignSign` を忘れると、DQS は静かに壊れます。** 2 つのボーンのデュアルクォータニオンが逆の半球にあると、足し算で打ち消し合い、実部の長さがほぼ 0 になります。その後の正規化で値が爆発し、頂点が飛びます。第 10 章の「たまに一回転する」と同種の、データ依存で発現するバグです。

### スケールを表せないこと

条件 ② が示すとおり、デュアルクォータニオンは**スケールを表現できません**。これは実装上の制約ではなく、定義そのものからくる性質です。

第 22 章で DQS を導入するとき、この制約は具体的な問題になります。ボーンにスケールが入っているモデルでは、DQS だけでは足りません。実務での対処は「スケールは LBS で、回転と平行移動は DQS で」という併用です。本書もその形にします。

`MakeDualQuat(const Transform&)` に `ANIM_ASSERT(!HasNonUniformScale(tr))` を置いたのは、この制約を早期に知らせるためです。第 11 章で `HasNonUniformScale` を作っておいたのが、ここで役に立ちます。

## 12.7　テストを書く

`AnimLib.Tests/DualQuatTests.cpp`：

```cpp
#include "CppUnitTest.h"

#include "TestSupport/MathAssert.h"
#include "TestSupport/TestRandom.h"
#include "TestSupport/Tolerance.h"

#include "anim/DualQuat.h"

#include <format>
#include <numbers>

using namespace Microsoft::VisualStudio::CppUnitTestFramework;
using namespace anim;
using anim::test::AssertNear;

namespace {

constexpr float kPi = std::numbers::pi_v<float>;

// スケールなしのランダムな剛体変換
Transform RandomRigid(anim::test::TestRandom& rng) {
    return {rng.NextVec3(5.0f), rng.NextQuat(), {1.0f, 1.0f, 1.0f}};
}

}  // namespace

namespace AnimLibTests {

TEST_CLASS(DualQuatTests) {
public:

    TEST_METHOD(IdentityDoesNothing) {
        test::TestRandom rng;
        for (int i = 0; i < 200; ++i) {
            const Vec3 p = rng.NextVec3();
            AssertNear(p, TransformPoint(DualQuatIdentity(), p));
        }
    }

    // --- Transform との一致（独立した 2 実装の突き合わせ）---------

    TEST_METHOD(TransformPointMatchesTransform) {
        test::TestRandom rng;
        for (int i = 0; i < 2000; ++i) {
            const Transform tr = RandomRigid(rng);
            const DualQuat d = MakeDualQuat(tr);
            const Vec3 p = rng.NextVec3();
            AssertNear(TransformPoint(tr, p), TransformPoint(d, p), test::kEpsAccum);
        }
    }

    TEST_METHOD(TranslationCanBeRecovered) {
        test::TestRandom rng;
        for (int i = 0; i < 2000; ++i) {
            const Transform tr = RandomRigid(rng);
            AssertNear(tr.translation, GetTranslation(MakeDualQuat(tr)),
                       test::kEpsAccum);
        }
    }

    TEST_METHOD(RoundTripThroughTransform) {
        test::TestRandom rng;
        for (int i = 0; i < 1000; ++i) {
            const Transform tr = RandomRigid(rng);
            const Transform back = ToTransform(MakeDualQuat(tr));
            AssertNear(tr.translation, back.translation, test::kEpsAccum);
            anim::test::AssertSameRotation(tr.rotation, back.rotation, test::kEpsAccum);
        }
    }

    // --- 剛体性の条件 ---------------------------------------------

    TEST_METHOD(ConstructedDualQuatSatisfiesRigidityConditions) {
        test::TestRandom rng;
        for (int i = 0; i < 2000; ++i) {
            const DualQuat d = MakeDualQuat(RandomRigid(rng));
            anim::test::AssertNear(1.0f, Length(d.real), test::kEpsUnit);
            anim::test::AssertNear(0.0f, Dot(d.real, d.dual), test::kEpsDir);
        }
    }

    // --- 合成 -----------------------------------------------------

    TEST_METHOD(ProductMatchesCombine) {
        test::TestRandom rng;
        for (int i = 0; i < 1000; ++i) {
            const Transform parent = RandomRigid(rng);
            const Transform child  = RandomRigid(rng);
            const Vec3 p = rng.NextVec3();
            AssertNear(TransformPoint(Combine(parent, child), p),
                       TransformPoint(MakeDualQuat(parent) * MakeDualQuat(child), p),
                       1.0e-2f, 1.0e-4f);
        }
    }

    TEST_METHOD(ProductIsAssociative) {
        test::TestRandom rng;
        for (int i = 0; i < 500; ++i) {
            const DualQuat a = MakeDualQuat(RandomRigid(rng));
            const DualQuat b = MakeDualQuat(RandomRigid(rng));
            const DualQuat c = MakeDualQuat(RandomRigid(rng));
            const Vec3 p = rng.NextVec3();
            AssertNear(TransformPoint((a * b) * c, p),
                       TransformPoint(a * (b * c), p),
                       1.0e-2f, 1.0e-4f);
        }
    }

    // --- 正規化 ---------------------------------------------------

    TEST_METHOD(NormalizeRestoresRigidity) {
        test::TestRandom rng;
        for (int i = 0; i < 1000; ++i) {
            // 重み付き和は剛体変換ではない
            const DualQuat a = MakeDualQuat(RandomRigid(rng));
            const DualQuat b = AlignSign(MakeDualQuat(RandomRigid(rng)), a);
            const float w = rng.NextUnit();
            const DualQuat blended = a * (1.0f - w) + b * w;

            const DualQuat n = Normalize(blended);
            anim::test::AssertNear(1.0f, Length(n.real), test::kEpsUnit);
            anim::test::AssertNear(0.0f, Dot(n.real, n.dual), test::kEpsDir);
        }
    }

    // 既に剛体なら、正規化しても変わらない
    TEST_METHOD(NormalizeIsIdempotentOnRigidInput) {
        test::TestRandom rng;
        for (int i = 0; i < 500; ++i) {
            const DualQuat d = MakeDualQuat(RandomRigid(rng));
            const Vec3 p = rng.NextVec3();
            AssertNear(TransformPoint(d, p), TransformPoint(Normalize(d), p),
                       test::kEpsAccum);
        }
    }

    TEST_METHOD(AlignSignPreservesTheTransform) {
        test::TestRandom rng;
        for (int i = 0; i < 500; ++i) {
            const DualQuat d = MakeDualQuat(RandomRigid(rng));
            const Vec3 p = rng.NextVec3();
            // -d は同じ変換
            AssertNear(TransformPoint(d, p), TransformPoint(-d, p), test::kEpsAccum);
            // 符号を揃えても変換は変わらない
            AssertNear(TransformPoint(d, p),
                       TransformPoint(AlignSign(-d, d), p), test::kEpsAccum);
        }
    }

    // --- 第 22 章への布石 -----------------------------------------

    // ブレンドで潰れないこと。LBS との差を数値で記録する。
    TEST_METHOD(BlendPreservesRigidityBetterThanMatrixAverage) {
        const Transform ta{{0, 0, 0}, QuatIdentity(), {1, 1, 1}};
        const Transform tb{{1, 0, 0},
                           MakeQuatAxisAngle({0, 0, 1}, kPi * 0.5f),
                           {1, 1, 1}};
        const Vec3 v{1, 0, 0};

        // DQS: デュアルクォータニオンを平均して正規化
        const DualQuat da = MakeDualQuat(ta);
        const DualQuat db = AlignSign(MakeDualQuat(tb), da);
        const Vec3 dqs = TransformPoint(Normalize(da * 0.5f + db * 0.5f), v);

        // LBS: 変換後の点を平均（行列を平均するのと同値）
        const Vec3 lbs = TransformPoint(ta, v) * 0.5f + TransformPoint(tb, v) * 0.5f;

        Logger::WriteMessage(std::format(
            L"DQS = ({:.4f}, {:.4f}, {:.4f}) |p| = {:.4f}\n"
            L"LBS = ({:.4f}, {:.4f}, {:.4f}) |p| = {:.4f}\n",
            dqs.x, dqs.y, dqs.z, Length(dqs),
            lbs.x, lbs.y, lbs.z, Length(lbs)).c_str());

        // LBS のほうが原点に寄る = 潰れる
        Assert::IsTrue(Length(lbs) < Length(dqs) - 0.1f);
    }
};

}  // namespace AnimLibTests
```

最後の `BlendPreservesRigidityBetterThanMatrixAverage` が、この章の存在理由をテストとして書き下したものです。実行すると出力ペインに

```
DQS = (1.2071, 0.5000, 0.0000) |p| = 1.3066
LBS = (1.0000, 0.5000, 0.0000) |p| = 1.1180
```

と出ます。第 21 章でこの差を「体積の潰れ」として測り、第 22 章で実際のメッシュに適用します。

`ProductMatchesCombine` のほうは、第 11 章の `CombineMatchesMatrixProduct` と同じ構造です。**`Mat4`、`Transform`、`DualQuat` という 3 つの独立した表現が、すべて同じ合成規則に従っている** ―― これが第 II 部を通じて積み上げてきたものであり、第 III 部以降で表現を切り替えながら作業できる根拠になります。

## 12.8　つまずきやすいところ

**頂点が明後日の方向へ飛ぶ**
`AlignSign` を忘れています。ブレンドの前に必ず符号を揃えてください。実部の長さが極端に小さくなっていないか、デバッガで確認すると分かります。

**平行移動が 2 倍（または半分）になる**
`MakeDualQuat` の `0.5f` か、`GetTranslation` の `2.0f` のどちらかが抜けています。`TranslationCanBeRecovered` が捕まえます。

**`dual` を作るときの積の順序を間違えた**
`(t * rotation)` であって `(rotation * t)` ではありません。逆にすると、平行移動が回転された位置に出ます。`TransformPointMatchesTransform` が検出します。

**スケールが消える**
仕様です。`MakeDualQuat(const Transform&)` はスケールを無視します。`ANIM_ASSERT` は**非一様**スケールしか検出しないので、一様スケール `(2,2,2)` は黙って落とされます。第 22 章では、スケールを別途 LBS で扱う形にします。

**正規化しても `real · dual` が 0 にならない**
直交化の行（`dual = dual - real * Dot(real, dual)`）を忘れていませんか。長さを 1 にするだけでは、条件 ② は回復しません。

**第 22 章まで `DualQuat` を一度も使わない**
そのとおりです。この章のコードは 10 章ぶん出番がありません。それでもここに置いたのは、第 IV 部でスキニングの本題（頂点の変形とその破綻）だけに集中したいからです。**道具は道具の章で作り、応用の章では応用だけをやる。**

## この章のまとめ

- デュアルクォータニオンは、**剛体変換を 8 個の float で表し、ブレンドしても剛体性を回復できる**表現。
- 鍵は `ε² = 0` という**二重数**。これによって、回転（掛け算）と平行移動（足し算）が 1 つの積にまとまる。積が 2 行で書けるのはこの性質のおかげ。
- 剛体変換の条件は 2 つ ―― **`|real| = 1`** と **`real · dual = 0`**。ブレンドで両方が崩れるので、正規化では**長さの回復と直交化の両方**を行う。
- **`AlignSign` を忘れると静かに壊れる。** 逆の半球にあるものを足すと打ち消し合う。データ依存で発現する、目視では見つからない種類のバグ。
- **スケールは表現できない**。定義からくる性質であり、実務では「スケールは LBS、回転と平行移動は DQS」と併用する（第 22 章）。
- LBS との差は既に数値で見えている。50:50 のブレンドで **LBS は 1.118、DQS は 1.307**。この差が第 21 章の「潰れ」の正体。

## 第 II 部を終えて

これで数学の道具が揃いました。`Vec3`、`Mat4`、`Quat`、`Transform`、`DualQuat`。

第 II 部で繰り返し使った検証の型を、あらためて確認しておきます。

**① 具体値との照合。** `Cross(X, Y) = Z`、`Rz(90°) : X → Y`。座標系や規約を固定する。

**② 構造的な性質。** 結合則、`R·Rᵀ = I`、`q·q* = 1`、ラグランジュの恒等式。実装の細部を知らなくても成り立つべきこと。

**③ 独立した実装どうしの一致。** 一般の逆行列 vs 剛体逆行列、`Rotate` vs 行列変換、`Transform` vs `Mat4` vs `DualQuat`。これが第 II 部で最も多く使った形です。

**④ 壊れることの記録。** 非一様スケールの合成、`Nlerp` の非等速性。制約を仕様として残す。

第 III 部からは、この道具を使ってスケルトンを組み立てます。行列とクォータニオンの符号に悩む時間は終わり、ここからは**アニメーションそのもの**の話になります。
