# 第 38 章　ポーズのブレンド

**この章で作るもの**：2 つのポーズを混ぜる `BlendPose` と、N 個のポーズを混ぜる 2 通りの方法。そして **N 個の場合に「混ぜる順序で結果が変わる」問題**を、実測して扱います。

---

## 38.1　第 VII 部が扱うもの

第 1 章のパイプラインの ② です。

```
① クリップをサンプル    ← ✅ 第 V 部
② ブレンド              ← 第 VII 部（ここ）
③ 階層を解く            ← ✅
④ IK で補正             ← 第 VIII 部
⑤ パレットを作る        ← ✅
⑥ 頂点を変形            ← ✅
```

キャラクターは、1 つのアニメーションだけで動いているわけではありません。

- 歩きから走りへ、なめらかに切り替わる（**クロスフェード**、第 39 章）
- 移動速度に応じて、待機・歩き・走りが連続的に混ざる（**ブレンドスペース**、第 42・43 章）
- 走りながら手を振る（**部分ブレンド**、第 41 章）
- 走りながら呼吸で胸が上下する（**加算ブレンド**、第 40 章）

これらすべての土台が、「2 つのポーズを重み `t` で混ぜる」という 1 つの操作です。

## 38.2　2 つのポーズを混ぜる

第 11 章で `Transform` の `Blend` を作ってあります。それをポーズ全体に広げるだけです。

```cpp
// AnimLib/include/anim/PoseBlend.h
#pragma once

#include "anim/Pose.h"

namespace anim {

// 回転の混ぜ方。第 10 章の実測に基づいて選ぶ。
enum class RotationBlend {
    Nlerp,   // 速い。角度差が 45 度以下なら誤差 0.12 度未満
    Slerp    // 角速度が一定。角度差が大きいときはこちら
};

[[nodiscard]] inline Transform BlendTransform(const Transform& a, const Transform& b,
                                              float t, RotationBlend mode) {
    return {
        a.translation * (1.0f - t) + b.translation * t,
        (mode == RotationBlend::Slerp) ? Slerp(a.rotation, b.rotation, t)
                                       : Nlerp(a.rotation, b.rotation, t),
        a.scale * (1.0f - t) + b.scale * t
    };
}

inline void BlendPose(const Pose& a, const Pose& b, float t, Pose& out,
                      RotationBlend mode = RotationBlend::Nlerp) {
    ANIM_ASSERT(a.Size() == b.Size() && a.Size() == out.Size());
    for (std::size_t i = 0; i < a.Size(); ++i) {
        const BoneIndex bone = static_cast<BoneIndex>(i);
        out[bone] = BlendTransform(a[bone], b[bone], t, mode);
    }
}

}  // namespace anim
```

**`out` が `a` や `b` と同じでも動く**ことが重要です。ループの各回で `out[i]` を書く前に `a[i]` と `b[i]` を読み終わっているので、エイリアスしていても壊れません。第 44 章のブレンドツリーでは、この性質を使って中間バッファを節約します。

**ローカルポーズを混ぜている**点も確認しておきます。グローバルポーズを混ぜてはいけません。混ぜた結果のグローバル姿勢は、階層の整合性を失います（骨の長さが変わる）。**混ぜるのは常にローカル、階層を解くのはその後**です。

## 38.3　`Nlerp` か `Slerp` か

第 10 章で測った表を、あらためて使います。

| 2 つの回転の角度差 | `Nlerp` の最大誤差 |
| --- | --- |
| 45° | 0.112° |
| 90° | 0.919° |
| 179° | 8.001° |

ブレンドの用途ごとに、角度差の大きさが違います。

| 用途 | 典型的な角度差 | 選択 |
| --- | --- | --- |
| キーフレーム補間（第 24 章） | 数度 | `Nlerp` |
| ブレンドスペース（第 42・43 章） | 数度〜30 度 | `Nlerp` |
| クロスフェード（第 39 章） | **大きくなりうる** | **`Slerp`** |
| ステートマシンの遷移（第 45 章） | 大きくなりうる | **`Slerp`** |

**歩きと走りは似た姿勢**なので、ブレンドスペースの角度差は小さい。一方、**待機から攻撃モーションへの遷移**では、腕の姿勢が 120 度違うこともあります。そこで `Nlerp` を使うと 2 度以上ずれ、「遷移の途中で腕が変な軌跡を描く」という結果になります。

既定を `Nlerp` にして、必要なところで `Slerp` を指定する ―― これが本書の方針です。

## 38.4　N 個のポーズを混ぜる ―― 逐次方式

ブレンドスペース（第 43 章）では、3 つのポーズを重心座標で混ぜます。ブレンドツリー（第 44 章）では、任意個のポーズが混ざります。

素朴な方法は、**2 つずつ順に混ぜていく**ことです。

```cpp
// N 個のポーズを、2 つずつ順に混ぜる
void BlendPosesSequential(std::span<const Pose* const> poses,
                          std::span<const float> weights, Pose& out) {
    float accumulated = 0.0f;
    bool first = true;

    for (std::size_t k = 0; k < poses.size(); ++k) {
        const float w = weights[k];
        if (w <= 0.0f) { continue; }

        if (first) {
            CopyPose(*poses[k], out);
            accumulated = w;
            first = false;
            continue;
        }
        // これまでの合成結果と、次のポーズを混ぜる
        const float t = w / (accumulated + w);
        BlendPose(out, *poses[k], t, out);
        accumulated += w;
    }
}
```

重み `t = w / (accumulated + w)` が要点です。既に重み `accumulated` ぶんを混ぜた結果に、重み `w` のポーズを足すには、この比率で混ぜます。

平行移動とスケールについては、**これは厳密に正しい**。線形なので、どの順で混ぜても同じ加重平均になります。

**回転は、そうではありません。**

## 38.5　逐次方式は、順序で結果が変わる

`Nlerp` は「2 つの点を直線で結んで球面に射影する」操作です。3 つ以上になると、**射影が入るたびに情報が失われ、順序が結果に影響します**。

測りました。4 つのポーズを重み `0.4 : 0.3 : 0.2 : 0.1` で混ぜ、**混ぜる順序を 200 通りシャッフル**して、結果の回転角の最大の食い違いを見ます。

| ポーズの散らばり | 逐次方式の順序依存 |
| --- | --- |
| ランダム（球面上に一様） | **152.10°** |
| 現実的（互いに近いポーズ） | **0.056°** |

**理論上は破滅的、実用上はほぼ無害。** これが正直なところです。

152 度というのは「まったく別の姿勢になる」という意味で、看過できません。しかし、その入力は**球面上にランダムに散らばった 4 つの回転**であり、アニメーションのブレンドでそんな状況は起こりません。歩きと走りと待機は、どれも似た姿勢です。

現実的な入力（互いに数度以内）では、**0.056 度**。第 4 章で決めた基準（腕の長さ 0.6 m で 0.0057 度 = 0.06 mm）に照らすと、0.056 度は 0.6 mm。**1080p で 1 px の 1/3** です。見えません。

**「理論上は問題があるが、実測すると無視できる」**という結論に至ることは、しばしばあります。大事なのは、**理論だけで判断せず、実測だけで安心もしない**ことです。この場合、「入力が散らばると壊れる」ことを知ったうえで無害だと判断しています。散らばる可能性のある用途（たとえばプロシージャルに生成した姿勢を混ぜる）が出てきたら、判断は変わります。

## 38.6　累積方式 ―― 順序に依らない混ぜ方

順序依存を消す方法もあります。**すべての回転を重み付きで足してから、最後に一度だけ正規化する**。

```cpp
void BlendPosesAccumulate(std::span<const Pose* const> poses,
                          std::span<const float> weights, Pose& out) {
    const std::size_t boneCount = out.Size();

    std::vector<Vec3> translation(boneCount, Vec3{0, 0, 0});
    std::vector<Vec3> scale(boneCount, Vec3{0, 0, 0});
    std::vector<Quat> rotation(boneCount, Quat{0, 0, 0, 0});

    // 符号合わせの基準は「最大ウェイトのポーズ」。
    // 反復順ではなくデータで決まるので、順序に依らない。
    std::size_t reference = 0;
    float best = -1.0f;
    for (std::size_t k = 0; k < poses.size(); ++k) {
        if (weights[k] > best) { best = weights[k]; reference = k; }
    }

    float total = 0.0f;
    for (std::size_t k = 0; k < poses.size(); ++k) {
        const float w = weights[k];
        if (w <= 0.0f) { continue; }
        total += w;

        for (std::size_t i = 0; i < boneCount; ++i) {
            const BoneIndex bone = static_cast<BoneIndex>(i);
            const Transform& x = (*poses[k])[bone];
            translation[i] = translation[i] + x.translation * w;
            scale[i]       = scale[i] + x.scale * w;

            // 第 8 章の二重被覆。基準と同じ半球へ揃えてから足す
            const Quat& r = (*poses[reference])[bone].rotation;
            const Quat aligned = (Dot(x.rotation, r) < 0.0f) ? -x.rotation : x.rotation;
            rotation[i] = rotation[i] + aligned * w;
        }
    }

    if (total <= 0.0f) { return; }
    const float inverse = 1.0f / total;
    for (std::size_t i = 0; i < boneCount; ++i) {
        out[static_cast<BoneIndex>(i)] = {
            translation[i] * inverse,
            Normalize(rotation[i]),      // ここで一度だけ正規化
            scale[i] * inverse
        };
    }
}
```

**基準の選び方が、この実装の肝**です。

最初、筆者は「最初に出てきたポーズを基準にする」と実装しました。テストしたところ、**順序依存が 104.9 度**。累積方式にした意味がありません。

原因は明白で、**「最初に出てきた」は反復順に依存する**からです。基準が変われば符号の揃え方が変わり、結果も変わります。

**基準は、データによって決まる規則で選ばなければなりません。** 最大ウェイトのポーズを基準にすると、順序依存は **0.000000 度**になりました。

> **同じ重みが複数あったら**
> 最大ウェイトが一意でない場合、`weights[k] > best` の比較は「最初に見つかった最大値」を選ぶので、順序依存が復活します。厳密にやるなら、ウェイトが同じときはポーズの識別子（ブレンドツリーのスロット番号など）で決着をつけます。実務ではブレンドスロットの順序が固定なので、この問題は表面化しません。**「順序に依らない」と言うときは、何が順序を決めているのかを意識してください。**

## 38.7　どちらを使うか

| | 逐次方式 | 累積方式 |
| --- | --- | --- |
| メモリ | 追加なし | ボーン数 × (Vec3×2 + Quat) |
| 正規化の回数 | N−1 回 | 1 回 |
| 順序依存 | あり（実用上は無視できる） | なし |
| 早期打ち切り | しやすい | しにくい |

**本書は逐次方式を既定にします。** 理由は 2 つです。

**① 追加のメモリが要らない。** 第 44 章のブレンドツリーは、ノードを再帰的に評価する構造です。逐次方式なら「2 つずつ混ぜる」という操作の連鎖として自然に表現できます。累積方式は、N 個をまとめて知っている必要があります。

**② 実用上の差が測定で無害だった。** 0.056 度。

累積方式を使うのは、**重みが動的に変わる多入力のノード**（ブレンドスペース、第 42・43 章）です。そこでは入力が 2〜3 個で、しかも姿勢が近いので、どちらでも構いません。実装が単純な逐次方式で通します。

**知っておくべきは、「N 個の回転の平均には唯一の正解がない」**ということです。球面上の平均（カルタン平均）を反復計算で求める手法もありますが、コストに見合いません。

## 38.8　テストを書く

`AnimLib.Tests/PoseBlendTests.cpp`：

```cpp
#include "CppUnitTest.h"

#include "TestSupport/MathAssert.h"
#include "TestSupport/TestRandom.h"
#include "TestSupport/Tolerance.h"

#include "anim/PoseBlend.h"

#include <format>
#include <numbers>

using namespace Microsoft::VisualStudio::CppUnitTestFramework;
using namespace anim;

namespace {

constexpr float kPi = std::numbers::pi_v<float>;

Pose RandomPose(std::size_t boneCount, anim::test::TestRandom& rng) {
    Pose p(boneCount);
    for (std::size_t i = 0; i < boneCount; ++i) {
        p[static_cast<BoneIndex>(i)] = {rng.NextVec3(2.0f), rng.NextQuat(), {1, 1, 1}};
    }
    return p;
}

// 2 つの回転のあいだの角度
float AngleBetween(const Quat& a, const Quat& b) {
    return 2.0f * std::acos(std::fmin(1.0f, std::fabs(Dot(a, b))));
}

}  // namespace

namespace AnimLibTests {

TEST_CLASS(PoseBlendTests) {
public:

    // --- 端点 -----------------------------------------------------

    TEST_METHOD(EndpointsAreExact) {
        anim::test::TestRandom rng;
        const Pose a = RandomPose(8, rng);
        const Pose b = RandomPose(8, rng);
        Pose out(8);

        BlendPose(a, b, 0.0f, out);
        for (BoneIndex i = 0; i < 8; ++i) {
            anim::test::AssertNear(a[i].translation, out[i].translation, test::kEpsPos);
            anim::test::AssertSameRotation(a[i].rotation, out[i].rotation, test::kEpsDir);
        }
        BlendPose(a, b, 1.0f, out);
        for (BoneIndex i = 0; i < 8; ++i) {
            anim::test::AssertNear(b[i].translation, out[i].translation, test::kEpsPos);
            anim::test::AssertSameRotation(b[i].rotation, out[i].rotation, test::kEpsAccum);
        }
    }

    TEST_METHOD(BlendIsSymmetric) {
        anim::test::TestRandom rng;
        const Pose a = RandomPose(8, rng);
        const Pose b = RandomPose(8, rng);
        Pose forward(8);
        Pose backward(8);

        BlendPose(a, b, 0.3f, forward);
        BlendPose(b, a, 0.7f, backward);
        for (BoneIndex i = 0; i < 8; ++i) {
            anim::test::AssertNear(forward[i].translation, backward[i].translation,
                                   test::kEpsPos);
            anim::test::AssertSameRotation(forward[i].rotation, backward[i].rotation,
                                           test::kEpsAccum);
        }
    }

    TEST_METHOD(RotationsStayUnitLength) {
        anim::test::TestRandom rng;
        const Pose a = RandomPose(8, rng);
        const Pose b = RandomPose(8, rng);
        Pose out(8);
        for (float t : {0.0f, 0.25f, 0.5f, 0.9f, 1.0f}) {
            BlendPose(a, b, t, out);
            for (BoneIndex i = 0; i < 8; ++i) {
                anim::test::AssertNear(1.0f, Length(out[i].rotation), test::kEpsUnit);
            }
        }
    }

    // 出力が入力と同じでも壊れないこと（第 44 章が依存する）
    TEST_METHOD(BlendingInPlaceIsSafe) {
        anim::test::TestRandom rng;
        const Pose a = RandomPose(8, rng);
        const Pose b = RandomPose(8, rng);

        Pose reference(8);
        BlendPose(a, b, 0.4f, reference);

        Pose inPlace = a;
        BlendPose(inPlace, b, 0.4f, inPlace);   // out == a

        for (BoneIndex i = 0; i < 8; ++i) {
            anim::test::AssertNear(reference[i].translation, inPlace[i].translation,
                                   test::kEpsPos);
        }
    }

    // --- N 個のブレンド -------------------------------------------

    TEST_METHOD(SingleNonZeroWeightReproducesThatPose) {
        anim::test::TestRandom rng;
        std::vector<Pose> poses;
        for (int k = 0; k < 4; ++k) { poses.push_back(RandomPose(4, rng)); }
        std::vector<const Pose*> pointers;
        for (const Pose& p : poses) { pointers.push_back(&p); }

        const std::vector<float> weights{0.0f, 1.0f, 0.0f, 0.0f};
        Pose sequential(4);
        Pose accumulated(4);
        BlendPosesSequential(pointers, weights, sequential);
        BlendPosesAccumulate(pointers, weights, accumulated);

        for (BoneIndex i = 0; i < 4; ++i) {
            anim::test::AssertSameRotation(poses[1][i].rotation, sequential[i].rotation,
                                           test::kEpsDir);
            anim::test::AssertSameRotation(poses[1][i].rotation, accumulated[i].rotation,
                                           test::kEpsDir);
        }
    }

    // 平行移動は、どちらの方式でも厳密に加重平均になる
    TEST_METHOD(TranslationIsAnExactWeightedAverage) {
        anim::test::TestRandom rng;
        std::vector<Pose> poses;
        for (int k = 0; k < 4; ++k) { poses.push_back(RandomPose(1, rng)); }
        std::vector<const Pose*> pointers;
        for (const Pose& p : poses) { pointers.push_back(&p); }
        const std::vector<float> weights{0.4f, 0.3f, 0.2f, 0.1f};

        Vec3 expected{0, 0, 0};
        for (std::size_t k = 0; k < poses.size(); ++k) {
            expected = expected + poses[k][0].translation * weights[k];
        }

        Pose sequential(1);
        Pose accumulated(1);
        BlendPosesSequential(pointers, weights, sequential);
        BlendPosesAccumulate(pointers, weights, accumulated);

        anim::test::AssertNear(expected, sequential[0].translation, test::kEpsAccum);
        anim::test::AssertNear(expected, accumulated[0].translation, test::kEpsAccum);
    }

    // --- 順序依存（38.5・38.6 節）--------------------------------

    // 逐次方式は順序に依存する。これは仕様であって、バグではない。
    TEST_METHOD(SequentialBlendIsOrderDependent) {
        anim::test::TestRandom rng;
        std::vector<Pose> poses;
        for (int k = 0; k < 4; ++k) { poses.push_back(RandomPose(1, rng)); }
        const std::vector<float> weights{0.4f, 0.3f, 0.2f, 0.1f};

        std::vector<const Pose*> ordered;
        for (const Pose& p : poses) { ordered.push_back(&p); }
        Pose baseline(1);
        BlendPosesSequential(ordered, weights, baseline);

        float worst = 0.0f;
        for (int trial = 0; trial < 200; ++trial) {
            std::vector<int> order{0, 1, 2, 3};
            rng.Shuffle(order);
            std::vector<const Pose*> shuffled;
            std::vector<float> shuffledWeights;
            for (const int k : order) {
                shuffled.push_back(&poses[k]);
                shuffledWeights.push_back(weights[k]);
            }
            Pose result(1);
            BlendPosesSequential(shuffled, shuffledWeights, result);
            worst = std::fmax(worst,
                AngleBetween(baseline[0].rotation, result[0].rotation) * 180.0f / kPi);
        }
        Logger::WriteMessage(std::format(
            L"sequential, random poses: order dependence = {:.4f} deg\n", worst).c_str());
        Assert::IsTrue(worst > 0.01f);   // 実測 152.10 度
    }

    // 現実的な入力（近いポーズ）では無視できる大きさになる
    TEST_METHOD(OrderDependenceIsNegligibleForSimilarPoses) {
        anim::test::TestRandom rng;
        const Pose center = RandomPose(1, rng);

        std::vector<Pose> poses;
        for (int k = 0; k < 4; ++k) {
            Pose p(1);
            p[0] = {center[0].translation + rng.NextVec3(0.05f),
                    Normalize(center[0].rotation
                              + Quat{rng.NextRange(-0.1f, 0.1f), rng.NextRange(-0.1f, 0.1f),
                                     rng.NextRange(-0.1f, 0.1f), 0.0f}),
                    {1, 1, 1}};
            poses.push_back(p);
        }
        const std::vector<float> weights{0.4f, 0.3f, 0.2f, 0.1f};

        std::vector<const Pose*> ordered;
        for (const Pose& p : poses) { ordered.push_back(&p); }
        Pose baseline(1);
        BlendPosesSequential(ordered, weights, baseline);

        float worst = 0.0f;
        for (int trial = 0; trial < 200; ++trial) {
            std::vector<int> order{0, 1, 2, 3};
            rng.Shuffle(order);
            std::vector<const Pose*> shuffled;
            std::vector<float> shuffledWeights;
            for (const int k : order) {
                shuffled.push_back(&poses[k]);
                shuffledWeights.push_back(weights[k]);
            }
            Pose result(1);
            BlendPosesSequential(shuffled, shuffledWeights, result);
            worst = std::fmax(worst,
                AngleBetween(baseline[0].rotation, result[0].rotation) * 180.0f / kPi);
        }
        Logger::WriteMessage(std::format(
            L"sequential, similar poses: order dependence = {:.4f} deg\n", worst).c_str());
        Assert::IsTrue(worst < 0.2f);   // 実測 0.056 度
    }

    // 累積方式は順序に依らない
    TEST_METHOD(AccumulateBlendIsOrderIndependent) {
        anim::test::TestRandom rng;
        std::vector<Pose> poses;
        for (int k = 0; k < 4; ++k) { poses.push_back(RandomPose(1, rng)); }
        const std::vector<float> weights{0.4f, 0.3f, 0.2f, 0.1f};

        std::vector<const Pose*> ordered;
        for (const Pose& p : poses) { ordered.push_back(&p); }
        Pose baseline(1);
        BlendPosesAccumulate(ordered, weights, baseline);

        float worst = 0.0f;
        for (int trial = 0; trial < 200; ++trial) {
            std::vector<int> order{0, 1, 2, 3};
            rng.Shuffle(order);
            std::vector<const Pose*> shuffled;
            std::vector<float> shuffledWeights;
            for (const int k : order) {
                shuffled.push_back(&poses[k]);
                shuffledWeights.push_back(weights[k]);
            }
            Pose result(1);
            BlendPosesAccumulate(shuffled, shuffledWeights, result);
            worst = std::fmax(worst,
                AngleBetween(baseline[0].rotation, result[0].rotation) * 180.0f / kPi);
        }
        Logger::WriteMessage(std::format(
            L"accumulate: order dependence = {:.6f} deg\n", worst).c_str());
        Assert::IsTrue(worst < 0.01f);   // 実測 0.000000 度
    }
};

}  // namespace AnimLibTests
```

`SequentialBlendIsOrderDependent` と `OrderDependenceIsNegligibleForSimilarPoses` を**対にして**書いているのが要点です。片方だけでは判断を誤ります。

- 前者だけを見れば「逐次方式は使えない」と結論する
- 後者だけを見れば「順序依存はない」と誤解する

**両方をテストとして残すことで、「性質としては存在するが、想定する入力では無害」という判断そのものが記録されます。**

## 38.9　つまずきやすいところ

**混ぜたら骨の長さが変わった**
グローバルポーズを混ぜています。**混ぜるのは常にローカルポーズ**です。

**混ぜたポーズが回転しすぎる／変な経路を通る**
`Nlerp` を使っていて、角度差が大きい可能性があります。`Slerp` を指定してください（38.3 節）。

**ブレンドスペースの結果が、入力の順序を変えると変わる**
逐次方式の性質です（38.5 節）。実用上は無視できる大きさのはずですが、入力の姿勢が大きく違うなら累積方式を検討してください。

**累積方式にしたのに順序依存が消えない**
符号合わせの基準が反復順に依存しています（38.6 節）。データで決まる規則で選んでください。

**重みの合計が 1 でない**
逐次方式は `w / (accumulated + w)` で正規化されるので、合計が 1 でなくても比率だけが効きます。累積方式は最後に `total` で割るので同じです。**どちらも合計に依存しません** ―― これは意図した設計で、第 43 章の重心座標が誤差でわずかに 1 からずれても問題になりません。

**ボーン数が違うポーズを混ぜた**
`ANIM_ASSERT` で落ちます。ブレンドツリーの入力がすべて同じスケルトンであることは、構築時に検査してください。

## この章のまとめ

- 第 VII 部のすべては、「**2 つのポーズを重み `t` で混ぜる**」という 1 つの操作の上に建つ。
- 混ぜるのは**ローカルポーズ**。グローバルポーズを混ぜると骨の長さが変わる。
- `BlendPose` は**出力が入力と同じでも安全**。第 44 章がこの性質を使う。
- **`Nlerp` を既定、必要なところで `Slerp`。** 第 10 章の実測表がそのまま判断基準になる。
- N 個のブレンドで、**平行移動とスケールは厳密**だが、**回転は順序に依存する**。
- 実測 ―― ランダムな姿勢では **152.10 度**、現実的な（近い）姿勢では **0.056 度**。**理論上は破滅的、実用上はほぼ無害。**
- 累積方式なら順序依存を消せる。ただし**符号合わせの基準を、反復順ではなくデータで決める**こと。最初は「最初に出てきたポーズ」を基準にして、順序依存が 104.9 度残った。
- **「性質としては存在するが、想定する入力では無害」という判断は、両方をテストとして残す**ことで記録できる。

次章、この道具を使って、アニメーションを切り替えます。
