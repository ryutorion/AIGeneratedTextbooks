# 第 55 章　キーフレーム圧縮（2）量子化

**この章で作るもの**：残ったキーを小さく格納する仕組み。`float` 4 個 = 16 バイトのクォータニオンを **6 バイト**にする **Smallest Three** と、平行移動の範囲量子化。

そして ―― この章でも測り方を間違えます。**誤差が 8.5 倍に見えていた**話が出てきます。

---

## 55.1　`float` の 32 bit は使いすぎ

第 54 章でキーの**数**を減らしました。次はキー **1 個あたりのサイズ**です。

```
現在のキー 1 個
  回転:     時刻 float 4 B + Quat float×4 16 B = 20 B
  平行移動: 時刻 float 4 B + Vec3 float×3 12 B = 16 B
```

`float` は 32 bit で、約 7 桁の精度を持ちます。**アニメーションに 7 桁は要りません。**

- **回転**：0.01 度の精度があれば、誰も違いに気づきません。1 回転 = 360 度を 0.01 度刻みで表すなら 36,000 段階 ―― **16 bit（65,536 段階）で足ります**。
- **平行移動**：ボーンの移動範囲はせいぜい数メートル。1 mm の精度なら数千段階 ―― これも 16 bit で余ります。
- **時刻**：クリップの長さは数秒。60 fps で数百フレーム ―― **16 bit あれば十分**すぎます。

**量子化**（quantization）とは、連続値を有限段階の整数に丸めることです。丸めた分の情報は失われますが、**失う量を数値で管理できます**。

---

## 55.2　平行移動：範囲量子化

いちばん素直な量子化は、**値の取りうる範囲を 0〜65535 に線形写像する**ことです。

```
u = (value − min) / extent        →  [0, 1]
q = round(u × 65535)              →  [0, 65535]
```

戻すときは逆をやります。

```cpp
struct Vec3Range { Vec3 min{0,0,0}; Vec3 extent{1,1,1}; };
struct QVec3 { std::uint16_t x, y, z; };

inline QVec3 QuantizeVec3(Vec3 v, const Vec3Range& r){
    auto q = [](float value, float lo, float ext) -> std::uint16_t {
        const float u = (value - lo) / ext;
        const float c = std::fmin(1.0f, std::fmax(0.0f, u));    // 範囲外を潰す
        return static_cast<std::uint16_t>(c * 65535.0f + 0.5f); // 四捨五入
    };
    return { q(v.x, r.min.x, r.extent.x),
             q(v.y, r.min.y, r.extent.y),
             q(v.z, r.min.z, r.extent.z) };
}

inline Vec3 DequantizeVec3(QVec3 q, const Vec3Range& r){
    return { r.min.x + r.extent.x * (q.x / 65535.0f),
             r.min.y + r.extent.y * (q.y / 65535.0f),
             r.min.z + r.extent.z * (q.z / 65535.0f) };
}
```

**`+ 0.5f` を忘れないこと。** C++ の `float → 整数`変換は切り捨てです。`0.9999` が `0` になってしまいます。四捨五入すれば最大誤差が半分になります。

**クランプも必要です。** 浮動小数の丸めで `u` がわずかに 1 を超えると、`65536` になって `std::uint16_t` が `0` に折り返します。**最大値が最小値に化ける**、最悪の壊れ方です。

### 範囲をどこから取るか

決定的に重要なのが、**`min` と `extent` をどこから取るか**です。

```cpp
inline Vec3Range MakeRange(const Track<Vec3>& t){
    Vec3 lo = t.Key(0).value, hi = lo;
    for (std::size_t i = 1; i < t.KeyCount(); ++i){
        const Vec3 v = t.Key(i).value;
        lo = {std::fmin(lo.x,v.x), std::fmin(lo.y,v.y), std::fmin(lo.z,v.z)};
        hi = {std::fmax(hi.x,v.x), std::fmax(hi.y,v.y), std::fmax(hi.z,v.z)};
    }
    Vec3Range r;
    r.min = lo;
    r.extent = { std::fmax(hi.x-lo.x, 1e-9f),      // 0 除算を避ける
                 std::fmax(hi.y-lo.y, 1e-9f),
                 std::fmax(hi.z-lo.z, 1e-9f) };
    return r;
}
```

**トラックごとに、実際に使われている範囲だけを取ります。** これが効きます。実測です。

```
範囲 min=(-0.3000, 0.9500, 0.0000) extent=(0.5998, 0.1000, 1.5000)
最大誤差 0.000012208 m（範囲の最大辺 1.5 m / 65535 = 0.000022889）
```

**12 マイクロメートル。** 実測値が理論上の 1 刻み（22.9 µm）の半分になっているのは、四捨五入しているからです。

範囲を取らずに「ワールド座標を丸ごと ±1000 m で量子化する」と、どうなるか。

```
±1000 m の範囲だと 1 成分の誤差 0.000396 m
```

**0.4 mm。** 32 倍悪化します。実用上まだ許容範囲かもしれませんが、**タダで手に入る 32 倍を捨てる理由はありません**。

`Vec3Range` 自体は 24 バイトのオーバーヘッドですが、キーが 10 個あれば元が取れます（`16 B × 10 = 160 B` が `8 B × 10 + 24 B = 104 B`）。

## 55.3　回転：Smallest Three

クォータニオンには、`Vec3` にはない**強い制約**があります。

```
x² + y² + z² + w² = 1
```

**4 成分のうち 3 つが分かれば、4 つ目は計算で求まります。**

```
w = √(1 − x² − y² − z²)
```

これで 4 成分ぶん送る必要がなくなりました ―― と言いたいところですが、2 つ問題があります。

**問題 1：符号が分からない。** 平方根は正の値しか返しません。`w` が負だったら復元できない。

**ここで第 8 章の二重被覆が効きます。** `q` と `−q` は同じ回転を表します。だから、**`w` が負なら `q` 全体を反転してから送ればいい**。受け取る側は常に `w ≥ 0` として復元します。同じ回転です。

**問題 2：どの成分を捨てるか。** `w` を捨てると決め打ちにすると、`w ≈ 0` のとき（180 度回転）に破綻します。`x, y, z` が `1/√2` 前後の大きな値になり、それを 15 bit で表すと、`w = √(1 − …)` の計算で**誤差が爆発**します。平方根は 0 の近くで傾きが無限大だからです。

解決策は、**「最大の成分」を捨てる**こと。どれを捨てたかを 2 bit で記録します。

**最大の成分は必ず `1/√2 ≈ 0.7071` 以上**です。4 つの二乗和が 1 なので、最大のものは少なくとも `√(1/4) = 0.5`。そして残り 3 つは、それぞれ最大成分以下 ―― つまり **残り 3 成分は `[−1/√2, +1/√2]` の範囲に収まります**。この狭い範囲を 15 bit で刻めば、精度が稼げます。

これが **Smallest Three** です。

```
  2 bit : どの成分を捨てたか（0=x, 1=y, 2=z, 3=w）
 15 bit : 残り 1 つ目  [−1/√2, +1/√2] を 32767 段階で
 15 bit : 残り 2 つ目
 15 bit : 残り 3 つ目
────────
 47 bit  →  6 バイト（48 bit）に収まる
```

**16 バイトが 6 バイト。62.5% 削減。**

## 55.4　実装

```cpp
inline constexpr float kInvSqrt2 = 0.70710678f;
inline constexpr int   kQuatBits = 15;
inline constexpr int   kQuatMax  = (1 << kQuatBits) - 1;      // 32767

inline std::uint64_t PackQuat(const Quat& qin){
    const Quat q = Normalize(qin);
    const float a[4] = { q.x, q.y, q.z, q.w };

    // ① 絶対値が最大の成分を探す
    int largest = 0;
    for (int i = 1; i < 4; ++i)
        if (std::fabs(a[i]) > std::fabs(a[largest])) largest = i;

    // ② その成分が正になるよう、全体の符号を揃える（二重被覆）
    const float sign = (a[largest] < 0.0f) ? -1.0f : 1.0f;

    std::uint64_t packed = static_cast<std::uint64_t>(largest);
    int shift = 2;
    for (int i = 0; i < 4; ++i) {
        if (i == largest) continue;
        const float v = a[i] * sign;                        // [−1/√2, +1/√2]
        const float u = v * kInvSqrt2 + 0.5f;               // → [0, 1]
        const float c = std::fmin(1.0f, std::fmax(0.0f, u));
        packed |= static_cast<std::uint64_t>(c * kQuatMax + 0.5f) << shift;
        shift += kQuatBits;
    }
    return packed;                                          // 下位 47 bit が有効
}

inline Quat UnpackQuat(std::uint64_t packed){
    const int largest = static_cast<int>(packed & 0x3);
    float a[4];
    float sumSq = 0.0f;
    int shift = 2;
    for (int i = 0; i < 4; ++i) {
        if (i == largest) continue;
        const std::uint32_t bits = static_cast<std::uint32_t>((packed >> shift) & kQuatMax);
        const float u = static_cast<float>(bits) / kQuatMax;
        a[i] = (u - 0.5f) / kInvSqrt2;
        sumSq += a[i]*a[i];
        shift += kQuatBits;
    }
    a[largest] = std::sqrt(std::fmax(0.0f, 1.0f - sumSq));   // 常に正
    return { a[0], a[1], a[2], a[3] };
}
```

**`std::fmax(0.0f, ...)` を平方根の中に入れる**のは必須です。丸め誤差で `sumSq` がわずかに 1 を超えると、`sqrt` が NaN を返します。ポーズ全体が消えます。

**`[−1/√2, 1/√2] → [0, 1]` の写像**を確認しておきます。`v × √2 / 2 = v × 0.70710678 = v × kInvSqrt2` で `[−0.5, 0.5]`、`+ 0.5` で `[0, 1]`。逆は `(u − 0.5) / kInvSqrt2`。

（ここは私が一度間違えた場所です。`v * kInvSqrt2 * 0.5f + 0.5f` と書いてしまい、範囲が `[0.25, 0.75]` になっていました。往復テストが即座に落ちたので、すぐ気づけました ―― **往復テストは、こういう凡ミスを捕まえるためにある**。）

### 48 bit の格納

C++ に 48 bit の整数型はありません。バイト列に手で書きます。

```cpp
inline void WriteU48(std::uint8_t* p, std::uint64_t v){
    for (int i = 0; i < 6; ++i) p[i] = static_cast<std::uint8_t>((v >> (i*8)) & 0xFF);
}
inline std::uint64_t ReadU48(const std::uint8_t* p){
    std::uint64_t v = 0;
    for (int i = 0; i < 6; ++i) v |= static_cast<std::uint64_t>(p[i]) << (i*8);
    return v;
}
```

**リトルエンディアン固定で書いています。** `std::memcpy(p, &v, 6)` と書くとホストのバイト順に依存し、ファイルに保存したデータが別のプラットフォームで読めなくなります。ループで 1 バイトずつ書けば、バイト順が明示的に決まります。最適化ビルドではどうせ 1 命令になります。

## 55.5　単体テスト：まず往復

```cpp
TEST_CLASS(SmallestThreeTests) {
public:
    TEST_METHOD(RoundTripPreservesUnitLength) {
        float worst = 0.0f;
        for (int i = 0; i < 10000; ++i) {
            unsigned s = 1u + i*2654435761u;
            auto rnd = [&]{ s = s*1664525u + 1013904223u;
                            return static_cast<float>((s>>8)&0xFFFF)/32767.5f - 1.0f; };
            const Quat q = Normalize(Quat{rnd(), rnd(), rnd(), rnd()+0.001f});
            worst = std::fmax(worst, std::fabs(1.0f - Length(UnpackQuat(PackQuat(q)))));
        }
        Assert::IsTrue(worst < 1e-5f);

};
```

実測 **`0.000000119`**。復元されたクォータニオンは単位長を保っています。当然です ―― `sqrt(1 − sumSq)` で作っているので、構造的に単位長になります。**このテストは「構造が壊れていないこと」を確認しているだけ**で、精度は測っていません。

## 55.6　単体テスト：回転空間を掃く

本命は「どれくらい精度が落ちるか」です。ランダムに 1 万個試すのではなく、**回転空間を系統的に掃きます**。

軸はフィボナッチ球で球面上に均等分散させ、角度は 0〜2π を細かく刻む。

```cpp
TEST_METHOD(SweepRotationSpace) {
    float worst = 0.0f;
    Quat worstQ{};
    const int A = 400, B = 180;                    // 軸 400 × 角度 180 = 72,000 通り

    for (int i = 0; i < A; ++i) {
        const float y = 1.0f - 2.0f*(i+0.5f)/A;
        const float r = std::sqrt(std::fmax(0.0f, 1.0f - y*y));
        const float phi = static_cast<float>(i) * 2.39996323f;      // 黄金角
        const Vec3 axis{ r*std::cos(phi), y, r*std::sin(phi) };

        for (int j = 0; j < B; ++j) {
            const Quat q = MakeQuatAxisAngle(axis, static_cast<float>(j)/B * 2.0f*kPi);
            const float e = ErrorOf(q, UnpackQuat(PackQuat(q)));
            if (e > worst) { worst = e; worstQ = q; }
        }
    }
    Logger::WriteMessage(std::format("最悪 {:.9f} rad = {:.6f} 度\n",
                                     worst, worst*180/kPi).c_str());
    Assert::IsTrue(worst < 0.0002f);
}
```

**フィボナッチ球**（黄金角 `2.39996323` ラジアンずつ回しながら、`y` を等間隔に降ろす）は、球面上に点をほぼ均等に置く簡単な方法です。緯度経度で刻むと極に点が集中してしまいます。

実測です。

```
72000 通りを掃引：最悪の角度誤差 0.000114507 rad = 0.006561 度
最悪だった回転 (-0.542771, 0.496204, 0.529693, -0.422618)
理論上の最小刻み: 0.000086319 rad = 0.004946 度
```

**最悪 0.0066 度。** 理論上の 1 刻み（0.0049 度）の 1.33 倍です。

**最悪の回転の 4 成分を見てください。** `−0.543, 0.496, 0.530, −0.423` ―― **4 つとも 0.5 前後**です。これは予測どおりです。捨てた成分を `√(1 − sumSq)` で復元するとき、その値が小さいほど平方根の傾きが急になる。最大成分が最小になる（＝すべて 0.5 になる）ところが最悪ケースです。

**0.0066 度がどれくらいか。** 腕の長さ 60 cm なら `0.6 m × 0.000115 rad = 0.069 mm`。**70 マイクロメートル。** 第 54 章のキー削減が持ち込む 16.5 mm と比べると、**240 分の 1** です。

> **量子化の誤差は、キー削減の誤差に完全に埋もれる。**
>
> これは実務的に大きな意味があります。「量子化で画が悪くなった」と言われたら、まず疑うべきはキー削減の許容値のほうです。

## 55.7　測り方を間違えた話

上のテストを最初に書いたとき、結果はこうでした。

```
72000 通りを掃引：最悪の角度誤差 0.000976562 rad = 0.055953 度
理論上の最小刻み:                0.000086319 rad = 0.004946 度
```

**理論値の 11 倍。** 実装のどこかが間違っている ―― そう考えて、パッキングの式を何度も見直しました。`shift` の値、マスク、範囲写像。全部合っている。

原因は、**誤差を測る関数**でした。当時の `ErrorOf` はこうでした。

```cpp
return 2.0f * std::acos(std::fmin(1.0f, std::fabs(Dot(a, b))));
```

第 54 章 54.3 で「これは使えない」と書いた形です。**書いておきながら、私は最初これを使っていました。**

なぜ壊れるか。角度 `8.6e-5` ラジアンに対応する内積は `1 − 3.7e-9`。しかし `float` で 1.0 のすぐ下に表現できる値は `1 − 5.96e-8` です。**`1 − 3.7e-9` は表現できず、ちょうど `1.0` に丸められます。** すると `acos` は `0` を返す ―― 誤差が過小評価される。

逆に、丸めが 1〜2 ulp 下に落ちると、`acos(1 − 1.19e-7) = 4.9e-4` のような**離散的で大きな値**が返ります。**測定値が 3.45e-4 ラジアン刻みの階段になる。** 0.000976562 という値は `sqrt(2 × 8 ulp)` に相当し、**測定の分解能そのもの**でした。

第 54 章の形に直します。

```cpp
inline float ErrorOf(const Quat& a, const Quat& b){
    const Quat r = Conjugate(Normalize(a)) * Normalize(b);
    return 2.0f * std::atan2(Length(Vec3{r.x, r.y, r.z}), std::fabs(r.w));
}
```

結果は **`0.000114507`** ―― 理論値の 1.33 倍。実装は最初から正しかった。

**両方をテストに残します。**

```cpp
TEST_METHOD(AcosMetricIsUnusableForSmallAngles) {
    // acos 版は 8.5 倍過大に見積もる。測り方を戻さないための番人。

    const float acos   = SweepWorstError(&ErrorOfAcos);

    Assert::IsTrue(acos   > 0.0008f);

}
```

第 46 章で `FromToRotationAcos` を残したのと同じ考え方です。**壊れているほうも、壊れ方を固定しておく。**

> **一致テストが赤いとき、容疑者は 3 人 ―― 新実装、旧実装、そして測り方。**

## 55.8　時刻の量子化

残るは時刻です。`float` 4 バイトを使っています。

クリップの長さを `[0, duration]` として、`uint16` で 65,536 段階に刻みます。

```cpp
std::uint16_t QuantizeTime(float t, float duration){
    const float u = (duration > 0.0f) ? std::fmin(1.0f, std::fmax(0.0f, t/duration)) : 0.0f;
    return static_cast<std::uint16_t>(u * 65535.0f + 0.5f);
}
```

**10 秒のクリップなら、時間分解能は `10 / 65535 = 0.15` ミリ秒。** 60 fps の 1 フレームが 16.7 ミリ秒なので、**100 分の 1 フレーム**の精度です。十分すぎます。

**時刻を量子化する副次的な利点**があります。キー探索が `uint16` の比較になり、**`float` の比較より速く、しかも `std::uint16_t` の配列は `float` の半分のキャッシュしか使いません**。第 56 章の探索が速くなる理由の 1 つです。

さらに一歩進めるなら、**キーの時刻を保存しない**という選択もあります。キーが等間隔（30 Hz など）と決まっていれば、添字から時刻が計算できる。

```
time = keyIndex / sampleRate
```

ただし、これは第 54 章のキー削減と両立しません。**キーを間引いた時点で、等間隔ではなくなる**からです。「等間隔で全キーを持つ（時刻 0 バイト）」と「間引いて時刻を持つ（キーあたり 2 バイト）」のどちらが小さいかは、削減率次第です。この本では後者を選びます ―― 削減率 35% なら、明らかに間引いたほうが小さい。

## 55.9　まとめて数える

第 54 章と第 55 章を合わせると、キー 1 個あたりのサイズはこうなります。

| | 元 | 圧縮後 | 削減 |
|---|---|---|---|
| 回転キー | 時刻 4 B + Quat 16 B = **20 B** | 時刻 2 B + 48 bit 6 B = **8 B** | 60% |
| 平行移動キー | 時刻 4 B + Vec3 12 B = **16 B** | 時刻 2 B + `uint16`×3 6 B = **8 B** | 50% |
| 定数トラック | キー数 × 20 B | 6 B（回転）/ 12 B（位置） | ほぼ 100% |

そしてキーの**数**が第 54 章で 35% になっている。掛け合わせると、

```
回転:  3660 キー × 20 B = 73,200 B
    →  1288 キー ×  8 B = 10,304 B     （14.1%）
```

第 56 章で、実際のクリップ全体を測ります。

## 55.10　やらなかったこと

圧縮にはまだ先があります。この本で扱わない手法を挙げておきます。

**① 曲線あてはめ。** キーを点として持つ代わりに、区間ごとの多項式やスプラインの係数として持つ。滑らかなモーションでは劇的に小さくなりますが、サンプリングのコストが上がります。

**② 主成分分析（PCA）。** クリップ群全体から「よく出る姿勢の組み合わせ」を学習し、各フレームをその線形結合として表す。**大量のモーションキャプチャデータには非常に効きます**が、クリップ 1 本だけでは効きません。

**③ 相対量子化。** 前のキーとの差分だけを保存する。差分は小さいので少ないビットで済む ―― ただしランダムアクセスができなくなります（先頭から積み上げないと復元できない）。第 56 章の「圧縮したまま任意の時刻を読む」という要求と相容れません。

**④ 可変ビット幅。** トラックごとに必要なビット数を測って、8 bit で足りるトラックは 8 bit にする。効果はありますが、ビット境界をまたぐ読み出しが必要になり、サンプリングが遅くなります。

**すべてに共通するトレードオフ**は、**「サイズ」と「サンプリングの速さ」**です。この本は「実行時に展開しない」を優先したので、②③④ は採りません。**圧縮率だけを追うと、実行時に困ります。**

## この章のまとめ

- `float` の 32 bit（7 桁）はアニメーションには過剰。**回転は 0.01 度、位置は 1 mm あれば足り、どちらも 16 bit で収まる。**
- 平行移動は**トラックごとの範囲**で量子化する。実測、範囲 1.5 m のトラックで **12 マイクロメートル**。ワールド ±1000 m で量子化すると **0.4 mm** ―― **32 倍悪化する。タダで手に入る 32 倍を捨てない。**
- 量子化のコードで忘れてはいけない 2 つ：**`+0.5f` の四捨五入**（切り捨てだと誤差が倍）と、**クランプ**（`65536` は `uint16` で `0` に折り返し、最大値が最小値に化ける）。
- 回転は **Smallest Three**。`x²+y²+z²+w²=1` から 1 成分は復元できる。**符号の問題は第 8 章の二重被覆で解決**（最大成分が正になるよう全体を反転）。**捨てるのは常に最大成分**（残り 3 つが `[−1/√2, 1/√2]` に収まり、平方根の精度が守られる）。
- **2 bit + 15 bit × 3 = 47 bit → 6 バイト。16 B が 6 B（62.5% 削減）。**
- 実装の注意：**`sqrt` の中に `fmax(0, ...)`**（NaN 防止）、**48 bit はバイト単位で明示的に書く**（`memcpy` はバイト順に依存する）。
- 72,000 通りの回転を掃引して、**最悪 `0.000114507` rad = 0.0066 度**（理論刻みの 1.33 倍）。最悪ケースは**4 成分がすべて 0.5 前後**の回転 ―― 予測どおり。
- 腕の長さ 60 cm で **70 マイクロメートル**。第 54 章のキー削減が持ち込む 16.5 mm の **240 分の 1**。**量子化の誤差はキー削減の誤差に完全に埋もれる。**
- **測り方を間違えた**：`acos(dot)` で測ると `0.000977`（理論値の 11 倍）に見え、実装を疑って時間を溶かした。原因は `float` で `1 − 3.7e-9` が表現できず、測定の分解能が `3.45e-4` ラジアンの階段になっていたこと。**壊れた測り方もテストに残す。**
- **一致テストが赤いとき、容疑者は 3 人 ―― 新実装、旧実装、そして測り方。**（第 52 章と同じ文章。3 章のうちに 2 回踏んだ。）
- 時刻も `uint16` で十分（10 秒のクリップで 0.15 ms = 100 分の 1 フレーム）。副次効果として**探索が速くなる**。
- 扱わなかった手法（曲線あてはめ、PCA、差分、可変ビット幅）に共通するのは「**サイズ**」と「**サンプリングの速さ**」のトレードオフ。**圧縮率だけを追うと実行時に困る。**

次章では、この形式を**展開せずにそのままサンプリング**します。そして ―― **圧縮したほうが速く読めた**という結果を測ります。
