# 第 10 章　クォータニオンの補間

**この章で作るもの**：`Lerp`、`Nlerp`、`Slerp`。第 8 章でクォータニオンを採用した最大の理由が、ここで回収されます。あわせて、両者の誤差を実測して**使い分けの基準**を決めます。

---

## 10.1　補間とは何をすることか

「歩き」のキーフレームが 0.0 秒と 0.5 秒にあり、今が 0.3 秒だとします。このとき肘のボーンの姿勢は、2 つのキーの「あいだ」でなければなりません。

平行移動とスケールなら簡単です。成分ごとに線形補間すればよい。

```
result = a·(1-t) + b·t
```

回転はそうはいきません。第 8 章で見たとおり、2 つの単位クォータニオンを成分ごとに平均したものは、**長さが 1 になりません**。長さ 1 でないクォータニオンは回転を表さないので、そのまま使うとモデルが膨らみます。

そして、仮に正規化して長さを 1 に戻したとしても、**回転が一定の速度で進むとは限りません**。この 2 つの問題への答えが、`Nlerp` と `Slerp` です。

---

## 10.2　まず最短経路の話をする

補間の実装に入る前に、片付けておくべきことがあります。第 8 章の**二重被覆**です。

`q` と `-q` は同じ回転を表します。ということは、`a` から `b` へ補間するとき、目的地として `b` を使うか `-b` を使うかで、**通る経路が変わります**。

4 次元の球面の上を移動すると考えてください。`b` と `-b` は球面上の正反対の点です。`a` からどちらへ向かうかで、短いほうの弧を通るか、長いほうの弧を通るかが決まります。姿勢としての到達点は同じでも、**途中の見た目がまるで違います**。長いほうを通ると、キャラクターが一回転してから目的の姿勢に落ち着く、という気味の悪い動きになります。

判定は内積の符号ひとつです。

```cpp
// AnimLib/include/anim/QuatInterp.h
#pragma once

#include "anim/Quat.h"

namespace anim {

// b を a と同じ半球へ寄せる。第 8 章の AlignSign と同じ処理だが、
// 補間の文脈では「最短経路を選ぶ」という意味になる。
constexpr Quat ShortestPathTarget(const Quat& a, const Quat& b) {
    return (Dot(a, b) < 0.0f) ? -b : b;
}

}  // namespace anim
```

**この処理を忘れると、アニメーションが「たまに」一回転します。** 「たまに」なのは、キーフレームの符号が偶然揃っていれば問題が出ないからです。データ次第で発現したりしなかったりするので、目視のテストでは非常に見つけにくいバグです。だから、補間するすべての関数の内側でこれを行います。

## 10.3　`Lerp` と `Nlerp`

```cpp
// 成分ごとの線形補間。結果は単位クォータニオンにならない。
// 途中式としてのみ使う。
constexpr Quat Lerp(const Quat& a, const Quat& b, float t) {
    return a * (1.0f - t) + b * t;
}

// 正規化つき線形補間。最短経路を選ぶ。
[[nodiscard]] inline Quat Nlerp(const Quat& a, const Quat& b, float t) {
    const Quat target = ShortestPathTarget(a, b);
    return Normalize(Lerp(a, target, t));
}
```

`Nlerp` は 4 次元空間で 2 点を直線で結び、その途中の点を球面に押し戻します。

- **長さは 1 になる。** 正規化しているので当然です。
- **端点は正確。** `t=0` で `a`、`t=1` で `b`（または `-b`）。
- **最短経路を通る。** 直線が短いほうの側にあるためです。
- **速度が一定ではない。** 直線上を等速で進んでも、球面に射影すると中央付近で速く、端で遅くなります。

最後の点だけが `Nlerp` の欠点です。ただし、この「欠点」がどれくらいの大きさなのかは、あとで数字で確認します。

## 10.4　`Slerp` ―― 球面上を等速で進む

`Slerp`（Spherical Linear Interpolation）は、球面上の弧に沿って**等速で**進みます。

2 つの単位クォータニオンのなす角を `Ω` とすると（`cos Ω = Dot(a, b)`）、

```
Slerp(a, b, t) = ( sin((1-t)Ω) · a + sin(tΩ) · b ) / sin Ω
```

`t=0` で `sin(Ω)·a / sin(Ω) = a`、`t=1` で `b`。そのあいだは、`a` から測った角度がちょうど `tΩ` になります。これが「角速度一定」の意味です。

```cpp
// 球面線形補間。角速度が一定になる。
// Ω が小さいときは sin Ω による除算が不安定になるため Nlerp に切り替える。
[[nodiscard]] inline Quat Slerp(const Quat& a, const Quat& b, float t) {
    Quat target = b;
    float cosOmega = Dot(a, b);

    // 最短経路
    if (cosOmega < 0.0f) {
        target = -b;
        cosOmega = -cosOmega;
    }

    // ほぼ同じ向きなら、直線補間で十分かつ安全
    if (cosOmega > kSlerpLinearThreshold) {
        return Normalize(Lerp(a, target, t));
    }

    // acos の定義域を守る（誤差で 1 をわずかに超えることがある）
    if (cosOmega > 1.0f) { cosOmega = 1.0f; }

    const float omega    = std::acos(cosOmega);
    const float sinOmega = std::sin(omega);
    const float wa = std::sin((1.0f - t) * omega) / sinOmega;
    const float wb = std::sin(t * omega) / sinOmega;
    return a * wa + target * wb;
}
```

```cpp
// これを超えたら Nlerp にフォールバックする。
// cos Ω = 0.9995 は Ω ≈ 1.81 度。この角度差での Nlerp の誤差は
// 0.001 度未満なので、切り替えによる不連続は観測できない。
inline constexpr float kSlerpLinearThreshold = 0.9995f;
```

### 2 つの特異点

`Slerp` には、放置すると壊れる箇所が 2 つあります。

**① `Ω → 0`（2 つの回転がほぼ同じ）。** `sinOmega` がゼロに近づき、ゼロ除算になります。**そしてこれは「めったに起きない」どころか、通常運転です。** 60fps でキャラクターが歩いているとき、隣接するフレームのボーン姿勢はほぼ同じです。フォールバックが必須なのは、このためです。

**② `acos` の定義域。** 数学的には `|Dot(a,b)| ≤ 1` ですが、float の誤差で `1.0000001` になることがあります。`std::acos(1.0000001f)` は NaN です。第 9 章の `asin` と同じ話で、**定義域を持つ関数の前では必ずクランプする**。

そして、このクランプは `/fp:fast` のもとで**消える可能性があります**。第 4 章で予告した「`#pragma float_control(precise, on)` を使う 4 箇所」の 3 つ目がここです。

```cpp
// /fp:fast は「特殊値は起きない」と仮定して比較を畳むことがある。
// クランプが消えると acos が NaN を返し、ポーズ全体が壊れる。
#pragma float_control(precise, on, push)

[[nodiscard]] inline Quat Slerp(const Quat& a, const Quat& b, float t) {
    // （上記の実装）
}

#pragma float_control(pop)
```

> **なぜ `kSlerpLinearThreshold` が `0.9995` なのか**
> `cos Ω = 0.9995` は `Ω ≈ 1.81°`。この角度差での `Nlerp` と `Slerp` の差は 0.001 度未満で、**切り替えによる不連続は原理的に観測できません**。しきい値を下げすぎると `sinOmega` の除算が不安定になり、上げすぎると `Nlerp` の誤差が見え始めます。この値は業界で広く使われている実績値です。

## 10.5　`Nlerp` と `Slerp` はどれくらい違うのか

「`Slerp` のほうが正しいが遅い」とだけ言われがちですが、**どれくらい違うのか**を知らなければ判断できません。測ります。

Z 軸まわりの単位クォータニオンから、指定角度だけ回したクォータニオンへ補間し、`t` を 0 から 1 まで動かしたときの「回転角の最大の食い違い」を求めました。

| 2 つの回転の角度差 | `Nlerp` の最大誤差 | 誤差が最大になる `t` |
| --- | --- | --- |
| 15° | 0.033° | 0.00 |
| 30° | 0.033° | 0.22 |
| 45° | 0.112° | 0.21 |
| 90° | 0.919° | 0.22 |
| 120° | 2.234° | 0.78 |
| 150° | 4.514° | 0.77 |
| 179° | 8.001° | 0.76 |

読み取れることは明確です。

**角度差が 45 度以下なら、`Nlerp` の誤差は 0.12 度未満。** これは見えません。第 4 章で決めた基準（腕の長さ 0.6 m で 0.1 mm）に換算すると、0.12 度は約 1.3 mm。1080p で 1 px 弱です。

**角度差が 90 度を超えると、`Nlerp` は 1 度以上ずれ始める。** 120 度で 2.2 度、179 度で 8 度。ここまで来ると、動きの「ため」や「加速感」として知覚されます。

### 使い分けの基準

この表から、本書の方針を決めます。

| 場面 | 隣接する姿勢の角度差 | 使うもの |
| --- | --- | --- |
| キーフレーム間の補間（第 24 章） | 通常 数度〜数十度 | **`Nlerp`** |
| ポーズのブレンド（第 38 章） | 数度〜90 度 | `Nlerp`（既定）／`Slerp`（選択可） |
| クロスフェード（第 39 章） | 大きくなりうる | **`Slerp`** |
| ブレンドスペース（第 42・43 章） | 大きくなりうる | **`Slerp`** |
| IK の反復（第 48 章） | 極小 | **`Nlerp`** |

キーフレーム補間で `Nlerp` を選べるのは大きな利点です。ここは**アニメーションの計算量の大半を占める**処理だからです。100 ボーン × 1000 体 × 60 fps = 600 万回/秒。`acos` と `sin` を 3 回ずつ呼ぶか呼ばないかは、無視できない差になります。

ただし**この判断はデータに依存します**。24 fps で作られたモーションを 60 fps で再生する場合、キー間の角度差は 2.5 倍になります。速い攻撃モーションでは 1 フレームで 90 度回ることもあります。だから `Clip` には補間方法を選ぶフラグを持たせ（第 24 章）、既定は `Nlerp`、必要なところだけ `Slerp` にできるようにします。

## 10.6　テストを書く

`AnimLib.Tests/QuatInterpTests.cpp`：

```cpp
#include "CppUnitTest.h"

#include "TestSupport/MathAssert.h"
#include "TestSupport/TestRandom.h"
#include "TestSupport/Tolerance.h"

#include "anim/QuatInterp.h"

#include <format>
#include <numbers>

using namespace Microsoft::VisualStudio::CppUnitTestFramework;
using namespace anim;
using anim::test::AssertNear;
using anim::test::AssertSameRotation;

namespace {

constexpr float kPi = std::numbers::pi_v<float>;

// 単位クォータニオンから見た回転角
float AngleOf(const Quat& q) {
    return 2.0f * std::acos(std::fmin(1.0f, std::fabs(q.w)));
}

}  // namespace

namespace AnimLibTests {

TEST_CLASS(QuatInterpTests) {
public:

    // --- 端点 -----------------------------------------------------

    TEST_METHOD(EndpointsAreExact) {
        test::TestRandom rng;
        for (int i = 0; i < 500; ++i) {
            const Quat a = rng.NextQuat();
            const Quat b = rng.NextQuat();
            AssertNear(a, Slerp(a, b, 0.0f), test::kEpsDir);
            AssertNear(a, Nlerp(a, b, 0.0f), test::kEpsDir);
            AssertSameRotation(b, Slerp(a, b, 1.0f), test::kEpsAccum);
            AssertSameRotation(b, Nlerp(a, b, 1.0f), test::kEpsAccum);
        }
    }

    // --- 単位性 ---------------------------------------------------

    TEST_METHOD(ResultsStayUnitLength) {
        test::TestRandom rng;
        for (int i = 0; i < 500; ++i) {
            const Quat a = rng.NextQuat();
            const Quat b = rng.NextQuat();
            for (float t : {0.0f, 0.13f, 0.37f, 0.5f, 0.86f, 1.0f}) {
                anim::test::AssertNear(1.0f, Length(Slerp(a, b, t)), test::kEpsUnit);
                anim::test::AssertNear(1.0f, Length(Nlerp(a, b, t)), test::kEpsUnit);
            }
        }
    }

    // --- 最短経路 -------------------------------------------------

    TEST_METHOD(AlwaysTakesTheShortPath) {
        test::TestRandom rng;
        for (int i = 0; i < 1000; ++i) {
            const Quat a = rng.NextQuat();
            const Quat b = rng.NextQuat();
            // 途中経過はすべて a と同じ半球にあるはず
            for (float t : {0.25f, 0.5f, 0.75f}) {
                Assert::IsTrue(Dot(a, Slerp(a, b, t)) >= -test::kEpsDir);
                Assert::IsTrue(Dot(a, Nlerp(a, b, t)) >= -test::kEpsDir);
            }
        }
    }

    // b を -b に変えても、補間の結果は変わらない
    TEST_METHOD(NegatingTargetDoesNotChangeResult) {
        test::TestRandom rng;
        for (int i = 0; i < 500; ++i) {
            const Quat a = rng.NextQuat();
            const Quat b = rng.NextQuat();
            AssertNear(Slerp(a, b, 0.4f), Slerp(a, -b, 0.4f), test::kEpsAccum);
        }
    }

    // --- 角速度一定（Slerp の存在理由）----------------------------

    TEST_METHOD(SlerpHasConstantAngularVelocity) {
        const Quat a = QuatIdentity();
        const Quat b = MakeQuatAxisAngle({0, 0, 1}, 2.0f);   // 2 ラジアン
        for (int i = 0; i <= 10; ++i) {
            const float t = i / 10.0f;
            anim::test::AssertNear(2.0f * t, AngleOf(Slerp(a, b, t)),
                                   test::kEpsAngle, 1.0e-4f);
        }
    }

    // Nlerp は等速ではない。「ずれること」を明示的に記録する。
    TEST_METHOD(NlerpDeviatesFromConstantVelocity) {
        const Quat a = QuatIdentity();
        const Quat b = MakeQuatAxisAngle({0, 0, 1}, 2.0f);
        const float angleAtQuarter = AngleOf(Nlerp(a, b, 0.25f));
        Logger::WriteMessage(std::format(
            L"nlerp t=0.25: {:.6f} rad (slerp = 0.5 rad)\n", angleAtQuarter).c_str());
        // 等速ではない = 0.5 と一致しない
        Assert::IsTrue(std::fabs(angleAtQuarter - 0.5f) > 0.01f);
    }

    // 使い分けの根拠を、テストとして固定する
    TEST_METHOD(NlerpIsAccurateEnoughForSmallAngles) {
        const Quat a = QuatIdentity();
        const Quat b = MakeQuatAxisAngle({0, 1, 0}, 45.0f * kPi / 180.0f);
        float worstDeg = 0.0f;
        for (int i = 0; i <= 100; ++i) {
            const float t = i / 100.0f;
            const float diff = std::fabs(AngleOf(Nlerp(a, b, t)) - AngleOf(Slerp(a, b, t)));
            worstDeg = std::fmax(worstDeg, diff * 180.0f / kPi);
        }
        Logger::WriteMessage(std::format(L"45deg: worst nlerp error = {:.4f} deg\n",
                                         worstDeg).c_str());
        Assert::IsTrue(worstDeg < 0.2f);   // 実測 0.112 度
    }

    // --- 特異点 ---------------------------------------------------

    TEST_METHOD(NearlyIdenticalQuatsDoNotProduceNaN) {
        test::TestRandom rng;
        for (int i = 0; i < 500; ++i) {
            const Quat a = rng.NextQuat();
            const Quat b = Normalize(Quat{a.x + 1.0e-7f, a.y, a.z, a.w});
            const Quat s = Slerp(a, b, 0.5f);
            Assert::IsFalse(std::isnan(s.x) || std::isnan(s.w));
            anim::test::AssertNear(1.0f, Length(s), test::kEpsUnit);
        }
    }

    TEST_METHOD(IdenticalQuatsAreHandled) {
        const Quat a = MakeQuatAxisAngle({1, 2, 3}, 0.9f);
        AssertNear(a, Slerp(a, a, 0.5f), test::kEpsDir);
        AssertNear(a, Nlerp(a, a, 0.5f), test::kEpsDir);
    }

    // q と -q（真反対）を渡しても壊れないこと
    TEST_METHOD(OppositeQuatsDoNotProduceNaN) {
        test::TestRandom rng;
        for (int i = 0; i < 200; ++i) {
            const Quat a = rng.NextQuat();
            const Quat s = Slerp(a, -a, 0.5f);
            Assert::IsFalse(std::isnan(s.x) || std::isnan(s.w));
            anim::test::AssertNear(1.0f, Length(s), test::kEpsAccum);
        }
    }

    // --- 合成則 ---------------------------------------------------

    // Slerp(a, b, 0.5) を 2 回に分けても同じところに着く
    TEST_METHOD(SlerpIsSubdividable) {
        test::TestRandom rng;
        for (int i = 0; i < 300; ++i) {
            const Quat a = rng.NextQuat();
            const Quat b = rng.NextQuat();
            const Quat direct = Slerp(a, b, 0.5f);
            const Quat viaQuarter = Slerp(Slerp(a, b, 0.25f), Slerp(a, b, 0.75f), 0.5f);
            AssertSameRotation(direct, viaQuarter, test::kEpsAccum);
        }
    }
};

}  // namespace AnimLibTests
```

3 つ、書き方の意図を説明します。

**`NlerpDeviatesFromConstantVelocity`** は、`Nlerp` が**等速でないことを主張する**テストです。奇妙に見えますが、これは仕様の記録です。将来だれかが `Nlerp` を「改良」して `Slerp` と同じにしてしまったら、このテストが落ちて「それは別の関数だ」と教えてくれます。

**`NlerpIsAccurateEnoughForSmallAngles`** は、10.5 節の表の一行をテストとして固定したものです。**判断の根拠をコードに埋め込む**という使い方です。「なぜキーフレーム補間で `Nlerp` を使っているのか」という問いに、このテストが答えます。

**`SlerpIsSubdividable`** は強力な性質テストです。分割して 2 段階で補間しても同じ場所に着く、というのは等速性の言い換えであり、`Slerp` の実装が正しくなければ成り立ちません。

## 10.7　つまずきやすいところ

**アニメーションが「たまに」一回転する**
最短経路の処理が抜けています。`Dot(a, b) < 0` のときに符号を反転しているか確認してください。`AlwaysTakesTheShortPath` が捕まえます。**データ依存で発現するので、目視のテストでは見つかりません。**

**`Slerp` が NaN を返す**
2 つの原因があります。① 引数が単位クォータニオンでない（`Dot` が 1 を大きく超えて `acos` が NaN）。② `sinOmega` がゼロに近い（フォールバックのしきい値が小さすぎる）。前者なら呼び出し元で `Normalize` を、後者なら `kSlerpLinearThreshold` を確認してください。

**`/fp:fast` にしたら `Slerp` が壊れた**
`#pragma float_control(precise, on, push)` を忘れています。`cosOmega > 1.0f` のクランプが最適化で消えた可能性があります。

**フォールバックの境界で動きが飛ぶ**
`kSlerpLinearThreshold` の前後で結果が不連続になっていないか確認してください。`0.9995`（約 1.8 度）なら、`Nlerp` と `Slerp` の差は 0.001 度未満で連続とみなせます。値を大きく変えるとここが破綻します。

**`t` が `[0, 1]` の外に出る**
本書の `Slerp` / `Nlerp` は `t` をクランプしません。外挿（`t > 1`）が意味を持つ場面もあるためです。`Slerp` は外挿でも数学的に妥当な結果を返しますが、`Nlerp` は正規化があるので挙動が直感的でなくなります。**呼び出し側でクランプするのが原則**で、第 26 章の `Clip::Sample` ではそうします。

**ボーンごとに補間方法が違って結果が食い違う**
第 24 章でトラックに補間モードを持たせるとき、`Nlerp` と `Slerp` が混ざります。テストで両者を比較するときは、どちらを使ったかを揃えてください。

## この章のまとめ

- 回転は成分ごとに補間できない。**正規化して球面に戻す（`Nlerp`）か、球面上を等速で進む（`Slerp`）か**。
- 補間の前に必ず**最短経路を選ぶ**（`Dot < 0` なら符号反転）。忘れると「たまに一回転する」という、目視では見つからないバグになる。
- `Slerp` の特異点は 2 つ。**`Ω → 0` は通常運転で起きる**（隣接フレームの姿勢はほぼ同じ）ので `Nlerp` へフォールバックし、**`acos` の前ではクランプ**する。クランプは `#pragma float_control(precise, on)` で守る。
- **`Nlerp` と `Slerp` の差は実測できる。** 角度差 45 度以下なら 0.12 度未満で見えない。90 度で 0.9 度、179 度で 8 度。
- だからキーフレーム補間（計算量の大半）は `Nlerp`、クロスフェードやブレンドスペース（角度差が大きい）は `Slerp`。**判断の根拠をテストとして残す。**

これで回転の道具は揃いました。次章では、平行移動・回転・スケールをまとめた `Transform` を作ります。第 III 部以降、ボーンの姿勢はすべてこの型で表現されます。
