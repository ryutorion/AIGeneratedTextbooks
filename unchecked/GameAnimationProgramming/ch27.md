# 第 27 章　アニメーションプレイヤー

**この章で作るもの**：`ClipPlayer` ―― 毎フレームのデルタタイムを受け取り、再生時刻を進めるもの。第 4 章で見た「`float` の時刻が凍結する」問題に、設計で決着をつけます。

---

## 27.1　第 4 章の宿題

第 4 章で、次のテストを書きました。

```cpp
TEST_METHOD(TimeStopsAdvancingWhenLarge) {
    float t = 1.0e6f;                   // 約 11.6 日
    const float before = t;
    t += 1.0f / 60.0f;
    Assert::IsTrue(t == before, L"時刻が進んでしまった");   // 通る
}
```

`1.0e6` 付近での `float` の刻みは 0.0625。加えようとしている 0.0167 はその半分未満なので、**加算が丸め戻されて何も起きません**。アニメーションが止まります。

第 4 章では対策を 3 つ挙げました。

1. 時刻を絶対値で持たない（クリップ長で折り返す）
2. 長い時間を扱う変数は `double` にする
3. 積算せず、フレーム数から計算する

**この章で 1 と 2 を実装します。**

---

## 27.2　折り返しを 1 か所に閉じ込める

素直に書くと、こうなりそうです。

```cpp
// ⚠ この設計は問題を起こします（27.4 節）
class ClipPlayer {
public:
    void Update(float dt) { time_ += dt * speed_; }
    void Evaluate(Pose& out) const { clip_->Sample(time_, out); }
private:
    float time_ = 0.0f;
};
```

`time_` が単調に増え、`Clip::AdjustTime` が折り返す。動きます。しかし第 4 章の凍結問題がそのまま残りますし、**もっと厄介な問題**が次章で表面化します。

本書の設計は、**プレイヤー自身が折り返しを行い、時刻を常に `[0, duration)` に保つ**ものです。

```cpp
// AnimLib/include/anim/ClipPlayer.h
#pragma once

#include "anim/Clip.h"

namespace anim {

// 1 回の Update で再生時刻がどう動いたか。
// previousTime / currentTime は必ずクリップ内 [0, duration] に折り返し済み。
// loopsCompleted はこのステップで跨いだループ境界の数（逆再生なら負）。
struct PlaybackStep {
    float previousTime   = 0.0f;
    float currentTime    = 0.0f;
    int   loopsCompleted = 0;
    bool  finished       = false;   // Once モードで端に到達した
};

class ClipPlayer {
public:
    void SetClip(const Clip* clip) { clip_ = clip; time_ = 0.0; }
    [[nodiscard]] const Clip* GetClip() const noexcept { return clip_; }

    void SetSpeed(float s) { speed_ = s; }
    [[nodiscard]] float Speed() const noexcept { return speed_; }

    [[nodiscard]] float Time() const noexcept { return static_cast<float>(time_); }
    void SetTime(double t);

    PlaybackStep Update(float deltaSeconds);

    void Evaluate(Pose& out) const;
    void Evaluate(SampleContext& context, Pose& out) const;

private:
    const Clip* clip_ = nullptr;
    double time_ = 0.0;      // 常に [0, duration) に保たれる
    float speed_ = 1.0f;
};

}  // namespace anim
```

```cpp
PlaybackStep ClipPlayer::Update(float deltaSeconds) {
    PlaybackStep step{};
    if (clip_ == nullptr || clip_->Duration() <= 0.0f) {
        return step;
    }

    const double duration = static_cast<double>(clip_->Duration());
    step.previousTime = static_cast<float>(time_);

    double next = time_ + static_cast<double>(deltaSeconds) * static_cast<double>(speed_);
    int loops = 0;

    switch (clip_->GetLoopMode()) {
    case LoopMode::Loop:
        while (next >= duration) { next -= duration; ++loops; }
        while (next < 0.0)       { next += duration; --loops; }
        break;

    case LoopMode::Once:
        if (next >= duration) { next = duration; step.finished = true; }
        if (next < 0.0)       { next = 0.0;      step.finished = true; }
        break;

    case LoopMode::PingPong:
        next = static_cast<double>(clip_->AdjustTime(static_cast<float>(next)));
        break;
    }

    time_ = next;
    step.currentTime    = static_cast<float>(next);
    step.loopsCompleted = loops;
    return step;
}
```

**この設計の要点は 3 つ**あります。

**① 時刻が大きくならない。** 常に `[0, duration)` に折り返されるので、第 4 章の凍結問題が**原理的に起こりません**。クリップの長さが 10 秒なら、時刻が 10 を超えることはありません。

**② 折り返しとループ回数を同じ場所で計算する。** これが決定的に重要です。次章でその理由を痛感することになります。

**③ 呼び出し側に情報を返す。** 「このフレームで何回ループしたか」「Once が終わったか」は、外側が知りたい情報です。ルートモーション（第 28 章）、アニメーションイベント（第 60 章）、ステートマシンの遷移条件（第 45 章）が、すべて `PlaybackStep` を必要とします。

---

## 27.3　なぜ `double` なのか

時刻を折り返すなら、`float` でも足りるはずです。10 秒のクリップなら、`float` の刻みは `1e-6` 程度。60 fps の 0.0167 に対して十分な精度があります。

それでも `double` にしているのは、2 つの理由からです。

**① `Once` モードでは折り返さない。** 10 分のカットシーン（600 秒）を `Once` で再生する場合、`float` の刻みは `6e-5`。0.0167 を足すことはできますが、**300 フレームで 1 ミリ秒ずつ誤差が積もります**。第 4 章で測ったとおり、`float` の積算は思ったより早く壊れます。

**② コストがない。** プレイヤーは 1 体につき 1 つ、時刻は 8 バイト。1000 体でも 8 KB です。頂点の 72 バイト × 10 万個とは桁が違います。**安いところでは安全側に倒す。**

逆に `Transform` を `double` にしないのは、そこが安くないからです（第 4 章）。**「どこで精度を買い、どこで速度を買うか」を意識的に決める**のが設計です。

---

## 27.4　可変フレームレートで結果が変わらないこと

ゲームのフレームレートは一定ではありません。60 fps で動いていたものが、負荷で 45 fps に落ちる。**それでもアニメーションの進み方は同じであるべき**です。

`time += dt * speed` という積算は、この要求を満たします。フレーム数によらず、経過した実時間の合計が同じなら、同じ時刻に到達します ―― 浮動小数点の誤差を除けば。

測りました。1 秒のクリップを 10 秒ぶん再生します。

| 更新の仕方 | 到達した時刻 | ループ回数 |
| --- | --- | --- |
| 固定 60 fps（1/60 秒 × 600 回） | 0.000001 | 10 |
| 可変（5〜50 ms のランダム） | 0.000001 | 10 |

**一致しました。** ループ回数も両方 10 回です。

`double` で積算しているので、10 秒程度では誤差が見えません。第 4 章で `float` の積算が 28 分で 2 秒ずれたのとは対照的です。

> **可変フレームレートで「一致する」とは何か**
> 厳密には、`dt` の分割の仕方が変われば浮動小数点の丸め方も変わるので、ビット単位の一致は保証されません。ここで確かめているのは「**知覚できる差が出ないこと**」です。テストの許容誤差も、それに合わせて `2e-3` 秒（0.12 フレーム）にしてあります。
> なお、**リプレイやネットワーク同期で厳密な再現性が必要な場合は、固定タイムステップにする**のが定石です。可変フレームレートと厳密な決定性は両立しません。

## 27.5　再生速度

`speed_` は単なる乗数です。

```
speed = 1.0   等速
speed = 2.0   倍速
speed = 0.5   半分の速さ
speed = 0.0   停止（ポーズ）
speed = -1.0  逆再生
```

**負の速度**が正しく動くことが、実装の質を測る良い指標になります。第 25 章のヒント探索の逆再生対応、第 26 章の `fmod` の符号補正 ―― どちらもここで初めて実際に使われます。

```cpp
ClipPlayer player;
player.SetClip(&clip);          // 1 秒のクリップ
player.SetSpeed(-1.0f);
player.Update(0.25f);
// time_ = 0.75（0 から 0.25 秒ぶん戻って折り返した）
```

`loopsCompleted` は `-1` になります。**符号があることに意味がある**ので、絶対値を取らないでください。第 28 章のルートモーションでは、負のループ回数が「後ろ向きに 1 周した」を意味します。

### 速度をアニメーションに使う

再生速度は、しばしばゲームプレイと連動します。

```cpp
// 移動速度に応じて歩行アニメーションの再生速度を変える
const float walkCycleSpeed = characterSpeed / kWalkCycleDistance;
player.SetSpeed(walkCycleSpeed);
```

これは**足滑り（foot sliding）を防ぐ**基本的な手法です。第 42 章のブレンドスペースと組み合わせるのが実務での定番で、第 62 章の総合演習で扱います。

## 27.6　`Once` モードの終了通知

`finished` フラグは、`Once` モードで端に到達したフレームだけ `true` になります。

```cpp
const PlaybackStep step = player.Update(dt);
if (step.finished) {
    // 攻撃モーションが終わった → 待機に戻る
    stateMachine.RequestTransition("Idle");
}
```

**「到達したフレームだけ」**である点に注意してください。到達後も `Update` を呼び続けると、2 回目以降は `next >= duration` の条件が既に満たされているため……実は毎フレーム `true` になります。

これは意図した動作です。**「終わっている」状態を毎フレーム知れるほうが、呼び出し側の実装が単純になる**からです。「終わった瞬間」だけを知りたいなら、呼び出し側で前フレームの状態と比較してください。

一方で「終わった瞬間だけ通知してほしい」という要求も自然です。第 45 章のステートマシンでは、`finished` を遷移条件として扱い、遷移が起きれば別のクリップに切り替わるので、この曖昧さは表面化しません。**曖昧さが問題にならない設計にする**のも一つの解決です。

#include "TestSupport/MathAssert.h"

using namespace Microsoft::VisualStudio::CppUnitTestFramework;

namespace {

// 1 秒で +X に 1 m 進む、ループするクリップ
Clip MakeUnitClip() {
    Clip c;
    c.Resize(1);
    c.SetDuration(1.0f);
    c.SetLoopMode(LoopMode::Loop);
    c.Bone(0).translation.AddKey(0.0f, {0, 0, 0});

namespace AnimLibTests {

TEST_CLASS(ClipPlayerTests) {
public:

    TEST_METHOD(TimeAdvancesWithDeltaTime) {
        const Clip c = MakeUnitClip();
        ClipPlayer p;
        p.SetClip(&c);

        p.Update(0.25f);
        anim::test::AssertNear(0.25f, p.Time(), test::kEpsPos);
        p.Update(0.25f);
        anim::test::AssertNear(0.50f, p.Time(), test::kEpsPos);

    // 時刻は常にクリップ内に収まること（27.2 節）
    TEST_METHOD(TimeNeverGrowsBeyondDuration) {

    TEST_METHOD(LongPlaybackKeepsAdvancing) {
        const Clip c = MakeUnitClip();

        const Clip c = MakeUnitClip();

        p.SetClip(&c);

    TEST_METHOD(DoubleSpeedWrapsTwicePerSecond) {
        const Clip c = MakeUnitClip();

        p.SetClip(&c);
        p.SetSpeed(2.0f);

        int loops = 0;
        for (int i = 0; i < 60; ++i) {
            loops += p.Update(1.0f / 60.0f).loopsCompleted;

        Assert::AreEqual(2, loops);

    TEST_METHOD(ZeroSpeedFreezes) {

        p.SetClip(&c);

        p.SetSpeed(0.0f);

    TEST_METHOD(FixedAndVariableFrameRatesAgree) {
        const Clip c = MakeUnitClip();

        ClipPlayer fixedRate;
        fixedRate.SetClip(&c);

        Assert::IsFalse(p.Update(0.5f).finished);

        p.SetClip(&c);

        const PlaybackStep step = p.Update(5.5f);

    TEST_METHOD(NoClipIsSafe) {
        ClipPlayer p;
        const PlaybackStep step = p.Update(1.0f);
        Assert::AreEqual(0, step.loopsCompleted);
        Assert::IsFalse(step.finished);

## 27.8　つまずきやすいところ

**長時間再生するとアニメーションが止まる**
時刻を折り返していません。27.2 節の設計にしてください。`Clip::AdjustTime` に折り返しを任せて `time_` を増やし続ける実装だと、第 4 章の凍結問題が残ります。

**フレームレートが落ちるとアニメーションが遅くなる**
`dt` を使わず、フレームごとに固定量を足しています。`time_ += dt * speed_` になっているか確認してください。

**逆再生でループ回数が 0 になる**
`while (next < 0.0)` の側で `--loops` を忘れています。

**大きな `dt` で 1 回しかループしない**
`if` で 1 回だけ引いています。`while` にしてください。ロード直後やブレークポイントの後に、`dt` が数秒になることは実際にあります。

**`finished` が毎フレーム `true` になる**
仕様です（27.6 節）。「終わった瞬間」が必要なら、呼び出し側で前フレームと比較してください。

**リプレイが再現しない**
可変フレームレートでは、浮動小数点の丸め方が実行ごとに変わります。厳密な再現性が必要なら固定タイムステップにしてください（27.4 節のコラム）。

## この章のまとめ

- **時刻を常に `[0, duration)` に折り返す。** これで第 4 章の凍結問題が原理的に消える。100000 フレーム（28 分）回しても正しく進み続ける。
- 時刻は **`double`**。折り返せば `float` でも足りるが、`Once` モードの長いクリップのためと、**安いから**。「どこで精度を買うか」を意識的に決める。
- **折り返しとループ回数を同じ場所で計算し、`PlaybackStep` として返す。** この設計の意味は次章で明らかになる。
- **固定 60 fps と可変フレームレートで結果が一致する**ことを実測で確認（到達時刻・ループ回数とも）。ただし厳密な再現性が要るなら固定タイムステップにする。
- **負の速度**が正しく動くことは、実装の質を測る良い指標。第 25 章のヒント探索の逆再生対応、第 26 章の `fmod` の符号補正が、ここで初めて実際に使われる。
- `loopsCompleted` の**符号には意味がある**。絶対値を取らないこと。

次章、この `PlaybackStep` がなぜこの形なのかを、実際に踏んだバグとともに説明します。
