# 第 47 章　2 ボーン IK

**この章で作るもの**：肩・肘・手首、あるいは腿・膝・足首 ―― ボーン 2 本の連鎖を、**反復なしの解析解**で目標に合わせるソルバ。ゲームで最もよく使う IK です。

---

## 47.1　なぜ 2 ボーンだけ特別扱いするのか

第 48 章の CCD、第 49 章の FABRIK は、任意の長さのチェーンを扱える汎用ソルバです。当然、2 ボーンにも使えます。

それでも 2 ボーンを別立てにする理由は 3 つあります。

**① 一発で解ける。** 反復も収束判定も要りません。三角形の三辺が分かれば角度が決まる ―― 余弦定理そのものです。速度は反復ソルバの数分の一で、しかも**結果が完全に決定的**です。

**② 曲がる向きを直接指定できる。** 肘や膝は、生き物として曲がる向きが決まっています。反復ソルバは「エフェクタが目標に届く」ことしか気にしないので、放っておくと膝が逆に曲がります（第 50 章で実測します）。2 ボーン IK は**極ベクトル**という追加の入力で、曲がる向きを明示的に指定します。

**③ 実務でこれしか要らないことが多い。** 腕、脚、指。ゲームの IK の大半は 2 ボーンです。

---

## 47.2　問題を三角形にする

チェーンは 3 つの関節でできています。

```
    A ────────── B
     ＼   l1     ／
      ＼        ／ l2
       ＼      ／
        ＼    ／
         ＼  ／
          ＼／
           C  ← エフェクタ（手首・足首）

    A: 根元（肩・股関節）
    B: 中間（肘・膝）
    C: 末端（手首・足首）
```

- `l1 = |B - A|`：上腕（腿）の長さ
- `l2 = |C - B|`：前腕（すね）の長さ

**この 2 つは IK の前後で変わりません。** ボーンの長さはローカル変換の平行移動成分で決まっていて、IK は回転しか触らないからです。第 1 章で挙げた「性質のテスト」の代表例です。

目標を **T** とします。`d = |T - A|` としたとき、三角形 A-B-T の三辺は `l1`、`l2`、`d`。三辺が分かっているので、**すべての角が決まります**。

余弦定理より、A における角 α（A→T 方向と A→B 方向のなす角）は、

```
l2² = l1² + d² − 2·l1·d·cos α

           l1² + d² − l2²
cos α = ────────────────────
             2·l1·d
```

これで「肘が根元からどれだけ横にずれるか」が決まりました。

---

## 47.3　残った自由度 ―― 極ベクトル

しかし、まだ答えは 1 つに決まっていません。

三角形 A-B-T は、**A-T を軸としてぐるりと一周、どこにでも置けます**。円錐の側面をなぞるように、肘は無数の位置を取れる。

```
             B'
            ／|
     B ────/  |     ← A-T 軸まわりに肘が回る
      ＼   \  |
       ＼   \ |
    A ───────T
             |\
             | \
             B''
```

この自由度を **極ベクトル（Pole Vector）** で潰します。

> **極ベクトル P** は、「肘をこちらの方向へ向けたい」という点。A、T、P の 3 点が作る平面が、腕の曲がる平面になる。

人間の腕なら、肘は後ろへ向きます。歩行キャラクターの膝なら、前へ向きます。ゲームでは通常、**キャラクターに追従する補助ボーン**を極ベクトルとして持たせます（`elbowPoleL` のような名前のボーンをリグに仕込む）。

実装では、A→T 方向 `dir` に直交する成分を極ベクトルから取り出します。

```
poleDir = P − A
perp    = poleDir − dir · (poleDir · dir)     ← dir 成分を引き去る
perp    = normalize(perp)
```

`dir` と `perp` は直交する単位ベクトルの組で、これが**曲げ平面の 2 軸**になります。この平面の上で、A から角 α、距離 `l1` の点が肘の新しい位置です。

```
newB = A + dir·(l1·cos α) + perp·(l1·sin α)
```

## 47.4　届かないとき、近すぎるとき

`cos α` の分母や `acos` に入る値は、`d` の大きさによっては壊れます。

**遠すぎる場合。** `d > l1 + l2` なら、腕をまっすぐ伸ばしても届きません。`cos α` の分子は `l1² + d² − l2²`、分母は `2·l1·d`。`d` が大きいと分子が分母を超え、`cos α > 1` になります。

**近すぎる場合。** `d < |l1 − l2|` なら、腕を完全に折りたたんでも遠すぎます。今度は `cos α < −1`。

どちらも `acos` に渡せば NaN です。ここでは `acos` を使いませんが（`cos α` と `sin α` を直接使う手もあります）、いずれにせよ**この 2 つの限界を明示的に扱う**必要があります。

対処は「目標を**到達可能な範囲へ引き寄せる**」。

```cpp
const float minReach = std::fabs(l1 - l2) + epsilon;
const float maxReach = l1 + l2 - epsilon;
const bool  reachable = (dist >= minReach && dist <= maxReach);
dist = std::fmin(maxReach, std::fmax(minReach, dist));
```

目標そのものは動かしません。**A から目標へ向かう「距離」だけをクランプ**します。方向はそのまま。結果として、届かない目標に対しては「その方向へ精一杯伸ばした」姿勢が出ます。これは絵として自然です。

**`epsilon` を足し引きしているのはなぜか。** `dist` をちょうど `l1 + l2` にすると、腕は完全に一直線になります。すると `sin α = 0` で肘は軸上に乗り、**次のフレームで曲げ平面が決まらなくなります**（`perp` を作るための情報が消える）。1e-4 だけ内側に置いておくと、ごくわずかに曲がった状態が保たれ、極ベクトルによる制御が生き続けます。

このイプシロンは**測定できる形で表に出ます**。後で、平らな床の上に立ったキャラクターの足首が `0.100000` ではなく `0.100100` になるのを見ます（第 51 章）。0.1 mm の誤差ですが、**なぜそこにあるかを知っている誤差**です。

## 47.5　実装

```cpp
// AnimLib/include/anim/Ik.h（追記）

struct TwoBoneIkResult {
    bool  reached  = false;   // クランプなしで届いたか
    float residual = 0.0f;    // エフェクタと目標の距離
};

inline TwoBoneIkResult SolveTwoBoneIk(const Skeleton& s, Pose& local,
                                      std::vector<Transform>& global,
                                      BoneIndex upper, BoneIndex mid, BoneIndex effector,
                                      Vec3 target, Vec3 pole,
                                      float epsilon = 1.0e-4f) {
    ComputeGlobalPose(s, local.Locals(), global);
    const Vec3 a = global[upper   ].translation;
    const Vec3 b = global[mid     ].translation;
    const Vec3 c = global[effector].translation;

    const float l1 = Length(b - a);
    const float l2 = Length(c - b);
    if (l1 < epsilon || l2 < epsilon) return {false, Length(target - c)};

    // --- 到達距離のクランプ ---
    const Vec3 toTarget = target - a;
    float dist = Length(toTarget);
    const float minReach = std::fabs(l1 - l2) + epsilon;
    const float maxReach = l1 + l2 - epsilon;
    const bool reachable = (dist >= minReach && dist <= maxReach);
    dist = std::fmin(maxReach, std::fmax(minReach, dist));
    const Vec3 dir = NormalizeSafe(toTarget, NormalizeSafe(c - a, {1,0,0}));

    // --- 曲げ平面を決める ---
    Vec3 poleDir = pole - a;
    Vec3 perp = poleDir - dir * Dot(poleDir, dir);
    if (LengthSquared(perp) < 1.0e-8f) {
        // 極ベクトルが dir と平行：現在の曲がり方向を使う
        const Vec3 currentBend = (b - a) - dir * Dot(b - a, dir);
        perp = (LengthSquared(currentBend) > 1.0e-8f) ? currentBend
                                                      : Cross(dir, Vec3{0,1,0});
        if (LengthSquared(perp) < 1.0e-8f) perp = Cross(dir, Vec3{1,0,0});
    }
    perp = Normalize(perp);

    // --- 余弦定理で中間関節の位置を直接求める ---
    const float cosAlpha = std::fmin(1.0f, std::fmax(-1.0f,
        (l1*l1 + dist*dist - l2*l2) / (2.0f * l1 * dist)));
    const float alpha = std::acos(cosAlpha);
    const Vec3 newB = a + dir * (l1 * std::cos(alpha)) + perp * (l1 * std::sin(alpha));
    const Vec3 newC = a + dir * dist;

    // --- 位置から回転へ ---
    const Quat deltaUpper = FromToRotation(b - a, newB - a);
    SetGlobalRotation(s, local, global, upper, deltaUpper * global[upper].rotation);
    ComputeGlobalPose(s, local.Locals(), global);

    const Vec3 b2 = global[mid     ].translation;
    const Vec3 c2 = global[effector].translation;
    const Quat deltaMid = FromToRotation(c2 - b2, newC - b2);
    SetGlobalRotation(s, local, global, mid, deltaMid * global[mid].rotation);
    ComputeGlobalPose(s, local.Locals(), global);

    return {reachable, Length(target - global[effector].translation)};
}
```

3 か所、設計判断を書いておきます。

**① 角度ではなく位置を求めている。** 教科書的な 2 ボーン IK は「A の回転角を α だけ変える、B の回転角を β にする」と角度で書きます。ここでは**肘の位置 `newB` と手首の位置 `newC` を先に求め、あとから `FromToRotation` で回転に変換**しています。

こうする理由は、**縮退への強さ**です。角度で書くと「どの軸まわりに α 回すか」を毎回決める必要があり、腕が伸びきった状態や `l1 == l2` の場合に軸が消えます。位置を先に決めてしまえば、あとは第 46 章の `FromToRotation` に任せられ、あの関数はすでに縮退を扱えます。**一度きちんと作った道具に難しい仕事を寄せる**のが、コードを小さく保つコツです。

**② `cos(acos(x))` を書いている。** `cosAlpha` を求めてから `acos` して、また `cos` を取っています。冗長です ―― `cos α` はもう手元にあるのだから、`sin α = sqrt(1 - cos²α)` で足りる。

```cpp
const float sinAlpha = std::sqrt(std::fmax(0.0f, 1.0f - cosAlpha*cosAlpha));
const Vec3 newB = a + dir * (l1 * cosAlpha) + perp * (l1 * sinAlpha);
```

こちらのほうが速く、精度も落ちません（`sin α ≥ 0` は α ∈ [0, π] から保証されます）。書籍のコードとしては `acos` 版のほうが「α という角度を求めている」ことが読み取りやすいので残しますが、**実装するなら平方根版を選んでください**。

**③ `ComputeGlobalPose` を 3 回呼んでいる。** 上腕を回したら肘と手首の位置が変わるので、前腕を回す前に再計算が要ります。第 46 章に書いた「`SetGlobalRotation` を呼ぶ前に `global[]` は最新であること」の実践です。骨格全体を 3 回なめるのは無駄に見えますが、2 ボーン IK はそもそも安いので、まずは素直に書きます（第 48 章でこのコストを測ります）。

## 47.6　単体テスト：手計算との照合

第 1 章で挙げた 4 種類のテストのうち、**① 手計算との照合**から始めます。

`l1 = 2`、`l2 = 1.5`、原点に肩、`+X` 方向に伸びた腕。目標を `(2, 1, 0)` とします。

紙の上で解きます。

```
d = |(2,1,0)| = √5 = 2.2360680

cos α = (2² + 5 − 1.5²) / (2 · 2 · 2.2360680)
      = (4 + 5 − 2.25) / 8.944272
      = 6.75 / 8.944272 = 0.7546
sin α = 0.6562

dir  = (2,1,0)/√5 = (0.894427, 0.447214, 0)
極 P = (2,5,0) → poleDir = (2,5,0)
       poleDir·dir = 1.788854 + 2.236068 = 4.024922
       perp = (2,5,0) − dir·4.024922 = (−1.6, 3.2, 0)
            → normalize = (−0.447214, 0.894427, 0)

newB = dir·(2·0.7546) + perp·(2·0.6562)
     = (1.3499, 0.6749, 0) + (−0.5869, 1.1738, 0)
     = (0.7630, 1.8487, 0)
```

コードの出力です。

```
届く目標 (2,1,0): reached=1 residual=0.000000400
肘の位置: (0.763165, 1.848670, 0.000000)
```

紙とコードが一致しました。手計算のほうは有効数字 4〜5 桁で丸めながら進めたので、下 4 桁のずれは私の暗算の精度です。

```cpp
TEST_CLASS(TwoBoneIkTests) {
    static Skeleton MakeArm(float l1, float l2) {
        Skeleton s;
        Transform t = TransformIdentity();
        s.AddBoneRaw("shoulder", kNoParent, t);
        t.translation = {l1,0,0};  s.AddBoneRaw("elbow", 0, t);
        t.translation = {l2,0,0};  s.AddBoneRaw("hand",  1, t);
        return s;
    }
public:
    TEST_METHOD(ReachesTargetExactly) {
        Skeleton s = MakeArm(2.0f, 1.5f);
        Pose p = Pose::FromRest(s);
        std::vector<Transform> g(s.BoneCount());

        const auto r = SolveTwoBoneIk(s, p, g, 0, 1, 2, {2,1,0}, {2,5,0});

        Assert::IsTrue(r.reached);
        Assert::IsTrue(r.residual < 1e-4f);
        Assert::AreEqual(0.763165f, g[1].translation.x, 1e-5f);
        Assert::AreEqual(1.848670f, g[1].translation.y, 1e-5f);
    }
};
```

肘の座標を**ゴールデン値として固定**しています（第 1 章の ④）。将来 `FromToRotation` を書き換えたり、`acos` を平方根に置き換えたりしたときに、この数字がずれたら気づけます。

## 47.8　単体テスト：極ベクトルが曲がる向きを決める

これが 2 ボーン IK の存在意義なので、3 方向で確かめます。

```cpp
TEST_METHOD(PoleVectorControlsBendDirection) {
    Skeleton s = MakeArm(2.0f, 1.5f);
    std::vector<Transform> g(s.BoneCount());

    Pose up = Pose::FromRest(s);
    SolveTwoBoneIk(s, up, g, 0,1,2, {2,1,0}, {2, 5,0});
    Assert::IsTrue(g[1].translation.y > 0.0f);        // 肘は上へ

    Pose down = Pose::FromRest(s);
    SolveTwoBoneIk(s, down, g, 0,1,2, {2,1,0}, {2,-5,0});
    Assert::IsTrue(g[1].translation.y < 0.0f);        // 肘は下へ

    Pose fwd = Pose::FromRest(s);
    SolveTwoBoneIk(s, fwd, g, 0,1,2, {2,1,0}, {2,1,5});
    Assert::IsTrue(g[1].translation.z > 0.0f);        // 肘は +Z へ
}
```

実測値です。目標はすべて `(2,1,0)` で同じ ―― **手首の位置は 3 通りとも同じ**なのに、肘だけが動いています。

| 極ベクトル | 肘の位置 | 残差 |
|---|---|---|
| `(2, 5, 0)` | `(0.763165, 1.848670, 0.000000)` | `0.000000400` |
| `(2, −5, 0)` | `(1.936835, −0.498670, 0.000000)` | `0.000000492` |
| `(2, 1, 5)` | `(1.350000, 0.675000, 1.312202)` | ― |

3 つ目の `x = 1.350000` は、`dir·(l1·cos α) = 0.894427 × 1.509` の X 成分にぴったり一致します（極が `dir` にほぼ直交する `+Z` 方向なので、肘は `dir` 成分 + `Z` 成分だけになる）。

## 47.9　単体テスト：届かない目標

```cpp
TEST_METHOD(UnreachableTargetFullyExtends) {
    Skeleton s = MakeArm(2.0f, 1.5f);
    Pose p = Pose::FromRest(s);

}

TEST_METHOD(TooCloseTargetFullyFolds) {
    Skeleton s = MakeArm(2.0f, 1.5f);
    Pose p = Pose::FromRest(s);
    std::vector<Transform> g(s.BoneCount());

    const auto r = SolveTwoBoneIk(s, p, g, 0,1,2, {0.1f,0,0}, {0,5,0});

    Assert::IsFalse(r.reached);

```

測定値：

```
届かない目標 (10,0,0): reached=0 residual=6.500100 （期待 6.500000）
近すぎる目標 (0.1,0,0): reached=0 residual=0.400099 （期待 0.400000）
```

**`0.0001` のずれは、47.4 で入れた `epsilon` そのものです。** 期待どおりの誤差が、期待どおりの大きさで出ています。「なぜかちょっとずれる」のではなく「1e-4 入れたから 1e-4 ずれる」。**説明できない誤差を残さない**のが、この本の方針です。

## 47.10　単体テスト：縮退した入力

極ベクトルが `dir` と平行な場合 ―― つまり「肘をどちらへ向けるか」の情報がまったくない場合です。

```cpp
TEST_METHOD(DegeneratePoleDoesNotBlowUp) {
    Skeleton s = MakeArm(2.0f, 1.5f);
    Pose p = Pose::FromRest(s);
    std::vector<Transform> g(s.BoneCount());

    // 目標も極も、腕が伸びている方向そのもの
    const auto r = SolveTwoBoneIk(s, p, g, 0,1,2, {3.5f,0,0}, {3.5f,0,0});

    Assert::IsTrue(std::isfinite(r.residual));
    Assert::IsTrue(r.residual < 1e-3f);
}
```

実測：`residual=0.000099659`、肘の `y = 0.000000000`。

NaN も無限大も出ていません。極が使えないので `currentBend` へフォールバックしますが、レストポーズでは腕が一直線なので `currentBend` もゼロ。最後の砦 `Cross(dir, {0,1,0})` が効いて、肘は `XZ` 平面のどこかに落ち着きます。残差は例のイプシロン。

**縮退のテストは「正しい答え」を主張しません。** 主張するのは「壊れない」ことだけです。この場合、肘がどこを向くかは**そもそも決まっていない**（入力に情報がない）ので、特定の値を期待するテストを書くと、実装の詳細を固定してしまいます。

## 47.11　単体テスト：ランダムな目標を掃く

最後に、到達可能な範囲のランダムな目標を大量に投げます。

```cpp
TEST_METHOD(RandomReachableTargetsAlwaysConverge) {
    Skeleton s = MakeArm(2.0f, 1.5f);
    std::vector<Transform> g(s.BoneCount());
    unsigned seed = 999;
    auto rnd = [&] { seed = seed*1664525u + 1013904223u;
                     return static_cast<float>((seed>>8)&0xFFFF)/32767.5f - 1.0f; };

    float worst = 0.0f;
    int n = 0;
    for (int i = 0; i < 1000; ++i) {
        const Vec3 tgt{rnd()*3.0f, rnd()*3.0f, rnd()*3.0f};
        const float d = Length(tgt);
        if (d < 0.55f || d > 3.45f) continue;          // 到達範囲の内側だけ
        Pose p = Pose::FromRest(s);
        worst = std::fmax(worst, SolveTwoBoneIk(s,p,g,0,1,2,tgt,{0,5,0}).residual);
        ++n;
    }
    Logger::WriteMessage(std::format("{} 目標、最大残差 {:.9f}\n", n, worst).c_str());
    Assert::IsTrue(worst < 1e-4f);
}
```

実測：**752 目標、最大残差 `0.000003538`**。

1000 個投げて 752 個が範囲内。残りは近すぎるか遠すぎるかで、そちらは前のテストが担当します。

## 47.12　実際に使うときの注意

**極ベクトルはどこから来るか。** 実務では 3 通りです。

1. **リグに補助ボーンを仕込む。** `elbowPoleL` のようなボーンをアニメーションデータに含め、クリップと一緒に動かす。最も自由度が高く、アーティストが制御できる。
2. **腰や胸のボーンから計算する。** 「胸の後ろ 50cm」のようなオフセットで済ませる。安上がりだが、極端なポーズで破綻する。
3. **現在のポーズから取る。** IK 適用前の肘の位置をそのまま極として使う。「アニメーションが作った曲がり方を尊重しつつ、手先だけ動かす」動作になり、多くの場合これが最も自然。

3 番目は、コードでは `pole = 現在の global[mid].translation` を渡すだけです。上のコードの `currentBend` フォールバックは、実質これと同じことをしています。

**IK の効き具合をブレンドしたい。** 「IK を 30% だけ効かせる」は、第 38 章の `BlendPose` で書けます。

```cpp
Pose animated = /* アニメーションの結果 */;
Pose corrected = animated;
SolveTwoBoneIk(s, corrected, g, thigh, shin, foot, target, pole);
BlendPose(animated, corrected, weight, out);   // weight ∈ [0,1]
```

IK の入り/切りを瞬間的に行うと、必ずポップします。**必ず 0.1〜0.3 秒程度かけてブレンドする**。第 51 章では、これを時間方向の平滑化という形で組み込みます。

## この章のまとめ

- 2 ボーン IK は**余弦定理で一発で解ける**。反復も収束判定も要らず、結果が決定的。
- 残る 1 自由度（A-T 軸まわりの回転）は**極ベクトル**で決める。極 P と A、T の 3 点が曲げ平面を作る。**目標が同じでも極を変えれば肘だけが動く**（実測：肘 `y = +1.85` / `−0.50` / `z = +1.31`）。
- 届かない・近すぎる目標は、**距離だけをクランプ**して方向は保つ。「精一杯伸ばす／折りたたむ」姿勢が自然に出る。
- クランプに `epsilon = 1e-4` を入れるのは、**腕が完全に伸びきると曲げ平面が決まらなくなる**から。この 1e-4 は残差として観測される（実測 `6.500100`、`0.400099`）。**説明できない誤差を残さない。**
- **角度ではなく位置を先に求め、`FromToRotation` で回転に変換する。** 縮退の処理を第 46 章の道具に寄せられ、コードが小さくなる。
- `cos(acos(x))` は `sqrt(1−x²)` で置き換えられる。書籍では意図を優先して `acos` を残したが、**実装は平方根版を選ぶ**。
- 縮退のテストは「正しい答え」ではなく「**壊れないこと**」だけを主張する。入力に情報がないなら、出力を固定してはいけない。

次章では、任意の長さのチェーンを扱える **CCD** を書きます。そして ―― この章では何事もなく動いた `FromToRotation` と `SetGlobalRotation` が、**反復ソルバの中では 2 つのバグを抱えていた**ことが分かります。
