# 第 45 章　ステートマシン

**この章で作るもの**：アニメーションの遷移をデータとして表現する仕組み。第 VII 部の総仕上げです。そして最後に、**この章を書きながら踏んだバグ**を記録します。

---

## 45.1　遷移をデータで表す

第 39 章のクロスフェードは、「いつ、何へ遷移するか」を呼び出し側が決めていました。

```cpp
if (speed > 0.1f && currentState == State::Idle) {
    crossFade.CrossFade(&walkClip, 0.2f);
    currentState = State::Walk;
}
if (speed > 3.0f && currentState == State::Walk) {
    crossFade.CrossFade(&runClip, 0.2f);
    currentState = State::Run;
}
// ... 状態が増えるたびに if が増える
```

状態が 10 個になれば、遷移は最大 90 通り。**`if` の網では管理できません。**

**ステートマシン**は、これを**状態と遷移のリスト**として表現します。

```
    ┌──────┐  speed > 0.1  ┌──────┐  speed > 3.0  ┌──────┐
    │ Idle │ ────────────→ │ Walk │ ────────────→ │ Run  │
    └──────┘ ←──────────── └──────┘ ←──────────── └──────┘
                speed ≤ 0.1              speed ≤ 3.0
        ↑
        │  finished
    ┌──────┐
    │ Wave │ ← Any State（trigger "wave"）
    └──────┘
```

データにできれば、**ツールで編集でき、ファイルに保存でき、コードを変えずに調整できます**。

## 45.2　状態と遷移

```cpp
// AnimLib/include/anim/StateMachine.h
#pragma once

#include "anim/BlendTree.h"
#include "anim/ClipPlayer.h"

#include <functional>
#include <string>
#include <unordered_map>

namespace anim {

// 遷移条件で参照するパラメータ。ゲームロジックが毎フレーム設定する。
class StateMachineParams {
public:
    void SetFloat(std::string_view name, float value) { floats_[std::string(name)] = value; }
    void SetBool(std::string_view name, bool value)   { bools_[std::string(name)] = value; }
    void SetTrigger(std::string_view name)            { triggers_[std::string(name)] = true; }

    [[nodiscard]] float GetFloat(std::string_view name) const;
    [[nodiscard]] bool GetBool(std::string_view name) const;

    // トリガーは 1 度だけ消費される（45.3 節）
    [[nodiscard]] bool ConsumeTrigger(std::string_view name);

private:
    std::unordered_map<std::string, float> floats_;
    std::unordered_map<std::string, bool> bools_;
    std::unordered_map<std::string, bool> triggers_;
};

struct Transition {
    int from = -1;                  // -1 = Any State（45.4 節）
    int to = 0;
    float duration = 0.2f;          // フェード時間
    bool waitForFinish = false;     // 遷移元が最後まで再生されるのを待つ
    std::function<bool(StateMachineParams&)> condition;
};

class StateMachine {
public:
    int AddState(std::string name, const Clip* clip);
    void AddTransition(Transition transition);

    void Start(int state);
    void Update(float deltaSeconds, StateMachineParams& params);
    void Evaluate(Pose& out, Pose& scratch) const;

    [[nodiscard]] int Current() const noexcept { return current_; }
    [[nodiscard]] bool IsBlending() const noexcept { return blending_; }
    [[nodiscard]] float BlendWeight() const noexcept {
        return blending_ ? (static_cast<float>(elapsed_) / duration_) : 0.0f;
    }

private:
    struct State { std::string name; const Clip* clip; };

    std::vector<State> states_;
    std::vector<Transition> transitions_;

    int current_ = 0;
    int next_ = 0;
    double time_ = 0.0;          // current_ の再生時刻
    double nextTime_ = 0.0;      // next_ の再生時刻
    double elapsed_ = 0.0;       // 遷移の経過時間
    float duration_ = 0.2f;
    bool blending_ = false;
};

}  // namespace anim
```

**遷移条件を `std::function` にしている**のは、本書の範囲を絞るためです。実務では「パラメータ名 + 比較演算子 + 閾値」という構造体にしてデータ化しますが、その変換はこの章の本題ではありません。

## 45.3　パラメータの 3 種類

**`float`** ―― 移動速度、体力、傾き。閾値との比較に使います。

**`bool`** ―― 接地しているか、武器を構えているか。状態を表します。

**`trigger`** ―― ジャンプボタンが押された、攻撃コマンドが入力された。**イベント**を表します。

トリガーだけ扱いが違います。**一度消費されたら消える**のです。

```cpp
bool StateMachineParams::ConsumeTrigger(std::string_view name) {
    const auto it = triggers_.find(std::string(name));
    if (it == triggers_.end() || !it->second) { return false; }
    it->second = false;      // 消費
    return true;
}
```

`bool` で「ジャンプボタンが押された」を表すと、**次のフレームで下ろし忘れると何度もジャンプします**。トリガーなら、遷移が 1 回起きた時点で消えます。

**「消費される」という性質が、イベントを正しく扱うための鍵**です。

## 45.4　Any State

「どの状態からでも、被弾したらリアクションへ遷移する」。これを個別の遷移で書くと、状態の数だけ必要になります。

`from = -1` を **Any State** として扱います。

```cpp
for (const Transition& t : transitions_) {
    const int source = blending_ ? next_ : current_;
    if (t.from >= 0 && t.from != source) { continue; }   // ← -1 なら常に通る
    if (t.to == source) { continue; }                    // 自分自身への遷移は無視
    // ...
}
```

**`t.to == source` を除外している**のが重要です。Any State 遷移は「自分自身」も含んでしまうので、被弾中にまた被弾遷移が発火して、リアクションが永久に最初から再生され続けます。

自己遷移が必要な場合（同じ攻撃を連打する、など）は、専用の遷移として明示的に書きます。

### 遷移の優先順位

複数の遷移条件が同時に成立したらどうするか。**リストの先頭から順に評価し、最初に成立したものを採用**します。

```cpp
    // 最初に成立した遷移を採用して、即座に return
    next_ = t.to;
    // ...
    return;
```

**順序が優先順位になる**という単純な規則です。「被弾は移動より優先」なら、被弾の遷移を先に登録します。

より複雑な優先度の仕組み（明示的な priority 値）もありえますが、**リスト順で足りる**うちは足りるままにしておきます。

## 45.5　遷移中の割り込み

第 39 章と同じ問題です。**遷移中に別の遷移条件が成立したら。**

ステートマシンでは、クロスフェードとは違う扱いができます。**遷移先を差し替える**のです。

```cpp
const int source = blending_ ? next_ : current_;
```

**ブレンド中は、遷移元を `next_`（遷移先）とみなします。** 「もう Walk へ向かっているのだから、次の遷移は Walk からの遷移として判定する」という考え方です。

これは実際の挙動として自然です。歩きへ遷移し始めた瞬間に加速したら、走りへ向かうのが正しい。「歩きへの遷移が完了するまで待つ」のは、操作への反応が悪くなります。

**結果として、中間状態を経由せずに最終状態へ直行することがあります。**

実測してみました。手を振るモーション（Wave）の再生中、移動速度を 5.0 に保ったまま待ちます。

```
遷移ログ: Walk → Run → Wave → Run → Idle
```

Wave が終わると `Wave → Idle` の遷移が始まりますが、**Idle へ向かっている途中で `Idle → Walk`（speed > 0.1）が成立し、さらに `Walk → Run`（speed > 3.0）が成立**します。結果、`current_` は Wave から直接 Run になりました。

**これは正しい挙動**です。速度 5 で走っているキャラクターが、手を振り終わった後に一瞬 Idle になるほうが不自然です。

ただし、**遷移ログに Idle と Walk が現れない**ことは知っておく必要があります。「状態が遷移したときに効果音を鳴らす」といった処理では、経由しなかった状態のイベントが発火しません。**それが望ましいかどうかは、用途次第**です。

## 45.6　踏んだバグ

上の実装を書いてテストしたところ、**トリガーによる Wave への遷移が起きませんでした**。

### 症状

```cpp
params.SetTrigger("wave");
step(15);                       // 0.25 秒。遷移時間は 0.1 秒なので完了するはず
Assert::AreEqual(sWave, sm.Current());   // 失敗。Idle のまま
```

デバッグすると、**Wave への遷移は始まっているのに、次のフレームで `Wave → Idle` が発火して打ち消されて**いました。

### 原因

`Wave → Idle` の遷移には `waitForFinish = true` が設定されています。「手を振り終わってから戻る」という意図です。

```cpp
if (t.waitForFinish) {
    const Clip* c = states_[source].clip;
    if (c && time_ < c->Duration()) { continue; }    // ← ここ
}
```

**`time_` は `current_`（遷移元）の再生時刻**です。しかし 45.5 節で決めたとおり、ブレンド中の `source` は `next_`（遷移先）です。

つまり ―― **「Wave の再生が終わったか」を、Idle の再生時刻で判定していました。**

Idle は長く再生されていたので `time_ >= duration` が成立し、`Wave → Idle` が即座に発火。Wave へ向かっていた遷移が、Idle へ差し替えられていました。

### 修正

**`source` に対応する時刻を使います。**

```cpp
const int source = blending_ ? next_ : current_;
// 【重要】ブレンド中に遷移元となるのは next_ なので、
// 経過時間も nextTime_ を見る。time_ を見ると、遷移先が
// 「もう再生し終わっている」と誤判定される。
const double sourceTime = blending_ ? nextTime_ : time_;

if (t.waitForFinish) {
    const Clip* c = states_[source].clip;
    if (c && sourceTime < static_cast<double>(c->Duration())) { continue; }
}
```

1 行の追加で直りました。

### 教訓

第 28 章のルートモーションのバグと、**構造がまったく同じ**です。

| | 第 28 章 | この章 |
| --- | --- | --- |
| 症状 | 1 ループぶんの移動が消える | 遷移が打ち消される |
| 原因 | ループ回数と時刻を**別々に計算**した | 状態と時刻を**別々に選んだ** |
| 修正 | セットで返す（`PlaybackStep`） | セットで選ぶ（`source` と `sourceTime`） |

**「対になっている 2 つの値を、別々の場所で決めた」**というのが共通の原因です。

第 28 章では、インターフェイスを変えて「矛盾した組み合わせを作れなくする」ことで対処しました。この章では、**1 行下に置いて対であることを目に見えるようにする**という、より軽い対処にしています。

理想は前者ですが、`source` と `sourceTime` を構造体にまとめるほど複雑ではありません。**コメントで対であることを明示する**のが、この規模では適切な落としどころです。

## 45.7　評価

```cpp
void StateMachine::Evaluate(Pose& out, Pose& scratch) const {
    if (states_[current_].clip == nullptr) { return; }

    states_[current_].clip->Sample(static_cast<float>(time_), out);

    if (blending_ && states_[next_].clip != nullptr) {
        states_[next_].clip->Sample(static_cast<float>(nextTime_), scratch);
        // 遷移は角度差が大きくなりうるので Slerp（第 10・38 章）
        BlendPose(out, scratch, BlendWeight(), out, RotationBlend::Slerp);
    }
}
```

**バッファは `scratch` 1 本だけ**です。第 44 章のブレンドツリーと同じ構造で、状態が何個あっても同時に混ざるのは 2 つだけだからです。

各状態を `const Clip*` ではなく `BlendNode*` にすれば、**状態そのものがブレンドツリーになります**。「Walk 状態の中身は、実は速度による 1D ブレンドスペース」という構成が自然に書けます。

```cpp
struct State {
    std::string name;
    std::unique_ptr<BlendNode> tree;    // ← クリップの代わりにツリー
};
```

これが、第 VII 部の到達点です。**ステートマシンがブレンドツリーを持ち、ブレンドツリーがブレンドスペースを持ち、ブレンドスペースがクリップを持つ。**

## 45.8　テストを書く

`AnimLib.Tests/StateMachineTests.cpp`：

```cpp
#include "CppUnitTest.h"

#include "TestSupport/MathAssert.h"
#include "TestSupport/Tolerance.h"

#include "anim/StateMachine.h"

#include <format>
#include <numbers>

using namespace Microsoft::VisualStudio::CppUnitTestFramework;
using namespace anim;

namespace {

constexpr float kPi = std::numbers::pi_v<float>;
constexpr std::size_t kBones = 6;

Clip MakeClip(float duration, float endZ, float endAngle, LoopMode loop = LoopMode::Loop) {
    Clip c;
    c.Resize(kBones);
    c.SetDuration(duration);
    c.SetLoopMode(loop);
    c.Bone(0).translation.AddKey(0.0f, {0, 0, 0});
    c.Bone(0).translation.AddKey(duration, {0, 0, endZ});
    c.Bone(0).translation.Finalize();
    for (std::size_t b = 1; b < kBones; ++b) {
        const BoneIndex bone = static_cast<BoneIndex>(b);
        c.Bone(bone).rotation.AddKey(0.0f, QuatIdentity());
        c.Bone(bone).rotation.AddKey(duration, MakeQuatAxisAngle({0, 0, 1}, endAngle));
        c.Bone(bone).rotation.Finalize();
    }
    return c;
}

}  // namespace

namespace AnimLibTests {

TEST_CLASS(StateMachineTests) {
public:

    // --- パラメータ -----------------------------------------------

    TEST_METHOD(TriggersAreConsumedOnce) {

        params.SetTrigger("jump");

        Assert::IsFalse(params.ConsumeTrigger("jump"));   // 2 回目は false
        Assert::IsFalse(params.ConsumeTrigger("never_set"));

    TEST_METHOD(BoolsPersist) {

        params.SetBool("grounded", true);
        Assert::IsTrue(params.GetBool("grounded"));
        Assert::IsTrue(params.GetBool("grounded"));       // 何度でも読める
        Assert::IsFalse(params.GetBool("unknown"));
    }

    TEST_METHOD(MissingFloatsDefaultToZero) {
        const StateMachineParams params;
        anim::test::AssertNear(0.0f, params.GetFloat("nonexistent"));
    }

    // --- 遷移 -----------------------------------------------------

    TEST_METHOD(BasicTransitionSequence) {
        const Clip idle = MakeClip(1.0f, 0.0f, 0.0f);
        const Clip walk = MakeClip(1.0f, 1.5f, 0.4f);
        const Clip run  = MakeClip(1.0f, 4.0f, 0.9f);

        StateMachine sm;
        const int sIdle = sm.AddState("Idle", &idle);
        const int sWalk = sm.AddState("Walk", &walk);
        const int sRun  = sm.AddState("Run", &run);

        sm.AddTransition({sIdle, sWalk, 0.2f, false,

            [](StateMachineParams& p) { return p.GetFloat("speed") > 3.0f; }});
        sm.AddTransition({sRun, sWalk, 0.2f, false,
            [](StateMachineParams& p) { return p.GetFloat("speed") <= 3.0f; }});
        sm.AddTransition({sWalk, sIdle, 0.2f, false,
            [](StateMachineParams& p) { return p.GetFloat("speed") <= 0.1f; }});
        sm.Start(sIdle);

        StateMachineParams params;
        Pose out(kBones);
        Pose scratch(kBones);
        const auto step = [&](int frames) {
            for (int i = 0; i < frames; ++i) {
                sm.Update(1.0f / 60.0f, params);

            }

        Assert::AreEqual(sIdle, sm.Current());

        params.SetFloat("speed", 1.0f);

        params.SetFloat("speed", 5.0f);
        step(30);
        Assert::AreEqual(sRun, sm.Current());

        params.SetFloat("speed", 0.0f);
        step(60);
        Assert::AreEqual(sIdle, sm.Current());

        sm.Start(sIdle);

        StateMachineParams params;
        Pose out(kBones);
        Pose scratch(kBones);

        Assert::AreEqual(sWalk, sm.Current());

        params.SetTrigger("hit");
        for (int i = 0; i < 15; ++i) { sm.Update(1.0f / 60.0f, params); }
        Assert::AreEqual(sHit, sm.Current());
    }

    // Any State が自分自身へ遷移しないこと（45.4 節）
    TEST_METHOD(AnyStateDoesNotSelfTransition) {
        const Clip idle = MakeClip(1.0f, 0.0f, 0.0f);
        const Clip hit  = MakeClip(0.5f, 0.0f, 1.2f, LoopMode::Once);

        StateMachine sm;
        sm.AddState("Idle", &idle);
        const int sHit = sm.AddState("Hit", &hit);
        sm.AddTransition({-1, sHit, 0.1f, false,

        Assert::IsTrue(sm.CurrentTime() > timeBefore);   // 再生が進んでいる
        Assert::IsFalse(sm.IsBlending());
    }

    // --- 割り込み（45.5 節）--------------------------------------

    TEST_METHOD(InterruptedTransitionsSkipIntermediateStates) {
        const Clip idle = MakeClip(1.0f, 0.0f, 0.0f);
        const Clip walk = MakeClip(1.0f, 1.5f, 0.4f);
        const Clip run  = MakeClip(1.0f, 4.0f, 0.9f);
        const Clip wave = MakeClip(1.0f, 0.0f, 1.2f);

        StateMachine sm;
        const int sIdle = sm.AddState("Idle", &idle);
        const int sWalk = sm.AddState("Walk", &walk);
        const int sRun  = sm.AddState("Run", &run);
        const int sWave = sm.AddState("Wave", &wave);

        sm.AddTransition({sIdle, sWalk, 0.2f, false,
            [](StateMachineParams& p) { return p.GetFloat("speed") > 0.1f; }});
        sm.AddTransition({sWalk, sRun, 0.2f, false,
            [](StateMachineParams& p) { return p.GetFloat("speed") > 3.0f; }});
        sm.AddTransition({-1, sWave, 0.1f, false,
            [](StateMachineParams& p) { return p.ConsumeTrigger("wave"); }});
        sm.AddTransition({sWave, sIdle, 0.2f, true,
            [](StateMachineParams&) { return true; }});
        sm.Start(sIdle);

        StateMachineParams params;
        std::vector<std::string> log;
        const auto step = [&](int frames) {
            for (int i = 0; i < frames; ++i) {
                const int before = sm.Current();
                sm.Update(1.0f / 60.0f, params);
                if (sm.Current() != before) { log.push_back(sm.StateName(sm.Current())); }
            }
        };

        params.SetFloat("speed", 5.0f);
        step(60);
        params.SetTrigger("wave");
        step(20);
        Assert::AreEqual(sWave, sm.Current());

        // speed が 5 のままなので、Wave 終了後は Idle を経由せず Run へ
        step(120);
        std::wstring joined;
        for (const std::string& s : log) { joined += anim::test::ToWide(s) + L" "; }
        Logger::WriteMessage((L"transition log: " + joined + L"\n").c_str());

        Assert::AreEqual(sRun, sm.Current());
    }

    // --- 45.6 節のバグに対する番人 -------------------------------

    // waitForFinish の判定に、遷移先の時刻が使われること。
    // time_ を見る実装に戻すと、この遷移が打ち消されて失敗する。
    TEST_METHOD(WaitForFinishUsesTheIncomingStatesTime) {
        const Clip idle = MakeClip(1.0f, 0.0f, 0.0f);
        const Clip wave = MakeClip(1.0f, 0.0f, 1.2f);

        StateMachine sm;
        const int sIdle = sm.AddState("Idle", &idle);
        const int sWave = sm.AddState("Wave", &wave);

        sm.AddTransition({-1, sWave, 0.1f, false,
            [](StateMachineParams& p) { return p.ConsumeTrigger("wave"); }});
        sm.AddTransition({sWave, sIdle, 0.2f, true,     // ← waitForFinish
            [](StateMachineParams&) { return true; }});
        sm.Start(sIdle);

        StateMachineParams params;
        // Idle を長く再生しておく（time_ が Wave の長さを超える）
        for (int i = 0; i < 120; ++i) { sm.Update(1.0f / 60.0f, params); }

        params.SetTrigger("wave");
        for (int i = 0; i < 15; ++i) { sm.Update(1.0f / 60.0f, params); }

        // Wave に到達していること。time_ を見る実装だと Idle のまま
        Assert::AreEqual(sWave, sm.Current());
    }

    TEST_METHOD(WaitForFinishActuallyWaits) {
        const Clip idle = MakeClip(1.0f, 0.0f, 0.0f);
        const Clip attack = MakeClip(0.8f, 0.0f, 1.5f, LoopMode::Once);

        StateMachine sm;
        const int sIdle = sm.AddState("Idle", &idle);
        const int sAttack = sm.AddState("Attack", &attack);

        sm.AddTransition({sIdle, sAttack, 0.1f, false,
            [](StateMachineParams& p) { return p.ConsumeTrigger("attack"); }});

            [](StateMachineParams&) { return true; }});
        sm.Start(sIdle);

        StateMachineParams params;
        params.SetTrigger("attack");
        for (int i = 0; i < 10; ++i) { sm.Update(1.0f / 60.0f, params); }
        Assert::AreEqual(sAttack, sm.Current());

        // 攻撃の途中（0.4 秒）ではまだ戻らない
        for (int i = 0; i < 24; ++i) { sm.Update(1.0f / 60.0f, params); }
        Assert::AreEqual(sAttack, sm.Current());

        // 0.8 秒を過ぎたら戻る
        for (int i = 0; i < 60; ++i) { sm.Update(1.0f / 60.0f, params); }
        Assert::AreEqual(sIdle, sm.Current());
    }

    // --- 連続性 ---------------------------------------------------

## 45.9　つまずきやすいところ

**トリガーで何度も遷移する**
`ConsumeTrigger` ではなく `GetBool` を使っています。

**被弾リアクションが永久に最初から再生される**
Any State 遷移が自分自身に発火しています。`t.to == source` の除外を確認してください。

**`waitForFinish` が効かない／効きすぎる**
45.6 節のバグです。`source` に対応する時刻を使ってください。

**遷移が起きない**
条件が成立しているか、`from` が正しいかを確認してください。優先順位の高い（先に登録した）遷移が先に成立していることもあります。

**遷移の途中で姿勢が飛ぶ**
`Slerp` を使っていますか。また、`nextTime_` が正しく進んでいるか確認してください。

**中間状態のイベントが発火しない**
45.5 節のとおり、割り込みで経由しないことがあります。「状態に入った瞬間」ではなく「遷移が始まった瞬間」でイベントを発火する設計にすれば、拾えます。

**状態が増えると遷移の管理が大変**
Any State と、遷移の優先順位を活用してください。それでも足りなければ、階層型ステートマシン（状態の中に状態を持つ）を検討します。本書の範囲外です。

## この章のまとめ

- ステートマシンは、遷移を **`if` の網ではなくデータ**として表現する。ツールで編集でき、保存でき、コードを変えずに調整できる。
- パラメータは 3 種類。**トリガーは消費される**という性質が、イベントを正しく扱う鍵。`bool` で代用すると何度も発火する。
- **Any State（`from = -1`）** で「どこからでも」を表す。ただし**自分自身への遷移を除外**しないと、永久に最初から再生され続ける。
- 遷移の優先順位は**リストの順**。単純な規則で足りるうちは、足りるままにしておく。
- **ブレンド中は `next_` を遷移元とみなす。** 結果として**中間状態を飛ばして直行する**ことがあるが、それが正しい挙動。実測で `Wave → Run`（Idle と Walk を経由せず）。
- **踏んだバグ**：`waitForFinish` の判定に `time_`（遷移元の時刻）を使っていたため、ブレンド中に遷移先の再生が「もう終わっている」と誤判定され、遷移が打ち消されていた。
- 原因は第 28 章とまったく同じ構造 ―― **「対になっている 2 つの値を、別々の場所で決めた」**。修正は `source` と `sourceTime` を隣に並べること。
- 状態の中身を `BlendNode` にすれば、**ステートマシン → ブレンドツリー → ブレンドスペース → クリップ**という階層が自然に組める。これが第 VII 部の到達点。

第 1 章のパイプラインの ② が完成しました。

② ブレンド              ← ✅ 第 VII 部
③ 階層を解く            ← ✅ 第 14 章
④ IK で補正             ← 第 VIII 部（次）
⑤ パレットを作る        ← ✅ 第 16 章
⑥ 頂点を変形            ← ✅ 第 18・22 章
```

**残るは IK だけ**になりました。

第 VII 部で繰り返した方針を、あらためて確認します。

**理論上の問題を測る。** N 個のブレンドの順序依存は、理論上 152 度、実用上 0.056 度。**理論だけで判断せず、実測だけで安心もしない。** 両方をテストとして残すことで、「性質としては存在するが、想定する入力では無害」という判断そのものが記録されます。

**自動化の限界を認める。** ボーンマスクのスムージングは、マスクを内側に狭め、親方向へは広がりません。だから**アーティストが直接指定する**のが主流。ツールにできることと、人がやるべきことの線を引く。

**「対になっている値を別々に決めない」。** 第 28 章と第 45 章で、まったく同じ構造のバグを踏みました。時刻とループ回数、状態と時刻。**対になっているものは、セットで返すか、せめて隣に並べる。**

**不変条件を大量の入力で掃く。** 2D ブレンドスペースの重みの合計は、20,000 点で `2.38e-07` 以内。幾何アルゴリズムの穴は、ランダムな入力でしか見つかりません。

**バッファを静的に数える。** ブレンドツリーの `MaxBuffers()` により、第 14 章から掲げた「毎フレーム 1 回もアロケートしない」が最後まで守られました。10,000 回評価してもプールは拡張されません。

次章から第 VIII 部。ここまでは「アニメーションデータをどう再生するか」でしたが、IK は**ポーズを後から計算で曲げる**話です。データにない姿勢を、その場で作ります。
