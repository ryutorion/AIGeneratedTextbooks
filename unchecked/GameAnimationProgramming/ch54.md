# 第 54 章　キーフレーム圧縮（1）キー削減

**この章で作るもの**：クリップからキーフレームを間引く仕組み。**定数トラックの検出**と、**誤差を指定して残すキーを選ぶ**アルゴリズム。

---

## 54.1　なぜ圧縮するのか

第 53 章の最後で、1000 体の階層解決がメモリ帯域律速になりました。計算をいくら速くしても、データが届かなければ意味がない。

アニメーションデータは、ゲームの中でも**とりわけ大きくなりやすい**部類です。この本のテスト用クリップで数えてみます。

```
60 ボーン、2.0 秒、30 Hz（61 キー）
  回転     60 × 61 = 3,660 キー × (時刻 4 B + Quat 16 B) = 73,200 B
  平行移動 60 × 61 = 3,660 キー × (時刻 4 B + Vec3 12 B) = 58,560 B
  スケール 60 × 61 = 3,660 キー × (時刻 4 B + Vec3 12 B) = 58,560 B
  ─────────────────────────────────────────────
  合計 10,980 キー、190,320 バイト（185.9 KB）
```

**2 秒のクリップで 186 KB。** 実際のゲームには、歩き・走り・待機・攻撃・被弾・死亡 … と何百ものクリップがあります。1 キャラクターで 100 クリップなら 18 MB。キャラクターが 20 種類なら 370 MB。

これはメモリだけの問題ではありません。

- **ディスクからのロード時間**が伸びる
- **メモリ帯域**を食う（第 53 章のボトルネック）
- **キャッシュ**が汚れる（サンプリングのたびに DRAM を叩く）

圧縮の目標は 3 つ、この順です。

1. **無駄なデータを消す**（第 54 章 ―― 情報を失わない、あるいはほぼ失わない）
2. **精度を落とす**（第 55 章 ―― 失う量を数値で管理する）
3. **展開せずに読む**（第 56 章 ―― 圧縮の意味を実行時まで持ち越す）

## 54.2　まず、無駄を数える

さきほどの内訳をもう一度見てください。**スケールに 58,560 バイト**使っています。

このクリップで、スケールが変化するボーンはいくつあるでしょうか。

```
定数トラック: 回転 12/60, 平行移動 59/60, スケール 60/60
```

**スケールは全 60 本が定数。平行移動も 59 本が定数**（動くのはルートだけ）。回転すら 12 本は定数です。

これは私の作ったテストデータの都合ではありません。**実際のリグでも、ほぼこうなります。**

- **スケール**は、キャラクターアニメーションではまず使いません（漫画的な誇張表現や、ボーンを消すための 0 スケールを除く）
- **平行移動**は、骨の長さが変わらない以上、動くのはルートだけです（顔の一部やメカのスライド機構は例外）
- **回転**も、動かない指の関節や、リグの補助ボーンは定数のままです

**削減できるのは 130,784 バイト、全体の 68.7%。** アルゴリズムらしいアルゴリズムを書く前に、**7 割近くが「何もしていないデータ」だと分かりました。**

> **圧縮の第一歩は、アルゴリズムではなく観察である。**

## 54.3　定数トラックの検出

```cpp
// AnimLib/include/anim/Compress.h
#pragma once
#include "anim/Clip.h"

namespace anim {

// 型ごとの「誤差」の定義
inline float ErrorOf(Vec3 a, Vec3 b){ return Length(a - b); }              // 距離（メートル）
inline float ErrorOf(const Quat& a, const Quat& b);                        // 角度（ラジアン）

template<typename T>
bool IsConstantTrack(const Track<T>& t, float tolerance){
    if (t.KeyCount() <= 1) return true;
    const T v0 = t.Key(0).value;
    for (std::size_t i = 1; i < t.KeyCount(); ++i)
        if (ErrorOf(t.Key(i).value, v0) > tolerance) return false;
    return true;
}
}  // namespace anim
```

**`ErrorOf` を型ごとにオーバーロードする**のが設計の要です。位置の誤差はメートル、回転の誤差はラジアン ―― **単位が違うものを同じ数値で比べてはいけません**。`0.01` という許容値は、位置なら 1 cm、回転なら 0.57 度。まったく別の意味です。

型ごとに関数を分けておけば、呼び出し側は自然に別々のしきい値を渡すことになります。

```cpp
IsConstantTrack(bone.translation, 1.0e-5f);   // 0.01 mm
IsConstantTrack(bone.rotation,    1.0e-4f);   // 0.0057 度
```

### 回転の誤差をどう測るか

2 つの回転がどれだけ違うかは、**なす角**で測ります。第 9 章の関係から、

```
cos(θ/2) = |dot(q1, q2)|
```

絶対値を取るのは二重被覆のため（`q` と `−q` は同じ回転）。素直に書くとこうなります。

```cpp
inline float ErrorOfAcos(const Quat& a, const Quat& b){
    const float d = std::fmin(1.0f, std::fabs(Dot(Normalize(a), Normalize(b))));
    return 2.0f * std::acos(d);
}
```

**これは使えません。** 第 46 章と同じ理由です ―― `acos(x)` は `x ≈ 1` の近傍で精度を失います。そして圧縮の誤差測定は、**まさに「ほぼ同じ 2 つの回転」を比べる仕事**です。どれくらい壊れるかは第 55 章で実測しますが（8.5 倍の過大評価でした）、先に正しい形を書いておきます。

```cpp
// 相対回転を作って atan2 で測る。小さい角度でも精度が落ちない。
inline float ErrorOf(const Quat& a, const Quat& b){
    const Quat r = Conjugate(Normalize(a)) * Normalize(b);
    const float v = Length(Vec3{r.x, r.y, r.z});
    return 2.0f * std::atan2(v, std::fabs(r.w));
}
```

`atan2(|v|, |w|)` は、角度が小さいとき `|v|` も小さくなり、**相対精度が保たれます**。第 10 章の `Slerp`、第 46 章の `FromToRotation`、第 50 章のヒンジ制限。この本で `acos` を避けるのは、これで 4 回目です。

> **`acos(dot)` は「2 つのベクトル / 回転が近い」ことを測るのに向かない。近いことを測りたいときこそ精度が要るのに、そこで一番精度が落ちる。**

## 54.4　定数トラックをどう表現するか

検出したら、どう格納するか。3 つのやり方があります。

**① キーを 1 個だけ残す。** 実装がいちばん簡単で、サンプリングのコードも変えなくて済みます（`Track::Sample` はキーが 1 個なら即座にその値を返します）。ただし「時刻 4 バイト」がキーごとに残り、`Track` オブジェクトのオーバーヘッドも残ります。

**② トラックを空にして、値を別に持つ。** 第 56 章の圧縮形式ではこれを採ります。

```cpp
struct CompressedBone {
    std::uint16_t rotCount = 0;      // 0 なら定数
    std::uint64_t constRot = 0;      //   ← こちらを使う
    Vec3 constPos{0,0,0};
    Vec3 constScale{1,1,1};
};
```

**③ そもそも持たない。** スケールが全ボーンで `(1,1,1)` なら、クリップに「スケールなし」というフラグを 1 つ立てて、サンプリング時にはレストポーズの値を使う。最も小さくなりますが、「スケールを使うクリップ」と「使わないクリップ」で分岐が増えます。

この本は **②** を採ります。ボーンごとに独立して判断でき、分岐は「カウントが 0 か」の 1 回だけです。

## 54.5　単体テスト：定数トラックの検出

```cpp
TEST_CLASS(ConstantTrackTests) {
public:
    TEST_METHOD(DetectsConstantAndNonConstant) {
        Track<Vec3> constant;
        for (int i = 0; i <= 10; ++i) constant.AddKey(i*0.1f, Vec3{1,2,3});
        constant.Finalize();
        Assert::IsTrue(IsConstantTrack(constant, 1e-5f));

        Track<Vec3> moving;
        for (int i = 0; i <= 10; ++i) moving.AddKey(i*0.1f, Vec3{1, 2, 3 + i*0.01f});
        moving.Finalize();
        Assert::IsFalse(IsConstantTrack(moving, 1e-5f));
        Assert::IsTrue (IsConstantTrack(moving, 0.2f));   // 許容を広げれば定数扱い
    }

    TEST_METHOD(CountsInRealisticClip) {
        Skeleton s = MakeHumanoid(60);
        const Clip clip = MakeWalkClip(s, 2.0f, 30);
        int cr=0, cp=0, cs=0;
        for (int b = 0; b < 60; ++b) {
            const BoneTracks& t = clip.Bone(static_cast<BoneIndex>(b));
            if (IsConstantTrack(t.rotation,    1e-4f)) ++cr;
            if (IsConstantTrack(t.translation, 1e-5f)) ++cp;
            if (IsConstantTrack(t.scale,       1e-5f)) ++cs;
        }
        Logger::WriteMessage(std::format("定数: 回転 {}/60, 移動 {}/60, スケール {}/60\n",
                                         cr, cp, cs).c_str());

        Assert::AreEqual(59, cp);        // 移動はルート以外定数
    }
};
```

`Assert::AreEqual(60, cs)` は**テストデータの性質を固定するテスト**です。将来テストデータを差し替えたときに、この期待値が変われば「クリップの性質が変わった」と気づけます。第 54〜56 章の測定値はすべてこのクリップに依存しているので、クリップ自体を守っておく価値があります。

## 54.6　キー削減 ―― 残りをどう減らすか

定数を除いても、動いている 48 本の回転トラックには **3,660 個のキー**が残っています。

30 Hz でキーが打たれているということは、**1/30 秒ごとに姿勢が記録されている**ということです。しかし、ゆっくり動いている部分では、途中のキーは前後から線形補間できます。

```
値
 │        ●
 │      ●   ●
 │    ●       ●
 │  ●           ●
 │●               ●        ← この直線部分のキーは、両端から復元できる
 └──────────────────── 時刻
```

**キーを消しても、補間結果が元と十分近ければよい。** 「十分近い」を数値で決めるのが、この節の仕事です。

### アルゴリズムの選択

素直な方法は**貪欲法**です。「消したときの誤差が最小のキーを消す」を、誤差が許容値を超えるまで繰り返す。品質は良いのですが、毎回すべてのキーの誤差を計算し直すので **O(n²)** になります。

この本では **Douglas-Peucker 型**（分割統治）を使います。地図の折れ線を簡略化する古典的アルゴリズムと同じ考え方です。

1. 両端のキーは必ず残す
2. 両端を直線で結び、**そこから最も離れているキー**を探す
3. その距離が許容値以下なら、**間のキーは全部消せる** ―― 終わり
4. 超えていたら、そのキーを残して、**左半分と右半分に分けて再帰**

```cpp
template<typename T>
static void MarkRecursive(const Track<T>& t, std::vector<std::uint8_t>& keep,
                          std::size_t lo, std::size_t hi, float tolerance){
    if (hi <= lo + 1) return;                      // 間にキーがない

    const Keyframe<T>& a = t.Key(lo);
    const Keyframe<T>& b = t.Key(hi);
    const float span = b.time - a.time;

    float worst = -1.0f;
    std::size_t worstIdx = lo;
    for (std::size_t i = lo+1; i < hi; ++i) {
        const float u = (span > 0.0f) ? (t.Key(i).time - a.time)/span : 0.0f;
        const T approx = Mix(a.value, AlignTo(b.value, a.value), u);
        const float e = ErrorOf(t.Key(i).value, approx);
        if (e > worst) { worst = e; worstIdx = i; }
    }

    if (worst <= tolerance) return;                // 間は全部消せる
    keep[worstIdx] = 1;
    MarkRecursive(t, keep, lo, worstIdx, tolerance);
    MarkRecursive(t, keep, worstIdx, hi, tolerance);
}
```

**`AlignTo(b.value, a.value)` を忘れないこと。** 第 23 章で作った関数で、クォータニオンの符号を揃えます。`a` と `b` の内積が負なら `b` を反転してから補間する ―― これをやらないと、**同じ回転なのに「遠回り」の補間になり**、誤差が過大に評価されてキーが消せなくなります。`Vec3` と `float` に対しては何もしない実装が用意してあるので、テンプレートのまま書けます。

```cpp
struct ReductionStats { std::size_t before = 0, after = 0; float maxError = 0.0f; };

template<typename T>
ReductionStats ReduceTrack(Track<T>& track, float tolerance){
    ReductionStats st; st.before = track.KeyCount();
    if (track.KeyCount() <= 2) { st.after = st.before; return st; }

    std::vector<std::uint8_t> keep(track.KeyCount(), 0);
    keep.front() = keep.back() = 1;
    MarkRecursive(track, keep, 0, track.KeyCount()-1, tolerance);

    Track<T> out;
    out.SetInterpolation(track.GetInterpolation());
    for (std::size_t i = 0; i < track.KeyCount(); ++i)
        if (keep[i]) out.AddKey(track.Key(i).time, track.Key(i).value);
    out.Finalize();

    // 元のキー時刻すべてで、実際の誤差を測り直す
    for (std::size_t i = 0; i < track.KeyCount(); ++i)
        st.maxError = std::fmax(st.maxError,
                                ErrorOf(track.Key(i).value, out.Sample(track.Key(i).time)));

    st.after = out.KeyCount();
    track = std::move(out);
    return st;
}
```

**最後に誤差を測り直している**のが重要です。アルゴリズムは「両端から補間したときの誤差」で判断しますが、**再帰の途中で残したキーが増えると、実際の補間はもっと正確になります**。理論上の上限ではなく、実際の値を返す。

## 54.7　このアルゴリズムが保証しないこと

正直に書いておきます。

**保証するのは「元のキーの時刻における誤差」だけです。** キーとキーの**間**の時刻でどうなるかは、保証していません。

```
    元のトラック          削減後
       ●                    ●
      ╱ ╲                  ╱
     ●   ●                ╱      ← ここでの誤差は測っていない
    ╱     ╲              ╱
   ●       ●            ●
```

元のデータが 30 Hz でサンプルされている以上、キーとキーの間の「真の値」はそもそも分かりません。だから測りようがない ―― というのが理屈ですが、実務的には**元のトラックを高い周波数で再サンプルしてから比較する**という手もあります。

もう 1 つ、**このアルゴリズムは最適ではありません。** 貪欲法のほうが同じ誤差で少ないキー数になることがあります。ただし O(n²) と O(n log n) の差があり、キーが数万個あるクリップでは無視できません。**「最適でないが十分によく、速い」** を選んでいます。

**そして最も大事な限界。** キー削減は**ボーンごとに独立**に行われます。しかし誤差は**階層を通じて伝播します**。腰の回転が 1 度ずれると、手首の位置は数センチ動く。次の節で、これを実測します。

## 54.8　測定 ―― 局所の角度と、ワールドの位置

許容誤差を変えて、キー数と実際の誤差を測ります。誤差は 2 種類とります。

- **局所の角度誤差**：各ボーンのローカル回転が、元と何度違うか
- **ワールド位置の誤差**：階層を解いた結果、各ボーンの原点が何メートル動くか

```cpp
TEST_METHOD(ReductionErrorSweep) {
    Skeleton s = MakeHumanoid(60);
    const Clip original = MakeWalkClip(s, 2.0f, 30);

    for (float tolDeg : {0.05f, 0.1f, 0.5f, 1.0f, 2.0f}) {
        Clip c = original;
        std::size_t before = 0, after = 0;
        for (int b = 0; b < 60; ++b) {
            BoneTracks& t = c.Bone(static_cast<BoneIndex>(b));
            before += t.rotation.KeyCount();
            ReduceTrack(t.rotation, tolDeg * kPi / 180.0f);
            after  += t.rotation.KeyCount();
        }
        const PoseError e = MeasureError(s, original,
            [&](float t, Pose& p){ c.Sample(t, p); }, 600);
        Logger::WriteMessage(std::format(
            "許容 {:.2f} 度: {} -> {} キー, 局所 {:.4f} 度, ワールド {:.6f} m\n",
            tolDeg, before, after, e.maxRot*180/kPi, e.maxWorld).c_str());
        Assert::IsTrue(e.maxRot * 180 / kPi <= tolDeg * 1.01f);
    }
}
```

| 許容 | 回転キー | 残った割合 | 実測（局所） | 実測（ワールド位置） |
|---|---|---|---|---|
| 0.05° | 3660 → **2566** | 70.1% | `0.0489°` | `0.000715` m |
| 0.10° | 3660 → **2299** | 62.8% | `0.0996°` | `0.002416` m |
| 0.50° | 3660 → **1288** | 35.2% | `0.4986°` | `0.016487` m |
| 1.00° | 3660 → **907** | 24.8% | `0.9975°` | `0.028139` m |
| 2.00° | 3660 → **626** | 17.1% | `1.9928°` | `0.056288` m |

読み取れることが 4 つあります。

**① アルゴリズムは約束を守っている。** 許容 0.5 度に対して実測 0.4986 度。上限を超えていません。

**② 効きが非線形。** 許容を 0.05 度から 0.5 度へ 10 倍緩めると、キーは 2566 → 1288 と**半分**になります。しかしそこから 2 度へさらに 4 倍緩めても、626 までしか減りません。**最初の緩和がいちばん効く。**

**③ 局所 0.5 度が、ワールドで 16.5 mm になる。** 誤差が階層を通じて増幅されています。腕の長さが 60 cm なら、`0.6 m × 0.5° = 0.6 × 0.0087 = 5.2 mm`。それが 8 段の階層で積み重なって 16.5 mm。

**④ どこまで許されるか。** 16.5 mm は、キャラクターの手先が指 1 本ぶんずれる量です。近接戦闘の当たり判定や、武器を両手で持つ場面では気づかれます。一方、遠景の群衆なら 5 cm でも分かりません。

> **許容誤差はクリップごと、いや、ボーンごとに変えるべきパラメータである。**

## 54.9　ボーンごとに許容誤差を変える

上の表の ④ から、自然に次の設計が出てきます。

```cpp
struct BoneCompressionSettings {
    float rotationTolerance    = 0.5f * kPi / 180.0f;
    float translationTolerance = 1.0e-3f;
};

// ボーンごとの設定。既定値を持ち、必要なものだけ上書きする。
struct ClipCompressionSettings {
    BoneCompressionSettings defaults;
    std::unordered_map<std::string, BoneCompressionSettings> overrides;
};
```

実務での指針です。

| ボーン | 許容 | 理由 |
|---|---|---|
| ルート・腰 | **厳しく**（0.05〜0.1°） | 全身に伝播する。ここの誤差が最も高くつく |
| 脚・足首 | 厳しく | 接地のずれは目立つ（第 51 章） |
| 手首・指 | 中くらい | 武器の保持に影響するが、IK で直せる |
| 髪・服・尻尾 | **緩く**（2〜5°） | 誰も見ていない。数もいちばん多い |
| 顔 | 厳しく | 表情はわずかな差が伝わる |

**「階層の上ほど厳しく」** が原則です。誤差が下流全部に効くからです。

**もっと良い方法**もあります。ボーンごとに「そのボーンから最も遠い子孫までの距離」を計算し、**ワールド位置の誤差**が一定になるよう角度の許容値を逆算する。

```cpp
// このボーンを θ 回すと、最も遠い子孫は maxChildDistance × θ 動く。
// ワールド誤差を worldTolerance に抑えたいなら:
float rotationTolerance = worldTolerance / std::fmax(maxChildDistance, 1e-3f);
```

これなら、アーティストは「手先のずれを 5 mm 以内に」という**意味のある単位**で指定できます。**ラジアンではなくメートルで語れるインターフェースにする** ―― 圧縮ツールの使いやすさは、ここで決まります。

## 54.10　キー削減が効かない場合

このアルゴリズムが役に立たないケースも知っておきます。

**① もともとキーが少ない。** アーティストが手打ちしたクリップは、そもそもキーが必要な場所にしかありません。削減率はほぼゼロです。効くのは**モーションキャプチャ**や、**DCC ツールがベイクしたデータ**（全フレームにキーが打たれているもの）です。

**② 高周波の動き。** 震え、細かい振動、ダメージリアクション。1 フレームごとに向きが変わるトラックからは、キーを 1 つも消せません。

**③ ステップ補間のトラック。** 第 24 章の `Interpolation::Step` を使うトラックは、値が変わる瞬間のキーがすべて意味を持ちます。線形補間を前提にしたこのアルゴリズムは、**そのまま適用してはいけません**（`Mix` で補間した値と比較しているため、消してはいけないキーを消します）。実装では補間モードで分岐するか、Step トラックは対象外にします。

```cpp
if (track.GetInterpolation() == Interpolation::Step) return st;   // 手を出さない
```

**④ キュービック補間のトラック。** 接線を持つキー（第 24 章の `CubicSpline`）は、線形の物差しで測ると過大に評価されます。接線ごと評価する版が要ります。この本では扱いません。

## この章のまとめ

- 60 ボーン・2 秒・30 Hz のクリップで **10,980 キー / 185.9 KB**。実ゲームでは数百クリップ × 数十キャラクター。**ロード時間・メモリ帯域・キャッシュ**の 3 方向で効いてくる。
- **圧縮の第一歩はアルゴリズムではなく観察。** このクリップでは**スケール 60/60、平行移動 59/60、回転 12/60 が定数** ―― **68.7% が「何もしていないデータ」**だった。
- `ErrorOf` を**型ごとにオーバーロード**する。位置はメートル、回転はラジアン。**単位の違うものを同じ数値で比べない。**
- 回転の誤差に **`acos(dot)` を使ってはいけない**。近い 2 つを測るのが仕事なのに、そこで一番精度が落ちる。**相対回転を作って `atan2(|v|, |w|)`** で測る（この本で `acos` を避けるのは 4 回目）。
- キー削減は **Douglas-Peucker 型**。両端を結んだ直線から最も遠いキーを探し、許容以下なら間を全消し、超えたら分割して再帰。O(n log n)。
- **`AlignTo` を忘れない。** 符号を揃えずに補間すると「遠回り」の誤差が出て、消せるキーが消せなくなる。
- 保証するのは**元のキー時刻での誤差だけ**。キーの間は測っていない。**最適でもない**（貪欲法のほうが良いが O(n²)）。
- 実測：許容 **0.5 度で 3660 → 1288 キー（35.2%）**、局所 `0.4986°`、ワールド位置 `0.016487` m。**最初の緩和がいちばん効く**（0.05° → 0.5° で半減、その先は鈍る）。
- **局所 0.5 度が、階層を通ってワールドで 16.5 mm になる。** キー削減はボーンごとに独立だが、誤差は階層を伝播する。
- だから**許容誤差はボーンごとに変える**。原則は「**階層の上ほど厳しく**」。さらに「最遠子孫までの距離」で割れば、アーティストが**メートルで指定できる**インターフェースになる。
- 効かないケース：手打ちのクリップ、高周波の動き、**Step 補間のトラック（適用してはいけない）**、キュービック補間のトラック。

次章では、残ったキーを**小さく格納**します。`float` 4 バイト × 4 のクォータニオンを **6 バイト**にする ―― 第 8 章の二重被覆が、ここで効いてきます。
