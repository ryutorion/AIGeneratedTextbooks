# 第 15 章　バインドポーズと逆バインド行列

**この章で作るもの**：逆バインド行列の計算。ここまで「ボーンをどう動かすか」を作ってきましたが、まだ**メッシュの頂点とボーンが結びついていません**。その最後の一本の橋を架けます。

---

## 15.1　頂点はどの空間にいるのか

素朴な疑問から始めます。

モデルファイルの中の頂点座標は、いったい何を基準にした座標なのでしょうか。

答えは、**「メッシュがスケルトンに紐づけられた瞬間の、モデル空間の座標」**です。3D モデラーが T ポーズのキャラクターを作り、スケルトンを埋め込み、「このメッシュをこのスケルトンにバインドする」という操作を行う。**その瞬間の姿勢**が基準になります。これを**バインドポーズ**と呼びます。

ここに問題があります。頂点 `(0.4, 1.5, 0.02)` が上腕の表面にあるとして、この座標は**モデル空間**の値です。しかし私たちが持っているのは、ボーンの**グローバル姿勢**（第 14 章）です。ボーンを動かしたとき、この頂点をどこへ持っていけばよいのか、直接には分かりません。

必要なのは、**「その頂点が、ボーンから見てどこにあるのか」**という情報です。それさえ分かれば、ボーンが動いた先に同じ相対位置で置き直せます。

そして「モデル空間 → ボーンのローカル空間」への変換こそが、**逆バインド行列**です。

---

## 15.2　3 つのポーズを区別する

用語が 3 つ出てくるので、整理しておきます。

**レストポーズ（rest pose）**
スケルトンが持つ既定の姿勢。第 13 章で `Skeleton::RestLocal` として持たせたものです。「アニメーションを何も再生していないときの姿勢」であり、glTF ではノードの TRS プロパティがこれにあたります。

**バインドポーズ（bind pose）**
メッシュがスケルトンに紐づけられたときの姿勢。**頂点座標の基準**です。

**カレントポーズ（current pose）**
今このフレームの姿勢。第 14 章で計算しているものです。

**多くのモデルでは、レストポーズとバインドポーズは一致します。** T ポーズで作り、T ポーズでバインドし、T ポーズをノードの既定値にする。自然な流れです。

しかし一致しないこともあります。T ポーズでバインドしたあと、作業しやすいように A ポーズを既定にする、といった運用があるためです。glTF は**この 2 つを別々に持てる設計**になっており、`skin.inverseBindMatrices` がバインドポーズ由来、ノードの TRS がレストポーズです。

したがって本書も**両者を分けて扱います**。混同すると、モデルをロードした瞬間にキャラクターがねじれます。

```
レストポーズ            バインドポーズ            カレントポーズ
（Skeleton が持つ）     （逆バインド行列の元）     （毎フレーム計算）
      │                      │                        │
      │                      ▼                        ▼
      │              inverseBind[i]            globalPose[i]
      │                      └──────────┬─────────────┘
      ▼                                 ▼
 ポーズの初期値                skinMatrix[i]（第 16 章）
```

---

## 15.3　式を導く

ボーン `i` に 100% 属する頂点 `v` を考えます。他のボーンの影響は受けないものとします（複数ボーンの場合は第 18 章で扱います）。

**ステップ 1：頂点をボーンのローカル空間に引き戻す。**

バインドポーズにおけるボーン `i` のグローバル変換を `B_i` とします。頂点 `v` はモデル空間の座標なので、ボーンから見た座標は

```
v_local = B_i⁻¹ · v
```

この `v_local` は**定数**です。頂点はボーンに固定されているので、ボーンがどう動こうと、ボーンから見た位置は変わりません。

**ステップ 2：現在のボーンの位置へ送る。**

現在のポーズにおけるボーン `i` のグローバル変換を `G_i` とすると、

```
v' = G_i · v_local = G_i · B_i⁻¹ · v
```

**これで完成です。**

```
skinMatrix[i] = G_i · B_i⁻¹ = globalPose[i] · inverseBind[i]
```

第 1 章で予告した式が、ここで導かれました。列ベクトル規約（第 6 章）なので、**右にある `inverseBind` が先に効きます** ―― まず引き戻し、次に送る。式の並びが処理の順序の逆になっているのは、第 6 章で確認したとおりです。

そして重要な確認 ―― **カレントポーズがバインドポーズと同じなら、`G_i = B_i` なので `skinMatrix[i] = B_i · B_i⁻¹ = I`（単位行列）** になります。頂点は 1 ミリも動きません。当然そうあるべきで、これがこの章と次章の最重要のテストになります。

## 15.4　逆バインド行列を計算する

```cpp
// AnimLib/include/anim/BindPose.h
#pragma once

#include "anim/Mat4.h"
#include "anim/Pose.h"
#include "anim/Skeleton.h"

#include <span>
#include <vector>

namespace anim {

// バインドポーズ（ローカル）から逆バインド行列を計算する。
// ロード時に一度だけ呼ぶ。out はボーン数ぶんの領域。
void ComputeInverseBindMatrices(const Skeleton& skeleton,
                                std::span<const Transform> bindLocalPose,
                                std::span<Mat4> outInverseBind);

// 既にグローバルなバインド姿勢が手元にある場合
void ComputeInverseBindMatricesFromGlobal(std::span<const Transform> bindGlobalPose,
                                          std::span<Mat4> outInverseBind);

}  // namespace anim
```

```cpp
void ComputeInverseBindMatricesFromGlobal(std::span<const Transform> bindGlobalPose,
                                          std::span<Mat4> outInverseBind) {
    ANIM_ASSERT(bindGlobalPose.size() == outInverseBind.size());

    for (std::size_t i = 0; i < bindGlobalPose.size(); ++i) {
        Mat4 inverse{};
        if (Invert(ToMat4(bindGlobalPose[i]), inverse)) {
            outInverseBind[i] = inverse;
        } else {
            // スケール 0 のボーンなど。そのボーンに属する頂点は動かなくなるが、
            // ここで落とすよりは処理を続けたほうがよい（第 7 章の判断）。
            outInverseBind[i] = Identity();
        }
    }
}

void ComputeInverseBindMatrices(const Skeleton& skeleton,
                                std::span<const Transform> bindLocalPose,
                                std::span<Mat4> outInverseBind) {
    std::vector<Transform> bindGlobal(skeleton.BoneCount());
    ComputeGlobalPose(skeleton, bindLocalPose, bindGlobal);
    ComputeInverseBindMatricesFromGlobal(bindGlobal, outInverseBind);
}
```

`std::vector` を関数内で確保していますが、**これはロード時にしか呼ばれない関数**なので問題ありません。毎フレーム呼ばれる関数とは基準が違います。「アロケーションを避ける」という方針は、**毎フレームの経路に対してのみ**適用します。どこにでも適用すると、コードが不必要に読みにくくなります。

`Invert` の失敗を単位行列で埋めているのは、第 7 章で述べた判断の適用です。0 スケールのボーンは DCC の運用として実在するので、`assert` で止めるべきではありません。**ただし黙って通すのも良くない**ので、実際のロード処理（第 34 章）では、この状況を検出したらログに残します。

## 15.5　なぜ `Mat4` で持つのか

第 11 章で「ボーンの姿勢は `Transform` で持つ」と決めました。なのに逆バインド行列は `Mat4` です。矛盾ではなく、**使われ方が違う**からです。

**① 補間しない。** `Transform` を選んだ最大の理由は補間できることでした（第 11 章 11.1 節）。逆バインド行列はロード時に一度計算したきり、二度と変わりません。補間の必要がないなら、`Transform` の利点は消えます。

**② 非一様スケールやせん断を含みうる。** DCC ツールでボーンに非一様スケールが設定されていると、バインドポーズのグローバル行列にはせん断が入ります（第 11 章 11.7 節）。`Transform` では表せませんが、`Mat4` なら表せます。**入ってきたものをそのまま保持できる**ほうが安全です。

**③ glTF が行列で持っている。** `skin.inverseBindMatrices` は 16 float の配列です。第 34 章では、**そのまま転置して読み込むだけ**になります。`Transform` に分解する必要がありません。

**④ 結局パレットで行列と掛ける。** 第 16 章で `globalPose[i] * inverseBind[i]` を計算するとき、どのみち `Mat4` に変換します。あらかじめ `Mat4` で持っていれば、変換が 1 回減ります。

### 誰が所有するのか

逆バインド行列は、**スケルトンと同じく「モデル固有で不変」**です。1000 体のキャラクターで共有できます。

```cpp
// メッシュとスケルトンの結びつきを表す。
// スケルトンと同様、1 つのモデルにつき 1 つ。キャラクター間で共有する。
struct SkinBinding {
    std::vector<Mat4> inverseBind;   // ボーン数ぶん
};
```

100 ボーンで 6.4 KB。1000 体でも 6.4 KB のままです（共有しているので）。

> **スケルトンとスキンは同じとは限らない**
> glTF では、`skin.joints` がスケルトン全体の**部分集合**であることがあります。「顔のボーンはスキニングに使わない」といったケースです。この場合、逆バインド行列の配列は `joints` の並び順で、スケルトンのボーンインデックスとは対応しません。第 34 章でこの対応表を作ります。本書では話を単純にするため、**第 33 章までは「スキンのジョイント = スケルトンのボーン」と仮定**して進めます。

## 15.6　レストポーズとバインドポーズが違うとき

15.2 節で「一致しないこともある」と書きました。実際に何が起きるのか、確認しておきます。

腕のスケルトンで、**バインドポーズだけ肩を 0.4 ラジアン回した状態**を考えます。レストポーズは今までどおり、腕を +X にまっすぐ伸ばした状態です。

このとき、

- **カレントポーズ = バインドポーズ**（肩 0.4 rad）なら、パレットは単位行列。頂点は動かない。
- **カレントポーズ = レストポーズ**（肩 0 rad）なら、パレットは単位行列**ではない**。メッシュは肩を −0.4 rad 戻した形に変形される。

つまり、**レストポーズはもはや「メッシュが正しく見える姿勢」ではありません。** これは正常な動作です。

ここで起きがちな事故は、**逆バインド行列をレストポーズから計算してしまう**ことです。そうすると「カレント = レストのとき無変形」になり、一見すると正しく動きます。しかしメッシュの実際の頂点座標はバインドポーズ基準なので、**モデル全体が微妙にねじれた状態が「無変形」として扱われます**。

症状は「モデルを読み込んだ直後から、肩や腰が少しおかしい」。目視では「そういうモデルかな」と見過ごしやすく、しかもアニメーションを再生すると全フレームに同じ歪みが乗ります。

**逆バインド行列は必ずバインドポーズから計算する。** 手書きのテストデータでは両者を一致させて構いませんが、**API の上では別物として扱い、区別を残しておく**ことが、第 34 章での事故を防ぎます。

## 15.7　テストを書く

`AnimLib.Tests/BindPoseTests.cpp`：

```cpp
#include "CppUnitTest.h"

#include "TestSupport/MathAssert.h"
#include "TestSupport/SkeletonSupport.h"
#include "TestSupport/TestRandom.h"
#include "TestSupport/Tolerance.h"

#include "anim/BindPose.h"

#include <numbers>
#include <vector>

using namespace Microsoft::VisualStudio::CppUnitTestFramework;
using namespace anim;
using anim::test::AssertNear;

namespace { constexpr float kPi = std::numbers::pi_v<float>; }

namespace AnimLibTests {

TEST_CLASS(BindPoseTests) {
public:

    // 定義そのもの：inverseBind[i] * bindGlobal[i] = I
    TEST_METHOD(InverseBindUndoesBindGlobal) {
        const Skeleton s = test::MakeArmSkeleton();
        const Pose bind = Pose::FromRest(s);

        std::vector<Transform> bindGlobal(s.BoneCount());
        ComputeGlobalPose(s, bind.Locals(), bindGlobal);

        std::vector<Mat4> inverseBind(s.BoneCount());
        ComputeInverseBindMatrices(s, bind.Locals(), inverseBind);

        for (BoneIndex i = 0; i < s.BoneCount(); ++i) {
            AssertNear(Identity(), inverseBind[i] * ToMat4(bindGlobal[i]),
                       test::kEpsAccum);
            AssertNear(Identity(), ToMat4(bindGlobal[i]) * inverseBind[i],
                       test::kEpsAccum);
        }
    }

    // 15.3 節の導出そのもの：
    // 頂点をボーンローカルへ引き戻し、現在の姿勢へ送ると正しい位置に来る
    TEST_METHOD(VertexFollowsItsBone) {
        const Skeleton s = test::MakeArmSkeleton();
        const Pose bind = Pose::FromRest(s);

        std::vector<Mat4> inverseBind(s.BoneCount());
        ComputeInverseBindMatrices(s, bind.Locals(), inverseBind);

        // 肘の少し先にある頂点（前腕の表面のつもり）
        // バインドポーズでのモデル空間座標
        const Vec3 vertex{0.4f, 1.5f, 0.02f};
        const BoneIndex forearm = s.FindBone("elbow");

        // 肘を +90 度曲げる
        Pose current = Pose::FromRest(s);
        current[forearm].rotation = MakeQuatAxisAngle({0, 0, 1}, kPi * 0.5f);
        std::vector<Transform> global(s.BoneCount());
        ComputeGlobalPose(s, current.Locals(), global);

        // ① 逆バインド行列を使って変形
        const Vec3 skinned =
            TransformPoint(ToMat4(global[forearm]) * inverseBind[forearm], vertex);

        // ② 手計算：肘は (0.3, 1.5, 0) にあり、頂点はそこから
        //    +X に 0.1 m、+Z に 0.02 m の位置。
        //    肘が Rz(90°) 回ると、+X 方向は +Y 方向になる。
        //    → (0.3, 1.5 + 0.1, 0.02) = (0.3, 1.6, 0.02)
        AssertNear(Vec3{0.3f, 1.6f, 0.02f}, skinned, test::kEpsPos);
    }

    // バインドポーズのままなら、どんな頂点も動かない
    TEST_METHOD(BindPoseProducesNoDeformation) {
        const Skeleton s = test::MakeArmSkeleton();
        const Pose bind = Pose::FromRest(s);

        std::vector<Transform> global(s.BoneCount());
        ComputeGlobalPose(s, bind.Locals(), global);
        std::vector<Mat4> inverseBind(s.BoneCount());
        ComputeInverseBindMatrices(s, bind.Locals(), inverseBind);

        test::TestRandom rng;
        for (BoneIndex i = 0; i < s.BoneCount(); ++i) {
            const Mat4 skin = ToMat4(global[i]) * inverseBind[i];
            for (int k = 0; k < 20; ++k) {
                const Vec3 v = rng.NextVec3(2.0f);
                AssertNear(v, TransformPoint(skin, v), test::kEpsPos);
            }
        }
    }

    // レストポーズと違うバインドポーズでも、同じ性質が成り立つ（15.6 節）
    TEST_METHOD(WorksWithBindPoseDifferentFromRest) {
        const Skeleton s = test::MakeArmSkeleton();

        Pose bind = Pose::FromRest(s);
        bind[s.FindBone("shoulder")].rotation = MakeQuatAxisAngle({0, 0, 1}, 0.4f);

        std::vector<Mat4> inverseBind(s.BoneCount());
        ComputeInverseBindMatrices(s, bind.Locals(), inverseBind);

        std::vector<Transform> global(s.BoneCount());
        ComputeGlobalPose(s, bind.Locals(), global);

        test::TestRandom rng;
        for (BoneIndex i = 0; i < s.BoneCount(); ++i) {
            const Mat4 skin = ToMat4(global[i]) * inverseBind[i];
            AssertNear(Identity(), skin, test::kEpsAccum);
            const Vec3 v = rng.NextVec3(2.0f);
            AssertNear(v, TransformPoint(skin, v), test::kEpsPos);
        }
    }

    // レストポーズから計算した逆バインド行列は「違う答え」になること
    // （15.6 節の事故を、仕様として記録する）
    TEST_METHOD(UsingRestInsteadOfBindGivesDifferentResult) {
        const Skeleton s = test::MakeArmSkeleton();

        Pose bind = Pose::FromRest(s);
        bind[s.FindBone("shoulder")].rotation = MakeQuatAxisAngle({0, 0, 1}, 0.4f);

        std::vector<Mat4> fromBind(s.BoneCount());
        std::vector<Mat4> fromRest(s.BoneCount());
        ComputeInverseBindMatrices(s, bind.Locals(), fromBind);
        ComputeInverseBindMatrices(s, s.RestLocals(), fromRest);

        // 肩より先のボーンでは異なる
        const BoneIndex hand = s.FindBone("hand");
        Assert::IsFalse(anim::test::IsNear(fromBind[hand].m[0][0],
                                           fromRest[hand].m[0][0], 1.0e-3f));
    }

    // 0 スケールのボーンでも落ちない（第 7 章の判断の確認）
    TEST_METHOD(DegenerateBoneFallsBackToIdentity) {
        SkeletonBuilder b;
        b.AddRoot("root");
        b.AddBone("dead", "root", Transform{{0, 0, 0}, QuatIdentity(), {0, 0, 0}});
        const Skeleton s = b.Build();

        std::vector<Mat4> inverseBind(s.BoneCount());
        ComputeInverseBindMatrices(s, s.RestLocals(), inverseBind);

        AssertNear(Identity(), inverseBind[1]);
    }

    // ランダムなバインドポーズでも成り立つ
    TEST_METHOD(HoldsForRandomBindPoses) {
        const Skeleton s = test::MakeArmSkeleton();
        test::TestRandom rng;

        for (int trial = 0; trial < 300; ++trial) {
            Pose bind(s.BoneCount());
            for (BoneIndex i = 0; i < s.BoneCount(); ++i) {
                bind[i] = Transform{rng.NextVec3(1.0f), rng.NextQuat(), {1, 1, 1}};
            }
            std::vector<Transform> global(s.BoneCount());
            ComputeGlobalPose(s, bind.Locals(), global);
            std::vector<Mat4> inverseBind(s.BoneCount());
            ComputeInverseBindMatrices(s, bind.Locals(), inverseBind);

            for (BoneIndex i = 0; i < s.BoneCount(); ++i) {
                const Vec3 v = rng.NextVec3(2.0f);
                AssertNear(v, TransformPoint(ToMat4(global[i]) * inverseBind[i], v),
                           1.0e-2f, 1.0e-4f);
            }
        }
    }
};

}  // namespace AnimLibTests
```

`VertexFollowsItsBone` が、この章の中心です。**逆バインド行列を使った計算結果と、紙の上の推論を突き合わせています。**

頂点 `(0.4, 1.5, 0.02)` は、バインドポーズで肘 `(0.3, 1.5, 0)` から +X に 0.1 m、+Z に 0.02 m の位置にあります。肘が Z 軸まわりに 90 度回れば、+X 方向は +Y 方向に変わります。だから `(0.3, 1.5+0.1, 0.02) = (0.3, 1.6, 0.02)`。**逆バインド行列という抽象が、具体的に何をしているのかがこの 1 本で見えます。**

`UsingRestInsteadOfBindGivesDifferentResult` は、第 11 章の非一様スケールのテストと同じく**「間違えたらどうなるか」を仕様として残す**タイプのテストです。第 34 章で glTF の `inverseBindMatrices` を読むとき、「ノードの TRS から計算すればいいのでは」という誘惑に対する答えになります。

## 15.8　つまずきやすいところ

**モデルが読み込んだ直後からねじれている**
逆バインド行列をレストポーズから計算しています。15.6 節を参照してください。glTF なら、ファイルが持っている `inverseBindMatrices` をそのまま使います（第 34 章）。

**メッシュが原点に潰れる、または巨大化する**
逆バインド行列の掛ける順序が逆です。`globalPose * inverseBind` が正しく、`inverseBind * globalPose` ではありません。バインドポーズで単位行列になるかどうかを確かめれば、すぐ分かります。

**特定のボーンに属する頂点だけが動かない**
そのボーンで `Invert` が失敗し、単位行列にフォールバックしています。バインドポーズのスケールに 0 が入っていないか確認してください。

**逆バインド行列を毎フレーム計算している**
ロード時に一度で足りるものです。100 ボーンぶんの `Invert` は決して軽くありません（第 7 章）。`SkinBinding` のような形で保持してください。

**逆バインド行列の配列とボーンインデックスがずれる**
glTF の `skin.joints` はスケルトンの部分集合でありうるので、逆バインド行列の `k` 番目は「`joints[k]` 番目のボーン」に対応します。第 34 章でこの対応表を作ります。

**行列が転置されている**
glTF の `inverseBindMatrices` は列優先格納です。本書は行優先なので、読み込み時に転置が必要です（第 6 章、第 34 章）。転置を忘れると、モデルが派手に歪みます。

## この章のまとめ

- 頂点座標の基準は**バインドポーズ**（メッシュがスケルトンに紐づけられた瞬間の姿勢）。
- **レストポーズ・バインドポーズ・カレントポーズ**は別物。多くのモデルでは前 2 つが一致するが、glTF は別々に持てる設計なので、API でも区別する。
- 導出は 2 ステップ ―― **`B_i⁻¹` で頂点をボーンのローカル空間に引き戻し、`G_i` で現在の位置へ送る**。だから `skinMatrix[i] = globalPose[i] · inverseBind[i]`。
- **カレント = バインドなら単位行列**。これが最重要のテスト。
- 逆バインド行列は `Transform` ではなく **`Mat4`** で持つ。補間しない・せん断を含みうる・glTF が行列でくれる・どのみち行列と掛ける、の 4 つの理由から。
- 逆バインド行列はスケルトンと同じく**モデル固有で不変**。1000 体で共有できる（100 ボーンで 6.4 KB）。
- 「アロケーションを避ける」方針は、**毎フレームの経路にだけ**適用する。ロード時の関数まで縛るとコードが読みにくくなるだけ。

次章で第 III 部が完成します。グローバルポーズと逆バインド行列を掛け合わせ、**スキニング行列パレット** ―― アニメーションシステムの最終出力を作ります。
