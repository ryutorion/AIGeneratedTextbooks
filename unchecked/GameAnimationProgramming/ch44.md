# 第 44 章　ブレンドツリー

**この章で作るもの**：ここまでの部品（ブレンド、加算、マスク、ブレンドスペース）を**組み合わせ可能**にする仕組み。そして「毎フレーム 1 回もアロケートしない」という第 14 章からの目標を、最後まで守ります。

---

## 44.1　部品を組み合わせる

実際のキャラクターのアニメーションは、こういう構造になります。

```
                    ┌─ マスク（上半身） ─┐
                    │                    │
      ┌─ 加算（呼吸）─┤                    ├─ 手を振る
      │              │                    │
 出力 ┤              └─ ロコモーション ────┤
      │                                   ├─ ブレンドスペース
      └─ 加算（被弾）                      │   （待機・歩き・走り）
```

これを手続き的に書くと、こうなります。

```cpp
// ⚠ 構造が固定される書き方
blendSpace.Evaluate(temp1);
BlendPoseMasked(temp1, waveClip, upperMask, temp2);
ApplyAdditive(temp2, breathAdditive, 1.0f, temp3);
ApplyAdditive(temp3, hitAdditive, hitWeight, out);
```

動きますが、**構造がコードに焼き付いています**。キャラクターごとに違う構成にしたい、ツールで編集したい、データとして保存したい ―― どれもできません。

**ブレンドツリー**は、この構造を**ノードのグラフ**として表現します。

## 44.2　ノードの設計

```cpp
// AnimLib/include/anim/BlendTree.h
#pragma once

#include "anim/AdditiveBlend.h"
#include "anim/BoneMask.h"
#include "anim/ClipPlayer.h"

namespace anim {

class PoseBufferPool;

class BlendNode {
public:
    virtual ~BlendNode() = default;

    // 時刻 time でのポーズを out に書く。
    // 中間結果が必要なら pool から借りて、必ず返すこと。
    virtual void Evaluate(float time, PoseBufferPool& pool, Pose& out) const = 0;

    // このノードの評価に必要な、追加バッファの最大数。
    // セットアップ時に一度だけ問い合わせる。
    [[nodiscard]] virtual int MaxBuffers() const = 0;
};

}  // namespace anim
```

**`MaxBuffers()` が、この設計の要**です。ツリーを構築した時点で、評価に必要なバッファ数が**静的に分かります**。だから起動時に確保して、以後は借りて返すだけ。

### 葉ノード

```cpp
class ClipNode : public BlendNode {
public:
    explicit ClipNode(const Clip* clip) : clip_(clip) {}

    void Evaluate(float time, PoseBufferPool&, Pose& out) const override {
        if (clip_ != nullptr) { clip_->Sample(time, out); }
    }
    [[nodiscard]] int MaxBuffers() const override { return 0; }

private:
    const Clip* clip_;
};
```

葉は**追加バッファを必要としません**。`out` に直接書くだけです。

### ブレンドノード

```cpp
class BlendNode2 : public BlendNode {
public:
    BlendNode2(std::unique_ptr<BlendNode> a, std::unique_ptr<BlendNode> b, float weight)
        : a_(std::move(a)), b_(std::move(b)), weight_(weight) {}

    void SetWeight(float w) { weight_ = w; }

    void Evaluate(float time, PoseBufferPool& pool, Pose& out) const override {
        // 重みが端なら、片方だけ評価すればよい（早期打ち切り）
        if (weight_ <= 0.0f) { a_->Evaluate(time, pool, out); return; }
        if (weight_ >= 1.0f) { b_->Evaluate(time, pool, out); return; }

        a_->Evaluate(time, pool, out);            // ① a を out に
        Pose* scratch = pool.Acquire();           // ② 1 本借りる
        b_->Evaluate(time, pool, *scratch);       // ③ b を scratch に
        BlendPose(out, *scratch, weight_, out);   // ④ その場で混ぜる
        pool.Release(1);
    }

    [[nodiscard]] int MaxBuffers() const override {
        return std::max(a_->MaxBuffers(), 1 + b_->MaxBuffers());
    }

private:
    std::unique_ptr<BlendNode> a_;
    std::unique_ptr<BlendNode> b_;
    float weight_;
};
```

**④ で `out` を入力にも出力にも使っている**のが要点です。第 38 章で「`BlendPose` は出力が入力と同じでも安全」と保証しておいたので、これができます。バッファが 1 本節約されます。

**早期打ち切り**（重み 0 や 1 で片方だけ評価）も重要です。ブレンドスペースでは、9 個のサンプルのうち 6 個の重みが 0 になります。それらを評価しないだけで、コストが大幅に下がります。

### `MaxBuffers` の式

```cpp
return std::max(a_->MaxBuffers(), 1 + b_->MaxBuffers());
```

- **`a` の評価中**：`a` が必要とするバッファだけ。自分はまだ借りていない
- **`b` の評価中**：自分が 1 本借りた状態 + `b` が必要とする数

この 2 つの最大値が、このノードの必要数です。

## 44.3　バッファプール

```cpp
// 評価中に使う一時ポーズの置き場。
// 起動時に必要数だけ確保し、以後アロケートしない。
class PoseBufferPool {
public:
    void Reset(std::size_t boneCount, std::size_t capacity) {
        buffers_.clear();
        buffers_.reserve(capacity);
        for (std::size_t i = 0; i < capacity; ++i) {
            buffers_.emplace_back(boneCount);
        }
        inUse_ = 0;
        peak_ = 0;
    }

    [[nodiscard]] Pose* Acquire() {
        if (inUse_ >= buffers_.size()) {
            ANIM_ASSERT(false && "バッファが足りない。MaxBuffers() の計算を確認");
            return nullptr;
        }
        peak_ = std::max(peak_, inUse_ + 1);
        return &buffers_[inUse_++];
    }

    void Release(std::size_t count) {
        ANIM_ASSERT(count <= inUse_);
        inUse_ -= count;
    }

    [[nodiscard]] std::size_t InUse() const noexcept { return inUse_; }
    [[nodiscard]] std::size_t Peak() const noexcept { return peak_; }
    [[nodiscard]] std::size_t Capacity() const noexcept { return buffers_.size(); }

private:
    std::vector<Pose> buffers_;
    std::size_t inUse_ = 0;
    std::size_t peak_ = 0;
};
```

**スタック的な借り方**を強制しています。`Acquire` は先頭から順に貸し、`Release(n)` は末尾から `n` 本返す。**評価が再帰的で、借りた順と逆順に返す**ので、この単純な方式で足ります。

`peak_` を記録しているのは、**`MaxBuffers()` の計算が正しいかを実行時に検証する**ためです。テストで `peak_ <= MaxBuffers()` を確認します。

## 44.4　必要なバッファ数を測る

44.1 節の構成を実際に組んで、`MaxBuffers()` を測りました。

```
MaskNode
 ├─ base:    BlendNode2（locomotion）
 │            ├─ a: BlendNode2（idle / walk）
 │            │      ├─ a: ClipNode(idle)
 │            │      └─ b: ClipNode(walk)
 │            └─ b: ClipNode(run)
 └─ overlay: ClipNode(wave)
```

結果は **1 本**でした。

意外に思うかもしれません。深さ 3 のツリーなのに、追加バッファは 1 本で足りる。

理由は、**`a` を `out` に直接評価してから `b` 用に 1 本借りる**という順序にあります。

```
① lower の a（idle）を out に        借用 0
② lower の b（walk）に 1 本借りる      借用 1 ← ピーク
③ 混ぜて返す                          借用 0
④ locomotion の b（run）に 1 本借りる  借用 1 ← ピーク
⑤ 混ぜて返す                          借用 0
⑥ mask の overlay に 1 本借りる        借用 1 ← ピーク
⑦ 混ぜて返す                          借用 0
```

**左の枝（`a`）は常に `out` を使い回すので、深さが増えてもバッファは増えません。** 増えるのは、**右の枝（`b`）がさらにブレンドノードだった場合**だけです。

```cpp
// 右の枝が深いツリー：バッファが積み上がる
auto deep = BlendNode2(
    ClipNode(a),
    BlendNode2(                    // ← 右がブレンドノード
        ClipNode(b),
        BlendNode2(ClipNode(c), ClipNode(d), 0.5f),
        0.5f),
    0.5f);
// MaxBuffers = max(0, 1 + max(0, 1 + max(0, 1+0))) = 3
```

**ツリーの形が、必要なメモリを決めます。** 左に深く伸ばせば 1 本、右に深く伸ばせば深さぶん。

これは実用上、意味のある知識です。ブレンドツリーを組むときは、**深い部分を左（`a`）に置く**ほうがメモリ効率が良い。ツールで自動的に並べ替えることもできます。

100 ボーンのポーズは 4 KB なので、バッファ 1 本と 3 本の差は 8 KB。1000 体で 8 MB です。**無視できる差ではありません。**

## 44.5　その他のノード

```cpp
// 加算ノード
class AdditiveNode : public BlendNode {
public:
    void Evaluate(float time, PoseBufferPool& pool, Pose& out) const override {
        base_->Evaluate(time, pool, out);
        if (weight_ <= 0.0f) { return; }          // 早期打ち切り
        Pose* scratch = pool.Acquire();
        additive_->Evaluate(time, pool, *scratch);
        ApplyAdditive(out, *scratch, weight_, out);
        pool.Release(1);
    }
    [[nodiscard]] int MaxBuffers() const override {
        return std::max(base_->MaxBuffers(), 1 + additive_->MaxBuffers());
    }
    // ...
};

// マスクノード
class MaskNode : public BlendNode {
public:
    void Evaluate(float time, PoseBufferPool& pool, Pose& out) const override {
        base_->Evaluate(time, pool, out);
        Pose* scratch = pool.Acquire();
        overlay_->Evaluate(time, pool, *scratch);
        BlendPoseMasked(out, *scratch, mask_, out);
        pool.Release(1);
    }
    // ...
};

// N 入力のブレンドスペースノード
class BlendSpace1DNode : public BlendNode {
public:
    void Evaluate(float time, PoseBufferPool& pool, Pose& out) const override {
        space_->ComputeWeights(parameter_, weights_);

        bool first = true;
        float accumulated = 0.0f;
        for (std::size_t k = 0; k < weights_.size(); ++k) {
            if (weights_[k] <= 0.0f) { continue; }   // 重み 0 は評価しない
            const float phase = phase_;
            const float clipTime = phase * space_->At(k).clip->Duration();

            if (first) {
                space_->At(k).clip->Sample(clipTime, out);
                accumulated = weights_[k];
                first = false;
            } else {
                Pose* scratch = pool.Acquire();
                space_->At(k).clip->Sample(clipTime, *scratch);
                BlendPose(out, *scratch, weights_[k] / (accumulated + weights_[k]), out);
                pool.Release(1);
                accumulated += weights_[k];
            }
        }
    }
    [[nodiscard]] int MaxBuffers() const override { return 1; }
    // ...
};
```

**`BlendSpace1DNode` の `MaxBuffers()` が 1** であることに注目してください。サンプルが 10 個あっても、1 本ずつ借りて返すので、同時に必要なのは 1 本だけです。第 38 章で逐次方式を既定にした理由の 1 つがこれです（累積方式なら、全サンプルぶんの中間結果が要ります）。

## 44.6　評価順序

ツリーの評価は**深さ優先**です。`out` に書き込む順序が、そのまま結果を決めます。

**同じノードを 2 回評価しないこと**にも注意が要ります。ブレンドツリーが DAG（同じノードを複数の親が共有する）になっていると、共有ノードが複数回評価されます。

```
    A       B
     ╲     ╱
      ╲   ╱
        C        ← A と B の両方から評価される
```

本書は**木（tree）に限定**します。`std::unique_ptr` で所有しているので、構造的に DAG を作れません。

DAG が必要になるのは「同じロコモーションを上半身と下半身で共有する」といった場面ですが、**その場合は評価結果をキャッシュする**仕組みが要ります。複雑さに見合わないので、本書は扱いません。

## 44.7　テストを書く

`AnimLib.Tests/BlendTreeTests.cpp`：

```cpp
#include "CppUnitTest.h"

#include "TestSupport/MathAssert.h"
#include "TestSupport/Tolerance.h"

#include "anim/BlendTree.h"

#include <format>
#include <numbers>

using namespace Microsoft::VisualStudio::CppUnitTestFramework;
using namespace anim;

namespace {

constexpr float kPi = std::numbers::pi_v<float>;
constexpr std::size_t kBones = 6;

Clip MakeClip(float endZ, float endAngle) {
    Clip c;
    c.Resize(kBones);
    c.SetDuration(1.0f);
    c.SetLoopMode(LoopMode::Loop);
    c.Bone(0).translation.AddKey(0.0f, {0, 0, 0});
    c.Bone(0).translation.AddKey(1.0f, {0, 0, endZ});
    c.Bone(0).translation.Finalize();
    for (std::size_t b = 1; b < kBones; ++b) {
        const BoneIndex bone = static_cast<BoneIndex>(b);
        c.Bone(bone).rotation.AddKey(0.0f, QuatIdentity());
        c.Bone(bone).rotation.AddKey(1.0f, MakeQuatAxisAngle({0, 0, 1}, endAngle));
        c.Bone(bone).rotation.Finalize();
    }
    return c;
}

std::unique_ptr<ClipNode> Leaf(const Clip* c) {
    return std::make_unique<ClipNode>(c);
}

}  // namespace

namespace AnimLibTests {

TEST_CLASS(BlendTreeTests) {
public:

    // --- バッファ数（44.4 節）------------------------------------

    TEST_METHOD(LeftHeavyTreeNeedsOneBuffer) {
        const Clip idle = MakeClip(0.0f, 0.0f);
        const Clip walk = MakeClip(1.5f, 0.4f);
        const Clip run  = MakeClip(4.0f, 0.9f);
        const Clip wave = MakeClip(0.0f, 1.2f);

        auto lower = std::make_unique<BlendNode2>(Leaf(&idle), Leaf(&walk), 0.5f);
        auto locomotion = std::make_unique<BlendNode2>(std::move(lower), Leaf(&run), 0.25f);

        BoneMask mask;
        mask.Resize(kBones);
        for (BoneIndex i = 3; i < kBones; ++i) { mask.Set(i, 1.0f); }

        auto tree = std::make_unique<MaskNode>(std::move(locomotion), Leaf(&wave), mask);

        Logger::WriteMessage(std::format(L"left-heavy tree needs {} buffers\n",
                                         tree->MaxBuffers()).c_str());
        Assert::AreEqual(1, tree->MaxBuffers());
    }

    // 右に深いツリーは、深さぶんのバッファが要る
    TEST_METHOD(RightHeavyTreeNeedsMoreBuffers) {
        const Clip a = MakeClip(1.0f, 0.1f);
        const Clip b = MakeClip(2.0f, 0.2f);
        const Clip c = MakeClip(3.0f, 0.3f);
        const Clip d = MakeClip(4.0f, 0.4f);

        auto inner = std::make_unique<BlendNode2>(Leaf(&c), Leaf(&d), 0.5f);
        auto middle = std::make_unique<BlendNode2>(Leaf(&b), std::move(inner), 0.5f);
        auto tree = std::make_unique<BlendNode2>(Leaf(&a), std::move(middle), 0.5f);

        Logger::WriteMessage(std::format(L"right-heavy tree needs {} buffers\n",
                                         tree->MaxBuffers()).c_str());
        Assert::AreEqual(3, tree->MaxBuffers());
    }

    // 実行時のピークが、静的な見積もりを超えないこと
    TEST_METHOD(RuntimePeakMatchesTheStaticEstimate) {
        const Clip a = MakeClip(1.0f, 0.1f);
        const Clip b = MakeClip(2.0f, 0.2f);

    // --- 深いツリーでもアロケートしないこと -----------------------

    TEST_METHOD(RepeatedEvaluationDoesNotAllocate) {
        const Clip a = MakeClip(1.0f, 0.1f);
        const Clip b = MakeClip(2.0f, 0.2f);
        const Clip c = MakeClip(3.0f, 0.3f);
        const Clip d = MakeClip(4.0f, 0.4f);

        auto inner = std::make_unique<BlendNode2>(Leaf(&c), Leaf(&d), 0.5f);
        auto middle = std::make_unique<BlendNode2>(Leaf(&b), std::move(inner), 0.5f);
        auto tree = std::make_unique<BlendNode2>(Leaf(&a), std::move(middle), 0.5f);

        PoseBufferPool pool;
        pool.Reset(kBones, static_cast<std::size_t>(tree->MaxBuffers()));
        const std::size_t capacityBefore = pool.Capacity();

        Pose out(kBones);
        for (int i = 0; i < 10000; ++i) {
            tree->Evaluate(static_cast<float>(i % 100) / 100.0f, pool, out);
        }
        // プールが拡張されていない = アロケートしていない
        Assert::AreEqual(capacityBefore, pool.Capacity());
        Assert::AreEqual(std::size_t{0}, pool.InUse());
    }
};

}  // namespace AnimLibTests
```

`LeftHeavyTreeNeedsOneBuffer` と `RightHeavyTreeNeedsMoreBuffers` を**対で書いている**のが要点です。「深さ 3 のツリーが 1 本で足りる」という事実は、`MaxBuffers()` の式の意味を理解していないと驚きます。両方をテストにすることで、**「ツリーの形がメモリを決める」という性質が記録されます**。

`RepeatedEvaluationDoesNotAllocate` は、第 14 章から掲げてきた「毎フレーム 1 回もアロケートしない」という目標の、最終的な確認です。10,000 回評価してもプールの容量が変わらない ―― つまり `Acquire` が一度も失敗せず、確保が起きていないことを意味します。

## 44.8　つまずきやすいところ

**「バッファが足りない」でアサートが出る**
`MaxBuffers()` の計算が実装と食い違っています。ノードを追加したら、`MaxBuffers()` も更新してください。`peak_` と `Capacity()` を比べるテストで検出できます。

**評価のたびに結果が違う**
バッファを返し忘れています。`InUse()` が 0 に戻るか確認してください。

**ツリーが深いとメモリを食う**
右の枝が深くなっています。深い部分を左（`a`）に置いてください（44.4 節）。

**同じノードを共有したい**
本書は木に限定しています（44.6 節）。DAG が必要なら、評価結果のキャッシュを実装してください。

**重み 0 のノードも評価されている**
早期打ち切りの分岐が抜けています。ブレンドスペースでは大きな差になります。

**`out` を入力にも使ったら結果が壊れた**
そのノードの演算が「入出力が同じでも安全」でない可能性があります。`BlendPose`、`ApplyAdditive`、`BlendPoseMasked` はすべて安全に作ってあります（第 38・40・41 章）。新しいノードを追加するときは、この性質を保ってください。

**ツリーをデータから構築したい**
ノードの種類を列挙型で持ち、ファクトリで生成する形になります。第 37 章のアセットパックに含めるのが実務的です。

## この章のまとめ

- ブレンドツリーは、ここまでの部品（ブレンド・加算・マスク・ブレンドスペース）を**ノードのグラフ**として組み合わせ可能にする。
- **`MaxBuffers()` が設計の要。** 構築時にバッファ数が静的に分かるので、起動時に確保して以後アロケートしない。
- **`a` を `out` に直接評価してから `b` 用に借りる**という順序が効く。第 38 章で「出力が入力と同じでも安全」を保証したから成立する。
- 実測 ―― **左に深いツリーは 1 本、右に深いツリーは深さぶん**。`max(a, 1 + b)` の式がそのまま出ている。**ツリーの形がメモリを決める。**
- **早期打ち切り**（重み 0 / 1 で片方だけ評価）は、ブレンドスペースで大きく効く。9 サンプルのうち 6 つは評価しない。
- `BlendSpace1DNode` は**サンプルが何個でもバッファ 1 本**。第 38 章で逐次方式を既定にした理由の 1 つ。
- 本書は**木に限定**（`unique_ptr` で構造的に DAG を作れない）。共有が必要ならキャッシュが要るが、複雑さに見合わない。
- **10,000 回評価してもアロケートしない**ことをテストで確認。第 14 章からの目標が、ここで達成された。

次章、この評価を時間軸で切り替える仕組み ―― ステートマシンを作ります。
