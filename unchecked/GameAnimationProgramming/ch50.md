# 第 50 章　関節制限とルックアット

**この章で作るもの**：**ヒンジ制限**（1 軸だけ回る関節）と**円錐制限**（開き角の上限）、それを CCD に組み込んだソルバ、そして**ルックアット**。膝が逆に曲がるのを止め、首が 180 度ひねれないようにします。

そして、この章でも 1 つバグを踏みます。今度は「**制限を差分に掛けた**」というバグです。

---

## 50.1　なぜ制限が要るのか

第 48 章の CCD を、脚に見立てたチェーンで動かしてみます。

```
hip   （腰、y = 1.0）
 ↓ 0.45
thigh （腿）
 ↓ 0.45
shin  （すね）
 ↓ 0.1
foot  （足首）
```

目標を後ろ上方 `(0, 0.55, −0.55)` に置いて解きます。結果:

```
残差 0.0000031  股 74.477 度 / 膝 60.133 度
```

エフェクタは目標にぴったり届いています。残差 `3.1e-6`。CCD としては満点です。

**しかし膝が +60 度曲がっています。** ここでの角度の符号は「`+X` 軸まわりの回転」で、人間の膝が曲がる向きは負です。**膝が逆関節になっている。**

CCD は「エフェクタが目標に届く」ことしか評価していません。そこへ至る途中経過が生物としてありえなくても、アルゴリズムには知る由がない。**解が無数にあるという IK の性質**（第 46 章）が、そのまま「変な解を選ぶ」という形で現れています。

制限とは、**解の集合を狭めて、残ったものだけから選ばせる**仕組みです。

## 50.2　ヒンジ制限 ―― 1 軸だけ回る

膝、肘、指の第 2 関節。これらは**1 つの軸まわりにしか回りません**。しかも回れる角度に上下限があります。

```cpp
struct HingeLimit {
    Vec3  axis     {0,0,1};      // 回れる軸（親のローカル座標系で）
    float minAngle = -kIkPi;
    float maxAngle =  kIkPi;
};
```

やることは 2 つです。

1. ローカル回転から、**軸まわりの成分だけを取り出す**（軸から外れた成分は捨てる）
2. その角度を `[minAngle, maxAngle]` にクランプする

**軸まわりの成分の取り出し**は、**スイング・ツイスト分解**という定石で書けます。クォータニオン `q = (v, w)` のベクトル部 `v` を軸 `a` に射影すると、

```
twist = normalize( (a·(v·a), w) )
```

これが「`a` 軸まわりの回転成分」です。証明は省きますが、直感的には ―― 軸まわりの回転のクォータニオンはベクトル部が軸と平行になるので、平行な成分だけ残せばいい、ということです。

```cpp
inline Quat ApplyHingeLimit(const Quat& localRot, const HingeLimit& limit) {
    const Vec3 axis = Normalize(limit.axis);

    // 軸まわり成分（スイング・ツイスト分解の twist）
    const Vec3 v{localRot.x, localRot.y, localRot.z};
    const Vec3 proj = axis * Dot(v, axis);
    Quat twist{proj.x, proj.y, proj.z, localRot.w};
    if (LengthSquaredQ(twist) < 1.0e-12f) return QuatIdentity();
    twist = Normalize(twist);

    // 角度を取り出してクランプ
    float angle = 2.0f * std::atan2(Length(Vec3{twist.x,twist.y,twist.z}), twist.w);
    if (Dot(Vec3{twist.x,twist.y,twist.z}, axis) < 0.0f) angle = -angle;
    while (angle >  kIkPi) angle -= 2.0f*kIkPi;
    while (angle < -kIkPi) angle += 2.0f*kIkPi;

    const float clamped = std::fmin(limit.maxAngle, std::fmax(limit.minAngle, angle));
    return MakeQuatAxisAngle(axis, clamped);
}
```

**`atan2` で角度を取り出している**のがポイントです。クォータニオンから角度を取るには `2·acos(w)` でもよいのですが、第 46 章で見たとおり `acos` は `w ≈ 1`（＝小さい角度）で精度を失います。`atan2(|v|, w)` なら、小さい角度でも `|v|` が正確に小さくなるので精度が保たれます。**`acos(w)` ではなく `atan2(|v|, w)`** ―― これは第 10 章の `Slerp` でも使った判断です。

**符号の復元。** `atan2(|v|, w)` は常に非負を返します。軸の向きに対して逆回りかどうかは、`v` と `axis` の内積の符号で判定します。

**二重被覆の巻き戻し。** `while` の 2 行は、角度を `[−π, π]` に畳み込んでいます。クォータニオンは `q` と `−q` が同じ回転を表す（第 8 章の二重被覆）ため、取り出した角度が `+270 度` になることがあります。これは `−90 度` と同じ回転です。畳み込まないと、`[−150°, 0°]` の制限に `+270°` を渡して `0°` にクランプされ、正しくは `−90°` で通るべきものが潰されます。

## 50.3　単体テスト：ヒンジ制限

```cpp
TEST_CLASS(HingeLimitTests) {
    static float ZAngleDeg(const Quat& q) {
        const Vec3 v = Rotate(q, Vec3{1,0,0});
        return std::atan2(v.y, v.x) * 180.0f / kIkPi;
    }
public:
    TEST_METHOD(WithinRangePassesThrough) {
        const HingeLimit h{{0,0,1}, 0.0f, kIkPi*0.5f};   // 0〜90 度
        const Quat q = MakeQuatAxisAngle({0,0,1}, 30.0f*kIkPi/180.0f);
        Assert::AreEqual(30.0f, ZAngleDeg(ApplyHingeLimit(q, h)), 1e-3f);
    }

    TEST_METHOD(AboveMaxIsClamped) {
        const HingeLimit h{{0,0,1}, 0.0f, kIkPi*0.5f};
        const Quat q = MakeQuatAxisAngle({0,0,1}, 120.0f*kIkPi/180.0f);
        Assert::AreEqual(90.0f, ZAngleDeg(ApplyHingeLimit(q, h)), 1e-3f);
    }

    TEST_METHOD(BelowMinIsClamped) {
        const HingeLimit h{{0,0,1}, 0.0f, kIkPi*0.5f};
        const Quat q = MakeQuatAxisAngle({0,0,1}, -40.0f*kIkPi/180.0f);
        Assert::AreEqual(0.0f, ZAngleDeg(ApplyHingeLimit(q, h)), 1e-3f);
    }

    TEST_METHOD(OffAxisComponentIsRemoved) {
        const HingeLimit h{{0,0,1}, 0.0f, kIkPi*0.5f};
        const Quat q = MakeQuatAxisAngle({1,0,0}, 50.0f*kIkPi/180.0f);  // X 軸まわり
        const Vec3 v = Rotate(ApplyHingeLimit(q, h), Vec3{0,1,0});
        Assert::AreEqual(0.0f, v.z, 1e-5f);     // Z 成分が消えている
    }
};
```

実測：

```
hinge 30 度   -> 30.000000 度
hinge 120 度  -> 89.999992 度
hinge -40 度  -> 0.000000 度
X 軸 50 度 -> hinge 後の Y 軸像 (0.000000, 1.000000, 0.000000)
```

最後のテストが本質的です。`Z` 軸ヒンジに `X` 軸まわり 50 度の回転を渡すと、**軸外の成分がまるごと捨てられ、単位回転が返ります**。`(0,1,0)` を回した結果が `(0,1,0)` のまま ―― `Z` 成分が `0.000000`。

ヒンジ制限は「クランプ」であると同時に「**投影**」です。許される 1 次元の空間へ、3 次元の回転を落とし込んでいます。

## 50.4　円錐制限 ―― 開き角の上限

肩、股関節、首。これらは**どの方向へも回るが、開きすぎない**関節です。

```cpp
struct ConeLimit {
    Vec3  axis    {1,0,0};        // 基準方向（親のローカル座標系で）
    float maxAngle = kIkPi*0.5f;  // 基準からの最大の開き角
};

inline Quat ApplyConeLimit(const Quat& localRot, const ConeLimit& limit) {
    const Vec3 axis = Normalize(limit.axis);
    const Vec3 rotated = Rotate(localRot, axis);
    const float cosAngle = std::fmin(1.0f, std::fmax(-1.0f, Dot(axis, rotated)));
    const float angle = std::acos(cosAngle);
    if (angle <= limit.maxAngle) return localRot;      // 範囲内：そのまま

    const Vec3 rotAxis = Cross(axis, rotated);
    if (LengthSquared(rotAxis) < 1.0e-12f) return localRot;
    return MakeQuatAxisAngle(Normalize(rotAxis), limit.maxAngle);
}
```

考え方は単純で、「基準方向 `axis` を回した先が、`axis` から `maxAngle` 以上開いていたら、縁まで引き戻す」。

```cpp
TEST_METHOD(ConeClampsOpeningAngle) {
    const ConeLimit c{{1,0,0}, 30.0f*kIkPi/180.0f};
    for (float deg : {10.0f, 30.0f, 70.0f}) {
        const Quat q = MakeQuatAxisAngle({0,0,1}, deg*kIkPi/180.0f);
        const Vec3 v = Rotate(ApplyConeLimit(q, c), Vec3{1,0,0});
        const float open = std::acos(std::fmin(1.0f, std::fmax(-1.0f, Dot(Vec3{1,0,0}, v))))
                         * 180.0f / kIkPi;
        Assert::IsTrue(open <= 30.0f + 1e-3f);
    }
}
```

実測：`10 度 → 10.000007`、`30 度 → 30.000000`、`70 度 → 30.000000`。

**この実装は「ねじれ」を捨てています。** 範囲外だった場合、`MakeQuatAxisAngle` で作り直すので、軸まわりのロールは失われます。厳密には「円錐の外に出た分だけスイングを戻し、ツイストは残す」べきです。ここでも 50.2 のスイング・ツイスト分解が使えます。書籍では単純版に留めますが、**肩や首のように「ねじれ」が意味を持つ関節では、この差が見えます**。

## 50.5　CCD に制限を組み込む

第 49 章 49.12 で予告したとおり、CCD なら素直に入ります。1 関節を回したあと、そのローカル回転にクランプを掛けるだけです。

```cpp
struct JointConstraint {
    bool hasHinge = false;  HingeLimit hinge;
    bool hasCone  = false;  ConeLimit  cone;
};

inline IkSolveResult SolveCcdConstrained(const Skeleton& s, Pose& local,
                                         std::vector<Transform>& global,
                                         const IkChain& chain,
                                         std::span<const JointConstraint> limits,
                                         Vec3 target,
                                         int maxIterations = 16, float tolerance = 1.0e-3f) {
    IkSolveResult r{};
    if (chain.Size() < 2) return r;
    const BoneIndex effector = chain.bones.back();
    ComputeGlobalPose(s, local.Locals(), global);

    for (int iter = 0; iter < maxIterations; ++iter) {
        r.iterations = iter + 1;
        for (std::size_t k = chain.Size() - 1; k-- > 0; ) {
            const BoneIndex joint = chain.bones[k];
            const Vec3 jointPos   = global[joint].translation;
            const Vec3 toEffector = global[effector].translation - jointPos;
            if (LengthSquared(toEffector) < 1.0e-12f) continue;

            const Quat delta = FromToRotation(toEffector, target - jointPos);
            SetGlobalRotation(s, local, global, joint, delta * global[joint].rotation);

            // ---- ここで制限を掛ける ----
            if (k < limits.size()) {
                const JointConstraint& c = limits[k];
                if (c.hasHinge) local[joint].rotation = ApplyHingeLimit(local[joint].rotation, c.hinge);
                if (c.hasCone)  local[joint].rotation = ApplyConeLimit (local[joint].rotation, c.cone);
            }

            UpdateChainGlobals(s, local, global, chain);
        }
        r.residual = Length(target - global[effector].translation);
        if (r.residual < tolerance) { r.converged = true; break; }
    }
    return r;
}
```

**制限は `local[joint].rotation` に掛ける**、つまり**ローカル回転に対して**掛けます。グローバル回転にではありません。「膝は前に曲がらない」は親（腿）から見た関係であって、ワールド座標とは無関係だからです。

**添字に注意。** `limits[k]` の `k` は**チェーン内の位置**です。チェーンが `{hip, thigh, shin, foot}` なら、「膝の曲がり具合」は**すね（shin）のローカル回転**で、チェーン添字は 2 です。腿ではありません。ここを 1 つずらすと、制限が隣の関節に掛かって、**それらしく動くのに何かおかしい**という最悪の症状になります。

（この原稿を書きながら、私はこれを間違えました。膝に掛けたつもりのヒンジが股関節に掛かっていて、「膝 +40 度」という制限範囲外の値が出て気づきました。**制限を入れたら、制限した関節の角度をテストで直接測る** ―― それが唯一の防波堤です。）

## 50.6　単体テスト：膝が逆に曲がらない

50.1 と同じチェーン、同じ目標で、膝に `[−150°, 0°]` のヒンジ、股関節に 90 度の円錐を入れます。

```cpp
TEST_METHOD(KneeNeverBendsBackward) {
    Skeleton s = MakeLeg();
    const IkChain chain{{0,1,2,3}};      // hip, thigh, shin, foot
    std::vector<JointConstraint> lim(3);
    lim[2].hasHinge = true;              // ← すね = 膝の曲がり
    lim[2].hinge = HingeLimit{{1,0,0}, -150.0f*kIkPi/180.0f, 0.0f};
    lim[1].hasCone = true;               // ← 腿 = 股関節の開き
    lim[1].cone = ConeLimit{{0,-1,0}, 90.0f*kIkPi/180.0f};

    Pose p = Pose::FromRest(s);
    std::vector<Transform> g(s.BoneCount());
    const auto r = SolveCcdConstrained(s, p, g, chain, lim, {0, 0.55f, -0.55f}, 32, 1e-4f);

    Assert::IsTrue(r.converged);
    Assert::IsTrue(PitchDeg(p[2].rotation) <=    0.05f);   // 逆関節にならない
    Assert::IsTrue(PitchDeg(p[2].rotation) >= -150.05f);
}
```

| | 残差 | 反復 | 股 | 膝 |
|---|---|---|---|---|
| 制限なし | `0.0000031` | 26 | `74.477°` | **`60.133°`（逆関節）** |
| 制限あり | `0.0000001` | **1** | `90.000°` | **`-0.000°`** |

**制限を入れたほうが、速く・正確に解けました。** 直感に反しますが、理由ははっきりしています。制限なしの CCD は「膝を 60 度逆に曲げ、股を 74 度回す」という、無駄に複雑な経路で目標へ到達していました。制限を入れると、**股関節を 90 度回すだけで脚をまっすぐ伸ばせば届く**ことが分かり、1 反復で終わっています。

**探索空間を狭めることは、必ずしも解を悪くしない。** むしろ「変な解」を除いた結果、素直な解が見つかりやすくなることがあります。

## 50.7　制限が強すぎると、届かなくなる

当然ですが、制限は解を消します。膝を `[−10°, 0°]` ―― ほぼ伸ばしたまま ―― に固定して、腰の真下 `0.5` の位置を狙わせます。脚の全長は `1.0` なので、膝を曲げなければ届きません。

```cpp
TEST_METHOD(OverConstrainedDoesNotConverge) {
    Skeleton s = MakeLeg();
    std::vector<JointConstraint> lim(3);
    lim[2].hasHinge = true;
    lim[2].hinge = HingeLimit{{1,0,0}, -10.0f*kIkPi/180.0f, 0.0f};

    Pose p = Pose::FromRest(s);
    std::vector<Transform> g(s.BoneCount());
    const auto r = SolveCcdConstrained(s, p, g, IkChain{{0,1,2,3}}, lim, {0,0.5f,0}, 32, 1e-4f);

    Assert::IsFalse(r.converged);
    Assert::IsTrue(std::isfinite(r.residual));
    Assert::AreEqual(0.5f, r.residual, 1e-2f);
}
```

実測：`残差 0.5000000  収束=0  膝 -0.000 度  足首 y=0.000000`。

膝は伸びたまま、足首は元の位置。**残差 `0.5` ちょうど**で、まったく動いていません。無限ループにも NaN にもなりません。

**呼び出し側は `converged == false` を見なければなりません。** 残差 `0.5` は「50 cm ずれている」ということです。これを無視して IK の結果をそのまま使うと、足が地面から 50 cm 浮いた絵になります。実務では、

- `converged == false` なら IK を諦めて素のポーズを使う
- `residual` に応じて IK の効き具合をフェードさせる（第 47 章 47.12 のブレンド）
- キャラクター全体を動かす（第 51 章の腰下げ）

のいずれかを選びます。**IK が解けなかったことを、上のレイヤーが知る必要がある**ので `IkSolveResult` に `converged` と `residual` を両方入れました（第 46 章 46.10）。

## 50.8　ルックアット ―― 第 1 版

キャラクターが何かを見る。単一のボーンなら簡単です。「現在の前方ベクトル」を「目標への方向」へ向ける ―― また `FromToRotation` です。首がねじ切れないように、角度に上限を付けます。

```cpp
inline Quat SolveLookAt(const Quat& currentGlobalRot, Vec3 forwardLocal,
                        Vec3 fromPos, Vec3 targetPos, float maxAngle) {
    const Vec3 currentForward = Rotate(currentGlobalRot, Normalize(forwardLocal));
    const Vec3 desired = NormalizeSafe(targetPos - fromPos, currentForward);
    const float cosAngle = std::fmin(1.0f, std::fmax(-1.0f, Dot(currentForward, desired)));
    const float angle = std::acos(cosAngle);
    if (angle <= 1.0e-5f) return currentGlobalRot;

    const Vec3 axis = Cross(currentForward, desired);
    if (LengthSquared(axis) < 1.0e-12f) return currentGlobalRot;

    const float limited = std::fmin(angle, maxAngle);
    return MakeQuatAxisAngle(Normalize(axis), limited) * currentGlobalRot;
}
```

**`forwardLocal` を引数に取る**のは、リグによって「前」がどの軸か違うからです。この本の規約は `-Z` 前方（第 6 章）ですが、DCC ツールから持ち込んだモデルは `+X` や `+Y` が前のことがあります。

単体で使う分には正しく動きます。

```
制限なし: 前方 (1.000000, 0.000000, -0.000000)      ← 真横の目標を正しく向く
45 度制限: 前方 (0.707107, 0.000000, -0.707107)      ← ちょうど 45 度で止まる
真後ろ:   前方 (0.000000, 0.000000, -1.000000)      ← 縮退しても壊れない
```

## 50.9　複数のボーンに分配する ―― そしてバグ

実際の「見る」動作は、首と頭（+ 胸、+ 目）に分配します。首が 30 度、頭がさらに 50 度。合わせて 80 度まで振り向ける。

```cpp
// 首 → 頭 の順に、それぞれ制限つきで目標へ向ける
ComputeGlobalPose(n, p.Locals(), ng);
SetGlobalRotation(n, p, ng, neck,
    SolveLookAt(ng[neck].rotation, {0,0,-1}, ng[neck].translation, target, neckMax));
ComputeGlobalPose(n, p.Locals(), ng);
SetGlobalRotation(n, p, ng, head,
    SolveLookAt(ng[head].rotation, {0,0,-1}, ng[head].translation, target, headMax));
ComputeGlobalPose(n, p.Locals(), ng);
```

1 パスで動かして測ります。目標は右前方 `(2, 1.85, −2)`（45 度の方向）。

```
1 パス: 残り角 0.000 度   首 30.000 度（上限 30）
```

正しい。首が上限いっぱいの 30 度、残り 15 度を頭が担当して、視線はぴったり目標を向いています。

ところが ―― CCD と同じように「2 パス回せばもっと良くなるだろう」と考えて、もう一度同じ処理を回すと。

```
2 パス: 残り角 0.000 度   首 45.080 度（上限 30）
```

**首が 45 度になりました。上限 30 度なのに。**

## 50.10　バグの正体 ―― 制限を「差分」に掛けている

`SolveLookAt` の最後の行を見てください。

```cpp
const float limited = std::fmin(angle, maxAngle);
return MakeQuatAxisAngle(Normalize(axis), limited) * currentGlobalRot;
```

`angle` は「**現在の向きから**目標までの角度」です。`maxAngle` はそれに対する上限。つまりこの関数が制限しているのは、

> **1 回の呼び出しで回す量**

であって、

> **首が最終的にどれだけひねられているか**

ではありません。1 パス目で 30 度回し、2 パス目は「（30 度回った状態から見て）あと 15 度」を制限内と判断してさらに回す。**上限 30 度の関数を 2 回呼べば、60 度まで行けてしまう。**

真後ろの目標 `(−1, 1.85, 3)` だと、もっとはっきり出ます。

```
1 パス: 残り角 81.584 度   首 30.000 度
2 パス: 残り角  1.445 度   首 60.000 度   ← 上限の 2 倍
```

2 パス目で「振り向けた」ように見えますが、これは**首が 60 度ひねれた**からです。絵としては、頭が肩を突き抜けます。

**これは、この本で 3 度目の同じ構造のバグです。**

- 第 28 章：ループ回数とサンプル時刻を、別々の場所で計算した
- 第 45 章：遷移元の状態と遷移元の時刻を、別々の場所で持った
- 第 50 章：**制限したい量（絶対のひねり）と、制限を掛けている量（1 回の差分）が別物だった**

前の 2 つは「対になる 2 つの値を別々に決めた」バグでした。今回は少し形が違って、「**制御したい量と、制御している量が違う**」。共通しているのは、**コードを読んでも気づけず、測って初めて分かる**ことです。1 パスのテストだけ書いていたら、永遠に見つかりませんでした。

## 50.11　絶対量に制限を掛ける

直し方は、**「向きそのもの」を円錐に閉じ込める**ことです。「どれだけ回すか」ではなく「どこを向いているか」を制限します。

```cpp
// dir を、reference を中心とする maxAngle の円錐の中へ閉じ込める
inline Vec3 ClampDirectionToCone(Vec3 dir, Vec3 reference, float maxAngle) {
    const Vec3 d = NormalizeSafe(dir, reference);
    const Vec3 r = Normalize(reference);
    const float c = std::fmin(1.0f, std::fmax(-1.0f, Dot(r, d)));
    const float ang = std::acos(c);
    if (ang <= maxAngle) return d;

    Vec3 axis = Cross(r, d);
    if (LengthSquared(axis) < 1.0e-12f) {
        axis = Cross(r, Vec3{0,1,0});
        if (LengthSquared(axis) < 1.0e-12f) axis = Cross(r, Vec3{1,0,0});
    }
    return Rotate(MakeQuatAxisAngle(Normalize(axis), maxAngle), r);
}

inline Quat SolveLookAtCone(const Quat& currentGlobalRot, Vec3 forwardLocal,
                            Vec3 fromPos, Vec3 targetPos,
                            Vec3 referenceForward, float maxAngle) {
    const Vec3 currentForward = Rotate(currentGlobalRot, Normalize(forwardLocal));
    const Vec3 wanted  = NormalizeSafe(targetPos - fromPos, currentForward);
    const Vec3 clamped = ClampDirectionToCone(wanted, referenceForward, maxAngle);
    return FromToRotation(currentForward, clamped) * currentGlobalRot;
}
```

**`referenceForward` が新しい引数**です。「首にとっての基準方向」＝ 胸の前方、「頭にとっての基準方向」＝ 首の前方を渡します。

```cpp
const Vec3 ref1 = Rotate(ng[chest].rotation, Vec3{0,0,-1});
SetGlobalRotation(n, p, ng, neck,
    SolveLookAtCone(ng[neck].rotation, {0,0,-1}, ng[neck].translation, target, ref1, neckMax));
ComputeGlobalPose(n, p.Locals(), ng);
const Vec3 ref2 = Rotate(ng[neck].rotation, Vec3{0,0,-1});
SetGlobalRotation(n, p, ng, head,
    SolveLookAtCone(ng[head].rotation, {0,0,-1}, ng[head].translation, target, ref2, headMax));
```

決定的なのは、**この関数は何度呼んでも結果が変わらない**ことです。すでに円錐の縁にいるなら、`ang <= maxAngle` を満たすかちょうど縁に張り付くので、さらに回りません。数学でいう**冪等（べきとう）**です。

**「差分を制限する」から「状態を制限する」へ。** 前者は呼び出し回数に依存し、後者は依存しません。IK のように「毎フレーム、何度も、どの順序で呼ばれるか分からない」処理では、**状態に対する制約として書くのが唯一安全な形**です。

## 50.12　単体テスト：冪等であること

このバグを二度と踏まないためのテストは、「上限を超えないこと」ではありません。**「何回呼んでも同じ結果になること」**です。

```cpp
TEST_METHOD(ConeLookAtIsIdempotent) {
    for (Vec3 tgt : {Vec3{2,1.85f,-2}, Vec3{0,1.85f,-3}, Vec3{-1,1.85f,3}}) {
        const float a = RunLookAtCone(tgt, /*passes=*/1);   // 首のひねり角を返す
        const float b = RunLookAtCone(tgt, /*passes=*/4);
        Assert::IsTrue(a <= 30.05f);
        Assert::IsTrue(b <= 30.05f);
        Assert::AreEqual(a, b, 1e-3f);      // ← これが本命
    }
}
```

そして、**壊れているほうも固定します**（第 46 章と同じ考え方）。

```cpp
TEST_METHOD(DeltaLookAtIsNotIdempotent) {
    // 第 1 版は「1 回の回転量」しか制限していない。2 回呼べば 2 倍まで回る。
    Assert::AreEqual(30.0f, RunLookAtDelta({2,1.85f,-2}, 1), 0.1f);
    Assert::IsTrue    (      RunLookAtDelta({2,1.85f,-2}, 2) > 40.0f);   // 実測 45.080
}
```

全 3 目標での実測です。

| 目標 | 版 | 1 パス | 2 パス（差分版）/ 4 パス（円錐版） |
|---|---|---|---|
| `(2, 1.85, −2)` | 差分 | 首 `30.000` | 首 **`45.080`** ← 違反 |
| | 円錐 | 首 `30.000` | 首 `30.000` |
| `(0, 1.85, −3)` | 差分 | 首 `2.862` | 首 `2.862`（制限に届かないので同じ） |
| | 円錐 | 首 `2.862` | 首 `2.862` |
| `(−1, 1.85, 3)` | 差分 | 首 `30.000`、残り角 `81.584` | 首 **`60.000`**、残り角 `1.445` ← 違反 |
| | 円錐 | 首 `30.000`、残り角 `81.584` | 首 `30.000`、残り角 `81.584` |

3 行目の `2.862` は「制限に達していないケース」で、ここでは両版が一致します。**バグは境界でしか現れません。** 目標を 1 つしかテストしていなかったら、それが真正面の目標だった場合、何も起きなかったでしょう。

そして真後ろのケース ―― 円錐版は**残り角 `81.584` を残したまま止まります**。これが正しい挙動です。首 30 度 + 頭 50 度 = 80 度が限界で、161.6 度先の目標には 81.6 度足りない。**「見えないものは見えない」を、正直に返す。**

実務では、この残り角を上のレイヤーが見て、「振り向けないので体ごと回す」「見るのを諦める」という判断をします。IK が勝手に首をねじって「見た」ことにしてはいけません。

## 50.13　実際に使うときの注意

**制限のパラメータはアーティストが決める。** 「膝は 0〜150 度」といった値は、リグごとに違います。ボーン名から自動で推測する仕組み（`.*[Kk]nee.*` にヒンジを当てる、など）は、動くように見えて必ず例外に出会います。**データとして持ち、ツールで編集できるようにする** ―― 第 45 章のステートマシンと同じ結論です。

**軸はどの座標系で定義するか。** この章の実装は、`HingeLimit::axis` を**親から見たローカル座標系**で解釈しています。レストポーズで膝の軸がどちらを向いているかは、リグの作り方次第です。実務では「レストポーズで軸を測って保存する」のが確実です。

**制限とブレンドの順序。** IK の効き具合をブレンドする場合（第 47 章 47.12）、**制限は IK の中で掛け、ブレンドはその後**です。逆にすると、ブレンド結果が制限を破ります ―― これも「差分に制限を掛ける」のと同じ形の間違いです。

## この章のまとめ

- 制限なしの CCD は**膝を逆に曲げる**（実測 `+60.133°`）。エフェクタが届くことしか見ていないので当然。制限とは**解の集合を狭める**仕組み。
- **ヒンジ制限**はスイング・ツイスト分解で軸まわり成分を取り出してクランプする。「クランプ」であると同時に「**投影**」―― 軸外の成分は捨てられる（実測：`X` 軸 50 度 → 単位回転）。
- 角度の取り出しは **`2·acos(w)` ではなく `2·atan2(|v|, w)`**（第 10 章・第 46 章と同じ判断）。二重被覆の**巻き戻しを忘れない**。
- **円錐制限**は基準方向からの開き角をクランプする。単純版はねじれを捨てるので、肩や首では差が見える。
- CCD への組み込みは、**ローカル回転にクランプを掛ける**だけ。ただし**添字はチェーン内の位置** ―― 「膝の曲がり」は「すね」のローカル回転。ずらすと「それらしく動くのに何かおかしい」になる。
- 制限を入れたほうが**速く正確に解けた**（26 反復・逆関節 → **1 反復**・残差 `1e-7`）。**探索空間を狭めることは、必ずしも解を悪くしない。**
- 制限が強すぎると解が消える。**`converged == false` と `residual` を上のレイヤーが見る**（実測：残差 `0.5000000` で完全に停止、NaN も無限ループもなし）。
- **踏んだバグ**：`SolveLookAt` は「1 回で回す量」を制限していた。2 回呼ぶと **上限 30 度が 45 度・60 度**になる。第 28 章・第 45 章に続く 3 度目の構造的バグ ―― 今回は「**制御したい量と、制御している量が違う**」。
- 直し方は「**差分を制限する**」から「**状態を制限する**」へ。`ClampDirectionToCone` で向きそのものを円錐へ閉じ込めると、**冪等**になる。
- テストは「上限を超えないこと」ではなく「**何回呼んでも同じ結果になること**」を主張する。**バグは境界でしか現れない** ―― 真正面の目標だけを試していたら、何も起きなかった。
- 振り向けない目標には**残り角 `81.584` を残したまま止まる**のが正しい。「見えないものは見えない」を正直に返し、判断は上のレイヤーに渡す。

次章は第 VIII 部の最終章、**フット IK**。この章までに作った 2 ボーン IK、制限、そして時間方向の平滑化を組み合わせて、**段差と坂を歩けるキャラクター**を作ります。そしてもう 1 つ ―― 第 46 章 46.3 で予告した「**前フレームの補正結果に重ねてはいけない**」を、実測で確かめます。
