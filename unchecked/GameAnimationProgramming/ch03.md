# 第 3 章　最初のテストヘルパー

**この章で作るもの**：浮動小数点を許容誤差つきで比較するアサート `AssertNear` と、その配列版 `AssertNearSpan`。失敗したときに「どこで」「どれだけ」ずれたのかが一目で分かるメッセージを出すところまで作ります。

---

## 3.1　`AreEqual` では困る

前章の最後で、こう書きました。

```cpp
Assert::AreEqual(2, 1 + 1);
```

整数なら何の問題もありません。では浮動小数点ではどうでしょうか。`AnimLib.Tests/SetupTests.cpp` に、次のテストを一時的に追加して実行してみてください。

```cpp
TEST_METHOD(FloatEqualityIsTricky) {
    Assert::AreEqual(0.3f, 0.1f + 0.2f);
}
```

**赤くなります。** 失敗メッセージはこうです。

```
Assert failed. Expected:<0.3> Actual:<0.3>
```

「0.3 を期待したが 0.3 だった」。これがこの章の出発点です。

`0.1f + 0.2f` の結果は `0.30000001192...`、`0.3f` は `0.29999998211...` で、実際には 1 ULP（表現可能な最小の刻み）ぶんずれています。しかし既定の書式は有効数字を絞って表示するので、メッセージ上では区別がつきません。

そして、これは**直せない種類の問題**です。二進浮動小数点で 0.1 も 0.2 も 0.3 も正確には表せない以上、この誤差は仕様どおりの正しい挙動です。私たちがやるべきなのは誤差をなくすことではなく、**どこまでのずれを「合っている」とみなすかを自分で決めること**です。

アニメーションのコードでは、この問題があらゆる場所に現れます。クォータニオンを補間して、行列に変換して、階層を 20 段たどって、頂点に適用する。この経路のどこにも「厳密に一致する」瞬間はありません。だから本書のテストは、最初から最後まで**許容誤差ベース**で書きます。

---

## 3.2　絶対誤差だけでも、相対誤差だけでも足りない

Microsoft Native Unit Test には、実は許容誤差つきのオーバーロードがあります。

```cpp
Assert::AreEqual(0.3f, 0.1f + 0.2f, 1.0e-5f);  // 通る
```

第 3 引数が許容誤差です。これで解決に見えますが、この `tolerance` は**絶対誤差**です。つまり `|expected - actual| <= tolerance` を見ているだけで、これは扱う数値の大きさが一定の範囲に収まっているときにしか使えません。

アニメーションで扱う数値の桁は、実際にはかなり広く散らばります。

| 量 | 典型的な大きさ |
| --- | --- |
| クォータニオンの成分 | −1 〜 1 |
| ボーンのローカル平行移動（メートル単位） | 0.01 〜 0.5 |
| キャラクターのワールド座標 | 0 〜 数千 |
| 経過時刻（秒） | 0 〜 数千 |
| ウェイト | 0 〜 1 |

ここで許容誤差 `1.0e-5f` を一律に使うとどうなるか。

**大きな値では厳しすぎます。** ワールド座標 `1000.0f` に対する float の刻みは約 `6.1e-5` です。表現可能な隣の値ですら許容誤差を超えてしまうので、このテストは**原理的に通せません**。

**小さな値では緩すぎます。** 正規化されたクォータニオンの成分が `1.0e-5` ずれるのは、実は相当な異常です。それを見逃します。

そこで、両方を組み合わせます。

```
|a - b| <= absTol  または  |a - b| <= relTol * max(|a|, |b|)
```

**片方でも満たせば「近い」とみなす**、という定義です。値が 0 付近のときは絶対誤差の項が効き（相対誤差は 0 付近で意味を失うため）、値が大きいときは相対誤差の項が効きます。

> **ULP 比較を使わない理由**
> 浮動小数点の比較には、ビットパターンを整数として見て「間に何個の表現可能な値があるか」を数える ULP 比較という手法もあります。精密ですが、本書では採用しません。第 4 章で採用する `/fp:fast` のもとでは、コンパイラが演算順序を組み替えるため ULP 単位の再現性そのものが保証されません。また「ボーンを 20 段たどった結果が 3 ULP 以内」のような要求は、そもそも意味のある基準になりません。本書が知りたいのは「**このずれはキャラクターの見た目に影響するか**」であって、それは絶対誤差と相対誤差で語るほうが素直です。

## 3.4　近さの判定を書く

`AnimLib.Tests/TestSupport/Near.h` を作り、まず判定関数だけを書きます。

```cpp
#pragma once

#include <cmath>

namespace anim::test {

// 本書の既定の許容誤差。
// 根拠（と、この値を変える場面）は第 4 章で扱う。
inline constexpr float kDefaultAbsTol = 1.0e-5f;
inline constexpr float kDefaultRelTol = 1.0e-5f;

[[nodiscard]] inline bool IsNear(float a, float b,
                                 float absTol = kDefaultAbsTol,
                                 float relTol = kDefaultRelTol) noexcept {
    // NaN はいかなる値とも「近く」ない。自分自身とも。
    if (std::isnan(a) || std::isnan(b)) {
        return false;
    }
    // ビット一致は無条件で真。同符号の無限大どうしもここで拾える。
    if (a == b) {
        return true;
    }
    // 片方だけ無限大なら差が計算できない（inf - inf は NaN）。
    if (std::isinf(a) || std::isinf(b)) {
        return false;
    }

    const float diff = std::fabs(a - b);
    if (diff <= absTol) {
        return true;       // 0 付近はこちらで救う
    }
    const float scale = std::fmax(std::fabs(a), std::fabs(b));
    return diff <= relTol * scale;   // 大きな値はこちらで救う
}

}  // namespace anim::test
```

短い関数ですが、先頭 3 つの分岐にはそれぞれ理由があります。

**NaN を先に弾く。** NaN が絡む比較はすべて `false` になるので、`diff <= absTol` は自動的に `false` になります。つまり明示的に書かなくても結果は同じです。それでも書くのは、**読む人に「NaN は考慮済みだ」と伝えるため**です。NaN はアニメーションのバグで実際によく出ます（長さ 0 のベクトルを正規化する、`acos` に 1 をわずかに超える値を渡す、など）。

**`a == b` を先に見る。** 無限大どうしを救うためです。`inf == inf` は真ですが、`inf - inf` は NaN なので、差を取る経路に入ると失敗します。

**片方だけ無限大なら偽。** 上と同じ理由で、差を計算する前に弾きます。

> `/fp:fast` のもとでは、コンパイラが NaN や無限大を「起きない」と仮定した最適化を行うことがあります。第 4 章で、この関数だけを局所的に `/fp:precise` に戻します。今はまだ既定の `/fp:precise` なので、このまま動きます。

## 3.5　失敗を報告する ― マクロを使わずに行番号を出す

判定ができたので、失敗をテストフレームワークに伝える部分を書きます。

`Assert::Fail` は、メッセージと**行情報**を受け取れます。

```cpp
Assert::Fail(L"だめでした", LINE_INFO());
```

`LINE_INFO()` は `__FILEW__` `__FUNCTION__` `__LINE__` から `__LineInfo` を組み立てるマクロです。しかしこれをヘルパー関数の中で呼ぶと、**ヘルパー関数自身の行番号**が報告されてしまいます。呼び出し元、つまりテストを書いた側の行を知りたいのに、これでは役に立ちません。

古典的な解決策はヘルパーをマクロにすることですが、C++20 以降は `std::source_location` を既定引数に置くという、はるかに素直な方法が使えます。

```cpp
void AssertNear(float expected, float actual,
                const std::source_location& loc = std::source_location::current());
```

既定引数の `std::source_location::current()` は**呼び出し側で評価される**ので、これだけで呼び出し元の位置が取れます。マクロは不要です。

ただし `__LineInfo` はポインタしか保持しない軽量な型なので、文字列の寿命を自分で管理する必要があります。小さなラッパーを用意します。

`TestSupport/Near.h` に追記します。

```cpp
#include "CppUnitTest.h"

#include <format>
#include <source_location>
#include <span>
#include <string>

namespace anim::test {

namespace detail {

// ASCII 前提の簡易ワイド化。ファイルパスと関数名にしか使わない。
[[nodiscard]] inline std::wstring ToWide(const char* s) {
    std::wstring w;
    for (const char* p = s; *p != '\0'; ++p) {
        w.push_back(static_cast<wchar_t>(static_cast<unsigned char>(*p)));
    }
    return w;
}

// __LineInfo は文字列を所有しないので、実体をここで抱えておく。
// メンバの宣言順（file_, func_, info_）が初期化順を決めるので、入れ替えないこと。
class ScopedLineInfo {
public:
    explicit ScopedLineInfo(const std::source_location& loc)
        : file_(ToWide(loc.file_name())),
          func_(loc.function_name()),
          info_(file_.c_str(), func_.c_str(), static_cast<int>(loc.line())) {}

    [[nodiscard]] const Microsoft::VisualStudio::CppUnitTestFramework::__LineInfo*
    Get() const noexcept {
        return &info_;
    }

private:
    std::wstring file_;
    std::string  func_;
    Microsoft::VisualStudio::CppUnitTestFramework::__LineInfo info_;
};

}  // namespace detail

}  // namespace anim::test
```

`ScopedLineInfo` はコピーすると内部ポインタが古い文字列を指したままになります。ローカル変数として使い、コピーしない、という前提で扱います（気になるならコピーコンストラクタを `= delete` してください）。

## 3.6　`AssertNear`

いよいよ本体です。

```cpp
namespace anim::test {

inline void AssertNear(float expected, float actual,
                       float absTol = kDefaultAbsTol,
                       float relTol = kDefaultRelTol,
                       const std::source_location& loc =
                           std::source_location::current()) {
    if (IsNear(expected, actual, absTol, relTol)) {
        return;
    }

    const float diff  = std::fabs(expected - actual);
    const float scale = std::fmax(std::fabs(expected), std::fabs(actual));

    const std::wstring msg = std::format(
        L"AssertNear failed\n"
        L"  expected : {:.9g}\n"
        L"  actual   : {:.9g}\n"
        L"  diff     : {:.9g}\n"
        L"  absTol   : {:.9g}  (diff/absTol = {:.3g})\n"
        L"  relTol   : {:.9g}  (diff/(relTol*scale) = {:.3g})",
        expected, actual, diff,
        absTol, diff / absTol,
        relTol, diff / (relTol * scale));

    const detail::ScopedLineInfo li(loc);
    Microsoft::VisualStudio::CppUnitTestFramework::Assert::Fail(msg.c_str(), li.Get());
}

}  // namespace anim::test
```

メッセージ設計に少し手を入れてあります。

**`{:.9g}` を使う。** float を往復変換しても値が変わらない有効桁数は 9 桁です（`std::numeric_limits<float>::max_digits10`）。3.1 節で見た「0.3 を期待したが 0.3 だった」を二度と起こさないために、常に 9 桁で出します。

**「許容誤差の何倍ずれたか」を出す。** これが実際にいちばん役に立ちます。`diff/absTol` が `1.3` なら、許容誤差をわずかに超えただけで、原因は誤差の蓄積かもしれません。`4.7e+05` なら、それは誤差ではなく**バグ**です。この 2 つを区別するために、毎回電卓を叩くのは避けたいところです。

**`\n` で改行する。** テストエクスプローラーの詳細ペインでは改行がそのまま表示されます。1 行に詰め込むより格段に読みやすくなります。

## 3.7　配列版 ― `AssertNearSpan`

ベクトルや行列は第 5 章以降に登場しますが、その中身は結局 float の並びです。今のうちに `std::span<const float>` を受け取る版を書いておけば、`Vec3` ができたときはそこへ転送するだけで済みます。

```cpp
namespace anim::test {

namespace detail {

// 数値の並びを "[1, 2, >>3<<, 4]" の形に整形する。
// highlight で指定した要素を >> << で囲んで目立たせる。
[[nodiscard]] inline std::wstring Join(std::span<const float> v,
                                       std::size_t highlight) {
    std::wstring s = L"[";
    for (std::size_t i = 0; i < v.size(); ++i) {
        if (i != 0) {
            s += L", ";
        }
        if (i == highlight) {
            s += L">>";
        }
        s += std::format(L"{:.6g}", v[i]);
        if (i == highlight) {
            s += L"<<";
        }
    }
    s += L"]";
    return s;
}

}  // namespace detail

inline void AssertNearSpan(std::span<const float> expected,
                           std::span<const float> actual,
                           float absTol = kDefaultAbsTol,
                           float relTol = kDefaultRelTol,
                           const std::source_location& loc =
                               std::source_location::current()) {
    namespace mst = Microsoft::VisualStudio::CppUnitTestFramework;
    const detail::ScopedLineInfo li(loc);

    if (expected.size() != actual.size()) {
        const std::wstring msg = std::format(
            L"AssertNearSpan failed: size mismatch\n"
            L"  expected size : {}\n"
            L"  actual size   : {}",
            expected.size(), actual.size());
        mst::Assert::Fail(msg.c_str(), li.Get());
    }

    for (std::size_t i = 0; i < expected.size(); ++i) {
        if (IsNear(expected[i], actual[i], absTol, relTol)) {
            continue;
        }
        const float diff = std::fabs(expected[i] - actual[i]);
        const std::wstring msg = std::format(
            L"AssertNearSpan failed at index {}\n"
            L"  expected : {}\n"
            L"  actual   : {}\n"
            L"  diff     : {:.9g}  (absTol = {:.9g}, relTol = {:.9g})",
            i,
            detail::Join(expected, i),
            detail::Join(actual, i),
            diff, absTol, relTol);
        mst::Assert::Fail(msg.c_str(), li.Get());
    }
}

}  // namespace anim::test
```

**配列全体を出す**のがポイントです。「index 5 が 0.7 のはずが 0.3 だった」だけでは何も分かりませんが、16 個の要素が並んだ行列がまるごと見えれば、「あ、転置されている」「符号が逆だ」と一目で気づけます。行列のバグの大半は、この方法で数秒で判明します。

最初に見つかった不一致で `Assert::Fail` して打ち切っている点に注意してください。すべての不一致を集めて報告する設計もありえますが、行列が転置されていれば 12 箇所が同時に食い違うので、報告が長くなるばかりで得るものがありません。**最初の 1 つと、配列全体の見た目**があれば十分です。

## 3.8　カスタム型を `Assert` に見せる方法（予告）

第 5 章で `Vec3` を作ると、こう書きたくなります。

```cpp
Assert::AreEqual(expected, actual);   // expected, actual は Vec3
```

これはコンパイルエラーになります。`Assert::AreEqual` はテンプレートで、失敗時にメッセージを作るために `ToString<T>` を呼ぶのですが、その既定実装がユーザー定義型に対応していないためです。解決策は特殊化を書くことです。

```cpp
namespace Microsoft::VisualStudio::CppUnitTestFramework {
template<>
inline std::wstring ToString<anim::Vec3>(const anim::Vec3& v) {
    return std::format(L"Vec3({:.9g}, {:.9g}, {:.9g})", v.x, v.y, v.z);
}
}  // namespace
```

第 5 章でこの形を使いますが、**`Assert::AreEqual` で `Vec3` を比較する場面はほとんどありません。** 浮動小数点なので、結局 `AssertNear` 系を使うことになるからです。`ToString` の特殊化が効いてくるのは、`Assert::IsTrue` の第 2 引数にメッセージを添えるときや、後述の `Logger::WriteMessage` で状態を吐き出すときです。

## 3.9　ヘルパー自身をテストする

テストを守るための道具が壊れていたら、その下のすべてが信用できません。`IsNear` にもテストを書きます。

`AnimLib.Tests/NearTests.cpp` を新規作成します。

```cpp
#include "CppUnitTest.h"

#include "TestSupport/Near.h"

#include <cmath>
#include <limits>

using namespace Microsoft::VisualStudio::CppUnitTestFramework;
using anim::test::IsNear;

namespace AnimLibTests {

TEST_CLASS(NearTests) {
public:

    TEST_METHOD(ExactlyEqualIsNear) {
        Assert::IsTrue(IsNear(1.0f, 1.0f));
        Assert::IsTrue(IsNear(0.0f, 0.0f));
        Assert::IsTrue(IsNear(0.0f, -0.0f));   // +0 == -0 は真
    }

    // 0 の近くでは絶対誤差が効く
    TEST_METHOD(AbsoluteToleranceRescuesNearZero) {
        // 相対誤差だけなら、この 2 つは 100% 違う値ということになってしまう
        Assert::IsTrue(IsNear(0.0f, 1.0e-7f));
        Assert::IsFalse(IsNear(0.0f, 1.0e-3f));
    }

    // 大きな値では相対誤差が効く
    TEST_METHOD(RelativeToleranceRescuesLargeValues) {
        // 1e6 に対する差 1.0 は、絶対誤差 1e-5 をはるかに超えるが
        // 相対誤差では 1e-6 なので許容される
        Assert::IsTrue(IsNear(1.0e6f, 1.0e6f + 1.0f));
        // 差 100 は相対 1e-4 なので、許容されない
        Assert::IsFalse(IsNear(1.0e6f, 1.0e6f + 100.0f));
    }

    // float の刻みそのものを超えられないケースが救われることの確認
    TEST_METHOD(AdjacentFloatsAreAlwaysNear) {
        const float a = 1000.0f;
        const float b = std::nextafterf(a, 2000.0f);  // 表現可能な次の値
        // 差は約 6.1e-05。絶対誤差 1e-05 では救えないが、相対誤差では救える。
        Assert::IsFalse(a == b);          // ビットとしては違う
        Assert::IsTrue(IsNear(a, b));     // が、「近い」
    }

    TEST_METHOD(NanIsNeverNear) {
        const float nan = std::numeric_limits<float>::quiet_NaN();
        Assert::IsFalse(IsNear(nan, 1.0f));
        Assert::IsFalse(IsNear(1.0f, nan));
        Assert::IsFalse(IsNear(nan, nan));   // 自分自身とも近くない
    }

    TEST_METHOD(InfinityCompares) {
        const float inf = std::numeric_limits<float>::infinity();
        Assert::IsTrue(IsNear(inf, inf));
        Assert::IsFalse(IsNear(inf, -inf));
        Assert::IsFalse(IsNear(inf, 1.0e30f));
    }

    // 0.1 + 0.2 問題が解決していることの確認（3.1 節のリベンジ）
    TEST_METHOD(TheClassicCase) {
        anim::test::AssertNear(0.3f, 0.1f + 0.2f);
    }
};

}  // namespace AnimLibTests
```

`Assert::IsTrue` / `IsFalse` で `IsNear`（**述語のほう**）をテストしている点に注目してください。`AssertNear`（**失敗するとテストを落とすほう**）は、その性質上「失敗すること」を素直にテストできません。だから、判定ロジックを述語として切り出し、そちらをテスト対象にしています。この分離は、ヘルパーを設計するときの定石です。

`Ctrl+R, A` で実行し、`NearTests` の 7 つが緑になることを確認してください。

## 3.10　わざと失敗させて、メッセージを読む

最後に、この章でいちばん大事な作業をします。**メッセージが実際にどう見えるかを、自分の目で確認します。**

`NearTests.cpp` に、一時的に次のテストを追加してください。

```cpp
    TEST_METHOD(TemporarilyFailing) {
        // 確認したら消すこと
        anim::test::AssertNear(1.0f, 1.5f);

        const float expectedMat[4] = {1.0f, 0.0f, 0.0f, 1.0f};
        const float actualMat[4]   = {1.0f, 0.0f, 0.5f, 1.0f};
        anim::test::AssertNearSpan(expectedMat, actualMat);
    }
```

実行すると、テストエクスプローラーの詳細ペインにこう出ます。

```
AssertNear failed
  expected : 1
  actual   : 1.5
  diff     : 0.5
  absTol   : 1e-05  (diff/absTol = 5e+04)
  relTol   : 1e-05  (diff/(relTol*scale) = 3.33e+04)
```

`diff/absTol = 5e+04` ―― 許容誤差の 5 万倍ずれています。これは誤差の蓄積ではなく、明確なバグだと即座に判断できます。

2 つ目のアサートを見るために 1 つ目をコメントアウトして再実行すると、

```
AssertNearSpan failed at index 2
  expected : [1, 0, >>0<<, 1]
```

配列全体が見え、問題の要素が `>> <<` で囲まれています。

## 3.11　つまずきやすいところ

**`error C2039: 'format': 'std' のメンバーではありません`**
`/std:c++latest` が効いていません。第 2 章の `AnimBook.props` がテストプロジェクトにも適用されているか確認してください。

**`std::format` にワイド文字列を渡すとエラーになる**
書式文字列とすべての引数の文字型が揃っている必要があります。`std::format(L"{}", "abc")` は失敗します（ワイドの書式に狭い文字列）。`L"abc"` にしてください。文字列の連結で `L` を付け忘れるのがよくあるミスです。

**`__LineInfo` が見つからない**
`#include "CppUnitTest.h"` が `Near.h` にも必要です。`SetupTests.cpp` 側で include しているから大丈夫、とはなりません（第 2 章の規約 2「ヘッダは自己完結する」）。

**行番号が `Near.h` の行を指してしまう**
`std::source_location` の既定引数を書き忘れているか、ヘルパーの中でさらに別のヘルパーを呼ぶときに `loc` を転送し忘れています。多段にする場合は必ず `loc` を引き回してください。

**テストは通るのに、`AssertNear` を使った行でブレークポイントが止まらない**
`inline` 関数がインライン展開されています。Debug 構成（`/Od`）ならまず起きませんが、Release でテストをデバッグするときは起こりえます。

## この章のまとめ

- 浮動小数点の比較は**厳密一致では書けない**。`0.1f + 0.2f != 0.3f` は仕様どおりの挙動であって、直すべきバグではない。
- 許容誤差は**絶対誤差と相対誤差の両方**が要る。0 付近は絶対誤差が、大きな値は相対誤差が救う。片方だけでは、どちらかの領域で必ず破綻する。
- **`std::source_location` を既定引数に置く**ことで、マクロなしに呼び出し元の行番号を報告できる。
- 失敗メッセージには **9 桁の値・差・許容誤差の何倍か・配列全体**を出す。「誤差なのかバグなのか」を数秒で判断できることが、この先 60 章ぶんの生産性を決める。
- 判定を**述語（`IsNear`）として切り出す**と、ヘルパー自身をテストできる。

次章では、この許容誤差の値そのものに根拠を与えます。`/fp:fast` を有効にし、その代償として何を失うのか、そして誤差がどう蓄積するのかを、テストで測りながら決めていきます。
