# 第 17 章　スキンメッシュのデータ構造

**この章で作るもの**：`SkinnedVertex` と `SkinnedMesh`、ウェイトの正規化・切り詰め処理、そして**テスト用の円柱メッシュをプロシージャルに生成する関数**。第 IV 部を通じて使う土台を整えます。

---

## 17.1　頂点は何を持つべきか

第 16 章でスキニング行列パレットが手に入りました。あとは頂点を流し込むだけ ―― そのために、頂点が「自分はどのボーンにどれだけ属するか」を知っている必要があります。

必要な情報を並べます。

| 項目 | 型 | 用途 |
| --- | --- | --- |
| 位置 | `Vec3` | 変形の対象（第 18 章） |
| 法線 | `Vec3` | ライティング。これも変形する（第 19 章） |
| 接線 | `Vec4` | 法線マップ。`w` は従法線の符号 |
| UV | `Vec2` | テクスチャ座標。変形しない |
| ボーンインデックス | `uint16 × 4` | どのボーンに属するか |
| ウェイト | `float × 4` | どれだけ属するか |

本書は描画をしないので UV と接線は使いません。それでも構造体に含めるのは、**glTF から読み込む対象（第 33 章）だから**であり、また GPU に渡す頂点バッファのレイアウト（第 58 章）を現実的なものにしておきたいからです。

## 17.2　`SkinnedVertex`

まず `Vec2` がないので作ります。`AnimLib/include/anim/Vec2.h`：

```cpp
#pragma once

namespace anim {

struct Vec2 {
    float x;
    float y;
};

constexpr Vec2 operator+(Vec2 a, Vec2 b) { return {a.x + b.x, a.y + b.y}; }
constexpr Vec2 operator-(Vec2 a, Vec2 b) { return {a.x - b.x, a.y - b.y}; }
constexpr Vec2 operator*(Vec2 a, float s) { return {a.x * s, a.y * s}; }

}  // namespace anim
```

本体です。`AnimLib/include/anim/SkinnedMesh.h`：

```cpp
#pragma once

#include "anim/Skeleton.h"
#include "anim/Vec2.h"
#include "anim/Vec3.h"
#include "anim/Vec4.h"

#include <cstdint>
#include <vector>

namespace anim {

// 1 頂点あたりの最大影響ボーン数。理由は 17.3 節。
inline constexpr int kMaxInfluences = 4;

// 72 バイト。第 58 章で GPU の頂点バッファにそのまま流す。
struct SkinnedVertex {
    Vec3 position;                          // 12 B  バインドポーズでのモデル空間座標
    Vec3 normal;                            // 12 B
    Vec4 tangent;                           // 16 B  xyz = 接線、w = 従法線の符号（±1）
    Vec2 uv;                                //  8 B
    BoneIndex joints[kMaxInfluences];       //  8 B
    float     weights[kMaxInfluences];      // 16 B
};

static_assert(sizeof(SkinnedVertex) == 72, "頂点サイズが想定と違う");

struct SkinnedMesh {
    std::vector<SkinnedVertex> vertices;
    std::vector<std::uint32_t> indices;     // 三角形リスト

    [[nodiscard]] std::size_t TriangleCount() const noexcept { return indices.size() / 3; }
};

}  // namespace anim
```

`static_assert` を置いたのは、**サイズが暗黙に変わることを防ぐため**です。メンバを 1 つ足しただけで頂点バッファのレイアウトが変わり、シェーダとの取り決めが崩れます。サイズを固定したいなら、それをコードに書いておくのが確実です。

`position` が**バインドポーズでの座標**であることを、コメントで明示しておきます。第 15 章で確認したとおり、ここを取り違えるとモデル全体がねじれます。

## 17.3　なぜ 4 本なのか

影響ボーン数を 4 に固定しました。3 でも 8 でもなく 4 です。

**GPU の都合**が大きな理由です。`float4` と `uint4`（あるいは `ubyte4`）はシェーダの自然な単位で、1 つのレジスタに収まります。5 本にすると 2 レジスタ必要になり、コストが跳ね上がります。

**glTF もそう定めています。** `JOINTS_0` と `WEIGHTS_0` は 4 要素のベクトルで、5 本以上必要なら `JOINTS_1` / `WEIGHTS_1` を追加する形になっています（本書では扱いません）。

**そして、実際に足ります。** 人型キャラクターの頂点の大半は 1〜2 本のボーンにしか属しません。3 本以上必要なのは、肩・股関節・首といった複数の関節が交わる場所だけです。この章の後半で作る円柱メッシュでも、影響ボーンは最大 2 本です。

代償は、DCC ツールが 5 本以上のウェイトを出力したときに切り詰めが必要になることです。それが 17.5 節の話になります。

## 17.4　ウェイトの正規化

**ウェイトの合計は 1 でなければなりません。** そうでないと、変形後の頂点が縮んだり膨らんだりします。

なぜかは、第 18 章の式を先取りすると分かります。頂点の変形は

```
p' = Σ w_k · (palette[j_k] · p)
```

です。すべてのボーンが恒等変換だったとすると、`p' = (Σ w_k) · p`。合計が 0.9 なら、頂点は原点方向に 10% 縮みます。**モデル全体が痩せます。**

合計が 1 からずれる原因は 3 つあります。

1. **DCC ツールの出力がそもそも 1 でない。** 珍しくありません。
2. **切り詰めで捨てた分がある**（17.5 節）。
3. **量子化した**（第 55 章）。ウェイトを 8 ビット整数で保存すると、合計がぴったり 1 にならないことがあります。

いずれの場合も、**ロード時に正規化して直します**。毎フレームやるものではありません。

## 17.5　ソートと切り詰め

5 本以上の影響がある頂点を 4 本に減らします。素直な方法は「**ウェイトの大きい順に 4 本を残し、残りを捨てて再正規化する**」です。

```cpp
namespace anim {

// 切り詰め前の、任意個数の影響。ロード時にだけ使う中間表現。
struct Influence {
    BoneIndex joint;
    float weight;
};

// in を降順にソートし、上位 kMaxInfluences 本を out に詰めて正規化する。
// in は破壊される。
void SortAndTruncate(std::vector<Influence>& in, SkinnedVertex& out);

// 切り詰めで失われるウェイトの割合（0 = 損失なし）。
// ロード時の警告に使う。
[[nodiscard]] float TruncationError(std::span<const Influence> sortedDescending);

}  // namespace anim
```

```cpp
void SortAndTruncate(std::vector<Influence>& in, SkinnedVertex& out) {
    std::sort(in.begin(), in.end(), [](const Influence& a, const Influence& b) {
        if (a.weight != b.weight) {
            return a.weight > b.weight;
        }
        return a.joint < b.joint;   // 同点なら番号順。順序を決定的にする
    });

    for (int i = 0; i < kMaxInfluences; ++i) {
        out.joints[i]  = 0;
        out.weights[i] = 0.0f;
    }

    const std::size_t n = std::min<std::size_t>(in.size(), kMaxInfluences);
    float sum = 0.0f;
    for (std::size_t i = 0; i < n; ++i) {
        sum += in[i].weight;
    }

    if (sum <= 0.0f) {
        // 全部 0（あるいは影響なし）。ボーン 0 に 100% 割り当てて、
        // 頂点が原点に潰れるのを防ぐ。
        out.joints[0]  = in.empty() ? BoneIndex{0} : in[0].joint;
        out.weights[0] = 1.0f;
        return;
    }

    const float inverseSum = 1.0f / sum;
    for (std::size_t i = 0; i < n; ++i) {
        out.joints[i]  = in[i].joint;
        out.weights[i] = in[i].weight * inverseSum;
    }
}
```

**同点のときに番号順にする**比較関数に注目してください。これがないと、`std::sort` が同じウェイトの要素をどう並べるかは未規定になり、**同じ入力から違う出力が出る**可能性が生じます。第 20 章のゴールデンテストや、第 58 章の CPU/GPU 一致テストは、**結果がビット単位で再現することを前提にしています**。ソートの安定性は、そのための地味だが重要な条件です。

`sum <= 0.0f` のフォールバックも重要です。ウェイトがすべて 0 の頂点は、実際のモデルに存在します（バインドし忘れ、あるいは意図的に固定した頂点）。ここで何もしないと、その頂点は第 18 章の式で **原点に飛びます**。モデルの一部が原点に向かって引き伸ばされる、という派手な症状になります。

### 切り詰めの誤差を測る

捨てた分がどれくらいなのかは、知っておく価値があります。

```cpp
float TruncationError(std::span<const Influence> sortedDescending) {
    float total = 0.0f;
    float kept  = 0.0f;
    for (std::size_t i = 0; i < sortedDescending.size(); ++i) {
        total += sortedDescending[i].weight;
        if (i < kMaxInfluences) {
            kept += sortedDescending[i].weight;
        }
    }
    return (total > 0.0f) ? (total - kept) / total : 0.0f;
}
```

実際に試してみます。5 本の影響 `{0.4, 0.25, 0.2, 0.1, 0.05}` を持つ頂点を切り詰めると、

```
切り詰め誤差 = 5.0%
結果 : joints = 7, 9, 2, 3    weights = 0.4211, 0.2632, 0.2105, 0.1053
```

捨てられたのは 5% のウェイトで、残った 4 本が比例配分で膨らんでいます。**5 番目のボーンの影響は 5% しかなかったので、捨てても見た目はほぼ変わりません。** 一般に、影響の 5 番目以降は数パーセント以下です。

とはいえ、10% を超えるようなら警告する価値があります。第 33 章のメッシュ読み込みでは、切り詰め誤差の最大値をログに出します。

## 17.6　接線の `w`

`tangent` を `Vec4` にして `w` に符号を入れているのは、**従法線（bitangent）を保存しないため**です。

従法線は `cross(normal, tangent)` で計算できます。ただし UV の巻き方によって向きが反転するので、`±1` の符号だけは保存が必要です。

```cpp
// bitangent = cross(normal, tangent.xyz) * tangent.w
```

`Vec3` 1 本（12 バイト）を `float` 1 個（4 バイト、しかも `Vec4` のパディングに収まる）に圧縮できます。glTF もこの規約で、`TANGENT` は 4 要素のベクトルです。

本書では接線を使いませんが、第 19 章で法線と同じ扱いをします（接線も変形が必要です）。

## 17.7　テスト用のメッシュを作る

ここからが、この章の実用的な部分です。**第 IV 部のテストには、実際のメッシュが要ります。**

第 21 章では「関節をねじると LBS が潰れる」ことを数値で測ります。そのためには、体積を持った閉じたメッシュが必要です。glTF を読めるようになるのは第 33 章なので、それまでは**自分で生成します**。

題材は**円柱**です。理由は 3 つあります。

1. **体積の理論値が分かる**（`πr²L`）。テストの正解を計算できます。
2. **腕や脚のモデル**として妥当です。関節の変形を論じるのに適しています。
3. **ねじりの影響が見やすい**。軸まわりに回すと何が起きるかが、円形の断面ではっきり分かります。

```cpp
// AnimLib.Tests/TestSupport/MeshSupport.h

namespace anim::test {

// X 軸に沿った円柱を生成する。
//   x = 0 から length まで、半径 radius
//   ボーン 0（根元）とボーン 1（先端）に、x に応じて線形にウェイトを配分する
//   blendStart / blendEnd は、ウェイトが遷移する区間（length に対する比率）
//
// 閉じたメッシュ（両端にフタあり）なので、体積が測れる。
[[nodiscard]] SkinnedMesh MakeCylinder(int segmentsX, int segmentsRadial,
                                       float length, float radius,
                                       float blendStart = 0.35f,
                                       float blendEnd   = 0.65f);

}  // namespace anim::test
```

```cpp
SkinnedMesh MakeCylinder(int segmentsX, int segmentsRadial,
                         float length, float radius,
                         float blendStart, float blendEnd) {
    constexpr float kPi = std::numbers::pi_v<float>;
    SkinnedMesh mesh;

    // --- 側面の頂点 ---
    for (int i = 0; i <= segmentsX; ++i) {
        const float t = static_cast<float>(i) / static_cast<float>(segmentsX);
        const float x = t * length;

        // ボーン 1 のウェイトを x に応じて 0 → 1 へ
        float w1 = (x - blendStart * length) / ((blendEnd - blendStart) * length);
        w1 = std::clamp(w1, 0.0f, 1.0f);

        for (int j = 0; j < segmentsRadial; ++j) {
            const float a = 2.0f * kPi * static_cast<float>(j)
                                       / static_cast<float>(segmentsRadial);
            SkinnedVertex v{};
            v.position = {x, radius * std::cos(a), radius * std::sin(a)};
            v.normal   = {0.0f, std::cos(a), std::sin(a)};
            v.tangent  = {1.0f, 0.0f, 0.0f, 1.0f};
            v.uv       = {t, static_cast<float>(j) / static_cast<float>(segmentsRadial)};
            v.joints[0] = 0;  v.weights[0] = 1.0f - w1;
            v.joints[1] = 1;  v.weights[1] = w1;
            v.joints[2] = 0;  v.weights[2] = 0.0f;
            v.joints[3] = 0;  v.weights[3] = 0.0f;
            mesh.vertices.push_back(v);
        }
    }

    auto ring = [&](int i, int j) {
        return static_cast<std::uint32_t>(i * segmentsRadial + (j % segmentsRadial));
    };

    // --- 側面の三角形（外向きの巻き方）---
    for (int i = 0; i < segmentsX; ++i) {
        for (int j = 0; j < segmentsRadial; ++j) {
            mesh.indices.insert(mesh.indices.end(),
                                {ring(i, j), ring(i + 1, j + 1), ring(i + 1, j)});
            mesh.indices.insert(mesh.indices.end(),
                                {ring(i, j), ring(i, j + 1), ring(i + 1, j + 1)});
        }
    }

    // --- フタ ---
    const std::uint32_t cap0 = static_cast<std::uint32_t>(mesh.vertices.size());
    {
        SkinnedVertex v{};
        v.position = {0.0f, 0.0f, 0.0f};
        v.normal   = {-1.0f, 0.0f, 0.0f};
        v.tangent  = {0.0f, 0.0f, 1.0f, 1.0f};
        v.joints[0] = 0;  v.weights[0] = 1.0f;
        mesh.vertices.push_back(v);
    }
    const std::uint32_t cap1 = static_cast<std::uint32_t>(mesh.vertices.size());
    {
        SkinnedVertex v{};
        v.position = {length, 0.0f, 0.0f};
        v.normal   = {1.0f, 0.0f, 0.0f};
        v.tangent  = {0.0f, 0.0f, 1.0f, 1.0f};
        v.joints[0] = 1;  v.weights[0] = 1.0f;
        mesh.vertices.push_back(v);
    }
    for (int j = 0; j < segmentsRadial; ++j) {
        mesh.indices.insert(mesh.indices.end(), {cap0, ring(0, j + 1), ring(0, j)});
        mesh.indices.insert(mesh.indices.end(),
                            {cap1, ring(segmentsX, j), ring(segmentsX, j + 1)});
    }
    return mesh;
}
```

### 巻き方（ワインディング）に注意

三角形の頂点の順序は、**外向きの法線になるように**決める必要があります。次章以降で体積を計算するとき、巻き方が逆だと体積が負になり、内側と外側が入れ替わったメッシュとして扱われてしまいます。

筆者は最初、側面の三角形を `{ring(i,j), ring(i+1,j), ring(i+1,j+1)}` の順で書いて内向きにしてしまいました。体積が `-0.0233`（理論値 `+0.0707`）になり、そこで気づきました。**巻き方の間違いは、体積を測るテストが即座に捕まえます。** これも「テストで検証する」方針の恩恵です。

### 体積を測る

閉じたメッシュの体積は、原点から各三角形へ張った四面体の符号付き体積を足し合わせて求められます（発散定理）。

```cpp
// AnimLib.Tests/TestSupport/MeshSupport.h

// 閉じたメッシュの符号付き体積。
// 外向きの巻き方なら正の値になる。原点がメッシュの外にあっても正しい。
[[nodiscard]] double MeshVolume(std::span<const Vec3> positions,
                                std::span<const std::uint32_t> indices) {
    double volume = 0.0;
    for (std::size_t t = 0; t + 2 < indices.size(); t += 3) {
        const Vec3 a = positions[indices[t]];
        const Vec3 b = positions[indices[t + 1]];
        const Vec3 c = positions[indices[t + 2]];
        volume += static_cast<double>(Dot(Cross(a, b), c));
    }
    return volume / 6.0;
}
```

`double` で累算しているのは、三角形が数千個あると `float` では誤差が積もるからです。第 4 章で決めた「誤差を測るコードは `double`」の適用例です。

24 × 24 分割、長さ 1.0 m、半径 0.15 m の円柱で測ると **0.069881**。理論値 `π × 0.15² × 1.0 = 0.070686` の **98.86%** です。

差の理由は分割の粗さです。半径 `r` の円を `M` 角形で近似すると面積は `(M/2)·r²·sin(2π/M)` になり、`M = 24` では円の 98.86% ―― **実測値とぴったり一致します**。理論値と実測値がここまで揃うと、生成コードも体積計算も正しいと確信できます。

## 17.8　テストを書く

`AnimLib.Tests/SkinnedMeshTests.cpp`：

```cpp
#include "CppUnitTest.h"

#include "TestSupport/MathAssert.h"
#include "TestSupport/MeshSupport.h"
#include "TestSupport/Tolerance.h"

#include "anim/SkinnedMesh.h"

#include <numbers>

using namespace Microsoft::VisualStudio::CppUnitTestFramework;
using namespace anim;

namespace { constexpr double kPi = std::numbers::pi; }

namespace AnimLibTests {

TEST_CLASS(SkinnedMeshTests) {
public:

    // --- ウェイトの正規化と切り詰め -------------------------------

    TEST_METHOD(WeightsAreNormalized) {
        std::vector<Influence> in{{0, 0.2f}, {1, 0.6f}};   // 合計 0.8
        SkinnedVertex v{};
        SortAndTruncate(in, v);

        float sum = 0.0f;
        for (int k = 0; k < kMaxInfluences; ++k) { sum += v.weights[k]; }
        anim::test::AssertNear(1.0f, sum, test::kEpsDir);
        anim::test::AssertNear(0.75f, v.weights[0], test::kEpsDir);   // 0.6 / 0.8
    }

    TEST_METHOD(InfluencesAreSortedDescending) {
        std::vector<Influence> in{{3, 0.1f}, {7, 0.4f}, {2, 0.2f}, {9, 0.25f}, {5, 0.05f}};
        SkinnedVertex v{};
        SortAndTruncate(in, v);

        Assert::AreEqual<int>(7, v.joints[0]);
        Assert::AreEqual<int>(9, v.joints[1]);
        Assert::AreEqual<int>(2, v.joints[2]);
        Assert::AreEqual<int>(3, v.joints[3]);
        for (int k = 1; k < kMaxInfluences; ++k) {
            Assert::IsTrue(v.weights[k - 1] >= v.weights[k]);
        }
    }

    TEST_METHOD(TruncationRenormalizes) {
        // {0.4, 0.25, 0.2, 0.1, 0.05} → 5 番目を捨てて 0.95 を 1 に伸ばす
        std::vector<Influence> in{{7, 0.4f}, {9, 0.25f}, {2, 0.2f}, {3, 0.1f}, {5, 0.05f}};
        SkinnedVertex v{};
        SortAndTruncate(in, v);

        anim::test::AssertNear(0.4f / 0.95f, v.weights[0], test::kEpsDir);
        float sum = 0.0f;
        for (int k = 0; k < kMaxInfluences; ++k) { sum += v.weights[k]; }
        anim::test::AssertNear(1.0f, sum, test::kEpsDir);
    }

    TEST_METHOD(TruncationErrorIsReported) {
        const std::vector<Influence> sorted{
            {7, 0.4f}, {9, 0.25f}, {2, 0.2f}, {3, 0.1f}, {5, 0.05f}};
        anim::test::AssertNear(0.05f, TruncationError(sorted), test::kEpsDir);
    }

    // 同点のときの順序が決定的であること（20 章・58 章の前提）
    TEST_METHOD(TiesAreBrokenDeterministically) {
        for (int trial = 0; trial < 10; ++trial) {
            std::vector<Influence> in{{9, 0.25f}, {2, 0.25f}, {7, 0.25f}, {4, 0.25f}};
            SkinnedVertex v{};
            SortAndTruncate(in, v);
            Assert::AreEqual<int>(2, v.joints[0]);
            Assert::AreEqual<int>(4, v.joints[1]);
            Assert::AreEqual<int>(7, v.joints[2]);
            Assert::AreEqual<int>(9, v.joints[3]);
        }
    }

    TEST_METHOD(AllZeroWeightsFallBackToFullInfluence) {
        std::vector<Influence> in{{5, 0.0f}, {6, 0.0f}};
        SkinnedVertex v{};
        SortAndTruncate(in, v);
        anim::test::AssertNear(1.0f, v.weights[0], test::kEpsDir);
        anim::test::AssertNear(0.0f, v.weights[1], test::kEpsDir);
    }

    TEST_METHOD(NoInfluencesDoesNotProduceZeroWeights) {
        std::vector<Influence> in;
        SkinnedVertex v{};
        SortAndTruncate(in, v);
        anim::test::AssertNear(1.0f, v.weights[0], test::kEpsDir);
    }

    // --- テスト用メッシュ -----------------------------------------

    TEST_METHOD(CylinderHasExpectedCounts) {
        const SkinnedMesh m = test::MakeCylinder(24, 24, 1.0f, 0.15f);
        // 側面 25 リング × 24 + フタの中心 2 個
        Assert::AreEqual(std::size_t{25 * 24 + 2}, m.vertices.size());
        // 側面 24×24×2 + フタ 24×2
        Assert::AreEqual(std::size_t{24 * 24 * 2 + 24 * 2}, m.TriangleCount());
    }

    TEST_METHOD(CylinderWeightsAreValid) {
        const SkinnedMesh m = test::MakeCylinder(24, 24, 1.0f, 0.15f);
        for (const SkinnedVertex& v : m.vertices) {
            float sum = 0.0f;
            for (int k = 0; k < kMaxInfluences; ++k) {
                Assert::IsTrue(v.weights[k] >= 0.0f);
                sum += v.weights[k];
            }
            anim::test::AssertNear(1.0f, sum, test::kEpsDir);
        }
    }

    // 巻き方が外向きであること（体積が正）
    TEST_METHOD(CylinderWindingIsOutward) {
        const SkinnedMesh m = test::MakeCylinder(24, 24, 1.0f, 0.15f);
        std::vector<Vec3> pos;
        for (const SkinnedVertex& v : m.vertices) { pos.push_back(v.position); }
        Assert::IsTrue(test::MeshVolume(pos, m.indices) > 0.0);
    }

    // 体積が理論値（多角形近似ぶんを含む）と一致すること
    TEST_METHOD(CylinderVolumeMatchesTheory) {
        constexpr int kRadial = 24;
        constexpr double kRadius = 0.15;
        constexpr double kLength = 1.0;

        const SkinnedMesh m = test::MakeCylinder(24, kRadial,
                                                 static_cast<float>(kLength),
                                                 static_cast<float>(kRadius));
        std::vector<Vec3> pos;
        for (const SkinnedVertex& v : m.vertices) { pos.push_back(v.position); }

        // 半径 r の円を M 角形で近似した面積 = (M/2) r² sin(2π/M)
        const double polygonArea =
            0.5 * kRadial * kRadius * kRadius * std::sin(2.0 * kPi / kRadial);
        const double expected = polygonArea * kLength;

        Assert::IsTrue(std::fabs(test::MeshVolume(pos, m.indices) - expected) < 1.0e-6);
    }

    // 分割を細かくすると円柱の体積に近づくこと
    TEST_METHOD(FinerCylinderApproachesAnalyticVolume) {
        const double analytic = kPi * 0.15 * 0.15 * 1.0;
        double previousError = 1.0;
        for (int radial : {8, 16, 32, 64}) {
            const SkinnedMesh m = test::MakeCylinder(8, radial, 1.0f, 0.15f);
            std::vector<Vec3> pos;
            for (const SkinnedVertex& v : m.vertices) { pos.push_back(v.position); }
            const double error = std::fabs(test::MeshVolume(pos, m.indices) - analytic);
            Assert::IsTrue(error < previousError);
            previousError = error;
        }
    }
```

`CylinderVolumeMatchesTheory` と `FinerCylinderApproachesAnalyticVolume` は、**テスト用のデータ生成コードそのものをテストしています**。地味ですが、これは重要です。第 21 章で「LBS は体積を 20% 失う」と主張するとき、その主張は**メッシュ生成と体積計算が正しいこと**に全面的に依存します。土台が信用できなければ、その上の結論も信用できません。

## 17.9　つまずきやすいところ

**モデルの一部が原点に向かって伸びる**
ウェイトの合計が 0 の頂点があります。`SortAndTruncate` のフォールバックが効いているか確認してください。glTF から読んだデータで実際に起こります。

**モデル全体が少し痩せる／太る**
ウェイトの合計が 1 でありません。ロード時に正規化してください。合計が 0.98 なら、モデルは 2% 縮みます。

**`static_assert` が落ちる**
`SkinnedVertex` にメンバを足したか、`BoneIndex` の型を変えました。頂点サイズを変えるなら、意図的な変更として `static_assert` の値も更新してください。**サイズが変わったことに気づかずに GPU へ渡すと、頂点データが 1 個ずつずれて読まれ、モデルが破裂します。**

**体積が負になる**
三角形の巻き方が内向きです。17.7 節を参照してください。

**同じ入力から違う結果が出る**
ソートの比較関数で同点の扱いを決めていません。第 20 章のゴールデンテストが不安定になります。

**ボーンインデックスが範囲外**
`SortAndTruncate` はウェイト 0 の枠に `joints[k] = 0` を入れます。ウェイトが 0 ならパレットを引かないので実害はありませんが、**シェーダ側では分岐なしで 4 本すべてを引く**のが普通です（第 58 章）。そのとき範囲外のインデックスが入っていると、GPU で未定義の読み出しが起きます。0 で埋めておくのが安全です。

## この章のまとめ

- 頂点は**位置・法線・接線・UV・ボーンインデックス 4 本・ウェイト 4 本**で 72 バイト。`static_assert` でサイズを固定する。
- `position` は**バインドポーズでの座標**。
- 影響ボーン数 **4** は、GPU のレジスタ単位・glTF の仕様・実際の必要量の 3 つが一致した数。
- **ウェイトの合計は必ず 1 に正規化する。** 0.98 ならモデルが 2% 痩せる。合計 0 の頂点は原点に飛ぶので、フォールバックが要る。
- 切り詰めは**降順ソートして上位 4 本、そして再正規化**。同点の順序を決定的にしておくことが、第 20・58 章の再現性テストの前提になる。
- 実測では、5 本目を捨てた誤差は **5%**。一般に 5 番目以降の影響は数パーセント以下。
- **テストデータは自分で生成する。** 円柱を選んだのは、体積の理論値が分かり、腕として妥当で、ねじりの影響が見えるから。
- **生成コードと体積計算そのものをテストする。** 24 分割の実測 0.069881 は、多角形近似の理論値と完全に一致した。第 21 章の主張は、この土台の正しさに依存している。
