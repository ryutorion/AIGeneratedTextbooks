# 第 19 章　法線と接線のスキニング

**この章で作るもの**：法線と接線の変形。「位置と同じように変換すればいい」と思えますが、そうではありません。**平行移動を掛けてはいけない**、そして**非一様スケールでは行列そのものを変えなければならない**。この 2 つを、実測しながら確認します。

---

## 19.1　法線も変形しなければならない

腕を曲げれば、肘の表面の向きも変わります。法線を変形せずに描画すると、キャラクターが動いても陰影だけが元の姿勢のまま貼り付いた、奇妙な見た目になります。

本書は描画をしませんが、法線は放置できません。理由が 2 つあります。

**① glTF が持っているデータだから**（第 33 章）。読んだ以上、正しく扱う必要があります。

**② 検証に使えるから。** 法線は「面に垂直である」という明確な性質を持ちます。変形後もその性質が保たれているかを調べれば、**描画せずに変形の正しさを検査できます**。この章のテストは、まさにそれを行います。

---

## 19.2　平行移動を掛けてはいけない

最初の落とし穴は単純です。法線は**位置ではなく方向**です。

肘の表面の法線が `(0, 1, 0)`（真上を向いている）だとして、肘が `(0.3, 1.5, 0)` に移動したとします。位置は移動しますが、**法線は移動しません**。向きだけが問題であり、原点からの相対位置には意味がないからです。

第 6 章で `TransformPoint` と `TransformVector` を別の関数にしたのは、まさにこのためでした。

```cpp
// 点：平行移動を足す
TransformPoint(m, p);
// 方向：平行移動を足さない
TransformVector(m, v);
```

法線に `TransformPoint` を使うと、法線に平行移動が加算されます。肘が原点から 1.5 m 離れていれば、長さ 1 のはずの法線が長さ 1.5 の何かになり、正規化すると**ほぼボーンの位置方向を向いたベクトル**になります。全身の陰影が崩壊する派手なバグです。

第 6 章で型ではなく**関数名**で区別する設計にしたのは、この事故をレビューで発見できるようにするためでした。

---

## 19.3　それでも足りない ―― 非一様スケールの問題

`TransformVector` を使えば解決 ―― ではありません。**行列に非一様スケールが入っていると、法線の向きが狂います。**

具体例で確かめます。X 方向に 2 倍引き伸ばす変換を考えます。

45 度傾いた面があり、その法線は `(1,1,0)/√2`、面内の接線は `(-1,1,0)/√2` です（両者は直交しています）。

X 方向に 2 倍すると、接線は `(-2,1,0)` の方向になります。面が寝るので、**法線はより立つ**はずです。しかし法線をそのまま `TransformVector` すると `(2,1,0)` の方向 ―― 逆に寝てしまいます。

実測しました。変形後の接線との内積（0 なら直交＝正しい）を測ります。

| X 方向のスケール | 素朴に変換 | 直交からのずれ |
| --- | --- | --- |
| 1.5 倍 | `n·t = −0.3846` | **22.62°** |
| 2.0 倍 | `n·t = −0.6000` | **36.87°** |
| 4.0 倍 | `n·t = −0.8824` | **61.93°** |

2 倍で 37 度。もはや法線として機能していません。

---

## 19.4　逆転置行列

正しい変換を導きます。

法線 `n` は、面内のあらゆる接線 `t` と直交しています。

```
n · t = 0
```

変形後もこれが成り立ってほしい。接線は普通に変換されるので `t' = M t`。法線には別の行列 `N` を使うとして `n' = N n` とすると、

```
n' · t' = (N n) · (M t) = nᵀ Nᵀ M t = 0
```

これが `nᵀ t = 0` を満たすすべての `t` について成り立つには、`Nᵀ M` が単位行列の定数倍でなければなりません。よって

```
N = (M⁻¹)ᵀ
```

**逆行列の転置**、略して**逆転置行列**です。

```cpp
// AnimLib/include/anim/Skinning.h に追加

// 法線変換用の行列（逆転置）を作る。
// 逆行列が存在しない場合は元の行列を返す（法線は狂うが落ちない）。
[[nodiscard]] inline Mat4 MakeNormalMatrix(const Mat4& m) {
    Mat4 inverse{};
    if (!Invert(m, inverse)) {
        return m;
    }
    return Transpose(inverse);
}
```

これを使うと、先ほどの表の内積はすべて **`+0.0000`**、直交からのずれは **0 度**になります。定義から導いたので当然ですが、実装が正しいことの確認になります。

### 「回転だけ取り出す」では直らない

よくある簡略化に「スケールを無視して回転部分だけ適用する」があります。試しました。

| X 方向のスケール | 回転のみ適用 | 直交からのずれ |
| --- | --- | --- |
| 1.5 倍 | `n·t = −0.1961` | 11.31° |
| 2.0 倍 | `n·t = −0.3162` | 18.43° |
| 4.0 倍 | `n·t = −0.5145` | 30.96° |

素朴に変換するよりはマシですが、**依然として大きく間違っています**。理由は明白で、面が寝たという事実そのものを無視しているからです。**非一様スケールがあるなら、逆転置行列以外に正解はありません。**

---

## 19.5　一様スケールと回転だけなら、逆転置は要らない

一方で、朗報もあります。

行列が**回転と平行移動と一様スケール**だけでできているなら、`M⁻¹ᵀ` は `M` の回転部分の定数倍になります。法線は変換後に正規化するので、**定数倍は消えます**。つまり `TransformVector(M, n)` を正規化するだけで正解に一致します。

実測で確かめました。平行移動 + 回転 + 一様スケール（0.5 倍、1 倍、3 倍）の行列で、素朴な変換・逆転置・回転のみ抽出の 3 通りを比較したところ、

```
s = 0.5 : |素朴 − 逆転置| = 2.98e-08,  |回転のみ − 逆転置| = 3.33e-08
s = 1.0 : |素朴 − 逆転置| = 2.98e-08,  |回転のみ − 逆転置| = 3.33e-08
s = 3.0 : |素朴 − 逆転置| = 7.45e-08,  |回転のみ − 逆転置| = 6.83e-08
```

**すべて float の丸め誤差の範囲で一致しました。**

第 11 章で「非一様スケールは使わない」と決めたことが、ここで報われます。**その方針を守っている限り、法線はスキニング行列をそのまま使って変換してよい。**

> **回転を抽出するときの注意**
> 「回転のみ」の実験を書いたとき、筆者は最初 `ToQuat(m)` を直接呼んで失敗しました。`ToQuat`（第 9 章）は**行列が純粋な回転であることを前提**にしており、スケール 3 が入った行列を渡すと、シェパードの分岐が誤った値を返します。正しくは、各列を正規化してスケールを取り除いてから抽出します。この手の「前提条件つきの関数」を前提外で呼ぶ間違いは、**エラーも警告も出ずに、それらしい値が返ってくる**ので厄介です。

---

## 19.6　コストと、実務上の判断

逆転置行列を使うなら、パレットとは別に**法線用のパレット**が要ります。

そのコストを測りました。100 ボーンぶんの `Invert` + `Transpose` は、**1 フレームあたり 2.58 µs**。第 16 章で測ったパレット構築が 2.12 µs だったので、**アニメーションシステムの負荷がほぼ倍になります**。

さらにメモリも倍です（100 ボーンで 6.4 KB → 12.8 KB）。GPU に渡すなら転送量も倍。

見合うかどうかは、モデル次第です。本書の判断は次のとおりです。

**既定は「スキニング行列をそのまま使う」。** 非一様スケールを使わない方針（第 11 章）のもとでは、これで正しい。

**非一様スケールを含むボーンがある場合のみ、法線パレットを作る。** 第 11 章で作った `HasNonUniformScale` で、ロード時に判定できます。

```cpp
// 法線変換用のパレット。非一様スケールを含むモデルでのみ構築する。
class NormalPalette {
public:
    // 非一様スケールが 1 つもなければ false を返し、何も構築しない。
    // その場合、法線変換にはスキニング行列パレットをそのまま使う。
    bool BuildIfNeeded(const SkinnedModel& model,
                       std::span<const Mat4> skinPalette);

    [[nodiscard]] bool IsUsed() const noexcept { return !matrices_.empty(); }
    [[nodiscard]] std::span<const Mat4> Matrices() const noexcept { return matrices_; }

private:
    std::vector<Mat4> matrices_;
};
```

**必要なときだけ払う。** そして「必要かどうか」をロード時に一度判定して、ランタイムでは分岐しない。第 7 章で `InvertRigid` と `Invert` を使い分けたのと同じ形です。

## 19.7　法線のスキニングと、正規化のタイミング

法線も、位置と同じようにウェイトで混ぜます。

```cpp
// 法線を変形する。
// normalPalette には、スキニング行列パレットか法線パレットのどちらかを渡す。
[[nodiscard]] inline Vec3 SkinNormalLBS(const SkinnedVertex& v,
                                        std::span<const Mat4> normalPalette) {
    Vec3 n{0.0f, 0.0f, 0.0f};
    for (int k = 0; k < kMaxInfluences; ++k) {
        const float w = v.weights[k];
        if (w == 0.0f) {
            continue;
        }
        n = n + w * TransformVector(normalPalette[v.joints[k]], v.normal);
    }
    // 混ぜた結果は長さ 1 ではない。必ず正規化する。
    return NormalizeSafe(n, v.normal);
}
```

**混ぜたあとの正規化が必須**です。長さ 1 のベクトルを 2 つ混ぜても、長さ 1 にはなりません。第 10 章の `Nlerp` とまったく同じ構図です。

正規化を忘れると、関節部分だけ法線が短くなり、ライティングが暗くなります。「関節に黒い帯が出る」という症状です。

`NormalizeSafe` のフォールバックに `v.normal`（変形前の法線）を渡しているのは、**混ぜた結果がゼロベクトルになる可能性**があるからです。2 つのボーンがちょうど正反対を向いていると起こります ―― そしてそれは、第 21 章で扱う 180 度ねじりの場面で実際に起こります。

### 接線も同じ

```cpp
// 接線を変形する。w（従法線の符号）はそのまま引き継ぐ。
[[nodiscard]] inline Vec4 SkinTangentLBS(const SkinnedVertex& v,
                                         std::span<const Mat4> palette) {
    const Vec3 t0{v.tangent.x, v.tangent.y, v.tangent.z};
    Vec3 t{0.0f, 0.0f, 0.0f};
    for (int k = 0; k < kMaxInfluences; ++k) {
        const float w = v.weights[k];
        if (w == 0.0f) {
            continue;
        }
        t = t + w * TransformVector(palette[v.joints[k]], t0);
    }
    const Vec3 n = NormalizeSafe(t, t0);
    return {n.x, n.y, n.z, v.tangent.w};
}
```

**接線には逆転置行列を使いません。** 接線は面**内**のベクトルなので、法線とは逆に、素直に `M` で変換するのが正しいのです。19.4 節の導出で `t' = M t` としたのは、そういう意味でした。

**法線は逆転置、接線は素直に。** 混同しやすいので、関数を分けておきます。

なお、変形後の法線と接線が厳密に直交しなくなることがあります。描画側でグラム・シュミット法により接線を直交化するのが通例です（本書の範囲外）。

## 19.8　テストを書く

`AnimLib.Tests/NormalSkinningTests.cpp`：

```cpp
#include "CppUnitTest.h"

#include "TestSupport/MathAssert.h"
#include "TestSupport/MeshSupport.h"
#include "TestSupport/TestRandom.h"
#include "TestSupport/Tolerance.h"

#include "anim/Skinning.h"

#include <numbers>

using namespace Microsoft::VisualStudio::CppUnitTestFramework;
using namespace anim;
using anim::test::AssertNear;

namespace { constexpr float kPi = std::numbers::pi_v<float>; }

namespace AnimLibTests {

TEST_CLASS(NormalSkinningTests) {
public:

    // --- 平行移動を無視すること -----------------------------------

    TEST_METHOD(NormalIgnoresTranslation) {
        const std::vector<Mat4> palette{MakeTranslation({100.0f, -50.0f, 7.0f})};

        SkinnedVertex v{};
        v.normal = {0, 1, 0};
        v.joints[0] = 0;  v.weights[0] = 1.0f;

        AssertNear(Vec3{0, 1, 0}, SkinNormalLBS(v, palette), test::kEpsDir);
    }

    // --- 回転には従うこと -----------------------------------------

    TEST_METHOD(NormalFollowsRotation) {
        const std::vector<Mat4> palette{
            MakeTranslation({5, 5, 5}) * MakeRotationZ(kPi * 0.5f)};

        SkinnedVertex v{};
        v.normal = {1, 0, 0};
        v.joints[0] = 0;  v.weights[0] = 1.0f;

        AssertNear(Vec3{0, 1, 0}, SkinNormalLBS(v, palette), test::kEpsDir);
    }

    // --- 一様スケールなら逆転置は不要（19.5 節）-------------------

    TEST_METHOD(UniformScaleNeedsNoNormalMatrix) {
        test::TestRandom rng;
        for (float s : {0.5f, 1.0f, 3.0f}) {
            const Mat4 m = MakeTranslation({1, 2, 3})
                         * ToMat4(MakeQuatAxisAngle({1, 2, 3}, 0.8f))
                         * MakeScale({s, s, s});
            const std::vector<Mat4> plain{m};
            const std::vector<Mat4> normalMat{MakeNormalMatrix(m)};

            for (int i = 0; i < 100; ++i) {
                SkinnedVertex v{};
                v.normal = Normalize(rng.NextVec3());
                v.joints[0] = 0;  v.weights[0] = 1.0f;
                AssertNear(SkinNormalLBS(v, normalMat), SkinNormalLBS(v, plain),
                           test::kEpsDir);
            }
        }
    }

    // --- 非一様スケールでは逆転置が必要（19.3・19.4 節）-----------

    // 変形後も法線が面に垂直であること。これが法線変換の定義そのもの。
    TEST_METHOD(NormalMatrixKeepsNormalPerpendicular) {
        for (float sx : {1.5f, 2.0f, 4.0f}) {
            const Mat4 m = ToMat4(MakeQuatAxisAngle({0, 0, 1}, 0.5f))
                         * MakeScale({sx, 1.0f, 1.0f});
            const std::vector<Mat4> normalMat{MakeNormalMatrix(m)};

            const Vec3 normal  = Normalize(Vec3{1, 1, 0});
            const Vec3 tangent = Normalize(Vec3{-1, 1, 0});   // 面内、法線に直交

            SkinnedVertex v{};
            v.normal = normal;
            v.joints[0] = 0;  v.weights[0] = 1.0f;

            const Vec3 deformedNormal  = SkinNormalLBS(v, normalMat);
            const Vec3 deformedTangent = Normalize(TransformVector(m, tangent));

            anim::test::AssertNear(0.0f, Dot(deformedNormal, deformedTangent),
                                   test::kEpsDir);
        }
    }

    // 素朴な変換は間違っていること（仕様の記録）
    TEST_METHOD(NaiveTransformFailsUnderNonUniformScale) {
        const Mat4 m = ToMat4(MakeQuatAxisAngle({0, 0, 1}, 0.5f))
                     * MakeScale({2.0f, 1.0f, 1.0f});
        const std::vector<Mat4> plain{m};

        SkinnedVertex v{};
        v.normal = Normalize(Vec3{1, 1, 0});
        v.joints[0] = 0;  v.weights[0] = 1.0f;

        const Vec3 deformedTangent = Normalize(TransformVector(m, Normalize(Vec3{-1, 1, 0})));
        // 実測 −0.6（直交から 36.87 度ずれる）
        anim::test::AssertNear(-0.6f, Dot(SkinNormalLBS(v, plain), deformedTangent),
                               test::kEpsDir);
    }

    // --- 混ぜたあとの長さ -----------------------------------------

    TEST_METHOD(BlendedNormalIsRenormalized) {
        const std::vector<Mat4> palette{
            Identity(), ToMat4(MakeQuatAxisAngle({0, 0, 1}, kPi * 0.5f))};

        SkinnedVertex v{};
        v.normal = {1, 0, 0};
        v.joints[0] = 0;  v.weights[0] = 0.5f;
        v.joints[1] = 1;  v.weights[1] = 0.5f;

        // (1,0,0) と (0,1,0) の中点は長さ 0.707。正規化されているはず。
        anim::test::AssertNear(1.0f, Length(SkinNormalLBS(v, palette)), test::kEpsUnit);
    }

    // 正反対の法線が打ち消し合っても NaN にならない
    TEST_METHOD(OppositeNormalsFallBackSafely) {
        const std::vector<Mat4> palette{
            Identity(), ToMat4(MakeQuatAxisAngle({0, 0, 1}, kPi))};

        SkinnedVertex v{};
        v.normal = {1, 0, 0};
        v.joints[0] = 0;  v.weights[0] = 0.5f;
        v.joints[1] = 1;  v.weights[1] = 0.5f;

        const Vec3 n = SkinNormalLBS(v, palette);
        Assert::IsFalse(std::isnan(n.x) || std::isnan(n.y) || std::isnan(n.z));
        anim::test::AssertNear(1.0f, Length(n), test::kEpsUnit);
    }

    // --- 接線 -----------------------------------------------------

    // 接線は素直に変換する（逆転置ではない）
    TEST_METHOD(TangentUsesThePlainMatrix) {
        const Mat4 m = ToMat4(MakeQuatAxisAngle({0, 0, 1}, 0.5f))
                     * MakeScale({2.0f, 1.0f, 1.0f});
        const std::vector<Mat4> palette{m};

        SkinnedVertex v{};
        v.tangent = {1, 0, 0, -1.0f};
        v.joints[0] = 0;  v.weights[0] = 1.0f;

        const Vec4 t = SkinTangentLBS(v, palette);
        AssertNear(Normalize(TransformVector(m, Vec3{1, 0, 0})),
                   Vec3{t.x, t.y, t.z}, test::kEpsDir);
        // 従法線の符号は保存される
        anim::test::AssertNear(-1.0f, t.w);
    }

    // --- メッシュ全体で ------------------------------------------

    // バインドポーズなら法線は変わらない
    TEST_METHOD(BindPoseKeepsNormals) {
        const SkinnedMesh mesh = test::MakeCylinder(12, 12, 1.0f, 0.15f);
        const std::vector<Mat4> palette{Identity(), Identity()};

        for (const SkinnedVertex& v : mesh.vertices) {
            AssertNear(v.normal, SkinNormalLBS(v, palette), test::kEpsDir);
        }
    }

    // 円柱を曲げても、側面の法線は軸に対して垂直のまま
    // （回転だけなら法線と面の関係は保たれる）
    TEST_METHOD(RigidTransformPreservesNormalLength) {
        const SkinnedMesh mesh = test::MakeCylinder(12, 12, 1.0f, 0.15f);
        const Mat4 m = MakeTranslation({3, -1, 2})
                     * ToMat4(MakeQuatAxisAngle({1, 1, 1}, 1.2f));
        const std::vector<Mat4> palette{m, m};

        for (const SkinnedVertex& v : mesh.vertices) {
            const Vec3 n = SkinNormalLBS(v, palette);
            anim::test::AssertNear(1.0f, Length(n), test::kEpsUnit);
            // 剛体変換なら、法線同士の角度も保存される
            AssertNear(Normalize(TransformVector(m, v.normal)), n, test::kEpsDir);
        }
    }
};

}  // namespace AnimLibTests
```

`NormalMatrixKeepsNormalPerpendicular` が、この章の中心です。**「法線とは面に垂直なベクトルである」という定義そのものをテストしています。** 逆転置行列がなぜ正しいのかは 19.4 節で導きましたが、その導出が正しいことを、コードが実際に確かめています。

`NaiveTransformFailsUnderNonUniformScale` は、期待値に `-0.6` という**具体的な間違いの値**を書いています。「なんとなく違う」ではなく「この条件ならこれだけ違う」と記録することで、将来この挙動が変わったときに気づけます。

## 19.9　つまずきやすいところ

**キャラクターの陰影が完全に崩壊する**
法線に `TransformPoint` を使っています。19.2 節です。

**関節部分に暗い帯が出る**
混ぜたあとの正規化を忘れています。関節では 2 つの法線が混ざるので、長さが 1 より短くなります。

**スケールを掛けたボーンの周りだけライティングがおかしい**
非一様スケールで逆転置行列を使っていません。まず `HasNonUniformScale`（第 11 章）でモデルを検査してください。そもそも非一様スケールを使わないのが本書の方針です。

**法線が NaN になる**
混ぜた結果がゼロベクトルです。`NormalizeSafe` にフォールバックを渡してください。180 度ねじりで実際に起こります（第 21 章）。

**接線に逆転置行列を使ってしまった**
接線は面**内**のベクトルなので、素直に変換するのが正しい。関数を分けておけば取り違えにくくなります。

**`ToQuat` で回転を取り出したら値がおかしい**
`ToQuat` は行列が純粋な回転であることを前提にしています。スケールが入っているなら、列を正規化してから渡してください（19.5 節のコラム）。**前提条件つきの関数を前提外で呼ぶと、それらしい間違った値が返ってきます。**

**法線パレットのコストが痛い**
必要なときだけ構築してください。100 ボーンで 2.58 µs は、パレット構築（2.12 µs）とほぼ同じ重さです。

## この章のまとめ

- 法線は**方向**なので、平行移動を掛けてはいけない。第 6 章で `TransformPoint` と `TransformVector` を分けたのは、この事故を名前で防ぐため。
- それでも**非一様スケールでは狂う**。実測で、X 方向 2 倍のスケールで直交から **36.87 度**ずれる。
- 正しい変換は**逆転置行列 `(M⁻¹)ᵀ`**。「法線は面内のあらゆる接線と直交し続ける」という条件から導かれる。
- **「回転部分だけ使う」では直らない**（2 倍で 18.43 度ずれる）。非一様スケールがあるなら、逆転置以外に正解はない。
- 逆に、**回転・平行移動・一様スケールだけなら逆転置は不要**。実測で `1e-7` 以内に一致した。第 11 章の「非一様スケールを使わない」方針が、ここで報われる。
- 法線パレットのコストは 100 ボーンで **2.58 µs** ―― パレット構築（2.12 µs）とほぼ同じ。**必要なときだけ払い、判定はロード時に済ませる。**
- **混ぜたあとは必ず正規化する。** 忘れると関節に暗い帯が出る。打ち消し合ってゼロになる場合に備えてフォールバックも要る。
- **法線は逆転置、接線は素直に。** 接線は面内のベクトルだから。

次章では、ここまでの素朴な実装を速くします。そして第 21 章で、この LBS が抱える根本的な問題を数値として突きつけます。
