# 第 22 章　デュアルクォータニオンスキニング

**この章で作るもの**：DQS の実装と、第 21 章の測定のやり直し。第 12 章で 10 章ぶん寝かせておいたデュアルクォータニオンが、ようやく仕事をします。そして DQS が万能ではないことも、同じ厳しさで測ります。

---

## 22.1　考え方

第 21 章で突き止めた LBS の問題は、一言でいえば「**円弧の上ではなく弦を横切る**」ことでした。

第 10 章で、回転について同じ問題に出会いました。そのときの解決は「混ぜてから正規化する」（`Nlerp`）でした。位置についてそれができないのは、位置には「正規化」に相当する操作がないからです。

**デュアルクォータニオンは、この「正規化」を剛体変換について可能にします。**

やることは第 12 章で作ったとおりです。

1. パレットの各行列を**デュアルクォータニオン**に変換する
2. ウェイトで**加重和**を取る（結果は剛体変換ではない）
3. **正規化**して剛体変換に戻す
4. その剛体変換で頂点を動かす

ステップ 3 が LBS には存在しない工程であり、それがすべての違いを生みます。

---

## 22.2　実装

### パレットの変換

```cpp
// AnimLib/include/anim/SkinningDQ.h
#pragma once

#include "anim/DualQuat.h"
#include "anim/QuatMat.h"
#include "anim/SkinnedMesh.h"

#include <span>

namespace anim {

// スキニング行列パレットをデュアルクォータニオンのパレットに変換する。
// 前提：各行列が剛体変換（回転 + 平行移動）であること。
// スケールが入っている場合は 22.5 節を参照。
inline void BuildDualQuatPalette(std::span<const Mat4> palette,
                                 std::span<DualQuat> out) {
    ANIM_ASSERT(palette.size() == out.size());
    for (std::size_t i = 0; i < palette.size(); ++i) {
        const Quat rotation = Normalize(ToQuat(palette[i]));
        const Vec3 translation{palette[i].m[0][3],
                               palette[i].m[1][3],
                               palette[i].m[2][3]};
        out[i] = MakeDualQuat(rotation, translation);
    }
}

}  // namespace anim
```

`ToQuat`（第 9 章）は行列が純粋な回転であることを前提にしています。第 19 章のコラムで触れた落とし穴がここにも顔を出すので、`Normalize` を挟んで保険をかけています。ただしこれは**回転の正規化であって、スケールの除去ではありません**。非一様スケールが入っていたら、この関数は静かに間違った答えを返します。

### 頂点の変形

```cpp
// DQS で頂点位置を変形する。
[[nodiscard]] inline Vec3 SkinPositionDQS(const SkinnedVertex& v,
                                          std::span<const DualQuat> palette) {
    // 符号合わせの基準は、最もウェイトの大きいボーン（= joints[0]、第 17 章）
    const DualQuat& reference = palette[v.joints[0]];

    DualQuat accumulated{{0, 0, 0, 0}, {0, 0, 0, 0}};
    for (int k = 0; k < kMaxInfluences; ++k) {
        const float w = v.weights[k];
        if (w == 0.0f) {
            continue;
        }
        // 符号を揃えてから足す。忘れると打ち消し合う（第 12 章）。
        accumulated = accumulated + AlignSign(palette[v.joints[k]], reference) * w;
    }

    if (LengthSquared(accumulated.real) < kTinyLengthSquared) {
        return v.position;   // 数値的に破綻。変形しない
    }
    return TransformPoint(Normalize(accumulated), v.position);
}
```

**`AlignSign` が要となる 1 行**です。第 12 章で「忘れると静かに壊れる」と書いたとおりで、これがないと逆の半球にあるデュアルクォータニオンどうしが打ち消し合い、頂点が飛びます。

基準に `palette[v.joints[0]]` を使えるのは、第 17 章でウェイトを降順にソートしておいたからです。**最もウェイトの大きいボーンを基準にすれば、他のボーンとの角度差が最小になる**ので、符号合わせが最も安定します。ここでもソートの伏線が回収されました。

法線と接線も同じ剛体変換で動かします。DQS の場合、**逆転置行列の議論は不要**です ―― 剛体変換にはスケールがないので、法線も接線も同じ変換で正しく動きます。第 19 章の複雑さが、ここでは消えます。

## 22.3　第 21 章の測定をやり直す

同じ円柱、同じ測定関数、同じねじり角。変えたのは変形の方法だけです。

### ねじり

| ねじり角 | LBS 体積比 | LBS 最小半径 | **DQS 体積比** | **DQS 最小半径** |
| --- | --- | --- | --- | --- |
| 0° | 100.00% | 0.15000 | 100.00% | 0.15000 |
| 45° | 96.86% | 0.13858 | **99.80%** | **0.15000** |
| 90° | 89.55% | 0.10607 | **99.49%** | **0.15000** |
| 135° | 82.35% | 0.05740 | **99.06%** | **0.15000** |
| **180°** | **79.48%** | **0.00000** | **99.61%** | **0.15000** |

**最小半径が、すべての角度で 0.15000 のまま**です。断面が一切潰れていません。180 度ねじっても、円柱は円柱のままです。

体積が 99% 台に留まって 100% にならないのは、**メッシュの分割の粗さ**によるものです。ねじれた曲面を 24 分割の多角形で近似しているので、わずかに内側に食い込みます。アルゴリズムの損失ではありません。

### 曲げ

| 曲げ角 | LBS 体積比 | **DQS 体積比** |
| --- | --- | --- |
| 45° | 98.44% | **99.92%** |
| 90° | 94.69% | **99.66%** |
| 120° | 92.03% | **99.40%** |
| 150° | 90.09% | **99.04%** |

曲げでも同様です。LBS が 10% 失うところを、DQS は 1% に抑えます。

**第 21 章のテストを、そのまま DQS で通せます。** これが第 12 章で「テストを先に用意しておく」意味でした。

## 22.4　なぜ潰れないのか

第 12 章で示した数値を思い出してください。単位変換と「90 度回転 + 平行移動」を 50:50 で混ぜ、点 `(1,0,0)` に適用した結果です。

| 手法 | 結果 | 原点からの距離 |
| --- | --- | --- |
| LBS | `(1.000, 0.500, 0.000)` | 1.118 |
| DQS | `(1.207, 0.500, 0.000)` | 1.307 |

LBS は 2 つの点を直線で結んだ中点を取ります。DQS は**中間の剛体変換**を作ってから点を動かします。前者は弦の上、後者は円弧の上です。

これを測定で裏づけました。**関節中心から変形後の頂点までの距離**を測ると、

| 曲げ角 | LBS 最大距離 | DQS 最大距離 |
| --- | --- | --- |
| 0°（未変形） | 0.19526 | 0.19526 |
| 45° | 0.19346 | **0.19526** |
| 90° | 0.18904 | **0.19526** |
| 150° | 0.18350 | **0.19526** |

**DQS では、関節中心からの距離が完全に保存されています。** 剛体変換は距離を変えないので、当然の結果です。LBS では距離が縮んでいき、それが「痩せ」として現れます。

## 22.5　DQS の代償

万能ではありません。3 つの代償があります。

### ① 遅い

同じ 10 万頂点で測りました。

| 実装 | 10 万頂点 |
| --- | --- |
| LBS（素朴） | 1.222 ms |
| **DQS（素朴）** | **3.036 ms（2.48 倍）** |

デュアルクォータニオンの加重和、符号合わせ、正規化（平方根 1 回と直交化）、そして頂点変換が外積 3 回。LBS の「行列 4 個の加重和 + 変換 1 回」より重くなります。

第 20 章と同じ最適化（SoA 化、影響数での特化）は DQS にも適用できますが、**LBS との比は縮まりません**。1 頂点あたりの演算量そのものが多いためです。

### ② スケールを表現できない

第 12 章で述べたとおり、これは定義からくる制約です。ボーンにスケールが入っていると、DQS はそれを落とします。

実務での対処は**併用**です。スキニング行列からスケール成分を分離し、

1. 頂点にスケールだけを **LBS で**適用する
2. 残った剛体変換を **DQS で**適用する

という 2 段構えにします。本書では、第 11 章の方針（非一様スケールを使わない）のもとで、この併用は実装しません。**必要になったときに、`HasNonUniformScale` が教えてくれます。**

### ③ 既存アセットとの互換性

これが実務では最も重いかもしれません。

アーティストは **LBS の挙動を前提にウェイトを調整**します。「ここは潰れるから、ウェイトを 45:55 にずらしておこう」「補正ボーンを足しておこう」。そうやって作り込まれたモデルを DQS で動かすと、**補正が二重にかかります**。関節が想定より膨らんで見える、という結果になります。

これが「DQS は膨らむ」と言われることの、実務上の中身です。

### 膨らみを測ろうとしたが、検出できなかった

DQS の欠点として「関節が膨らむ（joint bulge）」がよく挙げられます。本書の円柱でこれを測定しようとしました。

前節の表がその結果です。**関節中心からの最大距離は、すべての曲げ角で未変形時と完全に同じ 0.19526 でした。** 増えても減ってもいません。体積も 99% 台で、100% を超えることはありませんでした。

**この 2 ボーンの円柱では、DQS の膨らみは検出できませんでした。**

理由を考えると、DQS は各頂点を剛体変換で動かすので、**関節中心からの距離を原理的に増やせない**からです。「膨らむ」という表現は、正確には「LBS のように痩せないので、LBS を前提に作られたモデルでは相対的に太く見える」という意味だと考えるのが妥当です。

3 本以上のボーンが交わる箇所や、特定のウェイト配分では、DQS 固有のアーティファクトが報告されています。本書のテストデータでは再現できませんでした。**再現できなかったことを、再現できたかのように書くことはしません。** 読者が実際のモデルで確かめるべき事柄として、ここに残しておきます。

## 22.6　使い分け

| 状況 | 選択 |
| --- | --- |
| ねじり関節（前腕、首、腰） | **DQS**、またはツイストボーン + LBS |
| 通常の関節（膝、指） | LBS で十分 |
| スケールアニメーションがある | **LBS**（DQS は不可） |
| 既存アセットの流用 | **LBS**（ウェイトが LBS 前提） |
| CPU 負荷が厳しい | **LBS**（2.5 倍の差） |
| 新規制作、品質優先 | DQS を検討 |

**ボーンごと、あるいはメッシュ部位ごとに切り替える**のが現実的な運用です。前腕だけ DQS、他は LBS、といった形です。第 58 章でシェーダを書くときは、この切り替えをどう表現するかも設計の対象になります。

## 22.7　テストを書く

`AnimLib.Tests/DualQuatSkinningTests.cpp`：

```cpp
#include "CppUnitTest.h"

#include "TestSupport/MathAssert.h"
#include "TestSupport/MeshSupport.h"
#include "TestSupport/Tolerance.h"

#include "anim/SkinningDQ.h"
#include "anim/SkinnedCharacter.h"

#include <format>
#include <numbers>

using namespace Microsoft::VisualStudio::CppUnitTestFramework;
using namespace anim;
using anim::test::AssertNear;

namespace {

constexpr float kPi = std::numbers::pi_v<float>;

// 第 21 章の TwistFixture に DQS を足したもの
struct DqsFixture {
    SkinnedModel model;
    SkinnedMesh mesh;
    std::vector<DualQuat> dqPalette;
    std::vector<Vec3> deformed;
    double restVolume = 0.0;

    DqsFixture() {
        SkeletonBuilder b;
        b.AddRoot("root");
        b.AddBone("joint", "root", Transform{{0.5f, 0, 0}, QuatIdentity(), {1, 1, 1}});
        model.skeleton = b.Build();
        model.inverseBind.resize(2);
        ComputeInverseBindMatrices(model.skeleton, model.skeleton.RestLocals(),
                                   model.inverseBind);

        mesh = anim::test::MakeCylinder(24, 24, 1.0f, 0.15f);
        dqPalette.resize(2);
        deformed.resize(mesh.vertices.size());

        std::vector<Vec3> rest;
        for (const SkinnedVertex& v : mesh.vertices) { rest.push_back(v.position); }
        restVolume = anim::test::MeshVolume(rest, mesh.indices);
    }

    double DeformDQS(Vec3 axis, float angle) {
        SkinnedCharacter c(model);
        c.LocalPose()[1].rotation = MakeQuatAxisAngle(axis, angle);
        c.Update(model);
        BuildDualQuatPalette(c.Palette().Matrices(), dqPalette);
        for (std::size_t i = 0; i < mesh.vertices.size(); ++i) {
            deformed[i] = SkinPositionDQS(mesh.vertices[i], dqPalette);
        }
        return anim::test::MeshVolume(deformed, mesh.indices);
    }

    [[nodiscard]] float MinRadiusInBlendRegion() const {
        float minRadius = 1.0e9f;
        for (std::size_t i = 0; i < mesh.vertices.size(); ++i) {
            const SkinnedVertex& v = mesh.vertices[i];
            if (v.weights[0] < 0.01f || v.weights[1] < 0.01f) { continue; }
            const Vec3 p = deformed[i];
            minRadius = std::fmin(minRadius, std::sqrt(p.y * p.y + p.z * p.z));
        }
        return minRadius;
    }
};

}  // namespace

namespace AnimLibTests {

TEST_CLASS(DualQuatSkinningTests) {
public:

    // --- LBS と同じ土台を満たすこと -------------------------------

    TEST_METHOD(BindPoseProducesNoDeformation) {
        DqsFixture f;
        f.DeformDQS({1, 0, 0}, 0.0f);
        for (std::size_t i = 0; i < f.mesh.vertices.size(); ++i) {
            AssertNear(f.mesh.vertices[i].position, f.deformed[i], test::kEpsPos);
        }
    }

    TEST_METHOD(SingleBoneVertexFollowsRigidTransform) {
        DqsFixture f;
        SkinnedCharacter c(f.model);
        c.LocalPose()[1].rotation = MakeQuatAxisAngle({0, 0, 1}, 0.7f);
        c.Update(f.model);
        BuildDualQuatPalette(c.Palette().Matrices(), f.dqPalette);

        for (const SkinnedVertex& v : f.mesh.vertices) {
            int single = -1;
            for (int k = 0; k < kMaxInfluences; ++k) {
                if (v.weights[k] == 1.0f) { single = k; }
            }
            if (single < 0) { continue; }

            AssertNear(TransformPoint(c.Palette()[v.joints[single]], v.position),
                       SkinPositionDQS(v, f.dqPalette), test::kEpsAccum);
        }
    }

    // --- 第 21 章の破綻が解消していること -------------------------

    TEST_METHOD(TwistDoesNotCollapseTheCrossSection) {
        DqsFixture f;
        for (float degrees : {0.0f, 45.0f, 90.0f, 135.0f, 180.0f}) {
            const double v = f.DeformDQS({1, 0, 0}, degrees * kPi / 180.0f);
            const float minRadius = f.MinRadiusInBlendRegion();
            Logger::WriteMessage(std::format(
                L"DQS twist {:5.0f} deg : volume {:.2f}%, min radius {:.5f}\n",
                degrees, v / f.restVolume * 100.0, minRadius).c_str());

            // 断面が潰れない
            anim::test::AssertNear(0.15f, minRadius, test::kEpsPos);
            // 体積が 99% 以上残る（LBS は 79%）
            Assert::IsTrue(v / f.restVolume > 0.98);
        }
    }

    TEST_METHOD(BendPreservesVolume) {
        DqsFixture f;
        for (float degrees : {45.0f, 90.0f, 120.0f, 150.0f}) {
            const double ratio = f.DeformDQS({0, 0, 1}, degrees * kPi / 180.0f)
                               / f.restVolume;
            Assert::IsTrue(ratio > 0.98);
        }
    }

    // LBS より確実に良いことを、直接比較して主張する
    TEST_METHOD(DqsBeatsLbsAtLargeTwist) {
        DqsFixture f;
        const double dqs = f.DeformDQS({1, 0, 0}, kPi) / f.restVolume;

        SkinnedCharacter c(f.model);
        c.LocalPose()[1].rotation = MakeQuatAxisAngle({1, 0, 0}, kPi);
        c.Update(f.model);
        std::vector<Vec3> lbsOut(f.mesh.vertices.size());
        SkinMeshLBS(f.mesh, c.Palette().Matrices(), lbsOut);
        const double lbs = anim::test::MeshVolume(lbsOut, f.mesh.indices) / f.restVolume;

        Logger::WriteMessage(std::format(
            L"180 deg twist: LBS {:.2f}%, DQS {:.2f}%\n",
            lbs * 100.0, dqs * 100.0).c_str());
        Assert::IsTrue(dqs > lbs + 0.15);   // 実測で 15 ポイント以上の差
    }

    // --- 剛体性 ---------------------------------------------------

    // 関節中心からの距離が保存されること（22.4 節）
    TEST_METHOD(DistanceFromJointIsPreserved) {
        DqsFixture f;
        const Vec3 joint{0.5f, 0, 0};

        float restMax = 0.0f;
        for (const SkinnedVertex& v : f.mesh.vertices) {
            if (v.weights[0] < 0.01f || v.weights[1] < 0.01f) { continue; }
            restMax = std::fmax(restMax, Length(v.position - joint));
        }

        for (float degrees : {45.0f, 90.0f, 150.0f}) {
            f.DeformDQS({0, 0, 1}, degrees * kPi / 180.0f);
            float deformedMax = 0.0f;
            for (std::size_t i = 0; i < f.mesh.vertices.size(); ++i) {
                const SkinnedVertex& v = f.mesh.vertices[i];
                if (v.weights[0] < 0.01f || v.weights[1] < 0.01f) { continue; }
                deformedMax = std::fmax(deformedMax, Length(f.deformed[i] - joint));
            }
            anim::test::AssertNear(restMax, deformedMax, test::kEpsPos);
        }
    }

    // --- LBS との差が小さい領域 -----------------------------------

    // 角度が小さければ LBS と DQS はほぼ同じ。
    // 「常に DQS を使う必要はない」ことの根拠。
    TEST_METHOD(SmallAnglesAgreeWithLbs) {
        DqsFixture f;
        SkinnedCharacter c(f.model);
        c.LocalPose()[1].rotation = MakeQuatAxisAngle({1, 0, 0}, 15.0f * kPi / 180.0f);
        c.Update(f.model);
        BuildDualQuatPalette(c.Palette().Matrices(), f.dqPalette);

        float worst = 0.0f;
        for (const SkinnedVertex& v : f.mesh.vertices) {
            worst = std::fmax(worst, Length(SkinPositionLBS(v, c.Palette().Matrices())
                                          - SkinPositionDQS(v, f.dqPalette)));
        }
        Logger::WriteMessage(std::format(
            L"15 deg twist: max |LBS - DQS| = {:.6f} m\n", worst).c_str());
        Assert::IsTrue(worst < 0.002f);   // 実測 0.001283 m = 1.3 mm
    }

    TEST_METHOD(LargeAnglesDisagreeWithLbs) {
        DqsFixture f;
        SkinnedCharacter c(f.model);
        c.LocalPose()[1].rotation = MakeQuatAxisAngle({1, 0, 0}, kPi * 0.5f);
        c.Update(f.model);
        BuildDualQuatPalette(c.Palette().Matrices(), f.dqPalette);

        float worst = 0.0f;
        for (const SkinnedVertex& v : f.mesh.vertices) {
            worst = std::fmax(worst, Length(SkinPositionLBS(v, c.Palette().Matrices())
                                          - SkinPositionDQS(v, f.dqPalette)));
        }
        // 実測 0.043934 m = 4.4 cm。半径 15 cm の円柱では大きな差
        Assert::IsTrue(worst > 0.03f);
    }

    // --- 符号合わせ -----------------------------------------------

    // AlignSign を外すと壊れること（第 12 章の警告の実証）
    TEST_METHOD(SignAlignmentIsRequired) {
        DqsFixture f;
        SkinnedCharacter c(f.model);
        c.LocalPose()[1].rotation = MakeQuatAxisAngle({1, 0, 0}, kPi * 0.9f);
        c.Update(f.model);
        BuildDualQuatPalette(c.Palette().Matrices(), f.dqPalette);

        // 意図的に符号を反転させたパレットを作る
        std::vector<DualQuat> flipped = f.dqPalette;
        flipped[1] = NegateDQ(flipped[1]);

        SkinnedVertex v{};
        v.position = {0.5f, 0.15f, 0.0f};
        v.joints[0] = 0;  v.weights[0] = 0.5f;
        v.joints[1] = 1;  v.weights[1] = 0.5f;

        // AlignSign があるので、符号を反転しても結果は変わらない
        AssertNear(SkinPositionDQS(v, f.dqPalette),
                   SkinPositionDQS(v, flipped), test::kEpsPos);
    }
};

}  // namespace AnimLibTests
```

`SmallAnglesAgreeWithLbs` と `LargeAnglesDisagreeWithLbs` を対にしたのは、**使い分けの判断根拠をテストとして残す**ためです。第 10 章で `Nlerp` と `Slerp` の差を測ってテストにしたのと同じ形です。15 度で 1.3 mm、90 度で 4.4 cm。「小さい角度なら LBS で十分」という判断が、数値で裏づけられています。

`SignAlignmentIsRequired` は、**`AlignSign` が実際に効いていることを検査**しています。パレットの符号を意図的に反転させても結果が変わらない ―― これは `AlignSign` を消すと即座に落ちます。第 12 章で「忘れると静かに壊れる」と警告した箇所に、明示的な番人を置いた形です。

## 22.8　つまずきやすいところ

**一部の頂点が明後日の方向へ飛ぶ**
`AlignSign` を忘れています。第 12 章と 22.2 節を参照してください。

**DQS にしたらモデルのスケールが消えた**
仕様です。22.5 節の ② を参照してください。`HasNonUniformScale`（第 11 章）でモデルを検査してください。

**DQS にしたら関節が太くなった**
ウェイトが LBS 前提で調整されている可能性があります（22.5 節の ③）。DQS 用に調整し直すか、その部位だけ LBS に戻してください。

**`BuildDualQuatPalette` の結果がおかしい**
パレットの行列にスケールが入っています。`ToQuat` は純粋な回転を前提としています（第 9 章、第 19 章のコラム）。

**LBS より 2.5 倍遅い**
そのとおりです。全身に DQS を使う必要はありません。ねじりの大きい部位だけに限定してください。

**DQS でも体積が 99% で 100% にならない**
メッシュの分割の粗さです。`MakeCylinder` の分割数を上げれば 100% に近づきます。アルゴリズムの損失ではありません。

## この章のまとめ

- DQS は「**混ぜてから正規化する**」を剛体変換について行う。第 10 章の `Nlerp` と同じ発想を、位置を含む変換に拡張したもの。
- 第 21 章の測定をそのままやり直すと、**180 度ねじりで最小半径 0.15000（LBS は 0.00000）、体積 99.61%（LBS は 79.48%）**。断面が一切潰れない。
- 理由は、DQS が各頂点を**剛体変換**で動かすから。**関節中心からの距離が完全に保存される**ことを測定で確認した。
- 代償は 3 つ ―― **2.48 倍遅い**、**スケールを表現できない**、**既存アセットのウェイトが LBS 前提**。
- **「DQS は膨らむ」を測ろうとしたが、本書の 2 ボーン円柱では検出できなかった。** 剛体変換である以上、関節中心からの距離は増えようがない。「膨らむ」の実務上の中身は「LBS のように痩せないので、LBS 前提のモデルでは相対的に太く見える」ことだと考えられる。**再現できなかったことは、そう書く。**
- 使い分けは部位ごと。**15 度で差は 1.3 mm、90 度で 4.4 cm。** 小さい角度なら LBS で十分。

**破綻を数値に翻訳する。** 「キャンディラッパー現象」を「体積 79.48%、最小半径 0.00000」に置き換えました。描画せずにアニメーションを検証するとは、こういう作業です。そしてこの翻訳ができたからこそ、DQS の改善も数値で示せました。

**閉じた式で裏を取る。** `r' = r·√(w₀² + w₁² + 2w₀w₁cos θ)` が実測と小数第 6 位まで一致したとき、測定コードもスキニング実装も正しいと確信できました。**数値実験と理論の両方を持つ**と、片方の間違いをもう片方が捕まえます。

**素朴な実装を消さない。** 第 18 章の参照実装は、第 20 章の最適化版と第 22 章の DQS 版の両方を検証する基準になりました。この先の第 53 章（SIMD）、第 58 章（GPU）でも同じ役割を果たします。

**測れなかったことは、測れなかったと書く。** DQS の膨らみは検出できませんでした。第 13 章でキャッシュの効果が測れなかったときと同じです。**実測を根拠にする方針は、都合の悪い結果も引き受けることでしか成立しません。**
