# 第 37 章　ランタイム形式へ焼き込む

**この章で作るもの**：読み込んだデータを、毎フレーム使いやすい形に変換して保存する仕組み。ただし ―― **この章は、筆者の予想が大きく外れた章**です。測ってから考え直した経緯ごと書きます。

---

## 37.1　なぜ焼き込むのか（という思い込み）

ゲームエンジンは、たいてい**独自のランタイム形式**を持っています。glTF や FBX をそのまま読むのではなく、ビルド時に変換しておいて、実行時はそれを読む。

理由として挙げられるのは、こういうことです。

- JSON のパースが遅い
- ロード時の変換処理が無駄
- ファイルが小さくなる
- `memcpy` 1 回で読める

**筆者もそう思って、この章を書き始めました。** そして測ったら、そのほとんどが間違っていました。

---

## 37.2　まず測る

24,120 頂点・48,000 三角形のモデル（`.gltf` 1,391 バイト + `.bin` 1,733,888 バイト）で、読み込みの内訳を測りました。

| 処理 | 時間 | 割合 |
| --- | --- | --- |
| ファイルの読み込み | 5.630 ms | **81%** |
| JSON のパース | **0.032 ms** | **0.4%** |
| アクセサの読み出し | （上に含まれる） | |
| 頂点の組み立て | 1.307 ms | 19% |

**JSON のパースは、全体の 0.4% でした。**

第 31 章で「ロード時に 1 回のコストなので最適化しない」と判断しましたが、その判断は正しかっただけでなく、**想像以上に正しかった**わけです。100 倍速い JSON パーサに置き換えても、ロード時間は 0.4% しか改善しません。

支配しているのは**ファイルの読み込み**です。1.73 MB を読むのに 5.6 ms ―― 約 300 MB/s。これは SSD の速度ではなく、`std::ifstream` で `std::string` に読み込む処理のコストです。

**ここから導かれる結論は明確です。「JSON を避ける」のではなく「ファイルを小さくする」ことが速さにつながる。**

---

## 37.3　素朴に焼き込んだら、遅くなった

それでも試しました。`SkinnedVertex` の配列とインデックス配列を、そのままファイルに書き出す形式です。

```cpp
// 素朴な「焼き込み」形式
struct BakedHeader {
    std::uint32_t magic;         // 'APAK'
    std::uint32_t version;
    std::uint32_t vertexCount;
    std::uint32_t indexCount;
};
// この後に SkinnedVertex の配列、そして uint32 のインデックス配列が続く
```

読み込みは `memcpy` 2 回です。パースも変換もありません。**速いに決まっている**と思いました。

結果です。

| | 読み込み時間 | ファイルサイズ |
| --- | --- | --- |
| glTF（`.gltf` + `.bin`） | 7.87 ms | 1,735,279 B |
| 素朴な焼き込み | **9.81 ms** | **2,312,656 B** |

**遅くなり、しかもファイルが大きくなりました。**

原因は分かります。

**① 使わない属性を書いている。** `SkinnedVertex` は 72 バイトですが、このモデルは接線と UV を持っていません。既定値で埋めた 24 バイト × 24,120 頂点 = **579 KB のゼロ**を書いていました。

**② インデックスを太らせた。** glTF は `uint16` で持っていたインデックスを、`uint32` にしています。48,000 × 3 × 2 バイト = **288 KB の増加**。

つまり、**ファイルが 33% 大きくなり、読み込みが 81% を占める処理なので、そのぶん遅くなった**。単純な話です。

そして気づかされたのは、**glTF のバイナリバッファは、既に相当良いランタイム形式だ**ということです。位置 12 + 法線 12 + ジョイント 8 + ウェイト 16 = 48 バイト/頂点。無駄がありません。

---

## 37.4　では、何のために焼き込むのか

測定を踏まえて、理由を書き直します。

**理由 1：ファイルを小さくするため。**
これが最大の効果を持ちます。ただし「バイナリだから小さい」のではなく、**意識的に削るから小さい**。使わない属性を落とす、インデックス幅を保つ、そして第 55 章の量子化。**焼き込みは、圧縮のための場所**です。

**理由 2：ロード時の計算を省くため。**
測定では頂点の組み立てに 1.307 ms かかっていました。内訳の大半は、**頂点ごとに `std::vector<Influence>` を確保している**ことです（第 33 章の実装）。24,120 回のアロケーション。焼き込んでおけば、これがゼロになります。

**理由 3：名前を消すため。**
ランタイムに `std::string` は要りません。IK チェーンやソケットの設定は、ビルド時に名前をボーン番号へ解決しておけます。第 13 章で「`FindBone` はあえて線形探索のまま」と書いた理由がこれです ―― **ランタイムで名前を引く設計が、そもそも間違っている**。

**理由 4：メモリレイアウトを決めるため。**
第 20 章の SoA、第 52 章のデータ指向設計。ランタイムが欲しい形と、交換フォーマットが持っている形は違います。

**理由 5：1 ファイル・1 アロケーションにするため。**
モデル、スケルトン、複数のクリップを 1 つのファイルにまとめ、1 回の読み込みで済ませる。将来メモリマップドファイルにする道も開けます。

**「バイナリだから速い」は理由になりません。** 何を削り、何を事前計算するかが本体です。

## 37.5　焼き込み形式を設計する

```cpp
// AnimLib/include/anim/AssetPack.h

namespace anim {

// 焼き込み済みアセット。1 モデル + そのクリップ群。
struct AssetPackHeader {
    std::uint32_t magic;          // 'APAK'（0x4B415041）
    std::uint32_t version;        // 第 2 章の kVersionMajor/Minor から作る
    std::uint32_t boneCount;
    std::uint32_t vertexCount;
    std::uint32_t indexCount;
    std::uint32_t clipCount;
    std::uint32_t vertexFormat;   // どの属性が入っているかのビットフラグ
    std::uint32_t indexWidth;     // 2 または 4
};

enum VertexAttributeBits : std::uint32_t {
    kAttributePosition = 1u << 0,
    kAttributeNormal   = 1u << 1,
    kAttributeTangent  = 1u << 2,
    kAttributeUv       = 1u << 3,
    kAttributeSkin     = 1u << 4,
};

}  // namespace anim
```

**`vertexFormat` と `indexWidth` を持つ**のが、37.3 節の失敗から学んだ点です。「常に 72 バイト、常に `uint32`」ではなく、**モデルが実際に持っているものだけを書く**。

書き出しは属性ごとに分けます（第 20 章の SoA への布石でもあります）。

```
[ ヘッダ ]
[ 親インデックス配列    : uint16 × boneCount ]
[ レストポーズ          : Transform × boneCount ]
[ 逆バインド行列        : Mat4 × boneCount ]
[ 位置                  : Vec3 × vertexCount ]
[ 法線                  : Vec3 × vertexCount ]（フラグが立っていれば）
[ ジョイント            : uint16[4] × vertexCount ]
[ ウェイト              : float[4] × vertexCount ]
[ インデックス          : uint16 または uint32 × indexCount ]
[ クリップ 0 ... ]
```

**ボーン名は書きません。** 必要なら別ファイル（デバッグ用）に出します。

### バージョニング ―― 第 2 章の回収

第 2 章で、こんなコードを書きました。

```cpp
inline constexpr int kVersionMajor = 0;
inline constexpr int kVersionMinor = 1;
[[nodiscard]] int VersionNumber() noexcept;
```

「第 37 章のシリアライズで、焼き込み済みデータの互換性判定に使う」とコメントに書いたまま、35 章ぶん放置していました。ここで使います。

```cpp
[[nodiscard]] constexpr std::uint32_t AssetPackVersion() {
    return static_cast<std::uint32_t>(kVersionMajor) * 1000u
         + static_cast<std::uint32_t>(kVersionMinor);
}

std::expected<AssetPack, AssetError> LoadAssetPack(std::span<const std::uint8_t> data) {
    if (data.size() < sizeof(AssetPackHeader)) {
        return std::unexpected(AssetError{"ファイルが短すぎる"});
    }
    AssetPackHeader header{};
    std::memcpy(&header, data.data(), sizeof(header));

    if (header.magic != kAssetPackMagic) {
        return std::unexpected(AssetError{"マジックが違う"});
    }
    if (header.version != AssetPackVersion()) {
        return std::unexpected(AssetError{
            std::format("バージョンが違う（ファイル {}、実行ファイル {}）。"
                        "アセットを再ビルドしてください",
                        header.version, AssetPackVersion())});
    }
    // ...
}
```

**バージョンが違ったら、読まずに失敗させます。** 「古いバージョンも読めるようにする」という互換性の作り込みは、**ライブラリの開発中には有害**です。フォーマットが変わったのに古いデータで動いてしまうと、「なぜかテストが通るのに実機で壊れる」という状況になります。

エラーメッセージに「アセットを再ビルドしてください」と書いてあるのが重要です。**エラーは、次に何をすべきかを教えるもの**です。

## 37.6　書き出しと読み込み

```cpp
class AssetPackWriter {
public:
    void SetModel(const Skeleton& skeleton, std::span<const Mat4> inverseBind);
    void SetMesh(const SkinnedMesh& mesh);
    void AddClip(std::string name, const Clip& clip);

    [[nodiscard]] std::vector<std::uint8_t> Build() const;

private:
    // 実際に使われている属性を検出する
    [[nodiscard]] std::uint32_t DetectVertexFormat() const;
    [[nodiscard]] std::uint32_t DetectIndexWidth() const;
};
```

```cpp
std::uint32_t AssetPackWriter::DetectVertexFormat() const {
    std::uint32_t format = kAttributePosition;

    // 法線がすべて既定値なら書かない
    const bool hasNormals = std::any_of(mesh_.vertices.begin(), mesh_.vertices.end(),
        [](const SkinnedVertex& v) {
            return !anim::test::IsNear(v.normal.y, 1.0f, 1.0e-6f)
                || !anim::test::IsNear(v.normal.x, 0.0f, 1.0e-6f);
        });
    if (hasNormals) { format |= kAttributeNormal; }
    // 接線・UV も同様に検出する
    // ...
    return format;
}

std::uint32_t AssetPackWriter::DetectIndexWidth() const {
    const std::uint32_t maxIndex = mesh_.vertices.empty()
        ? 0u : static_cast<std::uint32_t>(mesh_.vertices.size() - 1);
    return (maxIndex <= 0xFFFFu) ? 2u : 4u;
}
```

**「実際に何が入っているか」を検出して書く**のが、37.3 節の失敗への対処です。

読み込み側は、フラグを見て分岐します。

```cpp
    if (header.vertexFormat & kAttributeNormal) {
        std::memcpy(normals.data(), cursor, vertexCount * sizeof(Vec3));
        cursor += vertexCount * sizeof(Vec3);
    } else {
        std::fill(normals.begin(), normals.end(), Vec3{0.0f, 1.0f, 0.0f});
    }
```

### `memcpy` で読める、ということの意味

`std::memcpy` でそのまま読めるのは、`Vec3` や `Mat4` が**トリビアルにコピー可能な集成体**だからです。第 5 章でコンストラクタを書かないと決めた理由の 1 つが、これでした。

ただし、**この形式は移植可能ではありません**。エンディアン、構造体のパディング、`float` の表現 ―― どれかが違う環境では読めません。

**それで構いません。** 焼き込み形式は**ビルド時に生成される中間ファイル**であって、配布物ではないからです。プラットフォームごとにビルドすればよい。むしろ「移植可能にしよう」として可変長エンコーディングなどを入れると、`memcpy` の速さを失います。

**交換フォーマット（glTF）と実行フォーマット（AssetPack）を分ける、というのはそういうことです。**

## 37.7　テストを書く

`AnimLib.Tests/AssetPackTests.cpp`：

```cpp
#include "CppUnitTest.h"

#include "TestSupport/GltfTestData.h"
#include "TestSupport/MathAssert.h"
#include "TestSupport/Tolerance.h"

#include "anim/AssetPack.h"
#include "anim/GltfAnimation.h"
#include "anim/GltfMesh.h"
#include "anim/GltfSkeleton.h"
#include "anim/SkinnedCharacter.h"

#include <format>

using namespace Microsoft::VisualStudio::CppUnitTestFramework;
using namespace anim;

namespace {

// glTF を読んで、焼き込んで、読み戻す
struct BakedRoundTrip {
    GltfSkeleton source;
    SkinnedMesh sourceMesh;
    Clip sourceClip;
    AssetPack baked;
};

BakedRoundTrip MakeRoundTrip() {
    auto doc = GltfDocument::LoadFromFile(anim::test::TestDataDir() / "cylinder.gltf");
    auto skeleton = LoadSkeleton(*doc, 0);
    auto mesh = LoadMesh(*doc, 0, nullptr, &*skeleton);
    auto clip = LoadAnimation(*doc, 0, *skeleton, nullptr);

    AssetPackWriter writer;
    writer.SetModel(skeleton->skeleton, skeleton->inverseBind);
    writer.SetMesh(*mesh);
    writer.AddClip("Twist", *clip);
    const std::vector<std::uint8_t> bytes = writer.Build();

    auto loaded = LoadAssetPack(bytes);
    Assert::IsTrue(loaded.has_value());

    return {std::move(*skeleton), std::move(*mesh), std::move(*clip), std::move(*loaded)};
}

}  // namespace

namespace AnimLibTests {

TEST_CLASS(AssetPackTests) {
public:

    // --- ラウンドトリップ -----------------------------------------

    TEST_METHOD(SkeletonSurvivesRoundTrip) {
        const BakedRoundTrip r = MakeRoundTrip();

        Assert::AreEqual(r.source.skeleton.BoneCount(), r.baked.skeleton.BoneCount());
        for (BoneIndex i = 0; i < r.source.skeleton.BoneCount(); ++i) {
            Assert::AreEqual<int>(r.source.skeleton.ParentOf(i),
                                  r.baked.skeleton.ParentOf(i));
            anim::test::AssertNear(r.source.skeleton.RestLocal(i).translation,
                                   r.baked.skeleton.RestLocal(i).translation,
                                   test::kEpsPos);
        }
    }

    TEST_METHOD(MeshSurvivesRoundTrip) {
        const BakedRoundTrip r = MakeRoundTrip();

        Assert::AreEqual(r.sourceMesh.vertices.size(), r.baked.mesh.vertices.size());
        Assert::AreEqual(r.sourceMesh.indices.size(), r.baked.mesh.indices.size());

        for (std::size_t i = 0; i < r.sourceMesh.vertices.size(); ++i) {
            const SkinnedVertex& a = r.sourceMesh.vertices[i];
            const SkinnedVertex& b = r.baked.mesh.vertices[i];
            // 位置・法線はビット単位で一致するはず（変換していないので）
            Assert::IsTrue(a.position.x == b.position.x);
            Assert::IsTrue(a.position.y == b.position.y);
            Assert::IsTrue(a.position.z == b.position.z);
            for (int k = 0; k < kMaxInfluences; ++k) {
                Assert::AreEqual<int>(a.joints[k], b.joints[k]);
                Assert::IsTrue(a.weights[k] == b.weights[k]);
            }
        }
        for (std::size_t i = 0; i < r.sourceMesh.indices.size(); ++i) {
            Assert::AreEqual(r.sourceMesh.indices[i], r.baked.mesh.indices[i]);
        }
    }

    // クリップは「サンプル結果が一致する」ことで検査する。
    // 内部表現が変わっても通るテストにしておく（第 54 章の圧縮への備え）
    TEST_METHOD(ClipProducesIdenticalPoses) {
        const BakedRoundTrip r = MakeRoundTrip();

        Pose a(r.source.skeleton.BoneCount());
        Pose b(r.source.skeleton.BoneCount());
        for (int step = 0; step <= 100; ++step) {
            const float t = static_cast<float>(step) / 100.0f * r.sourceClip.Duration();
            r.sourceClip.Sample(t, a);
            r.baked.clips[0].Sample(t, b);

            for (BoneIndex i = 0; i < r.source.skeleton.BoneCount(); ++i) {
                anim::test::AssertNear(a[i].translation, b[i].translation, test::kEpsPos);
                anim::test::AssertSameRotation(a[i].rotation, b[i].rotation, test::kEpsDir);
            }
        }
    }

    // --- 最終出力の一致（最も重要）--------------------------------

    // 焼き込み前後で、スキニングの結果が一致すること。
    // 途中の表現が何であれ、これが一致すれば実用上は同じ。
    TEST_METHOD(SkinnedOutputIsIdentical) {
        const BakedRoundTrip r = MakeRoundTrip();

        SkinnedModel modelA{r.source.skeleton, r.source.inverseBind};
        SkinnedModel modelB{r.baked.skeleton, r.baked.inverseBind};
        SkinnedCharacter a(modelA);
        SkinnedCharacter b(modelB);

        std::vector<Vec3> outA(r.sourceMesh.vertices.size());
        std::vector<Vec3> outB(r.baked.mesh.vertices.size());

        for (int step = 0; step <= 30; ++step) {
            const float t = static_cast<float>(step) / 30.0f * 0.99f;
            r.sourceClip.Sample(t, a.LocalPose());
            r.baked.clips[0].Sample(t, b.LocalPose());
            a.Update(modelA);
            b.Update(modelB);
            SkinMeshLBS(r.sourceMesh, a.Palette().Matrices(), outA);
            SkinMeshLBS(r.baked.mesh, b.Palette().Matrices(), outB);

            for (std::size_t i = 0; i < outA.size(); ++i) {
                anim::test::AssertNear(outA[i], outB[i], test::kEpsPos);
            }
        }
    }

    // --- 属性の検出（37.6 節）------------------------------------

    TEST_METHOD(UnusedAttributesAreNotWritten) {
        const BakedRoundTrip r = MakeRoundTrip();
        // テストモデルは接線と UV を持たない
        Assert::IsTrue((r.baked.vertexFormat & kAttributeNormal) != 0);
        Assert::IsTrue((r.baked.vertexFormat & kAttributeTangent) == 0);
        Assert::IsTrue((r.baked.vertexFormat & kAttributeUv) == 0);
    }

    TEST_METHOD(SmallMeshesUseSixteenBitIndices) {
        const BakedRoundTrip r = MakeRoundTrip();
        Assert::AreEqual<std::uint32_t>(2, r.baked.indexWidth);
    }

    // 37.3 節の失敗を繰り返さないための番人。
    // 焼き込み結果が glTF のバイナリより大きくなっていないこと。
    TEST_METHOD(BakedFileIsNotLargerThanTheSourceBinary) {
        auto doc = GltfDocument::LoadFromFile(anim::test::TestDataDir() / "cylinder.gltf");
        auto skeleton = LoadSkeleton(*doc, 0);
        auto mesh = LoadMesh(*doc, 0, nullptr, &*skeleton);
        auto clip = LoadAnimation(*doc, 0, *skeleton, nullptr);

        AssetPackWriter writer;
        writer.SetModel(skeleton->skeleton, skeleton->inverseBind);
        writer.SetMesh(*mesh);
        writer.AddClip("Twist", *clip);
        const std::size_t bakedSize = writer.Build().size();

        const std::size_t sourceSize =
            std::filesystem::file_size(anim::test::TestDataDir() / "cylinder.bin");

        Logger::WriteMessage(std::format(L"baked {} B vs source bin {} B\n",
                                         bakedSize, sourceSize).c_str());
        Assert::IsTrue(bakedSize <= sourceSize);
    }

    // --- バージョニング -------------------------------------------

    TEST_METHOD(WrongVersionIsRejected) {
        AssetPackWriter writer;
        writer.SetModel(anim::test::MakeArmSkeleton(), {});
        std::vector<std::uint8_t> bytes = writer.Build();

        // バージョン番号を書き換える
        const std::uint32_t bogus = 9999;
        std::memcpy(bytes.data() + offsetof(AssetPackHeader, version), &bogus, 4);

        const auto loaded = LoadAssetPack(bytes);
        Assert::IsFalse(loaded.has_value());
        Assert::IsTrue(loaded.error().message.find("再ビルド") != std::string::npos);
    }

    TEST_METHOD(BadMagicIsRejected) {
        std::vector<std::uint8_t> garbage(256, 0xAB);
        Assert::IsFalse(LoadAssetPack(garbage).has_value());
    }

    TEST_METHOD(TruncatedFileIsRejected) {
        AssetPackWriter writer;
        writer.SetModel(anim::test::MakeArmSkeleton(), {});
        std::vector<std::uint8_t> bytes = writer.Build();
        bytes.resize(bytes.size() / 2);
        Assert::IsFalse(LoadAssetPack(bytes).has_value());
    }
};

}  // namespace AnimLibTests
```

`SkinnedOutputIsIdentical` が、この章で最も重要なテストです。**途中の表現が何であれ、最終的な頂点位置が一致すればよい。** この形にしておくと、第 54〜56 章でキーフレームを圧縮したときも、同じテストがそのまま使えます（許容誤差を緩める必要はありますが）。

`BakedFileIsNotLargerThanTheSourceBinary` は、**37.3 節の失敗を繰り返さないための番人**です。「焼き込んだら大きくなった」という間違いは、意識していないと簡単に再発します。テストにしておけば、二度と起きません。

## 37.8　つまずきやすいところ

**焼き込んだのに遅くなった**
37.3 節です。ファイルサイズを比べてください。読み込み時間の大半は I/O です。

**「JSON パーサを最適化しよう」と思った**
測ってください。実測で 0.4% でした。

**別のマシンで焼き込んだファイルが読めない**
`memcpy` ベースの形式は移植可能ではありません。ビルド時に生成するものなので、それで構いません（37.6 節）。

**構造体を変えたのにバージョンを上げ忘れた**
静かに壊れます。**`AssetPackVersion()` を上げる**か、`static_assert(sizeof(SkinnedVertex) == 72)`（第 17 章）のようなサイズの固定を併用してください。

**古いアセットが読めてしまう**
バージョン検査を「警告」にしていませんか。開発中は**失敗させる**のが正しい。

**ボーン名がなくてデバッグできない**
デバッグビルドでは名前も書き出す、あるいは別ファイルに出す、という運用にしてください。

## この章のまとめ

- **測ったら、思い込みのほとんどが間違っていた。** JSON のパースはロード時間の **0.4%**。ファイルの読み込みが **81%**。
- **素朴に焼き込んだら、遅くなり、ファイルも大きくなった**（7.87 → 9.81 ms、1.73 → 2.31 MB）。使わない属性を既定値で埋め、インデックスを `uint32` に太らせたため。
- **glTF のバイナリバッファは、既にかなり良いランタイム形式**（48 バイト/頂点、無駄なし）。
- 焼き込みの本当の理由は 5 つ ―― **ファイルを小さくする（圧縮の場所）・ロード時の計算を省く・名前を消す・メモリレイアウトを決める・1 ファイル 1 アロケーションにする**。「バイナリだから速い」は理由にならない。
- 形式には **`vertexFormat` と `indexWidth`** を持たせ、**実際に使われているものだけを書く**。
- **第 2 章の `kVersionMajor` / `kVersionMinor` を、35 章ぶりに回収した。** バージョンが違うファイルは**読まずに失敗させる**。エラーメッセージには「次に何をすべきか」を書く。
- 交換フォーマット（glTF、移植可能）と実行フォーマット（AssetPack、`memcpy` で読める）を**分ける**。後者が移植可能でなくてよいのは、ビルド時に生成する中間ファイルだから。
- 検証は**最終出力の一致**で行う。途中の表現が変わっても通るテストにしておけば、第 54〜56 章の圧縮でもそのまま使える。
- **「焼き込んだら大きくなった」をテストで防ぐ。** 意識していないと簡単に再発する。

---

## 第 VI 部を終えて

9 章かけて、glTF を読めるようになりました。

```
第 30・31 章  JSON パーサ         ✅  不正入力 11 種を弾く
第 32 章      バッファとアクセサ   ✅  ストライド・正規化整数
第 33 章      メッシュ             ✅  第 17 章の型へ
第 34 章      ノード階層とスキン   ✅  転置・ソート・対応表
第 35 章      アニメーション       ✅  第 V 部の型へ
第 36 章      GLB                  ✅  3 形態でビット一致
第 37 章      焼き込み             ✅  測ってから設計した
```

そして、**手書きデータで確かめたことが、実データでも同じ数値で観測できました。**

| 検証 | 手書きデータ | glTF から |
| --- | --- | --- |
| バインドポーズでパレットが単位行列 | 第 16 章 ✅ | 第 34 章 ✅ |
| t = 0 でバインドポーズ | 第 15 章 ✅ | 第 35 章 ✅ |
| 180 度ねじりで断面が潰れる | 0.000000（第 21 章） | **0.000021**（第 35 章） |

**同じ現象が、まったく違う経路のデータで再現する。** JSON パース、Base64、アクセサ、転置、トポロジカルソート、対応表、キーフレーム補間 ―― この全部が正しくなければ、この数値は出ません。第 III 部・第 IV 部で書いたテストが、9 章あとの検証にそのまま使えたことになります。

第 VI 部で繰り返し出てきた方針も、あらためて確認しておきます。

**ファイルの中の情報を検証に使う。** `accessor.min`/`max`、`byteLength`、`input` の `max`。**ファイルが自分で正解を教えてくれる**場面は、逃さず使う。

**失敗と警告を分ける。** 読めないものは `std::expected` で失敗させる。読めるが怪しいものは、処理を続けて `Report` に記録する。ウェイト合計 0.98 は止める理由にならないが、黙って直すのも良くない。

**扱わないものを、無視ではなく報告する。** モーフターゲット、必須拡張、スキン外のチャンネル。「読めたつもりで壊れたデータを使う」のが最悪の結果。

**テストデータを都合よく作らない。** joints をわざと逆順にする、壊れた GLB を 5 種類作る、ロケールを変更する。**自分の実装が通りやすいデータだけでテストしても、何も保証できません。**

次章から第 VII 部。複数のアニメーションを混ぜます。第 10 章で測った `Nlerp` と `Slerp` の使い分けが、いよいよ実際に効いてくる領域です。
