# 第 40 章　加算ブレンド

**この章で作るもの**：「ポーズそのもの」ではなく「**ポーズの差分**」を扱う仕組み。呼吸、被弾リアクション、エイムオフセット ―― どれも「今の動きの上に、何かを乗せる」形で表現されます。

---

## 40.1　乗せる、という発想

これまでのブレンドは**置き換え**でした。歩きと走りを 3:7 で混ぜると、歩きの成分は 30% に減ります。

しかし、こういう要求があります。

**呼吸。** 待機中も、走行中も、しゃがみ中も、胸が上下してほしい。**今どんなアニメーションを再生していても、その上に乗せたい。**

**被弾リアクション。** 撃たれたら上半身がのけぞる。走っている最中でも、待機中でも。

**エイムオフセット。** 上を狙えば銃口が上を向く。歩きながらでも、しゃがみながらでも。

これらを置き換え型のブレンドで実現しようとすると、**組み合わせの数だけクリップが必要**になります。「走りながら呼吸」「しゃがみながら呼吸」「走りながら被弾」…… 現実的ではありません。

**加算ブレンド（additive blending）**は、これを「差分」として扱います。

```
呼吸クリップ − 基準ポーズ = 差分（胸が少し上がっている、という情報だけ）
現在のポーズ + 差分 × 重み = 呼吸しながらの現在のポーズ
```

**差分は、どんなポーズにも乗せられます。** クリップの組み合わせ爆発が消えます。

---

## 40.2　差分を作る

差分は、**アニメーションのポーズから基準ポーズを「引いた」もの**です。

引き算の意味は、成分ごとに違います。

| 成分 | 差分の定義 |
| --- | --- |
| 平行移動 | `source − base`（引き算） |
| 回転 | `source * conjugate(base)`（基準を打ち消す回転） |
| スケール | `source / base`（割り算） |

```cpp
// AnimLib/include/anim/AdditiveBlend.h
#pragma once

#include "anim/PoseBlend.h"

namespace anim {

// source から base を引いた差分を作る。ロード時に一度だけ行う。
inline void MakeAdditive(const Pose& source, const Pose& base, Pose& out) {
    ANIM_ASSERT(source.Size() == base.Size() && source.Size() == out.Size());
    for (std::size_t i = 0; i < source.Size(); ++i) {
        const BoneIndex bone = static_cast<BoneIndex>(i);
        const Transform& s = source[bone];
        const Transform& b = base[bone];
        out[bone] = {
            s.translation - b.translation,
            s.rotation * Conjugate(b.rotation),      // 単位クォータニオンなので共役 = 逆
            {s.scale.x / b.scale.x, s.scale.y / b.scale.y, s.scale.z / b.scale.z}
        };
    }
}

}  // namespace anim
```

**回転の順序に注意してください。** `s.rotation * Conjugate(b.rotation)` です。第 8 章の規約では「右が先」なので、これは「基準の回転を打ち消してから、目的の回転を適用する」という意味になります。

逆にすると（`Conjugate(b.rotation) * s.rotation`）、差分が**基準の座標系で表現された**ものになり、40.3 節の適用と食い違います。

**差分ポーズは、もはや「姿勢」ではありません。** 回転は「単位回転からのずれ」、平行移動は「オフセット」です。デバッガで見ると、ほとんどのボーンが `translation = (0,0,0)`、`rotation = (0,0,0,1)` になっているはずです。**それが正常**で、動いているボーンだけが値を持ちます。

## 40.3　差分を適用する

```cpp
// base に additive を weight の強さで乗せる。
inline void ApplyAdditive(const Pose& base, const Pose& additive,
                          float weight, Pose& out) {
    for (std::size_t i = 0; i < base.Size(); ++i) {
        const BoneIndex bone = static_cast<BoneIndex>(i);
        const Transform& b = base[bone];
        const Transform& d = additive[bone];

        // 回転差分を weight の強さに弱める（40.4 節）
        const Quat scaled = Nlerp(QuatIdentity(), d.rotation, weight);

        out[bone] = {
            b.translation + d.translation * weight,
            scaled * b.rotation,                     // 差分を外側から掛ける
            {b.scale.x * (1.0f + (d.scale.x - 1.0f) * weight),
             b.scale.y * (1.0f + (d.scale.y - 1.0f) * weight),
             b.scale.z * (1.0f + (d.scale.z - 1.0f) * weight)}
        };
    }
}
```

**`scaled * b.rotation`** ―― 差分を**左から**掛けます。40.2 節で `s * conj(b)` として作ったので、`(s * conj(b)) * b = s` になり、重み 1 で元のポーズが再現されます。

`out` が `base` と同じでも安全です（第 38 章と同じ理由）。ブレンドツリー（第 44 章）で使います。

---

## 40.4　回転の「部分適用」

重みが 0.5 のとき、平行移動なら `d.translation * 0.5` で済みます。回転はそうはいきません。**クォータニオンに 0.5 を掛けても、半分の回転にはなりません**（長さが 0.5 になるだけです）。

必要なのは「単位回転から差分までの、半分の位置」です。これは第 10 章の補間そのものです。

```cpp
const Quat scaled = Nlerp(QuatIdentity(), d.rotation, weight);
```

`Slerp` を使うべきかは、差分の大きさによります。第 10 章の表を思い出してください。

| 差分の回転角 | `Nlerp` の誤差 |
| --- | --- |
| 45° 以下 | 0.12° 未満 |
| 90° | 0.92° |

**加算ブレンドの差分は、たいてい小さい**（呼吸は数度、被弾でも 30 度程度）ので、`Nlerp` で十分です。エイムオフセットのように 90 度を超える差分を扱うなら、`Slerp` に切り替えてください。

> **`weight > 1` を許すか**
> `weight = 1.5` にすると、差分が 1.5 倍に誇張されます。`Nlerp(identity, d, 1.5)` は外挿になり、数学的には意味を持ちます。演出として使える一方、想定外の姿勢になりやすいので、本書は `[0, 1]` にクランプしません（呼び出し側の責任とします）が、ツール側で上限を設けるのが実務的です。

## 40.5　基準ポーズをどう選ぶか

差分を作るには「何から引くか」を決める必要があります。**この選択が、加算ブレンドの品質を決めます。**

**方法 ①：加算クリップの最初のフレーム。** 呼吸クリップの t=0 の姿勢を基準にする。最も一般的です。

```cpp
Pose base(boneCount);
Pose source(boneCount);
Pose additive(boneCount);

breathClip.Sample(0.0f, base);        // 基準 = 最初のフレーム
breathClip.Sample(currentTime, source);
MakeAdditive(source, base, additive);
```

**方法 ②：別の「基準クリップ」の同時刻。** 被弾リアクションを「待機」との差分として作る場合。アニメーターが「待機」と「待機＋被弾」の 2 つを作り、その差を取ります。

**方法 ③：レストポーズ。** 単純ですが、たいてい良くありません。レストポーズは T ポーズなので、差分が巨大になり、40.4 節の `Nlerp` の誤差が問題になります。

**方法 ①が既定**です。ただし**毎フレーム基準をサンプルするのは無駄**なので、ロード時に差分クリップを作っておきます。

```cpp
// ロード時：クリップ全体を差分に変換する
Clip MakeAdditiveClip(const Clip& source, const Clip& base, float baseTime,
                      std::size_t boneCount) {
    Pose basePose(boneCount);
    base.Sample(baseTime, basePose);

    Clip result;
    result.Resize(boneCount);
    result.SetDuration(source.Duration());
    result.SetLoopMode(source.GetLoopMode());

    // 元クリップのキー時刻をそのまま使い、値だけ差分にする
    for (BoneIndex bone = 0; bone < boneCount; ++bone) {
        const Track<Quat>& src = source.Bone(bone).rotation;
        Track<Quat>& dst = result.Bone(bone).rotation;
        dst.SetInterpolation(src.GetInterpolation());
        for (std::size_t k = 0; k < src.KeyCount(); ++k) {
            dst.AddKey(src.Key(k).time,
                       src.Key(k).value * Conjugate(basePose[bone].rotation));
        }
        dst.Finalize();
        // 平行移動・スケールも同様
    }
    return result;
}
```

**キーの時刻はそのまま、値だけを差分にする**のがポイントです。補間の挙動が元クリップと一致します。

> **三次補間の差分クリップ**
> `CUBICSPLINE` のクリップを差分化するときは、接線も変換する必要があります。回転の接線は「値と同じ回転を掛ける」だけでは正しくありません。本書は**差分クリップを線形補間に限定**します。呼吸や被弾のような加算アニメーションで三次補間が必要になることは稀です。

## 40.6　いくつ乗せられるか

加算ブレンドは**重ねられます**。

```cpp
Pose pose = /* 走りのポーズ */;
ApplyAdditive(pose, breathAdditive, 1.0f, pose);      // 呼吸
ApplyAdditive(pose, aimAdditive, aimWeight, pose);    // エイムオフセット
ApplyAdditive(pose, hitAdditive, hitWeight, pose);    // 被弾リアクション
```

**順序は結果に影響します。** 回転の合成は可換でないからです（第 8 章）。

ただし、**差分が小さければ影響も小さい**。第 38 章の N 個ブレンドと同じ構図です。呼吸（数度）と被弾（30 度）を入れ替えても、実用上の差は出ません。

**順序を決めておくこと**が大事です。本書は「小さい差分から順に乗せる」を推奨します。大きい差分を先に乗せると、その上の小さい差分が回転した座標系で効くことになり、意図とずれやすくなります。

## 40.7　テストを書く

`AnimLib.Tests/AdditiveBlendTests.cpp`：

```cpp
#include "CppUnitTest.h"

#include "TestSupport/MathAssert.h"
#include "TestSupport/TestRandom.h"
#include "TestSupport/Tolerance.h"

#include "anim/AdditiveBlend.h"

#include <numbers>

using namespace Microsoft::VisualStudio::CppUnitTestFramework;
using namespace anim;

namespace {

constexpr float kPi = std::numbers::pi_v<float>;

Pose RandomPose(std::size_t boneCount, anim::test::TestRandom& rng) {
    Pose p(boneCount);
    for (std::size_t i = 0; i < boneCount; ++i) {
        p[static_cast<BoneIndex>(i)] = {rng.NextVec3(2.0f), rng.NextQuat(), {1, 1, 1}};
    }
    return p;
}

}  // namespace

namespace AnimLibTests {

TEST_CLASS(AdditiveBlendTests) {
public:

    // --- 往復（この章の中心）--------------------------------------

    // 重み 1 で適用すれば、元のポーズが復元される
    TEST_METHOD(WeightOneReproducesTheSource) {
        anim::test::TestRandom rng;
        const Pose base = RandomPose(6, rng);
        const Pose source = RandomPose(6, rng);
        Pose additive(6);
        Pose result(6);

        MakeAdditive(source, base, additive);
        ApplyAdditive(base, additive, 1.0f, result);

        for (BoneIndex i = 0; i < 6; ++i) {
            anim::test::AssertNear(source[i].translation, result[i].translation,
                                   test::kEpsAccum);
            anim::test::AssertSameRotation(source[i].rotation, result[i].rotation,
                                           test::kEpsAccum);
        }
    }

    TEST_METHOD(WeightZeroLeavesTheBaseUnchanged) {
        anim::test::TestRandom rng;
        const Pose base = RandomPose(6, rng);
        const Pose source = RandomPose(6, rng);
        Pose additive(6);
        Pose result(6);

        MakeAdditive(source, base, additive);
        ApplyAdditive(base, additive, 0.0f, result);

        for (BoneIndex i = 0; i < 6; ++i) {
            anim::test::AssertNear(base[i].translation, result[i].translation,
                                   test::kEpsPos);
            anim::test::AssertSameRotation(base[i].rotation, result[i].rotation,
                                           test::kEpsDir);
        }
    }

    TEST_METHOD(ZeroDifferenceIsIdentity) {
        anim::test::TestRandom rng;
        const Pose base = RandomPose(6, rng);
        Pose additive(6);
        Pose result(6);

        MakeAdditive(base, base, additive);   // 自分自身との差分 = ゼロ

        // 差分ポーズは単位変換になっているはず
        for (BoneIndex i = 0; i < 6; ++i) {
            anim::test::AssertNear(Vec3{0, 0, 0}, additive[i].translation, test::kEpsPos);
            anim::test::AssertSameRotation(QuatIdentity(), additive[i].rotation,
                                           test::kEpsDir);
        }
        // どんな重みで乗せても base のまま
        for (float w : {0.0f, 0.5f, 1.0f}) {
            ApplyAdditive(base, additive, w, result);
            for (BoneIndex i = 0; i < 6; ++i) {
                anim::test::AssertNear(base[i].translation, result[i].translation,
                                       test::kEpsPos);
            }
        }
    }

    // --- 別の基準に乗せられること（加算ブレンドの存在理由）--------

    TEST_METHOD(AdditiveAppliesToADifferentBase) {
        anim::test::TestRandom rng;
        const Pose base = RandomPose(6, rng);
        const Pose source = RandomPose(6, rng);
        const Pose otherBase = RandomPose(6, rng);

        Pose additive(6);
        Pose result(6);
        MakeAdditive(source, base, additive);
        ApplyAdditive(otherBase, additive, 1.0f, result);

        for (BoneIndex i = 0; i < 6; ++i) {
            // 平行移動：差分がそのまま足される
            anim::test::AssertNear(otherBase[i].translation + additive[i].translation,
                                   result[i].translation, test::kEpsAccum);
            // 回転：差分が外側から掛かる
            anim::test::AssertSameRotation(additive[i].rotation * otherBase[i].rotation,
                                           result[i].rotation, test::kEpsAccum);
        }
    }

    // --- 重みの部分適用（40.4 節）--------------------------------

    TEST_METHOD(HalfWeightGivesHalfTheRotation) {
        Pose base(1);

        Pose source(1);
        source[0] = {{0, 0, 0}, MakeQuatAxisAngle({0, 0, 1}, kPi * 0.5f), {1, 1, 1}};

        Pose result(1);
        MakeAdditive(source, base, additive);
        ApplyAdditive(base, additive, 0.5f, result);

    TEST_METHOD(TranslationScalesLinearly) {

        Pose additive(1);
        Pose result(1);
        MakeAdditive(source, base, additive);
        for (float w : {0.0f, 0.25f, 0.5f, 1.0f}) {
            ApplyAdditive(base, additive, w, result);
            anim::test::AssertNear(w, result[0].translation.y, test::kEpsPos);

    TEST_METHOD(ApplyingInPlaceIsSafe) {

    TEST_METHOD(MultipleAdditivesStack) {
        Pose base(1);
        base[0] = TransformIdentity();

        Pose a(1);
        a[0] = {{0, 0.1f, 0}, QuatIdentity(), {1, 1, 1}};

        b[0] = {{0, 0.2f, 0}, QuatIdentity(), {1, 1, 1}};

        Pose result = base;

    TEST_METHOD(OrderOfSmallAdditivesBarelyMatters) {

        Pose ab = base;

        ApplyAdditive(ab, b, 1.0f, ab);

        Pose ba = base;
        ApplyAdditive(ba, b, 1.0f, ba);
        ApplyAdditive(ba, a, 1.0f, ba);

        const float diff = 2.0f * std::acos(std::fmin(1.0f,

        Logger::WriteMessage(std::format(
            L"two 3-degree additives, order difference = {:.4f} deg\n", diff).c_str());
        Assert::IsTrue(diff < 0.2f);
    }

    // 大きい回転差分では、順序が効くこと（仕様の記録）
    TEST_METHOD(OrderOfLargeAdditivesMatters) {
        Pose base(1);
        base[0] = TransformIdentity();

        Pose a(1);
        a[0] = {{0, 0, 0}, MakeQuatAxisAngle({1, 0, 0}, kPi * 0.5f), {1, 1, 1}};
        Pose b(1);
        b[0] = {{0, 0, 0}, MakeQuatAxisAngle({0, 1, 0}, kPi * 0.5f), {1, 1, 1}};

        Pose ab = base;
        ApplyAdditive(ab, a, 1.0f, ab);
        ApplyAdditive(ab, b, 1.0f, ab);

        Pose ba = base;
        ApplyAdditive(ba, b, 1.0f, ba);
        ApplyAdditive(ba, a, 1.0f, ba);

        Assert::IsTrue(std::fabs(Dot(ab[0].rotation, ba[0].rotation)) < 0.99f);
    }
```

`AdditiveAppliesToADifferentBase` が、**加算ブレンドの存在理由をそのままテストにしたもの**です。「呼吸クリップから作った差分を、走りのポーズに乗せられる」という性質を検査しています。

`OrderOfSmallAdditivesBarelyMatters` と `OrderOfLargeAdditivesMatters` は、第 38 章と同じ**対のテスト**です。「順序依存はある、しかし実用的な入力では無害」という判断を、両側から記録します。

## 40.8　つまずきやすいところ

**重み 1 で元のポーズに戻らない**
回転の合成順序です。差分は `s * conj(b)`、適用は `d * b`。どちらかを逆にすると往復しません。

**差分を別のポーズに乗せると、変な向きになる**
同上。あるいは差分を `conj(b) * s` として作っています。この形は「基準の座標系での差分」を意味し、適用も `b * d` にする必要があります。**どちらの規約でも動きますが、混ぜてはいけません。**

**呼吸が全身に効いてしまう**
差分クリップに、意図しないボーンの差分が入っています。基準ポーズと加算クリップで、動いていないボーンの値が完全に一致していますか。わずかでも違うと差分が残ります。**ボーンマスク（第 41 章）と組み合わせる**のが実務的な解決です。

**被弾リアクションが弱すぎる／強すぎる**
基準ポーズの選択を確認してください。レストポーズを基準にすると差分が巨大になります（40.5 節）。

**重みを 1 より大きくしたら壊れた**
外挿になります。演出としては使えますが、想定外の姿勢になりやすい。

**加算を重ねる順序で見た目が変わる**
仕様です（40.6 節）。順序を決めて固定してください。

## この章のまとめ

- 加算ブレンドは「置き換え」ではなく「**乗せる**」。呼吸・被弾・エイムオフセットのように、**どんなアニメーションの上にも重ねたいもの**に使う。
- これがないと**クリップの組み合わせ爆発**が起きる。「走りながら呼吸」「しゃがみながら呼吸」…… を全部作ることになる。
- 差分の定義は成分ごとに違う ―― 平行移動は**引き算**、回転は **`s * conj(b)`**、スケールは**割り算**。
- 適用は **`d * b`**（差分を左から）。作り方と適用の順序は**対**になっていなければならない。
- 回転の部分適用は **`Nlerp(identity, d, weight)`**。クォータニオンに重みを掛けても半分の回転にはならない。
- 基準ポーズは**加算クリップの最初のフレーム**が既定。レストポーズを基準にすると差分が巨大になる。
- 差分クリップは**ロード時に作る**。キーの時刻はそのまま、値だけを差分にする。
- **重ねられるが、順序は結果に影響する。** 小さい差分（3 度）なら 0.2 度未満、大きい差分（90 度）なら明確に変わる。**小さいものから順に乗せる**。

次章、乗せる範囲を体の一部に限定します。
