# 第 39 章　クロスフェード

**この章で作るもの**：アニメーションを滑らかに切り替える `CrossFade`。2 つのクリップを同時に再生し、重みを時間で動かします。「遷移中にまた遷移が起きる」場合の扱いが、この章の難所です。

---

## 39.1　切り替えの問題

待機から歩きへ切り替えるとき、素朴にクリップを差し替えると何が起きるか。

```cpp
player.SetClip(&walkClip);   // 待機 → 歩き
```

**1 フレームで姿勢が飛びます。** 待機の腕の位置と、歩きの最初のフレームの腕の位置は違うので、その差がそのまま瞬間移動になります。

必要なのは、**一定時間かけて重みを 0 から 1 へ動かすこと**です。これが**クロスフェード**です。

```
重み
 1 ┤              ┌─────────  歩き
   │            ╱
   │          ╱
 0 ┼────────╱──────────────  待機
   └──────┬──────┬─────────  時刻
        開始   完了（0.2 秒後）
```

---

## 39.2　実装

2 つのプレイヤーを持ち、両方を毎フレーム進めます。

```cpp
// AnimLib/include/anim/CrossFade.h
#pragma once

#include "anim/ClipPlayer.h"
#include "anim/PoseBlend.h"

namespace anim {

// 2 つのクリップをクロスフェードしながら再生する。
class CrossFadePlayer {
public:
    void Initialize(std::size_t boneCount) {
        scratch_.Resize(boneCount);
        currentContext_.Reset(boneCount);
        nextContext_.Reset(boneCount);
    }

    void Play(const Clip* clip) {
        current_.SetClip(clip);
        fading_ = false;
        currentContext_.Invalidate();     // 第 25 章：シークではヒントを捨てる
    }

    // duration 秒かけて clip へ遷移する。
    void CrossFade(const Clip* clip, float duration, float startTime = 0.0f);

    void Update(float deltaSeconds);
    void Evaluate(Pose& out);

    [[nodiscard]] bool IsFading() const noexcept { return fading_; }
    [[nodiscard]] float FadeWeight() const noexcept {
        return fading_ ? (elapsed_ / duration_) : 0.0f;
    }
    [[nodiscard]] const Clip* CurrentClip() const noexcept { return current_.GetClip(); }
    [[nodiscard]] const Clip* TargetClip() const noexcept {
        return fading_ ? next_.GetClip() : current_.GetClip();
    }

private:
    ClipPlayer current_;
    ClipPlayer next_;
    SampleContext currentContext_;
    SampleContext nextContext_;
    Pose scratch_;

    bool fading_ = false;
    float duration_ = 0.0f;
    float elapsed_ = 0.0f;
};

}  // namespace anim
```

```cpp
void CrossFadePlayer::CrossFade(const Clip* clip, float duration, float startTime) {
    if (clip == nullptr) { return; }

    // フェード時間が 0 なら即座に切り替える
    if (duration <= 0.0f) {
        current_.SetClip(clip);
        current_.SetTime(startTime);
        currentContext_.Invalidate();
        fading_ = false;
        return;
    }

    // 既にフェード中なら、進行中のフェードを畳んでから新しいフェードを始める（39.4 節）
    if (fading_) {
        FoldCurrentFade();
    }

    next_.SetClip(clip);
    next_.SetTime(startTime);
    nextContext_.Invalidate();
    duration_ = duration;
    elapsed_ = 0.0f;
    fading_ = true;
}

void CrossFadePlayer::Update(float deltaSeconds) {
    current_.Update(deltaSeconds);
    if (!fading_) { return; }

    next_.Update(deltaSeconds);
    elapsed_ += deltaSeconds;

    if (elapsed_ >= duration_) {
        // フェード完了。next を current に昇格させる
        current_ = next_;
        std::swap(currentContext_, nextContext_);
        fading_ = false;
    }
}

void CrossFadePlayer::Evaluate(Pose& out) {
    current_.Evaluate(currentContext_, out);
    if (!fading_) { return; }

    next_.Evaluate(nextContext_, scratch_);
    // 遷移は角度差が大きくなりうるので Slerp（第 10・38 章）
    BlendPose(out, scratch_, FadeWeight(), out, RotationBlend::Slerp);
}
```

**両方のプレイヤーを進める**のが要点です。歩きへフェードしている最中も、待機は再生され続けます。片方を止めると、フェードの途中で待機の姿勢が固まり、不自然な動きになります。

`Play` と `CrossFade` で `Invalidate()` を呼んでいるのは、第 25 章で決めた「シークではヒントを捨てる」の適用です。新しいクリップの時刻は前フレームと無関係なので、ヒントは必ず外れます。

## 39.3　開始時刻をどう決めるか

`CrossFade(clip, duration, startTime)` の `startTime` に何を渡すか。3 通りの選択があります。

**① 先頭から（`startTime = 0`）。** 攻撃モーションや被弾など、**一回性のアニメーション**ではこれが正しい。

**② 現在の時刻を引き継ぐ。** 歩きから走りへの遷移では、**足の位相を合わせたい**。左足が前にある状態から遷移するなら、走りも左足が前の状態から始めるべきです。

```cpp
// 位相を保って遷移する
const float phase = current.Time() / currentClip->Duration();
crossFade.CrossFade(runClip, 0.2f, phase * runClip->Duration());
```

**位相（0〜1 の正規化された進行度）で引き継ぐ**のがポイントです。歩きが 1.2 秒、走りが 0.8 秒なら、時刻をそのまま渡しても意味がありません。

**③ 指定の時刻から。** 特定のフレームから始めたい場合。

**位相の引き継ぎは、足滑りを防ぐうえで非常に効きます。** これをしないと、走りへの遷移のたびに足の位相がリセットされ、地面を滑ります。第 42 章のブレンドスペースでは、この同期がさらに重要になります。

## 39.4　遷移中の遷移

いちばん厄介なのがこれです。**歩きから走りへフェード中に、待機へ切り替えたくなった**らどうするか。

考えられる方針は 3 つあります。

**方針 A：新しい遷移を無視する。** 単純ですが、操作への反応が悪くなります。ボタンを押しても効かない、という体験になります。

**方針 B：プレイヤーを 3 本以上持つ。** 正確ですが、遷移が重なるたびに増えます。N 本の同時再生とブレンドが必要になり、コストが読めません。

**方針 C：進行中のフェードを「畳んで」から、新しいフェードを始める。** 現在の混合結果を 1 つのポーズとして固定し、それを起点に新しいフェードを行います。

**本書は C を採用します。** プレイヤーは常に 2 本で済み、反応も良い。

問題は、「現在の混合結果」は**クリップではなくポーズ**だということです。畳んだ後、それを再生し続けることはできません。

```cpp
// 進行中のフェードを畳む。
// 混合結果をスナップショットとして保持し、それを起点に次のフェードを行う。
void CrossFadePlayer::FoldCurrentFade() {
    // 現在の混合結果をスナップショットへ
    Evaluate(snapshot_);
    usingSnapshot_ = true;
    // current は「スナップショットを返すだけの状態」になる
}

void CrossFadePlayer::Evaluate(Pose& out) {
    if (usingSnapshot_) {
        CopyPose(snapshot_, out);            // 静止した姿勢
    } else {
        current_.Evaluate(currentContext_, out);
    }
    if (!fading_) { return; }
    next_.Evaluate(nextContext_, scratch_);
    BlendPose(out, scratch_, FadeWeight(), out, RotationBlend::Slerp);
}
```

**畳んだ姿勢は静止します。** 遷移元のアニメーションが止まって見えるわけですが、遷移時間は通常 0.1〜0.3 秒なので、実用上は気づかれません。

**この妥協は、意識的に選んでいます。** 完全に正しくやるなら方針 B ですが、そのコストは「遷移が重なることが稀である」という現実に見合いません。**「稀なケースでは品質を落とし、代わりにコストを一定に保つ」**という判断です。

第 45 章のステートマシンでは、また別の扱いをします（そちらは遷移先を差し替える形で対応します）。

## 39.5　フェードカーブ

線形にフェードするのが既定ですが、カーブを変えたくなることがあります。

```cpp
[[nodiscard]] float FadeWeight() const noexcept {
    if (!fading_) { return 0.0f; }
    const float t = elapsed_ / duration_;
    switch (curve_) {
    case FadeCurve::Linear:     return t;
    case FadeCurve::SmoothStep: return t * t * (3.0f - 2.0f * t);
    case FadeCurve::EaseIn:     return t * t;
    case FadeCurve::EaseOut:    return t * (2.0f - t);
    }
    return t;
}
```

`SmoothStep`（`3t² − 2t³`）は第 24 章で出てきた曲線です。両端で微分が 0 になるので、**フェードの開始と終了で速度が連続**します。

線形フェードだと、フェード開始の瞬間に「姿勢の変化速度」が不連続になります。0.2 秒のフェードでは気づきにくいですが、1 秒を超える長いフェード（カメラワークなど）では見えます。

**既定は線形のまま**にします。ほとんどの遷移は 0.2 秒程度で、差が見えないからです。

## 39.6　テストを書く

`AnimLib.Tests/CrossFadeTests.cpp`：

```cpp
#include "CppUnitTest.h"

#include "TestSupport/MathAssert.h"
#include "TestSupport/Tolerance.h"

#include "anim/CrossFade.h"

#include <format>
#include <numbers>

using namespace Microsoft::VisualStudio::CppUnitTestFramework;
using namespace anim;

namespace {

constexpr float kPi = std::numbers::pi_v<float>;
constexpr std::size_t kBones = 6;

// 0 → endPos / endAngle へ 1 秒で動くクリップ
Clip MakeClip(float duration, Vec3 endPosition, float endAngle) {
    Clip c;
    c.Resize(kBones);
    c.SetDuration(duration);
    c.SetLoopMode(LoopMode::Loop);

    c.Bone(0).translation.AddKey(0.0f, {0, 0, 0});
    c.Bone(0).translation.AddKey(duration, endPosition);
    c.Bone(0).translation.Finalize();

    for (std::size_t b = 1; b < kBones; ++b) {
        const BoneIndex bone = static_cast<BoneIndex>(b);
        c.Bone(bone).rotation.AddKey(0.0f, QuatIdentity());
        c.Bone(bone).rotation.AddKey(duration, MakeQuatAxisAngle({0, 0, 1}, endAngle));
        c.Bone(bone).rotation.Finalize();
    }
    return c;
}

}  // namespace

namespace AnimLibTests {

TEST_CLASS(CrossFadeTests) {
public:

    // --- 端点 -----------------------------------------------------

    TEST_METHOD(FadeStartsAtTheSourcePose) {
        const Clip idle = MakeClip(1.0f, {0, 0, 0}, 0.0f);
        const Clip walk = MakeClip(1.0f, {0, 0, 1.5f}, 0.4f);

        CrossFadePlayer player;
        player.Initialize(kBones);
        player.Play(&idle);
        player.Update(0.3f);

        Pose before(kBones);
        player.Evaluate(before);

        player.CrossFade(&walk, 0.2f);
        Pose after(kBones);
        player.Evaluate(after);   // Update を挟まないので重み 0

        for (BoneIndex i = 0; i < kBones; ++i) {
            anim::test::AssertNear(before[i].translation, after[i].translation,
                                   test::kEpsPos);
        }
    }

    TEST_METHOD(FadeCompletesExactlyOnTheTarget) {
        const Clip idle = MakeClip(1.0f, {0, 0, 0}, 0.0f);
        const Clip walk = MakeClip(1.0f, {0, 0, 1.5f}, 0.4f);

        CrossFadePlayer player;
        player.Initialize(kBones);
        player.Play(&idle);
        player.CrossFade(&walk, 0.2f);

        for (int i = 0; i < 20; ++i) { player.Update(1.0f / 60.0f); }
        Assert::IsFalse(player.IsFading());
        Assert::IsTrue(player.CurrentClip() == &walk);

        // 以後は walk だけを再生する
        Pose fromPlayer(kBones);
        Pose fromClip(kBones);
        player.Evaluate(fromPlayer);
        walk.Sample(player.CurrentClip() == &walk ? 20.0f / 60.0f : 0.0f, fromClip);
        // 時刻が一致していれば同じ姿勢になる
        for (BoneIndex i = 1; i < kBones; ++i) {
            anim::test::AssertSameRotation(fromClip[i].rotation, fromPlayer[i].rotation,
                                           test::kEpsAccum);
        }
    }

    // --- 連続性（この章の中心）------------------------------------

    TEST_METHOD(PoseIsContinuousThroughTheFade) {
        const Clip walk = MakeClip(1.0f, {0, 0, 1.5f}, 0.4f);
        const Clip run  = MakeClip(1.0f, {0, 0, 4.0f}, 0.9f);

        CrossFadePlayer player;
        player.Initialize(kBones);
        player.Play(&walk);
        for (int i = 0; i < 15; ++i) { player.Update(1.0f / 60.0f); }

        Pose previous(kBones);
        player.Evaluate(previous);

        player.CrossFade(&run, 0.3f);

        float worstJump = 0.0f;
        Pose current(kBones);
        for (int i = 0; i < 40; ++i) {
            player.Update(1.0f / 60.0f);
            player.Evaluate(current);
            for (BoneIndex b = 0; b < kBones; ++b) {
                worstJump = std::fmax(worstJump,
                    Length(current[b].translation - previous[b].translation));
            }
            for (BoneIndex b = 0; b < kBones; ++b) { previous[b] = current[b]; }
        }
        Logger::WriteMessage(std::format(
            L"max per-frame jump through the fade = {:.6f}\n", worstJump).c_str());
        Assert::IsTrue(worstJump < 0.15f);
    }

    // フェード完了の瞬間に飛ばないこと
    TEST_METHOD(NoJumpWhenTheFadeCompletes) {
        const Clip a = MakeClip(1.0f, {0, 0, 1.0f}, 0.3f);
        const Clip b = MakeClip(1.0f, {0, 0, -1.0f}, -0.3f);

        CrossFadePlayer player;
        player.Initialize(kBones);
        player.Play(&a);

    TEST_METHOD(ZeroDurationSwitchesImmediately) {

        const Clip b = MakeClip(1.0f, {0, 0, -1.0f}, -0.3f);

        CrossFadePlayer player;
        player.Initialize(kBones);
        player.Play(&a);
        player.CrossFade(&b, 0.0f);

        Assert::IsTrue(player.CurrentClip() == &b);

    // --- 位相の引き継ぎ（39.3 節）--------------------------------

    TEST_METHOD(PhaseCanBeCarriedOver) {
        const Clip walk = MakeClip(1.2f, {0, 0, 1.5f}, 0.4f);   // 1.2 秒

    TEST_METHOD(FadingDuringAFadeDoesNotJump) {
        const Clip a = MakeClip(1.0f, {0, 0, 1.0f}, 0.3f);
        const Clip b = MakeClip(1.0f, {0, 0, -1.0f}, -0.3f);
        const Clip c = MakeClip(1.0f, {0, 0, 2.5f}, 0.8f);

        CrossFadePlayer player;
        player.Initialize(kBones);

        for (int i = 0; i < 12; ++i) { player.Update(1.0f / 60.0f); }   // 半分ほど進める

        Pose before(kBones);
        player.Evaluate(before);

        player.CrossFade(&c, 0.3f);        // 途中で別の遷移
        Pose after(kBones);
        player.Evaluate(after);

        // 畳んだ直後は、姿勢が変わらないこと
        for (BoneIndex i = 0; i < kBones; ++i) {
            anim::test::AssertNear(before[i].translation, after[i].translation,

            anim::test::AssertSameRotation(before[i].rotation, after[i].rotation,
                                           test::kEpsDir);
        }
    }

    TEST_METHOD(RepeatedInterruptionsStillConverge) {
        const Clip a = MakeClip(1.0f, {0, 0, 1.0f}, 0.3f);
        const Clip b = MakeClip(1.0f, {0, 0, -1.0f}, -0.3f);

        CrossFadePlayer player;
        player.Initialize(kBones);
        player.Play(&a);

        // 毎フレーム遷移を要求し続ける
        for (int i = 0; i < 60; ++i) {
            player.CrossFade((i % 2 == 0) ? &b : &a, 0.2f);
            player.Update(1.0f / 60.0f);
        }
        // 最後の遷移だけ完了させる
        player.CrossFade(&b, 0.1f);
        for (int i = 0; i < 10; ++i) { player.Update(1.0f / 60.0f); }

        Assert::IsFalse(player.IsFading());
        Assert::IsTrue(player.CurrentClip() == &b);
    }

    // --- フェードカーブ -------------------------------------------

    TEST_METHOD(SmoothStepCurveHasZeroSlopeAtEnds) {
        CrossFadePlayer player;
        player.Initialize(kBones);
        player.SetFadeCurve(FadeCurve::SmoothStep);

        const Clip a = MakeClip(1.0f, {0, 0, 0}, 0.0f);
        const Clip b = MakeClip(1.0f, {0, 0, 1.0f}, 0.5f);
        player.Play(&a);
        player.CrossFade(&b, 1.0f);

        // 開始直後と終了直前で、重みの変化が小さいこと
        player.Update(0.01f);
        const float early = player.FadeWeight();
        Assert::IsTrue(early < 0.01f);      // 線形なら 0.01
    }
};
```

`FadingDuringAFadeDoesNotJump` が、39.4 節の設計を守る番人です。**畳んだ瞬間に姿勢が変わらない**ことを検査しています。畳み方を間違える（たとえば `current_` のクリップだけを残す）と、ここで飛びます。

`RepeatedInterruptionsStillConverge` は、**毎フレーム遷移を要求し続ける**という意地の悪い入力です。プレイヤーの状態が壊れないこと、最終的に収束することを確認します。実際のゲームでは、スティックを細かく動かされたときにこの状況になります。

## 39.7　つまずきやすいところ

**遷移の瞬間に姿勢が飛ぶ**
フェードの重みが 0 から始まっていません。`CrossFade` を呼んだ直後に `Evaluate` すると、`elapsed_ = 0` なので重み 0 のはずです。

**遷移元のアニメーションが止まる**
`Update` で `current_` だけを進めています。フェード中は**両方**進めてください。

**遷移のたびに足の位相がリセットされる**
`startTime = 0` で遷移しています。位相を引き継いでください（39.3 節）。

**遷移が重なると姿勢が飛ぶ**
畳み処理が正しくありません（39.4 節）。畳んだ直後に姿勢が変わらないことをテストしてください。

**遷移中に腕が変な軌跡を描く**
`Nlerp` を使っています。遷移は角度差が大きくなりうるので `Slerp` を指定してください（38.3 節）。

**フェード完了後に 1 フレームだけおかしい**
`current_ = next_` の代入で、`SampleContext` も一緒に移動していますか。ヒントがずれていると値は正しいまま遅くなるだけですが、`Pose` のサイズが違うと落ちます。

**長いフェードで開始・終了が不自然**
線形フェードの速度不連続です。`SmoothStep` を試してください（39.5 節）。

## この章のまとめ

- クリップを差し替えるだけでは**1 フレームで姿勢が飛ぶ**。一定時間かけて重みを動かすのがクロスフェード。
- **両方のプレイヤーを進める。** 片方を止めると遷移元の姿勢が固まる。
- 遷移は角度差が大きくなりうるので、**`Slerp` を使う**（第 10・38 章の判断）。
- 開始時刻は 3 通り。**位相（正規化された進行度）で引き継ぐ**と足滑りを防げる。クリップの長さが違っても正しく対応する。
- **遷移中の遷移**は 3 つの方針がある。本書は「進行中のフェードを畳む」を選び、**プレイヤーを常に 2 本に保つ**。畳んだ姿勢は静止するが、0.2 秒程度なら気づかれない。
- **「稀なケースでは品質を落とし、代わりにコストを一定に保つ」**という判断を、意識的に行う。
- 畳んだ瞬間に姿勢が変わらないことを、テストで守る。
- フェードカーブは既定で線形。長いフェードでは `SmoothStep` が有効。

次章は加算ブレンド ―― 「ポーズそのもの」ではなく「ポーズの差分」を混ぜる手法です。
