# 第 49 章　FABRIK

**この章で作るもの**：**FABRIK**（Forward And Backward Reaching Inverse Kinematics）― 回転を一切考えず、**関節の「位置」だけを動かして**解く反復ソルバ。CCD と実測で比べます。

---

## 49.1　回転を忘れる

CCD は「関節をどう回すか」を考え続けるアルゴリズムでした。FABRIK は逆の発想をします。

> **回転のことは一旦忘れる。関節を「点」、ボーンを「長さの決まった棒」だと思う。**
> **点を動かして棒の形を作り、最後にまとめて回転へ翻訳する。**

紙の上に、長さの決まった鎖を描くところを想像してください。鎖の端を目標の位置に持っていきたい。あなたはたぶんこうします。

1. まず**端を目標に置いてしまう**。すると隣の関節との距離が狂うので、隣の関節を「新しい端から正しい距離のところ」へ引き寄せる。それを根元まで繰り返す。
2. すると今度は**根元が動いてしまっている**。根元を元の位置に戻し、今度は根元から末端へ向かって、同じように距離を直していく。
3. 1 と 2 を繰り返す。

これだけです。「後退パス（backward）」と「前進パス（forward）」を交互に行うので FABRIK。

```
初期状態:      ●──●──●──●          T（目標）

後退パス:      末端を T に置き、根元へ向かって距離を直す
               ●   ●──●──●
                    ↑ 根元がずれた

前進パス:      根元を戻し、末端へ向かって距離を直す
               ●──●──●──●
                          ↑ 末端が T から少しずれる

→ 繰り返すと両方が満たされる点へ収束する
```

**ボーンの長さが厳密に保たれる**のがポイントです。各ステップで「長さ `L` のところに置く」と明示的に決めているので、誤差が蓄積しません。

---

## 49.2　位置を直すステップ

1 ステップは 1 行で書けます。点 `p[i]` を、点 `p[i+1]` から距離 `L[i]` のところへ、方向を保ったまま移す。

```
p[i] ← p[i+1] + normalize(p[i] − p[i+1]) · L[i]
```

`normalize(p[i] − p[i+1])` が「`p[i+1]` から見た `p[i]` の方向」。そこへ `L[i]` だけ進めば、方向は変えずに距離だけ正します。

前進パスは添字を反転するだけ。

```
p[i] ← p[i−1] + normalize(p[i] − p[i−1]) · L[i−1]
```

---

## 49.3　届かない場合を先に片付ける

FABRIK には気持ちのいい性質があります。**目標が届かない場合は、反復せずに答えが出る。**

根元から目標までの距離が、チェーンの全長を超えているなら、答えは「その方向へまっすぐ伸ばす」以外にありません。

```cpp
if (Length(target - rootPos) > total) {
    const Vec3 dir = NormalizeSafe(target - rootPos, {1,0,0});
    for (std::size_t i = 1; i < n; ++i) p[i] = p[i-1] + dir * lengths[i-1];
}
```

反復ループに入る前にこれを判定します。CCD だと `maxIterations` を全部回してしまうケースが、1 パスで終わります。

## 49.4　実装

```cpp
// AnimLib/include/anim/Ik.h（追記）

inline IkSolveResult SolveFabrik(const Skeleton& s, Pose& local,
                                 std::vector<Transform>& global,
                                 const IkChain& chain, Vec3 target,
                                 int maxIterations = 16, float tolerance = 1.0e-3f) {
    IkSolveResult r{};
    const std::size_t n = chain.Size();
    if (n < 2) return r;

    // --- 現在の関節位置と、各ボーンの長さを取り出す ---
    ComputeGlobalPose(s, local.Locals(), global);
    std::vector<Vec3> p(n);
    for (std::size_t i = 0; i < n; ++i) p[i] = global[chain.bones[i]].translation;
    const Vec3 rootPos = p[0];

    std::vector<float> lengths(n - 1);
    float total = 0.0f;
    for (std::size_t i = 0; i + 1 < n; ++i) {
        lengths[i] = Length(p[i+1] - p[i]);
        total += lengths[i];
    }

    if (Length(target - rootPos) > total) {
        // 届かない：まっすぐ伸ばす
        const Vec3 dir = NormalizeSafe(target - rootPos, {1,0,0});
        for (std::size_t i = 1; i < n; ++i) p[i] = p[i-1] + dir * lengths[i-1];
        r.iterations = 1;
    } else {
        for (int iter = 0; iter < maxIterations; ++iter) {
            r.iterations = iter + 1;

            // 後退パス：末端を目標に置いて根元へ
            p[n-1] = target;
            for (std::size_t i = n-1; i-- > 0; )
                p[i] = p[i+1] + NormalizeSafe(p[i]-p[i+1], {1,0,0}) * lengths[i];

            // 前進パス：根元を戻して末端へ
            p[0] = rootPos;
            for (std::size_t i = 1; i < n; ++i)
                p[i] = p[i-1] + NormalizeSafe(p[i]-p[i-1], {1,0,0}) * lengths[i-1];

            if (Length(p[n-1] - target) < tolerance) { r.converged = true; break; }
        }
    }

    // --- 位置から回転へ変換する ---
    for (std::size_t i = 0; i + 1 < n; ++i) {
        ComputeGlobalPose(s, local.Locals(), global);
        const BoneIndex joint = chain.bones[i];
        const Vec3 currentDir = global[chain.bones[i+1]].translation - global[joint].translation;
        const Vec3 desiredDir = p[i+1] - p[i];
        const Quat delta = FromToRotation(currentDir, desiredDir);
        SetGlobalRotation(s, local, global, joint, delta * global[joint].rotation);
    }

    ComputeGlobalPose(s, local.Locals(), global);
    r.residual = Length(target - global[chain.bones.back()].translation);
    r.converged = r.converged && (r.residual < tolerance * 10.0f);
    return r;
}
```

**`std::vector` を 2 つ作っている**のが目に付いたなら、正しい反応です。第 14 章から「毎フレーム 1 回もアロケートしない」と言ってきました。実装するときは、`p` と `lengths` を呼び出し側が持つ作業バッファ（第 44 章の `PoseBufferPool` と同じ発想）に移してください。書籍のコードでは読みやすさを優先しています。

**`lengths` は毎回測り直している**点も設計判断です。ボーンの長さはスケルトンから静的に求まる（レストポーズのローカル平行移動の長さ）ので、事前計算できます。ただし**スケールアニメーションがある場合**は毎回変わるので、測り直すほうが安全です。

**最後の `converged` の再判定**は重要です。位置空間で収束していても、回転へ変換する段階で誤差が入ります。`p[n-1]` が目標にぴったりでも、実際のエフェクタは少しずれる。だから**実際のボーン位置で測り直して**、そちらが許容範囲を大きく外れているなら `converged` を下ろします。**位置の計算と、実際のポーズが一致していることを、最後に必ず確認する。**

## 49.5　位置から回転へ ―― ここが一番危ない

FABRIK の解は点の列です。`Pose` に入れるには回転にしなければなりません。

やることは単純で、「関節 `i` の現在の子方向」を「求めた子方向」へ向ける ―― また `FromToRotation` です。

```cpp
const Vec3 currentDir = global[chain.bones[i+1]].translation - global[joint].translation;
const Vec3 desiredDir = p[i+1] - p[i];
SetGlobalRotation(s, local, global, joint, FromToRotation(currentDir, desiredDir) * global[joint].rotation);
```

ここには 2 つ、見落としやすい点があります。

**① 毎回 `global[]` を更新しなければならない。** 関節 `i` を回すと、その子孫すべてのグローバル位置が動きます。関節 `i+1` を処理するときの `currentDir` は、`i` を回したあとの値でなければなりません。だからループの中で `ComputeGlobalPose` を呼んでいます（第 48 章の `UpdateChainGlobals` に置き換えられます）。

**② ボーンの長さが一致しているから、方向だけ合わせれば位置も合う。** `|p[i+1] − p[i]| == lengths[i]` であり、現在のボーン長も `lengths[i]` です。だから方向を揃えれば、`i+1` は自動的に `p[i+1]` に来ます。**これは FABRIK が長さを厳密に保っているから成り立つ話**で、もし位置パスで長さが崩れていたら、この変換は破綻します。

**回転の「ねじれ」は決まらない。** ボーンの方向だけでは、そのボーン軸まわりの回転（ロール）が決まりません。`FromToRotation` は「最小の回転」を選ぶので、ロールは前フレームの値を引きずります。腕のように「手のひらの向き」が意味を持つチェーンでは、これだけでは足りません。実務では、ロールを別途決める処理（第 50 章の制限や、ツイストボーンの分配）が入ります。

## 49.6　単体テスト：収束

第 48 章と同じチェーン（ボーン 5 個、セグメント 4 本）、同じ目標 `(1, 2, 0)`。

```
反復ごとの残差
 1 回: 0.001519985
 2 回: 0.000010285
 3 回: 0.000000763
 4 回: 0.000000238
 5 回: 0.000000238   ← 床に着いた
```

**1 反復で `0.0015`、2 反復で `1.0e-5`。** CCD が同じ精度に達するのに 6 反復かかったところです。

```cpp
TEST_METHOD(ConvergesInFewIterations) {
    Skeleton s = MakeChain(5, 1.0f);
    Pose p = Pose::FromRest(s);
    std::vector<Transform> g(s.BoneCount());

    const auto r = SolveFabrik(s, p, g, IkChain{{0,1,2,3,4}}, {1,2,0}, 32, 1e-4f);

    Logger::WriteMessage(std::format("{} 反復、残差 {:.9f}\n", r.iterations, r.residual).c_str());
    Assert::IsTrue(r.iterations <= 3);        // 実測 2
    Assert::IsTrue(r.residual < 1e-3f);
}
```

## 49.7　単体テスト：ボーン長の保存

FABRIK の看板です。位置パスで明示的に長さを設定しているのだから、保たれて当たり前 ―― のはずですが、位置から回転への変換を経由するので、実測が要ります。

```cpp
TEST_METHOD(BoneLengthsArePreserved) {
    Skeleton s = MakeChain(5, 1.0f);
    Pose p = Pose::FromRest(s);
    std::vector<Transform> g(s.BoneCount());
    SolveFabrik(s, p, g, IkChain{{0,1,2,3,4}}, {1,2,1}, 32, 1e-4f);

    float worst = 0.0f;
    for (int i = 0; i < 4; ++i)
        worst = std::fmax(worst, std::fabs(Length(g[i+1].translation - g[i].translation) - 1.0f));
    Assert::IsTrue(worst < 1e-5f);
}
```

実測 **`0.000000358`**。CCD の `0.000001073` と同じオーダーです。

**同じ数字が出ることに意味があります。** どちらも `SetGlobalRotation` の正規化（第 48 章）で決まる床に着いていて、アルゴリズムの違いは効いていません。「FABRIK は長さを保つ」という宣伝文句は、**位置パスの話であって、最終的な `Pose` の精度は共通の土台で決まる**。

## 49.8　単体テスト：届かない目標

```cpp
TEST_METHOD(UnreachableTargetExtendsInOnePass) {
    Skeleton s = MakeChain(5, 1.0f);       // 全長 4

}
```

## 49.9　CCD と FABRIK ―― 反復回数

チェーンの長さを変えて、許容誤差 `1e-3` に達するまでの反復回数を測ります。目標はチェーン長に比例した位置に置きます。

| ボーン数 | CCD の反復数（残差） | FABRIK の反復数（残差） |
|---|---|---|
| 3 | 4（`0.0008644`） | **1**（`0.0006602`） |
| 5 | 4（`0.0004127`） | **2**（`0.0006400`） |
| 10 | 7（`0.0002543`） | **6**（`0.0008489`） |
| 20 | **13**（`0.0006206`） | 14（`0.0007323`） |

**短いチェーンでは FABRIK が明確に速い**（3 ボーンで 4 対 1）。**長くなると差が消え、20 ボーンでは逆転**しています。

理由は両者の情報の伝わり方です。CCD は 1 反復の中で全関節を順に処理するので、末端の情報が根元まで 1 反復で伝わります。FABRIK も後退・前進の 2 パスで全体をなめるので同じはず ―― ですが、FABRIK の各ステップは「距離を直す」だけで**角度の情報を持たない**ため、長いチェーンでは形が収束するのに時間がかかります。

**この表を「FABRIK のほうが優れている」と読んではいけません。** 読むべきなのは「**チェーンが短いうちは FABRIK、長くなると差はない**」であり、そして次の節が示すとおり、**反復回数はコストの一部でしかありません**。

## 49.10　CCD と FABRIK ―― 実時間

10 ボーンのチェーンで、反復回数を固定して 1 回の求解にかかる時間を測ります。

| 反復数 | CCD（チェーンのみ更新） | FABRIK |
|---|---|---|
| 1 | `2.416` µs | `3.075` µs |
| 2 | `4.547` µs | `3.320` µs |
| 4 | `8.829` µs | `4.069` µs |
| 8 | `17.596` µs | `5.303` µs |
| 16 | `34.589` µs | `7.792` µs |

直線に乗せると、

- **CCD**：固定コスト ≈ `0.3` µs、1 反復あたり **`2.14` µs**
- **FABRIK**：固定コスト ≈ **`2.76` µs**、1 反復あたり **`0.31` µs**

**FABRIK の 1 反復は CCD の 7 分の 1**。当然です。FABRIK の反復は `Vec3` の引き算・正規化・スカラー倍だけ ―― クォータニオンも `Combine` も出てきません。CCD は 1 関節ごとに `FromToRotation`、`SetGlobalRotation`、そしてチェーンの再計算をします。

代わりに FABRIK には **`2.76` µs の固定費**があります。位置から回転への変換パスです。これは反復回数に関係なく必ず払います。だから、

> **1 反復しかしないなら CCD のほうが速い。2 反復以上なら FABRIK。**

これが、この 2 つを実測で比べて出てくる実務的な結論です。

## 49.11　どちらを使うか

反復回数と時間の表から、選び方が見えてきます。

**2 ボーン（腕・脚）→ 第 47 章の解析解。** 反復ソルバを使う理由がありません。速く、決定的で、極ベクトルで曲がる向きを指定できます。

**3〜6 ボーン（背骨、指、短い尻尾）→ FABRIK。** 少ない反復で収束し、1 反復も安い。

**長いチェーン（触手、鎖、髪）→ どちらでも。** 反復回数は同程度なので、1 反復の安い FABRIK が有利。ただしこの領域は、そもそも IK より物理シミュレーションのほうが向いていることが多い。

**関節制限を厳しく入れたい → CCD。** これが実は最大の分かれ目です。CCD は 1 関節ずつ**回転を直接扱う**ので、「この関節の回転をこの範囲に収める」という制限をそのまま挟み込めます（第 50 章でやります）。FABRIK は位置を動かすので、制限を位置空間に翻訳する必要があり、実装が一段面倒になります。

**「エフェクタ以外を動かしたくない」→ CCD。** CCD は末端に近い関節から動かすので、根元が動きにくい。「手先だけちょっと直したい」用途には CCD の性格が合います。

## 49.12　FABRIK に関節制限を入れるには

第 50 章の前振りとして、方針だけ書いておきます。

FABRIK の位置パスの中で、`p[i]` を置く前に**「`p[i+1]` から見て、許される円錐の中に収まっているか」を確かめ、はみ出していれば円錐の縁へ引き戻す**、という形になります。第 50 章で作る `ClampDirectionToCone` がそのまま使えます。

```cpp
// 後退パスの中で
Vec3 dir = NormalizeSafe(p[i] - p[i+1], {1,0,0});
dir = ClampDirectionToCone(dir, allowedAxis[i], allowedAngle[i]);   // ← 追加
p[i] = p[i+1] + dir * lengths[i];
```

問題は `allowedAxis[i]` です。関節制限は「親のローカル座標系から見て」定義されるものなので、位置パスの途中で親の姿勢が確定していない FABRIK では、正しい基準軸を決めるのが難しい。近似としては「前フレームの親の姿勢を使う」「後退パスでは子側、前進パスでは親側を基準にする」といった手が使われます。

**CCD なら、この問題は起きません。** 各ステップで親のグローバル回転が確定しているからです。第 50 章で CCD 側に制限を入れるのは、そういう理由です。

## この章のまとめ

- FABRIK は**回転を忘れて位置だけを動かす**。「末端を目標に置いて根元へ距離を直す（後退）」「根元を戻して末端へ距離を直す（前進）」の繰り返し。
- **届かない目標は反復せず 1 パスで終わる**（実測 1 反復、残差 `16.000000`）。CCD は同じケースで 32 反復を空回りする。
- 位置から回転への変換で、**毎ステップ `global[]` を更新する**こと。そして**最後に実際のボーン位置で `converged` を測り直す** ―― 位置空間の収束は、ポーズの収束を意味しない。
- **ボーン軸まわりのねじれは決まらない。** 方向だけでは回転が一意にならない。
- 収束の実測：**1 反復で `0.0015`、2 反復で `1.0e-5`**。CCD が 6 反復かかるところ。
- ボーン長の誤差は **`3.58e-7`** ―― CCD の `1.07e-6` と同オーダー。**アルゴリズムの違いではなく、`SetGlobalRotation` の正規化で決まる共通の床**に着いている。
- 反復回数：3 ボーンで **4 対 1** と FABRIK 圧勝、20 ボーンでは **13 対 14** と逆転。
- 実時間（10 ボーン）：**FABRIK の 1 反復は CCD の 7 分の 1**（`0.31` µs 対 `2.14` µs）だが、**固定費 `2.76` µs**（位置→回転の変換）がある。**1 反復なら CCD、2 反復以上なら FABRIK。**
- **関節制限を入れるなら CCD。** 各ステップで親のグローバル回転が確定しているので、制限をそのまま挟める。FABRIK は基準軸が決まらない。

次章では、その関節制限を作ります。**膝が逆に曲がる**のを止め、頭が首を 180 度ひねらずに目標を見るようにします ―― そして、**制限を「差分」に掛けると壊れる**という、この本で何度目かの構造的なバグに出会います。
