# 第 7 章　逆行列

**この章で作るもの**：一般の 4×4 逆行列 `Invert`、剛体変換に特化した高速版 `InvertRigid`、そして行列式 `Determinant`。あわせて「失敗しうる演算」のインターフェイス設計を考えます。

---

## 7.1　なぜ逆行列が要るのか

本書で逆行列が必要になる場面は、実は限られています。しかしどれも中核です。

**① 逆バインド行列（第 15 章）。** スキニングの心臓部です。バインドポーズにおけるボーンのグローバル行列の逆行列を、モデルのロード時に一度だけ計算します。「頂点をボーンのローカル空間へ引き戻す」変換です。

**② ワールド空間からローカル空間への変換（第 51 章）。** フット IK で、レイキャストが返した地面の位置をキャラクターのローカル空間へ持ち込むときに使います。

**③ アニメーションの差分の抽出（第 40 章）。** 加算ブレンドで「基準ポーズからの差分」を作るとき、基準の逆を掛けます。

いずれも**毎フレーム大量に呼ぶ処理ではありません**。①はロード時、②③は数個〜数十個です。だから素朴な実装で構いません ―― と言いたいところですが、それでも 2 種類作ります。理由は速度ではなく、**精度と意図の表明**にあります。

---

## 7.2　行列式

逆行列の前に、行列式を作ります。逆行列の計算にそのまま使いますし、単独でも意味があります。

4×4 の行列式を余因子で展開すると項が 24 個になって手に負えません。**2×2 の小行列式を経由する**書き方を使います。上 2 行から作る 6 個と、下 2 行から作る 6 個です。

```cpp
namespace anim {

// 上 2 行 (0,1) と下 2 行 (2,3) から、列の組み合わせごとに 2x2 小行列式を作る。
// s[k] : 行 {0,1} × 列の組
// c[k] : 行 {2,3} × 列の組
struct Minors2x2 {
    float s[6];
    float c[6];
};

constexpr Minors2x2 ComputeMinors(const Mat4& a) {
    const auto& x = a.m;
    Minors2x2 r{};
    r.s[0] = x[0][0]*x[1][1] - x[0][1]*x[1][0];   // 列 {0,1}
    r.s[1] = x[0][0]*x[1][2] - x[0][2]*x[1][0];   // 列 {0,2}
    r.s[2] = x[0][0]*x[1][3] - x[0][3]*x[1][0];   // 列 {0,3}
    r.s[3] = x[0][1]*x[1][2] - x[0][2]*x[1][1];   // 列 {1,2}
    r.s[4] = x[0][1]*x[1][3] - x[0][3]*x[1][1];   // 列 {1,3}
    r.s[5] = x[0][2]*x[1][3] - x[0][3]*x[1][2];   // 列 {2,3}

    r.c[0] = x[2][0]*x[3][1] - x[2][1]*x[3][0];
    r.c[1] = x[2][0]*x[3][2] - x[2][2]*x[3][0];
    r.c[2] = x[2][0]*x[3][3] - x[2][3]*x[3][0];
    r.c[3] = x[2][1]*x[3][2] - x[2][2]*x[3][1];
    r.c[4] = x[2][1]*x[3][3] - x[2][3]*x[3][1];
    r.c[5] = x[2][2]*x[3][3] - x[2][3]*x[3][2];
    return r;
}

constexpr float Determinant(const Mat4& a) {
    const Minors2x2 k = ComputeMinors(a);
    return k.s[0]*k.c[5] - k.s[1]*k.c[4] + k.s[2]*k.c[3]
         + k.s[3]*k.c[2] - k.s[4]*k.c[1] + k.s[5]*k.c[0];
}

}  // namespace anim
```

符号の並び `+ - + + - +` が対称でなく見えますが、これは列の組を辞書順（01, 02, 03, 12, 13, 23）に並べたときの符号で、正しい配置です。

行列式には、覚えておくと役に立つ意味があります。**アフィン変換の行列式は、体積の倍率**です。

- スケール `(2, 3, 4)` の行列の行列式は `24`
- 回転行列の行列式は常に `1`（体積を変えない）
- 行列式が `0` なら、その変換は空間を潰している（逆変換が存在しない）
- 行列式が**負**なら、鏡映が含まれている（右手系が左手系に反転する）

最後の性質は実務で効きます。ネガティブスケール（`(-1, 1, 1)` など）が入ったモデルでは、三角形の表裏が反転し、法線の向きも狂います。行列式の符号を見れば検出できます。

## 7.3　一般の逆行列

行列式が計算できれば、あとは余因子行列（の転置＝随伴行列）を行列式で割るだけです。

```cpp
// 成功したら true を返し、out に逆行列を書く。
// 特異（またはそれに近い）行列なら false を返し、out は変更しない。
[[nodiscard]] inline bool Invert(const Mat4& a, Mat4& out) {
    const auto& x = a.m;
    const Minors2x2 k = ComputeMinors(a);
    const float* s = k.s;
    const float* c = k.c;

    const float det = s[0]*c[5] - s[1]*c[4] + s[2]*c[3]
                    + s[3]*c[2] - s[4]*c[1] + s[5]*c[0];
    if (std::fabs(det) < kSingularDeterminant) {
        return false;
    }
    const float r = 1.0f / det;

    out.m[0][0] = ( x[1][1]*c[5] - x[1][2]*c[4] + x[1][3]*c[3]) * r;
    out.m[0][1] = (-x[0][1]*c[5] + x[0][2]*c[4] - x[0][3]*c[3]) * r;
    out.m[0][2] = ( x[3][1]*s[5] - x[3][2]*s[4] + x[3][3]*s[3]) * r;
    out.m[0][3] = (-x[2][1]*s[5] + x[2][2]*s[4] - x[2][3]*s[3]) * r;

    out.m[1][0] = (-x[1][0]*c[5] + x[1][2]*c[2] - x[1][3]*c[1]) * r;
    out.m[1][1] = ( x[0][0]*c[5] - x[0][2]*c[2] + x[0][3]*c[1]) * r;
    out.m[1][2] = (-x[3][0]*s[5] + x[3][2]*s[2] - x[3][3]*s[1]) * r;
    out.m[1][3] = ( x[2][0]*s[5] - x[2][2]*s[2] + x[2][3]*s[1]) * r;

    out.m[2][0] = ( x[1][0]*c[4] - x[1][1]*c[2] + x[1][3]*c[0]) * r;
    out.m[2][1] = (-x[0][0]*c[4] + x[0][1]*c[2] - x[0][3]*c[0]) * r;
    out.m[2][2] = ( x[3][0]*s[4] - x[3][1]*s[2] + x[3][3]*s[0]) * r;
    out.m[2][3] = (-x[2][0]*s[4] + x[2][1]*s[2] - x[2][3]*s[0]) * r;

    out.m[3][0] = (-x[1][0]*c[3] + x[1][1]*c[1] - x[1][2]*c[0]) * r;
    out.m[3][1] = ( x[0][0]*c[3] - x[0][1]*c[1] + x[0][2]*c[0]) * r;
    out.m[3][2] = (-x[3][0]*s[3] + x[3][1]*s[1] - x[3][2]*s[0]) * r;
    out.m[3][3] = ( x[2][0]*s[3] - x[2][1]*s[1] + x[2][2]*s[0]) * r;
    return true;
}
```

```cpp
// これを下回ったら「逆行列は存在しない」と判断する。
// アニメーションで扱う行列のスケールは 0.01〜100 程度なので、
// 正常な行列の行列式が 1e-20 に達することはない。
inline constexpr float kSingularDeterminant = 1.0e-20f;
```

**この 16 行を手で写経する必要はありません。** 符号のパターンに意味を求めても得るものは少なく、間違えたら次節のテストが確実に捕まえます。写経して、テストが緑になったら、二度と読まなくてよいコードです。

### 失敗をどう返すか

`bool` を返して `out` 引数に書く形にしました。第 5 章で `Normalize` に契約（`ANIM_ASSERT`）を使ったのと違う判断です。理由は、**逆行列の失敗は「呼び出し側のバグ」とは限らない**からです。

外部から読み込んだモデルのボーンにスケール `0` が設定されていることは、実際にあります。DCC ツールで非表示にするために `0` スケールを使う運用があるためです。これは私たちのコードのバグではなく、**入力データの性質**です。契約違反として `assert` で落とすのは不適切で、呼び出し側が「そのボーンは飛ばす」と判断できるようにすべきです。

`std::expected` を使わないのは、この関数がロード時のループで回る可能性があり、また `Mat4` を戻り値で返すより出力引数のほうが素直だからです。エラーの「理由」が 1 種類しかないことも、`bool` で足りる理由です。第 31 章の JSON パーサでは理由が多岐にわたるので、そちらでは `std::expected` を使います。

**呼び出し側で毎回 `if` を書きたくない**場面のために、意図を明示した薄いラッパーも用意します。

```cpp
// 逆行列が存在しない場合は単位行列を返す。
// 「失敗しても処理を続けたい」ことを呼び出し側が宣言する形。
[[nodiscard]] inline Mat4 InvertOrIdentity(const Mat4& a) {
    Mat4 r = Identity();
    (void)Invert(a, r);
    return r;
}
```

## 7.4　剛体変換の逆

アニメーションで扱う行列の大半は、**回転と平行移動だけ**でできています（スケールなし）。この場合、逆行列は劇的に簡単になります。

回転部分を `R`、平行移動を `t` とすると、変換は `p' = R p + t` です。これを `p` について解くと

```
p = R⁻¹ (p' - t) = R⁻¹ p' - R⁻¹ t
```

そして**回転行列の逆行列は転置**です（`R` は直交行列なので `R⁻¹ = Rᵀ`）。第 6 章のテスト `RotationMatricesAreOrthogonal` で確かめた性質が、ここで実利になります。

```cpp
// 前提：a が回転と平行移動のみで構成されていること（スケール・せん断なし）。
// この前提が崩れている場合、結果は正しくない。
[[nodiscard]] inline Mat4 InvertRigid(const Mat4& a) {
    Mat4 r = Identity();

    // 回転部分を転置する
    for (int i = 0; i < 3; ++i) {
        for (int j = 0; j < 3; ++j) {
            r.m[i][j] = a.m[j][i];
        }
    }

    // 平行移動は -Rᵀ t
    const Vec3 t{a.m[0][3], a.m[1][3], a.m[2][3]};
    r.m[0][3] = -(r.m[0][0]*t.x + r.m[0][1]*t.y + r.m[0][2]*t.z);
    r.m[1][3] = -(r.m[1][0]*t.x + r.m[1][1]*t.y + r.m[1][2]*t.z);
    r.m[2][3] = -(r.m[2][0]*t.x + r.m[2][1]*t.y + r.m[2][2]*t.z);
    return r;
}
```

除算が一度も出てこないことに注目してください。**失敗しません。** 剛体変換は常に可逆だからです。

筆者の環境で 200 万回ずつ実行して比較したところ、`InvertRigid` は `Invert` の**約 2 倍速**でした。ただし速度以上に重要なのは、次の 2 点です。

**精度。** 一般の逆行列は行列式による除算を含むため、誤差が入ります。転置には誤差が一切ありません（ビット単位で正確です）。第 4 章で見たとおり、蓄積する誤差は避けられるなら避けるべきです。

**意図の表明。** `InvertRigid` を呼んでいるコードは、「この行列にはスケールが入っていないはずだ」と宣言しています。これは読み手への情報であり、前提が崩れたときに疑うべき場所を示してくれます。

### 一様スケール付きの場合

スケールが一様（`sx = sy = sz = s`）なら、もう少し手間をかけるだけで済みます。`R' = R * s` に対して `R'⁻¹ = Rᵀ / s` であり、`s` は列の長さから求められます。

```cpp
[[nodiscard]] inline Mat4 InvertRigidUniformScale(const Mat4& a) {
    // 1 列目の長さがスケール
    const float s2 = a.m[0][0]*a.m[0][0] + a.m[1][0]*a.m[1][0] + a.m[2][0]*a.m[2][0];
    ANIM_ASSERT(s2 > kTinyLengthSquared);
    const float invS2 = 1.0f / s2;

    Mat4 r = Identity();
    for (int i = 0; i < 3; ++i) {
        for (int j = 0; j < 3; ++j) {
            r.m[i][j] = a.m[j][i] * invS2;   // Rᵀ / s²  （転置で s が 1 つ、除算で 1 つ）
        }
    }
    const Vec3 t{a.m[0][3], a.m[1][3], a.m[2][3]};
    r.m[0][3] = -(r.m[0][0]*t.x + r.m[0][1]*t.y + r.m[0][2]*t.z);
    r.m[1][3] = -(r.m[1][0]*t.x + r.m[1][1]*t.y + r.m[1][2]*t.z);
    r.m[2][3] = -(r.m[2][0]*t.x + r.m[2][1]*t.y + r.m[2][2]*t.z);
    return r;
}
```

`s²` で割る理由に注意してください。`R' = R s` の転置は `Rᵀ s` なので、`s` で 2 回割る必要があります（1 回は転置に含まれる `s` を打ち消し、もう 1 回が本来の除算）。ここは間違えやすいので、テストで固定します。

## 7.5　どれを使うべきか

| 状況 | 使うもの |
| --- | --- |
| ボーンの姿勢（スケールなし） | `InvertRigid` |
| 一様スケール付きのボーン | `InvertRigidUniformScale` |
| 非一様スケール、または不明 | `Invert` |
| 逆バインド行列の事前計算（ロード時） | `Invert`（安全側。速度は問題にならない） |

**迷ったら `Invert`。** 速度が問題になってから特化版に置き換え、そのときテストで結果の一致を確認する ―― これが本書を通じての進め方です。

## 7.6　テストを書く

`AnimLib.Tests/Mat4InverseTests.cpp`：

```cpp
#include "CppUnitTest.h"

#include "TestSupport/MathAssert.h"
#include "TestSupport/TestRandom.h"
#include "TestSupport/Tolerance.h"

#include "anim/Mat4.h"

using namespace Microsoft::VisualStudio::CppUnitTestFramework;
using namespace anim;
using anim::test::AssertNear;

namespace AnimLibTests {

TEST_CLASS(Mat4InverseTests) {
public:

    // --- 行列式 ---------------------------------------------------

    TEST_METHOD(DeterminantOfIdentityIsOne) {
        anim::test::AssertNear(1.0f, Determinant(Identity()));
    }

    TEST_METHOD(DeterminantOfRotationIsOne) {
        test::TestRandom rng;
        for (int i = 0; i < 200; ++i) {
            const Mat4 r = MakeRotationX(rng.NextRange(-3, 3))
                         * MakeRotationY(rng.NextRange(-3, 3))
                         * MakeRotationZ(rng.NextRange(-3, 3));
            anim::test::AssertNear(1.0f, Determinant(r), test::kEpsDir);
        }
    }

    // 行列式は体積の倍率
    TEST_METHOD(DeterminantIsVolumeScale) {
        const Mat4 m = MakeTranslation({1, 2, 3})
                     * MakeRotationY(0.7f)
                     * MakeScale({2, 3, 4});
        anim::test::AssertNear(24.0f, Determinant(m), test::kEpsAccum);
    }

    TEST_METHOD(NegativeScaleGivesNegativeDeterminant) {
        Assert::IsTrue(Determinant(MakeScale({-1, 1, 1})) < 0.0f);
    }

    // --- 一般の逆行列 ---------------------------------------------

    TEST_METHOD(InverseTimesOriginalIsIdentity) {
        test::TestRandom rng;
        for (int i = 0; i < 1000; ++i) {
            const Mat4 m = MakeTranslation(rng.NextVec3(5.0f))
                         * MakeRotationX(rng.NextRange(-3, 3))
                         * MakeRotationY(rng.NextRange(-3, 3))
                         * MakeScale({rng.NextRange(0.3f, 3.0f),
                                      rng.NextRange(0.3f, 3.0f),
                                      rng.NextRange(0.3f, 3.0f)});
            Mat4 inv{};
            Assert::IsTrue(Invert(m, inv));
            AssertNear(Identity(), m * inv, test::kEpsAccum);
            AssertNear(Identity(), inv * m, test::kEpsAccum);
        }
    }

    TEST_METHOD(SingularMatrixIsRejected) {
        Mat4 out{};
        Assert::IsFalse(Invert(MakeScale({1, 0, 1}), out));   // Y 方向に潰れている
        Assert::IsFalse(Invert(Mat4{}, out));                 // ゼロ行列
    }

    TEST_METHOD(InvertOrIdentityFallsBack) {
        AssertNear(Identity(), InvertOrIdentity(MakeScale({1, 0, 1})));
    }

    // --- 剛体版 ---------------------------------------------------

    // 一般版と同じ結果になること（実装間の一致テスト）
    TEST_METHOD(RigidInverseMatchesGeneralInverse) {
        test::TestRandom rng;
        for (int i = 0; i < 1000; ++i) {
            const Mat4 m = MakeTranslation(rng.NextVec3(5.0f))
                         * MakeRotationX(rng.NextRange(-3, 3))
                         * MakeRotationY(rng.NextRange(-3, 3));
            Mat4 general{};
            Assert::IsTrue(Invert(m, general));
            AssertNear(general, InvertRigid(m), test::kEpsAccum);
        }
    }

    TEST_METHOD(UniformScaleInverseMatchesGeneralInverse) {
        test::TestRandom rng;
        for (int i = 0; i < 1000; ++i) {
            const float s = rng.NextRange(0.2f, 5.0f);
            const Mat4 m = MakeTranslation(rng.NextVec3(5.0f))
                         * MakeRotationY(rng.NextRange(-3, 3))
                         * MakeScale({s, s, s});
            Mat4 general{};
            Assert::IsTrue(Invert(m, general));
            AssertNear(general, InvertRigidUniformScale(m), test::kEpsAccum);
        }
    }

    // 剛体版は誤差が入らない：往復が厳密に近い
    TEST_METHOD(RigidInverseRoundTripIsPrecise) {
        test::TestRandom rng;
        for (int i = 0; i < 500; ++i) {
            const Mat4 m = MakeTranslation(rng.NextVec3(5.0f))
                         * MakeRotationZ(rng.NextRange(-3, 3));
            const Vec3 p = rng.NextVec3();
            const Vec3 back = TransformPoint(InvertRigid(m), TransformPoint(m, p));
            AssertNear(p, back, test::kEpsPos);
        }
    }
};

}  // namespace AnimLibTests
```

`RigidInverseMatchesGeneralInverse` が、この章でいちばん価値のあるテストです。**2 つの独立した実装が同じ答えを出す**という形で、両方の正しさを同時に検査しています。片方だけ書き間違えれば必ず落ちますし、両方を同じように間違える可能性は極めて低い。第 1 章で挙げた「実装間の一致テスト」の典型例です。

この形は本書で繰り返し登場します。第 20 章（素朴なスキニング vs 最適化版）、第 53 章（スカラー vs SIMD）、第 56 章（非圧縮 vs 圧縮）、第 58 章（CPU vs GPU）。**新しい実装を追加するときは古い実装を消さない**、というのが本書の方針です。

## 7.7　つまずきやすいところ

**`Invert` の結果が明らかにおかしい（`M * inv` が単位行列にならない）**
16 行のどこかで符号か添字を間違えています。`AssertNear(Mat4)` の失敗メッセージでどのインデックスが違うかを見てください。1 箇所だけなら写し間違い、4 箇所が規則的に違うなら符号パターンの誤りです。

**`InvertRigid` の結果が一般版と合わない**
渡している行列にスケールが入っていないか確認してください。`Determinant` が `1.0` に近くなければ、それは剛体変換ではありません。テスト中に `Assert::IsTrue(std::fabs(Determinant(m) - 1.0f) < 1e-3f)` を一時的に挟むと、すぐ分かります。

**`InvertRigidUniformScale` が合わない**
`invS2` を `1/s` にしていませんか。`1/s²` が正しいです。転置した時点で `s` が 1 つ残っているためです。

**特異行列の判定しきい値が厳しすぎる／緩すぎる**
`kSingularDeterminant = 1e-20f` は、スケールが 0.01〜100 の範囲を想定した値です。ミリメートル単位でモデルを作っている（スケールが 0.001 のオーダー）場合、正常な行列の行列式が `1e-9` 程度になることがあります。それでも `1e-20` には遠いので通常は問題になりませんが、極端に小さいスケールを扱うなら見直してください。

**逆行列を毎フレーム計算している**
設計を疑ってください。逆バインド行列はロード時に一度計算して保存するものです（第 15 章）。毎フレームの逆行列が必要になっているなら、たいていは変換の向きを取り違えています。

## この章のまとめ

- 逆行列が要るのは主に 3 箇所 ―― **逆バインド行列**（第 15 章）、**ワールド→ローカル変換**（第 51 章）、**差分の抽出**（第 40 章）。いずれも毎フレームの大量処理ではない。
- 一般の逆行列は **2×2 小行列式を経由**して書く。写経してテストで固定したら、二度と読まなくてよいコード。
- 逆行列は**失敗しうる演算**。ただしその失敗は呼び出し側のバグとは限らない（0 スケールのボーンは実在する）ので、`assert` ではなく `bool` で返す。
- **剛体変換の逆は転置**。誤差ゼロで、約 2 倍速く、そして「この行列にスケールはない」という意図の表明になる。
- 一様スケール版で割るのは `s` ではなく **`s²`**。
- **2 つの独立した実装を突き合わせるテスト**は、両方の正しさを同時に検査できる。本書ではこの形を最後まで使い続ける。

次章から回転の本題に入ります。ここまで回転行列で済ませてきたものを、クォータニオンに置き換えます。なぜそんな面倒なことをするのか、というところから始めます。
