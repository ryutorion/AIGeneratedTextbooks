# 第 23 章　キーフレームとトラック

**この章で作るもの**：`Keyframe` と `Track<T>`。ここまで手で書いてきたポーズを、**時間の関数**にします。第 V 部の土台です。

---

## 23.1　ポーズを時間の関数にする

第 III 部と第 IV 部では、ポーズを手で設定していました。

```cpp
character.LocalPose()[elbow].rotation = MakeQuatAxisAngle({0, 0, 1}, kPi * 0.5f);
```

これを、時刻から自動的に決まるようにします。

```cpp
clip.Sample(currentTime, character.LocalPose());
```

そのために必要なのが**キーフレーム**です。アニメーターは全フレームの姿勢を作るわけではなく、要所の姿勢（キー）だけを指定します。あいだはプログラムが補間します。

第 1 章のパイプラインの ① が、第 V 部の主題です。

```
① クリップをサンプル    ← 第 V 部（ここ）
② ブレンド              ← 第 VII 部
③ 階層を解く            ← ✅
④ IK で補正             ← 第 VIII 部
⑤ パレットを作る        ← ✅
⑥ 頂点を変形            ← ✅
```

## 23.2　なぜ平行移動・回転・スケールを別トラックにするのか

素直に考えると、「ボーンごとに `Transform` のキーを並べる」設計になりそうです。

```cpp
// 本書では採用しない
struct BoneAnimation {
    std::vector<Keyframe<Transform>> keys;
};
```

本書は、平行移動・回転・スケールを**別々のトラック**に分けます。理由が 4 つあります。

**① キーの密度が違う。** 歩行アニメーションで、ボーンの回転は毎フレーム変わりますが、平行移動は多くのボーンで**まったく変わりません**（骨の長さは変わらないため）。`Transform` でまとめると、変わらない平行移動のキーも回転と同じ数だけ作ることになります。

**② 定数トラックをまるごと省ける。** スケールが常に `(1,1,1)` のボーンは、スケールトラックを**空**にできます。人型モデルではほとんどのボーンがそうです。第 54 章のキーフレーム圧縮で、これが最初に効く削減です。

**③ 補間方法が違う。** 平行移動とスケールは線形補間、回転はクォータニオンの補間（第 10 章）。型が違えば処理も違うので、分けたほうが素直です。

**④ glTF がそうなっている。** `animation.channel.target.path` は `translation` / `rotation` / `scale` / `weights` のいずれかで、それぞれ独立したサンプラーを持ちます。第 35 章での読み込みが、そのまま 1 対 1 で対応します。

代償は、1 ボーンぶんのサンプリングで 3 回のキー探索が必要になることです。第 25 章でこのコストを扱います。

## 23.3　`Keyframe` と `Track`

`AnimLib/include/anim/Track.h`：

```cpp
#pragma once

#include "anim/Quat.h"
#include "anim/QuatInterp.h"
#include "anim/Vec3.h"

#include <algorithm>
#include <vector>

namespace anim {

// 補間方法。glTF の 3 つのモードに対応する（第 35 章）。
enum class Interpolation {
    Step,          // 次のキーまで値を保持
    Linear,        // 線形補間（回転は Nlerp）
    CubicSpline    // 三次エルミート。接線つき
};

template <typename T>
struct Keyframe {
    float time;
    T value;
    T inTangent;    // CubicSpline のときだけ使う
    T outTangent;
};

template <typename T>
class Track {
public:
    // --- 構築（ロード時）---
    void SetInterpolation(Interpolation mode) { interpolation_ = mode; }
    void AddKey(float time, const T& value);
    void AddKeyCubic(float time, const T& value, const T& inTangent, const T& outTangent);

    // キーを時刻順に並べ替える。追加が終わったら必ず呼ぶ。
    void Finalize();

    // --- 問い合わせ ---
    [[nodiscard]] bool IsEmpty() const noexcept { return keys_.empty(); }
    [[nodiscard]] std::size_t KeyCount() const noexcept { return keys_.size(); }
    [[nodiscard]] const Keyframe<T>& Key(std::size_t i) const { return keys_[i]; }
    [[nodiscard]] float StartTime() const { return keys_.empty() ? 0.0f : keys_.front().time; }
    [[nodiscard]] float EndTime()   const { return keys_.empty() ? 0.0f : keys_.back().time; }

    [[nodiscard]] Interpolation GetInterpolation() const noexcept { return interpolation_; }

    // --- サンプリング（第 24・25 章）---
    [[nodiscard]] T Sample(float time) const;

private:
    std::vector<Keyframe<T>> keys_;
    Interpolation interpolation_ = Interpolation::Linear;
};

}  // namespace anim
```

`T` には `float`、`Vec3`、`Quat` が入ります。テンプレートにしたのは、キーの管理と探索が型によらず同じだからです。**違うのは補間だけ**で、それは次節の `Mix` に切り出します。

`inTangent` / `outTangent` は `CubicSpline` のときしか使いませんが、常にメモリを消費します。`Vec3` のトラックでは、キー 1 つが 12 バイトから 40 バイトに増えます。無駄に見えますが、

- **キー配列を型ごとに分けるほうが複雑になる**
- 第 54・55 章でランタイム形式に焼き込むとき、どのみち別のレイアウトに変換する

ので、編集用の中間表現としてはこれで構いません。**「ロード時に使う形」と「毎フレーム使う形」を分ける**のは第 37 章の主題です。

## 23.4　型ごとの補間 ―― `Mix`

トラックのコードを型で分けないために、補間だけを外に出します。

```cpp
// AnimLib/include/anim/Interpolate.h

namespace anim {

// 線形補間。型ごとに正しい方法を選ぶ。
[[nodiscard]] inline float Mix(float a, float b, float t) {
    return a * (1.0f - t) + b * t;
}
[[nodiscard]] inline Vec3 Mix(Vec3 a, Vec3 b, float t) {
    return a * (1.0f - t) + b * t;
}
// 回転は Nlerp（第 10 章の判断：キーフレーム補間は Nlerp が既定）
[[nodiscard]] inline Quat Mix(const Quat& a, const Quat& b, float t) {
    return Nlerp(a, b, t);
}

}  // namespace anim
```

第 10 章で測った表がここで効いています。**キー間の角度差が 45 度以下なら `Nlerp` の誤差は 0.12 度未満**で見えない。24 fps で作られたモーションを再生する場合でも、隣接キーの角度差がそこまで開くことは稀です。

`Slerp` が必要な場面（クロスフェード、ブレンドスペース）は第 VII 部で扱います。トラックには `Slerp` を選ぶオプションを持たせません ―― **必要ないところに選択肢を作らない**、という判断です。

## 23.5　符号を揃える ―― クォータニオントラック固有の問題

第 8 章の二重被覆が、ここでも顔を出します。

キー `A` と キー `B` が隣り合っていて、`B` が `-B` として保存されていたらどうなるか。**回転としては同じ**ですが、補間すると長いほうの弧を回ります。第 10 章の「たまに一回転する」バグです。

`Nlerp` は内部で最短経路を選ぶので（第 10 章）、2 つのキーのあいだでは正しく動きます。問題は**キーをまたぐ連鎖**です。

```
キー0 = q,  キー1 = -q',  キー2 = q''
```

キー 0 → 1 の区間では `-q'` が `q` に近い側へ反転されて補間されます。キー 1 → 2 の区間では、保存されている `-q'` を基準に `q''` が反転されます。**区間ごとには連続ですが、キー 1 の値そのものは 2 つの区間で違う符号として扱われる**ため、区間の境界で不連続が生じる可能性があります。

対策は 2 つあります。

**① ロード時にトラック全体の符号を揃える。** 先頭から順に、前のキーと内積が負なら反転する。一度やれば以後は考えなくてよい。

**② 補間のたびに揃える。** 本書の `Mix(Quat)` はこれを行っています（`Nlerp` の内部）。

本書は**両方**やります。② だけでも動きますが、① をやっておくと第 55 章の圧縮（Smallest Three）で符号が揃っていることが前提にできます。

```cpp
// クォータニオントラックの符号を、隣接キーどうしで揃える。
// Finalize() の中から呼ぶ。
inline void AlignQuatTrackSigns(std::vector<Keyframe<Quat>>& keys) {
    for (std::size_t i = 1; i < keys.size(); ++i) {
        if (Dot(keys[i].value, keys[i - 1].value) < 0.0f) {
            keys[i].value      = -keys[i].value;
            keys[i].inTangent  = -keys[i].inTangent;
            keys[i].outTangent = -keys[i].outTangent;
        }
    }
}
```

**接線も一緒に反転する**のを忘れないでください。値だけ反転して接線をそのままにすると、三次補間が壊れます。

## 23.6　`Finalize` ―― 並べ替えを 1 か所に閉じ込める

```cpp
template <typename T>
void Track<T>::AddKey(float time, const T& value) {
    keys_.push_back({time, value, T{}, T{}});
}

template <typename T>
void Track<T>::AddKeyCubic(float time, const T& value,
                           const T& inTangent, const T& outTangent) {
    keys_.push_back({time, value, inTangent, outTangent});
}

template <typename T>
void Track<T>::Finalize() {
    std::stable_sort(keys_.begin(), keys_.end(),
                     [](const Keyframe<T>& a, const Keyframe<T>& b) {
                         return a.time < b.time;
                     });
}
```

**`AddKey` はソートしません。** 追加のたびにソートすると O(n² log n) になりますし、そもそもキーの追加は必ずロード時にまとめて行われます。

`std::stable_sort` を使っているのは、**同じ時刻のキーが 2 つあったときの順序を決定的にするため**です。第 17 章のウェイトのソートと同じ理由で、再現性のあるテスト（第 20 章のゴールデンテスト）の前提になります。

同じ時刻に 2 つのキーがあるのは異常ですが、DCC ツールの出力に実在します。本書は「後から追加したほうが後ろに来る」と決めて、それ以上は関与しません。

> **`Finalize` を呼び忘れたら**
> ソートされていないキー配列で二分探索（第 25 章）すると、静かに間違った結果が出ます。Debug ビルドで検出できるよう、`Sample` の先頭にソート済みチェックを入れておくのが安全です。
> ```cpp
> ANIM_ASSERT(std::is_sorted(keys_.begin(), keys_.end(),
>                            [](const auto& a, const auto& b) { return a.time < b.time; }));
> ```
> Release では消えるので、コストは気にしなくて構いません。

## 23.7　境界のケース

トラックには 3 つの特殊な状態があります。すべて実データで発生するので、最初から扱いを決めておきます。

**① 空トラック（キー 0 個）。** そのチャンネルはアニメーションしない、という意味です。第 26 章の `Clip::Sample` では、空トラックのチャンネルは**書き換えません**。呼び出し側が入れておいた値（通常はレストポーズ）がそのまま残ります。これが 23.2 節で述べた「スケールトラックをまるごと省ける」という利点の実装です。

**② キー 1 個。** 定数です。どの時刻でも同じ値を返します。「このボーンは常にこの姿勢」というデータで、これも実在します。

**③ 範囲外の時刻。** 最初のキーより前、最後のキーより後。**クランプ**します。トラックの範囲とクリップの長さが一致しないことがあるためです（あるボーンだけ 1.5 秒でキーが終わっているのに、クリップの長さは 2 秒、など）。

ループの折り返しは**クリップの責任**であって、トラックの責任ではありません（第 26 章）。トラックは「与えられた時刻の値を返す」だけの、状態を持たない部品にしておきます。

## 23.8　テストを書く

`AnimLib.Tests/TrackTests.cpp`：

```cpp
#include "CppUnitTest.h"

#include "TestSupport/MathAssert.h"
#include "TestSupport/Tolerance.h"

#include "anim/Track.h"

#include <numbers>

using namespace Microsoft::VisualStudio::CppUnitTestFramework;
using namespace anim;
using anim::test::AssertNear;

namespace { constexpr float kPi = std::numbers::pi_v<float>; }

namespace AnimLibTests {

TEST_CLASS(TrackTests) {
public:

    // --- 構築と並べ替え -------------------------------------------

    TEST_METHOD(KeysAreSortedByTime) {
        Track<Vec3> t;
        t.AddKey(1.0f, {1, 0, 0});
        t.AddKey(0.0f, {0, 0, 0});
        t.AddKey(0.5f, {0, 1, 0});
        t.Finalize();

        Assert::AreEqual(std::size_t{3}, t.KeyCount());
        anim::test::AssertNear(0.0f, t.Key(0).time);
        anim::test::AssertNear(0.5f, t.Key(1).time);
        anim::test::AssertNear(1.0f, t.Key(2).time);
    }

    // 同時刻のキーは追加順を保つ（決定性）
    TEST_METHOD(EqualTimesKeepInsertionOrder) {
        for (int trial = 0; trial < 5; ++trial) {
            Track<float> t;
            t.AddKey(0.0f, 10.0f);
            t.AddKey(0.0f, 20.0f);
            t.AddKey(0.0f, 30.0f);
            t.Finalize();
            anim::test::AssertNear(10.0f, t.Key(0).value);
            anim::test::AssertNear(20.0f, t.Key(1).value);
            anim::test::AssertNear(30.0f, t.Key(2).value);
        }
    }

    // --- キー上では厳密に一致すること ------------------------------

    TEST_METHOD(SamplingAtKeyTimesReturnsKeyValues) {
        Track<Vec3> t;
        t.AddKey(0.0f, {0, 0, 0});
        t.AddKey(0.5f, {0, 1, 0});
        t.AddKey(1.0f, {1, 0, 0});
        t.Finalize();

        AssertNear(Vec3{0, 0, 0}, t.Sample(0.0f), test::kEpsPos);
        AssertNear(Vec3{0, 1, 0}, t.Sample(0.5f), test::kEpsPos);
        AssertNear(Vec3{1, 0, 0}, t.Sample(1.0f), test::kEpsPos);
    }

    // --- 境界のケース ---------------------------------------------

    TEST_METHOD(EmptyTrackIsDetectable) {
        const Track<Vec3> t;
        Assert::IsTrue(t.IsEmpty());
        Assert::AreEqual(std::size_t{0}, t.KeyCount());
    }

    TEST_METHOD(SingleKeyTrackIsConstant) {
        Track<Vec3> t;
        t.AddKey(0.3f, {5, 6, 7});
        t.Finalize();

        AssertNear(Vec3{5, 6, 7}, t.Sample(0.0f), test::kEpsPos);
        AssertNear(Vec3{5, 6, 7}, t.Sample(0.3f), test::kEpsPos);
        AssertNear(Vec3{5, 6, 7}, t.Sample(99.0f), test::kEpsPos);
        AssertNear(Vec3{5, 6, 7}, t.Sample(-99.0f), test::kEpsPos);
    }

    TEST_METHOD(OutOfRangeTimesAreClamped) {
        Track<Vec3> t;
        t.AddKey(0.0f, {0, 0, 0});
        t.AddKey(1.0f, {1, 0, 0});
        t.Finalize();

        AssertNear(Vec3{0, 0, 0}, t.Sample(-5.0f), test::kEpsPos);
        AssertNear(Vec3{1, 0, 0}, t.Sample(5.0f), test::kEpsPos);
    }

    // --- クォータニオントラック -----------------------------------

    TEST_METHOD(QuatTrackOutputIsUnitLength) {
        Track<Quat> t;
        t.AddKey(0.0f, MakeQuatAxisAngle({0, 0, 1}, 0.0f));
        t.AddKey(1.0f, MakeQuatAxisAngle({1, 1, 0}, 1.7f));
        t.Finalize();

        for (int i = 0; i <= 20; ++i) {
            const float x = static_cast<float>(i) / 20.0f;
            anim::test::AssertNear(1.0f, Length(t.Sample(x)), test::kEpsUnit);
        }
    }

    // キーの符号が反転して保存されていても、最短経路を通ること
    TEST_METHOD(QuatTrackTakesShortestPathDespiteFlippedKeys) {
        const Quat a = QuatIdentity();
        const Quat b = MakeQuatAxisAngle({0, 0, 1}, kPi * 0.9f);

        Track<Quat> t;
        t.AddKey(0.0f, a);
        t.AddKey(1.0f, -b);        // わざと反転して保存
        t.Finalize();

        const Quat mid = t.Sample(0.5f);
        // 中間の姿勢は a と同じ半球にあるはず（長い弧を回っていない）
        Assert::IsTrue(Dot(mid, a) > 0.0f);
    }

    // Finalize がトラック全体の符号を揃えること
    TEST_METHOD(FinalizeAlignsQuatSigns) {
        Track<Quat> t;
        t.AddKey(0.0f, QuatIdentity());
        t.AddKey(1.0f, -MakeQuatAxisAngle({0, 0, 1}, 0.3f));
        t.AddKey(2.0f, MakeQuatAxisAngle({0, 0, 1}, 0.6f));
        t.Finalize();

        for (std::size_t i = 1; i < t.KeyCount(); ++i) {
            Assert::IsTrue(Dot(t.Key(i).value, t.Key(i - 1).value) >= 0.0f);
        }
    }

    // --- Mix --------------------------------------------------------

    TEST_METHOD(MixEndpointsAreExact) {
        AssertNear(Vec3{1, 2, 3}, Mix(Vec3{1, 2, 3}, Vec3{4, 5, 6}, 0.0f), test::kEpsPos);
        AssertNear(Vec3{4, 5, 6}, Mix(Vec3{1, 2, 3}, Vec3{4, 5, 6}, 1.0f), test::kEpsPos);
    }

    TEST_METHOD(MixOfQuatsStaysUnit) {
        const Quat a = MakeQuatAxisAngle({1, 0, 0}, 0.4f);
        const Quat b = MakeQuatAxisAngle({0, 1, 0}, 1.1f);
        for (int i = 0; i <= 10; ++i) {
            anim::test::AssertNear(1.0f, Length(Mix(a, b, i / 10.0f)), test::kEpsUnit);
        }
    }
};

}  // namespace AnimLibTests
```

`SamplingAtKeyTimesReturnsKeyValues` は、当たり前に見えて重要なテストです。**キー上で元の値が返らない補間実装**は、実際に書けてしまいます（区間の選び方を 1 つずらす、`u` の計算で開区間・閉区間を取り違える、など）。そしてその症状は「アニメーションが全体的に少しだけ遅れる」という、目視では気づきにくいものになります。

`QuatTrackTakesShortestPathDespiteFlippedKeys` は、第 10 章で「データ依存で発現するので目視では見つからない」と書いたバグに対する、直接の番人です。

## 23.9　つまずきやすいところ

**`Finalize` を呼び忘れた**
二分探索（第 25 章）がソート済みを前提にしているので、静かに間違った値が返ります。`ANIM_ASSERT(std::is_sorted(...))` を `Sample` の先頭に置いてください。

**アニメーションが全体的にわずかに遅れる／進む**
キー上で値が一致していない可能性があります。`SamplingAtKeyTimesReturnsKeyValues` を実行してください。

**回転が「たまに」一回転する**
`Mix(Quat)` が `Nlerp` を呼んでいるか、`Finalize` で符号を揃えているかを確認してください。

**メモリが想定より大きい**
`Keyframe<Vec3>` は接線ぶんを含めて 40 バイトです。編集用の形としては許容しますが、ランタイムに持ち込むものではありません（第 37・54 章）。

**空トラックのボーンが原点に飛ぶ**
`Clip::Sample` が空トラックのチャンネルをゼロで上書きしています。**空トラックは「書き換えない」**が正しい扱いです（第 26 章）。

## この章のまとめ

- ポーズを**時間の関数**にする。それが第 V 部。
- 平行移動・回転・スケールを**別トラック**にする。理由は**キーの密度が違う・定数トラックをまるごと省ける・補間方法が違う・glTF がそうなっている**の 4 つ。
- `Track<T>` はテンプレートにし、**型による違いは `Mix` に閉じ込める**。回転は `Nlerp`（第 10 章の判断）。
- クォータニオントラックは、**ロード時に符号を揃える**（接線も一緒に反転する）。補間時にも揃えるので二重の守りになる。
- `AddKey` はソートしない。**`Finalize` で `stable_sort` する** ―― 同時刻キーの順序を決定的にするため。
- 境界のケースは 3 つ。**空トラック（書き換えない）・単一キー（定数）・範囲外（クランプ）**。ループの折り返しはトラックの責任ではない。
- **「キー上で元の値が返る」は必ずテストする。** 破ると「全体がわずかに遅れる」という、目視で気づけない症状になる。

次章では、キーとキーのあいだをどう埋めるかを扱います。3 つの補間モードと、それぞれの誤差を測ります。
