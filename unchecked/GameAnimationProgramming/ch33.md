# 第 33 章　メッシュを読む

**この章で作るもの**：glTF の `meshes` から、第 17 章の `SkinnedMesh` を組み立てる処理。属性の対応づけ、インデックスの読み出し、そして**実データのウェイトを検査して直す**ところまで扱います。

---

## 33.1　`meshes` と `primitives`

glTF のメッシュは、**プリミティブの集まり**です。

```json
"meshes": [
  {
    "name": "Cylinder",
    "primitives": [
      {
        "attributes": {
          "POSITION": 0, "NORMAL": 1, "JOINTS_0": 2, "WEIGHTS_0": 3
        },
        "indices": 4,
        "material": 0,
        "mode": 4
      }
    ]
  }
]
```

なぜ 1 段挟まっているのか ―― **プリミティブごとにマテリアルが違う**からです。1 つのキャラクターモデルで、体・髪・目・服がそれぞれ別のプリミティブになっているのが典型です。

**描画をしない本書には、この分割は不要**です。プリミティブをすべて連結して 1 つの `SkinnedMesh` にします。インデックスをずらしながらつなぐだけです。

```cpp
// AnimLib/include/anim/GltfMesh.h

namespace anim {

// glTF のメッシュを SkinnedMesh に変換する。
// 複数のプリミティブは連結される（マテリアルの区別は失われる）。
[[nodiscard]] std::expected<SkinnedMesh, GltfError>
LoadMesh(const GltfDocument& doc, int meshIndex);

}  // namespace anim
```

## 33.2　属性の対応づけ

glTF が定める属性のうち、本書が使うものです。

| glTF の属性名 | 型 | 本書の `SkinnedVertex` |
| --- | --- | --- |
| `POSITION` | `VEC3` float（必須） | `position` |
| `NORMAL` | `VEC3` float | `normal` |
| `TANGENT` | `VEC4` float | `tangent` |
| `TEXCOORD_0` | `VEC2` float / 正規化整数 | `uv` |
| `JOINTS_0` | `VEC4` ubyte / ushort | `joints` |
| `WEIGHTS_0` | `VEC4` float / 正規化整数 | `weights` |

**`POSITION` だけが必須**です。他は存在しないことがあります。

- 法線がなければ、面法線から計算するか、`(0,1,0)` で埋める
- 接線がなければ、法線マップを使わないので `(1,0,0,1)` で埋める
- `JOINTS_0` / `WEIGHTS_0` がなければ、それはスキンメッシュではない

```cpp
std::expected<SkinnedMesh, GltfError> LoadMesh(const GltfDocument& doc, int meshIndex) {
    const JsonValue& mesh = doc.Json()["meshes"][static_cast<std::size_t>(meshIndex)];
    if (!mesh.Has("primitives")) {
        return std::unexpected(GltfError{"メッシュに primitives がない"});
    }

    SkinnedMesh out;

    for (const JsonValue& primitive : mesh["primitives"].AsArray()) {
        // 本書は三角形リストだけを扱う
        const int mode = primitive["mode"].AsInt(4);
        if (mode != 4) {
            return std::unexpected(GltfError{
                "未対応のプリミティブモード: " + std::to_string(mode)});
        }

        const JsonValue& attributes = primitive["attributes"];
        if (!attributes.Has("POSITION")) {
            return std::unexpected(GltfError{"POSITION 属性がない"});
        }

        const auto positions = doc.ReadAccessorAsFloat(attributes["POSITION"].AsInt());
        const std::size_t vertexCount = positions.size() / 3;
        const std::uint32_t base = static_cast<std::uint32_t>(out.vertices.size());

        // ... 属性を読んで頂点を組み立てる（次節）...
        // ... インデックスを base ぶんずらして追加する（33.3 節）...
    }
    return out;
}
```

**`mode` を検査する**のを忘れないでください。既定は `4`（三角形リスト）ですが、`5`（トライアングルストリップ）や `6`（トライアングルファン）のデータも存在します。**黙って三角形リストとして読むと、モデルが破裂します。**

### 属性を読む

```cpp
        // 存在しない属性は空の配列が返るようにする
        auto readOptional = [&](std::string_view name) -> std::vector<float> {
            return attributes.Has(name)
                 ? doc.ReadAccessorAsFloat(attributes[name].AsInt())
                 : std::vector<float>{};
        };

        const auto normals  = readOptional("NORMAL");
        const auto tangents = readOptional("TANGENT");
        const auto uvs      = readOptional("TEXCOORD_0");
        const auto weights  = readOptional("WEIGHTS_0");

        std::vector<std::uint32_t> joints;
        if (attributes.Has("JOINTS_0")) {
            joints = doc.ReadAccessorAsUInt(attributes["JOINTS_0"].AsInt());
        }

        // すべての属性が同じ頂点数であることを検査する
        auto checkCount = [&](const auto& array, int components,
                              std::string_view name) -> std::expected<void, GltfError> {
            if (!array.empty() && array.size() != vertexCount * components) {
                return std::unexpected(GltfError{
                    std::string(name) + " の要素数が POSITION と一致しない"});
            }
            return {};
        };
        if (auto r = checkCount(normals, 3, "NORMAL");    !r) { return std::unexpected(r.error()); }
        if (auto r = checkCount(tangents, 4, "TANGENT");  !r) { return std::unexpected(r.error()); }
        if (auto r = checkCount(joints, 4, "JOINTS_0");   !r) { return std::unexpected(r.error()); }
        if (auto r = checkCount(weights, 4, "WEIGHTS_0"); !r) { return std::unexpected(r.error()); }
```

**要素数の検査**が重要です。glTF の仕様では全属性が同じ `count` を持つはずですが、生成側のバグで食い違うことがあります。検査しなければ、後段で配列の範囲外を読みます。

第 31 章で「JSON の取り回しは緩く、glTF としての妥当性は厳しく」と書いた、その「厳しく」の部分がここです。

## 33.3　頂点を組み立てる

```cpp
        for (std::size_t i = 0; i < vertexCount; ++i) {
            SkinnedVertex v{};

            v.position = {positions[i*3 + 0], positions[i*3 + 1], positions[i*3 + 2]};

            v.normal = normals.empty()
                     ? Vec3{0.0f, 1.0f, 0.0f}
                     : Vec3{normals[i*3 + 0], normals[i*3 + 1], normals[i*3 + 2]};

            v.tangent = tangents.empty()
                      ? Vec4{1.0f, 0.0f, 0.0f, 1.0f}
                      : Vec4{tangents[i*4 + 0], tangents[i*4 + 1],
                             tangents[i*4 + 2], tangents[i*4 + 3]};

            v.uv = uvs.empty() ? Vec2{0.0f, 0.0f}
                               : Vec2{uvs[i*2 + 0], uvs[i*2 + 1]};

            // --- スキンウェイト ---
            if (joints.empty() || weights.empty()) {
                // スキンなし。ボーン 0 に 100% 割り当てる
                v.joints[0] = 0;
                v.weights[0] = 1.0f;
            } else {
                std::vector<Influence> influences;
                for (int k = 0; k < 4; ++k) {
                    const float w = weights[i*4 + k];
                    if (w > 0.0f) {
                        influences.push_back({
                            static_cast<BoneIndex>(joints[i*4 + k]), w});
                    }
                }
                SortAndTruncate(influences, v);   // 第 17 章
            }

            out.vertices.push_back(v);
        }
```

**`SortAndTruncate` をそのまま呼びます。** 第 17 章で「合計を 1 に正規化する」「降順にソートする」「ウェイト 0 の枠を 0 で埋める」を実装しておいたので、ここでやることは影響のリストを組み立てるだけです。

第 17 章の伏線が、ここで 3 つ同時に回収されます。

- **正規化**：実データのウェイト合計は 1 でないことがある
- **降順ソート**：第 20 章の高速パスと第 22 章の DQS が前提にしている
- **0 埋め**：GPU が分岐なしで 4 本すべてを引く（第 58 章）

### インデックス

```cpp
        if (primitive.Has("indices")) {
            const auto indices = doc.ReadAccessorAsUInt(primitive["indices"].AsInt());
            if (indices.size() % 3 != 0) {
                return std::unexpected(GltfError{"インデックス数が 3 の倍数でない"});
            }
            for (const std::uint32_t index : indices) {
                if (index >= vertexCount) {
                    return std::unexpected(GltfError{"インデックスが頂点数を超えている"});
                }
                out.indices.push_back(base + index);   // ← 連結のためのオフセット
            }
        } else {
            // indices がなければ、頂点が順に三角形を作る
            for (std::size_t i = 0; i < vertexCount; ++i) {
                out.indices.push_back(base + static_cast<std::uint32_t>(i));
            }
        }
```

**`base` を足すのが、プリミティブを連結する仕掛け**です。2 つ目のプリミティブのインデックス `0` は、連結後の `158` を指すことになります。

`indices` がない場合も仕様上ありえます。頂点が順番に三角形を作る（インデックスバッファなしの描画）形です。

**範囲の検査**も忘れずに。インデックスが頂点数を超えているデータは、破損したファイルで実際に起こります。検査しなければ、第 18 章のスキニングで範囲外アクセスになります。

## 33.4　`accessor.min` / `max` を検証に使う

第 32 章で触れましたが、あらためて。

glTF の仕様は、`POSITION` の accessor に `min` と `max` を持つことを**義務づけています**。これはバウンディングボックスの計算を省くための情報ですが、**私たちにとっては無料の検証データ**です。

```cpp
// 読み込んだ位置が accessor の min/max の範囲に収まっているか検査する。
// 収まっていなければ、オフセットかストライドの解釈を間違えている。
[[nodiscard]] bool VerifyPositionBounds(const GltfDocument& doc, int accessorIndex,
                                        std::span<const float> positions) {
    const JsonValue& accessor =
        doc.Json()["accessors"][static_cast<std::size_t>(accessorIndex)];
    if (!accessor.Has("min") || !accessor.Has("max")) {
        return true;   // 情報がなければ検査しない
    }
    for (std::size_t v = 0; v + 2 < positions.size(); v += 3) {
        for (int axis = 0; axis < 3; ++axis) {
            const float lo = static_cast<float>(accessor["min"][axis].AsNumber());
            const float hi = static_cast<float>(accessor["max"][axis].AsNumber());
            const float value = positions[v + axis];
            if (value < lo - 1.0e-4f || value > hi + 1.0e-4f) {
                return false;
            }
        }
    }
    return true;
}
```

**ファイルの中に「正解」が書いてある**という、珍しく恵まれた状況です。使わない手はありません。

## 33.5　実データの品質を報告する

読めることと、正しく使えることは別です。読み込み時に気づいた問題を、呼び出し側に伝えます。

```cpp
// メッシュの読み込みで検出した、データの品質に関する情報。
// 読み込みは成功しているが、注意が必要な状態を伝える。
struct MeshLoadReport {
    std::size_t verticesWithNoWeights = 0;    // ウェイト合計が 0 だった頂点
    std::size_t verticesRenormalized = 0;     // 合計が 1 から離れていた頂点
    std::size_t verticesTruncated = 0;        // 影響が 5 本以上あった頂点
    float worstTruncationError = 0.0f;        // 捨てたウェイトの最大割合
    float worstWeightSumError = 0.0f;         // 1 からの最大のずれ
    bool hasNormals = false;
    bool hasTangents = false;
};
```

**失敗（`GltfError`）と警告（`MeshLoadReport`）を分けている**のが要点です。

ウェイトの合計が 0.98 のモデルは、読み込みを失敗させるべきではありません。正規化して使えば問題なく動きます。しかし**黙って直すのも良くない** ―― モデル側に問題があることを、誰かが知るべきです。

第 5 章で `Normalize` に契約を置き、`NormalizeSafe` を別に用意したのと同じ判断です。**「処理は続ける、しかし記録は残す」。**

```cpp
    // 呼び出し側
    auto mesh = LoadMesh(doc, 0, &report);
    if (report.worstWeightSumError > 0.01f) {
        ANIM_LOG_WARN("ウェイトの合計が最大 {:.3f} ずれています", report.worstWeightSumError);
    }
    if (report.verticesWithNoWeights > 0) {
        ANIM_LOG_WARN("{} 個の頂点にウェイトがありません", report.verticesWithNoWeights);
    }
```

## 33.7　つまずきやすいところ

**モデルが破裂する（三角形が滅茶苦茶な形になる）**
`mode` が三角形リストでないか、インデックスの読み方を間違えています。`mode` を検査してください。

**2 つ目のプリミティブだけおかしい**
インデックスに `base` を足していません（33.3 節）。

**モデルが裏返って見える**
巻き方が逆です。体積で確認してください。ただし glTF は反時計回りを表とするので、本書の規約（第 17 章）と一致します。**転置や座標系の変換をどこかで余計に行っていないか**を疑ってください。

**特定のモデルだけウェイトがおかしい**
`JOINTS_0` が `unsigned byte` で格納されているかもしれません。`ReadAccessorAsUInt` が両方の型を扱えているか確認してください。

**ウェイトが 0 の頂点で原点に飛ぶ**
第 17 章の `SortAndTruncate` のフォールバックが効いているか確認してください。

**メッシュは読めるがスキニングで範囲外アクセス**
`JOINTS_0` の値は **`skin.joints` 配列の添字**であって、ノードの添字ではありません。第 34 章で対応表を作ります。

**接線が全部 `(1,0,0,1)` になる**
`TANGENT` 属性がないモデルです。法線マップを使うなら、UV から計算する必要があります（本書の範囲外）。

## この章のまとめ

- `meshes` → `primitives` の 1 段は**マテリアルの分割**のため。描画をしない本書は、**インデックスをずらして連結**して 1 つの `SkinnedMesh` にする。
- **`POSITION` だけが必須。** 他は既定値で埋める。
- **`mode` を必ず検査する。** トライアングルストリップを黙って三角形リストとして読むと、モデルが破裂する。
- **全属性の要素数が一致することを検査する。** 「JSON の取り回しは緩く、glTF としての妥当性は厳しく」。
- ウェイトの処理は第 17 章の **`SortAndTruncate` をそのまま呼ぶ**。正規化・降順ソート・0 埋めの 3 つの伏線が同時に回収される。
- **`accessor.min` / `max` は無料の検証データ。** ファイルの中に正解が書いてある。
- **失敗（`GltfError`）と警告（`MeshLoadReport`）を分ける。** ウェイト合計 0.98 は読み込みを止める理由にならないが、黙って直すのも良くない。「処理は続ける、しかし記録は残す」。
- **巻き方の検証には体積を使う。** 第 17 章で作った `MeshVolume` が、6 章あとで別の目的に再利用できた。

次章が第 VI 部の山場です。ノード階層とスキン ―― 転置、トポロジカルソート、対応表が一度に出てきます。
