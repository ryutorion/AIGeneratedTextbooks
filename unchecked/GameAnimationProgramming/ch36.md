# 第 36 章　GLB を読む

**この章で作るもの**：GLB コンテナの読み込み。仕様が短いので、章も短くなります。最後に、**3 つの形態から読んだデータがビット単位で一致すること**を確認します。

---

## 36.1　GLB とは

GLB（Binary glTF）は、JSON とバイナリを 1 つのファイルにまとめた形式です。`.gltf` + `.bin` の 2 ファイル構成を、**配布しやすくしたもの**と考えれば十分です。

利点が 3 つあります。

**① 1 ファイルで完結する。** アセットの管理が楽になります。
**② Base64 の膨張がない。** 埋め込み `.gltf` はサイズが 1.33 倍になりますが、GLB は生バイトのままです。
**③ 読み込みが速い。** Base64 デコードが不要で、バイナリチャンクをそのまま使えます。

実際のサイズを比較しておきます（本書のテストモデル）。

| 形態 | サイズ |
| --- | --- |
| `.gltf` + `.bin` | 3,193 + 9,680 = 12,873 B |
| 埋め込み `.gltf` | 約 16,000 B（1.24 倍） |
| `.glb` | 約 13,000 B |

## 36.2　ファイル構造

GLB は**ヘッダとチャンクの列**です。

```
┌────────────────────────────────┐
│ ヘッダ（12 バイト）                    │
│   magic   : 0x46546C67 ("glTF")      │
│   version : 2                        │
│   length  : ファイル全体のバイト数        │
├────────────────────────────────┤
│ チャンク 0（JSON、必須）                │
│   chunkLength : 4 バイト               │
│   chunkType   : 0x4E4F534A ("JSON")  │
│   chunkData   : JSON テキスト          │
├────────────────────────────────┤
│ チャンク 1（BIN、任意）                 │
│   chunkLength : 4 バイト               │
│   chunkType   : 0x004E4942 ("BIN\0") │
│   chunkData   : バイナリ               │
├────────────────────────────────┤
│ （未知のチャンクが続くことがある）          │
└────────────────────────────────┘
```

すべて**リトルエンディアンの `uint32`** です。glTF の仕様がリトルエンディアンを要求しているので、ビッグエンディアンの環境ではバイトスワップが必要ですが、本書が対象とする x64 では不要です。

**マジックナンバーが文字列として読める**のが、この手のフォーマットの慣習です。バイナリエディタで開くと先頭に `glTF` と見えます。デバッグの助けになります。

### パディング

チャンクデータは**4 バイト境界に揃える**ことが仕様で定められています。

- JSON チャンクは、末尾を**スペース（0x20）**で埋める
- BIN チャンクは、末尾を**ゼロ（0x00）**で埋める

**埋め文字が違う**のは、JSON チャンクをそのまま文字列としてパースできるようにするためです。ゼロで埋めると、パーサが「予期しない文字」で止まります（第 30 章の実装なら、そうなります）。

そして重要なのは、**パディングは `chunkLength` に含まれる**ことです。「JSON は 1000 バイトだが、chunkLength は 1000」ではなく、パディング込みで 1000（あるいは 1002 など 4 の倍数）になります。読む側は `chunkLength` ぶんを読めばよく、パディングを別に考慮する必要はありません。

## 36.3　実装

```cpp
// AnimLib/src/Gltf.cpp

namespace {

constexpr std::uint32_t kGlbMagic     = 0x46546C67u;   // "glTF"
constexpr std::uint32_t kChunkJson    = 0x4E4F534Au;   // "JSON"
constexpr std::uint32_t kChunkBinary  = 0x004E4942u;   // "BIN\0"

[[nodiscard]] std::uint32_t ReadU32(const char* p) {
    std::uint32_t v;
    std::memcpy(&v, p, 4);      // アライメントとエイリアシングの回避（第 32 章）
    return v;
}

}  // namespace

std::expected<GltfDocument, GltfError>
GltfDocument::LoadGlb(std::string_view data) {
    if (data.size() < 12) {
        return std::unexpected(GltfError{"GLB が短すぎる"});
    }
    if (ReadU32(data.data()) != kGlbMagic) {
        return std::unexpected(GltfError{"GLB のマジックが違う"});
    }
    const std::uint32_t version = ReadU32(data.data() + 4);
    if (version != 2) {
        return std::unexpected(GltfError{
            "GLB のバージョンが 2 でない: " + std::to_string(version)});
    }
    const std::uint32_t totalLength = ReadU32(data.data() + 8);
    if (totalLength > data.size()) {
        return std::unexpected(GltfError{"GLB の length がファイルサイズより大きい"});
    }

    std::string jsonChunk;
    std::vector<std::uint8_t> binaryChunk;
    bool sawJson = false;

    std::size_t position = 12;
    while (position + 8 <= totalLength) {
        const std::uint32_t chunkLength = ReadU32(data.data() + position);
        const std::uint32_t chunkType   = ReadU32(data.data() + position + 4);
        position += 8;

        if (position + chunkLength > totalLength) {
            return std::unexpected(GltfError{"GLB チャンクがファイル末尾を超えている"});
        }

        if (chunkType == kChunkJson) {
            if (sawJson) {
                return std::unexpected(GltfError{"GLB に JSON チャンクが 2 つある"});
            }
            jsonChunk.assign(data.data() + position, chunkLength);
            sawJson = true;
        } else if (chunkType == kChunkBinary) {
            const auto* begin = reinterpret_cast<const std::uint8_t*>(data.data() + position);
            binaryChunk.assign(begin, begin + chunkLength);
        }
        // 未知のチャンクは仕様上「無視すること」と定められている

        position += chunkLength;
    }

    if (!sawJson) {
        return std::unexpected(GltfError{"GLB に JSON チャンクがない"});
    }

    auto parsed = JsonParser::Parse(jsonChunk);
    if (!parsed) {
        return std::unexpected(GltfError{
            std::format("GLB の JSON: {} ({} 行)",
                        parsed.error().message, parsed.error().line)});
    }

    GltfDocument doc;
    doc.json_ = std::move(*parsed);
    doc.buffers_.resize(doc.json_["buffers"].Size());
    if (!doc.buffers_.empty()) {
        // buffers[0] だけが BIN チャンクを指す（uri がない）。
        // buffers[1] 以降に uri があれば外部ファイルだが、本書では扱わない。
        if (!doc.json_["buffers"][0].Has("uri")) {
            doc.buffers_[0] = std::move(binaryChunk);
        }
    }
    return doc;
}
```

**「未知のチャンクは無視する」**のが仕様です。将来の拡張のための余地で、この設計のおかげで、新しいチャンク型が追加されても古い読み込み側が壊れません。

`position += chunkLength` でパディングを飛び越えられるのは、36.2 節で述べたとおり `chunkLength` にパディングが含まれるからです。

### 形態の自動判別

呼び出し側では、拡張子ではなく**マジックナンバーで判別**します。

```cpp
std::expected<GltfDocument, GltfError>
GltfDocument::LoadFromFile(const std::filesystem::path& path) {
    std::ifstream file(path, std::ios::binary);
    if (!file) {
        return std::unexpected(GltfError{"ファイルを開けない: " + path.string()});
    }
    std::string data((std::istreambuf_iterator<char>(file)),
                      std::istreambuf_iterator<char>());

    // 拡張子ではなく中身で判別する
    if (data.size() >= 4 && ReadU32(data.data()) == kGlbMagic) {
        return LoadGlb(data);
    }
    return LoadGltfText(data, path.parent_path());
}
```

拡張子を信用しない理由は単純で、**`.gltf` という名前の GLB ファイルが実在する**からです。逆もあります。中身を見るほうが確実です。

`AnimLib.Tests/GlbTests.cpp`：

```cpp
#include "CppUnitTest.h"

#include "TestSupport/GltfTestData.h"

using namespace anim;

namespace AnimLibTests {

TEST_CLASS(GlbTests) {
public:

    // --- 読み込み -------------------------------------------------

    TEST_METHOD(LoadsGlb) {
        const auto doc = GltfDocument::LoadFromFile(
            anim::test::TestDataDir() / "cylinder.glb");
        Assert::IsTrue(doc.has_value());
        Assert::AreEqual(std::string("2.0"), doc->Json()["asset"]["version"].AsString());
        Assert::AreEqual(std::size_t{1}, doc->Json()["meshes"].Size());
    }

    // 拡張子ではなく中身で判別すること（36.3 節）
    TEST_METHOD(DetectsFormatByContentNotExtension) {
        // 中身は GLB だが .gltf という名前のファイル
        const auto path = anim::test::CopyTestFile("cylinder.glb", "misnamed.gltf");
        const auto doc = GltfDocument::LoadFromFile(path);
        Assert::IsTrue(doc.has_value());
        Assert::AreEqual(std::size_t{1}, doc->Json()["skins"].Size());
    }

    // 同じモデルを 3 つの形態から読み、アクセサの中身がビット単位で
    // 一致することを確認する。「入れ物が違うだけ」の実行可能な証明。
    TEST_METHOD(AllThreeContainersGiveIdenticalData) {
        const auto separate = GltfDocument::LoadFromFile(
            anim::test::TestDataDir() / "cylinder.gltf");
        const auto embedded = GltfDocument::LoadFromFile(
            anim::test::TestDataDir() / "cylinder_embedded.gltf");
        const auto binary = GltfDocument::LoadFromFile(
            anim::test::TestDataDir() / "cylinder.glb");

        Assert::IsTrue(separate.has_value());
        Assert::IsTrue(embedded.has_value());
        Assert::IsTrue(binary.has_value());

        const std::size_t accessorCount = separate->Json()["accessors"].Size();
        Assert::AreEqual(accessorCount, embedded->Json()["accessors"].Size());
        Assert::AreEqual(accessorCount, binary->Json()["accessors"].Size());

        for (int i = 0; i < static_cast<int>(accessorCount); ++i) {
            const auto a = separate->ReadAccessorAsFloat(i);
            const auto b = embedded->ReadAccessorAsFloat(i);
            const auto c = binary->ReadAccessorAsFloat(i);

            Assert::AreEqual(a.size(), b.size());
            Assert::AreEqual(a.size(), c.size());
            for (std::size_t k = 0; k < a.size(); ++k) {
                Assert::IsTrue(a[k] == b[k]);   // 厳密な一致
                Assert::IsTrue(a[k] == c[k]);
            }
        }
    }

    // 上位の層でも一致すること
    TEST_METHOD(SkeletonAndClipMatchAcrossContainers) {
        for (const char* file : {"cylinder.gltf", "cylinder_embedded.gltf", "cylinder.glb"}) {
            const auto doc = GltfDocument::LoadFromFile(anim::test::TestDataDir() / file);
            const auto skeleton = LoadSkeleton(*doc, 0);
            const auto clip = LoadAnimation(*doc, 0, *skeleton, nullptr);

            Assert::AreEqual(std::size_t{2}, skeleton->skeleton.BoneCount());

            anim::test::AssertNear(1.0f, clip->Duration(), test::kEpsPos);

    TEST_METHOD(RejectsBadMagic) {
        const auto path = anim::test::WriteCorruptGlb(
            anim::test::GlbCorruption::BadMagic);
        Assert::IsFalse(GltfDocument::LoadFromFile(path).has_value());
    }

    TEST_METHOD(RejectsWrongVersion) {
        const auto path = anim::test::WriteCorruptGlb(

        const auto doc = GltfDocument::LoadFromFile(path);
        Assert::IsFalse(doc.has_value());
        Assert::IsTrue(doc.error().message.find("バージョン") != std::string::npos);
    }

    TEST_METHOD(RejectsTruncatedFile) {
        const auto path = anim::test::WriteCorruptGlb(

    // --- 未知のチャンク（36.3 節）--------------------------------

    // 仕様どおり、未知のチャンクは無視して読み進めること
    TEST_METHOD(UnknownChunksAreSkipped) {
        const auto path = anim::test::WriteGlbWithExtraChunk();
        const auto doc = GltfDocument::LoadFromFile(path);

        Assert::IsTrue(doc.has_value());
        // 未知チャンクの後ろにある BIN チャンクも正しく読めていること
        const auto positions = doc->ReadAccessorAsFloat(0);
        Assert::AreEqual(std::size_t{158 * 3}, positions.size());
    }

    // --- パディング -----------------------------------------------

    // JSON チャンクの末尾がスペースで埋められていても読めること
    TEST_METHOD(JsonChunkPaddingIsHandled) {
        const auto doc = GltfDocument::LoadFromFile(
            anim::test::TestDataDir() / "cylinder.glb");
        Assert::IsTrue(doc.has_value());
        // パディングがパーサを止めていないことは、読めた時点で確認できている
        Assert::AreEqual(std::size_t{3}, doc->Json()["nodes"].Size());
    }
};

}  // namespace AnimLibTests
```

`AllThreeContainersGiveIdenticalData` が、この章の中心です。第 29 章で「中身は同じで、入れ物が違うだけ」と書いた主張の、**実行可能な証明**になっています。

`==` による厳密な一致を要求している点に注意してください。第 20 章では「ビット一致に依存するな」と書きましたが、ここは**同じバイト列を違う経路で読んでいる**だけなので、1 ビットも違ってはいけません。Base64 デコードのバグ、オフセット計算のずれ ―― どれもここで捕まります。

壊れた GLB のテストを 5 つ用意したのは、**バイナリフォーマットのパーサは「壊れた入力」への耐性が品質そのもの**だからです。第 31 章で JSON の不正な入力を 11 種類テストしたのと同じ考え方です。

## 36.5　つまずきやすいところ

**GLB が読めない**
マジックナンバーの読み方を確認してください。`0x46546C67` はリトルエンディアンで `"glTF"` です。文字列として `"glTF"` と比較する実装でも構いませんが、その場合エンディアンの考慮が不要になる代わりに、バイト列の比較になります。

**JSON チャンクのパースが失敗する**
末尾のスペースパディングでパーサが止まっていませんか。第 30 章の実装は空白を読み飛ばすので問題ありませんが、末尾の余分なデータを検査する処理（第 31 章）が空白を「余分」と判定しないか確認してください。**本書の `SkipWhitespace` は末尾の空白も飛ばすので、`End` トークンが返ります。**

**BIN チャンクが空になる**
チャンク型の定数を確認してください。`"BIN\0"` は `0x004E4942` で、末尾がゼロバイトです。`"BIN"` の 3 文字だと一致しません。

**チャンクの読み進めがずれる**
`position += 8`（チャンクヘッダ）と `position += chunkLength`（データ）の両方が必要です。

**`.gltf` という名前の GLB が読めない**
拡張子で判別しています。マジックナンバーを見てください（36.3 節）。

**外部バッファを持つ GLB が読めない**
仕様上、GLB でも `buffers[1]` 以降が外部ファイルを参照できます。本書は扱いませんが、実在するなら `uri` を見て第 32 章の経路に回してください。

## この章のまとめ

- GLB は **ヘッダ（12 B）+ チャンクの列**。すべてリトルエンディアンの `uint32`。
- マジックは `"glTF"`、JSON チャンクは `"JSON"`、BIN チャンクは `"BIN\0"`（末尾がゼロバイト）。
- **パディングの埋め文字が違う** ―― JSON はスペース、BIN はゼロ。JSON をそのまま文字列としてパースできるようにするため。
- **パディングは `chunkLength` に含まれる**ので、読む側は特別な処理が要らない。
- **未知のチャンクは無視する**のが仕様。将来の拡張への備え。
- **形態の判別は拡張子ではなくマジックナンバーで。** `.gltf` という名前の GLB は実在する。
- **3 つの形態から読んだデータがビット単位で一致する**ことをテストする。第 29 章の「入れ物が違うだけ」という主張の、実行可能な証明。
- バイナリフォーマットのパーサは、**壊れた入力への耐性が品質そのもの**。5 種類の壊れた GLB をテストに入れた。
