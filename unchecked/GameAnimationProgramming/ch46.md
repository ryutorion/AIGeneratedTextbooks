# 第 46 章　IK とは何か

**この章で作るもの**：IK チェーンの表現と、すべての IK ソルバが共通で使う 2 つの小さな道具 ―― **グローバル回転をローカルへ書き戻す関数**と、**ある方向を別の方向へ回す最小回転**。第 47 章以降のソルバは、この 2 つの上に建ちます。

---

## 46.1　FK と IK

ここまでの 45 章でやってきたことは、すべて **FK（Forward Kinematics、順運動学）** です。

```
ローカル回転が与えられる  →  階層をたどる  →  末端の位置が決まる
       （入力）                                    （出力）
```

第 14 章の `ComputeGlobalPose` がまさにそれです。腰の回転、腿の回転、すねの回転を与えると、足首がどこに来るかが**計算の結果として**出てきます。

**IK（Inverse Kinematics、逆運動学）** は矢印を逆に向けます。

```
末端をここに置きたい  →  ???  →  そうなるローカル回転を求める
     （入力）                          （出力）
```

「足首をこの座標に置きたい。そのとき腿とすねはどう回っていればいいか」を解く問題です。

**なぜ「逆」が難しいのか。** FK は一方通行の計算です。入力を入れれば答えが 1 つ出ます。IK はそうではありません。

- **解が無数にある。** 肩を固定して手先の位置だけ指定すると、肘はぐるりと一周どこにでも置けます。どれも手先の位置は同じです。
- **解が 1 つもないことがある。** 腕の長さの合計より遠い点は、どうやっても届きません。
- **解が 1 つだけのこともある。** 腕を完全に伸ばしきった位置は、ただ 1 通りです。

FK には「答えがない」も「答えが無数にある」もありません。この非対称性が、IK を難しくしています。

## 46.2　ゲームで IK が要る場面

理屈より、実際に何に使うかを先に見ておきます。

**① 足の接地（フット IK）。** 歩行アニメーションは平らな床を想定して作られています。階段や坂ではそのままだと足が地面にめり込むか、宙に浮きます。地面の高さを測り、足首をそこへ動かす。第 51 章の主題です。

**② 武器や物の保持。** 両手で銃を構えるとき、右手はグリップ、左手はフォアグリップに固定したい。しかし胴体は照準やダメージリアクションで動きます。動いた結果に対して、手を目標へ引き戻す。

**③ 注視（ルックアット）。** キャラクターがプレイヤーや会話相手のほうを見る。首と頭を少しずつ回して、視線を目標へ向ける。第 50 章で扱います。

**④ 壁や机への手の接触。** 狭い通路で壁に手をつく、机に手を置く。

共通しているのは、**アニメーションデータを作った時点では目標が分からない**ということです。地形も、相手の位置も、実行時にしか決まりません。だから実行時に計算でポーズを曲げます。

## 46.3　IK はパイプラインのどこに入るか

第 1 章の 6 段パイプラインを再掲します。

```
① クリップをサンプル
② ブレンド
③ 階層を解く          ← ここでグローバルポーズが確定する
④ IK で補正           ← この章から
⑤ パレットを作る
⑥ 頂点を変形
```

**IK は ③ の後、⑤ の前**に入ります。つまり、

1. アニメーションが「素のポーズ」を作る
2. 階層を解いて、各ボーンのグローバル姿勢が分かる
3. **IK が「素のポーズ」を目標に合わせて曲げる**
4. 曲げた結果からパレットを作る

ここで極めて重要な性質が 1 つあります。

> **IK は毎フレーム、アニメーションが作り直した素のポーズに対して適用する。前フレームの補正結果の上に重ねてはいけない。**

当たり前に聞こえますが、これを破ると何が起きるかは第 51 章で実測します（結論だけ先に書くと、足が目標を 20% 行き過ぎたあと数秒かけて戻ってきます）。IK は**状態を持たない関数**として設計するのが基本で、時間方向の連続性が要るときだけ、平滑化のための状態を**明示的に外に置きます**。

## 46.4　IK チェーン

IK が触るボーンの並びを **IK チェーン**と呼びます。

```
    thigh ──→ shin ──→ foot
    （根元）           （末端＝エフェクタ）
```

末端のボーンを**エフェクタ**（effector、末端効果器）と言います。エフェクタを目標へ持っていくのが IK の仕事です。

表現は素直に、ボーン番号の配列にします。

```cpp
// AnimLib/include/anim/Ik.h
#pragma once

#include "anim/Blend.h"

#include <numbers>
#include <span>
#include <vector>

namespace anim {

inline constexpr float kIkPi = std::numbers::pi_v<float>;

// IK が触るボーンの並び。根元 → 末端の順。
// 直系（chain[i] が chain[i+1] の親）であることを前提とする。
struct IkChain {
    std::vector<BoneIndex> bones;

    [[nodiscard]] std::size_t Size() const { return bones.size(); }
};

}  // namespace anim
```

**「直系である」という前提**は書いておく価値があります。`{thigh, shin, foot}` は直系ですが、`{thigh, foot}`（すねを飛ばす）や `{leftFoot, rightFoot}`（兄弟）はチェーンになりません。第 13 章のスケルトンと同じで、**前提を明文化しておくと、テストで検証できます**。

第 13 章の不変条件 `parents[i] < i` があるので、直系かどうかは簡単に確かめられます。

```cpp
inline bool IsValidChain(const Skeleton& s, const IkChain& chain) {
    if (chain.Size() < 2) return false;
    for (std::size_t i = 1; i < chain.Size(); ++i)
        if (s.ParentOf(chain.bones[i]) != chain.bones[i-1]) return false;
    return true;
}
```

## 46.5　道具 その 1：グローバル回転をローカルへ書き戻す

IK ソルバが考える世界は**グローバル座標**です。「肩から目標へのベクトル」も「肘の位置」も、ワールド空間の話です。

しかし `Pose` が持っているのは**ローカル変換**です（第 14 章）。ソルバが「このボーンをグローバルでこう回したい」と決めたら、それをローカルへ翻訳して書き戻さなければなりません。

第 14 章の関係を思い出します。

```
global[i] = global[parent] * local[i]
```

回転だけ取り出せば、

```
globalRot[i] = globalRot[parent] * localRot[i]
```

したがって、望むグローバル回転 `R` に対して、

```
localRot[i] = globalRot[parent]⁻¹ * R
```

クォータニオンの逆元は、単位クォータニオンなら共役です（第 8 章）。

```cpp
// グローバル回転を指定して、対応するローカル回転を書き戻す。
// global[] は呼び出し時点で最新であること。
inline void SetGlobalRotation(const Skeleton& s, Pose& local,
                              std::span<const Transform> global,
                              BoneIndex bone, const Quat& newGlobalRot) {
    const BoneIndex p = s.ParentOf(bone);
    const Quat parentRot = (p == kNoParent) ? QuatIdentity() : global[p].rotation;
    local[bone].rotation = Conjugate(parentRot) * newGlobalRot;
}
```

15 行にも満たない関数ですが、**この関数には後で 1 行足すことになります**。第 48 章で、CCD が収束しない原因を追いかけたときに見つかります。今はこのまま進めます。

**注意：`global[]` は最新でなければならない。** この関数は「親のグローバル回転」を `global[p]` から読みます。もし別のボーンを書き換えたあとで `global[]` を再計算せずに呼ぶと、古い親の回転を使ってしまいます。IK ソルバのループでは、**1 関節動かすたびに `global[]` を更新する**のが基本形になります。

## 46.6　道具 その 2：ある方向を別の方向へ回す

IK ソルバの中で最も多く呼ばれる操作は、これです。

> ベクトル **from** を、ベクトル **to** の向きへ回す。最小の回転で。

CCD は「関節からエフェクタへのベクトル」を「関節から目標へのベクトル」に向けます。FABRIK は位置を先に決めたあと、「現在のボーン方向」を「求めた方向」に向けます。2 ボーン IK も同じ操作を 2 回使います。

素直に書くと、こうなります。回転軸は 2 つのベクトルの外積、回転角は内積の `acos`。

```cpp
// from を to へ回す最小回転（第 1 版）
inline Quat FromToRotation(Vec3 from, Vec3 to) {
    const Vec3 f = NormalizeSafe(from, {1,0,0});
    const Vec3 t = NormalizeSafe(to,   {1,0,0});
    const float d = Dot(f, t);

    if (d >  0.99999f) return QuatIdentity();      // ほぼ同じ向き
    if (d < -0.99999f) {                            // ほぼ真逆：軸が決まらない
        Vec3 axis = Cross(f, Vec3{1,0,0});
        if (LengthSquared(axis) < 1.0e-6f) axis = Cross(f, Vec3{0,1,0});
        return MakeQuatAxisAngle(Normalize(axis), kIkPi);
    }

    const float clamped = std::fmin(1.0f, std::fmax(-1.0f, d));
    return MakeQuatAxisAngle(Normalize(Cross(f,t)), std::acos(clamped));
}
```

3 つの場所に地雷があります。

**① `acos` の前のクランプ。** 第 9 章・第 10 章とまったく同じ話です。`f` と `t` を正規化しても、丸め誤差で `Dot` が `1.0000001` になることがあります。`std::acos(1.0000001)` は NaN です。ここでは早期リターンでほぼ弾いていますが、**弾いた後もクランプする**のが習慣として正しい。

**② 真逆の場合、回転軸が決まらない。** `f` と `t` が正反対のとき `Cross(f,t)` はゼロベクトルです。「180 度回す」ことは決まっていても、**どの軸まわりに 180 度回すかは決まりません**。`f` に垂直ならどれでもいい。ここでは `X` 軸との外積を取り、それが退化していれば `Y` 軸で取り直しています。

**③ 早期リターンのしきい値。** `d > 0.99999f` は「ほぼ同じ向きなので何もしない」という判断です。妥当に見えます。**これが後で問題になります。**

## 46.7　単体テスト：FromToRotation

まず基本から。

```cpp
// AnimLib.Tests/IkBasicsTests.cpp
#include "CppUnitTest.h"
#include "anim/Ik.h"

using namespace Microsoft::VisualStudio::CppUnitTestFramework;
using namespace anim;

TEST_CLASS(FromToRotationTests) {
public:
    TEST_METHOD(RotatesFromOntoTo) {
        const Vec3 f{1,0,0}, t{0,1,0};
        const Vec3 r = Rotate(FromToRotation(f,t), f);
        Assert::AreEqual(0.0f, r.x, 1e-6f);
        Assert::AreEqual(1.0f, r.y, 1e-6f);
        Assert::AreEqual(0.0f, r.z, 1e-6f);
    }

    TEST_METHOD(SameDirectionGivesIdentity) {
        const Quat q = FromToRotation({1,0,0}, {2,0,0});
        Assert::AreEqual(1.0f, q.w, 1e-6f);
    }

    TEST_METHOD(OppositeDirectionIsFinite) {
        const Vec3 f{1,0,0};
        const Vec3 r = Rotate(FromToRotation(f, {-1,0,0}), f);
        Assert::AreEqual(-1.0f, r.x, 1e-5f);
    }
};
```

`OppositeDirectionIsFinite` は測ると `(-1.000000, 0.000000, 0.000000)` になります。軸の選び方は任意ですが、**結果は一意に決まる**ことが確認できます。

次に、この本で何度も使ってきた**性質のテスト**を。1000 通りのランダムな方向で、「`from` を回したら `to` になる」ことを確かめます。

```cpp
TEST_METHOD(RandomDirectionsAlwaysAlign) {
    unsigned seed = 12345;
    auto rnd = [&] { seed = seed*1664525u + 1013904223u;
                     return static_cast<float>((seed>>8) & 0xFFFF)/32767.5f - 1.0f; };
    float worst = 0.0f;
    for (int i = 0; i < 1000; ++i) {
        const Vec3 a{rnd(),rnd(),rnd()}, b{rnd(),rnd(),rnd()};
        if (LengthSquared(a) < 0.01f || LengthSquared(b) < 0.01f) continue;
        const Vec3 got = Rotate(FromToRotation(a,b), Normalize(a));
        worst = std::fmax(worst, Length(got - Normalize(b)));
    }
    Logger::WriteMessage(std::format("最大誤差 {:.9f}\n", worst).c_str());
    Assert::IsTrue(worst < 1e-5f);
}
```

実測 **`0.000003457`**。`float` の精度としては妥当です。

## 46.8　小さな角度を測る

ここで、あとで効いてくる測定を 1 つだけ済ませておきます。

`FromToRotation` は IK ソルバの内側ループで呼ばれます。反復が進むと、エフェクタは目標に近づき、**回す角度はどんどん小さくなります**。つまりこの関数は「ごく小さい角度」を精度よく作れる必要があります。

`X` 軸を、既知の角度 θ だけ回したベクトルへ向ける ―― という形で誤差を測ります。

```cpp
TEST_METHOD(SmallAngleAccuracy) {
    for (float ang : {1e-1f, 1e-2f, 1e-3f, 1e-4f, 1e-5f, 1e-6f}) {
        const Vec3 f{1,0,0};
        const Vec3 t{std::cos(ang), std::sin(ang), 0};
        const Vec3 r = Rotate(FromToRotation(f,t), f);
        const float got = std::atan2(r.y, r.x);
        Logger::WriteMessage(
            std::format("角度 {:.8f} -> 誤差 {:.3e}\n", ang, std::fabs(got-ang)).c_str());
    }
}
```

結果です。

```
真の角度        誤差
0.10000000    1.267e-07
0.01000000    8.717e-07
0.00100000    1.000e-03      ← 誤差 = 角度そのもの
0.00010000    1.000e-04      ← 同上
0.00001000    1.000e-05      ← 同上
0.00000100    1.000e-06      ← 同上
```

**0.001 ラジアン以下で、誤差が角度そのものになっています。** つまり**まったく回していない**。

原因は `d > 0.99999f` の早期リターンです。cos(0.001) = 0.9999995 なので、しきい値を超えてしまい、単位クォータニオンが返る。**0.00447 ラジアン（0.26 度）より小さい回転は、この関数では起こりません。**

さらに、しきい値を通り抜けた 0.01 ラジアンでも誤差は `8.7e-7` あります。角度 0.1 のときの `1.3e-7` より**大きい**。これは `acos` の性質です。`acos(x)` を `x = 1` の近くで微分すると `-1/√(1-x²)` で、これは発散します。**`x` のわずかな誤差が、角度の大きな誤差に化ける。**

## 46.9　三角関数を使わない書き方

この 2 つの問題 ―― 早期リターンのしきい値と `acos` の精度 ―― は、**同時に消せます**。三角関数を一切使わずにクォータニオンを作ればいい。

第 8 章で、軸 `n` まわり角 θ のクォータニオンは

```
q = (n·sin(θ/2), cos(θ/2))
```

でした。ここに半角の公式を持ち込みます。`f` と `t` の**中間のベクトル** `h = normalize(f + t)` を考えると、`f` から `h` への角は θ/2 です。すると、

```
Cross(f, h) = n · sin(θ/2)
Dot  (f, h) = cos(θ/2)
```

つまり `q = (Cross(f,h), Dot(f,h))` です。正規化を後回しにすれば `h` を求める割り算も要りません。`f + t` をそのまま使うと、

```
Cross(f, f+t) = Cross(f,t)
Dot  (f, f+t) = 1 + Dot(f,t)
```

**`q = normalize( (Cross(f,t), 1 + Dot(f,t)) )`**。`acos` も `sin` も `cos` も出てきません。

```cpp
// from を to へ回す最小回転（第 2 版・三角関数なし）
inline Quat FromToRotation(Vec3 from, Vec3 to) {
    const Vec3 f = NormalizeSafe(from, {1,0,0});
    const Vec3 t = NormalizeSafe(to,   {1,0,0});
    const float d = Dot(f, t);

    if (d < -0.99999f) {                    // 真逆のときだけ特別扱いが要る
        Vec3 axis = Cross(f, Vec3{1,0,0});
        if (LengthSquared(axis) < 1.0e-6f) axis = Cross(f, Vec3{0,1,0});
        axis = Normalize(axis);
        return {axis.x, axis.y, axis.z, 0.0f};   // 軸まわり 180 度
    }

    const Vec3 c = Cross(f, t);
    return Normalize(Quat{c.x, c.y, c.z, 1.0f + d});
}
```

**同じ向きの側に早期リターンが要らなくなった**ことに注目してください。`f == t` なら `Cross` はゼロ、`1+d` は 2 で、正規化すると `(0,0,0,1)` ―― 単位クォータニオンがそのまま出ます。特別扱いせずに正しい答えが出るなら、`if` を書く理由はありません。

真逆の側だけは残ります。`f == -t` だと `Cross` がゼロ、`1+d` もゼロで、`(0,0,0,0)` を正規化することになるからです。ゼロ除算は避けなければなりません。

同じ測定をやり直します。

```
真の角度        acos 版        三角関数なし版
0.10000000    1.267e-07      7.451e-09
0.01000000    8.717e-07      2.794e-09
0.00100000    1.000e-03      0.000e+00
0.00010000    1.000e-04      0.000e+00
0.00001000    1.000e-05      0.000e+00
0.00000100    1.000e-06      0.000e+00
```

**小さい角度で誤差がゼロ**、大きめの角度でも 100〜300 倍の改善。速度も速いはずです（`acos` と `sin`・`cos` が消え、平方根 1 回だけになる）。

古い実装は `FromToRotationAcos` という名前で残しておきます。第 48 章で「なぜこちらではダメなのか」を実測で示すためです。

```cpp
TEST_METHOD(StableVersionBeatsAcosAtSmallAngles) {
    const float ang = 1.0e-3f;
    const Vec3 f{1,0,0};
    const Vec3 t{std::cos(ang), std::sin(ang), 0};
    const float acosErr   = std::fabs(std::atan2(Rotate(FromToRotationAcos(f,t),f).y,
                                                 Rotate(FromToRotationAcos(f,t),f).x) - ang);
    const float stableErr = std::fabs(std::atan2(Rotate(FromToRotation(f,t),f).y,
                                                 Rotate(FromToRotation(f,t),f).x) - ang);
    Assert::IsTrue(acosErr   > 1e-4f);     // acos 版は「何もしない」
    Assert::IsTrue(stableErr < 1e-8f);     // 安定版は正しく回す
}
```

**このテストは「片方が壊れていること」を主張しています。** 第 3 章・第 21 章と同じで、壊れ方を固定するのもテストの仕事です。もし将来 `FromToRotationAcos` を「直して」しまったら、このテストが赤くなって、第 48 章の説明と食い違ったことを教えてくれます。

## 46.10　IK ソルバの共通の形

第 47 章から 3 種類のソルバを作りますが、外から見た形は揃えておきます。

```cpp
// 反復ソルバの結果
struct IkSolveResult {
    bool  converged  = false;   // 許容誤差以内に収まったか
    int   iterations = 0;       // 実際に回した反復数
    float residual   = 0.0f;    // 最終的なエフェクタと目標の距離
};
```

**`converged` と `residual` の両方を返す**のは意図的です。`converged == false` でも「あと一歩だった」のか「まったく届かなかった」のかは大違いで、呼び出し側の判断（IK を諦めて素のポーズに戻す／部分的に適用する）が変わります。

そして 3 つとも、引数の形はこうします。

```cpp
IkSolveResult SolveXxx(const Skeleton& s,             // 骨格（読み取り専用）
                       Pose& local,                    // ここを書き換える
                       std::vector<Transform>& global, // 作業用バッファ
                       const IkChain& chain,
                       Vec3 target,
                       int maxIterations, float tolerance);
```

**`global` を引数で受け取る**のは、第 14 章から掲げてきた「毎フレーム 1 回もアロケートしない」という方針のためです。ソルバの中で `std::vector` を作ると、100 体のキャラクターで毎フレーム 100 回のアロケーションが起きます。呼び出し側が持っているバッファを使い回します。

## この章のまとめ

- **FK は入力から出力への一方通行、IK は出力から入力への逆算**。解が無数にあるか、1 つもないか、どちらかであることが多い ―― この非対称性が IK を難しくしている。
- IK はパイプラインの **③ 階層解決の後、⑤ パレット生成の前**に入る。**毎フレーム、素のポーズに対して適用する**（前フレームの補正結果に重ねない ―― 第 51 章で実測）。
- **IK チェーンは直系のボーン列**。前提を明文化すると `IsValidChain` で検証できる。
- `SetGlobalRotation` は `localRot = parentGlobalRot⁻¹ * 望むグローバル回転`。**呼ぶ前に `global[]` が最新であること**が前提。この関数には第 48 章で 1 行足すことになる。
- `FromToRotation` は `acos` で書ける ―― が、**0.00447 ラジアン以下の回転が起きなくなる**（早期リターン）うえ、`acos` は 1 の近くで精度を失う（実測：角度 0.01 で誤差 `8.7e-7`）。
- **中間ベクトルを使えば三角関数なしで書ける**：`q = normalize((Cross(f,t), 1+Dot(f,t)))`。小角度の誤差が **`0.000e+00`** になり、同方向の早期リターンも不要になる。**特別扱いせずに正しい答えが出るなら、`if` を書かない。**

次章では、この 2 つの道具を使って **2 ボーン IK** を書きます。腕や脚 ―― ゲームで最もよく使う IK であり、しかも**反復せずに解析的に解ける**唯一のケースです。
