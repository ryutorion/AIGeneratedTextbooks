# 第 35 章　アニメーションを読む

**この章で作るもの**：glTF の `animations` から、第 V 部の `Clip` を組み立てる処理。前章の対応表がそのまま使えるので、ここは素直です。そして最後に、**実データで第 21 章のキャンディラッパー現象を再現**します。

---

## 35.1　`samplers` と `channels`

glTF のアニメーションは、2 つの配列でできています。

```json
"animations": [
  {
    "name": "Twist",
    "samplers": [
      { "input": 6, "output": 7, "interpolation": "LINEAR" },
      { "input": 6, "output": 8, "interpolation": "LINEAR" }
    ],
    "channels": [
      { "sampler": 0, "target": { "node": 2, "path": "rotation" } },
      { "sampler": 1, "target": { "node": 2, "path": "translation" } }
    ]
  }
]
```

**サンプラー**は「時刻の配列」と「値の配列」の組です。`input` が時刻の accessor、`output` が値の accessor。第 23 章の `Track` とほぼ同じものです。

**チャンネル**は「どのサンプラーを、どのノードのどのプロパティに適用するか」を指定します。

なぜ分かれているのか ―― **サンプラーを共有できる**からです。上の例では、2 つのチャンネルが同じ `input`（時刻の配列 6）を使っています。10 個のボーンが同じタイミングでキーを打たれているなら、時刻の配列は 1 つで済みます。

**時刻の配列を共有するのは、実データでは非常に多いパターン**です。DCC ツールは全ボーンのキーを同じフレームに打つのが普通だからです。

## 35.2　`path` の対応づけ

`target.path` は 4 種類です。

| `path` | 本書のトラック |
| --- | --- |
| `"translation"` | `BoneTracks::translation`（`Vec3`） |
| `"rotation"` | `BoneTracks::rotation`（`Quat`、`(x,y,z,w)`） |
| `"scale"` | `BoneTracks::scale`（`Vec3`） |
| `"weights"` | モーフターゲット。**本書では扱わない** |

`"weights"` は無視しますが、**黙って無視するのではなく報告します**（第 29 章の方針）。

```cpp
// AnimLib/include/anim/GltfAnimation.h

[[nodiscard]] std::expected<Clip, GltfError>
LoadAnimation(const GltfDocument& doc, int animationIndex,
              const GltfSkeleton& skeleton, AnimationLoadReport* report);
```

```cpp
std::expected<Clip, GltfError>
LoadAnimation(const GltfDocument& doc, int animationIndex,
              const GltfSkeleton& skel, AnimationLoadReport* report) {
    const JsonValue& animation =
        doc.Json()["animations"][static_cast<std::size_t>(animationIndex)];

    Clip clip;
    clip.Resize(skel.skeleton.BoneCount());
    clip.SetLoopMode(LoopMode::Loop);
    float duration = 0.0f;

    for (const JsonValue& channel : animation["channels"].AsArray()) {
        const JsonValue& target = channel["target"];

        // ① 対象ノードをボーンに変換する（第 34 章の対応表）
        if (!target.Has("node")) {
            continue;   // ノードのないチャンネルは仕様上ありうる。無視してよい
        }
        const int node = target["node"].AsInt();
        if (node < 0 || node >= static_cast<int>(skel.nodeToBone.size())) {
            return std::unexpected(GltfError{"チャンネルのノード番号が範囲外"});
        }
        const int bone = skel.nodeToBone[static_cast<std::size_t>(node)];
        if (bone < 0) {
            // このスキンのジョイントではないノード。カメラやメッシュのアニメーション
            if (report != nullptr) { ++report->channelsOutsideSkin; }
            continue;
        }

        // ② サンプラーを取り出す
        const int samplerIndex = channel["sampler"].AsInt();
        const JsonValue& sampler =
            animation["samplers"][static_cast<std::size_t>(samplerIndex)];

        const auto times  = doc.ReadAccessorAsFloat(sampler["input"].AsInt());
        const auto values = doc.ReadAccessorAsFloat(sampler["output"].AsInt());
        if (times.empty()) {
            return std::unexpected(GltfError{"サンプラーの input が空"});
        }
        for (const float t : times) { duration = std::fmax(duration, t); }

        const Interpolation mode = ParseInterpolation(sampler["interpolation"].AsString());

        // ③ トラックに流し込む
        const std::string& path = target["path"].AsString();
        if (path == "translation") {
            FillVec3Track(clip.Bone(static_cast<BoneIndex>(bone)).translation,
                          times, values, mode);
        } else if (path == "scale") {
            FillVec3Track(clip.Bone(static_cast<BoneIndex>(bone)).scale,
                          times, values, mode);
        } else if (path == "rotation") {
            FillQuatTrack(clip.Bone(static_cast<BoneIndex>(bone)).rotation,
                          times, values, mode);
        } else if (path == "weights") {
            if (report != nullptr) { ++report->morphChannelsIgnored; }
        } else {
            return std::unexpected(GltfError{"未知の path: " + path});
        }
    }

    clip.SetDuration(duration);
    return clip;
}
```

**`bone < 0` を `continue` で飛ばす**のが要点です。glTF のアニメーションは、スキンのジョイント以外のノードも動かせます（カメラ、小道具、メッシュノード自体）。それらは本書の `Clip` には入りません。**エラーではなく、無視して記録する**のが適切です。

## 35.3　補間モード

```cpp
[[nodiscard]] inline Interpolation ParseInterpolation(std::string_view name) {
    if (name == "STEP")        { return Interpolation::Step; }
    if (name == "CUBICSPLINE") { return Interpolation::CubicSpline; }
    return Interpolation::Linear;   // 既定。未知の値もここに落とす
}
```

## 35.4　CUBICSPLINE のデータ配置

`LINEAR` と `STEP` では、`output` の accessor には**値がそのまま**並んでいます。キーが 3 個で `VEC3` なら、float が 9 個。

`CUBICSPLINE` では違います。**キーごとに 3 つ組が並びます。**

```
[ inTangent₀, value₀, outTangent₀,  inTangent₁, value₁, outTangent₁, ... ]
```

つまり要素数が 3 倍です。キーが 3 個で `VEC3` なら、float が 27 個。

```cpp
void FillVec3Track(Track<Vec3>& track, std::span<const float> times,
                   std::span<const float> values, Interpolation mode) {
    track.SetInterpolation(mode);

    if (mode == Interpolation::CubicSpline) {
        // キーごとに inTangent, value, outTangent の 3 つ組
        ANIM_ASSERT(values.size() == times.size() * 9);
        for (std::size_t k = 0; k < times.size(); ++k) {
            const std::size_t base = k * 9;
            track.AddKeyCubic(times[k],
                              Vec3{values[base + 3], values[base + 4], values[base + 5]},
                              Vec3{values[base + 0], values[base + 1], values[base + 2]},
                              Vec3{values[base + 6], values[base + 7], values[base + 8]});
        }
    } else {
        ANIM_ASSERT(values.size() == times.size() * 3);
        for (std::size_t k = 0; k < times.size(); ++k) {
            track.AddKey(times[k],
                         Vec3{values[k*3 + 0], values[k*3 + 1], values[k*3 + 2]});
        }
    }
    track.Finalize();
}
```

**要素数の検査を必ず入れてください。** `CUBICSPLINE` を `LINEAR` として読むと、キーの値として接線を読むことになります。**モデルは動きますが、まったく違う動きになります** ―― そして「エクスポート設定が悪いのかな」と何時間も悩むことになります。

`ANIM_ASSERT` は Release で消えるので、実データを扱う経路では `std::expected` で返すほうが適切です。

```cpp
    const std::size_t expected = times.size() * (mode == Interpolation::CubicSpline ? 9 : 3);
    if (values.size() != expected) {
        return std::unexpected(GltfError{
            std::format("サンプラーの output の要素数が合わない（期待 {}、実際 {}）",
                        expected, values.size())});
    }
```

### クォータニオンの場合

```cpp
void FillQuatTrack(Track<Quat>& track, std::span<const float> times,
                   std::span<const float> values, Interpolation mode) {
    track.SetInterpolation(mode);

    if (mode == Interpolation::CubicSpline) {
        for (std::size_t k = 0; k < times.size(); ++k) {
            const std::size_t base = k * 12;
            track.AddKeyCubic(times[k],
                              ReadQuat4(values, base + 4),   // value
                              ReadQuat4(values, base + 0),   // inTangent
                              ReadQuat4(values, base + 8));  // outTangent
        }
    } else {
        for (std::size_t k = 0; k < times.size(); ++k) {
            track.AddKey(times[k], ReadQuat4(values, k * 4));
        }
    }
    track.Finalize();   // ここで符号が揃えられる（第 23 章）
}
```

**glTF のクォータニオンは `(x, y, z, w)` の順**で、本書の `Quat` と一致します。第 8 章でこの順序を選んだ理由が、ここで報われます。**4 つの float をそのまま読むだけ**です。

`Finalize()` が第 23 章の `AlignQuatTrackSigns` を呼び、トラック全体の符号を揃えます。glTF のデータは符号が揃っている保証がないので、この処理は必須です。

## 35.5　クリップの長さ

glTF は**クリップの長さを持ちません**。全サンプラーの時刻の最大値から決めます。

```cpp
for (const float t : times) { duration = std::fmax(duration, t); }
```

第 26 章で「`duration` を独立に持つ」と決めましたが、glTF から読む場合は最終キーの時刻がそれになります。「最後のキーの後に間がある」モーションは、glTF では表現できません（そういう場合は、最後に同じ値のキーをもう 1 つ打つのが慣習です）。

`input` accessor の `min` / `max` を使う手もあります。glTF の仕様は、アニメーションの `input` accessor に `min`/`max` を持つことを義務づけています。**第 32 章と同じく、ファイルの中に書いてある情報を検証に使えます。**

```cpp
// 時刻の範囲が accessor の min/max と一致することを確認する
const JsonValue& inputAccessor =
    doc.Json()["accessors"][static_cast<std::size_t>(sampler["input"].AsInt())];
if (inputAccessor.Has("max")) {
    const float declared = static_cast<float>(inputAccessor["max"][0].AsNumber());
    ANIM_ASSERT(std::fabs(declared - times.back()) < 1.0e-4f);
}
```

auto doc = GltfDocument::LoadFromFile("cylinder.gltf");

// 毎フレーム

### 実データで第 21 章を再現する

テストモデルには、joint1 を X 軸まわりに 0 → 180 度ねじるアニメーションが入っています。第 21 章で手書きデータを使って測ったキャンディラッパー現象が、**ファイルから読んだデータでも起きるはず**です。

測りました。

```
180 度ねじり時の LBS 最小半径 = 0.000021（理論値 0）
```

**再現しました。** 第 21 章の手書きデータでは `0.000000` でしたが、glTF ではキーフレーム補間を経由するぶん、わずかな誤差が乗っています（`duration - 1e-4` の時刻でサンプルしているため、正確には 179.98 度）。

**同じ現象が、手書きデータでも実データでも同じ数値で観測できる。** これは、glTF の読み込み経路 ―― JSON パース、Base64、アクセサ、転置、ソート、対応表、補間 ―― のすべてが正しいことの、かなり強い証拠です。

> **この測定で 1 つ引っかかりました**
> 最初、`clip.Sample(1.0f, pose)` と書いて、最小半径が `0.15`（未変形）のままになりました。第 26 章で書いたとおり、**`Loop` モードの `AdjustTime(duration)` は 0 を返す**からです。末尾を見たいなら `duration - ε` を使う必要がありました。
> 自分で書いた章の注意書きに、8 章あとで自分が引っかかったわけです。**注意書きを書くことと、それを覚えていることは別**だという良い例で、だからこそテストが要ります。

## 35.8　つまずきやすいところ

**アニメーションが再生されない**
`nodeToBone` の対応表が正しいか確認してください。チャンネルが指すノードがジョイントでなければ、無視されます（それが正しい動作です）。

**動きがまったく違う**
`CUBICSPLINE` を `LINEAR` として読んでいます（35.4 節）。**要素数の検査**を入れてください。「エクスポート設定が悪いのかな」と悩む前に、まずここを疑ってください。

**回転が「たまに」一回転する**
`Finalize()` を呼んでいない、または第 23 章の符号揃えが効いていません。

**クリップの長さが 0 になる**
時刻の accessor が空、あるいはすべてのチャンネルがスキン外のノードを指しています。

**t = duration でサンプルしたら先頭の姿勢が返る**
第 26 章のとおり、`Loop` モードでは `AdjustTime(duration)` が 0 を返します。`duration - ε` を使ってください。**筆者もこれで一度引っかかりました。**

**クォータニオンの成分が入れ替わる**
glTF は `(x,y,z,w)` の順です。文献によっては `(w,x,y,z)` で書かれているので、他のコードを参考にするときは注意してください。

**特定のノードだけアニメーションしない**
そのノードが `skin.joints` に含まれていない可能性があります。`AnimationLoadReport::channelsOutsideSkin` を確認してください。

## この章のまとめ

- glTF のアニメーションは **`samplers`（時刻と値の組）と `channels`（適用先）**に分かれる。**時刻の配列を共有できる**のが分けた理由で、実データでは非常に多いパターン。
- `path` の 4 種類のうち、`weights`（モーフターゲット）は扱わない。**無視せず報告する。**
- **スキンのジョイント以外のノードを指すチャンネルは、エラーではなく無視して記録する。** カメラや小道具のアニメーションが実際に含まれる。
- 補間モードは第 24 章の 3 つと **1 対 1 で対応**する。そう設計したから。
- **`CUBICSPLINE` は `(inTangent, value, outTangent)` の 3 つ組**で、要素数が 3 倍。`LINEAR` として読むと「動くが違う動きになる」ので、**要素数を必ず検査する**。
- glTF のクォータニオンは **`(x,y,z,w)`**。第 8 章でこの順序を選んだので、4 つの float をそのまま読める。
- クリップの長さは**全サンプラーの時刻の最大値**。glTF は長さを持たない。
- **実データで第 21 章のキャンディラッパー現象を再現できた**（最小半径 0.000021）。読み込み経路全体が正しいことの、かなり強い証拠。
- **自分で書いた注意書きに、8 章あとで自分が引っかかった。** 注意書きを書くことと覚えていることは別。だからテストが要る。

次章、GLB コンテナを扱います。短い章です。
