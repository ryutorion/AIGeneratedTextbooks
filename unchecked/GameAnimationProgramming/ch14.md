# 第 14 章　ポーズ

**この章で作るもの**：`Pose`（ローカルポーズ）と、そこからグローバルポーズを求める `ComputeGlobalPose`。第 13 章のスケルトンに姿勢を与え、**肘を曲げると手が上がる**ところまで進めます。紙の上で計算した手先の位置と、コードの出力を突き合わせます。

---

## 14.1　ローカルとグローバル

ボーンの姿勢には 2 つの表し方があります。

**ローカルポーズ**は、各ボーンの姿勢を**親から見た相対値**で表します。「肘は肩から見て X 方向に 0.3 m の位置にあり、Z 軸まわりに 40 度曲がっている」。

**グローバルポーズ**は、各ボーンの姿勢を**モデル空間の絶対値**で表します。「肘はモデル原点から見て (0.3, 1.5, 0) の位置にあり、こういう向きを向いている」。

アニメーションデータが持っているのは**ローカル**です。理由は明快で、そうでなければ関節が意味を持たないからです。「肘を 40 度曲げる」というモーションは、肩がどこを向いていようと成立してほしい。ローカルで持つとは、そういうことです。

一方、実際に必要なのは**グローバル**です。頂点を変形するにも、武器を手に持たせるにも、足が地面に着いているか調べるにも、モデル空間での位置が要ります。

だから毎フレーム、**ローカル → グローバル**の変換を行います。これが第 1 章のパイプラインの ③ です。

## 14.2　`Pose`

```cpp
// AnimLib/include/anim/Pose.h
#pragma once

#include "anim/Skeleton.h"
#include "anim/Transform.h"

#include <span>
#include <vector>

namespace anim {

// ローカルポーズ：各ボーンの、親から見た相対姿勢。
// スケルトンへの参照は持たない ―― ボーン数だけが対応の根拠。
// （参照を持たせるとコピー・保存・スレッド間の受け渡しが面倒になる）
class Pose {
public:
    Pose() = default;
    explicit Pose(std::size_t boneCount) : locals_(boneCount, TransformIdentity()) {}

    // スケルトンのレストポーズで初期化する
    [[nodiscard]] static Pose FromRest(const Skeleton& skeleton);

    [[nodiscard]] std::size_t Size() const noexcept { return locals_.size(); }

    [[nodiscard]] Transform& operator[](BoneIndex i) { return locals_[i]; }
    [[nodiscard]] const Transform& operator[](BoneIndex i) const { return locals_[i]; }

    [[nodiscard]] std::span<Transform> Locals() noexcept { return locals_; }
    [[nodiscard]] std::span<const Transform> Locals() const noexcept { return locals_; }

    void Resize(std::size_t boneCount) { locals_.assign(boneCount, TransformIdentity()); }

private:
    std::vector<Transform> locals_;
};

}  // namespace anim
```

```cpp
Pose Pose::FromRest(const Skeleton& skeleton) {
    Pose p(skeleton.BoneCount());
    const std::span<const Transform> rest = skeleton.RestLocals();
    std::copy(rest.begin(), rest.end(), p.locals_.begin());
    return p;
}
```

**`Pose` はスケルトンへのポインタや参照を持ちません。** 中身は `Transform` の配列だけです。

そうした理由は 3 つあります。**コピーが安い**（`vector` 1 本）。**スレッド間で受け渡せる**（第 57 章）。**そのまま保存できる**。対応するスケルトンは呼び出し側が知っている、という前提で押し通します。

代償は「別のスケルトンのポーズを渡してしまう」事故が型で防げないことですが、実際にはボーン数が違えばアサートで落ちますし、同じボーン数の別スケルトンを混ぜる状況は現実にはまず起きません。

**グローバルポーズには専用の型を作りません。** これも `Transform` の配列です。ローカルとグローバルを型で区別したくなりますが、そうすると `Transform` の配列を受け取る関数がすべて 2 通り必要になります。本書は**引数名と関数名で区別**します（`localPose` / `globalPose`）。

## 14.3　階層を解く

第 13 章の不変条件（**親は必ず自分より前**）が、ここで報われます。

```cpp
namespace anim {

// ローカルポーズからグローバルポーズを計算する。
// outGlobal は呼び出し側が用意する（アロケーションを起こさないため）。
inline void ComputeGlobalPose(const Skeleton& skeleton,
                              std::span<const Transform> localPose,
                              std::span<Transform> outGlobal) {
    const std::size_t n = skeleton.BoneCount();
    ANIM_ASSERT(localPose.size() == n);
    ANIM_ASSERT(outGlobal.size() == n);

    for (std::size_t i = 0; i < n; ++i) {
        const BoneIndex parent = skeleton.ParentOf(static_cast<BoneIndex>(i));
        outGlobal[i] = (parent == kNoParent)
                     ? localPose[i]
                     : Combine(outGlobal[parent], localPose[i]);
    }
}

}  // namespace anim
```

**これで全部です。**

再帰もスタックも訪問済みフラグもありません。前から順に見ていくだけで、自分の番が来たときには親の結果が `outGlobal[parent]` に入っています。第 13 章で不変条件を構造的に保証しておいたことの、最初にして最大の見返りです。

`Combine(outGlobal[parent], localPose[i])` の引数順に注意してください。第 11 章で決めたとおり `Combine(parent, child)` は「子を適用してから親を適用する」で、行列でいえば `parentGlobal * childLocal` です。逆にすると全身が崩壊します。

### 参照実装としての再帰版

素朴な再帰版も書いておきます。**これは遅くて使いませんが、テストの相手として価値があります。**

```cpp
// 指定したボーン 1 本のグローバル姿勢を、親をたどって求める。
// 参照実装。テストと、1 本だけ必要な場面で使う。
inline Transform ComputeGlobalOf(const Skeleton& skeleton,
                                 std::span<const Transform> localPose,
                                 BoneIndex bone) {
    const BoneIndex parent = skeleton.ParentOf(bone);
    if (parent == kNoParent) {
        return localPose[bone];
    }
    return Combine(ComputeGlobalOf(skeleton, localPose, parent), localPose[bone]);
}
```

第 7 章（一般 vs 剛体の逆行列）、第 9 章（`Rotate` vs 行列変換）と同じ、**独立した 2 実装を突き合わせる**構図です。

## 14.4　全ボーンを再帰で求めてはいけない

やってしまいがちな実装があります。

```cpp
// ⚠ やってはいけない
for (BoneIndex i = 0; i < n; ++i) {
    outGlobal[i] = ComputeGlobalOf(skeleton, localPose, i);
}
```

正しい答えは出ます。しかし、**ボーンごとにルートまで遡り直す**ので、計算量が O(n) から O(n²) に跳ね上がります。

100 ボーンの人型スケルトンで測りました。

| 実装 | 1 ポーズあたり |
| --- | --- |
| 1 パスのループ | **1.89 µs** |
| ボーンごとに再帰（O(n²)） | 26.56 µs（**14 倍**） |

深い階層ほど差が開きます。指先は、手 → 前腕 → 上腕 → 肩 → 胸 → 脊椎 → 腰 → ルートと 8 段。その途中のボーンも、それぞれ自分の分だけ遡り直します。

そして質が悪いことに、**この実装は正しく動きます**。バグではないので、テストは通ります。プロファイラを見るまで気づきません。

`ComputeGlobalOf` を用意しつつ、それをループで回すことを禁じる ―― この矛盾を扱うために、コメントで意図を書いておきます。

```cpp
// 【注意】この関数をボーン数ぶんループで呼ばないこと。O(n²) になる。
// 全ボーンが必要なら ComputeGlobalPose を使うこと。
inline Transform ComputeGlobalOf(...);
```

## 14.5　腕を曲げる ―― 紙とコードを突き合わせる

第 13 章で作った腕のスケルトンを使います。

```
root     : 原点
shoulder : root から (0,    1.5, 0)   肩の高さ 1.5 m
elbow    : shoulder から (0.3,  0, 0)  上腕 30 cm
hand     : elbow から    (0.25, 0, 0)  前腕 25 cm
```

回転はすべて単位、スケールはすべて 1。腕を +X 方向にまっすぐ伸ばした状態です。

### ケース 1：レストポーズ

回転がないので、平行移動が素直に積み上がります。

```
shoulder = (0, 1.5, 0)
elbow    = (0, 1.5, 0) + (0.3,  0, 0) = (0.3,  1.5, 0)
hand     = (0.3, 1.5, 0) + (0.25, 0, 0) = (0.55, 1.5, 0)
```

**手先は (0.55, 1.5, 0)。**

### ケース 2：肘を Z 軸まわりに +90 度

肘のローカル回転だけを変えます。ここが重要な点です ―― **肘の回転は、肘より先（手）にしか影響しません**。肘自身の位置は変わりません。

```
shoulder = (0, 1.5, 0)、回転なし
elbow    = (0.3, 1.5, 0)、回転 Rz(90°)
hand     = elbow の位置 + elbow の回転で回した (0.25, 0, 0)
         = (0.3, 1.5, 0) + Rz(90°)·(0.25, 0, 0)
         = (0.3, 1.5, 0) + (0, 0.25, 0)
         = (0.3, 1.75, 0)
```

**手先は (0.3, 1.75, 0)。** 前腕が上を向いたので、手が 25 cm 上がりました。

### ケース 3：肩を Z 軸まわりに +90 度

今度は肩を回します。**肩より先のすべて（肘も手も）が動きます。**

```
shoulder = (0, 1.5, 0)、回転 Rz(90°)
elbow    = shoulder の位置 + shoulder の回転で回した (0.3, 0, 0)
         = (0, 1.5, 0) + (0, 0.3, 0) = (0, 1.8, 0)
         回転は Rz(90°)（肘のローカル回転が単位なので親のまま）
hand     = (0, 1.8, 0) + Rz(90°)·(0.25, 0, 0)
         = (0, 1.8, 0) + (0, 0.25, 0) = (0, 2.05, 0)
```

**肘は (0, 1.8, 0)、手先は (0, 2.05, 0)。** 腕全体が真上を向きました。

### ケース 4：肩も肘も +90 度

回転が合成されます。

```
shoulder = (0, 1.5, 0)、回転 Rz(90°)
elbow    = (0, 1.8, 0)、回転 Rz(90°) · Rz(90°) = Rz(180°)
hand     = (0, 1.8, 0) + Rz(180°)·(0.25, 0, 0)
         = (0, 1.8, 0) + (-0.25, 0, 0) = (-0.25, 1.8, 0)
```

**手先は (-0.25, 1.8, 0)。** 腕を上げて、肘から先を折り返した形です。

この 4 つを、そのままテストにします。**紙で計算できる数字だけを選んだ**のがポイントです。90 度なら `sin` も `cos` も 0 か 1 になり、暗算できます。

## 14.6　バッファを使い回す

`ComputeGlobalPose` が出力先を引数で受け取る設計にしたのは、**毎フレームのアロケーションを避けるため**です。

100 ボーンのグローバルポーズは 4 KB。これを 1000 体ぶん、毎フレーム確保・解放すると、60 fps で毎秒 24 万回のアロケーションになります。

キャラクターごとに、必要なバッファをまとめて持ちます。

```cpp
// キャラクター 1 体ぶんのポーズ計算に必要な作業領域。
// 生成時に確保し、以後は使い回す。
class PoseBuffers {
public:
    explicit PoseBuffers(const Skeleton& skeleton)
        : local_(skeleton.BoneCount())
        , global_(skeleton.BoneCount(), TransformIdentity()) {}

    [[nodiscard]] Pose& Local() noexcept { return local_; }
    [[nodiscard]] const Pose& Local() const noexcept { return local_; }
    [[nodiscard]] std::span<Transform> Global() noexcept { return global_; }
    [[nodiscard]] std::span<const Transform> Global() const noexcept { return global_; }

    void UpdateGlobal(const Skeleton& skeleton) {
        ComputeGlobalPose(skeleton, local_.Locals(), global_);
    }

private:
    Pose local_;
    std::vector<Transform> global_;
};
```

第 44 章のブレンドツリーでは、中間結果のポーズが複数必要になります。そのときもこの方針を貫き、**評価に必要なバッファ数の上限を事前に計算して確保**します。「毎フレーム 1 回もアロケートしない」を目標にします。

100 ボーンでの内訳を確認しておきます。

| バッファ | サイズ |
| --- | --- |
| ローカルポーズ（`Transform` × 100） | 4,000 B |
| グローバルポーズ（`Transform` × 100） | 4,000 B |
| 親インデックス（`uint16_t` × 100、共有） | 200 B |

キャラクター 1 体あたり 8 KB。1000 体で 8 MB です。第 IX 部でこれを削ります。

## 14.7　誤差はどれくらい積み上がるのか

第 4 章で「変換の連鎖」を誤差の発生源として挙げました。実際に測ります。

**100 ボーンを一直線につなぎ、各ボーンを +X に 0.1 m ずらしただけ**のスケルトンで、末端の位置を求めます。理論値は 9.9 m。結果は **9.900002**。誤差 2 µm で、第 4 章で決めた `kEpsPos`（0.1 mm）の 50 分の 1 です。回転が入らなければ、深さ 100 でもこの程度で済みます。

回転が入るとどうなるか。**200 ボーンを、各段 0.02 ラジアンずつ回転させながらつないだ螺旋**で試すと、末端の回転クォータニオンの長さは **0.999998212** でした。1 から 1.8e-6 ずれています。

第 4 章で決めた `kEpsUnit`（1.0e-6）をわずかに超えます。人型のスケルトンで深さ 200 になることはないので実害はありませんが、**この方向に誤差が育つ**ことは覚えておく価値があります。

対策は第 8 章で述べたとおり、**定期的な正規化**です。本書では毎フレームの正規化は行いません（コストに見合わないため）が、次の 2 か所では明示的に正規化します。

- **キーフレームの補間直後**（第 24 章）。`Nlerp` が内部で正規化するので、実質ここで毎フレーム 1 回リセットされます。
- **IK ソルバの出力**（第 48 章）。反復のたびに回転を掛け合わせるので、収束後に正規化します。

つまり、通常のアニメーション再生では**補間が自動的に誤差をリセットしてくれる**構造になっています。これも `Nlerp` を既定にした副次的な利点です。

## 14.8　テストを書く

`AnimLib.Tests/PoseTests.cpp`：

```cpp
#include "CppUnitTest.h"

#include "TestSupport/MathAssert.h"
#include "TestSupport/SkeletonSupport.h"
#include "TestSupport/TestRandom.h"
#include "TestSupport/Tolerance.h"

#include "anim/Pose.h"

#include <numbers>
#include <vector>

using namespace Microsoft::VisualStudio::CppUnitTestFramework;
using namespace anim;
using anim::test::AssertNear;

namespace { constexpr float kPi = std::numbers::pi_v<float>; }

namespace AnimLibTests {

TEST_CLASS(PoseTests) {
public:

    // --- 手計算との照合（14.5 節）--------------------------------

    TEST_METHOD(RestPosePutsHandAtExpectedPlace) {
        const Skeleton s = test::MakeArmSkeleton();
        const Pose local = Pose::FromRest(s);
        std::vector<Transform> global(s.BoneCount());
        ComputeGlobalPose(s, local.Locals(), global);

        AssertNear(Vec3{0.0f,  1.5f, 0.0f}, global[1].translation, test::kEpsPos);
        AssertNear(Vec3{0.3f,  1.5f, 0.0f}, global[2].translation, test::kEpsPos);
        AssertNear(Vec3{0.55f, 1.5f, 0.0f}, global[3].translation, test::kEpsPos);
    }

    // 肘を曲げると、手だけが動く
    TEST_METHOD(BendingElbowMovesOnlyTheHand) {
        const Skeleton s = test::MakeArmSkeleton();
        Pose local = Pose::FromRest(s);
        local[2].rotation = MakeQuatAxisAngle({0, 0, 1}, kPi * 0.5f);

        std::vector<Transform> global(s.BoneCount());
        ComputeGlobalPose(s, local.Locals(), global);

        // 肩と肘の「位置」は変わらない
        AssertNear(Vec3{0.0f, 1.5f, 0.0f}, global[1].translation, test::kEpsPos);
        AssertNear(Vec3{0.3f, 1.5f, 0.0f}, global[2].translation, test::kEpsPos);
        // 手だけが 25 cm 上がる
        AssertNear(Vec3{0.3f, 1.75f, 0.0f}, global[3].translation, test::kEpsPos);
    }

    // 肩を回すと、肘も手も動く
    TEST_METHOD(RotatingShoulderMovesEverythingBelow) {
        const Skeleton s = test::MakeArmSkeleton();
        Pose local = Pose::FromRest(s);
        local[1].rotation = MakeQuatAxisAngle({0, 0, 1}, kPi * 0.5f);

        std::vector<Transform> global(s.BoneCount());
        ComputeGlobalPose(s, local.Locals(), global);

        AssertNear(Vec3{0.0f, 1.8f,  0.0f}, global[2].translation, test::kEpsPos);
        AssertNear(Vec3{0.0f, 2.05f, 0.0f}, global[3].translation, test::kEpsPos);
    }

    // 回転が合成される
    TEST_METHOD(RotationsCompoundDownTheChain) {
        const Skeleton s = test::MakeArmSkeleton();
        Pose local = Pose::FromRest(s);
        local[1].rotation = MakeQuatAxisAngle({0, 0, 1}, kPi * 0.5f);
        local[2].rotation = MakeQuatAxisAngle({0, 0, 1}, kPi * 0.5f);

        std::vector<Transform> global(s.BoneCount());
        ComputeGlobalPose(s, local.Locals(), global);

        AssertNear(Vec3{-0.25f, 1.8f, 0.0f}, global[3].translation, test::kEpsPos);
        // 肘のグローバル回転は 180 度になっているはず
        anim::test::AssertSameRotation(
            MakeQuatAxisAngle({0, 0, 1}, kPi), global[2].rotation, test::kEpsAccum);
    }

    // --- 独立した 2 実装の一致 ------------------------------------

    TEST_METHOD(IterativeMatchesRecursive) {
        const Skeleton s = test::MakeArmSkeleton();
        test::TestRandom rng;
        std::vector<Transform> global(s.BoneCount());

        for (int trial = 0; trial < 500; ++trial) {
            Pose local(s.BoneCount());
            for (BoneIndex i = 0; i < s.BoneCount(); ++i) {
                local[i] = Transform{rng.NextVec3(2.0f), rng.NextQuat(), {1, 1, 1}};
            }
            ComputeGlobalPose(s, local.Locals(), global);

            for (BoneIndex i = 0; i < s.BoneCount(); ++i) {
                const Transform recursive = ComputeGlobalOf(s, local.Locals(), i);
                AssertNear(recursive.translation, global[i].translation, test::kEpsAccum);
            }
        }
    }

    // 分岐のある階層でも一致すること
    TEST_METHOD(IterativeMatchesRecursiveOnBranchingSkeleton) {
        SkeletonBuilder b;
        b.AddRoot("root");
        b.AddBone("spine", "root");
        b.AddBone("leftArm",  "spine");
        b.AddBone("leftHand", "leftArm");
        b.AddBone("rightArm", "spine");
        b.AddBone("rightHand", "rightArm");
        const Skeleton s = b.Build();

        test::TestRandom rng;
        Pose local(s.BoneCount());
        for (BoneIndex i = 0; i < s.BoneCount(); ++i) {
            local[i] = Transform{rng.NextVec3(1.0f), rng.NextQuat(), {1, 1, 1}};
        }
        std::vector<Transform> global(s.BoneCount());
        ComputeGlobalPose(s, local.Locals(), global);

        for (BoneIndex i = 0; i < s.BoneCount(); ++i) {
            AssertNear(ComputeGlobalOf(s, local.Locals(), i).translation,
                       global[i].translation, test::kEpsAccum);
        }
    }

    // --- 性質 -----------------------------------------------------

    // ルートのグローバル姿勢はローカルと同じ
    TEST_METHOD(RootGlobalEqualsRootLocal) {
        const Skeleton s = test::MakeArmSkeleton();
        test::TestRandom rng;
        Pose local = Pose::FromRest(s);
        local[0] = Transform{rng.NextVec3(3.0f), rng.NextQuat(), {1, 1, 1}};

        std::vector<Transform> global(s.BoneCount());
        ComputeGlobalPose(s, local.Locals(), global);
        AssertNear(local[0].translation, global[0].translation, test::kEpsPos);
    }

    // ルートを動かすと、全ボーンが同じ変換を受ける
    TEST_METHOD(MovingRootTranslatesEveryBone) {
        const Skeleton s = test::MakeArmSkeleton();
        std::vector<Transform> before(s.BoneCount());
        std::vector<Transform> after(s.BoneCount());

        Pose local = Pose::FromRest(s);
        ComputeGlobalPose(s, local.Locals(), before);

        const Vec3 offset{10.0f, 0.0f, -5.0f};
        local[0].translation = offset;
        ComputeGlobalPose(s, local.Locals(), after);

        for (BoneIndex i = 0; i < s.BoneCount(); ++i) {
            AssertNear(before[i].translation + offset, after[i].translation, test::kEpsPos);
        }
    }

    // 誤差の蓄積（14.7 節）
    TEST_METHOD(DeepChainAccumulatesLittleError) {
        SkeletonBuilder b;
        b.AddRoot("b0");
        for (int i = 1; i < 100; ++i) {
            b.AddBone("b" + std::to_string(i), static_cast<BoneIndex>(i - 1),
                      Transform{{0.1f, 0, 0}, QuatIdentity(), {1, 1, 1}});
        }
        const Skeleton s = b.Build();

        const Pose local = Pose::FromRest(s);
        std::vector<Transform> global(s.BoneCount());
        ComputeGlobalPose(s, local.Locals(), global);

        // 理論値 9.9 m。実測 9.900002（誤差 2 µm）
        anim::test::AssertNear(9.9f, global[99].translation.x, test::kEpsPos);
    }

    TEST_METHOD(DeepChainKeepsRotationsNearlyUnit) {
        SkeletonBuilder b;
        b.AddRoot("b0");
        for (int i = 1; i < 200; ++i) {
            b.AddBone("b" + std::to_string(i), static_cast<BoneIndex>(i - 1),
                      Transform{{0.1f, 0, 0},
                                MakeQuatAxisAngle({0, 0, 1}, 0.02f), {1, 1, 1}});
        }
        const Skeleton s = b.Build();

        const Pose local = Pose::FromRest(s);
        std::vector<Transform> global(s.BoneCount());
        ComputeGlobalPose(s, local.Locals(), global);

        // 深さ 200 で長さが 1.8e-6 ずれる。kEpsUnit をわずかに超えるので
        // 蓄積後の基準（kEpsAccum）で見る。
        anim::test::AssertNear(1.0f, Length(global[199].rotation), test::kEpsAccum);
    }
};

}  // namespace AnimLibTests
```

`MovingRootTranslatesEveryBone` は、シンプルながら本質的なテストです。**ルートの変換が階層全体に伝播すること**を確かめており、これが成り立たなければキャラクターは移動できません。第 28 章のルートモーションの土台でもあります。

`IterativeMatchesRecursiveOnBranchingSkeleton` を別に書いたのは、**腕のスケルトンが一直線だから**です。一直線の階層では「親が 1 つ前のインデックス」という偶然が成り立ってしまい、`ParentOf` を使わずに `i-1` を参照する実装でもテストが通ってしまいます。分岐のあるスケルトンでは通りません。

## 14.9　つまずきやすいところ

**全身が崩壊する（ボーンが原点付近に集まる、または飛び散る）**
`Combine` の引数順です。`Combine(outGlobal[parent], localPose[i])` が正しい。逆にすると、子の変換が親の外側にかかります。

**ルートだけ正しく、他が全部おかしい**
`parent == kNoParent` の判定を忘れて、`outGlobal[65535]` を読んでいます。範囲外アクセスなので、Debug ビルドの `vector` なら `_ITERATOR_DEBUG_LEVEL` で捕まります。Release では静かに壊れます。

**一直線のスケルトンでは動くが、分岐すると壊れる**
`ParentOf(i)` の代わりに `i - 1` を使っています。テストに分岐のあるスケルトンを入れてください。

**プロファイラでポーズ計算が異様に重い**
14.4 節です。`ComputeGlobalOf` をループで呼んでいないか確認してください。

**フレームごとに `std::vector<Transform>` を作っている**
14.6 節です。`PoseBuffers` のような形で使い回してください。

**`Pose` と `Skeleton` のボーン数が合わない**
`ANIM_ASSERT` が Debug で落ちます。`Pose::FromRest(skeleton)` か `Pose(skeleton.BoneCount())` で作れば起きません。第 34 章で glTF から読んだあと、スケルトンを差し替えたのにポーズを作り直していない、というのが典型的な原因です。

**ボーンのスケールを設定したら、下位のボーンの位置が想定とずれる**
第 11 章の非一様スケール問題です。`HasNonUniformScale` で確認してください。一様スケールなら正しく伝播します。

## この章のまとめ

- アニメーションデータは**ローカル**（親から見た相対姿勢）で持ち、実際に必要なのは**グローバル**（モデル空間の絶対姿勢）。毎フレーム変換する。
- 第 13 章の不変条件のおかげで、階層の解決は**前方への 1 パスループ**だけで済む。再帰もスタックも訪問済みフラグも要らない。
- **ボーンごとに再帰で求めると O(n²)。** 実測で 14 倍遅い。しかも**正しく動く**のでテストでは見つからない。
- **紙で計算できる数字をテストにする。** 90 度回転なら暗算できる。肘を +90 度 → 手が 25 cm 上がって (0.3, 1.75, 0)。
- 出力バッファは呼び出し側が持つ。目標は「**毎フレーム 1 回もアロケートしない**」。
- 誤差は深さ 100 の平行移動で 2 µm、深さ 200 の回転で長さが 1.8e-6 ずれる程度。実務上は**補間（`Nlerp`）が毎フレーム正規化してくれる**ので育たない。
- **一直線のスケルトンだけでテストしない。** 分岐がないと `ParentOf` を使わない実装でも通ってしまう。

次章では、このグローバルポーズをメッシュの変形に結びつけるために欠けている最後のピース ―― **バインドポーズと逆バインド行列**を扱います。
