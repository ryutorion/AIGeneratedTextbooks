# 第 42 章　1D ブレンドスペース

**この章で作るもの**：1 つのパラメータ（移動速度など）で、複数のクリップを連続的に混ぜる仕組み。**時刻の同期**が、この章のいちばん重要な話です。

---

## 42.1　パラメータで混ぜる

キャラクターの移動速度が `0 → 1.5 → 4.0 m/s` と変化するとき、アニメーションも `待機 → 歩き → 走り` と連続的に変わってほしい。

第 39 章のクロスフェードでは、**離散的な切り替え**しかできません。速度 2.0 のときに「歩き 75% + 走り 25%」という状態を、常に維持する必要があります。

**ブレンドスペース**は、パラメータ空間にクリップを配置し、現在のパラメータ値から重みを決めます。

```
重み
 1 ┤●─────────●─────────●
   │ ╲       ╱ ╲       ╱
   │   ╲   ╱     ╲   ╱
 0 ┼─────╳─────────╳─────
   └──┬────┬─────────┬──── 速度
     0.0  1.5       4.0
    待機  歩き      走り
```

**同時に非ゼロになるのは、隣り合う 2 つだけ**です。これが 1D の良いところで、コストが一定に保てます。

---

## 42.2　実装

```cpp
// AnimLib/include/anim/BlendSpace1D.h
#pragma once

#include "anim/ClipPlayer.h"
#include "anim/PoseBlend.h"

namespace anim {

struct BlendSample1D {
    float position = 0.0f;      // パラメータ空間での位置
    const Clip* clip = nullptr;
};

class BlendSpace1D {
public:
    void AddSample(float position, const Clip* clip) {
        samples_.push_back({position, clip});
    }
    void Finalize() {
        std::stable_sort(samples_.begin(), samples_.end(),
            [](const BlendSample1D& a, const BlendSample1D& b) {
                return a.position < b.position;
            });
    }

    [[nodiscard]] std::size_t Size() const noexcept { return samples_.size(); }
    [[nodiscard]] const BlendSample1D& At(std::size_t i) const { return samples_[i]; }

    // パラメータ値から各サンプルの重みを求める。
    // 非ゼロになるのは高々 2 個。
    void ComputeWeights(float parameter, std::vector<float>& out) const;

private:
    std::vector<BlendSample1D> samples_;
};

}  // namespace anim
```

```cpp
void BlendSpace1D::ComputeWeights(float parameter, std::vector<float>& out) const {
    out.assign(samples_.size(), 0.0f);
    if (samples_.empty()) { return; }

    // 範囲外はクランプ
    if (samples_.size() == 1 || parameter <= samples_.front().position) {
        out.front() = 1.0f;
        return;
    }
    if (parameter >= samples_.back().position) {
        out.back() = 1.0f;
        return;
    }

    for (std::size_t i = 0; i + 1 < samples_.size(); ++i) {
        if (parameter >= samples_[i].position && parameter <= samples_[i + 1].position) {
            const float span = samples_[i + 1].position - samples_[i].position;
            const float t = (span > 0.0f)
                          ? (parameter - samples_[i].position) / span
                          : 0.0f;
            out[i]     = 1.0f - t;
            out[i + 1] = t;
            return;
        }
    }
}
```

第 23 章の `Track` とよく似た構造です。**「時刻」が「パラメータ」に変わっただけ**で、キー探索も補間も同じ形をしています。

キー数が多ければ第 25 章の二分探索やヒントを使うべきですが、**ブレンドスペースのサンプルは通常 3〜5 個**なので、線形探索で十分です（第 25 章の実測でも、10 個以下なら線形と二分探索の差はありませんでした）。

`span > 0.0f` のガードは、同じ位置に 2 つのサンプルを置いた場合のゼロ除算対策です。第 24 章の同時刻キーと同じ話で、これも実データで起こります。

## 42.3　時刻をどう合わせるか ―― この章の本題

重みが決まっても、**各クリップをどの時刻でサンプルするか**という問題が残ります。

素朴に、それぞれのクリップを独立に再生したらどうなるか。

```cpp
// ⚠ これは足が滑ります
walkPlayer.Update(dt);   // 1.2 秒周期
runPlayer.Update(dt);    // 0.8 秒周期
```

歩きは 1.2 秒で 1 歩、走りは 0.8 秒で 1 歩。**周期が違うので、位相が合いません。** 歩きが右足を出しているときに走りが左足を出していると、混ぜた結果は「両足が地面を擦る」ような動きになります。

**位相を同期させる**必要があります。

```cpp
// 正規化された位相（0〜1）を 1 つだけ持ち、各クリップに配る
class BlendSpace1DPlayer {
public:
    void Update(float deltaSeconds, float parameter) {
        space_->ComputeWeights(parameter, weights_);

        // 現在の重みでの「代表的な周期」を求める
        float blendedDuration = 0.0f;
        float totalWeight = 0.0f;
        for (std::size_t k = 0; k < weights_.size(); ++k) {
            if (weights_[k] <= 0.0f) { continue; }
            blendedDuration += space_->At(k).clip->Duration() * weights_[k];
            totalWeight += weights_[k];
        }
        if (totalWeight > 0.0f) { blendedDuration /= totalWeight; }
        if (blendedDuration <= 0.0f) { return; }

        // 位相を進める
        phase_ += deltaSeconds / blendedDuration;
        phase_ -= std::floor(phase_);        // [0, 1) に折り返す
    }

    void Evaluate(Pose& out, Pose& scratch) const {
        bool first = true;
        float accumulated = 0.0f;

        for (std::size_t k = 0; k < weights_.size(); ++k) {
            const float w = weights_[k];
            if (w <= 0.0f) { continue; }

            const Clip* clip = space_->At(k).clip;
            // 各クリップを、同じ位相の時刻でサンプルする
            const float time = phase_ * clip->Duration();

            if (first) {
                clip->Sample(time, out);
                accumulated = w;
                first = false;
            } else {
                clip->Sample(time, scratch);
                BlendPose(out, scratch, w / (accumulated + w), out);
                accumulated += w;
            }
        }
    }

private:
    const BlendSpace1D* space_ = nullptr;
    std::vector<float> weights_;
    float phase_ = 0.0f;
};
```

**位相を 1 つだけ持ち、各クリップの長さを掛けて時刻に変換する。** これが同期の中身です。

```
位相 0.25 のとき
  歩き（1.2 秒） → 時刻 0.30 秒
  走り（0.8 秒） → 時刻 0.20 秒
  どちらも「1 歩の 1/4 が進んだ状態」
```

そして**位相を進める速さ**は、混ぜたクリップの長さの加重平均から決めます。歩きだけなら 1.2 秒で 1 周、走りだけなら 0.8 秒で 1 周。中間では、その中間の速さで回ります。

**この同期がないと、ブレンドスペースはまったく使い物になりません。** 実装量は 10 行程度ですが、効果は決定的です。

> **クリップ側の準備が要る**
> 位相の同期が意味を持つには、**すべてのクリップで位相 0 が同じ足の状態**でなければなりません。歩きが右足接地から始まるなら、走りも右足接地から始まる必要があります。
> これは**アニメーターとの取り決め**であり、コードでは保証できません。第 26 章のループ連続性と同じく、**検査はできます**（各クリップの位相 0 での足の位置を比べる）。

## 42.4　単調性

ブレンドスペースには、成り立ってほしい性質があります。**パラメータを連続的に動かしたとき、ポーズも連続的に変わる。**

区間内では線形補間なので当然ですが、**サンプル点をまたぐとき**に注意が要ります。

```
速度 1.49 → 重み: 歩き 0.993, 走り 0.007
速度 1.50 → 重み: 歩き 1.000, 走り 0.000    ← サンプル点ちょうど
速度 1.51 → 重み: 歩き 0.996, 走り 0.004    ← 次の区間へ
```

`ComputeWeights` の実装では、`parameter == samples[i+1].position` のとき、**最初に見つかった区間** `[i, i+1]` で `t = 1.0` を返します。次の区間 `[i+1, i+2]` では `t = 0.0` になるので、**どちらで計算しても結果は同じ**です。連続です。

もし `>=` と `>` を取り違えると、サンプル点で 1 フレームだけ別の値が出ることがあります。**1000 分割して差分を見るテスト**（第 26 章の `PingPongIsContinuous` と同じ手口）で検査します。

## 42.5　パラメータをどう供給するか

`parameter` に何を入れるかは、ゲームロジック側の判断です。

**移動速度。** 最も一般的。ただし**入力の速度ではなく、実際の移動速度**を使うべきです。壁に押し付けられて動けないとき、入力が最大でもキャラクターは止まっているので、待機アニメーションになってほしい。

**平滑化が必要。** 生の速度をそのまま渡すと、地形の凹凸や物理の揺れでパラメータが振動し、アニメーションがちらつきます。

```cpp
// 指数移動平均で平滑化する
smoothedSpeed_ += (rawSpeed - smoothedSpeed_) * std::fmin(1.0f, deltaSeconds * responsiveness_);
```

`responsiveness_` は 5〜15 程度。大きいほど反応が速く、小さいほど滑らかになります。**この値の調整は、実際に動かして決めるもの**で、理屈では決まりません。

        const Clip walk = MakeClip(1.2f, 0.4f);
        const Clip run  = MakeClip(0.8f, 0.9f);

        BlendSpace1D space;

        space.AddSample(1.5f, &walk);
        space.AddSample(4.0f, &run);
        space.Finalize();

        BlendSpace1DPlayer player;
        player.SetSpace(&space);
        player.Initialize(kBones);

        Pose previous(kBones);
        Pose current(kBones);
        Pose scratch(kBones);

        player.Update(0.0f, 0.0f);
        player.Evaluate(previous, scratch);

        float worstJump = 0.0f;
        for (int i = 1; i <= 600; ++i) {
            const float speed = 5.0f * static_cast<float>(i) / 600.0f;
            player.Update(1.0f / 60.0f, speed);
            player.Evaluate(current, scratch);
            for (BoneIndex b = 0; b < kBones; ++b) {
                const float angle = 2.0f * std::acos(std::fmin(1.0f,
                    std::fabs(Dot(current[b].rotation, previous[b].rotation))));
                worstJump = std::fmax(worstJump, angle * 180.0f / kPi);
                previous[b] = current[b];
            }
        }
        Logger::WriteMessage(std::format(
            L"max per-frame rotation change while accelerating = {:.3f} deg\n",
            worstJump).c_str());
        Assert::IsTrue(worstJump < 5.0f);
    }
};

`PoseIsContinuousAsTheParameterChanges` は、**加速しながら**（パラメータを 0 → 5 へ動かしながら）ポーズが飛ばないことを見ています。ブレンドスペースの実装ミスは、たいてい「特定の速度でカクつく」という形で現れるので、範囲全体を掃く形のテストが有効です。

## 42.7　つまずきやすいところ

**足が滑る**
位相の同期をしていません（42.3 節）。ブレンドスペースで最も多い問題です。

**特定の速度でカクつく**
サンプル点の扱いです。`>=` と `>` の取り違えを確認してください。範囲全体を掃くテストで捕まります。

**アニメーションがちらつく**
パラメータが振動しています。平滑化してください（42.5 節）。

**位相が合っているのに足が揃わない**
クリップ側の問題です。すべてのクリップで位相 0 が同じ足の状態になっていますか（42.3 節のコラム）。

**壁に押されているのに走りアニメーションになる**
入力の速度を渡しています。実際の移動速度を使ってください。

**サンプルを追加したら並び順がおかしい**
`Finalize()` を呼び忘れています。

**位相を進める分母が 0 になる**
すべてのクリップの長さが 0、あるいは重みがすべて 0 です。ガードを入れてください。

## この章のまとめ

- ブレンドスペースは、**パラメータ空間にクリップを配置し、現在値から重みを決める**仕組み。1D では**非ゼロになるのは隣り合う 2 つだけ**なので、コストが一定。
- 構造は第 23 章の `Track` と同じ。「時刻」が「パラメータ」に変わっただけ。サンプルは通常 3〜5 個なので**線形探索で十分**（第 25 章の実測どおり）。
- **この章の本題は時刻の同期。** 周期の違うクリップを独立に再生すると、位相がずれて足が滑る。
- **位相（0〜1）を 1 つだけ持ち、各クリップの長さを掛けて時刻に変換する。** 進める速さは、混ぜたクリップの長さの加重平均から決める。実装は 10 行、効果は決定的。
- 位相の同期が意味を持つには、**すべてのクリップで位相 0 が同じ足の状態**である必要がある。これはアニメーターとの取り決めで、コードでは保証できない（が、検査はできる）。
- パラメータには**実際の移動速度**を使い、**平滑化**する。生の値だと地形の凹凸でちらつく。
- 検査の型は「**範囲全体を掃いて、不変条件と連続性を見る**」。重みの合計が 1、非ゼロは高々 2 個、隣接値の差が小さい。

次章、これを 2 次元に広げます。前後だけでなく左右にも動けるようにします。
