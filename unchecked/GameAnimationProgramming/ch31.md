# 第 31 章　JSON パーサを書く（2）構文解析

**この章で作るもの**：`JsonValue` と `JsonParser`。トークン列を木構造に組み立て、glTF を読み切れるところまで進めます。エラー処理には `std::expected` を使い、第 7 章で `bool` を選んだのとの使い分けを整理します。

---

## 31.1　`JsonValue` の設計

JSON の値は 6 種類です ―― null、真偽値、数値、文字列、配列、オブジェクト。C++ でこれを表すなら `std::variant` が素直です。

```cpp
// AnimLib/include/anim/Json.h
#pragma once

#include "anim/JsonLexer.h"

#include <expected>
#include <map>
#include <memory>
#include <variant>
#include <vector>

namespace anim {

class JsonValue;
using JsonArray  = std::vector<JsonValue>;
using JsonObject = std::map<std::string, JsonValue, std::less<>>;

class JsonValue {
public:
    JsonValue() = default;                                  // null
    JsonValue(bool b) : storage_(b) {}
    JsonValue(double d) : storage_(d) {}
    JsonValue(std::string s) : storage_(std::move(s)) {}
    JsonValue(JsonArray a)  : storage_(std::make_shared<JsonArray>(std::move(a))) {}
    JsonValue(JsonObject o) : storage_(std::make_shared<JsonObject>(std::move(o))) {}

    // ... 問い合わせと取り出し（31.3 節）...

private:
    std::variant<std::monostate,
                 bool,
                 double,
                 std::string,
                 std::shared_ptr<JsonArray>,
                 std::shared_ptr<JsonObject>> storage_;
};

}  // namespace anim
```

### なぜ配列とオブジェクトを `shared_ptr` にするのか

`JsonArray` は `std::vector<JsonValue>` で、`JsonValue` は `JsonArray` を含む ―― **再帰的な型**です。これをそのまま `variant` に入れようとすると、`JsonValue` のサイズを決めるのに `JsonValue` のサイズが必要になり、循環します。

間接参照を挟めば解決します。`unique_ptr` と `shared_ptr` のどちらでも成立しますが、本書は `shared_ptr` を選びました。

**`JsonValue` をコピー可能にしたいから**です。`unique_ptr` だとムーブ専用になり、`const JsonValue& v = doc["nodes"][3];` のような取り回しが窮屈になります。

代償は、コピーが**浅い**ことです。コピーした `JsonValue` は同じ配列を共有します。**パース後の JSON を読み取り専用として扱う限り、これは問題になりません**し、むしろコピーが安くなる利点があります。書き換える設計にするなら、この選択は見直しが必要です。

`sizeof(JsonValue)` は **40 バイト**でした。`std::string`（32 バイト）が最大の要素で、それに variant の識別子が乗った形です。

### `std::less<>` を使う理由

`JsonObject` のキー比較に `std::less<>`（透過的比較子）を指定しています。これにより、**`std::string` を作らずに `string_view` で検索できます**。

```cpp
const auto it = object.find("POSITION");   // std::string の一時オブジェクトを作らない
```

`std::map<std::string, JsonValue>` の既定は `std::less<std::string>` で、この場合は `find` のたびに `std::string` が構築されます。glTF のパースでは属性名の検索が頻繁に起きるので、地味に効きます。

## 31.2　安全なナビゲーション

glTF のパースでは、深い階層を辿ります。

```cpp
const int accessorIndex = doc["meshes"][0]["primitives"][0]["attributes"]["POSITION"];
```

途中のどこかが存在しなかったら？ 例外を投げるか、毎回 `if` を書くか ―― どちらも書き心地が悪い。

**存在しなければ null を返す**設計にします。

```cpp
    // 存在しないキー・範囲外の添字では「null の JsonValue」を返す。
    // 静的な null オブジェクトへの参照なので、寿命の問題はない。
    [[nodiscard]] const JsonValue& operator[](std::string_view key) const {
        static const JsonValue kNull;
        if (!IsObject()) { return kNull; }
        const JsonObject& obj = AsObject();
        const auto it = obj.find(key);
        return (it == obj.end()) ? kNull : it->second;
    }

    [[nodiscard]] const JsonValue& operator[](std::size_t index) const {
        static const JsonValue kNull;
        if (!IsArray()) { return kNull; }
        const JsonArray& arr = AsArray();
        return (index < arr.size()) ? arr[index] : kNull;
    }
```

これで、**存在しない経路を辿っても落ちません**。

```cpp
doc["nonexistent"]["deep"][42]["path"].IsNull()   // true。途中で落ちない
```

取り出しにも既定値を持たせます。

```cpp
    [[nodiscard]] double AsNumber(double fallback = 0.0) const {
        return IsNumber() ? std::get<double>(storage_) : fallback;
    }
    [[nodiscard]] int AsInt(int fallback = 0) const {
        return IsNumber() ? static_cast<int>(std::get<double>(storage_)) : fallback;
    }
    [[nodiscard]] bool AsBool(bool fallback = false) const {
        return IsBool() ? std::get<bool>(storage_) : fallback;
    }
    [[nodiscard]] const std::string& AsString() const {
        static const std::string kEmpty;
        return IsString() ? std::get<std::string>(storage_) : kEmpty;
    }
    [[nodiscard]] bool Has(std::string_view key) const {
        return IsObject() && AsObject().find(key) != AsObject().end();
    }
```

**この設計の危うさ**にも触れておきます。「存在しなければ 0」は、**タイポを静かに飲み込みます**。`doc["mehses"]` と書いても、0 が返るだけでエラーになりません。

glTF の読み込みでは、この危うさを別の層で受け止めます。**第 33〜35 章で、必要な要素の存在を明示的に検査する**からです。「JSON の取り回しは緩く、glTF としての妥当性は厳しく」という役割分担です。

## 31.3　再帰下降

構文解析の本体です。JSON の文法は、そのまま関数に対応します。

```
value  := object | array | string | number | true | false | null
object := '{' (string ':' value (',' string ':' value)*)? '}'
array  := '[' (value (',' value)*)? ']'
```

```cpp
class JsonParser {
public:
    [[nodiscard]] static std::expected<JsonValue, JsonError>
    Parse(std::string_view source, int maxDepth = 64);

private:
    JsonParser(std::string_view source, int maxDepth)
        : lexer_(source), maxDepth_(maxDepth) {}

    std::expected<JsonValue, JsonError> ParseValue(Token token, int depth);
    std::expected<JsonValue, JsonError> ParseObject(int depth);
    std::expected<JsonValue, JsonError> ParseArray(int depth);

    std::unexpected<JsonError> Fail(std::string message, const Token& token) {
        return std::unexpected(JsonError{std::move(message), token.line, token.column});
    }

    JsonLexer lexer_;
    int maxDepth_;
};
```

```cpp
std::expected<JsonValue, JsonError> JsonParser::ParseValue(Token token, int depth) {
    if (depth > maxDepth_) {
        return Fail("ネストが深すぎる", token);
    }
    switch (token.type) {
    case TokenType::ObjectBegin: return ParseObject(depth + 1);
    case TokenType::ArrayBegin:  return ParseArray(depth + 1);
    case TokenType::String:      return JsonValue(token.decoded);
    case TokenType::Number:      return JsonValue(token.number);
    case TokenType::True:        return JsonValue(true);
    case TokenType::False:       return JsonValue(false);
    case TokenType::Null:        return JsonValue();
    case TokenType::Error:       return Fail(lexer_.ErrorMessage(), token);
    default:                     return Fail("値が来るべき位置に別のトークン", token);
    }
}

std::expected<JsonValue, JsonError> JsonParser::ParseObject(int depth) {
    JsonObject object;

    Token token = lexer_.Next();
    if (token.type == TokenType::ObjectEnd) {
        return JsonValue(std::move(object));       // 空オブジェクト
    }
    for (;;) {
        if (token.type == TokenType::Error)  { return Fail(lexer_.ErrorMessage(), token); }
        if (token.type != TokenType::String) { return Fail("オブジェクトのキーは文字列", token); }
        std::string key = token.decoded;

        const Token colon = lexer_.Next();
        if (colon.type != TokenType::Colon) { return Fail("キーの後に ':' が必要", colon); }

        auto value = ParseValue(lexer_.Next(), depth);
        if (!value) { return value; }
        object.emplace(std::move(key), std::move(*value));

        const Token separator = lexer_.Next();
        if (separator.type == TokenType::ObjectEnd) { break; }
        if (separator.type != TokenType::Comma) { return Fail("',' か '}' が必要", separator); }
        token = lexer_.Next();
    }
    return JsonValue(std::move(object));
}
```

配列も同じ形です。**空のオブジェクト・配列を先に処理する**のがポイントで、これを忘れると `{}` や `[]` でエラーになります。

そして最上位です。

```cpp
std::expected<JsonValue, JsonError> JsonParser::Parse(std::string_view source, int maxDepth) {
    JsonParser parser(source, maxDepth);

    const Token first = parser.lexer_.Next();
    if (first.type == TokenType::Error) {
        return parser.Fail(parser.lexer_.ErrorMessage(), first);
    }
    auto value = parser.ParseValue(first, 0);
    if (!value) { return value; }

    const Token end = parser.lexer_.Next();
    if (end.type != TokenType::End) {
        return parser.Fail("末尾に余分なデータがある", end);
    }
    return value;
}
```

**最後の検査を忘れないでください。** これがないと `1 2` や `{} garbage` を「読めた」ことにしてしまいます。**「途中まで読めたら成功」は、ファイルフォーマットのパーサとしては危険な態度**です。

## 31.4　`std::expected` を使う ―― 第 7 章との使い分け

第 7 章の `Invert` では、失敗を `bool` で返しました。ここでは `std::expected` を使います。同じ「失敗しうる処理」なのに、なぜ違うのか。

| | 第 7 章 `Invert` | 第 31 章 `Parse` |
| --- | --- | --- |
| 失敗の理由 | 1 種類（特異行列） | 多数（構文の各所） |
| 呼ばれる頻度 | ロード時にボーン数ぶん | ファイルにつき 1 回 |
| 失敗時の情報 | 不要（「できなかった」で十分） | **必須**（どこで何が） |
| 戻り値の大きさ | `Mat4`（64 B）を出力引数で | `JsonValue`（40 B）を返せる |

**理由が 1 種類で情報が要らないなら `bool`、理由が多く情報が要るなら `std::expected`。** 判断基準はこれで足ります。

```cpp
struct JsonError {
    std::string message;
    int line = 0;
    int column = 0;
};
```

呼び出し側はこう書きます。

```cpp
auto parsed = JsonParser::Parse(source);
if (!parsed) {
    return std::unexpected(GltfError{
        std::format("JSON: {} ({} 行 {} 列)",
                    parsed.error().message, parsed.error().line, parsed.error().column)});
}
const JsonValue& doc = *parsed;
```

**`std::expected` は例外ではありません。** 呼び出し側が明示的に検査しなければ、`*parsed` で未定義動作になります。それでも例外より扱いやすいのは、**関数のシグネチャに「失敗しうる」と書いてある**からです。第 5 章で「Release では消える契約」と「実行時のエラー処理」を分けたのと、同じ考え方の延長です。

## 31.5　再帰の深さを制限する

`ParseValue` は再帰します。深くネストした JSON を渡されると、**スタックが尽きてプロセスが落ちます**。

```
[[[[[[[[[[[[[[[[ ... 100 万回 ... ]]]]]]]]]]]]]]]]
```

たった数百バイトの入力で、任意のプログラムをクラッシュさせられます。ゲームのランタイムがユーザー提供の glTF を読む可能性があるなら、これは看過できません。

対策は単純で、**深さを数えて上限で打ち切る**ことです。

```cpp
if (depth > maxDepth_) {
    return Fail("ネストが深すぎる", token);
}
```

既定を 64 にしました。glTF の構造で 64 段の入れ子が必要になることはありません（実際の最大は 5 段程度です）。

**「深さ 200 の JSON を渡してもクラッシュしない」ことをテストします。** 上限を設けない実装では、この入力でスタックオーバーフローします。

## 31.6　性能

測りました。

| 入力 | サイズ | 時間 | 速度 |
| --- | --- | --- | --- |
| `cylinder.gltf` | 3,193 B | 0.028 ms | 114 MB/s |
| 数値 20 万個の配列 | 2,517 KB | 20.1 ms | 128 MB/s |

**100 MB/s 前後**です。世の中の高速な JSON パーサ（simdjson など）は GB/s の桁なので、10 倍以上遅い計算になります。

それで困るかどうかを考えます。実際の glTF の JSON 部分は、頂点データを含まないので**数十 KB から数百 KB**です。500 KB でも 4 ms。ロード時に 1 回だけ払うコストとしては十分に許容範囲です。

**遅い原因も分かっています。**

**① 文字列を毎回 `std::string` で作る。** エスケープを含まない文字列（大多数）でもコピーが発生します。
**② `std::map` にキーを挿入するたびにノードを確保する。** `vector` + 線形探索のほうが、要素数が少ないうちは速い。
**③ `shared_ptr` の確保。** 配列・オブジェクトごとに 1 回。

**どれも直しません。** ロード時に 1 回、数ミリ秒の処理を最適化しても、フレーム時間には一切影響しないからです。第 20 章で頂点変形を 2.7 倍にしたのとは、状況がまったく違います。

**「速くできる」と「速くすべき」は別**です。プロファイラが指していない場所を最適化するのは、読みやすさを捨てて何も買わない取引です。

## 31.7　テストを書く

`AnimLib.Tests/JsonParserTests.cpp`：

```cpp
#include "CppUnitTest.h"

#include "TestSupport/MathAssert.h"
#include "TestSupport/Tolerance.h"

#include "anim/Json.h"

#include <format>
#include <string>

using namespace Microsoft::VisualStudio::CppUnitTestFramework;
using namespace anim;

namespace AnimLibTests {

TEST_CLASS(JsonParserTests) {
public:

    // --- 基本 -----------------------------------------------------

    TEST_METHOD(ParsesScalars) {
        Assert::IsTrue(JsonParser::Parse("null")->IsNull());
        Assert::IsTrue(JsonParser::Parse("true")->AsBool());
        anim::test::AssertNear(1.5f, static_cast<float>(JsonParser::Parse("1.5")->AsNumber()));
        Assert::AreEqual(std::string("hi"), JsonParser::Parse(R"("hi")")->AsString());
    }

    TEST_METHOD(ParsesNestedStructure) {
        auto parsed = JsonParser::Parse(
            R"({"a":1,"b":[true,false,null],"c":{"d":"x\ny"}})");
        Assert::IsTrue(parsed.has_value());
        const JsonValue& v = *parsed;

        Assert::AreEqual(1, v["a"].AsInt());
        Assert::IsTrue(v["b"][0].AsBool());
        Assert::IsFalse(v["b"][1].AsBool());
        Assert::IsTrue(v["b"][2].IsNull());
        Assert::AreEqual(std::string("x\ny"), v["c"]["d"].AsString());
    }

    TEST_METHOD(EmptyContainers) {
        Assert::IsTrue(JsonParser::Parse("{}")->IsObject());
        Assert::IsTrue(JsonParser::Parse("[]")->IsArray());
        Assert::AreEqual(std::size_t{0}, JsonParser::Parse("[]")->Size());
        Assert::IsTrue(JsonParser::Parse(R"({"a":{},"b":[]})")->IsObject());
    }

    // --- 安全なナビゲーション（31.2 節）---------------------------

    TEST_METHOD(MissingPathsReturnNullWithoutCrashing) {
        auto parsed = JsonParser::Parse(R"({"a":1})");
        const JsonValue& v = *parsed;

        Assert::IsTrue(v["missing"].IsNull());
        Assert::IsTrue(v["missing"]["deep"][42]["further"].IsNull());
        Assert::IsTrue(v[7].IsNull());                 // オブジェクトに添字
        Assert::IsTrue(v["a"]["nope"].IsNull());       // 数値にキー
        Assert::AreEqual(0, v["missing"].AsInt());
        Assert::AreEqual(-1, v["missing"].AsInt(-1));  // 既定値が使える
    }

    TEST_METHOD(HasDistinguishesMissingFromNull) {
        auto parsed = JsonParser::Parse(R"({"present":null})");
        Assert::IsTrue((*parsed).Has("present"));
        Assert::IsFalse((*parsed).Has("absent"));
        // どちらも IsNull() は true になる
        Assert::IsTrue((*parsed)["present"].IsNull());
        Assert::IsTrue((*parsed)["absent"].IsNull());
    }

    // --- 不正な入力 -----------------------------------------------

    TEST_METHOD(RejectsMalformedInput) {
        const char* cases[] = {
            "{",                 // 閉じていない
            "[1,]",              // 末尾カンマ
            R"({"a"})",          // ':' がない
            R"({"a":})",         // 値がない
            "tru",               // 不完全なリテラル
            R"("unterminated)",  // 閉じていない文字列
            "1 2",               // 末尾に余分
            R"({"a":1,})",       // オブジェクトの末尾カンマ
            "[1 2]",             // ',' がない
            "",                  // 空入力
            "}",                 // いきなり閉じ
        };
        for (const char* bad : cases) {
            Assert::IsFalse(JsonParser::Parse(bad).has_value(),
                            anim::test::ToWide(bad).c_str());
        }
    }

    TEST_METHOD(ErrorCarriesLineAndColumn) {
        auto parsed = JsonParser::Parse("{\n  \"a\": 1,\n  \"b\": @\n}");
        Assert::IsFalse(parsed.has_value());
        Assert::AreEqual(3, parsed.error().line);
        Assert::AreEqual(8, parsed.error().column);
        Assert::IsFalse(parsed.error().message.empty());
    }

    // --- 再帰の深さ（31.5 節）------------------------------------

    TEST_METHOD(DeepNestingIsRejectedNotCrashed) {
        std::string deep;
        for (int i = 0; i < 200; ++i) { deep += "["; }
        for (int i = 0; i < 200; ++i) { deep += "]"; }

        auto parsed = JsonParser::Parse(deep, 64);
        Assert::IsFalse(parsed.has_value());   // クラッシュせず、エラーを返す
    }

    TEST_METHOD(NestingWithinLimitIsAccepted) {
        std::string deep;
        for (int i = 0; i < 30; ++i) { deep += "["; }
        for (int i = 0; i < 30; ++i) { deep += "]"; }
        Assert::IsTrue(JsonParser::Parse(deep, 64).has_value());
    }

    // --- 数値の扱い -----------------------------------------------

    TEST_METHOD(IntegersRoundTripExactly) {
        auto parsed = JsonParser::Parse("[0, 1, 65535, 16777216, 12345678901234]");
        Assert::AreEqual(0, (*parsed)[0].AsInt());
        Assert::AreEqual(1, (*parsed)[1].AsInt());
        Assert::AreEqual(65535, (*parsed)[2].AsInt());
        Assert::AreEqual(16777216, (*parsed)[3].AsInt());
        // double なので 2^53 まで正確
        Assert::IsTrue((*parsed)[4].AsNumber() == 12345678901234.0);
    }

    // --- 実データ -------------------------------------------------

    TEST_METHOD(ParsesTheGeneratedGltf) {
        const std::string source = anim::test::ReadTextFile(
            anim::test::TestDataDir() / "cylinder.gltf");
        auto parsed = JsonParser::Parse(source);

        if (!parsed) {
            Logger::WriteMessage(std::format(L"parse failed: {} at line {}\n",
                anim::test::ToWide(parsed.error().message), parsed.error().line).c_str());
        }
        Assert::IsTrue(parsed.has_value());

        const JsonValue& doc = *parsed;
        Assert::AreEqual(std::string("2.0"), doc["asset"]["version"].AsString());
        Assert::AreEqual(std::size_t{1}, doc["meshes"].Size());
        Assert::AreEqual(std::size_t{1}, doc["skins"].Size());
        Assert::AreEqual(std::size_t{1}, doc["animations"].Size());
        Assert::AreEqual(std::size_t{3}, doc["nodes"].Size());
        Assert::AreEqual(std::size_t{9}, doc["accessors"].Size());
    }

    // --- 性能の記録（31.6 節）------------------------------------

    TEST_METHOD(ReportsParsingThroughput) {
        std::string big = "[";
        for (int i = 0; i < 200000; ++i) {
            if (i != 0) { big += ","; }
            big += std::to_string(i * 0.5);
        }
        big += "]";

        const auto begin = std::chrono::steady_clock::now();
        auto parsed = JsonParser::Parse(big);
        const auto end = std::chrono::steady_clock::now();

        Assert::IsTrue(parsed.has_value());
        Assert::AreEqual(std::size_t{200000}, parsed->Size());

        const double seconds = std::chrono::duration<double>(end - begin).count();
        Logger::WriteMessage(std::format(L"parsed {} KB in {:.1f} ms ({:.1f} MB/s)\n",
            big.size() / 1024, seconds * 1000.0, big.size() / 1.0e6 / seconds).c_str());
    }
};

}  // namespace AnimLibTests
```

`RejectsMalformedInput` の 11 ケースが、この章でいちばん価値のあるテストです。**パーサの品質は「正しい入力を読めること」より「不正な入力を弾けること」で決まります。** 正しい入力しか試していないパーサは、壊れたファイルを黙って受け入れ、その後の処理で不可解なクラッシュを起こします。

`ReportsParsingThroughput` は判定をせず、**性能を記録するだけ**です（第 4 章の `ReportDefaultDenormalBehavior` と同じ形）。しきい値を設けると、実行環境の違いでテストが不安定になります。数字は残す、判定はしない。

## 31.8　つまずきやすいところ

**`{}` や `[]` でエラーになる**
空のコンテナを先に処理する分岐を忘れています（31.3 節）。

**`1 2` や `{} garbage` が通ってしまう**
最上位の「末尾に余分なデータがある」検査を忘れています。**ファイルフォーマットのパーサでは致命的**です。

**深い JSON でプロセスが落ちる**
再帰深度の上限がありません（31.5 節）。

**タイポが静かに 0 になる**
`operator[]` の設計上、そうなります（31.2 節）。glTF の必須要素は、第 33〜35 章で明示的に検査してください。

**`JsonValue` をコピーしたら元も変わった**
`shared_ptr` による浅いコピーです（31.1 節）。読み取り専用として扱う前提の設計です。

**`AsInt()` で大きな値が壊れる**
`double` → `int` の変換です。glTF の添字が 21 億を超えることはありませんが、`AsNumber()` で受けるべき場面かどうかは意識してください。

**日本語のキーが見つからない**
ファイルの文字コードが UTF-8 でない可能性があります。glTF の仕様は UTF-8 を要求しています。BOM 付き UTF-8 の場合、先頭 3 バイトを読み飛ばす処理が要ります。

## この章のまとめ

- `JsonValue` は **`std::variant`**。配列とオブジェクトは再帰型なので **`shared_ptr` で間接参照**する。コピー可能にするために `unique_ptr` ではなく `shared_ptr` を選び、代わりに浅いコピーを受け入れた。`sizeof` は 40 バイト。
- **存在しないキーは null を返す**。深い経路を安全に辿れるが、**タイポを静かに飲み込む**危うさもある。glTF の妥当性検査は別の層（第 33〜35 章）が担う。
- `std::map` のキー比較に **`std::less<>`** を使うと、`string_view` で検索でき、一時 `std::string` が消える。
- **`std::expected` と `bool` の使い分け** ―― 理由が 1 種類で情報が要らないなら `bool`（第 7 章）、理由が多く情報が要るなら `std::expected`（この章）。
- **最上位で「末尾に余分なデータがない」ことを検査する。** 「途中まで読めたら成功」はファイルフォーマットのパーサとして危険。
- **再帰深度に上限を設ける。** 数百バイトの入力でプロセスをクラッシュさせられる。
- 性能は **114〜128 MB/s**。高速なパーサの 1/10 だが、**ロード時に 1 回のコストなので最適化しない**。プロファイラが指していない場所を最適化するのは、読みやすさを捨てて何も買わない取引。
- パーサの品質は「**不正な入力を弾けること**」で決まる。11 種類の壊れた入力をテストに入れた。
