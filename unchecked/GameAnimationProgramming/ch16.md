# 第 16 章　スキニング行列パレット

**この章で作るもの**：`SkinPalette`。第 1 章で「アニメーションシステムの最終出力」と呼んだものです。これで第 III 部が完成し、あとは頂点を流し込むだけになります。

---

## 16.1　パレットとは何か

前章で導いた式を、全ボーンぶん並べたものがパレットです。

```
palette[i] = globalPose[i] · inverseBind[i]      （i = 0 .. boneCount-1）
```

`Mat4` の配列。それだけです。

**「パレット（palette）」という名前**は、絵の具のパレットに由来します。頂点シェーダが「この頂点はボーン 3 の色を 70%、ボーン 7 の色を 30%」と混ぜる、その色見本の役割を果たすからです。

この配列が、アニメーションシステムと描画システムの**唯一の接点**です。

```
┌─────────────────────────────────────┐
│  アニメーションシステム（本書の範囲）             │
│                                             │
│  クリップ → ブレンド → ポーズ → IK → パレット   │
└──────────────────┬──────────────────┘
                       │  Mat4 の配列（ボーン数ぶん）
                       ▼
┌─────────────────────────────────────┐
│  頂点変形（第 IV 部）→ 描画（本書の範囲外）        │
└─────────────────────────────────────┘
```

第 1 章で「描画しないのにどうやって正しさを確認するのか」と問いました。その答えの構造的な根拠がここにあります。**アニメーションシステムの出力は `Mat4` の配列であって、ピクセルではない。** だから配列を検証すれば、システム全体を検証したことになります。

## 16.2　`SkinPalette`

```cpp
// AnimLib/include/anim/SkinPalette.h
#pragma once

#include "anim/BindPose.h"
#include "anim/Mat4.h"
#include "anim/Pose.h"
#include "anim/Skeleton.h"

#include <span>
#include <vector>

namespace anim {

// スキニング行列パレット。キャラクター 1 体につき 1 つ。
// 毎フレーム再構築するが、確保は生成時の 1 回だけ。
class SkinPalette {
public:
    SkinPalette() = default;
    explicit SkinPalette(std::size_t boneCount)
        : matrices_(boneCount, Identity()) {}

    // globalPose と inverseBind から再構築する。
    void Update(std::span<const Transform> globalPose,
                std::span<const Mat4> inverseBind) {
        ANIM_ASSERT(globalPose.size() == matrices_.size());
        ANIM_ASSERT(inverseBind.size() == matrices_.size());

        for (std::size_t i = 0; i < matrices_.size(); ++i) {
            matrices_[i] = ToMat4(globalPose[i]) * inverseBind[i];
        }
    }

    [[nodiscard]] std::size_t Size() const noexcept { return matrices_.size(); }
    [[nodiscard]] const Mat4& operator[](BoneIndex i) const { return matrices_[i]; }
    [[nodiscard]] std::span<const Mat4> Matrices() const noexcept { return matrices_; }

    // GPU への転送用（第 58 章）。連続領域であることを保証する。
    [[nodiscard]] const void* Data() const noexcept { return matrices_.data(); }
    [[nodiscard]] std::size_t ByteSize() const noexcept {
        return matrices_.size() * sizeof(Mat4);
    }

private:
    std::vector<Mat4> matrices_;
};

}  // namespace anim
```

ループ 1 本の、ごく短いクラスです。それでも `std::vector<Mat4>` を直接使わずクラスにしたのは、次の 3 つのためです。

**① `Update` の引数順を型で守れない**ので、せめて 1 か所に閉じ込める。`globalPose * inverseBind` の順序を間違える事故は、第 15 章のハマりどころで挙げたとおり実際に起きます。呼び出し箇所が 1 つなら、間違いも 1 か所で済みます。

**② GPU への転送インターフェイスを持たせる場所**が要る。第 58 章で `Data()` と `ByteSize()` を使います。

**③ 第 59 章で「更新を間引く」ときの入れ物**になる。距離が遠いキャラクターはパレットを毎フレーム更新しない、という最適化を入れる場所です。

## 16.3　パイプラインを組み立てる

第 13〜16 章の部品が揃ったので、キャラクター 1 体ぶんの更新を通しで書きます。

```cpp
// AnimLib/include/anim/SkinnedCharacter.h

namespace anim {

// モデル固有・不変のデータ。何体でも共有する。
struct SkinnedModel {
    Skeleton skeleton;
    std::vector<Mat4> inverseBind;
};

// キャラクター 1 体ぶんの、毎フレーム変化するデータ。
class SkinnedCharacter {
public:
    explicit SkinnedCharacter(const SkinnedModel& model)
        : localPose_(Pose::FromRest(model.skeleton))
        , globalPose_(model.skeleton.BoneCount(), TransformIdentity())
        , palette_(model.skeleton.BoneCount()) {}

    // ローカルポーズを書き換える窓口。
    // 第 V 部以降、ここにクリップの再生結果が流れ込む。
    [[nodiscard]] Pose& LocalPose() noexcept { return localPose_; }

    // 第 1 章のパイプライン ③ → ⑤。
    // ④（IK）は第 VIII 部でこの 2 行のあいだに入る。
    void Update(const SkinnedModel& model) {
        ComputeGlobalPose(model.skeleton, localPose_.Locals(), globalPose_);
        palette_.Update(globalPose_, model.inverseBind);
    }

    [[nodiscard]] std::span<const Transform> GlobalPose() const noexcept {
        return globalPose_;
    }
    [[nodiscard]] const SkinPalette& Palette() const noexcept { return palette_; }

private:
    Pose localPose_;
    std::vector<Transform> globalPose_;
    SkinPalette palette_;
};

}  // namespace anim
```

**`Update` が 2 行になりました。** これが第 III 部の成果です。

`SkinnedModel`（共有・不変）と `SkinnedCharacter`（個別・可変）に分けた構造にも注目してください。第 13 章で「スケルトンは形、ポーズは姿勢」と分離したことが、そのままこの形になっています。1000 体表示するなら、`SkinnedModel` は 1 つ、`SkinnedCharacter` は 1000 個です。

`globalPose_` を外に見せているのは、パレット以外にも用途があるからです。武器を手に持たせる（第 61 章のソケット）、足の位置を調べる（第 51 章のフット IK）、カメラを頭に追従させる ―― いずれもグローバルポーズを読みます。

## 16.4　テストを書く

`AnimLib.Tests/SkinPaletteTests.cpp`：

```cpp
#include "CppUnitTest.h"

#include "TestSupport/MathAssert.h"
#include "TestSupport/SkeletonSupport.h"
#include "TestSupport/TestRandom.h"
#include "TestSupport/Tolerance.h"

#include "anim/SkinnedCharacter.h"

#include <numbers>

using namespace Microsoft::VisualStudio::CppUnitTestFramework;
using namespace anim;
using anim::test::AssertNear;

namespace {

constexpr float kPi = std::numbers::pi_v<float>;

// 腕のスケルトン + そのレストポーズをバインドポーズとしたモデル
SkinnedModel MakeArmModel() {
    SkinnedModel model;
    model.skeleton = anim::test::MakeArmSkeleton();
    model.inverseBind.resize(model.skeleton.BoneCount());
    ComputeInverseBindMatrices(model.skeleton, model.skeleton.RestLocals(),
                               model.inverseBind);
    return model;
}

}  // namespace

namespace AnimLibTests {

TEST_CLASS(SkinPaletteTests) {
public:

    // 第 III 部で最も重要なテスト。
    // バインドポーズのままなら、パレットは単位行列の列になる。
    TEST_METHOD(PaletteIsIdentityAtBindPose) {
        const SkinnedModel model = MakeArmModel();
        SkinnedCharacter character(model);

        character.Update(model);

        for (BoneIndex i = 0; i < model.skeleton.BoneCount(); ++i) {
            AssertNear(Identity(), character.Palette()[i], test::kEpsAccum);
        }
    }

    // 100% 1 本のボーンに属する頂点は、そのボーンの剛体変換に従う
    TEST_METHOD(VertexFollowsSingleBone) {
        const SkinnedModel model = MakeArmModel();
        SkinnedCharacter character(model);

        const BoneIndex elbow = model.skeleton.FindBone("elbow");
        character.LocalPose()[elbow].rotation = MakeQuatAxisAngle({0, 0, 1}, kPi * 0.5f);
        character.Update(model);

        // 前腕の表面にある頂点（第 15 章と同じもの）
        const Vec3 vertex{0.4f, 1.5f, 0.02f};
        AssertNear(Vec3{0.3f, 1.6f, 0.02f},
                   TransformPoint(character.Palette()[elbow], vertex),
                   test::kEpsPos);
    }

    // ルートを動かすと、パレット全体が同じ平行移動を含む
    TEST_METHOD(MovingRootTranslatesWholePalette) {
        const SkinnedModel model = MakeArmModel();
        SkinnedCharacter character(model);

        const Vec3 offset{10.0f, 0.0f, -5.0f};
        character.LocalPose()[0].translation = offset;
        character.Update(model);

        test::TestRandom rng;
        for (BoneIndex i = 0; i < model.skeleton.BoneCount(); ++i) {
            const Vec3 v = rng.NextVec3(2.0f);
            AssertNear(v + offset, TransformPoint(character.Palette()[i], v),
                       test::kEpsPos);
        }
    }

    // パレットは「グローバル姿勢 × 逆バインド」であることの直接確認
    TEST_METHOD(PaletteMatchesManualComputation) {
        const SkinnedModel model = MakeArmModel();
        SkinnedCharacter character(model);
        test::TestRandom rng;

        for (BoneIndex i = 0; i < model.skeleton.BoneCount(); ++i) {
            character.LocalPose()[i].rotation = rng.NextQuat();
        }
        character.Update(model);

        std::vector<Transform> bindGlobal(model.skeleton.BoneCount());
        ComputeGlobalPose(model.skeleton, model.skeleton.RestLocals(), bindGlobal);

        for (BoneIndex i = 0; i < model.skeleton.BoneCount(); ++i) {
            const Vec3 v = rng.NextVec3(1.0f);
            // 手計算：バインド姿勢の逆で引き戻し、現在の姿勢へ送る
            const Vec3 expected =
                TransformPoint(character.GlobalPose()[i],
                               TransformPoint(Inverse(bindGlobal[i]), v));
            AssertNear(expected, TransformPoint(character.Palette()[i], v),
                       1.0e-2f, 1.0e-4f);
        }
    }

    // 更新は冪等：同じローカルポーズなら何度呼んでも同じ
    TEST_METHOD(UpdateIsIdempotent) {
        const SkinnedModel model = MakeArmModel();
        SkinnedCharacter character(model);
        character.LocalPose()[2].rotation = MakeQuatAxisAngle({0, 1, 0}, 0.9f);

        character.Update(model);
        const Mat4 first = character.Palette()[3];
        character.Update(model);
        character.Update(model);
        AssertNear(first, character.Palette()[3], test::kEpsAccum);
    }

    // モデルを共有した 2 体が、独立に動くこと
    TEST_METHOD(TwoCharactersShareModelButPoseIndependently) {
        const SkinnedModel model = MakeArmModel();
        SkinnedCharacter a(model);
        SkinnedCharacter b(model);

        a.LocalPose()[2].rotation = MakeQuatAxisAngle({0, 0, 1}, kPi * 0.5f);
        a.Update(model);
        b.Update(model);   // b はバインドポーズのまま

        for (BoneIndex i = 0; i < model.skeleton.BoneCount(); ++i) {
            AssertNear(Identity(), b.Palette()[i], test::kEpsAccum);
        }
        Assert::IsFalse(anim::test::IsNear(a.Palette()[3].m[0][0], 1.0f, 1.0e-3f));
    }

    // GPU 転送用インターフェイスが連続領域を返すこと（第 58 章の前提）
    TEST_METHOD(PaletteIsContiguous) {
        const SkinnedModel model = MakeArmModel();
        SkinnedCharacter character(model);
        character.Update(model);

        const SkinPalette& p = character.Palette();
        Assert::AreEqual(p.Size() * sizeof(Mat4), p.ByteSize());

        const float* raw = static_cast<const float*>(p.Data());
        // 2 番目の行列の先頭 = 16 float 先
        anim::test::AssertNear(p[1].m[0][0], raw[16]);
    }
};

}  // namespace AnimLibTests
```

`PaletteIsIdentityAtBindPose` が、第 III 部を通じて最も重要なテストです。これが通るということは、**スケルトンの構築・階層の解決・バインドポーズの計算・逆行列・パレットの構築のすべてが、互いに整合している**ことを意味します。どこか 1 か所でも規約を間違えていれば、単位行列にはなりません。

第 34 章で glTF のモデルを読み込んだとき、真っ先に確認するのもこれです。転置忘れ、座標系の取り違え、ジョイントインデックスのずれ ―― すべてこの 1 本が捕まえます。

`TwoCharactersShareModelButPoseIndependently` は、16.3 節の設計（共有と個別の分離）が実際に機能していることの確認です。共有すべきものを誤ってコピーしていたり、逆に個別に持つべきものを共有していたりすれば落ちます。

## 16.5　コストを測る ―― 第 IX 部への動機

第 III 部が完成したので、ここまでのコストを測っておきます。100 ボーンの人型スケルトンで、`SkinnedCharacter::Update` を 20 万回。

| 処理 | 1 体 1 フレームあたり |
| --- | --- |
| `ComputeGlobalPose`（階層の解決） | 1.87 µs |
| `SkinPalette::Update`（パレット構築） | 2.12 µs |
| **合計** | **3.99 µs** |

**パレット構築のほうが、階層の解決より重い。** 意外に思うかもしれませんが、内訳を見れば納得できます。ボーンごとに `ToMat4(Transform)`（クォータニオン → 行列）と `Mat4 * Mat4`（64 回の乗算）を行っており、`Combine`（クォータニオンの積 16 乗算 + 回転の適用）より計算量が多いのです。

ここから、1000 体を 60 fps で動かしたときの負荷が計算できます。

```
3.99 µs × 1000 体 = 3.99 ms
1 フレームの予算（60 fps）= 16.7 ms
→ フレーム時間の 23.9%
```

**まだクリップの再生もブレンドも IK も頂点変形もしていない状態で、24% を使っています。** これが第 IX 部（最適化）が必要な理由です。

メモリも見ておきます。

| データ | 100 ボーン | 1000 体 |
| --- | --- | --- |
| スケルトン（共有） | 200 B + 名前 | 200 B + 名前 |
| 逆バインド行列（共有） | 6,400 B | 6,400 B |
| ローカルポーズ（個別） | 4,000 B | 4.0 MB |
| グローバルポーズ（個別） | 4,000 B | 4.0 MB |
| **パレット（個別）** | **6,400 B** | **6.4 MB** |

キャラクターあたり 14.4 KB、1000 体で 14.4 MB。**パレットが最大**です。

### 削りどころは既に見えている

第 IX 部で何をするかの見当は、この表から既につきます。

**① パレットを 3×4 にする。** アフィン変換なので、最下行は常に `(0,0,0,1)` です。保存する必要がありません。`Mat4`（64 B）を 3 行 × 4 列（48 B）にすれば、パレットは 25% 減って 4.8 MB。GPU への転送量も同じだけ減ります（第 58 章）。

**② スキニングに使わないボーンを飛ばす。** 顔のボーンや、武器のアタッチ用ソケットは、頂点に影響しないことがあります。パレットに含める必要がありません（第 34 章で `skin.joints` を読むと、この情報が手に入ります）。

**③ グローバルポーズとパレットを 1 パスにまとめる。** 現在は配列を 2 回舐めていますが、階層の解決とパレット構築を同じループで行えば、`globalPose` の配列がキャッシュに乗ったまま処理できます。

**④ 更新を間引く。** 遠くのキャラクターは 2 フレームに 1 回でよい（第 59 章）。

**⑤ SIMD 化する。** `Mat4 * Mat4` は SIMD の教科書的な題材です（第 53 章）。

**どれも今はやりません。** 最適化する前に、まず**正しく動くもの**と、**それを守るテスト**が必要だからです。第 IX 部でこれらに着手するとき、この章までに書いたテストがすべての変更を検証します。第 7 章から繰り返している「独立した 2 実装の一致」が、そこで最大の武器になります。

## 16.6　つまずきやすいところ

**パレットが単位行列にならない**
最初に疑うのは掛ける順序（`globalPose * inverseBind`）、次にバインドポーズとレストポーズの取り違え（第 15 章 15.6 節）です。1 ボーンだけのスケルトンで試すと切り分けが早くなります。

**特定のボーンだけ単位行列にならない**
そのボーンの逆バインド行列が `Invert` に失敗して `Identity()` になっています（第 15 章）。バインドポーズのスケールを確認してください。

**`Update` を呼び忘れる**
パレットが前フレームのまま、あるいは初期値（単位行列）のままになります。ローカルポーズを書き換えたら必ず `Update` を呼ぶ、という順序を守ってください。将来的にはダーティフラグを持たせる手もありますが、第 59 章で「意図的に更新を飛ばす」機能を入れるので、本書では明示的な呼び出しのままにします。

**パレットのサイズとボーン数が合わない**
`SkinnedCharacter` を作ったあとにスケルトンを差し替えています。モデルとキャラクターは対で扱ってください。

**GPU に渡したら形が崩れる**
HLSL の既定は列優先パッキングです。転置するか、シェーダ側で `row_major` を指定します（第 58 章）。

## この章のまとめ

- **パレット = `globalPose[i] · inverseBind[i]` を全ボーンぶん並べた `Mat4` の配列。** これがアニメーションシステムの最終出力であり、描画との唯一の接点。
- だから**描画せずにアニメーションを検証できる。** 配列を検証すればシステム全体を検証したことになる。
- **`PaletteIsIdentityAtBindPose` は第 III 部で最重要のテスト。** これが通れば、スケルトン構築・階層解決・バインドポーズ・逆行列・パレット構築のすべてが整合している。
- **共有（`SkinnedModel`）と個別（`SkinnedCharacter`）を分ける。** 第 13 章の「形と姿勢の分離」がそのまま構造になる。
- コストは**1 体あたり 3.99 µs**（うちパレット構築が 2.12 µs で階層解決より重い）。1000 体でフレーム時間の 24%。**頂点をまだ 1 つも動かしていないのに。**
- 削りどころは既に見えている（3×4 化・不要ボーンの除外・1 パス化・間引き・SIMD）が、**まだやらない。** 正しく動くものとテストが先。

## 第 III 部を終えて

第 1 章で示したパイプラインのうち、③（階層の解決）と⑤（パレット生成）が完成しました。

```
① クリップをサンプル    ← 第 V 部
② ブレンド              ← 第 VII 部
③ 階層を解く            ← ✅ 第 14 章
④ IK で補正             ← 第 VIII 部
⑤ パレットを作る        ← ✅ 第 16 章
⑥ 頂点を変形            ← 第 IV 部（次）
```

第 III 部で決めたことを振り返っておきます。

**分離** ―― スケルトン（形・不変・共有）とポーズ（姿勢・可変・個別）。この分離が、コードの構造そのものになりました。

**不変条件** ―― 「親は必ず自分より前」。ビルダーで構造的に強制した結果、階層の解決が 1 パスのループになり、循環参照の検出すら不要になりました。**強い不変条件は、それに依存するコードをまとめて単純にします。**

**測ってから言う** ―― 配列レイアウトを選んだ理由は「キャッシュに優しいから」ではありませんでした（この規模では実測で差が出ない）。実際の理由は別にあり、キャッシュの議論が効くのは第 52 章です。

**紙で計算できる数字をテストにする** ―― 肘を 90 度曲げたら手が (0.3, 1.75, 0)。抽象的な性質テストと並べて、こういう具体値のテストを必ず置きます。

次章から第 IV 部。ようやく**頂点を動かします**。パレットは既に手元にあるので、あとは「どの頂点がどのボーンにどれだけ属するか」を決め、重み付きで混ぜるだけです ―― そしてその「混ぜる」ところに、第 21 章で扱う破綻が潜んでいます。
