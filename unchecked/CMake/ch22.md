# 第22章　`find_package` で使えるパッケージに仕上げる

## この章のゴール

- `install(EXPORT)` でターゲット情報を書き出す
- **`EXPORT_NAME` で `pixkit::core` という名前を実現する**（これを知らないと `pixkit::pixkit-core` になる）
- `Config.cmake.in` と `configure_package_config_file` でパッケージ設定ファイルを作る
- `write_basic_package_version_file` と互換性ポリシーを選ぶ
- `find_dependency` で依存を再解決する
- `export(EXPORT)` でビルドツリーから直接使えるようにする
- **消費者プロジェクトを作って検証する**
- よくある失敗を知る

第21章でファイルは正しい場所に置かれた。しかし、利用者はまだ手作業でインクルードパスとライブラリを指定しなければならない。この章でそれを解消する。

**ゴールは、利用者がこう書けるようにすることだ。**

```cmake
find_package(pixkit 0.1 CONFIG REQUIRED)
target_link_libraries(app PRIVATE pixkit::codec pixkit::filter)
```

## 22.1　`install(EXPORT)` とエクスポートセット

### 2段階になっている

第21章で `install(TARGETS ... EXPORT pixkit-targets ...)` と書いた。これは**エクスポートセットに登録した**だけで、まだ何も出力されていない。書き出すには別のコマンドが要る。

```cmake
install(EXPORT pixkit-targets
    FILE        pixkit-targets.cmake
    NAMESPACE   pixkit::
    DESTINATION ${CMAKE_INSTALL_LIBDIR}/cmake/pixkit
)
```

| 引数 | 意味 |
| --- | --- |
| `pixkit-targets` | 第21章で `EXPORT` に指定した名前 |
| `FILE` | 生成されるファイル名 |
| `NAMESPACE` | **ターゲット名に付ける接頭辞** |
| `DESTINATION` | 置き場所。**`lib/cmake/<name>/` が慣習** |

### 生成されるもの

```
lib/cmake/pixkit/
├── pixkit-targets.cmake              ← 共通部分
└── pixkit-targets-release.cmake      ← 構成ごとの情報
```

構成ごとにファイルが分かれるのがポイントだ。DebugとReleaseの両方をインストールすれば、`pixkit-targets-debug.cmake` も追加される。**利用者側で自動的に正しいほうが選ばれる**（第18章2節の `IMPORTED_LOCATION_<CONFIG>`）。

`pixkit-targets.cmake` の中身は、こういうものだ。

```cmake
add_library(pixkit::core INTERFACE IMPORTED)
set_target_properties(pixkit::core PROPERTIES
  INTERFACE_LINK_LIBRARIES "pixkit::options"
)
set_property(TARGET pixkit::core APPEND PROPERTY
  INTERFACE_INCLUDE_DIRECTORIES "${_IMPORT_PREFIX}/include"
)

add_library(pixkit::codec STATIC IMPORTED)
...
```

**第18章2節で見た `GTestTargets.cmake` と同じ構造だ。** 自分が「探される側」になった。

`${_IMPORT_PREFIX}` は、このファイル自身の位置から逆算されたインストールプレフィックスだ。だから**インストール先を移動しても動く。** 第21章7節で絶対パスが拒否された理由がここにある。

### エクスポートセットに漏れがあると

```cmake
install(TARGETS pixkit-core pixkit-codec EXPORT pixkit-targets ...)
# pixkit_options を入れ忘れた
```

```
CMake Error: install(EXPORT "pixkit-targets" ...) includes target "pixkit-core"
which requires target "pixkit_options" that is not in any export set.
```

**依存しているターゲットは、すべて同じエクスポートセットに入れる必要がある。** 第7章7節で「設定ターゲットをPUBLICでリンクすると配布で問題になる」と予告したのが、このエラーだ。

第21章のハンズオンで `pixkit_options` をインストール対象に含めておいたので、`pixkit` ではこれは起きない。

## 22.2　`EXPORT_NAME` — 名前空間の落とし穴

### 素朴に書くとどうなるか

第6章6節で、ALIASを定義した。

```cmake
add_library(pixkit-core INTERFACE)
add_library(pixkit::core ALIAS pixkit-core)
```

だから `install(EXPORT ... NAMESPACE pixkit::)` とすれば `pixkit::core` としてエクスポートされる——**と思いきや、そうならない。**

生成された `pixkit-targets.cmake` を見ると、こうなっている。

```cmake
add_library(pixkit::pixkit_options INTERFACE IMPORTED)
add_library(pixkit::pixkit-core INTERFACE IMPORTED)
add_library(pixkit::pixkit-codec STATIC IMPORTED)
add_library(pixkit::pixkit-filter SHARED IMPORTED)
```

**`pixkit::pixkit-core` になっている。**

理由は単純だ。`NAMESPACE` は**実ターゲット名**の前に接頭辞を付けるだけで、ALIASのことは見ていない。実ターゲット名が `pixkit-core` なので、`pixkit::` + `pixkit-core` = `pixkit::pixkit-core` になる。

これでは利用側がこう書くことになる。

```cmake
target_link_libraries(app PRIVATE pixkit::pixkit-codec)   # 不格好
```

しかも、**ビルドツリーから使う場合（`add_subdirectory`）は `pixkit::codec`、インストール先から使う場合は `pixkit::pixkit-codec`** という食い違いが生まれる。第6章6節でALIASを定義した目的が台無しだ。

### 解決：`EXPORT_NAME` プロパティ

```cmake
set_target_properties(pixkit-core PROPERTIES EXPORT_NAME core)
```

これで、エクスポート時の名前が `core` になる。`NAMESPACE pixkit::` と合わせて **`pixkit::core`** だ。

```cmake
add_library(pixkit::options INTERFACE IMPORTED)
add_library(pixkit::core INTERFACE IMPORTED)
add_library(pixkit::codec STATIC IMPORTED)
add_library(pixkit::filter SHARED IMPORTED)
```

**ALIASと完全に一致した。**

### 定型として書く

ALIASと `EXPORT_NAME` は必ずセットにする。

```cmake
add_library(pixkit-codec STATIC src/ppm.cpp)
add_library(pixkit::codec ALIAS pixkit-codec)
set_target_properties(pixkit-codec PROPERTIES EXPORT_NAME codec)
```

3行を1つの単位として覚えてしまうのがよい。ヘルパー関数にまとめる手もある。

```cmake
function(pixkit_add_alias TARGET SHORT_NAME)
    add_library(pixkit::${SHORT_NAME} ALIAS ${TARGET})
    set_target_properties(${TARGET} PROPERTIES EXPORT_NAME ${SHORT_NAME})
endfunction()

add_library(pixkit-codec STATIC src/ppm.cpp)
pixkit_add_alias(pixkit-codec codec)
```

**この落とし穴は、消費者プロジェクトを作って検証するまで気づけない**（22.7節）。自分のビルドツリーの中ではALIASが使えてしまうからだ。

## 22.3　`Config.cmake` を作る

### なぜ `targets.cmake` だけでは足りないのか

`pixkit-targets.cmake` はターゲット定義を持っているが、`find_package(pixkit)` はこれを直接は探さない。探すのは `pixkitConfig.cmake` または `pixkit-config.cmake` だ（第18章1節）。

そして、Configファイルには targets.cmake の読み込み以外にもやることがある。

- **依存パッケージを再解決する**（22.5節）
- コンポーネントの検査
- 利用者向けの変数の定義

### テンプレートを書く

`cmake/pixkit-config.cmake.in`

```cmake
@PACKAGE_INIT@

include(CMakeFindDependencyMacro)

# pixkit 自体は外部依存を持たないが、増えたらここに書く
# find_dependency(ZLIB)

include("${CMAKE_CURRENT_LIST_DIR}/pixkit-targets.cmake")

check_required_components(pixkit)
```

### `configure_package_config_file`

```cmake
include(CMakePackageConfigHelpers)

configure_package_config_file(
    "${CMAKE_CURRENT_SOURCE_DIR}/cmake/pixkit-config.cmake.in"
    "${CMAKE_CURRENT_BINARY_DIR}/pixkit-config.cmake"
    INSTALL_DESTINATION ${CMAKE_INSTALL_LIBDIR}/cmake/pixkit
)
```

第8章4節で使った `configure_file` の親戚だが、**`@PACKAGE_INIT@` を特別に展開する**点が違う。展開後はこうなる。

```cmake
get_filename_component(PACKAGE_PREFIX_DIR "${CMAKE_CURRENT_LIST_DIR}/../../../" ABSOLUTE)

macro(set_and_check _var _file)
  set(${_var} "${_file}")
  if(NOT EXISTS "${_file}")
    message(FATAL_ERROR "File or directory ${_file} referenced by variable ${_var} does not exist !")
  endif()
endmacro()

macro(check_required_components _NAME)
  foreach(comp ${${_NAME}_FIND_COMPONENTS})
    if(NOT ${_NAME}_${comp}_FOUND)
      if(${_NAME}_FIND_REQUIRED_${comp})
        set(${_NAME}_FOUND FALSE)
      endif()
    endif()
  endforeach()
endmacro()
```

`PACKAGE_PREFIX_DIR` は、**Configファイルの位置から逆算したインストールプレフィックス**だ。`INSTALL_DESTINATION` に `lib/cmake/pixkit` を指定したので、そこから3階層上がプレフィックスになる。この計算を自動でやってくれるのが `configure_package_config_file` の価値だ。

**普通の `configure_file` を使ってはいけない。** `@PACKAGE_INIT@` が展開されず、`PACKAGE_PREFIX_DIR` も定義されない。

### インストールする

```cmake
install(FILES
    "${CMAKE_CURRENT_BINARY_DIR}/pixkit-config.cmake"
    "${CMAKE_CURRENT_BINARY_DIR}/pixkit-config-version.cmake"
    DESTINATION ${CMAKE_INSTALL_LIBDIR}/cmake/pixkit
)
```

### ファイル名の規約

| 書き方 | 探されるファイル名 |
| --- | --- |
| `find_package(pixkit)` | `pixkitConfig.cmake` **または** `pixkit-config.cmake` |

どちらでもよい。本書は小文字ハイフン形式（`pixkit-config.cmake`）を使う。vcpkgのポートでもこの形式が多い。

**バージョンファイルの名前は、Configファイルに揃える。**

| Config | Version |
| --- | --- |
| `pixkitConfig.cmake` | `pixkitConfigVersion.cmake` |
| `pixkit-config.cmake` | `pixkit-config-version.cmake` |

## 22.4　バージョンファイルと互換性ポリシー

```cmake
write_basic_package_version_file(
    "${CMAKE_CURRENT_BINARY_DIR}/pixkit-config-version.cmake"
    VERSION       ${pixkit_VERSION}
    COMPATIBILITY SameMajorVersion
)
```

このファイルは、`find_package(pixkit 0.1 REQUIRED)` のようにバージョンが指定されたときに、**要求を満たすかどうかを判定する。**

### 互換性ポリシー

| 値 | 意味 |
| --- | --- |
| `AnyNewerVersion` | インストール版が要求以上なら何でもOK |
| **`SameMajorVersion`** | **メジャーが同じで、インストール版が要求以上ならOK** |
| `SameMinorVersion` | メジャーとマイナーが同じで、以上ならOK |
| `ExactVersion` | 完全一致のみ |

**セマンティックバージョニングに従うなら `SameMajorVersion` が標準的な選択だ。**

### 実際の挙動

インストールされているのが 0.1.0 のとき、

| 要求 | 結果 | 理由 |
| --- | --- | --- |
| `find_package(pixkit 0.1 ...)` | **成功** | メジャー一致、0.1.0 ≧ 0.1 |
| `find_package(pixkit 0.2 ...)` | **失敗** | 0.1.0 < 0.2 |
| `find_package(pixkit 1.0 ...)` | **失敗** | メジャーが違う |
| `find_package(pixkit ...)` | 成功 | バージョン指定なし |

失敗時のメッセージは親切だ。

```
CMake Error at CMakeLists.txt:3 (find_package):
  Could not find a configuration file for package "pixkit" that is compatible
  with requested version "0.2".

  The following configuration files were considered but not accepted:

    C:/work/pixkit/out/install/x64-release/lib/cmake/pixkit/pixkit-config.cmake, version: 0.1.0
```

**「見つかったが、バージョンが合わなかった」ことがはっきり分かる。** バージョンファイルを用意していないと、「見つからない」としか言われず原因が分からない。

### `ARCH_INDEPENDENT`

ヘッダーオンリーライブラリだけを配布する場合、アーキテクチャの検査を外せる。

```cmake
write_basic_package_version_file(
    "${CMAKE_CURRENT_BINARY_DIR}/pixkit-config-version.cmake"
    VERSION       ${pixkit_VERSION}
    COMPATIBILITY SameMajorVersion
    ARCH_INDEPENDENT
)
```

既定では「32bitでビルドしたパッケージを64bitのプロジェクトから使う」ことが拒否される。`pixkit` は `.lib` と `.dll` を持つので、**この検査は残すべきだ。**

## 22.5　`find_dependency` で依存を再解決する

### 問題

`pixkit` が `ZLIB` に `PUBLIC` でリンクしているとする。エクスポートされた `pixkit-targets.cmake` には、こう書かれる。

```cmake
set_target_properties(pixkit::codec PROPERTIES
  INTERFACE_LINK_LIBRARIES "pixkit::core;ZLIB::ZLIB"
)
```

利用者が `find_package(pixkit CONFIG REQUIRED)` すると、こうなる。

```
CMake Error: The link interface of target "pixkit::codec" contains:
    ZLIB::ZLIB
  but the target was not found.
```

**`ZLIB::ZLIB` は誰も定義していない。** `pixkit` 側で `find_package(ZLIB)` を呼んだのは**あなたのビルド時**であって、利用者のビルド時ではない。

### 解決：Configファイルで再解決する

```cmake
@PACKAGE_INIT@

include(CMakeFindDependencyMacro)

find_dependency(ZLIB REQUIRED)

include("${CMAKE_CURRENT_LIST_DIR}/pixkit-targets.cmake")

check_required_components(pixkit)
```

`find_dependency` は `find_package` の薄いラッパーで、**`QUIET` や `REQUIRED` の指定を呼び出し元から引き継ぐ**。利用者が `find_package(pixkit QUIET)` と書いたなら、依存の検索も静かに行われる。

### 何を書くべきか

第6章3節の判断基準がそのまま使える。

| リンク方法 | Configファイルに書くか |
| --- | --- |
| `PUBLIC` / `INTERFACE` でリンクした依存 | **書く** |
| `PRIVATE` でリンクした依存（静的ライブラリ） | **書く**（リンクは伝播するため。第9章4節） |
| `PRIVATE` でリンクした依存（動的ライブラリ） | 不要 |

**静的ライブラリの `PRIVATE` 依存は書く必要がある**ことに注意する。第9章4節で説明したとおり、`$<LINK_ONLY:...>` としてリンク情報は伝播するからだ。

### `pixkit` の場合

外部依存がないので、いまは何も書かない。しかし**書く場所を用意しておく**ことが大事だ。

```cmake
@PACKAGE_INIT@

include(CMakeFindDependencyMacro)

# 外部依存が増えたらここに追加する
# find_dependency(ZLIB)

include("${CMAKE_CURRENT_LIST_DIR}/pixkit-targets.cmake")

check_required_components(pixkit)
```

**依存を追加したときに、ここを更新し忘れる**のが最頻出の事故だ。22.7節の消費者プロジェクトでの検証が、それを捕まえる。

## 22.6　`export(EXPORT)` — ビルドツリーから使う

インストールせずに、ビルドツリーを直接 `find_package` の対象にできる。

```cmake
export(EXPORT pixkit-targets
    FILE      "${CMAKE_CURRENT_BINARY_DIR}/pixkit-targets.cmake"
    NAMESPACE pixkit::
)
```

`install(EXPORT)` とほぼ同じだが、**構成時にビルドディレクトリへ直接書き出す**（インストールを待たない）。

利用側は次のようにする。

```
cmake -S . -B build -Dpixkit_DIR=C:/work/pixkit/out/build/x64-debug
```

### 使い道

| 場面 | 説明 |
| --- | --- |
| CI での検証 | インストールせずに消費者プロジェクトをテストできる |
| 依存ライブラリを同時に開発している | ビルドツリーを直接指す |
| ユーザーパッケージレジストリ | `export(PACKAGE pixkit)` でシステムに登録（**非推奨**） |

`export(PACKAGE)` は、ユーザーのホームディレクトリにパッケージの場所を記録する仕組みだが、**「どこから来たか分からないパッケージが見つかる」という混乱を招く**ため、CMake 3.15以降は既定で無効になっている。使わない。

### `pixkit` では

本書では `install(EXPORT)` を主とし、`export(EXPORT)` は使わない。**インストールした状態で検証するほうが、本番に近いからだ。**

## 22.7　消費者プロジェクトで検証する

**この節が、この章で最も重要だ。**

自分のプロジェクトの中でいくらビルドが通っても、パッケージが正しいかは分からない。**別のプロジェクトから使ってみるまで、バグは見えない。**

検証で見つかる典型的な問題を挙げる。

| 問題 | 自分のビルドでは |
| --- | --- |
| `EXPORT_NAME` を書き忘れた（22.2節） | ALIASが使えるので気づかない |
| `find_dependency` を書き忘れた（22.5節） | 自分では `find_package` 済みなので気づかない |
| ヘッダのインストール漏れ | ソースツリーから読めるので気づかない |
| 内部ヘッダを公開してしまった | 問題として現れない |
| `$<INSTALL_INTERFACE:>` の書き間違い | ビルドツリーでは正しいパスが使われる |

**すべて「自分のビルドツリーからは見えない」問題だ。**

### 消費者プロジェクトの作り方

```cmake
cmake_minimum_required(VERSION 3.28)
project(pixkit-consumer LANGUAGES CXX)

find_package(pixkit 0.1 CONFIG REQUIRED)

add_executable(app main.cpp)
target_link_libraries(app PRIVATE pixkit::codec pixkit::filter)
```

**ポイントは、`pixkit` のソースツリーに一切触れないこと。** インストールツリーだけを見る。

```
cmake -S . -B build -DCMAKE_PREFIX_PATH=C:/work/pixkit/out/install/x64-release
```

### CIに組み込む

```yaml
      - name: pixkit をビルド・インストール
        run: |
          cmake --preset x64-release
          cmake --build --preset x64-release
          cmake --install out/build/x64-release --prefix ${{ github.workspace }}/dist

      - name: 消費者プロジェクトで検証
        run: |
          cmake -S examples/consumer -B out/consumer -G Ninja `
                -DCMAKE_BUILD_TYPE=Release `
                -DCMAKE_PREFIX_PATH=${{ github.workspace }}/dist
          cmake --build out/consumer
          ./out/consumer/app.exe
```

**パッケージの品質は、この検証を回しているかどうかで決まる。** 第15章7節で作ったCIに、必ず追加する。

## 22.8　よくある失敗

### 1. `EXPORT_NAME` の書き忘れ（22.2節）

`pixkit::pixkit-core` になる。**消費者プロジェクトを作るまで気づかない。**

### 2. 絶対パスの混入（第21章7節）

```
Target "pixkit-codec" INTERFACE_INCLUDE_DIRECTORIES property contains path:
  "C:/work/pixkit/libs/codec/include" which is prefixed in the source directory.
```

`$<BUILD_INTERFACE:>` か `FILE_SET HEADERS` を使う。

### 3. エクスポートセットの漏れ（22.1節）

```
includes target "pixkit-core" which requires target "pixkit_options"
that is not in any export set.
```

依存するターゲットをすべてエクスポートセットに入れる。

### 4. `find_dependency` の書き忘れ（22.5節）

```
The link interface of target "pixkit::codec" contains: ZLIB::ZLIB
but the target was not found.
```

### 5. `configure_file` を使ってしまった

```cmake
configure_file(cmake/pixkit-config.cmake.in pixkit-config.cmake @ONLY)   # 間違い
```

`@PACKAGE_INIT@` が展開されず、そのまま文字列として残る。`configure_package_config_file` を使う。

### 6. Debug構成をインストールしていない

利用者がDebugビルドをすると、Releaseの `.lib` がリンクされる（あるいは見つからない）。両構成をインストールする。

```
cmake --install out/build/x64-debug
cmake --install out/build/x64-release
```

**同じプレフィックスにインストールすれば、`pixkit-targets-debug.cmake` と `pixkit-targets-release.cmake` が共存する。** ただし、そのためには `DEBUG_POSTFIX`（第11章6節）でファイル名を分けておく必要がある。

### 7. コンポーネントを検査していない

```cmake
find_package(pixkit CONFIG REQUIRED COMPONENTS codec filter)
```

利用者がこう書いても、`check_required_components` が何も検査しなければ通ってしまう。厳密にやるなら、Configファイルでコンポーネントごとの検査を書く。

```cmake
foreach(comp ${pixkit_FIND_COMPONENTS})
    if(TARGET pixkit::${comp})
        set(pixkit_${comp}_FOUND TRUE)
    else()
        set(pixkit_${comp}_FOUND FALSE)
    endif()
endforeach()

check_required_components(pixkit)
```

## ハンズオン：`find_package` 対応を完成させる

### 手順1：`EXPORT_NAME` を設定する

各ライブラリの `CMakeLists.txt` に追加する。

`cmake/PixkitOptions.cmake`

```cmake
add_library(pixkit_options INTERFACE)
add_library(pixkit::options ALIAS pixkit_options)
set_target_properties(pixkit_options PROPERTIES EXPORT_NAME options)
```

`libs/core/CMakeLists.txt`

```cmake
add_library(pixkit-core INTERFACE)
add_library(pixkit::core ALIAS pixkit-core)
set_target_properties(pixkit-core PROPERTIES EXPORT_NAME core)
```

`libs/codec/CMakeLists.txt`、`libs/filter/CMakeLists.txt` も同様に。

**`pixkit_warnings` は含めない。** 第7章7節で述べたとおり、警告設定は利用者に押し付けない。`PRIVATE` でリンクしているので、エクスポートセットに入れる必要もない。

### 手順2：Configテンプレートを作る

`cmake/pixkit-config.cmake.in`

```cmake
@PACKAGE_INIT@

include(CMakeFindDependencyMacro)

# 外部依存が増えたら、ここに find_dependency を追加する
# find_dependency(ZLIB)
```

## この章のまとめ

- `install(TARGETS ... EXPORT <set>)` で登録し、**`install(EXPORT <set> ...)` で書き出す**。2段階になっている
- **`NAMESPACE` は実ターゲット名に接頭辞を付けるだけ。ALIASは見ていない。** `pixkit::core` を実現するには **`set_target_properties(pixkit-core PROPERTIES EXPORT_NAME core)`** が必要。ALIASと `EXPORT_NAME` は常にセットで書く
- 依存するターゲットは**すべて同じエクスポートセットに入れる**（`pixkit_options` を忘れない）
- Configファイルは **`configure_package_config_file`** で生成する。`configure_file` では `@PACKAGE_INIT@` が展開されない
- **`write_basic_package_version_file`** でバージョン照合ができるようにする。`COMPATIBILITY` は通常 **`SameMajorVersion`**
- `PUBLIC`/`INTERFACE` の依存（および**静的ライブラリの `PRIVATE` 依存**）は、Configファイルで **`find_dependency`** して再解決する
- **消費者プロジェクトを作って検証する。** `EXPORT_NAME` の書き忘れ、`find_dependency` の漏れ、ヘッダのインストール漏れは、**すべて自分のビルドツリーからは見えない**
- Debug/Release の両方をインストールするなら、**`DEBUG_POSTFIX` でファイル名を分ける**

これで `pixkit` は、CMakeの世界における「正しいパッケージ」になった。`find_package(pixkit CONFIG REQUIRED)` の1行で使える。

しかし、まだ利用者は「どこかからダウンロードして、自分でビルドして、インストールする」必要がある。次の第23章では、これを **vcpkgのポート**にして、`vcpkg install pixkit` で入るようにする。**この章で作った `find_package` 対応が、そのまま前提条件になる。**
