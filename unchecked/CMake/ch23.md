# 第23章　自作ライブラリをvcpkgポートにする

## この章のゴール

- ポートの構成要素（`vcpkg.json` / `portfile.cmake` / `usage`）を理解する
- `vcpkg_from_github` でソースを取得し、**SHA512を求める**
- `vcpkg_cmake_configure` / `vcpkg_cmake_install` / **`vcpkg_cmake_config_fixup`** を使う
- インストール後のレイアウトを vcpkg の規約に合わせる
- ライセンスファイルを正しく配置する
- **static / dynamic 両方のトリプレットで壊れないポートにする**
- `usage` ファイルで使い方を案内する
- **オーバーレイポートとして手元でテストする**

第22章で `pixkit` は `find_package` で使えるパッケージになった。この章では、それを **`vcpkg install pixkit` で入る**ようにする。

**重要な前提：第22章の作業が終わっていないと、この章は成立しない。** vcpkgのポートがやっているのは、要するに「ダウンロード → CMakeで構成 → ビルド → インストール」であり、その最後の「インストール」が正しくなければ何も始まらない。

---

## 23.1　ポートの構成要素

### 最小構成

```
ports/pixkit/
├── vcpkg.json           ← パッケージのメタデータ
├── portfile.cmake       ← ビルド手順
└── usage                ← 使い方の案内（任意だが推奨）
```

### `vcpkg.json`（ポート側）

**第19章2節で書いた `vcpkg.json`（プロジェクト側）とは役割が違う。** 紛らわしいので整理する。

| | プロジェクトの `vcpkg.json` | **ポートの `vcpkg.json`** |
| --- | --- | --- |
| 置き場所 | プロジェクトのルート | `ports/<name>/` |
| 役割 | **「私はこれを必要とする」** | **「私はこういうパッケージだ」** |
| `dependencies` | 使う側の依存 | このパッケージのビルド・利用に必要なもの |
| `version` | 任意 | **必須** |

```json
{
  "$schema": "https://raw.githubusercontent.com/microsoft/vcpkg-tool/main/docs/vcpkg.schema.json",
  "name": "pixkit",
  "version": "0.1.0",
  "description": "A small image processing library collection",
  "homepage": "https://github.com/example/pixkit",
  "license": "MIT",
  "supports": "windows",
  "dependencies": [
    {
      "name": "vcpkg-cmake",
      "host": true
    },
    {
      "name": "vcpkg-cmake-config",
      "host": true
    }
  ]
}
```

### `vcpkg-cmake` と `vcpkg-cmake-config`

この2つは**ヘルパーポート**だ。

| ポート | 提供する関数 |
| --- | --- |
| `vcpkg-cmake` | `vcpkg_cmake_configure` / `vcpkg_cmake_install` / `vcpkg_cmake_build` |
| `vcpkg-cmake-config` | **`vcpkg_cmake_config_fixup`** |

**`"host": true` が必須だ。** これらはビルドマシン上で動くツールであって、ターゲット環境向けにビルドするものではない。クロスコンパイル時に効いてくる。

### `supports`

```json
"supports": "windows"
```

対応プラットフォームを宣言する。`pixkit` はWindows専用（`__declspec` を使っている、第11章）なので、こう書く。

対応外の環境でインストールしようとすると、分かりやすく失敗する。

```
error: pixkit does not support x64-linux
```

**クロスプラットフォーム対応にするなら、この行を消す**。その場合は第11章3節の `CXX_VISIBILITY_PRESET` などが効いてくる。

### `description` と `homepage`

`vcpkg search` の結果に表示される。**英語で書くのが慣習**だ（公式レジストリに出すなら必須）。

## 23.2　ソースの取得とSHA512

### `vcpkg_from_github`

`portfile.cmake` の最初の仕事は、ソースを持ってくることだ。

```cmake
vcpkg_from_github(
    OUT_SOURCE_PATH SOURCE_PATH
    REPO            example/pixkit
    REF             "v${VERSION}"
    SHA512          0
    HEAD_REF        main
)
```

| 引数 | 意味 |
| --- | --- |
| `OUT_SOURCE_PATH` | 展開先を受け取る変数（**慣習的に `SOURCE_PATH`**） |
| `REPO` | `<owner>/<repo>` |
| `REF` | **タグまたはコミットID。ブランチ名は使わない** |
| `SHA512` | アーカイブのハッシュ |
| `HEAD_REF` | `--head` オプション用のブランチ名 |

`${VERSION}` は `vcpkg.json` の `version` から自動的に設定される変数だ。**`vcpkg.json` を更新すれば、`portfile.cmake` を直さなくてよい。**

### SHA512の求め方

**わざと `0` を指定してビルドし、エラーメッセージから読み取る。** これが公式に案内されている方法だ。

```cmake
SHA512 0
```

```
vcpkg install pixkit --overlay-ports=ports
```

```
error: Failed to download from mirror set
File does not have the expected hash:
             File path: [ .../downloads/example-pixkit-v0.1.0.tar.gz ]
         Expected hash: [ 0 ]
           Actual hash: [ 3a7bd3e2360a3d29eea436fcfb7e44c735d117c42d1c1835420b6b9942dd4735... ]
```

この `Actual hash` を `portfile.cmake` に書き戻す。

```cmake
SHA512 3a7bd3e2360a3d29eea436fcfb7e44c735d117c42d1c1835420b6b9942dd4735...
```

**このハッシュは、そのバージョンのソースが改ざんされていないことの保証になる。** タグを付け替えられても検出できる。

### 開発中はローカルソースを使う

ハッシュを毎回求めるのは面倒だ。ポートを書いている最中は、ローカルのディレクトリを直接使うほうが速い。

```cmake
# 開発中のみ
set(SOURCE_PATH "C:/work/pixkit")
```

あるいは、`vcpkg_from_git` でローカルリポジトリを指す方法もある。

```cmake
vcpkg_from_git(
    OUT_SOURCE_PATH SOURCE_PATH
    URL             "file:///C:/work/pixkit"
    REF             "abcdef1234567890..."
)
```

**23.8節のハンズオンでは、この手法でポートを開発する。**

## 23.3　構成・ビルド・インストール

### 3つの関数

```cmake
vcpkg_cmake_configure(
    SOURCE_PATH "${SOURCE_PATH}"
    OPTIONS
        -DPIXKIT_BUILD_TESTS=OFF
        -DPIXKIT_BUILD_BENCHMARKS=OFF
        -DPIXKIT_BUILD_APPS=OFF
)

vcpkg_cmake_install()

vcpkg_cmake_config_fixup(
    PACKAGE_NAME pixkit
    CONFIG_PATH  lib/cmake/pixkit
)
```

### `vcpkg_cmake_configure`

CMakeの構成を行う。vcpkgが自動的に渡すもの（トリプレットに応じた `CMAKE_MSVC_RUNTIME_LIBRARY`、`BUILD_SHARED_LIBS`、インストールプレフィックスなど）に加えて、`OPTIONS` で指定したものが渡る。

**テスト・ベンチマーク・CLIツールを明示的に切っている**のが重要だ。第8章5節で用意したオプションが、ここで効く。

- テストをビルドすると、GoogleTestが必要になる（ポートの依存が増える）
- 時間がかかる
- 配布物にCLIツールが混ざる

**第14章7節・第19章2節で「ライブラリの利用者にテストフレームワークを強制しない」と述べてきたことが、ここで具体的な形になる。**

### `vcpkg_cmake_install`

```cmake
vcpkg_cmake_install()
```

Debug構成とRelease構成の**両方**をビルドしてインストールする（トリプレットが `VCPKG_BUILD_TYPE release` でない限り。第20章3節）。

結果はこうなる。

```
${CURRENT_PACKAGES_DIR}/
├── include/                    ← Release からのヘッダ
├── lib/
├── bin/
├── share/
└── debug/
    ├── lib/
    └── bin/
```

**ヘッダは Release 側にだけ置き、Debug 側は削除する**のがvcpkgの規約だ（23.4節）。

### `vcpkg_cmake_config_fixup`

**この関数が、ポート作成で最も理解しにくい部分だ。**

```cmake
vcpkg_cmake_config_fixup(
    PACKAGE_NAME pixkit
    CONFIG_PATH  lib/cmake/pixkit
)
```

| 引数 | 意味 |
| --- | --- |
| `PACKAGE_NAME` | `find_package()` に渡す名前。既定は `${PORT}` |
| `CONFIG_PATH` | **Configファイルがインストールされた場所**。既定は `share/${PACKAGE_NAME}` |

やっていることは、

1. **DebugとReleaseのターゲットファイルを1つにまとめる**
   `vcpkg_cmake_install` は両構成をインストールするので、`lib/cmake/pixkit/` と `debug/lib/cmake/pixkit/` の両方に `pixkit-targets-*.cmake` ができる。これを Release 側にマージする
2. **Configファイルを `share/pixkit/` に移動する**
   vcpkgの規約では、CMakeのパッケージ設定は `share/<port>/` に置く
3. **絶対パスを `${_IMPORT_PREFIX}` に置き換える**
4. Debug側の重複ファイルを削除する

**`CONFIG_PATH` の指定を間違えると、この関数は何も見つけられずエラーになる。**

```
error: vcpkg_cmake_config_fixup called with CONFIG_PATH lib/cmake/pixkit
but that path does not exist
```

第22章3節で `DESTINATION ${CMAKE_INSTALL_LIBDIR}/cmake/pixkit` と書いたので、`lib/cmake/pixkit` が正しい。もし `share/pixkit` にインストールしていれば、`CONFIG_PATH` の指定自体が不要になる。

### 実行後のレイアウト

```
${CURRENT_PACKAGES_DIR}/
├── include/pixkit/...
├── lib/pixkit-codec.lib
├── bin/pixkit-filter.dll
├── share/pixkit/
│   ├── pixkit-config.cmake
│   ├── pixkit-config-version.cmake
│   ├── pixkit-targets.cmake
│   ├── pixkit-targets-release.cmake
│   ├── pixkit-targets-debug.cmake     ← Debug の情報がここに統合された
│   ├── copyright
│   └── usage
└── debug/
    ├── lib/pixkit-codecd.lib
    └── bin/pixkit-filterd.dll
```

**第20章5節で `vcpkg_installed/` の中を見たときの構造と同じだ。** 他のライブラリがどうなっていたかを思い出しながら作業すると、目標がはっきりする。

## 23.4　レイアウトを規約に合わせる

`vcpkg_cmake_install` の直後には、規約に合わない部分が残っている。整える。

### Debug側のヘッダを消す

```cmake
file(REMOVE_RECURSE "${CURRENT_PACKAGES_DIR}/debug/include")
```

**ヘッダは構成によらず同じなので、2つ持つ意味がない。** これを消さないと、vcpkgのポリシーチェックに引っかかる。

```
error: The following files are placed in .../debug/include: pixkit/core/pixel.hpp
Debug include files should not be duplicated.
```

**vcpkgは、ポートが規約に従っているかを自動的に検査する。** エラーメッセージが対処法まで教えてくれるので、素直に従えばよい。

### Debug側のshareを消す

```cmake
file(REMOVE_RECURSE "${CURRENT_PACKAGES_DIR}/debug/share")
```

`vcpkg_cmake_config_fixup` がたいてい面倒を見てくれるが、残ることもある。

### 実行ファイルの扱い

`pixcli.exe` をインストールしていると、`bin/` に入ってしまう。**vcpkgでは、ツール類は `tools/<port>/` に置く規約だ。**

```cmake
vcpkg_copy_tools(TOOL_NAMES pixcli AUTO_CLEAN)
```

ただし、`pixkit` のポートでは `-DPIXKIT_BUILD_APPS=OFF` にしているので、そもそも `pixcli` はビルドされない。**ライブラリとツールは別のポートに分けるのが本来の姿だ。**

### PDBをコピーする

```cmake
vcpkg_copy_pdbs()
```

`.dll` の隣に対応する `.pdb` を配置する。第12章6節・第21章5節で扱ったデバッグ情報だ。**動的ライブラリを提供するポートでは、書いておくのが親切。**

### 空ディレクトリを消す

静的リンクのトリプレット（第19章5節）では `bin/` が空になる。

```cmake
if(VCPKG_LIBRARY_LINKAGE STREQUAL "static")
    file(REMOVE_RECURSE
        "${CURRENT_PACKAGES_DIR}/bin"
        "${CURRENT_PACKAGES_DIR}/debug/bin")
endif()
```

これも規約チェックに引っかかる項目だ。

```
error: The following directories are empty: /bin
```

## 23.5　ライセンス

```cmake
vcpkg_install_copyright(FILE_LIST "${SOURCE_PATH}/LICENSE")
```

`share/<port>/copyright` にコピーされる。**第20章5節で他のライブラリを調べたときに見たファイルが、これだ。**

複数のライセンスファイルがある場合は、まとめられる。

```cmake
vcpkg_install_copyright(
    FILE_LIST
        "${SOURCE_PATH}/LICENSE"
        "${SOURCE_PATH}/third_party/LICENSE-zlib"
)
```

**これを書かないと、ポリシーチェックでエラーになる。**

```
error: The port did not install a copyright file.
```

vcpkgは**ライセンス表示を強制する。** 第18章7節で述べた配布の義務が、仕組みとして担保されている。

## 23.6　static / dynamic 両対応にする

vcpkgのポートは、**利用者が選んだトリプレットに応じて正しくビルドされなければならない**（第19章5節）。

### `BUILD_SHARED_LIBS` は自動で渡る

`vcpkg_cmake_configure` は、トリプレットの `VCPKG_LIBRARY_LINKAGE` に応じて `BUILD_SHARED_LIBS` を設定する。

| トリプレット | `VCPKG_LIBRARY_LINKAGE` | 渡る値 |
| --- | --- | --- |
| `x64-windows` | `dynamic` | `BUILD_SHARED_LIBS=ON` |
| `x64-windows-static` | `static` | `BUILD_SHARED_LIBS=OFF` |
| `x64-windows-static-md` | `static` | `BUILD_SHARED_LIBS=OFF` |

**第11章8節で `pixkit-filter` を `BUILD_SHARED_LIBS` 対応にしておいたのが、ここで効く。**

```cmake
add_library(pixkit-filter                        # SHARED を書かない
    src/filters.cpp
    ...
)

get_target_property(PIXKIT_FILTER_TYPE pixkit-filter TYPE)
if(PIXKIT_FILTER_TYPE STREQUAL "STATIC_LIBRARY")
    target_compile_definitions(pixkit-filter PUBLIC PIXKIT_FILTER_STATIC_DEFINE)
endif()
```

`PIXKIT_FILTER_STATIC_DEFINE` を `PUBLIC` にしてあることが決定的だ。この定義は**エクスポートされる**（第22章1節）ので、利用者のコンパイル時にも渡る。静的ライブラリなのに `__declspec(dllimport)` が付いてリンクエラーになる、という事故を防いでいる。

### CRTの整合

`VCPKG_CRT_LINKAGE` に応じて `CMAKE_MSVC_RUNTIME_LIBRARY` が設定される。**あなたのCMakeLists.txtで `CMAKE_MSVC_RUNTIME_LIBRARY` を上書きしていると、これを壊す。**

第12章5節で `/MT` を試したときの設定を残していないか確認する。**ライブラリ側では、ランタイムの選択を固定してはいけない。**

### 両方でテストする

```
vcpkg install pixkit:x64-windows        --overlay-ports=ports
vcpkg install pixkit:x64-windows-static --overlay-ports=ports
```

**両方が通って初めて、ポートとして成立する。**

### featureを持たせる

ポート側でもfeatureを定義できる（第20章1節）。

```json
"features": {
  "tools": {
    "description": "Install the pixcli command line tool",
    "supports": "!staticcrt"
  }
}
```

```cmake
vcpkg_check_features(
    OUT_FEATURE_OPTIONS FEATURE_OPTIONS
    FEATURES
        tools PIXKIT_BUILD_APPS
)

vcpkg_cmake_configure(
    SOURCE_PATH "${SOURCE_PATH}"
    OPTIONS
        ${FEATURE_OPTIONS}
        -DPIXKIT_BUILD_TESTS=OFF
        -DPIXKIT_BUILD_BENCHMARKS=OFF
)
```

`vcpkg_check_features` は、「featureが有効なら `-DPIXKIT_BUILD_APPS=ON`、無効なら `-DPIXKIT_BUILD_APPS=OFF`」というオプション列を作ってくれる。**featureとCMakeオプションの対応を宣言的に書ける。**

## 23.7　`usage` ファイル

`ports/pixkit/usage`

```
pixkit provides CMake targets:

    find_package(pixkit CONFIG REQUIRED)
    target_link_libraries(main PRIVATE pixkit::core pixkit::codec pixkit::filter)
```

```cmake
file(INSTALL "${CMAKE_CURRENT_LIST_DIR}/usage"
     DESTINATION "${CURRENT_PACKAGES_DIR}/share/${PORT}")
```

インストール後、vcpkgがこの内容を表示する。

```
The package pixkit provides CMake targets:

    find_package(pixkit CONFIG REQUIRED)
    target_link_libraries(main PRIVATE pixkit::core pixkit::codec pixkit::filter)
```

**利用者が最初に見る説明がこれだ。** ここに正しいターゲット名を書いておかないと、利用者は `pixkit::pixkit-core` と書いて悩むことになる（第22章2節）。

`${CMAKE_CURRENT_LIST_DIR}` は `portfile.cmake` があるディレクトリを指す。`${CURRENT_PORT_DIR}` でも同じだ。

**短く、コピーして貼れる形にする。** 長い説明はREADMEに書けばよい。

## 23.8　オーバーレイポートとしてテストする

第20章3節・9節で用意した仕組みを使う。

```
C:\work\pixkit\ports\pixkit\
├── vcpkg.json
├── portfile.cmake
└── usage
```

```
vcpkg install pixkit --overlay-ports=C:\work\pixkit\ports
```

あるいは、プリセットに `VCPKG_OVERLAY_PORTS` を設定してあるので（第20章9節）、**別のプロジェクトから `vcpkg.json` で依存すればよい。**

### 循環に注意

`pixkit` 自身のプロジェクトが `pixkit` に依存することはできない。**テスト用の消費者プロジェクトを別に用意する。** 第22章7節で作った `examples/consumer/` を、vcpkg経由で使う形に変える。

```
examples/consumer-vcpkg/
├── CMakeLists.txt
├── vcpkg.json
└── main.cpp
```

`examples/consumer-vcpkg/vcpkg.json`

```json
{
  "name": "pixkit-consumer",
  "version": "0.1.0",
  "dependencies": [ "pixkit" ]
}
```

これで、`vcpkg` がオーバーレイポートから `pixkit` を見つけてビルドし、`find_package(pixkit CONFIG REQUIRED)` で使えるようになる。

## ハンズオン：`pixkit` のポートを書く

### 手順1：ソースを公開する（またはローカルで代用する）

本来はGitHubにpushしてタグを付ける。

```
cd C:\work\pixkit
git tag v0.1.0
git push origin v0.1.0
```

**本書のハンズオンでは、ローカルのGitリポジトリで代用する。** 公開リポジトリを持っていなくても進められる。

```
cd C:\work\pixkit
git add -A
git commit -m "v0.1.0"
git rev-parse HEAD
```

出力されたコミットハッシュを控えておく。

### 手順2：ポートのディレクトリを作る

```
mkdir C:\work\pixkit\ports\pixkit
```

### 手順3：`vcpkg.json`（ポート側）を書く

`ports/pixkit/vcpkg.json`

```json
{
  "$schema": "https://raw.githubusercontent.com/microsoft/vcpkg-tool/main/docs/vcpkg.schema.json",
  "name": "pixkit",
  "version": "0.1.0",
  "description": "A small image processing library collection",
  "homepage": "https://github.com/example/pixkit",
  "license": "MIT",
  "supports": "windows",
  "dependencies": [
    { "name": "vcpkg-cmake",        "host": true },
    { "name": "vcpkg-cmake-config", "host": true }
  ]
}
```

### 手順4：`portfile.cmake` を書く

`ports/pixkit/portfile.cmake`

```cmake
# ------------------------------------------------------------------
# ソースの取得
# ------------------------------------------------------------------
# 本番（GitHub 公開後）はこちら:
#
# vcpkg_from_github(
#     OUT_SOURCE_PATH SOURCE_PATH
#     REPO            example/pixkit
#     REF             "v${VERSION}"
#     SHA512          0
#     HEAD_REF        main
# )

# 開発中はローカルの Git リポジトリを使う
vcpkg_from_git(
    OUT_SOURCE_PATH SOURCE_PATH
    URL             "file:///C:/work/pixkit"
    REF             "ここに手順1のコミットハッシュ"
)

# ------------------------------------------------------------------
# 構成とビルド
# ------------------------------------------------------------------
vcpkg_cmake_configure(
    SOURCE_PATH "${SOURCE_PATH}"
    OPTIONS
        -DPIXKIT_BUILD_TESTS=OFF
        -DPIXKIT_BUILD_BENCHMARKS=OFF
        -DPIXKIT_BUILD_APPS=OFF
        -DPIXKIT_INSTALL=ON
)

vcpkg_cmake_install()

# ------------------------------------------------------------------
# CMake パッケージ設定を vcpkg の規約に合わせる
# ------------------------------------------------------------------
vcpkg_cmake_config_fixup(
    PACKAGE_NAME pixkit
    CONFIG_PATH  lib/cmake/pixkit
)

# ------------------------------------------------------------------
# レイアウトの整形
# ------------------------------------------------------------------
file(REMOVE_RECURSE
    "${CURRENT_PACKAGES_DIR}/debug/include"
    "${CURRENT_PACKAGES_DIR}/debug/share"
)

if(VCPKG_LIBRARY_LINKAGE STREQUAL "static")
    file(REMOVE_RECURSE
        "${CURRENT_PACKAGES_DIR}/bin"
        "${CURRENT_PACKAGES_DIR}/debug/bin"
    )
endif()

vcpkg_copy_pdbs()

# ------------------------------------------------------------------
# ライセンスと使い方
# ------------------------------------------------------------------
vcpkg_install_copyright(FILE_LIST "${SOURCE_PATH}/LICENSE")

file(INSTALL "${CMAKE_CURRENT_LIST_DIR}/usage"
     DESTINATION "${CURRENT_PACKAGES_DIR}/share/${PORT}")
```

### 手順5：`usage` を書く

### 手順11：featureを追加する

`ports/pixkit/vcpkg.json` に追加する。

```json
"features": {
  "tools": {
    "description": "Install the pixcli command line tool"
  }
}
```

`portfile.cmake` を書き換える。

```cmake
vcpkg_check_features(
    OUT_FEATURE_OPTIONS FEATURE_OPTIONS
    FEATURES
        tools PIXKIT_BUILD_APPS
)

vcpkg_cmake_configure(
    SOURCE_PATH "${SOURCE_PATH}"
    OPTIONS
        ${FEATURE_OPTIONS}
        -DPIXKIT_BUILD_TESTS=OFF
        -DPIXKIT_BUILD_BENCHMARKS=OFF
        -DPIXKIT_INSTALL=ON
)

# ... (中略) ...

if("tools" IN_LIST FEATURES)
    vcpkg_copy_tools(TOOL_NAMES pixcli AUTO_CLEAN)
endif()
```

```
vcpkg install pixkit[tools] --overlay-ports=ports
dir %VCPKG_ROOT%\installed\x64-windows\tools\pixkit
```

```
pixcli.exe
```

**`tools/<port>/` に置かれる**のがvcpkgの規約だ（23.4節）。

### 発展課題

1. `supports` を `"!windows"` に変えて、インストールが拒否されることを確認する
2. `vcpkg_install_copyright` の行を消し、ポリシーチェックのエラーを実際に見る

## この章のまとめ

- ポートは **`vcpkg.json`（メタデータ）＋ `portfile.cmake`（ビルド手順）＋ `usage`（使い方）**
- ヘルパーポート **`vcpkg-cmake`** と **`vcpkg-cmake-config`** を `"host": true` で依存に入れる
- `vcpkg_from_github` の **SHA512 は `0` にしてビルドし、エラーメッセージから読み取る**。開発中は `vcpkg_from_git` でローカルを指すと速い
- `vcpkg_cmake_configure` の `OPTIONS` で、**テスト・ベンチマーク・ツールを明示的に切る**。第8章5節で用意したオプションがここで効く
- **`vcpkg_cmake_config_fixup`** が、Debug/Release のターゲットをマージし、Configファイルを `share/<port>/` に移動する。**`CONFIG_PATH` は第22章のインストール先と一致させる**
- レイアウトの整形が要る：**`debug/include` の削除**、静的リンク時の **`bin/` の削除**、`vcpkg_copy_pdbs`
- **`vcpkg_install_copyright` は必須。** vcpkgはライセンス表示を仕組みで強制する
- static / dynamic 両対応には、第11章8節の **`BUILD_SHARED_LIBS` 対応と `*_STATIC_DEFINE` の `PUBLIC` 定義**が前提になる。ライブラリ側で `CMAKE_MSVC_RUNTIME_LIBRARY` を固定しない
- **`usage` に正しいターゲット名を書く。** 利用者が最初に見る説明になる
- **オーバーレイポート（`--overlay-ports`）で手元でテストする。** 消費者プロジェクトは別に用意する

これで `pixkit` は「vcpkgでインストールできるライブラリ」になった。しかし、まだ**オーバーレイポートを手で指定しなければ使えない。**

最後の第24章では、これをカスタムレジストリとして公開し、**利用者が `vcpkg.json` に1行書くだけで使える**状態にする。
