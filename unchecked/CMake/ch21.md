# 第21章　`install()` でインストールできるようにする

## この章のゴール

- 「インストールする」が何をすることかを理解する
- `install(TARGETS)` の各 DESTINATION を正しく使い分ける
- `GNUInstallDirs` を使う
- **`FILE_SET HEADERS` でヘッダをディレクトリ構造ごとインストールする**
- PDB・ライセンス・実行時DLLを配布物に含める
- `cmake --install` とコンポーネント分割
- **`$<INSTALL_INTERFACE:>` がなぜ必要か**を、実際のエラーで確認する

第6部の始まりだ。ここから `pixkit` は「自分でビルドするもの」から「他人に配るもの」になる。

---

## 21.1　インストールとは何をすることか

### ビルドツリーと、インストールツリー

これまで成果物は**ビルドツリー**（`out/build/x64-debug/`）にあった。しかしこの中身は、

- 絶対パスに依存している
- 中間ファイルが大量にある
- ディレクトリ構造がビルドの都合で決まっている

配布には向かない。そこで、**必要なファイルだけを、決まった構造で別の場所にコピーする。** それが「インストール」だ。

```
ビルドツリー                          インストールツリー
out/build/x64-debug/                  C:/Program Files/pixkit/
├── bin/pixcli.exe          ────→     ├── bin/pixcli.exe
├── lib/pixkit-codec.lib    ────→     ├── lib/pixkit-codec.lib
├── CMakeFiles/...          ×         ├── include/pixkit/...
└── libs/codec/...          ×         └── lib/cmake/pixkit/...
```

### `CMAKE_INSTALL_PREFIX`

インストール先のルートを決める変数だ。既定値はWindowsでは `C:/Program Files/${PROJECT_NAME}` になる。

**開発中に既定値を使ってはいけない。** 管理者権限が必要になるうえ、システムを汚す。プリセットで明示する。

第4章で `installDir` を設定してあった。

```json
{
  "name": "base",
  "hidden": true,
  "binaryDir":  "${sourceDir}/out/build/${presetName}",
  "installDir": "${sourceDir}/out/install/${presetName}"
}
```

`installDir` はプリセットの専用フィールドで、`CMAKE_INSTALL_PREFIX` に対応する。**この章のためにあらかじめ入れておいた。**

### ステージング

「実際の配布先とは違う場所に、いったんインストールして中身を確認する」ことをステージングと呼ぶ。上の `out/install/x64-debug/` がそれだ。

**インストールした結果を目で見ることが、この章で最も大事な作業になる。** 余計なものが混ざっていないか、必要なものが揃っているかは、実際に見ないと分からない。

## 21.2　`install(TARGETS)` の DESTINATION

### 基本形

```cmake
include(GNUInstallDirs)

install(TARGETS pixkit-core pixkit-codec pixkit-filter pixcli
    RUNTIME       DESTINATION ${CMAKE_INSTALL_BINDIR}
    LIBRARY       DESTINATION ${CMAKE_INSTALL_LIBDIR}
    ARCHIVE       DESTINATION ${CMAKE_INSTALL_LIBDIR}
)
```

### 3つの種別

第11章1節・第8章6節で扱った分類が、そのまま出てくる。

| キーワード | Windowsで対象になるもの | 既定の行き先 |
| --- | --- | --- |
| `RUNTIME` | **`.exe` と `.dll`** | `bin/` |
| `ARCHIVE` | 静的ライブラリの `.lib`、**DLLのインポート `.lib`** | `lib/` |
| `LIBRARY` | Unixの `.so` / `.dylib`（Windowsではほぼ使われない） | `lib/` |

**DLLが `RUNTIME` である**ことを間違えると、DLLが `lib/` に入って実行時に見つからなくなる。第11章7節の問題が、配布物で再発することになる。

### 省略した場合

CMake 3.14以降、DESTINATION を省略すると `GNUInstallDirs` の既定値が使われる。

```cmake
install(TARGETS pixkit-codec)      # bin/ lib/ に振り分けられる
```

短く書けるが、**本書では明示する。** 「どこに何が入るか」を読む人に分からせるためだ。

## 21.3　`GNUInstallDirs`

```cmake
include(GNUInstallDirs)
```

これを `include` すると、標準的なディレクトリ名の変数が定義される。

| 変数 | 既定値 |
| --- | --- |
| `CMAKE_INSTALL_BINDIR` | `bin` |
| `CMAKE_INSTALL_LIBDIR` | `lib`（Linuxでは `lib64` になることがある） |
| `CMAKE_INSTALL_INCLUDEDIR` | `include` |
| `CMAKE_INSTALL_DATADIR` | `share` |
| `CMAKE_INSTALL_DOCDIR` | `share/doc/<project>` |

Windowsでは常に `bin` / `lib` / `include` なので、直接書いても動く。それでも `GNUInstallDirs` を使う理由は、

- **Linuxに移植したときに正しく動く**（`lib64` の問題）
- 利用者が `-DCMAKE_INSTALL_LIBDIR=lib/x86_64` のように上書きできる
- 意図が明確になる

**`include(GNUInstallDirs)` を書く前に変数を使うと、空文字列になる。** インストール関連の記述より前に置く。

## 21.4　ヘッダをインストールする

### 古い方法：`install(DIRECTORY)`

```cmake
install(DIRECTORY libs/core/include/
        DESTINATION ${CMAKE_INSTALL_INCLUDEDIR}
        FILES_MATCHING PATTERN "*.hpp")
```

ディレクトリごとコピーする。末尾のスラッシュ（`include/`）は「中身をコピーする」という意味で、なければ `include` ディレクトリごとコピーされる。**この違いを間違えると `include/include/pixkit/...` になる。**

問題点がある。

- **CMakeから見て「どのヘッダがどのターゲットのものか」が分からない**
- 生成されたヘッダ（`version.hpp`、`pixkit_filter_export.hpp`）は別のディレクトリにあるので、記述を分けなければならない
- インクルードパスの設定を別途 `$<INSTALL_INTERFACE:include>` で書く必要がある

### 新しい方法：`FILE_SET HEADERS`

CMake 3.23で導入された。第10章2節で「第21章のインストールで使う」と予告したものだ。

```cmake
target_sources(pixkit-core
    INTERFACE
        FILE_SET HEADERS
            BASE_DIRS
                "${CMAKE_CURRENT_SOURCE_DIR}/include"
                "${CMAKE_CURRENT_BINARY_DIR}/include"
            FILES
                "${CMAKE_CURRENT_SOURCE_DIR}/include/pixkit/core/pixel.hpp"
                "${CMAKE_CURRENT_SOURCE_DIR}/include/pixkit/core/color.hpp"
                "${CMAKE_CURRENT_SOURCE_DIR}/include/pixkit/core/image.hpp"
                "${CMAKE_CURRENT_BINARY_DIR}/include/pixkit/core/version.hpp"
)
```

```cmake
install(TARGETS pixkit-core ...
    FILE_SET HEADERS DESTINATION ${CMAKE_INSTALL_INCLUDEDIR}
)
```

**これだけで、`BASE_DIRS` からの相対構造を保ったままインストールされる。**

```
-- Installing: .../stage/include/pixkit/core/pixel.hpp
-- Installing: .../stage/include/pixkit/core/color.hpp
-- Installing: .../stage/include/pixkit/core/image.hpp
-- Installing: .../stage/include/pixkit/core/version.hpp
```

ソースツリーのヘッダと、ビルドツリーの生成ヘッダが、**同じ `include/pixkit/core/` にまとめられている。** `BASE_DIRS` を2つ指定した効果だ。

### さらに嬉しいこと

`FILE_SET HEADERS` は、**インクルードパスの設定も兼ねる。**

```cmake
# これを書かなくてよくなる
target_include_directories(pixkit-core INTERFACE
    $<BUILD_INTERFACE:${CMAKE_CURRENT_SOURCE_DIR}/include>
    $<INSTALL_INTERFACE:include>
)
```

`BASE_DIRS` がビルド時のインクルードパスになり、`FILE_SET HEADERS DESTINATION` がインストール後のインクルードパスになる。**2つの世界のパスが、1つの記述で両方設定される。**

第9章3節で `$<BUILD_INTERFACE:>` と `$<INSTALL_INTERFACE:>` を手で書いたが、`FILE_SET` を使うならそれも不要になる。

### 使い分け

| 状況 | 方法 |
| --- | --- |
| ヘッダの数が管理できる範囲 | **`FILE_SET HEADERS`** |
| ヘッダが数百あり、列挙が現実的でない | `install(DIRECTORY)` |
| CMake 3.23未満に対応する必要がある | `install(DIRECTORY)` |

**本書は `FILE_SET HEADERS` を使う。** 第8章7節の「ソースは明示的に列挙する」と同じ方針だ。

## 21.5　ライセンス・PDB・実行時DLL

### ライセンス

配布物にライセンス文書を含めるのは、多くのライセンスで**義務**だ（第18章7節）。

```cmake
install(FILES
    "${CMAKE_CURRENT_SOURCE_DIR}/LICENSE"
    "${CMAKE_CURRENT_SOURCE_DIR}/README.md"
    DESTINATION "${CMAKE_INSTALL_DATAROOTDIR}/pixkit"
)
```

第20章5節で見たとおり、vcpkgのパッケージは `share/<name>/copyright` にライセンスを置いている。**第23章でポート化するときは、この規約に合わせることになる。**

### PDB

第12章6節で扱ったデバッグ情報だ。**Releaseビルドの配布物には通常含めない**が、社内向けやデバッグ用の配布では必要になる。

```cmake
if(MSVC)
    install(FILES $<TARGET_PDB_FILE:pixkit-filter>
            DESTINATION ${CMAKE_INSTALL_BINDIR}
            OPTIONAL)
    install(FILES $<TARGET_PDB_FILE:pixcli>
            DESTINATION ${CMAKE_INSTALL_BINDIR}
            OPTIONAL)
endif()
```

**`OPTIONAL` が重要だ。** PDBが生成されない構成（`Release`、第12章6節）でインストールしようとすると、ファイルがなくてエラーになる。`OPTIONAL` を付ければ黙って飛ばされる。

`$<TARGET_PDB_FILE:...>` は**リンカが作るPDB**を指す。静的ライブラリ（`pixkit-codec`）はリンクされないのでPDBを持たない（第12章6節）。そちらは `COMPILE_PDB_*` プロパティで別途扱う。

### 実行時DLL

`pixcli.exe` は `pixkit-filter.dll` を必要とする。自分のプロジェクトのDLLは `install(TARGETS)` に含めれば `bin/` に入るので問題ない。

**外部のDLL**（vcpkg由来など）は別だ。第19章6節で触れた設定を使う。

```cmake
set(X_VCPKG_APPLOCAL_DEPS_INSTALL ON)
```

CMakeだけで解決するなら、`install(RUNTIME_DEPENDENCY_SET)`（CMake 3.21以降）という仕組みもある。

```cmake
install(TARGETS pixcli
    RUNTIME_DEPENDENCY_SET pixkit-deps
    RUNTIME DESTINATION ${CMAKE_INSTALL_BINDIR})

install(RUNTIME_DEPENDENCY_SET pixkit-deps
    PRE_EXCLUDE_REGEXES  "api-ms-" "ext-ms-"
    POST_EXCLUDE_REGEXES ".*system32/.*\\.dll"
    DESTINATION ${CMAKE_INSTALL_BINDIR})
```

**除外パターンを書かないと、`kernel32.dll` までコピーしようとする。** Windowsのシステムライブラリを配布物に入れてはいけない。`pixkit` は外部依存がないので本書では使わないが、実務では必要になる。

## 21.6　`cmake --install` とコンポーネント

### 実行する

```
cmake --install out/build/x64-release
```

プレフィックスを上書きすることもできる。

```
cmake --install out/build/x64-release --prefix C:/work/pixkit-dist
```

**マルチ構成ジェネレータでは `--config` が必要だ**（第2章7節、第13章2節と同じ話）。

```
cmake --install out/build/x64-vs --config Release
```

### 何が起きるか見る

```
cmake --install out/build/x64-release --verbose
```

一覧が出る。

```
-- Install configuration: "RelWithDebInfo"
-- Installing: C:/work/pixkit/out/install/x64-release/include/pixkit/core/pixel.hpp
-- Installing: C:/work/pixkit/out/install/x64-release/lib/pixkit-codec.lib
-- Installing: C:/work/pixkit/out/install/x64-release/bin/pixkit-filter.dll
...
```

**この一覧を毎回読む習慣をつける。** 意図しないものが混ざっていたら、ここで気づける。第14章4節で `INSTALL_GTEST OFF` にした効果も、ここで確認できる。

### コンポーネント

インストールを分割できる。

```cmake
install(TARGETS pixkit-core pixkit-codec pixkit-filter
    EXPORT  pixkit-targets
    RUNTIME       DESTINATION ${CMAKE_INSTALL_BINDIR}       COMPONENT runtime
    LIBRARY       DESTINATION ${CMAKE_INSTALL_LIBDIR}       COMPONENT runtime
    ARCHIVE       DESTINATION ${CMAKE_INSTALL_LIBDIR}       COMPONENT development
    FILE_SET HEADERS DESTINATION ${CMAKE_INSTALL_INCLUDEDIR} COMPONENT development
)

install(TARGETS pixcli
    RUNTIME DESTINATION ${CMAKE_INSTALL_BINDIR} COMPONENT tools)
```

```
cmake --install out/build/x64-release --component runtime
```

| コンポーネント | 中身 | 誰が要るか |
| --- | --- | --- |
| `runtime` | `.dll` | **アプリを動かす人** |
| `development` | `.lib`、ヘッダ、Config.cmake | **ライブラリを使う開発者** |
| `tools` | `pixcli.exe` | CLIツールが欲しい人 |

配布物を分けたいとき（ランタイム再頒布パッケージと開発者向けSDKを別にする、など）に使う。付録CのCPackでも、この分割がそのまま使える。

**小さなライブラリでは分ける必要はない。** ただし、「DLLとヘッダは別の役割を持つ」という認識は持っておくとよい。

## 21.7　`$<INSTALL_INTERFACE:>` がなぜ必要か

第9章3節で予告した問題を、ここで実際に起こす。

### わざと壊す

`FILE_SET HEADERS` を使わず、素朴に書いたとする。

```cmake
target_include_directories(pixkit-codec
    PUBLIC ${CMAKE_CURRENT_SOURCE_DIR}/include        # ジェネレータ式なし
)

install(TARGETS pixkit-codec EXPORT pixkit-targets ...)
```

構成すると、こうなる。

```
CMake Error in CMakeLists.txt:
  Target "pixkit-codec" INTERFACE_INCLUDE_DIRECTORIES property contains path:

    "C:/work/pixkit/libs/codec/include"

  which is prefixed in the source directory.
```

**エラーの意味はこうだ。** `install(EXPORT)`（第22章）でこのターゲットの情報を書き出そうとしたが、`INTERFACE_INCLUDE_DIRECTORIES` に**あなたのマシンのソースディレクトリの絶対パス**が入っている。それを配布物に書き込んでも、利用者の環境には存在しない。だからCMakeが拒否した。

### 解決の3通り

**方法1：`FILE_SET HEADERS` を使う（推奨）**

21.4節で述べたとおり、`BASE_DIRS` と `DESTINATION` が2つの世界のパスを両方設定してくれる。**ジェネレータ式を書く必要がない。**

**方法2：ジェネレータ式で書き分ける**

```cmake
target_include_directories(pixkit-codec
    PUBLIC
        $<BUILD_INTERFACE:${CMAKE_CURRENT_SOURCE_DIR}/include>
        $<INSTALL_INTERFACE:${CMAKE_INSTALL_INCLUDEDIR}>
)
```

| ジェネレータ式 | 有効になる場面 |
| --- | --- |
| `$<BUILD_INTERFACE:X>` | ビルドツリーから使うとき |
| `$<INSTALL_INTERFACE:X>` | **インストール先から使うとき（相対パス）** |

`$<INSTALL_INTERFACE:>` の中は**インストールプレフィックスからの相対パス**を書く。絶対パスを書くと同じエラーになる。

**方法3：`install(EXPORT)` を使わない**

エクスポートしなければこのエラーは出ない。しかし、それでは `find_package` 対応にならない（第22章）。

### なぜ気づきにくいのか

**このエラーは `install(EXPORT)` を書くまで出ない。** 第9章の時点では絶対パスをそのまま書いても何も起きなかった。第9章の発展課題1で「いまは通ってしまうことを確認しておく」と書いたのは、このためだ。

つまり、**インストールを後回しにすると、あとで全ターゲットを直すことになる。** 最初から `$<BUILD_INTERFACE:>` か `FILE_SET HEADERS` で書いておくのが正しい。

## ハンズオン：`pixkit` をインストールする

### 手順1：`GNUInstallDirs` を読み込む

トップレベルの `CMakeLists.txt` の、`project()` の直後に追加する。

```cmake
project(pixkit VERSION 0.1.0 ... LANGUAGES CXX)

include(GNUInstallDirs)
```

### 手順2：ライブラリを `FILE_SET HEADERS` に移行する

`libs/core/CMakeLists.txt` は第10章ですでに `FILE_SET HEADERS` を書いてある。`codec` と `filter` にも追加する。

`libs/codec/CMakeLists.txt`

```cmake
add_library(pixkit-codec STATIC src/ppm.cpp)
add_library(pixkit::codec ALIAS pixkit-codec)

target_sources(pixkit-codec
    PUBLIC
        FILE_SET HEADERS
            BASE_DIRS "${CMAKE_CURRENT_SOURCE_DIR}/include"
            FILES     "${CMAKE_CURRENT_SOURCE_DIR}/include/pixkit/codec/ppm.hpp"
    PRIVATE
        src/detail/binary_io.hpp
)

target_include_directories(pixkit-codec
    PRIVATE ${CMAKE_CURRENT_SOURCE_DIR}/src
)

target_link_libraries(pixkit-codec
    PUBLIC  pixkit::core
    PRIVATE pixkit::warnings
)

set_target_properties(pixkit-codec PROPERTIES FOLDER "libs")
```

**`target_include_directories` から `PUBLIC` の行が消えた。** `FILE_SET HEADERS` が肩代わりしている（21.4節）。`PRIVATE` の `src` は内部ヘッダ用なので残す。

`libs/filter/CMakeLists.txt` も同様に。**生成されたエクスポートヘッダを忘れないこと。**

```cmake
target_sources(pixkit-filter
    PUBLIC
        FILE_SET HEADERS
            BASE_DIRS
                "${CMAKE_CURRENT_SOURCE_DIR}/include"
                "${CMAKE_CURRENT_BINARY_DIR}/gen"
            FILES
                "${CMAKE_CURRENT_SOURCE_DIR}/include/pixkit/filter/filters.hpp"
                "${CMAKE_CURRENT_BINARY_DIR}/gen/pixkit/filter/pixkit_filter_export.hpp"
)
```

`generate_export_header` の出力先を `${CMAKE_CURRENT_BINARY_DIR}/gen/pixkit/filter/` にしてあったので（第11章3節）、`BASE_DIRS` を `gen` にすれば `pixkit/filter/` の構造が保たれる。

### 手順3：インストール規則を書く

トップレベルの `CMakeLists.txt` の末尾に追加する。

```cmake
# ============================================================
# インストール
# ============================================================
if(PROJECT_IS_TOP_LEVEL OR PIXKIT_INSTALL)
    install(TARGETS
                pixkit_options
                pixkit-core
                pixkit-codec
                pixkit-filter
            EXPORT pixkit-targets
            RUNTIME       DESTINATION ${CMAKE_INSTALL_BINDIR}
            LIBRARY       DESTINATION ${CMAKE_INSTALL_LIBDIR}
            ARCHIVE       DESTINATION ${CMAKE_INSTALL_LIBDIR}
            FILE_SET HEADERS DESTINATION ${CMAKE_INSTALL_INCLUDEDIR}
    )

    if(PIXKIT_BUILD_APPS)
        install(TARGETS pixcli
                RUNTIME DESTINATION ${CMAKE_INSTALL_BINDIR})
    endif()

    install(FILES
                "${CMAKE_CURRENT_SOURCE_DIR}/LICENSE"
                "${CMAKE_CURRENT_SOURCE_DIR}/README.md"
            DESTINATION "${CMAKE_INSTALL_DATAROOTDIR}/pixkit"
    )

    if(MSVC)
        install(FILES $<TARGET_PDB_FILE:pixkit-filter>
                DESTINATION ${CMAKE_INSTALL_BINDIR} OPTIONAL)
    endif()
endif()
```

**`pixkit_options` もインストール対象に入れている。** 第7章7節で予告した問題への対処だ。`pixkit-core` が `pixkit::options` に `INTERFACE` でリンクしているので、これをエクスポートしないと第22章で失敗する。

`EXPORT pixkit-targets` は次章で使う。いまはエクスポートセットに登録しているだけだ。

`PIXKIT_INSTALL` オプションも追加しておく。

```cmake
option(PIXKIT_INSTALL "インストール規則を有効にする" ${PROJECT_IS_TOP_LEVEL})
```

**第14章7節と同じ配慮だ。** 他人が `add_subdirectory` で取り込んだとき、勝手に自分のファイルをインストール対象に混ぜない。

### 手順8：`$<INSTALL_INTERFACE:>` のエラーを起こす

`libs/codec/CMakeLists.txt` に、わざと絶対パスを追加する。

```cmake
target_include_directories(pixkit-codec
    PUBLIC  ${CMAKE_CURRENT_SOURCE_DIR}/include      # ← 追加（ジェネレータ式なし）
    PRIVATE ${CMAKE_CURRENT_SOURCE_DIR}/src
)
```

```
cmake --preset x64-release
```

```
CMake Error in libs/codec/CMakeLists.txt:
  Target "pixkit-codec" INTERFACE_INCLUDE_DIRECTORIES property contains path:

    "C:/work/pixkit/libs/codec/include"

  which is prefixed in the source directory.
```

**21.7節で説明したエラーだ。** 第9章の時点では通っていた記述が、`install(EXPORT ...)` を書いた瞬間にエラーになる。

### 手順9：コンポーネント分割を試す

インストール規則を書き換える。

```cmake
install(TARGETS pixkit_options pixkit-core pixkit-codec pixkit-filter
        EXPORT pixkit-targets
        RUNTIME       DESTINATION ${CMAKE_INSTALL_BINDIR}        COMPONENT runtime
        LIBRARY       DESTINATION ${CMAKE_INSTALL_LIBDIR}        COMPONENT runtime
```

### 発展課題

1. `install(DIRECTORY)` 方式に書き換え、`FILE_SET HEADERS` と結果を比較する
2. `binary_io.hpp` を `FILE_SET HEADERS` に含めてしまい、内部ヘッダが漏れることを確認する

## この章のまとめ

- インストールとは、**必要なファイルだけを決まった構造で別の場所にコピーする**こと。`CMAKE_INSTALL_PREFIX`（プリセットの `installDir`）で行き先を決め、**既定値（`C:/Program Files/`）は使わない**
- `install(TARGETS)` の種別は **`RUNTIME`（`.exe` と `.dll`）／`ARCHIVE`（`.lib`）／`LIBRARY`（Unixの `.so`）**。**Windowsで DLL は `RUNTIME`**
- **`include(GNUInstallDirs)`** を、インストール関連の記述より前に置く
- ヘッダは **`FILE_SET HEADERS`** でインストールする。`BASE_DIRS` からの構造が保たれ、**ソースツリーと生成ヘッダを同じ階層にまとめられる**。しかも `target_include_directories` の `$<BUILD_INTERFACE:>` / `$<INSTALL_INTERFACE:>` を書かなくて済む
- ライセンスは配布物に含める。PDBは **`OPTIONAL`** を付ける。外部DLLは `install(RUNTIME_DEPENDENCY_SET)` で扱えるが、**除外パターンを書かないとシステムDLLまでコピーされる**
- **`cmake --install` の出力を毎回読む。** 意図しないものが混ざっていないかは、見ないと分からない
- `COMPONENT` で「ランタイム」と「開発用」を分割できる
- **絶対パスを `PUBLIC` に書くと `install(EXPORT)` でエラーになる。** `$<BUILD_INTERFACE:>` か `FILE_SET HEADERS` を使う。**このエラーは第22章の記述を書くまで出ない**ので、最初から正しく書いておく

次の第22章では、`install(EXPORT)` を使って **`find_package(pixkit CONFIG REQUIRED)` で使えるパッケージ**に仕上げる。この章で `EXPORT pixkit-targets` と書いておいたものが、そこで実を結ぶ。
