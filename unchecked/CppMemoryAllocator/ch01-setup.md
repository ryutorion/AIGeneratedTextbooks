# 第1章 5分でビルドできる状態にする

---

## この章のゴール

この本は、次の章からいきなりアロケーターを書きはじめます。だからこの章でやることは1つだけです。

> **「書いたコードが、すぐビルドできて、すぐ実行できる」状態を作る。**

具体的には、この章が終わったときに次の状態になっています。

- Visual Studio 2022 でコンソールアプリのプロジェクトが1つできている
- C++23 の機能が使える設定になっている
- 日本語のコメントや出力が文字化けしない
- `std::println("Hello, allocator")` が動く
- 自分の環境が本書の前提を満たしているか、プログラムが自分で教えてくれる

環境構築の話は退屈です。ですが、ここで手を抜くと第6章あたりで「なぜか `<print>` が見つからない」「日本語コメントで警告が出る」といった、本題と無関係なところで時間を溶かします。5分で終わらせて、さっさと第2章に行きましょう。

> **すでに VS2022 で C++23 のプロジェクトを日常的に作っている人へ**
> 1.6節のチェックプログラムだけ実行して、結果が期待どおりなら1.9節まで飛ばして構いません。

## 1.1 必要なもの

### Visual Studio 2022 のインストール

本書は **Visual Studio 2022 バージョン 17.9 以降** を前提とします。この版から MSVC の標準ライブラリに `<print>` が入ったためです。可能なら最新版を入れてください。

Community エディションで十分です。個人開発や小規模チームでは無償で使えます。

インストーラーを起動したら、**ワークロード** タブで次の1つだけチェックします。

- ☑ **C++ によるデスクトップ開発**

これだけで、MSVC コンパイラ、Windows SDK、CMake、デバッガ、プロファイラが揃います。ゲーム関連のワークロード(「C++ によるゲーム開発」など)は本書では不要です。ディスクを節約したい人はチェックしないでください。

「個別のコンポーネント」タブは基本的に触らなくて構いません。ただし1つだけ、後の章(第31章)で使うものがあります。今から入れておくと後で楽です。

- ☑ **C++ AddressSanitizer**

インストールには10〜20分ほどかかります。その間にこの先を読み進めてください。

### すでに VS2022 が入っている場合

バージョンを確認します。メニューの **ヘルプ → Microsoft Visual Studio のバージョン情報** で確認できます。17.9 より古ければ、Visual Studio Installer から「更新」を実行してください。

## 1.2 プロジェクトを作る

Visual Studio を起動し、**新しいプロジェクトの作成** を選びます。

1. テンプレート一覧から **コンソール アプリ** を選択
   - 言語フィルタが「C++」、プラットフォームが「Windows」になっていることを確認
   - よく似た名前の「空のプロジェクト」や C# 版のコンソールアプリと間違えないでください
2. **プロジェクト名** に `Playground` と入力
3. **ソリューション名** を `GrowingAllocator` に変更
4. 「ソリューションとプロジェクトを同じディレクトリに配置する」は **チェックを外す**
5. **作成**

なぜソリューション名とプロジェクト名を分けるのか。第13章で、育てたアロケーターを静的ライブラリ `AllocatorLib` として切り出し、`Playground` から使う構成にするからです。そのときソリューションの下にプロジェクトが2つ並びます。今のうちに入れ物を用意しておくと、あとで移行が楽になります。

できあがったフォルダ構成はこうなります。

```
GrowingAllocator/
├─ GrowingAllocator.sln
└─ Playground/
   ├─ Playground.vcxproj
   └─ Playground.cpp
```

### いったんビルドしてみる

`Playground.cpp` には自動生成された `Hello World!` のコードが入っています。まずはこれをビルドします。

**Ctrl + Shift + B**(ソリューションのビルド)を押してください。出力ウィンドウの最後にこう出れば成功です。

```
========== ビルド: 1 正常終了、0 失敗、0 更新不要、0 スキップ ==========
```

**Ctrl + F5**(デバッグなしで開始)を押すと、コンソールウィンドウが開いて `Hello World!` と表示されます。

ここまで来れば、コンパイラとリンカは正しく動いています。あとは設定を本書向けに調整するだけです。

## 1.3 構成とプラットフォームを決める

画面上部のツールバーに、2つのドロップダウンがあります。

- 左:**構成**(`Debug` / `Release`)
- 右:**プラットフォーム**(`x64` / `x86`)

まず **プラットフォームを `x64`** にしてください。新規プロジェクトの既定は x64 のはずですが、念のため確認します。本書は64ビット環境を前提とし、ポインタサイズは8バイトとして話を進めます。

構成については、本書ではこう使い分けます。

| 構成 | 用途 |
|---|---|
| `Debug` | バグを仕込んで検出する実験、デバッガでのステップ実行 |
| `Release` | **速度の計測は必ずこちら** |

これは強調しておきます。Debug 構成の MSVC は、変数を初期化パターンで塗りつぶし、境界チェックを入れ、インライン展開を止めます。`std::vector` の要素アクセスすら関数呼び出しになります。Debug 構成で測った「速い/遅い」は、ほぼ意味がありません。

第4章でベンチマークの道具を作りますが、そこで測るのは常に Release 構成です。

## 1.4 C++23 を有効にする

ここが本章のいちばん重要な設定です。

### 設定画面を開く

ソリューションエクスプローラーで **`Playground` プロジェクトを右クリック → プロパティ**。

### ⚠ 最初にやること:「すべての構成」に切り替える

プロパティページの左上に「構成」というドロップダウンがあります。既定では `Debug` などになっているはずです。これを **「すべての構成」** に変更してください。プラットフォームも **「すべてのプラットフォーム」** にします。

これを忘れると、Debug では通るのに Release でビルドが壊れる、という現象に必ず遭遇します。設定変更のたびに確認する癖をつけてください。**本書でプロパティを変更するときは、常に「すべての構成」です。**

### 言語標準を変える

**構成プロパティ → 全般 → C++ 言語標準** を開きます。

既定では「ISO C++20 標準 (/std:c++20)」あたりになっています。これを次に変更します。

> **プレビュー - 最新の C++ 作業ドラフトの機能 (/std:c++latest)**

MSVC には `/std:c++23` という選択肢がありません。C++23 の機能を使うには `/std:c++latest` を選ぶ必要があります。「プレビュー」という名前に不安を感じるかもしれませんが、本書で使う範囲(`std::expected`、`std::print`、`std::stacktrace` など)は正式に規格化されたものです。

### 追加のコンパイラオプションを入れる

**構成プロパティ → C/C++ → コマンド ライン** を開き、「追加のオプション」欄に次の2行を貼り付けます。

```
/utf-8
/Zc:__cplusplus
```

それぞれ何のためのものか説明します。

#### `/utf-8` — 文字化けを防ぐ

日本語圏の開発者にとって、これは実質必須です。

MSVC は既定で、ソースファイルの文字コードをシステムのロケール(日本語 Windows なら CP932)として解釈します。一方、Visual Studio のエディタや Git は UTF-8 でファイルを保存するのが普通です。この食い違いが、次のような症状を生みます。

- 日本語コメントに対して `warning C4819` が出る
- 文字列リテラルの日本語が実行時に化ける
- 「表」「ソ」「能」など特定の漢字を含むコメントで、**次の行が消える**(いわゆるダメ文字問題)

`/utf-8` は「ソースは UTF-8、実行時の文字列も UTF-8」とコンパイラに宣言するオプションです。1行足すだけで、これらの問題がまとめて消えます。

#### `/Zc:__cplusplus` — バージョンマクロを正しくする

歴史的な事情により、MSVC は既定で `__cplusplus` マクロの値を `199711L`(C++98 相当)と報告します。`/std:c++latest` を指定していてもです。

この値は、ライブラリが「この環境ではどの機能が使えるか」を判断するのに使われます。放置すると、正しく書いたコードが「C++98 環境向けの経路」に落ちてビルドが通らない、といった不可解な現象が起きます。1.6節のチェックプログラムでもこの値を確認します。

### 確認

**OK** を押して閉じ、**Ctrl + Shift + B** でビルドが通ることを確認してください。

## 1.5 「Hello, allocator」を書く

`Playground.cpp` の中身を全部消して、次に置き換えます。

```cpp
#include <print>

int main()
{
    std::println("Hello, allocator");
}
```

**Ctrl + F5** で実行。

```
Hello, allocator
```

と出れば成功です。

たった4行ですが、この時点で確認できたことは意外に多くあります。

- `/std:c++latest` が効いている(`<print>` は C++23 の機能です)
- 標準ライブラリのバージョンが十分に新しい
- リンクが通っている

### `std::println` について

`std::print` / `std::println` は C++23 で追加された出力機能です。本書ではこれを標準の出力手段として使います。理由は3つあります。

**書式指定が安全で読みやすい。** `printf` と違って型を書き間違えられません。

```cpp
std::println("確保サイズ: {} バイト, アドレス: {}", size, ptr);
```

**`std::cout` の `<<` 地獄から解放される。** 16進表示やパディングを組み合わせると、`std::cout` の書式操作子は途端に読めなくなります。本書ではアドレスやサイズを大量に表示するので、この差は効いてきます。

```cpp
// std::cout 版
std::cout << "0x" << std::hex << std::setw(16) << std::setfill('0') << addr << "\n";

// std::print 版
std::println("{:#018x}", addr);
```

**Windows のコンソールで Unicode がそのまま出る。** MSVC の実装は、出力先がコンソールのとき内部で `WriteConsoleW` を使います。日本語をそのまま出しても化けません。

書式指定の詳しい文法は、必要になった章で都度説明します。今は「`{}` が値の埋め込み場所」とだけ覚えておけば十分です。

### `<print>` が使えなかった場合の代替

環境の都合で `<print>` がどうしても使えない場合は、次のように置き換えてください。本書のコードはこの差し替えだけで動きます。

```cpp
#include <format>
#include <iostream>

template <class... Args>
void Println(std::format_string<Args...> fmt, Args&&... args)
{
    std::cout << std::format(fmt, std::forward<Args>(args)...) << '\n';
}
```

ただし、これは最後の手段です。まずは Visual Studio の更新を試してください。

## 1.6 環境チェックプログラムを走らせる

設定が本当に効いているかを、目視ではなくプログラムに確認させます。`Playground.cpp` を次のように書き換えてください。

```cpp
#include <print>
#include <version>   // 機能テストマクロの定義

int main()
{
    std::println("=== 本書の動作環境チェック ===");

    // --- コンパイラのバージョン ---
    std::println("MSVC バージョン (_MSC_VER) : {}", _MSC_VER);

    // --- 言語標準 ---
    std::println("__cplusplus               : {}", __cplusplus);

    // --- ビット数 ---
    std::println("ポインタのサイズ          : {} バイト", sizeof(void*));

    // --- ビルド構成 ---
#ifdef NDEBUG
    std::println("ビルド構成                : Release");
#else
    std::println("ビルド構成                : Debug");
#endif

    std::println("");
    std::println("--- 本書で使う C++23 機能 ---");

    // --- 個々の機能が使えるか ---
#ifdef __cpp_lib_print
    std::println("[  OK  ] std::print       ({})", __cpp_lib_print);
#else
    std::println("[ NG!! ] std::print       が使えません");
#endif

#ifdef __cpp_lib_expected
    std::println("[  OK  ] std::expected    ({})", __cpp_lib_expected);
#else
    std::println("[ NG!! ] std::expected    が使えません");
#endif

#ifdef __cpp_lib_stacktrace
    std::println("[  OK  ] std::stacktrace  ({})", __cpp_lib_stacktrace);
#else
    std::println("[ NG!! ] std::stacktrace  が使えません");
#endif

#ifdef __cpp_lib_span
    std::println("[  OK  ] std::span        ({})", __cpp_lib_span);
#else
    std::println("[ NG!! ] std::span        が使えません");
#endif

    std::println("");
    std::println("日本語が化けずに表示されていれば /utf-8 は有効です。");
}
```

### 期待される出力

Release 構成で実行すると、こうなるはずです(数値は環境によって多少前後します)。

```
=== 本書の動作環境チェック ===
MSVC バージョン (_MSC_VER) : 1944
__cplusplus               : 202302
ポインタのサイズ          : 8 バイト
ビルド構成                : Release

--- 本書で使う C++23 機能 ---
[  OK  ] std::print       (202207)
[  OK  ] std::expected    (202211)
[  OK  ] std::stacktrace  (202011)
[  OK  ] std::span        (202311)

日本語が化けずに表示されていれば /utf-8 は有効です。
```

### 結果の読み方

| 表示 | 期待値 | 違っていたら |
|---|---|---|
| `_MSC_VER` | 1939 以上 | Visual Studio を更新する(1.1節) |
| `__cplusplus` | `199711` 以外 | `/Zc:__cplusplus` が入っていない(1.4節) |
| ポインタのサイズ | 8 | プラットフォームが x86 になっている(1.3節) |
| `[ NG!! ]` がある | なし | `/std:c++latest` になっていない(1.4節) |
| 日本語が化ける | 化けない | `/utf-8` が入っていない(1.4節) |

### 機能テストマクロという仕組み

`__cpp_lib_print` のようなマクロは **機能テストマクロ** と呼ばれ、「その機能が実装済みなら定義される」という約束になっています。値は「その機能が規格に採択された年月」です。`202207` なら2022年7月です。

コンパイラのバージョン番号で分岐を書くと、コンパイラごとに条件が増えて手に負えなくなります。機能テストマクロなら「使いたい機能があるか」を直接聞けます。本書でも、環境差を吸収する必要があるときはこの方法を使います。

### Debug 構成でも確認する

構成を `Debug` に切り替えて、もう一度 **Ctrl + F5**。

「ビルド構成: Debug」に変わり、それ以外の行が Release と同じであることを確認してください。ここで `[ NG!! ]` が出るなら、1.4節の「すべての構成」を選び忘れています。

確認できたら、構成を `Release` に戻しておきましょう。

## 1.7 詰まったら:よくあるビルドエラー

### エラー1:`fatal error C1083: include ファイルを開けません。'print':No such file or directory`

**原因は2つ考えられます。**

**(a) 言語標準が C++23 になっていない**

いちばん多い原因です。1.4節に戻って、C++ 言語標準が `/std:c++latest` になっているか確認してください。「すべての構成」を選び忘れていて、片方の構成だけ古い設定のままというパターンも頻出します。

**(b) Visual Studio が古い**

チェックプログラムの `_MSC_VER` が 1939 未満なら、標準ライブラリに `<print>` 自体が存在しません。Visual Studio Installer から更新してください。更新できない事情があれば、1.5節末尾の代替コードを使います。

---

### エラー2:`warning C4819` が大量に出る / 日本語が化ける / 意味不明な構文エラー

```
warning C4819: ファイルは、現在のコード ページ (932) で表示できない文字を含んでいます。
```

`/utf-8` が入っていません。1.4節の「追加のオプション」を確認してください。

とくに厄介なのが、**警告ではなく構文エラーとして現れる**ケースです。コメントに「表」「ソ」「能」「暴」などの漢字が含まれていると、CP932 として解釈されたときに行末のバックスラッシュ扱いになり、次の行がコメントに巻き込まれて消えます。

```cpp
// このアロケーターの性能を測る   ← 「能」でやられる
int x = 0;                        ← この行が消える!
```

エラーメッセージは「`x` は未定義の識別子です」といった、原因と全く関係ないものになります。日本語コメントを書いた直後に不可解なエラーが出たら、まず `/utf-8` を疑ってください。

---

### エラー3:`__cplusplus` が `199711` のまま / ライブラリが古い経路に落ちる

`/Zc:__cplusplus` が入っていません。1.4節を確認してください。

このオプションを忘れたときの症状は分かりにくいのが特徴です。ビルドは通るのに一部の機能だけ使えない、サードパーティのヘッダが「C++11 以降が必要です」と `#error` を出す、といった形で現れます。本書の範囲では第38章以降で問題になりやすい部分です。

---

### そのほか、遭遇しやすいもの

**「デバッグなしで開始」でウィンドウが一瞬で閉じる**

**Ctrl + F5**(デバッグなしで開始)ではなく **F5**(デバッグ開始)を押しています。F5 の場合、プログラム終了と同時にコンソールが閉じます。本書のサンプルは Ctrl + F5 で実行してください。

**`std::println` で `{}` の数と引数の数が合わない**

C++20 以降の書式文字列はコンパイル時に検証されます。これは親切な機能ですが、エラーメッセージはテンプレートの奥深くを指すことがあります。まず `{}` の個数を数えてください。

**中括弧そのものを出力したい**

`{{` と `}}` で書きます。

```cpp
std::println("構造体 {{ size = {} }}", 16);
// → 構造体 { size = 16 }
```

## 次章の予告

環境は整いました。次の章から、いよいよアロケーターを書きます。

第2章で書くのは、**20行足らずのクラス**です。メモリを大きく1本確保して、要求されたぶんだけポインタを進めて返す。それだけです。解放処理はありません。エラー処理もありません。アラインメントも考えません。

「そんなものがアロケーターと呼べるのか」と思うかもしれません。ですが、そのクラスは第5章で `new` に対して**10倍以上の速度差**をつけます。そして本書の残り50章は、この20行に少しずつ手を入れて、実戦で使えるものへ育てていく作業です。

まずは動くものを作りましょう。

> だから今のうちに、**「環境は正しい」と言い切れる状態**を作っておきます。この先バグに出会ったとき、疑うべき対象を1つ減らせる。それだけのために、この章はあります。
